# 第七章：排版规范——专业感从细节来

## 核心观点

**排版不是装饰，是降低阅读阻力。**

## 7.1 微信排版三原则

1. **留白**：段与段之间空一行，块与块之间空两行
2. **对齐**：全文左对齐，不要两端对齐（字间距会乱）
3. **克制**：全文最多 2 种颜色、3 种字号

## 7.2 正文参数

**文字：**

- 字号：15-16px（微信默认 16px）
- 行高：1.75-2 倍
- 字间距：1-2px
- 段间距：空一行
- 对齐：左对齐
- 每段不超过 4 行（手机屏幕上约 3-4 屏）

**颜色：**

- 正文：#333333 或 #2f2f2f（不要纯黑）
- 强调：1 种主题色（与第 4 章的强调色一致）
- 辅助：灰色 #888888 或 #999999
- 背景：白色或浅灰 #f5f5f5

**层级：**

- 小标题用字号和留白区分，不要全文堆加粗
- 一级标题与上一段之间空两行，正文与代码块之间空一行
- 重点句可以单独成段，但每篇不超过 3 处

## 7.3 代码块排版

**技术号必备。** 用 Markdown 或第三方工具（如 Markdown Nice）：

```
推荐样式：
- 背景：#1e1e1e 或 #2d2d2d（深色）
- 文字：#f0f0f0（浅色）
- 圆角：4-8px
- 内边距：16px
- 行号：可选，长代码建议开
```

**规范：**

- 代码必须可复制，不要用截图代替
- 一段代码只讲一件事，超过 20 行就拆分
- 修复类文章用"修复前 / 修复后"两段对照，配一行注释说明改动点
- 终端输出和代码分开标注，别混在一起

**禁忌：** 不要截终端截图当代码块（模糊、不可复制、暗色背景下对比度差）。

## 7.4 图片处理

| 类型 | 要求 |
| --- | --- |
| 封面图 | 750×320，核心内容居中（见第 4 章） |
| 文中图 | 宽度 100%，高度自适应 |
| 流程图 | SVG 或高清 PNG，不要模糊截图 |
| 表情包 | 少用，除非是人设需要 |

**注意：** 微信会把超过一定宽度的图片压缩，流程图优先用 SVG 或 2 倍图；截图前调大系统字号，避免读者放大才能看清。

## 7.5 排版工具

| 工具 | 适合人群 | 特点 |
| --- | --- | --- |
| 微信自带编辑器 | 新手 | 简单，功能少 |
| Markdown Nice | 技术人 | 支持 Markdown，代码块好看 |
| 135 编辑器 | 运营 | 模板多，样式丰富 |
| 秀米 | 设计感 | 自由度高，学习成本稍高 |

**建议：** 技术号用 Markdown 写作 + Markdown Nice 排版，代码块和链接处理最省心；模板定下来后不要频繁更换。

## 7.6 发布前自检

- 手机预览一遍，检查字号、留白、代码块是否溢出
- 每段不超过 4 行，长段落拆开
- 全文颜色 ≤2 种、字号 ≤3 种
- 代码可复制，修复前后对照清楚
- 图片不模糊、不拉伸、无水印遮挡
- 文中链接在微信内可正常打开
