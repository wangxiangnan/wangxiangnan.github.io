# 第 17 章 类型提示与 MyPy

假设你去一家餐厅吃饭。菜单上写着"招牌菜"、"特色汤"，但不告诉你具体是什么食材、多少钱——你只能猜。没有类型提示的 Python 代码就像这种菜单：

```python
def process(data, config):
    # data 是什么？字典？列表？数据框？
    # config 有哪些字段？
    # 返回值是什么？
    ...
```

Python 从 3.5 版本开始引入了类型提示（Type Hints），让你可以在函数签名和变量声明中标注类型。这些注解不会影响运行（Python 解释器会忽略它们），但 IDE 可以据此提供智能补全，静态分析工具（如 MyPy）可以在运行前发现类型错误。类型提示就像给代码贴上了标签——不改变代码行为，但让人和工具都能更好地理解代码。

## 17.1 基本类型注解

### 函数参数与返回值

```python
def greet(name: str, age: int) -> str:
    """name 是字符串，age 是整数，返回字符串"""
    return f"你好，{name}！你今年 {age} 岁了。"

# 类型提示不影响运行
print(greet("小明", 20))        # 正常执行
print(greet(123, "二十"))       # 也能执行！Python 运行时不检查类型
```

注意：类型提示只是"提示"，Python 解释器在运行时完全忽略它们。上面的代码即使传入了错误类型也不会报错——要检查类型错误，需要使用 MyPy 等静态分析工具。

### 变量注解

```python
# 基本类型
name: str = "Alice"
age: int = 25
height: float = 1.68
is_student: bool = True

# 复杂类型
scores: list[int] = [90, 85, 92]
config: dict[str, int] = {"timeout": 30, "retries": 3}
names: tuple[str, ...] = ("Alice", "Bob", "Charlie")

# Python 3.10+ 可以用 | 代替 Union
value: int | str = "hello"
value = 42  # 也可以
```

小贴士：Python 3.9+ 可以直接用 `list`、`dict`、`tuple` 等内置类型做注解（不用从 `typing` 导入了）。Python 3.10+ 可以用 `X | Y` 代替 `Union[X, Y]`。如果你在维护旧项目，可能还需要用 `typing.List` 等写法。

## 17.2 Optional、Union 与 TypeAlias

### Optional：值可能是 None

```python
# Python 3.10+ 写法
def find_user(user_id: int) -> dict | None:
    """查找用户，找不到返回 None"""
    users = {1: {"name": "Alice"}, 2: {"name": "Bob"}}
    return users.get(user_id)

# 旧写法（等价）
from typing import Optional
def find_user_old(user_id: int) -> Optional[dict]:
    return users.get(user_id)
```

`Optional[X]` 等价于 `X | None`（或 `Union[X, None]`）。它告诉读者和工具："这个值可能是 X，也可能是 None，你得处理 None 的情况。"

### Union：多种类型之一

```python
from typing import Union

# 参数可以是字符串或整数
def parse_id(value: str | int) -> int:
    if isinstance(value, str):
        return int(value)
    return value

print(parse_id("42"))  # 42
print(parse_id(42))    # 42
```

### TypeAlias：给复杂类型取别名

```python
from typing import TypeAlias

# 给复杂类型取个简洁的名字
UserId: TypeAlias = int
UserData: TypeAlias = dict[str, str | int]
Matrix: TypeAlias = list[list[float]]

def get_user(user_id: UserId) -> UserData:
    return {"name": "Alice", "age": 25}

def multiply_matrix(a: Matrix, b: Matrix) -> Matrix:
    ...
```

## 17.3 typing 模块深入

### Callable：函数类型

```python
from typing import Callable

# Callable[[参数类型...], 返回类型]
def apply_twice(func: Callable[[int], int], value: int) -> int:
    return func(func(value))

def double(x: int) -> int:
    return x * 2

print(apply_twice(double, 3))  # 12  (3 → 6 → 12)

# 更实际的例子：回调函数
def fetch_data(url: str, on_success: Callable[[str], None]) -> None:
    data = f"data from {url}"
    on_success(data)

fetch_data("https://api.example.com", print)
```

### Generic：泛型

泛型让你编写"不关心具体类型"的代码：

```python
from typing import TypeVar, Generic

T = TypeVar("T")

class Stack(Generic[T]):
    """泛型栈：可以存放任意类型的元素"""

    def __init__(self) -> None:
        self._items: list[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> T:
        if not self._items:
            raise IndexError("栈为空")
        return self._items.pop()

    def peek(self) -> T:
        if not self._items:
            raise IndexError("栈为空")
        return self._items[-1]


# 使用时指定类型参数
int_stack: Stack[int] = Stack()
int_stack.push(1)
int_stack.push(2)
print(int_stack.pop())  # 2

str_stack: Stack[str] = Stack()
str_stack.push("hello")
print(str_stack.peek())  # hello
```

### Protocol：结构化子类型（鸭子类型的形式化）

`Protocol` 是 Python 类型系统中非常强大的特性。它不需要继承，只要对象"长得像"就算匹配：

```python
from typing import Protocol

class Drawable(Protocol):
    """任何有 draw() 方法的对象都满足这个协议"""
    def draw(self) -> str:
        ...

class Circle:
    def draw(self) -> str:
        return "○"

class Square:
    def draw(self) -> str:
        return "□"

# Circle 和 Square 没有继承 Drawable，但有 draw 方法，所以满足协议
def render(shape: Drawable) -> None:
    print(shape.draw())

render(Circle())  # ○
render(Square())  # □
```

小贴士：`Protocol` 是"鸭子类型"的类型化版本——如果一个东西走起来像鸭子、叫起来像鸭子，那类型系统就认为它是鸭子。

## 17.4 MyPy：静态类型检查

MyPy 是 Python 官方推荐的类型检查工具。它读取你的类型注解，在不运行代码的情况下检查类型是否正确。

### 安装与基本使用

```bash
# 安装
pip install mypy

# 检查单个文件
mypy my_script.py

# 检查整个项目
mypy src/

# 严格模式（推荐新项目使用）
mypy --strict src/
```

### MyPy 能发现的问题

```python
# mypy_test.py

def calculate_bmi(weight: float, height: float) -> float:
    return weight / (height ** 2)

# MyPy 会发现以下错误：
bmi = calculate_bmi("70", 1.75)   # error: 参数类型 str 不匹配 float
result: int = calculate_bmi(70, 1.75)  # error: float 不能赋值给 int

# MyPy 也能发现 None 相关的错误
def get_name(user: dict | None) -> str:
    return user["name"]  # error: user 可能是 None

# 正确写法
def get_name_safe(user: dict | None) -> str:
    if user is None:
        return "Unknown"
    return user["name"]  # MyPy 知道这里 user 不是 None
```

### MyPy 配置文件

在项目根目录创建 `mypy.ini`（或 `pyproject.toml` 中的 `[tool.mypy]` 部分）：

```ini
# mypy.ini
[mypy]
python_version = 3.11
warn_return_any = True
warn_unused_configs = True
disallow_untyped_defs = True  # 所有函数必须有类型注解
check_untyped_defs = True     # 也检查没有注解的函数

# 对第三方库的宽松配置
[mypy-requests.*]
ignore_missing_imports = True

[mypy-numpy.*]
ignore_missing_imports = True
```

### 处理第三方库缺少类型信息

```python
# 当第三方库没有类型存根（stubs）时，MyPy 会警告
# 解决方案 1：安装类型存根包
# pip install types-requests types-PyYAML

# 解决方案 2：在 mypy.ini 中忽略
# [mypy-requests.*]
# ignore_missing_imports = True

# 解决方案 3：在代码中加 type: ignore
import some_untyped_library  # type: ignore
```

## 17.5 Pydantic 与类型提示

Pydantic 是一个数据验证库，它把类型提示从"静态检查"推向了"运行时验证"。你定义数据模型，Pydantic 自动验证和转换数据：

```python
from pydantic import BaseModel, Field, ValidationError
from datetime import datetime


class User(BaseModel):
    """用户模型"""
    name: str = Field(min_length=1, max_length=50)
    age: int = Field(ge=0, le=150)
    email: str
    created_at: datetime = Field(default_factory=datetime.now)


# 自动验证和类型转换
user = User(name="Alice", age="25", email="alice@example.com")
print(user.age)          # 25（字符串 "25" 被自动转为 int）
print(user.created_at)   # 当前时间

# 验证失败会抛出清晰的错误
try:
    bad_user = User(name="", age=200, email="alice@example.com")
except ValidationError as e:
    print(e)
    # 2 validation errors for User
    # name: String should have at least 1 character
    # age: Input should be less than or equal to 150
```

### Pydantic 在 API 开发中的应用

```python
from pydantic import BaseModel, EmailStr
from typing import Optional


class UserCreate(BaseModel):
    """创建用户的请求模型"""
    username: str = Field(min_length=3, max_length=20)
    email: str
    password: str = Field(min_length=8)
    bio: Optional[str] = None


class UserResponse(BaseModel):
    """用户响应模型"""
    id: int
    username: str
    email: str
    bio: Optional[str] = None

    model_config = {"from_attributes": True}


def create_user(data: UserCreate) -> UserResponse:
    # data 已经被验证过了，放心使用
    user_id = 1  # 模拟数据库插入
    return UserResponse(
        id=user_id,
        username=data.username,
        email=data.email,
        bio=data.bio,
    )

# FastAPI 等框架深度集成 Pydantic
# @app.post("/users")
# def create_user_endpoint(user: UserCreate):
#     return create_user(user)
```

## 17.6 高级类型技巧

### Literal：限制值的范围

```python
from typing import Literal

def set_mode(mode: Literal["read", "write", "append"]) -> None:
    print(f"模式设为: {mode}")

set_mode("read")     # OK
# set_mode("delete")  # MyPy: error - "delete" 不在允许的值中
```

### TypedDict：字典的结构化类型

```python
from typing import TypedDict

class Movie(TypedDict):
    title: str
    year: int
    rating: float

# 字典的结构被明确定义
movie: Movie = {
    "title": "肖申克的救赎",
    "year": 1994,
    "rating": 9.7,
}

# MyPy 会检查：
# movie = {"title": "测试"}  # error: 缺少 year 和 rating
```

### overload：函数重载的类型签名

```python
from typing import overload

@overload
def parse(value: str) -> str: ...

@overload
def parse(value: int) -> int: ...

@overload
def parse(value: bytes) -> str: ...

def parse(value):
    """实际实现"""
    if isinstance(value, bytes):
        return value.decode("utf-8")
    return value
```

## 17.7 小贴士：类型提示的最佳实践

1. **新项目从一开始就用类型提示**，后期补会很痛苦。
2. **函数签名优先**：先给所有公开函数的参数和返回值加注解。
3. **不要在每个变量上都加注解**——如果类型很明显（`x = 42`），省略即可。
4. **用 `TypeAlias` 简化复杂类型**，提高可读性。
5. **CI 中集成 MyPy**：`mypy --strict src/` 作为构建检查的一部分。
6. **使用 `# type: ignore` 要谨慎**，加上注释说明为什么忽略。

## 17.8 延伸阅读

- **PEP 484**：类型提示的引入提案
- **PEP 585**：内置泛型类型（`list[int]` 代替 `typing.List[int]`）
- **PEP 604**：`X | Y` 联合类型语法
- **Pyright**：微软开发的类型检查器，速度比 MyPy 快
- **typeshed**：Python 标准库和第三方库的类型存根仓库

## 17.9 小结

类型提示是 Python 进化的重要方向——在保持动态灵活的同时，引入静态检查的安全网：

- **基本注解**：`name: str`、`def func(x: int) -> str`
- **复合类型**：`list[int]`、`dict[str, int]`、`X | None`（Optional）
- **typing 模块**：`Callable`、`Generic`、`Protocol`、`Literal`、`TypedDict`
- **MyPy**：静态类型检查工具，发现类型错误不靠运行
- **Pydantic**：将类型提示延伸到运行时验证

**第 2 题：**

```python
from typing import Protocol

class Sortable(Protocol):
    def __lt__(self, other: "Sortable") -> bool: ...

def sort_items(items: list[Sortable]) -> list[Sortable]:
    return sorted(items)
```

**第 3 题：**

```python
from pydantic import BaseModel
```

**第 4 题：**

```python
from typing import TypeVar, Generic

T = TypeVar("T")

class Pair(Generic[T]):
    def __init__(self, first: T, second: T) -> None:
        self.first = first
        self.second = second

    def swap(self) -> "Pair[T]":
        return Pair(self.second, self.first)
```

**第 5 题：**

MyPy 报错：`Item "None" of "str | None" has no attribute "__getitem__"`。修复：

```python
def get_first_char(s: str | None) -> str | None:
    if s is None:
        return None
    return s[0]
```

**第 6 题：**

```python
from typing import overload

@overload
def pad_string(s: str, width: int, fill_char: str = " ") -> str: ...
@overload
def pad_string(s: bytes, width: int, fill_char: bytes = b" ") -> bytes: ...

def pad_string(s, width, fill_char=" "):
    return s.ljust(width, fill_char)
```

**第 7 题：**

```python
from typing import Literal

def sort_data(data: list[int], order: Literal["asc", "desc"]) -> list[int]:
    return sorted(data, reverse=(order == "desc"))
```

## 17.12 常见错误与避坑

**1. 用了旧版语法在新版 Python 上**

```python
# Python 3.9+ 不需要 typing.List
from typing import List  # 不再需要
scores: List[int] = [1, 2, 3]  # 过时写法
scores: list[int] = [1, 2, 3]  # 推荐写法

# Python 3.10+ 不需要 Union/Optional
from typing import Union, Optional  # 不再需要
x: Union[int, str] = "hi"   # 过时写法
x: int | str = "hi"          # 推荐写法
```

**2. 可变默认参数 + 类型提示**

```python
# 类型提示没问题，但运行时有坑
def add_item(item: str, items: list[str] = []) -> list[str]:
    items.append(item)
    return items

# 多次调用共享同一个列表！
a = add_item("x")
b = add_item("y")
print(b)  # ['x', 'y'] ← 不是预期的 ['y']

# 正确做法
def add_item_safe(item: str, items: list[str] | None = None) -> list[str]:
    if items is None:
        items = []
    items.append(item)
    return items
```

**3. 忘记运行 MyPy 就以为类型正确**

类型注解本身不会在运行时检查类型。写了 `def func(x: int)` 并不意味着传字符串会报错——你必须运行 `mypy` 来检查。

**4. 过度注解**

```python
# 不需要这样：
x: int = 42          # 类型推断能搞定，不用写
name: str = "Alice"  # 同上

# 但函数签名应该写：
def greet(name: str) -> str:  # 这个值得写
    return f"Hello, {name}"
```

**5. 循环引用导致的 Forward Reference 问题**

```python
# 类引用自身时会报错（类还没定义完）
class Node:
    def __init__(self, value: int, next_node: Node):  # NameError!
        ...

# 解决方案 1：用字符串
class Node:
    def __init__(self, value: int, next_node: "Node"):
        ...

# 解决方案 2：Python 3.7+ 用 from __future__ import annotations
from __future__ import annotations

class Node:
    def __init__(self, value: int, next_node: Node):  # OK
        ...
```
