# 第 21 章：现代生态——Litestream/LiteFS/Turso/D1/加密

## 21.1 引言：SQLite 的文艺复兴

2020 年之后，SQLite 突然"又火了"。你能在 Hacker News 首页三天两头看到跟 SQLite 相关的项目：

- Litestream：SQLite 流式复制到 S3
- LiteFS：Fly.io 的分布式 SQLite FUSE
- Turso：SQLite 上云，边缘部署
- Cloudflare D1：Serverless SQLite
- rqlite：基于 Raft 的 SQLite 集群
- SQLite as-a-Service：一堆创业公司在做

为啥这么火？我总结几个原因：

1. **应用云化的成本反思**：过去以为"数据库必须重"，现在发现 90% 应用其实用 SQLite 就够
2. **边缘计算兴起**：Cloudflare Workers、Fly.io、Vercel Edge，全球分布式，SQLite 的"零启动"特性完美契合
3. **SQLite 官方的进化**：WAL、JSON、FTS5、生成列一步步完善
4. **数据本地化的诉求**：本地优先应用（local-first）思潮兴起，SQLite 是唯一选择

这一章我们逛一圈 SQLite 的现代生态。

## 21.2 Litestream：流式复制到云端

### 21.2.1 出场

作者：Ben Johnson（Boltdb、BoltDB 作者、Fly.io 员工）。

**核心思想**：SQLite 已经有 WAL 了，为啥不把 WAL 帧流式传到 S3？崩了从 S3 恢复。

### 21.2.2 工作原理

```
[App] --> [SQLite WAL] --> [Litestream 监听] --> [S3/GCS/Azure/FS]
```

Litestream 是一个独立进程：

1. 检测你的 SQLite 数据库的 WAL 变化
2. 把新增的 WAL 帧压缩、加密、上传到对象存储
3. 定期做完整 snapshot 上传
4. 出事了：从最近 snapshot + 后续 WAL 回放，重建数据库

**RPO（Recovery Point Objective）**：默认 1 秒，可配置。也就是最坏情况丢 1 秒数据。

### 21.2.3 部署示例

安装：

```bash
brew install benbjohnson/litestream/litestream
# 或者 Linux
wget https://github.com/benbjohnson/litestream/releases/download/v0.3.13/litestream-linux-amd64.tar.gz
tar -xzf litestream-linux-amd64.tar.gz
sudo mv litestream /usr/local/bin/
```

配置 `/etc/litestream.yml`：

```yaml
dbs:
  - path: /var/lib/myapp/app.db
    replicas:
      - type: s3
        bucket: my-app-backups
        path: prod/app.db
        region: us-east-1
        access-key-id: AKIA...
        secret-access-key: xxx
        retention: 72h
```

启动：

```bash
litestream replicate -config /etc/litestream.yml
```

恢复：

```bash
litestream restore -o /tmp/restored.db s3://my-app-backups/prod/app.db
```

**多简单**！你的 SQLite 数据库有了准实时的异地灾备。

### 21.2.4 Litestream 的优势与局限

优势：

- 零侵入：不改代码
- 便宜：只用对象存储，比开一个 RDS 便宜得多
- 简单：一个 YAML 就跑起来
- 复用 WAL：SQLite 本来就有的东西

局限：

- **单写者**：Litestream 只能有一个写节点。它是**备份**，不是**高可用**方案
- 恢复要时间：从 S3 拉回全部 WAL + snapshot，几分钟起
- 不适合读扩展：读节点还是要访问主库

### 21.2.5 适用场景

- 单体应用的异地灾备
- 小到中等规模 SaaS 的极简架构
- 想省数据库钱又要有备份的项目

**梗**：有人开玩笑说 Litestream 让 SQLite 变成"Postgres 的穷人替代品"。这个描述有点损但很贴切。

## 21.3 LiteFS：分布式 SQLite 的 FUSE 文件系统

### 21.3.1 出场

同样是 Ben Johnson 的作品，Fly.io 官方项目。

**核心思想**：把 SQLite 数据库放在 FUSE 文件系统里，让 LiteFS 拦截所有写操作，把 WAL 帧同步到其他节点。写在主，读在从。

### 21.3.2 架构

```
Node 1 (Primary):
  [App] -> [SQLite] -> [LiteFS FUSE] -> [WAL 帧广播]
                                            |
                                            v
Node 2 (Replica):                     [网络传输]
  [App (只读)] <- [SQLite] <- [LiteFS FUSE] <- [接收 WAL 帧]
Node 3 (Replica):
  [App (只读)] <- [SQLite] <- [LiteFS FUSE] <- [接收 WAL 帧]
```

- **写只能在 Primary**：从节点上写会被 LiteFS 拦截报错，或转发到主
- **读在任何节点**：主从都可读，副本延迟毫秒级
- **主节点故障**：手动或自动切换新主（用 Consul 做选主）

### 21.3.3 Fly.io 上的落地

Fly.io 的 "Global App with SQLite" 是一个经典案例：

- 一个 Rails/Node/Go 应用部署到全球 10 个 region
- 每个 region 有一个副本节点，读延迟 <10ms
- 写自动路由到 Primary region（比如 `fly-replay` header）

这种架构对**读多写少**的应用（大部分 Web 应用）非常划算。

### 21.3.4 简单示例

```bash
# 在容器里挂 LiteFS
litefs mount /var/lib/litefs

# 应用连接 /var/lib/litefs/app.db 就行
```

LiteFS 配置 `litefs.yml`：

```yaml
fuse:
  dir: "/var/lib/litefs"
data:
  dir: "/var/lib/litefs-data"
lease:
  type: "consul"
  consul:
    url: "http://consul:8500"
    key: "litefs/myapp"
```

## 21.4 Turso：边缘 SQLite（基于 libSQL）

### 21.4.1 出场

Turso 是 ChiselStrike（后来改名 Turso）的产品，**分布式边缘 SQLite** 服务。

**libSQL** 是 SQLite 的**分叉**（fork）。为什么要分叉？因为 SQLite 官方**接受 patch 但不接受外部贡献**（是的，SQLite 团队非常保守）。Turso 团队想加分布式特性，SQLite 官方不加，于是自己 fork 了一个 libSQL。

libSQL 完全兼容 SQLite，同时增加：

- 服务端流复制（多节点，异步复制）
- HTTP/gRPC 协议（不用文件系统访问）
- Kotlin/Rust/Go/Wasm/JS/Dart 客户端
- 加密扩展（内置）
- 用户函数（Wasm 编写）

### 21.4.2 Turso 的边缘复制

Turso 在全球 30+ 个数据中心部署了 libSQL 节点。你的数据库自动同步到所有你选中的边缘节点。用户请求就近路由。

- 主节点（Primary）：负责写
- 副本（Replica）：只读，位于边缘
- 写延迟：跟主节点距离有关
- 读延迟：<10ms（就近）

对全球化应用简直是量身定制。

### 21.4.3 Turso CLI

```bash
# 安装
curl -sSfL https://get.tur.so/install.sh | bash

# 登录
turso auth signup

# 创建数据库
turso db create my-notes

# 拿到连接 URL
turso db show my-notes --url
# libsql://my-notes-username.turso.io

# 生成 token
turso db tokens create my-notes
```

### 21.4.4 Dart SDK：libsql_dart

Turso 团队维护 `libsql_dart` 包（也可以用 HTTP API 手动调用）：

```yaml
# pubspec.yaml
dependencies:
  libsql_dart: ^0.4.0
```

```dart
import 'package:libsql_dart/libsql_dart.dart';

Future<void> main() async {
  final client = LibsqlClient(
    'libsql://my-notes-username.turso.io',
    authToken: 'YOUR_TOKEN',
  );

  await client.connect();

  await client.execute('CREATE TABLE IF NOT EXISTS notes(id INTEGER PRIMARY KEY, title TEXT)');
  await client.execute("INSERT INTO notes(title) VALUES('Hello Turso')");

  final rows = await client.query('SELECT * FROM notes');
  for (final r in rows) {
    print(r);
  }
}
```

### 21.4.5 嵌入式副本（Embedded Replica）

Turso 最酷的功能：**本地嵌入式副本**。

```dart
final client = LibsqlClient(
  'file:local.db',
  syncUrl: 'libsql://my-notes.turso.io',
  authToken: 'YOUR_TOKEN',
  syncIntervalSeconds: 60,
);
```

原理：

- 你的应用直接读本地 SQLite（微秒级延迟）
- 后台定期从 Turso 云端拉更新
- 写操作可以走本地（异步同步到云）或直连主库

对移动应用简直完美——**离线可用 + 云端同步**！第 22 章会用到。

## 21.5 Cloudflare D1：Serverless SQLite

### 21.5.1 出场

Cloudflare 官方的 SQLite 服务，跟 Workers（他们的 Serverless 平台）深度集成。

- 全球边缘部署
- 按请求计费（不用付固定实例费）
- 每个数据库最大 10GB（本文写作时）
- 复制模型是"主 + 只读副本"

### 21.5.2 用起来

```javascript
// Cloudflare Worker
export default {
  async fetch(request, env) {
    const { results } = await env.DB.prepare(
      "SELECT * FROM notes WHERE id = ?"
    ).bind(1).all();
    return Response.json(results);
  }
}
```

`env.DB` 是绑定在 `wrangler.toml` 里的 D1 数据库：

```toml
[[d1_databases]]
binding = "DB"
database_name = "my-notes"
database_id = "xxx-xxx-xxx"
```

### 21.5.3 D1 vs Turso

| 维度 | D1 | Turso |
| --- | --- | --- |
| 平台绑定 | Cloudflare Workers | 无（HTTP、SDK 到处能用） |
| 计费 | 按请求 | 按数据库/存储 |
| 边缘节点 | Cloudflare 全球网络 | Turso 自己的 30+ 节点 |
| 嵌入式副本 | ✗ | ✓（杀手锏） |
| Dart SDK | 不官方 | 官方 |
| 客户端友好 | Node/JS 生态 | 多语言 |

**结论**：

- 如果你已经在 Cloudflare 生态，用 D1
- 如果你要跨平台、要嵌入式副本、要 Flutter/Dart 支持，用 Turso

## 21.6 rqlite：Raft 协议的 SQLite 集群

### 21.6.1 出场

rqlite 是最早的 SQLite 分布式项目之一，作者 Philip O'Toole。

**核心思想**：多节点用 Raft 协议达成共识，写操作在 Leader 上执行然后同步到 Follower。SQLite 用作**状态机的存储**。

### 21.6.2 特点

- **强一致性**（跟 Turso 的最终一致不同）
- **高可用**：Leader 挂了自动选举新 Leader
- **HTTP API**：用 HTTP POST 提交 SQL
- **写性能一般**：每次写都要过 Raft，比单机慢很多

### 21.6.3 适用场景

- 需要强一致性 + HA 的中小规模应用
- 例如：配置中心、服务发现（跟 etcd 竞争但用 SQL）

### 21.6.4 简单使用

```bash
# 启动 3 节点集群
rqlited -node-id 1 -http-addr localhost:4001 -raft-addr localhost:4002 ~/rqlite/1
rqlited -node-id 2 -http-addr localhost:4003 -raft-addr localhost:4004 -join http://localhost:4001 ~/rqlite/2
rqlited -node-id 3 -http-addr localhost:4005 -raft-addr localhost:4006 -join http://localhost:4001 ~/rqlite/3

# 写操作
curl -XPOST localhost:4001/db/execute -d '["CREATE TABLE t(v INTEGER)"]'
curl -XPOST localhost:4001/db/execute -d '["INSERT INTO t VALUES(1)"]'

# 读操作
curl localhost:4001/db/query?q=SELECT+%2A+FROM+t
```

## 21.7 加密方案

移动端数据库经常需要加密——用户隐私、合规要求（GDPR）、企业数据。SQLite 官方的加密扩展 SEE 是收费的（价格不菲），所以社区搞出了替代方案。

### 21.7.1 SQLCipher

**最流行的 SQLite 加密方案**。开源版本 BSD 许可（个人/开源项目免费），商业版本需要授权。

**特点**：

- AES-256 CBC 加密
- 页级加密（每页独立加密）
- HMAC 完整性校验
- 密钥拉伸（PBKDF2，防暴力破解）

**用法（原生）**：

```sql
-- 打开一个加密数据库
sqlite> PRAGMA key = 'my-password';
sqlite> ATTACH DATABASE 'encrypted.db' AS encrypted KEY 'password';
```

### 21.7.2 Flutter 中用 SQLCipher：sqflite_sqlcipher

```yaml
dependencies:
  sqflite_sqlcipher: ^3.0.0
```

```dart
import 'package:sqflite_sqlcipher/sqflite.dart';

final db = await openDatabase(
  path,
  password: 'my-super-secret-password',
  version: 1,
  onConfigure: (db) async {
    await db.execute('PRAGMA journal_mode = WAL');
  },
);
```

**注意**：`sqflite_sqlcipher` 是 `sqflite` 的 fork，API 完全兼容，你只要改依赖和加个 `password` 参数就好。

### 21.7.3 密钥怎么存

**最关键的问题**：你把密钥存哪儿？

- **硬编码**：❌ 谁都能反编译看到
- **用户密码**：可以，但用户忘了就完蛋
- **平台 Keychain/Keystore**：✅ 推荐

Flutter 用 `flutter_secure_storage`：

```dart
final storage = FlutterSecureStorage();

Future<String> getOrCreateDbKey() async {
  var key = await storage.read(key: 'db_key');
  if (key == null) {
    // 首次运行，生成随机 key
    key = base64Encode(List.generate(32, (_) => Random.secure().nextInt(256)));
    await storage.write(key: 'db_key', value: key);
  }
  return key;
}
```

这样 key 存在 iOS Keychain / Android Keystore 里，其他 app 拿不到。

### 21.7.4 SEE：官方付费方案

如果你有钱有需求，可以买 [SQLite Encryption Extension](https://www.sqlite.org/see/)。特点：

- 4 种加密模式（AES128-OFB / AES256-OFB / AES128-CCM / RC4）
- 官方支持，与主线同步
- 一次性付费（几千美元）+ 源码分发权

大部分项目用 SQLCipher 就够了。

### 21.7.5 加密方案对比

| 方案 | 授权 | 性能开销 | 移动端 SDK |
| --- | --- | --- | --- |
| SQLCipher（社区） | BSD | ~5-15% | sqflite_sqlcipher（Flutter） |
| SQLCipher（商业） | 商业许可 | 同上 | 同上 + 支持 |
| SEE | ~2000$/license | ~5% | 需要自己集成 |
| Turso 加密 | libSQL 内置 | ~5% | libsql_dart |
| 自己封装 | 免费 | 不推荐！ | / |

**"自己封装"的坑**：加密不是简单的"过一遍 AES"，涉及 IV 管理、认证、密钥派生等。**别造轮子**！

## 21.8 移动端与云端同步策略

### 21.8.1 同步的核心问题

多设备/多用户同时改数据，冲突怎么处理？三个流派：

1. **Last-Write-Wins（LWW）**：谁最后改的算谁的。简单粗暴，可能丢数据
2. **CRDT（Conflict-free Replicated Data Types）**：数学上保证收敛的数据结构
3. **OT（Operational Transform）**：Google Docs 用的，操作变换

### 21.8.2 LWW：最简单的方案

给每行加 `updated_at`（时间戳）和 `deleted`（软删除）：

```sql
CREATE TABLE notes(
  id TEXT PRIMARY KEY,      -- 用 UUID 避免主键冲突
  title TEXT,
  body TEXT,
  updated_at INTEGER,
  deleted INTEGER DEFAULT 0
);
```

同步流程：

1. 本地记录"上次同步时间"
2. 上传所有 `updated_at > last_sync` 的行
3. 下载云端所有 `updated_at > last_sync` 的行
4. 冲突（同一 id）：`updated_at` 大的赢

**优点**：极简单
**缺点**：会丢字段级别的变更（比如你改标题，别人改正文，最终只留一个）

### 21.8.3 CRDT：无冲突

CRDT 是当前 local-first 应用的时髦技术。有很多类型：

- **G-Counter**：单调递增计数器
- **G-Set**：只加不减集合
- **LWW-Register**：LWW 的形式化版本
- **RGA / Yjs / Automerge**：文档级 CRDT

**Automerge** 和 **Yjs** 是 JS 生态最活跃的 CRDT 库。Flutter 的选择比较少，但可以用：

- `crdt`（Dart 包，通用 CRDT 抽象）
- `y_flutter`（Yjs 的 Flutter 绑定，正在发展）

### 21.8.4 SQLite + CRDT 的混合

**cr-sqlite** 是一个 SQLite 扩展，把普通 SQLite 表变成 CRDT：

```sql
-- 加载扩展
.load crsqlite

-- 创建 CRDT 表
CREATE TABLE notes(id PRIMARY KEY, title, body);
SELECT crsql_as_crr('notes');  -- 把 notes 变成 "conflict-free replicated relation"

-- 现在多设备可以直接同步，不用手写冲突解决
```

移动端场景成熟度还在提升，但值得关注。

### 21.8.5 Turso 嵌入式副本作为同步方案

对大多数 App，最简单的方案是：

- 本地：Turso 嵌入式副本（本地 SQLite + 后台同步）
- 云端：Turso 主库
- 冲突：Turso 内部用 LWW（基于时间戳）
- 离线：本地照读照写，联网后同步

第 22 章会展示这个方案的雏形。

## 21.9 Flutter 实战：集成 Turso

### 21.9.1 完整示例

```dart
// pubspec.yaml
// dependencies:
//   libsql_dart: ^0.4.0

import 'package:libsql_dart/libsql_dart.dart';
import 'package:path/path.dart' as p;
import 'package:path_provider/path_provider.dart';

class TursoSync {
  late LibsqlClient _client;

  Future<void> init() async {
    final dir = await getApplicationDocumentsDirectory();
    final path = p.join(dir.path, 'local.db');

    _client = LibsqlClient(
      'file:$path',
      syncUrl: 'libsql://your-db.turso.io',
      authToken: 'YOUR_TURSO_TOKEN',
      syncIntervalSeconds: 60,       // 每 60 秒同步一次
      readYourWrites: true,          // 读到自己的写
    );

    await _client.connect();

    // 初始化 schema（本地和云端都会有）
    await _client.execute('''
      CREATE TABLE IF NOT EXISTS notes(
        id TEXT PRIMARY KEY,
        title TEXT NOT NULL,
        body TEXT NOT NULL,
        updated_at INTEGER
      )
    ''');
  }

  Future<void> addNote(String title, String body) async {
    final id = Uuid().v4();
    final now = DateTime.now().millisecondsSinceEpoch;
    await _client.execute(
      'INSERT INTO notes(id, title, body, updated_at) VALUES(?, ?, ?, ?)',
      [id, title, body, now],
    );
  }

  Future<List<Map<String, dynamic>>> listNotes() async {
    return await _client.query('SELECT * FROM notes ORDER BY updated_at DESC');
  }

  Future<void> forceSyncNow() async {
    await _client.sync();
  }
}
```

### 21.9.2 离线优先的策略

- 应用启动：立刻能读本地库
- 后台：`syncIntervalSeconds` 触发同步
- 用户手动下拉刷新：`forceSyncNow()`
- 网络恢复：`Connectivity` 监听后触发同步

## 21.10 该用哪个？决策树

```
你需要 SQLite 云能力吗？
├─ 只需要单机 → 用原生 SQLite
├─ 需要备份/灾备 → Litestream
├─ 需要读扩展 + HA → LiteFS 或 rqlite
├─ 需要全球边缘部署 + 移动端离线
│   ├─ Cloudflare 生态 → D1
│   └─ 独立/多平台 → Turso
├─ 需要加密
│   ├─ 开源项目/内部 → SQLCipher（社区版）
│   ├─ 商业闭源 → SQLCipher 商业版 或 SEE
│   └─ 已用 Turso → libSQL 内置加密
└─ 需要 CRDT/协同 → cr-sqlite 或 Yjs
```

## 21.11 本章小结

SQLite 已经不是"一个文件的玩具"，而是**云原生 + 边缘计算 + local-first**时代的一等公民。

核心记忆点：

- **Litestream**：SQLite → S3 的准实时备份，零侵入
- **LiteFS**：分布式 SQLite 的 FUSE 文件系统，Fly.io 主推
- **Turso（libSQL）**：全球边缘 SQLite，杀手锏是嵌入式副本
- **Cloudflare D1**：Serverless SQLite，绑定 Workers
- **rqlite**：Raft 强一致 SQLite 集群
- **SQLCipher**：移动端最流行的 SQLite 加密方案
