# 第 23 章 日志与调试技巧

程序出了 bug，你的第一反应是什么？大概率是加几行 `print()`，看看变量值对不对。这不是丢人的事——连经验丰富的工程师也这么干。但 `print` 只是调试工具箱里的螺丝刀，你还需要扳手（logging）、放大镜（debugger）和测速仪（profiler）。

本章将带你从"到处 print"进化到"系统化调试"：用 logging 模块替代 print，用 pdb/breakpoint 断点调试，用性能分析工具找到瓶颈。调试不是玄学，是有方法论的。

## 23.1 logging 模块：专业的日志系统

### 为什么需要 logging 而不是 print

```python
# print 的问题：
# 1. 没有级别区分（哪些是调试信息，哪些是错误？）
# 2. 无法控制输出（生产环境不想看调试信息怎么办？）
# 3. 没有时间和上下文信息
# 4. 无法输出到文件

print("用户登录了")       # 这是正常信息还是调试信息？
print("数据库连接失败")    # 这是错误！但 print 看不出来
```

### logging 的五个级别

```python
import logging

# 五个级别，从低到高
logging.debug("详细调试信息，开发时使用")        # DEBUG = 10
logging.info("正常运行的信息")                   # INFO = 20
logging.warning("警告：有问题但不影响运行")      # WARNING = 30
logging.error("错误：某个功能失败了")             # ERROR = 40
logging.critical("严重错误：程序可能要崩溃了")    # CRITICAL = 50
```

### 基本配置

```python
import logging

# 最简单的配置
logging.basicConfig(
    level=logging.INFO,  # 只显示 INFO 及以上
    format="%(asctime)s [%(levelname)s] %(name)s: %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S",
)

logger = logging.getLogger(__name__)

logger.debug("这条不会显示（低于 INFO）")
logger.info("服务器启动在端口 8080")
logger.warning("配置文件未找到，使用默认配置")
logger.error("数据库连接失败: ConnectionRefused")

# 输出：
# 2024-03-15 10:30:45 [INFO] __main__: 服务器启动在端口 8080
# 2024-03-15 10:30:45 [WARNING] __main__: 配置文件未找到，使用默认配置
# 2024-03-15 10:30:45 [ERROR] __main__: 数据库连接失败: ConnectionRefused
```

### Handler：日志输出去哪里

```python
import logging
import sys

logger = logging.getLogger("myapp")
logger.setLevel(logging.DEBUG)  # 记录所有级别

# 控制台 Handler：只显示 INFO 及以上
console_handler = logging.StreamHandler(sys.stdout)
console_handler.setLevel(logging.INFO)
console_formatter = logging.Formatter(
    "%(levelname)s: %(message)s"
)
console_handler.setFormatter(console_formatter)

# 文件 Handler：记录 DEBUG 及以上（更详细）
file_handler = logging.FileHandler("app.log", encoding="utf-8")
file_handler.setLevel(logging.DEBUG)
file_formatter = logging.Formatter(
    "%(asctime)s [%(levelname)s] %(name)s:%(lineno)d - %(message)s"
)
file_handler.setFormatter(file_formatter)

# 添加 Handler
logger.addHandler(console_handler)
logger.addHandler(file_handler)

# 测试
logger.debug("变量 x = 42")        # 只写入文件
logger.info("请求处理完成")         # 控制台 + 文件
logger.error("发生了一个错误")      # 控制台 + 文件
```

### RotatingFileHandler：自动轮转日志文件

```python
from logging.handlers import RotatingFileHandler, TimedRotatingFileHandler

# 按大小轮转：文件超过 10MB 就创建新文件，保留 5 个备份
size_handler = RotatingFileHandler(
    "app.log",
    maxBytes=10 * 1024 * 1024,  # 10MB
    backupCount=5,
    encoding="utf-8",
)

# 按时间轮转：每天创建新日志文件
time_handler = TimedRotatingFileHandler(
    "app.log",
    when="midnight",       # 每天午夜轮转
    interval=1,
    backupCount=30,        # 保留 30 天
    encoding="utf-8",
)
```

### 记录异常信息

```python
import logging

logger = logging.getLogger(__name__)

def divide(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        # exc_info=True 会记录完整的异常堆栈
        logger.error("除零错误: %s / %s", a, b, exc_info=True)
        # 或者用 exception() 方法（自动记录异常）
        # logger.exception("除零错误: %s / %s", a, b)
        raise

divide(10, 0)
# ERROR:__main__:除零错误: 10 / 0
# Traceback (most recent call last):
#   File "...", line 3, in divide
# ZeroDivisionError: division by zero
```

## 23.2 pdb 与 breakpoint()：断点调试

### breakpoint() 内置函数

Python 3.7+ 引入了 `breakpoint()` 内置函数，它等价于 `import pdb; pdb.set_trace()`，但更简洁：

```python
def process_data(data):
    result = []
    for item in data:
        transformed = transform(item)
        breakpoint()  # 程序在这里暂停，进入交互式调试
        result.append(transformed)
    return result

def transform(item):
    return item * 2

process_data([1, 2, 3])
```

当程序运行到 `breakpoint()` 时，会进入交互式调试器：

```
> /path/to/script.py(8)process_data()
-> result.append(transformed)
(Pdb)
```

### pdb 常用命令

| 命令 | 缩写 | 说明 |
| ------ | ------ | ------ |
| `print(expr)` | `p expr` | 打印表达式的值 |
| `next` | `n` | 执行下一行（不进入函数） |
| `step` | `s` | 执行下一行（进入函数） |
| `continue` | `c` | 继续执行到下一个断点 |
| `list` | `l` | 显示当前代码上下文 |
| `where` | `w` | 显示调用栈 |
| `up` | | 切换到上层调用帧 |
| `down` | | 切换到下层调用帧 |
| `quit` | `q` | 退出调试器 |
| `!var = value` | | 修改变量值（`!` 防止与命令冲突） |

### 调试实战示例

```python
def calculate_discounts(prices, discount_rates):
    """计算折扣后的价格"""
    results = []
    breakpoint()  # 在这里暂停，检查输入
    for price, rate in zip(prices, discount_rates):
        discounted = price * (1 - rate / 100)
        results.append(discounted)
    return results

# 运行后的调试会话：
# (Pdb) p prices
# [100, 200, 300]
# (Pdb) p discount_rates
# [10, 20, 0.5]
# (Pdb) n                  # 执行下一行
# (Pdb) p discounted       # 检查计算结果
# 90.0
# (Pdb) p len(results)     # 检查结果列表
# 1
# (Pdb) c                  # 继续执行
```

### 条件断点

```python
def process_orders(orders):
    for i, order in enumerate(orders):
        # 只在特定条件下暂停
        if order["amount"] > 10000:
            breakpoint()
        process(order)
```

### 用 PYTHONBREAKPOINT 环境变量控制

```bash
# 禁用所有 breakpoint()（生产环境推荐）
PYTHONBREAKPOINT=0 python my_script.py

# 使用其他调试器（如 ipdb）
PYTHONBREAKPOINT=ipdb.set_trace python my_script.py
```

## 23.4 性能分析

### cProfile：函数级性能分析

```python
import cProfile
import pstats

def slow_function():
    total = 0
    for i in range(1_000_000):
        total += i * i
    return total

def main():
    for _ in range(10):
        slow_function()

# 使用 cProfile 分析
profiler = cProfile.Profile()
profiler.enable()
main()
profiler.disable()

# 查看结果
stats = pstats.Stats(profiler)
stats.sort_stats("cumulative")  # 按累计时间排序
stats.print_stats(20)  # 显示前 20 个函数
```

命令行使用更方便：

```bash
# 直接分析脚本
python -m cProfile -s cumtime my_script.py

# 保存分析结果
python -m cProfile -o profile.stats my_script.py

# 用 pstats 查看
python -c "import pstats; p = pstats.Stats('profile.stats'); p.sort_stats('cumulative'); p.print_stats(20)"
```

### timeit：代码片段计时

```python
import timeit

# 测试小段代码的执行时间
# 列表推导式 vs map
list_time = timeit.timeit(
    "[x**2 for x in range(1000)]",
    number=10000
)
print(f"列表推导式: {list_time:.2f}s")

map_time = timeit.timeit(
    "list(map(lambda x: x**2, range(1000)))",
    number=10000
)
print(f"map + lambda: {map_time:.2f}s")

# 命令行使用
# python -m timeit "[x**2 for x in range(1000)]"
# python -m timeit -s "import math" "[math.sqrt(x) for x in range(1000)]"
```

### line_profiler：行级性能分析

```python
# pip install line_profiler

# 在要分析的函数上加 @profile 装饰器
# （不需要 import，line_profiler 运行时注入）

@profile
def slow_data_processing(data):
    result = []
    for item in data:                    # 看哪行最慢
        cleaned = item.strip().lower()
        words = cleaned.split()
        filtered = [w for w in words if len(w) > 3]
        result.append(" ".join(filtered))
    return result

data = ["Hello World Test"] * 100000
slow_data_processing(data)
```

## 23.5 print 调试的正确姿势

虽然我们推崇 logging 和 debugger，但 `print` 调试在简单场景下仍然实用。关键是要"聪明地 print"：

```python
# 1. 用 f-string 的 = 号快速打印变量名和值
x = 42
name = "Alice"
print(f"{x=}")        # x=42
print(f"{name=}")     # name='Alice'
print(f"{x*2=}")      # x*2=84

# 2. 用分隔线和标记让输出更易读
print("=" * 60)
print(">>> 进入 process_data 函数")
print(f"输入数据: {data}")
print("=" * 60)

# 3. 用 pprint 格式化复杂数据结构
from pprint import pprint

complex_data = {
    "users": [{"name": "Alice", "age": 25}, {"name": "Bob", "age": 30}],
    "config": {"debug": True, "timeout": 30},
}
pprint(complex_data, indent=2, width=60)

# 4. 用 rich 库美化输出（可选）
# pip install rich
from rich import print as rprint
rprint("[bold red]错误![/bold red] 数据库连接失败")
rprint({"key": "value", "list": [1, 2, 3]})  # 自动语法高亮
```

小贴士：`f"{x=}"` 是 Python 3.8+ 的特性，非常适合快速调试。它同时显示变量名和值，省去了手动写 `f"x = {x}"` 的麻烦。

## 23.6 调试方法论

遇到 bug 时，有方法地调试比盲目加 print 高效得多：

1. **复现问题**：找到最小复现步骤，确认 bug 是稳定复现的
2. **阅读错误信息**：Python 的 traceback 包含了大量信息——文件名、行号、调用链
3. **二分法定位**：如果不知道问题在哪，先注释掉一半代码，看问题是否还在
4. **检查假设**：你觉得这个变量应该是整数？print 一下确认
5. **看最近的修改**：`git diff` 看看最近改了什么，80% 的 bug 来自最近的修改
6. **搜索错误信息**：把完整的错误信息粘贴到搜索引擎，大概率有人遇到过

## 23.9 小结

- **logging**：替代 print，提供级别、格式化、多输出目标（控制台/文件）
- **pdb/breakpoint()**：交互式断点调试，逐步执行、检查变量
- **IDE 调试**：图形化调试体验，变量监视和条件断点
- **cProfile**：函数级性能分析，找到最慢的函数
- **timeit**：代码片段计时，比较不同实现的性能

- **调试方法论**：复现 → 阅读错误 → 二分定位 → 检查假设

**第 5 题：**

`__name__` 在模块中是模块的名字（如 `"myapp.database"`），在主脚本中是 `"__main__"`。用 `__name__` 作为 logger 名的好处是：1. 日志输出中能看出是哪个模块产生的；2. 可以利用 logger 的层级关系，对特定模块设置不同的日志级别。

## 23.12 常见错误与避坑

**1. 生产环境忘了设置日志级别**

```python
# 开发时设了 DEBUG，忘了改回去
logging.basicConfig(level=logging.DEBUG)
# 生产环境输出大量调试日志，影响性能和磁盘空间

# 解决：用环境变量控制
import os
log_level = os.environ.get("LOG_LEVEL", "INFO")
logging.basicConfig(level=getattr(logging, log_level))
```

**2. 在循环中打日志**

```python
# 一个处理 100 万条记录的循环
for record in records:  # 100 万条
    logger.debug(f"处理记录: {record}")  # 100 万条日志！

# 解决：采样输出
import random
for record in records:
    if random.random() < 0.01:  # 只记录 1%
        logger.debug(f"处理记录: {record}")
```

**3. breakpoint() 提交到生产代码**

```python
# 非常尴尬的情况
def process_payment(amount):
    charge = create_charge(amount)
    breakpoint()  # 忘了删！用户在生产环境触发...
    return charge
```

避坑方法：

- pre-commit 配置 `debug-statements` 钩子（检测 `breakpoint()`、`pdb.set_trace()`）
- CI 中用 Ruff 的 `T100` 规则检查
- 代码审查时留意

**4. logging 的 f-string 问题**

```python
# 不推荐：即使日志级别高于 DEBUG，f-string 也会被求值
logger.debug(f"用户数据: {expensive_query()}")  # expensive_query() 总是执行

# 推荐：用 % 格式化，只有实际记录时才求值
logger.debug("用户数据: %s", expensive_query())  # 不调用就不执行
```

**5. 忽略 traceback 的信息**

Python 的异常堆栈包含大量信息——文件名、行号、函数名、代码行。很多人看到报错就慌了，直接把错误信息扔给搜索引擎。先仔细看 traceback，通常最后几行就能告诉你问题在哪。
