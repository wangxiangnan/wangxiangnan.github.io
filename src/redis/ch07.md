# 第7章：安全——给你的 Redis 穿上铠甲

## 引言：裸奔的 Redis

想象一下，你买了一辆超级跑车，性能炸裂，速度惊人——但你没装门锁，没装报警器，还把钥匙插在上面。这就是很多开发者对待 Redis 的方式：**默认配置直接上线**。

Redis 的设计哲学是"信任内网"，它假设所有连接过来的客户端都是"自己人"。这在开发环境没问题，但一旦暴露到公网……恭喜你，你的数据就像放在大街上的自助取款机，谁都能来取。

这一章，我们要给 Redis 穿上全套铠甲：密码认证、ACL 权限控制、TLS 加密、网络隔离——一件都不能少。

## 7.1 Redis 的安全模型：默认信任网络

Redis 默认的安全策略可以总结为一句话：**"我不管你是谁，连上来就能操作"**。

这和 PostgreSQL、MySQL 这些数据库完全不同。MySQL 至少还有个用户名密码，Redis 默认连这个都没有。

```
┌──────────────────────────────────────────────┐
│           Redis 默认安全模型                  │
│                                              │
│  客户端 ──连接──> Redis（来者不拒）          │
│                                              │
│  - 能读写所有数据                            │
│  - 能执行所有命令（包括 FLUSHALL）           │
│  - 能修改服务器配置（CONFIG SET）            │
│  - 没有任何审计日志                          │
└──────────────────────────────────────────────┘
```

> **Tip:** Redis 作者 Antirez 曾经说过："Redis should be accessed by trusted clients only。"翻译成人话就是：**你得自己保证网络安全，Redis 不管这个。**

## 7.2 密码认证：第一道防线

最简单的安全措施就是设个密码。在 `redis.conf` 中：

```bash
# redis.conf
requirepass your_super_secret_password_here
```

连接后需要先认证才能操作：

```bash
redis-cli> AUTH your_super_secret_password_here
OK
redis-cli> GET mykey
"value"
```

在 Node.js 中使用 ioredis 配置密码非常简单：

```js
const Redis = require('ioredis');

// 方式一：在配置中指定密码
const redis = new Redis({
  host: '127.0.0.1',
  port: 6379,
  password: 'your_super_secret_password_here',
});

// 方式二：在 URL 中指定
const redis2 = new Redis('redis://:your_super_secret_password_here@127.0.0.1:6379');

async function demo() {
  await redis.set('secret:data', 'This is protected now!');
  const value = await redis.get('secret:data');
  console.log('获取到:', value);
  await redis.quit();
}

demo();
```

> **Warning:** `requirepass` 只是最基础的认证。密码在配置文件中是明文存储的，而且所有连接共享同一个密码——你没法区分"管理员"和"普通用户"。这就好比整栋大楼只有一把钥匙，保洁阿姨和 CEO 用同一把。

## 7.3 Redis 6.0+ ACL：精细化的权限控制

Redis 6.0 引入了 **ACL（Access Control List）**，这是一个游戏规则改变者。如果说 `requirepass` 是大楼的门禁卡，那 ACL 就是每个房间独立的指纹锁。

ACL 就像前端开发中的 **RBAC（基于角色的访问控制）** 系统：

- **用户（User）**：每个连接者有自己的身份
- **权限（Permission）**：控制能执行什么命令、访问什么键、使用什么频道

### 7.3.1 核心命令一览

```bash
# 查看所有用户
ACL LIST

# 创建/修改用户
ACL SETUSER username [rules...]

# 查看用户详情
ACL GETUSER username

# 删除用户
ACL DELUSER username

# 当前连接认证
AUTH username password
```

### 7.3.2 创建不同权限的用户

让我们像搭积木一样，创建几种典型的用户角色：

```bash
# 1. 超级管理员：什么都能干
ACL SETUSER admin on >admin_password_here ~* &* +@all

# 2. 只读用户：只能读，不能写
ACL SETUSER readonly on >readonly_pass ~* +@read

# 3. 缓存专用用户：只能操作 cache:* 前缀的键
ACL SETUSER cache_user on >cache_pass ~cache:* +@all

# 4. 会话管理用户：只能操作 session:* 前缀的键，不能执行危险命令
ACL SETUSER session_mgr on >session_pass ~session:* +@all -@admin -@dangerous
```

让我来解读一下这些"密码"般的规则：

| 符号 | 含义 | 示例 |
|------|------|------|
| `on` | 启用用户 | - |
| `>password` | 设置密码 | `>my_secret` |
| `~pattern` | 允许访问的键模式 | `~cache:*` |
| `&pattern` | 允许访问的频道模式 | `&*` |
| `+command` | 允许的命令 | `+get` |
| `-command` | 禁止的命令 | `-flushall` |
| `+@category` | 允许的命令分类 | `+@read` |
| `-@category` | 禁止的命令分类 | `-@dangerous` |

### 7.3.3 Node.js 中实现 ACL 管理

```js
const Redis = require('ioredis');

const redis = new Redis({
  host: '127.0.0.1',
  port: 6379,
  password: 'admin_password_here',
});

async function setupACL() {
  // 1. 创建只读用户
  await redis.acl(
    'SETUSER', 'reader', 'on',
    '>reader_password_123',
    '~*',        // 可以访问所有键
    '+@read',    // 只能执行读命令
    '+ping',     // 额外允许 PING
    '+info'      // 额外允许 INFO
  );
  console.log('只读用户 reader 创建成功');

  // 2. 创建缓存写入用户（只能操作 cache:* 前缀的键）
  await redis.acl(
    'SETUSER', 'cache_writer', 'on',
    '>cache_writer_pass',
    '~cache:*',     // 只能访问 cache:* 前缀的键
    '+@all',        // 允许所有命令
    '-@admin',      // 但禁止管理类命令
    '-@dangerous'   // 且禁止危险类命令
  );
  console.log('缓存用户 cache_writer 创建成功');

  // 3. 创建发布订阅专用用户
  await redis.acl(
    'SETUSER', 'pubsub_user', 'on',
    '>pubsub_pass_456',
    '&notifications:*',
    '+subscribe', '+psubscribe',
    '+unsubscribe', '+punsubscribe',
    '+publish', '+ping'
  );
  console.log('Pub/Sub 用户 pubsub_user 创建成功');

  // 4. 查看所有用户
  const users = await redis.acl('LIST');
  console.log('\n所有用户列表:');
  users.forEach((u, i) => console.log(`  ${i + 1}. ${u}`));

  // 5. 查看特定用户的详细信息
  const readerInfo = await redis.acl('GETUSER', 'reader');
  console.log('\nreader 用户详情:', readerInfo);

  await redis.quit();
}

setupACL().catch(console.error);
```

### 7.3.4 验证权限是否生效

```js
const Redis = require('ioredis');

async function testPermissions() {
  const reader = new Redis({
    host: '127.0.0.1', port: 6379,
    username: 'reader', password: 'reader_password_123',
  });

  const cacheWriter = new Redis({
    host: '127.0.0.1', port: 6379,
    username: 'cache_writer', password: 'cache_writer_pass',
  });

  console.log('--- 测试只读用户 ---');
  try {
    await reader.set('test', 'value');
    console.log('SET 成功（不应该发生！）');
  } catch (err) {
    console.log('SET 被拒绝（符合预期）:', err.message);
  }

  try {
    const val = await reader.get('test');
    console.log('GET 成功:', val);
  } catch (err) {
    console.log('GET 失败:', err.message);
  }

  console.log('\n--- 测试缓存用户 ---');
  try {
    await cacheWriter.set('cache:user:1', JSON.stringify({ name: 'Alice' }));
    console.log('SET cache:* 成功');
  } catch (err) {
    console.log('SET cache:* 失败:', err.message);
  }

  try {
    await cacheWriter.set('user:1', 'data');
    console.log('SET user:* 成功（不应该发生！）');
  } catch (err) {
    console.log('SET user:* 被拒绝（符合预期）:', err.message);
  }

  await reader.quit();
  await cacheWriter.quit();
}

testPermissions().catch(console.error);
```

## 7.4 保护模式（Protected Mode）

Redis 3.2 引入了保护模式，这是为了防止你"忘记"设置密码就把 Redis 暴露到公网。

```bash
# redis.conf
protected-mode yes
bind 127.0.0.1
```

当保护模式开启时，如果 Redis 没有设置密码，且监听的不是本地地址，它会**拒绝外部连接**。这就像你家大门的自动上锁功能——即使你忘了锁门，门也会自己锁上。

> **Tip:** 如果你在开发环境中需要临时关闭保护模式（不建议在生产环境这么做）：
>
> ```bash
> redis-cli> CONFIG SET protected-mode no
> ```

## 7.5 危险命令禁用（rename-command）

有些命令就像核武器按钮——你可能永远都不需要按它，但万一有人不小心按了……

```bash
# redis.conf - 禁用或重命名危险命令
rename-command FLUSHALL ""
rename-command FLUSHDB ""
rename-command CONFIG "CONFIG_b8f29a3e_secret"
rename-command DEBUG ""
rename-command KEYS ""
```

将命令重命名为空字符串 `""` 等于完全禁用该命令。重命名为其他名字则相当于"改了个暗号"。

> **Warning:** `rename-command` 会影响所有客户端，包括你的管理工具。如果你把 `CONFIG` 改了名字，那 Redis Sentinel 和 Cluster 的配置命令也会受影响。就像你把"紧急出口"的牌子换了个名字，消防员来了也找不到。

## 7.6 TLS/SSL 加密连接

在网络上传输明文密码和数据？在2024年这简直是在"裸泳"。TLS 加密就像是给数据传输套上了一个密封的信封。

```bash
# redis.conf - TLS 配置
tls-port 6380
tls-cert-file /path/to/redis.crt
tls-key-file /path/to/redis.key
tls-ca-cert-file /path/to/ca.crt
tls-auth-clients yes
```

在 Node.js 中配置 TLS 连接：

```js
const Redis = require('ioredis');
const fs = require('fs');

const redis = new Redis({
  host: 'redis.example.com',
  port: 6380,
  password: 'your_password',
  tls: {
    ca: fs.readFileSync('/path/to/ca.crt'),
    cert: fs.readFileSync('/path/to/client.crt'),
    key: fs.readFileSync('/path/to/client.key'),
    rejectUnauthorized: true,
  },
});

redis.on('connect', () => {
  console.log('TLS 加密连接已建立');
});

redis.on('error', (err) => {
  console.error('连接错误:', err.message);
});

async function secureDemo() {
  await redis.set('secure:key', 'encrypted in transit!');
  const val = await redis.get('secure:key');
  console.log('通过 TLS 获取:', val);
  await redis.quit();
}

secureDemo().catch(console.error);
```

## 7.7 网络安全最佳实践

除了上面的措施，还有一些网络安全的基本功要做好：

```bash
# 1. 只监听必要的地址
bind 127.0.0.1 10.0.0.5   # 不要用 0.0.0.0

# 2. 修改默认端口（降低被扫描到的概率）
port 16379

# 3. 设置连接超时
timeout 300

# 4. 限制最大连接数
maxclients 10000
```

完整的 Node.js 安全连接示例：

```js
const Redis = require('ioredis');

function createSecureRedis(options = {}) {
  const defaults = {
    host: process.env.REDIS_HOST || '127.0.0.1',
    port: parseInt(process.env.REDIS_PORT) || 6379,
    password: process.env.REDIS_PASSWORD,
    username: process.env.REDIS_USERNAME || 'default',
    retryStrategy(times) {
      if (times > 10) return null;
      const delay = Math.min(times * 200, 5000);
      return delay;
    },
    connectTimeout: 10000,
    commandTimeout: 5000,
    autoResubscribe: true,
    enableReadyCheck: true,
    maxRetriesPerRequest: 3,
    lazyConnect: true,
    ...options,
  };

  if (process.env.REDIS_TLS === 'true') {
    defaults.tls = {
      rejectUnauthorized: true,
      ca: process.env.REDIS_CA_CERT
        ? require('fs').readFileSync(process.env.REDIS_CA_CERT)
        : undefined,
    };
  }

  const redis = new Redis(defaults);

  redis.on('error', (err) => {
    console.error(`[Redis Error] ${err.message}`);
  });

  redis.on('connect', () => {
    console.log('[Redis] 安全连接已建立');
  });

  redis.on('ready', () => {
    console.log('[Redis] 连接就绪');
  });

  return redis;
}

async function main() {
  const redis = createSecureRedis();
  try {
    await redis.connect();
    await redis.set('app:status', 'secure and running');
    console.log(await redis.get('app:status'));
  } catch (err) {
    console.error('操作失败:', err.message);
  } finally {
    await redis.quit();
  }
}

main();
```

## 7.8 安全检查清单

在你的 Redis 上生产之前，过一遍这个清单：

```
[ ] 设置了强密码（requirepass）
[ ] 配置了 ACL 用户和权限
[ ] 开启了保护模式（protected-mode yes）
[ ] bind 只监听必要的地址
[ ] 禁用或重命名了危险命令（FLUSHALL, CONFIG, DEBUG, KEYS）
[ ] 配置了 TLS 加密（如果在非内网环境）
[ ] 设置了连接超时和最大连接数
[ ] 防火墙只开放必要的端口
[ ] Redis 运行在非 root 用户下
[ ] 定期审计 ACL 用户列表
```

## 小结

| 安全措施 | 保护层级 | 复杂度 |
|----------|----------|--------|
| requirepass | 基础认证 | 低 |
| ACL | 精细化权限 | 高 |
| 保护模式 | 防暴露 | 低 |
| rename-command | 防误操作 | 中 |
| TLS/SSL | 传输加密 | 高 |
| 网络隔离 | 网络层防护 | 中 |

安全就像洋葱——要一层一层地包裹。没有哪一项单独的措施是万能的，但组合起来就能构成一个坚不可摧的防御体系。记住：**安全不是终点，而是一个持续的过程。**

## 练习题

1. **基础：** 为你的 Redis 设置一个密码，然后用 Node.js 连接并验证。
2. **进阶：** 创建三个 ACL 用户——admin（全权限）、reader（只读）、cache_only（只能操作 `cache:*` 前缀的键），并分别测试权限是否正确。
3. **挑战：** 配置 Redis 的 TLS 连接，生成自签名证书，并在 Node.js 中建立加密连接。
4. **思考：** 如果你不小心把 `CONFIG` 命令重命名了，Redis Sentinel 无法正常工作，你该怎么排查和解决？
