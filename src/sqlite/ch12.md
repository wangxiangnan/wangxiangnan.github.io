## 12.1 引言：LIKE的血泪史

想象一下这个场景：你做了一个笔记App，里面存了用户写的10万条笔记。有一天用户问："我三年前写的那条关于'量子力学与拿铁咖啡'的笔记去哪了？"

你自信满满地写下：

```sql
SELECT * FROM notes WHERE content LIKE '%量子力学%';
```

然后App卡住了。3秒。5秒。10秒。用户开始怀疑人生，你开始怀疑职业选择。

**为什么这么慢？**

因为`LIKE '%keyword%'`——注意，`%`在前面——会让SQLite放弃使用任何索引，退化成**全表扫描**。它要一条条读出10万条笔记，一个字节一个字节地在文本里找"量子力学"这四个字。这跟你在图书馆里没有索引卡，一本本翻书找关键词是一样的。

计算机大概哭着说："我明明有那么多CPU核心，为什么要让我干这种脏活？"

于是全文搜索（Full-Text Search，FTS）技术出现了。它的核心思想跟Google搜索一样：

> **不要每次都翻遍全部文档，而是提前建好一个"词→文档"的映射表。**

这就是传说中的**倒排索引（Inverted Index）**。

SQLite内置了FTS的支持，从FTS3、FTS4一路进化到今天的**FTS5**。今天我们就要把它吃透，让你的SQLite变身迷你版Elasticsearch。

## 12.2 核心概念：倒排索引到底是啥？

### 12.2.1 正排索引 vs 倒排索引

**正排索引**（普通的表就是这样）：

| 文档ID | 内容 |
| -------- | ------ |
| 1 | "我爱吃拿铁咖啡" |
| 2 | "量子力学很有趣" |
| 3 | "拿铁与量子力学的奇妙关系" |

你要找"量子力学"，就得挨个扫描每一行的内容。

**倒排索引**（FTS5内部维护的结构）：

| 词 | 出现在哪些文档 |
| ------ | ---------------- |
| 我 | [1] |
| 爱 | [1] |
| 吃 | [1] |
| 拿铁 | [1, 3] |
| 咖啡 | [1] |
| 量子 | [2, 3] |
| 力学 | [2, 3] |
| 很 | [2] |
| 有趣 | [2] |
| 奇妙 | [3] |
| 关系 | [3] |

现在找"量子力学"，只需要：

1. 查"量子" → [2, 3]
2. 查"力学" → [2, 3]
3. 取交集 → [2, 3]

从"扫描100000条"变成"查表2次"，性能提升可能是**上千倍**。

### 12.2.2 FTS的进化史：从FTS3到FTS5

SQLite的全文搜索模块经历了漫长的进化：

- **FTS1/FTS2**：远古时代的产物，已经淘汰。
- **FTS3**：2007年推出，能用，但功能有限。
- **FTS4**：FTS3的加强版，加了些优化。
- **FTS5**：2015年推出，**这是我们今天要用的**。

FTS5相比之前的版本，改进包括：

1. **更好的BM25排序算法**（后面细讲）
2. **更强的查询语法**（NEAR、AND/OR/NOT等）
3. **可插拔的分词器（Tokenizer）**
4. **辅助函数**：highlight、snippet、bm25
5. **更省磁盘**：外部内容表模式

一句话总结：**没有特殊理由，就用FTS5**。

## 12.3 创建你的第一个FTS5虚拟表

FTS5是通过SQLite的"虚拟表"机制实现的。虚拟表长得像普通表，但底层用的是另一套存储和查询逻辑（第15章会详细讲）。

### 12.3.1 最简单的例子

```sql
-- 创建一个FTS5虚拟表，包含title和body两列
CREATE VIRTUAL TABLE articles USING fts5(title, body);

-- 插入数据
INSERT INTO articles(title, body) VALUES
  ('SQLite入门', '这是一篇讲SQLite基础的文章'),
  ('MySQL对比', 'MySQL和SQLite有什么不同呢？'),
  ('全文搜索原理', '倒排索引是搜索引擎的基础'),
  ('SQLite性能优化', 'WAL模式和索引是提速关键');

-- 全文搜索！
SELECT * FROM articles WHERE articles MATCH 'SQLite';
```

看到那个`MATCH`关键字了吗？这就是FTS5的魔法咒语。它不是`LIKE`，不是`=`，是专门为全文搜索设计的。

**关键点**：查询语法是`表名 MATCH '搜索词'`，而不是`列名 MATCH ...`。这跟普通表查询不一样。

### 12.3.2 检查FTS5是否可用

不是所有SQLite都默认编译了FTS5。检查方法：

```sql
-- 方法1：看编译选项
SELECT sqlite_compileoption_used('ENABLE_FTS5');
-- 返回1表示可用

-- 方法2：尝试创建，出错就是没编译
CREATE VIRTUAL TABLE test_fts USING fts5(x);
```

好消息：从SQLite 3.9.0开始，官方发布的Windows/macOS/Linux预编译版本都默认启用了FTS5。Flutter的sqflite插件也默认支持。

## 12.4 内容表模式：省存储的秘诀

### 12.4.1 三种存储模式

FTS5支持三种"数据存哪里"的模式：

**模式1：默认模式（内部存储）**

```sql
CREATE VIRTUAL TABLE articles USING fts5(title, body);
```

FTS5自己存所有的原始文本。**缺点**：数据存了两份（如果你还有主表的话），浪费磁盘。

**模式2：外部内容表（content=）**

```sql
-- 先有一个"主表"存原始数据
CREATE TABLE posts (
    id INTEGER PRIMARY KEY,
    title TEXT,
    body TEXT,
    created_at INTEGER
);

-- FTS5表只存索引，原始内容去主表拿
CREATE VIRTUAL TABLE posts_fts USING fts5(
    title, 
    body,
    content='posts',        -- 指定内容存在posts表
    content_rowid='id'      -- posts表的主键
);
```

这样FTS5表只存倒排索引，原始内容通过`rowid`去`posts`表查。**磁盘节省50%+**。

**模式3：无内容表（contentless）**

```sql
CREATE VIRTUAL TABLE search_index USING fts5(
    title, body, 
    content=''  -- 不存原始内容
);
```

只存索引，不存内容。查询时只能返回rowid，无法返回原文。适合特殊场景。

### 12.4.2 生产环境推荐：外部内容表 + 触发器

真实项目里，你几乎总是想要"主表存数据，FTS5表存索引"的组合。但问题来了：**当主表数据变化时，FTS5索引怎么同步？**

答案：**触发器**！

```sql
-- 主表
CREATE TABLE posts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    body TEXT NOT NULL,
    author TEXT,
    created_at INTEGER DEFAULT (unixepoch())
);

-- FTS5索引表
CREATE VIRTUAL TABLE posts_fts USING fts5(
    title, 
    body,
    content='posts',
    content_rowid='id',
    tokenize='unicode61'   -- 分词器，后面讲
);

-- 触发器：INSERT时同步
CREATE TRIGGER posts_ai AFTER INSERT ON posts BEGIN
    INSERT INTO posts_fts(rowid, title, body) 
    VALUES (new.id, new.title, new.body);
END;

-- 触发器：DELETE时同步
CREATE TRIGGER posts_ad AFTER DELETE ON posts BEGIN
    INSERT INTO posts_fts(posts_fts, rowid, title, body) 
    VALUES('delete', old.id, old.title, old.body);
END;

-- 触发器：UPDATE时同步
CREATE TRIGGER posts_au AFTER UPDATE ON posts BEGIN
    INSERT INTO posts_fts(posts_fts, rowid, title, body) 
    VALUES('delete', old.id, old.title, old.body);
    INSERT INTO posts_fts(rowid, title, body) 
    VALUES (new.id, new.title, new.body);
END;
```

注意DELETE触发器里那个诡异的语法：`INSERT INTO posts_fts(posts_fts, ...) VALUES('delete', ...)`。这不是笔误！这是FTS5的"命令表达式"，用来告诉FTS5"从索引里删除这一条"。是不是有种黑魔法的感觉？

### 12.4.3 已有数据的情况：先建表后填索引

如果你的posts表已经有100万条数据，才想加FTS5搜索怎么办？

```sql
-- 1. 创建FTS5表
CREATE VIRTUAL TABLE posts_fts USING fts5(
    title, body,
    content='posts',
    content_rowid='id'
);

-- 2. 一次性重建索引
INSERT INTO posts_fts(posts_fts) VALUES('rebuild');

-- 3. 从此以后靠触发器维护
```

那句`INSERT INTO posts_fts(posts_fts) VALUES('rebuild')`是FTS5的另一个"命令"，会扫描一遍主表，重建整个倒排索引。100万条大概需要几秒到几十秒，看数据量。

## 12.5 MATCH查询语法：全文搜索的DSL

FTS5的`MATCH`后面跟的字符串不是普通SQL，而是一门小型DSL（领域特定语言）。功能强得离谱。

### 12.5.1 基础查询

```sql
-- 单个词
SELECT * FROM posts_fts WHERE posts_fts MATCH 'SQLite';

-- 多个词（默认是AND）
SELECT * FROM posts_fts WHERE posts_fts MATCH 'SQLite 索引';
-- 找同时包含"SQLite"和"索引"的

-- OR
SELECT * FROM posts_fts WHERE posts_fts MATCH 'SQLite OR MySQL';

-- NOT（排除）
SELECT * FROM posts_fts WHERE posts_fts MATCH 'SQLite NOT MySQL';

-- 括号分组
SELECT * FROM posts_fts 
WHERE posts_fts MATCH '(SQLite OR MySQL) AND 性能';
```

### 12.5.2 短语查询（Phrase Query）

用双引号表示"这几个词必须连在一起，顺序不变"：

```sql
-- 找"性能优化"这个短语（挨着出现）
SELECT * FROM posts_fts WHERE posts_fts MATCH '"性能优化"';

-- 不同于（下面这个是找同时包含两个词，不要求相邻）
SELECT * FROM posts_fts WHERE posts_fts MATCH '性能 优化';
```

### 12.5.3 前缀查询

想搜"program"开头的所有词（program、programmer、programming...）？

```sql
SELECT * FROM posts_fts WHERE posts_fts MATCH 'program*';
```

**注意**：`*`只能在词尾，不能在词首（这是FTS5的限制，因为倒排索引本质是B树，只支持前缀查询）。想支持任意位置的模糊匹配？用`trigram`分词器（后面讲）。

### 12.5.4 NEAR：距离查询

要求两个词在指定距离内出现：

```sql
-- "SQLite"和"性能"之间隔不超过10个词
SELECT * FROM posts_fts WHERE posts_fts MATCH 'NEAR(SQLite 性能, 10)';

-- 默认距离是10
SELECT * FROM posts_fts WHERE posts_fts MATCH 'NEAR(SQLite 性能)';
```

这在语义搜索里超有用。比如你想找"关于SQLite性能的讨论"，用普通AND可能匹配到"这篇讲SQLite的文章，还提到了汽车性能"这种驴唇不对马嘴的结果。NEAR就能过滤掉。

### 12.5.5 列筛选（Column Filter）

只在特定列里搜：

```sql
-- 只在title列搜"SQLite"
SELECT * FROM posts_fts WHERE posts_fts MATCH 'title:SQLite';

-- 只在body列搜
SELECT * FROM posts_fts WHERE posts_fts MATCH 'body:SQLite';

-- 组合：title里有SQLite，body里有性能
SELECT * FROM posts_fts 
WHERE posts_fts MATCH 'title:SQLite AND body:性能';

-- 多列筛选
SELECT * FROM posts_fts 
WHERE posts_fts MATCH '{title body}:SQLite';
```

## 12.6 排序：BM25算法与rank列

### 12.6.1 相关性排序

搜索引擎和普通数据库最大的区别：**排序不是ORDER BY id，而是按"相关性"排序**。

FTS5默认使用**BM25算法**（Best Matching 25，1994年提出，Google搜索也在用）来计算相关性得分。

```sql
-- 按相关性排序（分数越低越相关，因为是负数）
SELECT title, body, rank 
FROM posts_fts 
WHERE posts_fts MATCH 'SQLite 索引'
ORDER BY rank;
```

注意那个神奇的`rank`列——你没定义过它，但它就是存在。这是FTS5的"隐藏列"，值是BM25分数（负数，越小越相关）。

### 12.6.2 BM25公式的直觉

BM25大致的逻辑：

1. **词频（TF）**：一个词在文档里出现次数越多，越相关。但不是线性关系（出现100次不代表比出现10次相关10倍，会衰减）。
2. **逆文档频率（IDF）**：一个词在整个语料库里越罕见，越有区分度。"的"、"是"这种词权重接近0。
3. **文档长度归一化**：短文档里出现一次的词，比长文档里出现一次的更相关。

你不需要记公式，只要知道：**BM25能自动判断哪个结果更相关**。

### 12.6.3 自定义列权重

标题的重要性通常比正文高。可以给不同列不同权重：

```sql
-- title权重10，body权重1
SELECT title, body, bm25(posts_fts, 10.0, 1.0) AS score
FROM posts_fts 
WHERE posts_fts MATCH 'SQLite'
ORDER BY score;
```

`bm25()`函数第一个参数是表名，后面每个参数对应一列的权重。

## 12.7 高亮与摘要：给用户看的东西

### 12.7.1 highlight函数

```sql
SELECT highlight(posts_fts, 0, '<mark>', '</mark>') AS highlighted_title
FROM posts_fts 
WHERE posts_fts MATCH 'SQLite';
```

参数说明：

- 第1个：表名
- 第2个：列索引（0是第一列title，1是body）
- 第3、4个：高亮开始和结束标记

结果类似：`<mark>SQLite</mark>入门教程`

### 12.7.2 snippet函数

只要一小段包含关键词的摘要，用于搜索结果预览：

```sql
SELECT snippet(
    posts_fts,        -- 表
    1,                -- 列索引（1=body）
    '<b>', '</b>',    -- 高亮标记
    '...',            -- 省略号
    32                -- 摘要长度（token数）
) AS excerpt
FROM posts_fts 
WHERE posts_fts MATCH 'SQLite'
ORDER BY rank
LIMIT 10;
```

结果类似：

> `...是一款轻量级<b>SQLite</b>数据库，它的性能优化...`

这就是Google搜索结果里那种"关键词高亮+上下文摘要"的效果，一行SQL就能搞定。

### 12.7.3 完整搜索接口

一个生产级的搜索SQL大概长这样：

```sql
SELECT 
    p.id,
    highlight(posts_fts, 0, '<em>', '</em>') AS title_hl,
    snippet(posts_fts, 1, '<em>', '</em>', '...', 40) AS body_snippet,
    p.author,
    p.created_at,
    bm25(posts_fts, 10.0, 1.0) AS score
FROM posts_fts
JOIN posts p ON p.id = posts_fts.rowid
WHERE posts_fts MATCH ?
ORDER BY score
LIMIT 20 OFFSET ?;
```

这一段SQL就能实现Google搜索式的界面。

## 12.8 分词器（Tokenizer）：搜索的灵魂

### 12.8.1 什么是分词

倒排索引的第一步是"把文本切成词"。这个过程叫**分词（Tokenization）**。

英文很简单：按空格和标点切。`"Hello, world!"` → `["hello", "world"]`。

中文……

> "结婚的和尚未结婚的"

这句话到底该切成什么？

- 结婚 / 的 / 和 / 尚未 / 结婚 / 的
- 结婚 / 的 / 和尚 / 未 / 结婚 / 的

这就是中文分词的经典难题。

FTS5内置了几个分词器：

- **unicode61**（默认）：按Unicode规则切分，对英文很好，中文按字切
- **porter**：英文词干提取（running → run，goes → go）
- **trigram**：三字符切片，支持任意位置的模糊匹配
- **ascii**：只处理ASCII字符

### 12.8.2 unicode61详解

```sql
CREATE VIRTUAL TABLE t USING fts5(
    content,
    tokenize='unicode61'
);
```

选项：

```sql
-- 移除变音符号（é → e）
tokenize='unicode61 remove_diacritics 2'

-- 分隔符自定义（默认按标点分）
tokenize="unicode61 separators '.'"

-- token字符（默认字母数字，可自定义）
tokenize="unicode61 tokenchars '_@'"

-- 大小写敏感（默认不敏感）
tokenize='unicode61 case_sensitive 1'
```

### 12.8.3 trigram：模糊匹配救星

`unicode61`分完词后，你不能搜"中间部分"。比如内容是"programming"，你搜`gram*`可以（前缀），但搜`*gram*`就不行。

**trigram**把每3个字符当一个token：

```sql
CREATE VIRTUAL TABLE code_fts USING fts5(
    code,
    tokenize='trigram'
);

INSERT INTO code_fts VALUES ('function calculateTotal(x) { }');

-- 现在可以搜任意子串
SELECT * FROM code_fts WHERE code_fts MATCH 'lcul';
-- 会命中，因为"lcul"是calculateTotal的一部分
```

代价是：**索引变大很多**（每3个连续字符都要建立索引）。适合代码搜索、日志搜索这种"用户不知道完整关键词"的场景。

### 12.8.4 中文分词的挑战

`unicode61`对中文的分词是**逐字**的。也就是说，"量子力学"会被切成"量"、"子"、"力"、"学"四个token。

**这意味着什么？**

- 优点：召回率高。用户搜"力学"能命中"量子力学"。
- 缺点：会有一些"误伤"。搜"上海"会命中"上海边玩"（因为都包含"上"和"海"，虽然不相邻）。用短语查询`"上海"`可以缓解。

**真正的中文分词方案：**

1. **simple分词器扩展**：由wangfenjin开发的开源扩展，支持中文分词+拼音搜索。GitHub上很火。
2. **jieba分词**：在应用层用jieba分好词，用空格拼接后插入FTS5（用一个"外部分词"策略）。
3. **ICU分词器**：SQLite官方的ICU扩展，需要单独编译。

### 12.8.5 应用层预分词的技巧

如果你不想折腾扩展，可以在应用层用jieba分词，然后在SQL里以空格分隔词插入：

```dart
// Dart示例（伪代码，假设有jieba_dart包）
import 'package:jieba_dart/jieba_dart.dart';

String tokenize(String text) {
  final tokens = Jieba.cut(text);
  return tokens.join(' ');
}

// 插入时预处理
await db.insert('posts_fts', {
  'title': tokenize(title),
  'body': tokenize(body),
});

// 搜索时也预处理
final queryTokens = tokenize(userQuery);
await db.rawQuery(
  'SELECT * FROM posts_fts WHERE posts_fts MATCH ?',
  [queryTokens],
);
```

这样FTS5就用默认的unicode61分词，按空格切，能达到接近专业中文分词的效果。

## 12.9 Spellfix1：拼写纠错

用户输入`"sqllite"`（多打了一个l），你想帮他找到`"sqlite"`的结果。这就是拼写纠错。

SQLite有个扩展叫`spellfix1`，需要单独编译加载：

```sql
-- 加载扩展
.load ./spellfix

-- 创建词典表
CREATE VIRTUAL TABLE demo USING spellfix1;

-- 灌入词典（比如从你的文章标题里抽词）
INSERT INTO demo(word) VALUES ('sqlite'), ('mysql'), ('postgres');

-- 查询相似词
SELECT word, distance FROM demo 
WHERE word MATCH 'sqllite' 
LIMIT 3;
-- 结果：sqlite, distance=17（越小越相似）
```

在应用里的流程：

1. 用户输入"sqllite"
2. 先用FTS5搜"sqllite"，无结果
3. 用spellfix1找相似词 → "sqlite"
4. 提示用户"你是要搜sqlite吗？"（Google那个"Did you mean"）

## 12.10 Flutter实战：sqflite中启用FTS5

sqflite默认支持FTS5，直接用就行：

```dart
import 'package:sqflite/sqflite.dart';
import 'package:path/path.dart';

class SearchDatabase {
  static Database? _db;
  
  static Future<Database> open() async {
    if (_db != null) return _db!;
    
    final dbPath = await getDatabasesPath();
    _db = await openDatabase(
      join(dbPath, 'search.db'),
      version: 1,
      onCreate: (db, version) async {
        // 主表
        await db.execute('''
          CREATE TABLE posts (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            title TEXT NOT NULL,
            body TEXT NOT NULL,
            author TEXT,
            created_at INTEGER DEFAULT (unixepoch())
          )
        ''');
        
        // FTS5索引表
        await db.execute('''
          CREATE VIRTUAL TABLE posts_fts USING fts5(
            title, body,
            content='posts',
            content_rowid='id',
            tokenize='unicode61'
          )
        ''');
        
        // 触发器
        await db.execute('''
          CREATE TRIGGER posts_ai AFTER INSERT ON posts BEGIN
            INSERT INTO posts_fts(rowid, title, body) 
            VALUES (new.id, new.title, new.body);
          END
        ''');
        
        await db.execute('''
          CREATE TRIGGER posts_ad AFTER DELETE ON posts BEGIN
            INSERT INTO posts_fts(posts_fts, rowid, title, body) 
            VALUES('delete', old.id, old.title, old.body);
          END
        ''');
        
        await db.execute('''
          CREATE TRIGGER posts_au AFTER UPDATE ON posts BEGIN
            INSERT INTO posts_fts(posts_fts, rowid, title, body) 
            VALUES('delete', old.id, old.title, old.body);
            INSERT INTO posts_fts(rowid, title, body) 
            VALUES (new.id, new.title, new.body);
          END
        ''');
      },
    );
    return _db!;
  }
  
  /// 插入文章
  static Future<int> insertPost(String title, String body, String author) async {
    final db = await open();
    return await db.insert('posts', {
      'title': title,
      'body': body,
      'author': author,
    });
  }
  
  /// 搜索
  static Future<List<SearchResult>> search(String query, {int limit = 20}) async {
    final db = await open();
    
    // 清理用户输入，避免特殊字符导致MATCH报错
    final safeQuery = _sanitizeQuery(query);
    if (safeQuery.isEmpty) return [];
    
    final rows = await db.rawQuery('''
      SELECT 
        p.id,
        p.author,
        p.created_at,
        highlight(posts_fts, 0, '<mark>', '</mark>') AS title_hl,
        snippet(posts_fts, 1, '<mark>', '</mark>', '...', 40) AS body_snippet,
        bm25(posts_fts, 10.0, 1.0) AS score
      FROM posts_fts
      JOIN posts p ON p.id = posts_fts.rowid
      WHERE posts_fts MATCH ?
      ORDER BY score
      LIMIT ?
    ''', [safeQuery, limit]);
    
    return rows.map((r) => SearchResult.fromMap(r)).toList();
  }
  
  /// 用户输入的安全化处理
  /// FTS5的MATCH对特殊字符（" ' * : 等）敏感，会报syntax error
  static String _sanitizeQuery(String query) {
    // 移除FTS5的特殊字符
    final cleaned = query
        .replaceAll(RegExp(r'''[\"'*:()]'''), ' ')
        .trim();
    
    if (cleaned.isEmpty) return '';
    
    // 把每个词加上*做前缀匹配（可选）
    final tokens = cleaned.split(RegExp(r'\s+'));
    return tokens.map((t) => '$t*').join(' ');
  }
}

class SearchResult {
  final int id;
  final String? author;
  final int createdAt;
  final String titleHighlighted;
  final String bodySnippet;
  final double score;
  
  SearchResult({
    required this.id,
    this.author,
    required this.createdAt,
    required this.titleHighlighted,
    required this.bodySnippet,
    required this.score,
  });
  
  factory SearchResult.fromMap(Map<String, dynamic> map) {
    return SearchResult(
      id: map['id'] as int,
      author: map['author'] as String?,
      createdAt: map['created_at'] as int,
      titleHighlighted: map['title_hl'] as String,
      bodySnippet: map['body_snippet'] as String,
      score: (map['score'] as num).toDouble(),
    );
  }
}
```

使用：

```dart

await SearchDatabase.insertPost(
  'Flutter中使用SQLite的实践',
  '本文讲述如何在Flutter应用中集成SQLite数据库...',
  'Alice',
);
```

## 12.11 drift中的FTS5

drift（前身是moor）是Flutter生态里最流行的类型安全的SQLite ORM。它对FTS5的支持很优雅：

```dart
import 'package:drift/drift.dart';

// 主表
class Posts extends Table {
  IntColumn get id => integer().autoIncrement()();
  TextColumn get title => text()();
  TextColumn get body => text()();
  TextColumn get author => text().nullable()();
  DateTimeColumn get createdAt => dateTime().withDefault(currentDateAndTime)();
}

// FTS5虚拟表
@UseRowClass(PostSearchResult)
class PostsFts extends Table with VirtualTableInfo<PostsFts, PostSearchResult> {
  TextColumn get title => text()();
  TextColumn get body => text()();
  
  @override
  String get moduleAndArgs => 
      'fts5(title, body, content=posts, content_rowid=id)';
}

@DriftDatabase(tables: [Posts, PostsFts])
class AppDatabase extends _$AppDatabase {
  AppDatabase() : super(_openConnection());
  
  @override
  int get schemaVersion => 1;
  
  @override
  MigrationStrategy get migration => MigrationStrategy(
    onCreate: (m) async {
      await m.createAll();
      // 创建触发器
      await customStatement('''
        CREATE TRIGGER posts_ai AFTER INSERT ON posts BEGIN
          INSERT INTO posts_fts(rowid, title, body) 
          VALUES (new.id, new.title, new.body);
        END
      ''');
      // ... 其他触发器
    },
  );
  
  /// 搜索
  Future<List<SearchHit>> searchPosts(String query) async {
    final result = await customSelect(
      '''
      SELECT 
        p.id, p.author, p.created_at,
        highlight(posts_fts, 0, '<mark>', '</mark>') AS title_hl,
        snippet(posts_fts, 1, '<mark>', '</mark>', '...', 40) AS body_snippet,
        bm25(posts_fts, 10.0, 1.0) AS score
      FROM posts_fts
      JOIN posts p ON p.id = posts_fts.rowid
      WHERE posts_fts MATCH ?
      ORDER BY score
      LIMIT 20
      ''',
      variables: [Variable.withString(query)],
      readsFrom: {posts, postsFts},
    ).get();
    
    return result.map((row) => SearchHit(
      id: row.read<int>('id'),
      titleHighlighted: row.read<String>('title_hl'),
      bodySnippet: row.read<String>('body_snippet'),
      score: row.read<double>('score'),
    )).toList();
  }
}
```

## 12.12 原理深挖：FTS5的存储结构

FTS5在磁盘上其实创建了多张"影子表"（shadow tables），后缀分别是：

- `posts_fts_data`：存倒排索引的二进制数据
- `posts_fts_idx`：索引的B树结构
- `posts_fts_content`：如果不是外部内容表，存原始内容
- `posts_fts_docsize`：每个文档的长度（BM25计算需要）
- `posts_fts_config`：配置信息

你可以看到这些表：

```sql
SELECT name FROM sqlite_master WHERE name LIKE 'posts_fts%';
```

**别去直接改这些表！**它们是FTS5的内部实现，动了就会腐化数据。

倒排索引的具体存储用了一种叫**segment**的机制，类似Lucene：

1. 每次写入先进"内存segment"
2. 定期合并到磁盘的"level 0 segment"
3. 多个level 0合并成level 1，以此类推
4. 类似LSM Tree的思想

这就是为什么FTS5**写入很快，查询也快**——用空间换时间，用异步合并换稳定的写入延迟。

## 12.13 常见坑点

### 坑1：MATCH语法错误

用户输入`"C++"`，直接扔给MATCH会报错，因为`+`是保留字符。**必须做输入清理**。

### 坑2：忘记建触发器

只创建了FTS5表没建触发器，插数据后搜不到——因为FTS5表根本没数据。用`rebuild`命令补救。

### 坑3：BM25分数是负数

新手常犯：`ORDER BY rank DESC`——错了！`rank`是负数，`ORDER BY rank ASC`（或默认）才是"最相关的在前"。

### 坑4：外部内容表和主表不同步

如果绕过触发器直接改FTS5的shadow table，或者主表用了`REPLACE`触发器没跟上，会导致索引和内容不一致。定期跑：

```sql
INSERT INTO posts_fts(posts_fts) VALUES('integrity-check');
-- 有问题就rebuild
INSERT INTO posts_fts(posts_fts) VALUES('rebuild');
```

### 坑5：中文搜索"精度问题"

默认unicode61对中文按字切，会有语义误差。生产环境要么用simple扩展，要么应用层预分词。

### 坑6：FTS5表不能加PRIMARY KEY

FTS5虚拟表的`rowid`就是隐含的主键，不能再定义`INTEGER PRIMARY KEY`列。想关联主表就用`content_rowid`。

### 坑7：大量小更新导致索引膨胀

FTS5用segment机制，频繁小写入会产生很多segment。定期优化：

```sql
INSERT INTO posts_fts(posts_fts) VALUES('optimize');
```

## 12.14 本章小结

- FTS5是SQLite的全文搜索神器，底层是**倒排索引**
- 用**外部内容表 + 触发器**是生产环境最佳实践
- `MATCH`语法支持AND/OR/NOT、短语、前缀、NEAR、列筛选
- `rank`列+BM25算法自动排序
- `highlight()`和`snippet()`让搜索结果显示专业化
- 中文分词用simple扩展或应用层预分词
- Flutter里sqflite/drift都能优雅集成FTS5
