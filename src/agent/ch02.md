## 2.1 开篇引入：LLM 是 Agent 的 CPU

如果把 Agent 比作一个微服务系统，LLM 就是其中的 **CPU（中央处理器）**：

```
Agent 系统组成：

LLM（CPU）        → 核心推理引擎
Prompt（指令集）   → 告诉 LLM 做什么
Tools（外设）      → 扩展 LLM 的能力
Memory（内存/硬盘） → 存储上下文和知识
```

LLM 决定了 Agent 的**能力上限**。就像再好的外设也救不了烂 CPU — 再好的工具和 Prompt 也救不了理解力差的模型。

了解 LLM 的工作方式，才能：

1. **选对模型**：不是越大越好，要匹配任务复杂度
2. **写好 Prompt**：理解 LLM 怎么"阅读"才能写更有效的指令
3. **控制输出**：用 Temperature/Top-p 控制确定性 vs 创意
4. **管理成本**：知道 token 怎么算钱，避免浪费

## 2.2 Transformer 直觉理解 — "注意力"就是"重点阅读"

### 一个例子理解 Attention

> "Redis 是键值存储。它支持多种数据结构。由于**它**基于内存操作，所以速度非常快。"

当你读到第二个"它"时，大脑自动关联回"Redis"而不是"数据结构"。这就是 **Attention（注意力机制）** — 对每个词分配不同的关注度权重。

```python
# 注意力机制的直觉理解
# 读到 "它" 时，模型对前面每个词分配注意力权重：
attention_weights = {
    "Redis": 0.82,      # 最高 — "它"最可能指 Redis
    "键值存储": 0.08,   # 低 — 是 Redis 的属性
    "数据结构": 0.05,   # 很低 — 不是"它"的所指
    "内存操作": 0.03,   # 很低
    "速度": 0.02,       # 最低
}

# 模型用这些权重加权前面的信息，理解"它"= Redis
# 这就是为什么 LLM 能理解上下文，而不是简单的关键词匹配
```

### Transformer 处理流程

```
输入文本 "Redis 是 键值 存储"
   ↓
[1] Tokenization: ["Redis", "是", "键值", "存储"] → [1024, 89, 5678, 2345]
   ↓
[2] Token Embedding: 每个 token → 768维向量
   ↓
[3] 位置编码: 加入位置信息（第1个词、第2个词...）
   ↓
[4] Transformer Block × N:
   │  ├─ Multi-Head Attention: 多个"注意力头"并行
   │  │   ├─ 头1: 关注语法关系
   │  │   ├─ 头2: 关注语义关系
   │  │   └─ 头3: 关注指代关系
   │  ├─ Feed-Forward: 非线性变换
   │  └─ Layer Normalization: 稳定训练
   ↓
[5] 输出: 预测下一个 token 的概率分布
```

> 程序员视角：LLM 本质上是一个巨大的函数 `f(text_tokens) → next_token_probs`
>
> - 数十亿到万亿个参数
> - 用海量文本训练得到
> - 每次调用就是执行一次前向传播

## 2.3 自回归生成 + 涌现能力

```python
def generate_text(model, prompt, max_tokens=100):
    """逐 token 生成，每步基于之前所有内容"""
    tokens = tokenize(prompt)
    generated = []
    for _ in range(max_tokens):
        # 关键：每次基于完整序列预测下一个 token
        probs = model.predict(tokens + generated)
        next_tok = sample(probs)  # temperature/top_p 控制选择策略
        if next_tok == END: break
        generated.append(next_tok)
    return detokenize(generated)
```

**涌现能力**：模型够大时突然出现的能力（少样本学习、思维链、代码生成等）。

> ⚠️ 小模型(<7B)缺复杂推理。Agent 建议至少 70B 级。

## 2.4 Tokenization — LLM 怎么"读"文本

LLM 不是按字或按词读文本，而是按 **token** 读。Tokenization 就是把文本切成 token 的过程。

### BPE（Byte Pair Encoding）算法

```python
# BPE 的核心思想：频繁出现的字符组合合并成一个 token
# 训练过程：
# 初始: ["h","e","l","l","o"] → 每个字符一个 token
# 迭代1: "l"+"l"出现最多 → 合并为"ll" → ["h","e","ll","o"]
# 迭代2: "he"+"ll"出现多 → 合并为"hell" → ["hell","o"]
# 最终: "hello" 变成一个 token

import tiktoken  # pip install tiktoken
enc = tiktoken.encoding_for_model("gpt-4")

# 测试
examples = [
    "Hello, World!",           # [9906, 11, 2159, 0] — 4 tokens
    "def hello_world():",      # 多个 tokens
    "print('Hello')",          # 多个 tokens
    "Kubernetes",              # 1-2 tokens（常见词）
]

for text in examples:
    tokens = enc.encode(text)
    print(f"'{text}' → {len(tokens)} tokens: {tokens}")
```

### 中英文 Token 效率对比

```python
# 英文：一个常见单词 ≈ 1 token
en_text = "The quick brown fox jumps over the lazy dog."
en_tokens = enc.encode(en_text)
print(f"英文: '{en_text}' → {len(en_tokens)} tokens")  # ~10 tokens

# 中文：一个字 ≈ 1-3 tokens（效率低！）
cn_text = "敏捷的棕色狐狸跳过了懒狗。"
cn_tokens = enc.encode(cn_text)
print(f"中文: '{cn_text}' → {len(cn_tokens)} tokens")  # ~15-20 tokens

# 结论：中文 token 效率低 1.5-2 倍 → API 成本更高！
# 面向中文用户的应用需要考虑这个成本差异
```

### 成本估算

```python
def estimate_cost(input_tokens: int, output_tokens: int, 
                   model: str = "gpt-4o") -> str:
    """估算 API 调用成本"""
    prices = {
        "gpt-4o": {"input": 2.50, "output": 10.00},
        "gpt-4o-mini": {"input": 0.15, "output": 0.60},
        "gpt-4": {"input": 30.00, "output": 60.00},
    }
    
    p = prices[model]
    cost_usd = (input_tokens / 1e6) * p["input"] + \
               (output_tokens / 1e6) * p["output"]
    cost_cny = cost_usd * 7.2
    
    return f"${cost_usd:.4f} ≈ ¥{cost_cny:.2f}"

# 场景估算
scenarios = [
    ("简单问答", 1000, 200, "gpt-4o"),
    ("RAG问答", 5000, 500, "gpt-4o"),
    ("Agent工具调用", 3000, 300, "gpt-4o-mini"),
    ("长文档分析", 50000, 2000, "gpt-4o"),
]

print("=== 成本估算 ===")
for name, inp, out, model in scenarios:
    cost = estimate_cost(inp, out, model)
    print(f"{name:15s}: {cost} ({model})")

# 月度成本估算（假设每天 1000 次调用）
daily_calls = 1000
days = 30
monthly_calls = daily_calls * days
avg_input = 3000  # 平均输入 tokens
avg_output = 500  # 平均输出 tokens

monthly_cost_gpt4o = monthly_calls * (
    avg_input / 1e6 * 2.50 + avg_output / 1e6 * 10.00
)
monthly_cost_mini = monthly_calls * (
    avg_input / 1e6 * 0.15 + avg_output / 1e6 * 0.60
)

print(f"\n月度成本（{daily_calls}次/天 × {days}天）:")
print(f"  GPT-4o:      ${monthly_cost_gpt4o:.2f}/月")
print(f"  GPT-4o-mini: ${monthly_cost_mini:.2f}/月")
print(f"  节省: {monthly_cost_gpt4o/monthly_cost_mini:.1f}x")
```

> ⚠️ **Token 成本优化技巧**：
>
> 1. 用 `gpt-4o-mini` 做工具调用（便宜 20 倍）
> 2. System Prompt 精简到 <1000 tokens
> 3. 对话历史定期清理
> 4. RAG 检索结果只取 top-3
> 5. 中文应用考虑用中文优化的模型

## 2.5 Chat Completions vs Embeddings API

```python
import openai
client = openai.OpenAI(api_key="key")

# Chat Completions — 生成文本
chat = client.chat.completions.create(
    model="gpt-4",
    messages=[{"role":"user","content":"解释 Docker volume"}],
    temperature=0.3)
print(chat.choices[0].message.content)

# Embeddings — 文本转向量（用于语义搜索）
emb = client.embeddings.create(
    model="text-embedding-3-small",
    input="Docker volume 是持久化存储")
print(f"维度: {len(emb.data[0].embedding)}")  # 1536
```

| | Chat Completions | Embeddings |
| --- | --- | --- |
| 用途 | 生成文本 | 文本向量化 |
| 成本 | 高 | 低(~1/50) |
| 场景 | Agent推理 | 语义搜索 |

两者**配合**：Embeddings 检索文档，Chat Completions 生成回答。

## 2.6 Temperature / Top-p — 控制"确定性 vs 创意"

Temperature 和 Top-p 控制 LLM 输出时的"随机性"。

### Temperature 的直觉理解

```python
# 想象 LLM 要选下一个词，候选和概率：
# "Docker" (0.6) "容器" (0.3) "K8s" (0.08) "Nginx" (0.02)

# temp=0 → 总是选概率最高的 → "Docker"（确定性）
# temp=0.5 → 偏向高概率但偶尔选低概率 → 大部分时候 "Docker"
# temp=1.0 → 完全按原始概率 → 有时选 "容器"、"K8s"
# temp=2.0 → 放大低概率 → 可能选 "Nginx"（创意但不靠谱）
```

```python
# Agent 场景的 Temperature 推荐
temp_recommendations = {
    "工具调用":    {"temp": 0,    "reason": "必须准确，不能有随机性"},
    "技术问答":    {"temp": 0.2,  "reason": "偏确定，偶尔灵活"},
    "代码生成":    {"temp": 0.2,  "reason": "代码需要准确"},
    "通用对话":    {"temp": 0.5,  "reason": "平衡准确和自然"},
    "创意写作":    {"temp": 0.8,  "reason": "需要多样性和创意"},
    "头脑风暴":    {"temp": 1.0,  "reason": "最大化多样性"},
}

# ⚠️ temp 和 top_p 不要同时调！选一个就行
# 推荐：Agent 场景固定 temp=0 或 0.2，top_p=1.0（默认）
```

## 2.7 Context Window — LLM 的"工作内存"

Context Window 就像函数的参数列表 — 有大小限制。超出限制就报错了。

```python
context_windows = {
    "GPT-3.5-turbo": 16_385,     # ~12000 中文字
    "GPT-4o":        128_000,    # ~96000 中文字
    "GPT-4o-mini":   128_000,    # ~96000 中文字
    "Claude-3.5":    200_000,    # ~150000 中文字
    "Llama-3-70B":   8_192,      # ~6000 中文字
}

# 一个典型 Agent 请求的 token 分布
typical_request = {
    "System Prompt":     500,   # Agent 的人设
    "Few-shot Examples": 300,   # 示例
    "Conversation History": 3000, # 对话历史
    "RAG Results":       2000,  # 检索到的文档
    "Tool Descriptions": 1000,  # 工具说明
    "User Question":     100,   # 用户问题
    "TOTAL":             6900,  # 总计
}

# 对于 128K 窗口的 GPT-4o：还剩 121100 tokens 给输出
# 对于 8K 窗口的 Llama-3-70B：超了！需要裁剪
```

> ⚠️ **Lost in the Middle 问题**：
> LLM 对 Context Window **开头和结尾**的注意力更强，中间部分容易被"遗忘"。
>
> **解决方案**：
>
> - 重要信息放开头（System Prompt）或结尾（用户问题）
> - RAG 结果不要太多（3-5 条足够）
> - 对话历史定期清理（保留最近 5-10 条）
> - 长文档用摘要而不是全文

## 2.8 API 实操

```python
# === OpenAI API ===
import os
from openai import OpenAI
from dotenv import load_dotenv
load_dotenv()
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

# 基础调用
def chat(q):
    r = client.chat.completions.create(model="gpt-4",
        messages=[{"role":"system","content":"技术文档助手。"},
                  {"role":"user","content":q}],
        temperature=0.3)
    return r.choices[0].message.content

# 流式输出
def stream(q):
    s = client.chat.completions.create(model="gpt-4",
        messages=[{"role":"user","content":q}], temperature=0.3, stream=True)
    for c in s:
        if c.choices[0].delta.content:
            print(c.choices[0].delta.content, end="", flush=True)

# 多轮对话
def multi():
    msgs = [{"role":"system","content":"Python专家。"}]
    for q in ["什么是装饰器？","给个例子？","带参数呢？"]:
        msgs.append({"role":"user","content":q})
        r = client.chat.completions.create(model="gpt-4", messages=msgs, temperature=0.3)
        a = r.choices[0].message.content
        msgs.append({"role":"assistant","content":a})
        print(f"Q:{q}\nA:{a}\n")

# Function Calling
def fc():
    tools = [{"type":"function","function":{
        "name":"search_docs","description":"搜索文档",
        "parameters":{"type":"object","properties":{
            "query":{"type":"string"}}, "required":["query"]}}}]
    r = client.chat.completions.create(model="gpt-4",
        messages=[{"role":"user","content":"找 asyncio 用法"}],
        tools=tools, tool_choice="auto")
    if r.choices[0].message.tool_calls:
        tc = r.choices[0].message.tool_calls[0]
        print(f"调用: {tc.function.name}({tc.function.arguments})")
```

## 2.9 成本控制

```python
from dataclasses import dataclass
@dataclass
class P: n:str; i:float; o:float
PRICING = {"gpt-4o":P("4o",2.5,10), "gpt-4o-mini":P("mini",0.15,0.6)}

def monthly(daily, in_t=3000, out_t=500, model="gpt-4o"):
    p = PRICING[model]; m = daily*30
    c = m*in_t/1e6*p.i + m*out_t/1e6*p.o
    return round(c*7.2, 2)  # RMB

for s,d in [("10人",100),("50人",1000),("200人",5000)]:
    print(f"{s}: mini=¥{monthly(d,model='gpt-4o-mini')}, 4o=¥{monthly(d)}")
```

> ⚠️ `gpt-4o-mini` 成本是 `gpt-4o` 的 1/20，多数场景够用。

## 2.10 实战：DocMind 原型

```python
import os
from openai import OpenAI
from dotenv import load_dotenv
load_dotenv()

class DocMindPrototype:
    SYS = "你是 DocMind，智能技术文档助手。简洁准确，不编造，代码用Python。"
    def __init__(self, model="gpt-4o-mini"):
        self.c = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
        self.m = model; self.h = []
    def ask(self, q):
        msgs = [{"role":"system","content":self.SYS}] + self.h + [{"role":"user","content":q}]
        r = self.c.chat.completions.create(model=self.m, messages=msgs, temperature=0.3)
        a = r.choices[0].message.content
        self.h += [{"role":"user","content":q},{"role":"assistant","content":a}]
        print(f"  [Token: {r.usage.total_tokens}]")
        return a

dm = DocMindPrototype()
for q in ["什么是Docker多阶段构建？","给个Dockerfile示例？","镜像多大？"]:
    print(f"\nQ:{q}\nA:{dm.ask(q)}")
```
