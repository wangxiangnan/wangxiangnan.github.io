# 第18章：高可用架构设计

## 引言：从"能用"到"打不死"

写代码有两种境界：

1. "能跑就行"——本地开发，一台机器搞定一切
2. "打死都不能挂"——生产环境，任何单点故障都不能影响用户

Redis 的高可用架构演进，就像是一个程序员的成长历程：

```
Level 1: 单机 Redis          -> 实习生：代码能跑就行
Level 2: 主从复制            -> 初级工程师：至少有个备份
Level 3: 哨兵模式            -> 高级工程师：自动故障转移
Level 4: Cluster 集群        -> 架构师：水平扩展 + 高可用
Level 5: 跨机房多活          -> 技术专家：地域级容灾
```

本章将带你从架构设计的高度，理解如何根据业务规模选择最合适的 Redis 高可用方案。

> **编程隐喻时间**：高可用架构设计就像设计一个分布式系统——你需要在 CAP 三角（一致性、可用性、分区容错性）之间做权衡。Redis 选择了 AP（可用性 + 分区容错性），在分区发生时优先保证服务可用，牺牲强一致性，追求最终一致性。

## 18.1 Redis 高可用架构演进

```
Level 1: 单机 Redis
  [Master]
  优点：简单，性能好
  缺点：单点故障，无法扩展

Level 2: 主从复制
  [Master] -> [Rep1] [Rep2]
  优点：数据冗余，读扩展
  缺点：Master 挂了需要手动切换

Level 3: 哨兵模式
  [Sent1] [Sent2] [Sent3] <- 监控层
  [Master] -> [Rep1] [Rep2]
  优点：自动故障转移
  缺点：写扩展受限

Level 4: Cluster 集群
  [Master-1] [Master-2] [Master-3] <- 数据分片
  [Rep-1]    [Rep-2]    [Rep-3]
  优点：水平扩展 + 自动故障转移
  缺点：复杂度高，多 key 操作受限
```

### 18.3.2 数据同步策略

```js
const Redis = require('ioredis');

const localRedis = new Redis({ host: '10.0.1.10', port: 6379 });
const remoteRedis = new Redis({ host: '10.0.2.10', port: 6379 });

class CrossRegionSync {
  constructor(local, remote) {
    this.local = local;
    this.remote = remote;
    this.isProcessing = false;
  }

  async writeWithSync(key, value, options = {}) {
    // 1. 写入本地 Redis
    if (options.ex) {
      await this.local.set(key, value, 'EX', options.ex);
    } else {
      await this.local.set(key, value);
    }

    // 2. 记录到同步队列
    await this.local.rpush(
      '__sync_queue__',
      JSON.stringify({ key, value, ex: options.ex, ts: Date.now() })
    );

    // 3. 触发异步同步
    this._processQueue();
  }

  async _processQueue() {
    if (this.isProcessing) return;
    this.isProcessing = true;

    try {
      while (true) {
        const item = await this.local.lpop('__sync_queue__');
        if (!item) break;

        const { key, value, ex } = JSON.parse(item);
        try {
          if (ex) {
            await this.remote.set(key, value, 'EX', ex);
          } else {
            await this.remote.set(key, value);
          }
        } catch (err) {
          await this.local.lpush('__sync_queue__', item);
          console.error('同步失败，稍后重试:', err.message);
          break;
        }
      }
    } finally {
      this.isProcessing = false;
    }
  }
}

const sync = new CrossRegionSync(localRedis, remoteRedis);

(async () => {
  await sync.writeWithSync('user:1001', JSON.stringify({ name: '张三' }));
  console.log('写入本地完成，异步同步到远端...');
  localRedis.disconnect();
  remoteRedis.disconnect();
})();
```

### 18.3.3 延迟和一致性权衡

| 同步方式 | 延迟 | 一致性 | 适用场景 |
|----------|------|--------|----------|
| 同步复制 | 高（跨机房 RTT） | 强一致 | 金融、支付 |
| 异步复制 | 低 | 最终一致 | 社交、内容 |
| 半同步复制（WAIT） | 中等 | 较强 | 电商、O2O |

> [!WARNING] 注意
> 跨机房同步复制（WAIT）会显著增加写操作延迟。如果两个机房之间的 RTT 是 50ms，那每次写操作至少要多等 50ms。

## 18.4 容灾设计

### 18.4.1 带有熔断器的 Redis 客户端

```js
const Redis = require('ioredis');

class ResilientRedis {
  constructor(config) {
    this.redis = new Redis(config);
    this.circuitBreaker = {
      failures: 0,
      lastFailure: 0,
      threshold: 5,
      resetTimeout: 30000,
      state: 'CLOSED',  // CLOSED, OPEN, HALF_OPEN
    };
    this.fallbackCache = new Map();
  }

  async execute(command, ...args) {
    // 熔断器检查
    if (this.circuitBreaker.state === 'OPEN') {
      if (Date.now() - this.circuitBreaker.lastFailure > this.circuitBreaker.resetTimeout) {
        this.circuitBreaker.state = 'HALF_OPEN';
        console.log('[容灾] 熔断器半开，尝试恢复...');
      } else {
        return this._fallback(command, ...args);
      }
    }

    try {
      const result = await this.redis[command](...args);
      this._onSuccess();
      return result;
    } catch (err) {
      this._onFailure();
      return this._fallback(command, ...args);
    }
  }

  _onSuccess() {
    if (this.circuitBreaker.state === 'HALF_OPEN') {
      console.log('[容灾] 服务恢复，熔断器关闭');
    }
    this.circuitBreaker.failures = 0;
    this.circuitBreaker.state = 'CLOSED';
  }

  _onFailure() {
    this.circuitBreaker.failures++;
    this.circuitBreaker.lastFailure = Date.now();
    if (this.circuitBreaker.failures >= this.circuitBreaker.threshold) {
      this.circuitBreaker.state = 'OPEN';
      console.warn('[容灾] 熔断器打开！切换到降级模式');
    }
  }

  _fallback(command, ...args) {
    const cmd = command.toLowerCase();
    if (cmd === 'get' && args[0]) {
      const cached = this.fallbackCache.get(args[0]);
      if (cached) {
        console.log(`[降级] 从本地缓存读取: ${args[0]}`);
        return cached;
      }
    }
    console.warn(`[降级] 命令 ${command} 无法降级，返回 null`);
    return null;
  }

  async set(key, value, ...rest) {
    const result = await this.execute('set', key, value, ...rest);
    this.fallbackCache.set(key, value);
    if (this.fallbackCache.size > 10000) {
      const firstKey = this.fallbackCache.keys().next().value;
      this.fallbackCache.delete(firstKey);
    }
    return result;
  }

  disconnect() {
    this.redis.disconnect();
  }
}

const resilient = new ResilientRedis({
  sentinels: [
    { host: '10.0.1.10', port: 26379 },
    { host: '10.0.1.11', port: 26379 },
  ],
  name: 'mymaster',
  maxRetriesPerRequest: 1,
  retryStrategy(times) {
    if (times > 3) return null;
    return Math.min(times * 200, 2000);
  },
});

(async () => {
  await resilient.set('config:feature_flag', 'true');
  const flag = await resilient.execute('get', 'config:feature_flag');
  console.log('Feature flag:', flag);
  resilient.disconnect();
})();
```

### 18.4.2 数据备份策略

```
备份层次：

Level 1: Redis 自身持久化
  - RDB：定时快照（每 15 分钟）
  - AOF：每条写命令记录

Level 2: 文件级备份
  - 定时复制 RDB/AOF 文件到备份存储
  - 保留最近 7 天的每日备份
  - 保留最近 12 个月的每月备份

Level 3: 异地备份
  - 将备份文件复制到异地存储（S3/OSS）
  - 加密传输和存储

Level 4: 应用级备份
  - 关键业务数据写入消息队列，异步归档
  - 数据库和 Redis 的联合备份点
```

## 18.5 性能与可用性的平衡

### 18.5.1 CAP 定理与 Redis

```
CAP 定理：在分布式系统中，以下三个特性最多只能同时满足两个：
- C (Consistency)：一致性
- A (Availability)：可用性
- P (Partition Tolerance)：分区容错性

Redis 的选择：AP（可用性 + 分区容错性）

原因：
1. Redis 使用异步复制 -> 分区时数据可能不一致 -> 放弃 C
2. Redis 优先保证服务可用 -> 即使部分节点故障也能继续服务 -> 选择 A
3. 网络分区不可避免 -> 必须选择 P
```

### 18.5.2 最终一致性

```
时间线：

t0: Client 写入 Master -> SET key "v2"
t1: Master 返回 OK
t2: Replica-1 收到同步 -> key = "v2"
t3: Replica-2 收到同步 -> key = "v2"

在 t1~t3 之间，如果 Client 从 Replica-2 读取，可能读到旧值 "v1"
但在 t3 之后，所有节点的值都是 "v2" -> 最终一致
```

## 18.7 Node.js 应用层的高可用设计

```js
const Redis = require('ioredis');

class ProductionRedis {
  constructor(options = {}) {
    this.options = {
      sentinels: options.sentinels || [{ host: '127.0.0.1', port: 26379 }],
      name: options.name || 'mymaster',
      password: options.password || '',
      cbThreshold: options.cbThreshold || 5,
      cbResetTimeout: options.cbResetTimeout || 30000,
      fallbackEnabled: options.fallback !== false,
      maxCacheSize: options.maxCacheSize || 10000,
    };

    this._initConnection();
    this.circuitBreaker = { state: 'CLOSED', failures: 0, lastFailure: 0 };
    this.fallbackCache = new Map();
    this.stats = { totalRequests: 0, successRequests: 0, failedRequests: 0, fallbackRequests: 0 };
  }

  _initConnection() {
    this.redis = new Redis({
      sentinels: this.options.sentinels,
      name: this.options.name,
      password: this.options.password,
      connectTimeout: 5000,
      commandTimeout: 3000,
      maxRetriesPerRequest: 2,
      retryStrategy: (times) => {
        if (times > 10) return null;
        return Math.min(times * 300, 5000);
      },
      reconnectOnError: (err) => {
        return ['READONLY', 'ECONNRESET', 'ETIMEDOUT'].some(e => err.message.includes(e));
      },
    });

    this.redis.on('connect', () => {
      console.log('[Redis] 连接成功');
      this.circuitBreaker.state = 'CLOSED';
      this.circuitBreaker.failures = 0;
    });

    this.redis.on('error', (err) => {
      console.error('[Redis] 连接错误:', err.message);
    });

    this.redis.on('+switch-master', () => {
      console.log('[Redis] Master 已切换');
    });
  }

  async exec(command, ...args) {
    this.stats.totalRequests++;

    // 熔断器检查
    if (this.circuitBreaker.state === 'OPEN') {
      if (Date.now() - this.circuitBreaker.lastFailure > this.options.cbResetTimeout) {
        this.circuitBreaker.state = 'HALF_OPEN';
      } else {
        return this._fallbackExec(command, ...args);
      }
    }

    try {
      const result = await this.redis[command.toLowerCase()](...args);
      this.stats.successRequests++;
      if (this.circuitBreaker.state === 'HALF_OPEN') {
        this.circuitBreaker.state = 'CLOSED';
        this.circuitBreaker.failures = 0;
        console.log('[熔断器] 恢复，关闭');
      }
      return result;
    } catch (err) {
      this.stats.failedRequests++;
      this.circuitBreaker.failures++;
      this.circuitBreaker.lastFailure = Date.now();
      if (this.circuitBreaker.failures >= this.options.cbThreshold) {
        this.circuitBreaker.state = 'OPEN';
        console.warn('[熔断器] 打开！');
      }
      return this._fallbackExec(command, ...args);
    }
  }

  _fallbackExec(command, ...args) {
    if (!this.options.fallbackEnabled) {
      throw new Error(`Redis 不可用且降级已禁用: ${command}`);
    }
    this.stats.fallbackRequests++;

    const cmd = command.toLowerCase();
    if (cmd === 'get' && args[0]) {
      const cached = this.fallbackCache.get(args[0]);
      if (cached !== undefined) return cached;
    }
    if (cmd === 'set' && args[0] && args[1]) {
      this.fallbackCache.set(args[0], args[1]);
      if (this.fallbackCache.size > this.options.maxCacheSize) {
        const firstKey = this.fallbackCache.keys().next().value;
        this.fallbackCache.delete(firstKey);
      }
      return 'OK';
    }
    return null;
  }

  getStats() {
    return {
      ...this.stats,
      circuitBreakerState: this.circuitBreaker.state,
      successRate: this.stats.totalRequests > 0
        ? (this.stats.successRequests / this.stats.totalRequests * 100).toFixed(2) + '%'
        : 'N/A',
    };
  }

  disconnect() { this.redis.disconnect(); }
}

const redis = new ProductionRedis({
  sentinels: [
    { host: '10.0.1.10', port: 26379 },
    { host: '10.0.1.11', port: 26379 },
    { host: '10.0.1.12', port: 26379 },
  ],
  name: 'mymaster',
  password: 'redis123',
});

(async () => {
  await redis.exec('set', 'user:1', JSON.stringify({ name: '张三' }));
  const user = await redis.exec('get', 'user:1');
  console.log('用户信息:', user);
  console.log('统计信息:', redis.getStats());
  redis.disconnect();
})();
```

## 小结

高可用架构设计不是"越复杂越好"，而是"越合适越好"：

- **小型项目**：单机 + RDB，简单够用
- **中型项目**：Sentinel 模式，自动故障转移
- **大型项目**：Cluster 模式，水平扩展 + 高可用
- **超大型项目**：跨机房多活 + 应用层容灾

核心原则：

1. 先理解业务需求，再选择架构方案
2. 不要过度设计——Sentinel 能解决的问题，不要上 Cluster
3. 应用层的容灾设计是最后一道防线
4. 定期进行故障演练，验证架构的可靠性
