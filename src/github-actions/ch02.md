# 第2章：YAML 语法速查——你已经在写 .yml 了

## 引言：别怕，YAML 就是"人类可读的 JSON"

如果说 JSON 是给机器和人类之间的"翻译官"，那 YAML 就是给人类自己看的"便签纸"。

YAML（Yet Another Markup Language，又一个标记语言——没错，取名的时候就很敷衍）的设计哲学是：**让人类写起来舒服，读起来也不累。**

GitHub Actions 的配置文件使用 YAML 格式，后缀为 `.yml`（也可以用 `.yaml`，但 `.yml` 更常见，就像大家都写 `js` 而不是 `javascript` 一样）。

在你开始写 Workflow 之前，我们先花一章的时间把 YAML 的基础语法过一遍。别担心，YAML 的语法非常简单——如果你会写 JSON，那你已经会了 80% 的 YAML。

## 2.1 键值对：YAML 的基本细胞

YAML 中最基础的元素就是键值对，用冒号分隔：

```yaml
# 基本键值对
name: my-awesome-project
version: 1.0.0
isPublished: true
```

对应的 JSON 是：

```json
{
  "name": "my-awesome-project",
  "version": "1.0.0",
  "isPublished": true
}
```

**注意事项：**

- 冒号后面**必须有一个空格**。`name:value` 是错的，`name: value` 才对。这是新手最常犯的错误，没有之一。
- 字符串不需要加引号（除非包含特殊字符）。`name: hello` 和 `name: "hello"` 效果一样。
- 布尔值是 `true` / `false`（全小写），也可以用 `yes` / `no`、`on` / `off`——但**强烈建议只用 `true` / `false`**，否则你会遇到著名的 `Norway Problem`（`NO` 会被解析成布尔值 `false`，而不是字符串 "NO"，导致挪威的国家代码被吃掉）。

## 2.2 列表：用短横线表示数组

YAML 中的列表用短横线 `-` 开头，相当于 JSON 中的数组：

```yaml
# 简单列表
fruits:
  - apple
  - banana
  - cherry
```

等价于 JSON：

```json
{
  "fruits": ["apple", "banana", "cherry"]
}
```

列表也可以内联写在一行：

```yaml
fruits: [apple, banana, cherry]
```

两种写法效果完全一样。一般来说，元素少（2-3个）就用内联，元素多就换行写。

## 2.3 嵌套：YAML 的灵魂

YAML 通过**缩进**来表示层级关系，这是它和 JSON 最大的区别——JSON 用大括号 `{}`，YAML 用缩进：

```yaml
# 嵌套对象
server:
  host: localhost
  port: 3000
  database:
    name: myapp
    user: admin
    password: secret123
```

等价于 JSON：

```json
{
  "server": {
    "host": "localhost",
    "port": 3000,
    "database": {
      "name": "myapp",
      "user": "admin",
      "password": "secret123"
    }
  }
}
```

**列表 + 对象嵌套**（在 GitHub Actions 中极其常见）：

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4
      - name: Run tests
        run: npm test
```

注意这里的结构：`steps` 是一个列表，列表中的每个元素是一个对象（有 `name`、`uses`、`run` 等属性）。

## 2.4 缩进规则：2空格是你的好朋友

**YAML 的缩进规则只有一条：必须使用空格，绝对不能用 Tab。**

为什么？因为 Tab 在不同编辑器中的显示宽度不一样——在你的 VS Code 里是 4 个字符宽，在别人的 Vim 里可能是 8 个字符宽。如果用 Tab 缩进，同一个文件在不同人眼里看起来层级就不一样，那 YAML 解析器就得疯了。

**推荐缩进量：2 个空格。** 虽然 YAML 规范没有强制规定缩进量（你可以用 3 个、4 个），但 2 空格是事实上的标准，GitHub 官方的所有示例都用 2 空格。保持一致，你好我好大家好。

**VS Code 小贴士：**

在 VS Code 的右下角状态栏，点击 "Spaces" 可以设置缩进为 2 空格。你也可以安装 "YAML" 扩展（由 Red Hat 提供），它会帮你自动检查缩进错误。

## 2.5 多行字符串：`|` 和 `>`

有时候你需要写一段多行文本，比如一段脚本、一段说明文档。YAML 提供了两种方式：

**`|`（保留换行符）—— 所见即所得：**

```yaml
description: |
  这是一个多行描述。
  每一行的换行符都会被保留。

  空行也会被保留。
```

解析结果：`"这是一个多行描述。\n每一行的换行符都会被保留。\n\n空行也会被保留。\n"`

**`>`（折叠换行符）—— 把换行变成空格：**

```yaml
description: >
  这是一个多行描述。
  换行会被折叠成空格。

  但空行仍然会保留为换行。
```

解析结果：`"这是一个多行描述。 换行会被折叠成空格。\n但空行仍然会保留为换行。\n"`

**在 GitHub Actions 中，`|` 用得更多**，因为你要写的 Shell 脚本通常需要保留换行：

```yaml
steps:
  - name: Run multiple commands
    run: |
      echo "Step 1: Installing dependencies"
      npm install
      echo "Step 2: Running tests"
      npm test
      echo "Step 3: Building"
      npm run build
```

## 2.6 锚点和引用：`&` 和 `*`（高级但有用）

YAML 支持"锚点"（Anchor）和"引用"（Alias），用来避免重复写相同的内容。就像编程中的变量——定义一次，到处引用。

```yaml
# 定义锚点
defaults: &node_defaults
  node-version: '20'
  cache: 'npm'

jobs:
  test:
    strategy:
      matrix:
        include:
          - <<: *node_defaults   # 引用锚点，展开所有属性
            os: ubuntu-latest
          - <<: *node_defaults
            os: windows-latest
```

等价于：

```yaml
jobs:
  test:
    strategy:
      matrix:
        include:
          - node-version: '20'
            cache: 'npm'
            os: ubuntu-latest
          - node-version: '20'
            cache: 'npm'
            os: windows-latest
```

`&` 定义锚点，`*` 引用锚点，`<<` 是合并操作符（merge key），把锚点的所有属性展开到当前对象中。

**注意**：锚点和引用在 GitHub Actions 中可以用，但不要过度使用——如果你定义的锚点只被引用一次，那还不如直接写，可读性更好。

## 2.7 常见陷阱和调试技巧

**陷阱 1：`on` 关键字**

```yaml
# 错误写法！ 'on' 会被解析为布尔值 true
on: push

# 正确写法：加引号
'on': push
# 或者（GitHub Actions 文档的写法，其实不规范但能用）
on:
  push:
    branches: [main]
```

在 YAML 规范中，`on` 是布尔值 `true` 的同义词（和 `yes`、`true` 一样）。不过在 GitHub Actions 的 YAML 解析器中，`on` 作为顶级 key 时会被特殊处理，所以大多数时候不加引号也能工作——但为了安全，建议始终给 `on` 加引号或使用对象形式。

**陷阱 2：版本号被当成数字**

```yaml
# 错误！1.10 会被解析为浮点数 1.1，丢失末尾的 0
node-version: 1.10

# 正确：加引号，保持字符串
node-version: '1.10'
# 或者 '20' 这样的整数版本号
node-version: '20'
```

**陷阱 3：表达式中的特殊字符**

```yaml
# 错误！${{ }} 在 YAML 中可能有歧义
if: ${{ github.ref == 'refs/heads/main' }}

# 更安全：整个表达式加引号
if: "${{ github.ref == 'refs/heads/main' }}"
```

**调试技巧：**

1. **在线 YAML 校验器**：使用 [yaml-lint.com](https://www.yamllint.com/) 或 [codebeautify.org/yaml-validator](https://codebeautify.org/yaml-validator) 检查你的 YAML 语法。
2. **VS Code YAML 扩展**：安装 Red Hat 的 YAML 扩展，实时高亮语法错误。
3. **`act` 工具**：[act](https://github.com/nektos/act) 是一个在本地运行 GitHub Actions 的工具，可以快速验证 workflow 是否能正常执行，不用每次都 push 到远程。

## 小结

- YAML = 人类友好的 JSON，核心元素是键值对、列表、嵌套
- 缩进必须用空格（2空格），绝对不能用 Tab
- 多行字符串用 `|`（保留换行）或 `>`（折叠换行）
- 锚点 `&` 和引用 `*` 可以避免重复，但不要过度使用
- 版本号加引号、注意 `on` 关键字、善用在线校验工具

   ```json

       "build": "webpack"
     },
     "dependencies": ["express", "lodash", "axios"]

   ```
