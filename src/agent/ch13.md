## 为什么要学Prompt模板？

> **对应 Agent 部件**：角色与规则层——Prompt 模板定义 Agent 是谁、能做什么、不能做什么。

本章管"指令"的工程化——把散落在代码各处的 Prompt 字符串，变成可复用、可组合、可版本管理的模板。没有它会怎样？想象这些场景：你有 10 种不同的 Prompt，每种都有不同的变量；你想测试不同版本的 Prompt 哪个效果更好；你的 Prompt 需要根据用户输入动态插入不同的示例；多个开发者在同一个项目中修改 Prompt，冲突不断。这些问题的根源是：**Prompt 被当作"字符串"而不是"代码"来管理**。LangChain 的 Prompt 模板系统就是解决这个问题的——它让你像写组件化代码一样，把 Prompt 拆分为可复用、可组合、可版本管理的模块。

> [!WARNING] 先猜再读
> - 先猜一猜：Prompt 里想放 JSON 示例 `{"name": "张三"}`，直接写进模板行吗？——不行，`{...}` 会被当成变量解析，得写成<code v-pre>{{...}}</code>转义（见 13.1.3）。
> - 多数人以为 Few-shot 示例越多越好，其实 50 条全塞进 Prompt 会消耗大量 token——按问题相似度动态挑 2-3 条才是正解（见 13.3.1）。
> - 先猜一猜：`("placeholder", "{chat_history}")` 和普通变量 `{chat_history}` 是一回事吗？——不是，placeholder 能展开整条消息列表，普通变量只能接受字符串（见 13.2.2）。

## 13.1 PromptTemplate：最基础的模板

### 13.1.1 从字符串到模板

```python
# 不好的做法：手动拼接字符串
question = "Python"
prompt = f"请解释{question}是什么，用3句话。"
# 问题：变量多了就很难维护，而且容易出错

# 好的做法：使用 PromptTemplate
from langchain_core.prompts import PromptTemplate

template = PromptTemplate.from_template(
    "请解释{topic}是什么，用{n}句话。"
)

# 填充变量
prompt = template.invoke({
    "topic": "Python",
    "n": 3,
})
# prompt 是一个 StringPromptValue 对象
print(prompt.to_string())
# 输出: "请解释Python是什么，用3句话。"
```

### 13.1.2 PromptTemplate 的核心 API

上一小节已经演示了最常用的 `from_template()`，这里补齐另外两种写法和两个易混点：

```python
from langchain_core.prompts import PromptTemplate

# 方式二：完整构造 — 显式声明变量（from_template 的等价展开）
template2 = PromptTemplate(
    input_variables=["language", "feature"],  # 声明变量
    template="请用{language}写一个{feature}的示例代码。",
)

# 查看模板自动识别出的变量
template1 = PromptTemplate.from_template(
    "请用{language}写一个{feature}的示例代码。"
)
print(template1.input_variables)  # ['language', 'feature']

# 填充变量 — invoke 与 format 结果相同，返回类型不同
result1 = template1.invoke({"language": "Python", "feature": "排序"})
# 返回 PromptValue，可以直接接进第11章的管道
result2 = template1.format(language="Python", feature="排序")
# 直接返回字符串，适合打印调试
```

### 13.1.3 模板中嵌入"花括号"

有时候你的 Prompt 中需要包含 JSON 示例或代码块，里面也有花括号。这时需要用双花括号转义：

```python
from langchain_core.prompts import PromptTemplate

template = PromptTemplate.from_template(
    "请分析以下 JSON 数据：\n"
    '{{"name": "{name}", "age": {age}}}\n\n'
    "请以 JSON 格式返回分析结果：\n"
    '{{"analysis": "...", "category": "..."}}'
)

result = template.invoke({"name": "Alice", "age": 25})
print(result.to_string())
# {{ 和 }} 会被转义为单个 { 和 }
# 而 {name} 和 {age} 会被替换为实际值
```

## 13.2 ChatPromptTemplate：为对话而生

`PromptTemplate` 生成的是纯字符串，但在实际应用中，你几乎总是需要构建"消息列表"。`ChatPromptTemplate` 就是为这个场景设计的。

### 13.2.1 基本用法

```python
from langchain_core.prompts import ChatPromptTemplate

# 推荐使用 from_messages()
chat_template = ChatPromptTemplate.from_messages([
    ("system", "你是 DocMind，一个智能文档问答助手。你的回答应该{style}。"),
    ("human", "{question}"),
])

# 填充变量
messages = chat_template.invoke({
    "style": "简洁专业",
    "question": "什么是 Docker？",
})

# messages 是一个消息列表
for msg in messages.to_messages():
    print(f"[{msg.type}] {msg.content}")
# [system] 你是 DocMind，一个智能文档问答助手。你的回答应该简洁专业。
# [human] 什么是 Docker？
```

### 13.2.2 多轮对话的模板

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.messages import HumanMessage, AIMessage

# 包含对话历史的多轮模板
chat_template = ChatPromptTemplate.from_messages([
    ("system", "你是 DocMind，一个智能文档问答助手。"),
    ("placeholder", "{chat_history}"),  # 动态插入历史消息
    ("human", "{question}"),
])

# 使用
history = [
    HumanMessage(content="什么是微服务？"),
    AIMessage(content="微服务是一种将应用拆分为多个独立服务的架构风格。"),
]

messages = chat_template.invoke({
    "chat_history": history,
    "question": "它和单体架构有什么区别？",
})

for msg in messages.to_messages():
    print(f"[{msg.type}] {msg.content[:50]}...")
```

> [!NOTE] "placeholder" vs 普通变量
> `("placeholder", "{chat_history}")` 可以接受一个消息列表并将其展开到消息序列中。普通变量只能接受字符串。

### 13.2.3 带 Few-shot 示例的模板

```python
from langchain_core.prompts import ChatPromptTemplate

chat_template = ChatPromptTemplate.from_messages([
    ("system", """你是 DocMind，一个技术文档分析助手。

回答规范：
1. 先给出简短的定义
2. 然后用一个编程类比来解释
3. 最后给出一个实际应用场景

示例：
问题：什么是 API？
回答：API（应用程序编程接口）是软件组件之间交互的约定。
类比：就像餐厅的服务员——你不需要知道厨房怎么做菜，只需要通过菜单告诉服务员你想要什么。
场景：天气预报 App 通过 API 从气象服务器获取天气数据。

请用同样的格式回答用户的问题。"""),
    ("human", "{question}"),
])

messages = chat_template.invoke({"question": "什么是数据库索引？"})
```

## 13.3 FewShotPromptTemplate：动态选择最相关的示例

### 13.3.1 为什么需要"动态"示例？

在第7章中我们学过 Few-shot Prompting——给 LLM 看几个示例，让它学会回答的格式和风格。但如果你的示例库有 50 个示例，你不可能全部塞进 Prompt（会消耗太多 token）。

理想的做法是：**根据用户的问题，动态选择最相关的 2-3 个示例**。这就像搜索引擎——不是把所有结果都给你，而是给你最相关的几条。

### 13.3.2 实现动态 Few-shot

```python
from langchain_core.prompts import FewShotChatMessagePromptTemplate
from langchain_core.prompts import ChatPromptTemplate
from langchain_chroma import Chroma
from langchain_openai import OpenAIEmbeddings
from langchain_core.example_selectors import SemanticSimilarityExampleSelector

# 第一步：准备示例库
examples = [
    {"question": "什么是 REST API？",
     "answer": "REST API 是基于 HTTP 的 API 设计风格。\n"
               "类比：像邮局系统——你写好信，贴上地址，邮局帮你送到。"},
    {"question": "什么是 Docker？",
     "answer": "Docker 是容器化平台，把应用打包成独立单元。\n"
               "类比：像集装箱——不管里面装什么，外面尺寸标准。"},
    {"question": "什么是 Git？",
     "answer": "Git 是分布式版本控制系统。\n"
               "类比：像游戏存档系统——随时存档，出问题可以回档。"},
    {"question": "什么是 WebSocket？",
     "answer": "WebSocket 支持双向通信的网络协议。\n"
               "类比：HTTP 是发短信，WebSocket 是打电话。"},
    {"question": "什么是负载均衡？",
     "answer": "负载均衡是将请求分发到多台服务器的技术。\n"
               "类比：像超市多个收银台——引导员把顾客分配到排队最少的台。"},
]

# 第二步：创建示例选择器（Example Selector，基于向量相似度）
# 向量检索的完整原理在第22-23章，这里只需知道它能把"相似问题"找出来
example_selector = SemanticSimilarityExampleSelector.from_examples(
    examples,
    OpenAIEmbeddings(),
    Chroma,
    k=2,  # 选择最相关的2个示例
)

# 第三步：创建 Few-shot 模板
few_shot_prompt = FewShotChatMessagePromptTemplate(
    example_selector=example_selector,
    example_prompt=ChatPromptTemplate.from_messages([
        ("human", "{question}"),
        ("ai", "{answer}"),
    ]),
)

# 第四步：组合成完整模板
final_prompt = ChatPromptTemplate.from_messages([
    ("system", "你是 DocMind。请参考以下示例的风格来回答问题。"),
    few_shot_prompt,
    ("human", "{input}"),
])

# 使用
messages = final_prompt.invoke({"input": "什么是消息队列？"})
for msg in messages.to_messages():
    print(f"[{msg.type}] {msg.content[:80]}...")
```

### 13.3.3 不依赖向量搜索的简单方式

```python
from langchain_core.prompts import FewShotPromptTemplate, PromptTemplate

examples = [
    {"input": "Python", "output": "一种解释型、面向对象的高级编程语言"},
    {"input": "JavaScript", "output": "一种主要用于Web开发的动态脚本语言"},
]

example_template = PromptTemplate(
    input_variables=["input", "output"],
    template="概念: {input}\n定义: {output}",
)

few_shot = FewShotPromptTemplate(
    examples=examples,
    example_prompt=example_template,
    prefix="请参考以下格式来解释技术概念：\n",
    suffix="\n概念: {input}\n定义:",
    input_variables=["input"],
)

result = few_shot.invoke({"input": "Rust"})
print(result.to_string())
```

三种模板各管一个场景，选型可以记住这张表：

| 模板 | 生成什么 | 什么时候用 |
| ------ | ------ | ------ |
| PromptTemplate | 单个字符串 | 补全类场景：一句话指令、前缀拼接 |
| ChatPromptTemplate | 消息列表 | 对话场景：按角色组装 system/human |
| FewShot 系列 | 带示例的模板 | 想让模型模仿固定格式或风格时 |

## 13.4 Prompt 组合策略：像组件化开发一样拼装 Prompt

### 13.4.1 MessagesPlaceholder：动态插入消息列表

`MessagesPlaceholder` 是一个特殊的占位符，运行时可以动态插入任意数量的消息。这在处理对话历史时特别有用。

```python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.messages import HumanMessage, AIMessage

template = ChatPromptTemplate.from_messages([
    ("system", "你是 DocMind。"),
    MessagesPlaceholder(variable_name="chat_history"),  # 占位符
    ("human", "{question}"),
])

history = [
    HumanMessage(content="什么是缓存？"),
    AIMessage(content="缓存是将常用数据临时存储在高速介质中的技术。"),
    HumanMessage(content="Redis 是什么？"),
    AIMessage(content="Redis 是一个开源的内存数据结构存储。"),
]

messages = template.invoke({
    "chat_history": history,
    "question": "它和 Memcached 有什么区别？",
})

# 最终消息列表包含：
# 1. SystemMessage: "你是 DocMind。"
# 2-5. 历史消息（自动展开）
# 6. HumanMessage: "它和 Memcached 有什么区别？"
for msg in messages.to_messages():
    print(f"[{msg.type}] {msg.content[:50]}...")
```

三种"往模板里塞内容"的写法容易混淆，对照一次：

| 写法 | 能接受什么 | 典型用途 |
| ------ | ------ | ------ |
| `("human", "{question}")` | 字符串 | 单条消息填空 |
| `("placeholder", "{chat_history}")` | 消息列表（展开插入） | 对话历史占位（见 13.2.2） |
| `MessagesPlaceholder(optional=True)` | 消息列表，可为空 | 有无历史都兼容的模板 |

第三种写法多了一个 `optional=True` 参数：不传 `chat_history` 也不会报错——13.6 的实战会用到这个特性。

### 13.4.2 条件渲染：根据情况展示不同内容

LangChain 的模板不支持原生的条件逻辑，但你可以通过 Python 函数来实现：

```python
from langchain_core.prompts import ChatPromptTemplate
from typing import Optional

def build_docmind_prompt(
    question: str,
    context: Optional[str] = None,
    chat_history: Optional[list] = None,
    use_tools: bool = False,
):
    """根据场景动态构建 Prompt"""
    messages = []
    
    system_content = "你是 DocMind，一个智能文档问答助手。"
    
    if context:
        system_content += (
            "\n\n参考文档：\n{context}\n\n"
            "请基于参考文档回答问题。如果没有相关信息，请说明。"
        )
    
    if use_tools:
        system_content += (
            "\n\n你可以使用以下工具：\n"
            "- search_documents：搜索相关文档\n"
            "- calculate：执行数学计算\n"
            "- get_system_status：查询知识库规模与系统状态\n"
            "- analyze_code：分析代码片段\n"
            "- generate_summary：生成文档摘要"
        )
    
    messages.append(("system", system_content))
    if chat_history:
        messages.append(("placeholder", "{chat_history}"))
    messages.append(("human", "{question}"))
    
    template = ChatPromptTemplate.from_messages(messages)
    
    variables = {"question": question}
    if context:
        variables["context"] = context
    if chat_history:
        variables["chat_history"] = chat_history
    
    return template.invoke(variables)

# 场景1：简单问答
prompt1 = build_docmind_prompt("什么是 API？")

# 场景2：带上下文的问答
prompt2 = build_docmind_prompt(
    "这段代码有什么问题？",
    context="def process(data):\n    return data['key']",
)

# 场景3：带历史的问答
prompt3 = build_docmind_prompt(
    "能详细说说吗？",
    chat_history=[
        HumanMessage(content="什么是微服务？"),
        AIMessage(content="微服务是一种架构风格..."),
    ],
)
```

## 13.5 Prompt 版本管理和 Prompt Hub

### 13.5.1 为什么 Prompt 需要版本管理？

Prompt 是 AI 应用的"灵魂配置"——一个好的 Prompt 可以让模型表现翻倍，一个差的 Prompt 可以让模型胡言乱语。就像你对代码使用 Git 版本管理一样，Prompt 也需要版本管理：

- 记录每次修改
- 可以回滚到之前的版本
- 可以 A/B 测试不同版本

### 13.5.2 集中管理 Prompt 文件

第一步是让所有 Prompt 文案集中在一个文件里，配一个注册表（Registry）按名字取用。这一份 `DOCMIND_SYSTEM_PROMPT` 是全书唯一的人设定义：第10章的引导版到此收敛，第19章的 Agent 直接 `from config.prompts import DOCMIND_SYSTEM_PROMPT` 复用。

```python
# config/prompts.py — DocMind Prompt 集中管理

# 基础 Prompt
DOCMIND_SYSTEM_PROMPT = """你是 DocMind，一个智能文档问答助手。

你的核心能力：
1. 帮助开发者理解技术文档
2. 解答编程和架构相关的问题
```

## 13.6 实战演练：DocMind 的多级 Prompt 系统

13.5.2 把文案集中到了 `config/prompts.py`；实战中还要解决"同一份文案、不同场景怎么组装"。DocMind 的做法是：一个 `DocMindPrompts` 类，方法名即场景，内部通过 `get_prompt()` 取文案，再决定消息怎么排——文案层管"说什么"，组装层管"怎么排"：

```python
# src/agent/prompts.py — DocMind 多级 Prompt 系统（组装层）
"""DocMind Prompt 系统：只负责组装，所有 Prompt 文案来自 13.5.2 的 config/prompts.py"""

from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from config.prompts import get_prompt


class DocMindPrompts:
    """DocMind Prompt 模板集合：同一份文案，按场景包装成不同模板"""

    @staticmethod
    def basic_qa() -> ChatPromptTemplate:
        """基础问答 — 无文档上下文，可选挂对话历史"""
        return ChatPromptTemplate.from_messages([
            # system 文案复用注册表里的 system.default
            ("system", get_prompt("system.default")),
            # optional=True：不传 chat_history 也不报错，首问与追问共用同一模板
            MessagesPlaceholder(variable_name="chat_history", optional=True),
            ("human", "{question}"),
        ])

    @staticmethod
    def rag_qa() -> ChatPromptTemplate:
        """文档问答 — system 文案自带 {context} 占位（复用 rag.qa_v1）"""
        return ChatPromptTemplate.from_messages([
            ("system", get_prompt("rag.qa_v1")),
            MessagesPlaceholder(variable_name="chat_history", optional=True),
            ("human", "{question}"),
        ])

    @staticmethod
    def tool_calling() -> ChatPromptTemplate:
        """工具辅助 — 告诉模型有哪些工具可用（复用 tools.assist_v1）"""
        return ChatPromptTemplate.from_messages([
            ("system", get_prompt("tools.assist_v1")),
            MessagesPlaceholder(variable_name="chat_history", optional=True),
            ("human", "{question}"),
        ])

    @staticmethod
    def code_analysis() -> ChatPromptTemplate:
        """代码分析 — system 放通用要求，human 放本次关注点"""
        return ChatPromptTemplate.from_messages([
            ("system", get_prompt("tools.code_analysis_v1")),
            ("human", "请分析上面的代码。{specific_focus}"),
        ])

    @staticmethod
    def summary() -> ChatPromptTemplate:
        """文档摘要 — 变量由 13.5.2 的 SUMMARY_PROMPT 定义（含 {audience}，调用时需一并传入）"""
        return ChatPromptTemplate.from_messages([
            ("system", get_prompt("tools.summary_v1")),
            ("human", "请生成摘要。"),
        ])

    @staticmethod
    def select_prompt(has_context=False, has_tools=False):
        """根据场景自动选择模板 — 调用方的唯一入口"""
        if has_tools:
            return DocMindPrompts.tool_calling()
        elif has_context:
            return DocMindPrompts.rag_qa()
        else:
            return DocMindPrompts.basic_qa()


# 使用示例
if __name__ == "__main__":
    # 场景1：基础问答
    template = DocMindPrompts.select_prompt()
    messages = template.invoke({"question": "什么是微服务？"})
    print(f"基础问答模板生成了 {len(messages.to_messages())} 条消息\n")
    
    # 场景2：RAG 问答
    template = DocMindPrompts.select_prompt(has_context=True)
    messages = template.invoke({
        "context": "Docker 是一个容器化平台...",
        "question": "Docker 和虚拟机有什么区别？",
    })
    print(f"RAG 问答模板生成了 {len(messages.to_messages())} 条消息\n")
    
    # 场景3：代码分析
    template = DocMindPrompts.code_analysis()
    messages = template.invoke({
        "language": "python",
        "code": "def add(a, b): return a + b",
        "specific_focus": "请重点关注类型安全。",
    })
    for msg in messages.to_messages():
        print(f"[{msg.type}] {msg.content[:60]}...")
```

这个类的设计意图值得展开说，四个决定都不是随手写的：

- **文案与组装分离**：改 Prompt 文案只动 `config/prompts.py` 一处（13.5.2），模板结构（消息怎么排、历史挂哪）稳定不变——对应软件工程里"配置与代码分离"的老原则。
- **`optional=True` 的价值**：首问没有历史、追问有历史。加上这个参数，同一份模板全覆盖两种情况，调用方不用为"有没有历史"维护两套模板。
- **`select_prompt` 是唯一入口**：调用方只描述场景（有没有上下文、要不要工具），不直接挑模板。以后新增第四种模式，只需要改这一个函数，调用方代码零改动。
- **system 与 human 的分工**：`code_analysis` 把通用要求放 system、把本次关注点放 human——system 是"岗位说明书"，human 是"当天的任务单"，两层各改各的互不干扰。

## 本章小结

- **PromptTemplate** 是地基：`{variable}` 语法注入变量，<code v-pre>{{}}</code>转义字面花括号，`invoke` 返回 PromptValue 可直接进管道。
- **ChatPromptTemplate** 为对话而生：按角色组装消息列表，是实际项目中的默认选择。
- **Few-shot 示例要省着用**：固定列表用 `FewShotPromptTemplate`；示例库一大就改用示例选择器按相似度动态挑 2-3 条（见 13.3.2）。
- **MessagesPlaceholder** 是组合的关键：动态插入消息列表，`optional=True` 让同一份模板兼容首问与追问。
- **条件渲染靠 Python 函数**：模板本身保持简单，按场景拼接消息列表的逻辑写在函数里。
- **版本管理三件套**：集中文件、版本标记、注册表按名取用；多人协作和 A/B 测试都从这里起步。
- **文案与组装分离**是本章的设计核心：`config/prompts.py` 管"说什么"，`DocMindPrompts` 管"怎么排"——Prompt 从此当代码管。
