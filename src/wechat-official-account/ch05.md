# 第五章：内容选题——永远不缺灵感

## 核心观点

**选题不是等灵感，是建系统。**

## 5.1 选题的四个来源

| 来源 | 方法 | 频率 |
| --- | --- | --- |
| 用户痛点 | 留言区、社群、投稿 | 每周 |
| 热点事件 | 行业新闻、技术更新 | 适时 |
| 系统知识 | 你的专业领域框架 | 每月规划 |
| 竞品缺口 | 竞品没写 / 写得不好的 | 每月 |

## 5.2 选题库建设

**工具：** 用 Notion / 飞书 / Excel 建选题库，包含：

| 字段 | 说明 |
| --- | --- |
| 标题 | 暂定标题 |
| 来源 | 用户投稿 / 热点 / 系统知识 |
| 优先级 | P0 / P1 / P2 |
| 状态 | 待写 / 写作中 / 已完成 |
| 备注 | 参考资料、切入角度 |

**目标：** 保持选题库始终有 10+ 个备选，避免"本周不知道写什么"。

## 5.3 示例：英语404 的选题库（节选）

| 标题 | 来源 | 优先级 | 状态 |
| --- | --- | --- | --- |
| "Cannot read properties of undefined" 到底在说什么 | 用户留言 | P0 | 待写 |
| "is not a function" 为什么总在链式调用时出现 | 系统知识 | P0 | 写作中 |
| 从 "Unexpected token <" 看 HTML 被当成 JS 加载 | 竞品缺口 | P1 | 待写 |
| "Unhandled rejection" 的正确读法 | 系统知识 | P1 | 待写 |
| 英文文档里的 "deprecated" 不等于"坏了" | 用户痛点 | P2 | 已完成 |
| CORS 报错三连：谁在拦你，怎么放行 | 用户留言 | P0 | 待写 |
| 401 和 403 的英文措辞差别 | 系统知识 | P2 | 待写 |
| 构建报错 "Module not found" 的 5 种原因 | 竞品缺口 | P1 | 待写 |
| 报错信息里的 "unexpected" 家族 | 系统知识 | P1 | 待写 |
| devDependencies 和 dependencies，报错时先看哪一个 | 用户投稿 | P2 | 待写 |

一张表就能看出：P0 永远有货，系列感（"报错家族"）也有了。

## 5.4 选题检验清单

每个选题问自己：

- [ ] 我的目标读者会关心吗？
- [ ] 我能写出差异化吗？
- [ ] 这个选题能系列化吗？（至少 3 期）
- [ ] 标题能在 3 秒内让人想点开吗？

## 检查清单

- [ ] 选题库建立，有 10+ 个备选
- [ ] 确定 4 个选题来源
- [ ] 每月做一次选题规划
- [ ] 每个选题都通过 5.4 的四问
