# 第11章：多语言开发环境配置

> "Any fool can write code that a computer can understand. Good programmers write code that humans can understand." —— Martin Fowler

VSCode 的野心从来不是做一个"好的 JavaScript 编辑器"或者"好的 Python 编辑器"。它的目标是成为**万能 IDE**——同一个编辑器，通过扩展系统，可以在 Python、Java、Go、Rust、C++、TypeScript 之间无缝切换，而且每个语言都有接近原生 IDE 的开发体验。

这个野心的技术基础是 **Language Server Protocol（LSP）**——一个由微软提出的协议，让编辑器和语言工具之间实现"即插即用"的连接。在这一章中，我们将配置 VSCode 成为你的"多语言开发基地"。

## 11.1 LSP：万能 IDE 的秘密武器

在 LSP 出现之前，每个编辑器都要为每种语言单独实现代码补全、跳转定义、错误检查等功能。这意味着 N 个编辑器 × M 种语言 = N×M 个实现——一个巨大的重复劳动。

LSP 将这个问题变成了 N+M：每种语言只需要实现一个 Language Server，每个编辑器只需要实现一个 LSP Client。

```
┌─────────┐        ┌───────────────────┐
│ VSCode   │ ─────> │ Python LS (pyright)│
│ (LSP     │ ─────> │ TypeScript LS      │
│  Client) │ ─────> │ Go LS (gopls)      │
│          │ ─────> │ Rust LS (rust-analyzer)│
└─────────┘        └───────────────────┘
```

这就是为什么 VSCode 能在如此多语言上提供一致的、高质量的智能提示——因为底层都是同一套协议。

## 11.2 Python 开发环境

## 必备扩展

```
ms-python.python          # 官方 Python 扩展（含 Pylance）
ms-python.vscode-pylance  # 更快的类型检查和补全
ms-python.debugpy          # Python 调试器
ms-toolsai.jupyter         # Jupyter Notebook 支持
ms-python.black-formatter  # Black 格式化器
```

## 工作区设置

```json
// .vscode/settings.json
{
    // Python 解释器路径（虚拟环境）
    "python.defaultInterpreterPath": "${workspaceFolder}/.venv/bin/python",

    // 代码分析：使用 Pylance（最快最准）
    "python.analysis.typeCheckingMode": "basic",
    "python.analysis.autoImportCompletions": true,
    "python.analysis.diagnosticMode": "workspace",

    // 格式化：使用 Black
    "python.formatting.provider": "black",
    "[python]": {
        "editor.defaultFormatter": "ms-python.black-formatter",
        "editor.formatOnSave": true,
        "editor.codeActionsOnSave": {
            "source.organizeImports": "explicit"
        }
    },

    // Lint：使用 Ruff（极快的 Python linter）
    "python.linting.enabled": false,
    "[python]": {
        "editor.codeActionsOnSave": {
            "source.fixAll.ruff": "explicit"
        }
    },

    // Jupyter Notebook 设置
    "jupyter.askForKernelRestart": false,
    "notebook.formatOnSave.enabled": true
}
```

## 虚拟环境管理

```bash
# 创建虚拟环境
python -m venv .venv

# 激活（VSCode 终端通常自动激活）
source .venv/bin/activate   # macOS/Linux
.venv\Scripts\activate      # Windows

# VSCode 自动检测虚拟环境
# 按 Ctrl+Shift+P → Python: Select Interpreter → 选择 .venv
```

VSCode 的 Python 扩展会自动检测项目中的 `.venv`、`venv`、`env` 等目录，并在终端启动时自动激活它们。你也可以通过 `python.terminal.activateEnvironment` 控制此行为。

## Jupyter Notebook 集成

VSCode 的 Jupyter 集成已经非常成熟：

- 直接在编辑器中打开 `.ipynb` 文件
- 支持交互式单元格执行（`Shift+Enter`）

## tsconfig.json 集成

VSCode 会自动读取 `tsconfig.json`，但以下设置可以让集成更紧密：

```json
// tsconfig.json
{
    "compilerOptions": {
        "target": "ES2022",
        "module": "Node16",
        "moduleResolution": "Node16",
        "strict": true,
        "noUncheckedIndexedAccess": true,
        "exactOptionalPropertyTypes": true,
        "paths": {
            "@/*": ["./src/*"],
            "@/utils/*": ["./src/utils/*"]
        },
        "baseUrl": "."
    },
    "include": ["src/**/*"],
    "exclude": ["node_modules", "dist", "**/*.test.ts"]
}
```

`paths` 配置不仅在编译时生效，VSCode 的 IntelliSense 也会尊重它——你可以用 `@/utils/logger` 来导入，自动补全和跳转定义都正常工作。

## 11.8 实战：一台 VSCode 搞定五种语言

假设你是一个全栈开发者，你的项目涉及以下语言：

| 层 | 语言 | 用途 |
| ---- | ------ | ------ |
| 前端 | TypeScript/React | Web UI |
| 后端 API | Go | 微服务 |
| 数据分析 | Python | 数据处理和机器学习 |
| 系统组件 | Rust | 高性能计算模块 |
| 移动端 | Java/Kotlin | Android 应用 |

每个项目有自己的 `.vscode/settings.json`，VSCode 会在打开不同工作区时自动加载对应的配置。你的核心工作流是：

1. 打开 `frontend/` 工作区 → TypeScript + ESLint + Prettier 就绪
2. 打开 `api-service/` 工作区 → Go + gopls + Delve 就绪
3. 打开 `data-pipeline/` 工作区 → Python + Jupyter + Black 就绪
4. 打开 `compute-engine/` 工作区 → Rust + rust-analyzer + CodeLLDB 就绪
5. 打开 `mobile-app/` 工作区 → Java + Spring Boot + Maven 就绪

每个工作区的 `.vscode/` 目录包含该语言所需的完整配置，打开即开发，无需任何额外配置。

## 11.9 进阶：Profiles 为不同语言创建不同配置集

VSCode Profiles（配置文件）是解决"多语言环境配置冲突"的终极方案。不同语言可能需要不同的扩展组合——你不希望在写 Rust 时加载 Python 的所有扩展，反过来也一样。

## 创建 Profile

1. `Ctrl+Shift+P`（⌘+Shift+P）→ **Profiles: Create Profile**
2. 选择 **Empty Profile** 或基于当前配置创建
3. 命名：如 "Python Dev"、"Go Dev"、"Rust Dev"

## 为每个 Profile 安装不同的扩展

**Python Profile：**

- Python, Pylance, Jupyter, Black Formatter, Ruff

**Go Profile：**

- Go, Go Debug

**Rust Profile：**

- rust-analyzer, CodeLLDB, Even Better TOML

**Java Profile：**

- Extension Pack for Java, Spring Boot Extension Pack

## 工作区自动切换 Profile

你可以在 `.vscode/settings.json` 中指定工作区推荐的 Profile：

```json
{
    // 当打开此工作区时，VSCode 会提示切换到 "Python Dev" Profile
    "configurationProfiles.default": "Python Dev"
}
```

或者在打开工作区时，手动切换：

- 点击左下角的齿轮图标 → **Profiles** → 选择对应的 Profile
- 或使用命令面板 **Profiles: Switch Profile**

## Profile 的导出和分享

```bash
# 导出 Profile 为文件
# Ctrl+Shift+P → Profiles: Export Profile

# 导入 Profile
# Ctrl+Shift+P → Profiles: Import Profile
```

这意味着你可以为团队创建标准化的开发环境 Profile——新人只需导入 Profile，即可获得与资深开发者完全一致的编辑器配置。

📋 **本章小结**

- VSCode 通过 **LSP（Language Server Protocol）** 实现多语言统一支持
- **Python** 开发需要 Python + Pylance + Jupyter + Black 扩展组合
- **TypeScript** 开发通过 ESLint + Prettier + tsconfig 实现完整的代码质量链
- **Java** 通过 Extension Pack for Java 获得接近 IntelliJ 的体验
- **Go** 的官方扩展集成了 gopls、Delve、golangci-lint 等全套工具
- **Rust** 通过 rust-analyzer 获得极佳的代码分析和补全体验
- **C/C++** 通过 CMake Tools 实现从配置到构建到调试的完整工作流
- **Profiles** 让你为不同语言维护独立的扩展和设置集合，按需切换
