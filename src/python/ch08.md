想象你搬进了一间新公寓。第一天，所有东西都堆在客厅地上——衣服、锅碗、书、充电器……找一双袜子都要翻半天。过了几天你受不了了，买了衣柜、书架、收纳盒，把东西分门别类放好。从此找任何东西都快了很多。

写代码也是一样。当你只有几十行代码时，一个 `.py` 文件就够了。但当代码量增长到几百行、几千行，全塞在一个文件里就变成了一场灾难。Python 给你的"衣柜和收纳盒"就是**模块**和**包**——模块是单个 `.py` 文件，包是装有多个模块的文件夹。这一章，我们来学会怎么把自己的代码收拾得井井有条，以及怎么用别人已经写好的"工具箱"。

## 8.1 什么是模块

模块（module）就是一个普通的 Python 文件，后缀是 `.py`，里面可以放变量、函数、类。它的核心作用是**把相关的代码组织在一起，方便复用**。

比如你写了一个计算各种几何图形面积的工具文件：

```python
# geometry.py —— 这就是一个模块

def circle_area(radius):
    """计算圆的面积"""
    import math
    return math.pi * radius ** 2

def rectangle_area(width, height):
    """计算矩形的面积"""
    return width * height

def triangle_area(base, height):
    """计算三角形的面积"""
    return 0.5 * base * height
```

在其他文件中，你就可以导入（import）这个模块来使用它。这就像你从工具箱里拿出一把扳手来用，而不是自己从头造一把。

## 8.2 import 的几种姿势

Python 提供了好几种导入方式，每种适用于不同场景。

### 8.2.1 直接 import 整个模块

```python
import geometry

print(geometry.circle_area(5))    # 78.53981633974483
print(geometry.rectangle_area(3, 4))  # 12
```

用 `import geometry` 导入后，使用时必须带模块名前缀 `geometry.xxx`。这就像你买了整套工具箱，用的时候要说"从工具箱里拿扳手"。

### 8.2.2 from ... import 导入指定内容

```python
from geometry import circle_area, rectangle_area

print(circle_area(5))     # 不需要加前缀了
print(rectangle_area(3, 4))
```

如果你只需要模块中的一两个函数，可以用 `from ... import ...` 把它们直接"拿出来"。但注意，如果当前文件也有一个叫 `circle_area` 的函数，名字就会冲突。

### 8.2.3 import ... as 起别名

```python
import geometry as geo

print(geo.circle_area(5))
```

当模块名太长或和已有变量名冲突时，起个别名就很方便。你以后会经常看到 `import numpy as np`、`import pandas as pd` 这样的写法，这是 Python 社区的惯例。

### 8.2.4 from ... import * （慎用！）

```python
from geometry import *

print(circle_area(5))
print(rectangle_area(3, 4))
print(triangle_area(6, 3))
```

星号导入会把模块里所有公开的名字全倒进来。看起来很省事，但这是**非常危险**的做法——你根本不知道会覆盖哪些已有变量，代码可读性也大打折扣。除非你非常清楚模块里有什么，否则别用。

## 8.3 Python 怎样找到模块：sys.path

当你写 `import geometry` 时，Python 到底去哪里找这个文件？答案是按照 `sys.path` 里的目录列表逐个搜索。

```python
import sys
for p in sys.path:
    print(p)
```

你会看到类似这样的输出：

```
（当前脚本所在目录）
（Python 标准库目录）
（第三方包安装目录 site-packages）
...
```

搜索顺序是：

1. **当前脚本所在目录**（或当前工作目录）
2. **PYTHONPATH 环境变量**中的路径（如果你设置过的话）
3. **Python 标准库目录**（内置模块住的地方）
4. **site-packages 目录**（pip 安装的第三方包住的地方）

如果你自己写的模块放在别的目录，可以临时添加搜索路径：

```python
import sys
sys.path.append(r"D:\my_modules")
import my_custom_module  # 现在能找到这个模块了
```

但这种方式只是临时生效，程序退出后就失效了。更规范的做法是把模块安装到 site-packages，或者使用虚拟环境（后面会讲）。

## 8.4 `__name__` 与 `__main__`

你经常会看到这样的代码：

```python
if __name__ == "__main__":
    # 只有直接运行这个文件时才会执行下面的代码
    print("这个文件是被直接运行的")
```

这是什么意思？每个 Python 模块都有一个内置变量 `__name__`：

- 当你**直接运行**某个 `.py` 文件时，它的 `__name__` 被自动设为 `"__main__"`
- 当你**导入**某个模块时，它的 `__name__` 就是模块名（文件名去掉 `.py`）

来看一个例子。假设有两个文件：

```python
# helper.py
def greet(name):
    return f"你好，{name}！"

# 测试代码
print(greet("世界"))

if __name__ == "__main__":
    print("helper.py 被直接运行了")
```

```python
# main.py
from helper import greet

print(greet("小明"))
```

直接运行 `helper.py`，你会看到两行输出：`你好，世界！` 和 `helper.py 被直接运行了`。

但如果运行 `main.py`，你只会看到 `你好，小明！`——等等，不对。`helper.py` 里那行裸的 `print(greet("世界"))` 会在导入时也执行。这就是为什么我们通常把测试代码放在 `if __name__ == "__main__":` 下面——这样只有直接运行该文件时才会执行测试，被导入时不会执行。

正确写法：

```python
# helper.py（修正版）
def greet(name):
    return f"你好，{name}！"

if __name__ == "__main__":
    # 只在直接运行时测试
    print(greet("世界"))
    print("helper.py 被直接运行了")
```

现在导入 `helper` 时不会再有多余输出了。

## 8.5 自定义模块

创建一个模块非常简单——你写过的每一个 `.py` 文件都是模块。但一个好模块应该注意以下几点：

1. **文件头加文档字符串**（docstring），说明这个模块是干什么的
2. **命名要有意义**，全小写，可以用下划线（如 `data_utils.py`）
3. **不要在里面放太多无关的东西**

```python
"""
text_utils.py
文本处理工具模块，提供常用的字符串操作函数。
"""

def count_words(text):
    """统计英文单词数量"""
    return len(text.split())

def truncate(text, max_length=50, suffix="..."):
    """截断超长文本并添加后缀"""
    if len(text) <= max_length:
        return text
    return text[:max_length - len(suffix)] + suffix

def is_palindrome(text):
    """判断字符串是否是回文（忽略大小写和空格）"""
    cleaned = text.replace(" ", "").lower()
    return cleaned == cleaned[::-1]
```

在其他文件中使用：

```python
import text_utils

print(text_utils.count_words("Hello World Python"))  # 3
print(text_utils.truncate("这是一段非常非常长的文本内容", 10))  # 这是一段非常非常长的...
print(text_utils.is_palindrome("racecar"))  # True
```

## 8.6 包：用文件夹组织模块

当你的模块越来越多（比如十几个 `.py` 文件），光放在一个目录下就显得乱了。**包（package）就是一个包含 `__init__.py` 文件的文件夹**，它把相关模块组织在一起。

假设你在做一个数据分析项目，可以这样组织：

```
my_project/
├── main.py
└── utils/
    ├── __init__.py
    ├── text_utils.py
    ├── math_utils.py
    └── file_utils.py
```

`__init__.py` 是什么？它是包的"初始化文件"，当包被导入时会自动执行。它可以是空文件（只起标记作用），也可以在里面写导入语句来简化使用。

### 8.6.1 空的 `__init__.py`

最简单的情况，`__init__.py` 什么都不写：

```python
# utils/__init__.py
# 空文件，只标记这是一个包
```

使用时需要完整路径：

```python
from utils.text_utils import count_words
from utils.math_utils import circle_area
```

### 8.6.2 在 `__init__.py` 中简化导入

你可以在 `__init__.py` 里把常用功能"提上来"：

```python
# utils/__init__.py
from .text_utils import count_words, truncate
from .math_utils import circle_area, rectangle_area
```

这样使用时就更简洁了：

```python
from utils import count_words, circle_area

print(count_words("Hello World"))  # 2
print(circle_area(5))              # 78.53981633974483
```

注意那个小点 `.`——它代表"当前包"，这叫**相对导入**（relative import）。相对导入只能在包内部使用，不能在直接运行的脚本中使用。

### 8.6.3 嵌套包

包里面还可以有子包：

```
my_project/
├── main.py
└── data_toolkit/
    ├── __init__.py
    ├── text/
    │   ├── __init__.py
    │   └── cleaner.py
    └── numeric/
        ├── __init__.py
        └── stats.py
```

导入时像访问文件路径一样：

```python
from data_toolkit.text.cleaner import remove_html_tags
from data_toolkit.numeric.stats import mean, median
```

## 8.7 标准库：Python 自带的百宝箱

Python 之所以被称为"自带电池"（batteries included）的语言，是因为它安装好之后就自带了大量实用模块，这就是**标准库**。你不需要额外安装任何东西就能用它们。

几个常用的标准库模块：

```python
# os —— 操作系统交互
import os
print(os.getcwd())           # 当前工作目录
print(os.listdir("."))       # 列出当前目录的文件

# sys —— 系统相关
import sys
print(sys.version)           # Python 版本号
print(sys.platform)          # 操作系统平台

# math —— 数学函数
import math
print(math.sqrt(16))         # 4.0
print(math.ceil(3.2))        # 4（向上取整）
print(math.floor(3.8))       # 3（向下取整）

# random —— 随机数
import random
print(random.randint(1, 100))    # 1 到 100 之间的随机整数
print(random.choice(["红", "绿", "蓝"]))  # 随机选一个

# datetime —— 日期时间
from datetime import datetime, timedelta
now = datetime.now()
print(now.strftime("%Y-%m-%d %H:%M:%S"))  # 格式化当前时间
tomorrow = now + timedelta(days=1)
print(f"明天是 {tomorrow.date()}")

# json —— JSON 数据处理
import json
data = {"name": "小明", "age": 25, "hobbies": ["编程", "读书"]}
json_str = json.dumps(data, ensure_ascii=False, indent=2)
print(json_str)
parsed = json.loads(json_str)
print(parsed["name"])  # 小明

# collections —— 高级数据结构
from collections import Counter, defaultdict
words = ["apple", "banana", "apple", "cherry", "banana", "apple"]
counter = Counter(words)
print(counter)          # Counter({'apple': 3, 'banana': 2, 'cherry': 1})
print(counter.most_common(2))  # [('apple', 3), ('banana', 2)]
```

这只是冰山一角。Python 标准库有几百个模块，涵盖了文件操作、网络请求、多线程、加密、数据库、邮件发送等方方面面。遇到问题时，先想想"标准库有没有现成的"，往往能省下大量时间。

## 8.8 pip 与第三方包

标准库虽然丰富，但不可能包罗万象。当你需要更强大的功能时，就需要**第三方包**——这些是全世界开发者写好后发布到 PyPI（Python Package Index）上的模块。

### 8.8.1 安装第三方包

`pip` 是 Python 的包管理工具，安装 Python 时通常自带。

```python
# 在终端/命令行中运行（不是在 Python 交互器里）
# pip install requests
```

安装好之后就能在代码中使用了：

```python
import requests

response = requests.get("https://httpbin.org/get")
print(response.status_code)  # 200
print(response.json())       # 解析返回的 JSON 数据
```

常用 pip 命令：

```bash
# 安装包
pip install requests

# 安装指定版本
pip install requests==2.31.0

# 升级包
pip install --upgrade requests

# 卸载包
pip uninstall requests

# 查看已安装的包
pip list

# 搜索包（在 PyPI 网站上搜索更方便）
pip search keyword  # 注意：此命令已被禁用，直接去 pypi.org 搜索
```

### 8.8.2 requirements.txt

当你把项目分享给别人时，对方怎么知道要安装哪些第三方包？答案是 `requirements.txt` 文件——它列出项目依赖的所有包及其版本号。

```
# requirements.txt
requests>=2.28.0
numpy>=1.24.0
pandas>=2.0.0
matplotlib>=3.7.0
```

一行一个包，可以指定版本范围。常用版本标记：

- `==`：精确版本，`requests==2.31.0`
- `>=`：最低版本，`requests>=2.28.0`
- `<=`：最高版本
- `~=`：兼容版本，`~=2.28` 等价于 `>=2.28, <2.29`

用一条命令就能批量安装：

```bash
pip install -r requirements.txt
```

生成当前环境的依赖列表：

```bash
pip freeze > requirements.txt
```

`pip freeze` 会输出当前环境中所有已安装包及其精确版本号。但注意，它会把所有包都列出来，包括间接依赖。有时候你只需要列出"顶层依赖"就够了。

## 8.9 虚拟环境：给每个项目一个独立空间

假设项目 A 需要 `requests 2.28`，项目 B 需要 `requests 2.31`。两个版本装在全局环境中就会冲突。**虚拟环境**（virtual environment）解决了这个问题——它为每个项目创建一个隔离的 Python 环境，包的安装互不干扰。

### 8.9.1 使用 venv 创建虚拟环境

`venv` 是 Python 自带的虚拟环境工具，不需要额外安装：

```bash
# 在项目目录下创建虚拟环境，文件夹名叫 .venv
python -m venv .venv
```

这会在当前目录下创建一个 `.venv` 文件夹，里面有一份独立的 Python 解释器和包目录。

### 8.9.2 激活与使用

```bash
# Windows
.venv\Scripts\activate

# macOS / Linux
source .venv/bin/activate
```

激活后，终端提示符前面会出现 `(.venv)`，表示你当前在虚拟环境中。此后 `pip install` 安装的包只会装到这个虚拟环境里。

```bash
# 在虚拟环境中安装包
pip install requests

# 查看已安装的包（只有虚拟环境中的）
pip list

# 退出虚拟环境
deactivate
```

### 8.9.3 最佳实践

- **每个项目一个虚拟环境**，放在项目根目录下，命名为 `.venv` 或 `venv`
- **把虚拟环境目录加入 `.gitignore`**——千万不要把虚拟环境提交到 Git
- **配合 `requirements.txt` 使用**：创建虚拟环境 → 激活 → `pip install -r requirements.txt`
- 如果使用 Python 3.11+，也可以考虑 `pipenv` 或 `poetry` 等更高级的依赖管理工具

## 8.10 模块的搜索与加载细节（了解即可）

当你 `import` 一个模块时，Python 内部做了这些事：

1. 先在 `sys.modules` 字典中查找——如果模块已经被导入过，就直接复用，不会重复加载
2. 如果没找到，按 `sys.path` 的顺序搜索文件
3. 找到后执行模块中的代码（顶层代码），并将模块对象缓存到 `sys.modules`

```python
import sys

# 第一次导入：执行模块代码
import json

# 第二次导入：直接从缓存取，不会重新执行
import json

# 查看所有已加载的模块
print(len(sys.modules))  # 几百个模块
print("json" in sys.modules)  # True
```

这也是为什么模块顶层的代码只执行一次。如果你在模块顶层写了 `print("hello")`，它只会在第一次导入时打印。

## 8.11 小结

- **模块**就是一个 `.py` 文件，里面放着函数、类和变量，是代码复用的基本单位
- **包**是一个含有 `__init__.py` 的文件夹，用于组织多个相关模块
- `import` 有四种写法：`import`、`from ... import`、`import ... as`、`from ... import *`（最后一种慎用）
- `sys.path` 决定了 Python 去哪里找模块，搜索顺序：当前目录 → PYTHONPATH → 标准库 → site-packages
- `__name__ == "__main__"` 用于区分"文件被直接运行"和"文件被导入"
- `pip` 用于安装第三方包，`requirements.txt` 用于记录项目依赖
- **虚拟环境**为每个项目创建隔离的包环境，是 Python 开发的标准做法

## 8.13 参考答案

**第 1 题：**

```python
# temperature.py
"""温度转换工具模块"""

def celsius_to_fahrenheit(c):
    """摄氏度转华氏度"""
    return c * 9 / 5 + 32

def fahrenheit_to_celsius(f):
    """华氏度转摄氏度"""
    return (f - 32) * 5 / 9

def celsius_to_kelvin(c):
    """摄氏度转开尔文"""
    return c + 273.15

if __name__ == "__main__":
    print(f"100°C = {celsius_to_fahrenheit(100)}°F")  # 212.0
    print(f"32°F = {fahrenheit_to_celsius(32)}°C")     # 0.0
    print(f"0°C = {celsius_to_kelvin(0)}K")            # 273.15
```

```python
# use_temperature.py
from temperature import celsius_to_fahrenheit, celsius_to_kelvin

print(f"37°C = {celsius_to_fahrenheit(37):.1f}°F")  # 98.6
print(f"37°C = {celsius_to_kelvin(37):.2f}K")        # 310.15
```

**第 2 题：**

```python
# string_tools.py
"""字符串工具模块"""

def reverse_string(s):
    """反转字符串"""
    return s[::-1]

def is_anagram(s1, s2):
    """判断两个字符串是否是变位词（忽略大小写和空格）"""
    clean1 = sorted(s1.replace(" ", "").lower())
    clean2 = sorted(s2.replace(" ", "").lower())
    return clean1 == clean2

if __name__ == "__main__":
    print(reverse_string("Hello"))          # olleH
    print(is_anagram("listen", "silent"))   # True
    print(is_anagram("hello", "world"))     # False
```

直接运行 `python string_tools.py` 会输出三行测试结果。从其他文件导入时，`if __name__ == "__main__":` 下的代码不会执行。

```python
# my_math/advanced.py
def power(base, exponent):
    """幂运算"""
    return base ** exponent

def square_root(n):
    """开平方"""
    if n < 0:
        raise ValueError("不能对负数开方")
    return n ** 0.5
```

## 8.14 常见错误与避坑

**1. 循环导入（Circular Import）**

模块 A 导入模块 B，模块 B 又导入模块 A，形成死循环：

```python
# a.py
from b import y
x = 1
```

```python
# b.py
from a import x
y = 2
```

运行时会报 `ImportError`。**解决方法**：重新设计模块结构，把共同依赖提取到第三个模块中，或者把导入语句放在函数内部（延迟导入）。

**2. 在直接运行的脚本中使用相对导入**

```python
# 如果直接运行包内的某个文件，相对导入会报错
# utils/text_utils.py
from . import math_utils  # 直接运行 text_utils.py 时会报错

# 正确做法：从包外部运行，或者用绝对导入
```

**3. 忘记激活虚拟环境就安装包**

如果不激活虚拟环境就 `pip install`，包会装到全局 Python 里。养成习惯：打开终端第一件事就是激活虚拟环境。

**4. `from module import *` 导致命名污染**

```python
from math import *
from random import *

# 如果两个模块有同名函数，后面的会覆盖前面的
# 而且你根本不知道当前命名空间里到底有什么
```

**5. 模块顶层的副作用代码**

```python
# bad_module.py
print("连接数据库...")   # 顶层代码，每次导入都会执行
db = connect_to_database()  # 导入时就连接数据库，浪费资源

# good_module.py
def get_db():
    """需要时才连接"""
    return connect_to_database()
```

把"做事"的代码放在函数里，而不是放在模块顶层。模块顶层应该只放定义（函数定义、类定义、常量）。

**6. 忘记把 `.venv` 加入 `.gitignore`**

虚拟环境目录动辄几百 MB，提交到 Git 会让仓库爆炸。项目创建的第一件事就应该是写好 `.gitignore`：

```
# .gitignore
.venv/
__pycache__/
*.pyc
```
