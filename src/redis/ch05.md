# 第5章：事务与管道——批量操作的艺术

## 引言：一个人的战斗 vs 团队作战

到目前为止，我们写的 Redis 命令都是"一个接一个"执行的——发一个命令，等一个结果，再发下一个。这就像一个人搬砖：搬一块，走一趟，再搬一块。

但如果你需要一次性搬 100 块砖呢？

本章介绍三种"团队作战"方式：

- **事务（Transaction）**：把多个命令打包，一起执行
- **管道（Pipeline）**：把多个命令打包发送，减少网络往返
- **Lua 脚本**：在服务端执行一段脚本，原子性 + 高性能

## 5.1 Redis 事务（MULTI/EXEC/DISCARD）

Redis 的事务和 SQL 的事务……名字一样，但行为大不相同。这是很多初学者的第一个坑。

### 事务的执行流程

```
MULTI         → 开启事务（进入"事务模式"）
SET a 1       → 命令入队（不执行！）
SET b 2       → 命令入队
INCR a        → 命令入队
EXEC          → 一次性执行队列中的所有命令
```

**关键区别**：SQL 事务是真正的原子操作——要么全部成功，要么全部回滚。Redis 事务**不支持回滚**！如果中间某个命令出错，其他命令仍然会执行。

```
SQL 事务：  [命令A成功] [命令B失败] → 全部回滚，就像什么都没发生
Redis 事务：[命令A成功] [命令B失败] → A的结果保留，B的失败不撤回
```

> [!WARNING] 注意
> 这就是为什么很多人说"Redis 的事务不是真正的事务"。它保证了命令的"批量执行"，但不保证"全部成功或全部失败"。把它理解为"批量执行器"更准确。

### 在 Node.js 中使用事务

```js
const Redis = require('ioredis');
const redis = new Redis();

async function transactionDemo() {
  // ========== 基本事务 ==========
  const multi = redis.multi();  // 开启事务

  multi.set('tx:name', 'Alice');
  multi.set('tx:age', '25');
  multi.incr('tx:age');        // 26
  multi.get('tx:name');
  multi.get('tx:age');

  // EXEC：执行所有排队的命令
  const results = await multi.exec();
  console.log('事务结果：');
  results.forEach(([err, result], index) => {
    if (err) {
      console.log(`  命令${index + 1}：错误 - ${err.message}`);
    } else {
      console.log(`  命令${index + 1}：${result}`);
    }
  });
  // 命令1：OK
  // 命令2：OK
  // 命令3：26
  // 命令4：Alice
  // 命令5：26

  // ========== DISCARD：取消事务 ==========
  const multi2 = redis.multi();
  multi2.set('tx:cancel', 'this-will-be-discarded');
  await multi2.discard(); // 取消！命令不会执行
  const val = await redis.get('tx:cancel');
  console.log('\n取消事务后：', val); // null

  // 清理
  await redis.del('tx:name', 'tx:age');
  await redis.quit();
}

transactionDemo();
```

## 5.2 WATCH/UNWATCH：乐观锁

`WATCH` 是 Redis 事务的"安全网"——它实现了一种**乐观锁**机制。

工作原理：

1. `WATCH` 一个或多个 Key
2. 读取这些 Key 的值
3. 根据值做一些计算
4. `MULTI` 开启事务
5. 将修改命令入队
6. `EXEC` 执行——如果 WATCH 的 Key 在步骤 1 和 6 之间被别人修改过，EXEC 会**返回 null**（事务失败）

```js
const Redis = require('ioredis');
const redis = new Redis();

async function watchDemo() {
  // 初始化余额
  await redis.set('account:alice', '1000');
  await redis.set('account:bob', '500');

  // ========== 场景：Alice 向 Bob 转账 200 ==========
  async function transfer(from, to, amount) {
    // 最多重试3次
    for (let attempt = 1; attempt <= 3; attempt++) {
      try {
        // 1. WATCH 源账户（监控余额变化）
        await redis.watch(`account:${from}`);

        // 2. 读取当前余额
        const balance = parseInt(await redis.get(`account:${from}`));
        console.log(`  [尝试${attempt}] ${from} 余额：${balance}`);

        // 3. 检查余额是否充足
        if (balance < amount) {
          await redis.unwatch();
          console.log('  余额不足，取消转账');
          return false;
        }

        // 4. 开启事务
        const multi = redis.multi();
        multi.decrby(`account:${from}`, amount);
        multi.incrby(`account:${to}`, amount);

        // 5. 执行事务
        const results = await multi.exec();

        // EXEC 返回 null 说明 WATCH 的 Key 被修改了
        if (results === null) {
          console.log(`  [尝试${attempt}] 冲突！余额被其他操作修改，重试...`);
          continue; // 重试
        }

        console.log(`  转账成功！${from} → ${to}：${amount}`);
        return true;
      } catch (err) {
        console.error('  转账出错：', err.message);
        await redis.unwatch();
        return false;
      }
    }

    console.log('  重试次数用尽，转账失败');
    return false;
  }

  console.log('=== 正常转账 ===');
  await transfer('alice', 'bob', 200);
  console.log('Alice 余额：', await redis.get('account:alice')); // 800
  console.log('Bob 余额：', await redis.get('account:bob'));     // 700

  // 清理
  await redis.del('account:alice', 'account:bob');
  await redis.quit();
}

watchDemo();
```

## 5.3 Pipeline（管道）：批量发送命令

Pipeline 是性能优化的大杀器。它的核心思想很简单：**减少网络往返**。

```
逐条发送（3次网络往返）：
  Client → SET a 1 → Server → OK → Client
  Client → SET b 2 → Server → OK → Client
  Client → SET c 3 → Server → OK → Client

Pipeline（1次网络往返）：
  Client → [SET a 1, SET b 2, SET c 3] → Server → [OK, OK, OK] → Client
```

每次网络往返（RTT）大约 0.5-2ms（同机房）。如果你要执行 1000 条命令，逐条发送需要 500-2000ms，Pipeline 只需要 1-2ms。差距是 **500 倍**！

### Pipeline vs 事务的区别

| 特性 | 事务（MULTI/EXEC） | 管道（Pipeline） |
|------|-------------------|-----------------|
| 原子性 | 命令批量执行（但出错不回滚） | 不保证原子性 |
| 网络优化 | 不减少网络往返 | 大幅减少网络往返 |
| 命令排队 | 必须先入队再执行 | 直接发送，一起返回 |
| 适用场景 | 需要"一起执行"的语义 | 需要高性能批量操作 |

### 在 Node.js 中使用 Pipeline

```js
const Redis = require('ioredis');
const redis = new Redis();

async function pipelineDemo() {
  // ========== 基本 Pipeline ==========
  const pipeline = redis.pipeline();

  pipeline.set('pl:name', 'Pipeline测试');
  pipeline.set('pl:count', '0');
  pipeline.incr('pl:count');
  pipeline.incr('pl:count');
  pipeline.incr('pl:count');
  pipeline.get('pl:name');
  pipeline.get('pl:count');

  const results = await pipeline.exec();
  console.log('Pipeline 结果：');
  results.forEach(([err, result], index) => {
    console.log(`  命令${index + 1}：${err ? '错误' : result}`);
  });

  // ========== 性能对比 ==========
  console.log('\n=== 性能对比 ===');

  // 方式1：逐条发送
  const start1 = Date.now();
  for (let i = 0; i < 1000; i++) {
    await redis.set(`perf:individual:${i}`, `value-${i}`);
  }
  const time1 = Date.now() - start1;
  console.log(`逐条发送 1000 个 SET：${time1}ms`);

  // 方式2：Pipeline
  const start2 = Date.now();
  const pipe = redis.pipeline();
  for (let i = 0; i < 1000; i++) {
    pipe.set(`perf:pipeline:${i}`, `value-${i}`);
  }
  await pipe.exec();
  const time2 = Date.now() - start2;
  console.log(`Pipeline 1000 个 SET：${time2}ms`);
  console.log(`性能提升：${(time1 / time2).toFixed(1)} 倍`);

  // 清理
  const cleanPipe = redis.pipeline();
  for (let i = 0; i < 1000; i++) {
    cleanPipe.del(`perf:individual:${i}`, `perf:pipeline:${i}`);
  }
  await cleanPipe.exec();
  await redis.del('pl:name', 'pl:count');
  await redis.quit();
}

pipelineDemo();
```

> [!TIP] 提示
> ：Pipeline 中的命令不是原子执行的。如果在 Pipeline 执行过程中有其他客户端修改了相同的 Key，你的 Pipeline 命令和其他客户端的命令可能会交错执行。如果需要原子性，请用事务或 Lua 脚本。

## 5.4 Lua 脚本简介

Lua 脚本是 Redis 的"核武器"——它在 Redis 服务端执行，保证原子性，性能极高。

```js
const Redis = require('ioredis');
const redis = new Redis();

async function luaDemo() {
  // ========== EVAL：直接执行 Lua 脚本 ==========
  // KEYS[1] = 计数器Key, ARGV[1] = 增量, ARGV[2] = 最大值
  const rateLimitScript = `
    local current = redis.call('GET', KEYS[1])
    if not current then
      redis.call('SET', KEYS[1], 1, 'EX', ARGV[2])
      return 1
    end
    if tonumber(current) >= tonumber(ARGV[1]) then
      return 0
    end
    return redis.call('INCR', KEYS[1])
  `;

  // 限制60秒内最多5次请求
  for (let i = 1; i <= 7; i++) {
    const result = await redis.eval(rateLimitScript, 1, 'ratelimit:user:1001', 5, 60);
    console.log(`请求${i}：${result === 0 ? '❌ 被限流' : '✅ 通过'}`);
  }

  // ========== defineCommand：注册自定义命令（更优雅的方式） ==========
  redis.defineCommand('transferBalance', {
    numberOfKeys: 2,
    lua: `
      local fromBalance = tonumber(redis.call('GET', KEYS[1]))
      local amount = tonumber(ARGV[1])

      if fromBalance == nil then
        return -1  -- 源账户不存在
      end

      if fromBalance < amount then
        return -2  -- 余额不足
      end

      redis.call('DECRBY', KEYS[1], amount)
      redis.call('INCRBY', KEYS[2], amount)

      return fromBalance - amount  -- 返回转账后的余额
    `,
  });

  // 使用自定义命令（就像原生命令一样！）
  await redis.set('wallet:alice', '1000');
  await redis.set('wallet:bob', '500');

  const remaining = await redis.transferBalance('wallet:alice', 'wallet:bob', 300);
  console.log(`\n转账后 Alice 余额：${remaining}`); // 700
  console.log(`转账后 Bob 余额：${await redis.get('wallet:bob')}`); // 800

  // 测试余额不足
  const failed = await redis.transferBalance('wallet:alice', 'wallet:bob', 9999);
  console.log(`余额不足返回值：${failed}`); // -2

  // 清理
  await redis.del('ratelimit:user:1001', 'wallet:alice', 'wallet:bob');
  await redis.quit();
}

luaDemo();
```

> [!TIP] 提示
> ：`defineCommand` 是 ioredis 的特色功能，它把 Lua 脚本封装成一个"自定义命令"，用起来和 Redis 原生命令一样方便。而且 ioredis 会自动使用 `EVALSHA`（脚本缓存），重复调用时性能更好。

## 5.5 事务 vs Pipeline vs Lua：如何选择？

| 需求 | 推荐方案 | 原因 |
|------|----------|------|
| 批量执行，不关心原子性 | Pipeline | 性能最好，代码简单 |
| 需要"批量执行"的语义 | 事务（MULTI/EXEC） | 标准方式 |
| 需要原子性 + 复杂逻辑 | Lua 脚本 | 在服务端原子执行 |
| 需要条件判断后决定操作 | WATCH + 事务 或 Lua | 乐观锁模式 |
| 大批量数据写入 | Pipeline | 减少网络往返 |
| 限流、分布式锁等 | Lua 脚本 | 原子性保证 |

**决策流程图**：

```
需要批量操作？
  ├─ 否 → 用普通命令
  └─ 是 → 需要原子性？
              ├─ 否 → Pipeline（性能优先）
              └─ 是 → 逻辑复杂吗？
                        ├─ 简单 → WATCH + MULTI/EXEC
                        └─ 复杂 → Lua 脚本
```

## 5.6 小结

> **单挑不如组团，选对武器事半功倍**

- Redis 事务（MULTI/EXEC）是"批量执行器"，不是真正的原子操作，不支持回滚
- WATCH 实现乐观锁：监控 Key 变化，变化则重试
- Pipeline 是性能利器：减少网络往返，适合大批量操作
- Lua 脚本是终极方案：原子性 + 高性能 + 复杂逻辑
- 大部分场景 Pipeline 就够了，需要原子性就上 Lua

## 5.7 练习题

1. **编码题**：用 WATCH + MULTI/EXEC 实现一个"库存扣减"功能——两个客户端同时扣减同一商品的库存，确保不会超卖。
2. **性能题**：分别用逐条发送和 Pipeline 的方式向 Redis 写入 10000 条数据，对比耗时。
3. **编码题**：用 Lua 脚本实现一个"原子性的 Hash 更新"——只有当 Hash 的某个 field 等于预期值时，才更新另一个 field 的值（类似 CAS 操作）。
