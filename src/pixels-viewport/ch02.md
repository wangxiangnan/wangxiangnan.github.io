# 第2章 CSS 像素：开发者工作在逻辑世界

> **本章回答的问题**：CSS 里写的 px 是屏幕上的发光点吗？一台设备的 CSS 坐标系有多大、怎么算？

## 2.1 没有抽象会怎样

假设 CSS 的 `px` 直接等于物理像素，看看会发生什么：

- 27 寸 1080p 显示器（约 82 PPI）：`width: 400px` 占 400 个物理像素，约 12.4cm 宽。
- iPhone 16 Pro Max（460 PPI）：同样 400 个物理像素，只有约 2.2cm——按钮小得无法点击。
- 同一份代码，在不同密度屏幕上物理尺寸差 5 倍以上，布局完全失控。

问题的本质：**物理像素数量描述的是"屏幕有多精细"，而不是"元素有多大"**。开发者需要的是一个与密度无关的尺寸单位。

## 2.2 CSS 像素的定义

**CSS 像素（CSS pixel）**是 Web 开发的逻辑像素：CSS 代码里写 `width: 100px` 用的就是它，JS 里的坐标、鼠标事件的位置也全部在这个坐标系里。它与设备实际有多少发光点无关。

CSS 规范给了它一个锚点：**`1in = 96px` 恒成立**。也就是说 1 个 CSS 像素的"意图尺寸"是 1/96 英寸（约 0.265mm）。这个 96 继承自 Windows 时代的显示器基准（[第 3 章](/frontend/pixels-viewport/ch03)细讲）。

注意"意图"二字：CSS 像素对应的物理尺寸并非严格 1/96 英寸——手机上 1 CSS px 的实际物理长度由 DPR 决定（460 PPI 的屏幕上 1 CSS px ≈ 1/153 英寸）。96 这个值的作用是提供一个跨设备一致的换算约定，让"1 英寸"的排版意图在不同屏幕上大体成立。

## 2.3 从物理像素反推 CSS 尺寸

浏览器拿到一台设备后，做的第一件事就是确定 CSS 坐标系有多大：

```
CSS 像素尺寸 = 物理像素尺寸 ÷ DPR
```

**iPhone 16 Pro Max 实算（DPR=3，来源见[第 3 章](/frontend/pixels-viewport/ch03)）：**

```
宽：1320 ÷ 3 = 440 个 CSS 像素
高：2868 ÷ 3 = 956 个 CSS 像素
```

所以这台手机的 CSS 坐标系是 440×956。这正是真机上 `screen.width = 440`、`window.outerWidth = 440` 的来源（[第 5 章](/frontend/pixels-viewport/ch05)实测验证）。

**验证自洽**：440×956 的对角线 = √(440² + 956²) ≈ 1052 个 CSS 像素，除以 6.86 英寸 ≈ 153 PPI——即 1 个 CSS 像素 ≈ 1/153 英寸；乘回 DPR 3 恰好还原 460 PPI 的物理密度。链条闭合。

## 2.4 小结

- CSS 像素是逻辑单位，作用是把"屏幕精细度"与"元素尺寸"解耦。
- CSS 锚定 1in = 96px 作为参考换算。
- 设备的 CSS 坐标系大小 = 物理分辨率 ÷ DPR，是后续一切测量的基础。

## 2.5 练习题

1. 某手机物理分辨率 750×1334，DPR 为 2，求其 CSS 像素尺寸。（它就是 iPhone 6/7/8）
2. CSS 规定 1in = 96px。在 460 PPI 的手机上，CSS 里"1 英寸"对应的物理长度是多少？为什么不是精确的 25.4mm？

## 2.6 参考答案

> 1. 宽 750÷2 = 375，高 1334÷2 = 667，CSS 坐标系 375×667。
> 2. 1in = 96px 是逻辑换算约定：96 个 CSS 像素经 DPR=3 映射为 288 个物理像素，按 460 PPI 折合约 0.63 英寸。它表达的是跨设备一致的排版意图，物理长度由实际密度决定，所以不严格等于 25.4mm。
