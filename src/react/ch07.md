# 第7章：useEffect — 副作用的正确打开方式

![第7章封面](./images/ch07.png)

## 7.1 引言：组件也需要"做额外的事"

在前面的章节中，你学会了用 `useState` 让组件拥有自己的记忆。但是，真实的应用中，组件除了"渲染界面"这个本职工作之外，还需要做一些"额外的事"：

- 从服务器获取数据（发 HTTP 请求）
- 监听浏览器窗口大小变化
- 设置一个定时器，每隔几秒刷新一次
- 手动修改 DOM（比如设置页面标题）
- 订阅某个消息推送

这些"额外的事"有一个共同的名字——**副作用（Side Effects）**。

为什么叫"副作用"呢？借用数学的概念：一个函数除了返回结果之外，还对外部世界产生了影响，这就是副作用。就像一个厨师（组件）除了做菜（渲染）之外，还顺手把厨房打扫了（副作用）——这是"额外"做的事。

**`useEffect` 就是 React 专门用来处理副作用的 Hook。**

> **比喻**：`useEffect` 就像一个忠实的管家。你告诉他"当某某事情发生的时候，去做某某事"，他就会忠实地执行，不多不少。你还可以告诉他"当不需要的时候，把之前做的事清理干净"。一个靠谱的好管家！

## 7.2 useEffect 的基本语法

先来看看 `useEffect` 长什么样：

```jsx
import { useState, useEffect } from 'react';

function PageTitle() {
  const [title, setTitle] = useState('首页');

  // useEffect 接收两个参数：
  // 1. 一个函数（副作用函数）
  // 2. 一个依赖数组
  useEffect(() => {
    // 副作用：修改浏览器标签页的标题
    document.title = `我的应用 - ${title}`;
    console.log('标题已更新为:', title);
  }, [title]); // 只有 title 变化时才重新执行

  return (
    <div>
      <h1>{title}</h1>
      <button onClick={() => setTitle('关于')}>切换到"关于"</button>
      <button onClick={() => setTitle('联系')}>切换到"联系"</button>
    </div>
  );
}

export default PageTitle;
```

`useEffect` 的结构可以总结为：

```jsx
useEffect(() => {
  // 做副作用的事
  // ...

  // 可选：返回一个清理函数
  return () => {
    // 清理之前做的事
  };
}, [依赖项1, 依赖项2]);
```

> **Tip**: `useEffect` 的名字里有个 "Effect"，就是"效果、副作用"的意思。React 团队给它起名的时候就很直白：Use（使用）+ Effect（副作用）。

## 7.3 依赖数组的奥秘

`useEffect` 的第二个参数——依赖数组——是最让人困惑的部分，但也是最重要的。让我们彻底搞懂它。

### 情况一：有依赖项 `[dep1, dep2]`

```jsx
useEffect(() => {
  console.log('只有 count 变化时才执行');
}, [count]);
```

**行为**：组件首次渲染时执行一次，之后只有当 `count` 的值发生变化时才会重新执行。

这是最常用的形式，绝大多数情况下你都应该明确指定依赖项。

### 情况二：空数组 `[]`

```jsx
useEffect(() => {
  console.log('只在组件挂载时执行一次');
}, []);
```

**行为**：只在组件第一次渲染（挂载）时执行一次，之后再也不执行。就像你搬进新家时做一次大扫除——入住一次就够了。

适合用于：初始化数据请求、添加全局事件监听等只需要做一次的事。

### 情况三：不传第二个参数

```jsx
useEffect(() => {
  console.log('每次渲染后都会执行');
});
```

**行为**：每次组件渲染后都会执行，包括首次渲染和后续每一次更新。

> **Warning**: 慎用！不传依赖数组意味着每次渲染都执行副作用，很容易导致性能问题或无限循环。99% 的情况下你都应该传一个依赖数组。

### 依赖数组对照表

| 写法 | 何时执行 | 何时清理 | 常见用途 |
|------|---------|---------|---------|
| `useEffect(fn, [a, b])` | 首次 + a 或 b 变化时 | 重新执行前 + 卸载时 | 响应特定数据变化 |
| `useEffect(fn, [])` | 仅首次渲染后 | 组件卸载时 | 初始化请求、订阅 |
| `useEffect(fn)` | 每次渲染后 | 下次渲染前 + 卸载时 | 极少使用 |

## 7.4 清理函数（Cleanup Function）

这是 `useEffect` 中非常重要但容易被忽视的部分。当你的副作用需要"善后"时，就需要返回一个清理函数。

**为什么需要清理？** 想象你订阅了一份报纸——如果你搬家了但没取消订阅，报纸就会一直往旧地址送，浪费资源还可能泄露隐私。同样，如果组件卸载了但定时器还在跑、事件监听还在，就会导致内存泄漏。

```jsx
import { useState, useEffect } from 'react';

function WindowSize() {
  const [size, setSize] = useState({
    width: window.innerWidth,
    height: window.innerHeight,
  });

  useEffect(() => {
    // 副作用：监听窗口大小变化
    const handleResize = () => {
      setSize({
        width: window.innerWidth,
        height: window.innerHeight,
      });
    };

    window.addEventListener('resize', handleResize);
    console.log('已添加 resize 监听器');

    // 清理函数：组件卸载时移除监听器
    return () => {
      window.removeEventListener('resize', handleResize);
      console.log('已移除 resize 监听器');
    };
  }, []); // 空数组：只在挂载和卸载时处理

  return (
    <div>
      <h2>当前窗口尺寸</h2>
      <p>宽度：{size.width}px</p>
      <p>高度：{size.height}px</p>
      <p>试试缩放浏览器窗口看看效果！</p>
    </div>
  );
}

export default WindowSize;
```

> **Tip**: 一个简单的判断规则：**如果你的 useEffect 里做了"添加"操作（addEventListener、setInterval、subscribe），就必须返回一个对应的"移除"操作。** 有借有还，再借不难！

## 7.5 常见使用场景

### 场景一：数据请求

这是 `useEffect` 最经典的使用场景——组件加载后从服务器获取数据。

```jsx
import { useState, useEffect } from 'react';

function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    // 定义异步请求函数
    const fetchUsers = async () => {
      try {
        setLoading(true);
        setError(null);
        const response = await fetch('https://jsonplaceholder.typicode.com/users');
        if (!response.ok) {
          throw new Error(`请求失败: ${response.status}`);
        }
        const data = await response.json();
        setUsers(data);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    };

    fetchUsers();
  }, []); // 空数组：组件挂载时请求一次

  if (loading) return <p>正在加载用户数据...</p>;
  if (error) return <p style={{ color: 'red' }}>出错了: {error}</p>;

  return (
    <div>
      <h2>用户列表（共 {users.length} 人）</h2>
      <ul>
        {users.map(user => (
          <li key={user.id}>
            {user.name} — {user.email}
          </li>
        ))}
      </ul>
    </div>
  );
}

export default UserList;
```

> **Warning**: 你可能会问："为什么不在 useEffect 里直接写 `async`？"因为 `useEffect` 的回调函数不能是 async 函数（它需要返回 undefined 或清理函数，而 async 函数返回 Promise）。解决方案是在里面定义一个 async 函数再调用它。

### 场景二：定时器

```jsx
import { useState, useEffect } from 'react';

function Clock() {
  const [time, setTime] = useState(new Date());

  useEffect(() => {
    // 每秒更新一次时间
    const timerId = setInterval(() => {
      setTime(new Date());
    }, 1000);

    // 组件卸载时清除定时器
    return () => {
      clearInterval(timerId);
    };
  }, []); // 空数组：只设置一次定时器

  return (
    <div style={{ textAlign: 'center', padding: '20px' }}>
      <h2>⏰ 实时时钟</h2>
      <p style={{ fontSize: '2em', fontFamily: 'monospace' }}>
        {time.toLocaleTimeString('zh-CN')}
      </p>
      <p style={{ color: '#666' }}>
        {time.toLocaleDateString('zh-CN', {
          year: 'numeric',
          month: 'long',
          day: 'numeric',
          weekday: 'long',
        })}
      </p>
    </div>
  );
}

export default Clock;
```

### 场景三：依赖 Props 或 State 的请求

有时候，请求的参数来自某个 state 或 prop，这时需要把它加到依赖数组中：

```jsx
import { useState, useEffect } from 'react';

function UserPosts({ userId }) {
  const [posts, setPosts] = useState([]);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    // 当 userId 变化时，重新请求数据
    const fetchPosts = async () => {
      setLoading(true);
      try {
        const response = await fetch(
          `https://jsonplaceholder.typicode.com/posts?userId=${userId}`
        );
        const data = await response.json();
        setPosts(data);
      } catch (err) {
        console.error('请求失败:', err);
      } finally {
        setLoading(false);
      }
    };

    if (userId) {
      fetchPosts();
    }
  }, [userId]); // userId 变化时重新执行

  if (loading) return <p>加载中...</p>;

  return (
    <div>
      <h3>用户 {userId} 的文章</h3>
      {posts.length === 0 ? (
        <p>暂无文章</p>
      ) : (
        <ul>
          {posts.map(post => (
            <li key={post.id}>{post.title}</li>
          ))}
        </ul>
      )}
    </div>
  );
}

// 父组件
function App() {
  const [selectedUser, setSelectedUser] = useState(1);

  return (
    <div>
      <h2>查看用户文章</h2>
      <select
        value={selectedUser}
        onChange={(e) => setSelectedUser(Number(e.target.value))}
      >
        <option value={1}>用户 1</option>
        <option value={2}>用户 2</option>
        <option value={3}>用户 3</option>
      </select>
      <UserPosts userId={selectedUser} />
    </div>
  );
}

export default App;
```

## 7.6 useEffect 的执行时机

理解 `useEffect` 什么时候执行，对正确使用它非常重要。

**执行顺序**：

```
1. 组件函数执行（渲染）
2. React 把虚拟 DOM 更新到真实 DOM
3. 浏览器绘制屏幕（用户看到界面）
4. useEffect 的回调函数执行 ← 在这里！
```

也就是说，`useEffect` 是在**浏览器绘制之后**异步执行的。这意味着用户先看到界面，然后副作用才运行。这对大多数场景来说都是正确的——你不会想让用户看到一个空白页面等着你的副作用执行完。

> **Tip**: 如果你的副作用需要在浏览器绘制**之前**执行（比如测量 DOM 元素的尺寸来调整布局），可以使用 `useLayoutEffect`。但 99% 的场景用 `useEffect` 就够了。

## 7.7 不要滥用 useEffect

这是很多初学者最容易犯的错误：**把所有逻辑都塞进 useEffect 里**。

### 反面教材：用 useEffect 处理可以用事件处理解决的事

```jsx
// ❌ 不好的做法：用 useEffect 处理按钮点击后的逻辑
function BadExample() {
  const [count, setCount] = useState(0);
  const [message, setMessage] = useState('');

  // 不需要 useEffect！
  useEffect(() => {
    if (count >= 10) {
      setMessage('太厉害了！');
    } else if (count >= 5) {
      setMessage('继续加油！');
    } else {
      setMessage('');
    }
  }, [count]);

  return (
    <div>
      <p>{count} {message}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
    </div>
  );
}
```

### 正面教材：直接在事件处理函数中处理

```jsx
// ✅ 好的做法：在事件处理函数中直接处理
function GoodExample() {
  const [count, setCount] = useState(0);
  const [message, setMessage] = useState('');

  const handleClick = () => {
    const newCount = count + 1;
    setCount(newCount);

    // 直接根据新值计算 message
    if (newCount >= 10) {
      setMessage('太厉害了！');
    } else if (newCount >= 5) {
      setMessage('继续加油！');
    } else {
      setMessage('');
    }
  };

  return (
    <div>
      <p>{count} {message}</p>
      <button onClick={handleClick}>+1</button>
    </div>
  );
}
```

### 更好的做法：用计算值代替多余的 state

```jsx
// ✅✅ 最好的做法：message 根本不需要是 state，它可以从 count 计算出来
function BestExample() {
  const [count, setCount] = useState(0);

  // 计算值：每次渲染时自动计算，不需要额外的 state 和 useEffect
  const getMessage = () => {
    if (count >= 10) return '太厉害了！';
    if (count >= 5) return '继续加油！';
    return '';
  };

  return (
    <div>
      <p>{count} {getMessage()}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
    </div>
  );
}
```

> **Warning**: 使用 useEffect 之前先问自己：**"这个逻辑能不能用事件处理函数或计算值来代替？"** 如果能，就不要用 useEffect。useEffect 应该用于真正需要同步外部系统的场景（网络请求、定时器、订阅、手动 DOM 操作等）。

**什么时候该用 useEffect：**

- 从服务器获取数据
- 设置定时器/间隔器
- 添加事件监听
- 订阅消息推送
- 手动操作 DOM
- 读写 localStorage

**什么时候不该用 useEffect：**

- 根据 state 计算另一个值（用计算值）
- 处理用户点击/输入（用事件处理函数）
- 在 state 更新后做某些事（直接在 setState 后面写）

## 7.8 常见坑与避坑指南

### 坑 1：无限循环

```jsx
// ❌ 无限循环！useEffect 修改了依赖项，导致自己不断触发
function InfiniteLoop() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    setCount(count + 1); // 修改 count → 触发重新渲染 → useEffect 再次执行 → 修改 count → ...
  }, [count]);

  return <p>{count}</p>;
}
```

**解决方案**：检查你的依赖数组和副作用函数，确保副作用不会修改它所依赖的值。

### 坑 2：依赖项遗漏

```jsx
// ❌ 忘记把 name 加到依赖数组中
function SearchResults() {
  const [name, setName] = useState('');
  const [results, setResults] = useState([]);

  useEffect(() => {
    // 这里用了 name，但依赖数组里没有它
    fetch(`/api/search?q=${name}`)
      .then(res => res.json())
      .then(setResults);
  }, []); // 缺少 name！

  // ...
}

// ✅ 正确：把用到的变量都加到依赖数组中
useEffect(() => {
  fetch(`/api/search?q=${name}`)
    .then(res => res.json())
    .then(setResults);
}, [name]);
```

> **Tip**: 开启 ESLint 的 `react-hooks/exhaustive-deps` 规则，它会帮你自动检查遗漏的依赖项。强烈建议！

### 坑 3：对象和函数作为依赖项

```jsx
// ❌ 每次渲染都创建新对象，导致 useEffect 每次都执行
function BadDeps() {
  const [data, setData] = useState(null);

  const options = { page: 1, size: 10 }; // 每次渲染都是新对象！

  useEffect(() => {
    fetchData(options).then(setData);
  }, [options]); // 引用不同 → 每次都执行

  // ...
}

// ✅ 方案1：把对象移到 useEffect 内部
useEffect(() => {
  const options = { page: 1, size: 10 };
  fetchData(options).then(setData);
}, []);

// ✅ 方案2：用 useMemo 记住对象
const options = useMemo(() => ({ page: 1, size: 10 }), []);
```

### 坑 4：在 useEffect 中直接使用 async

```jsx
// ❌ 错误：useEffect 不能直接是 async 函数
useEffect(async () => {
  const data = await fetchData();
  setData(data);
}, []);

// ✅ 正确：在内部定义 async 函数
useEffect(() => {
  const loadData = async () => {
    const data = await fetchData();
    setData(data);
  };
  loadData();
}, []);
```

### 坑 5：竞态条件（Race Condition）

```jsx
// ❌ 快速切换用户时，旧请求可能覆盖新请求的结果
useEffect(() => {
  fetch(`/api/users/${userId}`)
    .then(res => res.json())
    .then(data => setUser(data));
}, [userId]);

// ✅ 用标记变量忽略过期的请求结果
useEffect(() => {
  let isCancelled = false; // 标记变量

  fetch(`/api/users/${userId}`)
    .then(res => res.json())
    .then(data => {
      if (!isCancelled) {
        setUser(data); // 只在未取消时更新
      }
    });

  return () => {
    isCancelled = true; // 清理时标记为取消
  };
}, [userId]);
```

> **Warning**: 竞态条件是一个非常隐蔽的 bug。当用户快速切换页面或搜索关键词时，先发的请求可能后返回，覆盖了正确的结果。使用 `isCancelled` 标记或 `AbortController` 来避免这个问题。

## 7.9 实战：一个自动保存的笔记组件

让我们综合运用本章所学，做一个实用的"自动保存笔记"组件：

```jsx
import { useState, useEffect } from 'react';

function AutoSaveNote() {
  const [content, setContent] = useState('');
  const [savedContent, setSavedContent] = useState('');
  const [saveStatus, setSaveStatus] = useState('未开始');
  const [lastSaved, setLastSaved] = useState(null);

  // 从 localStorage 加载上次保存的内容（只在挂载时执行一次）
  useEffect(() => {
    const saved = localStorage.getItem('my-note');
    if (saved) {
      setContent(saved);
      setSavedContent(saved);
      setSaveStatus('已加载上次保存的内容');
    }
  }, []);

  // 自动保存：内容变化后延迟 1.5 秒保存
  useEffect(() => {
    // 如果内容没变化，不需要保存
    if (content === savedContent) {
      return;
    }

    setSaveStatus('等待输入停止...');

    // 设置定时器：1.5 秒后自动保存
    const timerId = setTimeout(() => {
      localStorage.setItem('my-note', content);
      setSavedContent(content);
      setSaveStatus('已自动保存 ✓');
      setLastSaved(new Date().toLocaleTimeString('zh-CN'));
    }, 1500);

    // 清理：如果 1.5 秒内内容又变了，取消这次保存
    return () => {
      clearTimeout(timerId);
    };
  }, [content, savedContent]);

  // 更新页面标题显示未保存状态
  useEffect(() => {
    const isDirty = content !== savedContent;
    document.title = isDirty ? '(未保存) 我的笔记' : '我的笔记';
  }, [content, savedContent]);

  return (
    <div style={{ maxWidth: '600px', margin: '0 auto', padding: '20px' }}>
      <h2>📝 自动保存笔记</h2>

      <div style={{
        display: 'flex',
        justifyContent: 'space-between',
        marginBottom: '8px',
        color: '#666',
        fontSize: '14px',
      }}>
        <span>状态：{saveStatus}</span>
        {lastSaved && <span>上次保存：{lastSaved}</span>}
      </div>

      <textarea
        value={content}
        onChange={(e) => setContent(e.target.value)}
        placeholder="在这里写点什么吧...（会自动保存哦）"
        style={{
          width: '100%',
          height: '300px',
          padding: '12px',
          fontSize: '16px',
          lineHeight: '1.6',
          border: content !== savedContent ? '2px solid #f0ad4e' : '2px solid #5cb85c',
          borderRadius: '8px',
          resize: 'vertical',
          boxSizing: 'border-box',
        }}
      />

      <div style={{ marginTop: '8px', display: 'flex', gap: '8px' }}>
        <button onClick={() => {
          localStorage.setItem('my-note', content);
          setSavedContent(content);
          setSaveStatus('手动保存成功 ✓');
          setLastSaved(new Date().toLocaleTimeString('zh-CN'));
        }}>
          手动保存
        </button>
        <button onClick={() => {
          setContent('');
          setSaveStatus('已清空');
        }}>
          清空
        </button>
      </div>

      <p style={{ color: '#999', fontSize: '12px', marginTop: '16px' }}>
        提示：停止输入 1.5 秒后会自动保存到浏览器本地存储。刷新页面内容不会丢失！
      </p>
    </div>
  );
}

export default AutoSaveNote;
```

这个组件用到了三个 `useEffect`，各有不同的职责：

1. **加载已保存内容**（空依赖数组，只执行一次）
2. **自动保存**（依赖 content 和 savedContent，带清理函数取消定时器）
3. **更新页面标题**（依赖内容变化状态）

## 7.10 本章小结

`useEffect` 是 React 中处理副作用的核心工具，让我们来回顾关键要点：

| 概念 | 核心要点 |
|------|---------|
| **副作用** | 渲染之外对外部世界的影响（请求、定时器、订阅等） |
| **基本语法** | `useEffect(函数, 依赖数组)` |
| **依赖数组** | `[dep]` 指定时执行，`[]` 只执行一次，不传则每次都执行 |
| **清理函数** | 返回一个函数来清理副作用，防止内存泄漏 |
| **执行时机** | 在浏览器绘制之后异步执行 |
| **不要滥用** | 能用事件处理或计算值解决的，不要用 useEffect |

**比喻回顾**：`useEffect` 就像一个忠实的管家——你告诉他"当XX变化时去做XX事"，他就会忠实地执行。你还可以告诉他"不做了要收拾干净"（清理函数）。
