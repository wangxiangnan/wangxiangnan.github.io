# 第15章：虚拟表与自定义函数

## 15.1 引言：SQLite的"外挂系统"

如果说前面章节讲的FTS5、JSON1、R-Tree让你觉得"哇，SQLite原来这么强"——那这一章要告诉你的是：**这些强大功能的背后，都基于同一个机制——虚拟表**。

想象SQLite是一款单机游戏，虚拟表机制就是它的**MOD系统**。任何人（包括你）都能写一个模块，让SQLite表现得像另一个东西：像文件系统、像HTTP服务、像消息队列、甚至像另一个数据库。

而**用户定义函数（UDF）**则是它的另一个扩展点：你可以往SQL语句里塞进任何自定义逻辑，让它跟内置函数一样使用。

这一章我们会：

- 揭开虚拟表的黑魔法
- 玩转几个官方内置的虚拟表（csv、dbstat、carray）
- 学会创建自定义函数（标量/聚合/窗口）
- 处理加载扩展的各种坑
- 在Flutter里怎么"变通"实现类似效果

## 15.2 虚拟表机制：SQLite的插件系统

### 15.2.1 什么是虚拟表

普通表的数据存在磁盘的B-Tree页里。**虚拟表的数据存哪里？谁知道！它可以存在：**

- 内存里
- 另一张表里（FTS5就这样）
- 另一个文件里（csv虚拟表读CSV文件）
- 网络上（有人做过HTTP虚拟表）
- CPU寄存器里（好吧，太夸张了）

虚拟表通过一套**回调函数**跟SQLite内核对话。SQLite不关心你怎么存数据，只要你能响应它的"给我下一行"、"按这个条件筛选"这样的请求就行。

用C写一个虚拟表需要实现`sqlite3_module`结构体：

```c
typedef struct sqlite3_module {
    int iVersion;
    int (*xCreate)(...);        // CREATE VIRTUAL TABLE时调用
    int (*xConnect)(...);       // 打开数据库时调用
    int (*xBestIndex)(...);     // 查询规划时调用
    int (*xDisconnect)(...);    
    int (*xDestroy)(...);       // DROP TABLE时调用
    int (*xOpen)(...);          // 打开游标
    int (*xClose)(...);         // 关闭游标
    int (*xFilter)(...);        // 应用WHERE条件
    int (*xNext)(...);          // 移到下一行
    int (*xEof)(...);           // 结束了吗？
    int (*xColumn)(...);        // 获取某一列的值
    int (*xRowid)(...);         // 获取rowid
    int (*xUpdate)(...);        // INSERT/UPDATE/DELETE
    // ... 更多可选回调
} sqlite3_module;
```

看起来复杂，但实际上大部分虚拟表只实现其中几个。SQLite自己提供的FTS5、R-Tree、csv都是这么写出来的。

### 15.2.2 内置虚拟表

SQLite发行版里就带了几个虚拟表模块：

- **fts3/fts4/fts5** — 全文搜索（第12章讲了）
- **rtree** — 空间索引（第14章讲了）
- **csv** — 读CSV文件
- **dbstat** — 数据库统计信息
- **carray** — C数组适配
- **json_each / json_tree** — 严格说也是"表函数"，本质是虚拟表
- **generate_series** — 生成数字序列
- **zipfile** — 读写ZIP文件
- **sqlar** — SQLite Archive（备份归档格式）

`generate_series`是个宝藏，可以用来生成序列：

```sql
-- 生成1到10
SELECT value FROM generate_series(1, 10);

-- 生成2, 4, 6, ..., 20
SELECT value FROM generate_series(2, 20, 2);

-- 用于测试：造100行假数据
INSERT INTO users(name)
SELECT 'user_' || value FROM generate_series(1, 100);
```

（注意：`generate_series`不是所有编译都启用了，先测一下。）

## 15.3 csv虚拟表：把CSV当表查

想象你有一个巨大的CSV文件`sales.csv`，60万行销售数据。老板问："上个月各产品的销量？"

**传统方法**：写Python读CSV，pandas处理。

**SQLite方法**：

```sql
-- 加载csv扩展
.load ./csv

-- 把CSV文件"挂载"成虚拟表
CREATE VIRTUAL TABLE sales USING csv(
    filename='/path/to/sales.csv',
    header=YES,        -- 第一行是表头
    schema='CREATE TABLE x(date TEXT, product TEXT, quantity INT, revenue REAL)'
);

-- 直接查询！
SELECT product, SUM(quantity) AS total
FROM sales
WHERE date LIKE '2024-01%'
GROUP BY product
ORDER BY total DESC
LIMIT 10;
```

**关键点**：数据没有导入！查询时按需读CSV，节省内存。适合"临时分析大CSV"的场景。

局限：

- 只读，不能写
- 每次查询都要扫描CSV（除非用CTAS导入到真表）
- 不能建索引

## 15.4 dbstat：了解你的数据库

想知道你的数据库文件里的空间是怎么分配的？谁在浪费空间？dbstat虚拟表帮你看：

```sql
-- 3.7.9+ 自动启用（如果编译时打开）
SELECT * FROM dbstat 
WHERE aggregate = TRUE;
```

会返回每个表和索引占了多少页面、多少字节：

```
name         | pageno | pagetype | ncell | payload | ...
-------------+--------+----------+-------+---------
users        |      1 | leaf     |    30 |    1200 |
idx_users_email | 2 | leaf     |    30 |     450 |
posts        |      3 | leaf     |   100 |    5000 |
```

用途：

- 分析索引是否值得（占用大但没在用？考虑删除）
- 找出膨胀的表
- 定位空间浪费问题

## 15.5 carray：应用层数组注入SQL

**问题**：你在应用里有一个ID列表[1, 5, 8, 12]，想用它做`WHERE id IN (?)`。

普通做法：拼字符串或多个参数。

```dart
// 尴尬的做法：
final ids = [1, 5, 8, 12];
final placeholders = List.filled(ids.length, '?').join(',');
final rows = await db.rawQuery(
  'SELECT * FROM users WHERE id IN ($placeholders)',
  ids,
);
```

如果IDs有10000个呢？拼10000个`?`不优雅，还可能超过SQLite的参数上限（默认999）。

**carray方案**（在C API里更好用）：

```c
sqlite3_stmt *stmt;
sqlite3_prepare_v2(db, 
    "SELECT * FROM users WHERE id IN carray(?, ?, 'int64')",
    -1, &stmt, NULL);
sqlite3_bind_pointer(stmt, 1, ids, "carray", NULL);
sqlite3_bind_int(stmt, 2, ids_count);
```

在Dart/sqflite里，carray用起来比较别扭（因为没有直接的指针绑定API），一般还是用拼SQL或者join临时表的方式。

## 15.6 用户定义函数（UDF）

SQLite内置函数已经很多（`substr`、`upper`、`length`、`json_extract`…），但难免有你想要的它没有。这时你可以注册**用户定义函数**。

UDF分三种：

### 15.6.1 标量函数（Scalar Function）

输入N个参数，输出一个值。比如：

- `md5(x)` — 计算MD5
- `is_valid_email(x)` — 判断是否合法email
- `pinyin(x)` — 中文转拼音

### 15.6.2 聚合函数（Aggregate Function）

多行输入，一个值输出。比如：

- `median(x)` — 中位数
- `stddev(x)` — 标准差
- `mode(x)` — 众数
- `concat_ws(sep, x)` — 字符串拼接

### 15.6.3 窗口函数（Window Function）

跟聚合类似，但按窗口作用于每行。SQLite 3.25+ 支持自定义窗口函数。

### 15.6.4 通过C API注册

```c
static void md5_func(sqlite3_context *ctx, int argc, sqlite3_value **argv) {
    const unsigned char *input = sqlite3_value_text(argv[0]);
    // ... 计算MD5 ...
    sqlite3_result_text(ctx, hex_result, 32, SQLITE_TRANSIENT);
}

sqlite3_create_function(db, "md5", 1, SQLITE_UTF8, NULL, md5_func, NULL, NULL);
```

C语言的UDF可以做任何事：调用HTTP、读文件、算AI模型……不过这些"侧效应"通常是坏主意（SQL假设函数是纯函数）。

### 15.6.5 语言绑定中的UDF

Python的sqlite3模块支持很好：

```python
import sqlite3
import hashlib

def md5(s):
    return hashlib.md5(s.encode()).hexdigest()

conn = sqlite3.connect(':memory:')
conn.create_function('md5', 1, md5)

cur = conn.cursor()
cur.execute("SELECT md5('hello')")
print(cur.fetchone())  # ('5d41402abc4b2a76b9719d911017c592',)
```

Node.js的better-sqlite3也支持：

```javascript
db.function('md5', (s) => crypto.createHash('md5').update(s).digest('hex'));
```

Go的go-sqlite3也支持。

**但Flutter的sqflite……不支持！**

## 15.7 sqflite的限制：UDF与Flutter的困境

sqflite插件是Dart对原生SQLite的封装，但它**没有暴露UDF注册接口**。这是因为：

1. 跨语言函数调用性能差（Dart → Native → Dart再回来）
2. 增加维护复杂度

**替代方案：**

### 方案A：切换到sqflite_common_ffi

`sqflite_common_ffi`包用FFI直接绑定SQLite库。它是**桌面平台**（Windows/macOS/Linux）的推荐方案，也支持在Flutter Web（用sqlite3.wasm）上用。

FFI版本可以做到更多——包括加载扩展和某种程度的UDF。

### 方案B：用drift + native_sqlite库

drift底层可以选择不同的executor。用`SqliteAsyncQueryExecutor`或者drift自己的`NativeDatabase`，可以在纯Dart层用`sqlite3`包，它支持`createFunction`：

```dart
import 'package:sqlite3/sqlite3.dart';

final db = sqlite3.openInMemory();

// 注册标量UDF
db.createFunction(
  functionName: 'reverse_string',
  argumentCount: const AllowedArgumentCount(1),
  function: (args) {
    final s = args[0] as String;
    return s.split('').reversed.join();
  },
);

// 使用
final result = db.select('SELECT reverse_string(?)', ['hello']);
print(result.first[0]);  // 'olleh'
```

drift集成：

```dart
DatabaseConnection connectWithUdf() {
  return DatabaseConnection.delayed(Future.sync(() {
    final db = sqlite3.openInMemory();
    
    // 注册UDF
    db.createFunction(
      functionName: 'pinyin',
      argumentCount: const AllowedArgumentCount(1),
      function: (args) {
        final s = args[0] as String?;
        if (s == null) return null;
        return toPinyin(s);  // 你自己的实现
      },
    );
    
    db.createFunction(
      functionName: 'uuid',
      argumentCount: const AllowedArgumentCount(0),
      function: (args) => const Uuid().v4(),
      isDeterministic: false,  // 每次调用都不同
    );
    
    return NativeDatabase.opened(db);
  }));
}
```

**代价**：这条路只在**桌面平台+Web**通，**移动端**（Android/iOS）用sqflite_common_ffi也能走，但要单独打包SQLite库。

### 方案C：应用层做（无奈之举）

如果没办法用UDF，只能：

```dart
// 想按拼音排序？
final rows = await db.rawQuery('SELECT * FROM users');
final list = rows.map((r) => User.fromMap(r)).toList()
  ..sort((a, b) => toPinyin(a.name).compareTo(toPinyin(b.name)));
```

问题：数据量大时性能差（必须把所有数据拉到内存）。

## 15.8 加载扩展：load_extension()

除了UDF，SQLite还支持**加载外部扩展**（.so/.dll/.dylib文件）。这些扩展可以包含多个UDF、虚拟表、collation。

### 15.8.1 命令行加载

```sql
-- 出于安全，默认禁用
-- 命令行工具用 -cmd 或 .load
.load ./my_extension

-- 或者启用后用SQL加载
SELECT load_extension('/path/to/extension.so');
```

### 15.8.2 编程接口

```c
sqlite3_enable_load_extension(db, 1);   // 启用
sqlite3_load_extension(db, "path", NULL, &errmsg);
sqlite3_enable_load_extension(db, 0);   // 用完关掉
```

### 15.8.3 安全考虑

`load_extension`可以加载任意动态库执行任意代码。**如果你的SQLite被用户可控的SQL喂——不要启用！**

具体来说，如果用户能提交SQL到你的服务器，他就能`SELECT load_extension('/tmp/evil.so')`执行任意代码。这跟"用户能执行任意代码"是同等严重的漏洞。

**只在你完全信任的环境里启用扩展加载。**

### 15.8.4 常用扩展

- **spellfix1** — 拼写纠错（第12章讲了）
- **uuid** — UUID生成（`uuid()`函数）
- **regexp** — 正则匹配（让`REGEXP`操作符生效）
- **math** — 数学函数（sin/cos/atan2等，3.35+已内置）
- **crypto** — 加密函数（HMAC、AES）
- **sqlean** — 一堆流行扩展的合集（<https://github.com/nalgeon/sqlean）>

**sqlean**特别推荐，一个包里塞了几十个扩展：

```
sqlean-crypto     -- 加密函数
sqlean-fileio     -- 文件读写
sqlean-fuzzy      -- 模糊字符串匹配
sqlean-math       -- 数学函数
sqlean-regexp     -- 正则
sqlean-stats      -- 统计函数（median、percentile等）
sqlean-text       -- 字符串工具（slugify等）
sqlean-uuid       -- UUID
sqlean-vsv        -- CSV虚拟表增强版
```

## 15.9 自定义排序规则（Collation）

排序规则决定了`ORDER BY`怎么比较字符串。SQLite内置3个：

- **BINARY**（默认）：按字节比
- **NOCASE**：不区分大小写（只对ASCII有效）
- **RTRIM**：忽略结尾空格

**中文按拼音排序**——需要自定义collation！

### 15.9.1 C层注册

```c
int pinyin_collation(void *ctx, int len1, const void *s1, int len2, const void *s2) {
    char *p1 = to_pinyin(s1, len1);
    char *p2 = to_pinyin(s2, len2);
    int r = strcmp(p1, p2);
    free(p1); free(p2);
    return r;
}

sqlite3_create_collation(db, "PINYIN", SQLITE_UTF8, NULL, pinyin_collation);
```

### 15.9.2 使用

```sql
-- 表定义时指定
CREATE TABLE users (
    name TEXT COLLATE PINYIN
);

-- 或者查询时指定
SELECT * FROM users ORDER BY name COLLATE PINYIN;

-- 索引也可以
CREATE INDEX idx_users_pinyin ON users(name COLLATE PINYIN);
```

### 15.9.3 Dart侧

`sqlite3`包也支持注册collation：

```dart
db.createCollation(
  name: 'PINYIN',
  function: (a, b) {
    final pa = toPinyin(a ?? '');
    final pb = toPinyin(b ?? '');
    return pa.compareTo(pb);
  },
);
```

## 15.10 实战：实现UUID生成函数

假设你的表要用UUID做主键，但SQLite默认没有uuid函数。

### 方案1：Dart层生成后插入

```dart
import 'package:uuid/uuid.dart';
final uuid = Uuid().v4();
await db.insert('items', {'id': uuid, 'name': 'foo'});
```

**缺点**：不能用`DEFAULT`，每次插入都要在Dart层显式生成。

### 方案2：用sqlite3包注册UDF（drift/桌面/Web）

```dart
import 'package:sqlite3/sqlite3.dart';
import 'package:uuid/uuid.dart';

void setupDatabase(Database db) {
  const uuidGen = Uuid();
  
  db.createFunction(
    functionName: 'uuid',
    argumentCount: const AllowedArgumentCount(0),
    function: (args) => uuidGen.v4(),
    isDeterministic: false,
  );
}

// 现在SQL里可以直接用
db.execute('''
  CREATE TABLE items (
    id TEXT PRIMARY KEY DEFAULT (uuid()),
    name TEXT
  )
''');

db.execute("INSERT INTO items(name) VALUES ('foo')");
// id字段自动填充UUID
```

### 方案3：用sqlean的uuid扩展

如果是C/Python/Node.js环境：

```sql
.load ./uuid

CREATE TABLE items (
    id TEXT PRIMARY KEY DEFAULT (uuid4()),
    name TEXT
);

INSERT INTO items(name) VALUES ('foo');
-- id自动是一个UUIDv4
```

### 方案4：纯SQL模拟UUID

不完美，但没有扩展时能用：

```sql
-- 生成一个类UUID的随机字符串
SELECT lower(hex(randomblob(4))) || '-' || 
       lower(hex(randomblob(2))) || '-4' || 
       substr(lower(hex(randomblob(2))), 2) || '-' ||
       substr('89ab', 1 + (abs(random()) % 4), 1) ||
       substr(lower(hex(randomblob(2))), 2) || '-' ||
       lower(hex(randomblob(6)));
-- 结果类似：a1b2c3d4-1234-4567-8901-abcdef123456
```

设为默认值：

```sql
CREATE TABLE items (
    id TEXT PRIMARY KEY DEFAULT (
        lower(hex(randomblob(4))) || '-' || 
        lower(hex(randomblob(2))) || '-4' || 
        substr(lower(hex(randomblob(2))), 2) || '-' ||
        substr('89ab', 1 + (abs(random()) % 4), 1) ||
        substr(lower(hex(randomblob(2))), 2) || '-' ||
        lower(hex(randomblob(6)))
    ),
    name TEXT
);
```

## 15.11 应用集成扩展的正确姿势

在生产应用里加载扩展，考虑：

### 15.11.1 部署

扩展是动态库（.so/.dll/.dylib），要跟你的App一起打包，运行时能找到。

Flutter桌面App：

```
myapp/
├── myapp.exe
├── sqlite3.dll
└── extensions/
    ├── spellfix.dll
    └── uuid.dll
```

Dart代码：

```dart
final extPath = path.join(
  path.dirname(Platform.resolvedExecutable),
  'extensions',
  'uuid.dll',
);
db.execute("SELECT load_extension('$extPath')");
```

### 15.11.2 平台差异

- iOS：**不允许加载动态库**！扩展必须静态编译进主二进制。
- Android：可以加载，但要处理各种ABI（arm64、x86_64等）。
- Web（sqlite3.wasm）：目前不支持传统扩展，只能用WASM实现的等价物。

**移动端最好的策略是：**要什么扩展，就编译一个"带该扩展的自定义SQLite"，替换默认的。`sqlite3_flutter_libs`包可以帮你做这件事。

### 15.11.3 版本兼容

扩展是针对特定SQLite版本编译的。如果你换了SQLite版本，扩展可能ABI不兼容。生产环境一定要**扩展和SQLite一起测试**。

## 15.12 Flutter实战：sqflite_common_ffi + 加载扩展

在Windows/macOS/Linux桌面上：

```dart
import 'package:sqflite_common_ffi/sqflite_ffi.dart';

Future<Database> openDbWithExtensions() async {
  // 初始化FFI
  sqfliteFfiInit();
  
  // 打开数据库
  final dbFactory = databaseFactoryFfi;
  final db = await dbFactory.openDatabase('my.db');
  
  // FFI版本可以执行任意SQL，包括load_extension
  // 但需要先启用（安全考虑，默认关闭）
  await db.execute("SELECT load_extension('spellfix')");
  // 注意：路径和平台相关
  
  return db;
}
```

对于**移动端**，推荐用`sqlite3_flutter_libs`+`drift`组合：

```yaml
# pubspec.yaml
dependencies:
  drift: ^2.15.0
  sqlite3: ^2.4.0
  sqlite3_flutter_libs: ^0.5.0
  path_provider: ^2.1.0
```

```dart
import 'package:drift/drift.dart';
import 'package:drift/native.dart';
import 'package:sqlite3/sqlite3.dart';

LazyDatabase _openConnection() {
  return LazyDatabase(() async {
    final dbFolder = await getApplicationDocumentsDirectory();
    final file = File(path.join(dbFolder.path, 'db.sqlite'));
    
    return NativeDatabase.createInBackground(
      file,
      setup: (db) {
        // 注册UDF
        db.createFunction(
          functionName: 'pinyin',
          argumentCount: const AllowedArgumentCount(1),
          function: (args) {
            final s = args[0] as String?;
            return s == null ? null : toPinyin(s);
          },
        );
        
        db.createFunction(
          functionName: 'uuid',
          argumentCount: const AllowedArgumentCount(0),
          function: (args) => const Uuid().v4(),
          isDeterministic: false,
        );
        
        // 注册collation
        db.createCollation(
          name: 'PINYIN',
          function: (a, b) {
            if (a == null || b == null) return 0;
            return toPinyin(a).compareTo(toPinyin(b));
          },
        );
      },
    );
  });
}
```

这样在Android和iOS上，你就能在SQL里用`uuid()`、`pinyin()`函数了，跟内置函数一样。

## 15.13 实战案例：中文拼音搜索+排序

需求：一个通讯录App，用户按拼音首字母搜索联系人，联系人按拼音排序。

```dart
// 1. Dart层的拼音库（比如lpinyin包）
import 'package:lpinyin/lpinyin.dart';

String toPinyin(String input) {
  return PinyinHelper.getPinyinE(input, separator: '', defPinyin: '?');
}

String pinyinInitials(String input) {
  return PinyinHelper.getShortPinyin(input);
}

// 2. drift setup里注册UDF
setup: (db) {
  db.createFunction(
    functionName: 'pinyin',
    argumentCount: const AllowedArgumentCount(1),
    function: (args) => args[0] == null ? null : toPinyin(args[0] as String),
    isDeterministic: true,
  );
  
  db.createFunction(
    functionName: 'pinyin_initials',
    argumentCount: const AllowedArgumentCount(1),
    function: (args) => args[0] == null ? null : pinyinInitials(args[0] as String),
    isDeterministic: true,
  );
  
  db.createCollation(
    name: 'PINYIN',
    function: (a, b) {
      if (a == null && b == null) return 0;
      if (a == null) return -1;
      if (b == null) return 1;
      return toPinyin(a).compareTo(toPinyin(b));
    },
  );
},

// 3. 建表用生成列
CREATE TABLE contacts (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    phone TEXT,
    -- 生成列：把拼音存起来
    name_pinyin TEXT GENERATED ALWAYS AS (pinyin(name)) STORED,
    name_initials TEXT GENERATED ALWAYS AS (pinyin_initials(name)) STORED
);

CREATE INDEX idx_contacts_pinyin ON contacts(name_pinyin);
CREATE INDEX idx_contacts_initials ON contacts(name_initials);

// 4. 搜索："zg"应该能搜到"张三"、"郑刚"
SELECT * FROM contacts 
WHERE name_initials LIKE 'zg%' 
   OR name_pinyin LIKE 'zg%'
   OR name LIKE 'zg%';

// 5. 按拼音排序
SELECT * FROM contacts ORDER BY name_pinyin;
```

**关键点**：用生成列把拼音"物化"（STORED），既能建索引又只算一次。UDF在插入时被调用，之后每次查询都用现成的字符串。

## 15.14 原理深挖：SQLite扩展的动态加载

SQLite的扩展加载机制其实很简单：

1. `sqlite3_load_extension`用`dlopen`（Unix）或`LoadLibrary`（Windows）打开.so/.dll
2. 找到导出的入口函数（默认名`sqlite3_extension_init`）
3. 调用它，扩展在这个函数里注册UDF、虚拟表、collation等

扩展写起来大概长这样（C）：

```c
#include "sqlite3ext.h"
SQLITE_EXTENSION_INIT1

static void my_function(sqlite3_context *ctx, int argc, sqlite3_value **argv) {
    // ... 实现 ...
    sqlite3_result_text(ctx, "hello", -1, SQLITE_STATIC);
}

#ifdef _WIN32
__declspec(dllexport)
#endif
int sqlite3_myext_init(
    sqlite3 *db, 
    char **pzErrMsg, 
    const sqlite3_api_routines *pApi
) {
    SQLITE_EXTENSION_INIT2(pApi);
    sqlite3_create_function(db, "hello", 0, SQLITE_UTF8, 
                            NULL, my_function, NULL, NULL);
    return SQLITE_OK;
}
```

编译：

```bash
gcc -shared -fPIC -o myext.so myext.c
```

使用：

```sql
.load ./myext
SELECT hello();  -- 'hello'
```

写扩展比想象中简单，但坑不少：内存管理、错误处理、线程安全都要小心。真要写建议参考sqlean的代码。

## 15.15 常见坑点

### 坑1：sqflite用不了UDF

前面反复强调：sqflite不支持UDF。用drift+sqlite3或sqflite_common_ffi替代。

### 坑2：iOS不支持动态加载扩展

iOS禁止运行时加载代码。移动端要用扩展必须静态编译。

### 坑3：UDF性能陷阱

每次SQL调用UDF都是一次Dart↔Native的边界穿越。**在WHERE里用UDF会导致全表扫描**：

```sql
-- 用不到索引
SELECT * FROM users WHERE pinyin(name) LIKE 'zh%';

-- 用得到索引（如果pinyin是生成列并建了索引）
SELECT * FROM users WHERE name_pinyin LIKE 'zh%';
```

**尽量用生成列 + 索引，避免运行时反复调用UDF。**

### 坑4：UDF标记deterministic不当

如果一个UDF被标记为`isDeterministic: true`，但实际不是（比如返回值依赖时间），会导致查询结果被错误缓存/优化。反之，把确定性函数标记为非确定性会失去优化。**慎重设置**。

### 坑5：load_extension的路径问题

不同平台加载扩展的路径处理方式不同，且SQLite默认要求"完整路径 + 无扩展名"或"完整路径 + 完整名"。跨平台代码要小心：

```dart
final ext = Platform.isWindows ? 'myext.dll'
          : Platform.isMacOS   ? 'libmyext.dylib'
          : 'libmyext.so';
final full = path.join(dir, ext);
db.execute("SELECT load_extension('$full')");
```

### 坑6：并发访问UDF

如果UDF内部访问共享状态，注意线程安全。SQLite本身在serialized模式下是线程安全的，但你的UDF代码不一定。

## 15.16 本章小结

- **虚拟表**是SQLite的插件机制，FTS5/R-Tree/JSON1都基于它
- **csv虚拟表**能直接查询CSV文件，适合快速分析
- **dbstat**帮你了解数据库空间分配
- **UDF**分标量/聚合/窗口三种，让你在SQL里塞自定义逻辑
- Dart/Flutter中：
  - sqflite **不支持** UDF
  - **sqlite3 + drift + NativeDatabase** 支持
  - **sqflite_common_ffi** 也支持（桌面）
- 加载扩展要注意**安全和平台限制**（iOS不行）
- 中文拼音排序：用UDF + 生成列 + 索引的组合
