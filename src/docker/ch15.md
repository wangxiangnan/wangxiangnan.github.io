# 第15章：Docker Registry —— 私有仓库搭建与管理

## 引言：自己的"应用商店"

如果 Docker Hub 是"苹果的 App Store"——公开、方便但有各种限制，那私有 Registry 就是你公司内部的"企业应用商店"。只有你和你的团队能访问，你可以自由地管理镜像版本，不用担心 Docker Hub 的拉取限流（rate limit），也不用把公司的代码推到公共仓库。

想象一下这个场景：你公司有 20 个微服务，每个服务都有自己的 Docker 镜像。这些镜像包含了公司的核心业务逻辑，你肯定不想把它们放到 Docker Hub 上让全世界看到。这时候，你就需要一个私有 Registry——一个属于你自己的镜像仓库。

> [!TIP] 提示
> 私有 Registry 的好处不仅仅是安全。它还能大幅加速镜像拉取（因为走的是内网而非公网），避免 Docker Hub 的 rate limit（匿名100次/6小时，认证200次/6小时），以及支持自定义的镜像管理策略。

## 15.1 Docker Hub 的使用与限制

Docker Hub 是最常用的公共 Registry，但在生产环境中使用它有几个坑：

```bash
# Docker Hub 的拉取限制
# 匿名用户：100 次拉取 / 6 小时
# 认证用户：200 次拉取 / 6 小时
# 付费用户：无限制

# 登录 Docker Hub
docker login
# 会提示输入用户名和密码
# 登录后会在 ~/.docker/config.json 中保存认证信息

# 使用 Access Token 替代密码（更安全）
docker login --username myuser
# 然后在密码提示处输入 Access Token
# 可以在 Docker Hub 网站 -> Account Settings -> Security 中创建 Token
```

```json
// ~/.docker/config.json
// Docker 的认证配置文件（自动生成）
{
  "auths": {
    "https://index.docker.io/v1/": {
      "auth": "base64编码的用户名:密码"
      // 注意：这只是 base64 编码，不是加密！
      // 任何能读取这个文件的人都能获取你的凭据
    }
  }
}
```

> **Warning:** `~/.docker/config.json` 中的认证信息只是 base64 编码，几乎没有安全性。在 CI/CD 环境中，建议使用 credential helper（如 `docker-credential-pass`）或者环境变量方式管理凭据，而不是直接存储在这个文件中。

## 15.2 搭建私有 Registry

Docker 官方提供了一个轻量级的 Registry 实现——`registry:2` 镜像。搭建一个基础版本比你想象的简单：

```bash
# 最简单的私有 Registry，一条命令搞定
docker run -d \
  --name registry \
  --restart=always \
  -p 5000:5000 \
  -v registry-data:/var/lib/registry \
  registry:2

# 就这样！你现在有了一个运行在 localhost:5000 的私有 Registry
# 就像在你家后院开了一个小超市

# 测试推送一个镜像
docker pull nginx:alpine
docker tag nginx:alpine localhost:5000/my-nginx:v1
# 给镜像打上 Registry 地址的前缀
# 这是 Docker 识别推送目标的方式

docker push localhost:5000/my-nginx:v1
# 推送到私有 Registry

# 测试拉取
docker rmi localhost:5000/my-nginx:v1
# 先删除本地镜像
docker pull localhost:5000/my-nginx:v1
# 从私有 Registry 拉取
```

当然，生产环境不能这么简单。我们需要加上认证、TLS 和持久化存储。

## 15.3 Registry 认证配置

### 15.3.1 HTTP Basic Auth

```bash
# 步骤1：生成 htpasswd 文件
# 使用 htpasswd 工具创建用户名和密码
mkdir -p auth

# 使用 Docker 运行 htpasswd 工具
docker run --rm \
  --entrypoint htpasswd \
  httpd:2-alpine \
  -Bbn admin MyStr0ngP@ssw0rd > auth/htpasswd
  # -B：使用 bcrypt 加密（比 MD5 安全得多）
  # -b：从命令行读取密码（而非交互式输入）
  # -n：输出到 stdout

# 你也可以添加更多用户
docker run --rm \
  --entrypoint htpasswd \
  httpd:2-alpine \
  -Bbn developer DevP@ssw0rd >> auth/htpasswd
```

```bash
# 步骤2：使用认证启动 Registry
docker run -d \
  --name registry-secure \
  --restart=always \
  -p 5000:5000 \
  -v $(pwd)/auth:/auth \
  -v registry-data:/var/lib/registry \
  -e "REGISTRY_AUTH=htpasswd" \
  -e "REGISTRY_AUTH_HTPASSWD_REALM=Registry Realm" \
  -e "REGISTRY_AUTH_HTPASSWD_PATH=/auth/htpasswd" \
  registry:2

# 现在推送和拉取都需要登录了
docker login localhost:5000
# Username: admin
# Password: MyStr0ngP@ssw0rd
# 登录成功后才能 push/pull
```

### 15.3.2 Token 认证

对于更复杂的场景（比如不同用户有不同权限），可以使用 Token 认证：

```yaml
# registry-config.yml
# Registry 配置文件

version: 0.1
# Registry 配置版本号（固定为 0.1，不是 Registry 镜像版本）

log:
  level: info
  fields:
    service: registry

storage:
  filesystem:
    rootdirectory: /var/lib/registry
  delete:
    enabled: true
    # 允许删除镜像，用于垃圾回收

http:
  addr: 0.0.0.0:5000
  headers:
    X-Content-Type-Options: [nosniff]

auth:
  token:
    realm: https://auth.example.com/auth
    # Token 认证服务的地址
    service: registry.example.com
    # Registry 的服务名
    issuer: auth-server
    # Token 颁发者标识
    rootcertbundle: /etc/docker/registry/auth.crt
    # 用于验证 Token 签名的证书
    autoredirect: false

health:
  storagedriver:
    enabled: true
    interval: 10s
    threshold: 3
```

> [!TIP] 提示
> 大多数团队用 HTTP Basic Auth 就够了。Token 认证更适合需要细粒度权限控制的场景，比如你有一个统一的认证中心，多个服务共用同一套用户体系。如果你只是想让同事能登录你的私有 Registry，别搞复杂了，Basic Auth + TLS 足够了。

## 15.4 TLS/SSL 配置

在生产环境中，Registry 必须使用 HTTPS。否则，你推送的镜像数据（可能包含公司代码）会以明文传输，就像在明信片上写机密信息一样。

```bash
# 方式1：使用自签名证书（适合内网环境）

# 生成私钥
openssl req -newkey rsa:4096 -nodes \
  -keyout domain.key \
  -x509 -days 365 \
  -out domain.crt \
  -subj "/CN=registry.example.com" \
  -addext "subjectAltName=DNS:registry.example.com,IP:192.168.1.100"
  # subjectAltName 很重要！
  # 现代 Docker 要求证书中包含 SAN，否则会报错

# 方式2：使用 Let's Encrypt（适合有公网域名的场景）
# 使用 certbot 自动获取和续期证书
certbot certonly --standalone -d registry.example.com
```

```bash
# 使用 TLS 启动 Registry
docker run -d \
  --name registry-tls \
  --restart=always \
  -p 5000:5000 \
  -v $(pwd)/certs:/certs \
  -v $(pwd)/auth:/auth \
  -v registry-data:/var/lib/registry \
  -e "REGISTRY_HTTP_TLS_CERTIFICATE=/certs/domain.crt" \
  -e "REGISTRY_HTTP_TLS_KEY=/certs/domain.key" \
  -e "REGISTRY_AUTH=htpasswd" \
  -e "REGISTRY_AUTH_HTPASSWD_REALM=Registry Realm" \
  -e "REGISTRY_AUTH_HTPASSWD_PATH=/auth/htpasswd" \
  registry:2
```

```bash
# 如果使用自签名证书，客户端需要信任它
# 在每个 Docker 客户端上执行：

# 创建证书目录（注意目录名的格式）
mkdir -p /etc/docker/certs.d/registry.example.com:5000/

# 复制 CA 证书
cp domain.crt /etc/docker/certs.d/registry.example.com:5000/ca.crt

# 现在客户端就可以正常 push/pull 了
docker login registry.example.com:5000
docker push registry.example.com:5000/myapp:v1
```

> **Warning:** 如果你在内网环境中使用自签名证书，千万别忘了在每个需要拉取镜像的节点上配置 `ca.crt`。在 Swarm 或 K8s 集群中，这意味着你需要在**每个节点**上都配置。否则节点会因为证书不信任而无法拉取镜像，报错信息通常是 `x509: certificate signed by unknown authority`。

## 15.5 使用 Docker Compose 管理 Registry

把所有配置整合到 Compose 文件中，更方便管理：

```yaml
# docker-compose.yml
# 私有 Registry 完整部署配置

version: '3.8'

services:
  registry:
    image: registry:2
    container_name: docker-registry
    restart: always
    ports:
      - "5000:5000"
    environment:
      # 存储配置
      REGISTRY_STORAGE_FILESYSTEM_ROOTDIRECTORY: /var/lib/registry
      REGISTRY_STORAGE_DELETE_ENABLED: "true"
      # 允许删除镜像标签

      # HTTP 配置
      REGISTRY_HTTP_ADDR: "0.0.0.0:5000"

      # TLS 配置
      REGISTRY_HTTP_TLS_CERTIFICATE: /certs/domain.crt
      REGISTRY_HTTP_TLS_KEY: /certs/domain.key

      # 认证配置
      REGISTRY_AUTH: htpasswd
      REGISTRY_AUTH_HTPASSWD_REALM: "Registry Realm"
      REGISTRY_AUTH_HTPASSWD_PATH: /auth/htpasswd

      # 日志配置
      REGISTRY_LOG_LEVEL: info
    volumes:
      - registry-data:/var/lib/registry
      - ./certs:/certs:ro
      - ./auth:/auth:ro
    healthcheck:
      test: ["CMD", "wget", "--spider", "-q", "https://localhost:5000/v2/"]
      interval: 30s
      timeout: 10s
      retries: 3
    networks:
      - registry-net

  # Registry Web UI（可选）
  registry-ui:
    image: joxit/docker-registry-ui:latest
    container_name: registry-ui
    restart: always
    ports:
      - "8080:80"
    environment:
      - REGISTRY_URL=https://registry:5000
      - SINGLE_REGISTRY=true
      - DELETE_IMAGES=true
      # 允许通过 UI 删除镜像
      - SHOW_CONTENT_DIGEST=true
      # 显示镜像的 digest 信息
    depends_on:
      - registry
    networks:
      - registry-net

volumes:
  registry-data:
    driver: local

networks:
  registry-net:
    driver: bridge
```

```bash
# 启动整个 Registry 服务
docker-compose up -d

# 查看日志
docker-compose logs -f registry
```

## 15.7 镜像推送与拉取完整流程

```bash
#!/bin/bash
# push-image.sh
# 完整的镜像推送脚本

set -e
# 遇到错误立即退出

# ====== 配置 ======
REGISTRY="registry.example.com:5000"
PROJECT="myteam"
IMAGE_NAME="myapp"
TAG="${1:-latest}"
# 如果没有传入参数，默认使用 latest

FULL_IMAGE_NAME="${REGISTRY}/${PROJECT}/${IMAGE_NAME}:${TAG}"

# ====== 登录 Registry ======
echo "🔐 登录 Registry..."
docker login ${REGISTRY}

# ====== 构建镜像 ======
echo "🔨 构建镜像..."
docker build -t ${FULL_IMAGE_NAME} .

# ====== 安全扫描 ======
echo "🔍 安全扫描..."
docker scan ${FULL_IMAGE_NAME} || echo "扫描完成（可能有警告）"

# ====== 推送镜像 ======
echo "📤 推送镜像..."
docker push ${FULL_IMAGE_NAME}

# 同时打上 latest 标签
docker tag ${FULL_IMAGE_NAME} ${REGISTRY}/${PROJECT}/${IMAGE_NAME}:latest
docker push ${REGISTRY}/${PROJECT}/${IMAGE_NAME}:latest

# ====== 验证 ======
echo "✅ 推送成功！"
echo "镜像地址: ${FULL_IMAGE_NAME}"
echo "Digest: $(docker inspect --format='{{index .RepoDigests 0}}' ${FULL_IMAGE_NAME})"
```

```bash
#!/bin/bash
# pull-and-deploy.sh
# 完整的拉取和部署脚本

set -e

REGISTRY="registry.example.com:5000"
PROJECT="myteam"
IMAGE_NAME="myapp"
TAG="${1:-latest}"
CONTAINER_NAME="myapp"

FULL_IMAGE_NAME="${REGISTRY}/${PROJECT}/${IMAGE_NAME}:${TAG}"

echo "📥 拉取镜像 ${FULL_IMAGE_NAME}..."
docker pull ${FULL_IMAGE_NAME}

echo "🔄 停止旧容器..."
docker stop ${CONTAINER_NAME} 2>/dev/null || true
docker rm ${CONTAINER_NAME} 2>/dev/null || true

echo "🚀 启动新容器..."
docker run -d \
  --name ${CONTAINER_NAME} \
  --restart=always \
  -p 3000:3000 \
  -e NODE_ENV=production \
  ${FULL_IMAGE_NAME}

echo "🏥 健康检查..."
sleep 3
curl -f http://localhost:3000/health && echo " ✅ 服务正常" || echo " ❌ 服务异常"
```

## 15.8 Harbor：企业级 Registry

当你需要的是一个公司级别的 Registry，而不只是一个简单的镜像仓库时，[Harbor](https://goharbor.io/) 就是你要找的工具。Harbor 是 CNCF 毕业项目（和 Kubernetes 同级），功能远比 `registry:2` 丰富。

Harbor 的核心功能：

```bash
┌────────────────────────────────────────────────────┐
│                  Harbor 核心功能                     │
├────────────────────────────────────────────────────┤
│                                                     │
│  1. 镜像签名与验证（Notary/ Cosign）                │
│     → 确保镜像未被篡改                              │
│                                                     │
│  2. 漏洞扫描（Trivy / Clair 集成）                  │
│     → 推送时自动扫描，阻止有漏洞的镜像部署           │
│                                                     │
│  3. 基于角色的访问控制（RBAC）                       │
│     → 不同团队看到不同的项目，不同角色有不同权限     │
│                                                     │
│  4. 镜像复制（Replication）                          │
│     → 多数据中心之间的镜像同步                       │
│                                                     │
│  5. 垃圾回收（Garbage Collection）                   │
│     → 自动清理不再被引用的镜像层                    │
│                                                     │
│  6. Web UI 管理界面                                  │
│     → 可视化管理项目、用户、镜像                    │
│                                                     │
│  7. 审计日志                                        │
│     → 记录所有操作，满足合规要求                     │
│                                                     │
└────────────────────────────────────────────────────┘
```

```yaml
# harbor.yml（简化版）

hostname: harbor.example.com

https:
  port: 443
  certificate: /etc/harbor/certs/domain.crt
  private_key: /etc/harbor/certs/domain.key

# 管理员初始密码
harbor_admin_password: Change_Me_123!
# 请在安装后立即修改！

# 数据存储

  ignore_unfixed: false
  skip_update: false

# 垃圾回收（定时清理）

  max_job_workers: 10

# 日志
log:
  level: info
  local:
    rotate_count: 50
    rotate_size: 200M
    location: /var/log/harbor
```

## 15.9 实战：搭建一个带认证的私有 Registry

让我们从零搭建一个可用于生产的私有 Registry：

```bash
#!/bin/bash
# setup-registry.sh
# 一键搭建带认证和 TLS 的私有 Registry

set -e

REGISTRY_DOMAIN="registry.mycompany.com"
REGISTRY_PORT="5000"

echo "===== 步骤 1/5：创建目录结构 ====="
mkdir -p registry-setup/{auth,certs,data}

echo "===== 步骤 2/5：生成 TLS 证书 ====="
# 生成自签名证书（生产环境请使用正式证书）
openssl req -newkey rsa:4096 -nodes \
  -keyout registry-setup/certs/domain.key \
  -x509 -days 365 \
  -out registry-setup/certs/domain.crt \
  -subj "/CN=${REGISTRY_DOMAIN}" \
  -addext "subjectAltName=DNS:${REGISTRY_DOMAIN}"

echo "===== 步骤 3/5：创建认证文件 ====="
# 创建管理员账户
docker run --rm \
  --entrypoint htpasswd \
  httpd:2-alpine \
  -Bbn admin "Admin@2024" > registry-setup/auth/htpasswd

# 创建开发者账户
docker run --rm \
  --entrypoint htpasswd \
  httpd:2-alpine \
  -Bbn developer "Dev@2024" >> registry-setup/auth/htpasswd

echo "===== 步骤 4/5：编写 docker-compose.yml ====="
cat > registry-setup/docker-compose.yml << 'COMPOSE'
version: '3.8'

services:
  registry:
    image: registry:2
    restart: always
    ports:
      - "5000:5000"
    environment:
      REGISTRY_STORAGE_FILESYSTEM_ROOTDIRECTORY: /var/lib/registry
      REGISTRY_STORAGE_DELETE_ENABLED: "true"
      REGISTRY_HTTP_ADDR: "0.0.0.0:5000"
      REGISTRY_HTTP_TLS_CERTIFICATE: /certs/domain.crt
      REGISTRY_HTTP_TLS_KEY: /certs/domain.key
      REGISTRY_AUTH: htpasswd
      REGISTRY_AUTH_HTPASSWD_REALM: "Private Registry"
      REGISTRY_AUTH_HTPASSWD_PATH: /auth/htpasswd
    volumes:
      - ./data:/var/lib/registry
      - ./certs:/certs:ro
      - ./auth:/auth:ro

  registry-ui:
    image: joxit/docker-registry-ui:latest
    restart: always
    ports:
      - "8080:80"
    environment:
      - REGISTRY_URL=https://registry:5000
      - DELETE_IMAGES=true
      - SHOW_CONTENT_DIGEST=true
    depends_on:
      - registry
COMPOSE

echo "===== 步骤 5/5：启动服务 ====="
cd registry-setup
docker-compose up -d

echo ""
echo "✅ Registry 搭建完成！"
echo "📦 Registry: https://${REGISTRY_DOMAIN}:${REGISTRY_PORT}"
echo "🖥️  Web UI:    http://${REGISTRY_DOMAIN}:8080"
echo ""
echo "用户信息："
echo "  管理员 - admin / Admin@2024"
echo "  开发者 - developer / Dev@2024"
echo ""
echo "客户端配置（在每个 Docker 节点上执行）："
echo "  mkdir -p /etc/docker/certs.d/${REGISTRY_DOMAIN}:${REGISTRY_PORT}/"
echo "  cp certs/domain.crt /etc/docker/certs.d/${REGISTRY_DOMAIN}:${REGISTRY_PORT}/ca.crt"
```

## 15.10 镜像垃圾回收（Garbage Collection）

随着你不断推送镜像，Registry 的存储空间会越来越大。虽然你删除了某个 tag，但底层的镜像层（blob）并不会自动删除——就像你删了一个文件的快捷方式，文件本身还在硬盘上。

```bash
# 查看 Registry 占用的磁盘空间
docker exec registry-secure du -sh /var/lib/registry

# 运行垃圾回收（需要先停止 Registry 或使用只读模式）
# 方式1：停止 Registry 后运行 GC
docker stop registry-secure

docker run --rm \
  -v registry-data:/var/lib/registry \
  registry:2 \
  /bin/registry garbage-collect /etc/docker/registry/config.yml
  # garbage-collect 会扫描所有 blob
  # 删除没有被任何 manifest 引用的 blob
  # 就像 Python 的引用计数 GC 一样：
  # 没有任何引用的对象（镜像层）会被回收

docker start registry-secure

# 方式2：在运行中的 Registry 上开启在线 GC（Registry 2.8+）
# 在配置文件中添加：
# storage:
#   maintenance:
#     uploadpurging:
#       enabled: true
#       age: 168h    # 清理 7 天前的未完成上传
#       interval: 24h
#       dryrun: false
```

```bash
# 删除特定的镜像标签
# 需要先开启 REGISTRY_STORAGE_DELETE_ENABLED

# 获取镜像的 digest
DIGEST=$(curl -s -u admin:Admin@2024 \
  -H "Accept: application/vnd.docker.distribution.manifest.v2+json" \
  https://registry.example.com:5000/v2/myteam/myapp/manifests/v1.0.0 \
  -I | grep -i 'docker-content-digest' | awk '{print $2}' | tr -d '\r')

# 删除镜像
curl -X DELETE -u admin:Admin@2024 \
  https://registry.example.com:5000/v2/myteam/myapp/manifests/${DIGEST}

# 运行 GC 清理实际的 blob
docker exec registry-secure \
  /bin/registry garbage-collect /etc/docker/registry/config.yml
```

> [!TIP] 提示
> 垃圾回收就像你整理衣柜——你不穿的旧衣服（不再被引用的镜像层）还占着空间。定期运行 GC 可以回收大量存储空间。建议设置一个 cron job，每周日凌晨低峰期自动运行。

| 概念 | 说明 |
|------|------|
| Docker Hub | 公共 Registry，有拉取限制，不适合存储私有镜像 |
| registry:2 | Docker 官方轻量级 Registry 实现 |
| HTTP Basic Auth | 基于 htpasswd 的简单认证，适合大多数场景 |
| TLS/SSL | 生产环境必须启用，保护镜像数据传输安全 |
| Harbor | 企业级 Registry，支持 RBAC、漏洞扫描、镜像复制 |
| 垃圾回收 | 清理不再被引用的镜像层，释放存储空间 |

## 练习

1. **入门**：使用 `registry:2` 搭建一个本地私有 Registry，推送和拉取一个镜像验证工作正常。
2. **进阶**：为 Registry 添加 HTTPS 和 Basic Auth 认证，确保只有登录用户才能推送和拉取。
3. **挑战**：搭建 Harbor，创建一个项目，配置镜像复制规则将镜像同步到另一个 Harbor 实例。
