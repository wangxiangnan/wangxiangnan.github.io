# 第18章：下载工具与 API 调试

## 18.1 为什么命令行需要下载和调 API？

在图形界面里，你下载文件用浏览器，调 API 用 Postman。但在服务器上呢？没有浏览器，没有 GUI——你只有命令行。好消息是：命令行的下载和 API 调试工具比图形界面更强大、更灵活，而且可以写进脚本实现自动化。

## 18.2 curl：HTTP 的万能遥控器

`curl`（Client URL）是命令行世界最强大的 HTTP 工具，没有之一。它支持几乎所有网络协议，但最常用的是 HTTP/HTTPS。

```bash
# 最基本的 GET 请求
curl https://example.com
# 输出网页 HTML 内容

# 只看响应头（-I = HEAD 请求）
curl -I https://example.com
# HTTP/2 200
# content-type: text/html
# content-length: 1256
# server: nginx/1.18.0
# date: Mon, 01 Jan 2024 00:00:00 GMT

# 同时显示响应头和响应体
curl -i https://example.com

# 详细调试模式（显示完整的请求/响应过程）
curl -v https://example.com
# * Connected to example.com (93.184.216.34) port 443
# > GET / HTTP/2
# > Host: example.com
# > User-Agent: curl/7.81.0
# > Accept: */*
# < HTTP/2 200
# < content-type: text/html

# 保存响应到文件
curl -o output.html https://example.com
# 或用原始文件名
curl -O https://example.com/file.tar.gz

# 下载文件并显示进度条
curl -# -O https://example.com/large-file.iso

# POST 请求（发送表单数据）
curl -X POST https://api.example.com/users \
  -d "name=Alice&email=alice@example.com"

# POST JSON 数据（API 调用最常用！）
curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d '{"name": "Alice", "email": "alice@example.com"}'

# PUT 请求（更新资源）
curl -X PUT https://api.example.com/users/1 \
  -H "Content-Type: application/json" \
  -d '{"name": "Alice Updated"}'

# DELETE 请求（删除资源）
curl -X DELETE https://api.example.com/users/1

# 带认证信息的请求
# Basic Auth
curl -u username:password https://api.example.com/data

# Bearer Token（JWT 等）
curl -H "Authorization: Bearer your-token-here" https://api.example.com/data

# API Key
curl -H "X-API-Key: your-api-key" https://api.example.com/data

# 自定义请求头
curl -H "User-Agent: MyApp/1.0" \
  -H "Accept: application/json" \
  -H "X-Custom-Header: value" \
  https://api.example.com/data

# 跟随重定向（-L 非常重要！很多 API 会重定向）
curl -L https://github.com
# 不加 -L 只会返回 301/302，不会自动跳转到新地址

# Cookie 处理
curl -c cookies.txt https://example.com/login   # 保存 Cookie 到文件
curl -b cookies.txt https://example.com/dashboard  # 使用保存的 Cookie

# 超时设置
curl --connect-timeout 10 --max-time 30 https://api.example.com/slow
# --connect-timeout → 连接超时 10 秒
# --max-time        → 总超时 30 秒

# 重试机制
curl --retry 3 --retry-delay 2 --retry-max-time 60 https://api.example.com/data
# 失败后重试 3 次，每次间隔 2 秒，最多 60 秒

# 只获取响应状态码（API 健康检查常用）
curl -s -o /dev/null -w "%{http_code}" https://api.example.com/health
# 200

# 查看请求耗时
curl -o /dev/null -s -w "DNS: %{time_namelookup}s\nConnect: %{time_connect}s\nTLS: %{time_appconnect}s\nTotal: %{time_total}s\n" https://example.com

# 强制使用 IPv4 或 IPv6
curl -4 https://example.com    # 强制 IPv4
curl -6 https://example.com    # 强制 IPv6

# 使用代理
curl -x http://proxy:8080 https://example.com
curl --socks5 localhost:1080 https://example.com   # 通过 SSH SOCKS 代理
```

## 18.3 wget：下载利器

```bash
# wget 专注于文件下载（不支持发送复杂 HTTP 请求）
# 但下载功能比 curl 更方便

# 基本下载
wget https://example.com/file.tar.gz

# 指定输出文件名
wget -O custom-name.tar.gz https://example.com/file.tar.gz

# 断点续传（下载到一半断了，继续下！）
wget -c https://example.com/large-file.iso
# -c → continue，从断点继续

# 后台下载（大文件场景）
wget -b https://example.com/large-file.iso
# 下载日志写入 wget-log
tail -f wget-log    # 查看下载进度

# 递归下载整个网站（镜像网站！）
wget -r -l 2 -k -p https://example.com
# -r → 递归
# -l 2 → 深度 2 层
# -k → 转换链接为本地链接
# -p → 下载显示页面所需的所有文件（CSS、图片等）

# 安静模式（不显示进度条，适合脚本）
wget -q https://example.com/file.tar.gz

# 限速下载（避免占满带宽）
wget --limit-rate=5m https://example.com/large-file.iso
# 5m = 5 MB/s

# 下载多个文件
wget -i urls.txt
# urls.txt 每行一个 URL

# 带认证的下载
wget --user=username --password=password https://example.com/private/file

# 忽略 SSL 证书错误（自签名证书场景）
wget --no-check-certificate https://self-signed.example.com/file

# 用 wget 做简单的 API 健康检查
wget -q --spider https://api.example.com/health
# --spider → 只检查 URL 是否可访问（不下载内容）
# 返回 0 = 正常，非 0 = 有问题
echo $?    # 0 = 成功
```

## 18.4 curl vs wget

```bash
# | 特性           | curl                      | wget                     |
# |---------------|---------------------------|--------------------------|
# | 定位           | HTTP 客户端（请求+响应）     | 文件下载工具               |
# | GET 请求       | ✅ 完美                    | ✅ 可以                   |
# | POST/PUT/DEL   | ✅ 完美                    | ❌ 有限支持               |
# | 自定义 Header  | ✅ 完美                    | ⚠️ 有限                  |
# | 断点续传       | ✅ -C -                    | ✅ -c                    |
# | 递归下载       | ❌ 不支持                   | ✅ -r                    |
# | 管道友好       | ✅ 输出到 stdout            | ⚠️ 默认输出到文件         |
# | 协议支持       | HTTP/FTP/SMTP/IMAP...     | HTTP/FTP                 |
# | 脚本中使用     | ✅ 首选                    | ⚠️ 适合纯下载场景         |
#
# 选择建议：
# - 调试 API、发送请求、检查服务 → curl
# - 下载文件、镜像网站 → wget
# - 写脚本 → 看具体需求
```

## 18.5 HTTPie：更人性化的 HTTP 客户端

```bash
  name=Alice \

# 下载文件

# 会话管理（自动保持 Cookie）
http --session=myapi POST https://api.example.com/login username=admin password=secret
http --session=myapi GET https://api.example.com/dashboard    # 自动带上 Cookie
```

## 18.6 jq：JSON 处理神器

```bash
# API 返回的 JSON 数据在命令行里怎么解析？用 jq！
sudo apt install jq -y

# 格式化 JSON（美化输出）
echo '{"name":"Alice","age":30,"skills":["Python","Go"]}' | jq .
# {
#   "name": "Alice",
#   "age": 30,
#   "skills": [
#     "Python",
#     "Go"
#   ]
# }

# 提取字段
echo '{"name":"Alice","age":30}' | jq '.name'
# "Alice"

# 提取字段（纯文本，不带引号）
echo '{"name":"Alice","age":30}' | jq -r '.name'
# Alice

# 提取数组元素
echo '{"users":[{"name":"Alice"},{"name":"Bob"}]}' | jq '.users[0].name'
# "Alice"

# 遍历数组
echo '{"users":[{"name":"Alice"},{"name":"Bob"}]}' | jq '.users[].name'
# "Alice"
# "Bob"

# 过滤数组
echo '{"users":[{"name":"Alice","age":30},{"name":"Bob","age":25}]}' | \
  jq '.users[] | select(.age > 28)'
# {"name":"Alice","age":30}

# 构造新对象
echo '{"users":[{"name":"Alice","age":30},{"name":"Bob","age":25}]}' | \
  jq '.users[] | {username: .name, is_senior: (.age > 28)}'
# {"username":"Alice","is_senior":true}
# {"username":"Bob","is_senior":false}

# 统计数组长度
echo '{"users":[{"name":"Alice"},{"name":"Bob"}]}' | jq '.users | length'
# 2

# 提取所有键
echo '{"name":"Alice","age":30}' | jq 'keys'
# ["age","name"]

# 配合 curl 使用（最常见的组合！）
curl -s https://api.github.com/repos/torvalds/linux | jq '{name, stars: .stargazers_count, language}'
# {
#   "name": "linux",
#   "stars": 170000,
#   "language": "C"
# }

# 获取 GitHub 仓库列表
curl -s "https://api.github.com/users/torvalds/repos" | jq -r '.[].name'

# 处理 JSON 数组的 map 操作
echo '[1,2,3,4,5]' | jq 'map(. * 2)'
# [2,4,6,8,10]

# 分组和排序
echo '{"items":[{"name":"A","price":10},{"name":"B","price":5}]}' | \
  jq '.items | sort_by(.price)'

# 从文件读取 JSON
jq '.users[] | .name' data.json

# jq 实用脚本：监控 API 返回状态
while true; do
  status=$(curl -s https://api.example.com/health | jq -r '.status')
  if [ "$status" != "ok" ]; then
    echo "[$(date)] API 异常: $status"
  fi
  sleep 30
done
```

## 18.7 REST API 调试工作流

```bash
# 完整的 API 调试流程示例（以 GitHub API 为例）

# Step 1: 检查 API 是否可达
curl -s -o /dev/null -w "%{http_code}" https://api.github.com
# 200 → API 正常

# Step 2: 查看 API 响应头（了解限速、缓存等信息）
curl -I https://api.github.com/users/torvalds
# x-ratelimit-limit: 60         ← 限速：60 次/小时（未认证）
# x-ratelimit-remaining: 58     ← 还剩 58 次
# x-ratelimit-reset: 1704067200 ← 限速重置时间

# Step 3: 发送 GET 请求
curl -s https://api.github.com/users/torvalds | jq '{login, name, public_repos}'

# Step 4: 发送 POST 请求（需要认证）
curl -s -X POST https://api.github.com/repos/torvalds/linux/forks \
  -H "Authorization: token ghp_xxxx" \
  -H "Accept: application/vnd.github.v3+json" | jq .

# Step 5: 带分页的请求
curl -s "https://api.github.com/users/torvalds/repos?per_page=5&page=1" | \
  jq -r '.[].name'

# Step 6: 错误排查
# 401 → Token 过期或无效
# 403 → 权限不足或触达限速
# 404 → 资源不存在（或没权限看）
# 422 → 请求参数有误

# 实用的 API 测试脚本
cat > api-test.sh << 'SCRIPT'
#!/bin/bash
API_BASE="https://api.example.com"
TOKEN="your-token-here"

# 创建用户
echo "=== Creating user ==="
RESPONSE=$(curl -s -X POST "$API_BASE/users" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"name":"TestUser","email":"test@example.com"}')
echo "$RESPONSE" | jq .
USER_ID=$(echo "$RESPONSE" | jq -r '.id')

# 获取用户
echo "=== Getting user $USER_ID ==="
curl -s "$API_BASE/users/$USER_ID" \
  -H "Authorization: Bearer $TOKEN" | jq .

# 更新用户
echo "=== Updating user ==="
curl -s -X PUT "$API_BASE/users/$USER_ID" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"name":"UpdatedUser"}' | jq .

# 删除用户
echo "=== Deleting user ==="
HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" \
  -X DELETE "$API_BASE/users/$USER_ID" \
  -H "Authorization: Bearer $TOKEN")
echo "Delete status: $HTTP_CODE"
SCRIPT
chmod +x api-test.sh
```

## 18.8 curl 高级用法与脚本模式

```bash
# 1. curl 批量请求（循环调用 API）
for id in $(seq 1 100); do
    echo "Fetching user $id..."
    curl -s "https://api.example.com/users/$id" | jq -r '.name'
    sleep 0.5    # 别太快，小心被限速
done

# 2. 并发请求（用 xargs 或 GNU parallel）
# 方法 A：xargs 并发
seq 1 50 | xargs -P 10 -I {} sh -c '
    curl -s "https://api.example.com/users/{}" | jq -r "[.id, .name] | @tsv"
'

# 方法 B：后台进程 + wait
for id in $(seq 1 20); do
    curl -s "https://api.example.com/users/$id" \
        -o "user_$id.json" &
done
wait    # 等待所有后台任务完成
echo "全部下载完成"

# 3. curl 配合 jq 做数据处理管道
curl -s "https://api.github.com/repos/torvalds/linux/contributors?per_page=10" | \
    jq -r '.[] | "\(.login)\t\(.contributions)"' | \
    sort -t$'\t' -k2 -rn | head -5
# 输出 Linux 内核贡献最多的 5 个开发者

# 4. API 健康检查脚本
cat > ~/api-health.sh << 'SCRIPT'
#!/bin/bash
ENDPOINTS=(
    "https://api.example.com/health"
    "https://api.example.com/v1/status"
    "https://api.example.com/v2/status"
)

ALERT_THRESHOLD=2    # 连续失败 2 次告警
STATUS_FILE="/tmp/api-health-status"

for endpoint in "${ENDPOINTS[@]}"; do
    HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" \
        --connect-timeout 5 --max-time 10 "$endpoint")

    PREV_FAIL=$(grep -c "$endpoint" "$STATUS_FILE" 2>/dev/null || echo 0)

    if [ "$HTTP_CODE" -ge 200 ] && [ "$HTTP_CODE" -lt 400 ]; then
        echo "[✅ OK] $endpoint ($HTTP_CODE)"
        sed -i "\|$endpoint|d" "$STATUS_FILE" 2>/dev/null
    else
        FAIL_COUNT=$((PREV_FAIL + 1))
        echo "$endpoint" >> "$STATUS_FILE"
        if [ "$FAIL_COUNT" -ge "$ALERT_THRESHOLD" ]; then
            echo "[🚨 ALERT] $endpoint 连续失败 $FAIL_COUNT 次！($HTTP_CODE)"
            # 这里可以发邮件/钉钉/企业微信通知
        else
            echo "[⚠️ WARN] $endpoint ($HTTP_CODE) 失败 $FAIL_COUNT 次"
        fi
    fi
done
SCRIPT
chmod +x ~/api-health.sh

# 5. 文件上传（multipart/form-data）
curl -F "file=@/path/to/report.pdf" https://api.example.com/upload

# 多个文件
curl -F "file1=@report.pdf" -F "file2=@data.csv" https://api.example.com/upload

# 带额外字段
curl -F "file=@photo.jpg" -F "description=My photo" -F "tags=nature" \
    https://api.example.com/upload

# 6. curl 的 URL 模板（批量下载）
curl -O "https://example.com/images/[1-10].jpg"
# 下载 image-1.jpg 到 image-10.jpg

curl -O "https://example.com/page_{01,02,03,04,05}.html"
# 下载 page_01.html 到 page_05.html

# 7. 带详细计时信息的请求（性能分析）
curl -o /dev/null -s -w '
     DNS Lookup: %{time_namelookup}s
    TCP Connect: %{time_connect}s
    TLS Handshake: %{time_appconnect}s
  First Byte (TTFB): %{time_starttransfer}s
         Total: %{time_total}s
   Download Size: %{size_download} bytes
    Speed: %{speed_download} bytes/s
' https://example.com
```

## 18.10 Web Scraping 与数据处理

```bash
# 用 curl + 命令行工具做简单的网页数据提取

# 1. 提取网页中的所有链接
curl -s https://example.com | grep -oP 'href="\K[^"]+' | head -20

# 2. 提取网页标题
curl -s https://example.com | grep -oP '<title>\K[^<]+'

# 3. 下载网页中的所有图片
mkdir -p images
curl -s https://example.com | grep -oP 'src="\K[^"]+\.(jpg|png|gif|webp)' | \
    while read url; do
        wget -P images/ "https://example.com/$url" 2>/dev/null
    done

# 4. 检查死链（链接是否可达）
cat > ~/check-links.sh << 'SCRIPT'
#!/bin/bash
URL=$1
if [ -z "$URL" ]; then
    echo "Usage: $0 <url>"
    exit 1
fi

echo "=== 检查 $URL 中的链接 ==="
curl -s "$URL" | grep -oP 'href="\Khttps?://[^"]+' | sort -u | while read link; do
    CODE=$(curl -s -o /dev/null -w "%{http_code}" --max-time 5 "$link")
    if [ "$CODE" -ge 400 ]; then
        echo "❌ $CODE $link"
    else
        echo "✅ $CODE $link"
    fi
done
SCRIPT
chmod +x ~/check-links.sh

# 5. API 数据导出为 CSV
curl -s "https://api.example.com/users?page=1&per_page=100" | \
    jq -r '.[] | [.id, .name, .email, .created_at] | @csv' > users.csv

# 6. 多页数据爬取
cat > ~/api-paginate.sh << 'SCRIPT'
#!/bin/bash
BASE_URL="https://api.example.com/items"
PAGE=1
ALL_DATA="[]"

while true; do
    echo "Fetching page $PAGE..."
    RESPONSE=$(curl -s "$BASE_URL?page=$PAGE&per_page=50")
    COUNT=$(echo "$RESPONSE" | jq '.data | length')

    if [ "$COUNT" -eq 0 ]; then
        break
    fi

    ALL_DATA=$(echo "$ALL_DATA" "$RESPONSE" | jq -s '.[0] + .[1].data')
    PAGE=$((PAGE + 1))
    sleep 1    # 尊重 API 限速
done

echo "$ALL_DATA" | jq '.' > all_items.json
echo "共获取 $(echo "$ALL_DATA" | jq 'length') 条数据"
SCRIPT
chmod +x ~/api-paginate.sh
```

## 18.11 jq 进阶：复杂 JSON 处理

```bash
# jq 不只是简单的 JSON 提取器——它是一个完整的 JSON 编程语言

# 1. 条件过滤（找出满足条件的元素）
echo '{"servers":[{"name":"web1","cpu":85},{"name":"web2","cpu":45},{"name":"web3","cpu":92}]}' | \
    jq '.servers[] | select(.cpu > 80) | .name'
# "web1"
# "web3"

# 2. 对象合并
echo '{"a":1,"b":2}' | jq '. + {"c":3}'
# {"a":1,"b":2,"c":3}

# 3. 数组聚合函数
echo '[10,20,30,40,50]' | jq '{sum: add, avg: (add/length), min: min, max: max}'
# {"sum":150,"avg":30,"min":10,"max":50}

# 4. 字符串操作
echo '{"name":"hello world"}' | jq '.name | ascii_upcase'
# "HELLO WORLD"
echo '{"name":"HELLO"}' | jq '.name | ascii_downcase'
# "hello"
echo '{"name":"hello world"}' | jq '.name | split(" ") | .[0]'
# "hello"

# 5. 类型转换
echo '{"count":"42"}' | jq '.count | tonumber'
# 42
echo '{"count":42}' | jq '.count | tostring'
# "42"

# 6. 嵌套 JSON 展开（flatten）
echo '{"a":{"b":{"c":1},"d":2},"e":3}' | jq '[path(..)]'
# 显示所有路径

# 7. 条件赋值（if-then-else）
echo '{"users":[{"name":"Alice","role":"admin"},{"name":"Bob","role":"user"}]}' | \
    jq '.users[] | {name, level: (if .role == "admin" then "high" else "normal" end)}'

# 8. reduce（累加器）
echo '[1,2,3,4,5]' | jq 'reduce .[] as $x (0; . + $x)'
# 15

# 9. 格式化输出为表格
echo '{"users":[{"id":1,"name":"Alice","email":"alice@example.com"},{"id":2,"name":"Bob","email":"bob@example.com"}]}' | \
    jq -r '.users[] | [.id, .name, .email] | @tsv'
# 1    Alice    alice@example.com
# 2    Bob      bob@example.com

# 10. 处理大型 JSON（流式处理）
# 对于超大 JSON 文件，用 --stream 模式
jq --stream -n 'fromstream(1|truncate_stream(inputs))' large-file.json

# 11. 生成 JSON（从命令行构建）
jq -n \
  --arg name "Alice" \
  --argjson age 30 \
  --argjson skills '["Python","Go","Rust"]' \
  '{name: $name, age: $age, skills: $skills}'
# {"name":"Alice","age":30,"skills":["Python","Go","Rust"]}

# 12. 比较两个 JSON 的差异
# 方法：用 jd 工具（需要安装）
# sudo apt install jd
# jd file1.json file2.json

# 或用 jq 简单对比
diff <(jq -S . file1.json) <(jq -S . file2.json)
# -S 排序键名，方便 diff 比较
```

## 18.12 实用下载场景

```bash
# 场景 1：下载 GitHub Release 最新版本
cat > ~/gh-download.sh << 'SCRIPT'
#!/bin/bash
# 用法: gh-download.sh owner repo [asset-pattern]
OWNER=$1
REPO=$2
PATTERN=${3:-".tar.gz"}

if [ -z "$OWNER" ] || [ -z "$REPO" ]; then
    echo "Usage: $0 <owner> <repo> [asset-pattern]"
    echo "Example: $0 cli cli linux_amd64.tar.gz"
    exit 1
fi

# 获取最新 release 的下载链接
URL=$(curl -s "https://api.github.com/repos/$OWNER/$REPO/releases/latest" | \
    jq -r ".assets[] | select(.name | test(\"$PATTERN\")) | .browser_download_url" | head -1)

if [ -z "$URL" ] || [ "$URL" = "null" ]; then
    echo "未找到匹配的资产"
    exit 1
fi

echo "下载: $URL"
wget -O "$(basename $URL)" "$URL"
SCRIPT
chmod +x ~/gh-download.sh

# 场景 2：批量下载带进度显示
cat > ~/batch-download.sh << 'SCRIPT'
#!/bin/bash
URL_FILE=$1
OUTPUT_DIR=${2:-downloads}

if [ -z "$URL_FILE" ]; then
    echo "Usage: $0 <url-file> [output-dir]"
    exit 1
fi

mkdir -p "$OUTPUT_DIR"
TOTAL=$(wc -l < "$URL_FILE")
CURRENT=0

while read url; do
    [ -z "$url" ] && continue
    CURRENT=$((CURRENT + 1))
    FILENAME=$(basename "$url")
    echo "[$CURRENT/$TOTAL] $FILENAME"
    wget -q --show-progress -P "$OUTPUT_DIR" "$url" 2>&1 | \
        awk -v c="$CURRENT" -v t="$TOTAL" '/[0-9]+%/ {printf "  进度: %s\n", $0}'
done < "$URL_FILE"

echo "下载完成！文件在 $OUTPUT_DIR/"
SCRIPT
chmod +x ~/batch-download.sh
```

## 18.13 API 环境变量管理

```bash
# 管理多环境 API 配置（开发/测试/生产）

# 创建环境配置文件
mkdir -p ~/.api-env

cat > ~/.api-env/dev.env << 'EOF'
API_BASE=https://api-dev.example.com
API_TOKEN=dev-token-xxxx
API_VERSION=v1
EOF

cat > ~/.api-env/staging.env << 'EOF'
API_BASE=https://api-staging.example.com
API_TOKEN=staging-token-xxxx
API_VERSION=v2
EOF

cat > ~/.api-env/prod.env << 'EOF'
API_BASE=https://api.example.com
API_TOKEN=prod-token-xxxx
API_VERSION=v2
EOF

# 环境切换函数（加到 ~/.bashrc）
api_env() {
    local env=$1
    if [ -f "$HOME/.api-env/$env.env" ]; then
        source "$HOME/.api-env/$env.env"
        echo "已切换到 $env 环境"
        echo "  API_BASE: $API_BASE"
        echo "  API_VERSION: $API_VERSION"
    else
        echo "环境 '$env' 不存在！"
        echo "可用环境: $(ls ~/.api-env/ | sed 's/.env//')"
    fi
}

# 使用：
# api_env dev        # 切换到开发环境
# api_env staging    # 切换到预发布环境
# api_env prod       # 切换到生产环境

# 然后直接用环境变量调用 API
curl -H "Authorization: Bearer $API_TOKEN" "$API_BASE/$API_VERSION/users"
```

## 18.14 常见坑与注意事项

```bash
# 坑 1：curl 不加 -L 不跟随重定向
# 很多 API 返回 301/302，不加 -L 你只看到重定向响应
curl -L https://api.example.com/redirected-endpoint

# 坑 2：JSON 中的引号转义
# 在 bash 中嵌套 JSON 时引号容易搞混
# 推荐：外层用单引号，内层用双引号
curl -d '{"key": "value"}' https://api.example.com

# 坑 3：curl -d 会改变请求方法
# curl -d "data" URL  会自动变成 POST
# curl -d "data" -X PUT URL  需要显式指定 PUT

# 坑 4：wget 的 -O 和 -o 区别
wget -O output.html URL    # 大写 O → 输出到指定文件
wget -o log.txt URL        # 小写 o → 日志输出到文件

# 坑 5：API 返回的 JSON 用 jq 处理而不是 grep
# ❌ curl API | grep "name"      → 容易误匹配
# ✅ curl API | jq '.name'       → 精确提取
```

## 18.9 本章小结

`curl` 是 HTTP 调试的万能工具，`wget` 是文件下载的行家里手，`jq` 让 JSON 处理变得优雅。三者组合起来，你可以在命令行里完成几乎所有 HTTP 相关的任务——从下载文件到调试 API，从监控服务到自动化脚本。

## 18.10 命令速查表

| 命令 | 用途 | 常用参数 |
| ------ | ------ | ---------- |
| `curl` | HTTP 客户端 | `-I` 头部、`-X` 方法、`-H` 头、`-d` 数据、`-L` 跟随重定向 |
| `wget` | 文件下载 | `-c` 续传、`-r` 递归、`-q` 安静、`--limit-rate` 限速 |
| `http` | HTTPie 客户端 | `GET/POST`、`-a` 认证、`-b` 仅body、`-h` 仅headers |
| `jq` | JSON 处理 | `.` 格式化、`-r` 纯文本、`.field` 提取、`select()` 过滤 |
