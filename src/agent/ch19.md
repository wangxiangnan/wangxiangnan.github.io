## 19.1 开篇：从"通用知识"到"私有知识"

在前面的章节中，DocMind 虽然能和用户对话，但它的知识完全来自于 LLM 的训练数据。但真实场景中，你的用户需要的是**他们自己的文档中的知识**：

- "我们公司的 API 接口文档是怎么写的？"
- "这份架构设计文档里提到的'事件驱动'是什么意思？"
- "上周新加的那个模块的 README 说了什么？"

这就是 RAG（Retrieval-Augmented Generation，检索增强生成）的价值所在。核心思想很简单：

```
1. 用户提问
2. 先从文档库中"检索"相关内容
3. 把检索到的内容作为"上下文"提供给 LLM
4. LLM 基于这些上下文生成回答
```

这个过程就像一个开卷考试——你不需要记住所有知识，只需要知道去哪里找。本章我们将学习 RAG 管线的四个关键环节：**加载、分割、嵌入存储、检索**。

### 19.2.3 DocMind 的多格式加载器

```python
# src/rag/loader.py
"""DocMind 文档加载模块"""
import os
from typing import List
from langchain_core.documents import Document
from langchain_community.document_loaders import (
    TextLoader, PyPDFLoader, CSVLoader, DirectoryLoader,
)

class DocMindLoader:
    """统一文档加载器"""
    LOADERS = {
        ".txt": TextLoader, ".md": TextLoader,
        ".pdf": PyPDFLoader, ".csv": CSVLoader,
    }
    
    @classmethod
    def load_file(cls, file_path: str) -> List[Document]:
        ext = os.path.splitext(file_path)[1].lower()
        if ext not in cls.LOADERS:
            raise ValueError(f"不支持的格式: {ext}")
        loader_cls = cls.LOADERS[ext]
        if loader_cls == TextLoader:
            loader = loader_cls(file_path, encoding="utf-8")
        else:
            loader = loader_cls(file_path)
        docs = loader.load()
        for doc in docs:
            doc.metadata["file_name"] = os.path.basename(file_path)
            doc.metadata["file_type"] = ext
        print(f"加载 {file_path}: {len(docs)} 个片段")
        return docs
    
    @classmethod
    def load_directory(cls, dir_path: str) -> List[Document]:
        all_docs = []
        for ext, loader_cls in cls.LOADERS.items():
            kwargs = {"loader_kwargs": {"encoding": "utf-8"}} if loader_cls == TextLoader else {}
            try:
                loader = DirectoryLoader(
                    dir_path, glob=f"**/*{ext}",
                    loader_cls=loader_cls, show_progress=True, **kwargs,
                )
                docs = loader.load()
                all_docs.extend(docs)
            except Exception as e:
                print(f"  加载 {ext} 出错: {e}")
        print(f"总共加载了 {len(all_docs)} 个文档片段")
        return all_docs
```

## 19.3 文本分割(Text Splitter)

### 19.3.1 为什么需要分割？

加载完文档后，你得到的是一个个"大文本块"。你不能把整个文档直接塞给 LLM，原因有三：

1. **上下文窗口限制** — 一篇长文档可能超出限制
2. **检索精度** — 需要找到最相关的那几段话
3. **Token 成本** — 发送越多 token，费用越高、速度越慢

### 19.3.2 RecursiveCharacterTextSplitter：最推荐的方式

这是 LangChain 中最常用、最推荐的文本分割器。策略是"递归地尝试多种分隔符"：

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,         # 目标块大小：1000 字符
    chunk_overlap=200,       # 重叠：200 字符
    length_function=len,
    separators=[
        "\n\n",   # 段落分隔
        "\n",     # 行分隔
        "\u3002", # 中文句号
        ". ",     # 英文句号
        "\uff0c", # 中文逗号
        ", ",     # 英文逗号
        " ",      # 空格
        "",       # 字符（最后的回退）
    ],
)

# 从 Document 对象分割
from langchain_core.documents import Document
docs = [Document(page_content="很长的文档..." * 50, metadata={"source": "test.md"})]
chunks = splitter.split_documents(docs)

print(f"原始文档数: {len(docs)}")
print(f"分割后块数: {len(chunks)}")
for i, chunk in enumerate(chunks[:3]):
    print(f"块 {i+1}: {len(chunk.page_content)} 字符, 元数据: {chunk.metadata}")
```

### 19.3.3 chunk_overlap：为什么需要重叠？

```
文档原文：
"LangChain 是构建 AI 应用的框架。它提供模型调用、文档检索等功能。其中，文档检索是 RAG 的核心。"

chunk_size=50, chunk_overlap=0:
块1: "LangChain 是构建 AI 应用的框架。"
块2: "它提供模型调用、文档检索等功能。"
块3: "其中，文档检索是 RAG 的核心。"
-> 块2 和 块3 各有一半答案，单独来看都不完整

chunk_size=50, chunk_overlap=20:
块1: "LangChain 是构建 AI 应用的框架。它提供模"
块2: "框架。它提供模型调用、文档检索等功能。其中"
块3: "文档检索等功能。其中，文档检索是 RAG 的核心。"
-> 块2 包含了完整的相关信息
```

### 19.3.5 分割参数调优

| chunk_size | 适用场景 | 优点 | 缺点 |
| ----------- | --------- | ------ | ------ |
| 200-500 | FAQ、短句问答 | 检索精度高 | 可能丢失上下文 |
| 500-1000 | 技术文档 | 平衡精度和上下文 | **推荐** |
| 1000-2000 | 长文章 | 保留更多上下文 | 检索精度下降 |
| 2000+ | 不推荐 | - | 超出 Embedding 最佳范围 |

> ⚠️ **chunk_overlap 经验法则**：设为 chunk_size 的 10%-20%。太小起不到"桥接"作用，太大会浪费存储和 token。

## 19.4 Embedding 模型集成

在第20章中，我们从理论层面理解了 Embedding。现在让我们使用它：

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

# 单个文本
vector = embeddings.embed_query("什么是 Python？")
print(f"向量维度: {len(vector)}")  # 1536 维

# 批量文本
vectors = embeddings.embed_documents([
    "什么是 Python？",
    "Python 是一种高级编程语言。",
    "今天天气真好。",
])

# 计算余弦相似度
import numpy as np
def cosine_similarity(v1, v2):
    return np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2))

print(f"'Python' vs '编程语言': {cosine_similarity(vectors[0], vectors[1]):.4f}")
print(f"'Python' vs '天气': {cosine_similarity(vectors[0], vectors[2]):.4f}")
# 语义相近的文本相似度更高
```

**Embedding 模型选择**：

| 模型 | 维度 | 价格 | 适用场景 |
| ------ | ------ | ------ | --------- |
| text-embedding-3-small | 1536 | 低 | 大多数场景（推荐） |
| text-embedding-3-large | 3072 | 中 | 更高精度需求 |
| nomic-embed-text (Ollama) | 768 | 免费 | 离线/预算有限 |

## 19.5 向量存储(Vector Store)：Chroma 详解

### 19.5.1 什么是向量存储？

向量存储是**专门为向量相似度搜索优化的数据库**。

- 传统数据库：`WHERE name = 'Python'`（精确匹配）
- 向量存储：`WHERE vector ~ query_vector`（语义近似匹配）

### 19.5.2 创建和使用 Chroma

```python
from langchain_chroma import Chroma
from langchain_openai import OpenAIEmbeddings
from langchain_core.documents import Document

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

docs = [
    Document(page_content="Python 是一种解释型、面向对象的高级编程语言。",
             metadata={"source": "python_intro.md", "topic": "python"}),
    Document(page_content="JavaScript 是一种主要用于 Web 开发的脚本语言。",
             metadata={"source": "js_intro.md", "topic": "javascript"}),
    Document(page_content="Docker 是一个容器化平台，用于打包和部署应用。",
             metadata={"source": "docker_intro.md", "topic": "docker"}),

             metadata={"source": "react_intro.md", "topic": "react"}),
```

## 19.7 实战演练：DocMind 完整的文档索引管线

```python
# src/rag/pipeline.py
"""DocMind 文档索引管线：加载 -> 分割 -> 嵌入 -> 存储 -> 检索"""

import os, shutil
from typing import List
from dotenv import load_dotenv
from langchain_core.documents import Document
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import TextLoader, PyPDFLoader, DirectoryLoader

load_dotenv()

class DocMindPipeline:
    """DocMind RAG 管线"""
    
    def __init__(self, persist_dir="./data/vectorstore",
                 collection_name="docmind",
                 chunk_size=1000, chunk_overlap=200):
        self.persist_dir = persist_dir
        self.collection_name = collection_name
        self.embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
        self.splitter = RecursiveCharacterTextSplitter(
            chunk_size=chunk_size, chunk_overlap=chunk_overlap,
            separators=["\n\n", "\n", "\u3002", ". ", "\uff0c", ", ", " ", ""],
        )
        self.vectorstore = None
    
    def load_documents(self, data_dir: str) -> List[Document]:
        """加载文档"""
        print(f"正在加载文档: {data_dir}")
        all_docs = []
        for ext in ["*.txt", "*.md"]:
            loader = DirectoryLoader(
                data_dir, glob=f"**/{ext}", loader_cls=TextLoader,
                loader_kwargs={"encoding": "utf-8"}, show_progress=True,
            )
            try:
                all_docs.extend(loader.load())
            except Exception as e:
                print(f"  加载 {ext} 失败: {e}")
        pdf_loader = DirectoryLoader(data_dir, glob="**/*.pdf", loader_cls=PyPDFLoader)
        try:
            all_docs.extend(pdf_loader.load())
        except Exception as e:
            print(f"  加载 PDF 失败: {e}")
        print(f"  共加载 {len(all_docs)} 个文档片段")
        return all_docs
    
    def split_documents(self, docs: List[Document]) -> List[Document]:
        """分割文档"""
        chunks = self.splitter.split_documents(docs)
        for i, chunk in enumerate(chunks):
            chunk.metadata["chunk_id"] = i
        avg = sum(len(c.page_content) for c in chunks) / len(chunks)
        print(f"分割为 {len(chunks)} 个块, 平均 {avg:.0f} 字符")
        return chunks
    
    def create_vectorstore(self, chunks: List[Document]) -> Chroma:
        """创建向量存储"""
        if os.path.exists(self.persist_dir):
            shutil.rmtree(self.persist_dir)
        self.vectorstore = Chroma.from_documents(
            documents=chunks, embedding=self.embeddings,
            collection_name=self.collection_name,
            persist_directory=self.persist_dir,
        )
        print(f"向量存储创建成功: {self.persist_dir}")
        return self.vectorstore
    
    def load_vectorstore(self) -> Chroma:
        """加载已有存储"""
        self.vectorstore = Chroma(
            collection_name=self.collection_name,
            embedding_function=self.embeddings,
            persist_directory=self.persist_dir,
        )
        return self.vectorstore
    
    def get_retriever(self, k=3):
        if self.vectorstore is None:
            self.load_vectorstore()
        return self.vectorstore.as_retriever(search_kwargs={"k": k})
    
    def build_index(self, data_dir: str) -> Chroma:
        """完整管线"""
        print("=" * 50)
        print("DocMind 文档索引管线")
        print("=" * 50)
        docs = self.load_documents(data_dir)
        if not docs:
            raise ValueError(f"未找到文档: {data_dir}")
        chunks = self.split_documents(docs)
        return self.create_vectorstore(chunks)

# 端到端测试
```

### 19.7.3 RAG 问答的完整流程

让我们把检索和 LLM 结合起来，实现一个完整的 RAG 问答流程：

```python
# rag_qa_demo.py — 完整的 RAG 问答演示
"""把检索到的文档上下文传给 LLM，让 LLM 基于文档回答"""

from dotenv import load_dotenv
load_dotenv()

from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage
from src.rag.pipeline import DocMindPipeline

def rag_answer(question: str, pipeline: DocMindPipeline) -> str:
    """RAG 问答：检索 + 生成"""
    
    # 第一步：检索相关文档
    retriever = pipeline.get_retriever(k=3)
    docs = retriever.invoke(question)
    
    # 第二步：构建上下文
    context = "\n\n---\n\n".join(
        f"[来源: {doc.metadata.get('source', '未知')}]\n{doc.page_content}"
        for doc in docs
    )
    
    # 第三步：构建 Prompt
    system_prompt = f"""你是 DocMind，一个智能文档问答助手。

请基于以下参考文档来回答用户的问题。

参考文档：
{context}

回答规范：
1. 优先使用参考文档中的信息
2. 如果文档中没有相关信息，明确说明
3. 可以补充自己的知识，但标明"补充信息"
4. 回答时引用文档来源"""
    
    # 第四步：调用 LLM
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.7)
    messages = [
        SystemMessage(content=system_prompt),
        HumanMessage(content=question),
    ]
    
    response = llm.invoke(messages)
    return response.content

# 使用
if __name__ == "__main__":
    pipeline = DocMindPipeline()
    pipeline.load_vectorstore()
    
    questions = [
        "Docker 有哪些核心概念？",
        "如何设计一个好的 REST API？",
        "Python 的类和对象怎么使用？",
    ]
    
    for q in questions:
        print(f"\n{'='*50}")
        print(f"问题: {q}")
        print(f"{'='*50}")
        answer = rag_answer(q, pipeline)
        print(f"回答: {answer}")
```

> ⚠️ **RAG 的常见陷阱**：
>
> 1. 检索到的文档不够相关 — 优化 chunk_size 和 Embedding 模型
> 2. 上下文太长导致 LLM "迷路" — 控制检索结果数量（k 值）
> 3. LLM 编造文档中不存在的信息 — 在 Prompt 中明确要求"只基于文档回答"

## 19.8 本章小结

1. **Document Loader** — 统一接口加载各种文件格式。
2. **Text Splitter** — `RecursiveCharacterTextSplitter` 按优先级递归分割，是最佳选择。
3. **Embedding** — 把文本转换为向量，实现语义搜索。
4. **Vector Store (Chroma)** — 轻量级向量数据库，支持持久化和过滤。
5. **Retriever** — 标准化检索接口，无缝集成到 Chain 和 Agent。
