# 第13章：生命周期

## 开篇：Rust 编译器最"啰嗦"的报错

如果你在前几章的练习中写过返回引用的函数，你大概率见过这个报错：

```
error[E0106]: missing lifetime specifier
 --> src/main.rs:1:33
  |
1 | fn longest(x: &str, y: &str) -> &str {
  |               ----     ----     ^ expected named lifetime parameter
```

编译器在告诉你："你返回了一个引用，但我不知道它到底指向谁的数据，也不知道它能活多久。" 这就是**生命周期（Lifetime）**要解决的问题——它是 Rust 保证内存安全的最后一道防线。

## 为什么需要生命周期？——悬垂引用的根本问题

来看一段在 C/C++ 中完全合法但在 Rust 中会出问题的代码模式：

```rust
// 这段代码不会通过编译！
fn main() {
    let r;
    {
        let x = 5;
        r = &x; // r 借用了 x
    } // x 在这里被销毁
    println!("r = {}", r); // 悬垂引用！x 已经不存在了
}
```

在 C 中，这段代码会编译通过但产生**未定义行为（Undefined Behavior）**——你可能读到垃圾数据，也可能程序直接崩溃。Rust 编译器在编译期就拒绝了这种代码，因为它追踪到了 `r` 的生命周期比 `x` 长。

但编译器并不总是能自动推断引用的有效范围。当涉及函数参数和返回值时，就需要**生命周期标注**来帮忙。

## 生命周期标注语法

生命周期标注使用**撇号 + 名称**的语法，惯例是用小写字母，通常很短（`'a`、`'b`）：

```rust
&i32        // 一个普通的引用
&'a i32     // 一个带有显式生命周期 'a 的引用
&'a mut i32 // 一个带有显式生命周期 'a 的可变引用
```

生命周期标注**不会改变引用实际存活的时间**——它只是告诉编译器不同引用之间的生命周期关系。就像变量名不影响变量的值，生命周期名也不影响引用的实际存活范围。

## 函数中的生命周期标注

回到那个 `longest` 函数：

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}

fn main() {
    let string1 = String::from("long string");
    let result;
    {
        let string2 = String::from("xyz");
        result = longest(string1.as_str(), string2.as_str());
        println!("The longest string is: {}", result);
        // 必须在 string2 的作用域内使用 result，
        // 因为 result 的生命周期与 x、y 中较短的那个绑定
    }
    // println!("{}", result); // 错误！string2 已经出了作用域
}
```

`'a` 的含义是：**返回值的引用将与 `x` 和 `y` 中生命周期较短的那个一样长**。编译器据此检查所有调用点——如果调用者试图在较短的生命周期结束后继续使用返回值，就会报错。

让我们再看一个反例来理解为什么需要标注：

```rust
fn longest_or_default<'a>(x: &'a str, y: &str, default: &'a str) -> &'a str {
    if x.len() >= y.len() {
        x
    } else if !y.is_empty() {
        // 错误！y 没有 'a 标注，不能返回
        // y  // 编译错误
        default // 用 default 代替
    } else {
        default
    }
}

fn main() {
    let s1 = "hello";
    let s2 = "world!";
    let d = "default";
    println!("{}", longest_or_default(s1, s2, d));
}
```

注意 `y` 没有 `'a` 标注——这意味着 `y` 的生命周期与返回值无关。因此你不能返回 `y`，但可以用 `x` 或 `default`（它们有 `'a` 标注）。

## 生命周期推断规则（三条规则）

Rust 编译器使用三条规则自动推断引用的生命周期，大多数情况下你不需要手动标注：

**规则一：每个引用参数获得自己的生命周期参数。**

```
fn foo(x: &i32, y: &i32)
// 编译器理解为：fn foo<'a, 'b>(x: &'a i32, y: &'b i32)
```

**规则二：如果只有一个输入生命周期参数，它被赋给所有输出引用。**

```
fn first_word(s: &str) -> &str
// 规则1后：fn first_word<'a>(s: &'a str) -> &str
// 规则2后：fn first_word<'a>(s: &'a str) -> &'a str  ✓ 推断完成！
```

**规则三：如果有 `&self` 或 `&mut self` 参数，`self` 的生命周期被赋给所有输出引用。**

```rust
struct Article { title: String, content: String }

impl Article {
    fn title(&self) -> &str {
        &self.title
    }
    // 规则1后：fn title<'a, 'b>(&'a self, ...) -> &str  (没有其他参数)
    // 规则3后：fn title<'a>(&'a self) -> &'a str  ✓ 推断完成！
}
```

当三条规则都用完，仍然有输出引用没有获得生命周期时，编译就会报错——这就是为什么 `longest` 需要手动标注：两个输入参数各有各的生命周期（规则一），编译器不知道该把哪个赋给输出（规则三不适用，因为没有 `self`）。

## 结构体中的生命周期

当结构体持有引用时，必须标注生命周期：

```rust
#[derive(Debug)]
struct Excerpt<'a> {
    text: &'a str,
}

impl<'a> Excerpt<'a> {
    // 返回 Excerpt 中引用的部分文本
    fn first_sentence(&self) -> &'a str {
        // 找到第一个句号或返回全部文本
        match self.text.find('.') {
            Some(pos) => &self.text[..=pos],
            None => self.text,
        }
    }

    // 返回静态字符串，不需要生命周期标注
    fn level(&self) -> i32 {
        3
    }
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first_sentence = novel.split('.').next().unwrap();
    let excerpt = Excerpt {
        text: first_sentence,
    };
    println!("Excerpt: {:?}", excerpt);
    println!("First sentence: {}", excerpt.first_sentence());
    println!("Level: {}", excerpt.level());
}
```

**关键原则**：结构体实例不能比它引用的数据活得更久。生命周期标注 `'a` 确保了这一点——`Excerpt` 的实例只能在 `text` 指向的数据存活期间存在。

## 静态生命周期（'static）

`'static` 是一种特殊的生命周期，表示引用可以在**整个程序运行期间**存活：

```rust
// 字符串字面量的类型是 &'static str
let s: &'static str = "I live forever!";

// 静态变量
static GLOBAL_CONFIG: &str = "production";

fn main() {
    println!("{}", s);
    println!("{}", GLOBAL_CONFIG);
}
```

**小心 `'static` 的陷阱**：`'static` 表示"可以存活整个程序期间"，但不意味着"必须存活整个程序期间"。一个 `T: 'static` 的约束只意味着类型 `T` 不包含任何非静态引用——**它本身可以是栈上分配的拥有所有权的类型**：

```rust
fn print_static<T: 'static>(item: T) {
    println!("{:?}", item);
}

fn main() {
    let owned_string = String::from("hello");
    print_static(owned_string); // OK！String 不包含非静态引用
    print_static(42);           // OK！i32 不包含任何引用
    print_static("literal");    // OK！&'static str

    let local = String::from("temp");
    // let r = &local;
    // print_static(r); // 错误！&String 不是 'static
}
```

## 省略规则：什么时候可以不写生命周期标注

总结起来，以下情况可以省略生命周期标注：

1. **函数只接受一个引用参数并返回引用**：编译器自动推断返回值的生命周期等于输入。
2. **方法中通过 `&self` 返回引用**：返回值的生命周期等于 `self` 的生命周期。
3. **不返回引用的函数**：没有输出生命周期需要推断。
4. **返回拥有所有权的值**：不涉及引用，无需标注。

```rust
// 不需要标注
fn first_char(s: &str) -> char { s.chars().next().unwrap() }
fn count_chars(s: &str) -> usize { s.chars().count() }

struct Config { name: String }
impl Config {
    fn name(&self) -> &str { &self.name } // 自动推断
}

// 需要标注
fn select_ref<'a>(cond: bool, a: &'a str, b: &'a str) -> &'a str {
    if cond { a } else { b }
}

fn main() {
    println!("{}", first_char("hello"));
    let c = Config { name: "app".to_string() };
    println!("{}", c.name());
    println!("{}", select_ref(true, "yes", "no"));
}
```

## 实战：实现一个文本解析器，返回输入的引用

让我们构建一个简易的键值对解析器，它返回输入字符串的引用而非新分配的字符串——零分配（zero-allocation）解析：

```rust
#[derive(Debug)]
struct KeyValuePair<'a> {
    key: &'a str,
    value: &'a str,
}

#[derive(Debug)]
struct Config<'a> {
    entries: Vec<KeyValuePair<'a>>,
}

impl<'a> Config<'a> {
    fn parse(input: &'a str) -> Config<'a> {
        let mut entries = Vec::new();

        for line in input.lines() {
            let line = line.trim();

            // 跳过空行和注释
            if line.is_empty() || line.starts_with('#') {
                continue;
            }

            // 解析 "key = value" 格式
            if let Some(eq_pos) = line.find('=') {
                let key = line[..eq_pos].trim();
                let value = line[eq_pos + 1..].trim();
                entries.push(KeyValuePair { key, value });
            }
        }

        Config { entries }
    }

    fn get(&self, key: &str) -> Option<&'a str> {
        self.entries
            .iter()
            .find(|entry| entry.key == key)
            .map(|entry| entry.value)
    }

    fn keys(&self) -> Vec<&'a str> {
        self.entries.iter().map(|e| e.key).collect()
    }
}

fn main() {
    let config_text = "
# Database settings
host = localhost
port = 5432
database = myapp

# Cache settings
cache_ttl = 3600
";

    let config = Config::parse(config_text);
    println!("Parsed config: {:?}", config);
    println!("host = {:?}", config.get("host"));
    println!("port = {:?}", config.get("port"));
    println!("missing = {:?}", config.get("missing"));
    println!("All keys: {:?}", config.keys());
}
```

这个解析器的精妙之处在于：**`Config` 中的所有字符串都是对原始 `config_text` 的引用，没有任何内存分配**。`'a` 标注确保了 `Config` 不会比 `config_text` 活得更久。在处理大文件时，这种零分配解析可以显著减少内存使用和 GC 压力——在 Rust 里虽然没有 GC，但减少分配同样重要。

## 常见陷阱与易错点

**陷阱1：混淆引用范围和所有权**

```rust
fn longest_announced<'a>(x: &'a str, y: &'a str) -> &'a str {
    let result = String::from("really long string");
    // 错误！不能返回局部变量的引用
    // result.as_str()
    // 即使标注了 'a，返回的数据必须在 'a 期间有效
    if x.len() > y.len() { x } else { y }
}
```

生命周期标注不能"延长"数据的实际存活时间。它只是声明关系，不是魔法。

**陷阱2：不必要的标注**

```rust
// 不需要标注！编译器用规则2自动推断
fn first_word<'a>(s: &'a str) -> &'a str {
    // ...
    todo!()
}

// 直接写就好
fn first_word_clean(s: &str) -> &str {
    s.split_whitespace().next().unwrap_or("")
}
```

过度标注会让代码更嘈杂。信任编译器的推断规则。

**陷阱3：结构体中的引用 vs 拥有所有权**

```rust
// 持有引用——需要生命周期标注，但零分配
struct BorrowedName<'a> {
    name: &'a str,
}

// 拥有所有权——不需要生命周期标注，但有堆分配
struct OwnedName {
    name: String,
}
```

选择引用还是所有权取决于使用场景。如果数据生命周期清晰且短暂，用引用更高效；如果需要长期持有或跨线程传递，拥有所有权更省心。

## 小结

- 生命周期是 Rust 保证引用有效性的机制，防止悬垂引用。
- 生命周期标注不改变引用的实际存活时间，只描述引用之间的关系。
- 编译器有三条推断规则，覆盖大部分场景。
- 结构体持有引用时必须标注生命周期。
- `'static` 表示引用可以存活整个程序运行期间。
- 信任编译器的推断，只在必要时手动标注。
