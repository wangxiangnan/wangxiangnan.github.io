本卷是十二章的综合收口：四组题——章节八题（T1–T8）抽查各章的「3 个坑」、主线串联（T9–T12）复述四个 Part 的骨架、跨章硬依赖（T13–T16）考两章接缝处的推理、综合操作（T17–T18）考完整落地。玩法：闭卷作答，全部做完再逐题打开 `<details>`；答案带一句推导与回指，错的按回指重读，隔 1 天重做错题。

## 题目

**第一组 · 章节八题（T1–T8）**：乱序抽 8 章。每题只给章号与主题，合上书说出这一章的 3 个坑（最容易翻车的判断）。

**T1（第 2 章 动画工具箱）**：说出这一章的 3 个坑。

<details>
<summary>答案</summary>

①**spring 被误当成「没有时长参数」**：它自 3.0.27 起就有 `durationInFrames`，可以精确占位；②**`random(seed, i)` 多传参数**：第二个参数被静默忽略，所有元素拿到同一个值还叠在一起；③**interpolate 忘记 clamp**：帧号天然超出设计区间，元素会飞出画面。

推导：这一章的三个坑分别属于「API 认知」「函数签名」「参数默认值」，都是「不报错但结果错」的类型。回指：2.1、2.2、2.3。
</details>

**T2（第 5 章 时序组件与异步纪律）**：说出这一章的 3 个坑。

<details>
<summary>答案</summary>

①**`delayRender` 的句柄不是惰性初始化**：每次 React 重渲染都新建句柄、永不释放，渲染卡到超时；②**句柄写在模块顶层**：渲染其他 Composition 时也被卡住；③**把 `<Sequence>` 当已知前提**：本书从未正式教过它，却直接用了 `from`/`durationInFrames`/`layout="none"`。

推导：前两个坑都出自「句柄的生命周期」，第三个出自「先用了后教」——时序组件的地基是 Sequence。回指：5.1、5.5。
</details>

**T3（第 7 章 字幕与语音生态）**：说出这一章的 3 个坑。

<details>
<summary>答案</summary>

①**中文分页被空格坑住**：官方 `createTikTokStyleCaptions` 靠空格分词，中文整句挤成一页；②**Whisper 用了 `.en` 模型**：英文专用模型喂中文得到乱码；③**字体子集用 `latin` 渲染中文字幕**：子集里根本没有汉字。

推导：这一章的坑集中在「英文生态直接搬到中文场景」，三处都要先看清适用范围。回指：7.2、7.3、7.4。
</details>

**T4（第 9 章 图形扩展包）**：说出这一章的 3 个坑。

<details>
<summary>答案</summary>

①**`evolvePath` 的越界行为理解反了**：progress > 1 是从终点回缩、< 0 是整条不画，不是「从头回退」；②**`animationData` 引用不稳**：对象身份一变动画就重新初始化，要用 `useMemo` 钉住；③**自定义场景里的动画区间装不进结尾卡**：结尾卡只有 20 帧，区间却写了 45 帧。

推导：这一章的坑是「算出来的量」和「容器给的空间」对不上。回指：9.1、9.2、9.3。
</details>

**T5（第 3 章 音画同步）**：说出这一章的 3 个坑。

<details>
<summary>答案</summary>

①**重叠的 50 毫秒被当成「间隙」**：其实两句同时在区间内，字幕的兜底逻辑根本不会触发；②**场景帧数算两遍**：曾把结尾卡起点从 263 推到 265（晚 2 帧、0.07 秒）；③**字幕挂进场景**：转场进行时它会跟着淡出，而它必须全程纹丝不动。

推导：这一章的坑都源于「数据是脏的、帧数是算出来的」，必须靠单一来源与单调钳制兜住。回指：3.4、3.5、3.6。
</details>

**T6（第 10 章 规模化渲染）**：说出这一章的 3 个坑。

<details>
<summary>答案</summary>

①**在循环里 `bundle()`**：打包产物与 props 无关，应该循环外只打一次；②**封面帧号写死 157**：短于 157 帧的片子会取到越界帧，整批被 catch 成失败；③**规格与渲染用了不同的 props**：`selectComposition` 与 `renderMedia` 传的不是同一份，截图会按另一份数据渲染。

推导：这一章的坑都是「批量化把单条时的假设放大」。回指：10.1、10.2。
</details>

**T7（第 11 章 交互与可视化编辑）**：说出这一章的 3 个坑。

<details>
<summary>答案</summary>

①**在组合外用 `useCurrentFrame()`**：读的是最近一层 Sequence 的局部帧，网页组件不在组合里，拿不到值；②**把帧号放在页面顶层组件**：整页 UI 每帧重渲染，必须拆到 Player 的相邻组件；③**Player 里包 `<Composition>`**：规格声明了两次，直接报错。

推导：这一章的坑都是「组合边界」两侧的误解。回指：4.4、11.1、11.2。
</details>

**T8（第 12 章 工程化纵深）**：说出这一章的 3 个坑。

<details>
<summary>答案</summary>

①**CI 里没有生成 `out/timestamps.json` 的步骤**：`--props` 指向的文件不存在，「push 即出片」跑不通；②**`on.push.paths` 不含 package.json/lock**：升级依赖不触发 CI，本章自己的升级闭环断了；③**确定性自检误伤测试文件**：单元测试里的 fake timer 与固定随机数会被当成违规。

推导：这一章的坑都出在「把仓库当产品维护」的细节——缓存、触发条件、误报。回指：12.2、12.3。
</details>

**第三组 · 跨章硬依赖（T13–T16）**：四条接缝处的推理，答案必须同时用上两端的章。

**T13（第 2 章 插值 → 第 8 章 转场）**：把转场从 `fade()` 换成 `springTiming({ config: { damping: 200 } })`，总帧数会变成多少？结尾卡会怎样？

<details>
<summary>答案</summary>

转场从 15 帧变成实测 **23 帧**，总帧数从 283 变成 313 − 2×23 = **267 帧**（比原来还短，因为转场是重叠不是叠加）。但 23 帧转场塞不进只有 20 帧的结尾卡（转场不得长于相邻场景），要么把尾帧从 0.6 秒改 0.7 秒让结尾卡变 23 帧、总帧数变 286，要么调大 damping 缩短弹簧。

推导：换 timing 动的是「重叠窗口的宽度」，场景的名义边界（157、263）不动，但总帧数与「转场不得长于相邻场景」这条硬约束都会重新算一遍。回指：3.5、8.2。
</details>

**T14（第 1 章 纯函数 → 第 12 章 测试）**：为什么「画面本身」不做 golden 快照比对，而要拆成规格单测、确定性自检、单帧冒烟三层？

<details>
<summary>答案</summary>

因为画面是 283 张图，golden 文件体积巨大，且字体与浏览器版本一变就全红——**画面是「不报错但结果错」的重灾区**，二进制比对既脆弱又难维护。三层测试的分工是：规格函数（帧数、场景区间）用单测断言；禁用 API（`Math.random`、`Date.now`、`setTimeout`）用 grep/lint 拦在 code review 之前；渲染管线用单帧冒烟确认还活着。画面观感交给 4.1 的「三查」人工逐帧检查。

推导：纯函数纪律（同一帧必须同一画面）恰恰保证了画面可以由「帧号 + 数据」推出，所以断言规格比断言像素更本质。回指：1.4、12.3。
</details>

**T15（第 3 章 单一来源 → 第 10 章 批量）**：批量渲染 100 条城市天气视频时，为什么 `selectComposition()` 必须在循环内而 `bundle()` 必须在循环外？漏了会怎样？

<details>
<summary>答案</summary>

`bundle()` 的产物与 props 无关（同一份代码服务所有数据），所以循环外只打一次；`selectComposition()` 要按真实 props 跑一遍 `calculateMetadata`，不同文案算出不同总帧数（8.81 秒 → 283 帧只是其中一条），所以必须逐条重算。漏了循环内的重算，所有片子都会用同一条的帧数——短的那条画面被截断，长的那条结尾卡来不及出现。

推导：批量脚本的第一条分水岭是「与数据无关的事」与「随数据变的事」分开。回指：3.4、10.2。
</details>

**T16（第 6 章 媒体 → 第 4 章 三个出口）**：Player 网页里 `<Audio>` 没声音，依次给出三个排查方向。

<details>
<summary>答案</summary>

①**资产路径**：Player 环境没有 Studio 的静态服务，`staticFile("audio.mp3")` 要靠 `remotion_staticBase` 指向站点根（并用 Vite `publicDir` 把 `public/` 暴露在 `/` 下）；②**autoplay 策略**：Player 挂载后不会自动出声，需要用户在 `controls` 上点一下（用户手势）；③**预加载用错了 API**：`preloadAudio()` 只对原生 HTML5 标签生效，Remotion 自己的 `<Audio>` 要用 `prefetch()`。

推导：声音问题先分「有没有取到文件」「有没有被允许播」「有没有提前准备好」三层。回指：4.3、4.4、5.6、6.1。
</details>

**第四组 · 综合操作（T17–T18）**：完整情景，答出每一步属于哪一章、要点是什么，说明为什么是这个顺序。

**T17**：你要给「三城天气播报」做一套可批量出片的工程：一份中文文案 → 配音 + 词级时间戳 → 带字幕与转场的短视频 → 交付 mp4 与网页播放器，并且以后改一个字就能重跑全流程。请按顺序说出至少八步，每步注明属于哪一章、要点是什么。

<details>
<summary>答案</summary>

1. **装依赖**（第 4 章）：`npx remotion add @remotion/transitions` 等生态包必须与 `remotion` 主包同版本，否则 npm 报 ERESOLVE；
2. **写文案并合成**（第 3 章）：Edge-TTS 一次请求同时拿到音频与词级时间戳，落成 `out/timestamps.json`；
3. **注入 props**（第 3 章）：`--props` 注入时间戳，组件只认 props；
4. **算规格**（第 3 章）：`calculateMetadata` 按音频时长算总帧数（尾帧常量 `TAIL` 决定总长）；
5. **划分场景**（第 3 章）：`getScenePlan` 单一来源，脏时间戳用单调钳制处理；
6. **写画面**（第 2、3 章）：一切随时间变化的量都由 `frame` 算出来，雪花用种子化随机，字幕高亮用整数毫秒判定；
7. **交三个出口**（第 4 章）：同一份组件 + 同一份 props 分别进 Studio 调试、render 出片、Player 网页（记得 `remotion_staticBase` 与 `publicDir`）；
8. **串成本地命令**（第 4 章）：`npm run tts` → `npm run video`，流水线里「同步资产到 public/」保证三出口同源；
9. **批量与幂等**（第 10 章）：`bundle()` 循环外只打一次、`selectComposition()` 逐条重算、失败只收集不中断、产物存在即跳过；
10. **上 CI**（第 12 章）：`npm run tts` → 同步资产 → render → artifact，浏览器目录按锁文件缓存；
11. **补测试**（第 12 章）：规格函数单测 + 确定性自检 + 单帧冒烟；
12. **确认合规**（第 12 章）：团队规模、渲染位置、`licenseKey` 三问；云端渲染需 Automators 授权。

推导：这条链的顺序就是「数据 → 规格 → 画面 → 交付 → 规模 → 长期维护」，每一步的产物是下一步的输入——所以帧数只能算一次、组件只能写一份。回指：3.3、3.4、4.3、4.5、10.2、12.2、12.3。
</details>

**T18**：贯穿示例的成片出来后发现三个问题：①字幕有个别帧变成宋体；②转场点比预期晚了几帧；③渲染慢得离谱。请分别说明根因、查哪一章、怎么改。

<details>
<summary>答案</summary>

①**宋体帧**：该帧渲染时字体还没就绪（字体走 CDN，某帧加载失败）→ 查第 4 章 4.3，把字体离线化进 `public/fonts/`；也可看第 7 章 7.4 的 google-fonts 方案。
②**转场点晚了几帧**：场景帧数被算了两遍、取整结果不一致 → 查第 3 章 3.4/3.5，把帧数收敛成单一来源（`getScenePlan` 一处），并同步第 8 章的踩点公式。
③**渲染慢**：先看是「并发不够」还是「某一帧太重」→ 查第 1 章 1.5 的并发默认值与第 10 章 10.3 的 `slowestFrames`，单帧复测（`frameRange: [157,157]`）能区分两者。

推导：三个问题分属「资产」「数据」「资源」三层——先定位层，再对症下药，别用重渲染碰运气。回指：1.5、3.4、4.2、4.3、10.3。
</details>

## 通过线

- **第一组**：8 题里说得出 3 个坑的有 6 题以上；
- **第二组**：4 条主线能按顺序说全，并能用一句话串起来；
- **第三组**：4 题的推理链完整（不只要结论，要说得出两端章号的接口）；
- **第四组**：两题能答出 8 步以上且顺序正确。

以上四条都达标，就算把十二章装进同一套工具箱。没达标的题按「回指」回到对应小节重读，隔 1 天重做错题——**这是最后一次闭卷**。

## 毕业后怎么用

1. **建沙盒**：`npx create-video@latest` 起一个空项目，把贯穿示例的流水线抄进去跑通（骨架见[第四章 4.5 节](./ch04.md)）；
2. **换成自己的文案**：改完 props 按 `npm run video`，第一条属于你的片就出来了；
3. **每月自查**：抽 5 章乱序，用本卷第一组的格式各说 3 个坑——**坑比结论更值得记**，因为结论会忘、坑会救命；
4. **回头看全景**：[ch00](./ch00.md) 的心智模型与全景总览是这张地图，四组题是这张地图上的路标；走完之后，这张地图应该长在你脑子里。
