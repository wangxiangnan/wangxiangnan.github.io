# 第 22 章 代码规范与工具

你有没有看过这样的代码——有的函数名是 `calculate_total`，有的却是 `CalcTotal`；有的行缩进 4 个空格，有的 2 个；有的字符串用双引号，有的用单引号？读这种代码就像在崎岖山路上开车——不断被颠簸打断思路。

代码规范不是形式主义，而是团队协作的基础设施。当所有人的代码风格一致时，代码审查（Code Review）可以把精力集中在逻辑正确性上，而不是纠结空格和换行。好消息是，Python 社区有非常成熟的工具帮你自动格式化代码——你不需要记住规则，让工具来做。

## 22.1 PEP 8 核心规则

PEP 8 是 Python 官方的代码风格指南，由 Guido van Rossum 本人参与编写。以下是最核心的规则：

### 缩进与行长度

```python
# 缩进：4 个空格（不要用 Tab）
def long_function_name(
        var_one, var_two, var_three,
        var_four):
    print(var_one)

# 或者用对齐缩进
def long_function_name(
    var_one,
    var_two,
    var_three,
    var_four,
):
    print(var_one)

# 最大行长：79 字符（或项目约定的 88/100/120）
# 长字符串分行
long_string = (
    "这是一个非常非常长的字符串，"
    "它被分成了多行，"
    "Python 会自动拼接相邻的字符串字面量。"
)
```

### 命名规范

```python
# 变量和函数：snake_case
user_name = "Alice"
def calculate_total(items):
    pass

# 类：PascalCase
class ShoppingCart:
    pass

# 常量：UPPER_SNAKE_CASE
MAX_RETRIES = 3
DEFAULT_TIMEOUT = 30

# 模块：简短的全小写名
# utils.py, database.py, config.py

# 私有属性：前导下划线
class MyClass:
    def __init__(self):
        self._internal_value = 42  # 约定私有

    def _internal_method(self):
        pass
```

### 空格规则

```python
# 正确：运算符两侧有空格
x = 1 + 2
y = x * 3 - 1

# 错误：多余的空格
x  =  1  +  2     # 太多空格
my_list[ 1 ]       # 方括号内不要空格
my_dict[ "key" ]   # 同上
func( x, y )       # 圆括号内不要空格

# 正确：逗号后有空格
my_list = [1, 2, 3]
func(a, b, c)

# 比较：用 is 比较 None
if x is None:      # 正确
if x == None:      # 错误！
```

### import 规则

```python
# 1. 标准库 → 2. 第三方库 → 3. 本项目模块
# 每组之间空一行
import os
import sys
from pathlib import Path

import requests
from flask import Flask

from my_project import config
from my_project.utils import helper

# 避免星号导入
from module import *  # 不好！不知道导入了什么

# 推荐具体导入
from module import specific_function, SpecificClass
```

## 22.2 Black：不妥协的代码格式化器

Black 的哲学很简单：**只有一种正确的格式，你不用选择。** 它会自动把你的代码格式化为统一风格，消除团队中关于"缩进用几个空格"之类的无休止争论。

### 安装与使用

```bash
# 安装
pip install black

# 格式化指定文件
black my_script.py

# 格式化整个项目
black src/ tests/

# 预览改动（不实际修改）
black --diff src/

# 检查是否符合 Black 风格（CI 中常用）
black --check src/
```

### 配置

```toml
# pyproject.toml
[tool.black]
line-length = 88        # Black 默认 88 字符
target-version = ["py311"]
include = '\.pyi?$'
```

### Black 格式化示例

```python
# 格式化前（人类写出的混乱代码）
def  process_data(items,config,verbose=False):
    results=[]
    for  item in items:
        if item.is_valid and item.status=="active" and item.count>0:
            result=transform(item,config.get("mode","default"))
            results.append(result)
            if verbose:
                print( f"Processed {item.name}: {result}" )
    return results

# 格式化后（Black 处理）
def process_data(items, config, verbose=False):
    results = []
    for item in items:
        if (
            item.is_valid
            and item.status == "active"
            and item.count > 0
        ):
            result = transform(item, config.get("mode", "default"))
            results.append(result)
            if verbose:
                print(f"Processed {item.name}: {result}")
    return results
```

## 22.3 Ruff：极速 Linter + 格式化器

Ruff 是用 Rust 编写的 Python 代码检查工具，速度比传统 Linter（flake8、pylint）快 10-100 倍。它不仅能检查代码风格，还能检查潜在 bug、未使用的导入等问题。

### 安装与使用

```bash
# 安装
pip install ruff

# 检查代码问题
ruff check src/

# 自动修复
ruff check --fix src/

# 格式化（Ruff 也有格式化功能，兼容 Black）
ruff format src/
```

### 配置

```toml
# pyproject.toml
[tool.ruff]
line-length = 88
target-version = "py311"

[tool.ruff.lint]
# 启用的规则组
select = [
    "E",    # pycodestyle 错误
    "W",    # pycodestyle 警告
    "F",    # pyflakes
    "I",    # isort（导入排序）
    "N",    # pep8-naming（命名检查）
    "UP",   # pyupgrade（升级到新语法）
    "B",    # flake8-bugbear（常见 bug）
    "SIM",  # flake8-simplify（简化代码）
    "RUF",  # Ruff 特有规则
]

# 忽略特定规则
ignore = [
    "E501",  # 行长由 Black/Ruff formatter 控制
]

[tool.ruff.lint.isort]
known-first-party = ["my_project"]
```

### Ruff 能发现的问题

```python
# 未使用的导入（F401）
import os  # 如果没用到，Ruff 会提示删除

# 未使用的变量（F841）
def calculate():
    temp = 42  # 如果 temp 从未被使用，Ruff 会提示

# 可以用 set 代替的列表查找（SIM）
if x in [1, 2, 3, 4, 5]:  # Ruff: 用 set 更快
    pass

# 过时的语法（UP）
from typing import List  # Ruff: Python 3.9+ 直接用 list
scores: List[int] = []    # Ruff: 用 list[int]

# 常见 bug（B）
def func(items=[]):  # B006: 可变默认参数！
    pass
```

## 22.4 isort：导入排序

isort 自动排序和分组 `import` 语句（现在 Ruff 已经内置了这个功能）：

```python
# 格式化前（混乱的导入）
from my_project.models import User
import os
from flask import Flask, request
import sys
from my_project.utils import helper
import json
from pathlib import Path

# 格式化后（isort / ruff 处理）
import json
import os
import sys
from pathlib import Path

from flask import Flask, request

from my_project.models import User
from my_project.utils import helper
```

```bash
# 独立使用
pip install isort
isort src/

# 或者用 Ruff 替代（推荐）
ruff check --fix --select I src/
```

## 22.5 pre-commit：在提交前自动检查

`pre-commit` 是一个 Git 钩子管理器，可以在你 `git commit` 之前自动运行格式化和检查工具。如果你忘了运行 Black 或 Ruff，pre-commit 会帮你拦截不合格的提交。

### 安装与配置

```bash
# 安装
pip install pre-commit

# 在项目根目录创建 .pre-commit-config.yaml
```

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.4.0
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format

  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: trailing-whitespace     # 删除行尾空格
      - id: end-of-file-fixer       # 确保文件以换行结尾
      - id: check-yaml              # 检查 YAML 语法
      - id: check-toml              # 检查 TOML 语法
      - id: check-added-large-files # 防止提交大文件
      - id: debug-statements        # 检查 debugger 断点

  - repo: https://github.com/pre-commit/mirrors-mypy
    rev: v1.10.0
    hooks:
      - id: mypy
        additional_dependencies: [pydantic>=2.0]
```

```bash
# 安装 Git 钩子
pre-commit install

# 手动运行（对所有文件）
pre-commit run --all-files

# 更新钩子版本
pre-commit autoupdate
```

### 工作流程

```
开发者修改代码
  → git add .
  → git commit
  → pre-commit 自动运行：
    → ruff --fix（自动修复问题）
    → ruff format（格式化代码）
    → mypy（类型检查）
    → trailing-whitespace（清理空格）
  → 如果有修改：提交失败，需要你重新 add
  → 如果全部通过：提交成功
```

小贴士：pre-commit 第一次运行会比较慢（需要下载钩子），之后就有缓存了。每次 `git commit` 多等几秒，换来的是干净的代码库。

## 22.11 参考答案

**第 1 题：**

```python
class ShoppingCart:
    def __init__(self):
        self.items = []

    def add_item(self, item_name, price, quantity=1):
        self.items.append({
            "item_name": item_name,
            "price": price,
            "qty": quantity,
        })

    def get_total(self):
        total = 0
        for item in self.items:
            total += item["price"] * item["qty"]
        return total
```

主要修正：类名改为 PascalCase、`Self` → `self`、方法名改为 snake_case、字典键统一为 snake_case、添加空格。

**第 4 题：**

`ruff check --fix` 运行 lint 规则并自动修复可修复的问题（如删除未使用的导入、修复可变默认参数等）。`ruff format` 是代码格式化器（类似 Black），处理缩进、引号、换行、空格等风格问题。简单来说：check 管"对不对"，format 管"好不好看"。

**第 7 题：**

逐步引入代码规范的策略：

1. 先配置 `pyproject.toml` 中的工具规则，但只对新文件/修改的文件生效
2. 引入 pre-commit，配置 ruff 只检查修改的文件
3. 每次修改文件时，先对该文件运行 `ruff format` 和 `ruff check --fix`
4. 逐步扩大检查范围，最终覆盖所有文件
5. 运行 `ruff format src/` 一次性格式化所有文件，作为单独的 PR 提交（方便 review）
6. 在 CI 中加入检查，阻止不符合规范的新代码合入

## 22.12 常见错误与避坑

**1. 格式化后不运行测试**

格式化工具偶尔会暴露代码中的隐藏问题（比如不正确的缩进实际上掩盖了逻辑错误）。格式化后一定要跑一遍测试。

**2. pre-commit 修改了文件但没有 stage**

pre-commit 运行后如果修改了文件，这次 commit 会失败。你需要重新 `git add` 被修改的文件，然后再 commit。

**3. Black 和 Ruff formatter 冲突**

两者都声称兼容，但偶尔在极端情况下会有微小差异。推荐只用其中一个做格式化，不要同时用。

**4. CI 中只检查不修复**

```bash
# CI 中应该用 --check（只检查，不修改）
ruff check src/          # 检查 lint 问题
ruff format --check src/ # 检查格式问题
# 不要用 --fix，CI 不应该修改代码
```

**5. 忽略所有 lint 警告**

```python
# type: ignore 和 noqa 是"逃生舱"，不是"免费通行证"
x = do_something()  # type: ignore  # noqa  # 这样写说明你的代码有问题
```

每次使用 `# noqa` 或 `# type: ignore` 都应该加上注释解释为什么忽略，并定期检查是否可以移除。
