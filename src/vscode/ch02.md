# 第2章：工作区与多项目管理

> 在编程世界里，我们用模块化和分层来管理复杂度。VSCode 用同样的思路管理你的项目——**工作区（Workspace）就是编辑器层面的"模块化"**。一个配置良好的工作区，能让你在多个项目之间切换时如同切换浏览器标签页一样丝滑。但工作区不只是"把几个文件夹放在一起"：它还决定了设置、任务、调试配置的作用范围。

## 2.1 单文件夹与多根工作区

VSCode 有两种工作区形态，而不是三种：

| 形态 | 打开方式 | 配置文件 | 适用场景 |
| --- | --- | --- | --- |
| 单文件夹工作区 | `File > Open Folder` | `<folder>/.vscode/*` | 单一项目 |
| 多根工作区 | `File > Open Workspace from File...` | `*.code-workspace` | monorepo、前后端分离、微服务 |

`.code-workspace` 不是第三种"模式"，而是多根工作区的描述文件。它也可以只包含一个文件夹——只不过那样通常没必要。

类比：单文件夹像单个 npm 包，多根工作区像 monorepo 的根目录——你在一个窗口里管理多个包，但每个包仍保留自己的配置。

### 单文件夹工作区

最常见的方式：`File > Open Folder`。VSCode 以该文件夹为根，设置、任务、调试都以它为上下文：

```
my-project/
├── src/
├── package.json
├── .vscode/          ← 项目级配置
│   ├── settings.json
│   ├── tasks.json
│   ├── launch.json
│   └── extensions.json
└── README.md
```

适合：独立、结构简单的单一项目。

这里有一个常见误解：**扩展不是按文件夹隔离的**。扩展安装在用户或 Profile 级别，工作区只能通过 `extensions.recommendations` "推荐"，不能强制某个文件夹使用某组扩展。需要按项目切换扩展，用 Profiles（见 2.4）。

### 多根工作区（Multi-root Workspace）

多根工作区让你在一个窗口里同时打开多个文件夹，每个文件夹在资源管理器中独立显示，拥有自己的文件树：

```
📁 前端 (web/)
📁 后端 (api/)
📁 共享库 (packages/shared/)
```

一个 `.code-workspace` 文件可以包含：

- `folders`：根文件夹列表，`path` 相对于工作区文件
- `settings`：工作区级设置，覆盖用户设置
- `extensions.recommendations`：团队推荐扩展
- `tasks`：工作区级任务
- `launch`：工作区级调试配置

它和项目内配置文件的分工如下：

| 文件 | 作用范围 | 典型内容 |
| --- | --- | --- |
| `*.code-workspace` | 整个多根工作区 | 文件夹列表、工作区设置、扩展推荐、任务、调试 |
| `<folder>/.vscode/settings.json` | 单个根文件夹 | 该项目专属设置 |
| `<folder>/.vscode/tasks.json` / `launch.json` | 单个根文件夹 | 项目专属任务/调试 |

> 工作区文件通常提交到仓库，和团队共享；路径用相对路径，避免把本机绝对路径带进去。

## 2.2 工作区文件配置

一个 `.code-workspace` 文件本质上是一个允许注释的 JSON（JSONC），常用字段如下：

```jsonc
// fullstack-project.code-workspace
{
  // 根文件夹：name 会用于 ${workspaceFolder:name}
  "folders": [
    { "name": "前端", "path": "./frontend" },
    { "name": "后端", "path": "./backend" },
    { "name": "共享类型", "path": "./shared-types" }
  ],

  // 工作区设置：覆盖用户设置，但会被文件夹设置覆盖
  "settings": {
    "editor.tabSize": 2,
    "editor.formatOnSave": true,
    "files.associations": { "*.schema": "json" },
    "search.exclude": {
      "**/node_modules": true,
      "**/dist": true,
      "**/.next": true
    },
    "terminal.integrated.defaultProfile.windows": "PowerShell"
  },

  // 扩展推荐：团队成员打开工作区时会收到提示
  "extensions": {
    "recommendations": [
      "dbaeumer.vscode-eslint",
      "esbenp.prettier-vscode",
      "prisma.prisma",
      "bradlc.vscode-tailwindcss"
    ]
  },

  // 工作区任务：用 options.cwd 指定每个子项目
  "tasks": {
    "version": "2.0.0",
    "tasks": [
      {
        "label": "dev:all",
        "dependsOn": ["dev:frontend", "dev:backend"],
        "dependsOrder": "parallel",
        "group": { "kind": "build", "isDefault": true },
        "problemMatcher": []
      },
      {
        "label": "dev:frontend",
        "type": "shell",
        "command": "npm run dev",
        "options": { "cwd": "${workspaceFolder:前端}" },
        "problemMatcher": []
      },
      {
        "label": "dev:backend",
        "type": "shell",
        "command": "npm run dev",
        "options": { "cwd": "${workspaceFolder:后端}" },
        "problemMatcher": []
      },
      {
        "label": "build:backend",
        "type": "shell",
        "command": "npm run build",
        "options": { "cwd": "${workspaceFolder:后端}" },
        "problemMatcher": ["$tsc"]
      }
    ]
  },

  // 工作区调试配置
  "launch": {
    "version": "0.2.0",
    "configurations": [
      {
        "type": "chrome",
        "request": "launch",
        "name": "调试前端",
        "url": "http://localhost:3000",
        // Vite/大多数项目用项目根；CRA 等可能需要指向 src
        "webRoot": "${workspaceFolder:前端}"
      },
      {
        "type": "node",
        "request": "launch",
        "name": "调试后端",
        "program": "${workspaceFolder:后端}/dist/index.js",
        "preLaunchTask": "build:backend"
      }
    ]
  }
}
```

几个关键点：

- **路径相对于工作区文件**。`folders[].path` 用 `./frontend` 这种相对路径，工作区文件挪位置时不容易坏。
- **`${workspaceFolder:前端}` 用的是 `name` 字段**，不是文件夹名。没写 `name` 时才会用文件夹的 basename。在工作区级配置里优先用它，避免 `${workspaceFolder}` 的歧义。
- **设置优先级**：默认 < 用户 < 远程（如有） < 工作区 < 文件夹 < 语言级。工作区设置覆盖用户设置，但会被 `frontend/.vscode/settings.json` 这类文件夹设置覆盖。
- **`extensions.recommendations` 只是推荐**，团队成员可以忽略；还可以用 `extensions.unwantedRecommendations` 排除不需要的扩展。
- **任务和调试可以放在工作区级，也可以放在各文件夹的 `.vscode/` 里**。工作区级配置作用于所有根文件夹，文件夹级只作用于自己。
- **这里用 `type: "shell"` + `options.cwd`**，而不是 `type: "npm"` + `path`。npm 任务类型也能用，但在多根工作区里，shell + `cwd` 更直观，也不容易踩任务作用域的坑。
- **`preLaunchTask` 必须对应 `tasks` 里的 `label`**（这里是 `build:backend`），否则调试启动会失败。
- **`dev:all` 借用了 `Ctrl+Shift+B`**（默认 build 任务）作为"一键启动"快捷键；它本质上不是构建，只是方便。

> `Ctrl+Shift+B` 只运行 `group.kind = "build"` 且 `isDefault: true` 的任务。其他任务用 `Tasks: Run Task`。

## 2.3 实战：前后端分离项目

让我们为一个真实的前后端分离项目创建工作区配置。

### 项目结构

```
ecommerce-platform/
├── ecommerce.code-workspace     ← 我们要创建的文件
├── web/                         ← React 前端
│   ├── src/
│   ├── public/
│   ├── package.json
│   └── tsconfig.json
├── api/                         ← Node.js 后端
│   ├── src/
│   ├── prisma/
│   ├── package.json
│   └── tsconfig.json
├── packages/
│   ├── types/                   ← 共享类型
│   │   ├── src/
│   │   └── package.json
│   └── utils/                   ← 共享工具
│       ├── src/
│       └── package.json
└── docs/
    └── api-spec.yaml
```

### 步骤1：创建工作区文件

```jsonc
// ecommerce.code-workspace
{
  "folders": [
    { "name": "Web前端", "path": "./web" },
    { "name": "API后端", "path": "./api" },
    { "name": "共享类型", "path": "./packages/types" },
    { "name": "共享工具", "path": "./packages/utils" },
    { "name": "文档", "path": "./docs" }
  ],

  "settings": {
    "editor.formatOnSave": true,
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.codeActionsOnSave": {
      "source.fixAll.eslint": "explicit"
    },
    "typescript.preferences.importModuleSpecifier": "relative",
    "files.exclude": {
      "**/node_modules": true,
      "**/dist": true,
      "**/.turbo": true
    }
  },

  "extensions": {
    "recommendations": [
      "dbaeumer.vscode-eslint",
      "esbenp.prettier-vscode",
      "prisma.prisma",
      "bradlc.vscode-tailwindcss",
      "humao.rest-client"
    ]
  },

  "tasks": {
    "version": "2.0.0",
    "tasks": [
      {
        "label": "dev:all",
        "dependsOn": ["dev:web", "dev:api"],
        "dependsOrder": "parallel",
        "group": { "kind": "build", "isDefault": true },
        "problemMatcher": []
      },
      {
        "label": "dev:web",
        "type": "shell",
        "command": "npm run dev",
        "options": { "cwd": "${workspaceFolder:Web前端}" },
        "problemMatcher": []
      },
      {
        "label": "dev:api",
        "type": "shell",
        "command": "npm run dev",
        "options": { "cwd": "${workspaceFolder:API后端}" },
        "problemMatcher": []
      }
    ]
  }
}
```

### 步骤2：为每个文件夹配置专属设置

在每个子项目的 `.vscode/settings.json` 中可以放置特定于该文件夹的设置。这些设置的优先级高于工作区设置：

```jsonc
// web/.vscode/settings.json
{
  "editor.tabSize": 2,
  "tailwindCSS.experimental.classRegex": [
    ["cva\\(([^)]*)\\)", "[\"'`]([^\"'`]*?)[\"'`]"],
    ["cn\\(([^)]*)\\)", "[\"'`]([^\"'`]*?)[\"'`]"]
  ]
}
```

```jsonc
// api/.vscode/settings.json
{
  "editor.tabSize": 2,
  "typescript.preferences.importModuleSpecifier": "non-relative"
}
```

> 如果前后端使用不同的 TypeScript 版本，把 `typescript.tsdk` 放到各自的 `.vscode/settings.json`，不要在 `.code-workspace` 里写一个全局路径。

### 步骤3：打开和使用

```bash
# 用命令行打开工作区
code ecommerce.code-workspace

# 或者从 VSCode 中：File > Open Workspace from File...
```

打开后，你会在侧边栏看到所有文件夹，每个文件夹有自己的文件树。使用 `Ctrl+P`（`⌘+P`）快速打开文件时，VSCode 会自动在所有根文件夹中搜索，并在结果中标注所属文件夹。

跨文件搜索（`Ctrl+Shift+F` / `⌘+Shift+F`）同样作用于所有根文件夹。如果只想在某个子项目里搜索，可以：

- 在资源管理器中右键该文件夹，选择 **Find in Folder...**
- 或在搜索面板的 **files to include** 中填入对应路径

运行时也可以从命令面板执行 `Workspaces: Add Folder to Workspace...`，把新文件夹动态加入当前工作区。

## 2.4 用 Profiles 隔离不同项目环境

**Profile（配置文件）**是一套可切换的编辑器环境，可以包含：

- 设置（settings）
- 扩展（extensions）
- 键盘快捷键
- 用户代码片段
- 任务
- UI 布局与状态

这就像给不同工作流准备不同的"工作台"：前端、Python 数据科学、写文档，各自只出现需要的扩展和设置。

### 创建与切换

- 命令面板（`Ctrl+Shift+P`）→ `Profiles: Create Profile`，或左下角齿轮 → **Profiles** → **New Profile...**
- 选择从空白创建，或复制当前配置
- 切换：命令面板 → `Profiles: Switch Profile`，或齿轮 → **Profiles** → 选择目标 Profile
- 导出/导入：**Profiles** 菜单 → **Export...** / **Import Profile...**，导出的文件可以分享给团队

### 几个实用 Profile

| Profile | 典型扩展 | 关键设置 | 适用场景 |
| --- | --- | --- | --- |
| 前端开发 | ESLint、Prettier、Tailwind CSS IntelliSense、Auto Rename Tag | 2 空格、保存格式化、Emmet 模板 | React/Vue/普通前端 |
| Python 数据科学 | Python、Pylance、Jupyter、Black Formatter | 4 空格、Black 格式化、Jupyter 根目录 | 数据分析/Notebook |
| 文档写作 | Markdown All in One、Draw.io Integration | 自动换行、关闭 minimap、16px 字体 | 写博客/画图 |
| 代码审查 | GitLens、Git Graph | 关闭 minimap、常开 diff 视图 | Review PR/变更 |

Python 的格式化配置示例：

```jsonc
{
  "[python]": {
    "editor.defaultFormatter": "ms-python.black-formatter",
    "editor.formatOnSave": true
  },
  "jupyter.notebookFileRoot": "${workspaceFolder}"
}
```

> `python.formatting.provider` 已经废弃；现在用语言级 `editor.defaultFormatter` 指定 Black、Ruff 等格式化扩展。

### 命令行与工作区配合

```bash
# 用指定 Profile 打开项目
code --profile "前端开发" ./my-frontend-project

# 用指定 Profile 打开多根工作区
code --profile "前端开发" ecommerce.code-workspace
```

几个容易混淆的点：

- **Profile 是用户级配置**，不会因为打开某个工作区就自动切换；需要手动切换，或用 `--profile` 指定。
- **工作区/文件夹设置仍然覆盖 Profile 里的同名用户设置**。Profile 适合隔离"扩展集和默认偏好"，不能替代项目级配置。
- **同一个工作区可以用不同 Profile 打开**：例如全栈工作区用"前端开发" Profile 时，只启用前端相关扩展。
- **导出/导入用 Profiles 菜单**；命令行用 `--profile` 按 Profile 打开。

📋 **本章小结**

- VSCode 有两种工作区形态：**单文件夹工作区**与**多根工作区**；`.code-workspace` 是多根工作区的描述文件，不是第三种模式
- `.code-workspace` 支持 `folders`、`settings`、`extensions`、`tasks`、`launch`；路径相对于工作区文件
- `folders[].name` 会用于 `${workspaceFolder:名称}`；工作区级配置优先用它，避免路径歧义
- 设置优先级：默认 < 用户 < 远程 < 工作区 < 文件夹 < 语言级
- 扩展不是按文件夹隔离的；工作区只能推荐扩展，按项目切换扩展用 Profiles
- 多根工作区特别适合 **monorepo、前后端分离、微服务** 等多项目架构
- 跨文件夹任务用 `shell` + `options.cwd`；`preLaunchTask` 必须对应 `tasks` 里的 `label`
- Profiles 可包含设置、扩展、快捷键、代码片段、任务和 UI 状态；导出/导入用 Profiles 菜单，命令行用 `--profile`

> 设置系统是 VSCode 最容易被忽视、却又最强大的功能之一。下一章，我们将深入 `settings.json` 的"作用域链"。
