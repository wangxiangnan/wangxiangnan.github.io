# 第 20 章 单元测试与 pytest

你花了一下午写了一个精美的函数，测试了几个案例，一切正常，满意地提交了代码。第二天，同事告诉你："你那个函数在输入为空列表时会崩溃。"你一看——还真是。这种"改了 A 坏了 B"的经历，每个程序员都体会过。

单元测试就是给每个函数写"微型考试"：输入是什么、期望输出是什么、边界情况怎么处理。这些测试可以自动运行，每次修改代码后一键验证——如果你的改动破坏了已有功能，测试立刻亮红灯。这不是可选的"好习惯"，而是专业开发的底线要求。

## 20.1 unittest vs pytest

Python 内置了 `unittest` 模块，但社区更偏爱第三方库 `pytest`。对比一下：

```python
# unittest 风格（继承 TestCase）
import unittest

class TestCalculator(unittest.TestCase):
    def setUp(self):
        # 每个测试方法运行前执行
        self.calc = Calculator()

    def test_add(self):
        self.assertEqual(self.calc.add(2, 3), 5)

    def test_add_negative(self):
        self.assertEqual(self.calc.add(-1, -1), -2)

    def test_divide_by_zero(self):
        with self.assertRaises(ValueError):
            self.calc.divide(10, 0)

if __name__ == "__main__":
    unittest.main()
```

```python
# pytest 风格（直接写函数）
# test_calculator.py

def test_add():
    calc = Calculator()
    assert calc.add(2, 3) == 5

def test_add_negative():
    calc = Calculator()
    assert calc.add(-1, -1) == -2

def test_divide_by_zero():
    calc = Calculator()
    import pytest
    with pytest.raises(ValueError):
        calc.divide(10, 0)
```

pytest 的优势：

- **不需要继承 TestCase**：测试就是普通函数
- **用 `assert` 替代 `assertEqual`**：一个关键字搞定所有断言
- **更好的错误信息**：失败时自动显示变量值
- **fixture 机制**：比 setUp/tearDown 更灵活
- **丰富的插件生态**：覆盖率、并行执行、HTML 报告等

## 20.2 pytest 基础

### 安装与运行

```bash
# 安装
pip install pytest

# 运行所有测试（自动发现 test_*.py 和 *_test.py）
pytest

# 运行指定文件
pytest tests/test_calculator.py

# 运行指定函数
pytest tests/test_calculator.py::test_add

# 详细输出
pytest -v

# 显示 print 输出（默认被捕获）
pytest -s

# 失败时立即停止
pytest -x

# 失败时进入调试器
pytest --pdb
```

### 测试组织

```
my_project/
├── src/
│   └── calculator.py
├── tests/
│   ├── __init__.py
│   ├── conftest.py        # 共享 fixture
│   ├── test_calculator.py
│   └── test_formatter.py
└── pyproject.toml
```

pytest 自动发现规则：

- 文件名以 `test_` 开头或以 `_test` 结尾
- 函数名以 `test_` 开头
- 类名以 `Test` 开头（且没有 `__init__`）

## 20.3 Fixture：测试的"准备和清理"

fixture 是 pytest 最强大的特性之一。它解决了一个核心问题：**测试需要数据、需要数据库连接、需要临时文件……这些东西怎么优雅地准备和清理？**

### 基本 fixture

```python
# conftest.py（同目录下所有测试文件共享）
import pytest

@pytest.fixture
def sample_users():
    """提供测试用的用户数据"""
    return [
        {"name": "Alice", "age": 25, "role": "admin"},
        {"name": "Bob", "age": 30, "role": "user"},
        {"name": "Charlie", "age": 20, "role": "user"},
    ]


# test_user_service.py
def test_filter_admins(sample_users):
    """sample_users 自动注入"""
    admins = [u for u in sample_users if u["role"] == "admin"]
    assert len(admins) == 1
    assert admins[0]["name"] == "Alice"

def test_youngest_user(sample_users):
    youngest = min(sample_users, key=lambda u: u["age"])
    assert youngest["name"] == "Charlie"
```

### 带清理的 fixture

```python
import pytest
import tempfile
import os

@pytest.fixture
def temp_file():
    """创建临时文件，测试结束后自动删除"""
    fd, path = tempfile.mkstemp(suffix=".txt")
    os.write(fd, b"test data")
    os.close(fd)
    yield path  # yield 之前 = 准备，之后 = 清理
    os.unlink(path)  # 清理临时文件

def test_read_file(temp_file):
    with open(temp_file, "r") as f:
        content = f.read()
    assert content == "test data"
```

### fixture 的作用域

```python
@pytest.fixture(scope="function")  # 每个测试函数一个（默认）
def fresh_db():
    return create_test_db()

@pytest.fixture(scope="class")     # 每个测试类一个
def shared_connection():
    conn = create_connection()
    yield conn
    conn.close()

@pytest.fixture(scope="module")    # 每个测试模块一个
def expensive_resource():
    data = load_large_dataset()  # 只加载一次
    yield data

@pytest.fixture(scope="session")   # 整个测试会话一个
def app_config():
    return load_config()
```

小贴士：`scope` 越大，fixture 创建次数越少，但要注意状态污染——如果测试修改了 session 级的 fixture，后续测试可能受影响。

## 20.4 参数化：一个测试跑多组数据

当你想用不同的输入测试同一个函数时，参数化比复制粘贴测试函数优雅得多：

```python
import pytest

# 参数化：自动生成多个测试用例
@pytest.mark.parametrize("input_val, expected", [
    ("hello", "HELLO"),
    ("World", "WORLD"),
    ("", ""),
    ("123", "123"),
    ("MiXeD", "MIXED"),
])
def test_to_upper(input_val, expected):
    assert input_val.upper() == expected


# 参数化 + fixture 组合
@pytest.mark.parametrize("user_data", [
    {"name": "Alice", "age": 25},
    {"name": "Bob", "age": 0},       # 边界：年龄为 0
    {"name": "Charlie", "age": 150},  # 边界：超大年龄
])
def test_create_user(user_data):
    user = create_user(**user_data)
    assert user["name"] == user_data["name"]
    assert user["age"] == user_data["age"]
```

## 20.5 标记（Markers）

标记让你给测试分类，按需运行：

```python
import pytest
import sys

@pytest.mark.slow
def test_heavy_computation():
    """一个需要跑很久的测试"""
    result = sum(range(10_000_000))
    assert result > 0

@pytest.mark.skip(reason="API 接口暂未开放")
def test_external_api():
    response = call_external_api()
    assert response.status_code == 200

@pytest.mark.skipif(sys.platform == "win32", reason="Linux only")
def test_unix_specific():
    import fcntl  # 只有 Unix 系统有
    pass

@pytest.mark.xfail(reason="已知的 bug，待修复")
def test_known_bug():
    assert buggy_function() == "expected"  # 失败不报错，标记为 xfail
```

运行特定标记的测试：

```bash
# 只运行慢速测试
pytest -m slow

# 排除慢速测试
pytest -m "not slow"

# 运行慢速或集成测试
pytest -m "slow or integration"
```

在 `pytest.ini` 中注册自定义标记：

```ini
[pytest]
markers =
    slow: 标记为慢速测试
    integration: 集成测试
    smoke: 冒烟测试
```

## 20.6 Mock 与 Patch：隔离外部依赖

单元测试应该只测试你写的代码，不应该依赖数据库、网络、文件系统。Mock（模拟）让你用"假对象"替换真实依赖：

### unittest.mock.patch

```python
from unittest.mock import patch, MagicMock

# 被测函数
def get_weather(city: str) -> str:
    import requests
    response = requests.get(f"https://api.weather.com/{city}")
    data = response.json()
    return f"{city}: {data['temp']}C"


# 测试：mock 掉 requests.get
@patch("requests.get")
def test_get_weather(mock_get):
    # 设置 mock 的返回值
    mock_response = MagicMock()
    mock_response.json.return_value = {"temp": 25, "humidity": 60}
    mock_get.return_value = mock_response

    result = get_weather("beijing")
    assert result == "beijing: 25C"
    mock_get.assert_called_once_with("https://api.weather.com/beijing")


# 用 pytest + fixture 的方式
@pytest.fixture
def mock_weather_api():
    with patch("requests.get") as mock_get:
        mock_response = MagicMock()
        mock_response.json.return_value = {"temp": 20}
        mock_get.return_value = mock_response
        yield mock_get

def test_get_weather_with_fixture(mock_weather_api):
    result = get_weather("shanghai")
    assert "20C" in result
```

### Mock 数据库操作

```python
class UserRepository:
    def __init__(self, db_connection):
        self.db = db_connection

    def get_user(self, user_id):
        return self.db.execute(
            "SELECT * FROM users WHERE id = ?", (user_id,)
        )

    def create_user(self, name, email):
        return self.db.execute(
            "INSERT INTO users (name, email) VALUES (?, ?)", (name, email)
        )


def test_get_user():
    mock_db = MagicMock()
    mock_db.execute.return_value = {"id": 1, "name": "Alice", "email": "a@b.com"}

    repo = UserRepository(mock_db)
    user = repo.get_user(1)

    assert user["name"] == "Alice"
    mock_db.execute.assert_called_once_with(
        "SELECT * FROM users WHERE id = ?", (1,)
    )

def test_create_user():
    mock_db = MagicMock()
    mock_db.execute.return_value = 1  # 返回新 ID

    repo = UserRepository(mock_db)
    new_id = repo.create_user("Bob", "bob@example.com")

    assert new_id == 1
```

## 20.7 测试覆盖率

覆盖率告诉你"有多少代码被测试跑过"。它不是万能的（100% 覆盖率不代表没有 bug），但低覆盖率一定意味着测试不充分。

```bash
# 安装覆盖率插件
pip install pytest-cov

# 运行测试并生成覆盖率报告
pytest --cov=src --cov-report=term-missing

# 生成 HTML 报告
pytest --cov=src --cov-report=html
# 打开 htmlcov/index.html 查看可视化报告
```

配置覆盖率（`pyproject.toml`）：

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "--cov=src --cov-report=term-missing"

[tool.coverage.run]
omit = ["tests/*", "setup.py"]

[tool.coverage.report]
fail_under = 80  # 覆盖率低于 80% 则失败
exclude_lines = [
    "pragma: no cover",
    "if __name__ == .__main__.",
    "raise NotImplementedError",
]
```

## 20.8 CI 集成

在持续集成（CI）中自动运行测试是现代开发的标准实践：

```yaml
# .github/workflows/test.yml
name: Tests

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python-version: ["3.11", "3.12"]

    steps:
      - uses: actions/checkout@v4
      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
      - name: Install dependencies
        run: pip install -e ".[dev]"
      - name: Run tests
        run: pytest --cov=src --cov-report=xml
      - name: Check coverage
        run: coverage report --fail-under=80
```

## 20.9 测试最佳实践

1. **测试命名要说明意图**：`test_user_creation_with_duplicate_email_raises_error` 比 `test_user_2` 好一万倍
2. **每个测试只验证一件事**
3. **AAA 模式**：Arrange（准备）→ Act（执行）→ Assert（验证）
4. **测试应该是独立的**：不依赖其他测试的执行顺序
5. **测试要快**：单元测试应在秒级完成

```python
# AAA 模式示例
def test_shopping_cart_total():
    # Arrange: 准备
    cart = ShoppingCart()
    cart.add("Python book", price=59.9)
    cart.add("keyboard", price=299.0)

    # Act: 执行
    total = cart.calculate_total()

    # Assert: 验证
    assert total == 358.9
```

## 20.10 小结

- **pytest** 比 unittest 更简洁、更强大，是 Python 社区的测试首选
- **fixture** 提供灵活的测试准备和清理，支持作用域控制
- **参数化** 用 `@pytest.mark.parametrize` 一组数据跑多个测试
- **mock/patch** 隔离外部依赖，让测试只关注你的代码逻辑
- **覆盖率** 衡量测试充分度，配合 CI 自动化执行

## 20.12 参考答案

**第 1 题：**

```python
import pytest

class Stack:
    def __init__(self):
        self._items = []
    def push(self, item):
        self._items.append(item)
    def pop(self):
        if not self._items:
            raise IndexError("empty stack")
        return self._items.pop()
    def peek(self):
        if not self._items:
            raise IndexError("empty stack")
        return self._items[-1]
    def is_empty(self):
        return len(self._items) == 0
    def size(self):
        return len(self._items)

def test_push_and_pop():
    s = Stack()
    s.push(1)
    assert s.pop() == 1

def test_peek():
    s = Stack()
    s.push(42)
    assert s.peek() == 42
    assert s.size() == 1  # peek does not remove

def test_is_empty():
    s = Stack()
    assert s.is_empty()
    s.push(1)
    assert not s.is_empty()

def test_size():
    s = Stack()
    assert s.size() == 0
    s.push(1); s.push(2)
    assert s.size() == 2

def test_pop_empty_raises():
    s = Stack()
    with pytest.raises(IndexError):
        s.pop()

def test_peek_empty_raises():
    s = Stack()
    with pytest.raises(IndexError):
        s.peek()

def test_lifo_order():
    s = Stack()
    for i in range(5):
        s.push(i)
    assert [s.pop() for _ in range(5)] == [4, 3, 2, 1, 0]

def test_mixed_types():
    s = Stack()
    s.push(1); s.push("hello"); s.push([1, 2])
    assert s.pop() == [1, 2]
```

**第 7 题：**

`conftest.py` 是 pytest 的特殊配置文件：1. 其中定义的 fixture 自动被同目录及子目录下的所有测试文件共享，无需 import；2. 可以定义 hooks 来自定义测试行为；3. pytest 自动加载，不需要被测试发现机制匹配。

## 20.13 常见错误与避坑

**1. 测试之间有状态依赖**

```python
# 错误：test_b 依赖 test_a 的执行结果
_counter = 0

def test_a():
    global _counter
    _counter += 1
    assert _counter == 1

def test_b():
    assert _counter == 1  # 如果 test_b 先运行就挂了

# 正确：每个测试自己准备数据
def test_b_correct():
    counter = 0
    counter += 1
    assert counter == 1
```

**2. Mock 的路径不对**

```python
# 错误：patch 的是定义处
@patch("os.path.join")

# 正确：patch 的是使用处（被测代码 import 后的引用）
@patch("myapp.utils.os.path.join")
```

**3. 断言太宽泛**

```python
# 不好：只检查类型
assert isinstance(result, dict)

# 好：检查具体内容
assert result == {"name": "Alice", "age": 25}
```

**4. 忘记测试异常路径**

```python
# 不要只测 happy path
def test_divide():
    assert divide(10, 2) == 5

# 也要测异常
def test_divide_by_zero():
    with pytest.raises(ZeroDivisionError):
        divide(10, 0)
```

**5. 在 CI 中忽略测试失败**

永远不要让 CI 在测试失败时仍然标记为"成功"。配置 CI 时确保 `pytest` 的退出码被正确检查——非零退出码意味着构建失败。
