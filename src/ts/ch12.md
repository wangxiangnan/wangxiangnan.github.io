# 第十二章：类型兼容性与结构类型系统

TypeScript 使用**结构类型系统**（structural typing），而不是**名义类型系统**（nominal typing）。这是它类型系统的核心哲学之一。

## 结构类型 vs 名义类型

在名义类型系统里（比如 Java、C#），两个类型是否相同，取决于它们是否显式声明为同一个类型：

```java
class Dog { String name; }
class Cat { String name; }
// Dog 和 Cat 是不同的类型，即使结构一样
```

在结构类型系统里，只要两个类型的结构相同，它们就是兼容的：

```ts
interface Dog {
  name: string;
}

interface Cat {
  name: string;
}

let dog: Dog = { name: "Buddy" };
let cat: Cat = dog; // OK，因为结构相同
```

这种设计让 TypeScript 更灵活，但也意味着你不能像 Java 那样靠类型名来强制区分。

## 对象类型的兼容性

对象类型的兼容性遵循"鸭式辩型法"：只要一个对象包含目标类型要求的所有属性，且属性类型兼容，就可以赋值。

```ts
interface Point2D {
  x: number;
  y: number;
}

interface Point3D {
  x: number;
  y: number;
  z: number;
}

const point3D: Point3D = { x: 1, y: 2, z: 3 };
const point2D: Point2D = point3D; // OK，Point3D 包含 Point2D 的所有属性
```

但反过来不行：

```ts
const p2: Point2D = { x: 1, y: 2 };
const p3: Point3D = p2; // 错误，缺少 z
```

## 函数类型的兼容性

函数类型的兼容性更复杂。TypeScript 遵循以下规则：

1. 参数个数：目标函数参数可以比源函数少（函数可以忽略多余参数）。
2. 参数类型：源函数参数类型必须兼容目标函数参数类型。
3. 返回值类型：源函数返回值必须兼容目标函数返回值。

```ts
let fn1 = (a: number) => 0;
let fn2 = (a: number, b: string) => 0;

fn2 = fn1; // OK
fn1 = fn2; // 错误
```

这个规则看起来很反直觉，但想想回调函数就明白了：一个接收两个参数的函数，可以被一个只接收一个参数的函数替代，因为多余的参数会被忽略。

## 泛型的兼容性

泛型的兼容性取决于类型参数是否被实际使用：

```ts
interface Empty<T> {}

let x: Empty<number>;
let y: Empty<string>;

x = y; // OK，因为 T 没有被使用
```

如果泛型参数影响了结构，兼容性就会按实际结构判断。

## 为什么理解类型兼容性很重要

类型兼容性决定了一个值能不能赋值给另一个类型。理解结构类型系统，能帮你避免很多"为什么这里能赋值"或"为什么这里不能赋值"的困惑。
