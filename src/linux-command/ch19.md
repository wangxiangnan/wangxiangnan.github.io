# 第19章：DNS 与域名解析

## 19.1 DNS 是什么？

DNS（Domain Name System）就像互联网的"电话簿"——你输入 `google.com`，DNS 帮你查出 IP 地址 `142.250.80.46`。没有 DNS，你就得记住每个网站的 IP 地址来访问——你能记住几个？

**DNS 解析流程：**

1. 你的电脑先查本地缓存（`systemd-resolved` 缓存）
2. 缓存没有 → 问本地 DNS 服务器（`/etc/resolv.conf` 里配置的）
3. 本地 DNS 没有 → 问根域名服务器（`.`）
4. 根服务器说 → 去问 `.com` 顶级域服务器
5. `.com` 服务器说 → 去问 `google.com` 的权威 DNS
6. 权威 DNS 回答 → `142.250.80.46`

## 19.2 dig：DNS 调试利器

`dig`（Domain Information Groper）是 DNS 查询的"手术刀"——精确、详细、可控。

```bash
# 最基本的查询
dig google.com
# 输出示例：
# ;; ANSWER SECTION:
# google.com.        299    IN    A    142.250.80.46
#
# ;; Query time: 12 msec
# ;; SERVER: 8.8.8.8#53(8.8.8.8)
# ;; WHEN: Mon Jan 01 12:00:00 UTC 2024
# ;; MSG SIZE  rcvd: 55

# 输出字段详解：
# ANSWER SECTION → 回答部分（你要的结果）
# google.com.    → 查询的域名（末尾的 . 表示根域）
# 299            → TTL（缓存时间，秒）
# IN             → Internet 类（固定值）
# A              → 记录类型（A = IPv4 地址）
# 142.250.80.46  → 解析结果
# Query time     → 查询耗时
# SERVER         → 你使用的 DNS 服务器

# 只获取 IP 地址（最简洁！）
dig +short google.com
# 142.250.80.46

# 查询特定记录类型
dig google.com A          # A 记录（IPv4 地址）
dig google.com AAAA       # AAAA 记录（IPv6 地址）
dig google.com MX         # MX 记录（邮件服务器）
dig google.com NS         # NS 记录（域名服务器）
dig google.com TXT        # TXT 记录（文本记录，常用于 SPF/DKIM 验证）
dig google.com SOA        # SOA 记录（域名管理信息）
dig google.com CNAME      # CNAME 记录（别名）

# 查看 MX 记录（了解域名的邮件服务器）
dig +short google.com MX
# 10 smtp.google.com.
# 20 smtp2.google.com.
# 数字是优先级，越小越优先

# 查看 TXT 记录（常用于域名验证、SPF、DKIM）
dig +short google.com TXT
# "v=spf1 include:_spf.google.com ~all"

# 追踪完整的 DNS 解析过程（从根服务器一路追下来）
dig +trace google.com
# 输出每一步查询过程：
# 1. 问根服务器 → 得到 .com 服务器
# 2. 问 .com 服务器 → 得到 google.com 的 NS
# 3. 问 google.com 的 NS → 得到 A 记录

# 指定 DNS 服务器查询
dig @8.8.8.8 google.com           # 用 Google DNS
dig @1.1.1.1 google.com           # 用 Cloudflare DNS
dig @223.5.5.5 google.com         # 用阿里 DNS
dig @119.29.29.29 google.com      # 用腾讯 DNS

# 反向查询（IP → 域名）
dig -x 142.250.80.46
# 或 dig -x 8.8.8.8

# 查看某个域名的所有 NS 记录（了解域名的 DNS 托管商）
dig +short NS example.com
# ns1.cloudflare.com.
# ns2.cloudflare.com.

# 实用脚本：批量检查域名解析
for domain in google.com github.com example.com; do
  echo "=== $domain ==="
  dig +short $domain
done

# 检查 DNSSEC（域名系统安全扩展）
dig +dnssec google.com
```

## 19.3 nslookup 与 host

```bash
# nslookup：另一种 DNS 查询工具（交互式）
nslookup google.com
# Server:     8.8.8.8
# Address:    8.8.8.8#53
#
# Non-authoritative answer:
# Name:   google.com
# Address: 142.250.80.46

# 交互模式
nslookup
# > server 8.8.8.8              # 切换 DNS 服务器
# > set type=MX                 # 设置查询类型
# > google.com                  # 查询
# > set type=A
# > example.com
# > exit

# 指定 DNS 服务器
nslookup google.com 8.8.8.8

# host：最简洁的 DNS 查询
host google.com
# google.com has address 142.250.80.46
# google.com has IPv6 address 2607:f8b0:4004:800::200e
# google.com mail is handled by 10 smtp.google.com.

# 查询特定记录
host -t MX google.com
host -t NS google.com
host -t TXT google.com

# 反向查询
host 142.250.80.46

# dig vs nslookup vs host：
# dig      → 最详细，调试首选，输出结构化
# nslookup → 交互式，简单查询
# host     → 最简洁，快速查看
# 推荐：调试用 dig，快速查用 host
```

## 19.4 DNS 配置文件

```bash
# /etc/resolv.conf：DNS 解析器配置
cat /etc/resolv.conf
# 输出示例：
# nameserver 8.8.8.8
# nameserver 8.8.4.4
# search example.com local.lan
# options timeout:2 attempts:3

# 字段说明：
# nameserver → DNS 服务器 IP（最多 3 个，按顺序尝试）
# search     → 搜索域（输入短域名时自动补全）
#              如 search example.com → ping server1 自动查 server1.example.com
# options    → 解析选项
#   timeout:2   → 超时 2 秒
#   attempts:3  → 重试 3 次

# ⚠️  注意：直接编辑 /etc/resolv.conf 可能被覆盖！
# 如果系统用 systemd-resolved 或 NetworkManager
# 应该通过它们的配置来修改 DNS

# /etc/nsswitch.conf：名称解析顺序
cat /etc/nsswitch.conf | grep hosts
# hosts: files dns
# files → 先查 /etc/hosts
# dns   → 再查 DNS 服务器
# 可以改为：hosts: files mdns4_minimal [NOTFOUND=return] dns

# /etc/hosts：本地主机名映射（优先级最高！）
cat /etc/hosts
# 127.0.0.1   localhost
# ::1         localhost
# 192.168.1.100   web-prod-01
# 10.0.0.50       db-server
# 可以手动添加内网主机映射（不需要 DNS 服务器）
```


## 19.7 DNS 故障排查

```bash
# 当 "网站打不开" 时，DNS 排查流程：

# Step 1: 检查 DNS 解析是否正常
dig +short example.com
# 有 IP → DNS 正常，问题在其他地方
# 没有输出 → DNS 解析失败

# Step 2: 检查 DNS 服务器是否可达
dig @8.8.8.8 example.com
# 如果超时 → 8.8.8.8 不可达，换一个 DNS 试试
dig @223.5.5.5 example.com

# Step 3: 检查 resolv.conf 配置
cat /etc/resolv.conf
# nameserver 是否正常？

# Step 4: 清除 DNS 缓存
resolvectl flush-caches

# Step 5: 追踪解析过程
dig +trace example.com
# 看在哪一步失败

# Step 6: 检查 /etc/hosts 有没有干扰
cat /etc/hosts | grep example.com
# 如果 hosts 里有错误映射，会覆盖 DNS 结果！

# Step 7: 检查 nsswitch.conf 的解析顺序
grep hosts /etc/nsswitch.conf
# 确保 dns 在列表中

# 常见 DNS 问题：
# 1. DNS 服务器不可达 → 换一个
# 2. DNS 缓存中毒 → 清除缓存
# 3. /etc/hosts 干扰 → 检查并修正
# 4. TTL 太长导致更新不及时 → 等待或手动清除缓存
# 5. DNS 劫持（ISP 层面）→ 用 HTTPS DNS 或换 ISP

# DNS 诊断脚本
cat > dns-check.sh << 'SCRIPT'
#!/bin/bash
DOMAIN=$1
if [ -z "$DOMAIN" ]; then
  echo "Usage: $0 <domain>"
  exit 1
fi

echo "=== DNS Check for $DOMAIN ==="
echo ""

echo "--- Local DNS Resolution ---"
dig +short $DOMAIN

echo ""
echo "--- Google DNS (8.8.8.8) ---"
dig +short @8.8.8.8 $DOMAIN

echo ""
echo "--- Cloudflare DNS (1.1.1.1) ---"
dig +short @1.1.1.1 $DOMAIN

echo ""
echo "--- MX Records ---"
dig +short $DOMAIN MX

echo ""
echo "--- NS Records ---"
dig +short $DOMAIN NS

echo ""
echo "--- /etc/hosts Check ---"
grep -i $DOMAIN /etc/hosts || echo "No entry in /etc/hosts"

echo ""
echo "=== Done ==="
SCRIPT
chmod +x dns-check.sh
./dns-check.sh example.com
```

## 19.8 DNS 安全：DNSSEC 与 DNS-over-HTTPS

```bash
# DNS 的安全问题：
# 1. DNS 欺骗（缓存中毒）：攻击者篡改 DNS 缓存，让你访问假网站
# 2. DNS 劫持：ISP 篡改 DNS 结果（广告注入、 censorship）
# 3. DNS 查询明文传输：任何人可以窃听你查了什么域名

# DNSSEC（Domain Name System Security Extensions）
# 给 DNS 响应加上数字签名，防止篡改

# 检查域名是否启用 DNSSEC
dig +dnssec google.com
# 看 AD flag（Authenticated Data）：
# ;; flags: qr rd ra ad;  ← ad 表示 DNSSEC 验证通过

# 验证 DNSSEC 链（从根到目标域名）
dig +trace +dnssec google.com
# 每一级都有 RRSIG 签名记录

# 在线检测工具
# https://dnssec-analyzer.verisignlabs.com/
# 输入域名，查看 DNSSEC 链是否完整

# DNS-over-HTTPS（DoH）：加密 DNS 查询
# 传统 DNS 用 UDP 53 端口，明文传输，可被窃听和篡改
# DoH 用 HTTPS 传输 DNS，加密 + 防篡改

# 使用 curl 查询 DoH
curl -s "https://dns.google/resolve?name=google.com&type=A" | jq .
# 输出：
# {
#   "Status": 0,
#   "Question": [{"name": "google.com.", "type": 1}],
#   "Answer": [{"name": "google.com.", "type": 1, "data": "142.250.80.46"}]
# }

# 使用 Cloudflare DoH
curl -s "https://cloudflare-dns.com/dns-query?name=google.com&type=A" \
    -H "Accept: application/dns-json" | jq .

# 配置 systemd-resolved 使用 DoH
sudo nano /etc/systemd/resolved.conf
# [Resolve]
# DNS=1.1.1.1#cloudflare-dns.com 8.8.8.8#dns.google
# DNSOverTLS=opportunistic
# 重启：sudo systemctl restart systemd-resolved

# DNS-over-TLS（DoT）：另一种加密方案
# 用 TLS 853 端口传输 DNS
# systemd-resolved 支持 DoT：
sudo nano /etc/systemd/resolved.conf
# [Resolve]
# DNS=1.1.1.1 8.8.8.8
# DNSOverTLS=yes

# 本地 DNS 代理方案：dnsmasq
sudo apt install dnsmasq -y
sudo nano /etc/dnsmasq.conf
# 基本配置：
# listen-address=127.0.0.1
# no-resolv                    # 不使用 /etc/resolv.conf
# server=1.1.1.1               # 上游 DNS
# server=8.8.8.8
# cache-size=1000              # 缓存 1000 条记录
#
# 自定义域名解析（开发环境常用）
# address=dev.example.com/127.0.0.1
# address=test.local/192.168.1.100
#
# 广告拦截（类似 Pi-hole）
# conf-file=/etc/dnsmasq.adblock

# 重启 dnsmasq
sudo systemctl restart dnsmasq
```

## 19.9 搭建本地 DNS 服务器（dnsmasq 实战）

```bash

# 在本地开发时，让 dev.myapp.com 指向 127.0.0.1

sudo nano /etc/dnsmasq.d/internal.conf
# # 内网服务器
# address=/web-prod.internal/10.0.0.10
# address=/db-prod.internal/10.0.0.20
# address=/redis.internal/10.0.0.30
# address=/kafka.internal/10.0.0.40
#
# # 通配符（所有 *.dev.internal 都指向开发机）
# address=/.dev.internal/10.0.0.100

# 场景 3：DNS 缓存加速
sudo nano /etc/dnsmasq.d/cache.conf
# cache-size=10000        # 缓存 10000 条记录
# neg-ttl=3600           # 否定缓存 1 小时（NXDOMAIN）
# no-poll                # 不轮询 resolv.conf

# dnsmasq 日志和调试
sudo journalctl -u dnsmasq -f       # 实时查看 dnsmasq 日志
sudo tail -f /var/log/syslog | grep dnsmasq

# 查询缓存统计
sudo kill -SIGUSR1 $(pgrep dnsmasq)  # 发送信号，输出缓存统计到日志
```

## 19.10 DNS 自动化脚本

```bash
# 脚本 1：多 DNS 对比查询（检查 DNS 传播）
cat > ~/dns-compare.sh << 'SCRIPT'
#!/bin/bash
DOMAIN=$1
if [ -z "$DOMAIN" ]; then
    echo "Usage: $0 <domain>"
    exit 1
fi

declare -A DNS_SERVERS=(
    ["Google"]="8.8.8.8"
    ["Cloudflare"]="1.1.1.1"
    ["阿里"]="223.5.5.5"
    ["腾讯"]="119.29.29.29"
    ["114"]="114.114.114.114"
    ["Quad9"]="9.9.9.9"
)

echo "=== DNS 传播检查: $DOMAIN ==="
echo ""
printf "%-15s %-20s %s\n" "DNS服务器" "IP" "解析结果"
echo "----------------------------------------------"

for name in "${!DNS_SERVERS[@]}"; do
    ip="${DNS_SERVERS[$name]}"
    result=$(dig +short @"$ip" "$DOMAIN" 2>/dev/null | tr '\n' ', ' | sed 's/,$//')
    if [ -z "$result" ]; then
        result="(无结果)"
    fi
    printf "%-15s %-20s %s\n" "$name" "$ip" "$result"
done
SCRIPT
chmod +x ~/dns-compare.sh

# 脚本 2：DNS 变更监控（检测域名解析是否变化）
cat > ~/dns-watch.sh << 'SCRIPT'
#!/bin/bash
DOMAIN=$1
INTERVAL=${2:-60}    # 默认 60 秒检查一次
PREV_RESULT=""

if [ -z "$DOMAIN" ]; then
    echo "Usage: $0 <domain> [interval_seconds]"
    exit 1
fi

echo "监控 $DOMAIN 的 DNS 变化（每 ${INTERVAL}秒）"
echo "按 Ctrl+C 停止"
echo ""

while true; do
    CURRENT=$(dig +short "$DOMAIN" | sort | tr '\n' ',')
    TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')

    if [ -z "$PREV_RESULT" ]; then
        echo "[$TIMESTAMP] 初始结果: $CURRENT"
    elif [ "$CURRENT" != "$PREV_RESULT" ]; then
        echo "[$TIMESTAMP] ⚠️  DNS 变更！"
        echo "  旧: $PREV_RESULT"
        echo "  新: $CURRENT"
    else
        echo "[$TIMESTAMP] ✅ 无变化"
    fi

    PREV_RESULT="$CURRENT"
    sleep "$INTERVAL"
done
SCRIPT
chmod +x ~/dns-watch.sh

# 脚本 3：批量域名解析检查
cat > ~/dns-batch.sh << 'SCRIPT'
#!/bin/bash
DOMAIN_FILE=${1:-domains.txt}

if [ ! -f "$DOMAIN_FILE" ]; then
    echo "Usage: $0 <domains-file>"
    echo "文件格式：每行一个域名"
    echo "示例："
    echo "google.com"
    echo "github.com"
    echo "example.com"
    exit 1
fi

echo "=== 批量 DNS 解析 $(date) ==="
echo ""
printf "%-30s %-20s %s\n" "域名" "IP" "TTL"
echo "-------------------------------------------------------"

while read domain; do
    [ -z "$domain" ] && continue
    [[ "$domain" == \#* ]] && continue    # 跳过注释行

    RESULT=$(dig +short +time=3 "$domain" 2>/dev/null)
    TTL=$(dig +noall +answer "$domain" 2>/dev/null | awk '{print $2}' | head -1)

    if [ -z "$RESULT" ]; then
        printf "%-30s %-20s %s\n" "$domain" "(解析失败)" "-"
    else
        IP=$(echo "$RESULT" | head -1)
        printf "%-30s %-20s %s\n" "$domain" "$IP" "${TTL}s"
    fi
done < "$DOMAIN_FILE"
SCRIPT
chmod +x ~/dns-batch.sh

# 脚本 4：SSL 证书到期检查（结合 DNS）
cat > ~/ssl-check.sh << 'SCRIPT'
#!/bin/bash
DOMAINS=("example.com" "api.example.com" "blog.example.com")

echo "=== SSL 证书到期检查 $(date) ==="
echo ""

for domain in "${DOMAINS[@]}"; do
    # 先检查 DNS 解析
    IP=$(dig +short "$domain" | head -1)
    if [ -z "$IP" ]; then
        echo "$domain: DNS 解析失败"
        continue
    fi

    # 检查 SSL 证书
    EXPIRE=$(echo | openssl s_client -servername "$domain" -connect "$domain:443" 2>/dev/null | \
        openssl x509 -noout -enddate 2>/dev/null | cut -d= -f2)

    if [ -n "$EXPIRE" ]; then
        EXPIRE_EPOCH=$(date -d "$EXPIRE" +%s 2>/dev/null)
        NOW_EPOCH=$(date +%s)
        DAYS_LEFT=$(( (EXPIRE_EPOCH - NOW_EPOCH) / 86400 ))

        if [ "$DAYS_LEFT" -lt 0 ]; then
            echo "$domain ($IP): ❌ 已过期！($EXPIRE)"
        elif [ "$DAYS_LEFT" -lt 30 ]; then
            echo "$domain ($IP): ⚠️  $DAYS_LEFT 天后过期 ($EXPIRE)"
        else
            echo "$domain ($IP): ✅ $DAYS_LEFT 天后过期 ($EXPIRE)"
        fi
    else
        echo "$domain ($IP): 无法获取证书信息"
    fi
done
SCRIPT
chmod +x ~/ssl-check.sh
```

## 19.11 /etc/hosts 高级用法

```bash
# /etc/hosts 不只是简单的 IP-域名映射

# 1. 开发环境：本地域名映射
sudo nano /etc/hosts
# 127.0.0.1   myapp.local api.myapp.local admin.myapp.local
# 192.168.1.100   staging.myapp.com
# 10.0.0.50       db.internal cache.internal

# 2. 广告拦截（把广告域名指向空地址）
# 0.0.0.0   ads.doubleclick.net
# 0.0.0.0   pagead2.googlesyndication.com
# 0.0.0.0   analytics.google.com
# 更多列表：https://someonewhocares.org/hosts/

# 3. 安全：屏蔽恶意域名
# 0.0.0.0   malware-domain.com
# 0.0.0.0   phishing-site.com

# 4. 测试：让域名指向测试服务器
# 在 CI/CD 中临时修改 hosts 让测试跑在测试环境
sudo sh -c 'echo "10.0.0.200 api.example.com" >> /etc/hosts'
# 测试完成后删除
sudo sed -i '/api.example.com/d' /etc/hosts

# 5. hosts 文件的优先级
# /etc/nsswitch.conf 中的 hosts 行控制解析顺序
grep hosts /etc/nsswitch.conf
# hosts: files dns
# files = /etc/hosts（优先级最高）
# dns = DNS 服务器
# 可以改为：hosts: dns files    ← DNS 优先（通常不推荐）
```

## 19.12 DNS 记录类型速查

```bash
# 常见 DNS 记录类型及其用途：

# A 记录（Address）→ 域名指向 IPv4 地址
# 用途：最基本的记录，把域名解析到服务器 IP
# 示例：example.com → 93.184.216.34
dig example.com A

# AAAA 记录 → 域名指向 IPv6 地址
# 用途：IPv6 时代的 A 记录
# 示例：example.com → 2606:2800:220:1:248:1893:25c8:1946
dig example.com AAAA

# CNAME 记录（Canonical Name）→ 域名别名
# 用途：让一个域名指向另一个域名（不能和 A 记录共存）
# 示例：www.example.com → example.com
# 注意：根域名（apex）不能用 CNAME（RFC 规定）
dig www.example.com CNAME

# MX 记录（Mail Exchange）→ 邮件服务器
# 用途：指定处理该域名邮件的服务器
# 格式：优先级 + 邮件服务器域名
# 示例：10 mail.example.com（数字越小优先级越高）
dig example.com MX

# NS 记录（Name Server）→ 域名的 DNS 服务器
# 用途：指定该域名由哪个 DNS 服务器解析
# 示例：ns1.cloudflare.com, ns2.cloudflare.com
dig example.com NS

# TXT 记录 → 文本信息
# 用途：域名验证、SPF、DKIM、DMARC 等
# 示例：
# SPF:  "v=spf1 include:_spf.google.com ~all"
# DKIM: "v=DKIM1; k=rsa; p=MIGfMA0GCSqGSIb..."
# 域名验证: "google-site-verification=xxxxx"
dig example.com TXT

# SOA 记录（Start of Authority）→ 域名管理信息
# 用途：记录域名的主 DNS、管理员邮箱、序列号等
# 包含：主 NS、管理员邮箱、序列号、刷新/重试/过期时间
dig example.com SOA

# SRV 记录（Service）→ 服务定位
# 用途：指定某个服务运行在哪台服务器的哪个端口
# 格式：_service._protocol.name TTL class SRV priority weight port target
# 示例：_sip._tcp.example.com → 10 60 5060 sipserver.example.com
dig _sip._tcp.example.com SRV

# PTR 记录（Pointer）→ 反向解析（IP → 域名）
# 用途：邮件反垃圾、日志显示域名而非 IP
# 示例：93.184.216.34 → example.com
dig -x 93.184.216.34

# CAA 记录（Certification Authority Authorization）
# 用途：指定哪些 CA 可以为该域名颁发证书
# 示例：0 issue "letsencrypt.org"
dig example.com CAA

# DNS 记录优先级（查询时的匹配顺序）：
# 1. 精确匹配（= /path）
# 2. 最长前缀匹配
# 3. 正则匹配
# 4. 默认匹配（/）
```

## 19.13 DNS 故障排查决策树

```bash
# DNS 问题排查决策树（按顺序检查）：

# Q1: 能 ping 通 DNS 服务器吗？
ping -c 2 8.8.8.8
# ├─ Yes → Q2
# └─ No  → 网络层问题，回到第14章的诊断流程

# Q2: DNS 服务器能解析其他域名吗？
dig +short @8.8.8.8 google.com
# ├─ Yes → Q3（特定域名问题）
# └─ No  → DNS 服务器有问题，换一个

# Q3: 换一个 DNS 服务器能解析吗？
dig +short @1.1.1.1 yourdomain.com
# ├─ Yes → 原 DNS 服务器缓存了旧记录，等 TTL 过期
# └─ No  → Q4

# Q4: 域名的 NS 记录正常吗？
dig +short yourdomain.com NS
# ├─ 正常 → Q5
# └─ 异常 → 域名注册商配置问题，检查 NS 记录

# Q5: 权威 DNS 上的记录正确吗？
dig +short @ns1.your-dns-provider.com yourdomain.com A
# ├─ 正确 → 传播中，等 TTL 过期
# └─ 错误 → 修改 DNS 记录（在 DNS 管理面板）

# Q6: 本地缓存/hosts 有干扰吗？
resolvectl flush-caches        # 清缓存
cat /etc/hosts | grep domain   # 查 hosts

# 常见 DNS 错误及解决方案：
# SERVFAIL    → DNS 服务器配置错误/DNSSEC 验证失败
# NXDOMAIN    → 域名不存在（拼写错误？）
# REFUSED     → DNS 服务器拒绝查询（未授权区域）
# TIMEOUT     → DNS 服务器无响应（网络问题或服务器挂了）
```

## 19.14 常见坑与注意事项

```bash
# 坑 1：DNS 缓存导致修改不生效
# 修改了 DNS 记录但访问的还是旧 IP
# 解决：等 TTL 过期，或清除本地缓存
resolvectl flush-caches

# 坑 2：/etc/hosts 的优先级高于 DNS
# hosts 里有映射就不会查 DNS
# 调试时注意检查：cat /etc/hosts

# 坑 3：resolv.conf 被覆盖
# 手动编辑的 resolv.conf 被 NetworkManager/systemd-resolved 覆盖
# 解决：通过 nmcli 或 netplan 配置 DNS

# 坑 4：DNS 查询超时
# 某些 DNS 对特定记录查询很慢
# 解决：换 DNS 服务器，或设置 options timeout

# 坑 5：IPv6 DNS 问题
# 系统优先用 IPv6 DNS 但网络不支持 IPv6
# 解决：在 /etc/gai.conf 中设置 precedence ::ffff:0:0/96 100
# 让系统优先用 IPv4
```

## 19.9 本章小结

DNS 是互联网的"基础设施中的基础设施"。`dig` 是你调试 DNS 问题的首选工具，`+short` 看结果、`+trace` 看过程。记住排查链路：**本地缓存→resolv.conf→DNS 服务器→hosts 文件→nsswitch.conf**。大多数"网站打不开"的问题，在 DNS 这一层就能找到答案。
