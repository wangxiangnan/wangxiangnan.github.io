## 19.1 架构设计

在动手写代码之前，先理清架构。如果Function Calling是"接口协议"，ReAct是"设计模式"，LangGraph是"运行框架"，那么本章就是把接口、模式与框架整合成一个可运行的服务——服务本体，就是下面这张两节点循环图：

```text
START --> agent --(有tool_calls)--> tools --(执行完毕)--> agent
           |
           +--(没有tool_calls)--> END
```

- **Agent节点**：调用LLM，LLM可能返回文本回复，也可能返回tool_calls
- **Tool节点**：执行工具调用，返回ToolMessage
- **条件路由（Conditional Edge）**：检查Agent的输出，如果有tool_calls就走Tool节点，否则走END

这就是一个**带循环的两节点图**。简单，但极其强大。

## 19.2 完整代码：逐行解析

这是本章最重要的代码段。工具（15.7）、模型层（12.8）、人设（13.5.2）在前面章节已经定稿，本章只负责把它们组装成一张图；每一行仍有关键注释。

```python
"""
DocMind推理引擎 - LangGraph Agent完整实现
文件：src/agent/docmind_agent.py；后续章节从这里导入 DocMind、agent_node、tools
这是本教程的核心代码，请逐行理解

架构：Agent节点 <--> Tool节点，条件路由决定是否继续
"""

# ============================================================
# 导入部分
# ============================================================
from typing import TypedDict, Annotated, Literal
import json

# LangGraph核心
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.prebuilt import ToolNode

# LangChain核心
from langchain_core.messages import (
    HumanMessage,      # 用户消息
    AIMessage,         # AI消息（可能包含tool_calls）
    SystemMessage,     # 系统消息
    ToolMessage        # 工具结果消息
)
# 工具、模型层与人设分别来自 15.7、12.8、13.5.2，本章不再重复定义


# ============================================================
# 第一部分：定义State（Agent的"全局状态"）
# ============================================================

class AgentState(TypedDict):
    """
    DocMind Agent的状态定义
    
    为什么只有messages一个字段？
    - messages包含了整个对话历史（用户消息、AI回复、工具结果）
    - 使用add_messages reducer，新消息自动追加而非覆盖
    - 所有需要的信息（搜索结果、计算结果等）都在ToolMessage中
    - 这是一种"消息即状态"的设计模式
    """
    messages: Annotated[list, add_messages]
    # 关键：Annotated + add_messages = 消息追加模式
    # 每次节点返回 {"messages": [new_msg]}
    # new_msg会被追加到messages列表末尾
    # 而不是替换整个列表
```

State 只有 `messages` 一个字段——用户输入、AI 回复、工具结果都按追加方式留在这张共享白板上。接下来把工具和模型装上去。

```python
# ============================================================
# 第四部分：定义Agent节点（核心逻辑）
# ============================================================

def agent_node(state: AgentState) -> dict:
    """
    Agent节点：调用LLM，生成回复或工具调用请求
    
    这是整个Agent的"大脑"。它做一件事：
    把当前所有消息（包括用户输入、历史对话、工具结果）
    喂给LLM，让LLM决定：
    1. 直接给出文字回答？
    2. 还是调用工具获取更多信息？
    
    参数:
        state: 当前Agent状态，包含所有消息历史
    
    返回:
        dict: 包含新消息的字典（会被add_messages reducer追加到状态中）
    """
    
    # 获取当前消息列表
    messages = state["messages"]
    
    # 如果第一条消息不是SystemMessage，插入系统提示
    # 这确保LLM始终知道自己的角色和行为准则
    if not messages or not isinstance(messages[0], SystemMessage):
        messages = [SystemMessage(content=SYSTEM_PROMPT)] + messages
    
    # 调用LLM（带工具绑定）
    # LLM可能返回：
    # 1. AIMessage(content="文字回答") —— 不需要工具
    # 2. AIMessage(tool_calls=[...]) —— 需要调用工具
    response = llm_with_tools.invoke(messages)
    
    # 返回新消息
    # 因为messages字段使用了add_messages reducer
    # response会被追加到消息列表末尾
    return {"messages": [response]}


# ============================================================
# 第五部分：定义条件路由函数
# ============================================================

def should_continue(state: AgentState) -> Literal["tools", "__end__"]:
    """
    条件路由：决定下一步走工具节点还是结束
    
    这是LangGraph Agent的核心控制逻辑：
    - 检查最后一条AI消息是否包含tool_calls
    - 有tool_calls -> 走工具节点（执行工具）
    - 没有tool_calls -> 走END（给出最终回答）
    
    类比：这就像一个门卫，检查Agent的"出门证"
    - 如果Agent说"我还需要查资料"（有tool_calls）-> 放它去工具室
    - 如果Agent说"我已经知道答案了"（没有tool_calls）-> 放它出门
    """
    
    # 获取最后一条消息
    last_message = state["messages"][-1]
    
    # 检查是否有工具调用请求
    # AIMessage.tool_calls是一个列表：
    # - 空列表 [] -> 没有工具调用
    # - 非空列表 [tc1, tc2, ...] -> 有工具调用
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "tools"      # 有工具调用 -> 路由到工具节点
    else:
        return "__end__"    # 没有工具调用 -> 路由到结束节点
```

节点函数与路由函数都已就位，下面把节点和边接成图，并编译成可调用的 Agent。

```python
# ============================================================
# 第六部分：创建Tool节点
# ============================================================

# LangGraph内置的ToolNode
# 它自动处理：解析tool_calls -> 执行对应工具 -> 生成ToolMessage
# 我们只需要告诉它有哪些工具可用
tool_node = ToolNode(tools)


# ============================================================
# 第七部分：构建和编译图
# ============================================================

def build_agent_graph():
    """
    构建DocMind Agent的LangGraph
    
    图结构：
    START -> agent --(有tool_calls)--> tools --(执行完毕)--> agent
              |
              +--(没有tool_calls)--> END
    """
    
    # 1. 创建StateGraph
    # StateGraph接收一个TypedDict作为状态定义
    graph = StateGraph(AgentState)
    
    # 2. 添加节点
    graph.add_node("agent", agent_node)      # Agent节点（调用LLM）
    graph.add_node("tools", tool_node)        # Tool节点（执行工具）
    
    # 3. 添加边
    # 入口 -> Agent节点（所有请求都从Agent开始）
    graph.add_edge(START, "agent")
    
    # Tool节点 -> Agent节点（工具执行完后，让Agent看到结果继续推理）
    # 这就是循环的关键！
    graph.add_edge("tools", "agent")
    
    # 4. 添加条件边
    # Agent节点 -> 根据should_continue函数的返回值决定下一步
    graph.add_conditional_edges(
        "agent",           # 从agent节点出发
        should_continue,   # 路由函数
    )
    
    # 5. 编译图
    return graph.compile()


# ============================================================
# 第八部分：创建Agent实例
# ============================================================

docmind_agent = build_agent_graph()
```

图编译完成后，调用它只是往 `messages` 里追加一条新问题。下面先写两个薄薄的调用函数，再把它们收成一个门面。

```python
# ============================================================
# 第九部分：使用Agent
# ============================================================

def ask_docmind(question: str, verbose: bool = True) -> str:
    """
    向DocMind提问
    
    参数:
        question: 用户问题
        verbose: 是否打印执行过程
    
    返回:
        Agent的最终回答
    """
    if verbose:
        print(f"\n{'='*60}")
        print(f"问题: {question}")
        print(f"{'='*60}")
    
    # invoke()执行整个图，返回最终状态
    result = docmind_agent.invoke({
        "messages": [HumanMessage(content=question)]
    })
    
    # 打印执行过程
    if verbose:
        for msg in result["messages"]:
            msg_type = msg.__class__.__name__
            if msg_type == "SystemMessage":
                continue
            elif msg_type == "HumanMessage":
                print(f"  [用户] {msg.content}")
            elif msg_type == "AIMessage":
                if msg.tool_calls:
                    for tc in msg.tool_calls:
                        print(f"  [AI调用] {tc['name']}({tc['args']})")
                elif msg.content:
                    print(f"  [AI回答] {msg.content[:200]}")
            elif msg_type == "ToolMessage":
                print(f"  [工具结果] {msg.content[:150]}...")
    
    # 返回最后一条AI消息的内容
    final_message = result["messages"][-1]
    return final_message.content


def stream_docmind(question: str):
    """
    流式执行DocMind（实时显示每个节点的执行）
    """
    print(f"\n{'='*60}")
    print(f"问题: {question}")
    print(f"{'='*60}")
    print("执行过程:")
    
    for event in docmind_agent.stream({
        "messages": [HumanMessage(content=question)]
    }):
        for node_name, node_output in event.items():
            print(f"\n  --- 节点 '{node_name}' 执行完毕 ---")
            
            if "messages" in node_output:
                for msg in node_output["messages"]:
                    msg_type = msg.__class__.__name__
                    if msg_type == "AIMessage":
                        if msg.tool_calls:
                            for tc in msg.tool_calls:
                                print(f"    调用: {tc['name']}({json.dumps(tc['args'], ensure_ascii=False)})")
                        else:
                            print(f"    回答: {msg.content[:200]}")
                    elif msg_type == "ToolMessage":
                        print(f"    工具结果: {msg.content[:150]}")
    
    print(f"\n{'='*60}")


# ============================================================
# 统一入口：后续章节一律通过 DocMind().ask() 调用
# ============================================================

class DocMind:
    """DocMind 的统一门面：把图的编译与调用收在一处。

    第20-28章需要问答入口时一律用 DocMind().ask(q)，
    不再各自实现 ask_docmind / .run / .ask 多套方法名。
    """

    def __init__(self):
        self.graph = docmind_agent

    def ask(self, question: str) -> str:
        result = self.graph.invoke({
            "messages": [HumanMessage(content=question)]
        })
        return result["messages"][-1].content

    def stream(self, question: str):
        """逐 token 产出回答，供 SSE/CLI 使用"""
        for chunk, _meta in self.graph.stream(
            {"messages": [HumanMessage(content=question)]},
            stream_mode="messages",
        ):
            if chunk.content:
                yield chunk.content
```

## 19.3 代码深度解析

### 19.3.1 为什么Agent节点和Tool节点形成循环？

```python
graph.add_edge("tools", "agent")  # Tool执行完 -> 回到Agent
graph.add_conditional_edges("agent", should_continue)  # Agent决定下一步
```

这个设计模拟了ReAct的核心循环：

1. Agent思考并决定调用工具（返回tool_calls）
2. Tool节点执行工具（返回ToolMessage）
3. Agent看到工具结果，继续思考
4. 如果还需要更多信息，再次调用工具（回到步骤2）
5. 如果信息充分，给出最终回答（结束）

> 类比：这就像一个研究员的工作模式——去图书馆查资料（Tool），回来写论文（Agent），发现还缺资料（tool_calls），再去图书馆（Tool），直到论文写完（END）。

### 19.3.2 ToolNode做了什么？

```python
tool_node = ToolNode(tools)
```

`ToolNode`是LangGraph内置的"工具执行器"。它做了以下事情：

1. 从最后一条AIMessage中提取所有`tool_calls`
2. 对每个`tool_call`，在工具列表中查找对应的工具
3. 用`tool_call.args`调用工具函数
4. 将每个工具的执行结果包装成`ToolMessage`
5. 返回`{"messages": [tool_msg1, tool_msg2, ...]}`

**错误处理**：如果工具执行出错，ToolNode不会崩溃，而是生成一个包含错误信息的ToolMessage，让Agent知道发生了什么。

### 19.3.3 错误做法 vs 正确做法

```python
# 以下代码片段只作对照，导入见 19.2
# ---- 错误做法1：忘记绑定工具 ----
llm = DocMindModel().get_llm()
# 没有 llm.bind_tools(tools)
# 结果：LLM永远不会返回tool_calls，Agent变成了纯聊天机器人

# ---- 错误做法2：忘记添加tools->agent的边 ----
graph.add_edge(START, "agent")
graph.add_conditional_edges("agent", should_continue)
# 没有 graph.add_edge("tools", "agent")
# 结果：工具执行完后，图不知道该去哪，直接结束

# ---- 错误做法3：条件路由返回值不匹配 ----
def should_continue(state):
    if state["messages"][-1].tool_calls:
        return "continue"  # 但图中没有叫"continue"的节点！
    return "stop"          # 也没有"stop"节点！
# 结果：compile()报错或运行时KeyError

# ---- 正确做法 ----
llm_with_tools = llm.bind_tools(tools)          # 绑定工具
graph.add_edge("tools", "agent")                 # 循环边
graph.add_conditional_edges("agent", should_continue)  # 返回节点名
```

## 19.4 高级特性：自定义Tool节点

内置的ToolNode很方便，但有时我们需要自定义工具执行逻辑——比如加执行日志、权限检查、超时控制。自己写一个与ToolNode同职责的节点函数即可：

```python
"""
自定义Tool节点：添加日志、权限检查、超时控制
（承接 19.2：AgentState、tool_map 已在前面定义）
"""
import json
import time
from langchain_core.messages import ToolMessage

def custom_tool_node(state: AgentState) -> dict:
    """
    自定义工具节点
    在内置ToolNode的基础上添加：
    - 执行日志
    - 权限检查
    - 超时控制
    """
    last_message = state["messages"][-1]
    tool_messages = []
    
    for tool_call in last_message.tool_calls:
        tool_name = tool_call["name"]
        tool_args = tool_call["args"]
        tool_id = tool_call["id"]
        
        print(f"\n  [自定义Tool节点]")
        print(f"    工具: {tool_name}")
        print(f"    参数: {tool_args}")
        
        # 权限检查：某些工具需要特殊权限
        restricted_tools = ["delete_document", "modify_system"]
        if tool_name in restricted_tools:
            print(f"    状态: 被拒绝（需要管理员权限）")
            tool_messages.append(ToolMessage(
                content=json.dumps({
                    "error": f"工具 '{tool_name}' 需要管理员权限，当前用户无权使用"
                }, ensure_ascii=False),
                tool_call_id=tool_id,
                name=tool_name
            ))
            continue
        
        # 执行工具
        start_time = time.time()
        try:
            if tool_name in tool_map:
                result = tool_map[tool_name].invoke(tool_args)
                elapsed = time.time() - start_time
                print(f"    状态: 成功 ({elapsed:.2f}s)")
                
                tool_messages.append(ToolMessage(
                    content=json.dumps(result, ensure_ascii=False) if isinstance(result, dict) else str(result),
                    tool_call_id=tool_id,
                    name=tool_name
                ))
            else:
                print(f"    状态: 工具不存在")
                tool_messages.append(ToolMessage(
                    content=f"错误：工具 '{tool_name}' 不存在",
                    tool_call_id=tool_id,
                    name=tool_name
                ))
        except Exception as e:
            elapsed = time.time() - start_time
            print(f"    状态: 失败 ({elapsed:.2f}s) - {str(e)}")
            tool_messages.append(ToolMessage(
                content=f"工具执行失败: {str(e)}",
                tool_call_id=tool_id,
                name=tool_name
            ))
    
    return {"messages": tool_messages}
```

上面只是节点函数的定义，要让它真正跑起来还差两步：

```python
# 第一步：用自定义节点替换内置ToolNode接入图，其余结构一字不改
graph.add_node("tools", custom_tool_node)   # 原来是 graph.add_node("tools", tool_node)

# 第二步：条件边照旧
graph.add_edge("tools", "agent")
graph.add_conditional_edges("agent", should_continue)
```

两点如实说明：一是**节点必须经`add_node`接入才会生效**——只定义函数不接入，LangGraph不会执行它；二是`restricted_tools`里的`delete_document`、`modify_system`只是**示意名单**——本章定义的工具只有`search_documents`、`calculate`、`get_system_status`三个，都不是受限工具。实际使用时，把这一行换成你系统里真实存在的敏感工具名，权限检查才有意义。

## 19.5 添加Recursion Limit（安全阀）

Agent是一个带循环的图——如果LLM每次都坚持"我再查一次资料"，图就会永远转下去。**递归限制（recursion_limit）**就是安全阀：限制一次执行最多走多少个节点步，超过就抛出`GraphRecursionError`停下来。

它只有一个正确的传入位置——**调用时的config**，而不是编译期，也不存在什么"全局默认"：

```python
app = graph.compile()   # 编译期不涉及递归限制

result = app.invoke(
    {"messages": [HumanMessage(content="你好")]},
    config={"recursion_limit": 10}  # 本次执行最多10个节点步
)

# 流式执行同理，也是通过config传入
for event in app.stream(
    {"messages": [HumanMessage(content="你好")]},
    config={"recursion_limit": 10},
):
    ...
```

如果你曾在别的示例里见过`graph.compile(checkpointer=MemorySaver())`，并以为这与递归限制有关——那是误会。**Checkpointer（检查点器）是图的持久化组件**，负责把每一步状态存档，跟"最多执行几步"毫无关系；本章用不到它，下一章（第20章）会正式展开。

把要点收进一张速查表：

| 要点 | 说明 |
| ---- | ---- |
| 默认值 | 25 个节点步 |
| 传入位置 | invoke / stream 的 config：`{"recursion_limit": N}` |
| 计数方式 | 每执行一个节点记1步，一轮工具调用消耗agent+tools共2步 |
| 超限后果 | 抛出`GraphRecursionError`，本次执行终止 |
| 与Checkpointer的关系 | 无关——那是持久化组件，见第20章 |

**默认的recursion_limit是25**：如果你的Agent需要执行超过12轮工具调用，需要显式调大这个值。但一般来说，超过10轮工具调用说明问题设计有问题——要么问题太复杂应该拆分，要么工具不够好用。

## 本章小结

- **Agent节点调用LLM，Tool节点执行工具**——两者靠`add_edge("tools", "agent")`循环边与条件边构成ReAct闭环。
- **消息即状态**：State只有messages一个字段，`add_messages` reducer让新消息追加而非覆盖，对话历史自然生长在消息列表里。
- **ToolNode是内置工具执行器**——自动完成tool_calls解析、执行与ToolMessage包装，工具出错也不崩溃。
- **条件路由的返回值必须与图中节点名精确对应**——返回不存在的节点名，编译或运行时会直接报错。
- **要定制执行逻辑**，写一个同签名的节点函数并用`add_node("tools", ...)`替换内置ToolNode即可；权限名单要配真实的敏感工具，节点也必须真正接入图。
- **递归限制是安全阀**——在invoke/stream的config里传`recursion_limit`，默认25；它与Checkpointer无关，别混为一谈。
- **调试两板斧**——stream逐步观察每个节点的输出，`get_graph().draw_mermaid()`打印图结构。

把本章组件与下一章要补的能力对照着看，DocMind的升级路线一目了然：

| 本章组件 | 本章中的职责 | 第20章升级为 |
| ---- | ---- | ---- |
| AgentState（add_messages） | 单次运行内的消息状态 | Checkpointer给每一步状态存档 |
| docmind_agent.invoke(...) | 无状态调用，每次从零开始 | 带 thread_id 跨调用延续对话 |
| graph.compile() | 编译图 | compile(checkpointer=...) 接入持久化 |
| recursion_limit | 防单次执行无限循环 | 时间旅行可回溯任意历史状态 |

**下一章预告**：这个Agent目前每次运行都从零开始——下一章给它装上Checkpointer，让DocMind记住每一步状态，支持会话延续、崩溃恢复与时间旅行。
