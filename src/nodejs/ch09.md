# 第9章：Buffer 与二进制——字节级操作

## 引言：当 JavaScript 遇到了 0 和 1

JavaScript 最初是为浏览器设计的，处理的是字符串、数字、DOM——这些"高级"概念。它从不需要关心"这个字节是 0x4E 还是 0x6F"这种底层问题。

但 Node.js 要做服务器。服务器要：

- 读取二进制文件（图片、视频、压缩包）
- 处理网络协议（TCP 数据包是字节流）
- 操作加密数据（密钥和密文都是字节）

所以 Node.js 创造了 `Buffer`——一块直接操作内存的区域，让 JavaScript 能处理原始二进制数据。

> Buffer 就像是给 JavaScript 配了一副"显微镜"，让它能看到并操作单个字节。

---

## 9.1 Buffer 是什么？

Buffer 是一块**固定大小**的内存区域，存储原始二进制数据。你可以把它想象成一个字节数组。

```javascript
// 一个包含 5 个字节的 Buffer
const buf = Buffer.from([72, 101, 108, 108, 111]);
console.log(buf);           // <Buffer 48 65 6c 6c 6f>（十六进制显示）
console.log(buf.toString()); // "Hello"（因为这些字节的 UTF-8 编码是 H-e-l-l-o）
```

**Buffer 的关键特性**：

- 固定大小：创建后不能改变长度（不像数组可以 push）
- V8 堆外内存：Buffer 的数据不在 V8 的垃圾回收堆里，而是在 C++ 层分配的
- 类数组：可以用下标访问 `buf[0]`，有 `length` 属性
- Uint8Array 的子类：Buffer 继承自 `Uint8Array`

```typescript
// TypeScript 中的类型
const buf: Buffer = Buffer.from('hello');
// Buffer 是全局类型，不需要 import
```

## 9.2 创建 Buffer 的多种方式

### Buffer.from()——最常用

```javascript
// 从字符串创建
const buf1 = Buffer.from('你好世界', 'utf8');
console.log(buf1.length); // 12（中文 UTF-8 每字3字节，4个字 = 12）

// 从数组创建
const buf2 = Buffer.from([0x62, 0x75, 0x66, 0x66, 0x65, 0x72]);
console.log(buf2.toString()); // "buffer"

// 从另一个 Buffer 复制
const buf3 = Buffer.from(buf1);

// 从 ArrayBuffer 创建（共享内存！）
const ab = new ArrayBuffer(8);
const buf4 = Buffer.from(ab);

// 从十六进制字符串创建
const buf5 = Buffer.from('48656c6c6f', 'hex');
console.log(buf5.toString()); // "Hello"

// 从 Base64 创建
const buf6 = Buffer.from('SGVsbG8=', 'base64');
console.log(buf6.toString()); // "Hello"
```

### Buffer.alloc()——安全分配

```javascript
// 分配 256 字节，全部初始化为 0
const safe = Buffer.alloc(256);
console.log(safe[0]); // 0
console.log(safe[255]); // 0

// 指定填充值
const filled = Buffer.alloc(10, 0xFF);
console.log(filled); // <Buffer ff ff ff ff ff ff ff ff ff ff>

// 用字符串填充
const hello = Buffer.alloc(20, 'hello', 'utf8');
console.log(hello.toString()); // "hellohellohellohello"
```

### Buffer.allocUnsafe()——快但危险

```javascript
// ⚠️ 分配 256 字节，但不初始化！
// 可能包含旧数据（之前用过这块内存的程序留下的）
const unsafe = Buffer.allocUnsafe(256);
console.log(unsafe); // 里面可能有随机数据
```

**为什么有 allocUnsafe？**

因为**快**。`alloc` 需要把每个字节都设为 0（memset 操作），在分配大 Buffer 时这个开销很明显。如果你确定之后会覆盖所有数据，可以用 `allocUnsafe` 跳过初始化。

**安全隐患**：泄漏内存中的敏感数据（密码、密钥等）。在安全敏感的场景（生成响应给客户端等），请始终用 `alloc`。

```javascript
// ❌ 危险：可能泄漏内存中的旧数据
const response = Buffer.allocUnsafe(1024);
// 如果后面只写入了 500 字节，剩余 524 字节是泄漏的旧数据！
res.end(response);

// ✅ 安全
const response = Buffer.alloc(1024);
```

### Buffer.allocUnsafeSlow()——连池都不用

Node.js 内部有个"Buffer 池"（8KB 的预分配内存），小于 4KB 的 `allocUnsafe` 会从池里切一块。`allocUnsafeSlow` 跳过池子直接从操作系统申请内存。

一般你用不到它。除非你在写底层库，需要 Buffer 的生命周期完全由你控制。

## 9.3 Buffer 编码

Buffer 和字符串之间的转换需要指定**编码**（encoding）：

```javascript
const text = '你好';

// 各种编码的区别
console.log(Buffer.from(text, 'utf8'));    // <Buffer e4 bd a0 e5 a5 bd>（6 字节）
console.log(Buffer.from(text, 'utf16le')); // <Buffer 60 4f 7d 59>（4 字节）

const binary = Buffer.from([0xCA, 0xFE, 0xBA, 0xBE]);
console.log(binary.toString('hex'));    // "cafebabe"
console.log(binary.toString('base64')); // "yv66vg=="
console.log(binary.toString('latin1')); // 每个字节直接映射到 Unicode 码点
```

| 编码 | 用途 | 特点 |
| ------ | ------ | ------ |
| utf8 | 文本 | 变长(1-4字节/字符)，最常用 |
| ascii | 英文 | 7位，只支持 0-127 |
| utf16le | Windows | 固定2字节/字符（BMP） |
| latin1 | 二进制 | 1字节=1字符，无损转换 |
| base64 | 传输 | 6位编码，体积增大33% |
| base64url | URL安全 | 用 - 和 _ 替代 + 和 / |
| hex | 调试 | 每字节2个十六进制字符 |
| binary | 遗留 | latin1 的别名 |

## 9.4 Buffer 操作

### 读写字节

```javascript
const buf = Buffer.alloc(4);

// 写入单个字节
buf[0] = 0xCA;
buf[1] = 0xFE;
buf[2] = 0xBA;
buf[3] = 0xBE;

console.log(buf); // <Buffer ca fe ba be>（Java class 文件的魔数！）
```

### 读写整数

```javascript
const buf = Buffer.alloc(8);

// 大端序（网络字节序）
buf.writeUInt16BE(0x0102, 0);  // 在偏移0处写入 01 02
buf.writeUInt32BE(0x03040506, 2); // 在偏移2处写入 03 04 05 06

// 小端序（x86 CPU 字节序）
buf.writeUInt16LE(0x0708, 6);  // 在偏移6处写入 08 07（注意顺序反了）

console.log(buf); // <Buffer 01 02 03 04 05 06 08 07>

// 读取
console.log(buf.readUInt16BE(0)); // 258 (0x0102)
console.log(buf.readUInt32BE(2)); // 50595078 (0x03040506)
console.log(buf.readUInt16LE(6)); // 1800 (0x0708)
```

> **大端序 vs 小端序**：就像日期格式，中国人写 "2024年3月15日"（大端），美国人写 "03/15/2024"（奇怪序），而小端序是 "15-03-2024"。网络协议通常用大端序，Intel CPU 用小端序。

### 写入浮点数

```javascript
const buf = Buffer.alloc(8);

buf.writeFloatBE(3.14, 0);      // 4字节单精度浮点
buf.writeDoubleBE(3.14159, 0);  // 8字节双精度浮点

console.log(buf.readDoubleBE(0)); // 3.14159
```

### Buffer 切片与复制

```javascript
const original = Buffer.from('Hello World');

// slice 返回的是视图（共享内存！）
const slice = original.subarray(0, 5);
console.log(slice.toString()); // "Hello"

slice[0] = 0x4A; // 修改 slice 也会改变 original！
console.log(original.toString()); // "Jello World"

// 如果需要独立副本，用 Buffer.from() 或 copy()
const copy = Buffer.from(original);
copy[0] = 0x48;
console.log(copy.toString());     // "Hello World"
console.log(original.toString()); // "Jello World"（不受影响）
```

### Buffer 拼接

```javascript
// 拼接多个 Buffer
const buf1 = Buffer.from('Hello ');
const buf2 = Buffer.from('World');
const buf3 = Buffer.from('!');

const combined = Buffer.concat([buf1, buf2, buf3]);
console.log(combined.toString()); // "Hello World!"

// 指定总长度（性能优化）
const combined2 = Buffer.concat([buf1, buf2, buf3], 12);
```

### 比较和搜索

```javascript
const buf = Buffer.from('Hello World Hello');

// 比较两个 Buffer
console.log(Buffer.compare(Buffer.from('a'), Buffer.from('b'))); // -1
console.log(Buffer.compare(Buffer.from('b'), Buffer.from('a'))); // 1
console.log(Buffer.compare(Buffer.from('a'), Buffer.from('a'))); // 0

// 搜索
console.log(buf.indexOf('World'));     // 6
console.log(buf.indexOf('Hello', 1)); // 12
console.log(buf.includes('World'));   // true

// 判断是否为 Buffer
console.log(Buffer.isBuffer(buf));    // true
console.log(Buffer.isBuffer('hello')); // false
```

## 9.5 Buffer 与 TypedArray 的关系

Buffer 是 `Uint8Array` 的子类。它们共享很多 API，但有一些区别：

```javascript
// Buffer 是 Uint8Array 的子类
const buf = Buffer.from([1, 2, 3]);
console.log(buf instanceof Uint8Array); // true

// TypedArray 家族
const int8 = new Int8Array(4);      // 有符号8位
const uint8 = new Uint8Array(4);    // 无符号8位
const int16 = new Int16Array(4);    // 有符号16位
const uint16 = new Uint16Array(4);  // 无符号16位
const int32 = new Int32Array(4);    // 有符号32位
const float32 = new Float32Array(4); // 32位浮点
const float64 = new Float64Array(4); // 64位浮点
const bigInt64 = new BigInt64Array(4); // 64位大整数

// Buffer 与 TypedArray 互转
const buf2 = Buffer.from(uint8.buffer);
const uint8_2 = new Uint8Array(buf2.buffer, buf2.byteOffset, buf2.length);
```

**DataView：精确控制字节序**

```javascript
const buffer = new ArrayBuffer(16);
const view = new DataView(buffer);

// DataView 可以混合读写不同类型
view.setUint8(0, 0xFF);
view.setInt16(1, 256, false);      // false = 大端序
view.setFloat32(3, 3.14, true);    // true = 小端序

console.log(view.getUint8(0));             // 255
console.log(view.getInt16(1, false));      // 256
console.log(view.getFloat32(3, true));     // 3.14...
```

## 9.6 二进制协议解析实战

让我们解析一个自定义的消息协议：

```
协议格式：
+--------+--------+--------+--------+--------+---------+
| Magic  | Version| Type   | Length (2 bytes) | Payload |
| 1 byte | 1 byte | 1 byte | 2 bytes (BE)    | N bytes |
+--------+--------+--------+--------+--------+---------+

Magic: 0xAB (固定标识)
Version: 协议版本号
Type: 消息类型 (1=文本, 2=二进制, 3=心跳)
Length: Payload 长度（大端序 uint16）
Payload: 实际数据
```

```typescript
// 协议常量
const MAGIC = 0xAB;
const HEADER_SIZE = 5; // 1+1+1+2 = 5 字节

// 消息类型枚举
enum MessageType {
  TEXT = 1,
  BINARY = 2,
  HEARTBEAT = 3,
}

// 消息接口
interface Message {
  version: number;
  type: MessageType;
  payload: Buffer;
}

// 编码：消息 → Buffer
function encodeMessage(msg: Message): Buffer {
  const header = Buffer.alloc(HEADER_SIZE);

  header.writeUInt8(MAGIC, 0);
  header.writeUInt8(msg.version, 1);
  header.writeUInt8(msg.type, 2);
  header.writeUInt16BE(msg.payload.length, 3);

  return Buffer.concat([header, msg.payload]);
}

// 解码：Buffer → 消息
function decodeMessage(buf: Buffer): Message | null {
  if (buf.length < HEADER_SIZE) {
    return null; // 数据不够
  }

  const magic = buf.readUInt8(0);
  if (magic !== MAGIC) {
    throw new Error(`无效的魔数: 0x${magic.toString(16)}`);
  }

  const version = buf.readUInt8(1);
  const type = buf.readUInt8(2) as MessageType;
  const payloadLength = buf.readUInt16BE(3);

  if (buf.length < HEADER_SIZE + payloadLength) {
    return null; // 数据不完整
  }

  const payload = buf.subarray(HEADER_SIZE, HEADER_SIZE + payloadLength);

  return { version, type, payload };
}

// 使用示例
const msg: Message = {
  version: 1,
  type: MessageType.TEXT,
  payload: Buffer.from('Hello Protocol!', 'utf8'),
};

const encoded = encodeMessage(msg);
console.log('编码结果:', encoded.toString('hex'));
// ab0101000f48656c6c6f2050726f746f636f6c21

const decoded = decodeMessage(encoded);
console.log('解码结果:', {
  version: decoded!.version,
  type: MessageType[decoded!.type],
  payload: decoded!.payload.toString('utf8'),
});
// { version: 1, type: 'TEXT', payload: 'Hello Protocol!' }
```

### 处理 TCP 粘包：消息边界解析器

```typescript
class MessageParser {
  private buffer: Buffer = Buffer.alloc(0);

  /**
   * 喂入新数据，返回解析出的完整消息
   */
  feed(data: Buffer): Message[] {
    // 将新数据拼接到缓冲区
    this.buffer = Buffer.concat([this.buffer, data]);

    const messages: Message[] = [];

    while (this.buffer.length >= HEADER_SIZE) {
      // 检查魔数
      if (this.buffer.readUInt8(0) !== MAGIC) {
        // 寻找下一个魔数位置
        const nextMagic = this.buffer.indexOf(MAGIC, 1);
        if (nextMagic === -1) {
          this.buffer = Buffer.alloc(0);
          break;
        }
        this.buffer = this.buffer.subarray(nextMagic);
        continue;
      }

      // 读取 payload 长度
      const payloadLength = this.buffer.readUInt16BE(3);
      const totalLength = HEADER_SIZE + payloadLength;

      // 数据不够一个完整消息
      if (this.buffer.length < totalLength) {
        break;
      }

      // 解析完整消息
      const msg = decodeMessage(this.buffer.subarray(0, totalLength));
      if (msg) {
        messages.push(msg);
      }

      // 移除已解析的数据
      this.buffer = this.buffer.subarray(totalLength);
    }

    return messages;
  }
}
```

## 9.7 Buffer 拼接的正确姿势：中文乱码问题

### 问题复现

```javascript
import { createReadStream } from 'node:fs';

// 假设文件内容是中文
const stream = createReadStream('./chinese.txt', {
  highWaterMark: 11, // 故意设小，让中文字符被截断
});

let result = '';
stream.on('data', (chunk) => {
  // ❌ 直接 toString() 可能导致中文乱码！
  // 因为一个中文字符是3字节(UTF-8)，如果 chunk 在字符中间被截断...
  result += chunk.toString('utf8');
});

stream.on('end', () => {
  console.log(result); // 可能出现乱码："你好世�"
});
```

### 原因

UTF-8 编码中，一个中文字符占 3 个字节。如果 `highWaterMark` 是 11，那第4个字符（第10-12字节）会被截成两段：

- 第一个 chunk：字节 0-10（第4个字符只有1字节）
- 第二个 chunk：字节 11-...（第4个字符剩余2字节）

对不完整的字节序列做 `toString('utf8')` 就会产生乱码（替换字符 `�`）。

### 解决方案

```javascript
import { createReadStream } from 'node:fs';
import { StringDecoder } from 'node:string_decoder';

const stream = createReadStream('./chinese.txt', { highWaterMark: 11 });
const decoder = new StringDecoder('utf8');

let result = '';
stream.on('data', (chunk) => {
  // StringDecoder 会缓存不完整的字符，在下次调用时拼接
  result += decoder.write(chunk);
});

stream.on('end', () => {
  result += decoder.end(); // 刷新残留的不完整字符
  console.log(result); // 正确的中文！
});
```

`StringDecoder` 的原理：它会检查 Buffer 末尾的字节，如果发现一个多字节字符被截断了，就把截断的部分缓存起来，等下一个 chunk 到来时再拼接。

### 更好的方案：直接用正确的方式

```javascript
import { readFile } from 'node:fs/promises';

// 方案1：如果文件不大，直接 readFile
const text = await readFile('./chinese.txt', 'utf8');

// 方案2：用 readline 逐行处理（内部已处理编码问题）
import { createReadStream } from 'node:fs';
import { createInterface } from 'node:readline';

const rl = createInterface({
  input: createReadStream('./chinese.txt', 'utf8'),
});

for await (const line of rl) {
  console.log(line); // 正确的中文
}
```

## 9.8 TextEncoder / TextDecoder

这是 Web 标准 API，Node.js 也支持：

```javascript
// TextEncoder：字符串 → Uint8Array
const encoder = new TextEncoder();
const bytes = encoder.encode('你好世界');
console.log(bytes); // Uint8Array(12) [228, 189, 160, ...]
console.log(bytes.length); // 12

// TextDecoder：Uint8Array → 字符串
const decoder = new TextDecoder('utf-8');
const text = decoder.decode(bytes);
console.log(text); // "你好世界"

// 支持流式解码（处理被截断的多字节字符）
const streamDecoder = new TextDecoder('utf-8', { stream: true });
console.log(streamDecoder.decode(bytes.slice(0, 5), { stream: true })); // "你" + 不完整
console.log(streamDecoder.decode(bytes.slice(5))); // 剩余部分

// 支持其他编码
const gbkDecoder = new TextDecoder('gbk');
const gbkBytes = new Uint8Array([0xC4, 0xE3, 0xBA, 0xC3]);
console.log(gbkDecoder.decode(gbkBytes)); // "你好"
```

**TextEncoder/TextDecoder vs Buffer**：

- `TextEncoder` 只支持 UTF-8
- `TextDecoder` 支持多种编码（gbk, shift-jis, utf-16le 等）
- 跨平台兼容（浏览器+Node.js+Deno）
- 不需要 Node.js 特定的 `Buffer`

## 9.9 实战：简单的二进制序列化/反序列化库

让我们实现一个迷你版的 MessagePack / Protocol Buffers：

```typescript
/**
 * MiniPack - 一个简单的二进制序列化库
 * 
 * 格式：
 * - null:    0x00
 * - boolean: 0x01 + 1字节 (0/1)
 * - number:  0x02 + 8字节 double (BE)
 * - string:  0x03 + 4字节长度(BE) + UTF-8 数据
 * - array:   0x04 + 4字节元素数(BE) + 各元素
 * - object:  0x05 + 4字节键数(BE) + (键string + 值)*
 * - buffer:  0x06 + 4字节长度(BE) + 原始数据
 */

const enum TypeTag {
  NULL = 0x00,
  BOOLEAN = 0x01,
  NUMBER = 0x02,
  STRING = 0x03,
  ARRAY = 0x04,
  OBJECT = 0x05,
  BUFFER = 0x06,
}

class MiniPack {
  /**
   * 序列化任意 JavaScript 值为 Buffer
   */
  static serialize(value: unknown): Buffer {
    const chunks: Buffer[] = [];
    MiniPack.encodeValue(value, chunks);
    return Buffer.concat(chunks);
  }

  /**
   * 从 Buffer 反序列化为 JavaScript 值
   */
  static deserialize(buf: Buffer): unknown {
    const result = MiniPack.decodeValue(buf, 0);
    return result.value;
  }

  private static encodeValue(value: unknown, chunks: Buffer[]): void {
    if (value === null || value === undefined) {
      chunks.push(Buffer.from([TypeTag.NULL]));
    } else if (typeof value === 'boolean') {
      chunks.push(Buffer.from([TypeTag.BOOLEAN, value ? 1 : 0]));
    } else if (typeof value === 'number') {
      const buf = Buffer.alloc(9);
      buf.writeUInt8(TypeTag.NUMBER, 0);
      buf.writeDoubleBE(value, 1);
      chunks.push(buf);
    } else if (typeof value === 'string') {
      const strBuf = Buffer.from(value, 'utf8');
      const header = Buffer.alloc(5);
      header.writeUInt8(TypeTag.STRING, 0);
      header.writeUInt32BE(strBuf.length, 1);
      chunks.push(header, strBuf);
    } else if (Buffer.isBuffer(value)) {
      const header = Buffer.alloc(5);
      header.writeUInt8(TypeTag.BUFFER, 0);
      header.writeUInt32BE(value.length, 1);
      chunks.push(header, value);
    } else if (Array.isArray(value)) {
      const header = Buffer.alloc(5);
      header.writeUInt8(TypeTag.ARRAY, 0);
      header.writeUInt32BE(value.length, 1);
      chunks.push(header);
      for (const item of value) {
        MiniPack.encodeValue(item, chunks);
      }
    } else if (typeof value === 'object') {
      const keys = Object.keys(value as object);
      const header = Buffer.alloc(5);
      header.writeUInt8(TypeTag.OBJECT, 0);
      header.writeUInt32BE(keys.length, 1);
      chunks.push(header);
      for (const key of keys) {
        MiniPack.encodeValue(key, chunks); // 键作为 string 编码
        MiniPack.encodeValue((value as any)[key], chunks);
      }
    }
  }

  private static decodeValue(
    buf: Buffer,
    offset: number
  ): { value: unknown; newOffset: number } {
    const tag = buf.readUInt8(offset);
    offset += 1;

    switch (tag) {
      case TypeTag.NULL:
        return { value: null, newOffset: offset };

      case TypeTag.BOOLEAN:
        return { value: buf.readUInt8(offset) === 1, newOffset: offset + 1 };

      case TypeTag.NUMBER:
        return { value: buf.readDoubleBE(offset), newOffset: offset + 8 };

      case TypeTag.STRING: {
        const len = buf.readUInt32BE(offset);
        offset += 4;
        const str = buf.subarray(offset, offset + len).toString('utf8');
        return { value: str, newOffset: offset + len };
      }

      case TypeTag.BUFFER: {
        const len = buf.readUInt32BE(offset);
        offset += 4;
        const data = Buffer.from(buf.subarray(offset, offset + len));
        return { value: data, newOffset: offset + len };
      }

      case TypeTag.ARRAY: {
        const count = buf.readUInt32BE(offset);
        offset += 4;
        const arr: unknown[] = [];
        for (let i = 0; i < count; i++) {
          const result = MiniPack.decodeValue(buf, offset);
          arr.push(result.value);
          offset = result.newOffset;
        }
        return { value: arr, newOffset: offset };
      }

      case TypeTag.OBJECT: {
        const count = buf.readUInt32BE(offset);
        offset += 4;
        const obj: Record<string, unknown> = {};
        for (let i = 0; i < count; i++) {
          const keyResult = MiniPack.decodeValue(buf, offset);
          offset = keyResult.newOffset;
          const valResult = MiniPack.decodeValue(buf, offset);
          offset = valResult.newOffset;
          obj[keyResult.value as string] = valResult.value;
        }
        return { value: obj, newOffset: offset };
      }

      default:
        throw new Error(`未知类型标签: 0x${tag.toString(16)}`);
    }
  }
}

// 使用示例
const data = {
  name: '张三',
  age: 30,
  scores: [95, 87, 92],
  active: true,
  metadata: null,
};

const encoded = MiniPack.serialize(data);
console.log('序列化大小:', encoded.length, '字节');
console.log('十六进制:', encoded.toString('hex'));

const decoded = MiniPack.deserialize(encoded);
console.log('反序列化:', decoded);
// { name: '张三', age: 30, scores: [95, 87, 92], active: true, metadata: null }

// 性能对比
const jsonSize = Buffer.from(JSON.stringify(data)).length;
console.log(`JSON: ${jsonSize} 字节, MiniPack: ${encoded.length} 字节`);
console.log(`节省: ${((1 - encoded.length / jsonSize) * 100).toFixed(1)}%`);
```

## 9.10 常见坑点

### 坑1：Buffer.from(number) 不存在

```javascript
// ❌ 这不会创建一个"值为42"的 Buffer
// Buffer.from(42); // TypeError!

// ✅ 正确方式
const buf = Buffer.alloc(1);
buf.writeUInt8(42, 0);

// 或
const buf2 = Buffer.from([42]);
```

### 坑2：Buffer 比较用 equals，不用 ==

```javascript
const a = Buffer.from('hello');
const b = Buffer.from('hello');

console.log(a == b);       // false（引用比较）
console.log(a === b);      // false
console.log(a.equals(b));  // true ✅
```

### 坑3：Buffer.from(arrayBuffer) 是共享内存

```javascript
const ab = new ArrayBuffer(4);
const view = new Uint8Array(ab);
const buf = Buffer.from(ab);

view[0] = 42;
console.log(buf[0]); // 42！改了 view 也改了 buf

// 如果需要独立副本
const safeBuf = Buffer.from(Buffer.from(ab));
```

### 坑4：处理大整数

```javascript
// Number 能精确表示的最大整数是 2^53 - 1
console.log(Number.MAX_SAFE_INTEGER); // 9007199254740991

// 如果需要处理更大的数字，用 BigInt 相关方法
const buf = Buffer.alloc(8);
buf.writeBigInt64BE(9007199254740992n, 0); // 超过 MAX_SAFE_INTEGER
console.log(buf.readBigInt64BE(0)); // 9007199254740992n
```

## 9.11 本章小结

Buffer 是 Node.js 与底层二进制世界的桥梁。

| 操作 | 方法 | 安全性 |
| ------ | ------ | -------- |
| 安全创建 | Buffer.alloc(size) | ✅ 初始化为 0 |
| 快速创建 | Buffer.allocUnsafe(size) | ⚠️ 可能泄漏旧数据 |
| 从数据创建 | Buffer.from(...) | ✅ |
| 字符串转换 | toString(encoding) | 注意编码 |
| 整数读写 | readUInt32BE/writeUInt32BE | 注意字节序 |
| 拼接 | Buffer.concat([...]) | ✅ |
| 切片 | subarray() | ⚠️ 共享内存 |

**核心原则**：

1. 处理二进制数据时才需要 Buffer
2. 安全场景用 `alloc`，性能场景用 `allocUnsafe`
3. 注意字节序（BE/LE）
4. 注意 `subarray` 是视图不是副本
5. 中文等多字节字符的拼接要用 `StringDecoder`
