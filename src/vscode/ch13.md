# 第13章：精选插件推荐与配置

> [!TIP] Part IV: 插件生态与定制
> 如果把 VSCode 比作一个操作系统，那插件就是它的 App Store。但与手机 App 不同的是——装太多 App 手机只是变慢，装太多插件 VSCode 会让你怀疑人生。这一部分，我们将学会如何在插件的"花花世界"中保持理性，同时用代码片段和主题定制把 VSCode 打造成专属于你的开发利器。
> "There are only two hard things in Computer Science: cache invalidation and naming things." — Phil Karlton

如果让我在这句名言后面加一条，那就是：**第三件难事是给 VSCode 选插件**。

打开 VSCode 的插件市场，你会发现超过 40,000 个插件在向你招手。就像自助餐一样，每道菜看起来都不错，但全塞进盘子里只会让你消化不良。本章的核心理念是：**精选 + 精配 > 无脑安装一切**。

## 插件选择的哲学：少即是多

在安装任何插件之前，先问自己三个问题：

1. **我真的需要它吗？** 还是只是看别人装了觉得"也许有用"？
2. **它的功能是否已被内置或已有插件覆盖？** 比如 VSCode 已经内置了括号着色，你不需要再装 Bracket Pair Colorizer。
3. **它是否还在维护？** 看看最后更新时间、下载量、Issue 处理情况。

一个实用的原则：**将插件分为"必装"、"按需"和"尝鲜"三个层次**。必装插件控制在 10-15 个以内，按需插件根据项目类型启用/禁用，尝鲜插件用完即卸。

### 查看插件的性能影响

在命令面板（`Ctrl+Shift+P` / `⌘+Shift+P`）中搜索 `Developer: Startup Performance`，可以看到每个插件的启动耗时。如果某个插件启动时间超过 500ms，你就该审视它是否值得留下了。

## 代码质量类：让 Bug 无处遁形

### ESLint —— JavaScript/TypeScript 的守门员

ESLint 是前端开发的"安检门"——没有通过检查的代码，不配进入仓库。

**安装：**

```bash
# 项目依赖（必装）
npm install eslint --save-dev

# VSCode 扩展：在插件市场搜索 "ESLint" 安装（发布者：Microsoft）
```

**最佳配置（`.vscode/settings.json`）：**

```json
{
  "eslint.validate": [
    "javascript",
    "javascriptreact",
    "typescript",
    "typescriptreact",
    "vue",
    "svelte"
  ],
  "eslint.codeActionsOnSave.rules": null,
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit"
  },
  "eslint.format.enable": false
}
```

> **注意：** 不要让 ESLint 承担格式化的工作。格式化交给 Prettier，ESLint 只负责代码质量（比如未使用的变量、缺少依赖数组的 useEffect 等）。关闭 `eslint.format.enable` 是避免两者打架的关键。

**实用技巧：** 在状态栏看到 ESLint 的标识了吗？点击它，可以快速查看当前文件的错误/警告数量。右键点击可以查看 ESLint 的输出来排查配置问题——这在你遇到"ESLint 不工作了"的时候特别有用。

### Prettier —— 格式化的独裁者

Prettier 的设计哲学是" opiniated（有主见）"——它不给你太多选择，但给你的选择都是对的。这就像 TypeScript 的类型系统，约束越多，自由越多。

**安装：**

```bash
npm install prettier --save-dev
```

在项目根目录创建 `.prettierrc`：

```json
{
  "semi": true,
  "singleQuote": true,
  "tabWidth": 2,
  "trailingComma": "all",
  "printWidth": 100,
  "bracketSpacing": true,
  "arrowParens": "always",
  "endOfLine": "lf"
}
```

**VSCode 配置：**

```json
{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true,
  "[markdown]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.formatOnSave": true
  },
  "[python]": {
    "editor.defaultFormatter": null
  }
}
```

> **进阶：** 用 `editor.defaultFormatter` 按语言指定格式化器。比如 Python 用 Black，Java 用 Google Java Format，而不是全局一刀切。

**ESLint + Prettier 和平共处方案：**

```bash
npm install eslint-config-prettier --save-dev
```

在 ESLint 配置中继承 prettier：

```json
{
  "extends": [
    "eslint:recommended",
    "prettier"
  ]
}
```

`eslint-config-prettier` 会自动关闭所有与 Prettier 冲突的 ESLint 规则。从此 ESLint 管质量，Prettier 管颜值，各司其职。

### SonarLint —— 代码异味探测器

如果说 ESLint 是语法层面的检查，SonarLint 就是代码逻辑层面的 CT 扫描。它能发现更深层的问题，比如安全漏洞、逻辑缺陷、性能隐患。

```json
{
  "sonarlint.rules": {
    "javascript:S3776": {
      "level": "on",
      "parameters": {
        "threshold": 15
      }
    }
  }
}
```

SonarLint 特别适合在代码评审前提前发现问题。它的每一条建议都附带详细的解释和修复方案，堪比一位耐心的高级开发在旁边 pair programming。

## Git 增强类：让版本控制可视化

### GitLens —— Git 的 X 光机

GitLens 让你获得一种超能力：**看到任何一行代码，就能知道是谁、在什么时候、为什么写了这一行**。

**核心功能：**

- **行内 Blame（Git 追责）：** 光标停留在任意一行，行尾会显示最后修改者的信息
- **文件历史：** 查看一个文件的完整变更时间线
- **比较功能：** 快速比较不同分支、不同提交之间的差异

**推荐配置：**

```json
{
  "gitlens.codeLens.enabled": true,
  "gitlens.currentLine.enabled": true,
  "gitlens.hovers.currentLine.over": "line",
  "gitlens.blame.toggleMode": "file",
  "gitlens.views.commits.files.threshold": 100,
  "gitlens.advanced.blame.customArguments": [
    "--ignore-revs-file",
    ".git-blame-ignore-revs"
  ]
}
```

> **小技巧：** 如果你团队有人做了大规模格式化（比如 Prettier 一次性改了所有文件），把这些 commit 的 hash 放入 `.git-blame-ignore-revs` 文件，GitLens 的 blame 就会跳过这些无意义的提交。

**GitLens 的隐藏大招——`Git: Open File at Revision`：**

按 `Ctrl+Shift+P`（`⌘+Shift+P`），搜索 `GitLens: Open File at Revision...`，输入任意 commit hash，就能看到那个时间点的文件内容。这在排查"这个 bug 到底是什么时候引入的"时极其有用。

### Git Graph —— 分支可视化

Git Graph 给你的 Git 历史画了一张地铁线路图。所有的分支、合并、提交都一目了然。

```json
{
  "git-graph.graph.colour": true,
  "git-graph.graph.style": "rounded",
  "git-graph.dateFormat": "ISO Date & Time",
  "git-graph.repository.commits.fetchAvatars": true
}
```

打开方式：命令面板搜索 `Git Graph: View Git Graph`，或点击状态栏的 Git Graph 图标。

## 效率工具类：磨刀不误砍柴工

### Path Intellisense —— 路径自动补全

当你敲 `import ... from '` 的那一刻，Path Intellisense 就会自动弹出文件路径建议。再也不用手敲一长串相对路径了。

```json
{
  "path-intellisense.autoSlashAfterDirectory": true,
  "path-intellisense.absolutePathToWorkspace": true,
  "path-intellisense.mappings": {
    "@": "${workspaceFolder}/src",
    "@components": "${workspaceFolder}/src/components",
    "@utils": "${workspaceFolder}/src/utils"
  }
}
```

> **注意：** 如果你使用 TypeScript 并且配置了 `paths` 别名，Path Intellisense 的 `mappings` 需要与之对应。当然，TypeScript 自身的 IntelliSense 也能处理 `paths`，但对于 `.css`、图片等非 TS 文件，Path Intellisense 仍然是必要的。

### Error Lens —— 让错误"怼到脸上"

默认情况下，VSCode 的错误和警告信息需要你把鼠标悬停在波浪线上才能看到。Error Lens 改变了这一点——**它把错误信息直接显示在代码行的末尾**。

```json
{
  "errorLens.enabledDiagnosticLevels": ["error", "warning", "info"],
  "errorLens.delay": 500,
  "errorLens.excludeBySource": ["ts(80001)"],
  "errorLens.fontStyleItalic": false,
  "errorLens.messageTemplate": "$message [$source($code)]"
}
```

安装 Error Lens 后，你的代码会变成这样：

```javascript
const result = fetchData()  // ⚠️ 'fetchData' is defined but never used [eslint(no-unused-vars)]
```

没错，错误信息会像弹幕一样直接出现在代码行末尾。虽然看起来有点"吵"，但一旦习惯了，你会发现再也回不去了——因为**你不再需要移动鼠标去查看错误**。

### Todo Tree —— 别忘了那些 TODO

```javascript
// TODO: 优化这个查询的性能
// FIXME: 这里有个竞态条件
// HACK: 临时方案，下个月重构
```

这些注释散落在代码的各个角落，像地雷一样。Todo Tree 会把它们全部收集起来，在侧边栏形成一棵树状视图。

```json
{
  "todo-tree.general.tags": [
    "TODO",
    "FIXME",
    "HACK",
    "BUG",
    "XXX"
  ],
  "todo-tree.general.tagGroups": {
    "TODO": ["TODO", "XXX"],
    "FIXME": ["FIXME", "BUG", "HACK"]
  },
  "todo-tree.highlights.backgroundColourScheme": [
    "#ffcc00",
    "#ff6600"
  ],
  "todo-tree.filterCaseSensitive": false
}
```

## 外观增强类：让编码更愉悦

### Indent Rainbow —— 缩进可视化

对于 Python 或 YAML 这种依赖缩进的语言，Indent Rainbow 简直是救命神器。它用不同颜色标记不同层级的缩进，让你一眼看清代码的嵌套结构。

```json
{
  "indentRainbow.indicatorStyle": "light",
  "indentRainbow.colors": [
    "rgba(255,255,64,0.07)",
    "rgba(125,255,125,0.07)",
    "rgba(255,125,125,0.07)",
    "rgba(125,255,255,0.07)"
  ],
  "indentRainbow.errorColor": "rgba(255,20,147,0.3)"
}
```

### 括号着色：已内置

好消息：**VSCode 1.60+ 已经内置了括号对着色功能**，不需要再安装 `Bracket Pair Colorizer 2` 了！

```json
{
  "editor.bracketPairColorization.enabled": true,
  "editor.guides.bracketPairs": "active",
  "editor.guides.bracketPairsHorizontal": "active",
  "workbench.colorCustomizations": {
    "editorBracketHighlight.foreground1": "#FFD700",
    "editorBracketHighlight.foreground2": "#DA70D6",
    "editorBracketHighlight.foreground3": "#87CEEB",
    "editorBracketHighlight.foreground4": "#FF6347",
    "editorBracketHighlight.foreground5": "#98FB98",
    "editorBracketHighlight.foreground6": "#DDA0DD"
  }
}
```

如果你之前安装了 `Bracket Pair Colorizer 2`，建议卸载它——内置方案不仅功能等价，而且性能更好（毕竟是原生实现）。

### Peacock —— 多窗口识别神器

当你同时打开 5 个 VSCode 窗口时，如何快速区分哪个是哪个？Peacock 会为每个工作区设置不同的边框颜色，让你一眼识别。

```json
{
  "peacock.favoriteColors": [
    { "name": "Angular Red", "value": "#dd0031" },
    { "name": "Vue Green", "value": "#42b883" },
    { "name": "React Blue", "value": "#61dafb" },
    { "name": "Python Yellow", "value": "#306998" },
    { "name": "Rust Orange", "value": "#dea584" }
  ],
  "peacock.affectedSettings": [
    "activityBar",
    "titleBar",
    "statusBar",
    "tab"
  ]
}
```

## 进阶：工作区推荐插件深入

### `extensions.json` 的高级用法

除了简单的推荐列表，你还可以在团队 wiki 或 README 中说明每个插件的用途：

```json
{
  "recommendations": [
    "esbenp.prettier-vscode",
    "dbaeumer.vscode-eslint"
  ],
  "unwantedRecommendations": [
    "hookyqr.beautify"
  ]
}
```

`unwantedRecommendations` 用于标记那些不应该在这个项目中使用的插件。比如上面的例子中，我们告诉 VSCode 不要推荐 `Beautify`，因为我们已经用 Prettier 了。

### 按工作区管理插件

VSCode 支持为每个工作区单独启用/禁用插件：

1. 打开插件面板（`Ctrl+Shift+X` / `⌘+Shift+X`）
2. 找到目标插件
3. 点击齿轮图标 → 选择 `Disable (Workspace)` 或 `Enable (Workspace)`

**最佳实践：**

- 全局启用的插件：GitLens、Error Lens、Peacock 等通用工具
- 按工作区启用的插件：语言特定插件（如 Python 插件只在 Python 项目中启用）
- 按工作区禁用的插件：在特定项目中会产生大量噪音的插件

---

📋 **本章小结**

- 插件选择的核心原则是**少即是多**——精选 10-15 个必装插件，其余按需启用
- ESLint 管代码质量，Prettier 管格式化，各司其职不冲突
- GitLens + Git Graph 让 Git 操作从命令行走向可视化
- Error Lens 把错误信息直接显示在代码行末，改变你查看错误的方式
- 括号着色已内置，不需要再安装第三方插件
- 用 `.vscode/extensions.json` 为团队统一推荐插件
- 用 `.vscode/settings.json` 为项目统一编辑器配置
