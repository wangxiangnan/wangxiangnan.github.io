# 第24章：Docker容器化与CI/CD部署

## 引言：从"在我电脑上能跑"到"在任何地方都能跑"

每个程序员都经历过这个经典对话：

> 测试："这功能不行啊，报错了。"
> 开发："在我电脑上是好的啊！"
> 测试："......"
> 运维："......"

Docker解决的就是这个问题——它把你的应用连同整个运行环境（操作系统、依赖、配置）一起打包成一个"集装箱"（容器），无论在哪台机器上都能以完全相同的方式运行。

如果说Docker是"打包"，那CI/CD就是"快递"——自动化地把你的代码从Git仓库一路运送到生产服务器，中间还给你做质检（测试）和贴标签（版本号）。

## 24.1 Dockerfile最佳实践

### 24.1.1 基础Dockerfile

```dockerfile
# ===== 错误示范（新手常犯） =====
FROM node:20
WORKDIR /app
COPY . .
RUN npm install
EXPOSE 3000
CMD ["node", "dist/app.js"]

# 问题：
# 1. 使用完整node镜像（约1GB），太大
# 2. COPY . . 复制了node_modules、.git等不需要的文件
# 3. npm install包含devDependencies
# 4. 没有利用Docker层缓存
# 5. 以root用户运行（安全风险）
```

### 24.1.2 生产级多阶段构建

```dockerfile
# Dockerfile
# ===== 阶段1：安装依赖 =====
FROM node:20-alpine AS deps
WORKDIR /app

# 只复制package文件，利用Docker层缓存
# 只要package.json没变，这一层就不会重新构建
COPY package.json package-lock.json ./
RUN npm ci --production=false

# ===== 阶段2：构建 =====
FROM node:20-alpine AS builder
WORKDIR /app

COPY --from=deps /app/node_modules ./node_modules
COPY . .

# TypeScript编译
RUN npm run build

# 移除devDependencies
RUN npm prune --production

# ===== 阶段3：生产镜像 =====
FROM node:20-alpine AS runner
WORKDIR /app

# 安全：创建非root用户
RUN addgroup --system --gid 1001 nodejs && \
    adduser --system --uid 1001 appuser

# 只复制生产需要的文件
COPY --from=builder --chown=appuser:nodejs /app/dist ./dist
COPY --from=builder --chown=appuser:nodejs /app/node_modules ./node_modules
COPY --from=builder --chown=appuser:nodejs /app/package.json ./package.json

# 环境变量
ENV NODE_ENV=production
ENV PORT=3000

# 切换到非root用户
USER appuser

# 暴露端口
EXPOSE 3000

# 健康检查
HEALTHCHECK --interval=30s --timeout=10s --start-period=10s --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://localhost:3000/health || exit 1

# 启动命令
CMD ["node", "--max-old-space-size=512", "dist/app.js"]
```

# node:20          → ~1.1GB （包含完整Debian + 各种工具）

## 24.2 Docker Compose编排

```yaml
# docker-compose.yml
version: '3.8'

services:
  # ===== Node.js应用 =====
  app:
    build:
      context: .
      dockerfile: Dockerfile
      target: runner
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - DB_HOST=mysql
      - DB_PORT=3306
      - DB_USER=app
      - DB_PASSWORD=${DB_PASSWORD}
      - DB_NAME=myapp
      - REDIS_HOST=redis
      - REDIS_PORT=6379
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_healthy
    restart: unless-stopped
    deploy:
      resources:
        limits:
          memory: 512M
          cpus: '1.0'
    healthcheck:
      test: ["CMD", "wget", "--spider", "-q", "http://localhost:3000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 15s

  # ===== MySQL =====
  mysql:
    image: mysql:8.0
    ports:
      - "3306:3306"
    environment:
      - MYSQL_ROOT_PASSWORD=${MYSQL_ROOT_PASSWORD}
      - MYSQL_DATABASE=myapp
      - MYSQL_USER=app
      - MYSQL_PASSWORD=${DB_PASSWORD}
    volumes:
      - mysql_data:/var/lib/mysql
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql
    command: --default-authentication-plugin=mysql_native_password
      --character-set-server=utf8mb4
      --collation-server=utf8mb4_unicode_ci
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "root", "-p${MYSQL_ROOT_PASSWORD}"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s
    restart: unless-stopped

  # ===== Redis =====
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    command: redis-server --appendonly yes --maxmemory 256mb --maxmemory-policy allkeys-lru
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 3
    restart: unless-stopped

  # ===== Nginx反向代理 =====
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./nginx/certs:/etc/nginx/certs:ro
    depends_on:
      - app
    restart: unless-stopped

volumes:
  mysql_data:
  redis_data:
```

worker_processes auto;

    worker_connections 1024;

        location / {
            limit_req zone=api burst=50 nodelay;
            
            proxy_pass http://app_servers;
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection 'upgrade';
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_cache_bypass $http_upgrade;
            
            # 超时设置

            proxy_send_timeout 60s;
            proxy_read_timeout 60s;
        }

        location /health {
            access_log off;
            proxy_pass http://app_servers/health;
        }
    }

## 24.3 CI/CD流水线：GitHub Actions

```yaml
# .github/workflows/ci-cd.yml
name: CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

env:
  REGISTRY: ghcr.io
  IMAGE_NAME: ${{ github.repository }}
  NODE_VERSION: '20'

jobs:
  # ===== 代码质量检查 =====
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'
      
      - run: npm ci
      - run: npm run lint
      - run: npm run type-check

  # ===== 单元测试 =====
  test:
    runs-on: ubuntu-latest
    needs: lint
    
    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: test_password
          MYSQL_DATABASE: test_db
        ports:
          - 3306:3306
        options: >-
          --health-cmd="mysqladmin ping"
          --health-interval=10s
          --health-timeout=5s
          --health-retries=3
      
      redis:
        image: redis:7-alpine
        ports:
          - 6379:6379
        options: >-
          --health-cmd="redis-cli ping"
          --health-interval=10s
          --health-timeout=5s
          --health-retries=3
    
    steps:
      - uses: actions/checkout@v4
      
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'
      
      - run: npm ci
      
      - name: Run database migrations
        run: npx prisma migrate deploy
        env:
          DATABASE_URL: mysql://root:test_password@localhost:3306/test_db
      
      - name: Run tests
        run: npm run test -- --coverage
        env:
          DATABASE_URL: mysql://root:test_password@localhost:3306/test_db
          REDIS_URL: redis://localhost:6379
          NODE_ENV: test
      
      - name: Upload coverage
        uses: actions/upload-artifact@v4
        with:
          name: coverage
          path: coverage/

  # ===== 构建Docker镜像 =====
  build:
    runs-on: ubuntu-latest
    needs: test
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    
    permissions:
      contents: read
      packages: write
    
    steps:
      - uses: actions/checkout@v4
      
      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3
      
      - name: Log in to Container Registry
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      
      - name: Extract metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}
          tags: |
            type=sha,prefix=
            type=raw,value=latest
      
      - name: Build and push
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

  # ===== 部署到生产环境 =====
  deploy:
    runs-on: ubuntu-latest
    needs: build
    if: github.ref == 'refs/heads/main'
    environment: production
    
    steps:
      - name: Deploy to production
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.DEPLOY_HOST }}
          username: ${{ secrets.DEPLOY_USER }}
          key: ${{ secrets.DEPLOY_KEY }}
          script: |
            cd /opt/app
            docker compose pull
            docker compose up -d --remove-orphans
            docker image prune -f
            
            # 等待健康检查通过
            echo "Waiting for health check..."
            for i in $(seq 1 30); do
              if curl -sf http://localhost:3000/health > /dev/null; then
                echo "Application is healthy!"
                exit 0
              fi
              echo "Attempt $i/30..."
              sleep 2
            done
            echo "Health check failed!"
            docker compose logs app --tail=50
            exit 1
```

```typescript
// app.ts中的PM2优雅重启支持
import { createServer } from 'node:http';

const server = createServer(/* ... */);

server.listen(3000, () => {
  console.log('Server running on port 3000');
  
  // 通知PM2应用已就绪
  if (process.send) {
    process.send('ready');
  }
});

// 优雅关闭
process.on('SIGINT', gracefulShutdown);
process.on('SIGTERM', gracefulShutdown);

async function gracefulShutdown(signal: string): Promise<void> {
  console.log(`Received ${signal}, starting graceful shutdown...`);
  
  // 1. 停止接受新连接
  server.close(() => {
    console.log('HTTP server closed');
  });
  
  // 2. 等待现有请求完成（最多等10秒）
  const forceTimeout = setTimeout(() => {
    console.error('Forced shutdown after timeout');
    process.exit(1);
  }, 10000);
  
  try {
    // 3. 关闭数据库连接
    // await prisma.$disconnect();
    // await redis.quit();
    
    console.log('All connections closed, exiting...');
    clearTimeout(forceTimeout);
    process.exit(0);
  } catch (error) {
    console.error('Error during shutdown:', error);
    process.exit(1);
  }
}
```

### 24.5.1 结构化日志

```typescript
// logging/logger.ts
import pino from 'pino';

const logger = pino({
  level: process.env.LOG_LEVEL || 'info',
  
  // 生产环境使用JSON格式（便于ELK/Loki收集）
  ...(process.env.NODE_ENV === 'production' ? {} : {
    transport: {
      target: 'pino-pretty',
      options: { colorize: true, translateTime: 'SYS:standard' },
    },
  }),
  
  // 基础字段
  base: {
    service: process.env.SERVICE_NAME || 'my-app',
    version: process.env.APP_VERSION || '1.0.0',
    env: process.env.NODE_ENV || 'development',
  },
  
  // 序列化器
  serializers: {
    req: pino.stdSerializers.req,
    res: pino.stdSerializers.res,
    err: pino.stdSerializers.err,
  },
  
  // 自定义时间戳格式
  timestamp: pino.stdTimeFunctions.isoTime,
});

// 创建子logger（带请求上下文）
function createRequestLogger(requestId: string, userId?: number) {
  return logger.child({ requestId, userId });
}

export { logger, createRequestLogger };
```

### 24.5.2 健康检查端点

```typescript
// routes/health.ts
import { FastifyInstance } from 'fastify';
import { prisma } from '../db.js';
import { redis } from '../cache.js';

interface HealthStatus {
  status: 'healthy' | 'degraded' | 'unhealthy';
  timestamp: string;
  uptime: number;
  version: string;
  checks: {
    database: { status: string; latency?: number };
    redis: { status: string; latency?: number };
    memory: { heapUsed: string; heapTotal: string; rss: string };
  };
}

export async function healthRoutes(app: FastifyInstance): Promise<void> {
  // 简单的存活探针（liveness）
  app.get('/health', async () => {
    return { status: 'ok' };
  });

  // 详细的就绪探针（readiness）
  app.get('/health/ready', async (request, reply) => {
    const checks: HealthStatus['checks'] = {
      database: { status: 'unknown' },
      redis: { status: 'unknown' },
      memory: {
        heapUsed: '',
        heapTotal: '',
        rss: '',
      },
    };

    // 检查数据库
    try {
      const start = Date.now();
      await prisma.$queryRaw`SELECT 1`;
      checks.database = { status: 'up', latency: Date.now() - start };
    } catch {
      checks.database = { status: 'down' };
    }

    // 检查Redis
    try {
      const start = Date.now();
      await redis.ping();
      checks.redis = { status: 'up', latency: Date.now() - start };
    } catch {
      checks.redis = { status: 'down' };
    }

    // 内存使用
    const mem = process.memoryUsage();
    checks.memory = {
      heapUsed: `${(mem.heapUsed / 1024 / 1024).toFixed(2)} MB`,
      heapTotal: `${(mem.heapTotal / 1024 / 1024).toFixed(2)} MB`,
      rss: `${(mem.rss / 1024 / 1024).toFixed(2)} MB`,
    };

    const isHealthy = checks.database.status === 'up' && checks.redis.status === 'up';
    
    const health: HealthStatus = {
      status: isHealthy ? 'healthy' : 'unhealthy',
      timestamp: new Date().toISOString(),
      uptime: process.uptime(),
      version: process.env.APP_VERSION || '1.0.0',
      checks,
    };

    reply.status(isHealthy ? 200 : 503).send(health);
  });
}
```

## 24.6 常见坑点

### 坑点1：忘记处理信号

```typescript
// Docker发送SIGTERM时，如果应用不处理就直接kill -9
// 导致正在处理的请求被中断

// 必须处理SIGTERM实现优雅关闭！
process.on('SIGTERM', () => {
  // 停止接受新请求，等待现有请求完成，关闭连接
});
```

### 坑点2：Docker层缓存失效

```dockerfile
# 错误：每次代码变动都重新npm install
COPY . .
RUN npm install

# 正确：先复制package.json，利用层缓存
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
```

### 坑点3：环境变量泄露

```dockerfile
# 错误：在Dockerfile中硬编码敏感信息
ENV DB_PASSWORD=my_secret_password

# 正确：运行时注入
# docker run -e DB_PASSWORD=xxx my-app
# 或使用docker secrets / k8s secrets
```
