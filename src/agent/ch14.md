> [!WARNING] 先猜再读
> - 多数人以为"记忆"存在模型里，其实 LLM 是无状态的（Stateless）——所有记忆都要你在每次请求前自己拼好上下文。答案在 14.1。
> - 以为"保存全部对话"最安全，其实消息无限增长迟早撑爆上下文窗口，生产环境多用"摘要 + 窗口"混合策略。答案在 14.3。
> - 以为跨会话记忆要先微调模型，其实用 Embedding 加向量数据库按相似度检索就够了。答案在 14.4。

## 14.1 记忆的本质：管理上下文

在第12章（Model I/O）我们实践过：每次调用 LLM 都要把完整的历史消息发过去——因为 LLM 本身是无状态的，它不记得上一次对话说了什么。它像一个极其聪明但患有短期失忆症的专家，每次见面都像第一次见面。

但用户的期望不是这样的：

```text
用户: 什么是微服务？
AI:   微服务是一种将应用拆分为多个独立服务的架构风格。

用户: 它有什么优点？        <- "它"指的是微服务
AI:   ???                  <- 没有记忆，不知道"它"是什么
```

记忆系统（Memory）的本质是**管理上下文**——决定哪些信息应该保留在 LLM 的输入中，哪些可以被遗忘或归档。这就像管理一个缓存系统：空间（上下文窗口）有限，你需要智能地决定缓存什么、淘汰什么。

## 14.2 记忆类型分类

按照信息保存的位置和时长，Agent 的记忆分为三类：

| 记忆类型 | 人类类比 | Agent 实现 | 存储内容 | 生命周期 |
| --------- | --------- | ----------- | --------- | --------- |
| 短期记忆（Short-term Memory） | 工作记忆 | 对话上下文 | 当前对话消息列表 | 单次会话 |
| 长期记忆（Long-term Memory） | 长期记忆 | 向量数据库 | 用户偏好、历史知识 | 跨会话 |
| 工作记忆（Working Memory） | 便签纸 | 任务状态 | 当前任务中间结果 | 当前任务 |

```text
用户输入 -> [短期记忆(对话上下文)] -> Agent(LLM推理) <- [长期记忆(向量DB)]
                                      |
                                      v
                               [工作记忆(任务草稿)]
```

本章前半部分（14.3）解决短期记忆，14.4 解决长期记忆。

## 14.3 记忆策略实现

### 14.3.1 Buffer Memory：保存所有对话

最简单的方式——保存所有消息。

```python
from langchain_core.messages import HumanMessage, AIMessage, SystemMessage

class BufferMemory:
    """缓冲记忆：保存所有对话历史"""

    def __init__(self, system_prompt=""):
        self.system_prompt = system_prompt
        self.messages: list = []

    def add_user_message(self, content: str):
        self.messages.append(HumanMessage(content=content))

    def add_ai_message(self, content: str):
        self.messages.append(AIMessage(content=content))

    def get_messages(self) -> list:
        all_msgs = []
        if self.system_prompt:
            all_msgs.append(SystemMessage(content=self.system_prompt))
        all_msgs.extend(self.messages)
        return all_msgs

memory = BufferMemory("你是 DocMind。")
memory.add_user_message("什么是 Python？")
memory.add_ai_message("Python 是一种高级编程语言。")
memory.add_user_message("它有什么特点？")  # AI 能看到上下文
```

**优点**：简单、完整。**缺点**：消息无限增长，最终超出上下文窗口。

### 14.3.2 Window Memory：滑动窗口

只保留最近 K 轮对话。

```python
class WindowMemory:
    """滑动窗口记忆（Sliding Window）"""

    def __init__(self, k=5, system_prompt=""):
        self.k = k
        self.system_prompt = system_prompt
        self.messages: list = []

    def add_user_message(self, content: str):
        self.messages.append(HumanMessage(content=content))

    def add_ai_message(self, content: str):
        self.messages.append(AIMessage(content=content))

    def get_messages(self) -> list:
        max_msgs = self.k * 2  # K轮 = 2K条消息
        recent = self.messages[-max_msgs:] if len(self.messages) > max_msgs else self.messages
        all_msgs = []
        if self.system_prompt:
            all_msgs.append(SystemMessage(content=self.system_prompt))
        all_msgs.extend(recent)
        return all_msgs

memory = WindowMemory(k=3, system_prompt="你是 DocMind。")
# 模拟6轮对话后，前3轮会被丢弃
for i in range(6):
    memory.add_user_message(f"问题{i+1}")
    memory.add_ai_message(f"回答{i+1}")

msgs = memory.get_messages()
print(f"总存储: {len(memory.messages)}, LLM可见: {len(msgs) - 1}")
```

**优点**：token 可控。**缺点**：早期信息完全丢失。

### 14.3.3 Summary Memory：LLM 自动摘要

用 LLM 把旧对话压缩为摘要——这里正是第13章 Prompt 模板思想的落地：

```python
from langchain_openai import ChatOpenAI

class SummaryMemory:
    """摘要记忆 — 用 LLM 压缩历史"""

    def __init__(self, system_prompt="", max_messages=10, llm=None):
        self.system_prompt = system_prompt
        self.max_messages = max_messages
        self.messages: list = []
        self.summary = ""
        self.llm = llm or ChatOpenAI(model="deepseek-chat", temperature=0)

    def add_user_message(self, content: str):
        self.messages.append(HumanMessage(content=content))
        self._maybe_summarize()

    def add_ai_message(self, content: str):
        self.messages.append(AIMessage(content=content))
        self._maybe_summarize()

    def _maybe_summarize(self):
        if len(self.messages) <= self.max_messages:
            return
        half = len(self.messages) // 2
        old_msgs = self.messages[:half]

        # 压缩提示词：模板 + 变量（已有摘要 + 新对话）
        conv_text = "\n".join(
            f"{'用户' if isinstance(m, HumanMessage) else 'AI'}: {m.content}"
            for m in old_msgs
        )
        prompt = (
            f"将以下对话压缩为简洁摘要，保留关键信息。\n"
            f"已有摘要：{self.summary or '无'}\n"
            f"新对话：\n{conv_text}\n"
            f"输出合并后的摘要："
        )
        response = self.llm.invoke([HumanMessage(content=prompt)])
        self.summary = response.content
        self.messages = self.messages[half:]

    def get_messages(self) -> list:
        all_msgs = []
        if self.system_prompt:
            all_msgs.append(SystemMessage(content=self.system_prompt))
        if self.summary:
            all_msgs.append(SystemMessage(content=f"之前的对话摘要：{self.summary}"))
        all_msgs.extend(self.messages)
        return all_msgs
```

**优点**：保留关键信息，控制 token。**缺点**：摘要过程消耗额外 API 调用，可能丢失细节。

### 14.3.4 策略对比

| 策略 | Token 消耗 | 信息完整性 | 复杂度 | 适用场景 |
| ------ | ---------- | ----------- | -------- | --------- |
| Buffer | 无限增长 | 完整 | 低 | 短对话 |
| Window | 固定 | 丢失早期 | 低 | 中等长度对话 |
| Summary | 可控 | 保留关键 | 中 | 长对话 |
| Summary + Window | 可控 | 最佳平衡 | 高 | 生产环境推荐 |

## 14.4 向量记忆：用 Embedding 存储长期知识

对于跨会话的长期记忆，向量数据库（Vector Database）是最佳选择：

```python
from langchain_chroma import Chroma
from langchain_openai import OpenAIEmbeddings
from langchain_core.documents import Document

class VectorMemory:
    """向量长期记忆"""

    def __init__(self, persist_dir="./data/memory"):
        self.embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
        self.vectorstore = Chroma(
            collection_name="long_term_memory",
            embedding_function=self.embeddings,
            persist_directory=persist_dir,
        )

    def remember(self, content: str, metadata: dict = None):
        """记住一条信息"""
        doc = Document(
            page_content=content,
            metadata=metadata or {"type": "memory"},
        )
        self.vectorstore.add_documents([doc])

    def recall(self, query: str, k: int = 3) -> list:
        """回忆相关信息"""
        return self.vectorstore.similarity_search(query, k=k)

# 使用
memory = VectorMemory()
memory.remember("用户偏好详细的回答", {"type": "preference"})
memory.remember("用户的项目是用 Python 写的", {"type": "project"})
memory.remember("用户对微服务架构感兴趣", {"type": "interest"})

# 在新会话中回忆
results = memory.recall("用户喜欢什么样的回答？")
for doc in results:
    print(f"  回忆: {doc.page_content}")
```

> [!NOTE] Embedding 模型说明
> Embedding 模型与对话模型不同：DeepSeek 目前不提供 Embedding API，使用 `OpenAIEmbeddings` 需要单独配置 `OPENAI_API_KEY`，也可替换为本地开源 Embedding（如 BGE/M3E）。

## 14.5 实战演练：DocMind 的对话记忆

把"窗口 + 摘要"组合成 DocMind 的记忆管理器：

```python
# src/memory/conversation.py
"""DocMind 对话记忆模块"""
from langchain_core.messages import HumanMessage, AIMessage, SystemMessage
from langchain_openai import ChatOpenAI
from dotenv import load_dotenv

load_dotenv()

class DocMindMemory:
    """DocMind 的记忆管理器"""

    def __init__(self, system_prompt="", window_size=10, llm=None):
        self.system_prompt = system_prompt
        self.window_size = window_size
        self.messages: list = []
        self.summary = ""
        self.llm = llm or ChatOpenAI(model="deepseek-chat", temperature=0)

    def add_exchange(self, user_msg: str, ai_msg: str):
        """添加一轮对话"""
        self.messages.append(HumanMessage(content=user_msg))
        self.messages.append(AIMessage(content=ai_msg))
        self._maybe_summarize()

    def _maybe_summarize(self):
        """超出窗口时压缩旧消息"""
        max_msgs = self.window_size * 2
        if len(self.messages) <= max_msgs:
            return

        half = len(self.messages) // 2
        old = self.messages[:half]
        conv = "\n".join(
            f"{'用户' if isinstance(m, HumanMessage) else 'AI'}: {m.content}"
            for m in old
        )
        prompt = (
            f"压缩对话为摘要：\n已有：{self.summary or '无'}\n"
            f"新对话：\n{conv}\n输出合并摘要："
        )
        self.summary = self.llm.invoke([HumanMessage(content=prompt)]).content
        self.messages = self.messages[half:]

    def get_context(self) -> list:
        """获取当前上下文消息列表，可直接喂给模型"""
        msgs = []
        if self.system_prompt:
            msgs.append(SystemMessage(content=self.system_prompt))
        if self.summary:
            msgs.append(SystemMessage(content=f"对话摘要：{self.summary}"))
        msgs.extend(self.messages)
        return msgs

    def get_stats(self) -> dict:
        return {
            "messages_in_window": len(self.messages),
            "has_summary": bool(self.summary),
            "summary_length": len(self.summary),
        }
```

## 14.6 记忆管理最佳实践

1. **短对话（<10轮）**：直接用 Buffer Memory，简单可靠。
2. **中等对话（10-50轮）**：用 Window Memory，设置合理的 k 值。
3. **长对话（50+轮）**：用 Summary + Window 混合策略。
4. **跨会话记忆**：用向量数据库存储关键信息（用户偏好、项目信息）。
5. **何时遗忘**：当对话主题明确转换时，可以主动清除旧上下文。

### 14.6.1 记忆策略选择的决策树

```text
对话预计轮数？
├── < 10 轮 → Buffer Memory
│     理由：简单，不会超出上下文窗口
├── 10-50 轮 → Window Memory (k=5-10)
│     理由：token 可控，最近几轮信息最重要
├── 50+ 轮 → Summary + Window 混合
│     理由：长对话需要压缩，但不能完全丢失早期信息
└── 需要跨会话 → Vector Memory
      理由：向量检索可以找到最相关的历史信息
```

### 14.6.2 对话记忆的实际测试

验证记忆是否生效，核心就是下面这个循环——把记忆上下文喂给模型，再用"回忆类问题"试探：

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="deepseek-chat", temperature=0.7)
memory = WindowMemory(k=2, system_prompt="你是 DocMind，记住用户的信息。")

for user_msg in ["我叫张三，是一个后端开发者",
                 "我主要用 Python 和 Go",
                 "你还记得我叫什么吗？"]:
    memory.add_user_message(user_msg)
    response = llm.invoke(memory.get_messages())
    memory.add_ai_message(response.content)
    print(f"用户: {user_msg}")
    print(f"AI: {response.content[:80]}...")
```

测试要点：把 `WindowMemory(k=2)` 换成 `BufferMemory` 再跑一遍，前者到第三问往往已经答不出"我叫什么"，后者始终记得——这正是 14.3.2 说的"早期信息完全丢失"的直接证据。同一套对话脚本可以测任何实现了 `add_*` / `get_messages` 接口的记忆类。

### 14.6.3 Token 消耗估算

选择策略前先算成本。按"中文约 1.5 字符/token"粗估，50 轮对话（每条消息平均 200 字符）的消耗如下：

| 策略 | 50轮对话的上下文 | 预估 Token | 成本等级 |
| ------ | ---------------- | ----------- | --------- |
| Buffer Memory | 100 条消息，约 20000 字符 | 约 13000 | 高 |
| Window Memory (k=5) | 10 条消息，约 2000 字符 | 约 1300 | 低 |
| Window Memory (k=10) | 20 条消息，约 4000 字符 | 约 2700 | 低 |
| Summary + Window | 摘要 500 字符 + 4000 字符 | 约 3000 | 中 |

注意一个容易被忽略的事实：每轮新增消息是线性的，但**每次请求都要带上窗口内全部历史**——窗口设得越大，单次请求的固定成本越高，这就是为什么生产环境推荐"摘要 + 小窗口"而不是"大窗口"。

## 本章小结

- LLM 是无状态的——每次调用都要带完整上下文，记忆系统的本质是**管理上下文**：决定保留什么、遗忘什么。
- 三类记忆各管一摊：短期记忆（对话上下文）、长期记忆（向量数据库）、工作记忆（任务状态）。
- 四种策略按对话长度选：Buffer（<10轮）、Window（10-50轮）、Summary（50+轮）、Summary + Window 混合（生产推荐）。
- 滑动窗口 token 可控但丢早期信息；摘要压缩保关键信息，但每次压缩都是一次额外的 API 调用。
- 跨会话记忆用 Embedding + 向量数据库实现，`remember` 存、`recall` 取，两个动作就够起步。
- DocMindMemory 把"窗口 + 摘要"组合成 `get_context()`，输出可直接喂给模型。
- Token 成本按"总字符 ÷ 1.5"粗估：窗口越大单次请求固定成本越高，先算成本再选策略。
- 记忆何时遗忘也是设计点：主题明确转换时主动清空旧上下文，比被动等窗口淘汰更干净。
