# 第17章：Web 服务搭建

## 17.1 为什么要在命令行搭 Web 服务？

你可能会问：搭网站不是用宝塔面板或者 Docker 就行了吗？没错，但你知道宝塔和 Docker 底层在干什么吗？它们在操作 Nginx/Apache 的配置文件。如果你不理解底层的 Web 服务器，出了问题你就只能"重启试试"——这就像不会游泳的人穿着救生圈下水，能用但心里不踏实。

**本章目标：** 从零搭建一个生产级的 Web 服务器，包括静态文件服务、反向代理、HTTPS 证书、负载均衡——全部在命令行完成。

## 17.2 HTTP 基础：你得先懂"协议"

```bash
# HTTP 请求/响应模型（浏览器和服务器之间的"对话"）
# 请求：客户端 → 服务器
# GET /index.html HTTP/1.1         ← 请求行（方法 + 路径 + 协议）
# Host: example.com                ← 请求头
# User-Agent: curl/7.81.0
# Accept: */*
#
# 响应：服务器 → 客户端
# HTTP/1.1 200 OK                  ← 状态行（协议 + 状态码 + 描述）
# Content-Type: text/html          ← 响应头
# Content-Length: 1234
#
# <html>...</html>                 ← 响应体

# 常见 HTTP 状态码：
# 200 OK          → 成功
# 301 Moved       → 永久重定向
# 302 Found       → 临时重定向
# 304 Not Modified → 缓存命中
# 400 Bad Request → 请求格式错误
# 401 Unauthorized → 未认证
# 403 Forbidden   → 无权限
# 404 Not Found   → 找不到
# 500 Internal Server Error → 服务器内部错误
# 502 Bad Gateway → 反向代理的上游服务器挂了
# 503 Service Unavailable → 服务不可用
# 504 Gateway Timeout → 反向代理的上游超时

# 用 curl 看 HTTP 原始请求/响应
curl -v http://example.com 2>&1 | head -20
# -v 显示详细的请求和响应过程
```

## 17.3 Nginx 安装与基本配置

```bash
# 安装 Nginx
sudo apt update
sudo apt install nginx -y

# 启动并设置开机自启
sudo systemctl start nginx
sudo systemctl enable nginx

# 查看运行状态
sudo systemctl status nginx

# 验证配置文件语法（修改配置后的必做步骤！）
sudo nginx -t
# nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
# nginx: configuration file /etc/nginx/nginx.conf test is successful

# 重新加载配置（不中断服务）
sudo systemctl reload nginx
# 或
sudo nginx -s reload

# Nginx 目录结构
# /etc/nginx/
# ├── nginx.conf          # 主配置文件
# ├── sites-available/    # 所有站点配置（"草稿箱"）
# ├── sites-enabled/      # 启用的站点（软链接到 available）
# ├── conf.d/             # 额外的配置片段
# ├── snippets/           # 可复用的配置片段
# └── mime.types          # MIME 类型映射
#
# /var/www/               # 默认的网站根目录
# /var/log/nginx/         # Nginx 日志
#   ├── access.log        # 访问日志
#   └── error.log         # 错误日志
```

## 17.4 虚拟主机（Virtual Host）

```bash
# 虚拟主机：一台服务器托管多个网站
# 每个网站有自己的域名、目录和配置

# 创建网站目录
sudo mkdir -p /var/www/example.com
sudo mkdir -p /var/www/blog.example.com

# 创建测试页面
echo '<h1>Welcome to example.com!</h1>' | sudo tee /var/www/example.com/index.html
echo '<h1>Welcome to my blog!</h1>' | sudo tee /var/www/blog.example.com/index.html

# 设置目录权限
sudo chown -R www-data:www-data /var/www/example.com
sudo chown -R www-data:www-data /var/www/blog.example.com
sudo chmod -R 755 /var/www/

# 创建虚拟主机配置
sudo nano /etc/nginx/sites-available/example.com
# server {
#     listen 80;
#     listen [::]:80;
#     server_name example.com www.example.com;
#     root /var/www/example.com;
#     index index.html index.htm;
#
#     location / {
#         try_files $uri $uri/ =404;
#     }
#
#     # 自定义错误页面
#     error_page 404 /404.html;
#     error_page 500 502 503 504 /50x.html;
#
#     # 日志
#     access_log /var/log/nginx/example.com.access.log;
#     error_log /var/log/nginx/example.com.error.log;
# }

sudo nano /etc/nginx/sites-available/blog.example.com
# server {
#     listen 80;
#     server_name blog.example.com;
#     root /var/www/blog.example.com;
#     index index.html;
#
#     location / {
#         try_files $uri $uri/ =404;
#     }
# }

# 启用站点（创建软链接）
sudo ln -s /etc/nginx/sites-available/example.com /etc/nginx/sites-enabled/
sudo ln -s /etc/nginx/sites-available/blog.example.com /etc/nginx/sites-enabled/

# 删除默认站点（可选）
sudo rm /etc/nginx/sites-enabled/default

# 测试配置并重新加载
sudo nginx -t && sudo systemctl reload nginx

# 本地测试（不修改 DNS 的情况下）
# 在客户端的 /etc/hosts 中添加：
# 203.0.113.50 example.com www.example.com blog.example.com
curl -H "Host: example.com" http://localhost
curl -H "Host: blog.example.com" http://localhost
```

## 17.5 Nginx 反向代理

```bash
# 反向代理：Nginx 接收请求，转发给后端应用服务器
# 就像餐厅的服务员——客人（浏览器）不直接和厨师（后端）说话

# 基本反向代理配置
sudo nano /etc/nginx/sites-available/app
# server {
#     listen 80;
#     server_name app.example.com;
#
#     location / {
#         proxy_pass http://localhost:3000;   # 后端应用地址
#         proxy_http_version 1.1;
#         proxy_set_header Host $host;
#         proxy_set_header X-Real-IP $remote_addr;
#         proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
#         proxy_set_header X-Forwarded-Proto $scheme;
#
#         # WebSocket 支持
#         proxy_set_header Upgrade $http_upgrade;
#         proxy_set_header Connection "upgrade";
#     }
#
#     # API 路径单独转发到不同的后端
#     location /api/ {
#         proxy_pass http://localhost:8080/;
#         proxy_set_header Host $host;
#     }
#
#     # 静态文件直接由 Nginx 处理（不经过后端）
#     location /static/ {
#         alias /var/www/app/static/;
#         expires 30d;
#     }
# }

# 路径匹配规则
# location = /exact       → 精确匹配（最高优先级）
# location ^~ /prefix     → 前缀匹配（优先于正则）
# location ~ \.php$       → 正则匹配（区分大小写）
# location ~* \.jpg$      → 正则匹配（不区分大小写）
# location /prefix        → 前缀匹配（最低优先级）

# 超时设置
# proxy_connect_timeout 10s;   # 连接后端超时
# proxy_read_timeout 60s;      # 读取后端响应超时
# proxy_send_timeout 60s;      # 发送请求到后端超时
```

## 17.6 Nginx 负载均衡

```bash
# 当一台后端服务器扛不住时，用多台分担压力
# Nginx 可以做"调度员"，把请求分给不同的后端

# 负载均衡配置
sudo nano /etc/nginx/conf.d/upstream.conf
# # 定义后端服务器组
# upstream backend {
#     # 默认轮询（Round Robin）
#     server 10.0.0.10:8080 weight=3;   # 权重 3（性能好的多分配）
#     server 10.0.0.11:8080 weight=2;
#     server 10.0.0.12:8080 weight=1;
#     server 10.0.0.13:8080 backup;      # 备用（其他都挂了我才上）
#
#     # 健康检查
#     # max_fails=3 → 连续失败 3 次标记为不可用
#     # fail_timeout=30s → 30 秒后重试
#     server 10.0.0.14:8080 max_fails=3 fail_timeout=30s;
# }
#
# # IP Hash 负载均衡（同一 IP 总是访问同一后端，适合有 Session 的应用）
# upstream backend_session {
#     ip_hash;
#     server 10.0.0.10:8080;
#     server 10.0.0.11:8080;
#     server 10.0.0.12:8080;
# }
#
# # Least Connections（最少连接数，分给最闲的后端）
# upstream backend_least {
#     least_conn;
#     server 10.0.0.10:8080;
#     server 10.0.0.11:8080;
# }

# 在 server 块中使用上游
# server {
#     listen 80;
#     server_name app.example.com;
#     location / {
#         proxy_pass http://backend;
#     }
# }

# 三种负载均衡策略对比：
# 轮询（默认）  → 简单平均，适合无状态服务
# IP Hash       → 同 IP 同后端，适合有 Session 的服务
# Least Conn    → 给最闲的后端，适合请求处理时间差异大的场景
```

## 17.7 SSL/TLS 与 Let's Encrypt

```bash
# HTTPS = HTTP + TLS（加密层）
# Let's Encrypt 提供免费、自动续期的 SSL 证书

# 安装 Certbot（Let's Encrypt 的官方工具）

sudo certbot certonly --webroot -w /var/www/example.com -d example.com

sudo certbot renew --dry-run
```

## 17.8 Apache 基础

```bash
# Apache 是另一个流行的 Web 服务器
# 虽然 Nginx 在性能上更胜一筹，但 Apache 的 .htaccess 和模块生态依然有大量用户

# 安装 Apache
sudo apt install apache2 -y

# Apache 目录结构
# /etc/apache2/
# ├── apache2.conf          # 主配置
# ├── sites-available/      # 站点配置
# ├── sites-enabled/        # 启用的站点
# ├── mods-available/       # 可用模块
# ├── mods-enabled/         # 启用的模块
# └── conf-enabled/         # 额外配置
#
# /var/www/html/            # 默认网站根目录

# 启用/禁用模块
sudo a2enmod rewrite       # 启用 mod_rewrite（URL 重写）
sudo a2enmod ssl           # 启用 SSL 模块
sudo a2enmod proxy         # 启用代理模块
sudo a2enmod proxy_http    # 启用 HTTP 代理
sudo a2dismod autoindex    # 禁用目录列表

# 启用/禁用站点
sudo a2ensite example.com
sudo a2dissite 000-default

# 重启 Apache
sudo systemctl restart apache2

# Apache 虚拟主机配置
# /etc/apache2/sites-available/example.com.conf
# <VirtualHost *:80>
#     ServerName example.com
#     ServerAlias www.example.com
#     DocumentRoot /var/www/example.com
#
#     <Directory /var/www/example.com>
#         Options -Indexes +FollowSymLinks
#         AllowOverride All
#         Require all granted
#     </Directory>
#
#     ErrorLog ${APACHE_LOG_DIR}/example.com.error.log
#     CustomLog ${APACHE_LOG_DIR}/example.com.access.log combined
# </VirtualHost>
```

## 17.9 Nginx vs Apache 对比

```bash
# | 特性           | Nginx                    | Apache                   |
# |---------------|--------------------------|--------------------------|
# | 架构           | 事件驱动（异步非阻塞）      | 进程/线程驱动              |
# | 静态文件性能     | 更快（低内存消耗）          | 较慢                      |
# | 动态内容        | 需要 FastCGI/uWSGI        | 内置 mod_php 等模块        |
# | 配置风格        | 集中式配置                 | 分布式 .htaccess          |
# | 内存消耗        | 低                       | 高                        |
# | 并发连接        | 数万连接轻松               | 数百到数千                  |
# | 模块管理        | 编译时加载                 | 运行时动态加载              |
# | 社区生态        | 现代、增长快               | 成熟、历史悠久              |
#
# 选择建议：
# - 静态文件/反向代理/高并发 → Nginx
# - 共享主机/.htaccess/传统 PHP → Apache
# - 现代最佳实践 → Nginx 做前端反向代理 + 后端应用服务器
```

## 17.11 Nginx 性能调优

```bash
# Nginx 性能调优是生产环境的必修课

# 1. worker 进程数（建议 = CPU 核心数）
sudo nano /etc/nginx/nginx.conf
# worker_processes auto;         ← auto 自动检测 CPU 核心数
# worker_connections 4096;       ← 每个 worker 最大并发连接数
# worker_rlimit_nofile 65535;    ← 文件描述符上限

# 查看 CPU 核心数
nproc
# 4 → worker_processes 设为 4 或 auto

# 2. 启用 sendfile 和 tcp_nopush（静态文件加速）
# sendfile on;                   ← 内核级文件传输（跳过用户空间）
# tcp_nopush on;                 ← 配合 sendfile，合并发送
# tcp_nodelay on;                ← 小数据包立即发送（减少延迟）

# 3. 开启 Gzip 压缩（减少传输体积 60-80%）
# gzip on;
# gzip_vary on;
# gzip_min_length 1024;
# gzip_comp_level 5;             ← 压缩级别 1-9（5 是性价比最高的）
# gzip_types
#     text/plain
#     text/css
#     text/javascript
#     application/json
#     application/javascript
#     application/xml
#     image/svg+xml;

# 4. 客户端缓存（减少重复请求）
# location ~* \.(jpg|jpeg|png|gif|ico|css|js|woff2|ttf)$ {
#     expires 30d;
#     add_header Cache-Control "public, immutable";
# }
#
# location ~* \.(html|htm)$ {
#     expires -1;                ← HTML 不缓存
#     add_header Cache-Control "no-cache, no-store, must-revalidate";
# }

# 5. 缓冲区优化
# client_body_buffer_size 16k;
# client_max_body_size 50m;      ← 上传文件大小限制
# proxy_buffer_size 128k;
# proxy_buffers 4 256k;
# proxy_busy_buffers_size 256k;

# 6. Keep-Alive 连接复用
# keepalive_timeout 65;          ← 连接保持超时
# keepalive_requests 1000;       ← 单连接最大请求数

# 7. 文件缓存（减少磁盘 I/O）
# open_file_cache max=10000 inactive=60s;
# open_file_cache_valid 60s;
# open_file_cache_min_uses 2;
# open_file_cache_errors on;

# 验证配置并重载
sudo nginx -t && sudo systemctl reload nginx
```

## 17.12 Nginx 缓存配置

```bash
# Nginx 可以做反向代理缓存，加速后端响应

# 1. 在 http 块中定义缓存区
# proxy_cache_path /var/cache/nginx levels=1:2 \
#   keys_zone=my_cache:10m \
#   max_size=1g \
#   inactive=60m \
#   use_temp_path=off;

# 创建缓存目录
sudo mkdir -p /var/cache/nginx
sudo chown www-data:www-data /var/cache/nginx

# 2. 在 server/location 中使用缓存
# location /api/ {
#     proxy_pass http://backend;
#     proxy_cache my_cache;
#     proxy_cache_valid 200 10m;       # 200 响应缓存 10 分钟
#     proxy_cache_valid 404 1m;        # 404 响应缓存 1 分钟
#     proxy_cache_use_stale error timeout updating;  # 后端挂了用旧缓存
#     add_header X-Cache-Status $upstream_cache_status;  # 调试用
# }

# 缓存状态说明（看 X-Cache-Status 响应头）：
# HIT     → 缓存命中（从缓存返回）
# MISS    → 缓存未命中（从后端获取并缓存）
# EXPIRED → 缓存过期（从后端重新获取）
# STALE   → 使用过期缓存（后端不可用时的降级策略）
# BYPASS  → 绕过缓存

# 测试缓存效果
curl -I http://localhost/api/data
# X-Cache-Status: MISS    ← 第一次，未缓存
curl -I http://localhost/api/data
# X-Cache-Status: HIT     ← 第二次，命中缓存！

# 清除缓存
sudo rm -rf /var/cache/nginx/*
sudo systemctl reload nginx
```

## 17.13 Nginx 日志分析

```bash
# Nginx 日志是排查问题和优化性能的"金矿"

# 查看访问日志（实时滚动）
tail -f /var/log/nginx/access.log
# 输出示例：
# 203.0.113.50 - - [01/Jan/2024:12:00:00 +0800] "GET /index.html HTTP/1.1" 200 1234 "-" "Mozilla/5.0"
# 10.0.0.5 - - [01/Jan/2024:12:00:01 +0800] "POST /api/login HTTP/1.1" 200 567 "-" "curl/7.81.0"

# 统计访问量最高的 URL（Top 10）
awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -10

# 统计访问量最高的 IP（Top 10）
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -10

# 统计 HTTP 状态码分布
awk '{print $9}' /var/log/nginx/access.log | sort | uniq -c | sort -rn

# 统计每小时的请求量
awk '{print $4}' /var/log/nginx/access.log | cut -d: -f2 | sort | uniq -c

# 查看慢请求（响应时间 > 1 秒）
# 需要先配置 log_format 记录请求时间
# log_format main '$remote_addr - $request_time "$request" $status $body_bytes_sent';
```

## 17.14 Nginx 安全头配置

```bash
# HTTP 安全头是防止 XSS、CSRF、点击劫持等攻击的重要防线
# 在 Nginx 的 server 块中添加以下配置：

# server {
#     # ... 其他配置 ...
#
#     # 防止点击劫持（不允许在 iframe 中嵌入）
#     add_header X-Frame-Options "SAMEORIGIN" always;
#
#     # 防止 MIME 类型嗅探
#     add_header X-Content-Type-Options "nosniff" always;
#
#     # 启用 XSS 过滤
#     add_header X-XSS-Protection "1; mode=block" always;
#
#     # 防止信息泄露
#     add_header Referrer-Policy "strict-origin-when-cross-origin" always;
#
#     # 内容安全策略（CSP）——最强大的安全头
#     add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline' https://cdn.example.com; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' https://fonts.gstatic.com;" always;
#
#     # 权限策略（控制浏览器功能访问）
#     add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
#
#     # 隐藏 Nginx 版本号（安全加固）
#     server_tokens off;
#
#     # 限制请求方法（只允许 GET/POST/HEAD）
#     if ($request_method !~ ^(GET|POST|HEAD|PUT|DELETE|OPTIONS)$) {
#         return 444;    # 444 = Nginx 特殊码：直接关闭连接
#     }
#
#     # 限制请求体大小（防止大文件攻击）
#     client_max_body_size 20m;
# }

# 验证安全头配置
curl -I https://your-site.com
# 检查是否包含上述安全头
```

## 17.17 常见坑与注意事项

```bash
# 坑 1：Nginx 配置修改后不测试就 reload
# 配置有语法错误会导致 Nginx 停止服务！
# 永远先测试：sudo nginx -t

# 坑 2：文件权限问题（403 Forbidden）
# Nginx 用 www-data 用户运行，需要有权限读取网站目录
sudo chown -R www-data:www-data /var/www/mysite
sudo chmod -R 755 /var/www/mysite

# 坑 3：SELinux/AppArmor 阻止 Nginx 访问
# Ubuntu 默认启用 AppArmor
sudo aa-status | grep nginx

# 坑 4：反向代理后端地址末尾要不要 /
# proxy_pass http://backend;       → 保留原始 URI
# proxy_pass http://backend/;      → 替换 URI（注意末尾斜杠的影响）

# 坑 5：Let's Encrypt 证书续期失败
# 检查 cron/timer 是否正常运行
sudo systemctl list-timers | grep certbot
# 检查 webroot 路径是否还存在
sudo certbot renew --dry-run
```

## 17.12 本章小结

Web 服务器是互联网的基础设施。Nginx 凭借高性能和简洁的配置成为现代首选，但 Apache 在传统场景仍然有用。虚拟主机让你一台服务器跑多个网站，反向代理把请求转发给后端应用，SSL 证书保障通信安全。记住：永远先 `nginx -t` 再 `reload`。
