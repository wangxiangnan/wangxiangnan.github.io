# 第7章：文件系统(fs)——读写删改的艺术

## 引言：程序员与文件的爱恨情仇

如果说编程是一门手艺，那文件系统就是你的工作台。你的代码再漂亮，最终还是要落盘（写入磁盘）的。就像一个厨师再厉害，食材总得从冰箱里拿出来，做完了总得摆盘上桌。

Node.js 的 `fs` 模块就是你的冰箱+灶台+餐盘——它负责一切与文件相关的操作：读、写、删、改、看、听。

但这里有个有趣的历史包袱：`fs` 模块诞生于 Node.js 最早期，那时候回调地狱还是"设计模式"，所以你会发现它有**三种不同的 API 风格**。这就好比一个餐厅同时提供中餐、西餐和日料——菜品一样，但吃法完全不同。

让我们开始吧。

## 7.1 fs 模块的三种人格

### 回调风格（Callback Style）——元老级 API

```javascript
import { readFile } from 'node:fs';

readFile('/etc/passwd', 'utf8', (err, data) => {
  if (err) {
    console.error('出错了：', err.message);
    return;
  }
  console.log(data);
});
```

这是最原始的风格。每个操作都接受一个回调函数，第一个参数永远是 `err`（Node.js 的"错误优先回调"约定）。

**优点**：性能最好（没有 Promise 包装的开销）
**缺点**：嵌套多了会变成回调地狱，代码可读性差

### 同步风格（Sync Style）——带 `Sync` 后缀

```javascript
import { readFileSync } from 'node:fs';

try {
  const data = readFileSync('/etc/passwd', 'utf8');
  console.log(data);
} catch (err) {
  console.error('出错了：', err.message);
}
```

函数名后面加个 `Sync`，直接返回结果，出错就抛异常。

**优点**：代码简洁，像写同步语言一样
**缺点**：会**阻塞事件循环**！在服务器代码中使用就像在高速公路上停车拍照——后面全堵死了

**适用场景**：启动时加载配置文件、CLI 工具、脚本

### Promise 风格（fs/promises）——现代人的选择

```javascript
import { readFile } from 'node:fs/promises';

try {
  const data = await readFile('/etc/passwd', 'utf8');
  console.log(data);
} catch (err) {
  console.error('出错了：', err.message);
}
```

> 注意 import 路径是 `'node:fs/promises'`，不是 `'node:fs'`！

**优点**：可以用 `async/await`，代码优雅，错误处理清晰
**缺点**：比回调风格有一丢丢性能开销（真的只有一丢丢）

### TypeScript 类型标注示例

```typescript
import { readFile, writeFile } from 'node:fs/promises';
import type { FileHandle } from 'node:fs/promises';

async function readConfig(path: string): Promise<Record<string, unknown>> {
  const content: string = await readFile(path, 'utf8');
  return JSON.parse(content);
}
```

### 三种风格对比表

| 特性 | 回调式 | 同步式 | Promise 式 |
| ------ | -------- | -------- | ----------- |
| 阻塞事件循环 | ❌ | ✅ | ❌ |
| 错误处理 | 回调第一参数 | try/catch | try/catch |
| 代码可读性 | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ |
| 适合场景 | 高性能/兼容旧代码 | 启动脚本/CLI | 日常开发 |

**本章后续所有示例将使用 `fs/promises` 风格**，因为这是 2024 年应该写的代码。

## 7.2 文件读写：你的第一个 CRUD

### 读文件 readFile

```javascript
import { readFile } from 'node:fs/promises';

// 读取文本文件
const text = await readFile('./hello.txt', 'utf8');
console.log(text);

// 读取二进制文件（返回 Buffer）
const buffer = await readFile('./image.png');
console.log(buffer.length, '字节');
```

**关键参数**：

- 第二个参数是编码。传 `'utf8'` 返回字符串，不传返回 Buffer
- 支持的编码：`utf8`、`ascii`、`base64`、`hex`、`latin1`、`binary`

```typescript
// TypeScript 重载签名很优雅
import { readFile } from 'node:fs/promises';

// 传编码 → 返回 string
const str: string = await readFile('a.txt', 'utf8');

// 不传编码 → 返回 Buffer
const buf: Buffer = await readFile('a.txt');
```

### 写文件 writeFile

```javascript
import { writeFile } from 'node:fs/promises';

// 写入文本
await writeFile('./output.txt', '你好，世界！', 'utf8');

// 写入 Buffer
const data = Buffer.from([0x48, 0x65, 0x6c, 0x6c, 0x6f]);
await writeFile('./binary.dat', data);

// 写入 JSON（常见场景）
const config = { port: 3000, host: 'localhost' };
await writeFile(
  './config.json',
  JSON.stringify(config, null, 2),  // null, 2 → 格式化缩进
  'utf8'
);
```

**注意**：`writeFile` 默认会**覆盖**已有文件！如果文件不存在则创建。

### 追加写入 appendFile

```javascript
import { appendFile } from 'node:fs/promises';

// 追加日志
await appendFile('./app.log', `[${new Date().toISOString()}] 服务启动\n`);
await appendFile('./app.log', `[${new Date().toISOString()}] 收到请求\n`);
```

`appendFile` = "别覆盖，在后面接着写"。

### 高级选项：flag 参数

```javascript
import { writeFile } from 'node:fs/promises';

// flag: 'wx' → 排他性创建，文件已存在则报错
await writeFile('./lock.pid', process.pid.toString(), { flag: 'wx' });

// flag: 'a' → 追加模式（等价于 appendFile）
await writeFile('./log.txt', '新的一行\n', { flag: 'a' });
```

常用 flag：

- `'r'` - 读取（默认）
- `'w'` - 写入（创建或覆盖）
- `'a'` - 追加
- `'wx'` - 排他性写入（文件存在则失败）
- `'ax'` - 排他性追加

## 7.3 目录操作：文件夹也是一等公民

### 创建目录 mkdir

```javascript
import { mkdir } from 'node:fs/promises';

// 创建单层目录
await mkdir('./logs');

// 递归创建（类似 mkdir -p）
await mkdir('./data/cache/temp', { recursive: true });
```

`recursive: true` 是你最好的朋友——它不会因为父目录不存在而报错，也不会因为目录已存在而报错。

### 读取目录 readdir

```javascript
import { readdir } from 'node:fs/promises';

// 基本用法：返回文件名数组
const files = await readdir('./src');
console.log(files); // ['index.js', 'utils.js', 'lib']

// withFileTypes: 返回 Dirent 对象（推荐！）
const entries = await readdir('./src', { withFileTypes: true });
for (const entry of entries) {
  if (entry.isFile()) {
    console.log(`📄 ${entry.name}`);
  } else if (entry.isDirectory()) {
    console.log(`📁 ${entry.name}`);
  }
}

// recursive: true（Node.js 18.17+）递归列出所有文件
const allFiles = await readdir('./src', { recursive: true });
console.log(allFiles);
// ['index.js', 'utils.js', 'lib', 'lib/helper.js', 'lib/constants.js']
```

> `recursive: true` 是 Node.js 18.17 引入的，终于不用自己写递归了！

### 删除目录和文件

```javascript
import { rm, rmdir } from 'node:fs/promises';

// 删除空目录
await rmdir('./empty-dir');

// 删除文件
await rm('./temp.txt');

// 递归删除目录及其内容（危险操作！等同于 rm -rf）
await rm('./build', { recursive: true, force: true });
```

> **⚠️ 警告**：`rm` 加上 `recursive: true` + `force: true` 就是传说中的 `rm -rf`。请三思而后行。有个段子说：程序员最危险的时候，是输入 `rm -rf /` 时手抖按到了回车。

### 重命名/移动 rename

```javascript
import { rename } from 'node:fs/promises';

// 重命名
await rename('./old-name.txt', './new-name.txt');

// 移动文件（跨目录重命名）
await rename('./downloads/file.zip', './archive/file.zip');
```

### 复制文件 copyFile

```javascript
import { copyFile, constants } from 'node:fs/promises';

// 简单复制
await copyFile('./src.txt', './dest.txt');

// COPYFILE_EXCL：目标文件存在时报错（不覆盖）
await copyFile('./src.txt', './dest.txt', constants.COPYFILE_EXCL);
```

## 7.4 文件信息：stat 与文件描述符

### stat / lstat

```javascript
import { stat, lstat } from 'node:fs/promises';

const info = await stat('./package.json');

console.log({
  是否文件: info.isFile(),           // true
  是否目录: info.isDirectory(),      // false
  文件大小: info.size,               // 字节数
  创建时间: info.birthtime,          // Date 对象
  修改时间: info.mtime,             // Date 对象
  访问时间: info.atime,             // Date 对象
  权限模式: info.mode.toString(8),   // 八进制权限，如 '100644'
});
```

**stat vs lstat**：当路径指向一个符号链接（symlink）时：

- `stat` 追踪链接，返回目标文件的信息
- `lstat` 不追踪，返回链接本身的信息

```javascript
// 判断是否为符号链接
const linkInfo = await lstat('./my-link');
console.log(linkInfo.isSymbolicLink()); // true
```

### 文件描述符（File Descriptor）

文件描述符是操作系统给每个打开的文件分配的一个整数编号。就像餐厅给每桌客人一个号码牌。

```javascript
import { open } from 'node:fs/promises';

// 打开文件，获取 FileHandle 对象
const fileHandle = await open('./data.txt', 'r');

try {
  // 通过 FileHandle 操作
  const content = await fileHandle.readFile('utf8');
  const stats = await fileHandle.stat();
  console.log(content, stats.size);
} finally {
  // 重要！用完一定要关闭！
  await fileHandle.close();
}
```

**为什么需要 FileHandle？**

`readFile` 每次调用都会：打开文件 → 读取 → 关闭。如果你需要对同一个文件做多次操作，用 `open` 获取 FileHandle 更高效。

```javascript
import { open } from 'node:fs/promises';

// 使用 using 声明（Node.js 20+，需要 TypeScript 5.2+）
// 自动在作用域结束时关闭文件
{
  await using file = await open('./data.txt', 'r+');
  const { buffer, bytesRead } = await file.read(
    Buffer.alloc(100), 0, 100, 0
  );
  console.log('读了', bytesRead, '字节');
}
// 这里 file 已自动关闭
```

> Node.js 20+ 支持 `Symbol.asyncDispose`，配合 `await using` 语法可以自动关闭资源。这是 TC39 的显式资源管理提案（Explicit Resource Management）的实现。

### 检查文件是否存在

```javascript
import { access, constants } from 'node:fs/promises';

async function fileExists(path: string): Promise<boolean> {
  try {
    await access(path, constants.F_OK);
    return true;
  } catch {
    return false;
  }
}

// 检查是否可读可写
async function isReadableWritable(path: string): Promise<boolean> {
  try {
    await access(path, constants.R_OK | constants.W_OK);
    return true;
  } catch {
    return false;
  }
}
```

> **历史小知识**：曾经有个 `fs.exists()` 方法，但它不遵循 Node.js 的错误优先回调约定（回调只有一个布尔参数），所以被废弃了。用 `access` 代替。

## 7.5 文件监听：watch vs watchFile

### watch——基于操作系统的文件监听

```javascript
import { watch } from 'node:fs/promises';

// 监听单个文件
const watcher = watch('./config.json');

for await (const event of watcher) {
  console.log(`事件类型: ${event.eventType}, 文件: ${event.filename}`);
}
```

```javascript
import { watch } from 'node:fs';

// 监听目录（包括子目录中的变化）
const watcher = watch('./src', { recursive: true }, (eventType, filename) => {
  console.log(`[${eventType}] ${filename}`);
});

// 停止监听
// watcher.close();
```

### watchFile——基于轮询的监听

```javascript
import { watchFile, unwatchFile } from 'node:fs';

watchFile('./data.json', { interval: 1000 }, (curr, prev) => {
  if (curr.mtime !== prev.mtime) {
    console.log('文件被修改了！');
    console.log(`旧大小: ${prev.size}, 新大小: ${curr.size}`);
  }
});

// 停止监听
// unwatchFile('./data.json');
```

### watch vs watchFile：应该用哪个？

| 特性 | watch | watchFile |
| ------ | ------- | ----------- |
| 实现原理 | 操作系统事件（inotify/FSEvents/kqueue） | 定时轮询 stat |
| 性能 | 好（事件驱动） | 差（CPU 占用） |
| 可靠性 | 平台差异大，有些系统不可靠 | 稳定但延迟高 |
| 推荐度 | ⭐⭐⭐⭐ | ⭐⭐ |

**结论**：优先用 `watch`。如果遇到平台兼容问题，再考虑 `watchFile`。

**生产环境建议**：使用 `chokidar` 库，它在 `watch` 基础上做了大量平台兼容和边界处理：

```javascript
// npm install chokidar
import chokidar from 'chokidar';

const watcher = chokidar.watch('./src', {
  ignored: /node_modules/,
  persistent: true,
});

watcher
  .on('add', path => console.log(`新增: ${path}`))
  .on('change', path => console.log(`修改: ${path}`))
  .on('unlink', path => console.log(`删除: ${path}`));
```

## 7.6 大文件处理：别把内存撑爆了

### 为什么不能 readFile 一个 2GB 文件？

```javascript
// ❌ 千万别这么干！
const bigFile = await readFile('./database-dump.sql'); // 2GB 文件
// V8 堆内存默认限制约 1.7GB，这会直接 OOM（Out of Memory）！
```

`readFile` 会把**整个文件**读进内存。对于大文件，你应该使用 Stream（下一章会深入讲）。

```javascript
import { createReadStream } from 'node:fs';
import { createInterface } from 'node:readline';

// ✅ 逐行读取大文件
const fileStream = createReadStream('./huge-log.txt', 'utf8');
const rl = createInterface({ input: fileStream });

let lineCount = 0;
for await (const line of rl) {
  lineCount++;
  if (line.includes('ERROR')) {
    console.log(`第 ${lineCount} 行发现错误: ${line}`);
  }
}
console.log(`总共 ${lineCount} 行`);
```

### 分块读取

```javascript
import { open } from 'node:fs/promises';

async function readInChunks(filePath: string, chunkSize = 64 * 1024) {
  const file = await open(filePath, 'r');
  const buffer = Buffer.alloc(chunkSize);
  let totalBytesRead = 0;

  try {
    while (true) {
      const { bytesRead } = await file.read(buffer, 0, chunkSize);
      if (bytesRead === 0) break;

      totalBytesRead += bytesRead;
      // 处理这一块数据...
      console.log(`已读取 ${totalBytesRead} 字节`);
    }
  } finally {
    await file.close();
  }
}
```

## 7.7 递归目录遍历的优雅实现

### 方法一：利用 readdir 的 recursive 选项（Node.js 18.17+）

```javascript
import { readdir } from 'node:fs/promises';
import { join } from 'node:path';

// 最简单的方式
const allFiles = await readdir('./project', {
  recursive: true,
  withFileTypes: true,
});

const jsFiles = allFiles
  .filter(entry => entry.isFile() && entry.name.endsWith('.js'))
  .map(entry => join(entry.parentPath, entry.name));

console.log('找到 JS 文件：', jsFiles);
```

> `entry.parentPath` 是 Node.js 20.12+ 新增的属性，之前叫 `entry.path`。

### 方法二：手动递归（兼容旧版本）

```javascript
import { readdir, stat } from 'node:fs/promises';
import { join } from 'node:path';

async function* walkDir(dir: string): AsyncGenerator<string> {
  const entries = await readdir(dir, { withFileTypes: true });

  for (const entry of entries) {
    const fullPath = join(dir, entry.name);

    if (entry.isDirectory()) {
      yield* walkDir(fullPath); // 递归进入子目录
    } else {
      yield fullPath;
    }
  }
}

// 使用异步生成器遍历
for await (const filePath of walkDir('./src')) {
  console.log(filePath);
}
```

这个 `AsyncGenerator` 的写法非常优雅——它是**惰性的**（lazy），不会一次性把所有文件路径加载到内存里。

### 方法三：并行遍历（性能最优）

```javascript
import { readdir } from 'node:fs/promises';
import { join } from 'node:path';

async function walkDirParallel(dir: string): Promise<string[]> {
  const entries = await readdir(dir, { withFileTypes: true });
  const results: string[] = [];

  const tasks = entries.map(async (entry) => {
    const fullPath = join(dir, entry.name);
    if (entry.isDirectory()) {
      const subResults = await walkDirParallel(fullPath);
      results.push(...subResults);
    } else {
      results.push(fullPath);
    }
  });

  await Promise.all(tasks);
  return results;
}
```

## 7.8 实战：实现一个文件搜索工具

让我们实现一个支持 glob 匹配的文件搜索工具：

```javascript
import { readdir, stat } from 'node:fs/promises';
import { join, relative } from 'node:path';

/**
 * 简易 glob 匹配器
 * 支持 * (匹配任意字符) 和 ** (匹配任意路径)
 */
function matchGlob(pattern: string, filePath: string): boolean {
  // 将 glob 模式转换为正则表达式
  const regexStr = pattern
    .replace(/\./g, '\\.')          // 转义点号
    .replace(/\*\*/g, '{{GLOBSTAR}}')  // 先保护 **
    .replace(/\*/g, '[^/]*')        // * → 匹配除/外的任意字符
    .replace(/{{GLOBSTAR}}/g, '.*') // ** → 匹配任意字符（包括/）
    .replace(/\?/g, '[^/]');        // ? → 匹配单个字符

  return new RegExp(`^${regexStr}$`).test(filePath);
}

interface SearchOptions {
  pattern: string;       // glob 模式，如 "**/*.ts"
  cwd?: string;         // 搜索根目录
  ignore?: string[];    // 忽略的模式
  maxDepth?: number;    // 最大深度
}

async function* searchFiles(options: SearchOptions): AsyncGenerator<string> {
  const {
    pattern,
    cwd = process.cwd(),
    ignore = ['node_modules', '.git'],
    maxDepth = Infinity,
  } = options;

  async function* walk(dir: string, depth: number): AsyncGenerator<string> {
    if (depth > maxDepth) return;

    const entries = await readdir(dir, { withFileTypes: true });

    for (const entry of entries) {
      const fullPath = join(dir, entry.name);
      const relativePath = relative(cwd, fullPath);

      // 检查是否应该忽略
      if (ignore.some(ig => entry.name === ig)) continue;

      if (entry.isDirectory()) {
        yield* walk(fullPath, depth + 1);
      } else if (entry.isFile()) {
        if (matchGlob(pattern, relativePath)) {
          yield relativePath;
        }
      }
    }
  }

  yield* walk(cwd, 0);
}

// 使用示例
async function main() {
  console.log('搜索所有 TypeScript 文件：');
  for await (const file of searchFiles({ pattern: '**/*.ts', cwd: './src' })) {
    console.log(`  找到: ${file}`);
  }

  console.log('\n搜索所有测试文件：');
  for await (const file of searchFiles({
    pattern: '**/*.test.{js,ts}',
    cwd: '.',
    ignore: ['node_modules', 'dist', '.git'],
  })) {
    console.log(`  测试: ${file}`);
  }
}

main();
```

## 7.9 Node.js 20+ 新特性：fs.glob()

Node.js 22 引入了原生的 `fs.glob()` 方法（实验性），让我们不再需要第三方 glob 库！

```javascript
import { glob } from 'node:fs/promises';

// 基本用法
for await (const entry of glob('**/*.js')) {
  console.log(entry);
}

// 带选项
for await (const entry of glob('src/**/*.{ts,tsx}', {
  cwd: '/path/to/project',
  exclude: (name) => name === 'node_modules',
})) {
  console.log(entry);
}
```

> 注意：截至 Node.js 22，`fs.glob()` 还是实验性 API（带有 `ExperimentalWarning`）。生产环境暂时还是用 `fast-glob` 或 `globby`。

```javascript
// 生产环境推荐：fast-glob
import fg from 'fast-glob';

const files = await fg(['src/**/*.ts', '!**/*.test.ts'], {
  dot: true,       // 包含隐藏文件
  absolute: true,  // 返回绝对路径
});
```

## 7.10 原理深挖：fs 底层发生了什么？

当你调用 `readFile` 时，经历了以下旅程：

```
你的 JavaScript 代码
    ↓
fs.readFile() (JavaScript 层)
    ↓
Node.js C++ Binding (src/node_file.cc)
    ↓
libuv (跨平台异步 I/O 库)
    ↓
线程池中的工作线程
    ↓
操作系统系统调用 (open → read → close)
    ↓
磁盘驱动程序
    ↓
你的 SSD/HDD
```

**关键点**：文件 I/O 操作是在 libuv 的**线程池**中执行的（默认 4 个线程），不是在主线程上。这就是为什么异步文件操作不会阻塞事件循环。

```javascript
// 可以通过环境变量调整线程池大小
// UV_THREADPOOL_SIZE=16 node app.js

// 或在代码中（必须在任何 I/O 操作之前设置）
process.env.UV_THREADPOOL_SIZE = '16';
```

## 7.11 常见坑点

### 坑1：路径问题

```javascript
// ❌ 相对路径是相对于 process.cwd()，不是文件所在目录！
const data = await readFile('./config.json');

// ✅ 使用 import.meta.url 获取当前文件目录
import { fileURLToPath } from 'node:url';
import { dirname, join } from 'node:path';

const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);
const configPath = join(__dirname, 'config.json');
const data = await readFile(configPath, 'utf8');
```

### 坑2：竞态条件（TOCTOU）

```javascript
// ❌ 典型的 TOCTOU (Time Of Check To Time Of Use) 问题
import { access, readFile } from 'node:fs/promises';

// 在 access 和 readFile 之间，文件可能已经被删除了！
if (await fileExists('./data.json')) {
  const data = await readFile('./data.json'); // 可能报错！
}

// ✅ 直接操作，用 try/catch 处理错误
try {
  const data = await readFile('./data.json', 'utf8');
  // 处理数据
} catch (err) {
  if (err.code === 'ENOENT') {
    console.log('文件不存在，使用默认值');
  } else {
    throw err; // 其他错误继续抛出
  }
}
```

### 坑3：writeFile 的原子性问题

```javascript
// ❌ writeFile 不是原子操作！写到一半断电/崩溃会导致文件损坏
await writeFile('./important.json', JSON.stringify(data));

// ✅ "写入临时文件 + 重命名"模式（rename 在大多数文件系统上是原子的）
import { writeFile, rename } from 'node:fs/promises';
import { randomUUID } from 'node:crypto';

async function atomicWrite(filePath: string, content: string): Promise<void> {
  const tempPath = `${filePath}.${randomUUID()}.tmp`;
  await writeFile(tempPath, content, 'utf8');
  await rename(tempPath, filePath); // 原子性重命名
}
```

### 坑4：文件编码

```javascript
// ❌ 文件如果是 GBK 编码的中文，readFile('utf8') 会乱码
const data = await readFile('./gbk-file.txt', 'utf8'); // 乱码！

// ✅ 使用 iconv-lite 处理非 UTF-8 编码
import iconv from 'iconv-lite';

const buffer = await readFile('./gbk-file.txt');
const text = iconv.decode(buffer, 'gbk');
```

### 坑5：权限问题

```javascript
import { writeFile, chmod } from 'node:fs/promises';

// 创建只读配置文件
await writeFile('./secret.key', 'my-secret-key');
await chmod('./secret.key', 0o600); // 只有属主可读写

// 写入可执行脚本
await writeFile('./run.sh', '#!/bin/bash\necho "hello"');
await chmod('./run.sh', 0o755); // 属主可执行
```

## 7.12 本章小结

| 操作 | 方法 | 备注 |
| ------ | ------ | ------ |
| 读文件 | readFile | 小文件用，大文件用 Stream |
| 写文件 | writeFile | 覆盖写入 |
| 追加 | appendFile | 日志常用 |
| 创建目录 | mkdir | 加 recursive: true |
| 读目录 | readdir | 加 withFileTypes: true |
| 删除 | rm | 替代了 unlink 和 rmdir |
| 文件信息 | stat | 大小、时间、类型 |
| 监听变化 | watch | 优于 watchFile |
| 打开文件 | open | 获取 FileHandle |
| Glob | fs.glob() | Node.js 22+ 实验性 |

**核心原则**：

1. 日常开发用 `fs/promises`
2. 大文件用 Stream，别 readFile
3. 用 try/catch 而不是先检查再操作
4. 写入重要文件用"临时文件+重命名"模式
5. 别忘了关闭 FileHandle
