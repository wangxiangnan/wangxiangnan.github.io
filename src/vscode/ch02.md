# 第2章：工作区与多项目管理

> 在编程世界里，我们用模块化和分层来管理复杂度。VSCode用同样的思路管理你的项目——**工作区（Workspace）就是编辑器层面的"模块化"**。一个配置良好的工作区，能让你在多个项目之间切换时如同切换浏览器标签页一样丝滑。

## 单文件夹 vs 工作区 vs 多根工作区

VSCode有三种项目打开方式，它们的区别就像JavaScript中 `let`、`const` 和 `Object.freeze()` 的区别——功能递增，约束递增：

### 单文件夹模式

最常见的方式：`File > Open Folder`。VSCode会以该文件夹为根目录，所有设置、插件、任务都以这个文件夹为上下文。

```
my-project/
├── src/
├── package.json
├── .vscode/          ← 项目级配置
│   └── settings.json
└── README.md
```

适合：独立的、结构简单的单一项目。

### 工作区模式（.code-workspace 文件）

工作区文件是一个JSON配置文件，它可以包含：

- 多个文件夹（多根工作区）
- 工作区专属的设置覆盖
- 插件推荐
- 任务配置

```
my-workspace.code-workspace  ← 这个文件就是工作区的"配置中心"
frontend/
backend/
shared-lib/
```

### 多根工作区（Multi-root Workspace）

多根工作区是工作区模式的核心能力——你可以在一个VSCode窗口中同时打开多个不相关的文件夹，每个文件夹在侧边栏中独立显示。

```
📁 前端 (frontend/)
  📁 src/
  📁 public/
  📄 package.json
📁 后端 (backend/)
  📁 src/
  📁 migrations/
  📄 package.json
📁 共享库 (shared-lib/)
  📁 src/
  📄 package.json
```

## workspace文件的完整配置

一个 `.code-workspace` 文件本质上就是一个JSON文件，但它的schema比普通的settings.json丰富得多：

```jsonc
// fullstack-project.code-workspace
{
  // 多根文件夹配置
  "folders": [
    {
      "name": "前端",                    // 显示名称（不影响实际路径）
      "path": "./frontend"
    },
    {
      "name": "后端",
      "path": "./backend"
    },
    {
      "name": "共享类型",
      "path": "./shared-types"
    }
  ],

  // 工作区级别的设置（覆盖用户设置，但被文件夹设置覆盖）
  "settings": {
    // 编辑器设置
    "editor.tabSize": 2,
    "editor.formatOnSave": true,

    // 文件关联（不同项目可能有不同的文件类型需求）
    "files.associations": {
      "*.schema": "json"
    },

    // TypeScript相关
    "typescript.tsdk": "./frontend/node_modules/typescript/lib",

    // 搜索排除
    "search.exclude": {
      "**/node_modules": true,
      "**/dist": true,
      "**/.next": true
    },

    // 终端配置
    "terminal.integrated.defaultProfile.windows": "PowerShell"
  },

  // 推荐的插件（团队成员打开工作区时会提示安装）
  "extensions": {
    "recommendations": [
      "dbaeumer.vscode-eslint",
      "esbenp.prettier-vscode",
      "prisma.prisma",
      "bradlc.vscode-tailwindcss"
    ]
  },

  // 任务配置
  "tasks": {
    "version": "2.0.0",
    "tasks": [
      {
        "label": "启动全栈开发",
        "dependsOn": "启动所有服务",
        "group": {
          "kind": "build",
          "isDefault": true
        }
      },
      {
        "label": "启动前端",
        "type": "npm",
        "script": "dev",
        "path": "./frontend",
        "group": "build"
      },
      {
        "label": "启动后端",
        "type": "npm",
        "script": "dev",
        "path": "./backend",
        "group": "build"
      },
      {
        "label": "启动所有服务",
        "dependsOn": ["启动前端", "启动后端"],
        "dependsOrder": "parallel",
        "group": "build"
      }
    ]
  },

  // 启动配置
  "launch": {
    "version": "0.2.0",
    "configurations": [
      {
        "type": "chrome",
        "request": "launch",
        "name": "调试前端",
        "url": "http://localhost:3000",
        "webRoot": "${workspaceFolder:前端}/src"
      },
      {
        "type": "node",
        "request": "launch",
        "name": "调试后端",
        "program": "${workspaceFolder:后端}/dist/index.js",
        "preLaunchTask": "编译后端"
      }
    ]
  }
}
```

注意一个关键细节：`${workspaceFolder:前端}` 这个语法。在多根工作区中，你可以用 `文件夹名称` 来引用特定的根文件夹。这就像命名空间——避免了路径歧义。

## 实战：前后端分离项目的多根工作区

让我们为一个真实的前后端分离项目创建工作区配置。

### 项目结构

```
ecommerce-platform/
├── ecommerce.code-workspace    ← 我们要创建的文件
├── web/                         ← React前端
│   ├── src/
│   ├── public/
│   ├── package.json
│   └── tsconfig.json
├── api/                         ← Node.js后端
│   ├── src/
│   ├── prisma/
│   ├── package.json
│   └── tsconfig.json
├── packages/                    ← 共享包
│   ├── types/                   ← 共享类型定义
│   │   ├── src/
│   │   └── package.json
│   └── utils/                   ← 共享工具函数
│       ├── src/
│       └── package.json
└── docs/                        ← 项目文档
    └── api-spec.yaml
```

### 步骤1：创建工作区文件

在 `ecommerce-platform/` 目录下创建 `ecommerce.code-workspace`：

```jsonc
{
  "folders": [
    { "name": "Web前端",    "path": "./web" },
    { "name": "API后端",    "path": "./api" },
    { "name": "共享类型",   "path": "./packages/types" },
    { "name": "共享工具",   "path": "./packages/utils" },
    { "name": "文档",       "path": "./docs" }
  ],

  "settings": {
    // 全局工作区设置
    "editor.formatOnSave": true,
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.codeActionsOnSave": {
      "source.fixAll.eslint": "explicit"
    },

    // TypeScript配置（指向各项目的tsconfig）
    "typescript.preferences.importModuleSpecifier": "relative",

    // 文件浏览排除
    "files.exclude": {
      "**/node_modules": true,
      "**/.git": true,
      "**/dist": true,
      "**/.turbo": true
    }
  },

  "extensions": {
    "recommendations": [
      "dbaeumer.vscode-eslint",
      "esbenp.prettier-vscode",
      "prisma.prisma",
      "ms-vscode.vscode-typescript-next",
      "bradlc.vscode-tailwindcss",
      "humao.rest-client"
    ]
  },

  "tasks": {
    "version": "2.0.0",
    "tasks": [
      {
        "label": "dev:all",
        "dependsOn": ["dev:web", "dev:api"],
        "dependsOrder": "parallel",
        "group": { "kind": "build", "isDefault": true },
        "problemMatcher": []
      },
      {
        "label": "dev:web",
        "type": "npm",
        "script": "dev",
        "path": "./web",
        "problemMatcher": []
      },
      {
        "label": "dev:api",
        "type": "npm",
        "script": "dev",
        "path": "./api",
        "problemMatcher": []
      }
    ]
  }
}
```

### 步骤2：为每个文件夹配置专属设置

在每个子项目的 `.vscode/settings.json` 中可以放置特定于该文件夹的设置。这些设置的优先级高于工作区设置：

```jsonc
// web/.vscode/settings.json
{
  "editor.tabSize": 2,
  "tailwindCSS.experimental.classRegex": [
    ["cva\\(([^)]*)\\)", "[\"'`]([^\"'`]*?)[\"'`]"],
    ["cn\\(([^)]*)\\)",  "[\"'`]([^\"'`]*?)[\"'`]"]
  ]
}
```

```jsonc
// api/.vscode/settings.json
{
  "editor.tabSize": 2,
  "typescript.preferences.importModuleSpecifier": "non-relative",
  "typescript.preferences.moduleSpecifier": "shortest"
}
```

### 步骤3：设置和使用

```bash
# 用命令行打开工作区
code ecommerce.code-workspace

# 或者从VSCode中：File > Open Workspace from File...
```

打开后，你会在侧边栏看到所有文件夹，每个文件夹有自己的文件树。使用 `Ctrl+P`（`⌘+P`）快速打开文件时，VSCode会自动在所有根文件夹中搜索。

## 进阶：用Profiles为不同项目类型配置不同环境

VSCode的**配置文件（Profiles）**功能允许你为不同类型的项目创建完全不同的编辑器环境——包括设置、插件、快捷键、UI布局。

这类似于编程中的"环境变量"——同一个程序，不同的环境配置，产出不同的行为。

### 创建Profile

1. 点击左下角的齿轮图标 ⚙️
2. 选择 `Profiles > Create Profile...`
3. 选择创建方式：
   - **Empty Profile**：从零开始
   - **Copy from Current**：基于当前配置复制

### 实战：创建几个实用Profile

```
Profile: "前端开发"
├── 插件：ESLint, Prettier, Tailwind CSS IntelliSense, 
│        Auto Rename Tag, CSS Peek
├── 设置：
│   ├── editor.tabSize: 2
│   ├── editor.formatOnSave: true
│   └── emmet.includeLanguages: {...}
└── 主题：One Dark Pro

Profile: "Python数据科学"
├── 插件：Python, Pylance, Jupyter, Data Wrangler
├── 设置：
│   ├── editor.tabSize: 4
│   ├── python.formatting.provider: black
│   └── jupyter.notebookFileRoot: ${workspaceFolder}
└── 主题：GitHub Dark

Profile: "文档写作"
├── 插件：Markdown All in One, Markmap, 
│        Grammarly, Draw.io Integration
├── 设置：
│   ├── editor.wordWrap: on
│   ├── editor.minimap.enabled: false
│   └── editor.fontSize: 16
└── 主题：GitHub Light
```

### Profile的命令行操作

```bash
# 列出所有Profiles
code --list-profiles

# 用特定Profile打开项目
code --profile "前端开发" ./my-frontend-project

# 导出Profile
code --export-profile "前端开发" --output frontend-profile.json

# 导入Profile
code --import-profile frontend-profile.json --profile "前端开发-新"
```

### Profile切换场景

| 场景 | Profile | 关键区别 |
| ------ | --------- | --------- |
| 前端React项目 | frontend-dev | Tailwind插件、2空格缩进 |
| Python后端 | python-backend | Jupyter插件、4空格缩进 |
| 写技术博客 | writing | 大字体、自动换行、无minimap |
| 代码审查 | code-review | GitLens增强、内联diff |

## 📋 本章小结

- VSCode有三种项目打开方式：**单文件夹、工作区文件、多根工作区**，功能递增
- `.code-workspace` 文件是工作区的配置中心，可以配置文件夹、设置、插件推荐、任务、调试
- 多根工作区特别适合**monorepo、前后端分离、微服务**等多项目架构
- 每个文件夹可以有独立的 `.vscode/settings.json`，优先级高于工作区设置
- **Profiles**功能让你为不同项目类型定制完全不同的编辑器环境
- 善用 `${workspaceFolder:名称}` 语法在多根工作区中精确引用路径

> 设置系统是VSCode最容易被忽视、却又最强大的功能之一。下一章，我们将深入 `settings.json` 的"作用域链"。
