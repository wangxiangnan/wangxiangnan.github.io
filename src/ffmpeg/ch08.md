# 第8章：提取与合并——音视频手术刀

如果你把视频文件想象成一个"三明治"——视频流是一层，音频流是一层，字幕流又是一层——那么 FFmpeg 就是你的手术刀，可以精准地把每一层取出来、替换掉、或者把多个三明治拼成一个超级三明治。本章的核心概念是 `-map` 参数，这是 FFmpeg 最强大也最容易让人困惑的功能之一。

## 8.1 从视频提取音频

**保留原始编码（最快）：**

```bash
ffmpeg -i input.mp4 -vn -c:a copy output.aac
```

`-vn` 表示"不要视频"（video none），`-c:a copy` 表示音频直接复制。

**重新编码为特定格式：**

```bash
# 提取并转为 MP3
ffmpeg -i input.mp4 -vn -c:a libmp3lame -b:a 192k output.mp3

# 提取并转为 WAV（无损）
ffmpeg -i input.mp4 -vn -c:a pcm_s16le output.wav

# 提取并转为 FLAC（无损压缩）
ffmpeg -i input.mp4 -vn -c:a flac output.flac
```

> 💡 提示：如果你只是想把视频中的音乐提取出来听，`-c:a copy` 速度最快且零损失。但如果源音频是 AAC 而你想要 MP3，就必须重新编码。

## 8.2 提取纯视频（去掉音频）

```bash
ffmpeg -i input.mp4 -an -c:v copy output_nosound.mp4
```

`-an` 表示"不要音频"（audio none），`-c:v copy` 表示视频直接复制。处理速度同样飞快。

## 8.3 替换视频音轨

场景：你下载了一部电影，但音轨是英文的，你有一个中文配音的音频文件，想替换进去。

```bash
ffmpeg -i video.mp4 -i chinese_audio.mp3 -c:v copy -c:a aac -map 0:v:0 -map 1:a:0 output.mp4
```

这条命令的含义：

- `-i video.mp4`：第一个输入文件（编号 0）
- `-i chinese_audio.mp3`：第二个输入文件（编号 1）
- `-map 0:v:0`：取第 0 个输入文件的第 0 个视频流
- `-map 1:a:0`：取第 1 个输入文件的第 0 个音频流
- `-c:v copy`：视频不重编码
- `-c:a aac`：音频编码为 AAC

## 8.4 多音轨处理

**查看文件中有哪些流：**

```bash
ffprobe input.mkv
```

输出类似：

```
Stream #0:0: Video: h264 ...
Stream #0:1: Audio: aac (English)
Stream #0:2: Audio: ac3 (Chinese)
Stream #0:3: Subtitle: srt
```

**只保留第二个音轨（中文）：**

```bash
ffmpeg -i input.mkv -map 0:v:0 -map 0:a:1 -c copy output.mp4
```

**保留所有音轨：**

```bash
ffmpeg -i input.mkv -map 0 -c copy output.mkv
```

`-map 0` 表示"取第一个输入文件的所有流"。

**保留视频 + 第一个音轨 + 字幕：**

```bash
ffmpeg -i input.mkv -map 0:v:0 -map 0:a:0 -map 0:s:0 -c copy output.mkv
```

## 8.5 提取字幕流

**硬字幕 vs 软字幕：**

- 硬字幕（Hardsub）：字幕已经"烧"进视频画面里，无法关闭，无法提取
- 软字幕（Softsub）：字幕作为独立的流存在，可以开关、可以提取

**提取 SRT 字幕：**

```bash
ffmpeg -i input.mkv -map 0:s:0 output.srt
```

**提取 ASS 字幕：**

```bash
ffmpeg -i input.mkv -map 0:s:0 output.ass
```

**提取所有字幕流：**

```bash
ffmpeg -i input.mkv -map 0:s -c:s copy output_subtitles.mkv
```

> ⚠️ 注意：MP4 容器对字幕格式支持有限。如果你需要保留软字幕，建议使用 MKV 作为输出容器。

## 8.6 合并多个视频文件

这是 FFmpeg 中比较复杂的操作之一，有三种方式，适用于不同场景：

### 方式一：concat 协议（同编码快速合并）

适用于：所有文件的编码格式、分辨率、帧率完全一致。

```bash
ffmpeg -i "concat:part1.ts|part2.ts|part3.ts" -c copy output.ts
```

> ⚠️ 注意：concat 协议仅支持少数格式（主要是 TS、MPEG）。对于 MP4 等格式不适用。

### 方式二：concat demuxer（推荐方式）

适用于：编码格式相同但容器可能不同的文件。

首先创建一个文件列表 `filelist.txt`：

```text
file 'part1.mp4'
file 'part2.mp4'
file 'part3.mp4'
```

然后执行：

```bash
ffmpeg -f concat -safe 0 -i filelist.txt -c copy output.mp4
```

`-safe 0` 允许使用绝对路径和特殊字符。

> 💡 提示：如果文件路径包含中文或空格，必须加 `-safe 0`，并且路径用单引号包裹。

### 方式三：concat filter（不同编码/分辨率）

适用于：文件格式、分辨率、编码各不相同的文件。

```bash
ffmpeg -i part1.mp4 -i part2.avi -i part3.mkv \
  -filter_complex "[0:v][0:a][1:v][1:a][2:v][2:a]concat=n=3:v=1:a=1[outv][outa]" \
  -map "[outv]" -map "[outa]" output.mp4
```

这条命令看起来复杂，我们拆开来看：

- `[0:v][0:a]`：第一个文件的视频流和音频流
- `[1:v][1:a]`：第二个文件的视频流和音频流
- `[2:v][2:a]`：第三个文件的视频流和音频流
- `concat=n=3:v=1:a=1`：合并 3 个文件，有 1 个视频流和 1 个音频流
- `[outv][outa]`：输出的视频流和音频流的标签

> ⚠️ 注意：concat filter 会重新编码所有流，处理时间较长。如果文件编码一致，优先使用 concat demuxer。

**三种方式对比：**

| 方式 | 速度 | 适用场景 | 是否重编码 |
| ------ | ------ | --------- | ----------- |
| concat 协议 | 极快 | TS/MPEG 同编码 | 否 |
| concat demuxer | 极快 | 同编码不同文件 | 否 |
| concat filter | 慢 | 不同编码/分辨率 | 是 |

## 8.7 合并音频文件

**同格式快速合并：**

```bash
# 创建 filelist.txt
# file 'song1.mp3'
# file 'song2.mp3'
# file 'song3.mp3'

ffmpeg -f concat -safe 0 -i filelist.txt -c copy output.mp3
```

**不同格式合并：**

```bash
ffmpeg -i intro.wav -i main.mp3 -i outro.wav \
  -filter_complex "[0:a][1:a][2:a]concat=n=3:v=0:a=1[out]" \
  -map "[out]" -c:a libmp3lame -b:a 192k output.mp3
```

## 8.8 -map 参数深入：理解流映射

`-map` 是 FFmpeg 最核心的概念之一。它决定了输出文件中包含哪些流，以及流的顺序。

### 基本语法

```
-map 输入文件编号:流类型:流编号
```

- 输入文件编号：从 0 开始（第一个 `-i` 是 0，第二个是 1……）
- 流类型：`v`=视频，`a`=音频，`s`=字幕，`d`=数据
- 流编号：从 0 开始

### 示例详解

**示例1：最简单的映射**

```bash
ffmpeg -i input.mp4 output.avi
```

不使用 `-map` 时，FFmpeg 自动选择每个类型的第一个流：第一个视频流、第一个音频流。

**示例2：明确指定流**

```bash
ffmpeg -i input.mkv -map 0:v:0 -map 0:a:1 -c copy output.mkv
```

从输入文件取：第 0 个视频流 + 第 1 个音频流。

**示例3：多输入文件**

```bash
ffmpeg -i video.mp4 -i audio.mp3 -map 0:v -map 1:a -c copy output.mp4
```

从 video.mp4 取所有视频流，从 audio.mp3 取所有音频流。

**示例4：排除某种流（负映射）**

```bash
ffmpeg -i input.mkv -map 0 -map -0:s -c copy output.mkv
```

`-map 0` 取所有流，`-map -0:s` 排除所有字幕流。负映射用 `-` 前缀。

**示例5：调整流顺序**

```bash
ffmpeg -i input.mkv -map 0:a:1 -map 0:v:0 -map 0:a:0 -c copy output.mkv
```

输出文件的流顺序将是：第二个音轨 → 视频 → 第一个音轨。

> 💡 提示：一旦你在命令中使用了任何一个 `-map`，FFmpeg 就只包含你明确映射的流。没有 `-map` 参数时，FFmpeg 会自动选择。这是新手最常踩的坑——用了 `-map` 后发现字幕不见了，就是因为没有 `-map 0:s`。

**示例6：将同一音频复制为两条音轨**

```bash
ffmpeg -i video.mp4 -i audio.mp3 -map 0:v -map 1:a -map 1:a -c copy output.mkv
```

音频被映射了两次，输出文件将有两条相同的音轨。

### -map 的完整语法速查

| 语法 | 含义 |
| ------ | ------ |
| `-map 0` | 第一个输入的所有流 |
| `-map 0:v` | 第一个输入的所有视频流 |
| `-map 0:v:0` | 第一个输入的第一个视频流 |
| `-map 1:a` | 第二个输入的所有音频流 |
| `-map -0:s` | 排除第一个输入的所有字幕流 |
| `-map "[outv]"` | 映射滤镜输出的标签为 outv 的流 |

## 本章小结

- `-vn` 去掉视频，`-an` 去掉音频——简单粗暴但有效
- 合并视频优先用 concat demuxer（文件列表方式），兼顾速度和兼容性
- `-map` 参数是精确控制输出流的关键，一旦使用就必须明确指定所有需要的流
- 负映射 `-map -0:s` 可以方便地排除不需要的流类型
