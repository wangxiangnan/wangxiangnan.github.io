# 第5章：内置终端与命令行集成

> [!TIP] Part II: 核心工作流精通
> 在 VSCode 之前，开发者的日常是：左边一个编辑器，右边一个终端，`Alt+Tab`（`⌘+Tab`）在两者之间反复切换。VSCode 的内置终端不只是"把终端嵌进侧边栏"——它能知道当前工作目录、认得每条命令的退出状态，还能把编译错误里的文件路径变成可点击的跳转。这一章，我们把它调教成顺手的工作台。

## 5.1 终端 Profile 与默认 Shell

VSCode 的终端不是一个写死的 Shell，而是一组可以配置的 **Profile（终端配置）**。每个 Profile 描述：用哪个可执行文件、带什么启动参数、注入哪些环境变量。

> 这里的 Profile 指终端配置，不要和第 2 章讲的编辑器 Profile（一套设置 + 扩展 + 快捷键）混淆。

### 默认值

- Windows 默认使用 **PowerShell**
- Linux / macOS 默认使用 `$SHELL`
- VSCode 还会自动探测系统里的常见 Shell（Git Bash、zsh、fish、WSL 发行版等），放进新建终端的下拉菜单

### 定义一个 Profile

一个 Profile 支持这些字段：

| 字段 | 作用 |
| --- | --- |
| `path` | Shell 可执行文件的路径 |
| `source` | 让 VSCode 自动探测安装位置；仅 Windows 支持，值为 `PowerShell` 或 `Git Bash` |
| `args` | 启动参数，比如 `-l`（登录 Shell）、`-NoLogo`（隐藏启动横幅） |
| `env` | 仅对这个 Profile 生效的环境变量 |
| `icon` | 标签页图标 ID，如 `terminal-powershell`、`terminal-cmd`、`terminal-bash` |
| `color` | 标签页图标的主题颜色 ID |
| `overrideName` | 是否用 Profile 名固定标签标题，而不是跟随当前运行的程序变化 |

Windows 上的一份完整配置：

```jsonc
// settings.json
{
  "terminal.integrated.defaultProfile.windows": "PowerShell",
  "terminal.integrated.profiles.windows": {
    "PowerShell": {
      "source": "PowerShell",
      "args": ["-NoLogo"],
      "icon": "terminal-powershell"
    },
    "Command Prompt": {
      "path": "C:\\Windows\\System32\\cmd.exe",
      "icon": "terminal-cmd"
    },
    "Git Bash": {
      "source": "Git Bash",
      "args": ["--login"],
      "icon": "terminal-bash"
    },
    "Ubuntu (WSL)": {
      "path": "C:\\Windows\\System32\\wsl.exe",
      "args": ["-d", "Ubuntu"],
      "icon": "terminal-ubuntu"
    }
  }
}
```

macOS 和 Linux 用各自的键名；`source` 在非 Windows 平台不可用，所以要写 `path`：

```jsonc
{
  "terminal.integrated.defaultProfile.osx": "zsh",
  "terminal.integrated.profiles.osx": {
    "zsh": {
      "path": "/bin/zsh",
      "args": ["-l"]
    },
    "bash": {
      "path": "/bin/bash",
      "args": ["-l"]
    }
  },
  "terminal.integrated.defaultProfile.linux": "zsh",
  "terminal.integrated.profiles.linux": {
    "zsh": {
      "path": "zsh",
      "args": ["-l"]
    }
  }
}
```

两个容易踩的坑：

- **`-l` 不是可有可无的**。GUI 启动的 VSCode 不一定会读取 `~/.zprofile`、`~/.bash_profile`，用登录 Shell 启动能把 PATH 等环境变量补回来。macOS 上"外部终端能跑、VSCode 终端找不到命令"通常就是这个原因。
- **自定义 Profile 是追加，不是替换**。VSCode 探测到的内置 Profile 仍然会在下拉菜单里。想去掉某个内置项，把同名键设为 `null`：

```jsonc
{
  "terminal.integrated.profiles.windows": {
    "Command Prompt": null
  }
}
```

切换默认 Profile 用命令面板的 `Terminal: Select Default Profile`，或者点终端面板右上角 `+` 旁边的下拉箭头。已经打开的终端不会因为改默认值而换 Shell，新建一个才会生效。

### 任务与调试专用的 Shell

Tasks 和调试器默认也走默认 Profile。如果你的默认 Shell 加载了重型启动脚本（比如一堆 PowerShell 模块），而任务只需要一个轻量、行为稳定的 Shell，可以单独指定自动化 Profile：

```jsonc
{
  "terminal.integrated.automationProfile.windows": {
    "path": "C:\\Windows\\System32\\cmd.exe"
  },
  "terminal.integrated.automationProfile.osx": {
    "path": "/bin/sh"
  }
}
```

它只影响任务和调试，不会改变你平时手动打开的终端。任务本身怎么配置，第 7 章会展开。

## 5.2 布局、分屏与快捷键

### 放在面板还是编辑区

终端默认出现在底部面板，也可以整体搬到编辑区：

```jsonc
{
  "terminal.integrated.defaultLocation": "view",
  "workbench.panel.defaultLocation": "right"
}
```

- `terminal.integrated.defaultLocation`：`"view"` 表示面板，`"editor"` 表示编辑区
- `workbench.panel.defaultLocation`：面板停靠位置，可选 `"left"`、`"right"`、`"bottom"`

已有的终端可以用命令面板的 `Terminal: Move Terminal into Editor Area` 搬过去，也可以直接把终端标签拖进编辑区标签栏。把日志、监控这类需要长期盯着看的终端放进编辑区，再和代码分屏，比在底部反复拉面板舒服得多。

### 常用快捷键

| 操作 | Windows | Linux | macOS |
| --- | --- | --- | --- |
| 显示 / 隐藏终端 | `` Ctrl+` `` | `` Ctrl+` `` | `` ⌃` `` |
| 新建终端 | `` Ctrl+Shift+` `` | `` Ctrl+Shift+` `` | `` ⌃⇧` `` |
| 拆分终端 | `Ctrl+Shift+5` | `Ctrl+Shift+5` | `⌘\` |
| 在分屏间切换焦点 | `Alt+←/→` | `Alt+←/→` | `⌥⌘←/→` |
| 切换终端组 | `Ctrl+PageUp/PageDown` | `Ctrl+PageUp/PageDown` | `⇧⌘[` / `⇧⌘]` |
| 复制 | `Ctrl+C`（有选中时） | `Ctrl+Shift+C` | `⌘C` |
| 粘贴 | `Ctrl+V` | `Ctrl+Shift+V` | `⌘V` |
| 清屏 | 命令面板 `Terminal: Clear` | 命令面板 `Terminal: Clear` | `⌘K` |

几点说明：

- 拆分终端还可以 **`Alt` + 单击终端标签**，新分屏会落在同一个终端组里。
- Windows 上 `Ctrl+C` 的语义取决于有没有选中文本：有选中就复制，没有就发送中断信号（SIGINT）。Linux 下复制固定是 `Ctrl+Shift+C`，别把 `Ctrl+C` 当成复制用。
- macOS 的 `⌘K` 被留给了"清屏"，所以 `⌘K` 开头的组合键在终端里默认不可用。Windows/Linux 没有默认清屏键，用命令面板最稳。
- 分屏默认继承哪个目录，由 5.4 节的 `splitCwd` 决定。

### 管理标签

终端标签可以重命名、换颜色、换图标：

- 右键标签 → **Rename** / **Change Color** / **Change Icon**
- 或者用命令面板的 `Terminal: Rename`、`Terminal: Change Color`、`Terminal: Change Icon`

分屏出来的几个终端构成一个"组"，`Ctrl+PageUp/PageDown`（macOS `⇧⌘[` / `⇧⌘]`）在组之间切换，`Alt+←/→` 在同一个组的分屏之间切换。标签本身也能拖动排序，或拖到编辑区变成独立标签页。

## 5.3 Shell 集成：让终端"看懂"命令

Shell 集成（Shell Integration）是 VSCode 终端最有价值的功能。它会往受支持的 Shell 里注入一小段脚本，通过 OSC 633 转义序列告诉 VSCode：提示符从哪开始、命令从哪开始、命令何时结束、退出码是多少、当前目录在哪。

默认开启。受支持的 Shell：

- Linux / macOS：bash、fish、pwsh、zsh
- Windows：PowerShell 7（`pwsh`）、Git Bash

`cmd.exe` 没有 Shell 集成，这也是它在 VSCode 里显得"笨"的原因。

### 基础设置

```jsonc
{
  "terminal.integrated.shellIntegration.enabled": true,
  "terminal.integrated.shellIntegration.decorationsEnabled": "both",
  "terminal.integrated.shellIntegration.showCommandGuide": true,
  "terminal.integrated.stickyScroll.enabled": true
}
```

`decorationsEnabled` 的取值是 `both`、`gutter`、`overviewRuler`、`never`——注意它是字符串枚举，不是布尔值。`both` 表示左侧行内装饰和滚动条概览标尺都显示。

### 命令装饰与菜单

开启后，每条命令左侧会出现一个小圆点：

```text
●  npm run build     成功（绿色）
●  npm test          失败（红色）
○  npm run dev       正在运行（空心）
```

悬停能看到退出码等信息。点击装饰点会弹出菜单，可以 **Rerun Command**、**Copy Output**、**Copy Output as HTML**；命令之间用下面的快捷键跳转。滚动条上的概览标尺会标出每条命令的位置，长输出里找报错很方便。

### 命令导航

| 操作 | Windows / Linux | macOS |
| --- | --- | --- |
| 上一条 / 下一条命令 | `Ctrl+↑` / `Ctrl+↓` | `⌘↑` / `⌘↓` |
| 从当前位置选中到命令边界 | `Ctrl+Shift+↑/↓` | `⇧⌘↑/↓` |
| 跳到最近访问过的目录 | `Ctrl+G` | `⌘G` |

`Terminal: Run Recent Command` 打开的是命令历史快速选择器，来源包括当前会话、该 Shell 的历史会话以及公共历史文件。搜索框右侧可以切到模糊搜索；条目可以固定到顶部；按住 `Alt` 只把命令写入终端而不执行。选中条目右侧的剪贴板图标，还能把该命令的输出在编辑器中打开。

`Terminal: Go to Recent Directory` 则按目录跳转并直接 `cd` 过去。Windows/Linux 下如果想把 `Ctrl+G` 原样发给 Shell，用 `Ctrl+Alt+G`。

### 命令指南与粘性滚动

Shell 集成知道每条命令的输出范围，于是有了两个很实用的视觉辅助：

- **命令指南**：悬停时在命令和它的输出旁边显示一条竖线，方便确认"这段输出属于哪条命令"。对应设置 `terminal.integrated.shellIntegration.showCommandGuide`。
- **粘性滚动**：往上翻长输出时，当前命令固定在终端顶部，点击就能跳回命令位置。对应设置 `terminal.integrated.stickyScroll.enabled`。

### 快速修复

VSCode 会扫描命令输出，在少数确定性很高的场景给出快速修复：

| 场景 | 建议动作 |
| --- | --- |
| 端口已被占用 | 杀掉占用端口的进程并重跑上一条命令 |
| `git push` 没有设置上游 | 带 `--set-upstream` 重新推送 |
| `git` 子命令拼写错误 | 使用相近的正确命令 |
| `git push` 输出里带有创建 PR 的链接 | 直接打开链接 |
| PowerShell 报"找不到命令" | 采用 PowerShell 反馈提供者给出的候选 |

注意它只覆盖这些可判定的情况。比如运行 Node 服务时报 `Cannot find module 'express'`，VSCode **不会**自动提示你 `npm install express`——这种依赖判断应该交给语言服务或包管理器本身。

### 终端 IntelliSense

较新的 VSCode 版本给终端加了补全：输入命令、参数、路径时会出现建议列表。

- 手动触发：`Ctrl+Space`（macOS `⌃Space`）
- `Tab` 接受当前建议；用方向键移动后也可以按 `Enter`
- 开关：`terminal.integrated.suggest.enabled`

如果 `Ctrl+Space` 被系统输入法占用，可以在快捷键设置里改绑 `workbench.action.terminal.triggerSuggest`。觉得补全弹窗干扰时，直接把 `suggest.enabled` 关掉即可，不影响 Shell 本身。

### 集成不生效时

先悬停终端标签，看 Shell Integration 的质量：

- **Rich**：命令检测完整
- **Basic**：只能检测部分信息，比如没有退出码
- **None**：没有生效

常见原因有：用的是 `cmd.exe`、PowerShell 执行策略禁止运行脚本、或者 Shell 配置在 VSCode 之外被复杂地重写。自动注入在普通本地 Shell 上最可靠；通过裸 `ssh` 进入的远程会话、子 Shell 等场景，可能需要在 Shell 启动脚本里手动加载：

```bash
# 以 zsh 为例；bash / Git Bash 写法相同，fish / pwsh 的加载语法不同
[[ "$TERM_PROGRAM" == "vscode" ]] && . "$(code --locate-shell-integration-path zsh)"
```

Windows 上如果 PowerShell 的执行策略是 `Undefined`，可以考虑：

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

只在你独占这台机器的用户账户时这么做。

## 5.4 环境变量、工作目录与终端行为

### 注入环境变量

`terminal.integrated.env.<platform>` 可以给所有集成终端加环境变量：

```jsonc
{
  "terminal.integrated.env.windows": {
    "NODE_ENV": "development",
    "EDITOR": "code --wait",
    "PATH": "${env:PATH};C:\\tools\\bin"
  },
  "terminal.integrated.env.osx": {
    "NODE_ENV": "development",
    "EDITOR": "code --wait",
    "PATH": "${env:PATH}:/opt/homebrew/bin"
  },
  "terminal.integrated.env.linux": {
    "NODE_ENV": "development",
    "PATH": "${env:PATH}:/usr/local/bin"
  }
}
```

- `${env:PATH}` 会展开为当前进程的 PATH，Windows 用 `;` 分隔，macOS/Linux 用 `:`。
- 这些变量只注入 VSCode 启动的终端，不会改系统环境，也不影响你从桌面打开的终端。
- 设置改动后要新建终端才生效，旧终端仍然用旧环境。

macOS/Linux 上还有一个环境继承开关 `terminal.integrated.inheritEnv`，默认开启。遇到 PATH 重复、顺序反常时，先查 Shell 启动参数（是不是重复跑了登录脚本），通常比直接关掉继承更有效。

### 起始目录

```jsonc
{
  "terminal.integrated.cwd": "${workspaceFolder}",
  "terminal.integrated.splitCwd": "inherited"
}
```

`cwd` 决定新终端从哪里开始；不设置时通常落在工作区根目录。`splitCwd` 决定拆出来的终端从哪里开始：

| 取值 | 行为 |
| --- | --- |
| `workspaceRoot` | 从工作区根目录开始；多根工作区会让你选一个 |
| `initial` | 沿用父终端启动时的目录 |
| `inherited` | 沿用父终端**当前**所在的目录；macOS/Linux 生效，Windows 上等同于 `initial` |

默认是 `inherited`：在子目录里拆一个终端，它自然也在子目录里，不用再 `cd` 一次。

### 环境变化时重启终端

有些扩展会在运行中改变环境变量，比如 Python 解释器切换、`.env` 文件变化、版本管理器切换 Node 版本。如果终端还没有被用户操作过，VSCode 默认会为了应用新环境而自动重启它：

```jsonc
{
  "terminal.integrated.environmentChangesRelaunch": true
}
```

这是默认值（`true`）。如果你更希望终端保持现状、由自己决定什么时候重开，把它设为 `false`。自动重启发生时，终端里正在跑的长任务会被打断，这也是有人关掉它的原因。

> 旧版本里的 `terminal.integrated.environmentChangesIndicator` 和 `terminal.integrated.environmentChangesRevert` 已经移除，不要再写进 `settings.json`。现在只有 `environmentChangesRelaunch` 这一个开关。

### 行为与外观

常用行为设置：

| 设置 | 作用 | 常用值 |
| --- | --- | --- |
| `terminal.integrated.rightClickBehavior` | 右键行为 | `default` / `copyPaste` / `paste` / `selectWord` / `nothing` |
| `terminal.integrated.copyOnSelection` | 选中即复制 | `false`（推荐保持关闭，避免误复制） |
| `terminal.integrated.enableMultiLinePasteWarning` | 多行粘贴确认 | `auto` / `always` / `never` |
| `terminal.integrated.confirmOnExit` | 关闭窗口时，若有活动终端会话则确认 | `never` / `always` / `hasChildProcesses` |
| `terminal.integrated.confirmOnKill` | 终止有子进程的终端时确认 | `never` / `editor` / `panel` / `always` |
| `terminal.integrated.showExitAlert` | 进程以非零码退出时弹提示 | `true` / `false` |

`rightClickBehavior` 的平台默认值不同：Windows 默认 `copyPaste`，macOS 默认 `selectWord`，Linux 默认 `default`。另外，Git Bash 这类 Shell 的子进程检测不一定准确，`confirmOnKill` 未必能拦住所有"还有服务在跑"的情况。

外观配置：

```jsonc
{
  "terminal.integrated.fontFamily": "'JetBrains Mono', 'Cascadia Code', Consolas, monospace",
  "terminal.integrated.fontSize": 13,
  "terminal.integrated.lineHeight": 1.2,
  "terminal.integrated.letterSpacing": 0,
  "terminal.integrated.cursorStyle": "line",
  "terminal.integrated.cursorBlinking": true,
  "terminal.integrated.scrollback": 10000,
  "terminal.integrated.smoothScrolling": true
}
```

`cursorStyle` 可选 `block`、`line`、`underline`。如果你用 Oh My Posh、Starship 这类带图标的提示符，字体必须包含 Nerd Font 字形，否则图标会显示成方框；把 `fontFamily` 指向一个 Nerd Font 变体即可。

## 5.5 终端里的链接与跳转

终端会自动识别输出中的文件路径、行号列号和 URL：

```bash
$ npm run build
src/components/Button.tsx:42:8 - error TS2322: Type 'string' is not assignable ...

$ npm run dev
  ➜  Local:   http://localhost:5173/
```

`Ctrl+Click`（macOS `Cmd+Click`）路径会直接在编辑器中打开对应文件，并跳到第 42 行第 8 列；点击 URL 会在浏览器中打开。悬停时链接会显示下划线，可以先确认再点。

Shell 集成开启时，相对路径会按终端的**当前工作目录**解析。比如输出里只有 `package.json`，VSCode 知道你在 `web/` 目录下，就会直接打开 `web/package.json`；没有 Shell 集成时，工作区里有多个同名文件，它只能弹出选择框让你挑。

控制链接行为：

```jsonc
{
  "terminal.integrated.enableFileLinks": "on"
}
```

`enableFileLinks` 可选 `on`、`off`、`notRemote`。`notRemote` 表示本地窗口启用、远程窗口禁用，适合远程终端里路径无法在本机解析的场景。默认允许 `file`、`http`、`https`、`mailto`、`vscode`、`vscode-insiders` 这些协议；想收紧范围，用 `terminal.integrated.allowedLinkSchemes`：

```jsonc
{
  "terminal.integrated.allowedLinkSchemes": ["file", "http", "https"]
}
```

键盘操作：把光标移到链接附近，从命令面板执行 `Terminal: Open Detected Link...`，再用方向键选择。

链接检测不是万能的：路径必须能被解析且文件存在；被终端换行截断的长 URL 可能只识别出一半；自定义格式的输出（比如某些测试框架）如果不符合常见路径格式，也不会变成链接。

## 5.6 用 `code` 命令反向驱动编辑器

内置终端不只接收命令，也能反过来调用 VSCode。`code` 命令行是把终端和编辑器连起来的另一条通道。

### 先让 `code` 可用

- **Windows**：安装时勾选 "Add to PATH"。如果当时没勾，重新运行安装程序补上；或者直接用完整路径 `%LOCALAPPDATA%\Programs\Microsoft VS Code\bin\code.cmd`
- **macOS**：命令面板执行 `Shell Command: Install 'code' command in PATH`
- **Linux**：通过包管理器安装后通常已经有 `/usr/bin/code`
- **WSL**：在 WSL 里执行 `code .`，会通过 Remote - WSL 打开远程窗口（需要安装 WSL 扩展，见第 17 章）

### 常用命令

```bash
code .                          # 打开当前目录
code -r src/app.ts              # 在当前窗口打开文件
code -n .                       # 强制新窗口
code --goto src/app.ts:15:8     # 打开并跳到第 15 行第 8 列
code --diff old.ts new.ts       # 打开差异视图
code --wait notes.md            # 等文件关闭后再返回
code --install-extension dbaeumer.vscode-eslint
code --list-extensions
code . --profile "前端"          # 用指定 Profile 打开
```

`-r`（`--reuse-window`）很适合脚本和日常命令：不额外弹窗口，直接在当前窗口换文件。`--goto` 配合测试输出、`grep`/`rg` 结果特别顺手。

### 把 `code --wait` 当成 Git 编辑器

这是 `code` 命令行最经典的一个用途：

```bash
git config --global core.editor "code --wait"
```

没有 `--wait`，`code` 启动完就立刻返回，Git 会以为你什么都没写；加上它，Git 会一直等到你关闭编辑标签页。之后 `git commit`、`git rebase -i` 都会在 VSCode 里完成。Git 工作流本身在第 6 章。

## 5.7 实战：一套前端开发终端

目标：默认终端是开发环境，测试终端带 `NODE_ENV=test`，两个服务各占一个终端，再加一个能在编辑区看日志的终端。

### 步骤 1：定义开发与测试 Profile

```jsonc
// settings.json
{
  "terminal.integrated.defaultProfile.windows": "Dev",
  "terminal.integrated.profiles.windows": {
    "Dev": {
      "source": "PowerShell",
      "args": ["-NoLogo"],
      "env": {
        "NODE_ENV": "development"
      },
      "icon": "terminal-powershell"
    },
    "Test": {
      "source": "PowerShell",
      "args": ["-NoLogo"],
      "env": {
        "NODE_ENV": "test"
      },
      "icon": "terminal-powershell"
    }
  },
  "terminal.integrated.cwd": "${workspaceFolder}",
  "terminal.integrated.splitCwd": "inherited"
}
```

macOS/Linux 把 `windows` 换成 `osx`/`linux`，并把 `source` 换成 `path` 即可。Profile 里的 `env` 只对通过该 Profile 启动的终端生效，不会污染系统环境。

### 步骤 2：用 Tasks 一键拉起两个服务

```jsonc
// .vscode/tasks.json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "web:dev",
      "type": "npm",
      "script": "dev",
      "isBackground": true,
      "problemMatcher": [],
      "presentation": {
        "panel": "dedicated",
        "reveal": "always",
        "showReuseMessage": false,
        "clear": true
      }
    },
    {
      "label": "web:test",
      "type": "npm",
      "script": "test:watch",
      "isBackground": true,
      "problemMatcher": [],
      "presentation": {
        "panel": "dedicated",
        "reveal": "never"
      }
    },
    {
      "label": "dev",
      "dependsOn": ["web:dev", "web:test"],
      "dependsOrder": "parallel",
      "group": {
        "kind": "build",
        "isDefault": true
      }
    }
  ]
}
```

`Ctrl+Shift+B`（macOS `⌘+Shift+B`）会执行默认构建任务 `dev`，并行启动两个后台任务，各自占用一个独立终端。`problemMatcher: []` 表示先不解析输出；这两个进程本来就不会结束，`isBackground` 让任务系统知道它们是长期运行的后台任务。

如果希望任务等到开发服务器真正就绪再继续，或者把 TypeScript/Vite 的错误汇总到 Problems 面板，需要给 `problemMatcher` 配 `background.beginsPattern` / `endsPattern`，这是第 7 章的主题。这里先不把手写的正则塞进来。

### 步骤 3：安排终端布局

```text
┌────────────────────────────┬────────────────────────────┐
│ Dev                        │ Test                       │
│ $ npm run dev              │ $ npm run test:watch       │
│ NODE_ENV=development       │ NODE_ENV=test              │
├────────────────────────────┴────────────────────────────┤
│ Logs                                                     │
│ $ docker compose logs -f                                 │
└──────────────────────────────────────────────────────────┘
```

- `Ctrl+Shift+5` 拆分终端，分别重命名成 Dev / Test / Logs
- 右键标签改颜色，开发用蓝、测试用黄、日志用灰，扫一眼就知道在哪个环境
- 把 Logs 终端拖进编辑区，和代码左右分屏；日志长期滚屏时不占底部面板

### 步骤 4：给测试终端配一个专用快捷键

默认快捷键只能打开默认 Profile。想一键打开 Test，用 `workbench.action.terminal.newWithProfile`：

```jsonc
// keybindings.json
[
  {
    "key": "ctrl+alt+t",
    "command": "workbench.action.terminal.newWithProfile",
    "args": {
      "profileName": "Test"
    }
  }
]
```

macOS 上把 `key` 改成 `cmd+alt+t`。命令还接受可选的 `location` 参数（比如 `"editor"`），用来直接开在编辑区。

### 步骤 5：日常配合

1. `Ctrl+Shift+B` 启动两个后台服务
2. `` Ctrl+` `` 收起/展开面板，专注写代码
3. `Ctrl+↑/↓` 在命令之间跳，右键命令装饰点重跑失败的测试
4. 构建报错时 `Ctrl+Click` 路径，直接跳到出错的文件和行列
5. 切到别的目录看日志后，`Ctrl+G` 快速跳回最近访问的目录

## 5.8 常见问题排查

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 终端启动失败 | Profile 的 `path` 写错、参数不合法 | 用绝对路径；先用 `Terminal: Select Default Profile` 切回内置 Profile 验证 |
| 改了默认 Profile 没生效 | 旧终端仍用旧 Shell | 关闭旧终端，新建一个；默认值只影响新终端 |
| 外部终端能跑的命令，这里找不到 | GUI 启动未加载 Shell 配置；不是登录 Shell | macOS/Linux 给 Profile 加 `-l`；检查 PATH；必要时再动 `inheritEnv` |
| Shell 集成没有装饰、无法跳转 | 用的是 `cmd.exe`；PowerShell 脚本被策略拦截；自定义提示符覆盖了集成脚本 | 换 pwsh 或 Git Bash；检查悬停标签页里的集成质量；调整执行策略 |
| PowerShell 提示脚本被禁止运行 | 执行策略过严 | 用户级 `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser`（确认你独占该账户） |
| 中文或图标显示成方框 | 字体缺字形；提示符图标需要 Nerd Font | 换含中文的等宽字体；图标场景使用 Nerd Font 变体 |
| 粘贴多行时总弹确认 | 多行粘贴保护 | 将 `enableMultiLinePasteWarning` 调成 `never`，确认自己知道风险 |
| 拆分后的终端目录不对 | `splitCwd` 设成了 `workspaceRoot` 或 `initial` | 想让分屏跟随父终端当前目录，设为 `inherited`（Windows 上仍按 `initial` 处理） |
| 右键不是复制/粘贴 | 平台默认行为不同 | 设置 `rightClickBehavior` 为 `copyPaste`、`paste` 或 `selectWord` |
| 改了环境变量，旧终端没变 | 终端只在创建时读取环境 | 新建终端；如果自动重启被关掉了，确认 `environmentChangesRelaunch` 没被设为 `false` |
| 关掉终端后服务停了 | 进程是终端的子进程 | 隐藏面板不会杀进程；关闭终端标签或窗口会。需要常驻就用系统服务或容器 |

自动重启只发生在"终端还没有被操作过"的情况下；如果你已经在终端里干活，VSCode 不会贸然打断。想彻底避免重启，就把 `environmentChangesRelaunch` 设为 `false`。

📋 **本章小结**

- 终端 **Profile** 描述 Shell 的路径、参数和环境；Windows 默认 PowerShell，Linux/macOS 默认 `$SHELL`
- 自定义 Profile 是追加到自动探测结果上的，去掉内置项用 `null`；`-l` 能补回 GUI 启动缺失的登录环境
- 终端可放在底部面板或编辑区，拆分用 `Ctrl+Shift+5`（macOS `⌘\`），分屏焦点 `Alt+←/→`，终端组 `Ctrl+PageUp/PageDown`
- **Shell 集成**提供命令装饰、命令导航、命令指南、粘性滚动、快速修复和最近命令/目录
- 快速修复只覆盖少数确定性场景，不会替你做依赖安装之类的判断
- `terminal.integrated.env.*` 注入环境变量，`cwd` / `splitCwd` 控制起始目录，`environmentChangesRelaunch` 取代了已删除的两个旧设置
- 终端里的文件路径、`文件:行:列` 和 URL 可点击，配合 Shell 集成能按当前目录解析相对路径
- `code` 命令行支持 `-r`、`--goto`、`--diff`、`--wait`、扩展安装和 Profile；用它做 Git 编辑器记得加 `--wait`
- 多服务开发可以用 Tasks 一行命令拉起多个终端，后台任务的就绪检测与 problem matcher 见第 7 章
