# 第5章 用 JS 实测：API 与真机数据

> **本章回答的问题**：真机上 `innerWidth`、`outerWidth`、`devicePixelRatio` 到底读出多少？为什么各平台不一样？

原理讲完，这一章用真机数据验证。以下数据来自 iPhone 16 Pro Max（440×956 CSS，DPR 3，1320×2868 物理），**在不写 viewport 的页面上测得**。

## 5.1 五个常用测量 API

| API | 含义 | 期望读到 |
| ----- | ------ | ---------- |
| `window.innerWidth` | 布局视口宽度 | 受 viewport 标签控制 |
| `window.outerWidth` | 浏览器窗口宽度 | 平台相关（见 [5.3 节](/pixels-viewport/ch05#_5-3-平台差异对照表)） |
| `screen.width` | 屏幕的理想视口宽度 | 440 |
| `window.devicePixelRatio` | 有效 DPR | 平台相关（见 [5.3 节](/pixels-viewport/ch05#_5-3-平台差异对照表)） |
| `visualViewport.width` | 当前视觉视口宽度 | 随捏合缩放变化 |

## 5.2 实测结果与逐项解释

真机输出：

```javascript
window.innerWidth        // 980
window.outerWidth        // 440
screen.width             // 440
window.devicePixelRatio  // 3
```

**innerWidth = 980** ✓：未加 viewport，布局视口取默认 980px，`innerWidth` 读布局视口。桌面兼容模式生效的直接证据。

**outerWidth = 440**：等于 `screen.width`。iOS WebKit 把 `outerWidth` 定义为**设备屏幕的 CSS 像素宽度**——iOS 上没有带工具栏外框的窗口概念，页面直接铺满 App。桌面浏览器上 `outerWidth` 是含边框工具栏的窗口外框宽度，与屏幕无关；iOS 上两者语义完全不同。

**devicePixelRatio = 3**：按缩放逻辑推算，980 塞进 440 应产生 0.45 倍缩放，若 DPR 跟随缩放，读数应约为 1320/980 ≈ 1.35（Chrome/Firefox 的行为）。但 **Safari 把 DPR 定义为固定原生属性**：1 CSS 像素在 1 倍缩放下对应的物理像素数 = 1320/440 = 3。980→440 的适配作为"页面缩放"实现，不计入 DPR；连双指捏合也不改变 Safari 的 DPR 读数。

## 5.3 平台差异对照表

同一个"不加 viewport"的页面，不同环境的读数：

| 读数 | 桌面 Chrome（150% 系统缩放，1080p） | iPhone 16 Pro Max（Safari） |
| ------ | -------------------------------------- | ------------------------------ |
| innerWidth | 1280（桌面无 980 兼容问题） | 980 |
| outerWidth | 窗口外框宽度，随窗口拖拽变化 | 440，恒等于 screen.width |
| devicePixelRatio | 1.5 × 浏览器缩放，动态变化 | 3，固定不变 |

记忆要点：**`innerWidth` 唯一受 viewport 标签控制；`outerWidth` 和 `devicePixelRatio` 在 iOS 上是设备固有属性**。

## 5.4 调试建议

- 真机验证用 `vConsole` 或 Eruda 注入控制台，直接在页面上打印上述五个值。
- Chrome DevTools 的设备模拟可以模拟 DPR 和视口，但模拟不了 Safari 的 DPR 固定行为，涉及精确读数时以真机为准。
- `visualViewport` 在软键盘弹出、捏合缩放时都会变化，做"键盘弹起时固定底部输入栏"类需求必须监听它。

**可复制的测量面板**——保存为 `measure.html` 发到手机打开，即可复现 [5.2 节](/pixels-viewport/ch05#_5-2-实测结果与逐项解释)的全部数据：

```html

<meta name="viewport" content="width=device-width, initial-scale=1">

<style>
  body { font: 16px/1.9 system-ui, sans-serif; margin: 0; padding: 16px; }

</style>
</head>
<body>
  <h3>像素测量面板</h3>
  <table>
    <tr><th>布局视口 window.innerWidth</th><td id="vInner"></td></tr>
    <tr><th>布局视口 clientWidth</th><td id="vClient"></td></tr>
    <tr><th>视觉视口 visualViewport.width</th><td id="vVv"></td></tr>
    <tr><th>窗口 window.outerWidth</th><td id="vOuter"></td></tr>
    <tr><th>屏幕 screen.width</th><td id="vScreen"></td></tr>
    <tr><th>设备像素比 devicePixelRatio</th><td id="vDpr"></td></tr>
  </table>
  <p class="tip">

    outerWidth = screen.width = 440、DPR = 3；删掉 meta 刷新，innerWidth 变 980。
    双指缩放只有 visualViewport 变；桌面 Ctrl+加/减号改的是 DPR。

<script>

```

## 5.5 小结

- `innerWidth` 反映布局视口：不加 viewport 就是 980。
- iOS 上 `outerWidth = screen.width`（理想视口），语义与桌面不同。
- Safari 的 DPR 是固定原生值，不随页面缩放变化——与 Chrome 的动态 DPR 是两套行为。

## 5.6 练习题

1. 在不加 viewport 的页面上，iPhone 16 Pro Max 的 `innerWidth`、`outerWidth`、`screen.width`、`devicePixelRatio` 各是多少？
2. 桌面 Windows 系统缩放 100%，浏览器缩放 125%，`devicePixelRatio` 是多少？
3. 为什么双指捏合缩放时，Safari 的 `devicePixelRatio` 读数不变，而 Chrome 会变？

## 5.7 参考答案

> 1. 依次为 980（布局视口默认值）、440（iOS 定义为 screen.width）、440、3（固定原生值）。
> 2. 有效 DPR = 1.0 × 1.25 = 1.25。
> 3. 两家对 DPR 的实现定义不同：Safari 把它当作固定的设备属性（1 倍缩放下的物理像素比），页面缩放不计入；Chrome 把它定义为"当前每个 CSS 像素占多少物理像素"，随缩放实时变化。跨浏览器做缩放相关判断时要特性检测。
