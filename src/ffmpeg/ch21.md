# 第21章：直播录制与回放

> "这个直播太精彩了，能不能回放？"——每个主播都听过这句话。这一章，我们用 FFmpeg 把直播流变成可以随时回看的录像。

## 21.1 录制直播流到本地文件

直播录制看似简单——"把流存下来不就行了"——但实际做的时候你会发现很多坑。直播流不像普通文件那样"就在那里"，它是实时的、不连续的、可能中断的。一个好的录制方案需要考虑：时间戳连续性、文件完整性（断电/断网时不损坏）、分段策略（不能录成一个几百 GB 的巨型文件）、以及录制后的可用性。

在开始之前，先搞清楚"为什么需要录制"。直播录制的典型场景：

1. **直播回放**：用户错过了直播时间，想随时回看。这是最常见的需求
2. **内容存档**：合规要求保留直播记录，方便审计和回溯
3. **二次创作**：把直播内容剪辑成短视频，在不同平台分发
4. **质量分析**：回顾直播中的技术问题（卡顿、花屏），定位根因
5. **AI 训练**：用直播数据训练内容审核、质量检测等 AI 模型

最简单的录制命令：

```bash
# 录制 RTMP 流
ffmpeg -i rtmp://server/live/stream -c copy recording.flv

# 录制 HLS 流
ffmpeg -i http://server/hls/stream.m3u8 -c copy recording.ts

# 录制 RTSP 流（监控摄像头）
ffmpeg -rtsp_transport tcp -i rtsp://camera/stream -c copy recording.mp4

# 录制并指定格式
ffmpeg -i rtmp://server/live/stream -c copy -f mp4 recording.mp4
```

> **注意**：直播流录制时不要加 `-re`，因为直播本身就是实时的。加了 `-re` 反而会让录制跟不上实时流。

## 21.2 分段录制：按时长自动切片

一场直播可能持续几个小时，录成一个大文件既不灵活也不安全。分段录制是更好的选择：

```bash
# 每 60 秒切一个文件
ffmpeg -i rtmp://server/live/stream \
  -c copy \
  -f segment \
  -segment_time 60 \
  -reset_timestamps 1 \
  -strftime 1 \
  "recording_%Y%m%d_%H%M%S.mp4"

# 每 5 分钟切一个文件，保留最近 10 个（自动删除旧的）
ffmpeg -i rtmp://server/live/stream \
  -c copy \
  -f segment \
  -segment_time 300 \
  -segment_wrap 10 \
  -reset_timestamps 1 \
  "recording_%03d.mp4"
```

参数解释：

- `-f segment`：使用 segment muxer（分段输出）
- `-segment_time 60`：每 60 秒切一段
- `-reset_timestamps 1`：每段文件的时间戳从 0 开始
- `-strftime 1`：在文件名中使用时间格式
- `-segment_wrap 10`：只保留最近的 10 个文件（循环覆盖）

**按关键帧精确切片：**

```bash
# 确保在关键帧处切片（避免花屏）
ffmpeg -i rtmp://server/live/stream \
  -c copy \
  -f segment \
  -segment_time 60 \
  -segment_format mp4 \
  -force_key_frames "expr:gte(t,n_forced*60)" \
  -reset_timestamps 1 \
  "segment_%03d.mp4"
```

## 21.3 时间戳问题与修复

录制直播流时，**时间戳问题**是最常见的坑。

**问题现象：**

- 播放录制文件时，视频卡顿或加速播放
- 音画不同步
- 播放器显示错误的时长

**原因：**
直播流的时间戳可能不连续（推流端重启、网络中断），或者从非零时间开始。

**修复方案：**

```bash
# 方案一：复制原始时间戳
ffmpeg -i rtmp://server/live/stream \
  -c copy \
  -copyts \
  recording.mp4

# 方案二：从 0 开始时间戳（推荐）
ffmpeg -i rtmp://server/live/stream \
  -c copy \
  -copyts \
  -start_at_zero \
  recording.mp4

# 方案三：重新生成时间戳
ffmpeg -i rtmp://server/live/stream \
  -c copy \
  -bsf:a aac_adtstoasc \
  -movflags +faststart \
  recording.mp4
```

参数解释：

- `-copyts`：保留输入的时间戳，不重新计算
- `-start_at_zero`：将时间戳偏移到从 0 开始（配合 `-copyts` 使用）
- `-bsf:a aac_adtstoasc`：修复 AAC 音频的封装格式（从 ADTS 转为 ASC）
- `-movflags +faststart`：将 MP4 的元数据移到文件头部（支持边下边播）

## 21.4 录制 HLS 流

```bash
# 直接录制 HLS 流（最简单）
ffmpeg -i http://server/hls/stream.m3u8 \
  -c copy \
  recording.mp4

# 录制并修复时间戳
ffmpeg -i http://server/hls/stream.m3u8 \
  -c copy \
  -copyts -start_at_zero \
  -movflags +faststart \
  recording.mp4

# 录制 HLS 并选择特定的码率（如果有多个）
ffmpeg -i http://server/hls/master.m3u8 \
  -map 0:v:0 -map 0:a:0 \
  -c copy \
  recording.mp4
```

## 21.5 录制 RTMP 流

```bash
# 基础录制
ffmpeg -i rtmp://server/live/stream -c copy recording.flv

# 录制为 MP4（更好的兼容性）
ffmpeg -i rtmp://server/live/stream \
  -c copy \
  -bsf:a aac_adtstoasc \
  -movflags +faststart \
  recording.mp4

# 带超时保护的录制（防止无限等待）
ffmpeg -i rtmp://server/live/stream \
  -c copy \
  -timeout 10000000 \
  -rw_timeout 10000000 \
  recording.mp4
```

## 21.6 录制过程中的转码

有时候你不想直接 copy 原始流，而是想在录制时转码（比如降低码率节省存储空间）：

```bash
# 录制时转码：降低码率，改变分辨率
ffmpeg -i rtmp://server/live/stream \
  -c:v libx264 -preset veryfast -b:v 1500k -s 1280x720 \
  -c:a aac -b:a 96k \
  recording_720p.mp4

# 录制时添加水印（时间戳水印）
ffmpeg -i rtmp://server/live/stream \
  -vf "drawtext=text='%{localtime}':x=10:y=10:fontcolor=white:fontsize=24:box=1:boxcolor=black@0.5" \
  -c:v libx264 -preset veryfast -b:v 2000k \
  -c:a copy \
  recording_watermark.mp4

# 同时录制原始流和转码流
ffmpeg -i rtmp://server/live/stream \
  -c copy -f mp4 recording_original.mp4 \
  -c:v libx264 -preset veryfast -b:v 1000k -s 854x480 \
    -c:a aac -b:a 64k \
    -f mp4 recording_480p.mp4
```

## 21.7 直播回放的实现思路

直播回放的本质：**录制直播流 → 后处理 → 上传到点播系统**。

```
直播流 → FFmpeg 录制 → MP4 文件 → 转码 → HLS/DASH → CDN → 用户回放
```

一个简化的回放工作流：

```bash
#!/bin/bash
# 直播回放自动化脚本

STREAM_URL="rtmp://server/live/stream"
RECORDING_DIR="/data/recordings"
VOD_DIR="/var/www/vod"
STREAM_NAME="live_event_$(date +%Y%m%d_%H%M%S)"

echo "开始录制直播流..."

# 1. 录制直播
ffmpeg -i "$STREAM_URL" \
  -c copy \
  -copyts -start_at_zero \
  -movflags +faststart \
  "$RECORDING_DIR/${STREAM_NAME}.mp4"

echo "直播结束，开始后处理..."

# 2. 后处理：转码为多码率 HLS
ffmpeg -i "$RECORDING_DIR/${STREAM_NAME}.mp4" \
  -c:v libx264 -c:a aac \
  -map 0:v -map 0:v -map 0:a \
  -b:v:0 2000k -s:v:0 1280x720 \
  -b:v:1 800k -s:v:1 854x480 \
  -f hls \
  -hls_time 10 \
  -master_pl_name "${STREAM_NAME}_master.m3u8" \
  -var_stream_map "v:0,a:0 v:1,a:0" \
  "$VOD_DIR/${STREAM_NAME}/vs%v/index.m3u8"

# 3. 清理原始录制文件（可选，节省空间）
rm "$RECORDING_DIR/${STREAM_NAME}.mp4"

echo "回放准备完成: http://server/vod/${STREAM_NAME}_master.m3u8"
```

## 21.8 录制文件的后处理

录制完成后的文件可能需要修复和优化：

```bash
# 修复 MP4 的 moov atom（推流中断时文件可能损坏）
# 使用 untrunc 工具修复
untrunc good_file.mp4 broken_file.mp4

# FFmpeg 重新封装（修复容器格式问题）
ffmpeg -i broken_recording.mp4 \
  -c copy \
  -movflags +faststart \
  fixed_recording.mp4

# 去除开头的空白（直播还没开始时录到的数据）
ffmpeg -i recording.mp4 \
  -ss 5 \
  -c copy \
  trimmed_recording.mp4

# 合并多个分段录制文件
# 先创建文件列表
cat > filelist.txt << EOF
file 'segment_000.mp4'
file 'segment_001.mp4'
file 'segment_002.mp4'
EOF

# 合并
ffmpeg -f concat -safe 0 -i filelist.txt -c copy merged_recording.mp4

# 提取缩略图（用于回放页面展示）
ffmpeg -i recording.mp4 \
  -vf "select=eq(pict_type\,I)" \
  -vsync vfr \
  -q:v 2 \
  thumbnails/thumb_%03d.jpg
```

## 21.9 自动录制脚本

一个更完善的自动录制脚本，支持检测流状态和自动启停：

```bash
#!/bin/bash
# auto_record.sh - 智能直播录制脚本

STREAM_URL="rtmp://server/live/stream"
OUTPUT_DIR="/data/recordings"
MAX_FILE_SIZE="2G"
LOG_FILE="/var/log/recorder.log"

mkdir -p "$OUTPUT_DIR"

log() {
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] $1" | tee -a "$LOG_FILE"
}

check_stream() {
    # 使用 ffprobe 检测流是否可用
    timeout 5 ffprobe -v quiet "$STREAM_URL" 2>/dev/null
    return $?
}

record() {
    local filename="${OUTPUT_DIR}/rec_$(date +%Y%m%d_%H%M%S)"

    log "开始录制: $filename.mp4"

    ffmpeg -y \
        -i "$STREAM_URL" \
        -c copy \
        -copyts -start_at_zero \
        -movflags +faststart \
        -fs "$MAX_FILE_SIZE" \
        -timeout 5000000 \
        "$filename.mp4" 2>> "$LOG_FILE"

    local exit_code=$?

    if [ $exit_code -eq 0 ]; then
        log "录制正常结束: $filename.mp4"
    else
        log "录制中断 (exit: $exit_code): $filename.mp4"
    fi

    # 后处理：添加 faststart
    if [ -f "$filename.mp4" ]; then
        ffmpeg -y -i "$filename.mp4" \
            -c copy -movflags +faststart \
            "${filename}_final.mp4" 2>/dev/null
        mv "${filename}_final.mp4" "$filename.mp4"
        log "后处理完成: $filename.mp4"
    fi
}

# 主循环：持续监控流状态
while true; do
    if check_stream; then
        record
    else
        log "流不可用，等待中..."
    fi
    sleep 10
done
```

## 21.10 云端录制方案

如果你的直播系统部署在云上，录制方案需要做相应调整。云端录制的核心挑战是：存储成本、网络延迟、以及跨区域同步。

**方案一：服务器本地录制 + 定期上传**

```bash
#!/bin/bash
# cloud_record.sh - 云端录制脚本

RECORDING_DIR="/data/recordings"
S3_BUCKET="s3://my-recordings"
UPLOAD_DELAY=300  # 每 5 分钟上传一次

# 录制
ffmpeg -i rtmp://server/live/stream \
  -c copy -f segment -segment_time 300 \
  -reset_timestamps 1 \
  "$RECORDING_DIR/rec_%Y%m%d_%H%M%S.mp4" &

# 定期上传已完成的分段
while true; do
    sleep $UPLOAD_DELAY
    for file in "$RECORDING_DIR"/rec_*.mp4; do
        [ -f "$file" ] || continue
        # 只上传 5 分钟前完成的文件（避免上传正在写入的文件）
        if [ $(($(date +%s) - $(stat -c %Y "$file"))) -gt 300 ]; then
            aws s3 cp "$file" "$S3_BUCKET/" && rm "$file"
        fi
    done
done
```

**方案二：直接流式录制到对象存储**

某些云平台支持直接从 RTMP 流录制到对象存储，无需经过本地磁盘：

```bash
# 使用 FFmpeg 输出到管道，再通过 SDK 上传
ffmpeg -i rtmp://server/live/stream \
  -c copy -f mp4 -movflags frag_keyframe+empty_moov \
  pipe:1 | python3 upload_stream.py --bucket my-recordings --key live/stream.mp4
```

**多区域部署架构：**

```
北京推流端 ──RTMP──→ 北京 SRS 服务器 ──→ 录制到北京 OSS
                          │
                          └──转码──→ HLS → CDN（全国分发）

海外推流端 ──SRT──→ 新加坡 SRS 服务器 ──→ 录制到海外 S3
                          │
                          └──转码──→ HLS → CloudFront（海外分发）
```

**录制存储成本估算：**

| 码率 | 每小时文件大小 | 每月（24/7录制） | 阿里云 OSS 月费 |
| ------ | ------------- | ----------------- | ---------------- |
| 2 Mbps | 约 900 MB | 约 650 GB | 约 78 元 |
| 4 Mbps | 约 1.8 GB | 约 1.3 TB | 约 156 元 |
| 8 Mbps | 约 3.6 GB | 约 2.6 TB | 约 312 元 |

如果你的存储成本太高，可以考虑以下策略：

- **定时录制**：只在直播时段录制，而非 24 小时
- **录制后压缩**：用 FFmpeg 将录制的文件压缩后再存储（H.265 可省 40-50% 空间）
- **生命周期管理**：30 天前的录制自动转为低频存储或归档存储（成本降低 60-80%）
- **智能清理**：根据观看数据，自动删除没人看的录像

## 21.11 录制监控与统计

生产环境中的录制系统需要完善的监控：

```bash
#!/bin/bash
# record_monitor.sh - 录制状态监控脚本

RECORDING_DIR="/data/recordings"
ALERT_EMAIL="admin@example.com"
MIN_FREE_SPACE_GB=10

check_disk_space() {
    local available_gb=$(df -BG "$RECORDING_DIR" | tail -1 | awk '{print $4}' | tr -d 'G')
    if [ "$available_gb" -lt "$MIN_FREE_SPACE_GB" ]; then
        echo "警告：磁盘空间不足 ${available_gb}GB！" | mail -s "录制系统告警" "$ALERT_EMAIL"
        return 1
    fi
    return 0
}

report_status() {
    local total_files=$(find "$RECORDING_DIR" -name "*.mp4" | wc -l)
    local total_size=$(du -sh "$RECORDING_DIR" | cut -f1)
    local latest_file=$(ls -t "$RECORDING_DIR"/*.mp4 2>/dev/null | head -1)
    local latest_time=""

    if [ -n "$latest_file" ]; then
        latest_time=$(stat -c '%y' "$latest_file" | cut -d. -f1)
    fi

    echo "=== 录制系统状态报告 ==="
    echo "时间: $(date '+%Y-%m-%d %H:%M:%S')"
    echo "录制文件总数: $total_files"
    echo "总占用空间: $total_size"
    echo "最新录制文件: ${latest_file:-无}"
    echo "最新录制时间: ${latest_time:-无}"
    echo "========================"
}

check_disk_space
report_status
```

**用 ffprobe 生成录制质量报告：**

```bash
#!/bin/bash
# quality_report.sh - 批量检查录制文件质量

for file in /data/recordings/*.mp4; do
    [ -f "$file" ] || continue

    name=$(basename "$file")
    echo "--- $name ---"

    # 检查视频信息
    ffprobe -v error -select_streams v:0 \
        -show_entries stream=codec_name,width,height,bit_rate,r_frame_rate \
        -show_entries format=duration,size \
        -of csv=p=0 "$file"

    # 检查是否有损坏（快速扫描）
    ffmpeg -v error -i "$file" -f null - 2>&1 | head -5

    echo ""
done
```

## 21.12 常见问题与修复

**问题 1：花屏（马赛克）**

```
原因：录制从非关键帧开始，或推流端 GOP 过大
修复：确保推流端设置合理的 GOP（2-4秒），录制时加 -avoid_negative_ts make_zero
```

```bash
ffmpeg -i rtmp://server/live/stream \
  -c copy \
  -avoid_negative_ts make_zero \
  recording.mp4
```

**问题 2：音画不同步**

```bash
# 修复方案一：重新封装时调整音频偏移
ffmpeg -i recording.mp4 \
  -itsoffset 0.5 -i recording.mp4 \
  -map 0:v -map 1:a \
  -c copy \
  fixed_sync.mp4

# 修复方案二：重新编码（终极方案）
ffmpeg -i recording.mp4 \
  -c:v libx264 -preset medium -crf 23 \
  -c:a aac -b:a 128k \
  -async 1 \
  fixed_sync.mp4
```

**问题 3：文件损坏（推流突然中断）**

```bash
# 方案一：用 FFmpeg 尝试修复
ffmpeg -i broken.mp4 -c copy -movflags +faststart fixed.mp4

# 方案二：使用 MP4Box 修复
MP4Box -add broken.mp4 -new fixed.mp4

# 方案三：使用 untrunc（需要一个好的参考文件）
untrunc reference_good.mp4 broken.mp4
```

**问题 4：录制文件过大**

```bash
# 方案一：分段录制
ffmpeg -i rtmp://server/live/stream \
  -c copy -f segment -segment_time 300 \
  -reset_timestamps 1 \
  "recording_%03d.mp4"

# 方案二：录制时压缩
ffmpeg -i rtmp://server/live/stream \
  -c:v libx264 -preset veryfast -crf 28 \
  -c:a aac -b:a 64k \
  recording_compressed.mp4
```

## 本章小结

- 录制直播流核心命令就是 `ffmpeg -i <stream_url> -c copy output.mp4`
- **分段录制**是长时间直播的最佳实践
- 时间戳问题是最常见的坑，记住 `-copyts -start_at_zero` 这个组合
- `-movflags +faststart` 让 MP4 文件支持边下边播
- 自动化录制需要脚本配合流状态检测
