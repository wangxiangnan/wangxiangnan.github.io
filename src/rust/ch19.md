# 第19章：模式匹配进阶

## 场景引入

在前面的章节中，你已经见过 `match` 的基本用法——匹配枚举变体。但 Rust 的模式匹配远不止于此。它就像一把瑞士军刀：解构结构体、匹配嵌套数据、绑定变量、添加守卫条件……如果你用过 Haskell 或 Erlang 的模式匹配，你会感到亲切；如果你只用过 Python 的 `match`（3.10+），你会惊叹 Rust 的版本更加强大。

模式匹配是 Rust 的"灵魂特性"之一——它贯穿了整个语言：`match`、`if let`、`while let`、`for`、函数参数、`let` 语句，到处都有模式的身影。可以说，**不理解模式匹配，就没有真正理解 Rust**。

在 Java 中，你需要一连串的 `if-else` + `instanceof` 检查来处理不同的类型和状态。在 Python 中，你可以用字典映射或 `match-case`。但在 Rust 中，`match` + 模式是一种统一的、编译期检查的、穷尽的分支处理方式——编译器保证你不会遗漏任何情况。

## 19.1 字面量模式与变量模式

最简单的模式就是直接匹配具体的值：

```rust
fn describe_number(x: i32) -> &'static str {
    match x {
        0 => "零",           // 字面量模式
        1 => "一",           // 字面量模式
        2 | 3 => "二或三",   // 或模式：匹配 2 或 3
        4..=10 => "四到十",  // 范围模式（包含边界）
        n => {               // 变量模式：匹配任何值，绑定到 n
            // 注意：这里的 n 是一个新变量，遮蔽了外部的
            let _ = n;       // 使用 n 避免未使用警告
            "其他数字"
        }
    }
}

fn main() {
    println!("{}", describe_number(0));  // 零
    println!("{}", describe_number(3));  // 二或三
    println!("{}", describe_number(7));  // 四到十
    println!("{}", describe_number(42)); // 其他数字
}
```

## 19.2 解构模式

模式匹配最强大的能力之一是**解构（Destructuring）**——把复合数据拆开来匹配。这个概念在很多语言中都有：JavaScript 的解构赋值 `const {x, y} = point`、Python 的元组拆包 `a, b, c = (1, 2, 3)`。但 Rust 的解构更加强大——它不仅能拆数据，还能同时匹配条件。

解构的核心原则是：**模式的形状必须与数据的形状一致**。如果数据是结构体，模式也是结构体；如果数据是嵌套的，模式也可以嵌套。

```rust
// 解构结构体
struct Point {
    x: f64,
    y: f64,
}

fn describe_point(p: Point) {
    match p {
        Point { x, y: 0.0 } => println!("在 x 轴上, x={}", x),
        Point { x: 0.0, y } => println!("在 y 轴上, y={}", y),
        Point { x, y } if x == y => println!("在对角线上: ({}, {})", x, y),
        Point { x, y } => println!("普通点: ({}, {})", x, y),
    }
}

// 解构元组
fn describe_tuple(t: (i32, i32, i32)) {
    match t {
        (0, 0, 0) => println!("原点"),
        (x, 0, 0) => println!("在 x 轴上, x={}", x),
        (x, y, z) => println!("点 ({}, {}, {})", x, y, z),
    }
}

// 解构枚举
enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(i32, i32, i32),
}

fn process_message(msg: Message) {
    match msg {
        Message::Quit => println!("退出"),
        Message::Move { x, y } => println!("移动到 ({}, {})", x, y),
        Message::Write(text) => println!("文本: {}", text),
        Message::ChangeColor(r, g, b) => println!("颜色: RGB({}, {}, {})", r, g, b),
    }
}

fn main() {
    describe_point(Point { x: 3.0, y: 0.0 }); // 在 x 轴上
    describe_point(Point { x: 5.0, y: 5.0 }); // 在对角线上
    describe_tuple((0, 0, 0));                 // 原点
    process_message(Message::Move { x: 1, y: 2 });
    process_message(Message::Write(String::from("Hello")));
}
```

## 19.3 守卫（Guard）条件

有时候模式本身不够，你需要附加条件——这就是**匹配守卫（Match Guard）**：

```rust
#[derive(Debug)]
enum Temperature {
    Celsius(f64),
    Fahrenheit(f64),
}

fn describe_temp(temp: Temperature) {
    match temp {
        Temperature::Celsius(t) if t < 0.0 => println!("{}°C：冰天雪地！", t),
        Temperature::Celsius(t) if t < 20.0 => println!("{}°C：有点凉", t),
        Temperature::Celsius(t) if t < 35.0 => println!("{}°C：舒适宜人", t),
        Temperature::Celsius(t) => println!("{}°C：热浪来袭！", t),

        // 守卫可以访问模式中绑定的变量
        Temperature::Fahrenheit(t) if (t - 32.0) * 5.0 / 9.0 < 0.0 => {
            println!("{}°F：低于冰点！", t);
        }
        Temperature::Fahrenheit(t) => {
            let celsius = (t - 32.0) * 5.0 / 9.0;
            println!("{}°F（{:.1}°C）", t, celsius);
        }
    }
}

fn main() {
    describe_temp(Temperature::Celsius(-5.0));   // 冰天雪地
    describe_temp(Temperature::Celsius(25.0));   // 舒适宜人
    describe_temp(Temperature::Fahrenheit(100.0)); // 100°F（37.8°C）
}
```

## 19.4 @ 绑定

`@` 运算符让你在匹配的同时**保留整个值的引用**——既要解构看内部，又要保留外部整体。这是 Rust 模式匹配中非常独特的一个特性，在其他语言中很难找到直接对应物。

**什么时候需要 `@`？** 当你既需要检查数据的内部结构（解构），又需要把整个数据传递给另一个函数时。比如在处理 HTTP 响应时，你可能需要检查响体的大小来决定处理策略，但同时也要保留整个响应用于日志记录。

```rust
#[derive(Debug)]
enum HttpResponse {
    Ok { body: String, content_length: usize },
    Redirect { url: String },
    NotFound,
    ServerError(i32, String),
}

fn handle_response(response: HttpResponse) {
    match response {
        // @ 绑定：匹配 Ok 变体，同时把整个值绑定到 resp
        resp @ HttpResponse::Ok { body, .. } if body.len() > 1000 => {
            println!("大响应（{}字节），需要分块传输", body.len());
            println!("完整响应: {:?}", resp);
        }
        HttpResponse::Ok { body, content_length } => {
            println!("正常响应: {} 字节", content_length);
            println!("内容: {}", body);
        }
        // @ 绑定嵌套使用
        resp @ HttpResponse::Redirect { .. } => {
            println!("重定向: {:?}", resp);
        }
        HttpResponse::NotFound => println!("404 Not Found"),
        HttpResponse::ServerError(code, msg) => {
            println!("服务器错误 {}: {}", code, msg);
        }
    }
}

fn main() {
    handle_response(HttpResponse::Ok {
        body: "Hello".to_string(),
        content_length: 5,
    });

    handle_response(HttpResponse::Ok {
        body: "x".repeat(2000),
        content_length: 2000,
    });

    handle_response(HttpResponse::Redirect {
        url: "https://example.com".to_string(),
    });
}
```

## 19.5 嵌套模式

模式可以任意嵌套，匹配深层结构。这在处理复杂的数据结构（比如 JSON、配置文件、AST）时特别有用。在 Java 中，要访问嵌套数据你可能需要写 `if (a != null && a.b != null && a.b.c != null)` 这样的防御性代码。在 Rust 中，一个模式就可以优雅地处理所有层级——如果任何一层是 `None`，模式匹配会自动跳到下一个分支。

这就是 Rust 模式匹配的魅力：**把层层嵌套的条件判断，变成扁平的、可读的模式列表**。

```rust
#[derive(Debug)]
struct User {
    name: String,
    age: u32,
    address: Option<Address>,
}

#[derive(Debug)]
struct Address {
    city: String,
    zip: String,
}

fn describe_user(user: &User) {
    match user {
        User {
            name,
            age: 0..=17,
            address: Some(Address { city, .. }),
        } => {
            println!("{} 是 {} 市的未成年人", name, city);
        }
        User {
            name,
            age,
            address: Some(Address { city, zip }),
        } => {
            println!("{} 住在 {} 市，邮编 {}，今年 {} 岁", name, city, zip, age);
        }
        User {
            name,
            age,
            address: None,
        } => {
            println!("{}（{} 岁）地址未知", name, age);
        }
    }
}

fn main() {
    let users = vec![
        User {
            name: "小明".to_string(),
            age: 15,
            address: Some(Address {
                city: "北京".to_string(),
                zip: "100000".to_string(),
            }),
        },
        User {
            name: "Alice".to_string(),
            age: 30,
            address: Some(Address {
                city: "上海".to_string(),
                zip: "200000".to_string(),
            }),
        },
        User {
            name: "Bob".to_string(),
            age: 25,
            address: None,
        },
    ];

    for user in &users {
        describe_user(user);
    }
}
```

## 19.6 ref 与 ref mut

在模式中，默认行为是**移动（move）**值。如果你只想借用而不是移动，使用 `ref` 和 `ref mut`。

这个特性在 Rust 2018 之前是必须的——每次解构结构体时，如果不加 `ref`，字段值会被移走，原结构体就"散架"了。从 Rust 2018 开始，编译器引入了**匹配遍性（Match Ergonomics）**改进——如果你对一个引用做模式匹配，编译器会自动为你添加 `ref`。这大大减少了需要手动写 `ref` 的场景。

但在某些复杂场景中，你仍然需要显式使用 `ref` 和 `ref mut`——特别是当你需要在不可变上下文中创建可变借用时：

```rust
#[derive(Debug)]
struct Person {
    name: String,
    hobbies: Vec<String>,
}

fn analyze_person(person: &Person) {
    // ref 在模式中创建引用，而不是移动数据
    match person {
        Person {
            ref name,        // &String 而不是移动 String
            ref hobbies,     // &Vec<String>
        } => {
            println!("{} 有 {} 个爱好", name, hobbies.len());
            if hobbies.len() > 3 {
                println!("    爱好达人！");
            }
        }
    }
}

fn modify_person(person: &mut Person) {
    match person {
        Person {
            ref name,
            ref mut hobbies, // &mut Vec<String>
        } => {
            println!("正在为 {} 添加新爱好...", name);
            hobbies.push("Rust 编程".to_string());
        }
    }
}

fn main() {
    let mut person = Person {
        name: "张三".to_string(),
        hobbies: vec!["阅读".to_string(), "游泳".to_string()],
    };

    analyze_person(&person);
    modify_person(&mut person);
    analyze_person(&person);
}
```

**注意**：在大多数场景中，Rust 的**匹配遍性（Match Ergonomics）**会自动处理 `ref`/`ref mut`。只有当你需要显式控制时才需要手动写。

## 19.7 表达式中的模式

模式不仅出现在 `match` 中，它无处不在。事实上，Rust 中几乎所有"赋值"的地方都在使用模式——你只是没意识到而已。当你写 `let x = 5;` 时，`x` 就是一个最简单的变量模式。当你写 `for (key, value) in map.iter()` 时，`(key, value)` 就是一个元组解构模式。

让我们逐一看看模式在各种表达式中的用法：

```rust
fn main() {
    // 1. if let：只关心一个分支的简洁写法
    let config_value: Option<i32> = Some(42);
    if let Some(value) = config_value {
        println!("配置值: {}", value);
    }
    // 等价于 match config_value { Some(v) => println!(...), _ => {} }

    // 2. while let：持续匹配直到失败
    let mut stack = vec![1, 2, 3];
    print!("出栈顺序: ");
    while let Some(top) = stack.pop() {
        print!("{} ", top);
    }
    println!();
    // 输出: 出栈顺序: 3 2 1

    // 3. for 循环中的模式
    let pairs = vec![(1, "one"), (2, "two"), (3, "three")];
    for (num, name) in &pairs {
        println!("{} = {}", num, name);
    }

    // 4. let 语句中的模式
    let (x, y, z) = (1, 2, 3);
    println!("x={}, y={}, z={}", x, y, z);

    let Point { x: px, y: py } = Point { x: 10.0, y: 20.0 };
    println!("px={}, py={}", px, py);

    // 5. 函数参数中的模式
    fn print_pair(&(a, b): &(i32, i32)) {
        println!("({}, {})", a, b);
    }
    let pair = (5, 10);
    print_pair(&pair);

    // 6. let-else（Rust 1.65+）：不匹配时执行 else 分支（必须发散）
    let value: Option<&str> = Some("hello");
    let Some(text) = value else {
        println!("没有值");
        return;
    };
    println!("获取到: {}", text);
}
```

## 19.8 通配符与忽略模式

```rust
fn main() {
    let tuple = (1, "hello", 3.14, true);

    match tuple {
        // _ 忽略不关心的部分
        (1, msg, _, _) => println!("第一个是1，消息: {}", msg),
        _ => println!("其他情况"),
    }

    // let 中也可以用 _ 忽略
    let (_, second, _, _) = tuple;
    println!("第二个: {}", second);

    // .. 忽略剩余的字段
    struct BigStruct {
        a: i32,
        b: i32,
        c: i32,
        d: i32,
        e: i32,
    }

    let big = BigStruct { a: 1, b: 2, c: 3, d: 4, e: 5 };
    let BigStruct { a, b, .. } = big; // 只关心 a 和 b
    println!("a={}, b={}", a, b);
}
```

## 19.9 实战：用复杂模式匹配解析命令行参数

让我们用一个综合示例来展示模式匹配的全部威力——实现一个命令行参数解析器。这个例子展示了模式匹配如何替代大量的 `if-else` 链，让代码既简洁又易读。

**设计思路**：我们把命令行参数解析分成两步：

1. 将字符串参数解析为 `Command` 枚举（结构化数据）
2. 用模式匹配执行对应的命令

这种"先解析为枚举，再匹配执行"的模式在实际项目中非常常见——它和 Rust 的 `clap` 命令行库的设计思路如出一辙。

```rust
use std::env;

#[derive(Debug)]
enum Command {
    Help,
    Version,
    Add { file: String, force: bool },
    Remove { file: String, recursive: bool },
    List { pattern: Option<String> },
    Unknown(String),
}

fn parse_args(args: Vec<String>) -> Command {
    // 跳过第一个参数（程序名）
    let args: Vec<&str> = args.iter().skip(1).map(|s| s.as_str()).collect();

    match args.as_slice() {
        // 无参数
        [] => Command::Help,

        // 简单命令
        ["--help"] | ["-h"] => Command::Help,
        ["--version"] | ["-v"] => Command::Version,

        // add 命令：解析子命令和标志
        ["add", file, ..] => {
            let force = args.contains(&"--force") || args.contains(&"-f");
            Command::Add {
                file: file.to_string(),
                force,
            }
        }

        // remove 命令
        ["remove", file, ..] | ["rm", file, ..] => {
            let recursive = args.contains(&"--recursive") || args.contains(&"-r");
            Command::Remove {
                file: file.to_string(),
                recursive,
            }
        }

        // list 命令（可选参数）
        ["list"] | ["ls"] => Command::List { pattern: None },
        ["list", pattern] | ["ls", pattern] => Command::List {
            pattern: Some(pattern.to_string()),
        },

        // 未知命令
        [cmd, ..] => Command::Unknown(cmd.to_string()),
    }
}

fn execute_command(cmd: Command) {
    match cmd {
        Command::Help => {
            println!("用法: myapp <command> [options]");
            println!("命令:");
            println!("  add <file>     添加文件（--force 强制覆盖）");
            println!("  remove <file>  删除文件（--recursive 递归删除）");
            println!("  list [pattern] 列出文件");
        }
        Command::Version => println!("myapp v0.1.0"),
        Command::Add { file, force } => {
            if force {
                println!("强制添加: {}", file);
            } else {
                println!("添加: {}", file);
            }
        }
        Command::Remove { file, recursive } => {
            if recursive {
                println!("递归删除: {}", file);
            } else {
                println!("删除: {}", file);
            }
        }
        Command::List { pattern: Some(p) } => println!("列出匹配 '{}' 的文件", p),
        Command::List { pattern: None } => println!("列出所有文件"),
        Command::Unknown(cmd) => println!("未知命令: {}。使用 --help 查看帮助。", cmd),
    }
}

fn main() {
    let args: Vec<String> = env::args().collect();

    // 为了演示，如果没有命令行参数，使用默认值
    let args = if args.len() <= 1 {
        vec![
            "myapp".to_string(),
            "add".to_string(),
            "test.rs".to_string(),
            "--force".to_string(),
        ]
    } else {
        args
    };

    let command = parse_args(args);
    println!("解析结果: {:?}", command);
    execute_command(command);
}
```

## 常见陷阱

1. **不可达模式**：Rust 要求 `match` 是穷尽的（exhaustive），同时会警告你不可达的分支。把具体模式放在 `_` 前面，否则后面的分支永远不会被执行。编译器会给你 "unreachable pattern" 警告。

2. **变量遮蔽**：在模式中使用变量名会创建**新变量**，而不是与已有变量比较。这是新手最常犯的错误之一——以为 `Some(x)` 中的 `x` 是外部的变量 `x`，实际上它是一个全新的绑定，会匹配任何值。要比较已有变量的值，使用守卫条件 `if v == x`。

3. **`_` 和 `_name` 的区别**：`_` 立即丢弃值（不绑定），`_name` 绑定值但抑制未使用警告。这个区别在涉及 `Drop` trait 时很重要——`_` 会立即触发 `drop()`，而 `_name` 会在作用域结束时才 `drop()`。

```rust
let x = 5;
let value = Some(5);
match value {
    Some(x) => println!("匹配到: {}", x),  // 这里的 x 是新变量，遮蔽了外部的 x
    None => println!("无"),
}

// 如果要比较外部变量的值：
match value {
    Some(v) if v == x => println!("等于外部的 x!"),  // 用守卫比较
    Some(v) => println!("其他值: {}", v),
    None => println!("无"),
}

// _ 和 _name 的 Drop 区别：
struct Droppy(String);
impl Drop for Droppy {
    fn drop(&mut self) { println!("drop: {}", self.0); }
}

fn drop_test() {
    let _a = Droppy("立即丢弃".to_string()); // 立刻 drop！
    let _b = Droppy("稍后丢弃".to_string()); // 函数结束时 drop
    println!("函数体");
    // 输出顺序: drop: 立即丢弃 → 函数体 → drop: 稍后丢弃
}
```

1. **穷尽性检查遗漏**：Rust 编译器会强制检查 `match` 是否覆盖了所有可能的情况。如果你新增了一个枚举变体但忘了更新所有 `match`，编译器会报错——这是 Rust 模式匹配最大的优势之一。

## 小结

| 模式类型 | 示例 | 说明 |
| ---------- | ------ | ------ |
| 字面量 | `42`, `"hello"` | 直接匹配值 |
| 范围 | `1..=5` | 匹配范围内的值 |
| 变量 | `x` | 绑定到新变量 |
| 通配符 | `_` | 忽略，不绑定 |
| 解构 | `Point { x, y }` | 拆分复合类型 |
| 守卫 | `if x > 0` | 附加条件 |
| @ 绑定 | `val @ 1..=5` | 匹配同时保留整体引用 |
| 或模式 | `A | B` | 匹配多个模式之一 |
| 嵌套 | `Some(Point { x: 0, .. })` | 多层嵌套匹配 |
