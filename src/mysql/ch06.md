# 第6章 多表连接（JOIN）

> 如果说单表查询是在一本字典里找东西，那JOIN就是"多表相亲大会"——把不同表中有关联的数据撮合到一起，组成你想要的完整信息。

## 6.1 关系模型

关系型数据库的精髓在于"关系"。数据分散在不同的表中，通过外键或逻辑关联连接在一起。这样做的好处是**减少冗余、保证一致性**。

举个例子：一个电商系统至少有这些表：

- `users` 表：用户信息
- `orders` 表：订单信息（包含user_id）
- `order_items` 表：订单明细（包含order_id和product_id）
- `products` 表：商品信息

要查询"用户alice买了什么商品"，就需要把这四张表连起来。

## 6.2 准备示例数据

```sql
-- 创建分类表
CREATE TABLE categories (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50) NOT NULL

INSERT INTO categories (name) VALUES

-- 创建客户表
CREATE TABLE customers (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,

  email VARCHAR(100) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='客户表';

INSERT INTO customers (name, email) VALUES
('张三', 'zhangsan@test.com'),
('李四', 'lisi@test.com'),
('王五', 'wangwu@test.com'),
('赵六', 'zhaoliu@test.com');

-- 创建订单表
CREATE TABLE orders (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  customer_id INT UNSIGNED NOT NULL,
  order_date DATE NOT NULL,
  total_amount DECIMAL(10,2) NOT NULL,
  INDEX idx_customer (customer_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单表';

INSERT INTO orders (customer_id, order_date, total_amount) VALUES
(1, '2024-01-15', 7999.00),
(1, '2024-02-20', 1799.00),
(2, '2024-01-18', 8999.00),

```

## 6.3 INNER JOIN：内连接

内连接只返回**两个表中都有匹配**的行。这是最常用的JOIN类型。

```sql
-- 查询每个客户的订单信息
SELECT
  c.name AS customer_name,
  c.email,
  o.id AS order_id,
  o.order_date,
  o.total_amount
FROM customers c
INNER JOIN orders o ON c.id = o.customer_id
ORDER BY c.name, o.order_date;

-- 结果：
-- 张三 | zhangsan@test.com | 1 | 2024-01-15 | 7999.00
-- 张三 | zhangsan@test.com | 2 | 2024-02-20 | 1799.00
-- 李四 | lisi@test.com     | 3 | 2024-01-18 | 8999.00
-- 王五 | wangwu@test.com   | 4 | 2024-03-01 | 12999.00
-- 注意：赵六不在结果中，因为他没有订单
```

> **Tip：** `INNER JOIN`可以简写为`JOIN`，但为了代码可读性，建议始终写完整的`INNER JOIN`。

## 6.4 LEFT JOIN / RIGHT JOIN：外连接

### LEFT JOIN

左连接返回**左表的所有行**，右表没有匹配的行用NULL填充：

```sql
-- 查询所有客户及其订单（包括没有订单的客户）
SELECT
  c.name AS customer_name,
  o.id AS order_id,
  o.order_date,
  COALESCE(o.total_amount, 0) AS total_amount
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
ORDER BY c.name;

-- 结果：
-- 张三 | 1    | 2024-01-15 | 7999.00
-- 张三 | 2    | 2024-02-20 | 1799.00
-- 李四 | 3    | 2024-01-18 | 8999.00
-- 王五 | 4    | 2024-03-01 | 12999.00
-- 赵六 | NULL | NULL       | 0.00      <-- 左表有，右表没有

-- 找出没有订单的客户（经典用法）
SELECT c.name, c.email
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
WHERE o.id IS NULL;
-- 结果：赵六
```

### RIGHT JOIN

右连接和左连接相反，返回**右表的所有行**。实际开发中，RIGHT JOIN用得较少，通常可以用LEFT JOIN+调换表顺序替代：

```sql
-- 这两种写法等价：
SELECT * FROM customers c RIGHT JOIN orders o ON c.id = o.customer_id;
SELECT * FROM orders o LEFT JOIN customers c ON c.id = o.customer_id;
```

## 6.5 CROSS JOIN：交叉连接

交叉连接返回两个表的**笛卡尔积**——左表每一行和右表每一行组合。结果行数 = 左表行数 x 右表行数。

```sql
-- 交叉连接（慎用！表大了会爆炸）
SELECT
  c.name AS customer,
  cat.name AS category
FROM customers c
CROSS JOIN categories cat
ORDER BY c.name, cat.name;

-- 结果有 4 * 5 = 20 行
-- 张三-手机, 张三-电脑, 张三-耳机, 张三-平板, 张三-手表
-- 李四-手机, 李四-电脑, ...
```

> **Warning：** 交叉连接在表大的时候会产生天文数字的结果。两个1000行的表交叉连接就是100万行。除非你确实需要笛卡尔积（如生成测试数据），否则不要用。

## 6.6 SELF JOIN：自连接

自连接就是表自己和自己连接。典型场景是"员工-经理"关系、分类的父子级关系。

```sql
-- 创建员工表（含经理ID）
CREATE TABLE employees (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  manager_id INT UNSIGNED DEFAULT NULL,
  INDEX idx_manager (manager_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='员工表';

INSERT INTO employees (name, manager_id) VALUES
('CEO老王', NULL),
('技术VP小李', 1),
('产品VP小张', 1),
('前端组长小刘', 2),
('后端组长小陈', 2),
('产品经理小赵', 3);

-- 查询每个员工及其上级
SELECT
  e.name AS employee,
  m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id
ORDER BY e.id;

-- 结果：
-- CEO老王     | NULL
-- 技术VP小李  | CEO老王
-- 产品VP小张  | CEO老王
-- 前端组长小刘| 技术VP小李
-- 后端组长小陈| 技术VP小李
-- 产品经理小赵| 产品VP小张
```

## 6.7 多表JOIN链式查询

实际开发中，经常需要连接三个或更多表：

```sql
-- 创建订单明细表
CREATE TABLE order_items (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  order_id INT UNSIGNED NOT NULL,
  product_id INT UNSIGNED NOT NULL,
  quantity INT UNSIGNED NOT NULL DEFAULT 1,
  unit_price DECIMAL(10,2) NOT NULL,
  INDEX idx_order (order_id),
  INDEX idx_product (product_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单明细表';

-- 多表JOIN：查询订单的完整信息
SELECT
  c.name AS customer,
  o.id AS order_id,
  o.order_date,
  p.name AS product_name,
  oi.quantity,
  oi.unit_price,
  (oi.quantity * oi.unit_price) AS line_total
FROM customers c
INNER JOIN orders o ON c.id = o.customer_id
INNER JOIN order_items oi ON o.id = oi.order_id
INNER JOIN products p ON oi.product_id = p.id
ORDER BY o.order_date DESC, o.id;
```

```sql
-- 统计每个客户在每个分类上的消费
SELECT
  c.name AS customer,
  cat.name AS category,
  SUM(oi.quantity * oi.unit_price) AS total_spent
FROM customers c
INNER JOIN orders o ON c.id = o.customer_id
INNER JOIN order_items oi ON o.id = oi.order_id
INNER JOIN products p ON oi.product_id = p.id
INNER JOIN categories cat ON p.category_id = cat.id
GROUP BY c.id, c.name, cat.id, cat.name
ORDER BY c.name, total_spent DESC;
```

## 6.8 JOIN ON vs WHERE

`ON` 和 `WHERE` 在不同类型的JOIN中表现不同：

```sql
-- INNER JOIN中，ON和WHERE效果一样
SELECT * FROM customers c
INNER JOIN orders o ON c.id = o.customer_id
WHERE o.total_amount > 5000;

-- 等价写法（但不推荐，可读性差）
SELECT * FROM customers c
INNER JOIN orders o ON c.id = o.customer_id AND o.total_amount > 5000;
```

```sql
-- LEFT JOIN中，ON和WHERE效果完全不同！
-- ON中的条件：影响匹配，不匹配的行仍然保留（右表填NULL）
-- WHERE中的条件：在JOIN完成后过滤，会把不匹配的行直接删掉

-- 正确：找出所有客户，但只关联2024年的订单
SELECT c.name, o.id, o.order_date
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id AND o.order_date >= '2024-01-01';

-- 错误：WHERE会把没有2024年订单的客户过滤掉，LEFT JOIN退化为INNER JOIN
SELECT c.name, o.id, o.order_date
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
WHERE o.order_date >= '2024-01-01';
-- 赵六不在结果中了！因为WHERE o.order_date >= ... 对NULL不成立
```

> **Warning：** 这是很多初学者（甚至老手）会犯的错。**LEFT JOIN + WHERE 对右表条件的过滤 = INNER JOIN**。记住：对右表的筛选条件要放在ON里，对左表的过滤条件放在WHERE里。

## 6.9 USING 关键字

当两张表的连接列同名时，可以用`USING`简化语法：

```sql
-- 标准写法
SELECT p.name, c.name AS category
FROM products p
INNER JOIN categories c ON p.category_id = c.id;

-- 如果连接列同名，可以用USING
-- 例如两个表都有order_id列
SELECT *
FROM orders
INNER JOIN order_items USING (order_id);
-- 等价于：ON orders.order_id = order_items.order_id
-- 好处：结果集中order_id只出现一次（不会重复）
```

## 6.10 JOIN 性能简介

了解JOIN的底层执行方式，有助于你写出更高效的查询：

### Nested Loop Join（嵌套循环连接）

最基础的方式。外层表逐行扫描，内层表根据连接条件查找匹配行。当有索引时效率不错，没有索引就变成笛卡尔积扫描。

```sql
-- 确保连接列有索引！
EXPLAIN SELECT *
FROM orders o
INNER JOIN order_items oi ON o.id = oi.order_id;
-- 检查type列：ref 或 eq_ref 表示使用了索引
```

### Hash Join（哈希连接）

MySQL 8.0.18引入。对较小的表建立哈希表，然后扫描较大的表进行匹配。适合没有索引的大表连接。

### Sort-Merge Join（排序归并连接）

先对两个表按连接键排序，然后归并。在特定场景下效率很高。

```sql
-- 用EXPLAIN查看MySQL选择了哪种执行计划
EXPLAIN FORMAT=JSON
SELECT *
FROM customers c
INNER JOIN orders o ON c.id = o.customer_id
WHERE c.name = '张三';
```

### 性能优化建议

```sql
-- 1. 确保连接列有索引
ALTER TABLE orders ADD INDEX idx_customer_id (customer_id);

-- 2. 小表驱动大表（MySQL优化器通常会自动选择）
-- 以下写法让优化器先过滤小表
SELECT *
FROM customers c
INNER JOIN orders o ON c.id = o.customer_id
WHERE c.status = 'active'       -- 先过滤customers
  AND o.order_date >= '2024-01-01';  -- 再过滤orders

-- 3. 避免在连接列上使用函数
-- 错误：索引失效
SELECT * FROM orders WHERE YEAR(order_date) = 2024;

-- 正确：索引可用
SELECT * FROM orders
WHERE order_date >= '2024-01-01' AND order_date < '2025-01-01';

-- 4. 减少JOIN的表数量
-- 如果JOIN太多表（>5），考虑拆分查询或用子查询/临时表
```

> **Tip：** 一般建议单次查询JOIN不超过5张表。如果业务逻辑确实需要更多表的关联，考虑用子查询或分步查询来简化。

## 6.11 综合实战：一个完整的JOIN查询案例

```sql
-- 需求：生成月度销售报表
-- 显示：月份、分类名称、销售数量、销售总额、客户数量

SELECT
  DATE_FORMAT(o.order_date, '%Y-%m') AS month,
  cat.name AS category,
  SUM(oi.quantity) AS total_qty,
  SUM(oi.quantity * oi.unit_price) AS total_revenue,
  COUNT(DISTINCT o.customer_id) AS unique_customers
FROM orders o
INNER JOIN order_items oi ON o.id = oi.order_id
INNER JOIN products p ON oi.product_id = p.id
INNER JOIN categories cat ON p.category_id = cat.id
WHERE o.order_date >= '2024-01-01'
GROUP BY DATE_FORMAT(o.order_date, '%Y-%m'), cat.id, cat.name
ORDER BY month DESC, total_revenue DESC;
```

```sql
-- 需求：找出"购买了所有分类商品"的客户（关系除法）
SELECT c.name, c.email
FROM customers c
WHERE NOT EXISTS (
  SELECT cat.id
  FROM categories cat
  WHERE NOT EXISTS (
    SELECT 1
    FROM orders o
    INNER JOIN order_items oi ON o.id = oi.order_id
    INNER JOIN products p ON oi.product_id = p.id
    WHERE o.customer_id = c.id
      AND p.category_id = cat.id
  )
);
```

## 小结

JOIN是SQL中最强大也最复杂的功能之一。本章我们学习了五种JOIN类型（INNER、LEFT、RIGHT、CROSS、SELF）、多表链式连接、ON与WHERE的区别、以及基本的性能优化。记住几条核心原则：

1. 连接列要有索引
2. LEFT JOIN中右表的过滤条件放ON里
3. 控制JOIN表数量，不要超过5张
4. 用EXPLAIN检查执行计划
