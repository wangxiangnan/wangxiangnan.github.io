# 第3章：比特如何上路——物理层与数据链路层

## 物理层：比特变成信号

当你的程序发送一段数据时，它经历了从软件到硬件的华丽变身。在 TCP/IP 栈的最底层，数据最终以**物理信号**的形式在介质上传播。这就是物理层（Physical Layer）的工作。

物理层的核心任务是：**把比特（0 和 1）变成物理信号，并通过物理介质传输到另一端。**

不同的介质使用不同的信号形式：

- **铜缆（双绞线、同轴电缆）**：用**电平**表示比特。比如在高电平（+5V）表示 1，低电平（0V）表示 0。
- **光纤**：用**光脉冲**表示比特。有光为 1，无光为 0。光纤的优势是极高的带宽和极低的衰减，单模光纤可以传输上百公里而不需要中继。
- **无线（Wi-Fi、4G/5G）**：用**电磁波**的振幅、频率或相位来编码比特。Wi-Fi 使用的 2.4GHz 和 5GHz 频段，本质上是无线电波。

物理层不关心比特代表什么——它不知道也不在乎你传输的是一张猫的图片还是一份财务报表。它只管"把 0 变成信号 A，把 1 变成信号 B，发出去"。

## 编码方案

直接用高电平表示 1、低电平表示 0 听起来很合理，但实际工程中这种"天真编码"（NRZ，Non-Return-to-Zero）有几个严重问题：

**问题一：时钟同步。** 如果连续发送 100 个 0，信号就保持低电平 100 个周期。接收方怎么知道这是 100 个 0 而不是 99 个或 101 个？没有电平变化，接收方的时钟就会"漂移"，导致采样错误。

**问题二：直流分量。** 如果 1 比 0 多很多（或反过来），信号会产生直流偏置，在某些传输介质（比如变压器耦合的线路）上会导致信号失真。

为了解决这些问题，工程师们发明了各种编码方案：

**曼彻斯特编码（Manchester Encoding）**——以太网（10Mbps）使用的编码方式。规则是：每个比特周期的**中间**都有一次电平跳变。从低到高跳变表示 1，从高到低跳变表示 0（IEEE 802.3 标准的规定）。

```
数据:   1    0    1    1    0
信号:  ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐
       │  │ │  │ │  │ │  │ │  │
     ──┘  └─┘  └─┘  └─┘  └─┘  └──
       ↑    ↑    ↑    ↑    ↑
      低→高 高→低 低→高 低→高 高→低
       =1   =0   =1   =1   =0
```

曼彻斯特编码的绝妙之处在于：**每个比特周期都有一次跳变，这个跳变既携带了数据，又提供了时钟同步信号。** 接收方可以通过检测跳变来校准自己的时钟。代价是信号速率（波特率）是数据速率的两倍——传输 10Mbps 数据需要 20M 波特率的信号。

**4B/5B 编码**——百兆以太网（100BASE-TX）和光纤通道使用的编码方式。它的思路不同：把每 4 个比特映射为 5 个比特的编码，选择的 5 比特编码保证**不会出现连续 3 个以上的 0**。然后再用 NRZI（逢 1 翻转）编码发送。这样既解决了时钟同步问题，又比曼彻斯特编码更高效（效率 80% vs 50%）。

```
4位数据    5位编码
0000       11110
0001       01001
0010       10100
0011       10101
...        ...
1111       11101
```

## 数据链路层的核心任务

物理层只管传输比特，但比特流是"连续不断"的——接收方怎么知道一组比特从哪里开始、在哪里结束？这就是数据链路层（Data Link Layer）要解决的问题之一。

数据链路层的核心任务有三个：

**1. 成帧（Framing）**：把比特流组织成**帧（Frame）**——一个个有明确边界的数据块。就像一本书把文字组织成一个个有页码的页面。

**2. 物理寻址**：用 **MAC 地址**（Media Access Control Address）标识网络中的每个设备。MAC 地址是一个 48 位的全球唯一标识符（比如 `00:1a:2b:3c:4d:5e`），由设备制造商在生产时烧录。它就像一个设备的"身份证号"。

**3. 差错检测**：通过 **CRC（循环冗余校验）** 等技术检测数据在传输过程中是否出错。物理层传输的比特可能因为电磁干扰而发生翻转（0 变 1 或 1 变 0），数据链路层负责发现这种错误。

## 以太网帧结构

以太网（Ethernet）是当今最主流的数据链路层技术。一个以太网帧的结构如下：

```
┌──────────┬──────────┬────────┬──────────┬──────────┬─────┐
│ 前导码    │ 目的MAC   │ 源MAC  │ 类型     │ 数据     │ FCS │
│ 8 字节   │ 6 字节   │ 6 字节 │ 2 字节   │ 46-1500  │ 4   │
│          │          │        │          │ 字节     │ 字节│
└──────────┴──────────┴────────┴──────────┴──────────┴─────┘
```

- **前导码（Preamble）**：7 字节的 `10101010` 交替模式 + 1 字节的帧起始定界符 `10101011`。它的作用是告诉接收方"帧来了，请同步时钟"。Wireshark 通常不显示前导码，因为它在物理层就被处理掉了。
- **目的 MAC 地址**：6 字节，接收方的物理地址。特殊值 `ff:ff:ff:ff:ff:ff` 表示广播（发给所有人）。
- **源 MAC 地址**：6 字节，发送方的物理地址。
- **类型（EtherType）**：2 字节，标识帧体中的数据类型。`0x0800` = IPv4，`0x0806` = ARP，`0x86DD` = IPv6。这个字段是链路层与网络层的"接口"。
- **数据（Payload）**：46-1500 字节。如果上层数据不到 46 字节，需要填充（Padding）到 46 字节。1500 字节就是著名的 **MTU（最大传输单元）**。
- **FCS（Frame Check Sequence）**：4 字节的 CRC-32 校验值，覆盖从目的 MAC 到数据末尾的所有字节。接收方重新计算 CRC，如果不匹配，就静默丢弃这个帧。

## Wi-Fi（802.11）帧与以太网帧的差异

Wi-Fi 使用的 802.11 帧和以太网帧有显著差异，因为无线网络有几个有线网络不存在的特殊问题：

**1. 三个地址字段。** 以太网帧只有源 MAC 和目的 MAC（两个地址），因为有线网络中发送方和接收方都在同一个线路上。但 Wi-Fi 涉及**无线站点（Station）**、**接入点（AP）**和**最终目的地**三个角色，所以需要三个地址字段：

- Address 1：接收方的 MAC（直接接收者）
- Address 2：发送方的 MAC（直接发送者）
- Address 3：真正的目的 MAC（最终目标）

**2. 没有碰撞检测。** 以太网使用 CSMA/CD（载波监听多路访问/碰撞检测）——发数据时同时检测碰撞，撞了就停下来重试。但 Wi-Fi 无法在发送的同时检测碰撞（无线电信号互相干扰），所以改用 CSMA/CA（碰撞**避免**），通过 RTS/CTS 握手机制和随机退避来减少碰撞概率。

**3. 管理帧。** Wi-Fi 需要额外的帧类型来处理"扫描网络"、"关联/去认证"、"信标（Beacon）"等功能——这些在有线网络中根本不存在。你手机搜索 Wi-Fi 列表时看到的那些网络名（SSID），就是各个 AP 不断广播的 Beacon 帧。

## 交换机的工作原理

数据链路层最重要的设备是**交换机（Switch）**。交换机连接多台设备，智能地把帧转发到正确的端口——而不是像集线器（Hub）那样把帧广播到所有端口。

交换机的智能来自一个简单的数据结构：**MAC 地址表（CAM Table）**。

```
┌───────────┬─────────┐
│ MAC 地址   │ 端口号   │
├───────────┼─────────┤
│ 00:1a:2b.. │ Port 1  │
│ 00:3c:4d.. │ Port 2  │
│ 00:5e:6f.. │ Port 3  │
│ 00:7a:8b.. │ Port 4  │
└───────────┴─────────┘
```

**学习过程：** 当一个帧从某个端口进入交换机时，交换机会记录"源 MAC 地址 = 这个端口"。比如，从 Port 2 收到源 MAC 为 `00:3c:4d:..` 的帧，交换机就在表中添加一条 `00:3c:4d.. → Port 2`。

**转发过程：** 当交换机要转发一个帧时，它查找目的 MAC 地址：

- 如果表中有对应条目，就从对应端口发出去（**单播转发**）
- 如果表中没有这个地址，就把帧发到**除接收端口外**的所有端口（**泛洪，Flooding**）
- 如果目的地址是 `ff:ff:ff:ff:ff:ff`（广播），同样泛洪

**一个完整的通信场景：**

假设设备 A（MAC: `aa:aa:aa:aa:aa:aa`，Port 1）要给设备 B（MAC: `bb:bb:bb:bb:bb:bb`，Port 3）发一个帧。

1. 帧到达交换机的 Port 1
2. 交换机学习：`aa:aa:aa:aa:aa:aa → Port 1`
3. 交换机查找目的 MAC `bb:bb:bb:bb:bb:bb`
4. 如果表中有 → 从对应端口转发
5. 如果表中没有 → 泛洪到 Port 2、3、4
6. 设备 B 收到帧并回复
7. 回复帧到达交换机的 Port 3
8. 交换机学习：`bb:bb:bb:bb:bb:bb → Port 3`
9. 下次 A 给 B 发消息时，交换机就知道从 Port 3 转发了

交换机就是这样通过"观察学习"逐步建立起完整的转发表——它不需要人工配置，完全自动化。这是数据链路层的优雅之处。

## 抓包实践：捕获并分析以太网帧

在 Wireshark 中捕获一个以太网帧，展开 Ethernet II 层：

```
Ethernet II, Src: Cisco_12:34:56 (00:1a:2b:3c:4d:5e), Dst: Apple_aa:bb:cc (3c:15:c2:aa:bb:cc)
  Destination: 3c:15:c2:aa:bb:cc (Apple 设备)
    Addr: 3c:15:c2:aa:bb:cc
    .... ..0. .... .... .... .... = LG bit: Globally unique address (OUI enforced)
    .... ...0 .... .... .... .... = IG bit: Individual address (unicast)
  Source: 00:1a:2b:3c:4d:5e (Cisco 设备)
    Addr: 00:1a:2b:3c:4d:5e
    .... ..0. .... .... .... .... = LG bit: Globally unique address
    .... ...0 .... .... .... .... = IG bit: Individual address (unicast)
  Type: IPv4 (0x0800)
```

几个值得注意的细节：

- MAC 地址的前 3 字节（24 位）是 **OUI（Organizationally Unique Identifier）**，由 IEEE 分配给设备制造商。`00:1a:2b` 属于 Cisco，`3c:15:c2` 属于 Apple。Wireshark 内置了一个庞大的 OUI 数据库，所以能直接显示厂商名。
- MAC 地址的最低位（第一个字节的最低位）是 **I/G 位**：0 表示单播地址，1 表示组播地址。全 1（`ff:ff:ff:ff:ff:ff`）是广播地址。
- 倒数第二位是 **U/L 位**：0 表示全球唯一（由厂商分配），1 表示本地管理（手动设置）。

如果你在 Linux 上用 `tcpdump -e` 抓包，会看到类似输出：

```
12:34:56.789012 00:1a:2b:3c:4d:5e > 3c:15:c2:aa:bb:cc, ethertype IPv4 (0x0800), length 74: ...
```

`-e` 参数让 tcpdump 显示链路层信息（MAC 地址和 EtherType）。默认情况下 tcpdump 只显示网络层及以上的信息。
