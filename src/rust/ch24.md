# 第24章：Cargo与工具链生态

## 引子：不止是构建工具

如果你来自Java世界，你习惯了Maven/Gradle处理一切：依赖、构建、测试、打包。Node.js有npm，Python有pip+setuptools。Rust有Cargo——而且Cargo做得可能比它们都好。但Cargo只是冰山一角：围绕它的工具链生态（rustfmt、clippy、rustup、cargo子命令们）才是让你日常开发高效的秘密武器。

本章不讲语法，讲**工程实践**——怎么把Rust项目从"能跑"提升到"专业级"。

## Features与条件编译：按需启用功能

Features让你发布一个crate但提供可选功能，用户只为自己需要的功能买单（编译时间和依赖数量）。

```toml
# Cargo.toml
[features]
default = ["json"]
json = ["serde", "serde_json"]
async-runtime = ["tokio"]
full = ["json", "async-runtime"]

[dependencies]
serde = { version = "1", optional = true }
serde_json = { version = "1", optional = true }
tokio = { version = "1", optional = true, features = ["full"] }
```

在代码中使用条件编译：

```rust
// src/lib.rs

pub fn process(data: &str) -> String {
    data.trim().to_uppercase()
}

// 只有启用 "json" feature 时才编译这段代码
#[cfg(feature = "json")]
pub fn parse_json(input: &str) -> Result<serde_json::Value, serde_json::Error> {
    serde_json::from_str(input)
}

// 只有启用 "async-runtime" feature 时才编译
#[cfg(feature = "async-runtime")]
pub async fn async_process(data: String) -> String {
    tokio::task::spawn_blocking(move || process(&data))
        .await
        .unwrap()
}

// 多条件组合
#[cfg(all(feature = "json", feature = "async-runtime"))]
pub async fn async_parse_json(input: String) -> Result<serde_json::Value, serde_json::Error> {
    // 两个 feature 都启用时才有这个函数
    parse_json(&input)
}
```

用户使用你的crate时：

```toml
# 只使用基础功能
my-crate = "1.0"

# 启用 JSON 支持
my-crate = { version = "1.0", features = ["json"] }

# 启用所有功能
my-crate = { version = "1.0", features = ["full"] }
```

## 发布配置：Release Profile优化

Cargo有两套默认Profile：`dev`（debug构建）和`release`（发布构建）。你可以在`Cargo.toml`中精细调整：

```toml
# 开发构建：快速编译，方便调试
[profile.dev]
opt-level = 0        # 不优化
debug = true          # 包含调试信息

# 发布构建：最大化性能
[profile.release]
opt-level = 3         # 最大优化
lto = true            # 链接时优化（Link-Time Optimization）
codegen-units = 1     # 单编译单元，更好的优化（但编译更慢）
strip = true          # 去除符号表，减小二进制体积
panic = "abort"       # panic时直接终止（无回溯，但体积更小）

# 自定义 profile：用于 CI 测试（兼顾速度和优化）
[profile.ci]
inherits = "test"
opt-level = 1
```

```bash
# 构建发布版本
cargo build --release

# 使用自定义 profile
cargo build --profile ci

# 查看二进制体积对比
ls -lh target/debug/my_app target/release/my_app
```

> **实测数据**：一个典型Rust CLI工具，`dev`构建约30MB，`release`构建（开启`lto`+`strip`）约2-3MB——体积缩小10倍以上，运行速度提升3-5倍。

## cargo doc：生成文档站

```bash
# 为你的项目生成 HTML 文档
cargo doc --no-deps --open

# --no-deps: 不生成依赖的文档（只看你自己的）
# --open: 生成后自动在浏览器中打开
```

写好文档注释的规范：

```rust
/// 计算两个数的最大公约数（GCD）。
///
/// 使用欧几里得算法（Euclidean Algorithm），时间复杂度 O(log(min(a,b)))。
///
/// # Examples
///
/// ```
/// use my_math::gcd;
/// assert_eq!(gcd(12, 8), 4);
/// assert_eq!(gcd(7, 13), 1);
/// assert_eq!(gcd(0, 5), 5);
/// ```
///
/// # Panics
///
/// 当两个参数都为0时，函数会 panic。
///
/// ```should_panic
/// use my_math::gcd;
/// gcd(0, 0); // panic!
/// ```
pub fn gcd(a: u64, b: u64) -> u64 {
    if a == 0 && b == 0 {
        panic!("两个参数不能同时为0");
    }
    if b == 0 { a } else { gcd(b, a % b) }
}
```

文档注释的常用标记：

- `# Examples`：代码示例（自动变成文档测试）
- `# Panics`：说明什么情况下会panic
- `# Errors`：说明可能返回的错误类型
- `# Safety`：unsafe函数必须说明安全使用的前提条件

## rustfmt：代码格式化

就像Python有`black`、Go有`gofmt`，Rust有官方标准格式化工具`rustfmt`。团队统一代码风格从此不再是争论话题。

```bash
# 安装（通常随 rustup 一起安装）
rustup component add rustfmt

# 格式化整个项目
cargo fmt

# 只格式化特定文件
rustfmt src/main.rs

# 检查格式是否正确（CI中常用，不修改文件）
cargo fmt -- --check
```

自定义格式化规则（`rustfmt.toml`放在项目根目录）：

```toml
# rustfmt.toml
max_width = 100
tab_spaces = 4
use_field_init_shorthand = true
use_try_shorthand = true
edition = "2021"
```

## clippy：官方Linter

clippy是Rust的官方静态分析工具，它比编译器更"啰嗦"——能帮你发现编译器发现不了的问题：

```bash
# 安装
rustup component add clippy

# 运行（会给出详细建议）
cargo clippy

# 把警告当错误（CI中推荐）
cargo clippy -- -D warnings
```

clippy能抓出的问题示例：

```rust
// 问题代码
fn example(x: i32) -> bool {
    if x > 10 {
        return true;
    } else {
        return false;
    }
}

// clippy 建议：
// warning: this could be simplified
// help: replace with: `x > 10`
fn example_fixed(x: i32) -> bool {
    x > 10
}
```

```rust
// 问题代码：手动实现 Default
struct Config {
    timeout: u64,
    retries: u32,
}

impl Config {
    fn new() -> Self {
        Config { timeout: 30, retries: 3 }
    }
}

// clippy 建议：实现 Default trait
impl Default for Config {
    fn default() -> Self {
        Config { timeout: 30, retries: 3 }
    }
}
```

在项目根目录配置clippy规则（`clippy.toml`）：

```toml
# clippy.toml
too-many-arguments-threshold = 8
type-complexity-threshold = 300
```

## rustup与多工具链管理

rustup是Rust的工具链管理器，让你轻松切换编译器版本：

```bash
# 查看已安装的工具链
rustup toolchain list

# 安装特定版本
rustup toolchain install 1.75.0
rustup toolchain install nightly

# 设置项目默认工具链（创建 rust-toolchain.toml）
# rust-toolchain.toml
# [toolchain]
# channel = "1.75.0"
# components = ["rustfmt", "clippy"]

# 临时使用其他工具链
cargo +nightly build
cargo +1.75.0 test

# 更新所有工具链
rustup update

# 安装目标平台（交叉编译）
rustup target add x86_64-unknown-linux-musl  # Linux静态链接
rustup target add wasm32-unknown-unknown       # WebAssembly
rustup target add aarch64-apple-darwin         # Apple Silicon
```

## IDE集成最佳实践

**VS Code**（最主流选择）：

1. 安装 `rust-analyzer` 扩展（官方推荐，不要用旧的 rust-lang.rust）
2. 启用 inlay hints（类型推断提示）
3. 配置保存时自动格式化

```json
// .vscode/settings.json
{
    "rust-analyzer.check.command": "clippy",
    "editor.formatOnSave": true,
    "rust-analyzer.inlayHints.typeHints.enable": true,
    "rust-analyzer.inlayHints.parameterHints.enable": true
}
```

**JetBrains CLion/IntelliJ**：安装 Rust 插件（IntelliJ Rust），功能与rust-analyzer接近。

**其他编辑器**：rust-analyzer支持LSP协议，几乎所有现代编辑器都能集成。

## CI/CD中的Rust：GitHub Actions配置

一个专业的Rust CI配置：

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

env:
  CARGO_TERM_COLOR: always

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install Rust
        uses: dtolnay/rust-toolchain@stable
        with:
          components: rustfmt, clippy

      - name: Cache dependencies
        uses: Swatinem/rust-cache@v2

      - name: Check formatting
        run: cargo fmt -- --check

      - name: Run clippy
        run: cargo clippy -- -D warnings

      - name: Run tests
        run: cargo test --verbose

      - name: Build release
        run: cargo build --release

  # 可选：多平台测试
  test-windows:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - run: cargo test

  test-macos:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - run: cargo test
```

## 常用社区工具

```bash
# cargo-edit：命令行添加/删除依赖（类似 npm install）
cargo install cargo-edit
cargo add serde --features derive   # 添加依赖
cargo add tokio --features full --dev  # 添加为 dev-dependency
cargo remove old-crate               # 移除依赖
cargo upgrade                         # 升级所有依赖

# cargo-watch：文件变更时自动重新运行
cargo install cargo-watch
cargo watch -x run          # 代码变更时自动 cargo run
cargo watch -x test         # 代码变更时自动 cargo test
cargo watch -x "clippy -- -D warnings"  # 实时 clippy

# cargo-expand：查看宏展开后的代码
cargo install cargo-expand
cargo expand                    # 展开所有宏
cargo expand my_module          # 展开特定模块

# cargo-audit：安全漏洞检查
cargo install cargo-audit
cargo audit                     # 检查 Cargo.lock 中是否有已知漏洞

# cargo-nextest：更快更漂亮的测试运行器
cargo install cargo-nextest
cargo nextest run               # 并行运行测试，输出更友好
```

## 常见陷阱与易错点

**陷阱1：忘记`cargo fmt --check`和`cargo clippy`**
很多团队CI不过这两项，导致代码风格不统一、潜在问题积压。把它们加进CI是五分钟的事。

**陷阱2：release构建的lto让编译极慢**
`lto = true` + `codegen-units = 1`可能让大型项目编译时间翻3倍。可以只在最终发布时开启，日常release测试用`lto = "thin"`。

**陷阱3：忽略`cargo audit`**
供应链攻击是真实的。定期运行`cargo audit`检查依赖漏洞，最好加入CI。

## 小结

- Features提供可选功能，条件编译（`#[cfg]`）让代码按需编译
- Release profile的优化选项（`lto`、`strip`、`opt-level`）能显著提升性能并减小体积
- `cargo doc`生成文档站，文档注释自动变成测试
- `rustfmt`统一代码风格，`clippy`发现潜在问题
- `rustup`管理多工具链，支持交叉编译
- GitHub Actions + `rust-cache`提供快速的CI/CD体验
- `cargo-edit`、`cargo-watch`、`cargo-expand`等工具大幅提升开发效率
