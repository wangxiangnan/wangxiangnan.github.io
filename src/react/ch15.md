## 15.1 React 渲染机制简述：虚拟 DOM 的魔法

在开始优化之前，我们需要理解 React 是怎么工作的。

### 什么是"渲染"？

当你的组件的状态（state）或属性（props）发生变化时，React 需要做以下工作：

1. **调用你的组件函数** — 重新执行整个函数体
2. **生成新的虚拟 DOM** — 一棵描述 UI 结构的 JavaScript 对象树
3. **Diffing（对比差异）** — 将新的虚拟 DOM 与旧的进行对比，找出变化
4. **提交更新（Commit）** — 只把真正变化的部分更新到真实 DOM

打个比方：你在装修房子。你不会每次想换个窗帘就把整栋房子拆了重建吧？React 也一样 — 它通过"虚拟 DOM"这个设计蓝图，先对比哪里变了，然后只改动需要改的地方。

> 💡 **Tip**：虚拟 DOM 的 diffing 算法复杂度是 O(n)（n 是节点数量），这在大多数情况下已经足够快了。React 的 diffing 做了几个聪明的假设：不同类型的元素产生不同的树，开发者可以通过 `key` prop 来标识哪些子元素是稳定的。

### 组件什么时候会重新渲染？

一个组件会在以下情况重新渲染：

1. 组件自身的 `state` 发生变化
2. 父组件重新渲染（子组件也会跟着重新渲染！）
3. 组件依赖的 `context` 值发生变化

**重点来了** — 第 2 点是最容易被忽略的性能杀手。来看一个例子：

```jsx
// App.jsx
import { useState } from 'react';

function App() {
  const [count, setCount] = useState(0);
  const [text, setText] = useState('');

  return (
    <div>
      <h1>性能演示</h1>
      {/* 每次 count 或 text 变化，这三个组件都会重新渲染 */}
      <Counter count={count} onIncrement={() => setCount(c => c + 1)} />
      <TextInput value={text} onChange={setText} />
      <ExpensiveList /> {/* 这个组件根本不需要重新渲染！ */}
    </div>
  );
}

function Counter({ count, onIncrement }) {
  console.log('Counter 渲染了');
  return <button onClick={onIncrement}>计数: {count}</button>;
}

function TextInput({ value, onChange }) {
  console.log('TextInput 渲染了');
  return <input value={value} onChange={e => onChange(e.target.value)} />;
}

function ExpensiveList() {
  console.log('ExpensiveList 渲染了 — 但我其实不需要渲染！');
  // 假设这里有一个包含 1000 个项目的列表
  return (
    <ul>
      {Array.from({ length: 1000 }, (_, i) => (
        <li key={i}>项目 {i + 1}</li>
      ))}
    </ul>
  );
}

export default App;
```

在上面的例子中，当你在输入框打字时，`text` 状态变化导致 `App` 重新渲染，进而 `Counter`、`TextInput` 和 `ExpensiveList` 全部重新渲染。但 `ExpensiveList` 根本不依赖任何变化的数据 — 这就是**不必要的重渲染**！

> ⚠️ **Warning**：在 React 中，"组件重新渲染"不等于"DOM 更新"。React 会通过 diffing 判断是否需要真正操作 DOM。所以重新渲染本身不一定导致性能问题，但如果组件的计算量很大（比如渲染一个大列表），那些计算就会白白浪费。

## 15.2 React.memo — 给组件穿上"防弹衣"

`React.memo` 是 React 提供的一个高阶组件（Higher-Order Component），它的作用是：**如果组件的 props 没有变化，就跳过重新渲染，直接复用上次的渲染结果。**

就像给组件穿上一件"防弹衣"，外界的"渲染子弹"打过来时，如果 props 没变，就被弹开了。

```jsx
import { memo } from 'react';

// 用 memo 包裹组件，只有 props 变化时才会重新渲染
const ExpensiveList = memo(function ExpensiveList() {
  console.log('ExpensiveList 渲染了');
  return (
    <ul>
      {Array.from({ length: 1000 }, (_, i) => (
        <li key={i}>项目 {i + 1}</li>
      ))}
    </ul>
  );
});

export default ExpensiveList;
```

现在，即使父组件重新渲染，只要 `ExpensiveList` 的 props 没变，它就不会重新执行。

### 但是！注意 props 中的引用类型

`React.memo` 默认使用**浅比较（shallow comparison）**。这意味着如果 props 中包含对象或函数，每次父组件渲染都会创建新的引用，导致 memo 失效：

```jsx
function App() {
  const [count, setCount] = useState(0);

  // ❌ 每次渲染都会创建新的对象引用！
  const style = { color: 'red', fontSize: '16px' };

  // ❌ 每次渲染都会创建新的函数引用！
  const handleClick = () => console.log('clicked');

  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>Count: {count}</button>
      {/* memo 会失效，因为 style 和 onClick 每次都是新引用 */}
      <MemoizedChild style={style} onClick={handleClick} />
    </div>
  );
}
```

这就需要 `useMemo` 和 `useCallback` 来帮忙了！

## 15.3 useMemo — 缓存计算结果

`useMemo` 用于缓存一个**计算结果**。只有当依赖项发生变化时，才会重新计算。

打个比方：你每天上班要走同一条路，你不需要每天早上都打开地图重新规划路线，除非那条路施工了（依赖项变化了）。

```jsx
import { useState, useMemo } from 'react';

function ProductList({ products, filter }) {
  // 只有 products 或 filter 变化时，才会重新过滤
  // 而不是每次组件渲染都重新过滤
  const filteredProducts = useMemo(() => {
    console.log('正在过滤产品列表...');
    return products.filter(product =>
      product.name.toLowerCase().includes(filter.toLowerCase())
    );
  }, [products, filter]); // 依赖项数组

  return (
    <ul>
      {filteredProducts.map(product => (
        <li key={product.id}>{product.name} - ¥{product.price}</li>
      ))}
    </ul>
  );
}

export default ProductList;
```

### 什么时候该用 useMemo？

✅ **该用的场景**：

- 计算量大的派生数据（大数组过滤、排序等）
- 需要保持引用稳定的对象（作为其他 Hook 的依赖、作为 memo 组件的 props）

❌ **不该用的场景**：

- 简单的计算（`a + b` 这种，缓存的开销比计算本身还大）
- 所有东西都用 useMemo（会让代码变复杂，而且 React 的 diffing 本身已经很快了）

```jsx
// ❌ 不要这样做 — 过度使用 useMemo
const name = useMemo(() => `${firstName} ${lastName}`, [firstName, lastName]);

// ✅ 简单的字符串拼接不需要 memo
const name = `${firstName} ${lastName}`;
```

> 💡 **Tip**：如果你不确定是否需要 `useMemo`，那就先不用。等你用 React DevTools Profiler 发现了性能问题，再考虑添加。记住我们的黄金法则：**先测量，再优化！**

## 15.4 useCallback — 缓存函数引用

`useCallback` 和 `useMemo` 很像，只不过它缓存的是**函数本身**（函数引用），而不是函数的返回值。

这主要解决的问题是：在 React 中，函数也是对象，每次组件渲染都会创建新的函数实例。如果这个函数作为 props 传给被 `memo` 包裹的子组件，就会导致子组件不必要地重新渲染。

```jsx
import { useState, useCallback, memo } from 'react';

// 子组件用 memo 包裹
const TodoItem = memo(function TodoItem({ todo, onToggle }) {
  console.log(`TodoItem "${todo.text}" 渲染了`);
  return (
    <li
      onClick={() => onToggle(todo.id)}
      style={{ textDecoration: todo.done ? 'line-through' : 'none' }}
    >
      {todo.text}
    </li>
  );
});

function TodoList() {
  const [todos, setTodos] = useState([
    { id: 1, text: '学习 React', done: false },
    { id: 2, text: '学习性能优化', done: false },
    { id: 3, text: '成为大佬', done: false },
  ]);

  // ❌ 不用 useCallback：每次渲染都创建新函数，memo 失效
  // const handleToggle = (id) => {
  //   setTodos(prev => prev.map(t => t.id === id ? { ...t, done: !t.done } : t));
  // };

  // ✅ 使用 useCallback：函数引用稳定，memo 正常工作
  const handleToggle = useCallback((id) => {
    setTodos(prev =>
      prev.map(t => (t.id === id ? { ...t, done: !t.done } : t))
    );
  }, []); // 空依赖数组，因为 setTodos 是稳定引用

  return (
    <ul>
      {todos.map(todo => (
        <TodoItem key={todo.id} todo={todo} onToggle={handleToggle} />
      ))}
    </ul>
  );
}

export default TodoList;
```

> ⚠️ **Warning**：`useCallback` 和 `React.memo` 是一对好搭档。单独使用 `useCallback` 通常没有太大意义 — 它的价值主要体现在让 `memo` 正常工作上。

## 15.5 代码分割与懒加载：React.lazy + Suspense

想象你去吃自助餐。你不会一次性把所有菜都端到桌上吧？（桌子也放不下啊！）你会先吃想吃的，其他的等到需要的时候再去拿。

代码分割（Code Splitting）就是这个道理：**不要一次性把所有代码都加载进来，用户用到哪部分就加载哪部分。**

默认情况下，Vite 会把你的整个应用打包成一个巨大的 JavaScript 文件。当用户打开页面时，需要下载完整个文件才能看到内容。如果你的应用有 20 个页面，但用户只访问了其中 1 个，那其余 19 个页面的代码就白白下载了。

### 使用 React.lazy 和 Suspense

```jsx
// App.jsx
import { lazy, Suspense } from 'react';
import { BrowserRouter, Routes, Route, Link } from 'react-router-dom';

// 使用 lazy 动态导入组件
// 这些组件只有在对应路由被访问时才会被加载
const Home = lazy(() => import('./pages/Home'));
const Dashboard = lazy(() => import('./pages/Dashboard'));
const Settings = lazy(() => import('./pages/Settings'));
const UserProfile = lazy(() => import('./pages/UserProfile'));

// 加载中的 fallback 组件
function LoadingSpinner() {
  return (
    <div className="flex items-center justify-center h-screen">
      <div className="animate-spin rounded-full h-12 w-12 border-b-2 border-blue-500">
      </div>
      <span className="ml-3 text-gray-600">加载中...</span>
    </div>
  );
}

function App() {
  return (
    <BrowserRouter>
      <nav className="flex gap-4 p-4 bg-gray-100">
        <Link to="/" className="text-blue-500 hover:underline">首页</Link>
        <Link to="/dashboard" className="text-blue-500 hover:underline">仪表盘</Link>
        <Link to="/settings" className="text-blue-500 hover:underline">设置</Link>
      </nav>

      {/* Suspense 包裹 lazy 组件，提供加载中的 fallback UI */}
      <Suspense fallback={<LoadingSpinner />}>
        <Routes>
          <Route path="/" element={<Home />} />
          <Route path="/dashboard" element={<Dashboard />} />
          <Route path="/settings" element={<Settings />} />
          <Route path="/user/:id" element={<UserProfile />} />
        </Routes>
      </Suspense>
    </BrowserRouter>
  );
}

export default App;
```

这样做了之后：

- 用户访问首页时，只下载 `Home` 组件的代码
- 当用户点击"仪表盘"链接时，才开始下载 `Dashboard` 的代码
- 在 `Dashboard` 下载完成前，显示加载动画

> 💡 **Tip**：Vite 会自动为 `lazy()` 导入的模块生成独立的 chunk 文件，不需要额外配置 webpack 或其他打包工具。

### 预加载技巧

你还可以在用户"即将需要"某个组件时提前加载：

```jsx
import { lazy, Suspense, useState } from 'react';

const HeavyChart = lazy(() => import('./HeavyChart'));

function Dashboard() {
  const [showChart, setShowChart] = useState(false);

  // 鼠标悬停在按钮上时，提前加载图表组件
  const handleMouseEnter = () => {
    // 触发预加载（import() 会被缓存，不会重复请求）
    import('./HeavyChart');
  };

  return (
    <div>
      <button
        onClick={() => setShowChart(true)}
        onMouseEnter={handleMouseEnter}
      >
        显示图表
      </button>
      {showChart && (
        <Suspense fallback={<div>图表加载中...</div>}>
          <HeavyChart />
        </Suspense>
      )}
    </div>
  );
}
```

## 15.6 长列表优化：虚拟滚动

当你的列表有成百上千个项目时，即使数据加载没问题，把所有 DOM 节点都渲染出来也会让浏览器吃不消。

想象一个图书馆：你不会把所有书都摊在桌子上吧？你只会拿出你正在看的那几本，其他的都在书架上。虚拟滚动就是这个思路 — **只渲染用户看得见的部分，看不见的就不渲染。**

### 使用 react-window

`react-window` 是一个轻量级的虚拟滚动库（gzip 后只有约 6KB）。

```bash
npm install react-window
```

```jsx
import { FixedSizeList as List } from 'react-window';

// 每一行的渲染组件
function Row({ index, style }) {
  return (
    <div
      style={style} // 必须应用 style，它包含了定位信息
      className={`flex items-center px-4 ${index % 2 === 0 ? 'bg-white' : 'bg-gray-50'}`}
    >
      <span className="text-gray-500 w-16">#{index + 1}</span>
      <span className="flex-1">列表项目 {index + 1}</span>
      <span className="text-sm text-gray-400">
        {new Date(2024, 0, index % 28 + 1).toLocaleDateString()}
      </span>
    </div>
  );
}

function VirtualList() {
  return (
    <div className="h-screen p-4">
      <h2 className="text-xl font-bold mb-4">虚拟滚动列表（10000 个项目）</h2>

      {/*
        FixedSizeList: 每个项目高度固定的虚拟列表
        - height: 可视区域高度
        - itemCount: 总项目数
        - itemSize: 每个项目的高度（像素）
        - width: 列表宽度
      */}
      <List
        height={600}
        itemCount={10000}
        itemSize={48}
        width="100%"
      >
        {Row}
      </List>
    </div>
  );
}

export default VirtualList;
```

即使有 10000 个项目，页面上实际渲染的 DOM 节点也只有可视区域内的那十几个！

> 💡 **Tip**：如果你的列表项目高度不一致，可以使用 `VariableSizeList`。如果需要无限滚动加载，可以结合 `onItemsRendered` 回调来触发数据加载。

## 15.7 React DevTools Profiler：找到真正的瓶颈

还记得我们说的黄金法则吗？**先测量，再优化！** 那用什么来测量呢？React DevTools 的 Profiler 就是你的"性能检测仪"。

### 安装 React DevTools

1. 在 Chrome 浏览器中访问 [React DevTools 扩展页面](https://chrome.google.com/webstore/detail/react-developer-tools/fmkadmapgofadopljbjfkapdkoienihi)
2. 点击"添加到 Chrome"

### 使用 Profiler

1. 打开你的 React 应用，按 F12 打开开发者工具
2. 切换到 "Profiler" 标签页
3. 点击左上角的蓝色圆形按钮（Record）开始录制
4. 在应用中进行你想要分析的操作（比如点击按钮、切换页面）
5. 再次点击按钮停止录制

你会看到一个火焰图（Flamegraph），它展示了：

- 每个组件渲染花了多长时间
- 哪些组件渲染了，哪些被跳过了
- 每次渲染的"原因"是什么

### 关键指标

- **Commit 时间**：React 将变更提交到 DOM 所花的总时间
- **组件渲染时间**：每个组件的函数执行时间
- **颜色含义**：
  - 🟢 绿色 = 渲染很快，没问题
  - 🟡 黄色 = 渲染较慢，需要关注
  - 🔴 红色 = 渲染很慢，需要优化
  - ⚫ 灰色 = 被 memo 跳过，没有重新渲染

> 💡 **Tip**：在 Profiler 设置中，勾选 "Record why each component rendered"，这样你可以看到每个组件重新渲染的具体原因，帮你找到问题根源。

### 实战：用 Profiler 发现问题

```jsx
// 在开发阶段，给组件添加渲染计数
import { useRef } from 'react';

function useRenderCount(name) {
  const count = useRef(0);
  count.current += 1;
  console.log(`${name} 渲染次数: ${count.current}`);
  return count.current;
}

// 在组件中使用
function MyComponent() {
  const renderCount = useRenderCount('MyComponent');
  return <div>渲染了 {renderCount} 次</div>;
}
```

## 15.8 更多优化技巧

### 1. 避免在渲染中创建对象和函数

```jsx
// ❌ 每次渲染都创建新对象
<Child style={{ color: 'red' }} />

// ✅ 提取到组件外部（如果不依赖 props/state）
const childStyle = { color: 'red' };
// ...
<Child style={childStyle} />

// ✅ 或者用 useMemo（如果依赖 props/state）
const childStyle = useMemo(() => ({
  color: theme === 'dark' ? 'white' : 'black'
}), [theme]);
```

### 2. 状态下放（State Colocation）

把状态放在尽可能低的组件层级中，避免不必要的父组件渲染：

```jsx
// ❌ 状态提升太高，导致整个表单重新渲染
function Form() {
  const [inputValue, setInputValue] = useState('');
  return (
    <div>
      <Header />      {/* 不需要因为 inputValue 而重新渲染 */}
      <Sidebar />     {/* 不需要因为 inputValue 而重新渲染 */}
      <input value={inputValue} onChange={e => setInputValue(e.target.value)} />
    </div>
  );
}

// ✅ 状态下放到需要的组件中
function Form() {
  return (
    <div>
      <Header />
      <Sidebar />
      <SearchInput /> {/* 状态在这个小组件内部管理 */}
    </div>
  );
}

function SearchInput() {
  const [inputValue, setInputValue] = useState('');
  return <input value={inputValue} onChange={e => setInputValue(e.target.value)} />;
}
```

### 3. 使用 key 强制重新挂载

有时候你反而**想要**组件重新挂载（比如重置表单），这时 `key` 就派上用场了：

```jsx
function UserProfile({ userId }) {
  return (
    // 当 userId 变化时，整个组件会卸载并重新挂载
    // 确保内部状态被完全重置
    <UserForm key={userId} userId={userId} />
  );
}
```

### 4. 避免巨大的 Context

```jsx
// ❌ 一个巨大的 Context，任何值变化都导致所有消费者重新渲染
const AppContext = createContext();
function AppProvider({ children }) {
  const [user, setUser] = useState(null);
  const [theme, setTheme] = useState('light');
  const [notifications, setNotifications] = useState([]);

  return (
    <AppContext.Provider value={{ user, setUser, theme, setTheme, notifications, setNotifications }}>
      {children}
    </AppContext.Provider>
  );
}

// ✅ 按功能拆分 Context
const UserContext = createContext();
const ThemeContext = createContext();
const NotificationContext = createContext();
```

## 15.9 性能优化检查清单

当你觉得应用有性能问题时，按以下流程排查：

| 步骤 | 做什么 | 工具 |
|------|--------|------|
| 1 | 确认问题存在（用户能感知到卡顿吗？） | 自己的体验 + 用户反馈 |
| 2 | 测量（找到具体是哪个组件慢） | React DevTools Profiler |
| 3 | 分析原因（不必要的渲染？计算量大？） | Profiler 的 "why rendered" |
| 4 | 选择方案 | memo / useMemo / useCallback / 代码分割 |
| 5 | 实施优化 | 写代码 |
| 6 | 验证效果 | 再次用 Profiler 测量 |

> ⚠️ **Warning**：千万不要跳过第 1-3 步直接到第 4 步！盲目优化不仅浪费时间，还可能让代码变得更复杂、更难维护。记住：过早优化是万恶之源。

## 本章小结

恭喜你完成了性能优化这一章！让我们回顾一下学到的内容：

| 概念 | 用途 | 什么时候用 |
|------|------|-----------|
| React.memo | 避免组件不必要的重渲染 | 组件 props 经常不变时 |
| useMemo | 缓存计算结果 | 计算量大 + 依赖项不常变 |
| useCallback | 缓存函数引用 | 函数作为 props 传给 memo 组件 |
| React.lazy + Suspense | 代码分割、懒加载 | 路由级别 / 大型组件 |
| react-window | 虚拟滚动 | 长列表（数百个项目以上）|
| Profiler | 性能测量 | 发现性能问题时首先使用 |

**最重要的原则**：先测量，再优化。不要凭感觉优化，用数据说话。

## 小练习

### 练习 1：找出性能浪费

下面的代码有哪些不必要的重渲染？请找出并优化。

```jsx
function ShoppingCart() {
  const [items, setItems] = useState([]);
  const [coupon, setCoupon] = useState('');

  const total = items.reduce((sum, item) => sum + item.price * item.qty, 0);

  const removeItem = (id) => {
    setItems(prev => prev.filter(item => item.id !== id));
  };

  return (
    <div>
      <CouponInput value={coupon} onChange={setCoupon} />
      <ItemList items={items} onRemove={removeItem} />
      <OrderSummary total={total} />
    </div>
  );
}
```

<details>
<summary>点击查看答案</summary>

1. `removeItem` 函数每次渲染都会创建新引用，导致 `ItemList`（如果用 memo 包裹）的不必要重渲染。用 `useCallback` 包裹。
2. `total` 在 `coupon` 变化时也会重新计算（虽然 coupon 和 total 无关），用 `useMemo` 包裹，依赖项为 `[items]`。
3. `CouponInput`、`ItemList`、`OrderSummary` 都可以用 `React.memo` 包裹。

</details>
