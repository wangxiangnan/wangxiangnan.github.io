# 第15章：Express.js——经典框架深度解析

## 引言：Web框架界的"老大哥"

如果Node.js Web框架有一个家族聚会，Express一定是那个最德高望重的长辈。从2010年诞生至今，它就像编程界的"老干妈"——不一定是最时尚的，但几乎每个Node.js开发者的"厨房"里都有一瓶。

Express的下载量每周超过3000万次。不是因为它最快、最新、最酷，而是因为它**足够简单**、**足够灵活**、**生态足够丰富**。当你Google任何Node.js Web开发问题时，排名第一的答案大概率是Express的。

本章我们不只是"使用"Express，我们要**深入它的灵魂**——理解中间件是如何串联的，路由是如何匹配的，以及为什么一个看似简单的框架能统治Web开发十多年。

## 15.1 Express哲学：极简主义与中间件组合

Express的核心理念可以用一句话概括：**一切皆中间件**。

```typescript
import express, { Request, Response, NextFunction } from 'express';

const app = express();

// Express应用本质上就是一堆中间件函数的队列
// 请求从上到下经过每个中间件
// 每个中间件决定：处理请求 / 修改请求 / 传递给下一个

// 中间件1：记录请求
app.use((req: Request, res: Response, next: NextFunction) => {
  console.log(`${new Date().toISOString()} ${req.method} ${req.url}`);
  next(); // 传递给下一个中间件
});

// 中间件2：解析JSON请求体
app.use(express.json());

// 中间件3：路由处理（也是中间件！）
app.get('/', (req: Request, res: Response) => {
  res.send('Hello Express!');
});

app.listen(3000);
```

Express的设计哲学就像乐高积木——框架本身只提供最基础的地基，其他功能全靠中间件"插拔"。需要解析Cookie？加个中间件。需要压缩响应？加个中间件。需要CORS？还是加个中间件。

这和那些"全家桶"框架（如Django、Rails）形成鲜明对比。Express不替你做选择，而是给你选择的自由。

### 15.2.3 next()的三种用法

```typescript
import express from 'express';

const app = express();

// 1. next() - 正常传递
app.use((req, res, next) => {
  req.startTime = Date.now(); // 给req挂自定义属性
  next();
});

// 2. next('route') - 跳过当前路由的剩余处理器
app.get('/user/:id',
  (req, res, next) => {
    // 如果id不是数字，跳到下一个路由
    if (isNaN(Number(req.params.id))) {
      next('route');
    } else {
      next();
    }
  },
  (req, res) => {
    res.send(`User ID: ${req.params.id}`);
  }
);

app.get('/user/:id', (req, res) => {
  res.send(`User name: ${req.params.id}`);
});

// 3. next(error) - 传递错误，跳到错误处理中间件
app.get('/danger', (req, res, next) => {
  try {
    throw new Error('Something went wrong!');
  } catch (err) {
    next(err); // 跳转到错误处理中间件
  }
});

// 错误处理中间件（4个参数！）
app.use((err: Error, req: express.Request, res: express.Response, next: express.NextFunction) => {
  console.error('Error:', err.message);
  res.status(500).json({ error: err.message });
});

app.listen(3000);
```

### 15.2.4 手写Express中间件机制

想理解Express？让我们手写一个简化版：

```typescript
// 简化版Express核心——理解中间件链
type SimpleHandler = (req: any, res: any, next: () => void) => void;

class MiniExpress {
  private middlewares: SimpleHandler[] = [];

  use(handler: SimpleHandler): void {
    this.middlewares.push(handler);
  }

  // 核心：组合中间件为一个执行链
  private compose(req: any, res: any): void {
    let index = 0;

    const next = (): void => {
      if (index >= this.middlewares.length) return;

      const middleware = this.middlewares[index];
      index++;
      middleware(req, res, next);
    };

    next(); // 启动链式调用
  }

  handleRequest(req: any, res: any): void {
    this.compose(req, res);
  }
}

// 使用
const app = new MiniExpress();

app.use((req, res, next) => {
  console.log('Middleware 1');
  next();
});

app.use((req, res, next) => {
  console.log('Middleware 2');
  next();
});

app.use((req, res, next) => {
  console.log('Middleware 3 - respond');
  res.end('Hello');
});
```

```typescript
  next();

app.get('/users/:userId', (req, res) => {
  // 此时 req.user 已经加载好了
  res.json(req.user);

  return { id, name: 'Alice' }; // 模拟
```

### 15.3.3 Router模块化

当路由越来越多时，全塞在一个文件里会让你的 `app.ts` 变成一本电话簿。Express提供了 `Router` 来做模块化：

```typescript
// routes/users.ts
import { Router, Request, Response } from 'express';

const router = Router();

// 路由级中间件（只对这个router下的路由生效）
router.use((req, res, next) => {
  console.log('Users router middleware');
  next();
});

router.get('/', (req: Request, res: Response) => {
  res.json({ users: [] });
});

router.get('/:id', (req: Request, res: Response) => {
  res.json({ user: { id: req.params.id } });
});

router.post('/', (req: Request, res: Response) => {
  res.status(201).json({ user: req.body });
});

router.put('/:id', (req: Request, res: Response) => {
  res.json({ user: { ...req.body, id: req.params.id } });
});

router.delete('/:id', (req: Request, res: Response) => {
  res.status(204).end();
});

export default router;
```

### 15.4.2 multer（文件上传）

```typescript
import express from 'express';
import multer from 'multer';
import path from 'node:path';
import crypto from 'node:crypto';

// 配置存储引擎
const storage = multer.diskStorage({
  destination: (req, file, cb) => {
    cb(null, './uploads/');
  },
  filename: (req, file, cb) => {
    // 生成唯一文件名，保留扩展名
    const uniqueName = `${crypto.randomUUID()}${path.extname(file.originalname)}`;
    cb(null, uniqueName);
  },
});

// 文件过滤器
const fileFilter = (
  req: express.Request,
  file: Express.Multer.File,
  cb: multer.FileFilterCallback,
) => {
  const allowedTypes = ['image/jpeg', 'image/png', 'image/gif', 'image/webp'];
  if (allowedTypes.includes(file.mimetype)) {
    cb(null, true);
  } else {
    cb(new Error(`不支持的文件类型: ${file.mimetype}`));
  }
};

const upload = multer({
  storage,
  fileFilter,
  limits: {
    fileSize: 5 * 1024 * 1024, // 5MB
    files: 5, // 最多5个文件
  },
});

const app = express();

// 单文件上传
app.post('/upload/avatar', upload.single('avatar'), (req, res) => {
  if (!req.file) {
    return res.status(400).json({ error: 'No file uploaded' });
  }
  res.json({
    filename: req.file.filename,
    size: req.file.size,
    mimetype: req.file.mimetype,
    url: `/uploads/${req.file.filename}`,
  });
});

// 多文件上传
app.post('/upload/photos', upload.array('photos', 5), (req, res) => {
  const files = req.files as Express.Multer.File[];
  res.json({
    count: files.length,
    files: files.map((f) => ({
      filename: f.filename,
      size: f.size,
    })),
  });
});

// 混合字段上传
app.post('/upload/post',
  upload.fields([
    { name: 'cover', maxCount: 1 },
    { name: 'attachments', maxCount: 3 },
  ]),
  (req, res) => {
    const files = req.files as { [fieldname: string]: Express.Multer.File[] };
    res.json({
      cover: files.cover?.[0]?.filename,
      attachments: files.attachments?.map((f) => f.filename),
      body: req.body,
    });
  },
);

app.listen(3000);
```

## 15.5 错误处理中间件

这是Express中最容易被误解的部分。错误处理中间件有**4个参数**，这不是可选的——Express通过参数个数来区分普通中间件和错误中间件：

```typescript
import express, { Request, Response, NextFunction } from 'express';

const app = express();
app.use(express.json());

// 自定义错误类
class AppError extends Error {
  statusCode: number;
  isOperational: boolean;

  constructor(message: string, statusCode: number = 500) {
    super(message);
    this.statusCode = statusCode;
    this.isOperational = true; // 区分可预期的业务错误和程序bug
    Error.captureStackTrace(this, this.constructor);
  }
}

class NotFoundError extends AppError {
  constructor(resource: string = 'Resource') {
    super(`${resource} not found`, 404);
  }
}

class ValidationError extends AppError {
  errors: Record<string, string>;

  constructor(errors: Record<string, string>) {
    super('Validation failed', 400);
    this.errors = errors;
  }
}

// 业务路由
app.get('/api/users/:id', async (req, res, next) => {
  try {
    const user = await findUser(req.params.id);
    if (!user) {
      throw new NotFoundError('User');
    }
    res.json(user);
  } catch (error) {
    next(error); // 传递给错误处理中间件
  }
});

// Express 5.x 支持 async/await 自动错误传递！
// 不需要 try/catch + next(error) 了
// app.get('/api/users/:id', async (req, res) => {
//   const user = await findUser(req.params.id);
//   if (!user) throw new NotFoundError('User');
//   res.json(user);
// });

// 404处理（放在所有路由之后）
app.use((req: Request, res: Response, next: NextFunction) => {
  next(new NotFoundError('Endpoint'));
});

// 错误处理中间件（4个参数！）
app.use((err: Error, req: Request, res: Response, _next: NextFunction) => {
  // 打印错误日志
  if (!(err instanceof AppError) || !err.isOperational) {
    console.error('💥 Unexpected Error:', err);
  }

  // 确定状态码
  const statusCode = err instanceof AppError ? err.statusCode : 500;

  // 构建错误响应
  const response: any = {
    success: false,
    error: {
      message: err instanceof AppError ? err.message : 'Internal Server Error',
      ...(err instanceof ValidationError && { details: err.errors }),
    },
  };

  // 开发环境下返回堆栈信息
  if (process.env.NODE_ENV === 'development') {
    response.error.stack = err.stack;
  }

  res.status(statusCode).json(response);
});

async function findUser(id: string) {
  if (id === '1') return { id: '1', name: 'Alice' };
  return null;
}

app.listen(3000);
```

> **关键点**：错误处理中间件必须有4个参数 `(err, req, res, next)`。即使你不用 `next`，也不能省略它，否则Express不会把它当作错误处理器。这是Express通过 `function.length` 来判断的。

```typescript
  tags: z.array(z.string().max(20)).max(10).optional(),
  published: z.boolean().optional(),
});

export const paginationSchema = z.object({
  page: z.coerce.number().int().positive().default(1),
  limit: z.coerce.number().int().min(1).max(100).default(10),
  sort: z.enum(['createdAt', 'updatedAt', 'title']).default('createdAt'),
  order: z.enum(['asc', 'desc']).default('desc'),
});
```

```typescript
// middleware/validate.ts
import { Request, Response, NextFunction } from 'express';
import { ZodSchema, ZodError } from 'zod';

// 通用验证中间件工厂
export function validate(schema: ZodSchema, source: 'body' | 'query' | 'params' = 'body') {
  return (req: Request, res: Response, next: NextFunction) => {
    try {
      const data = schema.parse(req[source]);
      req[source] = data; // 替换为解析后的数据（包含默认值、类型转换等）
      next();
    } catch (error) {
      if (error instanceof ZodError) {
        res.status(400).json({
          success: false,
          error: {
            message: 'Validation failed',
            details: error.errors.map((e) => ({
              field: e.path.join('.'),
              message: e.message,
            })),
          },
        });
      } else {
        next(error);
      }
    }
  };
}
```

```typescript
// repositories/post.repository.ts
import crypto from 'node:crypto';
import type { Post, CreatePostDTO, UpdatePostDTO, PaginationQuery } from '../types/index.js';

// 模拟数据库（实际项目中用Prisma/TypeORM/Drizzle等）
const posts = new Map<string, Post>();

function slugify(title: string): string {
  return title
    .toLowerCase()
    .replace(/[^a-z0-9\u4e00-\u9fa5]+/g, '-')
    .replace(/^-|-$/g, '');
}

export class PostRepository {
  async findAll(query: PaginationQuery): Promise<{ posts: Post[]; total: number }> {
    let allPosts = Array.from(posts.values());

    // 排序
    const { sort = 'createdAt', order = 'desc' } = query;
    allPosts.sort((a, b) => {
      const aVal = a[sort as keyof Post];
      const bVal = b[sort as keyof Post];
      const comparison = aVal > bVal ? 1 : aVal < bVal ? -1 : 0;
      return order === 'desc' ? -comparison : comparison;
    });

    // 分页
    const page = query.page || 1;
    const limit = query.limit || 10;
    const start = (page - 1) * limit;
    const paginatedPosts = allPosts.slice(start, start + limit);

    return { posts: paginatedPosts, total: allPosts.length };
  }

  async findById(id: string): Promise<Post | null> {
    return posts.get(id) || null;
  }

  async findBySlug(slug: string): Promise<Post | null> {
    return Array.from(posts.values()).find((p) => p.slug === slug) || null;
  }

  async create(data: CreatePostDTO, authorId: string): Promise<Post> {
    const id = crypto.randomUUID();
    const now = new Date();
    const post: Post = {
      id,
      title: data.title,
      content: data.content,
      slug: slugify(data.title) + '-' + id.slice(0, 8),
      tags: data.tags || [],
      published: data.published || false,
      authorId,
      createdAt: now,
      updatedAt: now,
    };
    posts.set(id, post);
    return post;
  }

  async update(id: string, data: UpdatePostDTO): Promise<Post | null> {
    const post = posts.get(id);
    if (!post) return null;

    if (data.title !== undefined) {
      post.title = data.title;
      post.slug = slugify(data.title) + '-' + id.slice(0, 8);
    }
    if (data.content !== undefined) post.content = data.content;
    if (data.tags !== undefined) post.tags = data.tags;
    if (data.published !== undefined) post.published = data.published;
    post.updatedAt = new Date();

    return post;
  }

  async delete(id: string): Promise<boolean> {
    return posts.delete(id);
  }
}
```

```typescript
import { PostRepository } from '../repositories/post.repository.js';

      error.statusCode = 404;
      throw error;
    }
    return post;
  }

    return this.repository.create(data, authorId);
  }

  async updatePost(id: string, data: UpdatePostDTO) {
    const post = await this.repository.update(id, data);
    if (!post) {
      const error = new Error('Post not found') as Error & { statusCode: number };
      error.statusCode = 404;
      throw error;
    }
    return post;
  }

  async deletePost(id: string) {
    const success = await this.repository.delete(id);
    if (!success) {
      const error = new Error('Post not found') as Error & { statusCode: number };
      error.statusCode = 404;
      throw error;
    }
  }
```

## 15.9 常见坑点

1. **中间件顺序很重要**：`express.json()` 必须在路由之前，错误处理必须在最后。
2. **忘记 `return`**：在条件判断中发送响应后忘记return，会继续执行后面的代码。
3. **async错误丢失**（Express 4）：async函数中的错误不会自动传递给错误处理器。
4. **`req.body` 是 undefined**：忘记加body解析中间件。
5. **循环依赖**：Controller → Service → Repository，不要反过来引用。

```typescript
// 坑：Express 4中async错误处理
// 错误会被吞掉！
app.get('/bad', async (req, res) => {
  const data = await someAsyncFunction(); // 如果这里抛错...
  res.json(data); // ...永远执行不到，请求挂起
});

// 解决方案1：手动try/catch
app.get('/good', async (req, res, next) => {
  try {
    const data = await someAsyncFunction();
    res.json(data);
  } catch (error) {
    next(error);
  }
});

// 解决方案2：包装函数
function asyncHandler(fn: Function) {
  return (req: express.Request, res: express.Response, next: express.NextFunction) => {
    Promise.resolve(fn(req, res, next)).catch(next);
  };
}

app.get('/better', asyncHandler(async (req: express.Request, res: express.Response) => {
  const data = await someAsyncFunction();
  res.json(data);
}));
```

## 15.10 本章小结

| 概念 | 关键点 |
| ------ | -------- |
| 中间件 | `(req, res, next)` 函数链，next()传递控制权 |
| 路由 | 方法+路径匹配，支持参数、正则、Router模块化 |
| 请求处理 | json(), urlencoded(), multer文件上传 |
| 错误处理 | 4参数中间件，必须放在最后 |
| 分层架构 | Controller(路由) → Service(业务) → Repository(数据) |
| Express 5 | async/await原生支持，路径匹配升级 |

**Express像什么？** 它像一把瑞士军刀——不是最专业的，但总能在关键时刻帮到你。了解了它的中间件机制，你就掌握了Node.js Web开发的"内功心法"，学其他框架都会事半功倍。
