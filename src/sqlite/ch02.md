# 第 2 章 安装与工具链 —— CLI + GUI + 语言绑定

## 2.1 幽默开场："装个数据库"这件小事

对于 MySQL 用户来说，"装个数据库"通常意味着：

1. 下载 800 MB 安装包。
2. 阅读 30 页文档搞懂 my.cnf。
3. 忘记 root 密码。
4. 重置 root 密码。
5. 再忘一次。
6. 骂骂咧咧地 Google 了一小时。
7. 终于成功，请自己吃了顿烤肉庆祝。

对于 SQLite 用户来说，"装个数据库"通常意味着：

1. **……什么？装什么？**

大部分现代操作系统已经内置了 SQLite。你 macOS 打开终端 `sqlite3` 就能用，Ubuntu 大概也已经装了，Windows 10/11 系统里也躺着一份（只是没暴露 CLI）。

不过为了保证我们用的是**同一个较新版本**（3.45+），下面还是过一遍安装流程。

## 2.2 各平台安装

### 2.2.1 macOS

macOS 系统自带 SQLite，但版本比较老。推荐用 Homebrew 装最新版：

```bash
# 检查系统自带版本
sqlite3 --version
# 3.43.2 2023-10-10 ... (可能类似这种)

# 用 Homebrew 装最新版
brew install sqlite

# brew 装的不会覆盖系统的（macOS SIP 保护），需要显式路径或加入 PATH
which sqlite3
# /usr/bin/sqlite3  ← 系统的

/opt/homebrew/opt/sqlite/bin/sqlite3 --version
# 3.45.x 2024-... ← Homebrew 装的新版

# 优先使用新版，编辑 ~/.zshrc
echo 'export PATH="/opt/homebrew/opt/sqlite/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

sqlite3 --version
# 3.45.x  ✅
```

如果你是 Intel Mac，路径是 `/usr/local/opt/sqlite/bin`。

### 2.2.2 Windows

有几种方式：

**方式一：官方预编译二进制（推荐）**

1. 访问 <https://sqlite.org/download.html>
2. 找 `sqlite-tools-win-x64-*.zip`（约 3 MB，真的就 3 MB）。
3. 解压得到 `sqlite3.exe`。
4. 放到某个目录，比如 `C:\sqlite\`。
5. 把 `C:\sqlite\` 加入系统环境变量 `PATH`。
6. 打开新的 PowerShell / cmd，敲 `sqlite3 --version` 验证。

**方式二：Scoop**

```powershell
scoop install sqlite
```

**方式三：Chocolatey**

```powershell
choco install sqlite
```

**方式四：直接用 WSL2 里的 Linux 版本**（如果你已经在用 WSL2 开发，这是最推荐的方式）。

### 2.2.3 Linux

绝大多数发行版都自带或有官方包：

```bash
# Ubuntu / Debian
sudo apt update
sudo apt install sqlite3

# CentOS / RHEL / Fedora
sudo dnf install sqlite

# Arch
sudo pacman -S sqlite

# 验证
sqlite3 --version
```

如果发行版仓库版本过旧，可以从源码编译（大约 5 分钟）：

```bash
# 下载源码
wget https://sqlite.org/2024/sqlite-autoconf-3450300.tar.gz
tar xzf sqlite-autoconf-3450300.tar.gz
cd sqlite-autoconf-3450300

# 编译 & 安装
./configure --prefix=/usr/local
make -j$(nproc)
sudo make install

# 更新动态链接库缓存
sudo ldconfig

# 验证
/usr/local/bin/sqlite3 --version
```

### 2.2.4 验证安装

无论哪个平台，最终验证：

```bash
sqlite3 --version
# 应该显示 3.45.x 或更高

# 检查编译时开启了哪些特性
sqlite3 :memory: "PRAGMA compile_options;"
# ENABLE_FTS5
# ENABLE_RTREE
# ENABLE_JSON1
# THREADSAFE=1
# ... （越多越好）
```

`compile_options` 很重要 —— 有些发行版编译时禁用了 FTS5 或 R\*Tree，用起来会一脸懵："为啥官网说有这功能，我这儿报 no such module 呢？" 答案往往是编译选项没开。

## 2.3 `sqlite3` 命令行工具详解

`sqlite3` CLI 是 SQLite 官方提供的交互式命令行客户端。它既能敲 SQL，也能敲一大堆"**点命令（dot commands）**"来做元操作。

### 2.3.1 启动方式

```bash
# 方式 1：打开或创建数据库文件
sqlite3 mydb.db

# 方式 2：纯内存数据库（退出即销毁，做实验很爽）
sqlite3 :memory:

# 方式 3：无参启动，暂时用临时内存数据库
sqlite3

# 方式 4：一次性执行 SQL 并退出
sqlite3 mydb.db "SELECT * FROM users;"

# 方式 5：从文件读 SQL 执行
sqlite3 mydb.db < schema.sql

# 方式 6：把结果写到文件
sqlite3 mydb.db "SELECT * FROM users;" > out.txt
```

进入交互模式后，你会看到：

```
SQLite version 3.45.1 2024-01-30 16:01:20
Enter ".help" for usage hints.
sqlite>
```

**这个 `sqlite>` 提示符就是你的新家了。**

### 2.3.2 常用点命令（Dot Commands）

点命令**不是 SQL**，它是 `sqlite3` CLI 内建的元命令，用 `.` 开头，**行尾不加分号**。

```sql
-- 显示所有表
.tables

-- 显示某张表的结构（SQL DDL）
.schema users

-- 显示数据库文件路径
.databases

-- 帮助
.help

-- 退出
.quit    -- 或 .exit
```

**输出格式控制** —— 这是 CLI 最实用的部分：

```sql
-- 默认输出格式 list（用 | 分隔）
.mode list

-- 表格模式（人类友好，等宽对齐）
.mode column
.headers on

-- CSV
.mode csv

-- Markdown 表格（3.35+）
.mode markdown

-- JSON（3.33+）
.mode json

-- 竖排（每行一个字段，宽表看得清）
.mode line

-- 显示列头
.headers on

-- 设定列宽（column 模式下）
.width 8 20 15

-- NULL 显示为什么（默认空字符串）
.nullvalue NULL

-- 打印当前设置
.show
```

一次实战：

```sql
sqlite> .mode column
sqlite> .headers on
sqlite> SELECT 1 AS id, 'Alice' AS name, 25 AS age;
id  name   age
--  -----  ---
1   Alice  25
```

真香。

**导入导出**：

```sql
-- 把查询结果导出到文件（Excel 打得开的 CSV）
.mode csv
.headers on
.output result.csv
SELECT * FROM users;
.output stdout   -- 恢复输出到屏幕

-- 从 CSV 导入
.mode csv
.import users.csv users
-- 会自动用文件第一行作为表结构（如果表不存在）

-- 导出整个数据库为 SQL 脚本（备份的一种方式）
.output backup.sql
.dump
.output stdout

-- 导出单张表
.dump users
```

**执行外部 SQL 文件**：

```sql
.read schema.sql
.read seed.sql
```

**性能与调试**：

```sql
-- 显示每条 SQL 耗时
.timer on

-- 显示执行计划（就是 EXPLAIN QUERY PLAN 的语法糖）
.eqp on
SELECT * FROM users WHERE email = 'a@b.com';
-- 结果里会有 SEARCH users USING INDEX idx_email ...
```

**特殊常用**：

```sql
-- 查看当前所有 PRAGMA
.pragma

-- 一键漂亮打印
.mode box
SELECT * FROM users LIMIT 3;
-- ┌────┬───────┐
-- │ id │ name  │
-- ├────┼───────┤
-- │ 1  │ Alice │
-- └────┴───────┘
```

`.mode box` 是 SQLite 3.33+ 引入的，看起来最舒服，强烈推荐加到你的 `~/.sqliterc`。

### 2.3.3 `~/.sqliterc` —— 你的专属配置

每次进 CLI 都要敲 `.mode column`、`.headers on`？太傻了。

在 `~/.sqliterc`（Windows 是 `%USERPROFILE%\.sqliterc`）写一次：

```
.mode box
.headers on
.timer on
.nullvalue NULL
.prompt "sqlite> " "   ...> "
```

以后 `sqlite3` 启动会自动加载。舒服，人性化了不少。

### 2.3.4 交互技巧

- **多行 SQL**：你按回车没执行是因为它在等分号 `;`。
- **取消当前输入**：Ctrl+C 会打断当前输入，`.cancel`（较新版本）。
- **历史命令**：↑↓ 键翻历史（依赖 readline / libedit）。
- **Tab 补全**：新版本有部分补全，主要是点命令。
- **Ctrl+D**：EOF，等价于 `.quit`。

## 2.4 GUI 图形化工具对比

命令行虽好，但看几十列的表格时你会想哭。这时候 GUI 工具登场。

### 2.4.1 DB Browser for SQLite（免费，最推荐入门）

- **网址**：<https://sqlitebrowser.org/>
- **平台**：Win / macOS / Linux 全支持。
- **特点**：轻量、免费、开源、专为 SQLite 设计。
- **优点**：表结构可视化设计、直接编辑单元格、执行 SQL、导入导出、看 blob。
- **缺点**：UI 有点复古（2010 年代画风），大数据集稍卡。
- **一句话评价**：**新手第一款、老手常备的 SQLite 专用瑞士军刀。**

### 2.4.2 DBeaver（免费社区版 + 付费企业版）

- **网址**：<https://dbeaver.io/>
- **平台**：全平台。
- **特点**：Java 写的通用 DB 工具，支持 100+ 种数据库。
- **优点**：功能强大、ER 图、数据可视化、脚本管理。
- **缺点**：吃内存（Java 应用嘛，你懂的），启动慢。
- **一句话评价**：**你的电脑里同时要连 MySQL / PostgreSQL / Oracle / SQLite，那就用它。**

### 2.4.3 TablePlus（macOS / Win，付费）

- **网址**：<https://tableplus.com/>
- **特点**：颜值高、原生 UI、快。
- **优点**：交互流畅、支持多种 DB。
- **缺点**：免费版限制打开的窗口数和 tab 数。
- **一句话评价**：**"数据库界的 Sublime Text"，颜狗必备。**

### 2.4.4 SQLiteStudio（免费）

- **网址**：<https://sqlitestudio.pl/>
- **特点**：SQLite 专用、跨平台。
- **优点**：便携版可用（免安装），插件系统。
- **缺点**：UI 也偏工程师风。
- **一句话评价**：**DB Browser 之外的另一个免费选项，各有所爱。**

### 2.4.5 命令行党的番外：`litecli`

如果你就是不喜欢 GUI，但又想要智能补全和高亮，试试 `litecli`：

## 2.5 编程语言绑定生态一览

SQLite 的绑定几乎覆盖了所有主流语言：

| **C/C++** | 官方 `sqlite3.h` | 原厂 API，底层最全 |
| **Python** | 标准库 `sqlite3` | 内置 batteries |
| **JavaScript (Node)** | `better-sqlite3` / `sqlite3` | better 是同步的、性能好 |
| **Java** | JDBC (`sqlite-jdbc`) | Xerial 的实现最主流 |
| **Kotlin (Android)** | Room + SQLiteDatabase | Android 官方 ORM |

| **C#** | `Microsoft.Data.Sqlite` / EF Core | 微软官方支持 |
| **PHP** | PDO SQLite / SQLite3 类 | 内置 |
| **Ruby** | `sqlite3` gem | 简单直接 |
| **Dart / Flutter** | `sqflite` / `drift` / `sqlite3.dart` | 我们的主角 |

## 2.6 Flutter 中使用 SQLite：sqflite vs drift

Flutter 中最主流的两个方案：

### 2.6.1 sqflite

- **定位**：轻量的 Dart wrapper，把 SQLite C API 包装成 Dart 异步 API。
- **风格**：**你写 SQL 字符串，它帮你执行。**
- **优点**：直接、简单、学习成本低、控制感强。
- **缺点**：类型安全靠自觉，SQL 拼字符串容易出错。
- **平台支持**：iOS / Android 原生（含 macOS）。桌面端需要 `sqflite_common_ffi` 通过 FFI 走。
- **心智**：**"我是 SQL 老司机，SDK 你别管我，退后。"**

### 2.6.2 drift（原名 moor）

- **定位**：Dart 优先的类型安全 ORM + Query Builder + 代码生成器。
- **风格**：**你用 Dart 描述表和查询，它帮你生成代码 + 执行 SQL。**
- **优点**：编译时类型检查、支持迁移、支持 Web / 桌面、有 Stream 响应式。
- **缺点**：需要代码生成，学习曲线陡一点点，构建时间稍长。
- **平台支持**：全平台（Mobile / Desktop / Web via wasm）。
- **心智**：**"我要类型安全，我要响应式，我要跨端，请拿去。"**

### 2.6.3 选型建议

| 场景 | 推荐 |
| --- | --- |
| 简单 App、SQL 熟手、想要极致控制 | sqflite |
| 中大型 App、跨端（含 Web / Desktop）、追求类型安全 | drift |
| 学 SQL 本身、跟着本教程走 | 主用 sqflite，进阶章节引入 drift |

**本教程 Part 1 主要用 sqflite（因为它更贴近纯 SQL），后续章节引入 drift。**

### 2.7.2 Flutter 项目初始化

创建新项目并添加依赖：

```bash
flutter create sqlite_demo
cd sqlite_demo
flutter pub add sqflite path path_provider
```

`pubspec.yaml` 会自动多出：

```yaml
dependencies:
  flutter:
    sdk: flutter
  sqflite: ^2.3.3
  path: ^1.9.0
  path_provider: ^2.1.4
```

**`sqflite`** 是数据库库，**`path`** 用于拼接文件路径，**`path_provider`** 用于拿到应用可写目录。

写一个最小的入口：`lib/db.dart`

```dart
import 'package:path/path.dart' as p;
import 'package:path_provider/path_provider.dart';
import 'package:sqflite/sqflite.dart';

class AppDb {
  static Database? _instance;

  /// 单例式获取数据库连接
  static Future<Database> get instance async {
    if (_instance != null) return _instance!;
    _instance = await _open();
    return _instance!;
  }

  static Future<Database> _open() async {
    // 1. 获取应用的可写文件目录
    final dir = await getApplicationDocumentsDirectory();
    // 2. 拼出数据库文件路径
    final dbPath = p.join(dir.path, 'mydb.db');
    // 3. 打开（若不存在则创建）
    return openDatabase(
      dbPath,
      version: 1,
      onCreate: _onCreate,
    );
  }

  static Future<void> _onCreate(Database db, int version) async {
    // 首次创建数据库时执行 DDL
    await db.execute('''
      CREATE TABLE users (
        id    INTEGER PRIMARY KEY,
        name  TEXT NOT NULL,
        email TEXT NOT NULL UNIQUE,
        age   INTEGER CHECK (age >= 0)
      );
    ''');
  }
}
```

在 `main.dart` 里调用：

```dart
import 'package:flutter/material.dart';
import 'db.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();

  final db = await AppDb.instance;

  // 插入
  await db.insert('users', {
    'name': 'Alice',
    'email': 'alice@example.com',
    'age': 25,
  });

  // 查询
  final rows = await db.query('users');
  debugPrint('users = $rows');

  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});
  @override
  Widget build(BuildContext context) => const MaterialApp(home: Scaffold());
}
```

跑起来在控制台你会看到：

```
users = [{id: 1, name: Alice, email: alice@example.com, age: 25}]
```

**你已经在 Flutter 里读写 SQLite 了。** 接下来的章节我们会把 SQL 玩到飞起。

### 2.7.3 桌面 / 单元测试环境的坑

- **默认 sqflite 只支持 iOS/Android/macOS**。想在 Windows / Linux / 单元测试里跑？加：

  ```yaml
  dependencies:
    sqflite_common_ffi: ^2.3.3
  ```

  然后在 `main()` 顶部：

  ```dart
  import 'package:sqflite_common_ffi/sqflite_ffi.dart';
  
  void main() {
    sqfliteFfiInit();
    databaseFactory = databaseFactoryFfi;
    // ...
  }
  ```

- **单元测试记得初始化 databaseFactory**，否则会报 `MissingPluginException`。

## 2.8 原理深挖：CLI 和你的代码到底跑的是不是同一个 SQLite？

答案是：**代码是同一份 C 源代码，但可能是不同版本、不同编译选项的二进制。**

- macOS 系统的 `sqlite3` 命令、Homebrew 装的 `sqlite3`、你 Flutter App 里被 sqflite 静态链接的 SQLite —— **每一个都是独立的编译产物**。
- 它们的行为高度一致（因为源代码一样），但**开启的可选模块、版本号可能不同**。
- 常见坑：CLI 里用了 FTS5 好好的，App 里报 `no such module: fts5` —— 因为 App 用的那份 SQLite 编译时没开 FTS5。sqflite 默认开了 FTS5 和 R\*Tree，但仍要关注版本。

**验证方式**：

```dart
final version = (await db.rawQuery('SELECT sqlite_version() AS v')).first['v'];
debugPrint('SQLite version in app: $version');
```

## 2.9 常见坑点

1. **多个 SQLite 版本共存导致混乱**。特别是 macOS 上，`/usr/bin/sqlite3` 和 `brew` 版本并存。开发时明确用哪个。
2. **`.import` 只在 CLI 里可用**。想在代码里做批量 CSV 导入？得自己解析或用 `PRAGMA` + 事务。
3. **`~/.sqliterc` 会影响脚本执行**。写 shell 脚本调用 `sqlite3` 时，注意行为可能被 rc 文件改变，可以加 `-init /dev/null` 屏蔽。
4. **Windows CLI 中文乱码**。`chcp 65001` 切到 UTF-8 代码页，或者用 Windows Terminal。
5. **Flutter 忘记 `WidgetsFlutterBinding.ensureInitialized()`**。在异步 `main` 里，第一个用 platform channel 的调用之前必须初始化，否则报错。
6. **sqflite 数据库不能写在 assets 目录**。assets 是只读的，需要通过 `path_provider` 拷贝到 App 沙盒目录。

## 2.10 本章小结

- 常用点命令：`.tables` / `.schema` / `.mode` / `.headers` / `.dump` / `.import` / `.output` / `.timer` / `.eqp`。
- GUI 首选 **DB Browser**（免费）或 **TablePlus**（付费颜值高）。
- Flutter 生态两大方案：**sqflite**（写 SQL）与 **drift**（Dart 声明式 + 代码生成）。
- 已经跑通了 CLI 与 Flutter 里的"第一个数据库"，下一章开始正式讲 SQL。
