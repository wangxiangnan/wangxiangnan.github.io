# 第三章 函数——Go 的核心构建块

![ch03-cover](./images/ch03-cover.png)

如果说变量是程序的"名词"，那么函数就是程序的"动词"。在 Go 的世界里，没有类、没有继承、没有复杂的面向对象体系——**函数就是你组织代码的最核心手段**。理解了函数，你就理解了 Go 程序的基本骨架。

---

## 3.1 函数基础：定义与调用

### 用 `func` 定义你的第一个函数

在 Go 中，定义函数只需要一个关键字：`func`。来看一个最简单的例子：

```go
package main

import "fmt"

// add 是一个接收两个 int 参数并返回它们之和的函数
// 注意：Go 的类型写在变量名后面，这和大多数语言不同
func add(a int, b int) int {
    return a + b // 返回值不需要加括号
}

func main() {
    // 调用函数，将结果赋给变量
    result := add(3, 5)
    fmt.Println("3 + 5 =", result) // 输出: 3 + 5 = 8
}
```

这段代码里，`add(a int, b int) int` 就是函数的**签名（signature）**。签名告诉编译器三件事：

1. **函数叫什么**——`add`
2. **需要什么输入**——两个 `int` 类型的参数
3. **产出什么**——一个 `int` 类型的返回值

> **小贴士**：如果相邻参数类型相同，可以简写为 `func add(a, b int) int`，Go 编译器完全等价对待。

### 参数传递：Go 只有值传递

这是 Go 初学者最容易误解的知识点之一。先看一段代码：

```go
package main

import "fmt"

// 试图在函数内部修改参数
func double(x int) {
    x = x * 2 // 这里修改的是 x 的副本，不影响原始变量
    fmt.Println("函数内部 x =", x) // 输出: 函数内部 x = 10
}

func main() {
    num := 5
    double(num)
    fmt.Println("函数外部 num =", num) // 输出: 函数外部 num = 5（没有变！）
}
```

**为什么 `num` 没有被修改？** 因为 Go 在传递参数时，永远是把实参的**副本**交给函数。这就像你给朋友复印了一份笔记，他在复印件上涂涂画画，你的原件完好无损。

> **类比**：想象你有一份珍贵的菜谱。值传递就是——你把菜谱复印了一份交给厨师，厨师在复印件上做标记，你的原件始终干净。这虽然多了一次"复印"的成本，但换来了**绝对的安全**：函数内部的任何操作都不会意外污染外部数据。

对于 `int`、`float64`、`string`、`bool` 这些基础类型，值传递的"复制成本"几乎可以忽略——它们只占几个字节。而对于 `struct`、`slice`、`map` 等复杂类型，我们会在后续章节详细讨论它们与值传递的关系。现在你只需要记住一条铁律：

> **Go 只有值传递，没有引用传递。** 如果你想让函数修改外部变量，需要借助"指针"（后续章节会讲）。

## 3.2 多返回值：Go 的标志性设计

大多数编程语言一个函数只能返回一个值，但 Go 打破了这个限制。这看似是一个小功能，实际上深刻影响了 Go 的整体设计哲学。

### 返回多个值

```go
package main

import "fmt"

// divide 同时返回商和余数
// 返回类型用括号包裹：(int, int) 表示返回两个 int
func divide(dividend, divisor int) (int, int) {
    quotient := dividend / divisor
    remainder := dividend % divisor
    return quotient, remainder
}

func main() {
    // 用两个变量同时接收两个返回值
    q, r := divide(17, 5)
    fmt.Printf("17 ÷ 5 = %d 余 %d\n", q, r) // 输出: 17 ÷ 5 = 3 余 2
}
```

### 用 `_` 忽略不需要的返回值

有时候你只关心部分返回值。Go 提供了"空白标识符" `_` 来丢弃你不需要的值：

```go
q, _ := divide(17, 5) // 只要商，丢弃余数
```

### 命名返回值

你可以给返回值起名字，让代码变成"自文档化"的：

```go
// 返回值的名字直接写在签名里，让调用者一目了然
func rectangleInfo(width, height float64) (area float64, perimeter float64) {
    area = width * height
    perimeter = 2 * (width + height)
    return // 注意：裸 return，自动返回命名返回值 area 和 perimeter
}
```

> **注意**：命名返回值在短函数里很好用，但函数太长时建议显式写出 `return area, perimeter`，避免可读性下降。

### 多返回值与错误处理：为什么 Go 不需要异常

这是理解 Go 哲学的关键。在其他语言中，异常（Exception）机制隐藏在正常流程之外，让错误处理变得复杂且容易遗漏。Go 用多返回值给出了一个简洁到极致的方案——**把"错误"当作一个普通的返回值返回**：

```go
package main

import (
    "errors"
    "fmt"
)

// sqrt 计算平方根，如果输入为负数则返回错误
func sqrt(x float64) (float64, error) {
    if x < 0 {
        // 返回零值和具体的错误信息
        return 0, errors.New("不能对负数求平方根")
    }
    // 简单近似（实际开发中请用 math.Sqrt）
    result := x / 2
    return result, nil // nil 表示没有错误
}

func main() {
    result, err := sqrt(25)
    if err != nil {
        // 出错时优先处理错误，绝不忽视
        fmt.Println("出错了:", err)
        return
    }
    fmt.Println("结果:", result)
}
```

这段代码体现了 Go 的核心理念：**错误是值，不是例外**。每次调用可能失败的函数，你都必须显式检查 `err`。这看起来"啰嗦"，但它让错误处理**无处可藏**——你再也不会因为忘记 `catch` 而让程序在运行时崩溃。

> **深入理解**：Go 之父 Rob Pike 说过："异常不应该用于常规控制流。" Go 用多返回值强制你面对每一个可能的错误，这比"写一个 `try-catch` 然后祈祷"要可靠得多。

## 3.3 可变参数与默认值

### 可变参数函数

当参数个数不确定时，Go 用 `...T` 语法声明可变参数：

```go
package main

import "fmt"

// sum 接收任意数量的 int 参数
// nums 的类型实际上是 []int（切片），Go 自动帮你转换
func sum(nums ...int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

func main() {
    fmt.Println(sum(1, 2))          // 输出: 3
    fmt.Println(sum(1, 2, 3, 4, 5)) // 输出: 15

    // 也可以把一个已有的切片展开传入（注意 ...）
    numbers := []int{10, 20, 30}
    fmt.Println(sum(numbers...)) // 输出: 60
}
```

> **类比**：可变参数就像一个"弹性信封"——你可以往里面塞 1 张纸条，也可以塞 100 张，函数统一用"信封"（切片）来接住所有纸条。

### Go 没有默认参数值——为什么？

Python 可以写 `def greet(name="World")`，但 Go 没有这个语法。这是刻意的设计选择。Go 信奉一个原则：**显式优于隐式**。

默认值虽然方便，但会带来几个隐患：
- 调用者可能不知道参数有默认值，阅读代码时容易困惑
- 多个默认值组合时，行为难以预测
- 函数签名无法表达"哪些参数有默认值"

Go 的替代方案是**让调用者明确写出每一个参数**。如果你确实想要"可选配置"的灵活性，Go 社区有一套成熟的方案——函数选项模式。

### 函数选项模式（Functional Options Pattern）

```go
package main

import "fmt"

// Server 代表一个服务器的配置
type Server struct {
    Port int
    Host string
}

// Option 是一个函数类型：接收 *Server 指针并修改它
type Option func(*Server)

// WithPort 返回一个 Option，用于设置端口
func WithPort(port int) Option {
    return func(s *Server) {
        s.Port = port
    }
}

// WithHost 返回一个 Option，用于设置主机
func WithHost(host string) Option {
    return func(s *Server) {
        s.Host = host
    }
}

// NewServer 创建服务器，接受任意数量的 Option
func NewServer(opts ...Option) *Server {
    // 先设置"默认值"
    s := &Server{Port: 8080, Host: "localhost"}
    // 再逐一应用用户传入的选项
    for _, opt := range opts {
        opt(s)
    }
    return s
}

func main() {
    // 使用默认配置
    s1 := NewServer()
    fmt.Printf("s1: %s:%d\n", s1.Host, s1.Port) // 输出: s1: localhost:8080

    // 覆盖端口，其他保持默认
    s2 := NewServer(WithPort(3000))
    fmt.Printf("s2: %s:%d\n", s2.Host, s2.Port) // 输出: s2: localhost:3000
}
```

这个模式在 Go 标准库和流行框架中被广泛使用。它的优点是：**默认值在函数内部明确定义，每个选项都有名字，调用者一目了然**。

## 3.4 匿名函数与闭包

### 匿名函数

在 Go 中，函数可以没有名字——它可以被定义在另一个函数内部，也可以直接赋值给变量：

```go
package main

import "fmt"

func main() {
    // 定义一个匿名函数并赋值给变量 greet
    greet := func(name string) string {
        return "你好, " + name + "!"
    }

    fmt.Println(greet("小明")) // 输出: 你好, 小明!

    // 也可以立即执行（IIFE：立即调用函数表达式）
    result := func(a, b int) int {
        return a + b
    }(3, 7)
    fmt.Println("立即执行结果:", result) // 输出: 立即执行结果: 10
}
```

### 闭包：函数 + 环境

闭包是 Go 中最强大也最精妙的特性之一。简单说，**闭包就是一个函数，它能"记住"并访问自己定义时所在作用域中的变量**。

> **类比**：普通函数就像一个"独行侠"，走到哪里都只认识自己的参数。闭包就像一个"带着背包的旅行者"——背包里装着他出发时（定义时）所在环境中的变量，无论走到哪里都能拿出来用。

```go
package main

import "fmt"

// makeCounter 返回一个闭包，这个闭包"记住"了 count 变量
func makeCounter() func() int {
    count := 0 // 这个变量被闭包"捕获"了
    return func() int {
        count++          // 每次调用，修改被捕获的 count
        return count
    }
}

func main() {
    // counter1 和 counter2 各自有独立的 count
    counter1 := makeCounter()
    counter2 := makeCounter()

    fmt.Println(counter1()) // 输出: 1
    fmt.Println(counter1()) // 输出: 2
    fmt.Println(counter1()) // 输出: 3

    fmt.Println(counter2()) // 输出: 1（独立的计数器！）
    fmt.Println(counter2()) // 输出: 2
}
```

> **深入理解**：每次调用 `makeCounter()`，Go 都会在堆上为 `count` 分配内存（因为它被闭包引用，生命周期超出了 `makeCounter` 函数本身）。这就是为什么 `counter1` 和 `counter2` 各自有独立的 `count`——它们是两次不同的调用，捕获了两个不同的变量实例。

### 闭包的实用场景：延迟执行

闭包常被用来实现"延迟执行"和"工厂函数"：

```go
package main

import "fmt"

// wrap 是一个简单的工厂函数，返回不同的打招呼函数
func wrap(greeting string) func(string) string {
    return func(name string) string {
        return greeting + ", " + name + "!"
    }
}

func main() {
    hello := wrap("Hello")
    hi := wrap("Hi")

    fmt.Println(hello("Alice")) // 输出: Hello, Alice!
    fmt.Println(hi("Bob"))     // 输出: Hi, Bob!
}
```

## 3.5 函数是一等公民

在 Go 中，函数和 `int`、`string` 一样，是**一等公民（First-Class Citizen）**。这意味着你可以：

- 把函数赋值给变量
- 把函数作为参数传递
- 从函数中返回函数
- 定义函数类型

```go
package main

import "fmt"

// MathOp 是一个函数类型：接收两个 int，返回一个 int
type MathOp func(int, int) int

// calculate 接收一个 MathOp 类型的函数作为参数
func calculate(a, b int, op MathOp) int {
    return op(a, b) // 像调用普通函数一样调用 op
}

func main() {
    // 定义两个操作函数
    add := func(a, b int) int { return a + b }
    multiply := func(a, b int) int { return a * b }

    // 把函数当作参数传递
    fmt.Println("加法:", calculate(3, 4, add))       // 输出: 加法: 7
    fmt.Println("乘法:", calculate(3, 4, multiply))   // 输出: 乘法: 12
}
```

### 实际应用：sort 包中的排序回调

Go 标准库 `sort` 包就是函数一等公民的典型应用：

```go
package main

import (
    "fmt"
    "sort"
)

func main() {
    people := []string{"Charlie", "Alice", "Bob"}

    // sort.Slice 接收一个"比较函数"作为回调
    // 你告诉它"什么算排好序"，它负责排序
    sort.Slice(people, func(i, j int) bool {
        return people[i] < people[j] // 按字母顺序
    })

    fmt.Println(people) // 输出: [Alice Bob Charlie]
}
```

这段代码非常优雅：你不需要写一个类、实现一个接口、定义一堆方法——只需要传一个小函数进去。Go 用"函数一等公民"弥补了"没有泛型类"的缺憾（在 Go 1.18 引入泛型之前，这正是 Go 表达多态的主要方式）。

## 3.6 defer：优雅的收尾

`defer` 是 Go 中最独特的关键字之一。它的语义很简单：**把一条语句"推迟"到当前函数返回之前执行**。但就是这么一个小小的机制，让 Go 代码变得异常干净。

### 执行顺序：后进先出（LIFO）

```go
package main

import "fmt"

func main() {
    fmt.Println("开始")

    defer fmt.Println("我是第一个 defer") // 第三个执行
    defer fmt.Println("我是第二个 defer") // 第二个执行
    defer fmt.Println("我是第三个 defer") // 第一个执行

    fmt.Println("结束")
}
// 输出顺序:
// 开始
// 结束
// 我是第三个 defer
// 我是第二个 defer
// 我是第一个 defer
```

> **类比**：`defer` 就像叠盘子——最后放上去的盘子最先被拿走（后进先出）。这个顺序非常符合"资源清理"的直觉：后打开的资源应该先关闭。

### 参数求值时机

一个容易踩坑的细节：**`defer` 语句在注册时就会计算参数值，而不是在执行时**：

```go
package main

import "fmt"

func main() {
    x := 10
    // 注册 defer 时，x 的值 10 就已经被"冻结"了
    defer fmt.Println("defer 中 x =", x)

    x = 999
    fmt.Println("main 中 x =", x)
}
// 输出:
// main 中 x = 999
// defer 中 x = 10  ← 注意！不是 999
```

如果你想让 defer 使用变量的最新值，可以使用闭包：`defer func() { fmt.Println(x) }()`。

### 常见用途：资源清理

`defer` 最经典的用法是确保资源被正确释放：

```go
package main

import (
    "fmt"
    "os"
)

func readFile(filename string) {
    // 打开文件
    file, err := os.Open(filename)
    if err != nil {
        fmt.Println("打开文件失败:", err)
        return
    }
    // 立刻注册关闭操作——无论函数怎么退出，file 一定会被关闭
    defer file.Close()

    // 在这里安心地读写文件...
    fmt.Println("文件已打开，正在读取...")
    // 函数结束时，defer 自动调用 file.Close()
}
```

> **深入理解**：没有 `defer` 时，你需要在函数的每个 `return` 分支都写上 `file.Close()`，一旦遗漏就会导致资源泄露。`defer` 把"清理逻辑"和"获取逻辑"放在一起，这是 Go 优雅设计的典范。

### defer 的性能考量

`defer` 在 Go 1.14 之前有明显的性能开销（大约几十纳秒），但从 Go 1.14 开始，编译器对大多数 `defer` 场景做了"栈分配优化"，开销几乎可以忽略。在普通业务代码中，你应该**毫无顾虑地使用 defer**——代码清晰度远比那几纳秒重要。

## 3.7 init 函数：程序启动前的秘密

Go 有一个特殊的函数叫 `init`，它在 `main` 函数执行**之前**自动运行。你不需要（也不能）手动调用它。

```go
package main

import "fmt"

// init 在 main 之前自动执行
func init() {
    fmt.Println("init: 程序正在初始化...")
    // 这里适合做一些启动前的准备工作
}

func main() {
    fmt.Println("main: 程序正式开始运行")
}
// 输出顺序:
// init: 程序正在初始化...
// main: 程序正式开始运行
```

### 执行顺序

在一个复杂项目中，`init` 的执行遵循以下规则：

1. **同一个包内**：按文件名的字典序依次执行各文件的 `init`
2. **跨包依赖**：先执行被依赖包的 `init`，再执行依赖方的 `init`
3. **同包多文件**：每个文件的包级变量初始化 → 该文件的 `init`

可以把它想象成"盖楼"——先打好地基（依赖包），再一层层往上盖（上层包），最后封顶（`main`）。

### 适用场景

`init` 最适合做那些"程序启动时必须完成一次"的工作：

- **注册驱动**：如数据库驱动的自动注册
- **初始化配置**：从环境变量或配置文件加载设置
- **建立映射表**：如错误码到错误消息的映射

### 慎用 init 的原因

虽然 `init` 很方便，但过度使用会带来问题：

- **执行顺序不透明**：多包多文件时，很难一眼看清 `init` 的执行顺序
- **难以测试**：`init` 自动执行，无法在测试中灵活控制
- **隐式副作用**：调用 `init` 的副作用对调用者不可见，违背了 Go"显式优于隐式"的原则

> **建议**：除非是注册类操作（如 `import _ "github.com/lib/pq"` 自动注册 PostgreSQL 驱动），否则优先考虑在 `main` 中显式调用初始化函数。

## 3.8 本章小结

回顾这一章，我们可以提炼出 Go 函数设计的几个核心理念：

**1. 一致性**：Go 的函数从签名到调用，从参数传递到返回值，都遵循一套简洁统一的规则。没有"特殊语法糖"，没有让人困惑的"引用传递"——所有参数都是值传递，所有错误都是返回值。

**2. 显式优于隐式**：没有默认参数、没有隐藏的参数绑定、没有自动类型转换。你写什么就是什么，这降低了"惊喜"（surprise）的概率。

**3. 函数即一切**：Go 没有类（class）。当 Java 程序员写 `class MathUtils { static int add(int a, int b) {...} }` 时，Go 程序员只需写 `func add(a, b int) int`。函数在 Go 中不仅是组织代码的工具，更是传递行为、实现多态、构建抽象的核心手段。

**4. 优雅的资源管理**：`defer` 让"获取即释放"成为一种编程范式，而不是需要反复提醒自己遵守的规则。

> **一句话总结**：在 Go 的世界里，函数就是一切。没有类的束缚，函数以最纯粹的方式承载了程序的全部行为。掌握函数，你就掌握了 Go 的灵魂。
