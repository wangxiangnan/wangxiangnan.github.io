# 第4章：所有权（Ownership）——Rust的灵魂

## 钥匙与房间

想象一栋大楼有很多房间，每个房间有一把钥匙。Rust 的规则很简单：

1. **每个房间同一时刻只能有一把钥匙**（所有权唯一）
2. **你可以把钥匙交给别人**（移动语义）
3. **交出钥匙后，你就不能再进那个房间了**（原变量失效）

这听起来很严格，但正是这套规则让 Rust 不需要垃圾回收器（GC）也能保证内存安全。

## 什么是所有权？

在 C/C++ 里，你手动 `malloc`/`free`，忘了 free 就内存泄漏，free 两次就崩溃。在 Java/Python/JS 里，GC（垃圾回收器）帮你管理内存，但代价是性能开销和不可预测的暂停。

Rust 的第三条路：**所有权系统**。编译器在编译时检查内存使用是否合法，不合法就不让编译。没有运行时开销，没有 GC 暂停。

## 栈 vs 堆

```
栈（Stack）                     堆（Heap）
┌─────────────┐                ┌──────────────┐
│ x: 5 (i32)  │                │ "hello world"│ ← 长度不固定
│ y: true     │                │              │
│ z: 3.14     │                └──────────────┘
└─────────────┘                   ↑
固定大小，入栈出栈极快             String 的 ptr/len/cap 存在栈上
```

- **栈**：存储固定大小的数据（i32, bool, f64 等），速度极快
- **堆**：存储动态大小的数据（String, Vec 等），需要指针指向

## 三条所有权规则

1. **每个值有且只有一个所有者（owner）**
2. **同一时刻只能有一个所有者**
3. **当所有者离开作用域，值被丢弃（drop）**

```rust
fn main() {
    {
        let s = String::from("hello"); // s 进入作用域，获得所有权
        println!("{s}");
    }   // s 离开作用域，String 自动释放内存（调用 drop）

    // println!("{s}");  // 编译错误：s 已不存在
}
```

## 移动语义（Move）

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;  // s1 的所有权"移动"给了 s2

    // println!("{s1}");  // 编译错误！s1 已经无效
    println!("{s2}");     // 正常
}
```

**发生了什么？**

```
之前：
s1 → 堆上的 "hello"

之后：
s1 → ✗ （已失效）
s2 → 堆上的 "hello"
```

Rust 不会像 C++ 那样做深拷贝（性能开销大），也不会像 Python/JS 那样增加引用计数（运行时开销）。Rust 选择"移动"——直接把指针交给新变量，旧变量立即失效。

> **对比 Python**：
>
> ```python
> a = [1, 2, 3]
> b = a        # a 和 b 指向同一个列表
> b.append(4)
> print(a)     # [1, 2, 3, 4] — a 也被修改了！
> ```
>
> Rust 的移动语义从根本上杜绝了这种"隐式共享"带来的 bug。

## 基本类型的 Copy

等一下，为什么这段代码没问题？

```rust
fn main() {
    let x = 5;
    let y = x;      // 这里是"复制"，不是"移动"
    println!("{x}"); // 正常！x 仍然有效
    println!("{y}");
}
```

因为 `i32` 等简单类型实现了 `Copy` trait。对于存在栈上的小数据，复制成本极低，所以 Rust 选择复制而不是移动。

**哪些类型是 Copy？**

- 所有整数类型（i32, u64 等）
- `bool`
- `f32`, `f64`
- `char`
- 只包含 Copy 类型的元组，如 `(i32, bool)`

**哪些类型不是 Copy？**

- `String`（数据在堆上）
- `Vec<T>`
- 大多数自定义类型

## Clone：显式深拷贝

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone();  // 显式深拷贝

    println!("s1 = {s1}"); // 正常
    println!("s2 = {s2}"); // 正常
}
```

`clone()` 会复制堆上的数据，代价较高。Rust 让你**显式**调用，就是要你清楚知道"这里在做一件昂贵的事情"。

## 函数参数的所有权

```rust
fn takes_ownership(s: String) {
    println!("拿到了: {s}");
}   // s 在此被 drop

fn gives_ownership() -> String {
    String::from("我是礼物")
}

fn takes_and_gives_back(s: String) -> String {
    s  // 把所有权还回去
}

fn main() {
    let s = String::from("hello");
    takes_ownership(s);
    // s 已经被移动，不可用

    let s2 = gives_ownership();
    println!("{s2}"); // "我是礼物"

    let s3 = String::from("来回传递");
    let s3 = takes_and_gives_back(s3); // 所有权出去又回来
    println!("{s3}");
}
```

> **这太麻烦了吧？** 是的，每次传参都要考虑所有权确实繁琐。这就是为什么 Rust 有**引用和借用**机制（第5章），让你在不转移所有权的情况下使用数据。

## 返回值与所有权

```rust
fn create_and_return() -> (String, usize) {
    let s = String::from("hello");
    let len = s.len();
    (s, len)  // 把 s 的所有权和 len 一起返回
}

fn main() {
    let (text, length) = create_and_return();
    println!("{text} 长度为 {length}");
}
```

## 常见陷阱

1. **移动后继续使用**：最常见的编译错误，编译器会明确告诉你 "value used here after move"
2. **混淆 Copy 和 Move**：基本类型是 Copy，String/Vec 是 Move
3. **忘记 clone 的代价**：`clone()` 做深拷贝，大字符串 clone 很贵
4. **以为函数调用不转移所有权**：传 String 给函数默认会转移所有权

## 小结

- Rust 用所有权系统在编译时管理内存，无 GC 开销
- 每个值只有一个所有者，所有者离开作用域时值被 drop
- 赋值/传参默认是"移动"（堆数据）或"复制"（栈数据）
- `clone()` 做显式深拷贝，代价高但安全
- 函数参数涉及所有权转移，下一章的"引用"解决这个问题
