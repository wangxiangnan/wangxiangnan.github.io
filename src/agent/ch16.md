# 第16章 LangGraph Agent实战 —— 构建DocMind推理引擎

## 16.1 开篇：这是本教程最核心的章节

欢迎来到本教程的"心脏"章节。在前面三章中，我们分别学习了：

- **Function Calling**（Ch13）：Agent调用工具的协议
- **ReAct**（Ch13）：Agent推理与行动的模式
- **LangGraph**（Ch15）：Agent编排的状态图引擎

现在，我们要把这三者**融合**在一起，构建一个真正可用的、生产级的Agent。

我们要做的事情，用一句话说就是：**用LangGraph构建一个带Function Calling的ReAct Agent。**

> 用编程的话说：如果Function Calling是"接口协议"，ReAct是"设计模式"，LangGraph是"运行框架"，那么本章就是"把接口、模式和框架整合成一个可运行的服务"。

## 16.2 架构设计

在动手写代码之前，先理清架构。我们的DocMind Agent本质上是一个**两节点图**：

```
START --> agent --(有tool_calls)--> tools --(执行完毕)--> agent
           |
           +--(没有tool_calls)--> END
```

- **Agent节点**：调用LLM，LLM可能返回文本回复，也可能返回tool_calls
- **Tool节点**：执行工具调用，返回ToolMessage
- **条件路由**：检查Agent的输出，如果有tool_calls就走Tool节点，否则走END

这就是一个**带循环的两节点图**。简单，但极其强大。

## 16.3 完整代码：逐行解析

这是本章最重要的代码段。每一行都有关键注释，请仔细阅读。

```python
"""
DocMind推理引擎 - LangGraph Agent完整实现
这是本教程的核心代码，请逐行理解

架构：Agent节点 <--> Tool节点，条件路由决定是否继续
"""

# ============================================================
# 导入部分
# ============================================================
from typing import TypedDict, Annotated, Literal
import json

# LangGraph核心
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.prebuilt import ToolNode

# LangChain核心
from langchain_core.messages import (
    HumanMessage,      # 用户消息
    AIMessage,         # AI消息（可能包含tool_calls）
    SystemMessage,     # 系统消息
    ToolMessage        # 工具结果消息
)
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI


# ============================================================
# 第一部分：定义State（Agent的"全局状态"）
# ============================================================

class AgentState(TypedDict):
    """
    DocMind Agent的状态定义
    
    为什么只有messages一个字段？
    - messages包含了整个对话历史（用户消息、AI回复、工具结果）
    - 使用add_messages reducer，新消息自动追加而非覆盖
    - 所有需要的信息（搜索结果、计算结果等）都在ToolMessage中
    - 这是一种"消息即状态"的设计模式
    """
    messages: Annotated[list, add_messages]
    # 关键：Annotated + add_messages = 消息追加模式
    # 每次节点返回 {"messages": [new_msg]}
    # new_msg会被追加到messages列表末尾
    # 而不是替换整个列表


# ============================================================
# 第二部分：定义工具（Agent的"能力"）
# ============================================================

@tool
def search_documents(query: str, top_k: int = 3) -> str:
    """在DocMind知识库中搜索相关文档。
    当用户询问技术概念、项目信息、最佳实践等事实性问题时使用。
    
    Args:
        query: 搜索关键词，越具体越准确
        top_k: 返回结果数量，默认3条
    """
    # 模拟向量数据库（实际项目中替换为真实的向量检索）
    knowledge_base = [
        {
            "title": "AI Agent架构概述",
            "content": "AI Agent由三个核心部分组成：1) LLM作为推理引擎和决策大脑；"
                       "2) Memory（记忆系统）包括短期记忆和长期记忆；"
                       "3) Tools（工具集）让Agent能与外部世界交互。",
            "source": "agent_architecture.md",
            "relevance": 0.96
        },
        {
            "title": "ReAct模式深度解析",
            "content": "ReAct让LLM交替进行推理和行动。核心循环：Thought->Action->"
                       "Observation->重复直到信息充分->Answer。",
            "source": "react_pattern.md",
            "relevance": 0.93
        },
        {
            "title": "LangGraph状态图编排",
            "content": "LangGraph是状态图编排引擎。核心概念：State、Node、Edge、"
                       "Conditional Edge。支持循环、条件分支、人机协作。",
            "source": "langgraph_guide.md",
            "relevance": 0.91
        },
        {
            "title": "RAG检索增强生成",
            "content": "RAG通过检索外部文档增强LLM回答能力。流程：文档加载->分块->"
                       "向量化->存储->检索->生成。",
            "source": "rag_tutorial.md",
            "relevance": 0.89
        },
        {
            "title": "Function Calling协议",
            "content": "Function Calling是LLM调用工具的标准协议。返回结构化tool_calls。"
                       "支持并行调用。主流LLM都支持。",
            "source": "function_calling.md",
            "relevance": 0.87
        }
    ]
    
    # 简单的关键词匹配（生产中用向量相似度）
    results = []
    query_words = query.lower().split()
    
    for doc in knowledge_base:
        score = sum(1 for w in query_words 
                    if w in doc["content"].lower() or w in doc["title"].lower())
        if score > 0:
            results.append({**doc, "match_score": score})
    
    results.sort(key=lambda x: x["match_score"], reverse=True)
    results = results[:top_k]
    
    if not results:
        return f"未找到与'{query}'相关的文档。建议尝试不同的关键词。"
    
    output = f"找到 {len(results)} 条相关文档：\n\n"
    for i, doc in enumerate(results, 1):
        output += f"[{i}] {doc['title']} (来源: {doc['source']})\n"
        output += f"    {doc['content']}\n\n"
    
    return output


@tool
def calculate(expression: str, precision: int = 2) -> str:
    """执行数学计算。当需要数值计算、比例分析、统计量计算时使用。
    
    Args:
        expression: Python数学表达式，如 '(100 - 30) / 100 * 100'
        precision: 结果精度（小数位数），默认2位
    """
    try:
        safe_builtins = {
            "abs": abs, "round": round, "min": min, "max": max,
            "sum": sum, "pow": pow, "len": len, "int": int, "float": float
        }
        result = eval(expression, {"__builtins__": safe_builtins}, {})
        return f"计算结果: {expression} = {round(float(result), precision)}"
    except SyntaxError:
        return f"表达式语法错误: '{expression}'。请使用合法的Python数学表达式。"
    except ZeroDivisionError:
        return "除数不能为零。"
    except Exception as e:
        return f"计算失败: {str(e)}。请检查表达式。"


@tool
def get_system_status() -> str:
    """获取DocMind系统的当前状态信息，包括知识库统计和系统健康状况。
    当用户询问系统状态、知识库规模等信息时使用。
    """
    return json.dumps({
        "status": "healthy",
        "knowledge_base": {
            "total_documents": 1247,
            "total_chunks": 15832,
            "embedding_model": "text-embedding-3-small",
            "vector_dimension": 1536
        },
        "last_updated": "2025-01-15T10:30:00Z",
        "active_users": 23
    }, ensure_ascii=False)


# 工具列表和映射
tools = [search_documents, calculate, get_system_status]
tool_map = {t.name: t for t in tools}


# ============================================================
# 第三部分：创建LLM（Agent的"大脑"）
# ============================================================

llm = ChatOpenAI(model="gpt-4o", temperature=0)

# 绑定工具到LLM
# bind_tools()将工具定义转换为JSON Schema，每次调用时发送给模型
llm_with_tools = llm.bind_tools(tools)

# System Prompt——Agent的"宪法"
SYSTEM_PROMPT = """你是DocMind——一个智能文档问答助手。

## 你的身份
你由以下部分组成：
- 大脑：GPT-4o大语言模型
- 记忆：文档知识库（通过search_documents工具检索）
- 能力：文档搜索、数学计算、系统状态查询

## 工作原则
1. 事实性问题必须使用search_documents搜索后再回答，不要凭空编造
2. 数值计算必须使用calculate工具，不要心算
3. 回答要准确、简洁、有依据
4. 如果搜索结果不足以回答，如实告知用户
5. 使用中文回答
"""


# ============================================================
# 第四部分：定义Agent节点（核心逻辑）
# ============================================================

def agent_node(state: AgentState) -> dict:
    """
    Agent节点：调用LLM，生成回复或工具调用请求
    
    这是整个Agent的"大脑"。它做一件事：
    把当前所有消息（包括用户输入、历史对话、工具结果）
    喂给LLM，让LLM决定：
    1. 直接给出文字回答？
    2. 还是调用工具获取更多信息？
    
    参数:
        state: 当前Agent状态，包含所有消息历史
    
    返回:
        dict: 包含新消息的字典（会被add_messages reducer追加到状态中）
    """
    
    # 获取当前消息列表
    messages = state["messages"]
    
    # 如果第一条消息不是SystemMessage，插入系统提示
    # 这确保LLM始终知道自己的角色和行为准则
    if not messages or not isinstance(messages[0], SystemMessage):
        messages = [SystemMessage(content=SYSTEM_PROMPT)] + messages
    
    # 调用LLM（带工具绑定）
    # LLM可能返回：
    # 1. AIMessage(content="文字回答") —— 不需要工具
    # 2. AIMessage(tool_calls=[...]) —— 需要调用工具
    response = llm_with_tools.invoke(messages)
    
    # 返回新消息
    # 因为messages字段使用了add_messages reducer
    # response会被追加到消息列表末尾
    return {"messages": [response]}


# ============================================================
# 第五部分：定义条件路由函数
# ============================================================

def should_continue(state: AgentState) -> Literal["tools", "__end__"]:
    """
    条件路由：决定下一步走工具节点还是结束
    
    这是LangGraph Agent的核心控制逻辑：
    - 检查最后一条AI消息是否包含tool_calls
    - 有tool_calls -> 走工具节点（执行工具）
    - 没有tool_calls -> 走END（给出最终回答）
    
    类比：这就像一个门卫，检查Agent的"出门证"
    - 如果Agent说"我还需要查资料"（有tool_calls）-> 放它去工具室
    - 如果Agent说"我已经知道答案了"（没有tool_calls）-> 放它出门
    """
    
    # 获取最后一条消息
    last_message = state["messages"][-1]
    
    # 检查是否有工具调用请求
    # AIMessage.tool_calls是一个列表：
    # - 空列表 [] -> 没有工具调用
    # - 非空列表 [tc1, tc2, ...] -> 有工具调用
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "tools"      # 有工具调用 -> 路由到工具节点
    else:
        return "__end__"    # 没有工具调用 -> 路由到结束节点


# ============================================================
# 第六部分：创建Tool节点
# ============================================================

# LangGraph内置的ToolNode
# 它自动处理：解析tool_calls -> 执行对应工具 -> 生成ToolMessage
# 我们只需要告诉它有哪些工具可用
tool_node = ToolNode(tools)


# ============================================================
# 第七部分：构建和编译图
# ============================================================

def build_agent_graph():
    """
    构建DocMind Agent的LangGraph
    
    图结构：
    START -> agent --(有tool_calls)--> tools --(执行完毕)--> agent
              |
              +--(没有tool_calls)--> END
    """
    
    # 1. 创建StateGraph
    # StateGraph接收一个TypedDict作为状态定义
    graph = StateGraph(AgentState)
    
    # 2. 添加节点
    graph.add_node("agent", agent_node)      # Agent节点（调用LLM）
    graph.add_node("tools", tool_node)        # Tool节点（执行工具）
    
    # 3. 添加边
    # 入口 -> Agent节点（所有请求都从Agent开始）
    graph.add_edge(START, "agent")
    
    # Tool节点 -> Agent节点（工具执行完后，让Agent看到结果继续推理）
    # 这就是循环的关键！
    graph.add_edge("tools", "agent")
    
    # 4. 添加条件边
    # Agent节点 -> 根据should_continue函数的返回值决定下一步
    graph.add_conditional_edges(
        "agent",           # 从agent节点出发
        should_continue,   # 路由函数
    )
    
    # 5. 编译图
    return graph.compile()


# ============================================================
# 第八部分：创建Agent实例
# ============================================================

docmind_agent = build_agent_graph()


# ============================================================
# 第九部分：使用Agent
# ============================================================

def ask_docmind(question: str, verbose: bool = True) -> str:
    """
    向DocMind提问
    
    参数:
        question: 用户问题
        verbose: 是否打印执行过程
    
    返回:
        Agent的最终回答
    """
    if verbose:
        print(f"\n{'='*60}")
        print(f"问题: {question}")
        print(f"{'='*60}")
    
    # invoke()执行整个图，返回最终状态
    result = docmind_agent.invoke({
        "messages": [HumanMessage(content=question)]
    })
    
    # 打印执行过程
    if verbose:
        for msg in result["messages"]:
            msg_type = msg.__class__.__name__
            if msg_type == "SystemMessage":
                continue
            elif msg_type == "HumanMessage":
                print(f"  [用户] {msg.content}")
            elif msg_type == "AIMessage":
                if msg.tool_calls:
                    for tc in msg.tool_calls:
                        print(f"  [AI调用] {tc['name']}({tc['args']})")
                elif msg.content:
                    print(f"  [AI回答] {msg.content[:200]}")
            elif msg_type == "ToolMessage":
                print(f"  [工具结果] {msg.content[:150]}...")
    
    # 返回最后一条AI消息的内容
    final_message = result["messages"][-1]
    return final_message.content


def stream_docmind(question: str):
    """
    流式执行DocMind（实时显示每个节点的执行）
    """
    print(f"\n{'='*60}")
    print(f"问题: {question}")
    print(f"{'='*60}")
    print("执行过程:")
    
    for event in docmind_agent.stream({
        "messages": [HumanMessage(content=question)]
    }):
        for node_name, node_output in event.items():
            print(f"\n  --- 节点 '{node_name}' 执行完毕 ---")
            
            if "messages" in node_output:
                for msg in node_output["messages"]:
                    msg_type = msg.__class__.__name__
                    if msg_type == "AIMessage":
                        if msg.tool_calls:
                            for tc in msg.tool_calls:
                                print(f"    调用: {tc['name']}({json.dumps(tc['args'], ensure_ascii=False)})")
                        else:
                            print(f"    回答: {msg.content[:200]}")
                    elif msg_type == "ToolMessage":
                        print(f"    工具结果: {msg.content[:150]}")
    
    print(f"\n{'='*60}")


# ============================================================
# 第十部分：测试各种场景
# ============================================================

if __name__ == "__main__":
    
    # 场景1：直接回答（不需要工具）
    print("\n场景1: 直接回答")
    ask_docmind("你好，你叫什么名字？")
    # 预期：Agent直接回复，不调用任何工具
    
    # 场景2：单工具调用
    print("\n场景2: 单工具调用")
    ask_docmind("什么是AI Agent？")
    # 预期：Agent调用search_documents，基于搜索结果回答
    
    # 场景3：多工具串联
    print("\n场景3: 多工具串联")
    ask_docmind("搜索RAG的信息，然后计算15832个文档分块，每块500token，总共多少token？")
    # 预期：先search_documents，再calculate，最后综合回答
    
    # 场景4：流式执行
    print("\n场景4: 流式执行")
    stream_docmind("帮我查一下DocMind系统的状态")
```

## 16.4 代码深度解析

### 16.4.1 为什么Agent节点和Tool节点形成循环？

```python
graph.add_edge("tools", "agent")  # Tool执行完 -> 回到Agent
graph.add_conditional_edges("agent", should_continue)  # Agent决定下一步
```

这个设计模拟了ReAct的核心循环：

1. Agent思考并决定调用工具（返回tool_calls）
2. Tool节点执行工具（返回ToolMessage）
3. Agent看到工具结果，继续思考
4. 如果还需要更多信息，再次调用工具（回到步骤2）
5. 如果信息充分，给出最终回答（结束）

> 类比：这就像一个研究员的工作模式——去图书馆查资料（Tool），回来写论文（Agent），发现还缺资料（tool_calls），再去图书馆（Tool），直到论文写完（END）。

### 16.4.2 ToolNode做了什么？

```python
tool_node = ToolNode(tools)
```

`ToolNode`是LangGraph内置的"工具执行器"。它做了以下事情：

1. 从最后一条AIMessage中提取所有`tool_calls`
2. 对每个`tool_call`，在工具列表中查找对应的工具
3. 用`tool_call.args`调用工具函数
4. 将每个工具的执行结果包装成`ToolMessage`
5. 返回`{"messages": [tool_msg1, tool_msg2, ...]}`

**错误处理**：如果工具执行出错，ToolNode不会崩溃，而是生成一个包含错误信息的ToolMessage，让Agent知道发生了什么。

### 16.4.3 错误做法 vs 正确做法

```python
# ---- 错误做法1：忘记绑定工具 ----
llm = ChatOpenAI(model="gpt-4o")
# 没有 llm.bind_tools(tools)
# 结果：LLM永远不会返回tool_calls，Agent变成了纯聊天机器人

# ---- 错误做法2：忘记添加tools->agent的边 ----
graph.add_edge(START, "agent")
graph.add_conditional_edges("agent", should_continue)
# 没有 graph.add_edge("tools", "agent")
# 结果：工具执行完后，图不知道该去哪，直接结束

# ---- 错误做法3：条件路由返回值不匹配 ----
def should_continue(state):
    if state["messages"][-1].tool_calls:
        return "continue"  # 但图中没有叫"continue"的节点！
    return "stop"          # 也没有"stop"节点！
# 结果：compile()报错或运行时KeyError

# ---- 正确做法 ----
llm_with_tools = llm.bind_tools(tools)          # 绑定工具
graph.add_edge("tools", "agent")                 # 循环边
graph.add_conditional_edges("agent", should_continue)  # 返回节点名
```

## 16.5 高级特性：自定义Tool节点

内置的ToolNode很方便，但有时我们需要自定义工具执行逻辑：

```python
"""
自定义Tool节点：添加日志、权限检查、超时控制
"""
import time
from langchain_core.messages import ToolMessage

def custom_tool_node(state: AgentState) -> dict:
    """
    自定义工具节点
    在内置ToolNode的基础上添加：
    - 执行日志
    - 权限检查
    - 超时控制
    """
    last_message = state["messages"][-1]
    tool_messages = []
    
    for tool_call in last_message.tool_calls:
        tool_name = tool_call["name"]
        tool_args = tool_call["args"]
        tool_id = tool_call["id"]
        
        print(f"\n  [自定义Tool节点]")
        print(f"    工具: {tool_name}")
        print(f"    参数: {tool_args}")
        
        # 权限检查：某些工具需要特殊权限
        restricted_tools = ["delete_document", "modify_system"]
        if tool_name in restricted_tools:
            print(f"    状态: 被拒绝（需要管理员权限）")
            tool_messages.append(ToolMessage(
                content=json.dumps({
                    "error": f"工具 '{tool_name}' 需要管理员权限，当前用户无权使用"
                }, ensure_ascii=False),
                tool_call_id=tool_id,
                name=tool_name
            ))
            continue
        
        # 执行工具
        start_time = time.time()
        try:
            if tool_name in tool_map:
                result = tool_map[tool_name].invoke(tool_args)
                elapsed = time.time() - start_time
                print(f"    状态: 成功 ({elapsed:.2f}s)")
                
                tool_messages.append(ToolMessage(
                    content=json.dumps(result, ensure_ascii=False) if isinstance(result, dict) else str(result),
                    tool_call_id=tool_id,
                    name=tool_name
                ))
            else:
                print(f"    状态: 工具不存在")
                tool_messages.append(ToolMessage(
                    content=f"错误：工具 '{tool_name}' 不存在",
                    tool_call_id=tool_id,
                    name=tool_name
                ))
        except Exception as e:
            elapsed = time.time() - start_time
            print(f"    状态: 失败 ({elapsed:.2f}s) - {str(e)}")
            tool_messages.append(ToolMessage(
                content=f"工具执行失败: {str(e)}",
                tool_call_id=tool_id,
                name=tool_name
            ))
    
    return {"messages": tool_messages}
```

## 16.6 添加Recursion Limit（安全阀）

```python
"""
设置递归限制：防止Agent无限循环
"""

# 方法1：编译时设置
app = graph.compile()
result = app.invoke(
    {"messages": [HumanMessage(content="你好")]},
    config={"recursion_limit": 10}  # 最多执行10个节点
)

# 方法2：全局默认
from langgraph.checkpoint.memory import MemorySaver

app = graph.compile(checkpointer=MemorySaver())

# 在Agent图中，一次完整的工具调用循环消耗2个节点
# (agent + tools)，所以recursion_limit=10意味着最多5轮工具调用
# 根据实际需求调整这个值
```

> ⚠️ **默认的recursion_limit是25**。如果你的Agent需要执行超过12轮工具调用，需要增大这个值。但一般来说，超过10轮工具调用说明问题设计有问题——要么问题太复杂应该拆分，要么工具不够好。

## 16.8 本章小结

本章我们完成了DocMind的LangGraph实现——这是整个教程的核心：

### 架构总结

```
核心组件：
1. AgentState (TypedDict + add_messages)  -> 消息列表状态
2. agent_node (LLM + bind_tools)          -> 决策大脑
3. tool_node (ToolNode)                   -> 工具执行器
4. should_continue (条件路由)              -> 流程控制

图结构：
START -> agent <--> tools
           |
           +-> END (当没有tool_calls时)
```

### 关键收获

1. **Agent节点调用LLM，Tool节点执行工具**——两个节点形成循环
2. **条件路由函数是Agent的"门卫"**——决定是继续工作还是结束
3. **ToolNode是内置的工具执行器**——自动处理tool_calls解析和执行
4. **消息即状态**——所有信息都通过消息列表传递
5. **递归限制是安全阀**——防止Agent陷入无限循环
