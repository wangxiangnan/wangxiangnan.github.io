# 第13章：JSON1模块——SQLite变文档数据库

## 13.1 引言：关系与文档的世纪之争

十年前，NoSQL运动风起云涌，MongoDB这类文档数据库高举"Schemaless"大旗攻城略地，宣称："关系型数据库该退休了！"

十年后，我们发现：

- MongoDB加了事务、加了Schema校验，越来越像关系数据库
- PostgreSQL、MySQL加了JSON列，越来越像文档数据库
- 大家握手言和：**结构化字段用列存，半结构化数据用JSON存**

SQLite当然也没落下。它有一个叫**JSON1**的扩展，从**SQLite 3.38（2022年2月）开始直接内置**，不需要再手动启用。今天我们就来看，如何用SQLite把关系与文档"通吃"。

想象一下：你做一个电商App，商品有些字段是所有商品都有的（名字、价格、库存），有些字段是每个类目专属的（衣服有尺码颜色，图书有作者ISBN，食品有保质期）。传统方案要么建N张表（麻烦），要么建一张有几十列大部分为NULL的巨表（丑）。JSON列的方案：核心字段用列，专属字段塞JSON。**既保持SQL的严谨，又拥有文档的灵活。**

这就是JSON1的价值。

## 13.2 JSON支持的历史

- **SQLite 3.9.0（2015）**：作为可选扩展JSON1模块首次出现
- **SQLite 3.38.0（2022）**：JSON1**默认编译进核心**，同时引入了`->`和`->>`操作符
- **SQLite 3.45.0（2024）**：JSONB二进制格式加入，性能进一步提升

我们的教程针对**3.45+**，所以你能享受到最新的功能。

## 13.3 JSON值的存储：TEXT还是BLOB？

在SQLite里，JSON数据存在TEXT列里，就是普通字符串。**SQLite不校验它是不是合法的JSON**——如果你想存的就是普通字符串，塞进去也不会报错。

但从3.45开始，SQLite引入了**JSONB**——一种紧凑的二进制格式，存在BLOB列里，读写更快。

```sql
-- 创建表：用TEXT存JSON
CREATE TABLE products (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    price REAL,
    attributes TEXT   -- 就是普通TEXT
);

-- 插入
INSERT INTO products(name, price, attributes) VALUES 
  ('iPhone 15', 5999.0, '{"color": "black", "storage": "256GB", "5g": true}'),
  ('T-Shirt', 99.0, '{"color": "white", "size": ["S", "M", "L"], "material": "cotton"}');
```

## 13.4 json()函数：验证与规范化

`json()`函数做两件事：**验证**输入是合法JSON，**规范化**输出（去除多余空格）。

```sql
-- 验证 + 格式化
SELECT json('{"a": 1,  "b" : 2}');
-- 结果：{"a":1,"b":2}

-- 非法JSON会报错
SELECT json('{a: 1}');
-- Error: malformed JSON

-- 用于约束：只允许合法JSON
CREATE TABLE docs (
    id INTEGER PRIMARY KEY,
    data TEXT CHECK (json_valid(data))
);
```

`json_valid()`函数只做验证，返回0或1：

```sql
SELECT json_valid('{"a":1}');    -- 1
SELECT json_valid('not json');   -- 0
```

## 13.5 路径表达式：JSON的"XPath"

要在JSON里找某个值，你需要**路径表达式**。它长得像JavaScript的属性访问：

- `$` — 根节点
- `$.name` — 根对象的name字段
- `$.address.city` — 嵌套字段
- `$.tags[0]` — 数组的第一个元素
- `$.tags[#-1]` — 数组的最后一个元素（`#`是数组长度）
- `$.items[1].price` — 组合访问

```sql
-- 示例数据
CREATE TABLE t (data TEXT);
INSERT INTO t VALUES ('{
  "name": "Alice",
  "age": 30,
  "address": {"city": "Shanghai", "zip": "200000"},
  "hobbies": ["reading", "coding", "gaming"]
}');

SELECT json_extract(data, '$.name') FROM t;        -- Alice
SELECT json_extract(data, '$.address.city') FROM t; -- Shanghai
SELECT json_extract(data, '$.hobbies[1]') FROM t;   -- coding
SELECT json_extract(data, '$.hobbies[#-1]') FROM t; -- gaming
```

## 13.6 提取值：json_extract vs -> vs ->>

从3.38开始，SQLite支持了两个新操作符（跟PostgreSQL对齐）：

- `->` — 提取，**结果仍是JSON**（对象/数组不解开）
- `->>` — 提取，**结果是SQL值**（字符串/数字/NULL）

```sql
SELECT json_extract(data, '$.name') FROM t;  -- 'Alice'（TEXT）
SELECT data -> '$.name' FROM t;              -- '"Alice"'（JSON字符串）
SELECT data ->> '$.name' FROM t;             -- 'Alice'（TEXT）

-- 嵌套
SELECT data -> '$.address' FROM t;
-- 返回：{"city":"Shanghai","zip":"200000"}（JSON）

SELECT data ->> '$.address' FROM t;
-- 返回：{"city":"Shanghai","zip":"200000"}（TEXT，同一份字符串）

-- 数字类型
SELECT data ->> '$.age' FROM t;  -- 30（INTEGER）
SELECT data ->> '$.age' + 5 FROM t;  -- 35（可以直接算数）
```

**记忆诀窍**：

- 一个箭头`->` = 保持JSON类型，可以继续`->`往下走
- 两个箭头`->>` = 拆到底，返回SQL基本类型

```sql
-- 链式：先取address对象，再取city
SELECT data -> '$.address' ->> '$.city' FROM t;
-- 结果：Shanghai
```

在3.38之前，你只能写`json_extract(data, '$.address.city')`。3.38之后两种写法等价，推荐用`->>`（更简洁、跟其他DB兼容）。

## 13.7 修改：set/insert/replace/remove

四兄弟，各有分工：

| 函数 | 存在时 | 不存在时 |
| ------ | -------- | ---------- |
| `json_set` | 更新 | 创建 |
| `json_insert` | 保持不变 | 创建 |
| `json_replace` | 更新 | 保持不变 |
| `json_remove` | 删除 | 保持不变 |

```sql
-- 原始
SELECT json('{"a": 1, "b": 2}') AS orig;

-- json_set：如果不存在就创建，存在就更新
SELECT json_set('{"a": 1}', '$.a', 100, '$.c', 3);
-- 结果：{"a":100,"c":3}

-- json_insert：只在不存在时创建
SELECT json_insert('{"a": 1}', '$.a', 100, '$.c', 3);
-- 结果：{"a":1,"c":3}  ← a没变，c新增

-- json_replace：只在存在时更新
SELECT json_replace('{"a": 1}', '$.a', 100, '$.c', 3);
-- 结果：{"a":100}  ← c没被创建

-- json_remove：删除路径
SELECT json_remove('{"a": 1, "b": 2}', '$.a');
-- 结果：{"b":2}
```

### 13.7.1 UPDATE中的用法

```sql
-- 给所有产品加一个"warranty"字段（存在就更新，不存在就新增）
UPDATE products 
SET attributes = json_set(attributes, '$.warranty', '2 years');

-- 只更新iPhone的颜色
UPDATE products 
SET attributes = json_set(attributes, '$.color', 'blue')
WHERE name = 'iPhone 15';

-- 给数组追加一个元素
UPDATE products 
SET attributes = json_set(
    attributes, 
    '$.tags[#]',  -- '#'表示"末尾"
    'featured'
)
WHERE id = 1;

-- 删除某个字段
UPDATE products 
SET attributes = json_remove(attributes, '$.deprecated');
```

## 13.8 数组操作

```sql
-- 创建数组
SELECT json_array(1, 2, 'three', json('{"nested": true}'));
-- 结果：[1,2,"three",{"nested":true}]

-- 数组长度
SELECT json_array_length('[1,2,3,4]');  -- 4
SELECT json_array_length('{"a":1}', '$.tags');  
-- 从JSON里取路径下的数组长度

-- 判断数组是否包含（3.45+）
-- 注意：SQLite本身没有json_contains，需要用json_each变通
SELECT EXISTS (
    SELECT 1 FROM json_each('[1,2,3]') WHERE value = 2
);
```

## 13.9 展开：json_each 和 json_tree

这两个是**表函数**（table-valued function），把JSON展开成关系表。神器级功能。

### 13.9.1 json_each：浅遍历

```sql
-- 遍历一个数组
SELECT * FROM json_each('[10, 20, 30]');
```

结果：

| key | value | type    | atom | id | parent | fullkey | path |
|-----|-------|---------|------|-----|--------|---------|------|
| 0   | 10    | integer | 10   | 1   |        | $[0]    | $    |
| 1   | 20    | integer | 20   | 2   |        | $[1]    | $    |
| 2   | 30    | integer | 30   | 3   |        | $[2]    | $    |

```sql
-- 遍历一个对象
SELECT key, value FROM json_each('{"a": 1, "b": "hello"}');
-- key='a' value=1
-- key='b' value='hello'
```

**实战：找出所有产品的所有tag**

```sql
CREATE TABLE items (
    id INTEGER PRIMARY KEY,
    name TEXT,
    data TEXT  -- {"tags": ["hot", "sale"]}
);

INSERT INTO items(name, data) VALUES
  ('A', '{"tags": ["hot", "sale"]}'),
  ('B', '{"tags": ["new", "sale"]}'),
  ('C', '{"tags": ["hot", "premium"]}');

-- 展开所有tag，统计出现次数
SELECT je.value AS tag, COUNT(*) AS cnt
FROM items i, json_each(i.data, '$.tags') je
GROUP BY je.value
ORDER BY cnt DESC;
```

结果：

| tag      | cnt |
|----------|-----|
| hot      | 2   |
| sale     | 2   |
| new      | 1   |
| premium  | 1   |

### 13.9.2 json_tree：深度遍历

`json_each`只展开顶层，`json_tree`递归展开所有嵌套：

```sql
SELECT fullkey, value, type 
FROM json_tree('{"a": {"b": [1, 2]}, "c": true}');
```

这会遍历所有节点，包括嵌套对象和数组里的每个值。

**实战：找JSON里所有等于某值的路径**

```sql
-- 找所有值为true的字段路径
SELECT fullkey 
FROM json_tree('{"a": true, "b": {"c": false, "d": true}}')
WHERE type = 'true';
-- 结果：$.a  和  $.b.d
```

## 13.10 JSON列上的索引：表达式索引救场

普通索引只能索引"一整列"，但JSON里有很多字段，我们想按JSON里的某个字段快速查询。

**普通查询很慢：**

```sql
SELECT * FROM products WHERE json_extract(attributes, '$.color') = 'red';
-- 全表扫描！要读每一行，解析JSON，判断color=red
```

**救星：表达式索引（Expression Index）**

```sql
CREATE INDEX idx_products_color 
ON products (json_extract(attributes, '$.color'));

-- 或者用->>操作符（更简洁）
CREATE INDEX idx_products_color 
ON products (attributes ->> '$.color');
```

现在同样的查询会用上索引：

```sql
EXPLAIN QUERY PLAN
SELECT * FROM products WHERE attributes ->> '$.color' = 'red';
-- SEARCH products USING INDEX idx_products_color
```

**重要：查询里的表达式必须跟索引里的完全一样**，否则用不上索引。

### 13.10.1 部分索引 + JSON

```sql
-- 只索引"5G手机"（假设一半产品是5G）
CREATE INDEX idx_5g_phones ON products (name) 
WHERE attributes ->> '$.5g' = 'true';
```

这样索引会小很多，节省空间。

## 13.11 生成列 + JSON字段：黄金组合

SQLite支持**生成列（Generated Columns）**，可以基于其他列自动计算一个"虚拟列"。

**语法：**

```sql
CREATE TABLE products (
    id INTEGER PRIMARY KEY,
    name TEXT,
    attributes TEXT,
    
    -- 从JSON里抽出来做成"普通列"
    color TEXT GENERATED ALWAYS AS (attributes ->> '$.color') VIRTUAL,
    storage TEXT GENERATED ALWAYS AS (attributes ->> '$.storage') VIRTUAL,
    is_5g INTEGER GENERATED ALWAYS AS (attributes ->> '$.5g') VIRTUAL
);

-- 插入时不用管这些"虚拟列"，它们会自动填充
INSERT INTO products(name, attributes) 
VALUES ('iPhone 15', '{"color": "black", "storage": "256GB", "5g": true}');

-- 查询就跟普通列一样
SELECT name, color, storage FROM products WHERE color = 'black';
```

**VIRTUAL vs STORED**：

- **VIRTUAL**（默认）：每次读取时动态计算，**不占存储**
- **STORED**：写入时计算，**占存储但读取快**

对于JSON抽取字段，一般用VIRTUAL就够了（计算开销小），配合索引：

```sql
-- 给虚拟列建索引（这才是重点！）
CREATE INDEX idx_products_color ON products (color);
CREATE INDEX idx_products_5g ON products (is_5g);
```

这样你既有了"表面看起来的关系表"，又有JSON的灵活性。查询代码不用改，写JSON字段就能自动加索引。

## 13.12 SQLite JSON vs PostgreSQL JSONB

有人问：SQLite的JSON跟PostgreSQL的JSONB比呢？

| 项目          | SQLite (TEXT/JSONB) | PostgreSQL JSONB      |
|---------------|----------------------|------------------------|
| 存储格式      | TEXT 或 3.45+ JSONB二进制 | 二进制               |
| 解析开销      | TEXT每次读取都要解析<br>JSONB无需解析 | 无需解析（存的就是解析后的）|
| 索引          | 表达式索引            | GIN倒排索引，更强大   |
| 修改性能      | 整体重写JSON字段      | 也是整体重写          |
| 查询语法      | `json_extract`/`->`/`->>` | `->`/`->>`/`@>`/`?` |
| 大小          | 更小（无schema overhead）| 更大（存了类型信息）|

**结论**：SQLite的JSON对于中小型应用完全够用。移动App、桌面App、内嵌数据库——JSON1都能搞定。真需要海量JSON文档、复杂查询？那你可能已经该上Postgres了。

## 13.13 实战案例：电商商品目录

设计一个商品系统，核心字段用列，类目专属属性用JSON。

```sql
-- 类目表
CREATE TABLE categories (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL UNIQUE
);

INSERT INTO categories(name) VALUES ('phone'), ('clothing'), ('book');

-- 商品表
CREATE TABLE products (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    sku TEXT UNIQUE NOT NULL,
    name TEXT NOT NULL,
    category_id INTEGER NOT NULL REFERENCES categories(id),
    price REAL NOT NULL CHECK (price >= 0),
    stock INTEGER DEFAULT 0,
    
    -- 类目专属属性存JSON
    attributes TEXT CHECK (json_valid(attributes)),
    
    created_at INTEGER DEFAULT (unixepoch()),
    
    -- 常用查询字段做成生成列
    brand TEXT GENERATED ALWAYS AS (attributes ->> '$.brand') VIRTUAL,
    color TEXT GENERATED ALWAYS AS (attributes ->> '$.color') VIRTUAL
);

-- 索引
CREATE INDEX idx_products_category ON products(category_id);
CREATE INDEX idx_products_brand ON products(brand);
CREATE INDEX idx_products_color ON products(color);
CREATE INDEX idx_products_price ON products(price);

-- 插入手机
INSERT INTO products(sku, name, category_id, price, stock, attributes) VALUES 
('SKU-P001', 'iPhone 15', 1, 5999, 100, json_object(
    'brand', 'Apple',
    'color', 'black',
    'storage', '256GB',
    'screen', 6.1,
    'os', 'iOS',
    '5g', json('true')
));

-- 插入衣服
INSERT INTO products(sku, name, category_id, price, stock, attributes) VALUES 
('SKU-C001', 'Cotton T-Shirt', 2, 99, 500, json_object(
    'brand', 'Uniqlo',
    'color', 'white',
    'size', json_array('S', 'M', 'L', 'XL'),
    'material', 'cotton',
    'season', 'summer'
));

-- 插入图书
INSERT INTO products(sku, name, category_id, price, stock, attributes) VALUES 
('SKU-B001', 'SQLite实战', 3, 89, 200, json_object(
    'author', '张三',
    'isbn', '9787111111111',
    'publisher', '机械工业出版社',
    'pages', 500,
    'language', 'zh-CN'
));
```

**查询示例：**

```sql
-- 1. 找所有黑色手机
SELECT * FROM products p
JOIN categories c ON c.id = p.category_id
WHERE c.name = 'phone' AND p.color = 'black';

-- 2. 找有货的iPhone
SELECT * FROM products 
WHERE brand = 'Apple' AND stock > 0;

-- 3. 找有'L'码的衣服
SELECT * FROM products 
WHERE category_id = (SELECT id FROM categories WHERE name = 'clothing')
  AND EXISTS (
    SELECT 1 FROM json_each(attributes, '$.size') 
    WHERE value = 'L'
  );

-- 4. 更新库存
UPDATE products SET stock = stock - 1 WHERE id = 1;

-- 5. 给一款手机加一个"limited_edition"标签
UPDATE products 
SET attributes = json_set(attributes, '$.limited_edition', json('true'))
WHERE sku = 'SKU-P001';

-- 6. 统计各品牌的商品数
SELECT brand, COUNT(*) AS cnt 
FROM products 
WHERE brand IS NOT NULL
GROUP BY brand
ORDER BY cnt DESC;
```

## 13.14 Flutter实战：Dart对象与JSON列的drift集成

drift支持**类型转换器（Type Converter）**，可以在Dart对象和JSON字符串之间自动转换。

```dart
// 1. 定义你的Dart模型
class ProductAttributes {
  final String? brand;
  final String? color;
  final Map<String, dynamic> extras;
  
  ProductAttributes({
    this.brand,
    this.color,
    this.extras = const {},
  });
  
  factory ProductAttributes.fromJson(Map<String, dynamic> json) {
    final brand = json.remove('brand') as String?;
    final color = json.remove('color') as String?;
    return ProductAttributes(brand: brand, color: color, extras: json);
  }
  
  Map<String, dynamic> toJson() => {
    if (brand != null) 'brand': brand,
    if (color != null) 'color': color,
    ...extras,
  };
}

// 2. 定义类型转换器
class ProductAttributesConverter 
    extends TypeConverter<ProductAttributes, String> {
  const ProductAttributesConverter();
  
  @override
  ProductAttributes fromSql(String fromDb) {
    if (fromDb.isEmpty) return ProductAttributes();
    return ProductAttributes.fromJson(
      jsonDecode(fromDb) as Map<String, dynamic>
    );
  }
  
  @override
  String toSql(ProductAttributes value) => jsonEncode(value.toJson());
}

// 3. 定义drift表
class Products extends Table {
  IntColumn get id => integer().autoIncrement()();
  TextColumn get sku => text().unique()();
  TextColumn get name => text()();
  IntColumn get categoryId => integer().references(Categories, #id)();
  RealColumn get price => real()();
  IntColumn get stock => integer().withDefault(const Constant(0))();
  
  // JSON列，自动转换
  TextColumn get attributes => 
      text().map(const ProductAttributesConverter())();
  
  DateTimeColumn get createdAt => 
      dateTime().withDefault(currentDateAndTime)();
}

// 4. 使用
@DriftDatabase(tables: [Products, Categories])
class AppDatabase extends _$AppDatabase {
  Future<int> addProduct({
    required String sku,
    required String name,
    required int categoryId,
    required double price,
    required ProductAttributes attributes,
  }) async {
    return into(products).insert(ProductsCompanion.insert(
      sku: sku,
      name: name,
      categoryId: categoryId,
      price: price,
      attributes: attributes,
    ));
  }
  
  /// 查询：找特定颜色的商品
  Future<List<Product>> findByColor(String color) async {
    // drift支持自定义SQL访问JSON字段
    return await (customSelect(
      "SELECT * FROM products WHERE attributes ->> '\$.color' = ?",
      variables: [Variable.withString(color)],
      readsFrom: {products},
    ).map((row) => products.map(row.data)).get());
  }
  
  /// 更新JSON字段
  Future<void> updateColor(int productId, String newColor) async {
    // 应用层：先读，改，写回
    final product = await (select(products)
        ..where((t) => t.id.equals(productId)))
        .getSingle();
    
    final newAttrs = ProductAttributes(
      brand: product.attributes.brand,
      color: newColor,
      extras: product.attributes.extras,
    );
    
    await (update(products)..where((t) => t.id.equals(productId)))
        .write(ProductsCompanion(attributes: Value(newAttrs)));
  }
  
  /// 或者在SQL层更新（更高效，不用先读）
  Future<void> updateColorInSql(int productId, String newColor) async {
    await customUpdate(
      "UPDATE products SET attributes = json_set(attributes, '\$.color', ?) WHERE id = ?",
      variables: [
        Variable.withString(newColor),
        Variable.withInt(productId),
      ],
      updates: {products},
    );
  }
}
```

**使用体验：**

```dart
final db = AppDatabase();

// 插入：像操作普通对象一样
await db.addProduct(
  sku: 'SKU-P001',
  name: 'iPhone 15',
  categoryId: 1,
  price: 5999.0,
  attributes: ProductAttributes(
    brand: 'Apple',
    color: 'black',
    extras: {
      'storage': '256GB',
      'screen': 6.1,
      '5g': true,
    },
  ),
);

// 查询
final blackPhones = await db.findByColor('black');
for (final p in blackPhones) {
  print('${p.name}: ${p.attributes.brand} - ${p.attributes.color}');
}
```

## 13.15 原理深挖：JSONB到底快在哪

3.45之前，SQLite的JSON是**文本存储**：

- 存的时候：直接是字符串
- 读的时候：每次都要parse文本、找路径、返回值
- 修改的时候：先parse、再生成新字符串、整体重写

3.45+ 引入了**JSONB二进制格式**：

```sql
-- 转成JSONB
SELECT jsonb('{"a":1,"b":2}');
-- 返回一个BLOB，不是文本

-- 存BLOB更快
CREATE TABLE fast_json (
    data BLOB   -- 用BLOB存jsonb
);

INSERT INTO fast_json VALUES (jsonb('{"x":1}'));
```

JSONB用了**tag-length-value**编码，跟MessagePack、CBOR类似：

```
[Type Tag][Length][Value][Type Tag][Length][Value]...
```

好处：

1. **无需parse**：直接跳到需要的偏移量
2. **原地更新可能**：如果新值和旧值一样大，可以就地改
3. **紧凑**：数字用二进制存，不用把"123"存成三个字节

代价：

1. **不能人读**：肉眼看BLOB就是一堆乱码
2. **兼容性**：老版本SQLite读不了

**建议**：3.45+ 且不需要外部工具直接看数据 → 用JSONB。反之用TEXT。

## 13.16 常见坑点

### 坑1：JSON里的布尔值

SQLite本身没有布尔类型。你写`json_extract('{"a": true}', '$.a')`，返回的是`1`（整数），不是`true`（字符串）。

要保持JSON里的true/false语义：

```sql
-- 用json()包裹以保持JSON类型
SELECT json_object('flag', json('true'));
-- 结果：{"flag":true}

-- 不这样做：
SELECT json_object('flag', 'true');
-- 结果：{"flag":"true"}  ← 变成字符串了！

SELECT json_object('flag', 1);
-- 结果：{"flag":1}  ← 变成数字了！
```

### 坑2：路径不存在

```sql
SELECT json_extract('{"a":1}', '$.nonexistent');
-- 返回：NULL（不报错）

-- 如果想区分"null值"和"不存在"，用json_type
SELECT json_type('{"a":null}', '$.a');   -- 'null'
SELECT json_type('{"a":null}', '$.b');   -- NULL（表示路径不存在）
```

### 坑3：修改JSON会重写整个字段

```sql
-- 这个UPDATE：
UPDATE big_json_table 
SET data = json_set(data, '$.small_field', 'x');
```

不是"只改small_field"，而是"读整个data，改，写回整个data"。如果data有1MB，就有1MB的写入放大。**JSON适合中小型文档，不适合超大对象。**

### 坑4：索引匹配的坑

```sql
CREATE INDEX idx1 ON t (json_extract(data, '$.a'));

-- 用得上索引
SELECT * FROM t WHERE json_extract(data, '$.a') = 5;

-- 用不上！虽然逻辑等价
SELECT * FROM t WHERE data ->> '$.a' = 5;
```

因为索引里存的是`json_extract`的结果，查询用`->>`可能类型不同（`->>`返回SQL基本类型，`json_extract`可能返回JSON文本）。建索引和查询要用**同一种表达式**。

### 坑5：CHECK约束的成本

```sql
CREATE TABLE t (
    data TEXT CHECK (json_valid(data))
);
```

每次INSERT/UPDATE都要跑一遍json_valid。大量写入的场景下有开销。可以在应用层保证JSON合法，跳过这个约束。

### 坑6：中文字符的转义

```sql
SELECT json('{"name": "张三"}');
-- 结果：{"name":"张三"}  ← SQLite默认不转义UTF-8

-- 但有些工具期望\uXXXX转义
SELECT json_quote('张三');
-- 结果：'"张三"'  ← 加引号但不转义
```

跟其他系统交互JSON时注意编码问题。

## 13.17 本章小结

- SQLite从3.38开始内置JSON1模块，3.45+ 支持JSONB二进制
- `json_extract` / `->` / `->>` 是提取三剑客
- `json_set/insert/replace/remove` 是修改四兄弟
- `json_each` 和 `json_tree` 把JSON变关系表
- **生成列 + 表达式索引** 是JSON字段快速查询的黄金搭档
- 用SQLite做"文档数据库"，中小规模完全够用
- Flutter中通过drift的TypeConverter可以让Dart对象和JSON列无缝互转
