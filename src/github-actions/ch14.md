# 第14章：完整实战——Python 项目 CI/CD

## 14.1 引言：Python 项目的独特挑战

如果说 Node.js 是"标准化流水线上的常客"，那 Python 项目就是"需要更多注意力的VIP客人"。Python 世界有几个让人头疼的特点：多版本兼容（你的代码可能需要在 Python 3.9、3.10、3.11、3.12 上都能跑）、数据库集成测试（不像 Node.js 那么容易 mock）、代码质量工具繁多（pytest、flake8、black、mypy……）。

不过别担心，GitHub Actions 的 Matrix Strategy（矩阵策略）正是为这种"多版本并行测试"的场景量身定制的。本章我们将以一个 FastAPI 项目为例，构建一条健壮的 Python CI/CD 流水线。

## 14.3 多 Python 版本测试：Matrix Strategy 登场

为什么需要测试多个 Python 版本？因为你的库或应用可能运行在不同用户的环境中。如果你的 `pyproject.toml` 声称支持 Python 3.9+，那你最好真的在每个版本上都测一遍——否则就是"承诺过度，交付不足"。

Matrix Strategy 就像一台"平行宇宙生成器"：你定义一组变量，GitHub Actions 会自动生成所有排列组合，为每个组合创建一个独立的 Job。

## 14.4 数据库集成测试：GitHub Services

很多 Python Web 应用都离不开数据库。在 CI 中跑数据库测试有几种方案：

1. **SQLite 内存数据库**：速度快，但和生产环境的 PostgreSQL 行为有差异。
2. **Docker Compose**：灵活但配置复杂。
3. **GitHub Services**：最推荐的方式！GitHub 会在 runner 上自动启动一个 Docker 容器作为"服务"，你的测试代码可以直接连接。

GitHub Services 就像给 runner 配了一个"助手"——runner 跑你的代码，服务容器跑数据库，两者通过 localhost 通信。

## 14.5 代码质量三件套

Python 生态中，代码质量检查通常有三个独立工具，各司其职：

- **black**：代码格式化器。它像一台"自动排版机"，不管你原来怎么写，它都能给你统一成一种风格。团队中再也不用为"缩进用空格还是 tab"而吵架。
- **flake8**：代码风格检查器。它像一个"语法警察"，检查未使用的 import、过长的行、不符合 PEP8 规范的地方。
- **pytest**：测试框架。它是 Python 世界的"测试瑞士军刀"，功能强大且插件丰富。

## 14.6 完整的 Workflow YAML 文件

```yaml
# .github/workflows/ci-cd.yml
name: Python CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

env:
  REGISTRY: ghcr.io
  IMAGE_NAME: ${{ github.repository }}

jobs:
  # ========== 代码质量检查 ==========
  quality:
    name: 🔍 Code Quality
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'
          # 缓存 pip 依赖，避免每次都重新下载
          cache: 'pip'

      - name: Install dev dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements-dev.txt

      # Black 检查：--check 表示只检查不修改
      # 如果代码格式不符合 black 规范，命令会返回非零退出码
      - name: Check formatting with Black
        run: black --check --diff app/ tests/

      # Flake8 检查：使用 pyproject.toml 中的配置
      - name: Lint with Flake8
        run: flake8 app/ tests/ --count --statistics --show-source

  # ========== 多版本测试（Matrix Strategy）==========
  test:
    name: 🧪 Test (Python ${{ matrix.python-version }})
    runs-on: ubuntu-latest
    needs: quality

    # Matrix Strategy：定义变量的所有排列组合
    strategy:
      fail-fast: false
      # fail-fast: false 表示即使某个版本失败了，
      # 其他版本仍会继续运行（方便看到所有问题）
      matrix:
        python-version: ['3.9', '3.10', '3.11', '3.12']

    # GitHub Services：启动一个 PostgreSQL 容器
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_USER: testuser
          POSTGRES_PASSWORD: testpass
          POSTGRES_DB: testdb
        ports:
          - 5432:5432
        # 健康检查：等 PostgreSQL 完全启动后再继续
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Python ${{ matrix.python-version }}
        uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
          cache: 'pip'

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt
          pip install -r requirements-dev.txt

      # 运行数据库迁移（确保表结构就绪）
      - name: Run database migrations
        run: alembic upgrade head
        env:
          DATABASE_URL: postgresql://testuser:testpass@localhost:5432/testdb

      # 运行 pytest，生成 JUnit XML 报告
      - name: Run tests with pytest
        run: |
          pytest tests/ \
            --verbose \
            --cov=app \
            --cov-report=xml \
            --cov-report=html \
            --junitxml=test-results.xml \
            -x
        env:
          DATABASE_URL: postgresql://testuser:testpass@localhost:5432/testdb
          SECRET_KEY: test-secret-for-ci-only

      # 上传测试结果（GitHub 会在 PR 中显示）
      - name: Upload test results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: test-results-py${{ matrix.python-version }}
          path: |
            test-results.xml
            htmlcov/
          retention-days: 7

  # ========== 构建 Docker 镜像 ==========
  build:
    name: 🏗️ Build & Push Docker Image
    runs-on: ubuntu-latest
    needs: test
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    permissions:
      contents: read
      packages: write
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Extract metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}
          tags: |
            type=sha,prefix=
            type=ref,event=branch
            type=semver,pattern={{version}}

      - name: Build and push Docker image
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

  # ========== 部署 ==========
  deploy:
    name: 🚀 Deploy to Production
    runs-on: ubuntu-latest
    needs: build
    environment:
      name: production
      url: https://api.example.com
    steps:
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.PROD_HOST }}
          username: ${{ secrets.PROD_USER }}
          key: ${{ secrets.PROD_SSH_KEY }}
          script: |
            cd /opt/my-python-api
            docker compose pull
            docker compose up -d
            # 等待应用启动完成并检查健康状态
            timeout 60 bash -c 'until curl -sf http://localhost:8000/health; do sleep 3; done'
            echo "Deployment successful!"
```

## 14.7 Matrix Strategy 详解

上面的 `matrix.python-version: ['3.9', '3.10', '3.11', '3.12']` 会生成 4 个并行的 Job。你还可以组合多个维度：

```yaml
matrix:
  python-version: ['3.10', '3.11', '3.12']
  os: [ubuntu-latest, windows-latest]
```

这会生成 3 × 2 = 6 个 Job。就像排列组合——每个 Python 版本 × 每个操作系统 = 一个独立的测试环境。

如果你想排除某个特定组合：

```yaml
matrix:
  python-version: ['3.10', '3.11', '3.12']
  os: [ubuntu-latest, windows-latest]
  exclude:
    - python-version: '3.10'
      os: windows-latest
```

## 14.8 Docker 镜像构建与推送

对于 Python 项目，Dockerfile 通常长这样：

```dockerfile
# 使用官方的 slim 镜像，减小体积
FROM python:3.12-slim

# 设置工作目录
WORKDIR /app

# 先复制依赖文件，利用 Docker 层缓存
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 再复制应用代码
COPY . .

# 暴露端口
EXPOSE 8000

# 使用 gunicorn 作为生产 WSGI/ASGI 服务器
CMD ["gunicorn", "app.main:app", "-w", "4", "-k", "uvicorn.workers.UvicornWorker", "-b", "0.0.0.0:8000"]
```

这里的技巧是先 `COPY requirements.txt` 再 `pip install`，最后才 `COPY . .`。这样当代码变更但依赖不变时，Docker 会复用前面的缓存层，大大加速构建。就像做菜时先准备好所有配料，再开始烹饪——效率远高于边做边找。

## 14.9 小结

Python CI/CD 的关键在于：Matrix Strategy 保证多版本兼容，GitHub Services 解决数据库集成测试，代码质量三件套（black + flake8 + pytest）确保代码的"外在美观"和"内在正确"。本章的 Workflow 模板可以直接拿去用到你自己的项目中。
