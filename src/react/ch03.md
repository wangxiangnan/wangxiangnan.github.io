# 第3章：JSX — JavaScript 的"变形金刚"

![第3章封面](./images/ch03.png)

> *"JSX 看起来像 HTML，闻起来像 HTML，但它不是 HTML——它是披着 HTML 外衣的 JavaScript。"*

## 3.1 引言：第一次见到 JSX 的反应

每个初学者第一次看到 JSX 代码时，心里大概都是这个反应：

> "等等……这是 HTML 还是 JavaScript？为什么 HTML 里面有 JavaScript 的东西？这合法吗？"

别慌，你的反应完全正常。JSX 确实是 JavaScript 和 HTML 的"混血儿"——它结合了两种语言的优点，创造出一种全新的语法。一旦你习惯了它，你会发现它比把 HTML 和 JavaScript 分开写要直观得多。

> **比喻时间：** JSX 就像一个翻译官。你用它写"人类能看懂的标签"（类似 HTML），它帮你翻译成"React 能理解的函数调用"（`React.createElement`）。你不需要学会 React 的"方言"，JSX 翻译官帮你搞定一切。

## 3.2 JSX 是什么？

**JSX** 全称 **JavaScript XML**，是 JavaScript 语法的一种扩展。它允许你在 JavaScript 代码中写类似 HTML 的标签。

```jsx
// 这是一段 JSX 代码
const greeting = <h1>你好，世界！</h1>;

// 在 React 组件中使用 JSX
function Welcome() {
  return <p>欢迎来到 React 的世界</p>;
}
```

你可能会问："浏览器能理解 JSX 吗？"

答案是：**不能**。浏览器只认识纯 JavaScript。JSX 需要通过编译器（比如 Babel，Vite 内置了）转换成纯 JavaScript 才能运行。

## 3.3 JSX 的本质：语法糖

这是一个很重要的概念——**JSX 只是 `React.createElement()` 的语法糖**。

什么是语法糖？就是让代码写起来更甜（更方便）的东西，但它本质上还是普通的 JavaScript。

```jsx
// 你写的 JSX
const element = <h1 className="title">你好，React！</h1>;

// 编译后变成的 JavaScript
const element = React.createElement(
  'h1',                          // 标签名
  { className: 'title' },        // 属性（注意这里用的是 className）
  '你好，React！'                 // 子元素
);
```

两者完全等价！JSX 只是让你用更直观的方式写代码。想想看，如果每次都要写 `React.createElement`，那代码得有多长多难读：

```jsx
// 没有 JSX 的话，写一个简单的卡片组件会变成这样
function Card() {
  return React.createElement(
    'div',
    { className: 'card' },
    React.createElement('h2', null, '标题'),
    React.createElement('p', null, '这是一段描述文字'),
    React.createElement(
      'button',
      { onClick: handleClick },
      '点击我'
    )
  );
}

// 有了 JSX，同样的组件清爽多了
function Card() {
  return (
    <div className="card">
      <h2>标题</h2>
      <p>这是一段描述文字</p>
      <button onClick={handleClick}>点击我</button>
    </div>
  );
}
```

看到差距了吧？JSX 让你的代码像 HTML 一样直观，同时又有 JavaScript 的全部能力。这就是它被称为"变形金刚"的原因——它把两种语言的优势合二为一。

## 3.4 JSX 的核心语法规则

JSX 有几条必须遵守的规则，掌握了这些规则，你就掌握了 JSX 的 80%。

### 规则一：只能返回一个根元素

JSX 表达式必须有一个唯一的根元素来包裹所有内容。

```jsx
// ❌ 错误：返回了两个并列的元素
function Bad() {
  return (
    <h1>标题</h1>
    <p>内容</p>
  );
}

// ✅ 正确：用一个 div 包裹
function Good1() {
  return (
    <div>
      <h1>标题</h1>
      <p>内容</p>
    </div>
  );
}

// ✅ 更好：用 Fragment（<>...</>）包裹，不会多出一个 DOM 元素
function Good2() {
  return (
    <>
      <h1>标题</h1>
      <p>内容</p>
    </>
  );
}
```

> [!TIP] 提示
> `<>...</>` 是 `<React.Fragment>...</React.Fragment>` 的简写。它就像一个隐形的盒子，不会在最终生成的 HTML 中产生任何标签。当你不需要额外的样式或属性时，优先使用 `<>` 而不是 `<div>`。

### 规则二：用 `className` 代替 `class`

因为 `class` 是 JavaScript 的保留关键字（用来定义类的），所以 JSX 中要用 `className` 来指定 CSS 类名。

```jsx
// ❌ 错误
<div class="container">内容</div>

// ✅ 正确
<div className="container">内容</div>

// 多个类名用空格分隔，和 HTML 一样
<div className="container main-content">内容</div>
```

类似地，`for` 属性要写成 `htmlFor`：

```jsx
// ❌ 错误
<label for="name">姓名</label>

// ✅ 正确
<label htmlFor="name">姓名</label>
```

> [!WARNING] 注意
> 这是新手最常犯的错误之一！如果你发现样式没有生效，先检查一下是不是把 `className` 写成了 `class`。React 不会报错，只是静默忽略它。

### 规则三：标签必须闭合

所有的 JSX 标签都必须正确闭合，包括那些在 HTML 中可以自闭合的标签。

```jsx
// ❌ 错误（HTML 中可以，JSX 中不行）
<img src="photo.jpg">
<br>
<input type="text">

// ✅ 正确（自闭合标签要加 /）
<img src="photo.jpg" />
<br />
<input type="text" />
```

### 规则四：使用驼峰命名

JSX 中的属性名使用 **驼峰命名法（camelCase）**，而不是 HTML 中的全小写。

```jsx
// ❌ HTML 写法
<div onclick="handleClick()">
  <svg viewbox="0 0 100 100">
    <rect stroke-width="2"></rect>
  </svg>
</div>

// ✅ JSX 写法
<div onClick={handleClick}>
  <svg viewBox="0 0 100 100">
    <rect strokeWidth="2"></rect>
  </svg>
</div>
```

## 3.5 在 JSX 中使用表达式：`{}` 的魔法

JSX 最强大的地方在于——你可以在大括号 `{}` 中嵌入任何 **JavaScript 表达式**。

```jsx
function ExpressionDemo() {
  const name = '小明';
  const age = 18;
  const hobbies = ['编程', '游戏', '读书'];

  return (
    <div>
      {/* 使用变量 */}
      <p>姓名：{name}</p>

      {/* 使用表达式 */}
      <p>明年我就 {age + 1} 岁了</p>

      {/* 调用方法 */}
      <p>名字大写：{name.toUpperCase()}</p>

      {/* 使用数组方法 */}
      <p>爱好数量：{hobbies.length} 个</p>

      {/* 使用模板字符串 */}
      <p>{`${name}，今年 ${age} 岁`}</p>
    </div>
  );
}
```

> [!WARNING] 注意
> `{}` 里面只能放 **表达式**（expression），不能放 **语句**（statement）。也就是说，你不能在里面写 `if/else`、`for` 循环、`const`/`let` 声明等。但你可以用三元运算符、函数调用等来替代。

```jsx
// ❌ 不能这样写
<p>{if (age >= 18) { return '成年人' }}</p>

// ✅ 用三元运算符
<p>{age >= 18 ? '成年人' : '未成年'}</p>
```

### 在 JSX 中使用内联样式

JSX 中的内联样式是一个 **JavaScript 对象**，属性名用驼峰命名，值用字符串：

```jsx
function StyleDemo() {
  // 样式对象的属性名用驼峰命名
  const titleStyle = {
    color: '#333',
    fontSize: '24px',
    fontWeight: 'bold',
    backgroundColor: '#f0f0f0',  // 不是 background-color
    padding: '10px',
    borderRadius: '8px',         // 不是 border-radius
  };

  return (
    <div>
      {/* 使用样式对象 */}
      <h1 style={titleStyle}>我是带样式的标题</h1>

      {/* 直接写样式对象 */}
      <p style={{ color: 'red', fontSize: '16px' }}>
        我是红色的文字
      </p>
    </div>
  );
}
```

::: v-pre
> [!TIP] 提示
> 注意 `style={{ ... }}` 的双重大括号——外层 `{}` 表示"这是一个 JS 表达式"，内层 `{}` 是一个对象。很多人第一次见到会觉得奇怪，但理解了这个原理就觉得很自然了。
:::

## 3.6 条件渲染：让界面"有脑子"

在 React 中，我们经常需要根据不同的条件显示不同的内容。比如：用户登录了显示个人信息，没登录显示登录按钮。

JSX 提供了三种条件渲染的方式：

### 方式一：三元运算符 `? :`

适合简单的"二选一"场景。

```jsx
function UserStatus({ isLoggedIn }) {
  return (
    <div>
      {isLoggedIn ? (
        <p>欢迎回来，老朋友！</p>
      ) : (
        <p>请先登录</p>
      )}
    </div>
  );
}

// 使用
// <UserStatus isLoggedIn={true} />  → 显示"欢迎回来"
// <UserStatus isLoggedIn={false} /> → 显示"请先登录"
```

### 方式二：逻辑与 `&&`

适合"满足条件才显示"的场景（不需要"否则"的情况）。

```jsx
function Notification({ messages }) {
  return (
    <div>
      <h1>消息中心</h1>
      {/* 只有当 messages 数量大于 0 时才显示 */}
      {messages.length > 0 && (
        <p>你有 {messages.length} 条未读消息</p>
      )}
    </div>
  );
}
```

> [!WARNING] 注意
> 使用 `&&` 时要小心一个陷阱——当条件值是 `0` 时，`0 && <p>内容</p>` 会在页面上显示一个 `0`！所以最好把条件写成明确的布尔值比较，比如 `messages.length > 0` 而不是 `messages.length`。

### 方式三：提前 return

适合复杂的多条件判断。

```jsx
function PageContent({ status }) {
  // 根据状态提前 return 不同的内容
  if (status === 'loading') {
    return <div className="spinner">加载中，请稍候...</div>;
  }

  if (status === 'error') {
    return <div className="error">出错了，请稍后再试！</div>;
  }

  if (status === 'empty') {
    return <div className="empty">暂无数据</div>;
  }

  // 默认情况
  return (
    <div className="content">
      <h1>这是正式内容</h1>
      <p>欢迎来到页面！</p>
    </div>
  );
}
```

> [!TIP] 提示
> 选择哪种方式？简单原则——简单条件用三元或 `&&`，复杂条件用提前 return。别在一个 JSX 里嵌套太多三元运算符，那样读起来就像天书。

## 3.7 列表渲染：从数组到 UI

在 React 中，我们经常需要把一个数组渲染成一列元素。这就需要用到 `map()` 方法。

```jsx
function FruitList() {
  // 一个水果数组
  const fruits = [
    { id: 1, name: '苹果', emoji: '🍎', price: 5 },
    { id: 2, name: '香蕉', emoji: '🍌', price: 3 },
    { id: 3, name: '橘子', emoji: '🍊', price: 4 },
    { id: 4, name: '葡萄', emoji: '🍇', price: 8 },
    { id: 5, name: '西瓜', emoji: '🍉', price: 10 },
  ];

  return (
    <div>
      <h2>水果清单</h2>
      <ul>
        {/* 用 map 把数组变成一组 <li> 元素 */}
        {fruits.map(fruit => (
          <li key={fruit.id}>
            {fruit.emoji} {fruit.name} - ¥{fruit.price}/斤
          </li>
        ))}
      </ul>
    </div>
  );
}
```

### `key` 的重要性（必读！）

注意上面代码中的 `key={fruit.id}`——这不是可选的，而是 **必须的**。

**为什么需要 key？**

当你在列表中增加、删除或重新排序元素时，React 需要通过 `key` 来判断"哪些元素是原来的、哪些是新增的、哪些被移除了"。没有 key，React 可能会犯糊涂——把新数据渲染到旧的 DOM 元素上，导致各种奇怪的 bug。

```jsx
// ❌ 没有 key，React 会在控制台报 Warning
{items.map(item => <li>{item.name}</li>)}

// ❌ 用 index 作为 key（不推荐，列表顺序变化时会出问题）
{items.map((item, index) => <li key={index}>{item.name}</li>)}

// ✅ 用唯一标识作为 key（推荐！）
{items.map(item => <li key={item.id}>{item.name}</li>)}
```

> [!WARNING] 注意
> 用数组的 `index`（索引）作为 key 是一个常见的新手错误。如果你的列表可能重新排序、增加或删除元素，用 index 作为 key 会导致性能问题和状态错乱。始终使用数据中的唯一标识（如 id）作为 key。

> [!TIP] 提示
> 如果数据里没有唯一 id 怎么办？你可以在创建数据时自己生成一个（比如用 `crypto.randomUUID()` 或者 `Date.now()` + 随机数），或者——如果列表确实不会变——那就用 index 吧，但要清楚这样做的风险。

### 列表渲染的完整示例

来看一个更完整的例子——一个待办事项列表：

```jsx
import { useState } from 'react';

function TodoList() {
  // 待办事项列表
  const [todos, setTodos] = useState([
    { id: 1, text: '学习 React', done: true },
    { id: 2, text: '写一个 TodoList 组件', done: false },
    { id: 3, text: '理解 JSX 语法', done: false },
  ]);

  // 切换完成状态
  function toggleTodo(id) {
    setTodos(todos.map(todo =>
      todo.id === id ? { ...todo, done: !todo.done } : todo
    ));
  }

  return (
    <div style={{ maxWidth: '400px', margin: '0 auto' }}>
      <h2>📝 我的待办事项</h2>
      <ul style={{ listStyle: 'none', padding: 0 }}>
        {todos.map(todo => (
          <li
            key={todo.id}
            onClick={() => toggleTodo(todo.id)}
            style={{
              padding: '10px',
              marginBottom: '8px',
              borderRadius: '6px',
              backgroundColor: todo.done ? '#e8f5e9' : '#fff3e0',
              textDecoration: todo.done ? 'line-through' : 'none',
              cursor: 'pointer',
            }}
          >
            {todo.done ? '✅' : '⬜'} {todo.text}
          </li>
        ))}
      </ul>
      <p style={{ color: 'gray' }}>
        已完成 {todos.filter(t => t.done).length} / {todos.length}
      </p>
    </div>
  );
}

export default TodoList;
```

## 3.8 JSX 中的常见坑与解决方案

让我帮你避开新手最容易踩的坑：

### 坑 1：忘记 `return`

```jsx
// ❌ 没有 return，组件什么都不会渲染
function Forgot() {
  <h1>我忘记 return 了</h1>;
}

// ✅ 加上 return
function Correct() {
  return <h1>我有 return</h1>;
}
```

### 坑 2：JSX 中的换行陷阱

```jsx
// ❌ return 后面直接换行，JavaScript 的 ASI（自动分号插入）机制会让 return 变成 return undefined
function Broken() {
  return
    <h1>这行代码永远不会执行</h1>;
}

// ✅ 用小括号包裹 JSX，换行就安全了
function Working() {
  return (
    <h1>这才是正确的写法</h1>
  );
}
```

### 坑 3：布尔值属性的简写

```jsx
// 下面两种写法等价
<Button disabled={true} />
<Button disabled />

// 但注意：false 不能简写，否则属性值会变成字符串 "false"
// ✅ 如果要传 false，必须明确写
<Button disabled={false} />
```

### 坑 4：在 JSX 中渲染对象

```jsx
// ❌ 直接渲染对象会报错
const user = { name: '小明', age: 18 };
return <p>{user}</p>;  // Error!

// ✅ 渲染对象的属性
return <p>{user.name}, {user.age}岁</p>;

// ✅ 或者用 JSON.stringify
return <pre>{JSON.stringify(user, null, 2)}</pre>;
```

### 坑 5：`null`、`undefined` 和 `true`/`false` 不会被渲染

```jsx
// 以下这些都不会在页面上显示任何东西
return (
  <div>
    {null}         {/* 不渲染 */}
    {undefined}    {/* 不渲染 */}
    {true}         {/* 不渲染 */}
    {false}        {/* 不渲染 */}
    {0}            {/* 会渲染出 "0"！ */}
  </div>
);
```

> [!WARNING] 注意
> `0` 和 `""`（空字符串）是会被渲染的！这在条件渲染中是一个常见的 bug 来源。比如 `{items.length && <List />}` 当 `items` 为空时，页面上会显示一个 `0`。

## 3.9 实战：一个完整的 JSX 练习

把本章学到的知识综合运用一下，写一个个人简介卡片组件：

```jsx
function ProfileCard() {
  // 个人信息数据
  const person = {
    name: '张小明',
    title: '前端开发工程师',
    avatar: 'https://i.pravatar.cc/150?img=11',
    skills: ['React', 'JavaScript', 'HTML', 'CSS', 'TypeScript'],
    experience: 3,
    isAvailable: true,
  };

  return (
    <div style={{
      maxWidth: '350px',
      margin: '20px auto',
      borderRadius: '12px',
      overflow: 'hidden',
      boxShadow: '0 4px 12px rgba(0,0,0,0.1)',
      fontFamily: 'sans-serif',
    }}>
      {/* 头部背景 */}
      <div style={{
        background: 'linear-gradient(135deg, #667eea 0%, #764ba2 100%)',
        padding: '30px',
        textAlign: 'center',
        color: 'white',
      }}>
        <img
          src={person.avatar}
          alt={person.name}
          style={{
            width: '80px',
            height: '80px',
            borderRadius: '50%',
            border: '3px solid white',
          }}
        />
        <h2 style={{ margin: '10px 0 5px' }}>{person.name}</h2>
        <p style={{ margin: 0, opacity: 0.9 }}>{person.title}</p>
      </div>

      {/* 主体内容 */}
      <div style={{ padding: '20px' }}>
        {/* 状态标签 */}
        <div style={{ marginBottom: '15px' }}>
          <span style={{
            padding: '4px 12px',
            borderRadius: '20px',
            fontSize: '12px',
            backgroundColor: person.isAvailable ? '#e8f5e9' : '#ffebee',
            color: person.isAvailable ? '#2e7d32' : '#c62828',
          }}>
            {person.isAvailable ? '✅ 正在找工作' : '❌ 暂不考虑'}
          </span>
        </div>

        {/* 工作经验 */}
        <p>
          📅 工作经验：<strong>{person.experience} 年</strong>
        </p>

        {/* 技能列表 */}
        <div>
          <p style={{ fontWeight: 'bold', marginBottom: '8px' }}>🛠 技能栈：</p>
          <div style={{ display: 'flex', flexWrap: 'wrap', gap: '6px' }}>
            {person.skills.map(skill => (
              <span
                key={skill}
                style={{
                  padding: '4px 10px',
                  borderRadius: '4px',
                  backgroundColor: '#f0f0f0',
                  fontSize: '13px',
                }}
              >
                {skill}
              </span>
            ))}
          </div>
        </div>

        {/* 底部信息 */}
        <p style={{
          marginTop: '20px',
          paddingTop: '15px',
          borderTop: '1px solid #eee',
          color: 'gray',
          fontSize: '12px',
          textAlign: 'center',
        }}>
          共掌握 {person.skills.length} 项技能 · {person.experience >= 3 ? '资深' : '初级'}开发者
        </p>
      </div>
    </div>
  );
}

export default ProfileCard;
```

把这段代码保存到你的 `App.jsx` 中运行看看效果吧！

## 本章小结

| 概念 | 要点 |
|------|------|
| **JSX 是什么** | JavaScript 的语法扩展，看起来像 HTML 但本质是 JS |
| **JSX 的本质** | `React.createElement()` 的语法糖 |
| **单根元素** | JSX 表达式必须有一个根元素包裹（可用 `<>`） |
| **className** | 代替 HTML 的 `class` 属性 |
| **`{}` 表达式** | 在 JSX 中嵌入 JavaScript 表达式 |
| **条件渲染** | 三元运算符、`&&`、提前 return 三种方式 |
| **列表渲染** | 用 `map()` 将数组映射为元素列表 |
| **key** | 列表渲染时每个元素必须有唯一的 key |

## 小练习

1. **基础练习**：创建一个 `BookList` 组件，渲染一个包含 5 本书的列表，每本书显示书名、作者和评分。

2. **条件渲染练习**：创建一个 `Temperature` 组件，根据传入的温度值显示不同的内容：
   - 温度 < 10：显示"好冷啊 🥶"
   - 10 <= 温度 < 25：显示"温度刚好 😊"
   - 温度 >= 25：显示"好热啊 🥵"

3. **综合练习**：创建一个 `ShoppingCart` 组件，包含一个商品列表。要求：
   - 显示每个商品的名称和价格
   - 计算并显示总价
   - 如果购物车为空，显示"购物车是空的"
   - 如果总价超过 100 元，显示"已满 100 元，免运费！"

4. **Debug 练习**：以下代码有 3 个错误，找出来并修复：

```jsx
function BuggyComponent() {
  const items = ['苹果', '香蕉', '橘子']
  return (
    <div class="container">
      <h1>水果列表</h1>
      <ul>
        {items.map((item, index) => (
          <li>{item}</li>
        ))}
      </ul>
    </div>
  )
}
```

> 提示：想想本章讲的 className、key、还有 return 的换行问题。
