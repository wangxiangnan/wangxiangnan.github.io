# 第一章：TypeScript 到底在解决什么问题

在正式写代码之前，我们先搞清楚一个问题：**为什么需要 TypeScript？**

JavaScript 是一门动态类型语言。动态类型的优点是灵活、写法自由，缺点是：**很多错误要到运行时才会暴露**。

来看一个经典的 JS 噩梦：

```js
function getUserName(user) {
  return user.name.toUpperCase();
}

const user = { nama: "Alice" }; // 注意，这里是 nama，不是 name
console.log(getUserName(user));
```

这段代码在语法上完全正确，但运行时会报错：`Cannot read properties of undefined (reading 'toUpperCase')`。问题出在哪？`user.name` 是 `undefined`，而你对 `undefined` 调用了 `toUpperCase`。

在小型项目里，这种错误可能一眼就能看出来。但在大型项目、多人协作、复杂数据流中，类似的错误会层出不穷：传错参数、拼错字段名、返回了不存在的属性、异步数据还没拿到就访问……

TypeScript 的核心价值就是：**把这些运行时错误提前到编译时发现**。

上面的例子如果用 TypeScript 写：

```ts
interface User {
  name: string;
}

function getUserName(user: User): string {
  return user.name.toUpperCase();
}

const user = { nama: "Alice" };
console.log(getUserName(user));
```

TypeScript 会立刻报错：

```
Argument of type '{ nama: string; }' is not assignable to parameter of type 'User'.
  Object literal may only specify known properties, but 'nama' does not exist in type 'User'.
```

你看，它在运行之前就告诉你："你传的对象不对，少了个 `name` 字段，多了个 `nama` 字段。"

这就是 TypeScript 的魅力：**用类型约束代码，让错误无处遁形**。

## 类型系统到底是什么

类型系统是一门语言用来**分类和管理数据**的规则集合。它回答的是这样的问题：

- 这个变量可以存什么值？
- 这个函数接收什么参数？返回什么结果？
- 这个对象有哪些属性？属性是什么类型？

在 JavaScript 中，类型是运行时的概念。你用 `typeof` 可以检查一个值的类型，但代码本身不强制你遵守任何类型规则。

在 TypeScript 中，类型是**编译时**的概念。TypeScript 会在编译阶段检查你的代码是否符合类型规则，如果不符合，就报错。但这些类型信息最终会被擦除，生成的 JavaScript 代码里不会保留任何类型注解。

所以你可以把 TypeScript 理解为：**一个会在发布前帮你做额外检查的 JavaScript 预处理器**。

## TypeScript 的工作流程

TypeScript 代码不会直接运行，它要经过一个编译过程：

```
.ts 文件 → TypeScript 编译器 → .js 文件 → 浏览器 / Node.js 执行
```

编译器主要做两件事：

1. **类型检查**：分析代码中的类型是否一致，如果有错误就报告。
2. **代码生成**：把 TS 代码转译成 JS 代码，包括把类型注解、接口、泛型等"类型层"的东西全部去掉。

正是因为类型只存在于编译阶段，TypeScript 才有底气说自己是"JavaScript 的超集"——任何合法的 JS 代码都是合法的 TS 代码（前提是你没把严格模式开到极端）。
