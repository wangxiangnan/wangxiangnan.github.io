# 第21章：Worker Threads——多线程编程

## 引言：当单线程成为"独木桥"

JavaScript是单线程的，Node.js也是单线程的——这句话你听了无数遍了。但是，当你需要：

- 处理1000张图片的缩放
- 计算一个复杂的密码哈希
- 解析一个100MB的CSV文件
- 运行一个机器学习模型推理

这时候，单线程就像是一个人搬砖——不管你的事件循环设计得多精妙，CPU密集任务就是会把主线程堵得死死的，就像堵在北京三环上一样，后面的请求全得等着。

Worker Threads就是你的"分身术"，让你可以在不牺牲Node.js事件驱动优势的前提下，利用多核CPU的能力。

## 21.1 为什么需要Worker Threads？

### 21.1.1 CPU密集任务的困境

```typescript
// blocking-demo.ts - 单线程的痛苦
import { createServer } from 'node:http';

// 模拟CPU密集计算（斐波那契数列的递归实现）
function fibonacci(n: number): number {
  if (n <= 1) return n;
  return fibonacci(n - 1) + fibonacci(n - 2);
}

const server = createServer((req, res) => {
  if (req.url === '/heavy') {
    // 这个计算会阻塞事件循环约2-5秒
    const result = fibonacci(42);
    res.end(`Result: ${result}`);
  } else {
    // 即使是简单请求，也会被上面的计算阻塞
    res.end('Hello World');
  }
});

server.listen(3000, () => {
  console.log('Server on :3000');
  console.log('Try: curl localhost:3000/hello (fast)');
  console.log('Then: curl localhost:3000/heavy (blocks everything!)');
});
```

### 21.1.2 Worker Threads vs child_process vs cluster

```
┌──────────────────┬─────────────────┬──────────────────┬─────────────────┐
│     特性          │ Worker Threads  │  child_process   │     cluster     │
├──────────────────┼─────────────────┼──────────────────┼─────────────────┤
│ 共享内存          │ ✅ SharedArray   │ ❌               │ ❌              │
│ 启动开销          │ 低(~5ms)        │ 高(~30ms)        │ 高(~30ms)      │
│ 通信方式          │ MessagePort     │ IPC/stdio        │ IPC             │
│ 隔离级别          │ 线程级          │ 进程级           │ 进程级          │
│ 适用场景          │ CPU密集计算     │ 执行外部命令     │ HTTP负载均衡    │
│ 崩溃影响          │ 影响主进程      │ 不影响主进程     │ 不影响其他worker│
│ 内存占用          │ 较低(共享V8)    │ 高(独立V8实例)   │ 高             │
│ 资源限制          │ 不能限制        │ 可以限制         │ 可以限制        │
└──────────────────┴─────────────────┴──────────────────┴─────────────────┘
```

**选择指南**：

- **Worker Threads**：纯计算（图片处理、加密、数据解析）
- **child_process**：执行外部命令、隔离不稳定代码
- **cluster**：HTTP服务器多核利用

## 21.2 Worker Threads基础用法

### 21.2.1 Hello Worker

```typescript
// main.ts - 主线程
import { Worker, isMainThread, parentPort, workerData } from 'node:worker_threads';
import { fileURLToPath } from 'node:url';
import { dirname, join } from 'node:path';

const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);

if (isMainThread) {
  // ===== 主线程代码 =====
  console.log('Main thread started');
  
  const worker = new Worker(join(__dirname, 'worker.js'), {
    workerData: { taskId: 1, input: 42 },
  });

  worker.on('message', (result) => {
    console.log(`Worker result: ${result}`);
  });

  worker.on('error', (err) => {
    console.error('Worker error:', err);
  });

  worker.on('exit', (code) => {
    if (code !== 0) {
      console.error(`Worker stopped with exit code ${code}`);
    }
  });
}
```

```typescript

  input: number;
}

const { taskId, input } = workerData as TaskData;

// 执行CPU密集计算
```

### 21.2.2 单文件Worker（内联Worker）

```typescript
// inline-worker.ts
import { Worker, isMainThread, parentPort, workerData } from 'node:worker_threads';

if (isMainThread) {
  // 主线程：使用当前文件作为worker脚本
  async function runWorker<T>(data: unknown): Promise<T> {
    return new Promise((resolve, reject) => {
      const worker = new Worker(new URL(import.meta.url), {
        workerData: data,
      });
      
      worker.on('message', resolve);
      worker.on('error', reject);
      worker.on('exit', (code) => {
        if (code !== 0) reject(new Error(`Worker exited with code ${code}`));
      });
    });
  }

  // 使用
  async function main(): Promise<void> {
    console.log('Starting computation...');
    
    const results = await Promise.all([
      runWorker<number>({ n: 40 }),
      runWorker<number>({ n: 41 }),
      runWorker<number>({ n: 42 }),
    ]);
    
    console.log('Results:', results);
  }

  main();
} else {
  // Worker线程代码
  const { n } = workerData as { n: number };
  
  function fibonacci(num: number): number {
    if (num <= 1) return num;
    return fibonacci(num - 1) + fibonacci(num - 2);
  }

  parentPort!.postMessage(fibonacci(n));
}
```

### 21.2.3 MessageChannel：私密通信管道

```typescript
// message-channel-demo.ts
import { Worker, MessageChannel, isMainThread, parentPort } from 'node:worker_threads';

if (isMainThread) {
  const worker1 = new Worker(new URL(import.meta.url));
  const worker2 = new Worker(new URL(import.meta.url));

  // 创建一个消息通道，让两个worker直接通信
  const { port1, port2 } = new MessageChannel();

  // 将port分别发送给两个worker
  // transferList把port的所有权转移给worker（主线程不再持有）
  worker1.postMessage({ port: port1, role: 'producer' }, [port1]);
  worker2.postMessage({ port: port2, role: 'consumer' }, [port2]);

  // worker1直接发消息给worker2，不经过主线程
  // 这对高频通信的场景很有用
} else {
  parentPort!.on('message', ({ port, role }) => {
    if (role === 'producer') {
      // 生产者：定时发送数据
      let count = 0;
      const interval = setInterval(() => {
        port.postMessage({ data: `message-${count++}`, timestamp: Date.now() });
        if (count >= 10) {
          clearInterval(interval);
          port.close();
        }
      }, 100);
    } else {
      // 消费者：接收数据
      port.on('message', (msg: { data: string; timestamp: number }) => {
        console.log(`[Consumer] Received: ${msg.data} (latency: ${Date.now() - msg.timestamp}ms)`);
      });
    }
  });
}
```

## 21.3 SharedArrayBuffer：真正的共享内存

### 21.3.1 理解共享内存

`postMessage`传递数据时，默认会进行**结构化克隆**（深拷贝）。对于大数据，这个拷贝开销很大。`SharedArrayBuffer`让多个线程共享同一块内存——零拷贝！

```typescript
// shared-memory-demo.ts
import { Worker, isMainThread, workerData } from 'node:worker_threads';

if (isMainThread) {
  // 创建1MB的共享内存
  const sharedBuffer = new SharedArrayBuffer(1024 * 1024);
  const sharedArray = new Int32Array(sharedBuffer);

  // 主线程写入数据
  for (let i = 0; i < 100; i++) {
    sharedArray[i] = i * 2;
  }

  console.log('Main: Written data to shared memory');
  console.log('Main: sharedArray[50] =', sharedArray[50]); // 100

  // 创建worker，传递共享内存
  const worker = new Worker(new URL(import.meta.url), {
    workerData: { sharedBuffer },
  });

  worker.on('message', (msg) => {
    if (msg === 'done') {
      // Worker修改了共享内存，主线程能看到变化
      console.log('Main: After worker modification');
      console.log('Main: sharedArray[50] =', sharedArray[50]); // 被worker修改了
    }
  });
} else {
  const { sharedBuffer } = workerData as { sharedBuffer: SharedArrayBuffer };
  const sharedArray = new Int32Array(sharedBuffer);

  // Worker可以直接读写共享内存，无需序列化/反序列化
  console.log('Worker: sharedArray[50] =', sharedArray[50]); // 100

  // 修改数据
  for (let i = 0; i < 100; i++) {
    sharedArray[i] = sharedArray[i] * 10;
  }

  parentPort!.postMessage('done');
}
```

### 21.3.2 性能对比：postMessage vs SharedArrayBuffer

```typescript
// perf-comparison.ts
import { Worker, isMainThread, parentPort, workerData } from 'node:worker_threads';
import { performance } from 'node:perf_hooks';

const DATA_SIZE = 10_000_000; // 1000万个int32 = 40MB

if (isMainThread) {
  // 方案1：使用postMessage传递普通数组
  async function benchPostMessage(): Promise<number> {
    const data = new Int32Array(DATA_SIZE);
    for (let i = 0; i < DATA_SIZE; i++) data[i] = i;

    const start = performance.now();
    
    const worker = new Worker(new URL(import.meta.url), {
      workerData: { mode: 'copy' },
    });

    // 发送数据（结构化克隆 = 拷贝40MB）
    worker.postMessage(data);
    
    return new Promise((resolve) => {
      worker.on('message', () => {
        resolve(performance.now() - start);
      });
    });
  }

  // 方案2：使用SharedArrayBuffer
  async function benchShared(): Promise<number> {
    const sharedBuffer = new SharedArrayBuffer(DATA_SIZE * 4);
    const data = new Int32Array(sharedBuffer);
    for (let i = 0; i < DATA_SIZE; i++) data[i] = i;

    const start = performance.now();
    
    const worker = new Worker(new URL(import.meta.url), {
      workerData: { mode: 'shared', sharedBuffer },
    });

    worker.postMessage('start'); // 只发一个信号，数据已经共享了
    
    return new Promise((resolve) => {
      worker.on('message', () => {
        resolve(performance.now() - start);
      });
    });
  }

  // 方案3：使用Transfer（所有权转移）
  async function benchTransfer(): Promise<number> {
    const data = new Int32Array(DATA_SIZE);
    for (let i = 0; i < DATA_SIZE; i++) data[i] = i;

    const start = performance.now();
    
    const worker = new Worker(new URL(import.meta.url), {
      workerData: { mode: 'transfer' },
    });

    // 转移所有权（零拷贝，但主线程不能再用这个buffer）
    worker.postMessage(data, [data.buffer]);
    // 此时 data.buffer.byteLength === 0，主线程已失去所有权
    
    return new Promise((resolve) => {
      worker.on('message', () => {
        resolve(performance.now() - start);
      });
    });
  }

  async function main(): Promise<void> {
    const copyTime = await benchPostMessage();
    const sharedTime = await benchShared();
    const transferTime = await benchTransfer();

    console.log(`\n=== 40MB Data Transfer Benchmark ===`);
    console.log(`postMessage (copy):    ${copyTime.toFixed(2)}ms`);
    console.log(`SharedArrayBuffer:     ${sharedTime.toFixed(2)}ms`);
    console.log(`Transfer:              ${transferTime.toFixed(2)}ms`);
  }

  main();
} else {
  const { mode, sharedBuffer } = workerData as { mode: string; sharedBuffer?: SharedArrayBuffer };
  
  if (mode === 'shared') {
    parentPort!.on('message', () => {
      const data = new Int32Array(sharedBuffer!);
      let sum = 0;
      for (let i = 0; i < data.length; i++) sum += data[i];
      parentPort!.postMessage(sum);
    });
  } else {
    parentPort!.on('message', (data: Int32Array) => {
      let sum = 0;
      for (let i = 0; i < data.length; i++) sum += data[i];
      parentPort!.postMessage(sum);
    });
  }
}
```

## 21.4 Atomics：原子操作与线程同步

当多个线程同时读写共享内存时，会出现**竞态条件**。Atomics提供了原子操作来保证线程安全。

### 21.4.1 竞态条件演示

```typescript
// race-condition.ts
import { Worker, isMainThread, workerData } from 'node:worker_threads';

if (isMainThread) {
  const sharedBuffer = new SharedArrayBuffer(4);
  const counter = new Int32Array(sharedBuffer);
  counter[0] = 0;

  const WORKERS = 4;
  const INCREMENTS = 1_000_000;
  let completed = 0;

  for (let i = 0; i < WORKERS; i++) {
    const worker = new Worker(new URL(import.meta.url), {
      workerData: { sharedBuffer, increments: INCREMENTS, useAtomics: false },
    });

    worker.on('message', () => {
      completed++;
      if (completed === WORKERS) {
        // 预期值: 4 * 1000000 = 4000000
        // 实际值: 几乎肯定小于4000000（竞态条件！）
        console.log(`Without Atomics: ${counter[0]} (expected: ${WORKERS * INCREMENTS})`);
        runWithAtomics();
      }
    });
  }

  function runWithAtomics(): void {
    const sharedBuffer2 = new SharedArrayBuffer(4);
    const counter2 = new Int32Array(sharedBuffer2);
    counter2[0] = 0;
    let completed2 = 0;

    for (let i = 0; i < WORKERS; i++) {
      const worker = new Worker(new URL(import.meta.url), {
        workerData: { sharedBuffer: sharedBuffer2, increments: INCREMENTS, useAtomics: true },
      });

      worker.on('message', () => {
        completed2++;
        if (completed2 === WORKERS) {
          // 使用Atomics后，结果一定是精确的
          console.log(`With Atomics: ${counter2[0]} (expected: ${WORKERS * INCREMENTS})`);
        }
      });
    }
  }
} else {
  const { sharedBuffer, increments, useAtomics } = workerData as {
    sharedBuffer: SharedArrayBuffer;
    increments: number;
    useAtomics: boolean;
  };
  
  const counter = new Int32Array(sharedBuffer);

  for (let i = 0; i < increments; i++) {
    if (useAtomics) {
      Atomics.add(counter, 0, 1); // 原子加1，线程安全
    } else {
      counter[0]++; // 非原子操作，有竞态条件
    }
  }

  parentPort!.postMessage('done');
}
```

### 21.4.2 使用Atomics实现互斥锁

```typescript
// mutex.ts - 基于Atomics的简单互斥锁
export class Mutex {
  private lock: Int32Array;
  
  constructor(sharedBuffer: SharedArrayBuffer, offset: number = 0) {
    this.lock = new Int32Array(sharedBuffer, offset, 1);
  }

  acquire(): void {
    // 自旋等待：不断尝试将0改为1
    while (true) {
      // compareExchange: 如果当前值是0（未锁定），则设为1（锁定）
      // 返回旧值：如果返回0表示成功获取锁
      const oldValue = Atomics.compareExchange(this.lock, 0, 0, 1);
      if (oldValue === 0) {
        return; // 成功获取锁
      }
      // 等待锁被释放（避免忙等待浪费CPU）
      Atomics.wait(this.lock, 0, 1); // 当值为1时等待
    }
  }

  release(): void {
    // 将锁状态设回0
    Atomics.store(this.lock, 0, 0);
    // 唤醒一个等待的线程
    Atomics.notify(this.lock, 0, 1);
  }

  tryAcquire(): boolean {
    return Atomics.compareExchange(this.lock, 0, 0, 1) === 0;
  }
}

// 使用示例（在Worker中）：

//   mutex.release();
```

### 21.4.3 Atomics.wait和Atomics.notify：线程间的"对讲机"

```typescript
// producer-consumer.ts - 生产者-消费者模式
import { Worker, isMainThread, parentPort, workerData } from 'node:worker_threads';

// 共享内存布局：
// [0]: 状态标志 (0=空闲, 1=有数据)
// [1]: 数据长度
// [2...]: 实际数据

if (isMainThread) {
  const sharedBuffer = new SharedArrayBuffer(1024 * 4); // 4KB
  const control = new Int32Array(sharedBuffer);

  // 启动消费者
  const consumer = new Worker(new URL(import.meta.url), {
    workerData: { role: 'consumer', sharedBuffer },
  });

  // 主线程作为生产者
  async function produce(): Promise<void> {
    const data = new Int32Array(sharedBuffer);
    
    for (let i = 0; i < 10; i++) {
      // 等待消费者处理完上一条
      while (Atomics.load(control, 0) === 1) {
        Atomics.wait(control, 0, 1, 100); // 超时100ms
      }

      // 写入数据
      data[1] = i; // 数据长度/值
      data[2] = i * 100; // 数据内容
      
      // 标记有新数据
      Atomics.store(control, 0, 1);
      Atomics.notify(control, 0); // 唤醒消费者
      
      console.log(`[Producer] Sent: ${i}`);
      await new Promise(r => setTimeout(r, 200)); // 模拟生产间隔
    }

    // 发送结束信号
    Atomics.store(control, 0, 2); // 2 = 结束
    Atomics.notify(control, 0);
  }

  produce();
} else {
  const { sharedBuffer } = workerData as { role: string; sharedBuffer: SharedArrayBuffer };
  const control = new Int32Array(sharedBuffer);
  const data = new Int32Array(sharedBuffer);

  function consume(): void {
    while (true) {
      // 等待新数据
      const result = Atomics.wait(control, 0, 0, 5000); // 超时5s
      
      if (result === 'timed-out') {
        console.log('[Consumer] Timeout, checking...');
        continue;
      }

      const status = Atomics.load(control, 0);
      
      if (status === 2) {
        console.log('[Consumer] Received end signal, exiting');
        break;
      }

      if (status === 1) {
        // 读取数据
        const value = data[2];
        console.log(`[Consumer] Received: ${data[1]}, value: ${value}`);
        
        // 标记已处理
        Atomics.store(control, 0, 0);
        Atomics.notify(control, 0); // 唤醒生产者
      }
    }
  }

  consume();
}
```

## 21.5 线程池模式：Piscina

手动管理Worker的创建和销毁太麻烦了。Piscina是一个高性能的线程池库，让Worker Threads的使用变得像调用函数一样简单。

```typescript
// pool-demo.ts
import Piscina from 'piscina';
import { fileURLToPath } from 'node:url';
import { dirname, join } from 'node:path';

const __dirname = dirname(fileURLToPath(import.meta.url));

// 创建线程池
const pool = new Piscina({
  filename: join(__dirname, 'task-worker.js'),
  minThreads: 2,      // 最少保持2个线程
  maxThreads: 8,      // 最多8个线程
  idleTimeout: 30000, // 空闲30秒后回收线程
});

// task-worker.ts - 线程池的工作函数
// export default function (task: { type: string; data: any }) { ... }

interface TaskResult {
  taskId: string;
  result: number;
  duration: number;
}

async function main(): Promise<void> {
  console.log(`Thread pool: min=${pool.options.minThreads}, max=${pool.options.maxThreads}`);
  
  // 提交多个任务，线程池自动调度
  const tasks = Array.from({ length: 20 }, (_, i) => ({
    type: 'fibonacci',
    data: { n: 35 + (i % 5), taskId: `task-${i}` },
  }));

  const start = performance.now();
  
  // 并行执行所有任务
  const results: TaskResult[] = await Promise.all(
    tasks.map(task => pool.run(task))
  );
  
  const totalTime = performance.now() - start;
  
  console.log(`\nCompleted ${results.length} tasks in ${totalTime.toFixed(2)}ms`);
  console.log(`Pool stats:`, {
    completed: pool.completed,
    utilization: `${(pool.utilization * 100).toFixed(1)}%`,
    waitTime: `${pool.waitTime.mean.toFixed(2)}ms avg`,
    runTime: `${pool.runTime.mean.toFixed(2)}ms avg`,
  });
}

main();
```

```typescript
// task-worker.ts - Piscina worker文件
interface Task {
  type: string;
  data: { n: number; taskId: string };
}

function fibonacci(n: number): number {
  if (n <= 1) return n;
  return fibonacci(n - 1) + fibonacci(n - 2);
}

export default function handler(task: Task) {
  const start = performance.now();
  
  switch (task.type) {
    case 'fibonacci': {
      const result = fibonacci(task.data.n);
      return {
        taskId: task.data.taskId,
        result,
        duration: performance.now() - start,
      };
    }
    default:
      throw new Error(`Unknown task type: ${task.type}`);
  }
}
```

## 21.6 实战案例

### 21.6.1 图片处理：Sharp + Worker Threads

```typescript
// image-processor.ts
import Piscina from 'piscina';
import { join, dirname } from 'node:path';
import { fileURLToPath } from 'node:url';
import { readdir } from 'node:fs/promises';

const __dirname = dirname(fileURLToPath(import.meta.url));

const imagePool = new Piscina({
  filename: join(__dirname, 'image-worker.js'),
  maxThreads: 4, // 图片处理是内存密集型，不要开太多线程
});

interface ResizeOptions {
  inputPath: string;
  outputPath: string;
  width: number;
  height: number;
  quality: number;
  format: 'jpeg' | 'png' | 'webp' | 'avif';
}

async function processImages(inputDir: string, outputDir: string): Promise<void> {
  const files = await readdir(inputDir);
  const imageFiles = files.filter(f => /\.(jpg|jpeg|png|gif|webp)$/i.test(f));
  
  console.log(`Processing ${imageFiles.length} images...`);
  const start = performance.now();

  // 为每张图片创建多种尺寸
  const sizes = [
    { width: 1920, height: 1080, suffix: 'full' },
    { width: 800, height: 600, suffix: 'medium' },
    { width: 200, height: 200, suffix: 'thumb' },
  ];

  const tasks: ResizeOptions[] = imageFiles.flatMap(file =>
    sizes.map(size => ({
      inputPath: join(inputDir, file),
      outputPath: join(outputDir, `${file.replace(/\.[^.]+$/, '')}-${size.suffix}.webp`),
      width: size.width,
      height: size.height,
      quality: 80,
      format: 'webp' as const,
    }))
  );

  const results = await Promise.allSettled(
    tasks.map(task => imagePool.run(task))
  );

  const succeeded = results.filter(r => r.status === 'fulfilled').length;
  const failed = results.filter(r => r.status === 'rejected').length;
  
  console.log(`Done in ${((performance.now() - start) / 1000).toFixed(2)}s`);
  console.log(`Succeeded: ${succeeded}, Failed: ${failed}`);
}
```

```typescript
// custom-thread-pool.ts
import { Worker, MessageChannel, type MessagePort } from 'node:worker_threads';
import { EventEmitter } from 'node:events';

interface PoolOptions {
  workerScript: string;
  minWorkers?: number;
  maxWorkers?: number;
  taskTimeout?: number;
  idleTimeout?: number;
}

interface Task<T = unknown> {
  id: string;
  data: unknown;
  resolve: (value: T) => void;
  reject: (reason: Error) => void;
  createdAt: number;
}

interface WorkerInfo {
  worker: Worker;
  busy: boolean;
  taskCount: number;
  createdAt: number;
  lastActiveAt: number;
}

class ThreadPool extends EventEmitter {
  private workers: Map<number, WorkerInfo> = new Map();
  private taskQueue: Task[] = [];
  private nextWorkerId = 0;
  private options: Required<PoolOptions>;

  constructor(options: PoolOptions) {
    super();
    this.options = {
      minWorkers: options.minWorkers ?? 2,
      maxWorkers: options.maxWorkers ?? navigator?.hardwareConcurrency ?? 4,
      taskTimeout: options.taskTimeout ?? 30000,
      idleTimeout: options.idleTimeout ?? 60000,
      workerScript: options.workerScript,
    };

    // 预创建最小数量的worker
    for (let i = 0; i < this.options.minWorkers; i++) {
      this.createWorker();
    }

    // 定期清理空闲worker
    setInterval(() => this.cleanIdleWorkers(), this.options.idleTimeout);
  }

  async execute<T>(data: unknown): Promise<T> {
    return new Promise<T>((resolve, reject) => {
      const task: Task<T> = {
        id: crypto.randomUUID(),
        data,
        resolve: resolve as (value: unknown) => void,
        reject,
        createdAt: Date.now(),
      };

      this.taskQueue.push(task as Task);
      this.dispatch();
    });
  }

  private dispatch(): void {
    if (this.taskQueue.length === 0) return;

    // 找一个空闲的worker
    let idleWorker: WorkerInfo | undefined;
    for (const [, info] of this.workers) {
      if (!info.busy) {
        idleWorker = info;
        break;
      }
    }

    if (!idleWorker) {
      // 没有空闲worker，尝试创建新的
      if (this.workers.size < this.options.maxWorkers) {
        idleWorker = this.createWorker();
      } else {
        // 达到上限，任务留在队列等待
        return;
      }
    }

    const task = this.taskQueue.shift()!;
    this.assignTask(idleWorker, task);
  }

  private assignTask(workerInfo: WorkerInfo, task: Task): void {
    workerInfo.busy = true;
    workerInfo.taskCount++;
    workerInfo.lastActiveAt = Date.now();

    // 超时处理
    const timeout = setTimeout(() => {
      task.reject(new Error(`Task ${task.id} timed out after ${this.options.taskTimeout}ms`));
      // 终止超时的worker，创建新的替代
      workerInfo.worker.terminate();
    }, this.options.taskTimeout);

    workerInfo.worker.once('message', (result) => {
      clearTimeout(timeout);
      workerInfo.busy = false;
      task.resolve(result);
      this.emit('taskComplete', { taskId: task.id, duration: Date.now() - task.createdAt });
      this.dispatch(); // 处理队列中的下一个任务
    });

    workerInfo.worker.once('error', (error) => {
      clearTimeout(timeout);
      workerInfo.busy = false;
      task.reject(error);
      this.dispatch();
    });

    workerInfo.worker.postMessage({ taskId: task.id, data: task.data });
  }

  private createWorker(): WorkerInfo {
    const id = this.nextWorkerId++;
    const worker = new Worker(this.options.workerScript);
    
    const info: WorkerInfo = {
      worker,
      busy: false,
      taskCount: 0,
      createdAt: Date.now(),
      lastActiveAt: Date.now(),
    };

    worker.on('exit', (code) => {
      this.workers.delete(id);
      if (code !== 0) {
        console.error(`Worker ${id} exited with code ${code}`);
        // 自动补充到最小数量
        if (this.workers.size < this.options.minWorkers) {
          this.createWorker();
        }
      }
    });

    this.workers.set(id, info);
    return info;
  }

  private cleanIdleWorkers(): void {
    const now = Date.now();
    for (const [id, info] of this.workers) {
      if (
        !info.busy &&
        this.workers.size > this.options.minWorkers &&
        now - info.lastActiveAt > this.options.idleTimeout
      ) {
        info.worker.terminate();
        this.workers.delete(id);
      }
    }
  }

  get stats() {
    const workers = [...this.workers.values()];
    return {
      totalWorkers: workers.length,
      busyWorkers: workers.filter(w => w.busy).length,
      idleWorkers: workers.filter(w => !w.busy).length,
      queuedTasks: this.taskQueue.length,
      totalTasksProcessed: workers.reduce((sum, w) => sum + w.taskCount, 0),
    };
  }

  async destroy(): Promise<void> {
    for (const [, info] of this.workers) {
      await info.worker.terminate();
    }
    this.workers.clear();
  }
}

export { ThreadPool, PoolOptions };
```

## 21.8 常见坑点

### 坑点1：Worker中不能使用的API

```typescript
// Worker中这些不可用：
// - process.exit() → 使用 process.abort() 或 parentPort.close()
// - process.chdir()
// - process.stdin / process.stdout 有限制
// - 部分 native addon 可能不支持多线程
```

### 坑点2：序列化限制

```typescript
// postMessage使用结构化克隆，以下类型不能传递：
// - 函数/闭包
// - Symbol
// - DOM元素（Node.js中不存在）
// - Error对象的自定义属性可能丢失
// - class实例会丢失方法（只保留属性）

class MyClass {
  value: number;
  constructor(v: number) { this.value = v; }
  compute() { return this.value * 2; }
}

// 传递后，compute方法会丢失！
// 解决方案：只传数据，在worker中重新构建实例
```

### 坑点3：内存隔离的误解

```typescript
// 每个Worker有自己的V8实例和事件循环
// 约10MB的额外内存开销
// 不要创建太多Worker！

// 错误：为每个请求创建Worker
app.get('/heavy', (req, res) => {
  const worker = new Worker('./task.js'); // ← 每次都创建新Worker
  // 这样做Worker的创建/销毁开销会超过计算本身
});

// 正确：使用线程池复用Worker
const pool = new Piscina({ filename: './task.js', maxThreads: 4 });

  const result = await pool.run(req.body);
  res.json(result);
});
```

## 21.9 本章小结

Worker Threads是Node.js处理CPU密集任务的"正道"。记住这个决策树：

```
任务类型是什么？
├── I/O密集（网络/文件）→ 使用异步API，不需要Worker
├── CPU密集
│   ├── 计算时间 < 10ms → 不需要Worker
│   ├── 计算时间 10ms-1s → Worker Threads
│   └── 计算时间 > 数秒 → Worker Threads + 进度报告
├── 需要隔离/崩溃不影响主进程 → child_process
└── HTTP负载均衡 → cluster
```

> "多线程编程就像在厨房里多请了几个厨师——如果没有好的协调机制，他们会互相抢锅铲。" —— 某位被竞态条件折磨过的程序员
