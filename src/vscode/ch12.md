# 第12章：Dev Containers 容器化开发

> "It works on my machine." —— 每一个曾经被部署问题折磨的开发者

这句话大概是人类软件工程史上最著名的"遗言"之一了。它的潜台词是："我放弃理解为什么它在你的机器上不工作，所以我选择假装问题不存在。"

Dev Containers 就是来终结这句话的。它的核心理念极其简洁：**把你的开发环境装进一个 Docker 容器里。** 你的代码、你的依赖、你的工具链、你的 VSCode 配置——全部在一个容器中。不管是你、你的同事、还是 CI 服务器，打开的都是完全相同的环境。"It works on my machine" 这个问题从此不存在了——因为每个人用的都是同一个 "machine"。

## 12.1 为什么需要容器化开发

在我们深入配置之前，先理清 Dev Containers 解决的核心问题：

**问题 1：环境不一致**

```
开发者 A：Node.js 18 + Python 3.11 + Go 1.21
开发者 B：Node.js 20 + Python 3.12 + Go 1.22
CI 服务器：Node.js 18 + Python 3.10 + 没装 Go
```

同一个项目在不同环境中的行为可能完全不同。

**问题 2：依赖污染**
全局安装的包互相冲突。项目 A 需要 `webpack@4`，项目 B 需要 `webpack@5`，你的全局 `node_modules` 变成了一个定时炸弹。

**问题 3：新人上手慢**
新员工第一天：安装 Docker、Node.js、Python、Go、数据库、各种工具…… 配置环境变量、修改 hosts、解决版本冲突…… 一天过去了，代码一行没写。

**Dev Containers 的解决方案：**

```
打开 VSCode → 点击 "Reopen in Container" → 等待构建 → 开始写代码
```

所有依赖都在容器中，所有配置都跟随项目，所有开发者都使用完全相同的环境。

## 12.2 前提条件

1. **Docker Desktop**（Windows/macOS）或 **Docker Engine**（Linux）
2. **VSCode Dev Containers 扩展**：`ms-vscode-remote.remote-containers`
3. 基本的 Docker 知识（什么是镜像、容器、Dockerfile）

## 12.3 devcontainer.json：完整配置

Dev Container 的核心配置文件是 `.devcontainer/devcontainer.json`。让我们从一个简单配置开始，逐步扩展：

## 最简配置

```json
// .devcontainer/devcontainer.json
{
    "name": "My Dev Container",
    "image": "mcr.microsoft.com/devcontainers/base:ubuntu",
    "features": {
        "ghcr.io/devcontainers/features/node:1": {
            "version": "20"
        }
    }
}
```

就这么简单——一个 Ubuntu 基础镜像，加上 Node.js 20。打开项目后，VSCode 会提示你 "Reopen in Container"，点击后它就会构建容器并在其中打开 VSCode。

## 完整配置

```json
{
    "name": "Full Stack Dev Environment",

    // 使用 Dockerfile 构建
    "build": {
        "dockerfile": "Dockerfile",
        "context": ".."
    },

    // 或者使用 docker-compose
    // "dockerComposeFile": "docker-compose.yml",
    // "service": "app",
    // "workspaceFolder": "/workspace",

    // 容器特性（预配置的附加功能）
    "features": {
        "ghcr.io/devcontainers/features/node:1": {
            "version": "20",
            "nodeGypDependencies": true
        },
        "ghcr.io/devcontainers/features/python:1": {
            "version": "3.12",
            "installTools": true
        },
        "ghcr.io/devcontainers/features/docker-in-docker:2": {},
        "ghcr.io/devcontainers/features/git:1": {
            "version": "latest"
        },
        "ghcr.io/devcontainers/features/github-cli:1": {}
    },

    // 容器内的 VSCode 设置
    "customizations": {
        "vscode": {
            "extensions": [
                "dbaeumer.vscode-eslint",
                "esbenp.prettier-vscode",
                "ms-python.python",
                "ms-python.vscode-pylance",
                "bradlc.vscode-tailwindcss",
                "GitHub.copilot"
            ],
            "settings": {
                "editor.formatOnSave": true,
                "editor.defaultFormatter": "esbenp.prettier-vscode",
                "terminal.integrated.defaultProfile.linux": "zsh",
                "python.defaultInterpreterPath": "/usr/local/bin/python"
            }
        }
    },

    // 端口转发
    "forwardPorts": [3000, 4000, 5432, 6379],
    "portsAttributes": {
        "3000": { "label": "Frontend", "onAutoForward": "openBrowser" },
        "4000": { "label": "Backend API", "onAutoForward": "notify" },
        "5432": { "label": "PostgreSQL", "onAutoForward": "silent" }

    // 远程用户（避免以 root 运行）

    "mounts": [
        "source=${localEnv:HOME}/.ssh,target=/home/vscode/.ssh,type=bind,consistency=cached",

        "REDIS_URL": "redis://redis:6379",
        "NODE_ENV": "development"
    },

    // 容器运行参数
    "runArgs": [
        "--cap-add=SYS_PTRACE",
        "--security-opt", "seccomp=unconfined"
    ]
}
```

## 12.4 Dockerfile vs docker-compose

Dev Containers 支持三种定义容器的方式，适用于不同场景：

## 方式一：直接使用预构建镜像

```json
{
    "name": "Node.js Dev",
    "image": "mcr.microsoft.com/devcontainers/javascript-node:20"
}
```

**适用场景**：简单的单语言项目，不需要自定义基础环境。

## 方式二：使用 Dockerfile

```dockerfile
# .devcontainer/Dockerfile
FROM mcr.microsoft.com/devcontainers/base:ubuntu-22.04

# 安装系统依赖
RUN apt-get update && apt-get install -y \
    build-essential \
    libpq-dev \
    curl \
    && rm -rf /var/lib/apt/lists/*

# 安装 Rust（示例：项目中有一个 Rust 计算模块）
RUN curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
ENV PATH="/root/.cargo/bin:${PATH}"

# 安装 pnpm
RUN npm install -g pnpm

# 设置工作目录
WORKDIR /workspace
```

```json
// devcontainer.json
{
    "name": "Custom Dev",
    "build": {
        "dockerfile": "Dockerfile",
        "context": ".."
    }
}
```

**适用场景**：需要自定义基础环境、安装特定系统包、多语言混合项目。

## 方式三：使用 docker-compose（推荐用于全栈项目）

```yaml
# .devcontainer/docker-compose.yml
version: '3.8'

services:
  app:
    build:
      context: ..
      dockerfile: .devcontainer/Dockerfile
    volumes:
      - ..:/workspace:cached
    command: sleep infinity
    networks:
      - dev-network
    environment:
      - DATABASE_URL=postgresql://postgres:password@db:5432/myapp
      - REDIS_URL=redis://redis:6379

  db:
    image: postgres:16-alpine
    restart: unless-stopped
    volumes:
      - postgres-data:/var/lib/postgresql/data
    environment:
      POSTGRES_PASSWORD: password
      POSTGRES_DB: myapp
    ports:
      - "5432:5432"
    networks:
      - dev-network

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    volumes:
      - redis-data:/data
    ports:
      - "6379:6379"
    networks:
      - dev-network

volumes:
  postgres-data:
  redis-data:

networks:
  dev-network:
    driver: bridge
```

```json
// devcontainer.json
{
    "name": "Full Stack Dev",
    "dockerComposeFile": "docker-compose.yml",
    "service": "app",
    "workspaceFolder": "/workspace",
    "forwardPorts": [3000, 4000, 5432, 6379]
}
```

**适用场景**：需要数据库、缓存、消息队列等附属服务的全栈项目。你的应用容器可以直接通过服务名（`db`、`redis`）访问其他容器，无需 localhost 映射。

## 12.5 容器内的 VSCode 体验

当你在容器中打开 VSCode 时，你会注意到——**几乎没有任何区别**。这正是 Dev Containers 的精妙之处：

## 扩展安装

`customizations.vscode.extensions` 中列出的扩展会在容器创建时自动安装。你也可以在容器运行时手动安装更多扩展——它们会安装在容器内，不影响你本机的 VSCode。

扩展分为两类：

- **UI 扩展**（主题、图标等）：始终运行在本机
- **工作区扩展**（语言服务器、格式化器、调试器等）：运行在容器内

## 终端集成

容器内的集成终端直接运行在容器环境中：

```bash
# 这个终端已经在容器里了
$ which node
/usr/local/bin/node

$ python --version
Python 3.12.2

$ cat /etc/os-release
Ubuntu 22.04.3 LTS
```

## 文件同步

VSCode 使用卷挂载（volume mount）将你的本地代码目录映射到容器内的 `/workspace`。文件修改在两个方向上实时同步。

> ⚠️ **性能提示**：在 macOS 和 Windows 上，跨平台文件系统挂载可能比原生文件系统慢。如果项目很大（如大型 monorepo），考虑使用 Docker 的 `:cached` 或 `:delegated` 挂载选项来优化性能。

## 调试

容器内的调试完全透明——你在 VSCode 中设置断点，调试器连接到容器内的进程，就像调试本地应用一样：

```json
// .vscode/launch.json（在容器内也能用）
{
    "name": "Debug Node.js in Container",
    "type": "node",
    "request": "launch",
    "program": "${workspaceFolder}/src/index.js",
    "console": "integratedTerminal"
    // 不需要改任何配置——它已经在容器内运行了
}
```

## 12.7 实战：全栈项目 Dev Container 搭建

让我们为一个 React + Express + PostgreSQL + Redis 的全栈项目搭建完整的 Dev Container 开发环境。

## 项目结构

```
fullstack-app/
├── .devcontainer/
│   ├── devcontainer.json
│   ├── Dockerfile
│   └── docker-compose.yml
├── .vscode/
│   ├── launch.json
│   ├── tasks.json
│   └── settings.json
├── client/
│   ├── src/
│   ├── package.json
│   └── vite.config.ts
├── server/
│   ├── src/
│   ├── package.json
│   └── tsconfig.json
├── scripts/
│   └── init-db.sql
└── package.json
```

## .devcontainer/Dockerfile

```dockerfile
FROM mcr.microsoft.com/devcontainers/javascript-node:20-bookworm

# 安装额外的系统工具
RUN apt-get update && export DEBIAN_FRONTEND=noninteractive \
    && apt-get -y install --no-install-recommends \
        postgresql-client \
        redis-tools \
    && apt-get clean \
    && rm -rf /var/lib/apt/lists/*

# 安装全局 Node.js 工具
RUN npm install -g pnpm ts-node-dev

# 设置非 root 用户
USER node

# 预安装项目依赖（利用 Docker 层缓存加速重建）
WORKDIR /workspace
```

## .devcontainer/docker-compose.yml

```yaml
version: '3.8'

services:
  app:
    build:
      context: ..
      dockerfile: .devcontainer/Dockerfile
    volumes:
      - ..:/workspace:cached
      - node-modules-client:/workspace/client/node_modules
      - node-modules-server:/workspace/server/node_modules
    command: sleep infinity
    networks:
      - dev-net
    environment:
      DATABASE_URL: postgresql://dev:devpass@db:5432/fullstack_dev
      REDIS_URL: redis://cache:6379
      NODE_ENV: development
    depends_on:
      - db
      - cache

  db:
    image: postgres:16-alpine
    restart: unless-stopped
    volumes:
      - postgres-data:/var/lib/postgresql/data
      - ../scripts/init-db.sql:/docker-entrypoint-initdb.d/init.sql
    environment:
      POSTGRES_USER: dev
      POSTGRES_PASSWORD: devpass
      POSTGRES_DB: fullstack_dev
    ports:
      - "5432:5432"
    networks:
      - dev-net

  cache:
    image: redis:7-alpine
    restart: unless-stopped
    volumes:
      - redis-data:/data
    ports:
      - "6379:6379"
    networks:
      - dev-net

volumes:
  postgres-data:
  redis-data:
  node-modules-client:
  node-modules-server:

networks:
  dev-net:
    driver: bridge
```

注意 `node-modules-client` 和 `node-modules-server` 作为命名卷——这避免了容器挂载覆盖 `node_modules` 目录的常见问题。

## 使用流程

1. 克隆项目：`git clone https://github.com/your-org/fullstack-app.git`
2. 用 VSCode 打开项目目录
3. VSCode 检测到 `.devcontainer` 配置，右下角弹出提示："Reopen in Container"
4. 点击，等待容器构建（首次约 2-5 分钟，后续秒级）
5. 容器就绪后，VSCode 在容器内重新打开
6. 终端中已经可以访问 `db`（PostgreSQL）和 `cache`（Redis）
7. 运行 `cd server && npm run dev` 和 `cd client && npm run dev`
8. 开始开发

新同事加入？同样的步骤，3 分钟内开始写代码——不需要安装任何工具（除了 Docker 和 VSCode）。

## 12.8 进阶：预构建容器（Prebuild）

容器构建时间是 Dev Containers 的主要痛点之一——首次构建可能需要几分钟。对于团队来说，可以使用**预构建容器**来解决：

## 使用 GitHub Actions 预构建

```yaml
# .github/workflows/devcontainer-prebuild.yml
name: Prebuild Dev Container

on:
  push:
    paths:
      - '.devcontainer/**'
      - 'package.json'
      - 'package-lock.json'
  schedule:
    - cron: '0 6 * * 1'  # 每周一早上6点

jobs:
  prebuild:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Prebuild dev container image
        uses: devcontainers/ci@v0.3
        with:
          imageName: ghcr.io/your-org/fullstack-dev
          cacheFrom: ghcr.io/your-org/fullstack-dev
          push: always
```

然后在 `devcontainer.json` 中引用预构建镜像：

```json
{
    "name": "Full Stack App Dev",
    "image": "ghcr.io/your-org/fullstack-dev:latest",
    // ... 其他配置不变
}
```

这样，新成员打开项目时直接拉取预构建镜像（通常只需几秒），而不需要从头构建。

## 12.9 进阶：容器特性（Features）

Dev Container Features 是一种可复用的、模块化的容器配置单元。你不需要自己写 Dockerfile 来安装 Node.js、Python、Docker-in-Docker 等常见工具——直接用 Features：

```json
{
    "features": {
        // Node.js（指定版本）
        "ghcr.io/devcontainers/features/node:1": {
            "version": "20",
            "nodeGypDependencies": true
        },

        // Python（指定版本）
        "ghcr.io/devcontainers/features/python:1": {
            "version": "3.12",
            "installTools": true,
            "optimize": true
        },

        // Docker-in-Docker（容器内使用 Docker）
        "ghcr.io/devcontainers/features/docker-in-docker:2": {
            "version": "latest",
            "dockerDashComposeVersion": "v2"
        },

        // GitHub CLI
        "ghcr.io/devcontainers/features/github-cli:1": {},

        // AWS CLI
        "ghcr.io/devcontainers/features/aws-cli:1": {
            "version": "latest"
        },

        // Terraform
        "ghcr.io/devcontainers/features/terraform:1": {},

        // 社区维护的 Features
        "ghcr.io/devcontainers-contrib/features/pnpm:2": {
            "version": "8"
        }
    }
}
```

Features 的完整列表可以在 [devcontainers/features](https://github.com/devcontainers/features) 和 [devcontainers-contrib/features](https://github.com/devcontainers-contrib/features) 仓库中找到。你也可以创建自定义 Feature 发布到 GitHub Container Registry 供团队使用。

## 自定义 Feature 示例

```json
// 自定义 Feature: 安装公司内部 CLI 工具
{
    "id": "internal-cli",
    "version": "1.0.0",
    "name": "Internal CLI Tool",
    "options": {
        "version": {
            "type": "string",
            "default": "latest",
            "description": "Version of the CLI to install"
        }
    },
    "installsAfter": [
        "ghcr.io/devcontainers/features/node"
    ]
}
```

```bash
#!/bin/bash
# install.sh
VERSION=${VERSION:-"latest"}
npm install -g @your-org/cli@${VERSION}
```

## 12.10 进阶：开发和生产环境的 Dev Container 策略

一个成熟的团队通常会有多层 Dev Container 配置：

```
.devcontainer/
├── devcontainer.json          # 默认配置（日常开发）
├── devcontainer.testing.json # 测试环境（附加覆盖率工具）
├── devcontainer.debug.json  # 调试环境（附加调试工具）
├── Dockerfile
└── docker-compose.yml
```

你可以通过命令面板 **Dev Containers: Open Folder in Container...** 选择特定的配置文件打开。

或者，在 CI/CD 中使用 Dev Container：

```yaml
# GitHub Actions 中使用 Dev Container 运行测试
- name: Run tests in dev container
  uses: devcontainers/ci@v0.3
  with:
    runCmd: npm test
```

这确保了 CI 环境与开发环境完全一致——真正的 "It works on my machine, and on every other machine too."

- `devcontainer.json` 是核心配置文件，支持 **Dockerfile**、**docker-compose** 和**预构建镜像**三种方式
- **Features** 提供模块化的工具安装，避免手写复杂的 Dockerfile
- 容器内的 VSCode 体验与本地几乎无差异：扩展、终端、调试、Git 全部正常工作
- **生命周期钩子**（onCreateCommand、postCreateCommand 等）自动化环境初始化
- **端口转发**和**端口属性**让你在容器内无缝开发 Web 应用
- **预构建容器**通过 CI/CD 大幅缩短新成员的环境搭建时间
- **Profiles + Dev Containers** 的组合可以实现团队级的标准化开发环境
