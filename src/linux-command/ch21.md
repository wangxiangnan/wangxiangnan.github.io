## 21.1 循环结构——重复是计算机的超能力

循环是编程中最能体现"让机器干苦力活"的结构。Shell提供了四种循环方式，每一种都有它的用武之地。

```bash
# ============================
# for 循环——遍历列表
# ============================

# 遍历固定列表
for fruit in apple banana cherry; do
    echo "水果: $fruit"
done

# 遍历文件（通配符展开）
for file in /var/log/*.log; do
    echo "日志文件: $file ($(du -h "$file" | cut -f1))"
done

# 遍历数字序列
for i in $(seq 1 10); do
    echo "数字: $i"
done

# 遍历命令输出
for user in $(cut -d: -f1 /etc/passwd); do
    echo "系统用户: $user"
done

# 使用大括号展开
for i in {1..5}; do
    echo "编号: $i"
done

for letter in {a..z}; do
    echo "字母: $letter"
done

# ============================
# C风格 for 循环——经典三段式
# ============================
for ((i=0; i<10; i++)); do
    echo "索引: $i"
done

# 多变量
for ((i=0, j=10; i<j; i++, j--)); do
    echo "i=$i, j=$j"
done

# ============================
# while 循环——条件为真就继续
# ============================

# 基本while循环
count=1
while [ $count -le 5 ]; do
    echo "计数: $count"
    count=$((count + 1))
done

# 逐行读取文件（最常用的文件处理模式）
while IFS= read -r line; do
    echo "行内容: $line"
done < /etc/hosts
# IFS= 防止首尾空格被吃掉
# -r 防止反斜杠被解释为转义符

# 读取CSV文件（设置IFS为逗号）
while IFS=',' read -r name age email; do
    echo "姓名: $name, 年龄: $age, 邮箱: $email"
done < users.csv

# 无限循环（配合break使用）
while true; do
    read -p "请输入命令 (quit退出): " cmd
    if [ "$cmd" = "quit" ]; then
        break
    fi
    echo "执行: $cmd"
done

# ============================
# until 循环——条件为假就继续（while的反面）
# ============================
count=1
until [ $count -gt 5 ]; do
    echo "计数: $count"
    count=$((count + 1))
done

# 实用场景：等待服务启动
until curl -s http://localhost:8080/health > /dev/null 2>&1; do
    echo "等待服务启动..."
    sleep 2
done
echo "服务已就绪！"

# ============================
# 循环控制：break 和 continue
# ============================

# break: 跳出循环
for i in {1..100}; do
    if [ $i -eq 5 ]; then
        echo "到达5，退出循环"
        break
    fi
    echo $i
done

# continue: 跳过当前迭代
for i in {1..10}; do
    if [ $((i % 2)) -eq 0 ]; then
        continue    # 跳过偶数
    fi
    echo "奇数: $i"
done

# 嵌套循环中的break N / continue N
for i in {1..3}; do
    for j in {1..3}; do
        if [ $j -eq 2 ]; then
            break 2    # 跳出两层循环
        fi
        echo "i=$i, j=$j"
    done
done
```

## 21.2 case 语句——优雅的多分支选择

当你有超过3个分支要判断时，用if-elif-elif-elif就像用胶带绑电线——能用但丑。case语句是更优雅的选择，它就像其他语言中的switch/match。

```bash
# ============================
# 基本 case 结构
# ============================
cat > service_ctl.sh << 'SCRIPT'
#!/bin/bash

action="$1"

case "$action" in
    start)
        echo "启动服务..."
        systemctl start myapp
        ;;
    stop)
        echo "停止服务..."
        systemctl stop myapp
        ;;
    restart)
        echo "重启服务..."
        systemctl restart myapp
        ;;
    status)
        echo "查看状态..."
        systemctl status myapp
        ;;
    *)
        echo "用法: $0 {start|stop|restart|status}"
        exit 1
        ;;
esac
SCRIPT

# ============================
# 多模式匹配
# ============================
read -p "确认操作？(yes/no): " answer
case "$answer" in
    [Yy]|[Yy][Ee][Ss])
        echo "执行操作..."
        ;;
    [Nn]|[Nn][Oo])
        echo "操作已取消"
        ;;
    *)
        echo "无效输入"
        ;;
esac

# ============================
# 在菜单脚本中使用 case
# ============================
cat > menu.sh << 'SCRIPT'
#!/bin/bash

show_menu() {
    echo "========================="
    echo "  系统管理菜单"
    echo "========================="
    echo "1) 查看磁盘使用情况"
    echo "2) 查看内存使用情况"
    echo "3) 查看CPU信息"
    echo "4) 查看网络连接"
    echo "5) 查看运行时间"
    echo "0) 退出"
    echo "========================="
}

while true; do
    show_menu
    read -p "请选择 [0-5]: " choice

    case "$choice" in
        1)
            echo ""
            df -h
            ;;
        2)
            echo ""
            free -h
            ;;
        3)
            echo ""
            lscpu | head -15
            ;;
        4)
            echo ""
            ip -brief addr
            ;;
        5)
            echo ""
            uptime
            ;;
        0)
            echo "再见！"
            exit 0
            ;;
        *)
            echo "无效选项，请重新选择"
            ;;
    esac
    echo ""
    read -p "按回车键继续..."
done
SCRIPT
```

## 21.3 函数——Shell脚本的子程序

函数是代码复用的基石。在Shell中，函数就像自定义命令——你可以在脚本中定义它们，然后像调用普通命令一样使用它们。

```bash
# ============================
# 函数定义（两种方式）
# ============================

# 方式一：function关键字
function greet {
    echo "Hello, $1!"
}

# 方式二：POSIX风格（更常用）
greet() {
    echo "Hello, $1!"
}

# 调用函数
greet "World"        # Hello, World!
greet "Linux"        # Hello, Linux!

# ============================
# 函数参数
# ============================
calculate() {
    local a=$1
    local b=$2
    local op=$3

    case "$op" in
        add) echo $((a + b)) ;;
        sub) echo $((a - b)) ;;
        mul) echo $((a * b)) ;;
        div) echo $((a / b)) ;;
        *)   echo "未知操作: $op" ;;
    esac
}

result=$(calculate 10 3 add)
echo "10 + 3 = $result"       # 10 + 3 = 13

# ============================
# 局部变量（local）——极其重要！
# ============================
count=0                         # 全局变量

increment() {
    local count=$1              # 局部变量，不影响全局的count
    count=$((count + 1))
    echo $count
}

result=$(increment 5)
echo "函数返回: $result"        # 6
echo "全局count: $count"        # 0（没有被修改）

# ============================
# 函数返回值
# ============================
# 方式一：通过echo返回（推荐，可以返回字符串）
get_hostname() {
    hostname | tr '[:upper:]' '[:lower:]'
}
my_host=$(get_hostname)

# 方式二：通过return返回状态码（只能返回0-255的数字）
is_admin() {
    if [ "$(id -u)" -eq 0 ]; then
        return 0    # 成功（是admin）
    else
        return 1    # 失败（不是admin）
    fi
}

if is_admin; then
    echo "你是管理员"
else
    echo "你不是管理员"
fi

# ============================
# 实用函数库模式
# ============================
cat > lib.sh << 'EOF'
#!/bin/bash
# lib.sh - 通用工具函数库

# 日志函数
log() {
    local level=$1
    shift
    local msg="$*"
    local timestamp
    timestamp=$(date '+%Y-%m-%d %H:%M:%S')
    echo "[$timestamp] [$level] $msg"
}

log_info()  { log "INFO"  "$@"; }
log_warn()  { log "WARN"  "$@"; }
log_error() { log "ERROR" "$@"; }

# 检查命令是否存在
require_cmd() {
    local cmd=$1
    if ! command -v "$cmd" &>/dev/null; then
        log_error "缺少必要命令: $cmd"
        exit 1
    fi
}

# 确认操作
confirm() {
    local prompt="${1:-确认执行？}"
    read -p "$prompt (y/n): " answer
    [[ "$answer" =~ ^[Yy] ]]
}

# 重试执行
retry() {
    local max_attempts=$1
    local delay=$2
    shift 2
    local attempt=1

    while [ $attempt -le $max_attempts ]; do
        if "$@"; then
            return 0
        fi
        log_warn "第 $attempt/$max_attempts 次尝试失败，${delay}秒后重试..."
        sleep "$delay"
        attempt=$((attempt + 1))
    done

    log_error "命令在 $max_attempts 次尝试后仍然失败: $*"
    return 1
}
EOF

# 在其他脚本中使用
cat > myscript.sh << 'EOF'
#!/bin/bash

# 加载函数库
source "$(dirname "$0")/lib.sh"

# 使用库函数
require_cmd "curl"
require_cmd "jq"

log_info "开始执行任务..."

if confirm "是否继续？"; then
    retry 3 5 curl -s https://api.example.com/data
    log_info "任务完成"
else
    log_warn "用户取消操作"
fi
EOF
```

## 21.4 命令替换与算术运算

```bash
# ============================
# 命令替换——把命令输出当字符串用
# ============================

# 推荐方式：$()
today=$(date '+%Y-%m-%d')
file_count=$(ls -1 | wc -l)
ip_address=$(hostname -I | awk '{print $1}')

echo "今天是 $today，目录中有 $file_count 个文件"

# 旧方式：反引号 ``（不推荐，难嵌套，难阅读）
today=`date '+%Y-%m-%d'`

# $() 的优势：可以嵌套
backup_name="backup_$(hostname)_$(date '+%Y%m%d').tar.gz"
echo $backup_name    # backup_myserver_20240115.tar.gz

# ============================
# 算术运算——Shell的计算器
# ============================

# 方式一：$(( ))（推荐，Bash内置）
a=10
b=3
echo $((a + b))      # 13
echo $((a - b))      # 7
echo $((a * b))      # 30
echo $((a / b))      # 3（整数除法）
echo $((a % b))      # 1（取余）
echo $((a ** b))     # 1000（幂运算）
echo $((a > b))      # 1（真为1，假为0）

# 支持位运算
echo $((a << 2))     # 40（左移2位）
echo $((a >> 1))     # 5（右移1位）
echo $((a & b))      # 2（按位与）
echo $((a | b))      # 11（按位或）

# 方式二：expr（POSIX标准，更通用但更慢）
expr 10 + 3          # 13
expr 10 \* 3         # 30（* 需要转义）
expr 10 % 3          # 1

# 方式三：bc（支持浮点运算）
echo "10 / 3" | bc -l              # 3.33333333333333333333（-l 设 scale=20）
echo "scale=2; 10 / 3" | bc        # 3.33
echo "scale=4; 3.14 * 2.5" | bc    # 7.850

# 实用示例：计算磁盘使用百分比
used=$(df / | awk 'NR==2 {print $3}')
total=$(df / | awk 'NR==2 {print $2}')
echo "scale=1; $used * 100 / $total" | bc
```

## 21.6 错误处理——让脚本健壮如牛

生产环境的脚本不能假设一切顺利。磁盘可能满、网络可能断、命令可能不存在。错误处理就是把"可能出问题的地方"提前准备好。

```bash
# ============================
# set 命令——Shell的安全模式
# ============================

# set -e: 遇到错误立即退出（Exit on error）
set -e
# false                # 这条命令返回非0，脚本直接退出
# echo "这行不会执行"

# set -u: 使用未定义变量时报错
set -u
# echo $UNDEFINED_VAR  # 报错: UNDEFINED_VAR: unbound variable

# set -o pipefail: 管道中任何命令失败都视为失败
set -o pipefail
# 默认行为：管道的退出状态是最后一个命令的状态
# 开启pipefail后：管道中任何一个命令失败，整条管道就算失败

# 推荐的脚本开头（黄金三件套）
set -euo pipefail

# ============================
# trap——信号捕获与清理
# ============================

# 脚本退出时清理临时文件
tmpfile=$(mktemp)
trap "rm -f '$tmpfile'" EXIT

# 捕获 Ctrl+C（SIGINT）
trap 'echo ""; echo "收到中断信号，正在清理..."; cleanup; exit 1' INT

# 实用：脚本锁文件模式
LOCKFILE="/tmp/myscript.lock"

cleanup() {
    rm -f "$LOCKFILE"
}

trap cleanup EXIT

# 检查是否已有实例在运行
if [ -f "$LOCKFILE" ]; then
    pid=$(cat "$LOCKFILE")
    if kill -0 "$pid" 2>/dev/null; then
        echo "脚本已在运行 (PID: $pid)"
        exit 1
    else
        echo "发现过期的锁文件，清理中..."
        rm -f "$LOCKFILE"
    fi
fi

echo $$ > "$LOCKFILE"
echo "脚本正在运行..."
sleep 10
echo "脚本执行完毕"

# ============================
# 完整的错误处理模式
# ============================
cat > robust_script.sh << 'EOF'
#!/usr/bin/env bash

set -euo pipefail

readonly SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
readonly SCRIPT_NAME="$(basename "$0")"
readonly LOG_FILE="/tmp/${SCRIPT_NAME%.sh}.log"

log() {
    local level="$1"; shift
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] [$level] $*" | tee -a "$LOG_FILE"
}

cleanup() {
    local exit_code=$?
    log "INFO" "脚本退出，退出码: $exit_code"
    exit $exit_code
}

error_handler() {
    local line_number="$1"
    log "ERROR" "脚本在第 $line_number 行出错"
    log "ERROR" "最后执行的命令: $BASH_COMMAND"
}

trap cleanup EXIT
trap 'error_handler $LINENO' ERR

main() {
    log "INFO" "脚本开始执行"
    log "INFO" "脚本目录: $SCRIPT_DIR"
    log "INFO" "日志文件: $LOG_FILE"

    log "INFO" "执行任务1..."
    sleep 1

    log "INFO" "执行任务2..."
    sleep 1

    log "INFO" "脚本执行完成"
}

main "$@"
EOF
```

## 21.9 实战：自动化部署脚本

让我们把所有进阶知识综合运用，编写一个生产级别的自动化部署脚本。这个脚本模拟了一个真实的CI/CD流程：拉取代码、构建、备份、部署、健康检查、通知。

```bash
#!/usr/bin/env bash
# ============================================================
# deploy.sh - 自动化部署脚本
# 功能: 拉取代码 -> 构建 -> 备份旧版本 -> 部署新版本 -> 健康检查 -> 通知
# 用法: ./deploy.sh [--branch main] [--env production] [--rollback]
# ============================================================

set -euo pipefail

# ============================
# 配置
# ============================
readonly APP_NAME="myapp"
readonly DEPLOY_DIR="/opt/${APP_NAME}"
readonly BACKUP_DIR="/opt/backups/${APP_NAME}"
readonly LOG_DIR="/var/log/${APP_NAME}"
readonly REPO_URL="https://github.com/example/myapp.git"
readonly HEALTH_CHECK_URL="http://localhost:3000/health"
readonly MAX_HEALTH_RETRIES=30
readonly HEALTH_CHECK_INTERVAL=2

# 默认值
BRANCH="main"
ENVIRONMENT="production"
ROLLBACK=false
BUILD_DIR=""

# 颜色
readonly RED='\033[0;31m'
readonly GREEN='\033[0;32m'
readonly YELLOW='\033[1;33m'
readonly BLUE='\033[0;34m'
readonly NC='\033[0m'

# ============================
# 工具函数
# ============================
log_info()  { echo -e "${GREEN}[INFO]${NC}  $(date '+%H:%M:%S') $*"; }
log_warn()  { echo -e "${YELLOW}[WARN]${NC}  $(date '+%H:%M:%S') $*"; }
log_error() { echo -e "${RED}[ERROR]${NC} $(date '+%H:%M:%S') $*"; }
log_step()  { echo -e "\n${BLUE}>>> $*${NC}"; }

error_exit() {
    log_error "$*"
    log_error "部署失败！如需回滚请运行: $0 --rollback"
    exit 1
}

cleanup() {
    local exit_code=$?
    if [ $exit_code -ne 0 ]; then
        log_warn "部署过程中断（退出码: $exit_code）"
        log_warn "清理临时文件..."
        rm -rf "/tmp/${APP_NAME}_build_$$"
    fi
}
trap cleanup EXIT

# ============================
# 参数解析
# ============================
parse_args() {
    while [[ $# -gt 0 ]]; do
        case "$1" in
            --branch)
                BRANCH="$2"
                shift 2
                ;;
            --env)
                ENVIRONMENT="$2"
                shift 2
                ;;
            --rollback)
                ROLLBACK=true
                shift
                ;;
            --help|-h)
                echo "用法: $0 [选项]"
                echo "  --branch <name>   指定分支 (默认: main)"
                echo "  --env <name>      指定环境 (默认: production)"
                echo "  --rollback        回滚到上一个版本"
                echo "  --help            显示帮助"
                exit 0
                ;;
            *)
                error_exit "未知参数: $1"
                ;;
        esac
    done
}

# ============================
# 部署步骤
# ============================

step_preflight() {
    log_step "步骤 1/6: 预检查"

    local required_cmds=("git" "node" "npm" "tar")
    for cmd in "${required_cmds[@]}"; do
        if ! command -v "$cmd" &>/dev/null; then
            error_exit "缺少必要命令: $cmd"
        fi
    done
    log_info "所有必要命令已就绪"

    if [ ! -w "$(dirname "$DEPLOY_DIR")" ]; then
        error_exit "没有写入权限: $(dirname "$DEPLOY_DIR")"
    fi

    mkdir -p "$DEPLOY_DIR" "$BACKUP_DIR" "$LOG_DIR"
    log_info "目录结构已就绪"
}

step_pull_code() {
    log_step "步骤 2/6: 拉取代码"

    BUILD_DIR="/tmp/${APP_NAME}_build_$$"
    rm -rf "$BUILD_DIR"

    log_info "克隆分支 ${BRANCH} ..."
    git clone --depth 1 --branch "$BRANCH" "$REPO_URL" "$BUILD_DIR" 2>&1 | \
        while read -r line; do echo "    $line"; done

    local commit_hash commit_msg
    commit_hash=$(git -C "$BUILD_DIR" rev-parse --short HEAD)
    commit_msg=$(git -C "$BUILD_DIR" log -1 --format='%s')

    log_info "最新提交: ${commit_hash} - ${commit_msg}"
    echo "$commit_hash" > "${BUILD_DIR}/.deploy_commit"
}

step_build() {
    log_step "步骤 3/6: 构建项目"

    cd "$BUILD_DIR"

    log_info "安装依赖..."
    npm ci --production 2>&1 | tail -3

    log_info "执行构建..."
    if [ -f "package.json" ] && grep -q '"build"' package.json; then
        npm run build 2>&1 | tail -5
    else
        log_warn "未找到build脚本，跳过构建步骤"
    fi

    log_info "构建完成"
}

step_backup() {
    log_step "步骤 4/6: 备份当前版本"

    if [ -d "$DEPLOY_DIR" ] && [ "$(ls -A "$DEPLOY_DIR" 2>/dev/null)" ]; then
        local backup_name="${APP_NAME}_$(date '+%Y%m%d_%H%M%S').tar.gz"
        local backup_path="${BACKUP_DIR}/${backup_name}"

        log_info "备份到: ${backup_path}"
        tar -czf "$backup_path" -C "$(dirname "$DEPLOY_DIR")" "$(basename "$DEPLOY_DIR")"

        # 只保留最近5个备份
        ls -t "${BACKUP_DIR}"/${APP_NAME}_*.tar.gz 2>/dev/null | tail -n +6 | xargs -r rm -f
        log_info "备份完成（保留最近5个备份）"
    else
        log_info "首次部署，无需备份"
    fi
}

step_deploy() {
    log_step "步骤 5/6: 部署新版本"

    if systemctl is-active --quiet "$APP_NAME" 2>/dev/null; then
        log_info "停止旧服务..."
        sudo systemctl stop "$APP_NAME"
    fi

    log_info "同步文件到 ${DEPLOY_DIR} ..."
    if command -v rsync &>/dev/null; then
        rsync -a --delete \
            --exclude='.git' \
            --exclude='node_modules' \
            --exclude='.env' \
            "$BUILD_DIR/" "$DEPLOY_DIR/"
    else
        cp -r "$BUILD_DIR"/* "$DEPLOY_DIR"/
    fi

    chmod -R 755 "$DEPLOY_DIR"

    if [ -f "${DEPLOY_DIR}/.env.${ENVIRONMENT}" ]; then
        cp "${DEPLOY_DIR}/.env.${ENVIRONMENT}" "${DEPLOY_DIR}/.env"
        log_info "已加载 ${ENVIRONMENT} 环境配置"
    fi

    log_info "启动服务..."
    if [ -f "${DEPLOY_DIR}/systemd/${APP_NAME}.service" ]; then
        sudo cp "${DEPLOY_DIR}/systemd/${APP_NAME}.service" /etc/systemd/system/
        sudo systemctl daemon-reload
    fi
    sudo systemctl start "$APP_NAME" 2>/dev/null || \
        log_warn "systemd服务未配置，请手动启动"

    rm -rf "$BUILD_DIR"
    log_info "部署文件同步完成"
}

step_health_check() {
    log_step "步骤 6/6: 健康检查"

    log_info "等待服务启动..."
    local attempt=0

    while [ $attempt -lt $MAX_HEALTH_RETRIES ]; do
        if curl -sf "$HEALTH_CHECK_URL" > /dev/null 2>&1; then
            log_info "健康检查通过！服务运行正常"
            return 0
        fi
        attempt=$((attempt + 1))
        printf "."
        sleep "$HEALTH_CHECK_INTERVAL"
    done

    echo ""
    error_exit "健康检查失败！服务在 $((MAX_HEALTH_RETRIES * HEALTH_CHECK_INTERVAL))秒 内未就绪"
}

# ============================
# 回滚功能
# ============================
do_rollback() {
    log_step "执行回滚"

    local latest_backup
    latest_backup=$(ls -t "${BACKUP_DIR}"/${APP_NAME}_*.tar.gz 2>/dev/null | head -1)

    if [ -z "$latest_backup" ]; then
        error_exit "没有找到可用的备份"
    fi

    log_info "使用备份: $latest_backup"
    log_warn "这将覆盖当前部署目录！"

    sudo systemctl stop "$APP_NAME" 2>/dev/null || true

    tar -xzf "$latest_backup" -C "$(dirname "$DEPLOY_DIR")"

    sudo systemctl start "$APP_NAME" 2>/dev/null || true

    log_info "回滚完成"
}

# ============================
# 通知函数
# ============================
send_notification() {
    local status="$1"
    local message="$2"

    if [ -n "${SLACK_WEBHOOK_URL:-}" ]; then
        curl -s -X POST "$SLACK_WEBHOOK_URL" \
            -H 'Content-Type: application/json' \
            -d "{\"text\": \"[${APP_NAME}] ${status}: ${message}\"}" \
            > /dev/null 2>&1 || true
    fi

    log_info "通知已发送: [$status] $message"
}

# ============================
# 主函数
# ============================
main() {
    parse_args "$@"

    echo "============================================"
    echo "  ${APP_NAME} 自动部署"
    echo "  分支: ${BRANCH}"
    echo "  环境: ${ENVIRONMENT}"
    echo "  时间: $(date '+%Y-%m-%d %H:%M:%S')"
    echo "============================================"

    if [ "$ROLLBACK" = true ]; then
        do_rollback
        exit 0
    fi

    local start_time
    start_time=$(date +%s)

    step_preflight
    step_pull_code
    step_build
    step_backup
    step_deploy
    step_health_check

    local end_time duration
    end_time=$(date +%s)
    duration=$((end_time - start_time))

    echo ""
    echo "============================================"
    log_info "部署成功！耗时: ${duration}秒"
    echo "============================================"

    send_notification "SUCCESS" "部署成功，耗时 ${duration}秒"
}

main "$@"
```

**1. 写出"逐行读取文件"的循环，并说明 `IFS=` 与 `-r` 各防什么。**

<details>
<summary>点击查看答案</summary>

```bash
while IFS= read -r line; do
    echo "行内容: $line"
done < /etc/hosts
```

`IFS=` 把字段分隔符置空，防止行首行尾的空格被吃掉；`-r` 防止反斜杠被当成转义符。对照实验：内容为 `  padded line  ` 的一行，加了 `IFS=` 输出保留首尾空格，不加则被剥掉；含 `back\slash` 的一行，不加 `-r` 会变成 `backslash`。读 CSV 则把 IFS 设成逗号：`while IFS=',' read -r name age email; do ... done < users.csv`。见 21.1 节。

</details>

**2. while 与 until 有什么区别？写出"等待服务健康检查通过再继续"的循环。**

<details>
<summary>点击查看答案</summary>

while 是条件为真就继续，until 是条件为假就继续（while 的反面），适合"等到某件事成立"的场景：

```bash
until curl -s http://localhost:8080/health > /dev/null 2>&1; do
    echo "等待服务启动..."
    sleep 2
done
echo "服务已就绪！"
```

curl 探测失败（非 0）时条件为假，循环继续等待；一旦探测成功（返回 0），until 条件为真就退出循环。见 21.1 节。

</details>

**3. 预测输出：`for i in {1..100}; do if [ $i -eq 5 ]; then echo "到达5，退出循环"; break; fi; echo $i; done` 打印什么？嵌套循环里的 `break 2` 与 `continue 2` 又各是什么效果？**

<details>
<summary>点击查看答案</summary>

先逐行打印 1、2、3、4，然后打印"到达5，退出循环"——i 等于 5 时 break 在 `echo $i` 之前就跳出了，所以 5 不会被打印。`continue` 只跳过本次迭代剩下的语句（书中例子因此只打印奇数 1、3、5、7、9）。带层数时：`break N` 跳出 N 层循环，`continue N` 跳到外层循环的下一次迭代。书中 i、j 双层 `{1..3}` 的例子里，j 等于 2 时 `break 2` 只输出 `i=1, j=1` 就整体结束；换成 `continue 2` 则输出 `i=1, j=1`、`i=2, j=1`、`i=3, j=1`。见 21.1 节。

</details>

**4. case 语句里 `;;` 和 `*)` 各起什么作用？写出 service_ctl.sh 的分支骨架（start/stop/restart/status，其余打印用法并退出 1）。**

<details>
<summary>点击查看答案</summary>

```bash
case "$action" in
    start)   echo "启动服务..." ;;
    stop)    echo "停止服务..." ;;
    restart) echo "重启服务..." ;;
    status)  echo "查看状态..." ;;
    *)       echo "用法: $0 {start|stop|restart|status}"; exit 1 ;;
esac
```

`;;` 标记一个分支结束，漏写会直接报语法错误（bash 不像 C 那样允许"贯穿"）；`*)` 是兜底分支，匹配任何值，必须放在最后。多个模式用 `|` 分隔，例如 `[Yy]|[Yy][Ee][Ss])` 同时匹配 y、Y、yes、Yes 等写法。分支超过三个时，case 比 if-elif 链清晰得多。见 21.2 节。

</details>

**5. 函数怎么"返回"结果？`echo` 配 `$()` 与 `return` 有什么区别？预测 `result=$(calculate 10 3 add)` 的值。**

<details>
<summary>点击查看答案</summary>

`result` 是 13。推荐用 echo 输出、再用命令替换捕获，这样能返回任意字符串（如 `my_host=$(get_hostname)`）；`return` 只能返回 0–255 的退出状态码，用来表示成功/失败，配合 `if is_admin; then ...` 使用（函数内 `[ "$(id -u)" -eq 0 ]` 成立就 `return 0`，否则 `return 1`）。函数参数同样是 `$1`/`$2`/`$3`，与脚本自身的参数互不干扰；`shift` 可以逐个丢掉已处理的参数。见 21.3 节。

</details>

**6. 预测输出：`count=0`，`increment() { local count=$1; count=$((count + 1)); echo $count; }`，执行 `result=$(increment 5)` 后 `echo "$result"` 与 `echo "$count"` 各是什么？去掉 local 又会有什么不同？**

<details>
<summary>点击查看答案</summary>

`result` 是 6，全局 `count` 仍是 0——local 声明的 count 只在函数内可见，函数退出即消失。去掉 local 后要看调用方式：仍用 `result=$(increment 5)` 时，命令替换会开子 Shell，全局 count 依然是 0；只有直接调用 `increment 5`（不套 `$()`）才会把全局 count 改成 6。所以函数内一律用 local：既不污染全局，也不依赖调用方式。见 21.3 节（子 Shell 陷阱另见 20.10 节）。

</details>

**7. 预测输出：`a=10; b=3` 时 `echo $((a / b))`、`$((a % b))`、`$((a ** b))` 各是什么？要算 10/3 的浮点结果该用什么？`$()` 比反引号好在哪？**

<details>
<summary>点击查看答案</summary>

依次是 3（整数除法，直接截断小数）、1（取余）、1000（幂）。浮点运算交给 bc：`echo "scale=2; 10 / 3" | bc` 输出 3.33；expr 同样是整数运算，而且 `*` 必须转义成 `\*`。`$()` 的优势是可嵌套、可读性好，例如 `backup_name="backup_$(hostname)_$(date '+%Y%m%d').tar.gz"`，反引号嵌套时难以阅读。见 21.4 节。

</details>

**8. 写出命令：隐藏回显地读取密码；读取用户输入但最多等 10 秒，超时则用"（超时）"兜底。**

<details>
<summary>点击查看答案</summary>

```bash
read -s -p "请输入密码: " password
echo ""
read -t 10 -p "10秒内输入 (超时自动跳过): " input
echo "你输入了: ${input:-（超时）}"
```

`-s` 静默不回显（也不输出换行，所以要补一个 `echo ""`）；`-t` 超时后 read 返回非 0（大于 128），变量为空，用 `${input:-…}` 兜底；`-p` 给提示语，`-n 1` 只读一个字符，`read name age` 可按空格一次读入多个变量。见 21.5 节。

</details>

**9. 预测输出：`variable="EXPANDED"` 时，`cat << EOF` 与 `cat << 'EOF'` 两种写法中的 `$variable` 分别输出什么？`<<<` 又是什么？**

<details>
<summary>点击查看答案</summary>

不加引号的 EOF 会做变量展开与命令替换，输出 `EXPANDED`；加引号的 `'EOF'` 原样输出 `$variable`——生成配置文件或写另一个脚本时常用这种写法。`<<<` 是 Here String，把单个字符串当标准输入喂给命令：

```bash
wc -l <<< $'line1\nline2\nline3'      # 3
sort <<< $'cherry\napple\nbanana'     # apple / banana / cherry
```

重定向方面：`> out.log 2> err.log` 分开存，`> all.log 2>&1`（简写 `&> all.log`）合并存，`2>/dev/null` 丢弃错误输出。见 21.5 节。

</details>

**10. `set -euo pipefail` 三件套各防什么？为什么清理逻辑挂在 `trap EXIT` 上最可靠？写出临时文件自动清理的两行命令。**

<details>
<summary>点击查看答案</summary>

`-e` 遇到命令失败立即退出；`-u` 引用未定义变量就报错（unbound variable）；`-o pipefail` 让管道中任一环节失败都算整条失败——`false | true` 默认返回 0，开启后返回 1。EXIT 在脚本以任何方式结束时都会触发：正常跑完、`set -e` 中途退出、显式 `exit 1` 都算，所以清理挂这里最可靠；INT 捕获 Ctrl+C，ERR 捕获命令失败（书中用 `error_handler $LINENO` 记录出错行号与 `$BASH_COMMAND`）。

```bash
tmpfile=$(mktemp)
trap 'rm -f "$tmpfile"' EXIT
```

一个容易踩的细节：ERR trap 默认不被函数继承，要让函数内部的失败也触发它，需要再加 `set -E`（errtrace）。见 21.6 节。

</details>

**11. `bash -x`、`bash -n`、shellcheck 三者各做什么？`set -x` / `set +x` 与 PS4 又有什么用？**

<details>
<summary>点击查看答案</summary>

`bash -x` 边执行边把每条命令打印到 stderr（前缀 `+`），能看到变量展开后的真实命令；`bash -n` 只做语法检查、不执行，有错报 syntax error 并返回非 0，无错则静默；shellcheck 是静态分析，不运行脚本就指出引号缺失、废弃语法等问题。`set -x` / `set +x` 在脚本内部开关跟踪，只调试可疑片段；PS4 自定义跟踪前缀，书中 `export PS4='+(${BASH_SOURCE}:${LINENO}): ${FUNCNAME[0]:+${FUNCNAME[0]}(): }'` 能打出文件名、行号与函数名。临时调试输出走 stderr（`echo "DEBUG: var=$var" >&2`）不污染正常输出。这些正是 21.8 最佳实践清单的落地：变量加引号、用 `[[ ]]` 与 `$()`、函数内 local、常量大写 readonly。见 21.7、21.8 节。

</details>

**12. 把 deploy.sh 的六个部署步骤排序，并说明它的备份与回滚是怎么做的。**

<details>
<summary>点击查看答案</summary>

预检查 step_preflight → 拉取代码 step_pull_code → 构建 step_build → 备份旧版本 step_backup → 部署 step_deploy → 健康检查 step_health_check（成功后再 send_notification 通知）。备份用 `tar -czf` 打包到 BACKUP_DIR，文件名带 `date '+%Y%m%d_%H%M%S'`，再用 `ls -t … | tail -n +6 | xargs -r rm -f` 只保留最近 5 份；`--rollback` 走 do_rollback：取最新备份 `tar -xzf` 解回部署目录。参数解析是 `while [[ $# -gt 0 ]]` 配 `case "$1"`（`--branch`/`--env` 用 `shift 2`，`--rollback` 用 `shift`）；健康检查用 while 重试 `curl -sf`，最多 30 次、每次间隔 2 秒，仍失败就 error_exit。见 21.9 节。

</details>

## 本章命令速查表

| 概念/命令 | 说明 | 示例 |
| ----------- | ------ | ------ |
| `for ... in ... do` | 列表遍历循环 | `for f in *.log; do ...` |
| `for ((i=0;i<N;i++))` | C风格循环 | `for ((i=0;i<10;i++))` |
| `while condition` | 条件循环 | `while read -r line` |
| `until condition` | 反向条件循环 | `until curl -s url` |
| `case ... in ... esac` | 多分支选择 | `case "$1" in start) ...` |
| `function` / `name()` | 函数定义 | `greet() { echo "Hi $1"; }` |
| `local` | 局部变量声明 | `local count=0` |
| `$(command)` | 命令替换 | `today=$(date +%F)` |
| `$((expr))` | 算术运算 | `echo $((a + b))` |
| `read -p -s -t` | 读取输入 | `read -s -p "密码: " pw` |
| `<< EOF ... EOF` | Here Document | `cat << EOF` |
| `<<<` | Here String | `jq '.name' <<< "$json"` |
| `set -e` | 遇错即退 | `set -euo pipefail` |
| `set -u` | 未定义变量报错 | `set -euo pipefail` |
| `set -o pipefail` | 管道失败检测 | `set -euo pipefail` |
| `trap` | 信号捕获 | `trap cleanup EXIT` |
| `bash -x` | 调试执行 | `bash -x script.sh` |
| `bash -n` | 语法检查 | `bash -n script.sh` |
| `shellcheck` | 静态分析 | `shellcheck script.sh` |
