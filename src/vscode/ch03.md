# 第3章：设置系统深度解析

> 如果你写过 CSS，一定熟悉层叠：内联样式压过 ID 选择器，ID 压过类。VSCode 的设置系统也有几乎一样的"层叠"机制——只不过它的层级不是选择器，而是**作用域**。理解这条链，"为什么我改了设置却没生效"就不再是玄学。

## 3.1 作用域与优先级

VSCode 有五个设置作用域层级，外加语言级设置和企业策略：

| 优先级 | 作用域 | 存储位置 | 怎么打开 |
| --- | --- | --- | --- |
| 1（最低） | 默认设置 Default | VSCode 内置 | `Preferences: Open Default Settings (JSON)` |
| 2 | 用户设置 User | Windows `%APPDATA%\Code\User\settings.json`<br>macOS `~/Library/Application Support/Code/User/settings.json`<br>Linux `~/.config/Code/User/settings.json` | `Ctrl+,` 的 User 标签，或 `Preferences: Open User Settings (JSON)` |
| 3 | 远程设置 Remote | 远程机器 / 容器 / WSL 中 | 连上远程后，设置编辑器的 Remote 标签，或 `Preferences: Open Remote Settings (JSON)` |
| 4 | 工作区设置 Workspace | 单文件夹：`.vscode/settings.json`<br>多根：`.code-workspace` 的 `settings` 字段 | 设置编辑器的 Workspace 标签 |
| 5 | 文件夹设置 Folder | 多根工作区中的 `<folder>/.vscode/settings.json` | 设置编辑器的 Folder 标签 |
| 6 | 语言级设置 | `"[python]"` 这类块，可以出现在以上任意一层 | 设置编辑器搜 `@lang:python` |
| 7（最高） | 企业策略 Policy | 由管理员下发 | 搜 `@haspolicy` |

官方文档给出的完整覆盖顺序（后者覆盖前者）是：

```
默认 → 用户 → 远程 → 工作区 → 文件夹
     → 语言级默认 → 语言级用户 → 语言级远程 → 语言级工作区 → 语言级文件夹
     → 企业策略
```

有三个必须记住的细节：

- **逐键解析，不是整文件覆盖**。在用户设置里改 `editor.tabSize`、在工作区里改 `editor.fontSize`，最终两个都生效；只有同名键才比较优先级。
- **对象类型跨层合并，原始值和数组直接覆盖**。`files.exclude`、`search.exclude` 这类对象会把各层合并起来；`editor.rulers` 这类数组则整体替换。
- **语言级设置永远压过非语言级设置**，即使对方的范围更窄。用户设置里的 `"[python]": { "editor.tabSize": 4 }` 会盖过工作区里的 `"editor.tabSize": 2`。同一门语言在用户层和工作区层都有配置时，两者合并，工作区优先。

单文件夹工作区里，Workspace 和 Folder 其实是同一个文件——`.vscode/settings.json`；只有多根工作区才会出现 `.code-workspace` 与各文件夹两份配置（见第 2 章）。

如果你在用 Profile，用户设置实际来自 `<User 目录>/profiles/<profile-id>/settings.json`，`Ctrl+,` 打开的也是当前 Profile 那一份。切换 Profile 后觉得"设置全回默认了"，多半是这个原因。

### 类比作用域链

把每个设置项想象成一次变量查找：从最近的作用域往外找，找到就停。

```javascript
const layers = [
  { name: "默认",   values: { "editor.tabSize": 4, "editor.fontSize": 14 } },
  { name: "用户",   values: { "editor.tabSize": 2 } },
  { name: "工作区", values: { "editor.fontSize": 15 } },
];

function resolve(key) {
  for (let i = layers.length - 1; i >= 0; i--) {
    if (key in layers[i].values) {
      return { value: layers[i].values[key], from: layers[i].name };
    }
  }
}

resolve("editor.tabSize");  // { value: 2,  from: "用户" }
resolve("editor.fontSize"); // { value: 15, from: "工作区" }
```

一句话总结：**就近覆盖，逐键继承**。对象值的跨层合并是唯一需要额外记的例外。

## 3.2 settings.json 的语法与智能提示

`settings.json` 本质是 JSONC（JSON with Comments），可以写注释：

```jsonc
// 行注释、块注释都可以
{
  /* 标准 JSON 不允许，但这里没问题 */
  "editor.tabSize": 2
}
```

VSCode 会根据已安装扩展声明的 `contributes.configuration` 拼出设置 schema，因此在 `settings.json` 里能得到：

- **键名补全**：输入 `editor.` 会列出所有编辑器设置
- **值补全与类型提示**：枚举值自动提示，悬停可看默认值和说明
- **未知设置警告**：拼错的键会画波浪线（`Unknown Configuration Setting`），不用等运行时才发现
- **文档入口**：悬停或设置编辑器里可直接跳到该设置的文档

### 设置编辑器不只是给新手用的

`Ctrl+,`（`⌘+,`）打开的图形界面有几样很实用的能力：

- 左上角切 **User / Workspace / Folder**（多根工作区才有 Folder），直接决定写进哪一层
- 搜索支持过滤器：`@modified` 只看改过的、`@lang:python` 只看某语言、`@ext:esbenp.prettier-vscode` 只看某扩展、`@id:editor.tabSize` 精确匹配、`@feature:terminal` 按功能分组、`@haspolicy` 只看企业策略
- 每个设置项下方标注 **Modified in: User / Workspace / Folder**，排查"谁覆盖了谁"非常直观
- 齿轮菜单可以 *Copy Setting ID*、*Copy Setting as JSON*、*Reset Setting*

> 想把配置分享给团队时，先用 `@modified` 过滤，再逐项 *Copy Setting as JSON*，比翻整个文件快得多。

## 3.3 常用高价值设置

### 编辑器（editor.*）

```jsonc
{
  // ===== 外观 =====
  "editor.renderWhitespace": "selection",       // 仅选区显示空白字符
  "editor.renderLineHighlight": "all",          // 高亮当前行与行号
  "editor.matchBrackets": "always",             // 始终高亮匹配括号
  "editor.occurrencesHighlight": "singleFile",  // 高亮同文件中的同名符号
  "editor.semanticHighlighting.enabled": true,  // 语义高亮

  // ===== 折叠 =====
  "editor.showFoldingControls": "mouseover",    // 悬停才显示折叠箭头
  "editor.foldingImportsByDefault": true,       // 默认折叠 import 区

  // ===== 补全 =====
  "editor.quickSuggestions": {
    "other": "on",
    "comments": "off",
    "strings": "on"                             // 字符串里也出建议
  },
  "editor.suggestSelection": "first",           // 默认选第一项
  "editor.acceptSuggestionOnCommitCharacter": false,
  "editor.snippetSuggestions": "top",           // 片段排在建议顶部
  "editor.suggest.showWords": false,            // 不把纯单词混进建议

  // ===== 光标 =====
  "editor.multiCursorModifier": "alt",          // Alt/Option+点击加光标
  "editor.cursorSmoothCaretAnimation": "on",
  "editor.cursorBlinking": "smooth"
}
```

`editor.multiCursorModifier` 只有 `alt` 和 `ctrlCmd` 两个值。改成 `ctrlCmd` 会用 `Ctrl`/`Cmd`+点击加光标，但会和"跳转定义"抢手势，多数人保持 `alt`。

### 文件（files.*）

```jsonc
{
  // ===== 文件关联 =====
  "files.associations": {
    "*.jsx": "javascriptreact",
    "*.tsx": "typescriptreact",
    ".env.*": "dotenv",
    "*.graphql": "graphql",
    "*.mdx": "markdown"
  },

  // ===== 资源管理器里隐藏（不影响搜索、不影响文件监听） =====
  "files.exclude": {
    "**/.git": true,
    "**/.DS_Store": true,
    "**/node_modules": true,
    "**/__pycache__": true,
    "**/.next": true,
    "**/dist": true
  },

  // ===== 文件监听排除（性能关键） =====
  // 排除后，依赖文件事件的扩展也收不到这些目录的变化
  "files.watcherExclude": {
    "**/.git/objects/**": true,
    "**/.git/subtree-cache/**": true,
    "**/node_modules/**": true,
    "**/dist/**": true,
    "**/.cache/**": true
  }
}
```

这三个 exclude 各管一摊：`files.exclude` 管资源管理器显示，`search.exclude` 管搜索，`files.watcherExclude` 管文件监听。在资源管理器里隐藏文件，不代表它不被监听——想省 CPU 要动第三个。

### 搜索（search.*）

```jsonc
{
  "search.exclude": {
    "**/node_modules": true,
    "**/dist": true,
    "**/build": true,
    "**/coverage": true,
    "**/.git": true,
    "**/tmp": true,
    "**/package-lock.json": true
  },
  "search.smartCase": true,           // 输入大写时自动区分大小写
  "search.useIgnoreFiles": true,      // 尊重 .gitignore
  "search.useGlobalIgnoreFiles": true,// 尊重全局 .gitignore
  "search.followSymlinks": false      // 不跟随符号链接，减少误扫
}
```

`search.exclude` 是对象，所以会和默认排除项、用户级排除项合并，而不是整体替换。

### 终端（terminal.*）

```jsonc
{
  "terminal.integrated.defaultProfile.windows": "PowerShell",
  "terminal.integrated.profiles.windows": {
    "PowerShell": {
      "source": "PowerShell",
      "icon": "terminal-powershell",
      "args": ["-NoLogo"]
    },
    "Git Bash": {
      "source": "Git Bash",
      "icon": "terminal-bash"
    }
  },
  "terminal.integrated.scrollback": 10000,          // 回滚行数
  "terminal.integrated.copyOnSelection": false,      // 选中即复制
  "terminal.integrated.rightClickBehavior": "default",
  "terminal.integrated.enableMultiLinePasteWarning": "always"
}
```

`profiles.windows` 里的 `source` 从系统检测到的 shell 里取（Git Bash 需要本机已安装）。改默认 shell 只影响**新开**的终端，当前已打开的不会变。

## 3.4 语言特定设置

语言级设置用语言 ID 作为键名，是混合技术栈项目里最省心的功能：

```jsonc
{
  // 通用设置
  "editor.tabSize": 2,
  "editor.formatOnSave": true,

  // Python：4 空格、Black、88 列
  "[python]": {
    "editor.tabSize": 4,
    "editor.defaultFormatter": "ms-python.black-formatter",
    "editor.codeActionsOnSave": {
      "source.organizeImports": "explicit"
    },
    "editor.rulers": [88, 120]
  },

  // TypeScript / React
  "[typescript]": {
    "editor.tabSize": 2,
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.rulers": [100]
  },
  "[typescriptreact]": {
    "editor.tabSize": 2,
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.rulers": [100]
  },

  // Markdown：自动换行，关掉代码补全
  "[markdown]": {
    "editor.wordWrap": "on",
    "editor.quickSuggestions": {
      "comments": "off",
      "strings": "off",
      "other": "off"
    },
    "editor.renderWhitespace": "none",
    "files.trimTrailingWhitespace": false       // 行尾两个空格是硬换行
  },

  // Go：gofmt 用 Tab
  "[go]": {
    "editor.tabSize": 4,
    "editor.insertSpaces": false,
    "editor.defaultFormatter": "golang.go",
    "editor.codeActionsOnSave": {
      "source.organizeImports": "explicit"
    }
  },

  // YAML
  "[yaml]": {
    "editor.tabSize": 2,
    "editor.autoIndent": "advanced",
    "editor.defaultFormatter": "redhat.vscode-yaml"
  }
}
```

一个全栈项目里同时有 TypeScript（2 空格）、Python（4 空格）和 Go（Tab），不需要切文件时手动调缩进——语言级设置自动接管。

### 查找语言 ID

不确定某个语言的 ID？有两种方式：

- 点状态栏右下角的语言名（比如 `Plain Text`），选择 **Change Language Mode**，列表里括号中的就是 ID
- 命令面板执行 `Configure Language Specific Settings`，选择语言后会直接跳到用户设置里对应的 `[id]` 块

常用 ID：

| 语言 | ID |
| ------ | ----- |
| JavaScript | `javascript` |
| TypeScript | `typescript` |
| TypeScript React | `typescriptreact` |
| Python | `python` |
| Go | `go` |
| Rust | `rust` |
| Markdown | `markdown` |
| YAML | `yaml` |

> 记不住格式化器的 ID 时，别手写：打开一个该语言的文件，执行 `Format Document With...` → **Configure Default Formatter**，VSCode 会把正确的 ID 写进当前作用域的 `[lang]` 块。

## 3.5 设置同步（Settings Sync）

内置的 Settings Sync 让配置跨设备保持一致，但它的存储方式和一些老教程说的不一样。

### 开启

1. 左下角齿轮 → **Backup and Sync Settings...**（Accounts 菜单里也有入口）
2. 登录 GitHub 或 Microsoft 账号
3. 勾选要同步的数据类别

之后也可以用命令 `Settings Sync: Turn On` / `Settings Sync: Turn Off` 控制。

### 能同步什么

| 类别 | 内容 |
| --- | --- |
| Settings | 用户设置（排除 `machine`、`machine-overridable` 作用域的设置，以及手动排除的设置） |
| Keyboard Shortcuts | 自定义快捷键，默认按操作系统分别同步 |
| Snippets | 用户代码片段 |
| Tasks | 用户级任务；工作区任务不同步 |
| MCP Servers | 用户 Profile 中的 MCP 服务器配置 |
| UI State | 显示语言、视图布局、最近使用的命令、"不再提示"的选择等 |
| Extensions | 已安装扩展及其启用状态 |
| Profiles | Profile 及其数据，最多同步 20 个 |
| Prompts and Instructions | 用户提示词文件与本地 agent 指令 |

不用全勾。想排除个别项，用设置项齿轮菜单里的同步选项，或配置 `settingsSync.ignoredSettings` / `settingsSync.ignoredExtensions`。

### 数据存在哪

内置同步用的是 VSCode 自己的同步服务（账号用 GitHub 或 Microsoft 登录），**不是 GitHub Gist**，你没法去 GitHub 上浏览或手动编辑它。

网上"同步基于 Gist"的说法来自第三方扩展 *Settings Sync*（作者 Shan Khan），那是另一个产品，与内置功能无关。

```
设备 A ──上传──► VSCode 同步服务 ──下载──► 设备 B
                    │
              版本记录 + 冲突合并
```

### 冲突与备份

- 冲突时可选 **Accept Local / Replace Remote**、**Accept Remote / Replace Local**，或 **Show Conflicts** 打开 diff 手动合并后 **Complete Merge**
- `Settings Sync: Show Synced Data` 查看云端的历史备份；本地备份用 `Settings Sync: Open Local Backups Folder`
- 扩展不会同步到远程窗口（SSH、Dev Container、WSL）
- Stable 与 Insiders 默认使用不同的同步服务，数据不互通

> Profile 和 Sync 是两件事：Profile 是本地可切换的一套环境；勾选 Profiles 后，Profile 本身也会跨设备同步。

几个容易踩的点：

- `editor.defaultFormatter` 指向的扩展必须已安装，否则保存时不会格式化，且提示很容易错过

- `explorer.confirmDelete: false` 提升效率，但也意味着没有二次确认，自己权衡
- 主题、图标主题、产品图标主题都来自扩展，换机器时先装扩展再同步

## 3.7 设置没生效？按这个顺序排查

1. **语言级覆盖**：设置编辑器搜 `@modified` 或直接搜键名，看有没有 `"[python]"` 这类块；语言级永远赢，哪怕它写在用户层
2. **更近的作用域覆盖**：看设置项下方的 *Modified in*；多根工作区里再检查该文件夹自己的 `.vscode/settings.json`
3. **改错了层**：单文件夹工作区里 Workspace 就是 `.vscode/settings.json`；写进用户设置会被项目覆盖
4. **Profile 不对**：`Profiles: Switch Profile` 确认当前 Profile；用 `code --profile` 启动时也要对上
5. **扩展缺失**：`editor.defaultFormatter` 指向未安装/未启用的扩展时，保存格式化不会执行，提示也很容易错过；`$gcc`、`$python` 这类问题匹配器同样由对应扩展提供
6. **多个格式化器抢活**：装了 Prettier、ESLint、语言自带格式化器时，务必显式指定 `editor.defaultFormatter`，语言级最稳妥
7. **JSON 写错**：拼错的键、非法值、重复键。`settings.json` 里看波浪线，设置编辑器会提示写入失败
8. **需要重载或新终端**：终端 profile 只影响新终端；部分 UI 设置要 `Developer: Reload Window`
9. **受限模式或企业策略**：未信任工作区会忽略部分设置；策略设置不可覆盖（`@haspolicy`）
10. **同步覆盖**：另一台设备改完同步回来，会盖掉本机改动；用 `Settings Sync: Show Synced Data` 查历史

排查时常用的入口：

- `Preferences: Open User Settings (JSON)`
- `Preferences: Open Workspace Settings (JSON)`（单文件夹）或直接编辑 `.code-workspace`（多根）
- `Preferences: Open Remote Settings (JSON)`（连着远程时）
- `Developer: Reload Window`
- `Developer: Show Running Extensions`（确认扩展是否真的激活）

📋 **本章小结**

- 设置按作用域分五层：**默认 → 用户 → 远程 → 工作区 → 文件夹**，语言级设置整体优先，企业策略最高且不可覆盖
- **逐键解析**：原始值和数组覆盖，对象类型跨层合并；语言级设置永远压过非语言级设置
- 单文件夹工作区的 Workspace 与 Folder 是同一个 `.vscode/settings.json`；多根工作区才分 `.code-workspace` 与各文件夹配置
- `settings.json` 是 JSONC；未知设置会画波浪线；设置编辑器支持 `@modified`、`@lang`、`@ext`、`@id` 等过滤
- 语言特定设置用 `[languageId]`，ID 可从状态栏语言模式或 `Configure Language Specific Settings` 查
- 保存即格式化依赖 `editor.defaultFormatter` 指向已安装的格式化扩展
- 内置 Settings Sync 使用 VSCode 同步服务（**不是 GitHub Gist**），可同步设置、快捷键、片段、任务、扩展、Profiles 等
- 设置不生效时，按"语言级 → 更近作用域 → Profile → 扩展 → JSON → 重载 → 策略/同步"的顺序排查
