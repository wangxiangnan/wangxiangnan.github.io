## 8.1 开篇：推理策略 = 算法选择

写代码时，你会根据问题选择不同的算法：

- 排序 10 个数 → 插入排序（简单快）
- 排序 100 万个数 → 快速排序（高效）
- 搜索有序数组 → 二分查找（O(log n)）
- 搜索图 → BFS/DFS（遍历）

推理策略也是一样 — 不同的问题需要不同的"思考算法"：

> **相关**：第1章的 Agent 对象有个 `think()` 方法，推理策略就是在选 `think()` 内部的算法 — Zero-shot 是 O(1) 直接返回，Few-shot 是带样例的模板匹配，CoT 是分步推理，Self-Consistency 是多路投票。策略越复杂，Token 成本越高，但准确率也越高 — 就像算法里的时间换空间。

```
任务复杂度 vs 策略选择：

简单任务（分类、提取）
├── 格式要求低？ → Zero-shot
└── 格式严格？ → Few-shot

中等任务（解释、排查）
└── 多步推理？ → Chain-of-Thought

复杂任务（高风险、创意）
├── 需要准确性？ → Self-Consistency
└── 需要创造性？ → Tree-of-Thought
```

> 程序员视角：每种策略是一个"思维框架"，选对了事半功倍，选错了事倍功半。

## 8.2 Zero-shot — 像纯函数：输入→输出

**核心思想**：不给示例，直接问。就像纯函数 `f(x) -> y`，不依赖外部状态。

### 适用场景

- 简单分类（技术问题分类、情感分析）
- 格式提取（从文本提取日期、邮箱）
- 概念解释（一句话解释某个术语）

### 实现

```python
from openai import OpenAI
import os
from dotenv import load_dotenv

load_dotenv()

client = OpenAI(
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com"
)

def zero_shot_classify(question: str) -> str:
    """Zero-shot 分类 — 最快最便宜"""
    response = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": 
             "你是技术问题分类器。输出格式：分类:X 难度:初级/中级/高级。只输出分类结果，不要解释。"},
            {"role": "user", "content": question}
        ],
        temperature=0,  # 确定性
        max_tokens=50
    )
    return response.choices[0].message.content

# 测试
test_questions = [
    "FastAPI WebSocket 怎么用？",
    "PostgreSQL 索引优化？",
    "Docker depends_on 和 depends_on.condition 的区别？",
    "Python dataclass 和 NamedTuple 怎么选？",
    "如何设计百万并发的消息队列？"
]

print("=== Zero-shot 分类结果 ===")
for q in test_questions:
    result = zero_shot_classify(q)
    print(f"  {q}")
    print(f"  → {result}\n")
```

### Zero-shot 的优缺点

```python
zero_shot_analysis = {
    "优点": [
        "最快：一次请求，无额外 token",
        "最便宜：没有示例占用 token",
        "最简单：不需要准备示例"
    ],
    "缺点": [
        "格式不稳定：LLM 可能输出各种格式",
        "准确率低：复杂任务可能理解错",
        "无法展示边界：LLM 不知道什么不该做"
    ],
    "适用场景": [
        "简单分类（情感分析、主题分类）",
        "格式提取（日期、邮箱、URL）",
        "概念解释（一句话定义）",
        "快速原型（验证想法）"
    ]
}

# 实际测试：格式稳定性
formats_tested = []
for i in range(10):
    result = zero_shot_classify("Redis 持久化？")
    formats_tested.append(result)

# 可能得到：
# "分类:DB 难度:中级"
# "分类:数据库/Redis, 难度:中级"
# "DB/缓存 - 中级"
# ← 格式不一致！
```

**注意 Zero-shot 的坑**：格式不稳定——需要严格格式时用 Few-shot；复杂任务准确率低——多步推理用 CoT；小模型输出格式更不稳定——重要场景用 Few-shot 约束。

## 8.3 Few-shot — 像单测样例：用例子"教"格式

**核心思想**：给几个示例，让 LLM 精确模仿输出格式。就像单元测试的样例 — 定义期望的输入→输出映射。

### 为什么 Few-shot 格式更稳？

```python
# Zero-shot — LLM 自由发挥
zero_result = "这个问题属于数据库领域，难度中等"  # 格式乱

# Few-shot — LLM 模仿示例格式
few_examples = [
    {"role": "user", "content": "Redis 分布式锁？"},
    {"role": "assistant", "content": "分类:DB 子分类:Redis 难度:高"},
    {"role": "user", "content": "asyncio 事件循环？"},
    {"role": "assistant", "content": "分类:Python 子分类:异步 难度:中"},
]
few_result = "分类:Web 子分类:代理 难度:中"  # 格式一致！
```

### 完整实现

```python
def few_shot_classify(question: str) -> str:
    """Few-shot 分类 — 格式稳定"""
    messages = [
        {"role": "system", "content": "你是技术问题分类助手。严格按照示例格式输出。"},
        
        # 示例 1
        {"role": "user", "content": "Redis 分布式锁？"},
        {"role": "assistant", "content": "分类:DB 子分类:Redis 难度:高 标签:Redis,分布式锁,并发"},
        
        # 示例 2
        {"role": "user", "content": "asyncio 事件循环？"},
        {"role": "assistant", "content": "分类:Python 子分类:异步 难度:中 标签:Python,asyncio,事件循环"},
        
        # 示例 3（展示边界情况）
        {"role": "user", "content": "今天天气怎么样？"},
        {"role": "assistant", "content": "分类:OUT_OF_SCOPE 子分类:N/A 难度:N/A 标签:N/A"},
        
        # 待分类问题
        {"role": "user", "content": question}
    ]
    
    response = client.chat.completions.create(
        model="deepseek-chat",
        messages=messages,
        temperature=0,
        max_tokens=100
    )
    return response.choices[0].message.content

# 测试
test_cases = [
    "Nginx 反向代理配置？",
    "Docker Compose volumes？",
    "帮我写个情书"  # 边界测试
]

print("=== Few-shot 分类结果 ===")
for q in test_cases:
    result = few_shot_classify(q)
    print(f"  {q}")
    print(f"  → {result}\n")
```

### Zero-shot vs Few-shot 对比

```python
def compare_strategies(question: str) -> dict:
    """对比 Zero-shot 和 Few-shot"""
    import time
    
    # Zero-shot
    t0 = time.time()
    zero_msgs = [
        {"role": "system", "content": "分类技术问题。格式:分类:X 难度:Y"},
        {"role": "user", "content": question}
    ]
    zero_resp = client.chat.completions.create(
        model="deepseek-chat", messages=zero_msgs, temperature=0)
    zero_time = time.time() - t0
    
    # Few-shot
    t0 = time.time()
    few_msgs = [
        {"role": "system", "content": "分类技术问题。"},
        {"role": "user", "content": "Redis锁？"},
        {"role": "assistant", "content": "分类:DB 难度:高"},
        {"role": "user", "content": "asyncio？"},
        {"role": "assistant", "content": "分类:Python 难度:中"},
        {"role": "user", "content": question}
    ]
    few_resp = client.chat.completions.create(
        model="deepseek-chat", messages=few_msgs, temperature=0)
    few_time = time.time() - t0
    
    return {
        "zero_shot": {
            "result": zero_resp.choices[0].message.content,
            "tokens": zero_resp.usage.total_tokens,
            "time": f"{zero_time:.2f}s"
        },
        "few_shot": {
            "result": few_resp.choices[0].message.content,
            "tokens": few_resp.usage.total_tokens,
            "time": f"{few_time:.2f}s"
        }
    }

# 对比
comparison = compare_strategies("PostgreSQL 连接池配置？")
print(f"Zero-shot: {comparison['zero_shot']['result']}")
print(f"  Tokens: {comparison['zero_shot']['tokens']}, Time: {comparison['zero_shot']['time']}")
print(f"\nFew-shot: {comparison['few_shot']['result']}")
print(f"  Tokens: {comparison['few_shot']['tokens']}, Time: {comparison['few_shot']['time']}")

# 总结对比表
print("""
| 指标 | Zero-shot | Few-shot |
|------|-----------|----------|
| 准确率 | ~85% | ~95% |
| 格式稳定性 | 低（~70%） | 高（~100%） |
| Token 成本 | ~100 | ~400 |
| 延迟 | 最快 | 略慢 |
| 适用 | 简单任务 | 格式严格 |
""")
```

**何时用 Few-shot**：输出格式必须一致（API 返回、数据提取）；需要展示边界（什么不该做）；复杂分类（多类别、细粒度）。

## 8.4 Chain-of-Thought (CoT) — 像代码注释：分步思考

**核心思想**：强制 LLM 分步分析，而不是直接给答案。就像写代码时加注释解释每步逻辑。

### 为什么 CoT 能提升准确率？

```python
# 无 CoT — LLM "直觉"回答（像考试不写过程）
# 问题："一个函数处理1000条记录，每条50ms，并行处理（10个worker），总时间？"
# 直觉答案："50000ms" ← 错了！没考虑并行

# 有 CoT — 强制分步（像写解题过程）
# 1. 单条: 50ms
# 2. 1000条串行: 1000 × 50ms = 50000ms
# 3. 10个worker并行: 50000ms / 10 = 5000ms
# 4. 考虑开销: ~5500ms
# 答案："约 5.5 秒" ← 正确！
```

### CoT 实现：错误排查示例

DocMind 收到用户上报的报错时，用 CoT 模板强制分步排查：

```python
def cot_troubleshoot(error: str, context: str = "") -> str:
    """用 CoT 排查错误"""
    context_part = f"\n上下文: {context}" if context else ""
    prompt = f"""报错信息:
    `{error}`{context_part}

    请按以下步骤排查：

    1. **【分析】** 这个错误的含义是什么？
    2. **【原因】** 列出可能的原因（按概率排序）
    3. **【排查】** 对每个原因给出检查命令
    4. **【解决】** 给出解决方案（按优先级）"""
    
    response = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": "你是资深后端工程师，擅长排查技术问题。"},
            {"role": "user", "content": prompt}
        ],
        temperature=0
    )
    return response.choices[0].message.content

# 示例 1：网络连接错误
error1 = """
[Errno 99] Cannot assign requested address

Traceback:
  File "app.py", line 45, in fetch_data
    async with httpx.AsyncClient() as client:
  File "/lib/httpx/_client.py", line 1234
    await self._connect(request)
"""

print("=== 排查示例 1 ===")
print(cot_troubleshoot(error1, "FastAPI + httpx，500 req/s 并发"))

# 示例 2：数据库连接错误
error2 = """
psycopg2.OperationalError: FATAL: remaining connection slots are reserved 
for non-replication superuser connections
"""

print("\n=== 排查示例 2 ===")
print(cot_troubleshoot(error2, "FastAPI + SQLAlchemy + PostgreSQL，200 并发"))
```

### CoT 效果对比

```python
def compare_cot_effect(question: str) -> dict:
    """对比有无 CoT 的效果"""
    import time
    
    # 无 CoT
    t0 = time.time()
    no_cot_resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": "你是技术专家。直接给出答案。"},
            {"role": "user", "content": question}
        ],
        temperature=0
    )
    no_cot_time = time.time() - t0
    
    # 有 CoT
    t0 = time.time()
    cot_resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": "你是技术专家。逐步分析问题。"},
            {"role": "user", "content": f"{question}\n\n让我们一步一步思考。"}
        ],
        temperature=0
    )
    cot_time = time.time() - t0
    
    return {
        "no_cot": {
            "answer": no_cot_resp.choices[0].message.content,
            "tokens": no_cot_resp.usage.total_tokens,
            "time": f"{no_cot_time:.2f}s"
        },
        "with_cot": {
            "answer": cot_resp.choices[0].message.content,
            "tokens": cot_resp.usage.total_tokens,
            "time": f"{cot_time:.2f}s"
        }
    }

# 测试数学问题（CoT 效果最明显）
math_q = "一个 Redis 集群有 3 个 master，每个 master 有 2 个 slave。" \
         "如果 1 个 master 挂了，需要多少时间恢复？" \
         "假设故障检测 5s，选举 3s，同步 10s/GB，数据量 5GB。"

result = compare_cot_effect(math_q)
print("=== 无 CoT ===")
print(result["no_cot"]["answer"][:200])
print(f"Tokens: {result['no_cot']['tokens']}, Time: {result['no_cot']['time']}")

print("\n=== 有 CoT ===")
print(result["with_cot"]["answer"][:200])
print(f"Tokens: {result['with_cot']['tokens']}, Time: {result['with_cot']['time']}")

# 研究数据
print("""
=== CoT 效果研究数据 ===
GSM8K 数学题（小学应用题）:
- 无 CoT（标准提示）: ~17.9% 准确率（Wei et al. 2022）
- 有 CoT: ~56.9% 准确率（Wei et al. 2022）
- Self-Consistency: ~74% 准确率（Wang et al. 2022）

结论: CoT 对多步推理提升巨大
""")
```

**CoT 的 trade-off**：准确性提升（尤其是数学、逻辑），代价是 Token 成本增加 2-5 倍（思考过程也计费）、延迟增加（输出更长）。建议：Agent 场景默认用 CoT（准确性优先），简单查询不用。

## 8.5 Self-Consistency — 像多人 Code Review：投票决策

**核心思想**：同一问题问 N 次（temperature 高一点让思路不同），投票选最多答案。就像多人 Code Review — 大多数人同意的方案更可靠。

### 为什么 Self-Consistency 更准？

```python
# 单次 CoT — 可能走错路径
# 问："Python GIL 会影响多线程的 CPU 密集任务吗？"
# 回答 1："是的，GIL 会..." ← 对了

# 但如果运气不好：
# 回答 2："不一定，因为..." ← 走错路径

# Self-Consistency — 问 5 次，投票
# 回答 1: "是的"（对）
# 回答 2: "是的"（对）
# 回答 3: "是的"（对）
# 回答 4: "不一定"（错）
# 回答 5: "是的"（对）
# 投票: 4/5 = "是的" ← 更可靠！
```

### 完整实现

```python
from collections import Counter
import re

def self_consistency(question: str, n: int = 5, model: str = "deepseek-chat") -> dict:
    """Self-Consistency: 多次采样 + 投票"""
    answers = []
    reasoning_paths = []
    
    for i in range(n):
        response = client.chat.completions.create(
            model=model,
            messages=[
                {"role": "system", "content": 
                 "你是技术专家。逐步分析问题，最后一行用'答案：X'给出最终答案。"},
                {"role": "user", "content": question}
            ],
            temperature=0.7,  # 高温让思路多样化
            max_tokens=1000
        )
        
        content = response.choices[0].message.content
        reasoning_paths.append(content)
        
        # 提取最终答案
        answer = extract_answer(content)
        answers.append(answer)
    
    # 投票
    counter = Counter(answers)
    best_answer, count = counter.most_common(1)[0]
    confidence = count / n
    
    return {
        "answer": best_answer,
        "confidence": confidence,
        "votes": dict(counter),
        "all_reasoning": reasoning_paths
    }

def extract_answer(text: str) -> str:
    """从回答中提取最终答案"""
    # 尝试多种格式
    patterns = [
        r"答案：(.+)",
        r"答案是[：:]\s*(.+)",
        r"最终答案[：:]\s*(.+)",
        r"Final Answer[：:]\s*(.+)",
    ]
    for pattern in patterns:
        match = re.search(pattern, text)
        if match:
            return match.group(1).strip()
    
    # 默认取最后一行
    lines = text.strip().split("\n")
    return lines[-1] if lines else "未知"

# 示例 1：有明确答案的问题
result1 = self_consistency(
    "一个 PostgreSQL 表有 1000 万行，B-tree 索引高度大约是几层？" \
    "假设每个节点存 100 个键。",
    n=5
)
print("=== Self-Consistency 示例 1 ===")
print(f"问题: PostgreSQL 索引高度")
print(f"答案: {result1['answer']}")
print(f"置信度: {result1['confidence']:.0%}")
print(f"投票: {result1['votes']}")

# 示例 2：方案选择
result2 = self_consistency(
    "FastAPI 后台任务（发邮件、生成报表、数据同步）应该用哪种方案？" \
    "A) BackgroundTasks B) Celery C) asyncio.create_task D) 消息队列",
    n=5
)
print("\n=== Self-Consistency 示例 2 ===")
print(f"问题: 后台任务方案")
print(f"答案: {result2['answer']}")
print(f"置信度: {result2['confidence']:.0%}")
print(f"投票: {result2['votes']}")
```

### Self-Consistency 成本分析

```python
def self_consistency_cost(n: int, avg_tokens: int, model: str = "deepseek-chat") -> dict:
    """计算 Self-Consistency 的成本"""
    # 各模型价格（每 1M tokens，美元）
    prices = {
        "deepseek-chat": {"input": 0.15, "output": 0.60},
        "gpt-4o": {"input": 2.50, "output": 10.00},
        "gpt-4": {"input": 30.00, "output": 60.00},
    }
    
    price = prices[model]
    # 每次请求：输入 ~200 tokens，输出 ~avg_tokens
    input_cost = (200 * n / 1_000_000) * price["input"]
    output_cost = (avg_tokens * n / 1_000_000) * price["output"]
    total_cost = input_cost + output_cost
    
    # 对比单次 CoT
    single_cost = (200 / 1_000_000) * price["input"] + \
                  (avg_tokens / 1_000_000) * price["output"]
    
    return {
        "total_cost": f"${total_cost:.6f}",
        "single_cot_cost": f"${single_cost:.6f}",
        "multiplier": f"{total_cost/single_cost:.1f}x",
        "accuracy_gain": "~5-10%（复杂推理任务）"
    }

# 成本分析
cost = self_consistency_cost(n=5, avg_tokens=500, model="deepseek-chat")
print(f"Self-Consistency (n=5): {cost['total_cost']}")
print(f"单次 CoT: {cost['single_cot_cost']}")
print(f"成本倍数: {cost['multiplier']}")
print(f"准确性提升: {cost['accuracy_gain']}")

# 何时值得用 Self-Consistency？
print("""
何时值得用 Self-Consistency？

值得：
- 高风险决策（架构设计、安全配置）
- 数学/逻辑题（答案可验证）
- 一次性分析（不是每次请求）

不值得：
- 实时 API（延迟太高）
- 简单问题（单次 CoT 够了）
- 高频调用（成本爆炸）
""")
```

## 8.6 Tree-of-Thought (ToT) — 像 Git 分支：探索多路径

**核心思想**：不是线性思考，而是创建多个"思维分支"，评估每个分支，选最佳。就像 Git 分支 — 尝试多个方案，merge 最好的。

### ToT vs CoT

```python
# CoT（线性）
# A → B → C → 答案
# 如果 B 就错了，后面全错

# ToT（树形）
#     ┌─ B1 → C1 → 答案1 (70分)
# A ──┼─ B2 → C2 → 答案2 (85分) ← 选这个
#     └─ B3 → C3 → 答案3 (60分)
# 探索多条路径，选最佳
```

### 完整实现

```python
def tree_of_thought(question: str, num_branches: int = 3) -> dict:
    """Tree-of-Thought: 生成多方案 → 评估 → 选最佳"""
    
    # 阶段 1：生成多个方案（创建分支）
    print("=== 阶段 1：生成方案 ===")
    branches_response = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": 
             f"你是架构师。给出 {num_branches} 种不同的方案。" \
             "每个方案用'--- 方案N ---'开头，包含：\n" \
             "1. 方案描述\n2. 优点（2-3点）\n3. 缺点（2-3点）\n4. 适用场景"},
            {"role": "user", "content": question}
        ],
        temperature=0.8,  # 高温鼓励多样性
        max_tokens=2000
    )
    branches = branches_response.choices[0].message.content
    print(branches[:500] + "...\n")
    
    # 阶段 2：评估每个方案（Code Review）
    print("=== 阶段 2：评估方案 ===")
    eval_response = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": 
             "你是技术评审专家。对每个方案评分（1-10）并说明理由。\n" \
             "评分维度：\n" \
             "- 可行性：实现难度、团队技能匹配度\n" \
             "- 成本：开发成本、运维成本\n" \
             "- 效果：能否解决问题、扩展性\n\n" \
             "最后选出最佳方案，用'推荐：方案N'总结。"},
            {"role": "user", "content": f"问题：{question}\n\n方案：\n{branches}"}
        ],
        temperature=0.2,  # 低温确保评估稳定
        max_tokens=1500
    )
    evaluation = eval_response.choices[0].message.content
    print(evaluation[:500] + "...")
    
    return {
        "branches": branches,
        "evaluation": evaluation,
        "full_result": evaluation
    }

# 示例：DocMind 的架构设计问题
question = """
DocMind 的文档问答在高峰期响应变慢（P99 从 2s 涨到 8s）。
设计一个检索优化方案，要求：
- 不牺牲回答质量
- 新旧检索方案可以灰度切换
- 可以监控检索耗时与命中率
- 团队 3 人，技术栈 Python + Docker
"""

result = tree_of_thought(question, num_branches=3)

print("\n=== 最终评估 ===")
print(result["evaluation"])
```

### ToT 进阶：迭代优化

```python
def iterative_tot(question: str, iterations: int = 2) -> str:
    """迭代式 ToT：每轮优化最佳方案"""
    
    current_best = None
    
    for i in range(iterations):
        print(f"\n=== 迭代 {i+1}/{iterations} ===")
        
        # 生成方案
        if current_best:
            prompt = f"基于上一轮最佳方案，提出 3 个改进版本。" \
                     f"\n\n上一轮最佳：\n{current_best}\n\n原始问题：{question}"
        else:
            prompt = f"给出 3 种方案解决问题：{question}"
        
        branches = client.chat.completions.create(
            model="deepseek-chat",
            messages=[{"role": "user", "content": prompt}],
            temperature=0.8
        ).choices[0].message.content
        
        # 评估
        evaluation = client.chat.completions.create(
            model="deepseek-chat",
            messages=[
                {"role": "system", "content": "选出最佳方案并详细说明。"},
                {"role": "user", "content": branches}
            ],
            temperature=0.2
        ).choices[0].message.content
        
        current_best = evaluation
        print(f"当前最佳: {current_best[:200]}...")
    
    return current_best

# 使用
final = iterative_tot("设计一个高可用的 Redis 缓存架构", iterations=2)
print("\n=== 最终方案 ===")
print(final)
```

**ToT 的 trade-off**：探索空间大、可能找到创新方案，代价是成本最高（多次 LLM 调用）、延迟最高（串行多次）。建议：只用于一次性架构设计、创意方案，不用于实时场景。

## 8.7 策略对比与选择指南

### 综合对比表

| 策略 | 准确率（GSM8K 数学题） | 成本 | 延迟 | 适用场景 | 编程类比 |
| ------ | ------- | ------ | ------ | ---------- | --------- |
| Zero-shot | 低（~17.9%） | 最低 | 最快 | 简单分类、概念提取 | 纯函数 |
| Few-shot | 中 | 中 | 中 | 格式严格、复杂分类 | 单测样例 |
| CoT | 高（~56.9%） | 中高 | 中高 | 多步推理、排查 | 代码注释 |
| Self-C | 更高（~74%） | Nx | Nx | 高风险决策 | 多人Review |
| ToT | 高（复杂任务） | 最高 | 最高 | 架构设计、创意 | Git分支 |

> 注：准确率列为 GSM8K 数学题上的论文口径——17.9%/56.9% 来自 CoT 论文（Wei et al. 2022），74% 来自 Self-Consistency 论文（Wang et al. 2022）。分类类任务的绝对数值不同，但相对趋势一致。

什么时候该"升级策略"？出现下面这些信号再升级，不要一步到位：

| 升级信号 | 建议升级到 | 理由 |
| ------ | ------ | ------ |
| 输出格式每次都不一样 | Few-shot | 示例能锁住格式 |
| 答案跳步、算错 | CoT | 分步推理显式化 |
| 同一题多次提问答案打架 | CoT + Self-Consistency | 多路径投票降噪 |
| 方案想不出第三个 | ToT | 强制多分支探索 |

### 策略选择决策树

```python
def choose_strategy(task: dict) -> str:
    """根据任务特征选择推理策略"""
    
    # 任务特征
    complexity = task.get("complexity", "simple")  # simple/medium/complex
    format_required = task.get("format_required", False)  # 是否需要严格格式
    accuracy_critical = task.get("accuracy_critical", False)  # 准确性是否关键
    is_creative = task.get("is_creative", False)  # 是否需要创意
    is_realtime = task.get("is_realtime", True)  # 是否实时
    
    # 决策树
    if complexity == "simple":
        if format_required:
            return "Few-shot"  # 简单但格式严格
        else:
            return "Zero-shot"  # 简单且格式灵活
    
    elif complexity == "medium":
        if accuracy_critical:
            return "CoT + Self-Consistency"  # 中等复杂度 + 高准确性
        else:
            return "CoT"  # 中等复杂度，CoT 够了
    
    else:  # complex
        if is_creative:
            return "Tree-of-Thought"  # 需要创意，探索多路径
        elif accuracy_critical and not is_realtime:
            return "CoT + Self-Consistency (n=5)"  # 高风险，非实时
        else:
            return "CoT"  # 复杂但实时，用 CoT 平衡
    
# 测试
tasks = [
    {"name": "技术问题分类", "complexity": "simple", "format_required": True},
    {"name": "解释Python装饰器", "complexity": "medium", "format_required": False},
    {"name": "排查数据库死锁", "complexity": "medium", "accuracy_critical": True},
    {"name": "设计微服务架构", "complexity": "complex", "is_creative": True},
    {"name": "实时API问答", "complexity": "medium", "is_realtime": True},
]

for task in tasks:
    strategy = choose_strategy(task)
    print(f"{task['name']:20s} → {strategy}")
```

def hybrid_strategy(question: str) -> str:
    """混合策略：先分类，再用对应策略"""
    
    # 第一步：分类（Zero-shot，快）
    classification = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": 
             "分类问题：SIMPLE（概念）| DEBUG（排查）| DESIGN（设计）"},
            {"role": "user", "content": question}
        ],
        temperature=0
    ).choices[0].message.content
    
    # 第二步：根据分类选策略
    if "SIMPLE" in classification:
        # 简单问题：Zero-shot
        return ask_zero_shot(question)
    elif "DEBUG" in classification:
        # 排查问题：CoT
        return ask_with_cot(question)
    else:
        # 设计问题：ToT
        return ask_with_tot(question)

def ask_zero_shot(q): return f"[Zero-shot] {q}"
def ask_with_cot(q): return f"[CoT] {q}"
def ask_with_tot(q): return f"[ToT] {q}"

## 本章小结

- 推理策略就是给 think() 选算法：任务复杂度、格式要求、准确性、实时性四个维度决定选谁。
- Zero-shot 最快最便宜，适合简单分类与提取，但格式不稳定。
- Few-shot 用示例锁格式，是需要严格输出时的默认选择，成本略高。
- CoT 分步思考，是多步推理与排查的默认策略，Token 成本增加 2-5 倍。
- Self-Consistency 同题多采样投票，是高风险决策的保险，成本 N 倍。
- ToT 多分支探索加评估，创意与架构设计专用，成本与延迟最高。
- 按信号升级策略：格式乱上 Few-shot、跳步上 CoT、答案打架加投票、方案枯竭用 ToT；实时场景守住前三档。
