# 第3章：命令行基础——FFmpeg 的语法

> FFmpeg 的命令看起来像一堆乱码：`ffmpeg -i input.mp4 -c:v libx264 -crf 23 -c:a aac -b:a 128k output.mp4`。但其实它有非常清晰的语法结构，掌握了这个结构，你就能读懂任何 FFmpeg 命令，也能自己写出正确的命令。

## 3.1 FFmpeg 命令结构图

任何一条 FFmpeg 命令，都遵循以下结构：

```
ffmpeg [全局选项] [输入选项] -i 输入文件 [输出选项] 输出文件
```

让我们用一个完整的例子来拆解：

```bash
ffmpeg -hide_banner -y -i input.mp4 -c:v libx264 -crf 23 -c:a aac output.mp4
```

拆解如下：

```
ffmpeg          ← 调用 FFmpeg 主程序
-hide_banner    ← 全局选项：隐藏版本信息横幅
-y              ← 全局选项：覆盖文件时不询问确认
-i input.mp4    ← 输入文件：指定源视频
-c:v libx264    ← 输出选项：视频编码器用 H.264
-crf 23         ← 输出选项：恒定质量因子为 23
-c:a aac        ← 输出选项：音频编码器用 AAC
output.mp4      ← 输出文件名（FFmpeg 根据扩展名自动推断容器格式）
```

**核心原则：参数的位置决定了它作用的对象。**

这是 FFmpeg 命令最容易出错的地方，也是最重要的规则：

- 在 `-i` **之前**的参数：影响全局行为或输入文件的读取方式
- 在 `-i` **之后**、输出文件名**之前**的参数：影响输出文件的生成方式
- 最后一个非选项参数（没有 `-` 前缀的那个）：被视为输出文件名

```bash
# 错误示例：-ss 放在 -i 之后，变成输出选项（不是错误，但行为不同）
ffmpeg -i input.mp4 -ss 00:01:00 output.mp4   # 会先解码再截取，速度慢

# 正确示例：-ss 放在 -i 之前，作为输入选项（快速定位）
ffmpeg -ss 00:01:00 -i input.mp4 output.mp4   # 直接跳到目标位置，速度快
```

## 3.2 关键参数详解

**`-i`：指定输入文件**

最基本的参数，告诉 FFmpeg 你要处理哪个文件。可以有多个 `-i` 参数来处理多个输入文件：

```bash
# 处理单个输入
ffmpeg -i video.mp4 output.mp4

# 处理多个输入（比如合并两段视频）
ffmpeg -i part1.mp4 -i part2.mp4 -filter_complex concat=n=2:v=1:a=1 merged.mp4
```

**`-c`、`-c:v`、`-c:a`：指定编码器**

`-c` 是 codec（编码器）的缩写：

```bash
# -c:v 指定视频编码器（v = video）
ffmpeg -i input.mp4 -c:v libx264 output.mp4

# -c:a 指定音频编码器（a = audio）
ffmpeg -i input.mp4 -c:a aac output.mp4

# -c copy 表示直接复制流，不重新编码（速度极快，无损）
ffmpeg -i input.mkv -c copy output.mp4
```

> **`-c copy` 是你最常用的参数之一**。当只需要更换容器格式（比如 MKV 转 MP4）而不需要改变编码内容时，用 `-c copy` 可以在几秒内完成，而不是重新编码的几十分钟。

**`-y` 和 `-n`：覆盖与不覆盖**

```bash
# -y：输出文件已存在时直接覆盖，不询问
ffmpeg -y -i input.mp4 output.mp4

# -n：输出文件已存在时不覆盖，直接报错退出
ffmpeg -n -i input.mp4 output.mp4
```

建议在脚本中使用 `-y` 避免交互提示导致脚本挂起，在手动操作时用 `-n` 防止意外覆盖重要文件。

**`-t`、`-ss`、`-to`：时间控制**

```bash
# -ss：起始时间（seek）
# -to：结束时间（to）
# -t：持续时间（duration）

# 从第 10 秒开始，截取到第 30 秒（共 20 秒）
ffmpeg -ss 00:00:10 -to 00:00:30 -i input.mp4 -c copy clip.mp4

# 从第 10 秒开始，截取 20 秒（效果同上）
ffmpeg -ss 00:00:10 -i input.mp4 -t 20 -c copy clip.mp4

# 时间格式支持两种写法：
# 秒数：-ss 60（第60秒）
# 时分秒：-ss 00:01:00（1分钟处）
# 带小数：-ss 00:01:30.500（1分30秒500毫秒处）
```

> **性能提示**：当 `-ss` 放在 `-i` 之前时，FFmpeg 会利用关键帧快速跳转，速度极快（几乎瞬间）。当 `-ss` 放在 `-i` 之后时，FFmpeg 会从头开始解码直到目标时间，速度较慢。对于大文件，这个差异可能是几秒和几分钟的区别。

**`-map`：流的映射与选择**

一个视频文件可以包含多条流（视频流、音频流、字幕流等）。`-map` 参数让你精确控制哪些流进入输出文件：

```bash
# 查看所有流
ffprobe -i input.mkv -show_streams -select_streams a

# 只保留视频流和第一条音频流
ffmpeg -i input.mkv -map 0:v -map 0:a:0 -c copy output.mp4

# 保留所有流（视频、所有音频、字幕）
ffmpeg -i input.mkv -map 0 -c copy output.mkv

# 排除字幕流（负号表示排除）
ffmpeg -i input.mkv -map 0 -map -0:s -c copy output.mp4
```

`-map` 参数的格式是 `-map 输入序号:流类型:流序号`：

- `0:v` —— 第 1 个输入文件的视频流
- `0:a:0` —— 第 1 个输入文件的第 1 条音频流
- `0:a` —— 第 1 个输入文件的所有音频流
- `-0:s` —— 排除第 1 个输入文件的所有字幕流

## 3.3 日志与调试

FFmpeg 默认会输出大量信息，有时候你想知道更多，有时候你想让它安静点。

**`-loglevel`：控制日志详细程度**

```bash
# 完全安静（什么都不输出，出错了也不知道）
ffmpeg -loglevel quiet -i input.mp4 output.mp4

# 只显示错误
ffmpeg -loglevel error -i input.mp4 output.mp4

# 显示警告和错误（默认级别）
ffmpeg -loglevel warning -i input.mp4 output.mp4

# 显示详细信息（包括编码参数等，适合调试）
ffmpeg -loglevel verbose -i input.mp4 output.mp4

# 显示所有调试信息（非常多，适合开发者）
ffmpeg -loglevel debug -i input.mp4 output.mp4
```

日志级别从低到高排列：

```
quiet < panic < fatal < error < warning < info < verbose < debug
```

**`-hide_banner`：隐藏版本横幅**

每次运行 FFmpeg，它都会先打印版本信息和编译配置，占据好几行。加上 `-hide_banner` 可以让输出更清爽：

```bash
# 不加 -hide_banner，输出开头会有这些：
# ffmpeg version 7.0 Copyright (c) 2000-2024 the FFmpeg developers
# built with gcc 13.2.0 ...
# configuration: --enable-gpl ...

# 加上 -hide_banner，直接显示有用信息
ffmpeg -hide_banner -i input.mp4
```

建议在几乎所有命令中都加上 `-hide_banner`，除非你需要确认 FFmpeg 的版本信息。

## 3.4 查看文件信息的基本方法

在动手处理一个视频之前，通常需要先了解它的基本信息。有两种方式：

**方式一：ffmpeg 快速查看**

```bash
# 只显示基本信息（不处理，不输出文件）
ffmpeg -i input.mp4

# 输出示例：
# Duration: 00:10:30.50, start: 0.000000, bitrate: 3500 kb/s
# Stream #0:0: Video: h264 (High), yuv420p, 1920x1080, 30 fps
# Stream #0:1: Audio: aac (LC), 48000 Hz, stereo, fltp, 128 kb/s
```

这种方式简单快捷，但信息不够详细，而且 FFmpeg 会尝试寻找输出文件，最后报错退出（这是正常的）。

**方式二：ffprobe 专业分析（推荐）**

```bash
# 以 JSON 格式输出所有流的详细信息
ffprobe -v quiet -print_format json -show_format -show_streams input.mp4

# 只显示视频流信息
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,width,height,r_frame_rate -of default=noprint_wrappers=1 input.mp4

# 以紧凑格式显示每个帧的类型（前 20 帧）
ffprobe -v error -select_streams v:0 -show_entries frame=pict_type -of csv=p=0 -read_intervals "%+#20" input.mp4
```

## 3.5 第一个实战：把 MP4 转成 WebM

让我们来写人生中第一条完整的 FFmpeg 命令。目标：把一个 MP4 文件转换为 WebM 格式（VP9 视频 + Opus 音频），适合在网页上播放。

**第一步：确认输入文件信息**

```bash
# 查看输入文件的详细信息
ffprobe -v error -show_streams input.mp4

# 假设输出告诉我们：
# Stream #0:0 - Video: h264, 1920x1080, 30fps
# Stream #0:1 - Audio: aac, 48000Hz, stereo
```

**第二步：执行转换**

```bash
ffmpeg -i input.mp4 \
  -c:v libvpx-vp9 \
  -crf 30 \
  -b:v 0 \
  -c:a libopus \
  -b:a 128k \
  output.webm
```

逐行解释这条命令：

| 参数 | 含义 |
| ------ | ------ |
| `-i input.mp4` | 输入文件是 input.mp4 |
| `-c:v libvpx-vp9` | 视频编码器使用 VP9（libvpx 是 VP8/VP9 的编码器库） |
| `-crf 30` | 恒定质量因子为 30（VP9 的 CRF 范围是 0-63，数值越小质量越高，30 是中等偏低质量） |
| `-b:v 0` | 将目标码率设为 0，告诉编码器"我只要 CRF 模式，不要受码率限制" |
| `-c:a libopus` | 音频编码器使用 Opus（高质量开源音频编码器） |
| `-b:a 128k` | 音频码率设为 128kbps（立体声的良好质量） |
| `output.webm` | 输出文件为 output.webm |

**第三步：验证输出**

```bash
# 检查输出文件的流信息
ffprobe -v error -show_streams output.webm

# 用 ffplay 快速预览
ffplay output.webm
```

> **注意**：VP9 编码比较慢，一个 10 分钟的 1080p 视频可能需要 5-15 分钟才能编码完成（取决于 CPU 性能）。别担心，后面的章节我们会学习如何用硬件加速来解决这个问题。

## 3.6 命令的"顺序很重要"——核心原则

这是 FFmpeg 新手最容易踩坑的地方，值得单独强调。

**规则一：全局选项放在最前面**

```bash
# 正确：-y 和 -hide_banner 是全局选项
ffmpeg -y -hide_banner -i input.mp4 output.mp4

# 也能工作，但不规范：-y 放在最后
ffmpeg -i input.mp4 output.mp4 -y   # 可能会被误认为是第二个输出文件的选项
```

**规则二：输入选项紧跟在对应的 `-i` 之前**

```bash
# 对第一个输入文件设置时间起点
ffmpeg -ss 00:01:00 -i input1.mp4 -i input2.mp4 output.mp4
#         ↑ 只影响 input1.mp4

# 如果需要对两个输入分别设置选项
ffmpeg -ss 00:01:00 -i input1.mp4 -ss 00:00:30 -i input2.mp4 output.mp4
```

**规则三：输出选项放在输出文件名之前**

```bash
# 正确：-c:v 在输出文件名之前
ffmpeg -i input.mp4 -c:v libx264 output.mp4

# 错误：-c:v 在输出文件名之后，FFmpeg 会把它当成另一个输出文件名
ffmpeg -i input.mp4 output.mp4 -c:v libx264   # 会出错或产生意外结果
```

**规则四：`-ss` 的位置影响性能**

```bash
# 快速跳转（利用关键帧，几乎瞬间完成）
ffmpeg -ss 00:05:00 -i input.mp4 -c copy output.mp4

# 慢速跳转（从头解码到目标时间，精确但慢）
ffmpeg -i input.mp4 -ss 00:05:00 -c copy output.mp4
```

## 本章小结

- FFmpeg 命令结构为：`ffmpeg [全局选项] [输入选项] -i 输入 [输出选项] 输出`
- 参数的位置决定了它作用的对象，这是 FFmpeg 最重要的语法规则
- `-c copy` 可以无损复制流，是格式转换时最省时省力的选择
- `-ss` 放在 `-i` 之前是快速跳转，放在之后是精确跳转
- `-map` 参数让你精确控制哪些流进入输出文件
- 用 `-loglevel` 和 `-hide_banner` 控制输出的详细程度
