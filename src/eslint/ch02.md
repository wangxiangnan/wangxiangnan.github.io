# 旧版的 .eslintrc存在的问题

flat config 解决的核心问题就是一个词：可预测性。旧版的 .eslintrc 有太多隐式行为——隐式查找配置文件、隐式解析插件名、隐式加载 extends、隐式合并多层配置——导致"我看到的配置"和"实际生效的配置"经常不一致。Flat config 把所有隐式行为都消除了，一切都变成显式的 import 和数组展开，调试成本大幅降低。

## 一、配置文件的查找和合并规则复杂

旧版 ESLint 会从当前文件所在目录开始，逐层向上查找 .eslintrc 文件，每一层都可能有一份配置，再加上 extends 链式继承、root: true 截断查找，最终生效的配置可能是五六个文件合并出来的。你在子目录看到一个 .eslintrc，根本不知道最终规则是什么，必须把整条链路都看一遍才能搞清楚。

Flat config 只有一个入口文件 eslint.config.js，所有配置都在一个数组里，所见即所得。不存在逐层查找、不存在隐式合并，你在文件里看到什么，最终生效的就是什么。

## 二、隐式解析和加载

旧版 .eslintrc 里，你注册插件写的是字符串：

```json
{
  "plugins": ["vue", "@typescript-eslint"]
}
```

ESLint 收到这些字符串后，会自己去 node_modules 里找对应的包——"vue" 会去找 eslint-plugin-vue，"@typescript-eslint" 会去找 @typescript-eslint/eslint-plugin。这个过程是 ESLint 内部自动完成的，你看不到实际的包引用，全靠命名约定来匹配。这就叫"隐式解析"。

这个机制有几个问题：你不知道这个字符串最终对应的是哪个包、从哪里加载的；如果包名改了或者装了多个版本，解析结果不可预测；而且在 monorepo 里，不同子包的 node_modules 层级不同，经常出现解析到错误版本的情况。

Flat config 改成了直接 import：

```js
import pluginVue from "eslint-plugin-vue";
import tseslint from "typescript-eslint";

export default [
  { plugins: { vue: pluginVue } },
  tseslint.configs.recommended,
]
```

插件就是一个普通的 JS 模块，你用标准的 import 把它引进来，再手动注册到一个键名上。ESLint 不再做任何隐式查找，你给它什么它就用什么。这就叫"显式注册"。

好处很直接：依赖关系在代码里一目了然，编辑器能跳转定义、能检查类型，包解析走的是 Node.js 标准的模块解析规则，monorepo 里不会因为 node_modules 层级问题出幺蛾子。

旧版写 extends: ["airbnb", "plugin:vue/recommended"]，ESLint 会去 node_modules 里找 eslint-config-airbnb 和 eslint-plugin-vue，然后加载它们导出的配置。跟 plugins 一样是字符串隐式解析，你同样不知道实际加载了哪个包、哪个版本。而且如果配置包里又 extends 了别的包，就变成了递归隐式加载，调试起来非常痛苦。

Flat config 里所有"继承"都是通过 import + 数组展开实现的，加载了什么、顺序是什么、有没有重复，全在代码里明明白白。

## 三、overrides 嵌套导致规则来源不清

旧版针对不同文件类型要用 overrides 嵌套：

```js
{
  "rules": { "no-unused-vars": "error" },
  "overrides": [
    {
      "files": ["*.ts"],
      "rules": { "no-unused-vars": "off", "@typescript-eslint/no-unused-vars": "error" },
      "overrides": [
        {
          "files": ["*.vue"],
          "rules": { /* 又来一层 */ }
        }
      ]
    }
  ]
}
```

嵌套一深，规则的优先级和覆盖关系就很难追踪。Flat config 用数组 + files 字段把嵌套拍平了，每种文件类型的配置都在同一个层级，不再有嵌套。

## 四、全局变量声明方式不统一

旧版用 env 字段来声明环境：

```json
{
  "env": {
    "browser": true,
    "node": true,
    "es2021": true
  }
}
```

env 背后对应的是预设好的全局变量集合，但你不能自定义全局变量名（自定义要用另一个字段 globals），两套机制并存，容易混淆。而且 env 也是隐式的——你写 "browser": true，ESLint 内部去找预定义的 browser 全局变量列表，你看不到具体包含了哪些变量。

Flat config 统一用 languageOptions.globals，直接 import globals 包，展开具体变量列表。你写什么就是什么，没有隐式查找，想自定义全局变量也直接在同一个字段里加。

## 五、忽略文件的方式割裂

旧版用单独的 .eslintignore 文件，语法跟 .gitignore 一样。这导致忽略规则分散在两个文件里（.gitignore 管 git，.eslintignore 管 ESLint），维护成本高，而且 .eslintignore 的路径解析规则跟 .gitignore 还有微妙的差异，偶尔会踩坑。

Flat config 把 ignores 收进了配置文件，跟规则写在同一个地方，不需要维护额外的文件。
