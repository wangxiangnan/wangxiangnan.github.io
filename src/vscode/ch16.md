> "The best way to predict the future is to implement it." — David Heinemeier Hansson

2021 年 GitHub Copilot 横空出世时，很多开发者惊呼"程序员要被替代了"。几年过去，事实证明：**AI 不会替代程序员，但会使用 AI 的程序员会替代不会使用的。**

本章不是要讨论 AI 是否会取代人类的哲学问题，而是手把手教你如何在 VSCode 中高效使用 AI 编程工具，让它们成为你的"超级副驾驶"。

## 16.1 AI 编程工具格局概览

### 主流工具对比

| 工具 | 开发商 | 核心能力 | 价格 | 推荐场景 |
| ------ | -------- | ---------- | ------ | ---------- |
| **GitHub Copilot** | GitHub/Microsoft | 代码补全、Chat、Agent 模式 | Free 限额 / Pro $10/月起 | 日常开发，集成最完整 |
| **Gemini Code Assist** | Google | 代码补全、Chat | 个人免费额度 + 付费 | Google 生态、预算有限 |
| **Continue** | 开源社区 | 多模型后端、完全可定制 | 扩展免费，模型费用自理 | 隐私敏感、自定义 |
| **Cline** | 开源社区 | Agent 模式，自主执行任务 | 扩展免费，API 费用自理 | 自动化复杂任务 |
| **Windsurf Plugin（原 Codeium）** | Windsurf | 免费额度大、多语言补全 | 免费 + 付费 | 轻量补全 |
| **Tabnine** | Tabnine | 补全、Chat，强调代码隐私 | 免费 + 付费 | 私有化部署 |

> **工具状态提示：** Sourcegraph 的 Cody 免费版与 Pro 版已停止服务；Cursor 是独立编辑器而非 VSCode 扩展。AI 工具迭代很快，选型前请确认最新状态。

### 选择建议

- **个人开发者：** 先用 GitHub Copilot Free 的每月额度，不够再升级 Pro
- **企业团队：** GitHub Copilot Business / Enterprise（可统一管理策略与代码排除）
- **隐私敏感 / 本地部署需求：** Continue + 本地模型（如 Ollama + Qwen Coder）
- **预算有限：** GitHub Copilot Free、Gemini Code Assist 免费额度或 Windsurf Plugin
- **需要 Agent 能力：** Copilot Agent 模式或 Cline

## 16.2 GitHub Copilot：安装与配置

### 安装

1. 确认 GitHub 账号具备 Copilot 使用权（Free 有每月限额；Pro $10/月；学生、教师和开源维护者可免费使用 Pro）
2. 更新到最新版 VSCode：Copilot Chat 已内置于 VSCode，打开 Chat 视图并按提示登录 GitHub 即可
3. 如果你使用的是较旧版本，请安装 `GitHub Copilot Chat` 扩展。补全与聊天能力已合并到这一个扩展中，独立的 `GitHub Copilot` 扩展已弃用

### 基础配置

```jsonc
{
  // 启用内联建议
  "editor.inlineSuggest.enabled": true,

  // 按语言启用/禁用 Copilot 补全
  "github.copilot.enable": {
    "*": true,
    "plaintext": true,
    "markdown": true,
    "yaml": true
  }
}
```

> **注意：** Copilot 没有按路径排除文件的本地设置。要排除敏感文件，请在企业/仓库的 Copilot 内容排除（Content exclusion）中配置，或按语言关闭补全。

### Copilot 补全的使用方式

Copilot 会在你编码时以灰色文字显示建议。操作方式：

| 操作 | 快捷键 |
| ------ | -------- |
| 接受整个建议 | `Tab` |
| 部分接受（逐词/逐行） | `Ctrl+→`（`⌘+→`） |
| 查看下一个建议 | `Alt+]`（`⌥+]`） |
| 查看上一个建议 | `Alt+[`（`⌥+[`） |
| 主动触发建议 | `Alt+\`（`⌥+\`） |
| 打开建议面板（查看所有建议） | `Ctrl+Enter`（macOS 为 `Ctrl+Return`） |
| 拒绝建议 | `Esc` 或继续输入 |

## 16.3 Copilot Chat：对话式编程

### 聊天面板

按 `Ctrl+Alt+I`（macOS 为 `⌃⌘I`）或点击侧边栏的 Chat 图标打开聊天面板。

**有效的提问方式：**

```
❌ "帮我写代码"
✅ "用 TypeScript 写一个防抖函数，支持泛型，默认延迟 300ms"

❌ "这段代码有 bug"
✅ "这段代码在处理空数组时会抛出 TypeError，请帮我添加边界检查"

❌ "优化这段代码"
✅ "这个 O(n²) 的嵌套循环可以用哈希表优化到 O(n) 吗？请给出代码"
```

### 内联聊天（Inline Chat）

按 `Ctrl+I`（`⌘+I`）在当前编辑器位置打开内联聊天。这是最自然的 AI 交互方式——你不需要离开代码上下文。

```
# 选中一段代码，按 Ctrl+I，输入：
"将这段代码重构为使用 async/await 替代 .then() 链"

"为这个函数添加 JSDoc 注释，包含参数类型和返回值说明"

"这段代码有一个潜在的内存泄漏，请找出并修复"

"将这个 class 组件重写为函数式组件 + Hooks"
```

### Chat 上下文与命令

当前版本的 Copilot Chat 用 `#` 添加上下文：在输入框键入 `#`，会弹出可用项列表（文件、文件夹、符号、终端输出、源代码管理变更等），选中即可。

```
# 添加显式上下文
#file 这个文件的主要功能是什么？
#selection 解释选中的代码
#codebase 这个项目的数据流是怎样的？
#terminalLastCommand 解释最后一个命令的错误
#problems 当前工作区有哪些错误？
#changes 审查我尚未提交的改动

# 使用 / 命令
/explain 解释这段代码的工作原理
/tests 为选中的函数生成单元测试
/fix 修复选中的代码中的错误
/doc 为选中的代码生成文档
/plan 先为这个需求制定实现计划
/init 为项目生成自定义指令文件
```

> **兼容性说明：** 旧版 Copilot Chat 中的 `@workspace`、`@terminal`、`@vscode` 等参与者已逐步弃用。新版建议直接用自然语言提问，并用 `#` 显式添加上下文。

### Agent 模式

Copilot 的 Agent 模式（2025 年推出，现已正式可用）让 AI 不仅给建议，还能自主执行多步骤任务：

```
"请帮我做以下事情：
1. 在 src/api/users.ts 中添加一个新的 GET /users/:id/posts 端点
2. 为这个端点编写测试
3. 更新 API 文档"
```

Agent 模式下，Copilot 会自动读取文件、编辑代码、运行终端命令、创建新文件——整个过程你只需要审批关键步骤。

## 16.4 Copilot 最佳实践

### 1. 用注释引导 AI

Copilot 对注释的理解能力非常强。与其等着它猜你想要什么，不如先用注释"画好蓝图"：

```typescript
// TODO: Implement a retry wrapper with exponential backoff
// - Accept a function and max retries
// - Delay should double after each failure (100ms, 200ms, 400ms...)
// - Add optional jitter to prevent thundering herd
// - Return the result or throw after all retries exhausted
async function retryWithBackoff<T>(
  fn: () => Promise<T>,
  maxRetries: number = 3
): Promise<T> {
  // Copilot 会基于上面的注释生成高质量的实现
```

### 2. 管理上下文

Copilot 的建议质量取决于它能看到的上下文：

- **显式添加上下文：** Chat 中通过 `#file`、`#codebase` 等引用文件；内联补全主要参考当前文件及相邻打开的文件
- **保持代码结构清晰：** 良好的函数命名和类型定义帮助 Copilot 理解意图
- **使用类型标注：** TypeScript 的类型信息是 Copilot 最好的"参考资料"

```typescript
// 差的上下文 - Copilot 只能猜测
function processData(data) {
  // Copilot: ???
}

// 好的上下文 - Copilot 能生成精确的代码
interface UserProfile {
  id: string;
  name: string;
  email: string;
  preferences: {
    theme: 'light' | 'dark';
    notifications: boolean;
  };
}

function processUserData(user: UserProfile): UserViewModel {
  // Copilot 可以精确地生成转换逻辑
}
```

### 3. 接受/拒绝策略

```
✅ 接受：
- 简单的样板代码（CRUD、类型定义、配置）
- 你一眼就能看懂且正确的代码
- 正则表达式（这是 AI 最擅长的场景之一）

⚠️ 仔细检查后接受：
- 复杂的算法逻辑
- 安全相关的代码（认证、加密）
- 涉及数据库操作的代码

❌ 警惕：
- 看起来"太聪明"的代码（可能有隐藏 bug）
- 使用了你不熟悉的 API 的代码
- 硬编码了具体值的代码
```

### 4. 迭代式提示

不要指望一次提示就得到完美结果。采用"粗稿 → 精修"的策略：

```
第一轮：帮我写一个文件上传的 API 端点
第二轮：添加文件大小限制（最大 10MB）和 MIME 类型验证
第三轮：添加上传进度回调和取消上传的功能
第四轮：为这个端点编写集成测试
```

## 16.5 Continue：开源 AI 助手

如果你不想依赖商业服务，或者需要在内网环境中使用 AI 编程，Continue 是最佳选择。

### 安装与配置

1. 在 VSCode 扩展市场搜索 `Continue` 安装
2. 打开 Continue 面板，进入设置
3. 配置你的 LLM 后端

**配置示例（`~/.continue/config.yaml`，Windows 为 `%USERPROFILE%\.continue\config.yaml`）：**

```yaml
name: My Config
version: 1.0.0
schema: v1
models:
  - name: Claude Sonnet
    provider: anthropic
    model: claude-sonnet-4-5
    apiKey: ${{ secrets.ANTHROPIC_API_KEY }}
    roles: [chat, edit, apply]
  - name: GPT-5
    provider: openai
    model: gpt-5
    apiKey: ${{ secrets.OPENAI_API_KEY }}
    roles: [chat, edit, apply]
  - name: Local Qwen Coder
    provider: ollama
    model: qwen2.5-coder:7b
    apiBase: http://localhost:11434
    roles: [chat, edit, apply]
  - name: Codestral
    provider: mistral
    model: codestral-latest
    apiKey: ${{ secrets.MISTRAL_API_KEY }}
    roles: [autocomplete]
context:
  - provider: code
  - provider: docs
  - provider: diff
  - provider: terminal
  - provider: folder
```

> **注意：** Continue 已从 `config.json` 迁移到 `config.yaml`，旧格式虽仍可读取但已弃用。模型 ID 会随服务商更新，请以官方文档为准；`secrets.XXX` 形式的密钥引用可在 Continue 设置中配置。

### Continue 的独特优势

- **模型自由切换：** 可以针对不同任务使用不同模型（补全用小模型，聊天用大模型）
- **本地部署：** 配合 Ollama 运行本地模型，代码不出本机
- **自定义上下文：** 可以引入文档、代码库索引作为上下文
- **完全开源：** 可以 fork 并定制自己的工作流

## 16.6 AI 辅助编程的正确心态

### AI 是副驾驶，不是司机

记住这个类比：

```
🚗 你是司机（主驾驶）
   - 决定目的地（需求分析）
   - 选择路线（架构设计）
   - 控制方向盘（代码审查和决策）
   - 对事故负责（代码质量）

🤖 AI 是副驾驶
   - 提供路线建议（代码建议）
   - 帮忙看导航（搜索和参考）
   - 处理琐碎操作（样板代码）
   - 在你疲劳时提醒你（代码审查建议）
```

### 警惕"AI 依赖症"

```
❌ 不好的习惯：
- 不看 Copilot 的建议就按 Tab
- 不理解生成的代码就提交
- 让 AI 写整个文件而自己完全不参与
- 用 AI 代替学习基础知识

✅ 好的习惯：
- 每个建议都快速审查后再接受
- 用 AI 生成的代码作为学习材料（理解它为什么这样写）
- 让 AI 处理重复性工作，自己专注核心逻辑
- 定期不使用 AI 编程，保持基本功
```

## 16.7 实战：用 Copilot 辅助完成功能模块

让我们模拟一个实际场景：用 Copilot 辅助开发一个"用户认证模块"。

### 第一步：定义接口（AI 辅助）

```typescript
// 注释：定义用户认证模块的接口
// 需要包含：注册、登录、刷新Token、登出
// 使用 JWT 进行会话管理

interface AuthService {
  register(email: string, password: string): Promise<AuthResult>;
  login(email: string, password: string): Promise<AuthResult>;
  refreshToken(refreshToken: string): Promise<TokenPair>;
  logout(userId: string): Promise<void>;
}

interface AuthResult {
  user: UserPublicInfo;
  tokens: TokenPair;
}

interface TokenPair {
  accessToken: string;
  refreshToken: string;
  expiresIn: number;
}

interface UserPublicInfo {
  id: string;
  email: string;
  displayName: string;
}
// Copilot 会基于注释生成完整的接口定义 ✅
```

### 第二步：实现核心逻辑（AI 辅助 + 人工审查）

```typescript
// 实现 AuthService 的 register 方法
// - 检查邮箱是否已注册
// - 使用 bcrypt 加密密码（rounds=12）
// - 创建用户记录
// - 生成 JWT token pair（access: 15min, refresh: 7d）
// - 返回用户信息和 tokens

class AuthServiceImpl implements AuthService {
  constructor(
    private userRepo: UserRepository,
    private jwtService: JwtService,
    private bcrypt: typeof import('bcrypt'),
  ) {}

  async register(email: string, password: string): Promise<AuthResult> {
    // 使用 Ctrl+I 内联聊天让 Copilot 生成实现
    // 人工审查：确保密码哈希、错误处理、输入验证都到位
    
    const existingUser = await this.userRepo.findByEmail(email);
    if (existingUser) {
      throw new ConflictError('Email already registered');
    }

    const hashedPassword = await this.bcrypt.hash(password, 12);
    const user = await this.userRepo.create({
      email,
      password: hashedPassword,
      displayName: email.split('@')[0],
    });

    const tokens = this.generateTokenPair(user.id);
    return {
      user: { id: user.id, email: user.email, displayName: user.displayName },
      tokens,
    };
  }

  // ... 其他方法用类似方式实现
}
```

### 第三步：编写测试（AI 辅助）

在 Chat 中使用 `/tests` 命令，或者用内联聊天：

```
选中 register 方法，按 Ctrl+I：
"为这个方法编写全面的单元测试，覆盖以下场景：
1. 正常注册成功
2. 邮箱已存在时抛出 ConflictError
3. 密码哈希使用了 12 轮
4. 返回的 token 格式正确"
```

### 第四步：代码审查

最后，在 Chat 中问：

```
#file 请审查这个认证模块的安全性，关注：
- 密码存储是否安全
- Token 生成是否使用了足够强的密钥
- 是否有信息泄露风险（错误消息中不应暴露内部细节）
- 是否有时序攻击风险
```

## 16.8 进阶：自定义 Copilot 指令

### `.github/copilot-instructions.md`

在仓库根目录创建此文件，为 Copilot 提供项目级别的上下文指令：

```markdown
# Copilot Instructions

## Code Style
- Use TypeScript with strict mode enabled
- Prefer functional programming patterns over classes
- Use async/await instead of .then() chains
- All public functions must have JSDoc comments

## Project Conventions
- API endpoints follow RESTful conventions
- Use Zod for runtime validation
- Use the Repository pattern for database access
- All errors should extend from AppError base class

## Testing
- Use Vitest for unit tests
- Use Playwright for E2E tests
- Follow the Arrange-Act-Assert pattern
- Mock external services, never make real API calls in tests

## Do Not
- Do not use `any` type
- Do not use `console.log` in production code (use the logger service)
- Do not commit secrets or environment variables
- Do not generate code that uses deprecated Node.js APIs
```

### 针对不同项目类型的指令示例

对于不同类型的项目，指令也应该不同：

**React 项目：**

```markdown
- Use functional components with hooks only
- Use React.memo for expensive re-renders
- Custom hooks should be prefixed with 'use'
- Use barrel exports (index.ts) for module public APIs
- Component props interfaces should be named {ComponentName}Props
```

**Python/Django 项目：**

```markdown
- Follow PEP 8 style guide
- Use type hints for all function parameters and return types
- Use Django REST Framework for API endpoints
- Use pytest for testing (not Django's built-in test framework)
- Use django-environ for environment configuration
```
