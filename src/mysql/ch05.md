# 第5章 聚合函数与分组

> 聚合查询就像Excel的透视表——你不需要逐行看数据，而是想看"总数是多少"、"平均值是多少"、"按类别分组后各组有多少"。掌握聚合，你的SQL才算真正入门。

## 5.1 聚合函数

MySQL提供了五个核心聚合函数：

```sql
-- COUNT：计数
SELECT COUNT(*) FROM orders;                     -- 总行数
SELECT COUNT(phone) FROM users;                  -- phone非NULL的行数
SELECT COUNT(DISTINCT category_id) FROM products; -- 不同分类的数量

-- SUM：求和
SELECT SUM(total_amount) FROM orders WHERE status = 'completed';
SELECT SUM(price * stock) FROM products;          -- 库存总价值

-- AVG：平均值
SELECT AVG(price) FROM products WHERE category_id = 1;
-- 注意：AVG会忽略NULL值

-- MAX / MIN：最大值/最小值
SELECT MAX(price) AS max_price, MIN(price) AS min_price FROM products;
SELECT MAX(created_at) AS latest_order FROM orders;

-- 组合使用
SELECT
  COUNT(*) AS total_products,
  AVG(price) AS avg_price,
  MAX(price) AS max_price,
  MIN(price) AS min_price,
  SUM(stock) AS total_stock
FROM products
WHERE is_active = 1;
```

## 5.2 COUNT 的三种用法详解

这是面试常考的知识点：

```sql
-- 假设users表有以下数据：
-- id | username | phone
-- 1  | alice    | 13800001111
-- 2  | bob      | NULL
-- 3  | charlie  | 13800003333
-- 4  | david    | NULL

SELECT COUNT(*) FROM users;           -- 结果：4（统计所有行）
SELECT COUNT(phone) FROM users;      -- 结果：2（统计phone非NULL的行）
SELECT COUNT(1) FROM users;          -- 结果：4（和COUNT(*)效果一样）
SELECT COUNT(DISTINCT phone) FROM users; -- 结果：2（去重后非NULL的数量）
```

> **Tip：** `COUNT(*)`和`COUNT(1)`在InnoDB中性能几乎一样，MySQL优化器会做优化。但`COUNT(column)`需要检查该列是否为NULL，可能稍慢。日常使用中推荐`COUNT(*)`，语义最清晰。

## 5.3 GROUP BY：分组查询

分组是聚合的核心。你可以把它想象成"先把数据按某个维度分成堆，然后对每堆做统计"。

### 单列分组

```sql
-- 每个分类有多少个商品
SELECT category_id, COUNT(*) AS product_count
FROM products
GROUP BY category_id;

-- 每个分类的平均价格
SELECT category_id, ROUND(AVG(price), 2) AS avg_price
FROM products
GROUP BY category_id;

-- 每个用户的订单数和总消费
SELECT
  user_id,
  COUNT(*) AS order_count,
  SUM(total_amount) AS total_spent
FROM orders
GROUP BY user_id;
```

### 多列分组

```sql
-- 按分类+是否上架，统计商品数
SELECT
  category_id,
  is_active,
  COUNT(*) AS cnt,
  AVG(price) AS avg_price
FROM products
GROUP BY category_id, is_active;
```

### 分组 + 排序

```sql
-- 查出商品最多的5个分类
SELECT
  category_id,
  COUNT(*) AS product_count
FROM products
GROUP BY category_id
ORDER BY product_count DESC
LIMIT 5;
```

## 5.4 HAVING vs WHERE

这是一个经典问题。简单记：**WHERE在分组前过滤，HAVING在分组后过滤。**

```sql
-- WHERE：分组前过滤（过滤原始行）
-- HAVING：分组后过滤（过滤聚合结果）

-- 找出平均价格超过3000的分类
SELECT
  category_id,
  COUNT(*) AS cnt,
  AVG(price) AS avg_price
FROM products
WHERE is_active = 1          -- 先过滤：只要上架的商品
GROUP BY category_id
HAVING AVG(price) > 3000     -- 再过滤：平均价格>3000
ORDER BY avg_price DESC;

-- 找出订单超过10笔的用户
SELECT
  user_id,
  COUNT(*) AS order_count,
  SUM(total_amount) AS total
FROM orders
GROUP BY user_id
HAVING COUNT(*) > 10         -- 注意：HAVING中不能用列别名（标准SQL）
ORDER BY total DESC;

-- HAVING中可以用SELECT中的别名（MySQL扩展特性）
SELECT
  user_id,
  COUNT(*) AS order_count
FROM orders
GROUP BY user_id
HAVING order_count > 10;
```

> **Tip：** 在标准SQL中，HAVING不能引用SELECT的别名。但MySQL对此做了扩展，允许在HAVING中使用SELECT列表中的别名。不过要注意，如果你写的SQL需要兼容其他数据库，最好别这么写。

## 5.5 WITH ROLLUP

`WITH ROLLUP`能在分组结果后面添加一行汇总：

```sql
-- 基本用法
SELECT
  category_id,
  COUNT(*) AS cnt,
  SUM(price * stock) AS total_value
FROM products
GROUP BY category_id WITH ROLLUP;

-- 结果示例：
-- category_id | cnt | total_value
-- 1           | 50  | 250000.00
-- 2           | 30  | 180000.00
-- 3           | 20  | 90000.00
-- NULL        | 100 | 520000.00   <-- ROLLUP汇总行

-- 多列ROLLUP
SELECT
  category_id,
  is_active,
  COUNT(*) AS cnt
FROM products
GROUP BY category_id, is_active WITH ROLLUP;

-- 使用GROUPING()函数区分NULL是真实值还是汇总行（MySQL 8.0+）
SELECT
  CASE
    WHEN GROUPING(category_id) = 1 THEN '=== 总计 ==='
    ELSE CAST(category_id AS CHAR)
  END AS category_display,
  COUNT(*) AS cnt
FROM products
GROUP BY category_id WITH ROLLUP;
```

## 5.6 分组最佳实践与常见陷阱

### 陷阱一：SELECT中的非聚合列必须在GROUP BY中

```sql
-- 错误写法！（SQL_MODE含ONLY_FULL_GROUP_BY时会报错）
SELECT category_id, name, COUNT(*) FROM products GROUP BY category_id;
-- 'name'既不在GROUP BY中，也不是聚合函数的结果

-- 正确写法
SELECT category_id, MIN(name) AS first_name, COUNT(*) FROM products GROUP BY category_id;
```

### 陷阱二：GROUP BY的隐式排序

```sql
-- MySQL 8.0+ 不再支持GROUP BY的隐式排序
-- 如果需要排序，必须显式写ORDER BY
SELECT category_id, COUNT(*) AS cnt
FROM products
GROUP BY category_id
ORDER BY cnt DESC;  -- 不要依赖GROUP BY自动排序
```

### 最佳实践

```sql
-- 1. 确保SQL_MODE包含ONLY_FULL_GROUP_BY
SELECT @@sql_mode;

-- 2. 用子查询优化复杂分组
SELECT
  c.category_name,
  stats.product_count,
  stats.avg_price
FROM categories c
INNER JOIN (
  SELECT
    category_id,
    COUNT(*) AS product_count,
    ROUND(AVG(price), 2) AS avg_price
  FROM products
  WHERE is_active = 1
  GROUP BY category_id
) stats ON c.id = stats.category_id
ORDER BY stats.product_count DESC;

-- 3. 大表分组注意索引
-- GROUP BY的列最好有索引，否则会产生临时表
EXPLAIN SELECT category_id, COUNT(*) FROM products GROUP BY category_id;
```

## 小结

本章我们学习了五大聚合函数、GROUP BY分组、HAVING过滤、以及WITH ROLLUP。最关键的是理解了WHERE和HAVING的区别，以及分组的常见陷阱。聚合查询是数据分析和报表生成的基础，多多练习。
