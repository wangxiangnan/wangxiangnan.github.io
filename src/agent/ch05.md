# 第5章 Agent 的推理策略 — 让 AI 学会"思考"

> **本章目标**：掌握 5 种核心推理策略，理解每种策略的适用场景和成本收益  
> **关键概念**：Zero-shot、Few-shot、Chain-of-Thought、Self-Consistency、Tree-of-Thought  
> **读完本章你将能够**：根据任务复杂度选择最合适的推理策略

---

## 5.1 开篇：推理策略 = 算法选择

写代码时，你会根据问题选择不同的算法：

- 排序 10 个数 → 插入排序（简单快）
- 排序 100 万个数 → 快速排序（高效）
- 搜索有序数组 → 二分查找（O(log n)）
- 搜索图 → BFS/DFS（遍历）

推理策略也是一样 — 不同的问题需要不同的"思考算法"：

```
任务复杂度 vs 策略选择：

简单任务（分类、提取）
├── 格式要求低？ → Zero-shot
└── 格式严格？ → Few-shot

中等任务（解释、排查）
└── 多步推理？ → Chain-of-Thought

复杂任务（高风险、创意）
├── 需要准确性？ → Self-Consistency
└── 需要创造性？ → Tree-of-Thought
```

> 程序员视角：每种策略是一个"思维框架"，选对了事半功倍，选错了事倍功半。

## 5.2 Zero-shot — 像纯函数：输入→输出

**核心思想**：不给示例，直接问。就像纯函数 `f(x) -> y`，不依赖外部状态。

### 适用场景

- 简单分类（技术问题分类、情感分析）
- 格式提取（从文本提取日期、邮箱）
- 概念解释（一句话解释某个术语）

### 实现

```python
from openai import OpenAI
import os

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

def zero_shot_classify(question: str) -> str:
    """Zero-shot 分类 — 最快最便宜"""
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": 
             "你是技术问题分类器。输出格式：分类:X 难度:初级/中级/高级。只输出分类结果，不要解释。"},
            {"role": "user", "content": question}
        ],
        temperature=0,  # 确定性
        max_tokens=50
    )
    return response.choices[0].message.content

# 测试
test_questions = [
    "FastAPI WebSocket 怎么用？",
    "PostgreSQL 索引优化？",
    "Docker depends_on 和 depends_on.condition 的区别？",
    "Python dataclass 和 NamedTuple 怎么选？",
    "如何设计百万并发的消息队列？"
]

print("=== Zero-shot 分类结果 ===")
for q in test_questions:
    result = zero_shot_classify(q)
    print(f"  {q}")
    print(f"  → {result}\n")
```

### Zero-shot 的优缺点

```python
zero_shot_analysis = {
    "优点": [
        "最快：一次请求，无额外 token",
        "最便宜：没有示例占用 token",
        "最简单：不需要准备示例"
    ],
    "缺点": [
        "格式不稳定：LLM 可能输出各种格式",
        "准确率低：复杂任务可能理解错",
        "无法展示边界：LLM 不知道什么不该做"
    ],
    "适用场景": [
        "简单分类（情感分析、主题分类）",
        "格式提取（日期、邮箱、URL）",
        "概念解释（一句话定义）",
        "快速原型（验证想法）"
    ]
}

# 实际测试：格式稳定性
formats_tested = []
for i in range(10):
    result = zero_shot_classify("Redis 持久化？")
    formats_tested.append(result)

# 可能得到：
# "分类:DB 难度:中级"
# "分类:数据库/Redis, 难度:中级"
# "DB/缓存 - 中级"
# ← 格式不一致！
```

> ⚠️ **Zero-shot 的坑**：
>
> - 格式不稳定 → 如果需要严格格式，用 Few-shot
> - 复杂任务准确率低 → 多步推理用 CoT
> - 小模型更不稳定 → gpt-4o-mini 比 gpt-4 格式更乱

## 5.3 Few-shot — 像单测样例：用例子"教"格式

**核心思想**：给几个示例，让 LLM 精确模仿输出格式。就像单元测试的样例 — 定义期望的输入→输出映射。

### 为什么 Few-shot 格式更稳？

```python
# Zero-shot — LLM 自由发挥
zero_result = "这个问题属于数据库领域，难度中等"  # 格式乱

# Few-shot — LLM 模仿示例格式
few_examples = [
    {"role": "user", "content": "Redis 分布式锁？"},
    {"role": "assistant", "content": "分类:DB 子分类:Redis 难度:高"},
    {"role": "user", "content": "asyncio 事件循环？"},
    {"role": "assistant", "content": "分类:Python 子分类:异步 难度:中"},
]
few_result = "分类:Web 子分类:代理 难度:中"  # 格式一致！
```

### 完整实现

```python
def few_shot_classify(question: str) -> str:
    """Few-shot 分类 — 格式稳定"""
    messages = [
        {"role": "system", "content": "你是技术问题分类助手。严格按照示例格式输出。"},
        
        # 示例 1
        {"role": "user", "content": "Redis 分布式锁？"},
        {"role": "assistant", "content": "分类:DB 子分类:Redis 难度:高 标签:Redis,分布式锁,并发"},
        
        # 示例 2
        {"role": "user", "content": "asyncio 事件循环？"},
        {"role": "assistant", "content": "分类:Python 子分类:异步 难度:中 标签:Python,asyncio,事件循环"},
        
        # 示例 3（展示边界情况）
        {"role": "user", "content": "今天天气怎么样？"},
        {"role": "assistant", "content": "分类:OUT_OF_SCOPE 子分类:N/A 难度:N/A 标签:N/A"},
        
        # 待分类问题
        {"role": "user", "content": question}
    ]
    
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages,
        temperature=0,
        max_tokens=100
    )
    return response.choices[0].message.content

# 测试
test_cases = [
    "Nginx 反向代理配置？",
    "Docker Compose volumes？",
    "帮我写个情书"  # 边界测试
]

print("=== Few-shot 分类结果 ===")
for q in test_cases:
    result = few_shot_classify(q)
    print(f"  {q}")
    print(f"  → {result}\n")
```

### Zero-shot vs Few-shot 对比

```python
def compare_strategies(question: str) -> dict:
    """对比 Zero-shot 和 Few-shot"""
    import time
    
    # Zero-shot
    t0 = time.time()
    zero_msgs = [
        {"role": "system", "content": "分类技术问题。格式:分类:X 难度:Y"},
        {"role": "user", "content": question}
    ]
    zero_resp = client.chat.completions.create(
        model="gpt-4o-mini", messages=zero_msgs, temperature=0)
    zero_time = time.time() - t0
    
    # Few-shot
    t0 = time.time()
    few_msgs = [
        {"role": "system", "content": "分类技术问题。"},
        {"role": "user", "content": "Redis锁？"},
        {"role": "assistant", "content": "分类:DB 难度:高"},
        {"role": "user", "content": "asyncio？"},
        {"role": "assistant", "content": "分类:Python 难度:中"},
        {"role": "user", "content": question}
    ]
    few_resp = client.chat.completions.create(
        model="gpt-4o-mini", messages=few_msgs, temperature=0)
    few_time = time.time() - t0
    
    return {
        "zero_shot": {
            "result": zero_resp.choices[0].message.content,
            "tokens": zero_resp.usage.total_tokens,
            "time": f"{zero_time:.2f}s"
        },
        "few_shot": {
            "result": few_resp.choices[0].message.content,
            "tokens": few_resp.usage.total_tokens,
            "time": f"{few_time:.2f}s"
        }
    }

# 对比
comparison = compare_strategies("PostgreSQL 连接池配置？")
print(f"Zero-shot: {comparison['zero_shot']['result']}")
print(f"  Tokens: {comparison['zero_shot']['tokens']}, Time: {comparison['zero_shot']['time']}")
print(f"\nFew-shot: {comparison['few_shot']['result']}")
print(f"  Tokens: {comparison['few_shot']['tokens']}, Time: {comparison['few_shot']['time']}")

# 总结对比表
print("""
| 指标 | Zero-shot | Few-shot |
|------|-----------|----------|
| 准确率 | ~85% | ~95% |
| 格式稳定性 | 低（~70%） | 高（~100%） |
| Token 成本 | ~100 | ~400 |
| 延迟 | 最快 | 略慢 |
| 适用 | 简单任务 | 格式严格 |
""")
```

> 💡 **何时用 Few-shot**：
>
> - 输出格式必须一致（API 返回、数据提取）
> - 需要展示边界（什么不该做）
> - 复杂分类（多类别、细粒度）

## 5.4 Chain-of-Thought (CoT) — 像代码注释：分步思考

**核心思想**：强制 LLM 分步分析，而不是直接给答案。就像写代码时加注释解释每步逻辑。

### 为什么 CoT 能提升准确率？

```python
# 无 CoT — LLM "直觉"回答（像考试不写过程）
# 问题："一个函数处理1000条记录，每条50ms，并行处理（10个worker），总时间？"
# 直觉答案："50000ms" ← 错了！没考虑并行

# 有 CoT — 强制分步（像写解题过程）
# 1. 单条: 50ms
# 2. 1000条串行: 1000 × 50ms = 50000ms
# 3. 10个worker并行: 50000ms / 10 = 5000ms
# 4. 考虑开销: ~5500ms
# 答案："约 5.5 秒" ← 正确！
```

### CoT 实现：错误排查示例

```python
def cot_troubleshoot(error: str, context: str = "") -> str:
    """用 CoT 排查错误"""
    prompt = f"""报错信息:
```

{error}

```
{f"\n上下文: {context}" if context else ""}

请按以下步骤排查：

1. **【分析】** 这个错误的含义是什么？
2. **【原因】** 列出可能的原因（按概率排序）
3. **【排查】** 对每个原因给出检查命令
4. **【解决】** 给出解决方案（按优先级）"""
    
    response = client.chat.completions.create(
        model="gpt-4o-mini",

            {"role": "system", "content": "你是资深后端工程师，擅长排查技术问题。"},
            {"role": "user", "content": prompt}
        ],
        temperature=0
    )
    return response.choices[0].message.content

# 示例 1：网络连接错误
error1 = """
```

>
> **建议**：Agent 场景默认用 CoT（准确性优先），简单查询不用。

## 5.5 Self-Consistency — 像多人 Code Review：投票决策

**核心思想**：同一问题问 N 次（temperature 高一点让思路不同），投票选最多答案。就像多人 Code Review — 大多数人同意的方案更可靠。

### 为什么 Self-Consistency 更准？

```python
# 单次 CoT — 可能走错路径
# 问："Python GIL 会影响多线程的 CPU 密集任务吗？"
# 回答 1："是的，GIL 会..." ← 对了

# 但如果运气不好：
# 回答 2："不一定，因为..." ← 走错路径

# Self-Consistency — 问 5 次，投票
# 回答 1: "是的" ✓
# 回答 2: "是的" ✓
# 回答 3: "是的" ✓
# 回答 4: "不一定" ✗
# 回答 5: "是的" ✓
# 投票: 4/5 = "是的" ← 更可靠！
```

### 完整实现

```python
from collections import Counter
import re

def self_consistency(question: str, n: int = 5, model: str = "gpt-4o-mini") -> dict:
    """Self-Consistency: 多次采样 + 投票"""
    answers = []
    reasoning_paths = []
    
    for i in range(n):
        response = client.chat.completions.create(
            model=model,
            messages=[
                {"role": "system", "content": 
                 "你是技术专家。逐步分析问题，最后一行用'答案：X'给出最终答案。"},
                {"role": "user", "content": question}
            ],
            temperature=0.7,  # 高温让思路多样化
            max_tokens=1000
        )
        
        content = response.choices[0].message.content
        reasoning_paths.append(content)
        
        # 提取最终答案
        answer = extract_answer(content)
        answers.append(answer)
    
    # 投票
    counter = Counter(answers)
    best_answer, count = counter.most_common(1)[0]
    confidence = count / n
    
    return {
        "answer": best_answer,
        "confidence": confidence,
        "votes": dict(counter),
        "all_reasoning": reasoning_paths
    }

def extract_answer(text: str) -> str:
    """从回答中提取最终答案"""
    # 尝试多种格式
    patterns = [
        r"答案：(.+)",
        r"答案是[：:]\s*(.+)",
        r"最终答案[：:]\s*(.+)",
        r"Final Answer[：:]\s*(.+)",
    ]
    for pattern in patterns:
        match = re.search(pattern, text)
        if match:
            return match.group(1).strip()
    
    # 默认取最后一行
    lines = text.strip().split("\n")
    return lines[-1] if lines else "未知"

# 示例 1：有明确答案的问题
result1 = self_consistency(
    "一个 PostgreSQL 表有 1000 万行，B-tree 索引高度大约是几层？" \
    "假设每个节点存 100 个键。",
    n=5
)
print("=== Self-Consistency 示例 1 ===")
print(f"问题: PostgreSQL 索引高度")
print(f"答案: {result1['answer']}")
print(f"置信度: {result1['confidence']:.0%}")
print(f"投票: {result1['votes']}")

# 示例 2：方案选择
result2 = self_consistency(
    "FastAPI 后台任务（发邮件、生成报表、数据同步）应该用哪种方案？" \
    "A) BackgroundTasks B) Celery C) asyncio.create_task D) 消息队列",
    n=5
)
print("\n=== Self-Consistency 示例 2 ===")
print(f"问题: 后台任务方案")
print(f"答案: {result2['answer']}")
print(f"置信度: {result2['confidence']:.0%}")
print(f"投票: {result2['votes']}")
```

### Self-Consistency 成本分析

```python
def self_consistency_cost(n: int, avg_tokens: int, model: str = "gpt-4o-mini") -> dict:
    """计算 Self-Consistency 的成本"""
    # GPT-4o-mini 价格（每 1M tokens）
    prices = {
        "gpt-4o-mini": {"input": 0.15, "output": 0.60},
        "gpt-4o": {"input": 2.50, "output": 10.00},
        "gpt-4": {"input": 30.00, "output": 60.00},
    }
    
    price = prices[model]
    # 每次请求：输入 ~200 tokens，输出 ~avg_tokens
    input_cost = (200 * n / 1_000_000) * price["input"]
    output_cost = (avg_tokens * n / 1_000_000) * price["output"]
    total_cost = input_cost + output_cost
    
    # 对比单次 CoT
    single_cost = (200 / 1_000_000) * price["input"] + \
                  (avg_tokens / 1_000_000) * price["output"]
    
    return {
        "total_cost": f"${total_cost:.6f}",
        "single_cot_cost": f"${single_cost:.6f}",
        "multiplier": f"{total_cost/single_cost:.1f}x",
        "accuracy_gain": "~5-10%（复杂推理任务）"
    }

# 成本分析
cost = self_consistency_cost(n=5, avg_tokens=500, model="gpt-4o-mini")
print(f"Self-Consistency (n=5): {cost['total_cost']}")
print(f"单次 CoT: {cost['single_cot_cost']}")
print(f"成本倍数: {cost['multiplier']}")
print(f"准确性提升: {cost['accuracy_gain']}")

# 何时值得用 Self-Consistency？
print("""
何时值得用 Self-Consistency？

✅ 值得：
- 高风险决策（架构设计、安全配置）
- 数学/逻辑题（答案可验证）
- 一次性分析（不是每次请求）

❌ 不值得：
- 实时 API（延迟太高）
- 简单问题（单次 CoT 够了）
- 高频调用（成本爆炸）
""")
```

## 5.6 Tree-of-Thought (ToT) — 像 Git 分支：探索多路径

**核心思想**：不是线性思考，而是创建多个"思维分支"，评估每个分支，选最佳。就像 Git 分支 — 尝试多个方案，merge 最好的。

### ToT vs CoT

```python
# CoT（线性）
# A → B → C → 答案
# 如果 B 就错了，后面全错

# ToT（树形）
#     ┌─ B1 → C1 → 答案1 (70分)
# A ──┼─ B2 → C2 → 答案2 (85分) ← 选这个
#     └─ B3 → C3 → 答案3 (60分)
# 探索多条路径，选最佳
```

### 完整实现

```python
def tree_of_thought(question: str, num_branches: int = 3) -> dict:
    """Tree-of-Thought: 生成多方案 → 评估 → 选最佳"""
    
    # 阶段 1：生成多个方案（创建分支）
    print("=== 阶段 1：生成方案 ===")
    branches_response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": 
             f"你是架构师。给出 {num_branches} 种不同的方案。" \
             "每个方案用'--- 方案N ---'开头，包含：\n" \
             "1. 方案描述\n2. 优点（2-3点）\n3. 缺点（2-3点）\n4. 适用场景"},
            {"role": "user", "content": question}
        ],
        temperature=0.8,  # 高温鼓励多样性
        max_tokens=2000
    )
    branches = branches_response.choices[0].message.content
    print(branches[:500] + "...\n")
    
    # 阶段 2：评估每个方案（Code Review）
    print("=== 阶段 2：评估方案 ===")
    eval_response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": 
             "你是技术评审专家。对每个方案评分（1-10）并说明理由。\n" \
             "评分维度：\n" \
             "- 可行性：实现难度、团队技能匹配度\n" \
             "- 成本：开发成本、运维成本\n" \
             "- 效果：能否解决问题、扩展性\n\n" \
             "最后选出最佳方案，用'推荐：方案N'总结。"},
            {"role": "user", "content": f"问题：{question}\n\n方案：\n{branches}"}
        ],
        temperature=0.2,  # 低温确保评估稳定
        max_tokens=1500
    )
    evaluation = eval_response.choices[0].message.content
    print(evaluation[:500] + "...")
    
    return {
        "branches": branches,
        "evaluation": evaluation,
        "full_result": evaluation
    }
```

### ToT 进阶：迭代优化

```python
def iterative_tot(question: str, iterations: int = 2) -> str:
    """迭代式 ToT：每轮优化最佳方案"""
    
    current_best = None
    
    for i in range(iterations):
        print(f"\n=== 迭代 {i+1}/{iterations} ===")
        
        # 生成方案
        if current_best:
            prompt = f"基于上一轮最佳方案，提出 3 个改进版本。" \
                     f"\n\n上一轮最佳：\n{current_best}\n\n原始问题：{question}"
        else:
            prompt = f"给出 3 种方案解决问题：{question}"
        
        branches = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}],
            temperature=0.8
        ).choices[0].message.content
        
        # 评估
        evaluation = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {"role": "system", "content": "选出最佳方案并详细说明。"},
                {"role": "user", "content": branches}
            ],
            temperature=0.2
        ).choices[0].message.content
        
        current_best = evaluation
        print(f"当前最佳: {current_best[:200]}...")
    
    return current_best

# 使用
final = iterative_tot("设计一个高可用的 Redis 缓存架构", iterations=2)
print("\n=== 最终方案 ===")
print(final)
```

> ⚠️ **ToT 的 trade-off**：
>
> - ✅ 探索空间大，可能找到创新方案
> - ❌ 成本最高（多次 LLM 调用）
> - ❌ 延迟最高（串行多次）
>
> **建议**：只用于一次性架构设计、创意方案，不用于实时场景。

## 5.7 策略对比与选择指南

### 综合对比表

| 策略 | 准确率 | 成本 | 延迟 | 适用场景 | 编程类比 |
| ------ | ------- | ------ | ------ | ---------- | --------- |
| Zero-shot | 中（~85%） | 最低 | 最快 | 简单分类、概念提取 | 纯函数 |
| Few-shot | 高（~95%） | 中 | 中 | 格式严格、复杂分类 | 单测样例 |
| CoT | 很高（~79%数学） | 中高 | 中高 | 多步推理、排查 | 代码注释 |
| Self-C | 最高（~90%+） | Nx | Nx | 高风险决策 | 多人Review |
| ToT | 最高（创意） | 最高 | 最高 | 架构设计、创意 | Git分支 |

### 策略选择决策树

```python
def choose_strategy(task: dict) -> str:
    """根据任务特征选择推理策略"""
    
    # 任务特征
    complexity = task.get("complexity", "simple")  # simple/medium/complex
    format_required = task.get("format_required", False)  # 是否需要严格格式
    accuracy_critical = task.get("accuracy_critical", False)  # 准确性是否关键
    is_creative = task.get("is_creative", False)  # 是否需要创意
    is_realtime = task.get("is_realtime", True)  # 是否实时
    
    # 决策树
    if complexity == "simple":
        if format_required:
            return "Few-shot"  # 简单但格式严格
        else:
            return "Zero-shot"  # 简单且格式灵活
    
    elif complexity == "medium":
        if accuracy_critical:
            return "CoT + Self-Consistency"  # 中等复杂度 + 高准确性
        else:
            return "CoT"  # 中等复杂度，CoT 够了
    
    else:  # complex
        if is_creative:
            return "Tree-of-Thought"  # 需要创意，探索多路径
        elif accuracy_critical and not is_realtime:
            return "CoT + Self-Consistency (n=5)"  # 高风险，非实时
        else:
            return "CoT"  # 复杂但实时，用 CoT 平衡
    
# 测试
tasks = [
    {"name": "技术问题分类", "complexity": "simple", "format_required": True},
    {"name": "解释Python装饰器", "complexity": "medium", "format_required": False},
    {"name": "排查数据库死锁", "complexity": "medium", "accuracy_critical": True},
    {"name": "设计微服务架构", "complexity": "complex", "is_creative": True},
    {"name": "实时API问答", "complexity": "medium", "is_realtime": True},
]

for task in tasks:
    strategy = choose_strategy(task)
    print(f"{task['name']:20s} → {strategy}")
```

```python
def hybrid_strategy(question: str) -> str:
    """混合策略：先分类，再用对应策略"""
    
    # 第一步：分类（Zero-shot，快）
    classification = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": 
             "分类问题：SIMPLE（概念）| DEBUG（排查）| DESIGN（设计）"},
            {"role": "user", "content": question}
        ],
        temperature=0
    ).choices[0].message.content
    
    # 第二步：根据分类选策略
    if "SIMPLE" in classification:
        # 简单问题：Zero-shot
        return ask_zero_shot(question)
    elif "DEBUG" in classification:
        # 排查问题：CoT
        return ask_with_cot(question)
    else:
        # 设计问题：ToT
        return ask_with_tot(question)

def ask_zero_shot(q): return f"[Zero-shot] {q}"
def ask_with_cot(q): return f"[CoT] {q}"
def ask_with_tot(q): return f"[ToT] {q}"

print(hybrid_strategy("Python 的 GIL 是什么？"))
# → [Zero-shot] ...

# → [CoT] ...
```

## 5.9 本章小结

1. **Zero-shot**：最快最便宜，适合简单分类，格式不稳定
2. **Few-shot**：用例子教格式，适合严格输出要求，成本略高
3. **CoT**：分步思考，推理准确率高 4.6 倍，Agent 默认策略
4. **Self-Consistency**：多次投票，最可靠，成本 Nx
5. **ToT**：多分支探索，适合创意设计，成本最高
6. **按任务选策略**：简单用 Zero/Few，复杂用 CoT，高风险用 Self-C

### 策略速查卡

```
┌────────────────────────────────────────────┐
│  推理策略速查卡                              │
├────────────────────────────────────────────┤
│  简单分类 → Zero-shot                      │

│  高风险 → CoT + Self-Consistency           │
```
