# 第3章：函数与控制流

## 为什么厨师需要菜谱？

函数就像菜谱：输入是食材，输出是一道菜。Rust 的函数定义比其他语言更"挑剔"——参数必须标注类型，返回值也有特别的语法。但一旦习惯了，你会发现这种"挑剔"实际上是在帮你。

## 函数定义

```rust
// 无参数，无返回值
fn greet() {
    println!("Hello!");
}

// 有参数，有返回值
fn add(x: i32, y: i32) -> i32 {
    x + y  // 注意：没有分号！这是表达式，作为返回值
}

// 有参数，无返回值
fn print_sum(x: i32, y: i32) {
    println!("Sum: {}", x + y);
}

fn main() {
    greet();
    let result = add(3, 5);
    println!("3 + 5 = {result}");
    print_sum(10, 20);
}
```

## 表达式 vs 语句

这是 Rust 的核心概念之一，很多人一开始会搞混：

- **语句（Statement）**：执行操作但不返回值，以分号结尾
- **表达式（Expression）**：计算并产生一个值，**没有**分号

```rust
fn main() {
    // 语句
    let x = 5;         // let 绑定是语句
    println!("{x}");   // 宏调用是语句

    // 表达式
    let y = {
        let a = 3;
        let b = 4;
        a + b          // 没有分号 → 这是表达式，值 = 7
    };
    println!("y = {y}"); // 输出 7

    // 如果加了分号，就变成了语句，返回 ()
    let z = {
        let a = 3;
        let b = 4;
        a + b;         // 有分号 → 语句，z = ()
    };
    println!("z = {:?}", z); // 输出 ()
}
```

> **Python 类比**：Python 里 `lambda x: x + 1` 是表达式，`def f(x): return x + 1` 里的 `return` 是语句。Rust 里不需要 `return` 关键字，最后一个表达式自动就是返回值。

## if/else 表达式

Rust 的 `if` 是**表达式**，意味着它可以产生值：

```rust
fn main() {
    let number = 7;

    // 基本 if/else
    if number > 5 {
        println!("大于5");
    } else {
        println!("不大于5");
    }

    // if 作为表达式赋值
    let description = if number % 2 == 0 {
        "偶数"
    } else {
        "奇数"
    };
    println!("{number} 是 {description}");

    // 多条件：else if
    let score = 85;
    let grade = if score >= 90 {
        "A"
    } else if score >= 80 {
        "B"
    } else if score >= 70 {
        "C"
    } else {
        "D"
    };
    println!("分数 {score}，等级 {grade}");
}
```

> **注意**：if 的条件必须是 `bool` 类型！`if 1` 或 `if "hello"` 在 Rust 里是编译错误，不像 Python/JS 那样有"truthy/falsy"。

## 循环

### loop：无限循环

```rust
fn main() {
    let mut counter = 0;

    // loop 可以返回值！
    let result = loop {
        counter += 1;
        if counter == 10 {
            break counter * 2;  // break 可以带值
        }
    };

    println!("result = {result}"); // 20

    // 循环标签（嵌套循环时有用）
    let mut x = 0;
    'outer: loop {
        let mut y = 0;
        loop {
            if y == 3 {
                break;           // 跳出内层
            }
            if x == 2 && y == 2 {
                break 'outer;    // 跳出外层
            }
            y += 1;
        }
        x += 1;
    }
    println!("x={x}");
}
```

### while 循环

```rust
fn main() {
    let mut n = 5;
    while n > 0 {
        println!("{n}");
        n -= 1;
    }
    println!("发射！");
}
```

### for 循环

```rust
fn main() {
    // 遍历范围（Range）
    for i in 0..5 {
        println!("i = {i}");  // 0, 1, 2, 3, 4（不含5）
    }

    // 包含终点的范围
    for i in 0..=5 {
        print!("{i} ");  // 0 1 2 3 4 5
    }
    println!();

    // 遍历数组
    let fruits = ["苹果", "香蕉", "橘子"];
    for fruit in fruits.iter() {
        println!("水果: {fruit}");
    }

    // 带索引遍历
    for (i, fruit) in fruits.iter().enumerate() {
        println!("{i}: {fruit}");
    }

    // 反转遍历
    for i in (1..=5).rev() {
        println!("{i}");
    }
}
```

## 模式匹配初识：match

`match` 是 Rust 的超级武器，这里先简单认识：

```rust
fn main() {
    let number = 3;

    match number {
        1 => println!("一"),
        2 | 3 => println!("二或三"),
        4..=10 => println!("四到十"),
        _ => println!("其他"),   // _ 是通配符，匹配所有其他情况
    }
}
```

> **关键规则**：`match` 必须覆盖所有可能的情况（exhaustive），否则会编译错误。`_` 通配符用来兜底。

## 所有权预告

当你把一个变量传给函数时，Rust 会做一些"不寻常"的事情：

```rust
fn take_ownership(s: String) {
    println!("我拿到了: {s}");
}   // s 在这里被销毁

fn main() {
    let my_string = String::from("hello");
    take_ownership(my_string);
    // println!("{my_string}");  // 编译错误！my_string 已经被"移动"走了
}
```

别慌！这个"所有权"概念是 Rust 最核心的设计，第4章会详细讲解。现在只需要知道：**函数参数可能涉及"所有权的转移"**。

## 常见陷阱

1. **忘记分号导致类型错误**：函数最后一个表达式加分号会变成返回 `()`
2. **if 条件不是 bool**：Rust 不接受非 bool 类型的条件
3. **for 循环范围搞混**：`0..5` 不含 5，`0..=5` 包含 5
4. **match 不覆盖所有情况**：编译器会强制要求你处理所有可能

## 小结

- `fn` 定义函数，参数必须标注类型，`->` 后是返回类型
- 表达式（无分号）产生值，语句（有分号）不产生值
- `if` 是表达式，可以用于赋值
- `for..in` 遍历范围和迭代器，`loop` 可带返回值
- `match` 必须穷尽所有可能
