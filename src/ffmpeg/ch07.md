## 7.1 视频转码基础命令

最基本的转码命令长这样：

```bash
ffmpeg -i input.mp4 output.avi
```

就这么简单？没错。FFmpeg 会根据输出文件的扩展名自动选择合适的编码器。但这种"全自动"模式往往不是最优选择——它可能使用默认的低效编码器，或者压缩质量不理想。

更推荐的写法是明确指定编码器：

```bash
ffmpeg -i input.mp4 -c:v libx264 -c:a aac output.mp4
```

这里 `-c:v libx264` 告诉 FFmpeg 视频用 H.264 编码，`-c:a aac` 告诉它音频用 AAC 编码。明确指定编码器，你就掌控了一切。

## 7.2 -c:v 与 -c:a 的完整用法

`-c` 是 `-codec` 的缩写，后面跟 `:v`（视频）或 `:a`（音频）来指定作用于哪种流。

**重新编码（默认行为）：**

```bash
ffmpeg -i input.mp4 -c:v libx264 -c:a aac output.mp4
```

**复制流（不重新编码）：**

```bash
ffmpeg -i input.mkv -c:v copy -c:a copy output.mp4
```

`copy` 是一个特殊的值，意思是"直接复制原始数据，不做任何处理"。这意味着转换速度极快（几乎瞬间完成），而且没有任何质量损失。

**混合模式——只重编码视频，音频直接复制：**

```bash
ffmpeg -i input.mp4 -c:v libx264 -c:a copy output.mkv
```

**针对不同流分别指定编码器（多音轨场景）：**

```bash
ffmpeg -i input.mkv -c:v libx264 -c:a:0 aac -c:a:1 copy output.mp4
```

这里 `:a:0` 表示第一个音频流用 AAC 重新编码，`:a:1` 表示第二个音频流直接复制。

## 7.3 -c copy 的妙用：秒转容器格式

这是一个超实用的技巧。当你只需要更换容器格式（比如 MKV 转 MP4），而不需要改变内部编码时：

```bash
ffmpeg -i input.mkv -c copy output.mp4
```

> 💡 提示：这条命令处理一部两小时的电影只需要几秒钟，因为它只是把数据从一个"盒子"搬到另一个"盒子"，完全不需要重新编码。

这个技巧适用的前提是：源文件中的编码格式在目标容器中被支持。比如 H.264 视频 + AAC 音频可以从 MKV 秒转到 MP4，但 VP9 视频 + Opus 音频就不能直接 copy 到 MP4（MP4 不支持这两种编码）。

> ⚠️ 注意：`-c copy` 不支持在不同编码格式之间转换。如果源编码与目标容器不兼容，FFmpeg 会报错。此时你需要去掉 `-c copy`，让 FFmpeg 重新编码。

## 7.4 CRF（恒定质量）模式详解

CRF（Constant Rate Factor，恒定质量因子）是 libx264 和 libx265 编码器的默认质量控制模式，也是最推荐的方式。它的核心理念是：**你告诉 FFmpeg 你想要的画质，FFmpeg 自动决定码率。**

```bash
ffmpeg -i input.mp4 -c:v libx264 -crf 23 output.mp4
```

CRF 的取值范围是 0-51（对于 H.264）：

| CRF 值 | 画质描述 | 文件大小 | 推荐场景 |
| -------- | --------- | --------- | --------- |
| 0 | 无损 | 极大 | 存档，几乎不实际使用 |
| 17-18 | 视觉上几乎无损 | 较大 | 高质量收藏 |
| 21-23 | 高质量，肉眼几乎无差异 | 中等 | **日常推荐值** |
| 25-28 | 良好，有轻微压缩痕迹 | 较小 | 网络分享 |
| 30-35 | 可接受，明显压缩 | 小 | 手机观看 |
| 40-51 | 画质较差 | 极小 | 预览/草稿 |

> 💡 提示：CRF 23 是 x264 的默认值，也是大多数场景的最佳起点。CRF 值每增加 6，文件大小大约减半，画质相应下降。

**H.265 (HEVC) 的 CRF：**

```bash
ffmpeg -i input.mp4 -c:v libx265 -crf 28 output.mp4
```

HEVC 的 CRF 28 大约等同于 H.264 的 CRF 23（同等画质），因为 HEVC 的压缩效率更高。

## 7.5 Preset 参数：速度与质量的平衡

Preset 决定了编码的速度和压缩效率。更快的预设编码速度快但文件更大，更慢的预设编码时间长但压缩更充分。

可用预设（从快到慢）：

| Preset | 编码速度 | 压缩效率 | 适用场景 |
| -------- | --------- | --------- | --------- |
| ultrafast | 最快 | 最低 | 实时直播预览 |
| superfast | 很快 | 低 | 快速预览 |
| veryfast | 快 | 较低 | 快速测试 |
| faster | 较快 | 中等偏低 | 赶时间时 |
| fast | 快 | 中等 | 平衡选择 |
| medium | 中等 | 中等 | **默认值，日常推荐** |
| slow | 慢 | 较高 | 追求质量 |
| slower | 较慢 | 高 | 高质量输出 |
| veryslow | 很慢 | 很高 | 最终成品 |
| placebo | 极慢 | 最高（几乎无提升） | 别用，浪费生命 |

```bash
ffmpeg -i input.mp4 -c:v libx264 -crf 23 -preset slow output.mp4
```

> 💡 提示：`placebo` 比 `veryslow` 慢很多，但画质提升微乎其微（不到 1%）。除非你有强迫症，否则永远不要用它。

> 💡 提示：如果你在做测试/预览，用 `veryfast` 快速出结果；最终输出时用 `slow` 或 `slower` 获得更好的压缩。

## 7.6 码率控制：CBR、VBR 与 CRF

除了 CRF，FFmpeg 还支持其他码率控制模式：

**CBR（恒定码率）：**

```bash
ffmpeg -i input.mp4 -c:v libx264 -b:v 2500k -maxrate 2500k -minrate 2500k -bufsize 5000k output.mp4
```

CBR 让整个视频保持固定码率。适合直播推流，但日常使用不推荐——静态画面浪费码率，复杂画面码率不够。

**VBR（可变码率），指定目标码率：**

```bash
ffmpeg -i input.mp4 -c:v libx264 -b:v 2500k output.mp4
```

仅用 `-b:v` 时，FFmpeg 会尝试达到目标平均码率，但允许波动。

**约束 VBR（推荐用于流媒体）：**

```bash
ffmpeg -i input.mp4 -c:v libx264 -b:v 2500k -maxrate 3000k -bufsize 5000k output.mp4
```

`-maxrate` 限制峰值码率，`-bufsize` 定义码率控制缓冲区大小。

**CRF + 最大码率限制（最佳实践）：**

```bash
ffmpeg -i input.mp4 -c:v libx264 -crf 23 -maxrate 3000k -bufsize 6000k output.mp4
```

这种组合在保持 CRF 画质的同时，限制码率不超过某个值。适合上传到视频网站。

> 💡 提示：日常使用优先选 CRF。只有在平台明确要求特定码率时才用 CBR 或 VBR。

## 7.7 Tune 参数：场景调优

`-tune` 参数让编码器针对特定类型的内容做优化：

```bash
ffmpeg -i input.mp4 -c:v libx264 -crf 23 -tune film output.mp4
```

可用 tune 值：

| Tune 值 | 适用场景 | 优化内容 |
| --------- | --------- | --------- |
| film | 真人电影/视频 | 增强去块效应 |
| animation | 动画/卡通 | 优化大面积纯色区域 |
| grain | 保留胶片颗粒 | 保留画面颗粒感 |
| stillimage | 静态图片幻灯片 | 优化静态画面 |
| psnr | 客观指标测试 | 优化 PSNR 指标 |
| ssim | 客观指标测试 | 优化 SSIM 指标 |
| fastdecode | 低性能设备播放 | 降低解码复杂度 |
| zerolatency | 实时直播/视频会议 | 消除编码延迟 |

```bash
# 动画视频推荐
ffmpeg -i anime.mp4 -c:v libx264 -crf 20 -tune animation output.mp4

# 实时直播推流
ffmpeg -i input.mp4 -c:v libx264 -tune zerolatency -preset ultrafast rtmp://server/live/stream
```

## 7.8 音频转码

音频转码同样重要，主要控制参数有三个：

**采样率 `-ar`：**

```bash
# 将采样率设为 44100Hz（CD 音质）
ffmpeg -i input.mp4 -ar 44100 output.mp4
```

常见采样率：8000（电话）、22050（广播）、44100（CD）、48000（DVD/视频标准）

**声道数 `-ac`：**

```bash
# 转为立体声（双声道）
ffmpeg -i input.mp4 -ac 2 output.mp4

# 转为单声道
ffmpeg -i input.mp4 -ac 1 output.mp4
```

**音频码率 `-b:a`：**

```bash
# 音频码率设为 192kbps
ffmpeg -i input.mp4 -c:a aac -b:a 192k output.mp4
```

| 码率 | 音质描述 | 推荐场景 |
| ------ | --------- | --------- |
| 64k | 语音够用 | 播客/有声书 |
| 128k | 普通音质 | 日常听歌 |
| 192k | 良好音质 | 音乐收藏 |
| 256k | 高音质 | 发烧友 |
| 320k | 极高音质 | 最高 MP3 品质 |

**综合示例：**

```bash
ffmpeg -i input.mp4 -c:v libx264 -crf 23 -c:a aac -b:a 192k -ar 48000 -ac 2 output.mp4
```

## 7.9 两遍编码（Two-pass）

两遍编码是追求极致压缩效率时的选择。第一遍分析视频内容，第二遍根据分析结果进行编码，能在目标码率下获得最优画质。

```bash
# 第一遍：分析（不生成最终文件）
ffmpeg -i input.mp4 -c:v libx264 -b:v 2000k -pass 1 -an -f null NUL

# 第二遍：正式编码
ffmpeg -i input.mp4 -c:v libx264 -b:v 2000k -pass 2 -c:a aac -b:a 128k output.mp4
```

> ⚠️ 注意：Windows 上第一遍输出到 `NUL`（等价于丢弃），Linux/Mac 上则是 `/dev/null`。

第一遍会生成一个 `ffmpeg2pass-0.log` 日志文件，第二遍需要读取它。两遍完成后可以删除这个日志文件。

**什么时候需要两遍编码？**

- 需要精确控制输出文件大小时（比如必须小于 700MB 放进 CD）
- 对码率利用率要求极高时
- CRF 无法满足你的需求时

> 💡 提示：大多数情况下，CRF 一遍编码就够了，效果也很好。两遍编码主要是给需要精确码率控制的场景准备的。

## 7.10 批量转码脚本

当你有一堆文件需要转码时，手动一个个输入命令太痛苦了。以下是批量处理脚本：

**Windows Batch（.bat）：**

```bash
@echo off
for %%f in (*.avi) do (
    ffmpeg -i "%%f" -c:v libx264 -crf 23 -preset slow "output\%%~nf.mp4"
)
echo 全部转换完成！
pause
```

**PowerShell：**

```bash
$files = Get-ChildItem -Path "C:\Videos" -Filter "*.avi"
foreach ($file in $files) {
    $output = "C:\Videos\Output\$($file.BaseName).mp4"
    ffmpeg -i $file.FullName -c:v libx264 -crf 23 -preset slow $output
    Write-Host "已完成: $($file.Name)"
}
```

**Linux/Mac Bash：**

```bash
#!/bin/bash
mkdir -p output
for file in *.avi; do
    output="output/${file%.*}.mp4"
    ffmpeg -i "$file" -c:v libx264 -crf 23 -preset slow "$output"
    echo "已完成: $file"
done
echo "全部转换完成！"
```

> 💡 提示：批量处理时建议先用一两个文件测试参数，确认效果满意后再跑全部。否则等了一整夜发现参数不对，会很崩溃。

## 7.11 常见转码场景速查表

| 场景 | 命令 |
| ------ | ------ |
| AVI → MP4 | `ffmpeg -i input.avi -c:v libx264 -crf 23 output.mp4` |
| MOV → MP4 | `ffmpeg -i input.mov -c:v libx264 -crf 23 output.mp4` |
| MKV → MP4（秒转） | `ffmpeg -i input.mkv -c copy output.mp4` |
| MP4 → WebM | `ffmpeg -i input.mp4 -c:v libvpx-vp9 -crf 30 output.webm` |
| MP4 → GIF | `ffmpeg -i input.mp4 output.gif` |
| FLV → MP4 | `ffmpeg -i input.flv -c:v libx264 -crf 23 output.mp4` |
| TS → MP4 | `ffmpeg -i input.ts -c copy output.mp4` |
| MP4 → 压缩版 | `ffmpeg -i input.mp4 -c:v libx265 -crf 28 output.mp4` |
| WMV → MP4 | `ffmpeg -i input.wmv -c:v libx264 -crf 23 output.mp4` |
| 4K → 1080p | `ffmpeg -i input_4k.mp4 -vf scale=1920:1080 -c:v libx264 -crf 23 output.mp4` |

## 本章小结

- `-c copy` 是速度之王——只需换容器时必用
- CRF 是最推荐的质量控制模式，23 是万能默认值
- Preset 控制速度-质量平衡，`medium` 是默认值，`slow` 是质量优先的好选择
- 日常转码优先用 CRF，需要精确码率时才用两遍编码
- `-map` 参数可以精确控制哪些流被包含在输出中
