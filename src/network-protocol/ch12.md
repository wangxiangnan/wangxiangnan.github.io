## 12.1 端口的本质：传输层内的「子地址」

IP 地址解决了「数据送到哪台机器」的问题（第4章的主场），但一台机器上通常运行着多个网络应用——Web 服务器、数据库、SSH 守护进程……如果所有数据都送到同一个 IP 地址，操作系统怎么知道某个数据包应该交给哪个程序？

**端口（Port）**就是答案。它是一个 16 位的整数（0~65535），作为传输层内的「子地址」，标识一台机器上的具体应用程序。打个比方：IP 地址相当于小区的街道地址，端口号相当于房间号——快递送到「阳光小区 3 号楼」（IP），具体给主卧还是次卧（端口），还需要第二个标识。

你在 7.2 的 UDP 报头和 8.2 的 TCP 报头里都见过「源端口 + 目的端口」这对字段——它们就是这套寻址机制的载体。TCP 和 UDP 中端口的作用略有不同：

- **TCP 端口**：标识一个具体的服务或连接。同一台机器上可以同时存在多个 TCP 连接，每个连接由五元组唯一标识（细节见 12.4）。
- **UDP 端口**：标识一个接收数据报的套接字。UDP 无连接，同一端口可以接收来自任何源的数据报。

一个端口被 TCP 和 UDP 同时占用并不冲突——它们是两套独立的寻址空间，所以 DNS 才能同时在 TCP 53 和 UDP 53 上服务。

## 12.2 端口范围：知名端口、注册端口、动态端口

IANA（Internet Assigned Numbers Authority）把 65536 个端口分为三个范围。

**知名端口（Well-Known Ports，0-1023）**：分配给最核心的网络服务，通常需要 root/管理员权限才能绑定——这是历史遗留的安全设计：在多用户系统上，绑定低端口意味着「我有系统管理员授权」。

| 端口 | 协议 | 用途 |
| ------ | ------ | ------ |
| 20/21 | TCP | FTP（数据/控制） |
| 22 | TCP | SSH |
| 25 | TCP | SMTP（邮件发送） |
| 53 | UDP/TCP | DNS |
| 80 | TCP | HTTP |
| 110 | TCP | POP3（邮件接收） |
| 143 | TCP | IMAP（邮件接收） |
| 443 | TCP | HTTPS |
| 993 | TCP | IMAPS（加密 IMAP） |

**注册端口（Registered Ports，1024-49151）**：可被特定应用注册使用，如 3306（MySQL）、5432（PostgreSQL）、6379（Redis）、8080（HTTP 代理/备用 Web）、27017（MongoDB）。注册不是强制的——任何人都可以用这些端口，遵循约定只是为了避免冲突。

**动态/私有端口（Dynamic Ports，49152-65535）**：由操作系统自动分配给客户端的出站连接。你打开浏览器访问网站时，浏览器请求操作系统分配一个临时端口作为源端口；连接关闭后端口回收重用。

注意：各操作系统的动态端口范围并不一致。Linux 默认使用 32768-60999（`/proc/sys/net/ipv4/ip_local_port_range` 可调整），Windows 从 Vista 起遵循 IANA 建议使用 49152-65535。所以 tcpdump 里看到 4 万多甚至 5 万多的源端口都属于正常现象。

## 12.3 多路复用与多路分解：一个 IP 上跑多个服务

**多路复用（Multiplexing）**与**多路分解（Demultiplexing）**是传输层的核心功能：

- **多路复用**（发送端）：从多个应用程序收集数据，给每段加上带端口的报头，统一交给 IP 层发送。
- **多路分解**（接收端）：从 IP 层收到数据段后，根据报头中的端口信息，把数据交付给正确的应用程序。

两个方向的分解规则不一样，「先猜再读」第三问的答案就在这里：

- **UDP 多路分解**：按 `(目的端口)` 匹配 socket——无连接，源是谁不重要，发到这个端口就收。如果多个 UDP socket 用 `SO_REUSEPORT` 绑定同一端口，内核会选一个接收（常用于多进程负载分担）。
- **TCP 多路分解**：按 `(协议, 源IP, 源端口, 目的IP, 目的端口)` **五元组**精确匹配 socket。根源在于 TCP 有连接状态：内核必须区分「这条数据属于哪一条已建立的连接」，才能交给正确的接收缓冲区，维持 9.1 的按序交付。

## 12.4 五元组：一条连接的身份证

TCP 连接由**五元组（5-tuple）**唯一标识：

```
(协议, 源IP, 源端口, 目的IP, 目的端口)
```

例如同一台客户端（192.168.1.100）同时存在：

```
连接1: (TCP, 192.168.1.100, 49152, 93.184.216.34, 80)
连接2: (TCP, 192.168.1.100, 49153, 93.184.216.34, 80)
连接3: (TCP, 192.168.1.100, 49152, 172.217.14.206, 443)
```

连接 1 和连接 2 只有源端口不同——是两条独立连接；连接 1 和连接 3 目的不同——也是独立的。

这个设计直接回答了「先猜再读」的前两问：

- **服务器只有一个 80 端口，凭什么服务几千个连接？**——因为五元组里的源 IP 和源端口各不相同。每条连接的身份证都唯一，80 只是它们共同的目的端口。
- **两台电脑都用源端口 50000 访问同一个 443，会撞车吗？**——不会。源 IP 不同，五元组依然唯一。端口号只需要在「一台主机」内不重复，全局唯一性由 IP 地址补齐。

推论：浏览器对同一个服务器开 6 个并行连接下载资源，靠的就是 6 个不同的源端口——这也是 8.1 说的「一条连接一个字节流」模型的自然延伸：要并行，就多开连接。

## 12.5 端口扫描的原理与防御

**端口扫描**是探测一台主机开放了哪些服务的技术。安全评估里有正当用途（管理员检查自己的服务器），也是攻击者侦察的第一步——所以值得双向了解。

**四种常见扫描方式：**

1. **TCP Connect 扫描**：完整走三次握手（8.3）。连接成功→端口开放；收到 RST→关闭。简单可靠，但完整握手会在应用日志里留痕。
2. **SYN 扫描（半开扫描）**：只发 SYN，不完成握手。收到 SYN+ACK→开放（扫描方随即发 RST 挂断）；收到 RST→关闭。比 Connect 扫描隐蔽，应用层日志通常记不到未完成的连接。
3. **FIN 扫描**：发 FIN 报文。按 RFC 793，关闭的端口应回 RST，开放的端口不回复。可绕过只盯 SYN 的简单防火墙，但结果不如 SYN 扫描可靠。
4. **UDP 扫描**：向 UDP 端口发空报文。收到 ICMP「端口不可达」→关闭；收到应用响应→开放；什么都没有→可能是开放（也可能报文或 ICMP 被过滤了）。UDP 扫描慢，因为「无响应」需要等超时——这与 7.3 说的 UDP 不反馈对端状态一脉相承。

**防御措施：**

- **最小化开放端口**：只开必要的服务，其余全部关闭——最有效的一招。
- **防火墙规则**：用 `iptables`/`nftables` 限制敏感端口的访问来源。
- **端口敲门（Port Knocking）**：按特定顺序访问一组预设端口后，才临时打开目标端口。
- **入侵检测系统（IDS）**：识别异常模式（短时间内对大量端口的 SYN 请求）。
- **限速**：限制单个来源的新建连接速率。

```bash
# 示例：限制 SSH 端口的新连接速率为每分钟 3 次
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
    -m hashlimit --hashlimit-above 3/min --hashlimit-mode srcip \
    --hashlimit-name ssh_limit -j DROP
```

更系统的安全视角（防火墙体系、VPN、零信任）属于第22章的主场，本章只管「端口」这一层的攻防。

## 12.6 编程实践：用 Python 写一个简单的端口扫描器

```python
import socket
import threading
import time
from queue import Queue

class PortScanner:
    def __init__(self, target, timeout=1.0, max_threads=50):
        self.target = target
        self.timeout = timeout
        self.max_threads = max_threads
        self.open_ports = []
        self.lock = threading.Lock()
        self.queue = Queue()

    def scan_port(self, port):
        """扫描单个端口（TCP Connect 扫描）"""
        try:
            sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
            sock.settimeout(self.timeout)
            result = sock.connect_ex((self.target, port))
            if result == 0:
                with self.lock:
                    self.open_ports.append(port)
                    try:
                        service = socket.getservbyport(port)
                    except OSError:
                        service = "unknown"
                    print(f"  [开放] 端口 {port:>5} - {service}")
            sock.close()
        except (socket.timeout, socket.error):
            pass

    def worker(self):
        """线程工作函数"""
        while True:
            port = self.queue.get()
            self.scan_port(port)
            self.queue.task_done()

    def scan(self, start_port=1, end_port=1024):
        """扫描端口范围"""
        print(f"扫描目标: {self.target}")
        print(f"端口范围: {start_port}-{end_port}")
        print(f"超时: {self.timeout}s, 线程数: {self.max_threads}")
        print("-" * 50)

        start_time = time.perf_counter()

        for port in range(start_port, end_port + 1):
            self.queue.put(port)

        threads = []
        for _ in range(self.max_threads):
            t = threading.Thread(target=self.worker, daemon=True)
            t.start()
            threads.append(t)

        self.queue.join()

        elapsed = time.perf_counter() - start_time
        print("-" * 50)
        print(f"扫描完成！耗时: {elapsed:.2f} 秒")
        print(f"开放端口数: {len(self.open_ports)}")

        if self.open_ports:
            print(f"开放端口列表: {sorted(self.open_ports)}")

        return sorted(self.open_ports)

if __name__ == '__main__':
    # 扫描本地主机的前 1024 个端口
    # 注意：扫描他人主机可能违法，请仅扫描自己授权的主机
    scanner = PortScanner('127.0.0.1', timeout=0.5, max_threads=100)
    scanner.scan(start_port=1, end_port=1024)
```

要点：

- `connect_ex()` 返回 0 表示连接成功（端口开放），返回错误码表示失败——它不像 `connect()` 那样抛异常，适合扫描场景。
- 线程池 + 队列：100 个线程并行扫 100 个端口，比逐个扫描快两个数量级；加锁保护共享的 `open_ports` 列表。
- 想验证 12.5 的 SYN 扫描，可以用 `nmap -sS <目标>` 对比观察（需要 root，且同样只对授权目标使用）。

**安全提醒**：未经授权扫描他人主机在很多国家和地区属违法行为。请仅扫描自己拥有或获得书面授权的主机。

## 12.7 抓包实践：观察同一主机多个连接的端口分配

先建立 5 个并行连接，观察操作系统怎么分配源端口：

```python
import socket
import time

def observe_port_assignment():
    """同时建立多个连接，观察源端口分配"""
    sockets = []

    for i in range(5):
        sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        sock.connect(('93.184.216.34', 80))  # example.com
        local_addr = sock.getsockname()
        print(f"连接 {i+1}: 源端口={local_addr[1]}, 目的={sock.getpeername()}")
        sockets.append(sock)

    time.sleep(2)  # 保持连接以便抓包

    for sock in sockets:
        sock.close()

observe_port_assignment()
```

```
15:30:01.003 IP 192.168.1.100.54322 > 93.184.216.34.80: Flags [S], seq 2001
15:30:01.005 IP 192.168.1.100.54323 > 93.184.216.34.80: Flags [S], seq 3001
15:30:01.007 IP 192.168.1.100.54324 > 93.184.216.34.80: Flags [S], seq 4001
15:30:01.009 IP 192.168.1.100.54325 > 93.184.216.34.80: Flags [S], seq 5001
```

**关键观察：**

1. **源端口递增**：Linux 内核从 `ip_local_port_range` 中按序分配（54321~54325），不是随机散布——这也是同一浏览器短时间内发出的连接源端口往往相邻的原因。
2. **五元组唯一性**：5 个连接的 `(协议, 源IP, 目的IP, 目的端口)` 全部相同，仅源端口不同——源端口是区分同一对主机间多条连接的唯一变量。
3. **端口回收**：连接关闭后源端口进入 TIME_WAIT（8.6），在 `ss -tan state time-wait` 里可见；倒计时结束后才能被新连接重用——动态端口在大量短连接场景下也会「用紧」。

```bash
# 查看当前所有 TCP 连接及其端口
ss -tan state established
ss -tan state time-wait
```

这就是多路复用在实际工作的样子：五个独立连接共享同一个 IP，靠不同的源端口和谐共存。传输层像一个精密的邮件分拣中心——每个包裹进来，看一眼端口号，就准确送到正确的应用程序手中。

## 本章小结

- 端口是 16 位传输层「子地址」：IP 找到机器，端口找到进程；TCP/UDP 各有一套独立的端口空间。
- 三类端口：0-1023 知名（root 才能绑定）、1024-49151 注册（约定俗成）、49152+ 动态（Linux 实际用 32768-60999）。
- 复用是发送端把多个应用的数据合流发出，分解是接收端按端口分发——端口是分发的唯一依据。
- TCP 按五元组精确匹配 socket（因为有连接状态要区分），UDP 只按目的端口（无连接、源不重要）。
- 一个 80 端口能服务几千连接：五元组不同即不同连接；源端口号只需在单机内唯一，全局唯一性由 IP 补齐。
- 扫描四式各有取舍：Connect 可靠但留痕、SYN 半开隐蔽、FIN 钻防火墙空子、UDP 慢且结果模糊。
- 防御三板斧：最小化开放端口、防火墙限速规则、IDS 异常检测——最有效的永远是「少开服务」。
- 动态端口回收要等 TIME_WAIT 结束（8.6），海量短连接场景下端口是会被「用紧」的资源。
