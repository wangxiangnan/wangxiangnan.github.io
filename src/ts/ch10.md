# 第十章：模块系统与声明文件

## ES Module

现代 TypeScript 项目通常使用 ES Module：

```ts
// math.ts
export function add(a: number, b: number): number {
  return a + b;
}

export const PI = 3.14;
```

```ts
// main.ts
import { add, PI } from "./math";

console.log(add(1, 2), PI);
```

## CommonJS

Node.js 传统项目使用 CommonJS：

```ts
// math.ts
export = {
  add,
  PI,
};
```

```ts
// main.ts
import math = require("./math");
console.log(math.add(1, 2));
```

现代项目建议统一用 ES Module。

## 重新导出

```ts
export * from "./user";
export { default as UserCard } from "./UserCard";
```

## 类型导入导出

从 TypeScript 3.8 开始，可以显式导入导出类型：

```ts
import type { User } from "./types";
export type { User };
```

这在 `isolatedModules` 模式下非常有用，可以避免把类型误当作值导出。

## 声明文件 .d.ts

当你使用没有 TypeScript 类型的 JavaScript 库时，需要写声明文件：

```ts
// lodash.d.ts
declare function cloneDeep<T>(value: T): T;
export = cloneDeep;
```

更常见的是通过 `@types/lodash` 这样的包获取社区维护的类型声明。

## 包的类型入口

库发布后，`package.json` 要告诉消费方两件事：**运行时入口在哪**，**类型入口在哪**：

```json
{
  "name": "my-lib",
  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    }
  }
}
```

各字段的用途：

- `name`：包名，消费方 `import` 时使用的名字。
- `main`：**CommonJS（CJS）入口**。Node.js 中 `require("my-lib")` 加载的就是这个文件。
- `module`：**ES Module（ESM）入口**。注意 Node.js 本身并不认识这个字段，它主要是给打包工具（Vite、webpack、Rollup）看的——打包时优先取 ESM 版本，才能做 tree-shaking。真正供 Node.js 加载的 ESM 入口要靠 `exports` 里的 `import` 条件。
- `types`：类型声明入口，TypeScript 据此提供类型提示。
- `exports`：现代规范（Node 12+），按"消费方式"分发不同入口：`require` 条件走 CJS 文件，`import` 条件走 ESM 文件。其中的 `types` 条件要放在最前面，让解析器优先读取类型声明。

两套字段的关系：`main` / `module` / `types` 是"一个入口，消费者各取所需"的老方案；`exports` 是"一个入口，按条件分发"的新方案，优先级更高——一旦设置了 `exports`，Node 和现代打包工具只会解析它列出的路径，`main` / `module` 就退化为给老工具兜底的角色。

### exports 的完整条件

条件是一个约定俗成的名字，解析器根据自己的环境和加载方式挑选**第一个命中**的条件。常用条件：

| 条件 | 含义 | 谁会命中 |
| --- | --- | --- |
| `types` | 类型声明入口 | TypeScript |
| `import` | ESM 方式加载（`import` 语句、动态 `import()`） | Node.js、打包工具 |
| `require` | CJS 方式加载（`require()`） | Node.js、打包工具 |
| `default` | 兜底分支，前面的条件都没命中时使用 | 所有解析器 |
| `node` | Node.js 运行环境 | Node.js |
| `browser` | 浏览器运行环境 | 打包工具按构建目标判断 |
| `development` | 开发模式构建 | 打包工具按 mode 注入 |
| `production` | 生产模式构建 | 打包工具按 mode 注入 |

几个要点：

- **匹配按书写顺序进行**，第一个命中的生效。所以 `types` 永远放最前，`default` 永远放最后。
- `development` / `production` 由消费方决定：Node 默认**不**启用这两个条件；webpack、Vite 等打包工具会根据构建模式注入。典型用法是开发版带调试警告、生产版精简：

```json
{
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "development": "./dist/index.dev.mjs",
      "production": "./dist/index.min.mjs",
      "default": "./dist/index.mjs"
    }
  }
}
```

- 可以定义**自定义条件**，名字任意，由消费方显式开启。比如用 `node --conditions my-app index.js` 启动时会命中 `my-app` 条件：

```json
{
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "my-app": "./dist/debug.mjs",
      "default": "./dist/index.mjs"
    }
  }
}
```

React 的 `react-server` 条件就是这个机制：RSC 环境开启后，`import { useState } from "react"` 会解析到服务端专用实现。

- 支持 `*` 通配符做子路径映射：

```json
{
  "exports": {
    ".": "./dist/index.mjs",
    "./utils": "./dist/utils.mjs",
    "./features/*": "./dist/features/*.mjs",
    "./package.json": "./package.json"
  }
}
```

`import { helper } from "my-lib/features/date"` 会解析到 `./dist/features/date.mjs`。把 `./package.json` 列出来，是允许用户读到版本号等元信息。

- **`exports` 同时是一份封装清单**：没有列出的子路径一律禁止访问，`import "my-lib/src/internal"` 会直接报错，哪怕文件真实存在。这解决了 `main` 时代"包内部文件全部裸露、用户可以深挖到任意路径"的问题——想让用户访问的路径，必须显式列出。

### 其他与包解析、发布相关的字段

- `type`：决定裸 `.js` 文件按什么模块格式解析，取值 `"module"`（ESM）或 `"commonjs"`（默认）。`.mjs` 和 `.cjs` 扩展名永远优先于这个字段。第十一章的 `module: "NodeNext"` 会读取它来自动判断输出形式。

- `types` / `typings`：同义字段，`typings` 是老名字，现在统一写 `types`。

- `browser`：给打包工具的浏览器专用入口，浏览器构建目标下优先级为 `browser` > `module` > `main`。对象形式还能按文件做替换：

  ```json
  {
    "browser": {
      "./node-only.js": "./browser-shim.js"
    }
  }
  ```

  当代码 import `./node-only.js` 时，浏览器构建会换成 `./browser-shim.js`。

- `sideEffects`：tree-shaking 提示。`false` 声明"所有文件都没有副作用，没被用到的导出可以放心删"；也可以列出**有**副作用的文件（如 CSS），让打包工具跳过它们：

  ```json
  {
    "sideEffects": ["*.css", "./dist/polyfill.mjs"]
  }
  ```

- `files`：发布到 npm 时包含哪些文件（`package.json`、`README` 等始终包含）。不设置时整个目录都会发上去，通常用它收敛包体积：

  ```json
  {
    "files": ["dist"]
  }
  ```

- `imports`：包**内部**的子路径导入，键以 `#` 开头，只能在包自己的代码里使用，外部无法 import。适合在包内做环境分支，同时不暴露内部结构：

  ```json
  {
    "imports": {
      "#config": {
        "node": "./dist/config.node.mjs",
        "default": "./dist/config.default.mjs"
      }
    }
  }
  ```

  ```ts
  import config from "#config"; // 包内代码中使用
  ```

- `engines`：声明运行环境要求，npm 安装时会给出警告（默认不强制，除非用户开启 `engine-strict`）：

  ```json
  {
    "engines": { "node": ">=18" }
  }
  ```

## declare 关键字

`declare` 用于告诉 TypeScript："这个名字已经存在了，你相信我，不用检查它的实现"。

```ts
declare const API_BASE_URL: string;
declare function log(message: string): void;
declare module "legacy-lib" {
  export function init(): void;
}
```

`declare` 在写类型声明文件、扩展第三方库类型时非常常用。
