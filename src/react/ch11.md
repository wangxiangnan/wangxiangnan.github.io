# 第11章：Context — 跨级传数据的秘密武器

![第11章封面](./images/ch11.png)

## 引言：Props Drilling 的噩梦

想象一下这个场景：你住在一栋 10 层楼的公寓里，你住 1 楼，你朋友住 10 楼。你想给他送一本书，但公寓的规矩是——你只能交给下一层的邻居，邻居再交给下一层的邻居……就这样一本《JavaScript 高级程序设计》从 1 楼传到 2 楼、2 楼传到 3 楼……最终传到了 10 楼。

问题是：2 楼到 9 楼的邻居根本不在乎这本书啊！他们只是被迫当了"快递员"。

这个场景在 React 中有一个专业名字——**Props Drilling**（属性钻洞）。当你需要把数据从顶层组件传递到深层子组件时，中间的每一层组件都不得不接收并转发这些 props，即使它们根本不需要这些数据。

```jsx
// Props Drilling 的噩梦示例
function App() {
  const [user, setUser] = useState({ name: '张三', avatar: '...' });
  return <Layout user={user} setUser={setUser} />; // Layout 不需要 user
}

function Layout({ user, setUser }) {
  return <Sidebar user={user} setUser={setUser} />; // Sidebar 不需要 user
}

function Sidebar({ user, setUser }) {
  return <UserProfile user={user} setUser={setUser} />; // 终于到了需要的地方！
}

function UserProfile({ user, setUser }) {
  // 这才是真正需要 user 数据的组件
  return <h1>你好，{user.name}</h1>;
}
```

看到了吗？`Layout` 和 `Sidebar` 只是无辜的中间人，它们被迫接收和传递自己不需要的 props。如果嵌套更深（5层、10层），代码会变得极其臃肿和难以维护。

**Context 就是来解决这个问题的！**

> **比喻时间**：Context 就像小区的广播系统。物业（Provider）通过广播发布一条消息（数据），所有住户（组件）只要打开收音机（useContext），就能直接收到这条消息——不需要挨家挨户敲门（Props Drilling）。2 楼到 9 楼的邻居终于可以安心看自己的电视了！

---

## 11.1 Context API 的核心思想

Context 的工作流程分为三步：

1. **创建 Context**：定义要广播的"频道"
2. **提供数据（Provider）**：在某个组件中"广播"数据
3. **消费数据（useContext）**：在任意子组件中"收听"数据

整个过程就像电台广播：先有一个电台频率（createContext），然后电台开始播放节目（Provider），最后你用收音机调到这个频率就能收听了（useContext）。

---

## 11.2 基础用法：createContext + Provider + useContext

让我们从一个最简单的例子开始：

```jsx
import { createContext, useContext } from 'react';

// 第一步：创建 Context（定义"频道"）
// 参数是默认值，当组件不在 Provider 内时使用
const ThemeContext = createContext('light');

// 提供数据的组件（"广播电台"）
function App() {
  return (
    // Provider 是"广播站"，value 是广播的内容
    <ThemeContext.Provider value="dark">
      <Layout />
    </ThemeContext.Provider>
  );
}

function Layout() {
  // Layout 不需要接收任何 theme 相关的 props！
  return <Toolbar />;
}

function Toolbar() {
  // Toolbar 也不需要！
  return <ThemedButton />;
}

// 消费数据的组件（"收音机"）
function ThemedButton() {
  // useContext 直接从最近的 Provider 获取数据
  // 不管中间隔了多少层组件！
  const theme = useContext(ThemeContext);
  
  return (
    <button style={{
      background: theme === 'dark' ? '#333' : '#fff',
      color: theme === 'dark' ? '#fff' : '#333',
      padding: '12px 24px',
      border: 'none',
      borderRadius: '4px',
      cursor: 'pointer'
    }}>
      当前主题：{theme}
    </button>
  );
}

export default App;
```

看到魔法了吗？`ThemedButton` 距离 `App` 隔了好几层组件，但它通过 `useContext` 直接获取了 theme 数据，中间的 `Layout` 和 `Toolbar` 完全不需要知道 theme 的存在！

> **Tip**：`createContext` 的参数是默认值。只有当组件不在任何对应的 Provider 内部时，才会使用这个默认值。这在测试和组件独立开发时非常有用。

## 11.3 完整实战：主题切换系统

上面的例子只能显示静态主题，让我们做一个可以动态切换的亮色/暗色主题系统：

```jsx
// src/contexts/ThemeContext.jsx
import { createContext, useContext, useState } from 'react';

// 创建主题 Context
const ThemeContext = createContext(null);

// 主题配置对象
const themes = {
  light: {
    background: '#ffffff',
    text: '#333333',
    primary: '#007bff',
    secondary: '#6c757d',
    border: '#e0e0e0',
    cardBg: '#f8f9fa',
  },
  dark: {
    background: '#1a1a2e',
    text: '#e0e0e0',
    primary: '#4da6ff',
    secondary: '#adb5bd',
    border: '#333355',
    cardBg: '#16213e',
  },
};

// 自定义 Provider 组件 —— 封装主题逻辑
export function ThemeProvider({ children }) {
  const [themeName, setThemeName] = useState('light');

  // 切换主题的函数
  const toggleTheme = () => {
    setThemeName(prev => prev === 'light' ? 'dark' : 'light');
  };

  // 提供给子组件的值：当前主题样式 + 切换函数
  const value = {
    theme: themes[themeName],
    themeName,
    toggleTheme,
  };

  return (
    <ThemeContext.Provider value={value}>
      {children}
    </ThemeContext.Provider>
  );
}

// 自定义 Hook —— 简化 useContext 的使用
// 这样其他组件只需要调用 useTheme() 就行了
export function useTheme() {
  const context = useContext(ThemeContext);
  if (context === null) {
    throw new Error('useTheme 必须在 ThemeProvider 内部使用');
  }
  return context;
}
```

```jsx
// src/App.jsx
import { ThemeProvider, useTheme } from './contexts/ThemeContext';

// 主题切换按钮
function ThemeToggle() {
  const { themeName, toggleTheme } = useTheme();
  
  return (
    <button 
      onClick={toggleTheme}
      style={{
        padding: '8px 16px',
        borderRadius: '20px',
        border: 'none',
        cursor: 'pointer',
        fontSize: '16px',
      }}
    >
      {themeName === 'light' ? '🌙 暗色模式' : '☀️ 亮色模式'}
    </button>
  );
}

// 卡片组件 —— 自动适配当前主题
function Card({ title, content }) {
  const { theme } = useTheme();
  
  return (
    <div style={{
      background: theme.cardBg,
      border: `1px solid ${theme.border}`,
      borderRadius: '8px',
      padding: '16px',
      marginBottom: '16px',
    }}>
      <h3 style={{ color: theme.primary, margin: '0 0 8px 0' }}>{title}</h3>
      <p style={{ color: theme.text, margin: 0 }}>{content}</p>
    </div>
  );
}

// 导航栏 —— 自动适配当前主题
function Navbar() {
  const { theme } = useTheme();
  
  return (
    <nav style={{
      background: theme.background,
      borderBottom: `1px solid ${theme.border}`,
      padding: '12px 24px',
      display: 'flex',
      justifyContent: 'space-between',
      alignItems: 'center',
    }}>
      <h2 style={{ color: theme.primary, margin: 0 }}>🎨 主题切换 Demo</h2>
      <ThemeToggle />
    </nav>
  );
}

// 主内容区域
function Content() {
  const { theme } = useTheme();
  
  return (
    <main style={{ 
      padding: '24px', 
      background: theme.background,
      minHeight: '100vh',
    }}>
      <h1 style={{ color: theme.text }}>Hello, Context!</h1>
      <p style={{ color: theme.secondary }}>
        点击上面的按钮切换亮色/暗色主题，所有组件都会自动更新！
      </p>
      <Card title="什么是 Context？" content="Context 是 React 提供的跨组件传递数据的机制。" />
      <Card title="什么时候用？" content="当你发现 Props Drilling 太深的时候，就是 Context 登场的时机。" />
      <Card title="注意事项" content="Context 不适合频繁变化的数据，可能导致不必要的重新渲染。" />
    </main>
  );
}

// App 组件 —— 用 ThemeProvider 包裹
function App() {
  return (
    <ThemeProvider>
      <Navbar />
      <Content />
    </ThemeProvider>
  );
}

export default App;
```

**关键设计模式：**

1. **自定义 Provider 组件**：把 Context 的创建和逻辑封装在一个组件中，外部只需要 `<ThemeProvider>` 包裹就行。
2. **自定义 Hook**：`useTheme()` 封装了 `useContext(ThemeContext)` 并添加了错误检查。
3. **主题配置对象**：把样式值集中在一个对象中管理，切换主题就是切换整个对象。

> **Warning**：初学者常犯的错误是把 `createContext` 和 `useContext` 搞混。记住：`createContext` 只调用一次（创建频道），`useContext` 在每个需要数据的组件中调用（收听广播）。

## 11.4 用户认证 Context

另一个非常适合 Context 的场景是**用户认证状态管理**。登录状态几乎是所有组件都可能需要访问的：

```jsx
// src/contexts/AuthContext.jsx
import { createContext, useContext, useState } from 'react';

// 创建认证 Context
const AuthContext = createContext(null);

// 模拟的用户数据库
const fakeUsers = [
  { id: 1, name: '张三', email: 'zhangsan@example.com', avatar: '👨' },
  { id: 2, name: '李四', email: 'lisi@example.com', avatar: '👩' },
];

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null); // null 表示未登录

  // 登录
  const login = (email, password) => {
    // 模拟验证（实际项目中应该调用 API）
    const foundUser = fakeUsers.find(u => u.email === email);
    if (foundUser && password === '123456') {
      setUser(foundUser);
      return { success: true };
    }
    return { success: false, message: '邮箱或密码错误' };
  };

  // 登出
  const logout = () => {
    setUser(null);
  };

  const value = {
    user,           // 当前登录用户（null 表示未登录）
    isLoggedIn: !!user, // 是否已登录的布尔值
    login,          // 登录函数
    logout,         // 登出函数
  };

  return (
    <AuthContext.Provider value={value}>
      {children}
    </AuthContext.Provider>
  );
}

// 自定义 Hook
export function useAuth() {
  const context = useContext(AuthContext);
  if (context === null) {
    throw new Error('useAuth 必须在 AuthProvider 内部使用');
  }
  return context;
}
```

```jsx
// src/App.jsx
import { AuthProvider, useAuth } from './contexts/AuthContext';
import { useState } from 'react';

// 登录表单
function LoginForm() {
  const { login } = useAuth();
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const [error, setError] = useState('');

  const handleSubmit = (e) => {
    e.preventDefault();
    const result = login(email, password);
    if (!result.success) {
      setError(result.message);
    }
  };

  return (
    <div style={{ maxWidth: '400px', margin: '48px auto', padding: '24px', border: '1px solid #ddd', borderRadius: '8px' }}>
      <h2>登录</h2>
      {error && <p style={{ color: 'red' }}>{error}</p>}
      <form onSubmit={handleSubmit}>
        <div style={{ marginBottom: '12px' }}>
          <label>邮箱：</label>
          <input 
            type="email" 
            value={email} 
            onChange={(e) => setEmail(e.target.value)}
            placeholder="zhangsan@example.com"
            style={{ width: '100%', padding: '8px' }}
          />
        </div>
        <div style={{ marginBottom: '12px' }}>
          <label>密码：</label>
          <input 
            type="password" 
            value={password} 
            onChange={(e) => setPassword(e.target.value)}
            placeholder="123456"
            style={{ width: '100%', padding: '8px' }}
          />
        </div>
        <button type="submit" style={{ padding: '10px 24px' }}>登录</button>
      </form>
      <p style={{ color: '#999', fontSize: '12px' }}>
        测试账号：zhangsan@example.com / 123456
      </p>
    </div>
  );
}

// 用户信息面板（深层组件，直接使用 useAuth 获取登录状态）
function UserPanel() {
  const { user, isLoggedIn, logout } = useAuth();

  if (!isLoggedIn) {
    return <LoginForm />;
  }

  return (
    <div style={{ maxWidth: '400px', margin: '48px auto', padding: '24px', border: '1px solid #ddd', borderRadius: '8px' }}>
      <div style={{ textAlign: 'center' }}>
        <div style={{ fontSize: '48px' }}>{user.avatar}</div>
        <h2>{user.name}</h2>
        <p style={{ color: '#666' }}>{user.email}</p>
        <button 
          onClick={logout} 
          style={{ padding: '10px 24px', background: '#dc3545', color: '#fff', border: 'none', borderRadius: '4px', cursor: 'pointer' }}
        >
          登出
        </button>
      </div>
    </div>
  );
}

// 导航栏 —— 也使用 useAuth 显示登录状态
function AuthNavbar() {
  const { user, isLoggedIn } = useAuth();

  return (
    <nav style={{ background: '#333', color: '#fff', padding: '12px 24px', display: 'flex', justifyContent: 'space-between' }}>
      <span>我的应用</span>
      <span>
        {isLoggedIn ? `你好，${user.name} 👋` : '未登录'}
      </span>
    </nav>
  );
}

// 主应用
function App() {
  return (
    <AuthProvider>
      <AuthNavbar />
      <UserPanel />
    </AuthProvider>
  );
}

export default App;
```

## 11.5 组合多个 Context

在真实项目中，你通常会有多个 Context。它们可以像俄罗斯套娃一样嵌套使用：

```jsx
import { ThemeProvider } from './contexts/ThemeContext';
import { AuthProvider } from './contexts/AuthContext';

function App() {
  return (
    <ThemeProvider>
      <AuthProvider>
        {/* 你的应用组件 */}
        <YourApp />
      </AuthProvider>
    </ThemeProvider>
  );
}
```

如果嵌套太多层，可以写一个工具函数来简化：

```jsx
// 组合多个 Provider 的工具函数
function composeProviders(...providers) {
  return ({ children }) => {
    return providers.reduceRight((acc, Provider) => {
      return <Provider>{acc}</Provider>;
    }, children);
  };
}

// 使用
const AppProviders = composeProviders(ThemeProvider, AuthProvider);

function App() {
  return (
    <AppProviders>
      <YourApp />
    </AppProviders>
  );
}
```

## 11.6 Context 的局限性

Context 虽然好用，但并不是万能的。它有一些需要注意的局限性：

### 1. 不必要的重新渲染

当 Provider 的 value 改变时，**所有**使用这个 Context 的组件都会重新渲染，即使它们只用了 value 中的某个字段而其他字段没变。

```jsx
// 问题示例：theme 和 toggleTheme 在一个对象中
// 即使 theme 没变，toggleTheme 的引用变了也会导致所有消费者重新渲染
<ThemeContext.Provider value={{ theme, toggleTheme }}>
  ...
</ThemeContext.Provider>

// 解决方案：拆分成多个小 Context
<ThemeContext.Provider value={theme}>
  <ThemeActionsContext.Provider value={toggleTheme}>
    ...
  </ThemeActionsContext.Provider>
</ThemeContext.Provider>
```

### 2. 不适合高频变化的数据

如果你的数据每秒变化很多次（比如鼠标位置、动画进度），Context 不是好选择。每次变化都会触发所有消费者重新渲染，性能会急剧下降。

### 3. 增加测试复杂度

被 Provider 包裹的组件在测试时需要额外提供 Provider，否则会报错。

## 11.7 什么时候该用 Context？什么时候不该？

### ✅ 适合用 Context 的场景

| 场景 | 原因 |
|------|------|
| 主题（亮色/暗色） | 全局状态，很多组件需要，变化不频繁 |
| 用户认证状态 | 全局状态，导航栏/页面守卫等多处需要 |
| 国际化（语言切换） | 全局状态，所有文本组件都需要 |
| 全局配置 | 如 API 地址、功能开关等 |

### ❌ 不适合用 Context 的场景

| 场景 | 更好的方案 |
|------|-----------|
| 父子组件间的数据传递 | 直接用 Props |
| 高频变化的数据（鼠标位置） | useRef 或状态管理库 |
| 复杂的跨组件状态 | Redux、Zustand 等状态管理库 |
| 只有一两个组件需要的数据 | useState 就够了 |

> **经验法则**：如果你发现自己在连续 3 层以上的组件中传递同一个 props，那就是 Context 该出手的时候了。如果只是 1-2 层，老实实用 Props 就好，不要过度设计。

## 本章小结

| 概念 | 作用 | 比喻 |
|------|------|------|
| createContext | 创建一个 Context "频道" | 开一个新的广播频率 |
| Provider | 在组件树中广播数据 | 广播电台发射信号 |
| useContext | 在组件中接收广播数据 | 用收音机收听广播 |
| 自定义 Hook 封装 | 简化 useContext 的使用 | 预设好频道号的智能收音机 |

**核心要点回顾：**

1. Context 解决了 Props Drilling 问题，让数据可以"跳级"传递
2. 最佳实践：自定义 Provider + 自定义 Hook 封装
3. Context 适合"全局的、变化不频繁的"数据
4. 不要滥用 Context，简单的 Props 传递有时候更好
5. 多个 Context 可以组合使用
