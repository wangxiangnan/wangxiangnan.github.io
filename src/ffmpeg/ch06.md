# 第6章：容器格式——文件的"包装盒"

> 你可能遇到过这样的困惑：为什么同样是 H.264 编码的视频，有的是 .mp4，有的是 .mkv，有的是 .mov？它们有什么区别？为什么有些视频播放器放不了某些格式？这一切的答案，都在"容器格式"这个概念里。

## 6.1 最容易混淆的概念：容器 ≠ 编解码器

这是新手最容易搞混的概念，我们先把它彻底说清楚。

**用一个比喻来说明：**

想象你要寄一封信。信的内容是你写的文字（这相当于"编解码器"编码后的视频/音频数据），而信封（这相当于"容器格式"）负责把信封装好，写上报文地址，保护信件在运输过程中不受损。

关键点是：**同一个信封可以装不同类型的信（不同的编码格式），同一封信也可以装进不同的信封里**。

```
容器（信封）        编解码器（信的内容）
MP4    ← 可装入 →  H.264, H.265, AAC, MP3 ...
MKV    ← 可装入 →  H.264, H.265, VP9, AV1, AAC, FLAC, SRT字幕 ...
WebM   ← 可装入 →  VP8, VP9, AV1, Opus, Vorbis
```

具体来说：

- **编解码器（Codec）**：负责"如何压缩和解压数据"。比如 H.264 编码器把原始画面压缩成紧凑的数据流。
- **容器（Container）**：负责"如何组织和封装数据"。它把视频流、音频流、字幕流打包在一起，加上索引、元数据、时间戳等信息。

文件扩展名（.mp4、.mkv、.avi）代表的是容器格式，而不是编码格式。一个 .mp4 文件里面的视频可能是 H.264 编码，也可能是 H.265 编码——扩展名只能告诉你容器是什么，不能告诉你里面用了什么编码。

这就是为什么你需要 ffprobe 来查看文件内部到底用了什么编码。

## 6.2 容器的作用

一个容器文件通常包含以下内容：

```
┌─────────────────────────────────────────┐
│              容器格式（如 MP4）           │
│                                         │
│  ┌─────────────┐  ┌─────────────────┐  │
│  │  视频流      │  │  音频流          │  │
│  │ (H.264编码)  │  │ (AAC编码)       │  │
│  └─────────────┘  └─────────────────┘  │
│                                         │
│  ┌─────────────┐  ┌─────────────────┐  │
│  │  字幕流      │  │  元数据          │  │
│  │ (SRT/ASS)    │  │ (标题、作者等)   │  │
│  └─────────────┘  └─────────────────┘  │
│                                         │
│  索引信息（用于快速跳转/Seek）            │
│  时间戳（同步音视频播放）                │
└─────────────────────────────────────────┘
```

容器的核心职责：

1. **封装**：把多条流（视频、音频、字幕）打包进一个文件
2. **同步**：通过时间戳确保音视频同步播放
3. **索引**：提供关键帧索引，支持快速跳转（Seek）
4. **元数据**：存储标题、作者、封面图片等信息

## 6.3 常见容器详解

**MP4（MPEG-4 Part 14）**

- **扩展名**：.mp4, .m4v, .m4a
- **诞生年份**：2001 年（基于 Apple 的 QuickTime 格式）
- **优势**：兼容性最好，几乎所有设备、浏览器、平台都支持
- **劣势**：不支持所有编码格式（比如不支持 VP9、不支持 FLAC 音频），不支持部分字幕格式
- **支持的编码**：
  - 视频：H.264, H.265, MPEG-4, AV1（较新标准）
  - 音频：AAC, MP3, AC3, Opus
  - 字幕：tx3g（不支持 SRT/ASS 内嵌）
- **适用场景**：几乎所有通用场景，Web 视频，移动设备

```bash
# 生成兼容性最好的 MP4（H.264 + AAC）
ffmpeg -i input.mkv -c:v libx264 -c:a aac -movflags +faststart output.mp4
```

> **`-movflags +faststart` 是什么？** 默认情况下，MP4 的索引信息（moov atom）放在文件末尾。这意味着在线播放时必须下载完整个文件才能开始播放。加上 `+faststart` 后，FFmpeg 会把索引信息移到文件开头，使视频可以"边下边播"。这对网页视频来说非常重要。

**MKV（Matroska）**

- **扩展名**：.mkv, .mka（纯音频）, .mks（纯字幕）
- **诞生年份**：2002 年（开源项目）
- **优势**：万能容器，几乎支持所有编解码器；支持多音轨、多字幕、章节信息
- **劣势**：部分设备和平台不支持（如 iPhone 原生不支持、部分智能电视不支持）
- **支持的编码**：几乎所有（H.264, H.265, VP9, AV1, AAC, FLAC, DTS, TrueHD, PGS字幕、SRT、ASS 等）
- **适用场景**：高质量视频存储、多音轨电影、动漫字幕组发布

```bash
# MKV 可以装下任何编码，非常灵活
ffmpeg -i input.mp4 -c:v libx265 -c:a flac output.mkv
ffmpeg -i input.mp4 -c copy -c:s copy output.mkv   # 连字幕也一起复制
```

**AVI（Audio Video Interleave）**

- **扩展名**：.avi
- **诞生年份**：1992 年（Microsoft 创建）
- **优势**：历史悠久，老旧系统兼容性好
- **劣势**：
  - 不支持现代编码（H.265、VP9 等）
  - 不支持可变帧率（VFR）
  - 不支持流式传输（没有内置索引机制，文件损坏后难以恢复）
  - 不支持 B 帧的正确时间戳
  - 字幕支持极差
- **适用场景**：几乎不推荐使用，除非你需要兼容非常老旧的系统

```bash
# 如果实在需要 AVI 格式
ffmpeg -i input.mp4 -c:v mpeg4 -c:a mp3 output.avi
```

**MOV（QuickTime Movie）**

- **扩展名**：.mov
- **诞生年份**：1998 年（Apple 创建）
- **优势**：Apple 生态的原生格式，支持 ProRes 等专业编码
- **劣势**：在非 Apple 平台上兼容性不如 MP4
- **支持的编码**：H.264, H.265, ProRes, DNxHD 等
- **适用场景**：Apple 设备、专业视频编辑（Final Cut Pro）

```bash
# MOV 和 MP4 的内部结构非常相似（都基于 ISO BMFF）
ffmpeg -i input.mp4 -c copy output.mov
```

> **有趣的事实**：MP4 格式实际上是基于 Apple 的 QuickTime（MOV）格式发展而来的。两者在底层结构上非常相似，这就是为什么 MP4 和 MOV 之间经常可以用 `-c copy` 无损转换。

**FLV（Flash Video）**

- **扩展名**：.flv
- **诞生年份**：2002 年（Macromedia/Adobe）
- **优势**：曾经是互联网视频的标准格式（Flash 播放器时代）
- **劣势**：Flash 已被淘汰（2020 年底 Adobe 停止支持），不支持 H.265，现代浏览器不再原生支持
- **适用场景**：老式直播系统（RTMP 推流仍在使用 FLV），遗留系统维护

```bash
# RTMP 推流时使用 FLV 封装（现在仍在使用）
ffmpeg -i input.mp4 -c:v libx264 -c:a aac -f flv rtmp://server/live/stream
```

**TS（MPEG Transport Stream）**

- **扩展名**：.ts, .m2ts
- **诞生年份**：1990 年代
- **优势**：专为不可靠传输设计（数字电视广播），每个数据包很小（188 字节），即使丢失部分数据也能继续播放
- **劣势**：文件体积较大（因为大量冗余的包头信息），不适合本地存储
- **适用场景**：HLS 流媒体（将视频切成很多 .ts 小片段）、数字电视广播、蓝光光盘

```bash
# 将视频转换为 TS 格式
ffmpeg -i input.mp4 -c copy -bsf:v h264_mp4toannexb output.ts

# 生成 HLS 流（自动切成 .ts 分片 + 生成 .m3u8 播放列表）
ffmpeg -i input.mp4 -c:v libx264 -c:a aac \
  -hls_time 10 \
  -hls_playlist_type vod \
  -hls_segment_filename "segment_%03d.ts" \
  playlist.m3u8
```

**WebM**

- **扩展名**：.webm
- **诞生年份**：2010 年（Google 创建）
- **优势**：完全开源免费，专为 Web 设计，所有现代浏览器支持
- **劣势**：支持的编码格式有限，Apple 原生支持较弱
- **支持的编码**：
  - 视频：VP8, VP9, AV1
  - 音频：Opus, Vorbis
- **适用场景**：网页视频、HTML5 `<video>` 标签

```bash
# 标准 WebM（VP9 + Opus）
ffmpeg -i input.mp4 -c:v libvpx-vp9 -crf 30 -b:v 0 -c:a libopus -b:a 128k output.webm
```

## 6.4 容器的"兼容性矩阵"

这张表格告诉你哪些编解码器能装进哪些容器：

| 编解码器 | MP4 | MKV | AVI | MOV | FLV | TS | WebM |
| --------- | ----- | ----- | ----- | ----- | ----- | ----- | ------ |
| **视频** | | | | | | | |
| H.264 | ✅ | ✅ | ⚠️ | ✅ | ✅ | ✅ | ❌ |
| H.265 | ✅ | ✅ | ❌ | ✅ | ❌ | ✅ | ❌ |
| VP9 | ⚠️ | ✅ | ❌ | ❌ | ❌ | ❌ | ✅ |
| AV1 | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ✅ |
| ProRes | ❌ | ✅ | ❌ | ✅ | ❌ | ❌ | ❌ |
| **音频** | | | | | | | |
| AAC | ✅ | ✅ | ⚠️ | ✅ | ✅ | ✅ | ❌ |
| MP3 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ |
| Opus | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ✅ |
| FLAC | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| Vorbis | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ | ✅ |
| **字幕** | | | | | | | |
| SRT | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ | ✅ |
| ASS/SSA | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ | ✅ |
| tx3g | ✅ | ✅ | ❌ | ✅ | ❌ | ❌ | ❌ |

✅ = 完全支持，⚠️ = 有限支持，❌ = 不支持

**从这张表可以得出几个实用结论：**

1. **MP4 最通用**，但它不能装所有东西（不支持 FLAC 音频、不支持 SRT 字幕）
2. **MKV 是万能容器**，什么都能装，但播放器兼容性不如 MP4
3. **WebM 只能装开放格式**（VP8/VP9/AV1 + Opus/Vorbis），但 Web 兼容性极好
4. 如果你需要多字幕、多音轨、FLAC 音频，只能用 MKV

## 6.5 ffprobe 深度使用

ffprobe 是你的"文件体检工具"。让我们系统学习它的用法。

**基本用法：查看文件概况**

```bash
# 查看所有流的基本信息
ffprobe -v error -show_streams input.mp4

# 输出会列出每条流的详细参数，例如：
# [STREAM]
# index=0
# codec_name=h264
# codec_long_name=H.264 / AVC / MPEG-4 AVC / MPEG-4 part 10
# width=1920
# height=1080
# r_frame_rate=30/1
# ...
# [/STREAM]
```

**查看特定信息**

```bash
# 只显示视频流的编码名称和分辨率
ffprobe -v error -select_streams v:0 \
  -show_entries stream=codec_name,width,height \
  -of default=noprint_wrappers=1 \
  input.mp4

# 输出：
# codec_name=h264
# width=1920
# height=1080
```

**以 JSON 格式输出（方便程序处理）**

```bash
# JSON 输出，适合用脚本解析
ffprobe -v quiet -print_format json -show_format -show_streams input.mp4

# 输出示例（部分）：
# {
#   "streams": [
#     {
#       "index": 0,
#       "codec_name": "h264",
#       "width": 1920,
#       "height": 1080,
#       "r_frame_rate": "30/1",
#       "bit_rate": "4000000"
#     },
#     {
#       "index": 1,
#       "codec_name": "aac",
#       "sample_rate": "48000",
#       "channels": 2
#     }
#   ],
#   "format": {
#     "filename": "input.mp4",
#     "duration": "600.000000",
#     "size": "375000000",
#     "bit_rate": "5000000"
#   }
# }
```

**查看容器格式信息**

```bash
# 显示容器格式信息（时长、文件大小、总码率等）
ffprobe -v error -show_entries format=duration,size,bit_rate,format_name \
  -of default=noprint_wrappers=1 \
  input.mp4

# 输出示例：
# format_name=mov,mp4,m4a,3gp,3g2,mj2
# duration=600.000000
# size=375000000
# bit_rate=5000000
```

**统计流的数量和类型**

```bash
# 列出所有流的数量和类型
ffprobe -v error -show_entries stream=index,codec_type,codec_name \
  -of csv=p=0 \
  input.mkv

# 输出示例：
# 0,video,h264
# 1,audio,aac
# 2,audio,ac3
# 3,subtitle,srt
# （这个 MKV 文件包含 1 条视频流、2 条音频流、1 条字幕流）
```

**查看关键帧分布**

```bash
# 查看前 50 帧的类型（I帧、P帧、B帧）
ffprobe -v error -select_streams v:0 \
  -show_entries frame=pict_type,key_frame \
  -of csv=p=0 \
  -read_intervals "%+#50" \
  input.mp4

# 输出示例：
# I,1     ← I帧（关键帧）
# B,0     ← B帧
# B,0     ← B帧
# P,0     ← P帧
# B,0
# ...
```

## 6.6 用 ffprobe 做"文件体检"

当你拿到一个视频文件，在做任何处理之前，先用 ffprobe 给它做一次全面"体检"：

**快速体检脚本**

```bash
# 一键查看文件的所有关键信息
ffprobe -v error \
  -show_entries format=filename,duration,size,bit_rate,format_name \
  -show_entries stream=index,codec_type,codec_name,width,height,r_frame_rate,sample_rate,channels,bit_rate \
  -of json \
  input.mp4
```

这条命令用 JSON 格式输出文件的全部关键信息，包括：

- 文件名、时长、文件大小、总码率、容器格式
- 每条流的序号、类型（视频/音频/字幕）、编码名称
- 视频流的分辨率和帧率
- 音频流的采样率和声道数

**实用体检案例**

假设你有一个文件，想知道"它能不能直接转成 MP4 而不用重新编码"：

```bash
# 第一步：查看编码格式
ffprobe -v error -select_streams v:0 \
  -show_entries stream=codec_name \
  -of default=noprint_wrappers=1 \
  input.mkv

# 如果输出 codec_name=h264，恭喜你，可以直接 -c copy
# 如果输出 codec_name=vp9 或 hevc，需要检查目标播放器是否支持

# 第二步：检查音频编码
ffprobe -v error -select_streams a:0 \
  -show_entries stream=codec_name \
  -of default=noprint_wrappers=1 \
  input.mkv

# 如果输出 codec_name=aac，可以直接 -c copy
# 如果输出 codec_name=flac 或 vorbis，MP4 不支持，需要重新编码音频

# 第三步：如果编码都兼容，直接无损转换
ffmpeg -i input.mkv -c copy -movflags +faststart output.mp4
```

**另一个实用场景：判断视频是否需要重新编码**

```bash
# 查看视频编码参数
ffprobe -v error -select_streams v:0 \
  -show_entries stream=codec_name,profile,level,width,height,color_space,color_transfer \
  -of default=noprint_wrappers=1 \
  input.mp4

# 输出示例：
# codec_name=h264
# profile=High
# level=41
# width=1920
# height=1080
# color_space=bt709
# color_transfer=bt709

# 这告诉我们：
# - H.264 High Profile Level 4.1：支持 1080p 30fps，大多数设备都能播放
# - bt709 色彩空间：标准 SDR 视频，不是 HDR
```

**检查文件是否有 HDR 信息**

```bash
# 查看 HDR 相关信息
ffprobe -v error -select_streams v:0 \
  -show_entries stream=color_transfer,color_primaries,color_space \
  -of default=noprint_wrappers=1 \
  input.mp4

# 如果是 HDR10 视频，你会看到：
# color_transfer=smpte2084      ← PQ 传输函数（HDR10 的标志）
# color_primaries=bt2020        ← BT.2020 色域（宽色域）
# color_space=bt2020nc          ← BT.2020 色彩空间

# 如果是 SDR 视频，你会看到：
# color_transfer=bt709
# color_primaries=bt709
# color_space=bt709
```

## 本章小结

- 容器格式是"信封"，编解码器是"信的内容"，两者是不同的概念
- MP4 兼容性最好，MKV 功能最强，WebM 专为 Web 设计
- 文件扩展名只代表容器格式，不能反映内部使用的编码格式
- 用 ffprobe 可以查看文件的全部技术细节，是视频处理的第一步
- `-c copy` 可以无损复制流，但前提是目标容器支持该编码格式
- `-movflags +faststart` 让 MP4 支持边下边播，对网页视频很重要
- 处理任何视频之前，先用 ffprobe 做"体检"，了解文件结构后再决定处理方案
