# 第12章 JSON 数据类型与操作（MySQL 8.0）

## 12.1 JSON：当关系型数据库遇上NoSQL

JSON（JavaScript Object Notation）是互联网时代最流行的数据交换格式，几乎所有API都在使用JSON来传输数据。在MySQL引入原生JSON类型之前，如果你想在数据库中存储JSON数据，只能把它塞进一个TEXT或VARCHAR字段里，然后默默祈祷自己不会写错格式，也不会在查询时遇到解析问题。

MySQL 5.7开始引入了原生JSON数据类型，MySQL 8.0又大幅增强了JSON相关的功能（新增了更多JSON函数、JSON_TABLE等）。这就好比你家里原来只有一个大箱子（TEXT字段），所有东西都混在一起堆着。现在有了专门的分类收纳盒（JSON类型），不仅东西放得整齐有序，还能快速找到你要的那件物品。

原生JSON类型相比TEXT存储有很多优势。首先MySQL会自动验证JSON格式——如果你试图插入格式错误的JSON，会直接报错而不是悄悄存入脏数据。其次JSON使用优化的二进制格式存储，读取时不需要重新解析文本。最重要的是，MySQL提供了丰富的JSON函数来查询和操作JSON内部的字段和元素：

```sql
-- JSON vs TEXT存储JSON的区别演示
CREATE TABLE products_text (
    id INT PRIMARY KEY, name VARCHAR(100),
    attributes TEXT  -- 存JSON字符串，MySQL不验证格式
);
CREATE TABLE products_json (
    id INT PRIMARY KEY, name VARCHAR(100),
    attributes JSON  -- 原生JSON类型，自动验证格式
);

-- TEXT字段：格式错了也能存进去（后续使用时才会发现问题）
INSERT INTO products_text VALUES (1, '手机', '{"color": "black", invalid}');

-- JSON字段：格式错误直接报错，从源头杜绝脏数据
-- INSERT INTO products_json VALUES (1, '手机', '{"color": invalid}');  -- 报错！
```

## 12.2 JSON路径表达式（$语法）

JSON路径表达式是访问JSON数据内部的"导航地址"，以 `$` 符号开头代表JSON文档的根节点。通过路径表达式，你可以精确定位到JSON中任意层级的字段或数组元素：

```sql
-- JSON路径语法速查
-- $             根对象
-- $.key         访问对象属性
-- $.key1.key2   嵌套属性访问
-- $[0]          数组第一个元素（索引从0开始）
-- $[*]          数组所有元素
-- $.skills[0]   对象中数组的第一个元素

SELECT JSON_EXTRACT('{"name": "张三", "age": 28}', '$.name');  -- "张三"
SELECT JSON_EXTRACT('[1,2,3]', '$[1]');                         -- 2
SELECT JSON_EXTRACT('{"a": {"b": 42}}', '$.a.b');              -- 42
```

## 12.3 -> 和 ->> 操作符

MySQL 8.0引入了两个简洁的JSON操作符，大大简化了JSON值的提取语法。`->` 等价于JSON_EXTRACT()，返回的值保持JSON格式（字符串会带引号）；`->>` 等价于JSON_UNQUOTE(JSON_EXTRACT())，返回的是去掉引号的纯文本值：

```sql
-- 创建测试数据
CREATE TABLE users (
    user_id INT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50),
    profile JSON,
    tags JSON
);

INSERT INTO users VALUES
(1, '张三', '{"age": 28, "city": "北京", "skills": ["Python", "MySQL"]}', '["技术", "后端"]'),
(2, '李四', '{"age": 32, "city": "上海", "skills": ["JavaScript", "React"]}', '["前端", "设计"]'),
(3, '王五', '{"age": 25, "city": "深圳", "skills": ["Java", "Spring", "MySQL"]}', '["技术", "全栈"]'),
(4, '赵六', '{"age": 35, "city": "北京", "skills": ["管理", "PMP"], "married": true}', '["管理"]');

-- 对比 -> 和 ->> 的区别
SELECT profile->'$.city' AS with_quotes,     -- "北京"（带引号，JSON格式）
       profile->>'$.city' AS without_quotes  -- 北京（不带引号，纯文本）
FROM users;

-- 日常使用中 ->> 更常用（大多数场景你不需要引号）
SELECT username, profile->>'$.city' AS city, profile->>'$.age' AS age FROM users;
```

> [!TIP] 提示
> 日常使用中 `->>` 更常用，因为大多数时候你不想要结果带引号。在WHERE条件中比较时尤其重要：`WHERE profile->'$.city' = '北京'` 不会匹配（因为左边是JSON格式的"北京"带引号），而 `WHERE profile->>'$.city' = '北京'` 才能正确匹配。

## 12.4 JSON函数详解

**创建JSON数据：**

```sql
-- JSON_OBJECT：从键值对创建JSON对象
SELECT JSON_OBJECT('name', '张三', 'age', 28, 'city', '北京');
-- 结果：{"age": 28, "city": "北京", "name": "张三"}

-- JSON_ARRAY：从值列表创建JSON数组
SELECT JSON_ARRAY('Python', 'MySQL', 'Linux');
-- 结果：["Python", "MySQL", "Linux"]
```

**读取和查询JSON：**

```sql
-- JSON_CONTAINS：检查JSON是否包含指定值（第二个参数必须是有效JSON格式）
SELECT username FROM users
WHERE JSON_CONTAINS(profile->'$.skills', '"MySQL"');
-- 张三和王五的skills数组包含"MySQL"
-- 注意：字符串值要加引号 '"MySQL"'，数字直接写 '28'，布尔写 'true'

-- JSON_CONTAINS_PATH：检查JSON中是否存在指定路径
SELECT username FROM users
WHERE JSON_CONTAINS_PATH(profile, 'one', '$.married');
-- 只有王五和赵六有married字段

-- JSON_KEYS：获取JSON对象的所有键名
SELECT JSON_KEYS(profile) FROM users WHERE user_id = 1;
-- ["age", "city", "skills"]

-- JSON_LENGTH：获取JSON数组的元素个数或对象的键数
SELECT username, JSON_LENGTH(profile->'$.skills') AS skill_count FROM users;
-- 张三:2, 李四:2, 王五:3, 赵六:2

-- JSON_SEARCH：在JSON中搜索值，返回匹配的路径
SELECT JSON_SEARCH(profile, 'one', '北京') FROM users;
-- 返回 "$.city"
```

> [!TIP] 提示
> JSON_CONTAINS的第二个参数必须是有效的JSON值格式，这是新手最容易犯错的地方。字符串要写成 `'"MySQL"'`（外面单引号是SQL字符串，里面双引号是JSON字符串），数字写成 `'28'`，布尔值写成 `'true'` 或 `'false'`。如果忘记给字符串加JSON引号，MySQL会报类型错误。

**修改JSON数据：**

```sql
-- JSON_SET：设置值（存在则更新，不存在则添加——"智能合并"）
SELECT JSON_SET(profile, '$.age', 29, '$.email', 'zhang@example.com')
FROM users WHERE user_id = 1;

-- JSON_REPLACE：只替换已存在的键（不会添加新键）
SELECT JSON_REPLACE(profile, '$.age', 29, '$.email', 'zhang@example.com')
FROM users WHERE user_id = 1;
-- email不会被添加，因为profile中原本没有email键

-- JSON_INSERT：只添加不存在的键（不会修改已有的值）
SELECT JSON_INSERT(profile, '$.age', 29, '$.email', 'zhang@example.com')
FROM users WHERE user_id = 1;
-- age保持28不变，email会被添加

-- JSON_REMOVE：删除指定的键
SELECT JSON_REMOVE(profile, '$.city') FROM users WHERE user_id = 1;

-- JSON_ARRAY_APPEND：向JSON数组末尾追加元素
SELECT JSON_ARRAY_APPEND(profile, '$.skills', 'Docker') FROM users WHERE user_id = 1;

-- 实际更新操作：给张三涨一岁
UPDATE users
SET profile = JSON_SET(profile, '$.age', (profile->>'$.age') + 1)
WHERE username = '张三';
```

## 12.5 虚拟列（Generated Column）与JSON索引

JSON列不能直接建索引——因为MySQL把整个JSON文档当作一个整体来存储，无法对文档内部的某个字段建立B-Tree索引。但是MySQL提供了一个巧妙的解决方案：**虚拟列（Generated Column）**。你可以添加一个虚拟列，其值自动从JSON字段中提取，然后在这个虚拟列上建索引。这样既保留了JSON的灵活性，又获得了关系型数据库索引的高性能：

```sql
-- 添加虚拟列（值自动从JSON中计算，不需要手动维护）
ALTER TABLE users
ADD COLUMN city VARCHAR(50) GENERATED ALWAYS AS (profile->>'$.city') VIRTUAL,
ADD COLUMN age INT GENERATED ALWAYS AS (profile->>'$.age') VIRTUAL;

-- 在虚拟列上建索引（和普通列建索引一样）
CREATE INDEX idx_city ON users(city);
CREATE INDEX idx_age ON users(age);

-- 现在这些查询可以走索引了，性能杠杠的
SELECT * FROM users WHERE city = '北京';   -- 走idx_city索引
SELECT * FROM users WHERE age > 30;        -- 走idx_age索引

-- 也可以在创建表时就定义好虚拟列
CREATE TABLE products (
    id INT PRIMARY KEY AUTO_INCREMENT,
    info JSON,
    price DECIMAL(10,2) GENERATED ALWAYS AS (info->>'$.price') VIRTUAL,
    category VARCHAR(50) GENERATED ALWAYS AS (info->>'$.category') VIRTUAL,
    INDEX idx_price (price),
    INDEX idx_category (category)
);
```

虚拟列有两种类型：VIRTUAL（不实际存储在磁盘上，每次查询时实时计算，不占空间但每次要算）和STORED（实际存储在磁盘上，写入时计算好存下来，占空间但读取快）。大多数场景用VIRTUAL就够了，除非计算特别复杂或读取频率极高。

> [!WARNING] 注意
> 虚拟列虽然解决了JSON字段的索引问题，但它也有局限：虚拟列只能提取JSON中的标量值（字符串、数字、布尔），不能提取数组或嵌套对象。而且如果你修改了JSON字段中被虚拟列引用的键，虚拟列的值会自动更新，这可能影响到索引的一致性——虽然MySQL内部会处理好，但你应该意识到这层依赖关系。

## 12.6 JSON_TABLE函数：JSON转关系表

JSON_TABLE是MySQL 8.0的杀手级JSON功能——它能把JSON数据"展开"成关系型表格，让你可以用标准SQL的JOIN、GROUP BY、WHERE等操作来处理JSON中的嵌套数据。这在处理订单明细、标签数组等一对多嵌套结构时特别有用：

```sql
-- 将users表中每个人的skills数组展开成多行
SELECT u.username, jt.skill
FROM users u,
JSON_TABLE(
    u.profile->'$.skills',
    '$[*]' COLUMNS (
        skill VARCHAR(50) PATH '$'
    )
) AS jt;
-- 张三 | Python
-- 张三 | MySQL
-- 李四 | JavaScript
-- 李四 | React
-- ...每人的每个skill都变成独立一行
```

```sql
-- 更复杂的场景：展开嵌套的订单数据
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    order_data JSON
);

INSERT INTO orders VALUES
(1, '{"customer": "张三", "items": [{"name": "手机", "qty": 1, "price": 5999}, {"name": "耳机", "qty": 2, "price": 299}]}'),
(2, '{"customer": "李四", "items": [{"name": "键盘", "qty": 1, "price": 499}]}');

-- 用NESTED PATH展开嵌套数组
SELECT o.order_id, jt.customer, jt.item_name, jt.qty, jt.price,
       jt.qty * jt.price AS subtotal
FROM orders o,
JSON_TABLE(
    o.order_data, '$' COLUMNS (
        customer VARCHAR(50) PATH '$.customer',
        NESTED PATH '$.items[*]' COLUMNS (
            item_name VARCHAR(100) PATH '$.name',
            qty INT PATH '$.qty',
            price DECIMAL(10,2) PATH '$.price'
        )
    )
) AS jt;
-- 1 | 张三 | 手机 | 1 | 5999.00 | 5999.00
-- 1 | 张三 | 耳机 | 2 | 299.00  | 598.00
-- 2 | 李四 | 键盘 | 1 | 499.00  | 499.00
```

## 12.7 JSON性能考量与最佳实践

JSON很方便，但它不是万能的银弹。在使用JSON之前，你需要了解一些重要的性能考量和最佳实践，避免把JSON当成"什么都能装"的万能口袋。

**适合使用JSON的场景：** 属性不固定或经常变化的场景（如用户偏好设置、产品的自定义属性）；需要存储嵌套结构且通常作为整体读写的场景（如配置信息、地址簿）；属性数量很多但每次查询只关注少数几个字段的场景。

**不适合使用JSON的场景：** 经常需要JOIN的字段（应该独立成表）；需要频繁单独更新的字段（关系表更新更高效）；数据需要强一致性保证的场景（JSON内部字段无法加外键约束）。

```sql
-- 好的做法：高频查询条件提取到虚拟列并建索引
SELECT * FROM users WHERE city = '北京';   -- 走虚拟列索引，快

-- 不好的做法：直接在WHERE中对大JSON字段使用JSON_EXTRACT
SELECT * FROM users
WHERE JSON_EXTRACT(profile, '$.city') = '"北京"';  -- 全表扫描，慢！

-- 检查JSON占用的存储空间
SELECT username,
    JSON_STORAGE_SIZE(profile) AS profile_bytes,
    JSON_STORAGE_SIZE(tags) AS tags_bytes
FROM users;
```

> [!TIP] 提示
> MySQL的JSON类型使用二进制格式存储，对于读取操作比TEXT快很多（不需要重新解析整个文本）。但如果你的JSON文档特别大（比如超过几KB），应该认真考虑是否可以把部分数据拆分到关系表中。一个经验法则是：如果一个JSON文档中的某些字段需要频繁被用于WHERE条件或JOIN，就应该把这些字段提取出来作为普通列或虚拟列。

**JSON使用的最佳实践总结：**

```sql
-- 1. 高频查询的字段提取为虚拟列 + 索引
ALTER TABLE users ADD INDEX idx_city ((CAST(profile->>'$.city' AS CHAR(50))));

-- 2. 合理使用JSON的部分更新功能，避免全量替换整个JSON文档
UPDATE users
SET profile = JSON_SET(profile, '$.last_login', NOW())
WHERE user_id = 1;
-- 只更新一个字段，MySQL内部只修改对应的二进制区域

-- 3. 使用JSON_TABLE展开数组做聚合分析
SELECT jt.skill, COUNT(*) AS popularity
FROM users u,
JSON_TABLE(u.profile->'$.skills', '$[*]' COLUMNS (skill VARCHAR(50) PATH '$')) AS jt
GROUP BY jt.skill
ORDER BY popularity DESC;
```

## 小结

MySQL 8.0的JSON支持让关系型数据库也能灵活处理半结构化数据，实现了"结构化数据用列，半结构化数据用JSON"的混合存储模式。`->` 和 `->>` 操作符简化了JSON值的提取，JSON_SET/JSON_REPLACE/JSON_REMOVE实现了部分更新，JSON_TABLE可以把JSON数组展开为关系表。关键是要配合虚拟列和索引来保证查询性能，避免在大JSON字段上直接做过滤导致全表扫描。
