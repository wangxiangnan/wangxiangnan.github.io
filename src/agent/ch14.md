# 第14章 Function Calling —— Agent与工具的通信协议

## 14.1 开篇：从"瞎猜"到"签约"

还记得我们在第12章创建的Tools吗？我们定义了`search_documents`、`calculate`等工具，让Agent能调用外部能力。但这里有一个关键问题我们故意绕过了：**LLM是怎么知道该调用哪个工具、传什么参数的？**

在Function Calling协议出现之前，开发者们用的是一种"蛮力"方法：

```python
# 远古方法：让LLM输出特定格式，然后用正则表达式解析
prompt = """
你是一个助手。如果需要搜索文档，请输出：
SEARCH_QUERY: 你的搜索词

如果需要计算，请输出：
CALCULATE: 数学表达式

用户问题：DocMind项目的代码量大概有多少行？
"""

response = llm.invoke(prompt)
# 然后用正则表达式去"猜"LLM的意图
if "SEARCH_QUERY:" in response:
    query = response.split("SEARCH_QUERY:")[1].strip()
    result = search_documents(query)
elif "CALCULATE:" in response:
    expr = response.split("CALCULATE:")[1].strip()
    result = calculate(expr)
```

这种方法的问题显而易见：

- LLM可能不遵守格式（"我觉得你应该搜索……"）
- 参数解析极其脆弱（多了个换行就崩了）
- 无法处理复杂参数（嵌套JSON？祝你好运）
- 没有类型安全（传了个字符串进去，期望的是数字）

这就好比你和一个外国朋友合作，靠"比划手势"来沟通——有时候能懂，有时候完全误解。

**Function Calling**就是那个"签约"的过程：你和LLM之间签订一份严格的"接口协议"，LLM保证按照这个协议来告诉你它想调用什么函数、传什么参数，你保证按照协议执行并返回结果。

> 用编程的话说：Function Calling就是LLM世界的**RPC协议**。以前是靠stdout传字符串（像CGI），现在是结构化的JSON Schema（像gRPC/REST）。

## 14.2 Function Calling协议的演进

### 14.2.1 前Function Calling时代

2023年初，开发者们为了让LLM调用工具，可谓八仙过海：

- **正则解析派**：约定特殊标记，用正则提取
- **JSON输出派**：要求LLM输出JSON，然后`json.loads()`
- **ReAct文本派**：让LLM输出`Thought: ... Action: ... Action Input: ...`格式的文本

这些方法都能用，但都不可靠。核心问题是：**LLM本质上是一个文本生成器，你无法保证它的输出格式。**

### 14.2.2 OpenAI的突破（2023年6月）

OpenAI在API层面引入了`functions`参数（后来演进为`tools`），这不是一个prompt技巧，而是**模型微调+API协议**的双重创新：

- 模型在训练阶段就学会了何时调用函数、如何生成合规的参数
- API返回的不是普通文本，而是结构化的`function_call`对象
- 参数是严格的JSON，符合你定义的JSON Schema

### 14.2.3 协议的成熟（2024年至今）

随后各大厂商跟进：

- **OpenAI**：`functions` → `tools`（支持并行调用）
- **Anthropic**：`tool_use`协议
- **Google**：`function_calling`
- **开源模型**：通过各种微调支持

现在Function Calling已经成为事实上的标准协议，就像HTTP之于Web——不是唯一选择，但是最通用的选择。

## 14.3 OpenAI Function Calling协议详解

### 14.3.1 定义函数Schema

Function Calling的核心是**JSON Schema**。你需要告诉模型：

- 这个函数叫什么名字
- 它是干什么的
- 它接受什么参数（类型、是否必填、描述）

```python
# 定义一个搜索文档的函数Schema
search_tool = {
    "type": "function",
    "function": {
        "name": "search_documents",
        "description": "在知识库中搜索相关文档。当用户询问文档内容、需要查找特定信息时使用此工具。",
        "parameters": {
            "type": "object",
            "properties": {
                "query": {
                    "type": "string",
                    "description": "搜索查询关键词"
                },
                "top_k": {
                    "type": "integer",
                    "description": "返回结果数量，默认3",
                    "default": 3
                },
                "doc_type": {
                    "type": "string",
                    "description": "文档类型过滤",
                    "enum": ["pdf", "markdown", "docx", "all"]
                }
            },
            "required": ["query"]  # 只有query是必填的
        }
    }
}

# 再定义一个计算函数
calculate_tool = {
    "type": "function",
    "function": {
        "name": "calculate",
        "description": "执行数学计算。当需要进行数值计算、统计分析时使用此工具。",
        "parameters": {
            "type": "object",
            "properties": {
                "expression": {
                    "type": "string",
                    "description": "数学表达式，如 '2 + 3 * 4'"
                },
                "precision": {
                    "type": "integer",
                    "description": "小数精度，默认2位"
                }
            },
            "required": ["expression"]
        }
    }
}

# 工具列表
tools = [search_tool, calculate_tool]
```

> ⚠️ **坑1：description非常重要！** 模型是根据description来判断"什么时候该调用这个函数"的。一个含糊的描述会导致模型乱调用或不调用。写description就像写API文档——清晰、准确、包含使用场景。

> ⚠️ **坑2：enum约束很有用。** 像`doc_type`这种有限选项，用`enum`约束后，模型只会返回合法值。不加enum？模型可能给你返回"Word文档"、".doc"、"Microsoft Word"等各种奇怪的值。

### 14.3.2 模型返回tool_calls

当你把tools和消息一起发给模型时，模型可能返回两种结果：

**情况1：不需要工具**——返回普通文本回复
**情况2：需要工具**——返回`tool_calls`（结构化的函数调用请求）

```python
import json
from openai import OpenAI

client = OpenAI()

messages = [
    {"role": "system", "content": "你是DocMind智能文档助手，帮助用户查询和分析文档内容。"},
    {"role": "user", "content": "帮我查一下关于Agent架构的文档"}
]

# 发送请求，带上工具定义
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    tools=tools,
    tool_choice="auto"  # "auto"让模型自己决定是否调用工具
)

message = response.choices[0].message

# 检查模型是否要调用工具
if message.tool_calls:
    print("模型决定调用工具！")
    for tool_call in message.tool_calls:
        print(f"  函数名: {tool_call.function.name}")
        print(f"  参数: {tool_call.function.arguments}")
        print(f"  调用ID: {tool_call.id}")
else:
    print(f"模型直接回答: {message.content}")

# 输出示例：
# 模型决定调用工具！
#   函数名: search_documents
#   参数: {"query": "Agent架构", "doc_type": "all", "top_k": 3}
#   调用ID: call_abc123
```

关键理解：

- `tool_calls`是一个**列表**（模型可能同时调用多个工具）
- 每个`tool_call`有一个唯一的`id`（后续返回结果时需要用这个id关联）
- `arguments`是**JSON字符串**，需要`json.loads()`解析
- 模型**不执行函数**，它只是告诉你"我想调用这个函数，参数是这些"

### 14.3.3 完整的调用流程

整个Function Calling是一个**循环**过程，就像一个`while`循环：

```
用户提问 → LLM判断是否需要工具
  ├─ 不需要 → 直接回答，结束
  └─ 需要 → 返回tool_calls
       ↓
    执行工具，得到结果
       ↓
    将工具结果作为ToolMessage喂回LLM
       ↓
    LLM再次判断：还需要更多工具吗？
       ├─ 需要 → 继续循环
       └─ 不需要 → 基于工具结果生成最终回答
```

## 14.4 原生实现：不依赖LangChain的完整Function Calling

理论讲够了，让我们写一个完整的、可运行的Function Calling系统。不依赖LangChain，纯原生实现——这是为了让你真正理解底层发生了什么。

```python
"""
原生Function Calling完整实现
不依赖LangChain，使用OpenAI SDK直接实现
"""
import json
from openai import OpenAI
from typing import Any, Callable

client = OpenAI()

# ============================================================
# 第一步：定义实际的Python函数（工具的实现）
# ============================================================

def search_documents(query: str, top_k: int = 3, doc_type: str = "all") -> dict:
    """搜索文档知识库"""
    # 这里用模拟数据代替真实的向量数据库查询
    mock_docs = [
        {"title": "Agent架构设计指南", "content": "Agent由LLM、Memory、Tools三部分组成...", "score": 0.95},
        {"title": "ReAct模式详解", "content": "ReAct是推理与行动交替进行的模式...", "score": 0.88},
        {"title": "LangChain快速入门", "content": "LangChain是一个用于构建LLM应用的框架...", "score": 0.82},
    ]
    
    # 模拟过滤
    results = mock_docs[:top_k]
    return {"status": "success", "results": results, "count": len(results)}


def calculate(expression: str, precision: int = 2) -> dict:
    """安全地执行数学计算"""
    try:
        # 生产环境中应该用ast.literal_eval或sympy，这里简化用eval
        # ⚠️ 永远不要在生产环境中对用户输入直接使用eval！
        allowed_names = {"abs": abs, "round": round, "min": min, "max": max, "sum": sum}
        result = eval(expression, {"__builtins__": {}}, allowed_names)
        return {"status": "success", "expression": expression, "result": round(result, precision)}
    except Exception as e:
        return {"status": "error", "error": str(e)}


def get_document_summary(doc_id: str) -> dict:
    """获取指定文档的摘要信息"""
    mock_summaries = {
        "doc_001": {"title": "Agent架构设计指南", "pages": 42, "author": "张三",
                     "summary": "全面介绍AI Agent的设计模式"},
        "doc_002": {"title": "ReAct模式详解", "pages": 18, "author": "李四",
                     "summary": "深入解析推理与行动的结合"},
    }
    if doc_id in mock_summaries:
        return {"status": "success", "data": mock_summaries[doc_id]}
    return {"status": "error", "error": f"文档 {doc_id} 不存在"}


# ============================================================
# 第二步：建立函数名 → 函数对象的映射（工具注册表）
# ============================================================

TOOL_REGISTRY: dict[str, Callable] = {
    "search_documents": search_documents,
    "calculate": calculate,
    "get_document_summary": get_document_summary,
}

# ============================================================
# 第三步：定义工具的JSON Schema（告诉模型有哪些工具可用）
# ============================================================

TOOL_SCHEMAS = [
    {
        "type": "function",
        "function": {
            "name": "search_documents",
            "description": "在知识库中搜索相关文档。当用户询问文档内容、需要查找特定信息时使用。",
            "parameters": {
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "搜索查询关键词"},
                    "top_k": {"type": "integer", "description": "返回结果数量", "default": 3},
                    "doc_type": {
                        "type": "string", "description": "文档类型",
                        "enum": ["pdf", "markdown", "docx", "all"]
                    }
                },
                "required": ["query"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "calculate",
            "description": "执行数学计算。用于数值计算、统计分析等场景。",
            "parameters": {
                "type": "object",
                "properties": {
                    "expression": {"type": "string", "description": "数学表达式"},
                    "precision": {"type": "integer", "description": "小数精度", "default": 2}
                },
                "required": ["expression"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "get_document_summary",
            "description": "获取指定文档的摘要信息。需要提供文档ID。",
            "parameters": {
                "type": "object",
                "properties": {
                    "doc_id": {"type": "string", "description": "文档ID，如 doc_001"}
                },
                "required": ["doc_id"]
            }
        }
    }
]


# ============================================================
# 第四步：执行工具调用的函数
# ============================================================

def execute_tool_call(tool_call) -> dict:
    """
    执行单个工具调用
    tool_call: OpenAI API返回的tool_call对象
    """
    function_name = tool_call.function.name
    function_args = json.loads(tool_call.function.arguments)
    
    print(f"  [执行工具] {function_name}")
    print(f"     参数: {function_args}")
    
    # 从注册表中查找函数
    if function_name not in TOOL_REGISTRY:
        return {"status": "error", "error": f"未知工具: {function_name}"}
    
    # 执行函数
    try:
        result = TOOL_REGISTRY[function_name](**function_args)
        print(f"     结果: {result}")
        return result
    except Exception as e:
        print(f"     错误: {e}")
        return {"status": "error", "error": str(e)}


# ============================================================
# 第五步：主循环——Agent的核心逻辑
# ============================================================

def agent_loop(user_message: str, max_iterations: int = 5) -> str:
    """
    Agent主循环
    这就是Function Calling的核心：一个while循环
    
    类比理解：
    - 你问一个专家问题
    - 专家可能需要查资料（调用工具）
    - 查完资料后，专家可能还需要查更多资料（继续调用）
    - 直到专家觉得信息足够了，才给出最终回答
    """
    
    # 初始化消息历史
    messages = [
        {
            "role": "system",
            "content": (
                "你是DocMind——一个智能文档问答助手。\n"
                "你可以帮助用户搜索文档、进行计算、获取文档摘要。\n"
                "请优先使用工具获取准确信息，不要凭空编造答案。\n"
                "回答时使用中文。"
            )
        },
        {"role": "user", "content": user_message}
    ]
    
    print(f"\n{'='*60}")
    print(f"用户提问: {user_message}")
    print(f"{'='*60}")
    
    for iteration in range(max_iterations):
        print(f"\n--- 第 {iteration + 1} 轮 ---")
        
        # 调用LLM
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=TOOL_SCHEMAS,
            tool_choice="auto"
        )
        
        assistant_message = response.choices[0].message
        
        # 将助手的回复加入消息历史
        messages.append(assistant_message)
        
        # 检查是否有工具调用
        if not assistant_message.tool_calls:
            # 没有工具调用 -> 模型给出了最终回答
            print(f"\n[最终回答] {assistant_message.content}")
            return assistant_message.content
        
        # 有工具调用 -> 执行每个工具
        print(f"模型请求调用 {len(assistant_message.tool_calls)} 个工具")
        
        for tool_call in assistant_message.tool_calls:
            # 执行工具
            result = execute_tool_call(tool_call)
            
            # 将工具结果作为ToolMessage加入消息历史
            # 注意：tool_call_id必须与tool_call.id对应
            tool_message = {
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": json.dumps(result, ensure_ascii=False)
            }
            messages.append(tool_message)
        
        # 循环继续，让模型看到工具结果后决定下一步
    
    return "达到最大迭代次数，Agent停止执行。"


# ============================================================
# 第六步：测试
# ============================================================

if __name__ == "__main__":
    # 测试1：需要搜索工具
    print("\n测试1: 搜索文档")
    agent_loop("帮我找一下关于Agent架构的文档")
    
    # 测试2：需要计算工具
    print("\n\n测试2: 数学计算")
    agent_loop("帮我算一下 (1024 * 768) / (1024 + 768) 等于多少")
    
    # 测试3：可能需要多个工具串联
    print("\n\n测试3: 多工具串联")
    agent_loop("帮我搜索ReAct相关的文档，然后查一下doc_002的摘要")
    
    # 测试4：不需要工具，直接回答
    print("\n\n测试4: 直接回答")
    agent_loop("你好，你叫什么名字？")
```

### 代码解析：关键细节

让我们逐一审视这段代码的关键设计：

**1. 消息角色的四种类型**

```python
# system: 系统指令（模型的行为准则）
{"role": "system", "content": "你是DocMind..."}

# user: 用户的消息
{"role": "user", "content": "帮我搜索..."}

# assistant: 模型的回复（可能包含tool_calls）
{"role": "assistant", "content": "...", "tool_calls": [...]}

# tool: 工具执行的结果（必须关联tool_call_id）
{"role": "tool", "tool_call_id": "call_abc123", "content": "{...}"}
```

这四种角色构成了一个完整的"对话协议"：

- `system` 相当于宪法（不可违反的基本法）
- `user` 是用户的请求
- `assistant` 是模型的决策
- `tool` 是外部世界的反馈

**2. tool_call_id的重要性**

```python
# 错误做法：不传tool_call_id
tool_message = {"role": "tool", "content": "结果..."}
# 模型不知道这个结果对应哪个调用请求！

# 正确做法：关联tool_call_id
tool_message = {
    "role": "tool",
    "tool_call_id": tool_call.id,  # 必须对应
    "content": "结果..."
}
```

> ⚠️ 当模型并行请求多个工具调用时，每个ToolMessage必须通过`tool_call_id`关联到对应的调用请求。否则模型会"张冠李戴"，把A工具的结果当成B工具的。

**3. 最大迭代次数（安全阀）**

```python
for iteration in range(max_iterations):  # max_iterations = 5
```

这是一个**安全阀**。如果模型陷入无限循环（不断调用工具，永远不给出最终回答），我们需要一个终止条件。就像`while`循环里的`break`条件。

## 14.5 用LangChain实现同样的功能

现在看看LangChain如何简化这一切：

```python
"""
用LangChain实现Function Calling
对比原生实现，感受简洁性的差异
"""
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain_core.messages import HumanMessage

# ============================================================
# 第一步：用@tool装饰器定义工具（比手写JSON Schema简洁10倍）
# ============================================================

@tool
def search_documents(query: str, top_k: int = 3, doc_type: str = "all") -> dict:
    """在知识库中搜索相关文档。当用户询问文档内容、需要查找特定信息时使用。
    
    Args:
        query: 搜索查询关键词
        top_k: 返回结果数量，默认3
        doc_type: 文档类型过滤 (pdf/markdown/docx/all)
    """
    mock_docs = [
        {"title": "Agent架构设计指南", "content": "Agent由LLM、Memory、Tools三部分组成...", "score": 0.95},
        {"title": "ReAct模式详解", "content": "ReAct是推理与行动交替进行的模式...", "score": 0.88},
        {"title": "LangChain快速入门", "content": "LangChain是一个用于构建LLM应用的框架...", "score": 0.82},
    ]
    return {"status": "success", "results": mock_docs[:top_k], "count": len(mock_docs[:top_k])}


@tool
def calculate(expression: str, precision: int = 2) -> dict:
    """执行数学计算。用于数值计算、统计分析等场景。
    
    Args:
        expression: 数学表达式，如 '2 + 3 * 4'
        precision: 小数精度，默认2位
    """
    try:
        allowed_names = {"abs": abs, "round": round, "min": min, "max": max, "sum": sum}
        result = eval(expression, {"__builtins__": {}}, allowed_names)
        return {"status": "success", "expression": expression, "result": round(result, precision)}
    except Exception as e:
        return {"status": "error", "error": str(e)}


# 工具列表
tools = [search_documents, calculate]

# ============================================================
# 第二步：创建LLM并绑定工具
# ============================================================

llm = ChatOpenAI(model="gpt-4o", temperature=0)

# bind_tools() 自动将@tool的docstring转换为JSON Schema
# 这相当于原生实现中手写TOOL_SCHEMAS + 传tools参数
llm_with_tools = llm.bind_tools(tools)

# ============================================================
# 第三步：调用（LLM自动决定是否使用工具）
# ============================================================

# 测试1：需要工具
response = llm_with_tools.invoke([HumanMessage(content="帮我搜索Agent架构的文档")])
print(f"回复内容: {response.content}")
print(f"工具调用: {response.tool_calls}")
# tool_calls是一个列表，每个元素包含 name, args, id

# 测试2：不需要工具
response2 = llm_with_tools.invoke([HumanMessage(content="你好")])
print(f"回复内容: {response2.content}")
print(f"工具调用: {response2.tool_calls}")  # 空列表
```

### LangChain做了什么？

对比原生实现，LangChain帮我们做了这些事：

| 原生实现 | LangChain |
| --------- | ----------- |
| 手写JSON Schema | `@tool`装饰器自动从docstring生成 |
| 手动`json.loads(arguments)` | `tool_calls`直接返回解析好的dict |
| 手动管理`tool_call_id` | 自动管理 |
| 手动检查`tool_calls`是否存在 | `response.tool_calls`列表（空=没有调用） |
| 手动构建ToolMessage | `ToolMessage`类自动构建 |

但**底层原理完全一样**。LangChain只是在协议层做了封装，核心的"循环调用"逻辑是不变的。

## 14.6 并行工具调用（Parallel Tool Calls）

从GPT-4开始，模型支持在一个回复中同时请求多个工具调用。这就像你同时让两个助手去做不同的事，而不是让一个助手做完一件再做另一件。

```python
"""
并行工具调用示例
模型一次请求多个工具，我们可以并行执行它们
"""
import json
from openai import OpenAI

client = OpenAI()

# 复用之前的工具定义
tools = [
    {
        "type": "function",
        "function": {
            "name": "search_documents",
            "description": "搜索文档",
            "parameters": {
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "搜索关键词"}
                },
                "required": ["query"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "calculate",
            "description": "数学计算",
            "parameters": {
                "type": "object",
                "properties": {
                    "expression": {"type": "string", "description": "数学表达式"}
                },
                "required": ["expression"]
            }
        }
    }
]


def execute_parallel_tool_calls(tool_calls):
    """
    并行执行多个工具调用
    在实际应用中，如果工具涉及IO操作（数据库查询、API调用），
    并行执行可以显著减少延迟
    """
    results = []
    
    # 这里用线程池实现并行（也可以用asyncio）
    from concurrent.futures import ThreadPoolExecutor
    
    def execute_single(tool_call):
        name = tool_call.function.name
        args = json.loads(tool_call.function.arguments)
        # 实际执行逻辑...
        return {
            "tool_call_id": tool_call.id,
            "result": f"执行 {name}({args}) 的结果"
        }
    
    with ThreadPoolExecutor(max_workers=len(tool_calls)) as executor:
        futures = [executor.submit(execute_single, tc) for tc in tool_calls]
        results = [f.result() for f in futures]
    
    return results


# 触发并行调用的提示词
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "你是DocMind助手。"},
        {"role": "user", "content": "帮我同时搜索Agent架构和ReAct模式的文档，另外算一下 256 * 512"}
    ],
    tools=tools,
    # parallel_tool_calls=True 是默认行为
    # 如果你想禁用并行调用，可以设置：
    # parallel_tool_calls=False
)

message = response.choices[0].message
if message.tool_calls:
    print(f"模型请求了 {len(message.tool_calls)} 个并行工具调用:")
    for tc in message.tool_calls:
        print(f"  - {tc.function.name}({tc.function.arguments})")
```

### 什么时候该禁用并行调用？

```python
# 场景1：工具有依赖关系
# 如果工具B需要工具A的结果作为输入，必须串行
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    tools=tools,
    parallel_tool_calls=False  # 强制串行
)

# 场景2：工具有副作用
# 如果两个工具同时写同一个文件，并行可能导致冲突
```

> ⚠️ **并行调用的陷阱**：当工具之间有依赖关系或共享状态时，并行执行可能导致竞态条件。比如同时调用"读取文件"和"写入文件"——读到的可能是写了一半的内容。

## 14.7 错误处理：工具执行失败时的Agent行为

工具调用不总是成功的。数据库可能宕机、API可能超时、参数可能不合法。一个健壮的Agent需要优雅处理这些失败。

### 14.7.1 三种错误处理策略

```python
def execute_tool_with_error_handling(tool_call, max_retries: int = 2):
    """
    带错误处理的工具执行
    策略优先级：重试 -> 返回错误信息让Agent自行处理
    """
    function_name = tool_call.function.name
    function_args = json.loads(tool_call.function.arguments)
    
    for attempt in range(max_retries + 1):
        try:
            if function_name not in TOOL_REGISTRY:
                # 工具不存在——这种错误重试也没用
                return {
                    "status": "error",
                    "error_type": "tool_not_found",
                    "error": f"工具 '{function_name}' 不存在。可用工具: {list(TOOL_REGISTRY.keys())}"
                }
            
            result = TOOL_REGISTRY[function_name](**function_args)
            
            # 检查工具自身返回的错误
            if isinstance(result, dict) and result.get("status") == "error":
                if attempt < max_retries:
                    print(f"  工具返回错误，重试中... ({attempt + 1}/{max_retries})")
                    continue
                # 重试耗尽，返回错误让Agent处理
                return result
            
            return result
            
        except TypeError as e:
            # 参数类型错误——重试也没用，需要模型调整参数
            return {
                "status": "error",
                "error_type": "invalid_arguments",
                "error": f"参数错误: {str(e)}。请检查参数类型和格式。"
            }
        except Exception as e:
            if attempt < max_retries:
                print(f"  执行异常，重试中... ({attempt + 1}/{max_retries})")
                continue
            return {
                "status": "error",
                "error_type": "execution_error",
                "error": f"执行失败: {str(e)}"
            }
    
    return {"status": "error", "error": "未知错误"}
```

### 14.7.2 让Agent从错误中恢复

关键在于：**把错误信息也返回给模型**。聪明的模型会根据错误信息调整策略。

```python
def agent_loop_with_error_handling(user_message: str, max_iterations: int = 8):
    """
    带错误处理的Agent循环
    注意max_iterations增加了——因为错误重试会消耗迭代次数
    """
    messages = [
        {"role": "system", "content": (
            "你是DocMind智能文档助手。\n"
            "如果工具调用失败，请根据错误信息调整策略：\n"
            "- 如果参数错误，修正参数后重试\n"
            "- 如果工具不可用，尝试用其他工具完成任务\n"
            "- 如果实在无法完成，如实告知用户\n"
        )},
        {"role": "user", "content": user_message}
    ]
    
    for iteration in range(max_iterations):
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=TOOL_SCHEMAS,
            tool_choice="auto"
        )
        
        assistant_message = response.choices[0].message
        messages.append(assistant_message)
        
        if not assistant_message.tool_calls:
            return assistant_message.content
        
        for tool_call in assistant_message.tool_calls:
            result = execute_tool_with_error_handling(tool_call)
            
            tool_message = {
                "role": "tool",
                "tool_call_id": tool_call.id,
                # 即使结果包含错误，也原样返回给模型
                # 模型会阅读错误信息并决定下一步
                "content": json.dumps(result, ensure_ascii=False)
            }
            messages.append(tool_message)
    
    return "达到最大迭代次数。"
```

### 14.7.3 错误处理的三种模式

| 模式 | 触发条件 | Agent行为 |
| ------ | --------- | ----------- |
| 重试 | 临时性错误（网络超时） | 用相同参数重新调用 |
| 换工具 | 工具不可用/不支持 | 用替代工具完成任务 |
| 告知用户 | 无法恢复的错误 | 如实报告问题，建议用户操作 |

```python
# 示例：模型看到错误后自动换策略
# 第一轮：模型调用 search_documents(query="Agent", doc_type="pdf")
# 工具返回：{"status": "error", "error": "PDF解析服务不可用"}
# 第二轮：模型看到错误，改为 search_documents(query="Agent", doc_type="markdown")
# 工具返回：{"status": "success", "results": [...]}
# 第三轮：模型给出最终回答
```

> ⚠️ **重要原则**：永远把错误信息返回给模型，而不是抛异常或静默吞掉。模型比你想象的更善于处理错误——给它信息，它就能做出更好的决策。

## 14.8 Anthropic的Tool Use协议对比

OpenAI不是唯一的选择。Anthropic的Claude也支持工具调用，协议略有不同：

```python
"""
Anthropic Tool Use 协议示例
注意与OpenAI的差异
"""
import anthropic

client = anthropic.Anthropic()

# Anthropic的工具定义格式（本质也是JSON Schema，但包装方式不同）
tools = [
    {

        "description": "在知识库中搜索相关文档",
        "input_schema": {  # 注意是input_schema，不是parameters
            "type": "object",
            "properties": {
                "query": {"type": "string", "description": "搜索关键词"},
                "top_k": {"type": "integer", "description": "返回数量", "default": 3}

            "required": ["query"]
        }
    }
]

response = client.messages.create(
    model="claude-sonnet-4-20250514",

    system="你是DocMind智能文档助手。",
    tools=tools,
    messages=[
        {"role": "user", "content": "搜索Agent架构的文档"}
    ]
)

# Anthropic的响应处理方式不同
for block in response.content:
    if block.type == "text":
        print(f"文本回复: {block.text}")
    elif block.type == "tool_use":
        print(f"工具调用: {block.name}")
        print(f"参数: {block.input}")  # 注意是input，不是arguments
        print(f"ID: {block.id}")
        
        # 返回工具结果
        tool_result_message = {
            "role": "user",  # Anthropic用user角色返回工具结果！
            "content": [
                {
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": json.dumps({"results": [...]})
                }
            ]
        }
```

### 关键差异对比

| 特性 | OpenAI | Anthropic |
| ------ | -------- | ----------- |
| 工具定义嵌套 | `function.name` | `name` |
| 参数Schema键 | `parameters` | `input_schema` |
| 工具调用参数 | `function.arguments` | `input` |
| 工具结果角色 | `role: "tool"` | `role: "user"` + `tool_result` |
| 并行调用 | `parallel_tool_calls`参数 | 默认支持 |

> 好消息是：**LangChain帮你抹平了这些差异**。用LangChain的`@tool`装饰器定义一次工具，就能同时用于OpenAI和Anthropic的模型。

## 14.9 实操：让DocMind通过Function Calling调用工具

现在，让我们把本章所学整合到DocMind项目中：

```python
"""
DocMind - Function Calling实战
整合Ch12创建的Tools，通过Function Calling协议让Agent调用
"""
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain_core.messages import HumanMessage, SystemMessage, ToolMessage
from typing import Optional
import json

# ============================================================
# DocMind工具集（基于Ch12的Tools改进）
# ============================================================

@tool
def search_documents(query: str, top_k: int = 3) -> dict:
    """在DocMind知识库中搜索相关文档。
    当用户询问文档内容、需要查找特定信息、或需要引用文档时使用此工具。
    
    Args:
        query: 搜索查询关键词，应该是具体的技术概念或问题
        top_k: 返回的文档数量，默认3
    """
    # 模拟向量数据库搜索结果
    # 实际项目中这里会调用embedding模型 + 向量数据库
    knowledge_base = {
        "agent": [
            {"title": "Agent架构概述",
             "content": "AI Agent由三部分组成：LLM（大脑）、Memory（记忆）、Tools（能力）。",
             "relevance": 0.95},
            {"title": "Agent设计模式",
             "content": "常见模式：ReAct、Plan-and-Execute、Multi-Agent。",
             "relevance": 0.88},
        ],
        "langchain": [
            {"title": "LangChain核心概念",
             "content": "LangChain提供Model I/O、Chains、Agents、Memory等核心模块。",
             "relevance": 0.92},
            {"title": "LangChain工具系统",
             "content": "通过@tool装饰器快速定义工具，自动转换为JSON Schema。",
             "relevance": 0.85},
        ],
        "rag": [
            {"title": "RAG原理",
             "content": "RAG通过检索外部知识增强LLM生成能力，解决幻觉问题。",
             "relevance": 0.94},
            {"title": "RAG优化策略",
             "content": "查询改写、多路召回、重排序(Reranking)、上下文压缩。",
             "relevance": 0.87},
        ]
    }
    
    # 简单的关键词匹配（实际项目用向量相似度）
    results = []
    query_lower = query.lower()
    for key, docs in knowledge_base.items():
        if key in query_lower or any(k in query_lower for k in knowledge_base):
            results.extend(docs[:top_k])
    
    if not results:
        results = [{"title": "无匹配结果", "content": f"未找到与'{query}'相关的文档", "relevance": 0}]
    
    return {"results": results[:top_k], "total": len(results)}


@tool
def calculate(expression: str, precision: int = 2) -> dict:
    """执行数学计算。当需要计算数值、比例、统计量时使用。
    
    Args:
        expression: Python数学表达式，如 '(100 - 30) / 100 * 100'
        precision: 结果的小数位数，默认2
    """
    try:
        safe_builtins = {"abs": abs, "round": round, "min": min, "max": max, "sum": sum, "pow": pow}
        result = eval(expression, {"__builtins__": safe_builtins}, {})
        return {"expression": expression, "result": round(float(result), precision)}
    except Exception as e:
        return {"error": f"计算失败: {str(e)}", "suggestion": "请检查表达式语法"}


@tool
def get_word_count(text: str) -> dict:
    """统计文本的字数、行数等基本信息。
    
    Args:
        text: 需要统计的文本内容
    """
    chars = len(text)
    words = len(text.split())
    lines = len(text.split('\n'))
    return {
        "characters": chars,
        "words": words,
        "lines": lines,
        "estimated_reading_time_minutes": round(words / 200, 1)
    }


# ============================================================
# DocMind Agent核心
# ============================================================

class DocMindAgent:
    """DocMind智能文档问答Agent"""
    
    def __init__(self, model_name: str = "gpt-4o"):
        self.llm = ChatOpenAI(model=model_name, temperature=0)
        self.tools = [search_documents, calculate, get_word_count]
        self.llm_with_tools = self.llm.bind_tools(self.tools)
        
        # 工具注册表
        self.tool_map = {t.name: t for t in self.tools}
        
        self.system_prompt = """你是DocMind——一个智能文档问答助手。

你的职责：
1. 帮助用户搜索和理解文档内容
2. 进行必要的数学计算
3. 提供准确、有依据的回答

工作原则：
- 优先使用search_documents查找相关信息，不要凭空编造
- 如果搜索结果不足以回答问题，如实告知用户
- 需要计算时使用calculate工具，不要心算
- 回答要简洁清晰，使用中文
"""
    
    def run(self, user_input: str, max_iterations: int = 5, verbose: bool = True) -> str:
        """
        执行Agent循环
        
        Args:
            user_input: 用户输入
            max_iterations: 最大迭代次数
            verbose: 是否打印执行过程
        """
        messages = [
            SystemMessage(content=self.system_prompt),
            HumanMessage(content=user_input)
        ]
        
        if verbose:
            print(f"\n{'='*60}")
            print(f"DocMind | 用户: {user_input}")
            print(f"{'='*60}")
        
        for i in range(max_iterations):
            # 调用LLM
            response = self.llm_with_tools.invoke(messages)
            messages.append(response)
            
            if verbose:
                if response.tool_calls:
                    for tc in response.tool_calls:
                        print(f"  调用工具: {tc['name']}({tc['args']})")
                else:
                    print(f"  回答: {response.content}")
            
            # 检查是否结束
            if not response.tool_calls:
                return response.content
            
            # 执行工具
            for tool_call in response.tool_calls:
                tool_name = tool_call["name"]
                tool_args = tool_call["args"]
                
                if tool_name in self.tool_map:
                    try:
                        result = self.tool_map[tool_name].invoke(tool_args)
                        tool_message = ToolMessage(
                            content=json.dumps(result, ensure_ascii=False),
                            tool_call_id=tool_call["id"]
                        )
                    except Exception as e:
                        tool_message = ToolMessage(
                            content=json.dumps({"error": str(e)}, ensure_ascii=False),
                            tool_call_id=tool_call["id"]
                        )
                else:
                    tool_message = ToolMessage(
                        content=json.dumps({"error": f"未知工具: {tool_name}"}, ensure_ascii=False),
                        tool_call_id=tool_call["id"]
                    )
                
                messages.append(tool_message)
        
        return "抱歉，处理您的请求时遇到了问题，请尝试简化问题后重试。"


# ============================================================
# 测试DocMind Agent
# ============================================================

if __name__ == "__main__":
    agent = DocMindAgent()
    
    # 测试1：文档搜索
    print("\n" + "="*60)
    print("测试1: 文档搜索")
    agent.run("什么是AI Agent？它由哪些部分组成？")
    
    # 测试2：计算
    print("\n" + "="*60)
    print("测试2: 数学计算")
    agent.run("知识库有10000篇文档，检索top-5召回率85%，大概有多少相关文档未被检索到？")
    
    # 测试3：多工具串联
    print("\n" + "="*60)
    print("测试3: 多步推理")
    agent.run("帮我查找RAG优化的方法，然后统计一下找到的方法名称数量")
    
    # 测试4：直接回答
    print("\n" + "="*60)
    print("测试4: 闲聊")
    agent.run("你好！你是谁？")
```

## 14.10 本章小结

本章我们深入学习了Function Calling——Agent与工具对话的"协议层"：

1. **为什么需要Function Calling**：从正则解析的"蛮力时代"到结构化协议的演进，解决了LLM输出格式不可靠的核心问题
2. **协议详解**：JSON Schema定义工具 -> 模型返回tool_calls -> 执行并返回ToolMessage
3. **原生实现**：不依赖框架的完整实现，理解了底层的每一步
4. **LangChain封装**：`@tool` + `bind_tools()` 大幅简化开发
5. **并行调用**：模型可以同时请求多个工具调用
6. **错误处理**：把错误信息返回给模型，让它自主调整策略
7. **协议对比**：OpenAI vs Anthropic的差异

### 核心要点速记

```
Function Calling = LLM世界的RPC协议
- 你定义"接口"（JSON Schema）
- 模型决定"调用"（tool_calls）
- 你负责"执行"（实际运行函数）
- 你反馈"结果"（ToolMessage）
- 模型生成"回答"（最终文本）
```
