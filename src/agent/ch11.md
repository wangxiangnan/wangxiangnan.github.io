# 第11章：LCEL —— LangChain的声明式编排核心

> [!TIP] Part 4: 装备升级 —— LangChain开发基础（基础篇）
> 上一章把地基打好，本 Part 进入 LangChain 核心抽象的正题。本章先拿下第一个、也是最关键的一个：LCEL（LangChain Expression Language，LangChain 表达式语言）——学会它，后面所有组件都能用同一种"管道语法"串起来。

## 为什么要学LCEL？

本章管编排——把"调用模型"这件手工作业，升级成一条可组合、可流式、可重试的声明式（Declarative）管道。手工作业到底有多亏？先看 DocMind 的一组真实数字：RAG 主链上线第一周跑了约 2000 次调用，DeepSeek 偶发 429 限流导致失败 60 次（失败率 3%）；手写重试要自己维护计数器和退避时间，而 LCEL 一行 `.with_retry(stop_after_attempt=3)` 就把失败率压到 0.1% 以下。同一个链，手写版每加一个能力（流式、重试、异步）都要改一遍函数，LCEL 版只多挂一个方法。

如果你对 Unix 管道不陌生，你会秒懂 LCEL：

```bash
# Unix管道
cat file.txt | grep "error" | sort | uniq -c

# LCEL
prompt | llm | output_parser
```

同一个"检索→填模板→调模型→解析"的流程，两种写法的差别：

```python
# 反例：手写编排——能力每加一个，函数就得改一遍
def ask(question: str) -> str:
    messages = prompt.format_messages(question=question)  # 手动填模板
    response = llm.invoke(messages)                       # 手动调用
    return parser.parse(response)                         # 手动解析
# 产品说"加流式"：自己攒 chunk 拼缓冲
# 产品说"限流要重试"：自己写 try/except + sleep
# 产品说"Web 后台要异步"：从头再抄一套 async 版

# 正例：LCEL 管道——同一条链，流式、重试、异步全是免费附赠
chain = prompt | llm | parser
chain.stream({"question": "..."})             # 流式
chain.with_retry(stop_after_attempt=3)        # 重试
await chain.ainvoke({"question": "..."})      # 异步
```

两种写法的差距可以量化成一张表（同一个 RAG 主链，产品迭代三轮后）：

| 能力 | 手写编排 | LCEL 管道 |
| ------ | ------ | ------ |
| 流式输出 | 自己攒 chunk 拼缓冲，约 30 行 | `.stream()` 直接可用，0 行 |
| 异步版 | 再抄一套 async 函数 | `ainvoke`/`astream` 免费获得 |
| 失败重试 | 手写 try/except + 退避，约 20 行 | `.with_retry()` 一行 |
| 换模型 | 改函数内部实现 | 换一个对象，管道不动 |
| 批量并发 | 自己管线程/事件循环 | `.batch()`/`.abatch()` 直接用 |

核心理念：**每个 LangChain 组件都是 Runnable**，统一接口，管道串联。它解决的痛点正是上面这些：代码冗长、流式输出困难、错误处理繁琐、异步支持不一致。

回扣第1章：Agent 对象的 `run()` 方法内部，数据是这样流动的：`用户输入 → think() → call_tool() → 更新 messages → 再 think()`。LCEL 就是让你用 `|` 管道运算符声明这条数据流，而不是手写一堆变量赋值和函数调用。如果说第1章的 `run()` 是"命令式"写法，LCEL 就是同样逻辑的"声明式"写法。

> [!WARNING] 先猜再读
> - 先猜一猜：`prompt | llm | parser` 里的 `|` 是 LangChain 发明的特殊语法吗？——不是，它是 Python 原生的运算符重载，组件实现了 `__or__`，管道拼出来的还是一个 Runnable（见 11.2）。
> - 多数人以为组件拼成链后就"失去了"单个组件的能力，其实链本身仍是 Runnable——`stream`、`ainvoke`、`with_retry` 全部继承（见 11.1）。
> - 先猜一猜：RunnableParallel 的多路检索是排队执行还是同时执行？——同时执行，总耗时约等于最慢的那一路（见 11.3）。

## 11.1 核心概念：Runnable接口

```python
class Runnable:
    """所有LangChain组件的统一接口"""
    def invoke(self, input): ...     # 同步调用
    def batch(self, inputs): ...     # 批量调用
    def stream(self, input): ...     # 流式调用
    async def ainvoke(self, input): ...   # 异步
    async def astream(self, input): ...   # 异步流式
```

精妙之处：组合后的链仍是 Runnable。像乐高——不管怎么拼，最终还是一个整体。而且这个接口无处不在：模型、提示模板、输出解析器、检索器，全都实现了 Runnable，所以它们之间可以任意拼接。

## 11.2 管道操作符

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

llm = ChatOpenAI(model="deepseek-chat")
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是技术文档助手。"),
    ("human", "{question}")
])
parser = StrOutputParser()

chain = prompt | llm | parser

# 同步调用
result = chain.invoke({"question": "什么是LCEL？"})

# 流式调用
for chunk in chain.stream({"question": "解释Python的GIL"}):
    print(chunk, end="", flush=True)
```

数据流动：

```
{"question": "..."} → prompt → ChatPromptValue → llm → AIMessage → parser → "纯文本"
```

`|` 之所以能用在组件上，是因为每个 Runnable 都实现了 Python 的 `__or__` 运算符重载——`prompt | llm` 返回的仍是一个 Runnable 对象，所以才能继续接 `| parser`。

这条"三件套"链是本章的主角：后面小节出现的 `chain`、`prompt`、`llm`、`parser` 都指这里定义的这几个对象。

## 11.3 关键Runnable组件

五个工具组件负责补齐管道里"模型干不了"的杂活——透传、转换、并行、分支、回退。先用一张表总览，再逐个看：

| 组件 | 一句话作用 | Unix 类比 |
| ------ | ------ | --------- |
| RunnablePassthrough | 输入原样透传 | cat |
| RunnableLambda | 把任意 Python 函数接入管道 | awk / sed |
| RunnableParallel | 一次输入并行跑多路 | & 后台并行 |
| RunnableBranch | 按条件选分支执行 | if-else |
| with_fallbacks / with_retry | 失败回退 / 失败重试 | \|\| 与 while 循环 |

### 11.3.1 RunnablePassthrough：透传数据

先定义一个本章反复复用的示意检索器（向量库的完整教学在第22-23章，这里用假数据代替）：

```python
from langchain_core.documents import Document
from langchain_core.runnables import RunnableLambda

# 示意变量：输入问题字符串、返回文档列表的检索器
def fake_retriever(question: str) -> list:
    """示意检索器，真实实现见第22-23章"""
    return [Document(page_content="DocMind 的示意文档内容", metadata={"source": "demo"})]

retriever = RunnableLambda(fake_retriever)
```

有了它，经典的 RAG 组合就能跑起来：

```python
from langchain_core.runnables import RunnablePassthrough

chain = (
    {"context": retriever, "question": RunnablePassthrough()}
    | prompt | llm | parser
)
# question原样传递，context由retriever获取
```

### 11.3.2 RunnableLambda：自定义转换

```python
from langchain_core.runnables import RunnableLambda


def format_docs(docs: list) -> str:
    """格式化检索文档"""
    return "\n\n".join([
        f"[文档{i+1}] {d.metadata.get('source','?')}\n{d.page_content}"
        for i, d in enumerate(docs)
    ])


chain = (
    {"context": retriever | RunnableLambda(format_docs), 
     "question": RunnablePassthrough()}
    | prompt | llm | parser
)
```

### 11.3.3 RunnableParallel：并行执行

```python
from langchain_core.runnables import RunnableParallel, RunnablePassthrough

# 示意变量：第二路检索，用字符串匹配模拟关键词检索
keyword_retriever = RunnableLambda(
    lambda q: [Document(page_content=f"关键词命中：{q}", metadata={"source": "keyword"})]
)

def merge_results(data: dict) -> str:
    """合并两路检索结果为一段上下文"""
    docs = data["vector_search"] + data["keyword_search"]
    return "\n".join(d.page_content for d in docs)

parallel = RunnableParallel(
    vector_search=retriever,
    keyword_search=keyword_retriever,
    original_query=RunnablePassthrough()
)

chain = parallel | RunnableLambda(merge_results) | prompt | llm | parser
```

三路同时开跑：`vector_search` 和 `keyword_search` 并行执行，`original_query` 立刻返回，总耗时约等于最慢的那一路。

### 11.3.4 RunnableBranch：条件分支

```python
from langchain_core.runnables import RunnableBranch

# 示意变量：路由分类器与三条回答链（真实分类器见第17章 Function Calling）
classify = RunnableLambda(
    lambda q: {"type": "technical", "question": q} if "代码" in q
    else {"type": "general", "question": q}
)

technical_chain = (
    ChatPromptTemplate.from_template("你是资深工程师，请严谨回答：{question}")
    | llm | parser
)
general_chain = (
    ChatPromptTemplate.from_template("你是友好助手，请通俗回答：{question}")
    | llm | parser
)
fallback_chain = general_chain  # 兜底也走通用链

branch = RunnableBranch(
    (lambda x: x.get("type") == "technical", technical_chain),
    (lambda x: x.get("type") == "general", general_chain),
    fallback_chain
)
full_chain = classify | branch
```

## 11.4 流式传播

LCEL最强大的特性——LLM每个token实时流经整个链：

```python
llm = ChatOpenAI(model="deepseek-chat", streaming=True)
chain = prompt | llm | parser

print("回答：", end="", flush=True)
for chunk in chain.stream({"question": "详细解释Python装饰器"}):
    print(chunk, end="", flush=True)
print()
```

用户在LLM还在生成时就能看到前几段，体验好太多。以 DocMind 为例：一次回答约 300 token、耗时 8 秒，非流式用户要盯白屏 8 秒；流式下首字 1 秒内就出现，感知等待时间只剩约 1 秒。

## 11.5 异步支持

```python
import asyncio

async def run_async():
    chain = prompt | llm | parser
    
    # 异步调用
    result = await chain.ainvoke({"question": "什么是LCEL？"})
    
    # 异步流式
    async for chunk in chain.astream({"question": "Python异步编程"}):
        print(chunk, end="", flush=True)
    
    # 批量异步（并发）
    questions = [{"question": "什么是Agent？"}, {"question": "什么是RAG？"}]
    results = await chain.abatch(questions)

asyncio.run(run_async())
```

## 11.6 重试和错误处理

```python
from langchain_core.runnables import RunnableConfig

chain = prompt | llm | parser

# 重试
robust = chain.with_retry(stop_after_attempt=3, wait_exponential_jitter=True)

# 回退
fallback_chain = prompt | ChatOpenAI(model="deepseek-chat") | parser
final = robust.with_fallbacks([fallback_chain])

# 配置
config = RunnableConfig(
    max_concurrency=5,
    run_name="docmind_rag",
    tags=["production"]
)
result = final.invoke({"question": "什么是微服务？"}, config=config)
```

这行 `with_retry` 就是本章开头那个 3% 失败率的解药：3 次尝试加指数退避抖动，把偶发限流的损失自动吃掉。

### 11.6.1 高级LCEL模式

前面都是一条管道走到底，真实系统还需要更复杂的玩法：让链根据输入特征自动调整行为、把质量检查做成循环。这一节给两个可以直接抄进项目的高级模式——它们都建立在本章前半的组件之上，只是把"数据怎么流"设计得更讲究。

### 复杂数据流控制

```python
from langchain_core.runnables import (
    RunnablePassthrough, RunnableLambda, RunnableParallel, RunnableBranch
)
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 模块级定义，供本节的多个链复用
answer_prompt = ChatPromptTemplate.from_messages([
    ("system", "基于上下文回答问题。\n上下文：{context}"),
    ("human", "{query}")
])


def build_smart_rag_chain(retriever, llm):
    """智能RAG链：根据查询复杂度选择不同策略"""
    
    def preprocess(query: str) -> dict:
        """预处理：分析查询特征"""
        words = query.split()
        complexity = min(1.0, len(words) / 15)  # 越长越复杂
        has_code = any(kw in query for kw in ["代码", "函数", "class", "def", "import"])
        return {"query": query, "complexity": complexity, "has_code": has_code}
    
    def smart_retrieve(data: dict) -> dict:
        """智能检索：简单查询少检索，复杂查询多检索"""
        query = data["query"]
        k = 5 if data["complexity"] > 0.5 else 3
        docs = retriever.invoke(query)[:k]
        context = "\n\n".join([d.page_content for d in docs])
        return {**data, "context": context, "docs_count": len(docs)}

    chain = (
        RunnableLambda(preprocess)
        | RunnableLambda(smart_retrieve)
        | RunnableLambda(lambda d: {"query": d["query"], "context": d["context"]})
        | answer_prompt
        | llm
        | StrOutputParser()
    )
    return chain
```

### LCEL与LangGraph结合

```python
from langgraph.graph import StateGraph, END
from typing import TypedDict


class QualityState(TypedDict):
    query: str
    context: str
    answer: str
    quality: float


def build_quality_loop(retriever, llm):
    """带质量检查的循环管线"""
    
    retrieve_chain = retriever | RunnableLambda(lambda docs: "\n".join(d.page_content for d in docs))
    answer_chain = answer_prompt | llm | StrOutputParser()
    
    def retrieve_node(state):
        ctx = retrieve_chain.invoke(state["query"])
        return {"context": ctx}
    
    def answer_node(state):
        ans = answer_chain.invoke({"query": state["query"], "context": state["context"]})
        return {"answer": ans}
    
    def quality_node(state):
        score = llm.invoke(f"评分(0-10)：Q:{state['query']}\nA:{state['answer']}").content
        try:
            return {"quality": int(score.strip()) / 10}
        except:
            return {"quality": 0.5}
    
    def route(state):
        return "done" if state["quality"] >= 0.7 else "retry"
    
    def retry_node(state):
        # 用增强策略重新检索
        new_ctx = retriever.invoke(state["query"] + " 详细解释")
        new_ctx = "\n".join(d.page_content for d in new_ctx[:7])
        return {"context": new_ctx}
    
    builder = StateGraph(QualityState)
    builder.add_node("retrieve", retrieve_node)
    builder.add_node("answer", answer_node)
    builder.add_node("quality", quality_node)
    builder.add_node("retry", retry_node)
    builder.set_entry_point("retrieve")
    builder.add_edge("retrieve", "answer")
    builder.add_edge("answer", "quality")
    builder.add_conditional_edges("quality", route, {"done": END, "retry": "retry"})
    builder.add_edge("retry", "answer")
    return builder.compile()
```

这里只需要感受"LCEL 链可以嵌进图节点"这件事；状态图、条件边、循环回跳的完整语法在第18章 LangGraph 才正式展开。

### 流式处理完整示例

```python
import asyncio
import time


async def stream_with_metrics(chain, input_data):
    """带性能指标的流式输出"""
    start = time.time()
    tokens = 0
    chunks = 0
    
    async for chunk in chain.astream(input_data):
        tokens += len(chunk.split())
        chunks += 1
        elapsed = time.time() - start
        
        yield {
            "content": chunk,
            "tokens": tokens,
            "chunks": chunks,
            "elapsed_ms": round(elapsed * 1000, 1),
            "tokens_per_sec": round(tokens / max(elapsed, 0.01), 1)
        }


async def demo():
    from langchain_openai import ChatOpenAI
    from langchain_core.prompts import ChatPromptTemplate
    from langchain_core.output_parsers import StrOutputParser

    prompt = ChatPromptTemplate.from_messages([
        ("system", "你是技术文档助手。"),
        ("human", "{question}")
    ])
    chain = prompt | ChatOpenAI(model="deepseek-chat", streaming=True) | StrOutputParser()
    
    last = None
    async for item in stream_with_metrics(chain, {"question": "解释量子计算"}):
        print(item["content"], end="", flush=True)
        last = item
    
    print(f"\n\nTokens: {last['tokens']}, 耗时: {last['elapsed_ms']}ms")
    print(f"速度: {last['tokens_per_sec']} tokens/sec")
```

在使用LCEL时，遵循以下最佳实践可以让你的代码更健壮：

        ("system", "基于上下文回答问题。\n上下文：{context}"),

        RunnableParallel(
            context=(retriever | format_docs),

    if output_format == "markdown":

    elif output_format == "json":

## 11.7 实操：用LCEL重构DocMind

先说明一点：这段代码直接用到了 Chroma 向量库和 `as_retriever()`——向量库的完整教学在第22-23章，此处仅作管道末端示意。重点看 `DocMindLCEL` 如何用本章的管道语法，把检索、模板、模型、解析器组装成一条带重试回退的主链：

```python
"""DocMind RAG管线 — LCEL版本"""

from langchain_openai import ChatOpenAI
from langchain_community.vectorstores import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import (
    RunnablePassthrough, RunnableLambda, RunnableParallel
)


class DocMindLCEL:
    def __init__(self, vectorstore: Chroma):
        self.llm = ChatOpenAI(model="deepseek-chat", temperature=0, streaming=True)
        self.fast_llm = ChatOpenAI(model="deepseek-chat", temperature=0)
        self.retriever = vectorstore.as_retriever(search_kwargs={"k": 5})
        self._build_chains()
    
    def _build_chains(self):
        self.format_docs = RunnableLambda(self._format_docs)
        self.answer_prompt = ChatPromptTemplate.from_messages([
            ("system", "你是DocMind。基于上下文回答问题。不足则说明。\n上下文：{context}"),
            ("human", "{question}")
        ])
        
        # 主链
        self.main_chain = (
            RunnableParallel(
                context=(self.retriever | self.format_docs),
                question=RunnablePassthrough()
            ) | self.answer_prompt | self.llm | StrOutputParser()
        )
        
        # 回退链
        fallback = (
            RunnableParallel(
                context=(self.retriever | self.format_docs),
                question=RunnablePassthrough()
            ) | self.answer_prompt | self.fast_llm | StrOutputParser()
        )
        self.robust_chain = self.main_chain.with_retry(
            stop_after_attempt=3
        ).with_fallbacks([fallback])
    
    def _format_docs(self, docs: list) -> str:
        if not docs:
            return "（无相关文档）"
        return "\n---\n".join([
            f"[{i+1}] {d.metadata.get('source','?')}\n{d.page_content}"
            for i, d in enumerate(docs)
        ])
    
    def ask(self, question: str) -> str:
        return self.robust_chain.invoke(question)
    
    def ask_stream(self, question: str):
        for chunk in self.main_chain.stream(question):
            yield chunk
    
    async def ask_async(self, question: str) -> str:
        return await self.robust_chain.ainvoke(question)
    
    def ask_batch(self, questions: list) -> list:
        return self.robust_chain.batch(questions)
    
    def ask_with_sources(self, question: str) -> dict:
        chain = RunnableParallel(answer=self.robust_chain, docs=self.retriever)
        result = chain.invoke(question)
        return {
            "answer": result["answer"],
            "sources": [{"source": d.metadata.get("source",""), "preview": d.page_content[:100]}
                        for d in result["docs"]]
        }
```

注意一个设计细节：`ask` 走带重试回退的 `robust_chain`，`ask_stream` 却走不带重试的 `main_chain`——因为流式场景下重试会导致已输出的内容重复，宁可让首 token 快，也不要让用户看到重复段落。

## 本章小结

- 所有组件都是 Runnable——invoke、batch、stream、ainvoke、astream 五种调用方式全组件通用，这是管道串联的前提。
- `|` 是 Python 运算符重载：组件拼成链，链还是 Runnable，stream、重试、异步等能力全部继承。
- 五大工具组件各管一件事：Passthrough 透传、Lambda 包函数、Parallel 并行、Branch 分支、with_fallbacks 回退。
- 流式传播是 LCEL 最大的红利：LLM 的每个 token 实时流经整条链，用户从盯白屏变成秒见首字。
- 异步不需要重写代码：把 invoke 换成 ainvoke、stream 换成 astream 即可，批量并发交给 abatch。
- 线上调用不裸奔：with_retry 吃掉限流抖动，with_fallbacks 兜住模型不可用，RunnableConfig 控并发并打标追踪。
- DocMind 主链由 RunnableParallel + 模板 + 模型 + 解析器组装而成，5 个 ask 接口共用一条管道，流式与可靠性的取舍各有分工。
