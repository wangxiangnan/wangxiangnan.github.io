## 3.1 安装与密钥生成

登入服务器（Ubuntu 22.04/24.04 或 Debian 12），安装包：

```text
$ sudo apt update && sudo apt install -y wireguard
```

内核 5.6+ 自带 WireGuard 模块，所以装的这个包主要是 `wg`、`wg-quick` 两个工具（1.4 介绍过族谱）。装完确认版本：

```text
$ wg --version
wireguard-tools v1.0.20210914
```

然后生成服务器密钥对。先收紧 umask 再生成，保证私钥文件落盘就是 `600` 权限：

```text
$ umask 077
$ mkdir -p /etc/wireguard/clients
$ cd /etc/wireguard
$ wg genkey | tee server_private.key | wg pubkey > server_public.key
$ cat server_public.key
k5S+1xDqB0dJ8YqFzX9v...(43 字符 base64，尾部一个 =)
```

锚点文件布局现在成型，全书不再变：

| 文件 | 内容 | 权限 |
| ---- | ---- | ---- |
| /etc/wireguard/server_private.key | 服务器私钥，永不外传 | 600 |
| /etc/wireguard/server_public.key | 服务器公钥，发给每个客户端 | 644 即可 |
| /etc/wireguard/clients/ | 各客户端的密钥与 conf（第四、五章使用） | 目录 700 |

> 私钥纪律重复一遍 1.4 的约定：私钥不出服务器，`server_public.key` 那一行的内容才是发给客户端的东西。第五章的脚本会自动维护这个纪律。

## 3.2 wg0.conf 解剖

创建 `/etc/wireguard/wg0.conf`——全书最重要的一张文件：

```ini
[Interface]
# 本机（网关）在 VPN 网段里的地址
Address = 10.66.66.1/24
# 监听端口：公网 UDP 流量从这进（3.6 还要在安全组放行）
ListenPort = 51820
# 服务器私钥：用文件内容填入
PrivateKey = k5S...(server_private.key 的内容)
# MTU：1500 减去外层封装开销（约 80 字节）的安全值，防分片
MTU = 1420
# 接口起来时加转发规则、down 时移除（3.4 详解）
PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; iptables -A FORWARD -o wg0 -m state --state ESTABLISHED,RELATED -j ACCEPT; iptables -t nat -A POSTROUTING -o ens3 -j MASQUERADE
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT; iptables -D FORWARD -o wg0 -m state --state ESTABLISHED,RELATED -j ACCEPT; iptables -t nat -D POSTROUTING -o ens3 -j MASQUERADE

# 客户端 Peer 段在 3.7 添加
```

[Interface] 段各字段的意义：

| 字段 | 值（锚点） | 说明 |
| ---- | ---- | ---- |
| Address | 10.66.66.1/24 | 服务器在 VPN 网段的地址，也是客户端的 DNS 与默认网关 |
| ListenPort | 51820 | 监听的 UDP 端口 |
| PrivateKey | 私钥内容 | 直接写进文件——这也是 conf 必须 600 权限的原因 |
| MTU | 1420 | 隧道内网卡的传输单元上限；不配则默认 1420，写出来是显式声明 |
| PostUp / PostDown | iptables 规则 | 接口 up/down 时由 wg-quick 代为执行的钩子（3.4 详解） |

注意两点：一是 **PrivateKey 是直接写内容的**，不是文件路径——`wg-quick` 只认内容；二是 `PostUp` 里的 `ens3` 要换成 1.7 探测出来的你自己的外网网卡名，锚点用 `ens3` 只是为了行文统一。

## 3.3 内核转发——sysctl 持久化

为什么 ping 服务器能通、访问服务器背后的服务不通？因为前者是「包到达目的地」，后者要求「服务器替你把包再转出去」——Linux 默认**关闭** IP 转发（IP Forwarding），收到的、目标不是自己的包会被直接丢弃。

打开它。不直接改 `/etc/sysctl.conf`，而是新建独立文件，方便管理也不怕升级覆盖：

**命令格式**：`sysctl [OPTIONS] [VARIABLE=VALUE]...`

```text
$ cat > /etc/sysctl.d/99-wireguard.conf <<'EOF'
net.ipv4.ip_forward = 1
EOF
$ sysctl -p /etc/sysctl.d/99-wireguard.conf
net.ipv4.ip_forward = 1
```

`sysctl -p <文件>` 立即生效并回显，重启后 `systemd-sysctl` 也会自动加载 `/etc/sysctl.d/` 下的所有文件——**立即生效与持久化一步到位**。验证用 `sysctl net.ipv4.ip_forward`，期待输出 `= 1`。

> IPv6 场景（客户端要有 IPv6 才需要）：同一文件里加一行 `net.ipv6.conf.all.forwarding = 1`，并把 conf 的 Address 扩成双栈。本书主线只走 IPv4，需要时照此扩展。

## 3.4 NAT 伪装——PostUp 与 iptables

转发开了还不够：客户端的包源地址是 `10.66.66.2`（VPN 网段），服务器把它转发到公网时，对端服务器根本不知道 `10.66.66.x` 是谁、应答也回不来。解法是 NAT 伪装（MASQUERADE）：包从外网网卡出去时，源地址改写成服务器自己的公网出口地址——对内网服务来说，流量都「来自服务器本机」。

回顾 3.2 conf 里的两行钩子（现在可以逐条读了）：

```text
PostUp = iptables -A FORWARD -i wg0 -j ACCEPT                          # 允许隧道进来的包被转发
      + iptables -A FORWARD -o wg0 -m state --state ESTABLISHED,RELATED -j ACCEPT
                                                                        # 允许已建立连接的回程包回来
      + iptables -t nat -A POSTROUTING -o ens3 -j MASQUERADE           # 出公网时改写源地址
PostDown = （同样三条，把 -A 换成 -D：up 时加，down 时删）
```

三条规则各司其职。**注意方向**：第二条特别容易被漏掉——很多发行版的 FORWARD 链默认策略是 DROP（拒绝所有转发），没有这条，去程通了回程被拦，症状恰好是「ping 服务器通、ping 内网不通」的另一半。兑现「先猜再读」第三问：PostUp/PostDown 是成对钩子，`wg-quick down` 会执行 PostDown 移除规则，接口不存在了规则也不留残渣——但前提是你用了这对钩子，手工敲进去的 iptables 规则是不会自己消失的，这正是把规则写进 conf 而不是手敲的理由。

启用 ufw 的读者多一个坑：ufw 会接管 FORWARD 链策略。两个选择——改 `/etc/default/ufw` 里的 `DEFAULT_FORWARD_POLICY` 为 `"ACCEPT"`，或保持 DROP 并追加 `ufw route allow in on wg0`。没启用 ufw 的服务器（多数云主机默认）跳过这段。

写完 conf 先做一次空跑检查，语法错不落库：

**命令格式**：`wg-quick [up|down|save|strip] [INTERFACE]`

```text
$ wg-quick strip wg0    # 去掉 wg-quick 专属字段，输出 wg 可读的裸配置；语法错会在这里报出
```

## 3.5 启动、自启与验证

万事俱备，拉起服务并设开机自启（systemctl 的族谱见 1.4）：

```text
$ systemctl enable --now wg-quick@wg0
$ wg show
interface: wg0
  public key: k5S+1xDqB0dJ8YqFzX9v...
  listening port: 51820
```

`enable --now` 一条命令完成「设自启 + 立即启动」。验证清单按现象分三层：

| 检查 | 命令 | 期待 | 说明 |
| ---- | ---- | ---- | ---- |
| 服务活着 | `systemctl status wg-quick@wg0` | active (exited) | wg-quick 是 oneshot 型服务，exited 是正常态 |
| 网卡存在 | `ip addr show wg0` | inet 10.66.66.1/24 | Address 字段已生效 |
| 端口监听 | `ss -ulnp \| grep 51820` | 有输出 | UDP 无 LISTEN 概念，出现 wg 进程项即可 |
| 密钥与端口 | `wg show` | public key + port | 与 server_public.key 一致 |

`wg show` 里暂时没有 peer 行——因为还没有任何客户端。下一节把第一个对端登记进来。

## 3.6 防火墙与云安全组

最后一个坑留给粗心的人：**通往 51820/udp 的路上有两道门**，任何一道关着，客户端都连不上且症状一模一样（超时）。

- **第一道：服务器系统防火墙**。启用了 ufw/nftables/firewalld 的机器要放行端口，ufw 为例：`sudo ufw allow 51820/udp`。
- **第二道：云安全组**。云厂商在虚拟化层之外还有一层独立防火墙（各家叫法不同：安全组、防火墙规则、网络 ACL），控制台里添加入站规则：协议 UDP、端口 51820、来源 0.0.0.0/0（任意来源——客户端 IP 不固定）。

> [!NOTE]
> 为什么两道都要放？`ListenPort` 只是让服务器进程在 OS 层监听该端口；云安全组在更外层（宿主机/虚拟化网络层）拦截。这是两层独立机制，互不替代。排障口诀记住：**连不上，先查第二道门**——它不在服务器里，最容易被忘。

放行之后可以先用外部机器做一次连通性探测（只验证端口可达，不验证协议）：`nc -zvu 203.0.113.10 51820`，或第四章接上真客户端后看 `wg show` 的握手行。安全组放行是免费操作，但选错协议（TCP 而不是 UDP）是最常见的手滑。

## 3.7 手动接入第一个 peer

服务端就绪，现在登记第一个对端。为了不依赖第四章的客户端，我们先在**服务器本地**生成一对「笔记本」的密钥（它将被发给未来的笔记本设备）：

```text
$ cd /etc/wireguard/clients
$ umask 077
$ wg genkey | tee laptop_private.key | wg pubkey > laptop_public.key
```

把 Peer 段追加进 `/etc/wireguard/wg0.conf`：

```ini
[Peer]
# laptop（笔记本）
PublicKey = 8KxrmP...(laptop_public.key 的内容)
AllowedIPs = 10.66.66.2/32
```

三个字段正是 2.5 讲过的 cryptokey 路由：公钥定身份，`10.66.66.2/32` 圈定这台设备在隧道里**独占**的地址——既是「允许它用 .2 发进来」的白名单，也是「发给 .2 的包走这条隧道」的路由。**地址必须 /32 且互不重叠**：两个 Peer 抢同一地址时，后到的流量会被路由到先到的那条隧道，这类错乱排障极难。

热更新运行中的接口，不必整机重启：

```text
$ wg syncconf wg0 <(wg-quick strip wg0)
$ wg show
interface: wg0
  ...
peer: 8KxrmP...
  allowed ips: 10.66.66.2/32
  latest handshake: never        # 还没有真机来握手，正常
```

`latest handshake: never` 是此时的**正确状态**——对端登记了但还没来握手。第五章的脚本会用到同样的 syncconf 手法热加载（避免闪断），第四章则让真正的笔记本拿着 `laptop_private.key` 来点亮这行握手。

## 本章小结

- 搭建六步：安装 → 密钥 → conf → 转发 → 服务 → 防火墙，每步缺一的症状不同，排障时回指图 3-1；
- 密钥生成纪律：先 `umask 077` 再 `wg genkey`，私钥文件 600 权限、永不离开本机；
- `wg0.conf` 是全书唯一的配置文件：Address、ListenPort、PrivateKey、MTU、PostUp/PostDown 五个字段各管一事；
- 内核转发是「网关」与「单机」的分水岭：`/etc/sysctl.d/99-wireguard.conf` 独立文件，立即生效且重启保留；
- NAT 伪装让内网包「借服务器身份」出公网；FORWARD 链三条规则成套出现，漏掉回程那条是最经典的半通故障；
- PostUp/PostDown 成对钩子保证规则随接口生灭——所以规则写进 conf，不手敲 iptables；
- 两道防火墙门（系统防火墙 + 云安全组）都要放行 UDP 51820，连不上先查更外面那道；
- Peer 段三字段：公钥定身份，AllowedIPs 用 /32 独占地址，`wg syncconf` 热更新不闪断。

**下一章预告**：服务端已经张开怀抱，下一章让真机进来——笔记本与手机用官方客户端接入，AllowedIPs 的「全隧道还是分流」在这里第一次产生真实后果。
