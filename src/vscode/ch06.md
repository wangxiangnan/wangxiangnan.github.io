# 第6章：Git与版本控制深度集成

> 在终端里敲 `git add . && git commit -m "fix"` 是每个程序员都会的基本功。但你真的需要每次都这样做吗？VSCode内置了强大的Git集成——从暂存、提交、推送，到Diff查看、合并冲突解决、交互式Rebase，几乎所有Git操作都可以在图形界面中完成。这不是要取代命令行，而是让你在**该用GUI的时候用GUI，该用命令行的时候用命令行**。

## SCM面板全面解析

源代码管理（Source Control Management）面板是VSCode中Git操作的核心入口。快捷键：`Ctrl+Shift+G`（`⌘+Shift+G`）。

### 面板结构

```
📋 源代码管理
├── 📝 更改 (Changes)               ← 未暂存的修改
│   ├── M src/components/Button.tsx  ← Modified
│   ├── M src/utils/helpers.ts       ← Modified
│   ├── A src/hooks/useAuth.ts       ← Added (新文件)
│   ├── D src/old-utils.ts           ← Deleted
│   └── U src/config.ts              ← Untracked
│
├── 📦 暂存的更改 (Staged Changes)   ← 已暂存，准备提交
│   ├── M src/App.tsx
│   └── M package.json
│
├── 🔄 合并中的更改 (Merge Changes)  ← 合并冲突文件
│   └── UU src/config.ts
│
└── 📋 提交消息输入框
    [输入提交消息...]
    [✓] [↑] [↓] [...]
```

### 常用操作快捷键

```
快捷键                        说明
──────────────────────────────────────────────────────
Ctrl+Shift+G (⌘+Shift+G)   打开SCM面板
Ctrl+Enter                   提交（输入消息后）
Alt+Click（文件）             暂存/取消暂存单个文件
Ctrl+K, Ctrl+S              打开快捷键设置
```

### 文件状态图标

```
状态    图标    说明
───────────────────────────────
M       ✏️     Modified（已修改）
A       ➕     Added（新增）
D       🗑️     Deleted（已删除）
U       ❓     Untracked（未追踪）
C       🔀     Conflict（冲突）
R       ➡️     Renamed（重命名）
```

### 暂存操作的完整流程

```
方式1：逐个文件暂存
  点击文件旁边的 "+" 按钮 → 暂存单个文件
  点击 "Changes" 标题旁的 "+" → 暂存所有文件

方式2：部分暂存（Partial Stage）
  打开文件 → 在编辑器中选择特定行 → 右键 → "Stage Selected Ranges"
  ⚡ 这是VSCode独有的功能！你可以只暂存一个文件的部分修改

方式3：命令行
  内置终端 → git add -p → 交互式选择
```

### 提交消息的最佳实践

```jsonc
// settings.json - Git提交相关设置
{
  "git.enableSmartCommit": true,       // 无暂存文件时自动暂存所有
  "git.confirmSync": false,            // 同步时不确认
  "git.autofetch": true,               // 自动fetch
  "git.autofetchPeriod": 180,          // 每3分钟自动fetch
  "git.pruneOnFetch": true,            // fetch时清理已删除的远程分支
  "git.showActionButton": {
    "commit": true,
    "publish": true,
    "sync": true
  },
  "scm.diffDecorations": "all",       // 在编辑器中显示Diff装饰
  "scm.defaultViewMode": "tree"       // 以树形视图显示文件
}
```

## 内置Diff编辑器

VSCode的Diff编辑器是查看代码变更的最佳工具之一。

### 打开Diff视图

```
方式1：在SCM面板中点击已修改的文件
方式2：Ctrl+Shift+P → "Git: Open Changes"
方式3：命令面板 → "Git: Open All Changes"  打开所有修改的文件
方式4：点击编辑器顶部的"Changes"指示器
```

### Diff视图的两种模式

**并排对比（Side by Side）**——默认模式：

```
┌──────────────────────┬──────────────────────┐
│ 原始版本 (HEAD)       │ 修改版本 (Working)    │
│                      │                      │
│  function add(a, b) {│  function add(       │
│    return a + b;     │    a: number,        │
│  }                   │    b: number         │
│                      │  ): number {         │
│                      │    return a + b;     │
│                      │  }                   │
└──────────────────────┴──────────────────────┘
         ← 删除（红色）       → 新增（绿色）
```

**内联对比（Inline）**：

```
┌────────────────────────────────────────────┐
│ - function add(a, b) {                     │ ← 红色背景
│ + function add(                            │ ← 绿色背景
│ +   a: number,                             │
│ +   b: number                              │
│ + ): number {                              │
│    return a + b;                           │
│  }                                         │
└────────────────────────────────────────────┘
```

切换模式：Diff视图右上角的 `...` 菜单 → `Inline View` / `Side by Side`。

### Diff编辑器的高级功能

**可编辑Diff**：右侧（修改版本）是可以直接编辑的。你可以在查看Diff的同时修改代码——不用切换回普通编辑器。

**Diff导航**：

```
快捷键                        说明
──────────────────────────────────────────────
Alt+F5 (Option+F5)          跳到下一个变更
Shift+Alt+F5                跳到上一个变更
```

**Diff中的代码操作**：

```
在并排Diff视图中，你可以：
- 在任意位置编辑修改版本（右侧）
- 点击变更区域旁的箭头：
  - → 接受当前变更（将左侧应用到右侧）
  - ← 撤销当前变更（将右侧恢复到左侧）
  - ↩  恢复到原始版本
```

### 多文件Diff浏览

```
// 打开所有变更文件的Diff
Ctrl+Shift+P → "Git: Open All Changes"

// 然后在Diff标签间用以下快捷键导航：
Ctrl+Tab                    下一个文件
Ctrl+Shift+Tab             上一个文件
```

## 时间线视图（Timeline）

时间线视图（Timeline）显示**单个文件**的Git提交历史，是追踪文件演变的利器。

### 打开Timeline

在侧边栏底部的 `TIMELINE` 面板中，自动显示当前打开文件的提交历史。

```
📅 TIMELINE
├── 10 minutes ago · You
│   └── feat: add user authentication      [a1b2c3d]
├── 2 hours ago · You
│   └── fix: correct login redirect URL    [e4f5g6h]
├── Yesterday · Alice
│   └── refactor: extract auth service     [i7j8k9l]
├── 3 days ago · Bob
│   └── feat: initial auth setup           [m0n1o2p]
└── 📋 Local History
    ├── Auto Save 5 min ago
    └── Auto Save 10 min ago
```

### Timeline的妙用

1. **快速对比**：点击任意提交，直接查看该提交对此文件的Diff
2. **本地历史**：即使你没有提交，VSCode也会保存本地编辑历史（Local History），帮你找回"不小心删掉的代码"
3. **提交回溯**：右键某个提交 → `Copy Commit ID` 或 `Open Commit`

```jsonc
// 本地历史相关设置
{
  "localHistory.enabled": true,
  "localHistory.maxFileEntries": 50,      // 每个文件最多保存50条记录
  "localHistory.exclude": {               // 排除不需要保存历史的文件
    "**/node_modules/**": true
  },
  "localHistory.mergeWindow": 10          // 10秒内的编辑合并为一条记录
}
```

## 交互式Rebase编辑器

VSCode为Git的交互式Rebase提供了可视化编辑器——再也不用面对Vim的Rebase界面发呆了。

### 启动Rebase

```
方式1：命令面板 → "Git: Rebase Branch..."
方式2：在GitLens扩展中操作
方式3：SCM面板的分支菜单
```

### 交互式Rebase编辑器界面

```
┌─ Interactive Rebase ──────────────────────────────┐
│                                                   │
│ Base: main                                        │
│                                                   │
│ Pick   a1b2c3d feat: add user authentication      │
│ Pick   e4f5g6h fix: correct login redirect        │
│ Squash i7j8k9l style: fix formatting              │
│ Pick   m0n1o2p refactor: clean up imports          │
│ Drop   q3r4s5t wip: temporary debug code           │
│                                                   │
│ [Start Rebase]  [Cancel]                          │
└───────────────────────────────────────────────────┘
```

### Rebase操作一览

```
操作        缩写     说明
──────────────────────────────────────────────────
Pick        p       保留该提交
Reword      r       保留提交但修改消息
Edit        e       暂停在该提交，允许修改
Squash      s       合并到前一个提交
Fixup       f       合并到前一个提交（丢弃消息）
Drop        d       丢弃该提交
```

在VSCode中，你可以通过**拖拽**来重新排列提交顺序，通过**下拉菜单**来切换操作类型——比在Vim中编辑文本直观得多。

## 合并冲突编辑器

合并冲突是最让人头疼的Git操作之一。VSCode的三向合并编辑器让这个痛苦的过程变得可视化且可操作。

### 冲突文件标记

当有合并冲突时，SCM面板会用特殊标记显示冲突文件：

```
📋 合并中的更改
└── ⚠️ src/config.ts    [C]    ← C表示Conflict
```

### 内联冲突解决

VSCode会在冲突位置上方显示CodeLens按钮：

```typescript
// 在冲突文件中，VSCode会显示：

<<<<<<< HEAD
const API_URL = "https://api.production.com";
||||||| merged common ancestors
const API_URL = "https://api.example.com";
=======
const API_URL = "https://api.staging.com";
>>>>>>> feature/update-api

// VSCode在每段上方显示操作按钮：
// [Accept Current Change]  [Accept Incoming Change]
// [Accept Both Changes]    [Compare Changes]
```

### 三向合并编辑器（3-Way Merge Editor）

VSCode 1.69+ 引入了专门的三向合并编辑器，同时显示三个版本：

```
┌──────────────────┬──────────────────┬──────────────────┐
│ Input 1 (Current) │    Base (共同祖先) │ Input 2 (Incoming)│
│                  │                  │                  │
│ const URL =      │ const URL =      │ const URL =      │
│  "production"    │  "example"       │  "staging"       │
│                  │                  │                  │
├──────────────────┴──────────────────┴──────────────────┤
│                    Result (结果)                        │
│                                                        │
│ const URL = "production"  ← 你可以选择/编辑/组合       │
│                                                        │
└────────────────────────────────────────────────────────┘
```

在Result面板中，你可以：

- 点击按钮接受Current或Incoming的变更
- 同时接受双方的变更（Accept Both）
- 手动编辑结果
- 从Base版本重新开始

### 开启三向合并编辑器

```jsonc
{
  "merge-editor.diffAlgorithm": "advanced",  // 使用高级Diff算法
  "git.mergeEditor": true                     // 启用三向合并编辑器
}
```

## Git Blame内联显示

虽然VSCode内置的Git功能不包含Blame，但配合 **GitLens** 插件（最流行的VSCode扩展之一），你可以获得强大的Blame功能。

### GitLens提供的Blame功能

```typescript
// 行内Blame（每行代码后面显示最后修改者和时间）
const API_URL = "https://api.example.com"; // Alice, 3 days ago • feat: update API endpoints

// 光标所在行的Blame（在行尾或编辑器底部显示详细信息）
// ┃ You, 2 hours ago ┃ fix: correct API URL for production environment ┃ a1b2c3d4
```

### GitLens配置

```jsonc
{
  // GitLens Blame配置
  "gitlens.currentLine.enabled": true,           // 显示当前行的Blame
  "gitlens.codeLens.enabled": true,              // 显示CodeLens
  "gitlens.hovers.currentLine.over": "line",     // 悬停显示Blame
  "gitlens.blame.toggleMode": "file",            // Blame切换模式
  "gitlens.currentLine.format": "${author|20}, ${ago|14} • ${message|50}",
  "gitlens.codeLens.authors.enabled": true,
  "gitlens.codeLens.recentChange.enabled": true
}
```

## 实战：完全在VSCode中完成一次Feature分支开发流程

让我们模拟一个真实的开发场景：你要为项目添加一个"用户头像上传"功能。

### 步骤1：创建Feature分支

```
Ctrl+Shift+P → "Git: Create Branch..."
输入分支名：feature/avatar-upload
基于：main
```

或者在状态栏点击当前分支名 → `Create new branch...`

### 步骤2：开发并查看变更

编码过程中，SCM面板实时更新变更状态。每个修改的文件旁边显示变更类型（M/A/D）。

```jsonc
// 编辑器中的Diff装饰（ gutter decorations ）
{
  "scm.diffDecorations": "all",
  "scm.diffDecorationsGutterWidth": 3,
  "scm.diffDecorationsGutterAction": "diff"  // 点击gutter装饰打开Diff
}
```

编辑器左侧gutter中的颜色标记：

- 🟢 绿色条：新增的行
- 🟡 黄色条：修改的行
- 🔴 红色三角：删除的行（悬停可以看到被删的内容）

### 步骤3：智能暂存和提交

```
1. 在SCM面板中查看所有变更
2. 打开某个文件 → 选择部分修改 → 右键 → "Stage Selected Ranges"
   （只暂存你确认正确的修改，保留其他修改继续调试）
3. 输入提交消息：
   feat(user): add avatar upload component
   
   - Add AvatarUpload component with drag & drop
   - Implement image cropping with react-cropper
   - Add file size and type validation
   - Update UserSettings page to include avatar upload
   
   Closes #142

4. Ctrl+Enter 提交
```

### 步骤4：Review和推送

```
1. Ctrl+Shift+P → "Git: Push" (或点击状态栏的同步按钮)
2. 如果远程有新的提交，VSCode会提示你先Pull
3. 选择 "Pull (Rebase)" 保持提交历史整洁
```

### 步骤5：创建Pull Request

```
1. 安装 GitHub Pull Requests 插件
2. 推送后，VSCode底部弹出通知："Create Pull Request"
3. 点击后直接在VSCode中填写PR标题和描述
4. 提交PR，全程不离开VSCode
```

## 进阶：Git高级操作的VSCode实现

### Git Stash

```
// 暂存当前工作进度
Ctrl+Shift+P → "Git: Stash"
→ 输入stash消息："WIP: avatar upload - need to fix cropping"

// 恢复stash
Ctrl+Shift+P → "Git: Pop Stash..."
→ 选择要恢复的stash

// 查看stash列表
SCM面板 → "..." 菜单 → "Stash" → 查看所有stash
```

### Git Cherry-pick

```
// 从其他分支挑选特定提交
1. 打开Timeline视图或GitLens的Commit面板
2. 找到目标提交
3. 右键 → "Cherry Pick Commit"
```

### Git Revert

```
// 撤销某个提交的更改（创建新的反向提交）
1. 在Timeline中找到要撤销的提交
2. 右键 → "Revert Commit"

// 或者在终端中：
git revert <commit-hash>
// VSCode会自动打开编辑器让你编辑revert提交消息
```

### Git Log和搜索

```jsonc
{
  // Git日志配置
  "git.showInlineOpenRepositoryAction": true,
  "git.decorations.enabled": true,
  "git.openRepositoryInParentFolders": "prompt"
}
```

### 多仓库管理

如果你的工作区包含多个Git仓库：

```jsonc
{
  "git.autoRepositoryDetection": "openEditors",  // 自动检测打开文件所属的仓库
  "git.scanRepositories": [                      // 指定要扫描的仓库路径
    "./frontend",
    "./backend",
    "./shared-lib"
  ],
  "git.repositoryScanMaxDepth": 3               // 最大扫描深度
}
```

SCM面板会自动按仓库分组显示变更：

```
📋 源代码管理
├── 📁 frontend (3)
│   ├── M src/App.tsx
│   ├── M src/styles.css
│   └── A src/components/Avatar.tsx
├── 📁 backend (2)
│   ├── M src/routes/user.ts
│   └── A src/middleware/upload.ts
└── 📁 shared-lib (1)
    └── M src/types/user.ts
```

```jsonc
// settings.json - 完整的Git配置
```

## 📋 本章小结

- **SCM面板**是Git操作的中心，支持暂存、提交、推送的完整流程
- **部分暂存（Stage Selected Ranges）**是VSCode独有的功能，让你精确控制每次提交的内容
- **Diff编辑器**支持并排和内联两种模式，且右侧可直接编辑
- **Timeline视图**追踪单个文件的完整历史，包括本地编辑历史
- **交互式Rebase编辑器**用可视化拖拽替代了Vim中的文本编辑
- **三向合并编辑器**让冲突解决变得直观可控
- 配合**GitLens**插件获得行内Blame、详细历史等增强功能
- 整个**Feature分支开发流程**可以完全在VSCode中完成，无需切换到浏览器或终端
- 多仓库项目通过 `git.scanRepositories` 实现统一管理
