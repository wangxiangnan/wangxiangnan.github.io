# 第25章：FFI、Unsafe与项目实战总结

## 引子：Rust的安全围栏与那把钥匙

前24章里，Rust像一个严格的教练：不让你有悬垂引用、不让你数据竞争、不让你内存泄漏。但现实世界里，有时你必须绕过这些保护——调用C库、操作硬件寄存器、实现极致性能的数据结构。这时你需要`unsafe`——Rust给你的一把钥匙，上面刻着"后果自负"。

> **类比**：Python的`ctypes`让你调用C函数，Java的JNI让你调用本地代码，JS的WebAssembly让你运行编译后的C/Rust。Rust的FFI（Foreign Function Interface，外部函数接口）同样是跨语言调用的桥梁——但Rust通过`unsafe`明确标记了所有"不安全的边界"，让代码审查时一眼就能看到危险操作。

---

## unsafe Rust：为什么需要它？

Rust的安全保证建立在一组规则之上（所有权、借用检查等）。但有些操作本质上无法被这些规则验证：

- C库函数不遵守Rust的借用规则
- 裸指针可能指向任意内存
- 某些硬件操作需要精确的内存布局

`unsafe`不是"关闭安全检查"——它是**你向编译器承诺"我知道我在做什么"**。编译器仍然检查你能检查的部分，但把一部分验证责任交给了你。

unsafe给你5种超能力：

1. 解引用裸指针（raw pointer）
2. 调用unsafe函数
3. 实现unsafe trait
4. 访问或修改`static mut`变量
5. 访问`union`的字段

## 裸指针操作

裸指针（Raw Pointer）分两种：`*const T`（只读）和`*mut T`（可写）。它们不受所有权和借用规则约束：

```rust
fn main() {
    let mut value = String::from("hello");

    // 创建裸指针（这一步是安全的！）
    let const_ptr: *const String = &value;
    let mut_ptr: *mut String = &mut value;

    // 解引用裸指针需要 unsafe
    unsafe {
        println!("通过 const_ptr 读取：{}", *const_ptr);
        *mut_ptr = String::from("world");
        println!("通过 mut_ptr 修改后：{}", *mut_ptr);
    }

    // 裸指针可以指向任意地址（危险！）
    let arbitrary_addr = 0x12345usize as *const i32;
    // unsafe { println!("{}", *arbitrary_addr); }  // 未定义行为！不要这么做

    // 裸指针可以为 null（和C兼容）
    let null_ptr: *const i32 = std::ptr::null();
    println!("空指针：{:?}", null_ptr);  // 输出：0x0
}
```

裸指针的实际用途：实现自定义数据结构（如链表、树），与C交互，以及实现智能指针内部。

## unsafe函数与unsafe trait

```rust
// unsafe 函数：调用者必须在 unsafe 块中调用
unsafe fn dangerous_operation(ptr: *mut i32) {
    // 调用者有责任确保 ptr 有效且对齐
    *ptr = 42;
}

fn main() {
    let mut value: i32 = 0;
    let ptr = &mut value as *mut i32;

    // 必须在 unsafe 块中调用
    unsafe {
        dangerous_operation(ptr);
    }
    println!("值变成了：{}", value);  // 42
}

// unsafe trait：实现者必须保证某些编译器无法验证的约束
unsafe trait MemorySafe {
    fn get_buffer(&self) -> *const u8;
    fn buffer_len(&self) -> usize;
}

// 实现 unsafe trait 也需要 unsafe 关键字
struct SafeBuffer {
    data: Vec<u8>,
}

unsafe impl MemorySafe for SafeBuffer {
    fn get_buffer(&self) -> *const u8 {
        self.data.as_ptr()
    }
    fn buffer_len(&self) -> usize {
        self.data.len()
    }
}
```

> **最佳实践**：尽量把unsafe代码封装在安全API（Safe Wrapper）里。外部用户只看到安全接口，unsafe细节藏在内部。标准库的`Vec`、`String`、`Box`都是这么做的。

## FFI基础：从Rust调用C函数

Rust可以直接调用C标准库函数，也可以被C代码调用：

```rust
use std::ffi::CString;
use std::os::raw::c_int;

// 声明外部C函数（来自C标准库）
extern "C" {
    fn abs(n: c_int) -> c_int;
    fn strlen(s: *const std::os::raw::c_char) -> usize;
    fn puts(s: *const std::os::raw::c_char) -> c_int;
}

fn main() {
    // 调用 C 的 abs 函数
    unsafe {
        println!("abs(-42) = {}", abs(-42));
    }

    // 调用 C 的 strlen
    let rust_str = "Hello from Rust!";
    let c_str = CString::new(rust_str).unwrap();
    unsafe {
        let len = strlen(c_str.as_ptr());
        println!("C strlen(\"{}\") = {}", rust_str, len);
    }

    // 调用 C 的 puts
    let msg = CString::new("这是通过C的puts输出的！").unwrap();
    unsafe {
        puts(msg.as_ptr());
    }
}
```

## extern与ABI：让C调用Rust

反过来，你也可以导出Rust函数给C调用：

```rust
// 导出 Rust 函数，使用 C ABI（应用二进制接口）
#[no_mangle]  // 防止 Rust 修改函数名（name mangling）
pub extern "C" fn add_numbers(a: i32, b: i32) -> i32 {
    a + b
}

// 导出一个带错误处理的函数
#[no_mangle]
pub extern "C" fn safe_divide(a: f64, b: f64, result: *mut f64) -> i32 {
    if b == 0.0 {
        return -1;  // 错误码
    }
    unsafe {
        *result = a / b;
    }
    0  // 成功
}

// 对应的 C 头文件（add_numbers.h）：
// int32_t add_numbers(int32_t a, int32_t b);
// int32_t safe_divide(double a, double b, double* result);
```

编译为C动态库：

```toml
# Cargo.toml
[lib]
name = "my_rust_lib"
crate-type = ["cdylib"]  # 生成 C 动态库（.so / .dll / .dylib）
```

```bash
cargo build --release
# 生成 target/release/libmy_rust_lib.so（Linux）
# 或 target/release/my_rust_lib.dll（Windows）
```

> **ABI（Application Binary Interface）**：定义了函数调用时参数如何传递、返回值如何传递、栈如何管理等。`extern "C"`表示使用C的ABI，这是跨语言调用的"通用语言"。Rust还支持`extern "Rust"`（默认）、`extern "system"`（Windows API）等。

## 实战项目：命令行JSON处理工具

让我们用前面学到的所有知识，构建一个实用的命令行工具——`jsonproc`，一个异步的JSON文件处理工具：

```toml
# Cargo.toml
[package]
name = "jsonproc"
version = "0.1.0"
edition = "2021"

[dependencies]
clap = { version = "4", features = ["derive"] }
serde = { version = "1", features = ["derive"] }
serde_json = "1"
tokio = { version = "1", features = ["full"] }
anyhow = "1"
```

```rust
// src/main.rs
use anyhow::{Context, Result};
use clap::{Parser, Subcommand};
use serde_json::Value;
use std::path::PathBuf;

#[derive(Parser)]
#[command(name = "jsonproc", about = "异步 JSON 文件处理工具")]
struct Cli {
    #[command(subcommand)]
    command: Commands,
}

#[derive(Subcommand)]
enum Commands {
    /// 验证 JSON 文件格式是否合法
    Validate {
        /// JSON 文件路径
        file: PathBuf,
    },
    /// 提取 JSON 中指定字段的值
    Extract {
        /// JSON 文件路径
        file: PathBuf,
        /// 字段路径（用 . 分隔，如 "user.name"）
        path: String,
    },
    /// 合并多个 JSON 文件
    Merge {
        /// 输入文件路径列表
        files: Vec<PathBuf>,
        /// 输出文件路径
        #[arg(short, long, default_value = "merged.json")]
        output: PathBuf,
    },
}

// 异步读取并解析 JSON 文件
async fn read_json(path: &PathBuf) -> Result<Value> {
    let content = tokio::fs::read_to_string(path)
        .await
        .with_context(|| format!("无法读取文件：{}", path.display()))?;

    let value: Value = serde_json::from_str(&content)
        .with_context(|| format!("JSON 解析失败：{}", path.display()))?;

    Ok(value)
}

// 按路径提取嵌套字段
fn extract_field(value: &Value, path: &str) -> Option<&Value> {
    path.split('.').fold(Some(value), |acc, key| {
        acc.and_then(|v| v.get(key))
    })
}

// 处理 validate 子命令
async fn cmd_validate(file: PathBuf) -> Result<()> {
    let value = read_json(&file).await?;
    let kind = match value {
        Value::Object(_) => "对象（Object）",
        Value::Array(_) => "数组（Array）",
        _ => "其他类型",
    };
    println!("✓ {} 是合法的 JSON 文件，顶层类型：{}", file.display(), kind);
    Ok(())
}

// 处理 extract 子命令
async fn cmd_extract(file: PathBuf, path: String) -> Result<()> {
    let value = read_json(&file).await?;
    match extract_field(&value, &path) {
        Some(field) => {
            let output = serde_json::to_string_pretty(field)?;
            println!("{}", output);
        }
        None => {
            anyhow::bail!("字段路径 '{}' 不存在", path);
        }
    }
    Ok(())
}

// 处理 merge 子命令
async fn cmd_merge(files: Vec<PathBuf>, output: PathBuf) -> Result<()> {
    // 并发读取所有文件
    let mut handles = vec![];
    for file in files {
        let handle = tokio::spawn(async move {
            read_json(&file).await.map(|v| (file, v))
        });
        handles.push(handle);
    }

    let mut merged = serde_json::Map::new();
    for handle in handles {
        let (file, value) = handle.await??;
        match value {
            Value::Object(map) => {
                for (k, v) in map {
                    merged.insert(k, v);
                }
                println!("  已合并：{}", file.display());
            }
            _ => {
                eprintln!("  警告：{} 不是 JSON 对象，跳过", file.display());
            }
        }
    }

    let output_str = serde_json::to_string_pretty(&Value::Object(merged))?;
    tokio::fs::write(&output, output_str).await?;
    println!("✓ 合并结果已写入：{}", output.display());
    Ok(())
}

#[tokio::main]
async fn main() -> Result<()> {
    let cli = Cli::parse();

    match cli.command {
        Commands::Validate { file } => cmd_validate(file).await?,
        Commands::Extract { file, path } => cmd_extract(file, path).await?,
        Commands::Merge { files, output } => cmd_merge(files, output).await?,
    }

    Ok(())
}
```

使用方式：

```bash
# 验证 JSON 文件
cargo run -- validate config.json

# 提取嵌套字段
cargo run -- extract user_data.json "user.address.city"

# 合并多个 JSON 文件
cargo run -- merge file1.json file2.json file3.json -o combined.json
```

## 项目结构与最佳实践

一个成熟的Rust项目结构：

```
my_project/
├── Cargo.toml
├── Cargo.lock          # 二进制项目提交，库项目不提交
├── src/
│   ├── main.rs         # 入口点（薄层，只调用 lib.rs）
│   ├── lib.rs          # 核心逻辑
│   ├── config.rs       # 配置模块
│   └── error.rs        # 自定义错误类型
├── tests/
│   ├── common/
│   │   └── mod.rs      # 共享测试工具
│   └── integration.rs  # 集成测试
├── benches/
│   └── benchmark.rs    # 基准测试
├── examples/
│   └── basic_usage.rs  # 使用示例（cargo run --example basic_usage）
├── .github/
│   └── workflows/
│       └── ci.yml      # CI 配置
├── rustfmt.toml        # 格式化配置
└── clippy.toml         # Lint 配置
```

最佳实践清单：

- **把逻辑放在`lib.rs`**：`main.rs`只负责解析参数和调用`lib`函数，方便测试
- **自定义错误类型**：用`thiserror`（库）或`anyhow`（应用）替代裸字符串错误
- **用`examples/`展示用法**：用户可以`cargo run --example xxx`
- **CI必跑三件套**：`cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test`
- **语义化版本**：遵守SemVer，公开API变更对应major版本升级

## 常见陷阱与易错点

**陷阱1：过度使用unsafe**
新手常被unsafe的"超能力"吸引，到处使用。记住：绝大多数Rust代码不需要unsafe。标准库已经为你封装好了不安全操作。只在必要且充分理解后果时使用unsafe，并用安全API封装。

**陷阱2：unsafe不等于"关闭所有检查"**
`unsafe`块内，编译器仍然检查类型安全、借用检查（除了裸指针相关）。unsafe只解锁5种特定能力，不是"免死金牌"。

**陷阱3：FFI中的字符串问题**
Rust的`String`不是以null结尾的，不能直接传给C。必须用`CString`转换。从C接收的字符串可能是无效UTF-8，用`CStr::from_ptr`并检查结果。

## 小结

- `unsafe`给你5种超能力，但你要对安全性负责
- 裸指针（`*const T`、`*mut T`）绕过借用检查，用于底层数据结构和FFI
- FFI通过`extern "C"`实现Rust与C的双向调用
- 成熟的Rust项目应该有清晰的结构、完善的CI、规范的错误处理
- Rust的学习之路是渐进式的：从基础语法到系统思维，再到领域专精
- 社区是Rust最大的财富——积极参与，你会进步得更快
