# 第六章：写作技巧——让读者读下去

## 核心观点

**写作不是展示你知道多少，是帮读者节省时间。**

## 6.1 标题的五个公式

| 公式 | 示例 | 适用场景 |
| --- | --- | --- |
| 数字 + 结果 | "3 个技巧，让你的代码可读性提升 10 倍" | 教程类 |
| 痛点 + 方案 | "每次写 this 都头疼？一期讲透四种指向" | 问题解决 |
| 反常识 | "为什么 typeof null 返回 'object'？" | 知识科普 |
| 身份认同 | "前端新人必看的 10 个报错" | 人群定位 |
| 悬念 | "这个 bug 保留了 28 年，没人敢修" | 故事类 |

**检验：** 把标题给 3 个人看，问"你想点开吗？"2 人以上说想，过关。

## 6.2 开头的三种写法

| 写法 | 示例 | 效果 |
| --- | --- | --- |
| 场景代入 | "页面白屏，控制台第一条红字就是它。" | 共鸣 |
| 结论先行 | "undefined 不是 bug，是 JS 的设计选择。" | 好奇 |
| 故事引入 | "1995 年，JS 作者手滑了…" | 兴趣 |

**禁忌：** 开头不要写"今天我们来聊聊…"（废话）。

## 6.3 结构的四个模型

**模型 1：问题 - 分析 - 方案**

```
1. 这是什么问题？
2. 为什么会出现？
3. 怎么解决？
```

**模型 2：总 - 分 - 总**

```
1. 核心观点（1 句）
2. 分点论述（3-5 点）
3. 总结升华（1 句）
```

**模型 3：时间线**

```
1. 过去（背景）
2. 现在（现状）
3. 未来（趋势）
```

**模型 4：对比**

```
1. A 方案（优点/缺点）
2. B 方案（优点/缺点）
3. 如何选择
```

## 6.5 完整范文：一条报错怎么写

以下是英语404 某期的正文骨架（约 600 字），可直接套用"问题 - 分析 - 方案"模型。

**标题：** Cannot read properties of undefined (reading 'map')：这条报错到底在说什么

**开头（场景代入）：**

> 页面白屏，控制台红字一片，第一条就是它。你刷新了三次，它还在。

**小标题 1：先拆句子**

- `Cannot read properties of undefined`：不能读取 undefined 的属性
- `(reading 'map')`：你要读的属性叫 map
- 合起来：你在一个 undefined 的值上调用了 `.map()`

**小标题 2：为什么会 undefined**

三种常见来源：接口没返回数据、数组还没初始化、解构写错了层级。

```js
// 1. 接口没返回
const list = res.data.items; // res.data 是 undefined 时，这里就炸

// 2. 还没初始化
let list;
list.map(...); // undefined 没有 map

// 3. 解构层级写错
const { items } = res; // 实际数据在 res.data.items
```

**小标题 3：怎么修**

```js
// 修复前
const list = res.data.items;
list.map(...)

// 修复后
const list = res.data?.items ?? [];
list.map(...)
```

**小标题 4：怎么避免**

- 接口数据类型在边界处校验一次
- 默认值写在数据源头，而不是每个使用点

**结尾（行动号召）：**

> 下期拆 `Unexpected token <`。回复「目录」查看全部报错。
