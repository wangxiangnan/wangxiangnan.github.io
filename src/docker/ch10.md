# 第10章：Docker Compose 高级特性 —— 从"能用"到"好用"

## 引言：从原型到生产

上一章你学会了用 Compose 搭建多服务应用——恭喜，你的应用已经能在开发环境跑起来了。但距离生产级别还差得远：如果数据库还没准备好就启动 API 会怎样？如何在开发环境和生产环境之间切换配置？敏感信息（数据库密码、API 密钥）怎么安全管理？

这就好比你的原型 demo 获得了老板的认可，现在要把它变成能扛住双十一的生产系统。本章将带你掌握 Compose 的高级特性。

## 10.1 depends_on 与等待策略

`depends_on` 控制的是**启动顺序**，但它有一个常见陷阱：默认情况下，它只保证容器"启动了"，不保证容器里的服务"准备好了"。

```yaml
# 基础用法：只保证启动顺序
services:
  api:
    image: my-api:latest
    depends_on:
      - db        # db 容器先启动，但数据库可能还没完成初始化
      - redis
```

这就像你约了朋友去吃饭，朋友说"我到了"（容器启动），但其实他还在找停车位（服务没就绪）。

**解决方案：使用 condition 等待策略**

```yaml
services:
  api:
    image: my-api:latest
    depends_on:
      db:
        condition: service_healthy    # 等数据库健康检查通过
      redis:
        condition: service_started    # 只等容器启动

  db:
    image: postgres:15-alpine
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
```

`depends_on` 支持三种 condition：

| condition | 含义 | 使用场景 |
|-----------|------|---------|
| `service_started` | 容器已启动（默认） | 启动快的服务 |
| `service_healthy` | 健康检查通过 | 数据库等需要初始化的服务 |
| `service_completed_successfully` | 容器已正常退出（exit 0） | 数据库迁移等一次性任务 |

```yaml
# 实战：完整的启动顺序控制
services:
  # 第一步：数据库迁移（完成后退出）
  migrate:
    image: my-api:latest
    command: npm run migrate
    depends_on:
      db:
        condition: service_healthy

  # 第二步：API 启动（等迁移完成 + 数据库健康）
  api:
    image: my-api:latest
    depends_on:
      migrate:
        condition: service_completed_successfully
      db:
        condition: service_healthy
      redis:
        condition: service_started

  db:
    image: postgres:15-alpine
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d myapp"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s              # 给数据库初始化留出时间

  redis:
    image: redis:7-alpine
```

> **Warning:** 在 Compose V2 中，`depends_on` 的 `condition` 语法需要写在 YAML 的 map 格式下，而不是 V1 时代的列表格式。如果报错 `depends_on contains an invalid type`，检查一下语法格式。

## 10.2 Healthcheck 配置

Healthcheck 是 Docker 的"健康监控系统"——它定期执行一个命令来判断容器内的服务是否正常工作。

```yaml
services:
  api:
    image: my-api:latest
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000/health"]
      interval: 30s      # 每 30 秒检查一次
      timeout: 10s        # 单次检查超时 10 秒
      retries: 3          # 连续失败 3 次标记为 unhealthy
      start_period: 40s   # 启动后 40 秒内不检查

  db:
    image: postgres:15-alpine
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s
```

```bash
# 查看容器健康状态
docker compose ps
# 输出中会显示 (healthy) 或 (unhealthy)

# 查看健康检查的详细日志
docker inspect --format='{{json .State.Health}}' my-container
```

> **Tip:** 不是所有镜像都内置了 `curl`。如果健康检查报 `exec: "curl": not found`，可以用 `wget --spider`（Alpine）或在 Dockerfile 中预装检查工具。

## 10.3 Profiles：多环境配置切换

Profiles 允许你标记某些服务只在特定"配置集"下启动。

```yaml
services:
  api:
    image: my-api:latest
    # 没有 profiles = 默认启动

  db:
    image: postgres:15-alpine

  # 调试工具：只在 debug profile 下启动
  mongo-express:
    image: mongo-express:1
    profiles: ["debug"]

  # 监控：只在 monitoring profile 下启动
  prometheus:
    image: prom/prometheus
    profiles: ["monitoring"]

  grafana:
    image: grafana/grafana
    profiles: ["monitoring"]
```

```bash
# 只启动核心服务
docker compose up -d
# 启动：api, db

# 启动核心服务 + 调试工具
docker compose --profile debug up -d
# 启动：api, db, mongo-express

# 启动核心服务 + 监控
docker compose --profile monitoring up -d

# 同时启用多个 profiles
docker compose --profile debug --profile monitoring up -d

# 也可以用环境变量
COMPOSE_PROFILES=debug,monitoring docker compose up -d
```

> **Tip:** 善用 profiles 可以让一个 `docker-compose.yml` 服务于多个场景。把调试工具、监控面板都放在 profiles 里，日常开发按需启用，不要把所有服务都默认启动——你的笔记本风扇会感谢你的。

## 10.4 Override 文件：docker-compose.override.yml

Compose 有一个"自动合并"机制：如果你在项目根目录放一个 `docker-compose.override.yml`，Compose 会自动将它的配置合并到 `docker-compose.yml` 上。

```yaml
# docker-compose.yml —— 基础配置（提交到 Git）
services:
  api:
    build: .
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production

  db:
    image: postgres:15-alpine
    volumes:
      - postgres-data:/var/lib/postgresql/data
```

```yaml
# docker-compose.override.yml —— 开发环境覆盖（加入 .gitignore！）
services:
  api:
    environment:
      - NODE_ENV=development
      - DEBUG=true
    volumes:
      - ./src:/app/src
    ports:
      - "3000:3000"
      - "9229:9229"         # Node.js debugger 端口

  db:
    ports:
      - "5432:5432"         # 开发时暴露数据库端口
```

```bash
# 默认行为：自动合并 override 文件
docker compose up -d

# 在 CI/CD 中：显式只使用基础配置
docker compose -f docker-compose.yml up -d
```

> **Warning:** `docker-compose.override.yml` **应该加入 .gitignore**！它是给本地开发用的，不应该提交到版本库。

## 10.5 多 Compose 文件合并（-f 参数）

```yaml
# docker-compose.yml —— 基础配置
services:
  api:
    build: .
    depends_on:
      - db
  db:
    image: postgres:15-alpine
```

```yaml
# docker-compose.dev.yml —— 开发环境扩展
services:
  api:
    environment:
      - NODE_ENV=development
    volumes:
      - ./src:/app/src
    ports:
      - "3000:3000"
  db:
    ports:
      - "5432:5432"
```

```yaml
# docker-compose.prod.yml —— 生产环境扩展
services:
  api:
    environment:
      - NODE_ENV=production
    deploy:
      replicas: 3
      resources:
        limits:
          memory: 512M
    restart: always
  db:
    restart: always
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
    depends_on:
      - api
```

```bash
# 开发环境
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d

# 生产环境
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d

# 预览合并后的最终配置
docker compose -f docker-compose.yml -f docker-compose.prod.yml config
```

> **Tip:** 你可以设置环境变量 `COMPOSE_FILE=docker-compose.yml:docker-compose.dev.yml` 来简化命令。

## 10.6 Compose Secrets 管理

```yaml
# docker-compose.yml
services:
  api:
    image: my-api:latest
    secrets:
      - db_password
      - jwt_secret
    environment:
      DB_PASSWORD_FILE: /run/secrets/db_password
      JWT_SECRET_FILE: /run/secrets/jwt_secret

  db:
    image: postgres:15-alpine
    secrets:
      - db_password
    environment:
      POSTGRES_PASSWORD_FILE: /run/secrets/db_password

secrets:
  db_password:
    file: ./secrets/db_password.txt
  jwt_secret:
    file: ./secrets/jwt_secret.txt
```

```bash
# 创建 secrets 文件
mkdir -p secrets
echo "my_super_secret_db_password" > secrets/db_password.txt
echo "my_jwt_secret_key_2024" > secrets/jwt_secret.txt

# 确保 secrets 不被提交到 Git！
echo "secrets/" >> .gitignore
```

> **Warning:** Compose 的 secrets 适合开发和单机部署。在 Docker Swarm 或 Kubernetes 中，请使用平台原生的 secrets 管理方案。secrets 文件**绝对不能**提交到 Git 仓库！

## 10.7 Compose 扩展字段（x- 开头的 YAML 锚点）

```yaml
# 定义公共配置模板
x-common-env: &common-env
  TZ: Asia/Shanghai
  LOG_LEVEL: info
  REDIS_URL: redis://redis:6379

x-backend-service: &backend-defaults
  restart: unless-stopped
  networks:
    - backend
  logging:
    driver: json-file
    options:
      max-size: "10m"
      max-file: "3"

services:
  api:
    image: my-api:latest
    <<: *backend-defaults            # 引用锚点，展开合并
    environment:
      <<: *common-env
      SERVICE_NAME: api
    ports:
      - "3000:3000"

  worker:
    image: my-api:latest
    <<: *backend-defaults            # 复用同样的默认配置
    command: npm run worker
    environment:
      <<: *common-env
      SERVICE_NAME: worker

  redis:
    image: redis:7-alpine
    networks:
      - backend

networks:
  backend:
```

这就像你在代码中用变量和函数来避免重复一样——DRY 原则在 YAML 中同样适用。

## 10.8 实战：开发/测试/生产三套环境配置

项目文件结构：

```
my-project/
├── docker-compose.yml              # 基础配置
├── docker-compose.dev.yml          # 开发环境扩展
├── docker-compose.test.yml         # 测试环境扩展
├── docker-compose.prod.yml         # 生产环境扩展
├── .env                            # 默认环境变量
├── .env.dev                        # 开发环境变量
├── .env.prod                       # 生产环境变量
├── secrets/
│   ├── db_password.txt
│   └── jwt_secret.txt
└── .gitignore
```

```yaml
# docker-compose.yml —— 基础配置（所有环境共享）
x-common-env: &common-env
  TZ: Asia/Shanghai
  LOG_LEVEL: ${LOG_LEVEL:-info}

x-service-defaults: &service-defaults
  restart: unless-stopped
  networks:
    - app-network

services:
  api:
    build: .
    <<: *service-defaults
    environment:
      <<: *common-env
      DATABASE_URL: postgresql://postgres@db:5432/myapp
    depends_on:
      db:
        condition: service_healthy

  db:
    image: postgres:15-alpine
    <<: *service-defaults
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d myapp"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s
    volumes:
      - postgres-data:/var/lib/postgresql/data

  redis:
    image: redis:7-alpine
    <<: *service-defaults

networks:
  app-network:
    driver: bridge

volumes:
  postgres-data:
```

```yaml
# docker-compose.dev.yml
services:
  api:
    build:
      target: development
    environment:
      - NODE_ENV=development
      - DEBUG=true
    volumes:
      - ./src:/app/src
    ports:
      - "3000:3000"
      - "9229:9229"
  db:
    ports:
      - "5432:5432"
    environment:
      POSTGRES_PASSWORD: dev_password
```

```yaml
# docker-compose.prod.yml
services:
  api:
    build:
      target: production
    environment:
      - NODE_ENV=production
    secrets:
      - db_password
    deploy:
      replicas: 3
      resources:
        limits:
          memory: 512M
    restart: always
  db:
    secrets:
      - db_password
    restart: always
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    depends_on:
      - api
    restart: always

secrets:
  db_password:
    file: ./secrets/db_password.txt
```

```bash
# 各环境启动命令
# 开发环境
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d

# 运行测试
docker compose -f docker-compose.yml -f docker-compose.test.yml up --abort-on-container-exit --exit-code-from api

# 生产环境
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

> **Tip:** 在 CI/CD 流水线中，推荐使用 `--abort-on-container-exit` 和 `--exit-code-from` 参数。测试通过返回 0，失败返回非 0，CI 系统可以根据退出码判断是否继续部署。

## 本章小结

- `depends_on` + `condition: service_healthy` 确保服务按正确顺序启动
- Healthcheck 是容器的"心跳检测"，生产环境必备
- Profiles 让你在一个 Compose 文件中管理多套功能组合
- Override 文件和多文件合并是管理多环境配置的两种策略
- Secrets 提供了比环境变量更安全的敏感信息管理方式
- 扩展字段（`x-` + YAML 锚点）让你在 YAML 中实践 DRY 原则

## 练习

1. **基础练习**：为第9章的 Flask 项目添加 healthcheck，让 API 和数据库都具备健康检查能力。
2. **进阶练习**：使用 `x-` 扩展字段重构 Flask 项目的 Compose 文件，消除 worker 和 beat 之间的重复配置。
3. **挑战练习**：搭建完整的 dev/test/prod 三套环境，实现一键切换，并确保生产环境密码通过 secrets 管理。
