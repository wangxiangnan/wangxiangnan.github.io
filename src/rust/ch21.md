# 第21章：异步进阶

## 引子：一个程序员等了40秒

上一章的HTTP请求器有个严重问题：请求4篇文章是**顺序执行**的。每篇文章1秒延迟，总共要等4秒。如果请求100篇呢？100秒！

在Python里你会用`asyncio.gather()`，在JS里你会用`Promise.all()`。Rust和tokio提供了同样强大的工具——而且因为编译器的严格检查，你的并发代码比动态语言里更不容易出错。

---

## 并发执行多个Future：join

`tokio::join!`宏让你同时等待多个Future，它们在底层**交错执行**（并发），总耗时约等于最慢的那个：

```rust
use std::time::{Duration, Instant};

async fn fetch_data(source: &str) -> String {
    tokio::time::sleep(Duration::from_millis(500)).await;
    format!("来自{}的数据", source)
}

#[tokio::main]
async fn main() {
    let start = Instant::now();

    // 顺序执行：需要约 1.5 秒
    // let a = fetch_data("A").await;
    // let b = fetch_data("B").await;
    // let c = fetch_data("C").await;

    // 并发执行：只需要约 0.5 秒（三个同时开始）
    let (a, b, c) = tokio::join!(
        fetch_data("数据库"),
        fetch_data("缓存"),
        fetch_data("API")
    );

    println!("{}, {}, {}", a, b, c);
    println!("总耗时：{:?}", start.elapsed());
    // 输出：约 500ms，而不是 1500ms
}
```

如果你有一组数量动态的Future，用`futures::future::join_all`：

```rust
use futures::future::join_all;

#[tokio::main]
async fn main() {
    let tasks: Vec<_> = (1..=5)
        .map(|i| async move {
            tokio::time::sleep(Duration::from_millis(100 * i)).await;
            i * i
        })
        .collect();

    let results = join_all(tasks).await;
    println!("结果：{:?}", results);
    // 输出：[1, 4, 9, 16, 25]，总耗时约 500ms（最慢的那个）
}
```

> **类比JS**：`join!` ≈ `Promise.all()`，`join_all` ≈ `Promise.all(array_of_promises)`。

## select!：谁先完成就用谁

有时你不想等所有任务完成，而是"谁先到就用谁的结果"——比如同时请求多个服务器，取响应最快的那个：

```rust
use tokio::time::{sleep, Duration};

async fn fetch_from_server_a() -> String {
    sleep(Duration::from_millis(300)).await;
    "服务器A的响应".to_string()
}

async fn fetch_from_server_b() -> String {
    sleep(Duration::from_millis(100)).await;
    "服务器B的响应".to_string()
}

#[tokio::main]
async fn main() {
    tokio::select! {
        result_a = fetch_from_server_a() => {
            println!("A赢了：{}", result_a);
        }
        result_b = fetch_from_server_b() => {
            println!("B赢了：{}", result_b);
        }
    }
    // 输出：B赢了：服务器B的响应
    // 注意：另一个Future会被取消（drop），不会继续执行
}
```

> **类比Python**：类似`asyncio.wait(tasks, return_when=FIRST_COMPLETED)`，但语法更优雅。

## tokio::spawn：真正的并行任务

`join!`和`select!`是在**同一个任务内**交错执行Future。`tokio::spawn`则是把一个Future变成独立的**任务（Task）**，可以被调度到不同的操作系统线程上真正并行执行：

```rust
#[tokio::main]
async fn main() {
    // spawn 返回一个 JoinHandle，它本身也是一个 Future
    let handle1 = tokio::spawn(async {
        tokio::time::sleep(Duration::from_millis(200)).await;
        42
    });

    let handle2 = tokio::spawn(async {
        tokio::time::sleep(Duration::from_millis(100)).await;
        "hello".to_string()
    });

    // 等待两个任务完成
    let result1 = handle1.await.unwrap();
    let result2 = handle2.await.unwrap();

    println!("任务1：{}，任务2：{}", result1, result2);
}
```

**spawn的约束**：传给`spawn`的Future必须满足`Send + 'static`，因为任务可能在线程间迁移。这意味着：

```rust
use std::rc::Rc;

#[tokio::main]
async fn main() {
    // Rc 不是 Send，不能跨线程共享
    let data = Rc::new(vec![1, 2, 3]);

    // 编译错误！Rc<String> 不是 Send
    // tokio::spawn(async move {
    //     println!("{:?}", data);
    // });

    // 正确做法：用 Arc（原子引用计数）
    use std::sync::Arc;
    let data = Arc::new(vec![1, 2, 3]);
    let data_clone = Arc::clone(&data);
    tokio::spawn(async move {
        println!("{:?}", data_clone);
    });
}
```

## Stream trait：异步版的迭代器

`Iterator`是同步的逐项产出，`Stream`是异步的逐项产出——可以理解为"会异步产生多个值的Future"。在Python里对应`async for`，在JS里对应Async Iterable。

```toml
[dependencies]
tokio = { version = "1", features = ["full"] }
tokio-stream = "0.1"
futures = "0.3"
```

```rust
use tokio_stream::StreamExt;
use tokio::time::{sleep, Duration};

// 创建一个异步流：每隔100ms产生一个数字
async fn number_stream() -> impl tokio_stream::Stream<Item = u32> {
    tokio_stream::iter(0..5).then(|i| async move {
        sleep(Duration::from_millis(100)).await;
        i
    })
}

#[tokio::main]
async fn main() {
    use futures::StreamExt;
    let mut stream = Box::pin(number_stream().await);

    while let Some(value) = stream.next().await {
        println!("收到：{}", value);
    }
}
```

Stream特别适合处理：WebSocket消息流、文件逐块读取、数据库游标结果等。

## 异步通道：任务间的消息传递

第16章讲了`std::sync::mpsc`，tokio提供了异步版本的通道，适用于异步任务间通信：

```rust
use tokio::sync::mpsc;

#[tokio::main]
async fn main() {
    // 创建容量为 100 的异步通道
    let (tx, mut rx) = mpsc::channel::<String>(100);

    // 生产者任务
    tokio::spawn(async move {
        for i in 0..5 {
            let msg = format!("消息 #{}", i);
            tx.send(msg).await.unwrap();
            tokio::time::sleep(Duration::from_millis(100)).await;
        }
        // tx 在这里被 drop，rx 会收到 None
    });

    // 消费者：接收所有消息
    while let Some(msg) = rx.recv().await {
        println!("收到：{}", msg);
    }
    println!("通道已关闭，所有消息接收完毕");
}
```

tokio还提供了其他类型的异步同步原语：

| 类型 | 用途 | 类比 |
| ------ | ------ | ------ |
| `mpsc` | 多生产者单消费者通道 | Go的channel |
| `oneshot` | 单次发送/接收 | JS的Promise resolver |
| `broadcast` | 多生产者多消费者广播 | 事件总线 |
| `watch` | 只发送最新值 | Vue的reactive watch |

```rust
// oneshot 示例：等待某个事件完成一次
use tokio::sync::oneshot;

#[tokio::main]
async fn main() {
    let (tx, rx) = oneshot::channel::<String>();

    tokio::spawn(async move {
        tokio::time::sleep(Duration::from_secs(1)).await;
        tx.send("任务完成！".to_string()).unwrap();
    });

    let result = rx.await.unwrap();
    println!("{}", result);
}
```

## 异步中的共享状态：tokio::sync::Mutex

`std::sync::Mutex`的`lock()`会阻塞线程，在异步上下文中使用时可能阻塞工作线程。`tokio::sync::Mutex`的`lock()`是异步的，不会阻塞：

```rust
use std::sync::Arc;
use tokio::sync::Mutex;

#[tokio::main]
async fn main() {
    let counter = Arc::new(Mutex::new(0u64));

    let mut handles = vec![];
    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        let handle = tokio::spawn(async move {
            let mut num = counter.lock().await; // 异步等待锁
            *num += 1;
        });
        handles.push(handle);
    }

    for handle in handles {
        handle.await.unwrap();
    }

    println!("最终计数：{}", *counter.lock().await);
    // 输出：最终计数：10
}
```

> **什么时候用哪个Mutex？** 如果锁的持有时间很短，且不跨越`.await`点，用`std::sync::Mutex`性能更好。如果需要跨`.await`持锁，或者锁竞争激烈，用`tokio::sync::Mutex`。

## 取消与超时

`tokio::time::timeout`让你给异步操作设置时间上限：

```rust
use tokio::time::{timeout, Duration};

async fn slow_operation() -> String {
    tokio::time::sleep(Duration::from_secs(10)).await;
    "终于完成了".to_string()
}

#[tokio::main]
async fn main() {
    let result = timeout(Duration::from_secs(2), slow_operation()).await;

    match result {
        Ok(value) => println!("成功：{}", value),
        Err(_) => println!("超时了！操作在2秒内未完成"),
    }
    // 输出：超时了！操作在2秒内未完成
}
```

取消是自动的：当`timeout`返回`Err`时，内部的Future会被drop，其`.await`点会停止执行。

## 实战：并发爬虫框架

```rust
use std::time::Instant;

#[derive(Debug)]
struct CrawlResult {
    url: String,
    status: u16,
    body_len: usize,
}

async fn crawl_url(url: String) -> CrawlResult {
    // 实际项目用 reqwest，这里用 sleep 模拟网络延迟
    tokio::time::sleep(tokio::time::Duration::from_millis(
        rand::random::<u64>() % 500 + 100
    )).await;

    CrawlResult {
        status: 200,
        body_len: 1024,
        url,
    }
}

#[tokio::main]
async fn main() {
    let urls: Vec<String> = (1..=20)
        .map(|i| format!("https://example.com/page/{}", i))
        .collect();

    let start = Instant::now();

    // 限制并发数：使用 Semaphore 控制最多同时5个请求
    let semaphore = std::sync::Arc::new(tokio::sync::Semaphore::new(5));
    let mut handles = vec![];

    for url in urls {
        let sem = semaphore.clone();
        let handle = tokio::spawn(async move {
            let _permit = sem.acquire().await.unwrap(); // 获取许可
            crawl_url(url).await
        });
        handles.push(handle);
    }

    // 收集所有结果
    let mut results = vec![];
    for handle in handles {
        results.push(handle.await.unwrap());
    }

    println!("爬取 {} 个页面，耗时 {:?}", results.len(), start.elapsed());
    for r in &results {
        println!("  {} -> {} ({}字节)", r.url, r.status, r.body_len);
    }
}
```

## 常见陷阱与易错点

**陷阱1：在异步循环中忘记`.await`导致内存泄漏**

```rust
// 错误：Future 永远不会被 poll，循环会疯狂创建对象
loop {
    some_async_fn();  // 没有 .await！
}
// 正确：
loop {
    some_async_fn().await;
}
```

**陷阱2：持有tokio::Mutex跨越.await点时死锁**

```rust
// 可能导致死锁的代码
let lock = mutex.lock().await;
some_other_async_fn().await; // 等待时仍持有锁，其他任务可能等这个锁
drop(lock); // 记得及时释放
```

**陷阱3：spawn后忘记await JoinHandle**
`spawn`后如果不`await`其`JoinHandle`，任务会在后台运行但你无法得知它是否成功（包括panic）。

## 小结

- `join!`并发等待多个Future，`select!`取最先完成的结果
- `tokio::spawn`创建独立任务，可真正并行执行，要求`Send + 'static`
- `Stream`是异步迭代器，处理持续产生的值流
- 异步通道（`mpsc`、`oneshot`等）是任务间通信的首选方式
- 用`tokio::sync::Mutex`处理异步共享状态，用`timeout`处理超时取消
- 并发控制用`Semaphore`，避免同时发起过多请求
