# 第9章：Docker Compose 入门 —— 从手动挡到自动挡

## 引言：告别"命令地狱"

你还记得上一章为了搭建前后端分离应用，我们敲了多少条 `docker run` 命令吗？创建网络、启动数据库、启动缓存、启动 API、启动网关、启动前端、连接网络……足足十几条命令！如果每次启动开发环境都要这样，你大概会怀念在本地直接 `npm start` 的美好时光。

这就好比你每次出门都要手动做以下事情：穿衣服、拿钥匙、锁门、叫车、告诉司机目的地……而 Docker Compose 就像你的"智能管家"，你只需要写一份"出行计划"（YAML 文件），它就能一键帮你把所有事情安排好。

**Docker Compose 的本质**：一个用来定义和运行多容器 Docker 应用的工具。你用 YAML 文件描述应用的所有服务、网络和卷，然后一条命令启动整个应用栈。

---

## 9.1 为什么需要 Compose？

在没有 Compose 的日子里，部署一个典型 Web 应用可能需要：

```bash
# 手动启动一个三服务应用的"命令地狱"
docker network create my-app-net

docker run -d --name mongo --network my-app-net \
  -v mongo-data:/data/db mongo:6

docker run -d --name redis --network my-app-net \
  redis:7-alpine

docker run -d --name api --network my-app-net \
  -p 3000:3000 \
  -v $(pwd):/app \
  -e MONGO_URL=mongodb://mongo:27017/myapp \
  -e REDIS_URL=redis://redis:6379 \
  node:18-alpine sh -c "cd /app && npm start"
```

每次都要记住容器名、网络名、环境变量、端口映射、卷挂载……这就像用汇编语言写 Web 应用——技术上可行，精神上折磨。

用 Compose 之后，同样的事情只需要一个 `docker-compose.yml` 文件和一条命令：

```yaml
# docker-compose.yml - 同样的三服务应用，优雅得多
services:
  api:
    image: node:18-alpine
    ports:
      - "3000:3000"
    volumes:
      - .:/app
    environment:
      - MONGO_URL=mongodb://mongo:27017/myapp
      - REDIS_URL=redis://redis:6379
    command: sh -c "cd /app && npm start"

  mongo:
    image: mongo:6
    volumes:
      - mongo-data:/data/db

  redis:
    image: redis:7-alpine

volumes:
  mongo-data:
```

```bash
# 一条命令启动所有服务！
docker compose up -d

# 一条命令停止所有服务！
docker compose down
```

## 9.2 docker-compose.yml 语法详解

`docker-compose.yml` 就是 Compose 的"配方文件"。它的结构像一棵树，根节点定义了三大类资源：`services`（服务）、`networks`（网络）、`volumes`（卷）。

```yaml
# docker-compose.yml 完整语法结构
services:
  web:
    image: nginx:alpine              # 使用已有镜像
    # build: .                       # 或者从当前目录的 Dockerfile 构建
    # build:
    #   context: .                   # 构建上下文
    #   dockerfile: Dockerfile.prod  # 指定 Dockerfile

    ports:
      - "8080:80"                    # 宿主机 8080 -> 容器 80

    environment:
      - NODE_ENV=production          # 列表格式
      - PORT=3000

    env_file:
      - .env                         # 从文件加载环境变量

    volumes:
      - ./src:/app/src               # 绑定挂载（开发用）
      - node_modules:/app/node_modules  # 命名卷

    networks:
      - frontend
      - backend

    depends_on:
      - db
      - redis

    restart: unless-stopped          # no | always | on-failure | unless-stopped
    container_name: my-web-app
    working_dir: /app
    command: npm run start:prod

  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: admin
      POSTGRES_PASSWORD: secret      # 实际项目请用 secrets！
    volumes:
      - postgres-data:/var/lib/postgresql/data
    networks:
      - backend

networks:
  frontend:
    driver: bridge
  backend:
    driver: bridge
    internal: true                   # 不允许外部访问

volumes:
  postgres-data:
    driver: local
```

> [!TIP] 提示
> YAML 对缩进非常敏感，必须用空格而不是 Tab。如果你遇到 `yaml: line XX: mapping values are not allowed in this context` 这种报错，99% 是缩进问题。推荐使用 VS Code 的 YAML 插件来辅助编辑。

## 9.3 核心概念：services、networks、volumes

### Services（服务）

Service 是 Compose 中最核心的概念，代表一个"逻辑上完整的功能单元"。每个 service 对应一类容器（可以水平扩展多个实例）。

```yaml
services:
  api:
    image: my-api:1.0
    # 可以扩展为多个副本（docker compose up --scale api=3）
```

### Networks（网络）

Compose 会自动创建一个默认网络（`<project_name>_default`），所有服务自动加入。你也可以定义自定义网络实现隔离。

```yaml
services:
  api:
    networks: [frontend, backend]   # API 同时在两个网络中
  db:
    networks: [backend]             # 数据库只在后端网络

networks:
  frontend:
  backend:
    internal: true                  # 后端网络不可访问外网
```

### Volumes（卷）

```yaml
services:
  api:
    volumes:
      - ./src:/app/src              # 绑定挂载：宿主机目录 -> 容器目录
      - app-data:/app/data          # 命名卷：Docker 管理的持久化存储

volumes:
  app-data:
    driver: local
```

## 9.4 常用命令速查

```bash
# ========== 生命周期管理 ==========
docker compose up -d                # 启动所有服务（后台运行）
docker compose up -d --build        # 启动并强制重新构建镜像
docker compose down                 # 停止并删除容器、网络（保留卷）
docker compose down -v              # 停止并删除容器、网络、卷（慎用！）
docker compose down --rmi all       # 停止并删除容器、网络、镜像
docker compose stop                 # 仅停止服务（不删除容器）
docker compose restart              # 重启服务
docker compose start                # 启动已停止的服务

# ========== 日常操作 ==========
docker compose ps                   # 查看服务状态
docker compose logs                 # 查看所有日志
docker compose logs -f api          # 实时跟踪指定服务日志
docker compose exec api sh          # 在指定服务中执行命令
docker compose run --rm api npm install  # 运行一次性命令
docker compose up -d --scale api=3  # 水平扩展（3 个副本）

# ========== 构建相关 ==========
docker compose build                # 构建服务镜像
docker compose build --no-cache     # 不使用缓存构建

# ========== 信息查看 ==========
docker compose config               # 查看合并后的最终配置
docker compose images               # 查看镜像信息
docker compose top                  # 查看进程列表
```

> [!TIP] 提示
> `docker compose exec` 和 `docker compose run` 的区别：`exec` 在已运行的容器中执行命令，`run` 会创建一个新容器来执行命令。日常调试用 `exec`，跑一次性任务（如数据库迁移）用 `run --rm`。

## 9.5 Compose V1 vs V2 的区别

```bash
# Compose V1（旧版，Python 编写）
docker-compose up -d     # 注意中间是短横线

# Compose V2（新版，Go 编写）
docker compose up -d     # 注意中间是空格
```

| 特性 | V1 (docker-compose) | V2 (docker compose) |
|------|---------------------|---------------------|
| 语言 | Python | Go |
| 安装方式 | pip install | Docker CLI 插件 |
| 命令格式 | `docker-compose` | `docker compose` |
| 状态 | 已停止维护 | 当前推荐版本 |
| 性能 | 较慢 | 更快 |

> [!WARNING] 注意
> Compose V1 已于 2023 年 6 月停止维护。如果你还在用 `docker-compose`（带短横线），请升级到 `docker compose`（空格）。如果你输入 `docker compose version` 能看到版本号，说明 V2 已就绪。

## 9.6 环境变量与 .env 文件

```yaml
# docker-compose.yml
services:
  api:
    image: node:18-alpine
    environment:
      - NODE_ENV=${NODE_ENV:-development}    # 使用 shell 变量，默认 development
      - PORT=3000
    env_file:
      - .env
      - .env.local    # 本地覆盖（不要提交到 Git！）
```

```bash
# .env 文件 —— Docker Compose 会自动读取
NODE_ENV=development
DATABASE_URL=postgres://admin:secret@db:5432/myapp
REDIS_URL=redis://redis:6379
JWT_SECRET=my-super-secret-key
API_PORT=3000
```

环境变量的优先级（从高到低）：

1. `docker compose run -e KEY=VALUE` 命令行参数
2. `environment:` 中的显式定义
3. `env_file:` 指定的文件（后列出的覆盖前面的）
4. `.env` 文件（Compose 自动读取）
5. Shell 环境变量

> [!WARNING] 注意
> `.env` 文件可能包含敏感信息。务必在 `.gitignore` 中排除 `.env.local` 和 `.env.production`。保留一个 `.env.example` 作为模板。

## 9.7 实战：用 Compose 编排 Node.js + MongoDB + Redis 应用

项目结构：

```bash
my-node-app/
├── docker-compose.yml
├── .env
├── Dockerfile
├── package.json
└── src/
    └── index.js
```

```dockerfile
# Dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
EXPOSE 3000
CMD ["node", "src/index.js"]
```

```yaml
# docker-compose.yml
services:
  api:
    build: .
    ports:
      - "${API_PORT:-3000}:3000"
    environment:
      - NODE_ENV=${NODE_ENV:-development}
      - MONGODB_URI=mongodb://mongo:27017/myapp
      - REDIS_URL=redis://redis:6379
      - JWT_SECRET=${JWT_SECRET}
    depends_on:
      - mongo
      - redis
    volumes:
      - ./src:/app/src               # 开发时热重载
    restart: unless-stopped
    networks:
      - app-network

  mongo:
    image: mongo:6
    ports:
      - "27017:27017"
    environment:
      MONGO_INITDB_DATABASE: myapp
    volumes:
      - mongo-data:/data/db
    restart: unless-stopped
    networks:
      - app-network

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    command: redis-server --appendonly yes
    volumes:
      - redis-data:/data
    restart: unless-stopped
    networks:
      - app-network

  mongo-express:
    image: mongo-express:1
    ports:
      - "8081:8081"
    environment:
      ME_CONFIG_MONGODB_URL: mongodb://mongo:27017/
    depends_on:
      - mongo
    profiles:
      - debug
    networks:
      - app-network

networks:
  app-network:
    driver: bridge

volumes:
  mongo-data:
  redis-data:
```

```bash
# 启动所有服务
docker compose up -d

# 启动时带上 debug profile（额外启动 Mongo Express）
docker compose --profile debug up -d

# 查看日志
docker compose logs -f api

# 停止所有服务（保留数据）
docker compose down

# 停止并清除所有数据
docker compose down -v
```

## 9.8 实战：用 Compose 编排 Python Flask + PostgreSQL + Celery 应用

项目结构：

```bash
my-flask-app/
├── docker-compose.yml
├── .env
├── Dockerfile
├── requirements.txt
├── app/
│   ├── __init__.py
│   ├── main.py
│   └── tasks.py
└── nginx/
    └── nginx.conf
```

```dockerfile
# Dockerfile
FROM python:3.11-slim
WORKDIR /app
RUN apt-get update && apt-get install -y gcc && rm -rf /var/lib/apt/lists/*
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["gunicorn", "--bind", "0.0.0.0:5000", "app.main:app"]
```

```yaml
# docker-compose.yml
services:
  web:
    build: .
    command: gunicorn --bind 0.0.0.0:5000 --workers 4 --reload app.main:app
    ports:
      - "5000:5000"
    environment:
      - FLASK_ENV=${FLASK_ENV:-development}
      - DATABASE_URL=postgresql://postgres:${DB_PASSWORD}@db:5432/myapp
      - REDIS_URL=redis://redis:6379/0
      - CELERY_BROKER_URL=redis://redis:6379/1
    volumes:
      - ./app:/app/app
    depends_on:
      - db
      - redis
    restart: unless-stopped
    networks:
      - app-net

  worker:
    build: .
    command: celery -A app.tasks.celery worker --loglevel=info
    environment:
      - DATABASE_URL=postgresql://postgres:${DB_PASSWORD}@db:5432/myapp
      - CELERY_BROKER_URL=redis://redis:6379/1
    volumes:
      - ./app:/app/app
    depends_on:
      - db
      - redis
    restart: unless-stopped
    networks:
      - app-net

  beat:
    build: .
    command: celery -A app.tasks.celery beat --loglevel=info
    environment:
      - CELERY_BROKER_URL=redis://redis:6379/1
    depends_on:
      - redis
    restart: unless-stopped
    networks:
      - app-net

  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - postgres-data:/var/lib/postgresql/data
    restart: unless-stopped
    networks:
      - app-net

  redis:
    image: redis:7-alpine
    command: redis-server --appendonly yes --maxmemory 128mb --maxmemory-policy allkeys-lru
    volumes:
      - redis-data:/data
    restart: unless-stopped
    networks:
      - app-net

  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - web
    profiles:
      - production
    restart: unless-stopped
    networks:
      - app-net

networks:
  app-net:
    driver: bridge

volumes:
  postgres-data:
  redis-data:
```

```bash
# 开发环境启动（不包含 Nginx）
docker compose up -d

# 生产环境启动（包含 Nginx）
docker compose --profile production up -d

# 水平扩展 Worker
docker compose up -d --scale worker=3

# 进入 Web 容器执行数据库迁移
docker compose exec web flask db upgrade
```

> [!TIP] 提示
> Celery Worker 和 Web 服务使用相同的 Dockerfile（同一个镜像），只是 `command` 不同。这就是 Docker 的魅力——同一个镜像，不同的启动命令，就能扮演不同角色。

## 本章小结

- Docker Compose 将多容器应用的编排从"手动挡"升级为"自动挡"
- `docker-compose.yml` 通过 services、networks、volumes 三大核心概念描述应用架构
- Compose V2（`docker compose`）是当前的推荐版本，V1 已停止维护
- 环境变量和 `.env` 文件是管理配置的利器，但要注意敏感信息保护
- 同一个镜像 + 不同的 `command` = 不同角色的服务

## 练习

1. **基础练习**：为上面的 Node.js 示例添加一个 `docker-compose.override.yml`，在开发环境中自动挂载源码目录并开启热重载。
2. **进阶练习**：在 Flask 项目中添加一个 Flower 服务（Celery 监控面板），只在 `monitoring` profile 下启动。
3. **挑战练习**：搭建一个完整的 WordPress + MySQL + phpMyAdmin + Redis 的博客系统，要求 phpMyAdmin 只在 debug profile 下可用。
