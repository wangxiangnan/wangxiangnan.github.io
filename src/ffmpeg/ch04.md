# 第4章：多媒体基础——视频是怎么存起来的

> 在写更多 FFmpeg 命令之前，我们需要搞清楚一个根本问题：视频到底是什么？它是怎么被存在硬盘上的？为什么同一个视频，MP4 格式 500MB，WebM 格式只有 300MB，画面却看起来差不多？理解这些底层原理，你才能真正掌控 FFmpeg 的每一个参数，而不是只会背命令。

## 4.1 数字图像基础：像素、分辨率、色彩深度

**像素（Pixel）**

视频的每一帧画面，本质上是一张数字图片。这张图片由无数个微小的方格组成，每个方格就是一个"像素"（Pixel，即 Picture Element 的缩写）。每个像素记录了一个颜色值。

**分辨率（Resolution）**

分辨率就是"这张图片有多少个像素"。常见的分辨率：

| 名称 | 像素数 | 总像素（每帧） |
| ------ | -------- | -------------- |
| 720p (HD) | 1280 × 720 | 921,600 |
| 1080p (Full HD) | 1920 × 1080 | 2,073,600 |
| 4K (UHD) | 3840 × 2160 | 8,294,400 |
| 8K | 7680 × 4320 | 33,177,600 |

可以看到，4K 的像素数量是 1080p 的 4 倍——这意味着每帧画面的数据量也是 4 倍。

**色彩深度（Bit Depth）**

每个像素用多少个 bit 来描述颜色？

- **8-bit**：每个颜色通道 256 个级别，RGB 三个通道组合起来可以表示 256×256×256 = 约 1677 万种颜色。这是最常见的色彩深度。
- **10-bit**：每个颜色通道 1024 个级别，总共约 10.7 亿种颜色。HDR 视频通常使用 10-bit。
- **12-bit**：更专业的领域使用，如杜比视界（Dolby Vision）。

## 4.2 色彩空间：RGB vs YUV

**RGB（红绿蓝）**

计算机显示器使用 RGB 色彩空间：每个像素由红（R）、绿（G）、蓝（B）三个颜色通道组成，每个通道 8-bit，总共 24-bit（3 字节）描述一个像素的颜色。

**YUV（亮度 + 色度）**

视频领域几乎都使用 YUV 色彩空间，而不是 RGB。为什么？

这源于人类视觉系统的一个生理特性：**人眼对亮度变化非常敏感，但对颜色变化的敏感度要低得多**。

YUV 把颜色信息分成两部分：

- **Y（Luma / 亮度）**：描述画面的明暗程度
- **U 和 V（Chroma / 色度）**：描述画面的颜色信息

这种分离带来了一个巨大的好处：**可以对色度信息进行"压缩"（降低采样率），而人眼几乎察觉不到差异**。

**色度子采样（Chroma Subsampling）**

这就是 YUV 色彩空间最实用的技巧。常见的子采样格式：

- **4:4:4**：亮度和色度都不压缩，每个像素都有独立的 Y、U、V 值。专业影视后期使用。
- **4:2:2**：水平方向色度分辨率减半。每 2 个水平相邻像素共享一组 UV 值。专业视频制作使用。
- **4:2:0**：水平和垂直方向色度分辨率都减半。每 2×2 的像素块共享一组 UV 值。这是消费级视频（YouTube、Netflix、蓝光光盘）的标准格式，也是最常用的格式。

```
4:4:4 示意（每像素独立UV）    4:2:0 示意（2x2像素块共享UV）

Y U V  Y U V  Y U V  Y U V   Y U V  Y     Y U V  Y
Y U V  Y U V  Y U V  Y U V   Y      Y     Y      Y
Y U V  Y U V  Y U V  Y U V   Y U V  Y     Y U V  Y
Y U V  Y U V  Y U V  Y U V   Y      Y     Y      Y
```

用 4:2:0 子采样，数据量可以减少约 25%，而画质损失微乎其微——这就是为什么几乎所有消费级视频都使用 4:2:0。

## 4.3 帧的概念：I帧、P帧、B帧

视频本质上是一连串快速播放的图片（帧）。但如果每一帧都完整存储，数据量会大到无法接受。视频编码的核心魔法就是：**不是每一帧都存完整画面，大部分帧只存"变化量"**。

这就是 I帧、P帧、B帧 的由来。用一个"抄作业"的比喻来理解：

**I帧（Intra-coded frame / 关键帧）**

I帧是"完全自己写作业的好学生"。它是一帧完整的、独立编码的画面，不依赖任何其他帧就能解码显示。

- I帧 = 完整的快照
- 文件体积最大
- 是视频的"锚点"，P帧和B帧都需要参照它

**P帧（Predictive frame / 前向预测帧）**

P帧是"抄前一帧作业，只写差异部分"的学生。它参考前面的 I帧或P帧，只记录"从上一帧到这一帧发生了什么变化"。

- P帧 = 差异补丁（diff patch）
- 文件体积比 I帧小很多（通常只有 I帧的 1/3 到 1/5）
- 需要按顺序解码，先有前面的参考帧，才能还原 P帧

**B帧（Bi-predictive frame / 双向预测帧）**

B帧是"同时抄前面和后面同学作业，然后取平均值"的学生。它同时参考前面和后面的帧来做插值预测，只记录"插值预测与真实画面的差异"。

- B帧 = 双向插值 + 残差
- 文件体积最小（可以小到 I帧的 1/10 甚至更少）
- 编码和解码都更复杂，但压缩效率最高

**三者的压缩效率对比（近似值）：**

| 帧类型 | 相对大小 | 压缩比 | 编码复杂度 |
| -------- | --------- | -------- | ----------- |
| I帧 | 100% | 低 | 低 |
| P帧 | 20%-35% | 中 | 中 |
| B帧 | 5%-15% | 高 | 高 |

这就是为什么一段 30 分钟的视频压缩后只有几百 MB——大部分帧只存储了"变化量"，而不是完整画面。

## 4.4 GOP（Group of Pictures）结构

GOP 是"画面组"的缩写，指的是从一个 I帧到下一个 I帧之间的帧序列。

```
一个典型的 GOP 结构（GOP 大小 = 12）：

I  B  B  P  B  B  P  B  B  P  B  B  |  I  B  B  P ...
↑  ←——— 一个 GOP（12帧）———→  ↑      ↑
I帧                        下一个I帧  再下一个I帧
```

**GOP 大小的影响：**

- **较小的 GOP（如 30，约 1 秒）**：I帧更频繁，随机跳转（seek）更快更精确，但文件更大。适合直播、视频会议。
- **较大的 GOP（如 250，约 10 秒）**：I帧更少，压缩效率更高，文件更小，但 seek 更慢。适合点播视频、电影存储。

在 FFmpeg 中可以用 `-g` 参数控制 GOP 大小：

```bash
# 设置 GOP 大小为 60（假设 30fps，即每 2 秒一个关键帧）
ffmpeg -i input.mp4 -c:v libx264 -g 60 output.mp4
```

## 4.5 帧率（FPS）

帧率是指每秒钟播放多少帧画面。不同的场景使用不同的帧率：

| 场景 | 常用帧率 | 原因 |
| ------ | --------- | ------ |
| 电影 | 24fps | 历史惯例（胶片时代），24fps 有"电影感"的动态模糊 |
| 电视剧/综艺 | 25fps（PAL）或 30fps（NTSC） | 与当地电视制式的电源频率匹配 |
| 网络视频 | 30fps | 流畅度与文件大小的良好平衡 |
| 游戏视频/直播 | 60fps | 动作场景需要更高帧率来保证流畅 |
| 慢动作拍摄 | 120fps / 240fps | 高帧率拍摄后减速播放实现慢动作效果 |

```bash
# 查看视频帧率
ffprobe -v error -select_streams v:0 -show_entries stream=r_frame_rate,avg_frame_rate -of default=noprint_wrappers=1 input.mp4

# 输出示例：
# r_frame_rate=30/1       ← 原始帧率
# avg_frame_rate=30000/1001  ← 平均帧率（29.97fps 常见于 NTSC 制式视频）

# 在 FFmpeg 中改变帧率
ffmpeg -i input.mp4 -r 30 output.mp4         # 输出 30fps
ffmpeg -i input.mp4 -r 60 output.mp4         # 输出 60fps（会用插帧或重复帧来补充）
```

> **注意**：用 `-r` 降低帧率会丢弃帧，用 `-r` 提高帧率会重复帧（不会变得更流畅，只是文件变大）。如果要真正提升流畅度，需要使用帧插值滤镜（如 `minterpolate`），但计算量很大。

## 4.6 码率（Bitrate）

码率是视频文件每秒包含的数据量，单位通常是 kbps（千比特每秒）或 Mbps（兆比特每秒）。码率直接决定了视频的文件大小和画质。

**算一笔账**：1080p 30fps 4:2:0 8-bit 的未压缩原始视频数据量：

```
每帧像素数：1920 × 1080 = 2,073,600 像素
Y通道：2,073,600 × 8 bit = 16,588,800 bit
U通道（4:2:0，四分之一像素）：518,400 × 8 bit = 4,147,200 bit
V通道（同U通道）：4,147,200 bit
每帧总计：24,883,200 bit ≈ 3.11 MB
每秒 30 帧：93.3 MB/s ≈ 746 Mbps
一分钟：5,598 MB ≈ 5.5 GB/分钟
```

**5.5 GB/分钟！** 这就是为什么我们必须压缩。经过 H.264 编码后，通常只需要 5-10 Mbps（压缩了约 100 倍），画质依然很好。

**三种码率控制模式：**

**CBR（Constant Bitrate / 恒定码率）**

码率始终不变，无论画面是静止还是剧烈运动。

- 优点：码率稳定，适合直播推流（带宽可预测）
- 缺点：静止画面浪费码率，运动画面码率不够用

```bash
# CBR 模式（使用 -b:v 设定目标码率，配合 -maxrate 和 -bufsize）
ffmpeg -i input.mp4 -c:v libx264 -b:v 5M -maxrate 5M -bufsize 10M output.mp4
```

**VBR（Variable Bitrate / 可变码率）**

码率根据画面复杂度动态调整。运动场景分配更多码率，静止场景分配更少。

- 优点：同文件大小下画质更好
- 缺点：码率不可预测，不适合严格带宽限制的直播

**CRF（Constant Rate Factor / 恒定质量因子）**

这是最推荐的码率控制方式。你告诉编码器"我要这个质量水平"，编码器自动调整码率来达到目标质量。

- CRF 值越小 → 质量越高 → 文件越大
- CRF 值越大 → 质量越低 → 文件越小
- libx264 的默认 CRF 是 23，视觉无损大约在 18 以下

```bash
# CRF 模式（推荐）
ffmpeg -i input.mp4 -c:v libx264 -crf 23 output.mp4

# 高质量（几乎看不出压缩痕迹）
ffmpeg -i input.mp4 -c:v libx264 -crf 18 output.mp4

# 低质量（明显有压缩痕迹，但文件很小）
ffmpeg -i input.mp4 -c:v libx264 -crf 32 output.mp4
```

**CRF 数值与视觉质量的对应关系（libx264）：**

| CRF 值 | 视觉质量 | 适用场景 |
| -------- | --------- | --------- |
| 0 | 数学无损 | 几乎不用 |
| 18 | 视觉无损 | 高质量存档 |
| 23 | 默认，良好 | 日常使用 |
| 28 | 可接受的压缩痕迹 | 网络传播、节省空间 |
| 35+ | 明显块效应 | 低带宽场景 |

## 4.7 音频基础

视频不只有画面，还有声音。音频也有自己的基本参数：

**采样率（Sample Rate）**

声波是连续的模拟信号，数字化时需要以固定频率"采样"。采样率就是每秒采集多少次。

- **44100 Hz**：CD 音质标准，每秒采样 44100 次。人耳能听到 20Hz-20000Hz，根据奈奎斯特定理，采样率需要至少是最高频率的 2 倍，所以 44100Hz 刚好能覆盖人耳听觉范围。
- **48000 Hz**：视频领域的标准采样率（DVD、蓝光、流媒体视频）
- **96000 Hz / 192000 Hz**：高解析度音频（Hi-Res Audio），用于专业音乐制作

**位深（Bit Depth）**

每次采样用多少 bit 来记录振幅值。

- **16-bit**：65536 个振幅级别，CD 音质标准，足够日常使用
- **24-bit**：16777216 个级别，专业录音使用
- **32-bit float**：浮点运算，专业后期制作使用

**声道（Channels）**

- **单声道（Mono）**：1 个声道
- **立体声（Stereo）**：2 个声道（左/右），最常见
- **5.1 环绕声**：6 个声道（左、右、中、左环绕、右环绕、低音），家庭影院标准
- **7.1 环绕声**：8 个声道，蓝光电影常用

```bash
# 查看音频流信息
ffprobe -v error -select_streams a:0 -show_entries stream=sample_rate,bits_per_sample,channels,codec_name -of default=noprint_wrappers=1 input.mp4

# 输出示例：
# codec_name=aac
# sample_rate=48000
# bits_per_sample=0     ← AAC 是有损编码，不直接暴露位深
# channels=2
```

## 本章小结

- 数字视频由像素组成，分辨率决定像素数量，色彩深度决定每个像素的精度
- 视频使用 YUV 而非 RGB，因为人眼对亮度比色度更敏感，可以对色度做子采样压缩
- 4:2:0 子采样是最常用的格式，每 2×2 像素块共享色度信息，节省约 25% 数据量
- I帧是完整快照，P帧只存前向差异，B帧做双向插值——这是视频压缩的核心原理
- GOP 是相邻两个 I帧之间的帧序列，大小影响 seek 性能和压缩效率
- 未压缩的 1080p 视频约 5.5GB/分钟，编码后只需几十 MB/分钟
- CRF 是最推荐的码率控制方式，数值越小质量越高
- 音频关注采样率（44100/48000Hz）、位深（16bit）、声道数（单声道/立体声/环绕声）
