# Ch08: Node.js 后端应用 — apps/api

## 本章目标

> 搭建一个生产就绪的 Express 后端应用，涵盖 RESTful 路由设计、中间件架构、请求验证（Zod 4 + 共享 Schema）、Prisma 7 数据库集成，以及端到端类型安全。重点讲解 monorepo 环境下后端服务的组织方式和最佳实践。

**开发脚本里的 `--conditions=development` 是做什么的？**

`@taskflow/shared` 的 `exports` 中，`development` 条件指向 `src/*.ts` 源码。`tsx` 默认只看 `import` 条件，会加载 `dist/*.js`；加上 `--conditions=development` 后，开发时直接运行 shared 的 TS 源码，修改后 `tsx watch` 会立即重启，不需要先构建 shared。生产构建仍然走 `import` 条件读取 `dist`。

**为什么用 `tsx` 而不是 `ts-node`？**

`tsx` 基于 esbuild，启动速度远快于 `ts-node`。`tsx watch` 能在文件变更后毫秒级重启，而 `ts-node` 在大型项目中往往需要数秒。更重要的是，`tsx` 原生支持 ESM、`exports` 条件解析和现代 TypeScript 语法，与本章的 ESM 配置天然契合。

## 8.2 应用入口和中间件配置

把 HTTP 应用与服务器启动拆成两个文件：`app.ts` 负责组装中间件和路由，`index.ts` 只负责监听端口。这样测试可以直接导入 `app`，不必真的占用端口。

创建 `apps/api/src/app.ts`：

```typescript
import express from 'express';
import cors from 'cors';
import helmet from 'helmet';
import morgan from 'morgan';
import { createHealthResponse } from '@taskflow/shared';
import { env } from './config/env.js';
import { errorHandler } from './middleware/error-handler.js';
import { authRoutes } from './routes/auth.routes.js';
import { userRoutes } from './routes/user.routes.js';

export const app = express();

// ====== 安全中间件 ======
app.use(helmet());

// CORS 配置 — 只允许白名单中的前端地址
app.use(cors({
  origin: env.CORS_ORIGINS,
  credentials: true,
}));

// ====== 解析中间件 ======
app.use(express.json({ limit: '1mb' }));
app.use(express.urlencoded({ extended: true }));

// ====== 日志中间件 ======
app.use(morgan(env.NODE_ENV === 'production' ? 'combined' : 'dev'));

// ====== 健康检查 ======
// 使用 shared 中的构造函数，版本号与共享包保持一致
app.get('/api/health', (_req, res) => {
  res.json(createHealthResponse());
});

// ====== 业务路由 ======
app.use('/api/auth', authRoutes);
app.use('/api/users', userRoutes);

// ====== 404 处理 ======
app.use((_req, res) => {
  res.status(404).json({
    success: false,
    error: { code: 'NOT_FOUND', message: '请求的资源不存在' },
  });
});

// ====== 全局错误处理中间件（必须放在最后）======
app.use(errorHandler);
```

创建 `apps/api/src/index.ts`：

```typescript
import { app } from './app.js';
import { env } from './config/env.js';

const server = app.listen(env.PORT, () => {
  console.log(`[api] http://localhost:${env.PORT} (${env.NODE_ENV})`);
});

// 收到终止信号时先停止接收新请求，再退出进程
for (const signal of ['SIGINT', 'SIGTERM'] as const) {
  process.on(signal, () => {
    console.log(`[api] received ${signal}, shutting down`);
    server.close(() => process.exit(0));
  });
}

export { server };
```

**为什么错误处理中间件必须放在最后？**

Express 的中间件按注册顺序执行。错误处理中间件（四个参数的函数）只能捕获在它之前注册的中间件和路由中抛出的错误。如果放在路由前面，后面的错误就不会流到它这里。这是 Express 的核心设计，也是初学者最容易踩的坑之一。

**Express 5 的异步错误处理**

Express 5 会自动捕获 async 处理器返回的 rejected Promise，并转交给错误处理中间件。因此控制器里不再需要为每个函数包一层 `try/catch + next(err)`——直接 `throw` 即可。这大幅减少了样板代码，也让错误处理路径更统一。

## 8.3 环境变量管理（dotenv + 类型化的 env）

创建 `apps/api/src/config/env.ts`：

```typescript
import 'dotenv/config';
import { z } from 'zod';

/**
 * 使用 Zod 对环境变量做运行时验证
 *
 * 为什么不直接用 process.env？
 * 1. process.env 的值都是 string | undefined，需要手动转换
 * 2. 缺失的变量往往在运行时才暴露，而且通常是在最不该出错的时候
 * 3. 没有集中管理和文档化的地方
 */
const envSchema = z.object({
  NODE_ENV: z.enum(['development', 'production', 'test']).default('development'),
  PORT: z.coerce.number().int().positive().default(3000),

  // 数据库
  DATABASE_URL: z.url(),

  // JWT
  JWT_SECRET: z.string().min(32, 'JWT_SECRET 至少需要 32 个字符'),
  JWT_REFRESH_SECRET: z.string().min(32, 'JWT_REFRESH_SECRET 至少需要 32 个字符'),

  // CORS：逗号分隔的允许来源列表
  CORS_ORIGINS: z.string()
    .default('http://localhost:5173')
    .transform((value) => value.split(',').map((item) => item.trim())),
});

const parsed = envSchema.safeParse(process.env);

if (!parsed.success) {
  console.error('环境变量验证失败:\n' + z.prettifyError(parsed.error));
  process.exit(1);
}

export const env = parsed.data;
export type Env = z.infer<typeof envSchema>;
```

**Zod 4 的写法变化：** 字符串格式校验从 `z.string().url()` / `z.string().email()` 迁移到顶层的 `z.url()` / `z.email()`；错误格式化推荐使用 `z.prettifyError()`，比已被废弃的 `error.format()` 输出更清晰。

## 8.4 错误处理中间件

创建 `apps/api/src/middleware/error-handler.ts`：

```typescript
import type { Request, Response, NextFunction } from 'express';
import { ZodError } from 'zod';
import { AppError } from '@taskflow/shared/utils';
import type { ApiResponse } from '@taskflow/shared/types';
import { HTTP_STATUS } from '@taskflow/shared/constants';
import { env } from '../config/env.js';

/**
 * 全局错误处理中间件
 *
 * 所有路由和中间件中未被捕获的错误都会到达这里。
 * Express 5 会自动把 async 函数中 rejected 的 Promise 转交过来。
 */
export function errorHandler(
  err: unknown,
  _req: Request,
  res: Response,
  _next: NextFunction,
): void {
  let statusCode: number = HTTP_STATUS.INTERNAL_SERVER_ERROR;
  let code = 'INTERNAL_ERROR';
  let message = '服务器内部错误';
  let details: unknown;

  if (err instanceof AppError) {
    statusCode = err.statusCode;
    code = err.code;
    message = err.message;
    details = err.details;
  } else if (err instanceof ZodError) {
    statusCode = HTTP_STATUS.BAD_REQUEST;
    code = 'VALIDATION_ERROR';
    message = '请求数据验证失败';
    details = err.issues;
  } else if (err instanceof Error) {
    // 非业务错误：开发环境返回原始信息，生产环境隐藏细节
    message = env.NODE_ENV === 'production' ? '服务器内部错误' : err.message;
    if (env.NODE_ENV === 'development') {
      details = { stack: err.stack };
    }
  }

  const response: ApiResponse<never> = {
    success: false,
    error: {
      code,
      message,
      ...(details !== undefined && { details }),
    },
  };

  if (statusCode >= 500) {
    console.error(`[error] ${code}:`, err);
  } else if (env.NODE_ENV === 'development') {
    console.warn(`[warn] ${code}: ${message}`);
  }

  res.status(statusCode).json(response);
}
```

这里用 `err instanceof ZodError` 而不是比较 `err.name`：前者在跨模块、压缩后依然可靠，TypeScript 也能正确收窄类型，不需要任何 `as any`。

> 如果后续接入 `jsonwebtoken`，可以在这个中间件里补充 `TokenExpiredError`、`JsonWebTokenError` 的分支。本章为了保持示例可独立运行，使用模拟 Token，尚未引入该依赖。

创建 `packages/shared/src/schemas/index.ts`：

```typescript
import { z } from 'zod';
import { UserRole } from '../types/index.js';
import {
  PASSWORD_MIN_LENGTH,
  USERNAME_MIN_LENGTH,
  USERNAME_MAX_LENGTH,
} from '../constants/index.js';

/**
 * Zod Schema — 运行时验证 + 自动类型推导
 *
 * 把 Schema 放在 shared 中：
 * 1. 前端可以直接复用做表单验证
 * 2. 从 Schema 推导出的类型与后端 DTO 保持一致
 * 3. 修改验证规则时，前后端同步更新
 */

export const createUserSchema = z.object({
  username: z.string()
    .min(USERNAME_MIN_LENGTH, `用户名至少 ${USERNAME_MIN_LENGTH} 个字符`)
    .max(USERNAME_MAX_LENGTH, `用户名最多 ${USERNAME_MAX_LENGTH} 个字符`)
    .regex(/^[a-zA-Z0-9_-]+$/, '用户名只允许字母、数字、下划线和连字符'),

  email: z.email('邮箱格式不正确'),

  password: z.string()
    .min(PASSWORD_MIN_LENGTH, `密码至少 ${PASSWORD_MIN_LENGTH} 个字符`)
    .regex(/[a-z]/, '密码必须包含小写字母')
    .regex(/[A-Z]/, '密码必须包含大写字母')
    .regex(/[0-9]/, '密码必须包含数字'),

  // z.enum 直接接受原生枚举，推导出的类型就是 UserRole
  role: z.enum(UserRole).optional(),
});

export const updateUserSchema = createUserSchema
  .partial()
  .refine(
    (data) => Object.keys(data).length > 0,
    { message: '至少需要提供一个要更新的字段' },
  );

export const loginSchema = z.object({
  email: z.email('邮箱格式不正确'),
  password: z.string().min(1, '请输入密码'),
});

export const paginationSchema = z.object({
  page: z.coerce.number().int().min(1).default(1),
  pageSize: z.coerce.number().int().min(1).max(100).default(20),
  search: z.string().trim().optional(),
  sortBy: z.enum(['createdAt', 'username', 'email']).default('createdAt'),
  sortOrder: z.enum(['asc', 'desc']).default('desc'),
});

export const idParamSchema = z.object({
  id: z.string().min(1, '缺少资源 ID'),
});

// 从 Schema 推导类型 — 不再手动维护一份 DTO 接口
export type CreateUserInput = z.infer<typeof createUserSchema>;
export type UpdateUserInput = z.infer<typeof updateUserSchema>;
export type LoginInput = z.infer<typeof loginSchema>;
export type PaginationInput = z.infer<typeof paginationSchema>;
export type IdParam = z.infer<typeof idParamSchema>;
```

创建验证中间件 `apps/api/src/middleware/validate.ts`：

```typescript
import type { Request, Response, NextFunction } from 'express';
import type { ZodType } from 'zod';

type ValidationSource = 'body' | 'query' | 'params';

declare global {
  namespace Express {
    interface Request {
      validated?: Partial<Record<ValidationSource, unknown>>;
    }
  }
}

/**
 * 通用请求验证中间件工厂
 *
 * 注意：Express 5 中 req.query 是只读 getter，不能直接赋值。
 * 因此验证结果统一挂到 req.validated，而不是覆盖 req[source]。
 */
export function validate<T>(schema: ZodType<T>, source: ValidationSource = 'body') {
  return (req: Request, _res: Response, next: NextFunction) => {
    const result = schema.safeParse(req[source]);

    if (!result.success) {
      next(result.error);
      return;
    }

    req.validated = { ...req.validated, [source]: result.data };
    next();
  };
}

/** 取出已经验证过的数据；类型断言集中在这一个边界函数里 */
export function validated<T>(req: Request, source: ValidationSource): T {
  const value = req.validated?.[source];
  if (value === undefined) {
    throw new Error(`请求的 ${source} 尚未通过验证`);
  }
  return value as T;
}
```

**为什么不能写 `req.query = result.data`？**

Express 5 把 `req.query` 改成了惰性解析的 getter，直接赋值会抛出 `TypeError: Cannot set property query of #<IncomingMessage> which has only a getter`。把验证结果放进 `req.validated` 既绕开了这个限制，也让"原始请求"和"已验证数据"在类型上保持分离。`noUncheckedIndexedAccess` 下读取 `req.validated?.[source]` 会得到 `unknown | undefined`，因此 `validated<T>` 中的断言是必要的，但它被收敛在一个函数里，而不是散落在业务代码中。

## 8.6 RESTful 路由设计

创建用户路由 `apps/api/src/routes/user.routes.ts`：

```typescript
import { Router } from 'express';
import {
  createUserSchema,
  updateUserSchema,
  paginationSchema,
  idParamSchema,
} from '@taskflow/shared/schemas';
import { validate } from '../middleware/validate.js';
import * as userController from '../controllers/user.controller.js';

const router = Router();

// GET /api/users — 分页、搜索、排序
router.get(
  '/',
  validate(paginationSchema, 'query'),
  userController.listUsers,
);

// GET /api/users/:id
router.get(
  '/:id',
  validate(idParamSchema, 'params'),
  userController.getUser,
);

// POST /api/users
router.post(
  '/',
  validate(createUserSchema),
  userController.createUser,
);

// PUT /api/users/:id
router.put(
  '/:id',
  validate(idParamSchema, 'params'),
  validate(updateUserSchema),
  userController.updateUser,
);

// DELETE /api/users/:id
router.delete(
  '/:id',
  validate(idParamSchema, 'params'),
  userController.deleteUser,
);

export { router as userRoutes };
```

创建认证路由 `apps/api/src/routes/auth.routes.ts`：

```typescript
import { Router } from 'express';
import { loginSchema } from '@taskflow/shared/schemas';
import { validate } from '../middleware/validate.js';
import * as authController from '../controllers/auth.controller.js';

const router = Router();

router.post('/login', validate(loginSchema), authController.login);
router.post('/logout', authController.logout);
router.post('/refresh', authController.refreshToken);
```

**路由前缀只写一次**

`app.use('/api/users', userRoutes)` 已经提供了 `/api/users` 前缀，路由文件内部只写 `/`、`/:id`。共享常量 `API_ROUTES` 中的 `/api/users` 供前端和文档使用；后端如果再把完整路径写进路由，反而会出现 `/api/users/api/users` 这类重复拼接。

## 8.7 控制器层 — 共享类型在 API 响应中的使用

创建 `apps/api/src/controllers/user.controller.ts`：

```typescript
import { randomUUID } from 'node:crypto';
import type { Request, Response } from 'express';
import { UserRole } from '@taskflow/shared/types';
import type { User } from '@taskflow/shared/types';
import type {
  CreateUserInput,
  UpdateUserInput,
  PaginationInput,
  IdParam,
} from '@taskflow/shared/schemas';
import {
  successResponse,
  NotFoundError,
  formatDate,
} from '@taskflow/shared/utils';
import { HTTP_STATUS } from '@taskflow/shared/constants';
import { validated } from '../middleware/validate.js';

const mockUser: User = {
  id: '1',
  username: 'admin',
  email: 'admin@example.com',
  role: UserRole.ADMIN,
  createdAt: '2024-01-01T00:00:00.000Z',
  updatedAt: '2024-01-01T00:00:00.000Z',
};

/** 获取用户列表 */
export async function listUsers(req: Request, res: Response): Promise<void> {
  const query = validated<PaginationInput>(req, 'query');

  // 模拟数据库查询；接入 Prisma 后替换为 prisma.user.findMany(...)
  const users: User[] = [mockUser];

  res.json(successResponse(users, {
    page: query.page,
    pageSize: query.pageSize,
    total: users.length,
    totalPages: 1,
  }));
}

/** 获取单个用户 */
export async function getUser(req: Request, res: Response): Promise<void> {
  const { id } = validated<IdParam>(req, 'params');
  const user: User | null = id === mockUser.id ? mockUser : null;

  if (!user) {
    throw new NotFoundError('用户', id);
  }

  res.json(successResponse(user));
}

/** 创建用户 */
export async function createUser(req: Request, res: Response): Promise<void> {
  const data = validated<CreateUserInput>(req, 'body');

  const newUser: User = {
    id: randomUUID(),
    username: data.username,
    email: data.email,
    role: data.role ?? UserRole.VIEWER,
    createdAt: formatDate(new Date()),
    updatedAt: formatDate(new Date()),
  };

  // 密码不会出现在响应中 — 这是 DTO 与实体分离的价值
  res.status(HTTP_STATUS.CREATED).json(successResponse(newUser));
}

/** 更新用户 */
export async function updateUser(req: Request, res: Response): Promise<void> {
  const { id } = validated<IdParam>(req, 'params');
  const data = validated<UpdateUserInput>(req, 'body');

  const updatedUser: User = {
    ...mockUser,
    id,
    username: data.username ?? mockUser.username,
    email: data.email ?? mockUser.email,
    role: data.role ?? mockUser.role,
    updatedAt: formatDate(new Date()),
  };

  res.json(successResponse(updatedUser));
}

/** 删除用户 */
export async function deleteUser(
  _req: Request,
  res: Response,
): Promise<void> {
  res.status(HTTP_STATUS.NO_CONTENT).send();
}
```

创建认证控制器 `apps/api/src/controllers/auth.controller.ts`：

```typescript
import type { Request, Response } from 'express';
import type { LoginInput } from '@taskflow/shared/schemas';
import type { LoginResponse } from '@taskflow/shared/types';
import { UserRole } from '@taskflow/shared/types';
import {
  successResponse,
  UnauthorizedError,
  formatDate,
} from '@taskflow/shared/utils';
import { JWT_CONFIG } from '@taskflow/shared/constants';
import { validated } from '../middleware/validate.js';

export async function login(req: Request, res: Response): Promise<void> {
  const { email, password } = validated<LoginInput>(req, 'body');

  // 模拟认证；生产环境应查询数据库并用 bcrypt/argon2 校验哈希
  if (email !== 'admin@example.com' || password !== 'Admin123') {
    throw new UnauthorizedError('邮箱或密码不正确');
  }

  const response: LoginResponse = {
    user: {
      id: '1',
      username: 'admin',
      email: 'admin@example.com',
      role: UserRole.ADMIN,
      createdAt: formatDate(new Date()),
      updatedAt: formatDate(new Date()),
    },
    accessToken: 'mock-access-token-' + Date.now(),
    refreshToken: 'mock-refresh-token-' + Date.now(),
    expiresIn: JWT_CONFIG.ACCESS_TOKEN_EXPIRY,
  };

  res.json(successResponse(response));
}

export async function logout(
  _req: Request,
  res: Response,
): Promise<void> {
  // 生产环境应将 refresh token 加入黑名单或删除服务端会话
  res.json(successResponse({ message: '已退出登录' }));
}

export async function refreshToken(
  _req: Request,
  res: Response,
): Promise<void> {
  // 模拟刷新；生产环境应校验 refresh token 并轮换
  res.json(successResponse({
    accessToken: 'new-mock-access-token-' + Date.now(),
    expiresIn: JWT_CONFIG.ACCESS_TOKEN_EXPIRY,
  }));
}
```

注意所有控制器都没有 `try/catch`：Express 5 会自动把 async 函数抛出的错误交给 `errorHandler`。`UserRole.ADMIN` 来自共享枚举，因此不再需要 `'admin' as any` 这类断言。

> 示例使用模拟 Token。生产环境应使用 `jsonwebtoken` 或 `jose` 签发短期 access token，并把 refresh token 存入可撤销的服务端存储；密码必须用 bcrypt/argon2 哈希，绝不能明文保存。

## 8.8 数据库集成：Prisma 7 在 Monorepo 中的放置策略

数据库相关代码放在独立包 `packages/database` 中，而不是塞进 `apps/api`：

- **职责分离**：HTTP 层不应直接依赖 ORM 细节，未来 WebSocket 服务、定时任务可以复用同一个数据库包
- **迁移集中**：Schema 和 migration 只存在一份
- **类型单一来源**：Prisma Schema 生成的数据类型可以被多个服务引用

### 创建数据库包

```bash
mkdir -p packages/database/prisma
cd packages/database
pnpm init
```

创建 `packages/database/package.json`：

**与 `@taskflow/shared` 不同，数据库包导出的是构建产物（`dist/`），而不是源码。** 原因有三点：

### Prisma 7 配置

Prisma 7 有四个关键变化：默认生成器改为 `prisma-client`、必须指定 `output`、连接数据库必须使用 driver adapter、`prisma.config.ts` 取代了 `package.json#prisma` 且不再自动加载 `.env`。

创建 `packages/database/prisma.config.ts`：

```typescript
import 'dotenv/config';
import { defineConfig } from 'prisma/config';

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: {
    path: 'prisma/migrations',
  },
  datasource: {
    // 直接读 process.env：这样 prisma generate 在没有 DATABASE_URL 时也能运行
    url: process.env.DATABASE_URL ?? '',
  },
});
```

创建 `packages/database/prisma/schema.prisma`：

```prisma
generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"
}

datasource db {
  provider = "postgresql"
}

model User {
  id        String   @id @default(uuid())
  username  String   @unique
  email     String   @unique
  password  String   // 存储 bcrypt/argon2 哈希，永远不返回给前端
  role      Role     @default(VIEWER)
  avatar    String?
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  @@map("users")
}

enum Role {
  ADMIN
  EDITOR
  VIEWER
}
```

注意 `datasource` 块里没有 `url`：Prisma 7 从 `prisma.config.ts` 读取连接串，这样同一份 Schema 可以在不同环境中复用。

创建 `packages/database/.env`（CLI 专用，与 `apps/api/.env` 中的连接串保持一致）：

```bash
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/taskflow?schema=public
```

执行迁移并生成客户端：

```bash
pnpm db:migrate -- --name init
pnpm db:generate
```

`src/generated/prisma` 是生成产物，建议加入 `.gitignore`，并在 CI/Docker 构建时通过 `pnpm build` 重新生成。

### Prisma Client 单例

创建 `packages/database/src/index.ts`：

```typescript
import { PrismaPg } from '@prisma/adapter-pg';
import { PrismaClient } from './generated/prisma/client.js';

const connectionString = process.env.DATABASE_URL;
if (!connectionString) {
  throw new Error('DATABASE_URL 未设置，无法初始化 Prisma Client');
}

/**
 * 全局单例：开发环境的 watch 模式会反复重新执行模块，
 * 每次 new PrismaClient() 都会新建连接池，最终耗尽数据库连接。
 */
const globalForPrisma = globalThis as unknown as {
  prisma?: PrismaClient;
};

export const prisma =
  globalForPrisma.prisma ??
  new PrismaClient({
    adapter: new PrismaPg({ connectionString }),
    log: process.env.NODE_ENV === 'development'
      ? ['query', 'error', 'warn']
      : ['error'],
  });

if (process.env.NODE_ENV !== 'production') {
  globalForPrisma.prisma = prisma;
}

export { PrismaClient };
export type { User as PrismaUser } from './generated/prisma/client.js';
export { Role } from './generated/prisma/enums.js';
```

**为什么需要 `PrismaPg`？** Prisma 7 移除了内置的 Rust 查询引擎，`new PrismaClient()` 必须传入 driver adapter。PostgreSQL 使用 `@prisma/adapter-pg` + `pg`，连接串由 adapter 接管。忘记 adapter 会在启动时直接报错，而不是等到第一次查询。

在 `apps/api` 中添加依赖：

```bash
pnpm --filter @taskflow/api add @taskflow/database@workspace:*
pnpm install
```

然后先构建数据库包，API 才能加载到 `dist`：

```bash
pnpm --filter @taskflow/database build
```

> Turborepo 的 `dependsOn: ["^build"]` 会在根目录执行 `pnpm build` 时自动保证这个顺序；单独开发 API 时，数据库 Schema 变更后记得重新执行一次 `pnpm --filter @taskflow/database build`。

## 8.9 端到端类型安全的完整链路

类型在整个 monorepo 中的流动路径：

```
packages/database (Prisma Schema)
    │
    │  prisma generate
    ▼
packages/database (PrismaUser / Role)
    │
    │  显式映射（字段名、枚举大小写、Date → ISO 字符串）
    ▼
packages/shared (User / UserRole / Zod Schema)
    │
    ├──▶ apps/api（用 shared 类型构造响应）
    │       │
    │       │  HTTP JSON
    │       ▼
    │    apps/web（用 shared 类型解析响应）
    │
    └──▶ 类型一致性由 TypeScript 编译器保证
```

Prisma 的 `Role` 是大写枚举，shared 的 `UserRole` 是小写字符串枚举；Prisma 的 `createdAt` 是 `Date`，shared 的 `User.createdAt` 是 ISO 字符串。这层差异不应该泄漏到前端，应该在数据库包或服务层显式转换：

```typescript
import { Role } from '@taskflow/database';
import type { PrismaUser } from '@taskflow/database';
import { UserRole } from '@taskflow/shared/types';
import type { User } from '@taskflow/shared/types';

// satisfies 保证映射覆盖所有 Prisma 角色，新增枚举值时会编译报错
const ROLE_MAP = {
  ADMIN: UserRole.ADMIN,
  EDITOR: UserRole.EDITOR,
  VIEWER: UserRole.VIEWER,
} satisfies Record<Role, UserRole>;

export function toSharedUser(row: PrismaUser): User {
  return {
    id: row.id,
    username: row.username,
    email: row.email,
    avatar: row.avatar ?? undefined,
    role: ROLE_MAP[row.role],
    createdAt: row.createdAt.toISOString(),
    updatedAt: row.updatedAt.toISOString(),
  };
}
```

**实际效果：**

```typescript
// ====== apps/api ======
const row = await prisma.user.findUniqueOrThrow({ where: { id } });
const user: User = toSharedUser(row);
res.json(successResponse(user));

// ====== apps/web ======
const response = await apiClient.get<ApiResponse<User>>(`/api/users/${id}`);
const username = response.data.data?.username;
// username 的类型是 string | undefined — 编译器提醒你处理用户不存在的情况
```

如果给 `User` 增加 `phone?: string` 字段，TypeScript 会检查 `toSharedUser` 是否补上了该字段；如果给 Prisma 的 `Role` 新增枚举值，`ROLE_MAP` 的 `satisfies` 会立刻报错。业务代码中不再出现 `as any`，唯一一处类型断言被收敛在 `validated<T>` 这个边界函数中。

## 本章小结

- Express 5 会自动捕获 async 错误，控制器可以直接 `throw`，无需层层 `try/catch`
- 类型化环境变量（Zod 4）在启动时立即暴露配置错误
- 请求验证使用共享 Zod Schema，前后端复用同一份规则
- 验证结果放在 `req.validated`，避免 Express 5 中 `req.query` 只读 getter 的赋值错误
- Prisma 7 使用 `prisma-client` 生成器、`prisma.config.ts` 和 driver adapter，数据库包导出编译产物
- 端到端类型安全的核心链路：Prisma Schema → 显式映射 → shared 类型 → API 响应 → 前端解析
