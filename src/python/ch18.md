# 第 18 章 上下文管理器与元类初探

你去酒店入住，前台给你一张房卡（资源），你进房间享受设施（使用资源），退房时把房卡还给前台（释放资源）。如果忘了还房卡，后面的人就没法入住——这就是"资源泄漏"。在编程中，打开文件、建立网络连接、获取数据库连接、加锁……都是需要"借用再归还"的资源。

上下文管理器（Context Manager）就是 Python 版的"酒店前台"：它保证你借走的资源一定会归还，即使你中途出了意外（抛异常）。而元类则是更底层的概念——如果说类是对象的模具，那元类就是类的模具。元类让你在类被创建的那一刻介入，修改类的行为。这两个特性一个偏实用（日常管理资源），一个偏底层（控制类的创建），但都是 Python 高级编程的必备知识。

## 18.1 with 语句与上下文管理器协议

### 回顾 with 语句

你在文件操作章节已经用过 `with`：

```python
with open("data.txt", "r") as f:
    content = f.read()
# 离开 with 块时，文件自动关闭——即使中间发生了异常
```

`with` 语句的背后是**上下文管理器协议**，它由两个方法组成：

- `__enter__(self)`：进入 `with` 块时调用，返回值赋给 `as` 后面的变量
- `__exit__(self, exc_type, exc_val, traceback)`：离开 `with` 块时调用，负责清理

### 手写一个上下文管理器

```python
class FileManager:
    """自定义文件管理器（演示协议）"""

    def __init__(self, filename, mode):
        self.filename = filename
        self.mode = mode

    def __enter__(self):
        print(f"打开文件: {self.filename}")
        self.file = open(self.filename, self.mode)
        return self.file  # 这个值赋给 as 后面的变量

    def __exit__(self, exc_type, exc_val, traceback):
        print(f"关闭文件: {self.filename}")
        self.file.close()
        # 返回 False 表示不抑制异常（让异常继续传播）
        return False


with FileManager("test.txt", "w") as f:
    f.write("Hello, World!")
# 输出：
# 打开文件: test.txt
# 关闭文件: test.txt
```

### **exit** 的异常处理

`__exit__` 方法接收三个参数，它们描述了 `with` 块中发生的异常：

```python
class ExceptionHandler:
    def __enter__(self):
        print("进入上下文")
        return self

    def __exit__(self, exc_type, exc_val, traceback):
        if exc_type is not None:
            print(f"捕获到异常: {exc_type.__name__}: {exc_val}")
            return True  # 返回 True = 抑制异常（不让它继续传播）
        print("正常退出")
        return False


# 情况 1：正常执行
with ExceptionHandler():
    print("一切正常")
# 进入上下文 → 一切正常 → 正常退出

# 情况 2：发生异常但被抑制
with ExceptionHandler():
    print("要出错了")
    raise ValueError("测试错误")
    print("这行不会执行")
# 进入上下文 → 要出错了 → 捕获到异常: ValueError: 测试错误
```

小贴士：`__exit__` 返回 `True` 会抑制异常，返回 `False` 或 `None` 会让异常继续传播。大部分上下文管理器应该返回 `False`——除非你明确知道要在这里处理异常。

## 18.2 contextlib：更简洁的写法

手写类来实现上下文管理器有时太啰嗦。`contextlib` 模块提供了更轻量的方式。

### @contextmanager 装饰器

用生成器函数 + `@contextmanager` 装饰器，几行代码就能创建上下文管理器：

```python
from contextlib import contextmanager
import time

@contextmanager
def timer(label=""):
    """计时上下文管理器"""
    start = time.perf_counter()
    yield  # yield 之前 = __enter__，之后 = __exit__
    elapsed = time.perf_counter() - start
    print(f"{label} 耗时: {elapsed:.4f} 秒")


with timer("数据库查询"):
    time.sleep(0.1)  # 模拟耗时操作
# 数据库查询 耗时: 0.1003 秒
```

`yield` 把函数分成两半：

- `yield` 之前：相当于 `__enter__`
- `yield` 的值：赋给 `as` 后面的变量
- `yield` 之后：相当于 `__exit__`

### 带异常处理的 @contextmanager

```python
from contextlib import contextmanager

@contextmanager
def suppress_errors(*exceptions):
    """抑制指定类型的异常"""
    try:
        yield
    except exceptions as e:
        print(f"已抑制异常: {type(e).__name__}: {e}")


with suppress_errors(ValueError, TypeError):
    int("not a number")  # ValueError 被抑制

# with suppress_errors(ValueError):
#     1 / 0  # ZeroDivisionError 不会被抑制
```

### contextlib.closing

`closing` 把任何有 `close()` 方法的对象变成上下文管理器：

```python
from contextlib import closing
import urllib.request

# 没有 closing 时，你需要手动确保 close
# 有了 closing，即使出错也会关闭
with closing(urllib.request.urlopen("https://httpbin.org/get")) as response:
    data = response.read()
# response.close() 自动调用
```

### contextlib.ExitStack：动态管理多个上下文

```python
from contextlib import ExitStack

# 当你不确定要打开多少个文件时
filenames = ["file1.txt", "file2.txt", "file3.txt"]

with ExitStack() as stack:
    files = [stack.enter_context(open(f, "w")) for f in filenames]
    for f, name in zip(files, filenames):
        f.write(f"写入 {name}")
# 所有文件都会被关闭
```

## 18.3 上下文管理器的实际应用场景

### 临时切换目录

```python
import os
from contextlib import contextmanager

@contextmanager
def working_directory(path):
    """临时切换工作目录"""
    old_dir = os.getcwd()
    os.chdir(path)
    try:
        yield path
    finally:
        os.chdir(old_dir)  # 无论发生什么，切回原目录


with working_directory("/tmp"):
    print(f"当前目录: {os.getcwd()}")  # /tmp
print(f"回到: {os.getcwd()}")          # 原来的目录
```

### 数据库事务管理

```python
from contextlib import contextmanager

class Database:
    def __init__(self):
        self.committed = False
        self.rolled_back = False

    def commit(self):
        self.committed = True
        print("事务已提交")

    def rollback(self):
        self.rolled_back = True
        print("事务已回滚")


@contextmanager
def transaction(db):
    """数据库事务上下文管理器"""
    try:
        yield db
        db.commit()   # 一切正常 → 提交
    except Exception:
        db.rollback()  # 出错 → 回滚
        raise          # 让异常继续传播


db = Database()
with transaction(db):
    print("执行数据库操作...")
# 执行数据库操作...
# 事务已提交
```

### 临时修改配置

```python
from contextlib import contextmanager

_config = {"debug": False, "timeout": 30}

@contextmanager
def temporary_config(**overrides):
    """临时修改配置，退出时恢复"""
    old_values = {k: _config[k] for k in overrides if k in _config}
    _config.update(overrides)
    try:
        yield _config
    finally:
        _config.update(old_values)
        # 删除新增的键
        for k in overrides:
            if k not in old_values:
                del _config[k]


print(_config)  # {'debug': False, 'timeout': 30}
with temporary_config(debug=True, timeout=5):
    print(_config)  # {'debug': True, 'timeout': 5}
print(_config)  # {'debug': False, 'timeout': 30}  ← 自动恢复
```

## 18.4 元类基础

### type 是类的类

在 Python 中，一切皆对象——包括类本身。那么类是由谁创建的呢？答案是 `type`。

```python
class MyClass:
    pass

obj = MyClass()

print(type(obj))      # <class '__main__.MyClass'>  ← obj 是 MyClass 的实例
print(type(MyClass))  # <class 'type'>               ← MyClass 是 type 的实例！

# type 既是函数（查看类型），也是元类（创建类）
print(type(int))      # <class 'type'>
print(type(str))      # <class 'type'>
print(type(type))     # <class 'type'>  ← type 是自己的实例（元循环）
```

理解这个关系链：**`type` → 创建 → `MyClass` → 创建 → `obj`**

### 用 type() 动态创建类

`type()` 除了查看类型，还能动态创建类：

```python
# type(类名, 基类元组, 属性字典)
Dog = type("Dog", (), {"species": "犬科", "bark": lambda self: "汪汪!"})

dog = Dog()
print(dog.species)   # 犬科
print(dog.bark())    # 汪汪!
print(type(Dog))     # <class 'type'>

# 等价于手写：
# class Dog:
#     species = "犬科"
#     def bark(self):
#         return "汪汪!"
```

### **new** vs **init**

类的创建过程分为两步：`__new__`（创建实例）和 `__init__`（初始化实例）。

```python
class Person:
    def __new__(cls, name, age):
        print(f"__new__ 被调用：创建 {cls.__name__} 实例")
        instance = super().__new__(cls)  # 创建实例
        return instance

    def __init__(self, name, age):
        print(f"__init__ 被调用：初始化 {self.__class__.__name__}")
        self.name = name
        self.age = age


p = Person("Alice", 25)
# __new__ 被调用：创建 Person 实例
# __init__ 被调用：初始化 Person
```

`__new__` 是类方法（第一个参数是 `cls`），负责创建并返回实例。`__init__` 是实例方法（第一个参数是 `self`），负责初始化已经创建的实例。大多数时候你只需要 `__init__`，但在单例模式和不可变类型中，`__new__` 非常有用。

## 18.5 元类：控制类的创建

元类是"类的类"。当 Python 执行 `class` 语句时，它会调用元类来创建类。默认元类是 `type`，但你可以指定自定义元类：

```python
class MyMeta(type):
    """一个简单的元类"""

    def __new__(mcs, name, bases, namespace):
        # mcs: 元类自身
        # name: 类名
        # bases: 基类元组
        # namespace: 类的属性字典

        print(f"正在创建类: {name}")
        print(f"  基类: {bases}")
        print(f"  属性: {list(namespace.keys())}")

        # 可以在这里修改类的属性
        namespace["created_by"] = "MyMeta"

        return super().__new__(mcs, name, bases, namespace)


class MyClass(metaclass=MyMeta):
    x = 10
    def method(self):
        pass

# 输出：
# 正在创建类: MyClass
#   基类: ()
#   属性: ['x', 'method', '__module__', '__qualname__']

print(MyClass.created_by)  # MyMeta
```

### 元类的实用场景

#### 自动注册子类

```python
class PluginMeta(type):
    """插件注册元类：自动收集所有插件子类"""
    _registry: dict[str, type] = {}

    def __new__(mcs, name, bases, namespace):
        cls = super().__new__(mcs, name, bases, namespace)
        # 跳过基类本身，只注册子类
        if bases:
            mcs._registry[name.lower()] = cls
        return cls

    @classmethod
    def get_plugin(mcs, name: str):
        return mcs._registry.get(name.lower())


class Plugin(metaclass=PluginMeta):
    """插件基类"""
    pass


class PDFExporter(Plugin):
    def export(self):
        return "导出 PDF"


class CSVExporter(Plugin):
    def export(self):
        return "导出 CSV"


# 自动注册
print(PluginMeta._registry)
# {'pdfexporter': <class 'PDFExporter'>, 'csvexporter': <class 'CSVExporter'>}

# 通过名字获取插件
exporter_cls = PluginMeta.get_plugin("pdfexporter")
print(exporter_cls().export())  # 导出 PDF
```

#### 属性验证元类

```python
class ValidatedMeta(type):
    """确保所有子类都定义了 docstring"""

    def __new__(mcs, name, bases, namespace):
        cls = super().__new__(mcs, name, bases, namespace)
        # 跳过基类
        if bases and not cls.__doc__:
            raise TypeError(f"类 {name} 必须定义文档字符串！")
        return cls


class Base(metaclass=ValidatedMeta):
    """基类"""
    pass


class GoodChild(Base):
    """这是一个好孩子"""
    pass


# class BadChild(Base):  # TypeError: 类 BadChild 必须定义文档字符串！
#     pass
```

## 18.6 元类的替代方案

元类虽然强大，但大多数情况下有更简单的替代方案。Python 社区有句名言："如果你不确定是否需要元类，那你就不需要。"

### 用 `__init_subclass__` 替代元类

Python 3.6+ 引入了 `__init_subclass__`，它让父类可以在子类被定义时介入，无需元类：

```python
class PluginBase:
    _registry: dict[str, type] = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        # 子类被定义时自动调用
        PluginBase._registry[cls.__name__.lower()] = cls
        print(f"注册插件: {cls.__name__}")


class ImageProcessor(PluginBase):
    pass

class VideoProcessor(PluginBase):
    pass

print(PluginBase._registry)
# {'imageprocessor': ..., 'videoprocessor': ...}
```

### 用类装饰器替代元类

```python
def auto_repr(cls):
    """自动生成 __repr__ 方法的类装饰器"""
    def __repr__(self):
        attrs = ", ".join(f"{k}={v!r}" for k, v in self.__dict__.items())
        return f"{cls.__name__}({attrs})"
    cls.__repr__ = __repr__
    return cls


@auto_repr
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(3, 4)
print(p)  # Point(x=3, y=4)
```

小贴士：能用 `__init_subclass__` 解决的，不用元类。能用类装饰器解决的，不用元类。元类是最后的手段。

## 18.7 延伸阅读

- **dataclasses 模块**：用装饰器自动生成 `__init__`、`__repr__`、`__eq__` 等方法
- **attrs 库**（PyPI）：比 dataclasses 更强大的替代方案
- **abc 模块**：`ABCMeta` 元类用于定义抽象基类，强制子类实现特定方法
- **PEP 487**：`__init_subclass__` 的引入提案

## 18.8 小结

- **上下文管理器**：`__enter__` + `__exit__` 协议，保证资源清理。`@contextmanager` 用生成器简化实现。
- **元类**：`type` 是所有类的元类。自定义元类可以控制类的创建过程，但大多数场景可以用 `__init_subclass__` 或类装饰器替代。
- ****new** vs **init****：`__new__` 创建实例，`__init__` 初始化实例。单例等模式需要 `__new__`。

import os
from contextlib import contextmanager

@contextmanager
def temp_env(**vars):
    old_values = {}
    for key, value in vars.items():
        old_values[key] = os.environ.get(key)
        os.environ[key] = value
    try:
        yield

class ReadOnlyMeta(type):
    def __call__(cls, *args, **kwargs):
        instance = super().__call__(*args, **kwargs)
        instance.__frozen__ = True
        return instance

## 18.11 常见错误与避坑

**1. **exit** 忘了处理异常**

```python
# 如果 __exit__ 中做清理工作，要用 try/finally
class ResourceManager:
    def __exit__(self, exc_type, exc_val, tb):
        # 如果这里的清理代码本身抛异常，原异常会丢失！
        self.resource.close()

# 更安全的写法
class SafeResourceManager:
    def __exit__(self, exc_type, exc_val, tb):
        try:
            self.resource.close()
        except Exception:
            if exc_type is None:
                raise  # 没有原异常时才重新抛出
```

**2. @contextmanager 中 yield 后忘记处理异常**

```python
from contextlib import contextmanager

# 不安全：异常会跳过清理代码
@contextmanager
def unsafe():
    setup()
    yield
    cleanup()  # 如果 yield 处抛异常，这行不执行！

# 安全：用 try/finally
@contextmanager
def safe():
    setup()
    try:
        yield
    finally:
        cleanup()  # 无论是否异常都会执行
```

**3. 元类冲突**

```python
# 如果一个类继承了两个使用不同元类的基类，会报错
class MetaA(type): pass
class MetaB(type): pass
class A(metaclass=MetaA): pass
class B(metaclass=MetaB): pass
# class C(A, B): pass  # TypeError: metaclass conflict!

# 解决：创建一个继承两者的元类
class MetaAB(MetaA, MetaB): pass
class C(A, B, metaclass=MetaAB): pass
```

**4. 过度使用元类**

元类很酷，但不要为了炫技而用。90% 的场景可以用 `__init_subclass__`、类装饰器或普通继承解决。只有在需要控制"类如何被创建"时才考虑元类。
