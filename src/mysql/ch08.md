# 第8章 集合操作

## 8.1 集合操作的比喻：SQL里的集合论

还记得高中数学里的集合运算吗？并集、交集、差集——这些概念在SQL里同样适用，而且非常实用。当你的数据分布在不同的表或来自不同的查询条件时，集合操作就像"拼接积木"一样，把多个查询结果合并成一个统一的结果集。

想象你有两个购物清单：一个是你老婆让买的菜，一个是你自己想买的零食。并集（UNION）就是两份清单合在一起全买了；交集（INTERSECT）就是碰巧两份清单上都有的东西（比如奶茶，两个人都爱喝）；差集（EXCEPT）就是只在老婆清单上有但你自己不想买的（比如苦瓜）。

SQL中的集合操作有一个重要特点：它是**纵向合并**（按行拼接），和JOIN的**横向合并**（按列拼接）完全不同。UNION是把一个查询的结果"堆"在另一个查询结果的下面，而JOIN是把两个表按条件"并排"放在一起。

## 8.2 UNION 与 UNION ALL

UNION是最常用的集合操作，它把两个查询的结果纵向合并在一起。UNION默认会去重——如果两个查询中有完全相同的行，最终结果只保留一份。UNION ALL则保留所有行，不去重。

我们先准备两张示例表来演示集合操作：

```sql
-- 创建在职员工表和离职员工表
CREATE TABLE current_employees (
    emp_id INT, emp_name VARCHAR(50), department VARCHAR(30)
);
CREATE TABLE former_employees (
    emp_id INT, emp_name VARCHAR(50), department VARCHAR(30)
);

INSERT INTO current_employees VALUES
(1, '张三', '技术部'), (2, '李四', '市场部'), (3, '王五', '技术部');

INSERT INTO former_employees VALUES
(2, '李四', '市场部'), (4, '赵六', '财务部'), (5, '钱七', '技术部');
```

```sql
-- UNION：合并并自动去重（李四在两张表中都有，只出现一次）
SELECT emp_name, department FROM current_employees
UNION
SELECT emp_name, department FROM former_employees;
-- 结果：张三、李四、王五、赵六、钱七（共5行，李四去重了）

-- UNION ALL：合并但保留所有行（李四出现两次）
SELECT emp_name, department FROM current_employees
UNION ALL
SELECT emp_name, department FROM former_employees;
-- 结果：6行，李四出现两次
```

> [!TIP] 提示
> UNION 默认去重，需要对整个结果集进行排序和比较来找出重复行，这个过程有额外的性能开销。如果你确定不会有重复数据，或者根本不关心是否有重复，始终用 UNION ALL。在大数据量场景下，UNION ALL 的性能可以是 UNION 的好几倍。

## 8.3 INTERSECT（MySQL 8.0.31+）

INTERSECT返回两个查询结果的交集——只保留在两个结果集中都存在的行。这就像两个朋友圈的共同好友列表。MySQL从8.0.31版本开始支持INTERSECT，之前的版本需要用其他方法模拟：

```sql
-- 找出既在在职员工表又在离职员工表中的人（可能离职后又重新入职了）
SELECT emp_name, department FROM current_employees
INTERSECT
SELECT emp_name, department FROM former_employees;
-- 结果：李四, 市场部（他在两张表中都有完全匹配的记录）

-- 老版本MySQL模拟INTERSECT的写法（用INNER JOIN）
SELECT DISTINCT ce.emp_name, ce.department
FROM current_employees ce
INNER JOIN former_employees fe
  ON ce.emp_name = fe.emp_name AND ce.department = fe.department;
```

> [!WARNING] 注意
> INTERSECT在MySQL 8.0.31之前的版本不支持，如果你用的是MySQL 5.7或8.0.30及更早的版本，执行INTERSECT会报语法错误。可以先用 `SELECT VERSION()` 检查你的MySQL版本号。

## 8.4 EXCEPT（差集）

EXCEPT返回在第一个查询中存在、但在第二个查询中不存在的行——也就是"差集"。注意EXCEPT是有方向的：`A EXCEPT B` 和 `B EXCEPT A` 的结果完全不同。就像"你有但我没有的东西"和"我有但你没有的东西"是两回事：

```sql
-- 找出只在在职表中、不在离职表中的员工
SELECT emp_name, department FROM current_employees
EXCEPT
SELECT emp_name, department FROM former_employees;
-- 结果：张三(技术部), 王五(技术部)
-- 李四被排除了（因为他在离职表中也有）

-- 反过来：找出只在离职表中的员工
SELECT emp_name, department FROM former_employees
EXCEPT
SELECT emp_name, department FROM current_employees;
-- 结果：赵六(财务部), 钱七(技术部)
```

和INTERSECT一样，EXCEPT也需要MySQL 8.0.31+。老版本可以用NOT EXISTS或LEFT JOIN来模拟差集操作。

## 8.5 集合操作的列匹配规则

使用集合操作时，有几条重要规则必须遵守，否则MySQL会报语法错误。第一条是两个查询返回的列数必须一致，不能一个返回3列另一个返回2列。第二条是对应位置的列数据类型需要兼容，MySQL会自动做隐式类型转换，但如果类型差异太大（比如一个是日期一个是字符串）可能出问题。第三条是结果集的列名取自第一个SELECT语句，后面的查询的列名会被忽略：

```sql
-- 正确做法：列数匹配，类型兼容
SELECT emp_name, department FROM current_employees
UNION
SELECT emp_name, department FROM former_employees;

-- 可以用常量列来补齐列数（标记数据来源）
SELECT emp_name, department, '在职' AS status FROM current_employees
UNION ALL
SELECT emp_name, department, '离职' AS status FROM former_employees;
-- 结果集有3列：emp_name, department, status
```

## 8.6 ORDER BY 在集合操作中的使用

ORDER BY只能在整个集合操作的最后使用一次，对最终合并后的结果进行排序。你不能在中间的某个SELECT后面单独加ORDER BY，MySQL会报语法错误。这是因为集合操作的结果是一个整体，排序应该在所有数据合并完成后统一进行：

```sql
-- 正确：ORDER BY放在最后一个查询的后面，对合并结果排序
SELECT emp_name, department FROM current_employees
UNION ALL
SELECT emp_name, department FROM former_employees
ORDER BY department, emp_name;

-- 如果希望控制子查询的优先级（比如让在职的排在前面），
-- 需要借助派生表加一个排序辅助列
SELECT * FROM (
    SELECT emp_name, department, 1 AS sort_order FROM current_employees
    UNION ALL
    SELECT emp_name, department, 2 AS sort_order FROM former_employees
) combined
ORDER BY sort_order, emp_name;
```

> [!WARNING] 注意
> 不能在集合操作的中间某个SELECT后面加ORDER BY。比如 `SELECT ... ORDER BY a UNION SELECT ...` 这种写法会报错。排序只能在最终结果上做，这是SQL标准规定的行为。

## 8.7 实际应用场景

集合操作在实际开发中有很多用武之地。最常见的场景是合并多张结构相同但数据不同的表（比如按年份或按地区分表的数据），找出不同数据集之间的差异（如新增用户、流失用户），以及把多个维度的统计信息合并到同一个结果集中：

```sql
-- 场景一：合并多个分表的数据做统一查询
SELECT * FROM orders_2023
UNION ALL
SELECT * FROM orders_2024
UNION ALL
SELECT * FROM orders_2025
ORDER BY order_date DESC
LIMIT 20;

-- 场景二：报表汇总——不同部门的统计合并到一个结果集
SELECT '技术部' AS dept, COUNT(*) AS cnt, AVG(salary) AS avg_sal
FROM employees WHERE department = '技术部'
UNION ALL
SELECT '市场部', COUNT(*), AVG(salary)
FROM employees WHERE department = '市场部'
UNION ALL
SELECT '财务部', COUNT(*), AVG(salary)
FROM employees WHERE department = '财务部'
UNION ALL
SELECT '全公司', COUNT(*), AVG(salary)
FROM employees;
```

> [!TIP] 提示
> 最后一个报表汇总场景的写法虽然能用，但效率不高（要扫描employees表4次）。更好的做法是用GROUP BY + WITH ROLLUP，或者用第10章的窗口函数来实现，只需要扫描一次表就能得到所有统计信息。

## 小结

集合操作让你可以把多个查询结果像集合一样进行并、交、差运算。UNION和UNION ALL是最常用的，区别在于是否去重；INTERSECT和EXCEPT需要MySQL 8.0.31+才支持。记住三个核心规则：列数必须匹配、类型要兼容、ORDER BY只能放最后。性能上，UNION ALL优于UNION（省去了去重排序的开销）。
