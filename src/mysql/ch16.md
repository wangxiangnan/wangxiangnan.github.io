# 第16章 触发器与事件

**生活类比：** 触发器就像自动感应门——你不需要手动开门，走近了就自动打开。事件就像闹钟——到了设定的时间就自动执行某个任务。它们都是数据库的"自动化装置"，让某些操作在满足条件时自动发生。

## 16.1 创建触发器

触发器是在特定事件（INSERT/UPDATE/DELETE）发生前后自动执行的SQL代码块。

```sql
DELIMITER $$

-- BEFORE INSERT 触发器：插入前自动设置入职日期
CREATE TRIGGER trg_before_insert_employee
BEFORE INSERT ON employees
FOR EACH ROW
BEGIN
    IF NEW.hire_date IS NULL THEN
        SET NEW.hire_date = CURDATE();
    END IF;
END$$

-- AFTER INSERT 触发器：插入后记录日志
CREATE TRIGGER trg_after_insert_employee
AFTER INSERT ON employees
FOR EACH ROW
BEGIN
    INSERT INTO employee_audit_log (
        action, employee_id, employee_name, created_at
    ) VALUES (
        'INSERT', NEW.id, NEW.name, NOW()
    );
END$$

DELIMITER ;
```

## 16.2 NEW 与 OLD 关键字

在触发器中，`NEW` 代表新数据（即将写入的值），`OLD` 代表旧数据（修改前的值）：

| 操作 | NEW | OLD |
|------|-----|-----|
| INSERT | 有（新插入的行） | 无 |
| UPDATE | 有（更新后的值） | 有（更新前的值） |
| DELETE | 无 | 有（被删除的行） |

```sql
DELIMITER $$

-- UPDATE 触发器：记录薪资变更
CREATE TRIGGER trg_salary_change
AFTER UPDATE ON employees
FOR EACH ROW
BEGIN
    IF OLD.salary != NEW.salary THEN
        INSERT INTO salary_change_log (
            employee_id, old_salary, new_salary, change_date
        ) VALUES (
            NEW.id, OLD.salary, NEW.salary, NOW()
        );
    END IF;
END$$

-- DELETE 触发器：防止删除在职员工
CREATE TRIGGER trg_before_delete_employee
BEFORE DELETE ON employees
FOR EACH ROW
BEGIN
    IF OLD.status = 'active' THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '不能删除在职员工，请先将其状态改为离职';
    END IF;
END$$

DELIMITER ;
```

## 16.3 触发器执行顺序

对于同一个表的同一种操作，执行顺序是固定的：

1. **BEFORE 触发器** —— 在操作之前执行
2. **实际操作** —— INSERT / UPDATE / DELETE
3. **AFTER 触发器** —— 在操作之后执行

```sql
DELIMITER $$

-- 演示执行顺序
CREATE TRIGGER trg_before_update
BEFORE UPDATE ON employees
FOR EACH ROW
BEGIN
    INSERT INTO trigger_log (message) VALUES ('1. BEFORE UPDATE 触发');
END$$

CREATE TRIGGER trg_after_update
AFTER UPDATE ON employees
FOR EACH ROW
BEGIN
    INSERT INTO trigger_log (message) VALUES ('3. AFTER UPDATE 触发');
END$$

DELIMITER ;

-- 执行UPDATE后查看trigger_log，你会发现：
-- 1. BEFORE UPDATE 触发
-- 2. （实际的UPDATE操作在这里发生）
-- 3. AFTER UPDATE 触发
```

> [!TIP] 提示
> 如果 BEFORE 触发器中抛出了异常（通过 SIGNAL），那么实际操作和 AFTER 触发器都不会执行。这让你可以在操作发生前做校验和拦截。

## 16.4 触发器的限制与注意事项

触发器虽然强大，但也有不少限制：

- **同一个表、同一个事件、同一个时机只能有一个触发器**（例如不能有两个 BEFORE INSERT）
- **触发器中不能使用事务控制语句**（COMMIT / ROLLBACK）
- **触发器不能调用存储过程中带有OUT参数的过程**
- **触发器可能导致级联效应**：一个触发器触发另一个操作，又触发另一个触发器...
- **调试困难**：触发器是"隐式"执行的，不容易追踪问题

```sql
-- 查看已有触发器
SHOW TRIGGERS FROM your_database;

-- 查看触发器的详细信息
SELECT * FROM information_schema.TRIGGERS
WHERE TRIGGER_SCHEMA = 'your_database';

-- 删除触发器
DROP TRIGGER IF EXISTS trg_before_insert_employee;
```

> [!WARNING] 注意
> 触发器是"隐形杀手"——它们在背后默默运行，不看表定义很难发现。团队协作时一定要做好文档记录，避免"为什么这条INSERT莫名其妙失败了"的灵异事件。

## 16.5 事件调度器(Event Scheduler)

事件就是数据库的"定时任务"，相当于Linux的cron。

```sql
-- 首先开启事件调度器（默认关闭）
SET GLOBAL event_scheduler = ON;

-- 查看状态
SHOW VARIABLES LIKE 'event_scheduler';
```

**一次性事件（AT）：**

```sql
-- 在指定时间执行一次
CREATE EVENT evt_archive_old_logs
ON SCHEDULE AT '2024-12-31 23:59:00'
DO
BEGIN
    INSERT INTO logs_archive
    SELECT * FROM system_logs WHERE log_date < '2024-01-01';

    DELETE FROM system_logs WHERE log_date < '2024-01-01';
END;
```

**周期性事件（EVERY）：**

```sql
-- 每小时执行一次：清理过期会话
CREATE EVENT evt_clean_sessions
ON SCHEDULE EVERY 1 HOUR
STARTS CURRENT_TIMESTAMP
DO
    DELETE FROM user_sessions WHERE expires_at < NOW();

-- 每天凌晨2点执行：生成日报
CREATE EVENT evt_daily_report
ON SCHEDULE EVERY 1 DAY
STARTS CONCAT(CURDATE() + INTERVAL 1 DAY, ' 02:00:00')
DO
BEGIN
    INSERT INTO daily_reports (report_date, order_count, revenue)
    SELECT
        CURDATE() - INTERVAL 1 DAY,
        COUNT(*),
        SUM(amount)
    FROM orders
    WHERE DATE(created_at) = CURDATE() - INTERVAL 1 DAY;
END;
```

## 16.6 管理事件

```sql
-- 查看所有事件
SHOW EVENTS FROM your_database;

-- 暂停事件（不删除）
ALTER EVENT evt_clean_sessions DISABLE;

-- 重新启用
ALTER EVENT evt_clean_sessions ENABLE;

-- 修改调度时间
ALTER EVENT evt_clean_sessions
ON SCHEDULE EVERY 30 MINUTE;

-- 删除事件
DROP EVENT IF EXISTS evt_clean_sessions;
```

> [!TIP] 提示
> 事件调度器在MySQL服务重启后需要重新开启（除非在配置文件中设置 `event_scheduler=ON`）。建议把它写到 my.cnf 配置文件中：`[mysqld] event_scheduler = ON`。

## 16.7 触发器 vs 应用层逻辑

什么时候用触发器，什么时候用应用层代码？一个简单的决策框架：

| 场景 | 推荐方式 | 原因 |
|------|---------|------|
| 自动填充审计字段 | 触发器 | 与业务无关，所有入口都需要 |
| 数据校验 | 应用层 | 方便返回友好错误信息 |
| 复杂业务逻辑 | 应用层 | 方便调试、测试、版本控制 |
| 跨表数据同步 | 视情况 | 简单同步用触发器，复杂的用应用层或消息队列 |
| 数据级联删除 | 外键约束 | 比触发器更可靠、更透明 |

## 小结

触发器和事件是MySQL的两大自动化工具。触发器让你在数据变更前后自动执行逻辑，事件让你按时间表自动执行任务。它们很强大但也很"隐蔽"，使用时要克制——能用应用层代码清晰实现的逻辑，不要硬塞给触发器。
