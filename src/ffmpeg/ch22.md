# 第22章：HLS 切片与点播服务

> HLS 是流媒体世界的"普通话"——虽然不是最完美的，但人人都会、人人都懂。掌握了 HLS，你就掌握了覆盖 90% 场景的流媒体能力。

## 22.1 HLS 基础切片命令

先来看一条最完整的 HLS 切片命令：

```bash
ffmpeg -i input.mp4 \
  -c:v libx264 -c:a aac \
  -hls_time 10 \
  -hls_list_size 0 \
  -hls_flags delete_segments \
  -hls_segment_filename "segments/seg%03d.ts" \
  "output/stream.m3u8"
```

参数详解：

| 参数 | 说明 |
| ------ | ------ |
| `-hls_time 10` | 每个切片的时长（秒），实际会在关键帧处切割 |
| `-hls_list_size 0` | m3u8 列表中保留的切片数量，0 = 保留所有（点播模式） |
| `-hls_flags delete_segments` | 自动删除超出列表的旧切片（直播模式用） |
| `-hls_segment_filename` | 切片文件的命名模式 |

## 22.2 m3u8 索引文件详解

让我们看看 FFmpeg 生成的 m3u8 文件长什么样：

```
#EXTM3U
#EXT-X-VERSION:3
#EXT-X-TARGETDURATION:10
#EXT-X-MEDIA-SEQUENCE:0
#EXTINF:10.010,
segments/seg000.ts
#EXTINF:10.000,
segments/seg001.ts
#EXTINF:9.500,
segments/seg002.ts
#EXTINF:10.010,
segments/seg003.ts
#EXT-X-ENDLIST
```

各字段含义：

- `#EXTM3U`：文件头标识
- `#EXT-X-VERSION:3`：HLS 版本号（3 支持 AES 加密，6 支持 fMP4，7 支持 LL-HLS）
- `#EXT-X-TARGETDURATION:10`：目标切片时长（实际切片不会超过这个值太多）
- `#EXT-X-MEDIA-SEQUENCE:0`：第一个切片的序号（直播中会递增）
- `#EXTINF:10.010,`：切片的实际时长（秒）
- `#EXT-X-ENDLIST`：结束标记（点播必须有，直播中没有表示还在持续）

## 22.3 自定义切片参数

```bash
# 精确控制切片时长（在关键帧处切割）
ffmpeg -i input.mp4 \
  -c:v libx264 -g 60 -keyint_min 60 \
  -c:a aac \
  -hls_time 6 \
  -hls_flags split_by_time \
  -force_key_frames "expr:gte(t,n_forced*6)" \
  "output/stream.m3u8"
```

- `-force_key_frames "expr:gte(t,n_forced*6)"`：每 6 秒强制插入一个关键帧
- `-hls_flags split_by_time`：按时间切割（而非按关键帧），配合 `-force_key_frames` 使用

**直播模式的 HLS 参数：**

```bash
# 直播模式：只保留最近 5 个切片，自动删除旧的
ffmpeg -re -i input.mp4 \
  -c:v libx264 -preset veryfast -b:v 2000k \
  -c:a aac -b:a 128k \
  -hls_time 6 \
  -hls_list_size 5 \
  -hls_flags delete_segments+append_list \
  -hls_segment_filename "live/seg%05d.ts" \
  "live/stream.m3u8"
```

- `-hls_list_size 5`：m3u8 中只保留最近 5 个切片
- `delete_segments`：自动删除不再需要的切片
- `append_list`：新切片追加到列表末尾（而非替换）

## 22.4 HLS 加密：AES-128

HLS 原生支持 AES-128 加密，保护你的视频内容不被随意下载：

```bash
# 步骤 1：生成加密密钥
openssl rand -base64 16 > enc.key
# 或者生成十六进制密钥
openssl rand 16 > enc.key

# 步骤 2：创建密钥信息文件
echo "http://your-server.com/keys/enc.key" > keyinfo.txt
echo "/path/to/enc.key" >> keyinfo.txt
echo "$(openssl rand -hex 16)" >> keyinfo.txt

# 步骤 3：使用密钥进行 HLS 切片
ffmpeg -i input.mp4 \
  -c:v libx264 -c:a aac \
  -hls_time 10 \
  -hls_list_size 0 \
  -hls_key_info_file keyinfo.txt \
  -hls_segment_filename "encrypted/seg%03d.ts" \
  "encrypted/stream.m3u8"
```

keyinfo.txt 文件格式说明：

- 第 1 行：密钥的 URI（播放器从哪里获取密钥）
- 第 2 行：密钥文件的本地路径（FFmpeg 加密用）
- 第 3 行：IV（初始化向量，可选）

加密后的 m3u8 文件会包含加密信息：

```
#EXTM3U
#EXT-X-VERSION:3
#EXT-X-TARGETDURATION:10
#EXT-X-MEDIA-SEQUENCE:0
#EXT-X-KEY:METHOD=AES-128,URI="http://your-server.com/keys/enc.key",IV=0x1234567890abcdef
#EXTINF:10.0,
seg000.ts
#EXTINF:10.0,
seg001.ts
#EXT-X-ENDLIST
```

**Nginx 密钥服务配置：**

```nginx
server {
    listen 443 ssl;

    # 密钥访问需要鉴权
    location /keys/ {
        # 简单的 token 验证
        if ($arg_token != "your-secret-token") {
            return 403;
        }
        alias /path/to/keys/;
    }

    # HLS 切片
    location /hls/ {
        alias /path/to/hls/;
        types {
            application/vnd.apple.mpegurl m3u8;
            video/mp2t ts;
        }
        add_header Access-Control-Allow-Origin *;
    }
}
```

## 22.5 自适应码率 HLS：多码率变体

这是 HLS 的"完全体"——根据用户网速自动切换画质：

```bash
# 一步生成多码率 HLS
ffmpeg -i input.mp4 \
  -map 0:v -map 0:v -map 0:v -map 0:a -map 0:a -map 0:a \
  -c:v libx264 -c:a aac \
  \
  -b:v:0 5000k -maxrate:v:0 5500k -bufsize:v:0 10000k -s:v:0 1920x1080 \
  -b:v:1 2500k -maxrate:v:1 2750k -bufsize:v:1 5000k -s:v:1 1280x720 \
  -b:v:2 1000k -maxrate:v:2 1100k -bufsize:v:2 2000k -s:v:3 854x480 \
  \
  -b:a:0 128k \
  -b:a:1 96k \
  -b:a:2 64k \
  \
  -f hls \
  -hls_time 6 \
  -hls_playlist_type vod \
  -master_pl_name master.m3u8 \
  -var_stream_map "v:0,a:0 v:1,a:1 v:2,a:2" \
  "hls/vs%v/index.m3u8"
```

这条命令会生成：

```
hls/
├── master.m3u8          ← 主播放列表（包含所有码率信息）
├── vs0/
│   ├── index.m3u8       ← 1080p 播放列表
│   ├── seg000.ts
│   ├── seg001.ts
│   └── ...
├── vs1/
│   ├── index.m3u8       ← 720p 播放列表
│   └── ...
└── vs2/
    ├── index.m3u8       ← 480p 播放列表
    └── ...
```

生成的 `master.m3u8` 内容：

```
#EXTM3U
#EXT-X-VERSION:3
#EXT-X-STREAM-INF:BANDWIDTH=5500000,RESOLUTION=1920x1080
vs0/index.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=2750000,RESOLUTION=1280x720
vs1/index.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=1100000,RESOLUTION=854x480
vs2/index.m3u8
```

## 22.6 HLS 点播服务器搭建

用 Nginx 搭建一个完整的 HLS 点播服务：

```nginx
server {
    listen 80;
    server_name vod.example.com;

    root /var/www/vod;

    # HLS 切片服务
    location /hls/ {
        types {
            application/vnd.apple.mpegurl m3u8;
            video/mp2t ts;
        }

        # 缓存控制
        add_header Cache-Control "public, max-age=31536000";
        add_header Access-Control-Allow-Origin *;
        add_header Access-Control-Allow-Methods "GET, OPTIONS";
        add_header Access-Control-Allow-Headers "Range";

        # TS 切片缓存
        location ~* \.ts$ {
            add_header Cache-Control "public, max-age=31536000";
        }

        # m3u8 不缓存（直播模式）
        location ~* \.m3u8$ {
            add_header Cache-Control "no-cache, no-store";
        }
    }

    # 视频原始文件下载
    location /videos/ {
        add_header Access-Control-Allow-Origin *;
    }

    # 简单的播放器页面
    location / {
        index index.html;
    }
}
```

## 22.7 HLS 与 DASH 的对比和互转

有时候你需要在 HLS 和 DASH 之间转换：

```bash
# HLS 转 DASH（使用 Shaka Packager）
packager \
  in=hls/seg000.ts,stream=video,output=video.mp4 \
  --mpd_output output.mpd

# 用 FFmpeg 从同一源同时生成 HLS 和 DASH
ffmpeg -i input.mp4 \
  -c:v libx264 -c:a aac \
  -f dash \
  -seg_duration 6 \
  -hls_playlist 1 \
  output.mpd
```

`-hls_playlist 1` 参数会让 FFmpeg 在生成 DASH 的同时也生成 HLS 播放列表，一举两得。

## 22.8 Low-Latency HLS (LL-HLS)

标准 HLS 延迟 10-30 秒，LL-HLS 可以做到 2-5 秒。核心改进：

1. **部分片段（Partial Segments）**：把 6 秒的切片再分成多个 1 秒的部分片段
2. **阻塞式播放列表**：播放器请求新的 m3u8 时，服务器等到有新内容才返回
3. **预加载提示（Preload Hints）**：告诉播放器下一个片段即将到来

FFmpeg 5.0+ 支持 LL-HLS：

```bash
ffmpeg -re -i input.mp4 \
  -c:v libx264 -preset veryfast -b:v 2500k \
  -c:a aac -b:a 128k \
  -f hls \
  -hls_time 6 \
  -hls_flags low_latency \
  -hls_fmp4_init_filename init.mp4 \
  -hls_segment_type fmp4 \
  -hls_list_size 10 \
  -lhls 1 \
  "ll-hls/stream.m3u8"
```

- `-hls_flags low_latency`：启用低延迟模式
- `-hls_segment_type fmp4`：使用 fMP4 格式（LL-HLS 要求）
- `-lhls 1`：启用 LL-HLS 特有标签

**HLS fMP4 片段 vs TS 片段：**

传统 HLS 使用 MPEG-TS（`.ts`）格式的切片，但现代 HLS 推荐使用 fMP4（fragmented MP4，`.m4s`）格式：

| 特性 | TS 片段 | fMP4 片段 |
| ------ | --------- | ---------- |
| 文件扩展名 | .ts | .m4s |
| 容器格式 | MPEG Transport Stream | Fragmented MP4 |
| 编码兼容 | 仅 H.264/AAC | H.264/H.265/AV1/AAC/Opus |
| 初始化数据 | 每个片段都携带 | 独立的 init 文件 |
| LL-HLS 支持 | 不支持 | 必须使用 |
| CMAF 兼容 | 不兼容 | 兼容（HLS+DASH共用） |

```bash
# 生成 fMP4 格式的 HLS（推荐用于新项目）
ffmpeg -i input.mp4 \
  -c:v libx264 -c:a aac \
  -hls_time 6 \
  -hls_list_size 0 \
  -hls_segment_type fmp4 \
  -hls_fmp4_init_filename init.mp4 \
  -hls_segment_filename "segments/seg%03d.m4s" \
  "output/stream.m3u8"
```

fMP4 的最大优势是**CMAF（Common Media Application Format）** 兼容——同一套切片文件可以同时用于 HLS 和 DASH，不需要编码两遍。这在大规模视频处理中能省下大量时间和存储空间。

**HLS 性能优化清单：**

在生产环境中部署 HLS 时，以下优化措施可以显著提升用户体验：

1. **预热（Pre-warm）**：在用户访问前先触发 HLS 生成，避免"第一个用户等很久"
2. **分片时长选择**：直播用 2-6 秒（低延迟），点播用 6-10 秒（减少请求数）
3. **GOP 对齐**：确保关键帧间隔是切片时长的因子（如切片 6 秒，GOP 设 2 秒）
4. **CDN 预取**：使用 `preload` 标签告诉 CDN 提前缓存下一个切片
5. **HTTP/2 或 HTTP/3**：多路复用减少连接开销
6. **gzip 压缩 m3u8**：播放列表很小，压缩后更快传输
7. **合理的 CORS 配置**：允许播放器域名的跨域请求

```nginx
# 生产级 HLS Nginx 配置
server {
    listen 443 ssl http2;
    server_name cdn.example.com;

    # Gzip 压缩 m3u8
    gzip on;
    gzip_types application/vnd.apple.mpegurl;
    gzip_min_length 128;

    location /hls/ {
        alias /data/hls/;

        # fMP4 初始化文件
        types {
            application/vnd.apple.mpegurl m3u8;
            video/mp2t ts;
            video/mp4 m4s;
            video/mp4 mp4;
        }

        # VOD 切片：永久缓存
        location ~* /vod/.*\.(ts|m4s|mp4)$ {
            add_header Cache-Control "public, max-age=31536000, immutable";
            add_header Access-Control-Allow-Origin *;
        }

        # 直播切片：短期缓存（3 秒）
        location ~* /live/.*\.(ts|m4s)$ {
            add_header Cache-Control "public, max-age=3";
            add_header Access-Control-Allow-Origin *;
        }

        # VOD m3u8：长期缓存
        location ~* /vod/.*\.m3u8$ {
            add_header Cache-Control "public, max-age=86400";
            add_header Access-Control-Allow-Origin *;
        }

        # 直播 m3u8：不缓存
        location ~* /live/.*\.m3u8$ {
            add_header Cache-Control "no-cache, no-store, must-revalidate";
            add_header Access-Control-Allow-Origin *;
        }
    }
}
```

## 22.9 HLS 播放器兼容性

在前端播放 HLS，最常用的方案：

```html
<!-- 方案一：hls.js（推荐，兼容性最好） -->
<script src="https://cdn.jsdelivr.net/npm/hls.js@latest"></script>
<video id="video" controls></video>
<script>
    const video = document.getElementById('video');
    const url = 'http://server/hls/stream.m3u8';

    if (Hls.isSupported()) {
        const hls = new Hls({
            lowLatencyMode: true,    // 启用低延迟模式
            backBufferLength: 30,    // 保留的缓冲区长度
        });
        hls.loadSource(url);
        hls.attachMedia(video);
        hls.on(Hls.Events.MANIFEST_PARSED, () => video.play());
    } else if (video.canPlayType('application/vnd.apple.mpegurl')) {
        // Safari 原生支持 HLS
        video.src = url;
        video.addEventListener('loadedmetadata', () => video.play());
    }
</script>

<!-- 方案二：video.js -->
<link href="https://vjs.zencdn.net/8.0.4/video-js.css" rel="stylesheet">
<script src="https://vjs.zencdn.net/8.0.4/video.min.js"></script>
<video id="player" class="video-js" controls>
    <source src="http://server/hls/stream.m3u8" type="application/x-mpegURL">
</video>
<script>
    videojs('player', {
        html5: {
            vhs: {
                overrideNative: true,  // 在非 Safari 浏览器使用 hls.js
            }
        }
    });
</script>
```

## 22.10 实战：搭建完整的 HLS 点播 + 直播服务

把前面学的东西整合起来：

```bash
#!/bin/bash
# setup_hls_service.sh - 一键搭建 HLS 点播+直播服务

VOD_DIR="/var/www/hls/vod"
LIVE_DIR="/var/www/hls/live"
INPUT_VIDEO="$1"
VIDEO_NAME="$(basename "$INPUT_VIDEO" .mp4)"

# 创建目录结构
mkdir -p "$VOD_DIR/$VIDEO_NAME"
mkdir -p "$LIVE_DIR"

echo "=== 生成点播 HLS ==="

# 生成多码率 HLS 点播
ffmpeg -i "$INPUT_VIDEO" \
  -map 0:v -map 0:v -map 0:v -map 0:a \
  -c:v libx264 -preset medium -crf 23 \
  -c:a aac -b:a 128k \
  -b:v:0 4000k -s:v:0 1920x1080 \
  -b:v:1 2000k -s:v:1 1280x720 \
  -b:v:2 800k -s:v:2 854x480 \
  -f hls \
  -hls_time 10 \
  -hls_playlist_type vod \
  -master_pl_name master.m3u8 \
  -var_stream_map "v:0,a:0 v:1,a:0 v:2,a:0" \
  "$VOD_DIR/$VIDEO_NAME/vs%v/index.m3u8"

echo "=== 点播 HLS 生成完成 ==="
echo "播放地址: http://server/hls/vod/$VIDEO_NAME/master.m3u8"

# 直播模式（后台运行）
echo "=== 启动直播 HLS ==="
ffmpeg -re -i "$INPUT_VIDEO" \
  -c:v libx264 -preset veryfast -b:v 2500k \
  -c:a aac -b:a 128k \
  -g 60 \
  -f hls \
  -hls_time 6 \
  -hls_list_size 5 \
  -hls_flags delete_segments \
  -hls_segment_filename "$LIVE_DIR/seg%05d.ts" \
  "$LIVE_DIR/stream.m3u8" &

echo "直播地址: http://server/hls/live/stream.m3u8"
echo "服务启动完成！"
```

## 22.11 CDN 分发注意事项

把 HLS 部署到 CDN 时需要注意：

```nginx
# CDN 回源配置
location /hls/ {
    # TS 切片：永久缓存（内容不变）
    location ~* \.ts$ {
        add_header Cache-Control "public, max-age=31536000, immutable";
        add_header CDN-Cache-Control "max-age=31536000";
    }

    # VOD m3u8：短期缓存
    location ~* /vod/.*\.m3u8$ {
        add_header Cache-Control "public, max-age=3600";
    }

    # Live m3u8：不缓存！
    location ~* /live/.*\.m3u8$ {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }
}
```

**CDN 分发最佳实践：**

- TS 切片文件名包含内容哈希或使用递增序号，避免同名覆盖
- 点播 m3u8 可以缓存，直播 m3u8 绝对不能缓存
- 使用 HTTPS 避免运营商劫持
- 配置 CORS 头允许跨域访问

## 22.12 HLS 常见问题排查

在实际部署 HLS 服务时，你大概率会遇到以下问题。这里列出常见症状和解决方案：

**问题 1：播放器显示"无法加载播放列表"**

```
排查步骤：
1. 直接访问 m3u8 URL，看是否返回内容
2. 检查 CORS 头是否正确配置
3. 检查 Content-Type 是否为 application/vnd.apple.mpegurl
4. 检查防火墙是否放行了对应端口
```

**问题 2：视频能播放但频繁卡顿**

```
可能原因：
1. 切片时长太长（>10秒）：降低 -hls_time
2. 码率过高：降低视频码率或提供多码率
3. CDN 缓存未命中：检查 CDN 配置
4. 关键帧间隔不匹配：确保 -g 值是 -hls_time 的因子
```

**问题 3：播放到一半突然黑屏**

```
常见原因：
1. 某个 ts 切片损坏：用 ffprobe 逐个检查切片
2. 推流中断后恢复，导致 m3u8 序号不连续
3. 切片文件被 CDN 或缓存层损坏
```

```bash
# 批量检查 HLS 切片的完整性
for ts in /path/to/hls/*.ts; do
    echo "检查: $ts"
    ffprobe -v error "$ts" 2>&1
done

# 验证 m3u8 文件中的切片是否都存在
while read -r line; do
    if [[ "$line" == *.ts ]] || [[ "$line" == *.m4s ]]; then
        if [ ! -f "/path/to/hls/$line" ]; then
            echo "缺失切片: $line"
        fi
    fi
done < stream.m3u8
```

**问题 4：iOS Safari 无法播放，但 Chrome 正常**

```
排查清单：
1. 确认 HLS 版本兼容性（VERSION:3 最广泛兼容）
2. 确认视频编码为 H.264（iOS 对 H.265 的 HLS 支持有限）
3. 确认音频编码为 AAC（iOS 不支持 MP3 音频的 HLS）
4. 检查 HTTPS（iOS 的 ATS 要求 HTTPS 传输）
5. 检查 m3u8 中是否包含 #EXT-X-ENDLIST（点播模式必须有）
```

**问题 5：直播延迟越来越高**

```
原因分析：
HLS 的延迟 = 切片时长 × 3（播放器缓冲） + 网络传输时间
如果延迟持续增加，说明播放器消费速度跟不上生产速度

解决方案：
1. 减小 -hls_time（如从 10 降到 4）
2. 使用 LL-HLS（延迟可降到 2-5 秒）
3. 检查推流端是否稳定（帧率是否恒定）
4. 播放器端设置较低的 buffer 目标
```

## 本章小结

- HLS 切片核心参数：`-hls_time`（切片时长）、`-hls_list_size`（列表大小）、`-hls_flags`（行为控制）
- m3u8 是 HLS 的索引文件，理解它的每一个标签就能理解 HLS 的一切
- AES-128 加密可以保护你的视频内容不被随意下载，密钥通过 HTTP 分发
- 多码率自适应是提升用户体验的关键，用户网速好就看高清，网速差就自动降画质
- fMP4 切片比传统 TS 切片更现代，支持更多编码格式，且兼容 CMAF（HLS+DASH 共用切片）
- LL-HLS 可以将延迟降低到 2-5 秒，是直播场景的推荐方案
- CDN 部署时要注意缓存策略：TS 切片永久缓存，直播 m3u8 绝对不能缓存，点播 m3u8 短期缓存
- HLS 排查问题时，先检查 m3u8 的 Content-Type 和 CORS 头，再检查切片完整性
