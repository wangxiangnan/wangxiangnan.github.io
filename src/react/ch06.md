# 第6章：useState — 让你的组件"活"起来

![第6章封面](./images/ch06.png)

## 6.1 引言：从"木头人"到"活"组件

在前面的章节里，你已经学会了创建组件、传递 Props、处理事件。但是你有没有发现一个问题？你的组件就像一个"木头人"——它只能展示别人传给它的数据，自己却不会"变"。

想象一下：你做了一个计数器按钮，点击之后数字应该加 1。但是……数字存在哪里呢？Props 是父组件传过来的，子组件不能改。这就好比你开了一家餐厅，菜单上的价格（Props）是老板定的，你作为服务员不能偷偷改——但你需要记住今天卖了多少份菜（这个数据属于你自己）。

**这就是 State 登场的时刻！**

State（状态）是属于组件自己的数据。它让组件能够"记住"一些东西，并在这些东西变化时自动更新界面。有了 State，你的组件就从"木头人"变成了有记忆、能反应的"活"组件。

> **Tip**: 如果你之前学过 class 组件，State 的概念是一样的，只是写法不同。用 `useState` Hook 写起来更简洁，这也是 React 官方推荐的方式。

---

## 6.2 Props vs State：到底有什么区别？

在动手写代码之前，我们先搞清楚一个核心问题：**Props 和 State 到底有什么不同？**

用一个生活中的比喻来说：

| | Props | State |
|---|---|---|
| **比喻** | 别人给你的东西（像生日礼物） | 你自己的东西（像你的体重） |
| **谁拥有** | 父组件 | 当前组件自己 |
| **能不能改** | 不能！只读！ | 能，但要通过 setState |
| **变化时** | 父组件重新传值 | 组件自己重新渲染 |
| **例子** | 用户名、商品列表 | 计数器、输入框的值、弹窗开关 |

**State 就像你的体重**——它属于你自己，别人不能直接修改你的体重，你得自己通过"锻炼"或"吃火锅"来 `setState`。而 Props 就像你的名字——是爸妈（父组件）给你的，你不能自己改（至少在传统家庭里不行 😄）。

---

## 6.3 useState 的基本用法

好了，废话不多说，让我们看看 `useState` 怎么用！

```jsx
import { useState } from 'react';

function Counter() {
  // 声明一个 state 变量，初始值为 0
  // count 是当前值，setCount 是用来更新的函数
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>你点了 {count} 次</p>
      <button onClick={() => setCount(count + 1)}>
        点我 +1
      </button>
    </div>
  );
}

export default Counter;
```

让我们来拆解这段代码：

1. **`import { useState } from 'react'`**：从 React 中导入 `useState` 这个 Hook。
2. **`const [count, setCount] = useState(0)`**：这是"数组解构"语法。`useState(0)` 返回一个数组，里面有两个东西：
   - 第一个：当前的状态值（我们叫它 `count`）
   - 第二个：更新状态的函数（我们叫它 `setCount`）
   - `0` 是初始值，只在组件第一次渲染时使用
3. **`setCount(count + 1)`**：调用这个函数来更新状态，React 收到后会重新渲染组件。

> **Tip**: `count` 和 `setCount` 这两个名字是你可以随便起的！你完全可以写成 `const [banana, setBanana] = useState(0)`，只不过按照惯例，我们一般写成 `xxx` 和 `setXxx` 的形式。

> **Warning**: 千万不要直接修改 state 变量！比如 `count = 5` 是**错误的**。你必须使用 `setCount(5)`。直接修改不会触发重新渲染，界面不会更新——就像你偷偷在心里给自己改了个名字，但身份证上还是旧名字，没人知道。

---

## 6.4 State 更新的"异步"特性

这是一个非常重要的概念，也是很多初学者踩坑的地方。看下面的代码：

```jsx
import { useState } from 'react';

function DelayedCounter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount(count + 1);
    console.log('点击后的 count:', count); // 打印的还是旧值！
  };

  return (
    <div>
      <p>当前值: {count}</p>
      <button onClick={handleClick}>+1</button>
    </div>
  );
}

export default DelayedCounter;
```

你点击按钮后，`console.log` 打印出来的 `count` **还是旧值**！为什么？

因为 **State 更新是"异步"的**。调用 `setCount` 之后，React 不会立刻修改 `count` 变量，而是安排一次重新渲染。在这次渲染完成之前，`count` 仍然是旧值。

这就好比你下单了一杯奶茶——你下了单（调了 setState），但奶茶不会立刻出现在你手里，外卖小哥需要时间送达（重新渲染）。

**如果你想基于上一次的 state 来更新**，请传入一个函数：

```jsx
const handleClick = () => {
  // 错误示范：连续调用不会累加
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1);
  // 结果只加了 1！因为 count 在这三次调用中都是同一个旧值

  // 正确做法：使用函数式更新
  setCount(prevCount => prevCount + 1);
  setCount(prevCount => prevCount + 1);
  setCount(prevCount => prevCount + 1);
  // 结果加了 3！每次都能拿到最新的 prevCount
};
```

> **Warning**: 记住这个黄金法则：**当新值依赖旧值时，永远使用函数式更新 `setState(prev => ...)`。** 这在批量更新、事件合并等场景下至关重要。

## 6.5 State 是替换，不是合并

如果你以前用过 class 组件的 `this.setState()`，你会知道它会自动合并新状态和旧状态。但 `useState` 不一样——**它是直接替换！**

```jsx
// Class 组件时代（自动合并）
this.setState({ name: '张三' }); // 只改 name，其他属性保留

// Hook 时代（直接替换）
const [user, setUser] = useState({ name: '李四', age: 25 });

// 如果你这样做，age 就丢了！
setUser({ name: '张三' }); // user 变成了 { name: '张三' }，age 没了！

// 正确做法：手动展开旧状态
setUser(prevUser => ({ ...prevUser, name: '张三' }));
// user 变成 { name: '张三', age: 25 }，age 保住了
```

> **Tip**: 这也是为什么 React 官方建议：**如果状态之间没有关联，就用多个独立的 `useState`，而不是一个大对象。** 这样每个状态独立管理，更简单清晰。

## 6.6 多个 State 变量

在实际开发中，一个组件通常需要管理多个状态。好消息是，你可以调用多次 `useState`：

```jsx
import { useState } from 'react';

function UserProfile() {
  const [name, setName] = useState('');
  const [age, setAge] = useState(0);
  const [isVip, setIsVip] = useState(false);

  return (
    <div>
      <h2>用户信息</h2>

      <div>
        <label>姓名：</label>
        <input
          value={name}
          onChange={(e) => setName(e.target.value)}
        />
      </div>

      <div>
        <label>年龄：</label>
        <input
          type="number"
          value={age}
          onChange={(e) => setAge(Number(e.target.value))}
        />
      </div>

      <div>
        <label>
          <input
            type="checkbox"
            checked={isVip}
            onChange={(e) => setIsVip(e.target.checked)}
          />
          VIP 会员
        </label>
      </div>

      <hr />
      <p>你好，{name || '匿名用户'}！</p>
      <p>年龄：{age} 岁</p>
      <p>会员状态：{isVip ? '尊贵的 VIP' : '普通用户'}</p>
    </div>
  );
}

export default UserProfile;
```

每个 `useState` 独立管理一个状态，互不影响。是不是清爽多了？

> **Tip**: 选择拆分成多个 `useState` 还是用一个对象，可以遵循这个原则：**如果几个值经常一起变化，用对象；如果它们独立变化，就用多个 useState。**

## 6.7 状态提升（Lifting State Up）

这是 React 中一个非常重要的设计模式。有时候，两个子组件需要共享同一个状态，怎么办？

**答案：把状态提升到它们最近的共同父组件中。**

想象一个场景：你有一个"温度输入框"和一个"温度显示器"，它们需要共享温度值。

```jsx
import { useState } from 'react';

// 温度输入组件
function TemperatureInput({ temperature, onTemperatureChange }) {
  return (
    <div>
      <label>输入温度：</label>
      <input
        type="number"
        value={temperature}
        onChange={(e) => onTemperatureChange(e.target.value)}
        placeholder="请输入温度"
      />
    </div>
  );
}

// 温度显示组件
function TemperatureDisplay({ temperature }) {
  // 判断温度对应的状态
  const getStatus = () => {
    if (temperature < 0) return '🥶 冰天雪地';
    if (temperature < 15) return '🧥 有点冷';
    if (temperature < 28) return '😊 舒适宜人';
    if (temperature < 35) return '🥵 热浪来袭';
    return '🔥 人间炼狱';
  };

  return (
    <div>
      <p>当前温度：<strong>{temperature}°C</strong></p>
      <p>体感：{getStatus()}</p>
      <p>华氏温度：{(temperature * 9 / 5 + 32).toFixed(1)}°F</p>
    </div>
  );
}

// 父组件：管理共享状态
function TemperatureApp() {
  const [temperature, setTemperature] = useState(25);

  return (
    <div style={{ padding: '20px' }}>
      <h2>温度转换器</h2>
      <TemperatureInput
        temperature={temperature}
        onTemperatureChange={setTemperature}
      />
      <hr />
      <TemperatureDisplay temperature={temperature} />
    </div>
  );
}

export default TemperatureApp;
```

**状态提升的流程**：

1. 子组件 `TemperatureInput` 不自己持有 `temperature` 状态
2. 父组件 `TemperatureApp` 用 `useState` 管理 `temperature`
3. 父组件通过 Props 把值传给 `TemperatureInput`（展示用）和 `TemperatureDisplay`（展示用）
4. 父组件通过 Props 把更新函数传给 `TemperatureInput`（修改用）

这就像一个家庭：两个小孩（子组件）想要共享一个玩具（状态），那就把玩具放在客厅（父组件），谁想玩就来客厅拿。

> **Tip**: 状态提升是 React 中"单一数据源"原则的体现。同一个数据应该只存在一份，通过 Props 分发给需要它的组件。这样可以避免数据不一致的 bug。

## 6.8 实战：一个 Todo 输入框

让我们把学到的知识综合起来，做一个 Todo 输入框。这是很多 React 项目的"入门仪式"！

```jsx
import { useState } from 'react';

function TodoApp() {
  // 管理输入框的值
  const [inputValue, setInputValue] = useState('');
  // 管理 todo 列表
  const [todos, setTodos] = useState([]);

  // 处理输入框变化
  const handleInputChange = (e) => {
    setInputValue(e.target.value);
  };

  // 添加 todo
  const handleAdd = () => {
    // 空内容不添加
    if (inputValue.trim() === '') return;

    // 创建新的 todo 对象
    const newTodo = {
      id: Date.now(),           // 用时间戳当临时 ID
      text: inputValue.trim(),
      completed: false,
    };

    // 把新 todo 加到列表里（注意：不要 push，要创建新数组！）
    setTodos(prevTodos => [...prevTodos, newTodo]);

    // 清空输入框
    setInputValue('');
  };

  // 按回车也能添加
  const handleKeyDown = (e) => {
    if (e.key === 'Enter') {
      handleAdd();
    }
  };

  // 删除 todo
  const handleDelete = (id) => {
    setTodos(prevTodos => prevTodos.filter(todo => todo.id !== id));
  };

  // 切换完成状态
  const handleToggle = (id) => {
    setTodos(prevTodos =>
      prevTodos.map(todo =>
        todo.id === id
          ? { ...todo, completed: !todo.completed }
          : todo
      )
    );
  };

  return (
    <div style={{ maxWidth: '500px', margin: '0 auto', padding: '20px' }}>
      <h2>📝 我的待办事项</h2>

      {/* 输入区域 */}
      <div style={{ display: 'flex', gap: '8px', marginBottom: '16px' }}>
        <input
          type="text"
          value={inputValue}
          onChange={handleInputChange}
          onKeyDown={handleKeyDown}
          placeholder="今天要做什么？"
          style={{ flex: 1, padding: '8px' }}
        />
        <button onClick={handleAdd}>添加</button>
      </div>

      {/* Todo 列表 */}
      {todos.length === 0 ? (
        <p style={{ color: '#999' }}>暂无待办事项，享受清闲吧！</p>
      ) : (
        <ul style={{ listStyle: 'none', padding: 0 }}>
          {todos.map(todo => (
            <li
              key={todo.id}
              style={{
                display: 'flex',
                alignItems: 'center',
                padding: '8px',
                marginBottom: '4px',
                background: '#f5f5f5',
                borderRadius: '4px',
              }}
            >
              <input
                type="checkbox"
                checked={todo.completed}
                onChange={() => handleToggle(todo.id)}
              />
              <span
                style={{
                  flex: 1,
                  marginLeft: '8px',
                  textDecoration: todo.completed ? 'line-through' : 'none',
                  color: todo.completed ? '#999' : '#333',
                }}
              >
                {todo.text}
              </span>
              <button
                onClick={() => handleDelete(todo.id)}
                style={{ color: 'red', border: 'none', cursor: 'pointer' }}
              >
                删除
              </button>
            </li>
          ))}
        </ul>
      )}

      {/* 统计 */}
      {todos.length > 0 && (
        <p style={{ color: '#666', fontSize: '14px' }}>
          共 {todos.length} 项，已完成 {todos.filter(t => t.completed).length} 项
        </p>
      )}
    </div>
  );
}

export default TodoApp;
```

这个例子涵盖了本章几乎所有核心知识点：

- 多个 `useState`（输入框值 + todo 列表）
- 事件处理（onChange、onClick、onKeyDown）
- 函数式更新（`prevTodos => ...`）
- 不可变数据（用展开运算符创建新数组，而不是 push）
- 条件渲染（列表为空时的提示）

> **Warning**: 注意我们添加 todo 时用的是 `setTodos(prevTodos => [...prevTodos, newTodo])`，而不是 `todos.push(newTodo)` + `setTodos(todos)`。**永远不要直接修改 state！** 要创建新的数组/对象来替代旧的。这是 React 检测变化的核心机制。

## 6.9 常见坑与避坑指南

### 坑 1：直接修改 State

```jsx
// ❌ 错误：直接修改
const [list, setList] = useState([1, 2, 3]);
list.push(4);        // 直接修改了原数组
setList(list);       // React 发现引用没变，不会重新渲染！

// ✅ 正确：创建新数组
setList(prev => [...prev, 4]);
```

### 坑 2：闭包陷阱

```jsx
// ❌ 问题：定时器里拿到的是旧值
const [count, setCount] = useState(0);

const startTimer = () => {
  setInterval(() => {
    setCount(count + 1); // count 永远是 0！闭包记住了旧值
  }, 1000);
};

// ✅ 解决：用函数式更新
const startTimer = () => {
  setInterval(() => {
    setCount(prev => prev + 1); // 每次都能拿到最新值
  }, 1000);
};
```

### 坑 3：忘记 key

```jsx
// ❌ 忘记 key 属性
{todos.map(todo => (
  <li>{todo.text}</li>  // React 会报警告！
))}

// ✅ 加上唯一的 key
{todos.map(todo => (
  <li key={todo.id}>{todo.text}</li>
))}
```

> **Warning**: 千万不要用数组的 `index` 作为 key（除非列表不会重新排序或过滤）。如果列表项的顺序发生变化，用 index 做 key 会导致 React 错误地复用 DOM 元素，产生诡异的 bug。

### 坑 4：在渲染过程中调用 setState

```jsx
// ❌ 这会导致无限循环渲染！
function BadComponent() {
  const [value, setValue] = useState('');
  setValue('hello'); // 每次渲染都会调用 → 触发重新渲染 → 又调用 → 又渲染...
  return <p>{value}</p>;
}

// ✅ 如果需要初始化，直接传初始值
function GoodComponent() {
  const [value, setValue] = useState('hello');
  return <p>{value}</p>;
}
```

## 6.10 本章小结

恭喜你！你已经掌握了 React 中最重要的概念之一——State。让我们来回顾一下：

| 概念 | 核心要点 |
|------|---------|
| **State 是什么** | 组件自己管理的数据，变化时会触发重新渲染 |
| **Props vs State** | Props 是别人给的（只读），State 是自己的（可更新） |
| **useState 用法** | `const [value, setValue] = useState(初始值)` |
| **异步更新** | setState 后不会立刻拿到新值，用函数式更新解决 |
| **替换而非合并** | useState 的更新是替换整个值，不是合并 |
| **状态提升** | 共享状态放到共同父组件，通过 Props 向下传递 |
| **不可变性** | 永远不要直接修改 state，要创建新值 |

**比喻回顾**：State 就像你的体重——属于你自己，别人不能直接改，你得自己 `setState`。
