## 5.1 为什么手写撑不住——手工流程的痛点清单

第三章的六步是「搭一次」的成本，真正的日常是**发放与注销**。把第四章的发放动作展开，手工流程长这样：登服务器 → 生成密钥对 → 挑一个没被占用的地址 → 写客户端 conf → 往 wg0.conf 追加 [Peer] → 同步内核 → 生成二维码 → 更新自己的记录表。八步，每步都可能错：

- **地址冲突**：人脑记不住谁占了 .3，两台设备同地址的「时通时断」是 4.7 排障表里的慢性病；
- **步骤遗漏**：忘 `wg syncconf` 时服务端配置与内存不一致，下次重启后「新设备突然失效」；
- **记录漂移**：设备清单散落在聊天记录和便签里，三个月后没人说得清隧道里有几台设备；
- **注销不彻底**：只删 conf 不删 Peer 段，被盗设备仍持有效密钥（4.4 讲过泄露面）。

脚本的职责就是把这八步固化成一个不可跳步的事务：**分配、生成、登记、同步、出示二维码，一次完成，任何一步失败则全部不动**（5.6 的 `set -euo pipefail`）。三个脚本 + 一本花名册（5.5），就是服务器侧的全部日常。

## 5.2 服务端初始化脚本 wg-server-init.sh

这是三章六步的完整固化。保存为 `/usr/local/bin/wg-server-init.sh`（或临时目录跑一次即可，它只该执行一次）：

```bash
#!/usr/bin/env bash
set -euo pipefail

# 锚点参数：换环境时只改这三行
VPN_ADDR="10.66.66.1/24"
VPN_PORT="51820"
VPN_NET="10.66.66.0/24"

IFACE=$(ip route get 1.1.1.1 | awk '{for(i=1;i<NF;i++) if($i=="dev") print $(i+1); exit}')

if ip link show wg0 &>/dev/null; then
  echo "wg0 已存在——初始化只应执行一次（幂等保护见 5.6）" >&2
  exit 1
fi

apt update && apt install -y wireguard qrencode

umask 077
mkdir -p /etc/wireguard/clients
cd /etc/wireguard
wg genkey | tee server_private.key | wg pubkey > server_public.key

cat > wg0.conf <<EOF
[Interface]
Address = $VPN_ADDR
ListenPort = $VPN_PORT
PrivateKey = $(cat server_private.key)
MTU = 1420
PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; iptables -A FORWARD -o wg0 -m state --state ESTABLISHED,RELATED -j ACCEPT; iptables -t nat -A POSTROUTING -o $IFACE -j MASQUERADE
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT; iptables -D FORWARD -o wg0 -m state --state ESTABLISHED,RELATED -j ACCEPT; iptables -t nat -D POSTROUTING -o $IFACE -j MASQUERADE
EOF

cat > /etc/sysctl.d/99-wireguard.conf <<'EOF'
net.ipv4.ip_forward = 1
EOF
sysctl -p /etc/sysctl.d/99-wireguard.conf >/dev/null

touch clients/index
systemctl enable --now wg-quick@wg0

echo "服务器就绪。公钥：$(cat server_public.key)"
echo "提醒：云安全组放行 UDP $VPN_PORT 需要人工操作（3.6），脚本不碰控制台"
```

逐段对回第三章：`IFACE` 一行是 1.7 探测命令的脚本化（不写死网卡名）；`umask 077 + wg genkey` 是 3.1 的密钥纪律；heredoc 生成 conf 与 3.2 的手工版逐字段一致；sysctl 块照搬 3.3；`enable --now` 照搬 3.5。**脚本没有新增任何魔法**——它只是把已验证的命令按顺序写下来，这正是「先教命令、后固化为脚本」的用意。

注意结尾的边界声明：脚本管不了云安全组（那是控制台里的第二道门），把人工步骤打印出来而不是假装完成。

## 5.3 客户端发放脚本 wg-client-add.sh

日常主角来了。保存为 `/usr/local/bin/wg-client-add.sh` 并 `chmod +x`：

```bash
#!/usr/bin/env bash
set -euo pipefail

NAME=${1:?用法: wg-client-add.sh <设备名> [AllowedIPs]}
ALLOWED=${2:-10.66.66.0/24}          # 第二参数留空 = 分流模式（4.2）
CLIENTS=/etc/wireguard/clients
WG_CONF=/etc/wireguard/wg0.conf
ENDPOINT=${ENDPOINT:-203.0.113.10:51820}   # 环境变量可覆盖锚点

if grep -q "^$NAME	" "$CLIENTS/index" 2>/dev/null; then
  echo "设备名 '$NAME' 已在花名册中，换一个名字（或先 revoke）" >&2
  exit 1
fi

umask 077

# 自动分配下一个空闲地址：花名册里最大 IP + 1（起始 .2）
IP=$(awk 'BEGIN{max=1} {n=$2; sub(/^10\.66\.66\./,"",n); if(n+0>max) max=n+0}
          END{printf "10.66.66.%d", max+1}' "$CLIENTS/index")

wg genkey | tee "$CLIENTS/$NAME.private" | wg pubkey > "$CLIENTS/$NAME.public"

cat > "$CLIENTS/$NAME.conf" <<EOF
[Interface]
Address = $IP/24
PrivateKey = $(cat "$CLIENTS/$NAME.private")
DNS = 1.1.1.1

[Peer]
PublicKey = $(cat /etc/wireguard/server_public.key)
Endpoint = $ENDPOINT
AllowedIPs = $ALLOWED
PersistentKeepalive = 25
EOF

cat >> "$WG_CONF" <<EOF

[Peer]
# $NAME
PublicKey = $(cat "$CLIENTS/$NAME.public")
AllowedIPs = $IP/32
EOF

echo -e "$NAME	$IP	$(cat "$CLIENTS/$NAME.public")	$(date +%F)" >> "$CLIENTS/index"

# 热加载：不重启服务，不闪断现有设备
wg syncconf wg0 <(wg-quick strip wg0)

echo "设备 $NAME 已发放：$IP"
echo "全隧道模式发放：wg-client-add.sh $NAME 0.0.0.0/0"
qrencode -t ansiutf8 < "$CLIENTS/$NAME.conf"
```

用法与产出：

```text
$ wg-client-add.sh phone
设备 phone 已发放：10.66.66.3
全隧道模式发放：wg-client-add.sh phone 0.0.0.0/0
▄▄▄▄▄▄▄▄  （终端里打印出可扫的二维码）
```

兑现「先猜再读」第一问：不重启服务靠的是 `wg syncconf wg0 <(wg-quick strip wg0)`——把 conf 原样喂给运行中的接口，新增的 [Peer] 立即生效；正在使用的其他设备**全程无感**（对比 3.7 注过的 `restart` 会闪断）。密钥生成、conf 模板、[Peer] 段、花名册登记、热加载、二维码——第四章的发放八步在这里是六段代码，顺序不可跳、失败即中止。

## 5.4 注销与轮换脚本 wg-client-revoke.sh

设备丢失、员工离职、密钥疑似泄露时，止血脚本：

```bash
#!/usr/bin/env bash
set -euo pipefail

NAME=${1:?用法: wg-client-revoke.sh <设备名>}
CLIENTS=/etc/wireguard/clients
ARCHIVE="$CLIENTS/archive"

if ! grep -q "^$NAME	" "$CLIENTS/index"; then
  echo "花名册中没有 '$NAME'" >&2
  exit 1
fi

# 从 wg0.conf 摘除该设备的 [Peer] 段（按段注释名匹配）
awk -v name="$NAME" 'BEGIN{RS="";ORS="\n\n"}
  $0 ~ /\[Peer\]/ && $0 ~ ("# " name "$") {next}
  {print}' /etc/wireguard/wg0.conf > /etc/wireguard/wg0.conf.tmp
mv /etc/wireguard/wg0.conf.tmp /etc/wireguard/wg0.conf
chmod 600 /etc/wireguard/wg0.conf

# 同步内核：摘除立即生效
wg syncconf wg0 <(wg-quick strip wg0)

# 归档密钥与配置（不删除——留取证与回收余地）
mkdir -p "$ARCHIVE"
mv "$CLIENTS/$NAME.private" "$CLIENTS/$NAME.public" \
   "$CLIENTS/$NAME.conf" "$ARCHIVE/" 2>/dev/null || true

# 从花名册除名
grep -v "^$NAME	" "$CLIENTS/index" > "$CLIENTS/index.tmp"
mv "$CLIENTS/index.tmp" "$CLIENTS/index"

echo "设备 $NAME 已注销：Peer 摘除、内核同步、材料归档至 $ARCHIVE/"
```

关键设计是**摘除 ≠ 删除**：注销后归档目录里的密钥原样保留——既留了「事后取证」的证据，也留了「恢复发放」的可能。从隧道视角，效力已经清零：2.5 的 cryptokey 路由里，这个公钥已不在任何 AllowedIPs 白名单上，**该设备发来的每一个包在内核被静默丢弃**，连握手都不回应（2.3 的对陌生人静默）。所以「先猜再读」第二问的答案是：删 conf 文件远远不够——设备的安全身份由服务端 [Peer] 段决定，摘除它并同步内核才是真正的注销。

**轮换（Rotate）** = revoke 后立刻用同名 re-add：`wg-client-revoke.sh phone && wg-client-add.sh phone`。旧密钥作废、新 conf 出炉，怀疑泄露时两分钟完成止血加换血。归档的旧材料在 `archive/` 里按时间自然堆积，需要时按名字索引。

## 5.5 花名册——目录结构与字段设计

三个脚本共享的单一事实源是一本纯文本花名册：

```text
/etc/wireguard/clients/
├── index              # 花名册本体
├── server_private.key  server_public.key   # （上层目录，3.1）
├── laptop.private  laptop.public  laptop.conf
├── phone.private   phone.public   phone.conf
└── archive/            # 注销设备归档
```

`index` 每行一台设备，四个字段用制表符分隔：

| 字段 | 例 | 谁写 | 谁读 |
| ---- | ---- | ---- | ---- |
| 设备名 | laptop | add 写入 | add 查重、revoke 定位 |
| VPN 地址 | 10.66.66.2 | add 分配 | add 计算下一个空闲 |
| 公钥 | 8KxrmP...= | add 写入 | 人工核对 |
| 登记日期 | 2026-11-24 | add 写入 | 审计时看 |

```text
$ cat /etc/wireguard/clients/index
laptop   10.66.66.2   8KxrmP...=   2026-11-24
phone    10.66.66.3   jN3nQ2...=   2026-11-24
nas      10.66.66.4   uT9bVc...=   2026-11-24
```

设计取舍说明：地址分配用「最大值 + 1」而非位图——注销腾出的地址不会被立即复用（旧地址可能还在 NAT/ARP 表里游荡），号码单调递增到 10.66.66.254 为止，253 台设备容量对个人与小型团队绰绰有余；纯文本 + tab 分隔让 `cut`、`awk`、`grep` 全部可用，不引入数据库依赖——**花名册的价值在于绝对一致，而不在于 sophistication**。

## 5.6 幂等与健壮性——脚本的三条纪律

每个脚本第一行的 `set -euo pipefail` 是本章最重要的一个词，三个标志各管一件事：

| 标志 | 含义 | 防的事故 |
| ---- | ---- | ---- |
| `-e` | 任何命令失败立即退出 | 中途失败还继续执行（如生成密钥失败仍写 conf） |
| `-u` | 使用未定义变量即报错 | 拼错变量名静默展开成空串（如 `$NAME` 写成 `$Naem`） |
| `-o pipefail` | 管道中段失败视作整体失败 | `wg genkey | tee ...` 前半失败但后半成功 |

加上显式的幂等保护，构成三条纪律：

- **init 只跑一次**：开头检查 `ip link show wg0`，已存在即拒跑——重复执行不会覆盖密钥、不会叠加 iptables 规则（回应「先猜再读」第三问：第二遍会被第一行保护拦下，服务器毫发无损）；
- **add 不重名**：查重花名册后才分配地址，杜绝同址双设备；
- **先落盘后生效**：conf 写完整才 syncconf；失败时磁盘上的文件与内核状态保持一致，没有「半新半旧」的中间态。

同时也说明脚本**不做**什么：不做错误回滚（失败后人工看报错重跑，比隐式回滚更可控）、不碰云安全组（控制台操作无 API 标准路径）、不做自动续期（WireGuard 密钥无过期概念，2.4 的会话密钥轮换是协议内置的，与静态密钥无关）。工程化的边界感与功能本身同样重要。

## 本章小结

- 手工发放的四大痛点：地址冲突、步骤遗漏、记录漂移、注销不彻底——脚本把它们固化成不可跳步的事务；
- `wg-server-init.sh` 是第三章六步的顺序固化，开头有 wg0 存在性检查，结尾打印人工步骤（安全组）；
- `wg-client-add.sh` 六段完成发放：查重 → 分配 → 密钥 → conf → 登记 → 热加载，参数第二位留空即分流模式；
- 热加载靠 `wg syncconf wg0 <(wg-quick strip wg0)`，新 Peer 立即生效且现有设备无感；
- `wg-client-revoke.sh` 摘除 [Peer] 段 + 同步内核 + 归档材料——真正的注销发生在服务端，删客户端文件无效；
- 轮换 = revoke + 同名 re-add，两分钟止血换血；
- 花名册是单一事实源：四个字段、tab 分隔、地址单调递增不复用，纯文本零依赖；
- `set -euo pipefail` 三标志 + 三条纪律（只跑一次、不重名、先落盘后生效）是脚本健壮性的全部家当。
