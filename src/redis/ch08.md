# 第8章：Pub/Sub 与 Pipeline——消息与效率

## 引言：邮递员与快递柜

想象两种场景：

- **Pub/Sub** 就像一个广播电台——主持人说话（发布），所有调到该频道的听众（订阅者）同时收到消息。但如果你当时没在听？对不起，消息就丢了。
- **Pipeline** 就像快递柜——你不用一个一个地去取快递，而是一次性把所有快递都放进柜子，快递员一趟搞定，效率翻倍。

这一章，我们既要学会"广播"，又要学会"提速"。

## 8.1 Pub/Sub：发布/订阅模式

Pub/Sub 是一种经典的消息模式，Redis 对它的支持非常直观。就像收音机调频一样：你先订阅一个频道，然后当有人往这个频道发消息时，你就能收到。

```
   发布者 (Publisher)
       |
       +--> 频道 "news"  --> 订阅者A
       |                 --> 订阅者B
       |                 --> 订阅者C
       |
       +--> 频道 "sports" --> 订阅者D
                          --> 订阅者C (同时订阅两个频道)
```

### 8.1.1 核心命令

```bash
# 订阅一个或多个频道
SUBSCRIBE news sports weather

# 发布消息到频道
PUBLISH news "Breaking: Redis 8.0 released!"

# 模式订阅（通配符匹配）
PSUBSCRIBE news.*

# 取消订阅
UNSUBSCRIBE news

# 取消模式订阅
PUNSUBSCRIBE news.*
```

### 8.1.2 Node.js 实现发布者和订阅者

```js
const Redis = require('ioredis');

// 重要：发布者和订阅者需要独立的连接！
// 因为订阅后连接会进入"订阅模式"，不能执行其他命令

const subscriber = new Redis({ host: '127.0.0.1', port: 6379 });

subscriber.on('message', (channel, message) => {
  console.log(`收到 [${channel}]: ${message}`);
});

subscriber.on('pmessage', (pattern, channel, message) => {
  console.log(`模式匹配 [${pattern}] 频道 [${channel}]: ${message}`);
});

subscriber.on('subscribe', (channel, count) => {
  console.log(`已订阅频道: ${channel} (共 ${count} 个订阅)`);
});

const publisher = new Redis({ host: '127.0.0.1', port: 6379 });

async function startSubscription() {
  await subscriber.subscribe('news', 'sports');
  await subscriber.psubscribe('app:*');

  console.log('订阅者已就绪，等待消息...\n');
  await new Promise((resolve) => setTimeout(resolve, 500));

  const receivers1 = await publisher.publish('news', 'Redis 8.0 发布！');
  console.log(`发布到 news，${receivers1} 个订阅者收到`);

  const receivers2 = await publisher.publish('sports', '中国队夺冠！');
  console.log(`发布到 sports，${receivers2} 个订阅者收到`);

  const receivers3 = await publisher.publish('app:deploy', 'v2.1.0 已部署');
  console.log(`发布到 app:deploy，${receivers3} 个订阅者收到`);

  const receivers4 = await publisher.publish('weather', '明天晴天');
  console.log(`发布到 weather，${receivers4} 个订阅者收到（没人听！）`);

  setTimeout(async () => {
    await subscriber.unsubscribe('news', 'sports');
    await subscriber.punsubscribe('app:*');
    await subscriber.quit();
    await publisher.quit();
  }, 1000);
}

startSubscription().catch(console.error);
```

### 8.1.3 频道信息查看

```bash
# 查看某个频道的订阅者数量
PUBSUB NUMSUB news sports

# 查看当前活跃的频道
PUBSUB CHANNELS

# 查看匹配某个模式的所有频道
PUBSUB CHANNELS app:*
```

## 8.2 Pub/Sub 的局限性

Pub/Sub 虽然简单好用，但它有几个"硬伤"，你得心里有数：

| 局限性 | 说明 | 影响 |
|--------|------|------|
| **消息不持久化** | 消息发出去就没了 | 重启后所有消息丢失 |
| **无法回溯** | 没有消息历史 | 新订阅者看不到之前的消息 |
| **无确认机制** | 发出去就算送达 | 不知道订阅者是否处理成功 |
| **订阅者必须在线** | 不在线就收不到 | 错过就是错过 |
| **无消费者组** | 所有订阅者都收到同一条消息 | 无法实现负载均衡 |

这就像广播——你错过了一首歌，电台不会为你重播。如果你需要消息持久化、回溯、消费者组这些高级功能，别急，第9章的 **Redis Stream** 就是为此而生的。

## 8.3 Pipeline：批量操作的涡轮增压器

正常模式下，每个 Redis 命令都是一次完整的网络往返（RTT）。如果你有 1000 个命令要执行，那就是 1000 次网络往返。即使每次只要 1ms，加起来也要 1 秒。

```
正常模式（逐个执行）：
客户端 --SET--> Redis --OK--> 客户端
客户端 --SET--> Redis --OK--> 客户端
... x 1000 = 1000 次网络往返

Pipeline 模式（批量发送）：
客户端 --[SET, SET, SET, ..., SET]--> Redis --[OK, OK, ...]--> 客户端
x 1 = 仅 1 次网络往返！
```

### 8.3.1 基本用法

```js
const Redis = require('ioredis');
const redis = new Redis({ host: '127.0.0.1', port: 6379 });

async function pipelineDemo() {
  const pipeline = redis.pipeline();
  pipeline.set('user:1:name', 'Alice');
  pipeline.set('user:1:age', '28');
  pipeline.set('user:1:email', 'alice@example.com');
  pipeline.get('user:1:name');
  pipeline.get('user:1:age');
  pipeline.get('user:1:email');

  const results = await pipeline.exec();
  console.log('Pipeline 结果:');
  results.forEach(([err, result], index) => {
    if (err) {
      console.log(`  命令 ${index + 1}: 错误 - ${err.message}`);
    } else {
      console.log(`  命令 ${index + 1}: ${result}`);
    }
  });

  await redis.quit();
}

pipelineDemo().catch(console.error);
```

### 8.3.2 链式调用（更优雅）

```js
const Redis = require('ioredis');
const redis = new Redis({ host: '127.0.0.1', port: 6379 });

async function chainedPipeline() {
  const results = await redis
    .pipeline()
    .set('product:1', JSON.stringify({ name: 'iPhone', price: 999 }))
    .set('product:2', JSON.stringify({ name: 'MacBook', price: 1999 }))
    .set('product:3', JSON.stringify({ name: 'AirPods', price: 199 }))
    .get('product:1')
    .get('product:2')
    .get('product:3')
    .incr('stats:product_views')
    .get('stats:product_views')
    .exec();

  console.log('链式 Pipeline 结果:');
  results.forEach(([err, result], index) => {
    console.log(`  #${index + 1}:`, err ? `Error: ${err.message}` : result);
  });

  await redis.quit();
}

chainedPipeline().catch(console.error);
```

### 8.3.3 性能对比

```js
const Redis = require('ioredis');
const redis = new Redis({ host: '127.0.0.1', port: 6379 });

async function benchmark() {
  const COUNT = 10000;

  console.log(`逐个执行 ${COUNT} 个 SET 命令...`);
  const start1 = Date.now();
  for (let i = 0; i < COUNT; i++) {
    await redis.set(`bench:seq:${i}`, `value_${i}`);
  }
  const time1 = Date.now() - start1;
  console.log(`   耗时: ${time1}ms`);

  console.log(`Pipeline 执行 ${COUNT} 个 SET 命令...`);
  const start2 = Date.now();
  const pipeline = redis.pipeline();
  for (let i = 0; i < COUNT; i++) {
    pipeline.set(`bench:pipe:${i}`, `value_${i}`);
  }
  await pipeline.exec();
  const time2 = Date.now() - start2;
  console.log(`   耗时: ${time2}ms`);

  console.log(`Pipeline 提速: ${(time1 / time2).toFixed(1)}x`);

  const cleanPipeline = redis.pipeline();
  for (let i = 0; i < COUNT; i++) {
    cleanPipeline.del(`bench:seq:${i}`);
    cleanPipeline.del(`bench:pipe:${i}`);
  }
  await cleanPipeline.exec();

  await redis.quit();
}

benchmark().catch(console.error);
```

> [!TIP] 提示
> 实际测试中，Pipeline 通常能提速 **5-50 倍**，取决于网络延迟。网络延迟越高，Pipeline 的优势越明显。

### 8.3.4 Pipeline 与事务的区别

| 特性 | Pipeline | MULTI/EXEC 事务 |
|------|----------|----------------|
| **原子性** | 不保证 | 保证顺序执行 |
| **网络优化** | 批量发送 | 批量发送 |
| **错误处理** | 单个失败不影响其他 | 队列中的命令仍会执行 |
| **性能** | 更快（开销小） | 稍慢（有事务开销） |
| **适用场景** | 批量读写、数据导入 | 需要原子性的操作 |

```js
const Redis = require('ioredis');
const redis = new Redis({ host: '127.0.0.1', port: 6379 });

async function pipelineVsTransaction() {
  const pipeResult = await redis
    .pipeline()
    .set('p:1', 'hello')
    .incr('p:1')        // 失败但不影响其他命令
    .set('p:2', 'world')
    .exec();

  console.log('Pipeline 结果:');
  pipeResult.forEach(([err, val], i) => {
    console.log(`  #${i + 1}:`, err ? `Error: ${err.message}` : val);
  });

  const txResult = await redis
    .multi()
    .set('t:1', 'hello')
    .incr('t:1')
    .set('t:2', 'world')
    .exec();

  console.log('\n事务结果:');
  txResult.forEach(([err, val], i) => {
    console.log(`  #${i + 1}:`, err ? `Error: ${err.message}` : val);
  });

  await redis.quit();
}

pipelineVsTransaction().catch(console.error);
```

## 8.4 Pub/Sub vs Redis Stream

| 特性 | Pub/Sub | Redis Stream |
|------|---------|-------------|
| 持久化 | 否 | 是 |
| 消息回溯 | 否 | 是 |
| 消费者组 | 否 | 是 |
| 确认机制 | 否 | 是 |
| 消息上限控制 | 否 | 是 |
| 复杂度 | 低 | 中 |
| 适用场景 | 实时通知、聊天 | 事件溯源、消息队列 |

## 8.5 实战：实现一个简单的聊天室

```js
const Redis = require('ioredis');
const readline = require('readline');

class ChatRoom {
  constructor(username) {
    this.username = username;
    this.roomName = 'general';
    this.subscriber = new Redis({ host: '127.0.0.1', port: 6379 });
    this.publisher = new Redis({ host: '127.0.0.1', port: 6379 });
    this.setupSubscriber();
  }

  setupSubscriber() {
    this.subscriber.on('message', (channel, message) => {
      const data = JSON.parse(message);
      if (data.username !== this.username) {
        console.log(`\n[${data.timestamp}] ${data.username}: ${data.text}`);
      }
    });

    this.subscriber.on('pmessage', (pattern, channel, message) => {
      if (channel === 'chat:events') {
        const event = JSON.parse(message);
        console.log(`\n[系统] ${event.text}`);
      }
    });
  }

  async join() {
    await this.subscriber.subscribe(`chat:${this.roomName}`);
    await this.subscriber.psubscribe('chat:events');

    await this.publisher.publish('chat:events', JSON.stringify({
      type: 'join',
      text: `${this.username} 加入了聊天室`,
      timestamp: new Date().toISOString(),
    }));

    await this.publisher.pipeline()
      .sadd('chat:online_users', this.username)
      .hset(`chat:user:${this.username}`, 'last_seen', Date.now())
      .incr('chat:stats:total_joins')
      .exec();

    console.log(`${this.username} 已加入聊天室 "${this.roomName}"`);
  }

  async sendMessage(text) {
    const message = {
      username: this.username, text,
      timestamp: new Date().toISOString(),
    };

    await this.publisher.pipeline()
      .publish(`chat:${this.roomName}`, JSON.stringify(message))
      .rpush(`chat:history:${this.roomName}`, JSON.stringify(message))
      .ltrim(`chat:history:${this.roomName}`, -100, -1)
      .incr('chat:stats:total_messages')
      .exec();
  }

  async leave() {
    await this.publisher.publish('chat:events', JSON.stringify({
      type: 'leave',
      text: `${this.username} 离开了聊天室`,
      timestamp: new Date().toISOString(),
    }));
    await this.publisher.srem('chat:online_users', this.username);
    await this.subscriber.unsubscribe();
    await this.subscriber.punsubscribe();
    await this.subscriber.quit();
    await this.publisher.quit();
  }

  startInteractive() {
    const rl = readline.createInterface({
      input: process.stdin, output: process.stdout,
    });

    rl.on('line', async (input) => {
      const text = input.trim();
      if (!text) return;
      if (text === '/quit') {
        await this.leave();
        process.exit(0);
      } else if (text === '/users') {
        const users = await this.publisher.smembers('chat:online_users');
        console.log(`在线用户: ${users.join(', ')}`);
      } else {
        await this.sendMessage(text);
      }
    });
  }
}

async function main() {
  const username = process.argv[2] || `User_${Math.random().toString(36).slice(2, 6)}`;
  const chat = new ChatRoom(username);
  await chat.join();
  chat.startInteractive();
}

main().catch(console.error);
```

## 小结

- **Pub/Sub** 是实时消息推送的利器，但消息不持久化、无法回溯。
- **Pipeline** 是性能优化的核心手段，通过减少网络往返实现批量操作。
- Pipeline 和事务不是一回事：Pipeline 追求效率，事务追求原子性。
