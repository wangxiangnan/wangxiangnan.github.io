# 第1章：Redis是什么？为什么你的系统需要它

## 引言：程序世界的"超级全局变量"

想象一下，你写了一个超大的 Node.js 应用，所有数据都存在 `let cache = {}` 里——读写飞快，跨函数共享，完美！

然后老板说："我们要部署 10 个实例做负载均衡。"

你的 `{}` 当场裂开。

**Redis 就是那个"升级版的全局变量"**——它跨进程、跨服务器、支持持久化、还能组集群。如果说普通变量是你桌上的便签纸，Redis 就是一块所有程序员都能看到的电子白板，而且擦不掉（除非你主动擦）。

更准确地说，Redis 是内存数据结构存储的**瑞士军刀**：它能当缓存、能当消息队列、能当排行榜、能当分布式锁……一把刀，十八种用法。

## 1.1 Redis 的定义和定位

**Redis** 全称 **Re**mote **Di**ctionary **S**erver，是一个开源的、基于内存的键值数据库。

让我们用一个表格来定位它：

| 特性 | Redis | MySQL/PostgreSQL | 普通变量 |
|------|-------|-----------------|----------|
| 存储位置 | 内存（可持久化到磁盘） | 磁盘 | 内存 |
| 读写速度 | 极快（~10万QPS） | 较慢（~1千QPS） | 极快 |
| 跨进程共享 | 是 | 是 | 否 |
| 数据结构 | String/Hash/List/Set/ZSet | 表（行/列） | 任意 |
| 持久化 | 可选 | 默认 | 不持久化 |
| 事务支持 | 有限 | 完整ACID | 无 |
| SQL查询 | 不支持 | 支持 | 不适用 |

**一句话总结**：Redis 不是用来替代 MySQL 的，而是用来**配合** MySQL 的。MySQL 是你的"档案柜"（持久、可靠、但慢），Redis 是你的"办公桌"（快速、方便、但容量有限）。

## 1.2 Redis vs 传统数据库

很多新手会问："Redis 这么快，我干嘛不全部用 Redis？"

这就好比问："高铁这么快，我干嘛不全程坐高铁？"——因为高铁不到你家楼下啊！

**Redis 的局限**：

- **内存贵**：内存价格大约是 SSD 的 10-20 倍。把所有数据都放内存里？你的钱包会哭。
- **查询弱**：没有 SQL，没有 JOIN，没有 WHERE 子句。想找"所有年龄大于 25 岁的用户"？你得把所有用户数据读出来自己过滤。
- **事务弱**：Redis 的事务不是真正的原子操作（第5章会详细讲），不像 MySQL 那样有完整的回滚机制。
- **数据大小**：单个 Value 最大 512MB，但实际上超过几 KB 的 Value 就该考虑是不是用错了场景。

**正确的姿势**：

```
用户请求 → Redis（缓存层，快速响应）
              ↓ 缓存未命中
           MySQL（持久层，可靠存储）
              ↓ 查到数据
           写入 Redis（下次直接命中）
```

这就是经典的 **Cache-Aside Pattern**，后面章节会详细实现。

## 1.3 Redis 的应用场景

Redis 的应用场景多到让你怀疑它是不是偷偷学了分身术。以下是六大核心场景：

### 场景一：缓存（Cache）

这是 Redis 最经典的用途，就像给你的数据库加了一个"快速通道"。

```js
// 伪代码示意
async function getUserById(id) {
  // 先查 Redis
  let user = await redis.get(`user:${id}`);
  if (user) {
    return JSON.parse(user); // 命中缓存，直接返回！
  }

  // 没命中，查数据库
  user = await db.query('SELECT * FROM users WHERE id = ?', [id]);
  await redis.setex(`user:${id}`, 3600, JSON.stringify(user)); // 缓存1小时
  return user;
}
```

### 场景二：会话管理（Session Store）

传统的 session 存在服务器内存里，一重启就没了，多实例还不同步。Redis 来拯救：

```js
// 所有实例共享同一个 Redis，session 同步不是问题
await redis.setex(`session:${sessionId}`, 1800, JSON.stringify({
  userId: 12345,
  role: 'admin',
  loginTime: Date.now()
}));
```

### 场景三：消息队列（Message Queue）

Redis 的 List 和 Pub/Sub 可以实现轻量级消息队列。Redis 5.0 引入的 Stream 更是专门为此而生。

### 场景四：排行榜（Leaderboard）

Sorted Set 天生适合做排行榜，按分数排序、取 Top N，性能 O(log(N))：

```js
// 游戏排行榜：添加玩家分数
await redis.zadd('game:leaderboard', 9527, 'player:张三');
// 获取前10名
const top10 = await redis.zrevrange('game:leaderboard', 0, 9, 'WITHSCORES');
```

### 场景五：实时计数器（Counter）

原子递增操作，再也不怕并发冲突：

```js
// 文章阅读量 +1，原子操作，无需加锁
await redis.incr(`article:${articleId}:views`);
```

### 场景六：分布式锁

多实例环境下，用 Redis 做"互斥锁"，防止重复操作：

```js
// 尝试获取锁（SET NX = 不存在才设置）
const locked = await redis.set('lock:order:12345', 'my-instance-id', 'EX', 10, 'NX');
if (locked) {
  // 拿到锁了，安心处理订单
  try {
    await processOrder(12345);
  } finally {
    await redis.del('lock:order:12345'); // 释放锁
  }
}
```

## 1.4 Redis 为什么这么快？

面试必问，面试必问，面试必问。

Redis 快得像开了挂，主要有四大原因：

### 1. 纯内存操作

磁盘 I/O 是数据库最大的瓶颈。机械硬盘寻道要 10ms，SSD 也要 0.1ms。而内存访问？纳秒级别！差了 100 万倍。

打个比方：去磁盘读数据就像去图书馆找书，去内存读数据就像看你手边的书。

### 2. 单线程模型（核心执行）

没错，Redis 的核心命令处理是**单线程**的。这不是缺点，而是**优势**！

- 没有多线程的上下文切换开销
- 没有锁竞争的问题（不存在死锁）
- 代码路径简洁高效

```
客户端A → SET name "Alice"  ─┐
客户端B → GET name           ─┤──→ 排队执行（一个接一个，快得你感觉是同时的）
客户端C → INCR counter       ─┘
```

> **注意**：Redis 6.0 开始引入了多线程 I/O（用于网络数据的读写），但命令执行本身仍然是单线程的。Redis 7.0 进一步优化了这一点。

### 3. I/O 多路复用

Redis 使用 epoll（Linux）、kqueue（macOS）等 I/O 多路复用机制，一个线程就能同时处理成千上万个客户端连接。

比喻：一个超级前台，一个人同时接 1000 个电话，每个电话只需要几毫秒就处理完了。

### 4. 高效的数据结构

Redis 内部对数据结构做了大量优化：

- **SDS**（Simple Dynamic String）：预分配空间，减少内存重分配
- **跳表**（Skip List）：有序集合的底层实现，查询效率媲美平衡树
- **压缩列表**（Zip List）：小数据量时，用连续内存存储，减少内存碎片
- **哈希表**（Hash Table）：渐进式 rehash，避免卡顿

## 1.5 Redis 7.x 新功能概览

Redis 7.0 是一个大版本，带来了不少好东西：

| 新特性 | 说明 |
|--------|------|
| **Redis Functions** | 取代 EVAL 的新脚本管理方式，可以持久化存储 Lua 函数 |
| **Multi-part AOF** | AOF 文件拆分为多个，重写更高效 |
| **Client-side caching 增强** | 客户端缓存协议改进，减少无效通知 |
| **Sharded Pub/Sub** | 集群模式下的发布订阅 |
| **内存优化** | 更紧凑的列表编码（listpack 取代 ziplist） |
| **ACL V2** | 更细粒度的权限控制 |

## 1.6 小结

> **Redis = 内存数据库的瑞士军刀**

- Redis 是内存数据结构存储，不是传统数据库的替代品，而是最佳拍档
- 六大应用场景：缓存、会话、消息队列、排行榜、计数器、分布式锁
- 快的秘密：内存操作 + 单线程执行 + I/O 多路复用 + 高效数据结构
- 把它当成"跨进程、可持久化、支持集群的全局变量"就对了
