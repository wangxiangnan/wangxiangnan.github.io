## 3.1 Tokenization——模型的"字符编码"

为什么 Agent 开发者要懂分词？你用 LangChain 调 API，API 封装了模型细节，却封装不了计费——Token 数量直接决定成本和速度。更根本地，**你可以不会手推 Transformer 的公式，但你需要知道数据在模型里怎么流动**：当 Agent 输出不理想时，你要能判断问题出在 Prompt 结构（注意力没分配到关键信息）、Token 截断（上下文溢出）还是模型能力（推理链太长）。数据流动的第一站，就是 Tokenization（分词）。

### 人类读文本 vs 模型读文本

你读 `"Hello world"` 看到的是 11 个字符（含空格）或 2 个单词。模型看到的既不是字符也不是单词——它看到的是 Token，一种介于字符和单词之间的奇怪单位。

```
输入: "Hello world"

人类视角: 2 个单词, 11 个字符
模型视角: [15496, 2159]  ← 2 个 Token（GPT-2 的 BPE 结果）

输入: "Tokenization is fascinating"

人类视角: 3 个单词
模型视角: [30642, 287, 739, 312]  ← 4 个 Token
          "Token" + "ization" + " is" + " fascinating"
```

为什么 `"Tokenization"` 被切成了 `"Token"` + `"ization"` 而不是整个词？为什么 `" is"` 前面的空格被粘到了 `"is"` 上？这取决于 Tokenization 算法。

### Tokenization 算法演进：从字符到子词

分词方案经历了三代演进，核心矛盾始终是"序列长度 vs 词汇表大小"：

**表 3-1｜三代分词方案对比**（"切分示例"列给出同一段文本的 Token 化结果）：

| 方案 | 切分示例 | 词汇表规模 | 致命问题 | 代表 |
| ------ | ------ | ------ | ------ | ------ |
| 字符级（Character-level） | "hello" → h·e·l·l·o，5 个 Token | 只有几十个字符 | Token 序列太长，模型效率低 | 早期 RNN 模型 |
| 词级（Word-level） | "unbelievable" → 整词，1 个 Token | 几十万词，爆炸式增长 | 遇到没见过的词就完蛋——OOV（Out-of-Vocabulary）问题 | Word2Vec、GloVe |
| 子词级（Subword-level，当前主流） | "unbelievable" → un·believ·able，3 个 Token | 3-10 万，适中 | 无明显短板：能处理任意新词，在效率和表达力之间取平衡 | BPE、WordPiece、SentencePiece |

> **编程类比**：Tokenization 就像数据序列化格式。字符级 = 逐字节传输（安全但慢）；词级 = 整个对象序列化（快但遇到新类型就崩）；子词级 = Protocol Buffers（结构化、紧凑、可扩展）。

### BPE 算法详解 —— 当前最主流的 Tokenization

**Byte Pair Encoding (BPE)** 是 GPT 系列、LLaMA、DeepSeek 等模型使用的算法。它的核心思想极其简单：**从字符开始，反复合并最高频的相邻对，直到词汇表达到目标大小。**

用 Python 实现一遍你就能彻底理解：

```python
from collections import Counter

def train_bpe(corpus: str, vocab_size: int) -> dict:
    """
    BPE 训练算法：从字符级开始，反复合并最高频的相邻 Token 对
    
    Args:
        corpus: 训练文本
        vocab_size: 目标词汇表大小
    
    Returns:
        merges: 合并规则字典 {(token_a, token_b): merged_token}
    """
    # Step 1: 把文本拆成字符序列（每个字符后面跟一个特殊标记 'Ġ' 表示词边界）
    # 实际实现中会先做 Unicode 标准化和预分词
    words = corpus.split()
    
    # 每个词拆成字符列表，最后一个字符加 '</w>' 标记词尾
    word_freqs = Counter(words)
    
    # 初始化: 每个词 = 字符列表 + 词尾标记
    splits = {
        word: [c for c in word] + ['</w>']
        for word in word_freqs
    }
    
    merges = {}
    vocab = set()
    
    # 收集初始词汇表（所有单字符）
    for chars in splits.values():
        vocab.update(chars)
    
    print(f"初始词汇表: {sorted(vocab)}")
    print(f"初始词汇表大小: {len(vocab)}")
    
    # Step 2: 循环合并，直到达到目标词汇表大小
    while len(vocab) < vocab_size:
        # 统计所有相邻 Token 对的出现频率
        pair_freqs = Counter()
        for word, freq in word_freqs.items():
            chars = splits[word]
            for i in range(len(chars) - 1):
                pair = (chars[i], chars[i + 1])
                pair_freqs[pair] += freq
        
        if not pair_freqs:
            break
        
        # 找到最高频的相邻对（同频时按字典序取第一个，确保结果确定性）
        max_freq = max(pair_freqs.values())
        candidates = sorted([p for p, f in pair_freqs.items() if f == max_freq])
        best_pair = candidates[0]
        
        # 创建合并后的新 Token
        merged = best_pair[0] + best_pair[1]
        
        # 在所有词中执行合并
        for word in splits:
            chars = splits[word]
            i = 0
            new_chars = []
            while i < len(chars):
                if (i < len(chars) - 1 and 
                    chars[i] == best_pair[0] and 
                    chars[i + 1] == best_pair[1]):
                    new_chars.append(merged)
                    i += 2
                else:
                    new_chars.append(chars[i])
                    i += 1
            splits[word] = new_chars
        
        merges[best_pair] = merged
        vocab.add(merged)
    
    print(f"最终词汇表大小: {len(vocab)}")
    print(f"合并规则数: {len(merges)}")
    return merges


# ===== 用一个微型语料演示 =====
# 使用4个形容词的原形和比较级形式（去掉最高级 -est，减少同频歧义）

corpus = """
low lower
new newer
wide wider
high higher
"""

merges = train_bpe(corpus, vocab_size=30)

print("\n前10条合并规则（按学习顺序）:")
for i, (pair, merged) in enumerate(list(merges.items())[:10]):
    print(f"  {i+1}. {pair[0]!r} + {pair[1]!r} → {merged!r}")
```

运行结果（确定性排序，可复现）：

```
初始词汇表: ['</w>', 'd', 'e', 'g', 'h', 'i', 'l', 'n', 'o', 'r', 'w']
初始词汇表大小: 11
最终词汇表大小: 30
合并规则数: 19

前10条合并规则（按学习顺序）:
  1. 'e' + 'r' → 'er'        ← 频率4，最高频对（出现在 lower/newer/wider/higher）
  2. 'er' + '</w>' → 'er</w>'  ← 频率4，新合并的 er 后面紧跟词尾
  3. 'e' + 'w' → 'ew'        ← 频率2，new/newer 中共有
  4. 'g' + 'h' → 'gh'        ← 频率2，high/higher 中共有
  5. 'h' + 'i' → 'hi'        ← 频率2
  6. 'hi' + 'gh' → 'high'    ← 频率2，两步拼出完整词 high
  7. 'i' + 'd' → 'id'        ← 频率2，wide/wider 中共有
  8. 'l' + 'o' → 'lo'        ← 频率2
  9. 'lo' + 'w' → 'low'      ← 频率2，两步拼出 low
 10. 'n' + 'ew' → 'new'      ← 频率2，拼出 new
```

> **为什么加了确定性排序？** 当多个 Token 对频率相同时（如第3步时 `e,w`、`g,h`、`h,i` 等都是频率2），Python 的 `Counter.most_common()` 返回顺序取决于哈希值，每次运行可能不同。我们用 `sorted()` 按字典序取第一个，确保结果可复现。实际 BPE 实现（如 tiktoken）也有类似的确定性机制。

> **关键洞察**：BPE 从字符开始，按频率"生长"出子词和词。高频词（如 `"the"`）会合并成一个 Token，低频词（如 `"tokenizer"`）会保持多个子词 Token。这就是为什么常见词编码短、罕见词编码长。

### BPE 编码过程 —— 从文本到 Token ID

训练完成后，用学到的合并规则对新文本进行编码（推理时使用）：

```python
def bpe_encode(text: str, merges: dict) -> list:
    """
    用训练好的 BPE 合并规则编码文本
    
    编码策略: 按照合并规则的学习顺序（优先级从高到低）贪心地应用合并
    """
    # Step 1: 拆成字符
    tokens = list(text) + ['</w>']
    
    # Step 2: 按合并规则的优先级反复合并
    # 优先级 = 合并规则被学习到的顺序（越早学到的越优先）
    for pair, merged in merges.items():
        i = 0
        new_tokens = []
        while i < len(tokens):
            if (i < len(tokens) - 1 and 
                tokens[i] == pair[0] and 
                tokens[i + 1] == pair[1]):
                new_tokens.append(merged)
                i += 2
            else:
                new_tokens.append(tokens[i])
                i += 1
        tokens = new_tokens
    
    return tokens


# 演示
result = bpe_encode("lower", merges)
print(f"'lower' → {result}")
# 输出: 'lower' → ['lower</w>']  ← 训练语料中的高频词，经过 16 次合并成为单个 Token

result = bpe_encode("coldly", merges)
print(f"'coldly' → {result}")
# 输出: 'coldly' → ['c', 'o', 'l', 'd', 'l', 'y', '</w>']  ← 未登录词，保持 7 个字符级 Token
```

### 真实模型的 Tokenization 参数

主流模型都在 BPE 上微调出自己的词表，参数差异直接体现在中文效率上：

**表 3-2｜主流模型的 Tokenizer 参数**（四家均支持 byte fallback——任何字节序列都能编码，不会出现编码失败）：

| 模型 | 算法 | 词表大小 | 中文表现 |
| ------ | ------ | ------ | ------ |
| GPT-4 / GPT-4o | BPE（cl100k_base / o200k_base） | 100,277 / 199,997 | o200k_base 对中文优化更好，同一文本 Token 数更少 |
| DeepSeek V3 / R1 | BPE（基于 SentencePiece） | 128,000 | 中英双语优化，中文 Token 效率接近英文 |
| LLaMA 3 | BPE（tiktoken 兼容） | 128,256 | 多语言覆盖广，但中文效率一般 |
| Qwen 2.5 | BPE（基于 SentencePiece） | 151,936 | 中文 Token 效率极高（词表大，中文子词覆盖好） |

> **中文的 Token 陷阱**：同一个意思，中文表达的 Token 数通常是英文的 1.5-3 倍（取决于模型的中文优化程度）。这意味着：同样 8K 上下文窗口，英文能放约 6000 个单词，中文可能只能放 3000-4000 个字。做 Agent 时如果不注意，中文场景下上下文更容易溢出。

### 用 tiktoken 实操体验

```python
# pip install tiktoken
import tiktoken

# 加载 GPT-4 的 Tokenizer
enc = tiktoken.encoding_for_model("gpt-4")

# 编码: 文本 → Token IDs
text = "AI Agent is the future of software"
token_ids = enc.encode(text)
print(f"文本: {text}")
print(f"Token IDs: {token_ids}")
print(f"Token 数: {len(token_ids)}")
print()

# 解码: Token IDs → 文本
decoded = enc.decode(token_ids)
print(f"解码: {decoded}")
print()

# 观察每个 Token 对应的文本片段
for token_id in token_ids:
    print(f"  ID {token_id:>6} → {enc.decode([token_id])!r}")

print()

# 中英文对比
en = "Tokenization is fundamental to understanding LLMs"
cn = "分词是理解大语言模型的基础"

en_tokens = enc.encode(en)
cn_tokens = enc.encode(cn)

print(f"英文 ({len(en)} 字符): {len(en_tokens)} Tokens")
print(f"中文 ({len(cn)} 字符): {len(cn_tokens)} Tokens")
print(f"中文/英文 Token 比: {len(cn_tokens)/len(en_tokens):.1f}x")
```

**表 3-3｜tiktoken 常用操作速查**：

| 操作 | 代码 | 作用 |
| ------ | ------ | ------ |
| 加载词表 | `tiktoken.encoding_for_model("gpt-4")` | 拿到指定模型的 Tokenizer |
| 编码 | `enc.encode(text)` | 文本 → Token ID 列表 |
| 解码 | `enc.decode(token_ids)` | Token ID 列表 → 文本 |
| 数 Token | `len(enc.encode(text))` | 估算成本与上下文占用 |

## 3.2 思考题

**思考题 1**：BPE 算法按频率贪心合并。这意味着一个词如果恰好被切分成了语义上不合理的子词组合（比如 `"import"` 被切成 `"im"` + `"port"`），分词阶段本身无从修正。你觉得后续的模型还能正确理解这个词吗？先记录你的猜想，第4章（Embedding 如何表示子词）和第5章（注意力如何用上下文纠偏）会给你验证的依据。

**思考题 2**：动手算一算：语料中 `low` 出现 2 次、`lower` 出现 1 次。从字符级词表出发，按"反复合并最高频相邻对（同频按字典序）"的规则，前两次合并会学出什么规则？到第几次合并时 `low` 已成为单个 Token？

## 本章小结

- 模型读到的既不是字符也不是单词，而是 Token——介于两者之间的子词单位，成本与上下文全部按它计算
- 三代分词方案各有一伤：字符级序列太长，词级栽在 OOV（Out-of-Vocabulary），子词级成为当前主流
- BPE 的核心只有一句话：从字符开始，反复合并最高频相邻对，直到词表达到目标大小
- 高频词长成整词、低频词保持多子词——这就是常见词编码短、罕见词编码长的原因
- 主流模型词表在 10 万-20 万级（GPT-4o 199,997、DeepSeek 128,000、Qwen 2.5 151,936），且都支持 byte fallback
- 中文 Token 效率通常是英文的 1.5-3 倍：同样 8K 窗口，英文约放 6000 词，中文只放 3000-4000 字
- Token 是钱的单位：做 Agent 前先用 tiktoken 量一遍 Prompt，中文场景更要留足上下文余量
