# 第4章 viewport：浏览器的呈现策略

> **本章回答的问题**：浏览器把页面画在多大的画布上？不加 viewport 为什么字那么小？

[第 2 章](/pixels-viewport/ch02)解决了"单位"问题，本章解决"画布"问题：浏览器的布局画布到底多宽？答案由 viewport 决定。

## 4.1 三种视口

移动浏览器里同时存在三个"视口"概念，先分清再谈配置：

- **布局视口（layout viewport）**：CSS 布局所依据的画布宽度，`document.documentElement.clientWidth` 可读。百分比宽度、媒体查询都以它为基准。
- **视觉视口（visual viewport）**：用户当前实际看到的区域，`window.visualViewport.width` 可读。双指缩放改变的是它——放大时看到的内容变少。
- **理想视口（ideal viewport）**：设备的 CSS 像素宽度，即[第 2 章](/pixels-viewport/ch02)算出的 440。它是"布局视口等于它"时最理想的状态，`screen.width` 反映它。

三者的关系：布局视口是画布，视觉视口是取景框，理想视口是我们希望画布达到的尺寸。

## 4.2 不写 viewport 会发生什么

移动浏览器为了兼容桌面时代的网页，**默认布局视口宽 980px**（iOS Safari 与 Android Chrome 均如此）。流程是：

1. 按 980px 宽排版页面（模拟桌面显示器）；
2. 整体缩小塞进 440px 宽的屏幕（缩放系数 ≈ 440/980 ≈ 0.45）。

后果：页面完整可见但字极小，相当于"看缩略图"，必须手动双指放大才能阅读。这是 2007 年 iPhone 发布时的历史方案——当时手机上绝大多数网站只有桌面版，980 兼容模式保证"能看"，代价是体验糟糕。

## 4.3 `width=device-width` 的作用

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

这行代码的作用是：**把布局视口宽度设为设备的理想视口（CSS 像素宽度）**。

加上后：

- 布局视口从 980 变为 440，页面按手机屏真实宽度排版；
- `@media (max-width: 768px)` 等媒体查询以真实屏宽生效，响应式布局才成立；
- CSS 里的百分比、flex、grid 都以 440 为基准计算。

**注意**：`device-width` 指的是 CSS 像素宽度（440），不是物理像素（1320）。设备相关的换算由浏览器按 DPR 自动完成，开发者始终只写 CSS 像素。

`initial-scale=1` 保证初始缩放为 1:1，布局视口不被额外放大缩小（`width=device-width` 与 `initial-scale=1` 同时写，取二者中较大的生效，正常设备上两者结果一致）。

## 4.4 完整 meta 配置逐项解析

```html
<meta name="viewport"
      content="width=device-width,
               initial-scale=1.0,
               minimum-scale=1.0,
               maximum-scale=1.0,
               user-scalable=no,
               viewport-fit=cover">
```

| 属性 | 作用 | 建议 |
| ------ | ------ | ------ |
| `width=device-width` | 布局视口 = 理想视口 | 必写 |
| `initial-scale` | 初始缩放比 | 写 1 |
| `minimum/maximum-scale` | 允许的缩放范围 | 一般不限制 |
| `user-scalable` | 是否允许用户缩放 | **不要设 no**（无障碍要求） |
| `viewport-fit=cover` | 内容延伸到刘海/安全区 | iPhone X 以后配合 `env(safe-area-inset-*)` 使用 |

一个有争议但值得知道的现状：部分 App 内嵌 WebView 或国产浏览器会无视 `user-scalable=no`；而 iOS Safari 从 10 开始直接忽略它，允许用户始终缩放——这是 Apple 为可访问性做的强制决定。

## 4.5 小结

- 布局视口是 CSS 的画布，视觉视口是取景框，理想视口是设备 CSS 宽度。
- 不写 viewport → 980 兼容模式 → 整体缩小。
- `width=device-width` 把画布还给真实屏宽，是响应式的第一前提。

## 4.6 练习题

1. 在 iPhone 16 Pro Max 上，不写 viewport 与写 `width=device-width` 后，布局视口分别是多少？
2. 用户双指放大页面时，布局视口和视觉视口各发生什么变化？CSS 布局会重排吗？
3. `user-scalable=no` 在 iOS Safari（10 及以后）上的实际效果是什么？

## 4.7 参考答案

> 1. 不写时默认 980px（桌面兼容模式）；写后为理想视口 440px。
> 2. 布局视口不变、页面不重排，变化的是视觉视口——放大后取景框变小，看到的内容变少。这正是"缩放不影响布局"的设计。
> 3. 被 Safari 直接忽略，用户始终可以缩放页面。这是 Apple 为可访问性做的强制决定，不要依赖它禁用缩放。
