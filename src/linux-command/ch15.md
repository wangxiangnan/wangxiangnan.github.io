# 第15章：SSH 远程访问

## 15.1 什么是 SSH？

SSH（Secure Shell）就是你和远程服务器之间的"加密隧道"。你在本地敲的命令，通过 SSH 加密后传到服务器上执行，服务器的返回结果也加密传回来。没有 SSH，你就得跑到机房里对着服务器的显示器敲键盘——那画面太美我不敢看。

**SSH 的三个"超能力"：**

1. **加密通信**：所有数据加密传输，窃听者看到的是一堆乱码
2. **身份认证**：密码或密钥验证，确保"你是你"
3. **端口转发**：可以把远程端口"映射"到本地（后面会讲）

## 15.2 SSH 基本连接

```bash
# 最基本的 SSH 连接
ssh user@server-ip
# 示例：ssh root@192.168.1.200
# 会提示输入密码（输入时不显示字符，这是正常的！）

# 指定端口（默认是 22）
ssh -p 2222 user@server-ip

# 指定用户名和主机
ssh alice@web-prod-01
# 前提是 ~/.ssh/config 或 /etc/hosts 里有对应配置

# SSH 第一次连接会问你是否信任服务器指纹
# The authenticity of host '...' can't be established.
# ECDSA key fingerprint is SHA256:xxxxxxx.
# Are you sure you want to continue connecting (yes/no)?
# 输入 yes（不是 y！必须写完整的 yes）

# 直接执行远程命令（不进入交互式 shell）
ssh user@server "df -h && free -h"
# 输出远程服务器的磁盘和内存使用情况

# 在远程服务器上执行脚本
ssh user@server "bash -s" < local-script.sh

# SSH 连接超时自动断开？设置 ServerAliveInterval
ssh -o ServerAliveInterval=60 user@server
# 每 60 秒发一个心跳包，防止连接超时断开
```

## 15.3 SSH 密钥认证

密码认证的缺点：容易忘记、容易被暴力破解、每次都要输入。密钥认证就是"用一把加密的钥匙代替密码"——更安全、更方便。

```bash
# Step 1: 生成密钥对（在你自己的电脑上执行！不是服务器上！）
ssh-keygen -t ed25519 -C "your_email@example.com"
# -t ed25519 → 使用 Ed25519 算法（比 RSA 更安全更快）
# -C         → 注释（标识这把钥匙是谁的）
# 输出：
# Generating public/private ed25519 key pair.
# Enter file in which to save the key (/home/you/.ssh/id_ed25519):
# Enter passphrase (empty for no passphrase):
# 建议设置 passphrase（密钥的密码），多一层保护

# 如果你还在用 RSA（兼容老系统）
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"
# -b 4096 → 4096 位密钥（至少 2048，推荐 4096）

# 生成的文件：
# ~/.ssh/id_ed25519       → 私钥（你的钥匙，绝对不能泄露！）
# ~/.ssh/id_ed25519.pub   → 公钥（可以给别人，贴在服务器上）

# Step 2: 把公钥复制到服务器
ssh-copy-id user@server-ip
# 会要求输入一次密码，之后公钥就自动添加到服务器的
# ~/.ssh/authorized_keys 文件中

# 指定端口和密钥
ssh-copy-id -p 2222 -i ~/.ssh/id_ed25519.pub user@server-ip

# Step 3: 测试免密码登录
ssh user@server-ip
# 如果设置了 passphrase，会要求输入 passphrase（不是服务器密码）
# 没设置 passphrase 的话就直接登录了！

# 如果 ssh-copy-id 不可用，手动复制：
cat ~/.ssh/id_ed25519.pub | ssh user@server "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

# 使用 ssh-agent 缓存密钥密码（避免每次输入 passphrase）
eval $(ssh-agent -s)
ssh-add ~/.ssh/id_ed25519
# 输入一次 passphrase，之后这个终端会话就不用再输了

# macOS 用户：让 ssh-agent 记住密码（重启也不丢）
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
```

## 15.4 SSH 配置文件：~/.ssh/config

这个文件是 SSH 的"快捷方式管理器"——把常用的服务器配置保存下来，以后一个别名就能连接。

```bash
# 编辑 SSH 配置文件
nano ~/.ssh/config

# 配置示例：
# # 生产环境 Web 服务器
# Host web-prod
#     HostName 203.0.113.50
#     User deploy
#     Port 22
#     IdentityFile ~/.ssh/id_ed25519_prod
#     ServerAliveInterval 60
#     ServerAliveCountMax 3
#     ForwardAgent yes
#
# # 测试环境
# Host test
#     HostName 10.0.0.100
#     User root
#     Port 2222
#     IdentityFile ~/.ssh/id_ed25519_test
#
# # 跳板机
# Host jump
#     HostName 203.0.113.1
#     User admin
#     IdentityFile ~/.ssh/id_jump
#
# # 通过跳板机访问内网服务器
# Host internal
#     HostName 10.0.0.200
#     User deploy
#     ProxyJump jump
#
# # 通配符：所有 *.example.com 的服务器
# Host *.example.com
#     User admin
#     IdentityFile ~/.ssh/id_example
#     StrictHostKeyChecking accept-new

# 配置文件权限必须正确！
chmod 600 ~/.ssh/config

# 配置好后，直接用别名连接
ssh web-prod          # 等价于 ssh deploy@203.0.113.50 -p 22 -i ~/.ssh/id_ed25519_prod
ssh test              # 等价于 ssh root@10.0.0.100 -p 2222
ssh internal          # 自动通过 jump 跳板机中转

# 常用配置项说明：
# Host              → 别名（你给服务器起的名字）
# HostName          → 实际 IP 或域名
# User              → 登录用户名
# Port              → SSH 端口
# IdentityFile      → 私钥文件路径
# ServerAliveInterval → 心跳间隔（秒），防止连接超时
# ServerAliveCountMax → 心跳失败几次后断开
# ForwardAgent      → 是否转发 ssh-agent（在跳板机上用本地密钥）
# ProxyJump         → 通过哪个主机跳转
# StrictHostKeyChecking → ask(默认)/yes/no/accept-new
# ConnectTimeout    → 连接超时（秒）
```

## 15.5 文件传输：scp、sftp、rsync

### 15.5.1 scp：简单的文件复制

```bash
# 上传文件到远程服务器
scp local-file.txt user@server:/remote/path/
# 示例：scp report.pdf alice@web-prod:/home/alice/

# 下载远程文件到本地
scp user@server:/remote/file.txt ./local-dir/

# 递归复制整个目录
scp -r local-dir/ user@server:/remote/path/

# 指定端口
scp -P 2222 file.txt user@server:/path/    # 注意：scp 用 -P（大写）

# 使用压缩传输（大文件加速）
scp -C large-file.tar.gz user@server:/path/

# 复制多个文件
scp file1.txt file2.txt file3.txt user@server:/remote/path/
```

### 15.5.2 sftp：交互式文件管理

```bash
# 连接 SFTP
sftp user@server
# 进入 sftp> 交互界面

# sftp 常用命令
# sftp> ls                    # 列出远程文件
# sftp> cd /var/www           # 切换远程目录
# sftp> lcd ~/Downloads       # 切换本地目录（lcd = local cd）
# sftp> pwd                   # 显示远程当前目录
# sftp> lpwd                  # 显示本地当前目录
# sftp> get file.txt          # 下载文件
# sftp> put file.txt          # 上传文件
# sftp> get -r remote-dir/    # 递归下载目录
# sftp> put -r local-dir/     # 递归上传目录
# sftp> rm file.txt           # 删除远程文件
# sftp> mkdir new-dir         # 创建远程目录
# sftp> rename old.txt new.txt # 重命名
# sftp> bye                   # 退出
```

### 15.5.3 rsync：终极文件同步工具

```bash
# rsync 是最强大的文件同步工具
# 支持增量传输（只传变化的部分）、断点续传、压缩传输

# 基本同步（本地→远程）
rsync -avz local-dir/ user@server:/remote/dir/
# -a → 归档模式（保留权限、时间戳、软链接等）
# -v → 显示详细信息
# -z → 传输时压缩（省带宽）
# 注意：local-dir/ 末尾有 / → 同步目录内容
#       local-dir  末尾没 / → 同步整个目录（包括目录本身）

# 远程→本地
rsync -avz user@server:/remote/dir/ ./local-dir/

# 显示进度条
rsync -avz --progress local-dir/ user@server:/remote/dir/

# 镜像同步（让远程和本地完全一致，远程多出的文件会被删除！）
rsync -avz --delete local-dir/ user@server:/remote/dir/
# ⚠️  --delete 很危险！远程有但本地没有的文件会被删掉
# 建议先 --dry-run 预览：
rsync -avz --delete --dry-run local-dir/ user@server:/remote/dir/

# 排除特定文件/目录
rsync -avz --exclude='*.log' --exclude='node_modules/' local-dir/ user@server:/remote/dir/

# 排除多个（用排除文件）
rsync -avz --exclude-from=exclude-list.txt local-dir/ user@server:/remote/dir/
# exclude-list.txt 内容：
# *.log
# node_modules/
# .git/
# .env

# 限制带宽（避免同步把网络占满）
rsync -avz --bwlimit=5000 local-dir/ user@server:/remote/dir/
# --bwlimit=5000 → 限速 5000 KB/s ≈ 5 MB/s

# 断点续传（大文件传一半断了，继续传）
rsync -avz --partial --progress large-file.iso user@server:/path/
# 或简写为 -P（等价于 --partial --progress）
rsync -avP large-file.iso user@server:/path/

# 指定 SSH 端口
rsync -avz -e 'ssh -p 2222' local-dir/ user@server:/remote/dir/

# 备份场景：每天同步到备份服务器
rsync -avz --delete --exclude='*.tmp' \
  /data/important/ \
  backup-user@backup-server:/backups/daily/

# 对比本地和远程的差异（不同步，只查看）
rsync -avz --dry-run --itemize-changes local-dir/ user@server:/remote/dir/
```

## 15.6 SSH 隧道与端口转发

SSH 隧道是 SSH 最强大的功能之一——它可以把远程端口"映射"到本地，让你像在本地一样访问远程服务。

### 15.6.1 本地端口转发（-L）

```bash
# 场景：服务器上有个 MySQL 只监听 localhost:3306，你在本地想连
# 把远程的 3306 映射到本地的 33060
ssh -L 33060:localhost:3306 user@server -N
# -N → 不执行远程命令（只做端口转发）
# 现在你可以在本地用 localhost:33060 连接远程 MySQL

# 场景：访问远程服务器上的 Web 管理面板（只监听内网）
ssh -L 8080:localhost:8080 user@server -N
# 浏览器打开 http://localhost:8080 就能访问远程的管理面板

# 场景：转发到内网另一台机器
ssh -L 5432:db-server:5432 user@jump-server -N
# 通过跳板机访问内网的数据库服务器
```

### 15.6.2 远程端口转发（-R）

```bash
# 场景：你的本地电脑在 NAT 后面，想让外面的人访问你本地的 Web 服务
# 把你本地的 8080 映射到远程服务器的 9000
ssh -R 9000:localhost:8080 user@public-server -N
# 现在别人访问 public-server:9000 就是在访问你本地的 8080

# 注意：远程端口转发默认只监听远程的 localhost
# 要让外部访问，需要在服务器的 sshd_config 里设置：
# GatewayPorts yes
```

### 15.6.3 动态端口转发（-D）：SOCKS 代理

```bash
# 把 SSH 变成一个 SOCKS5 代理！
ssh -D 1080 user@server -N
# 现在本地 1080 端口就是一个 SOCKS5 代理
# 所有通过 1080 的流量都会通过 SSH 隧道从服务器出去

# 配合浏览器使用：
# 在浏览器设置里配置 SOCKS 代理：127.0.0.1:1080
# 或者用命令行：
curl --socks5 127.0.0.1:1080 https://google.com

# 实用场景：在公共 WiFi 下保护你的流量
# 所有流量都走 SSH 加密隧道，WiFi 窃听者看不到你的数据
```

## 15.7 SSH 安全加固

```bash
# SSH 是黑客攻击的首要目标（因为它是服务器的"前门"）
# 以下措施能大幅提升 SSH 安全性

# 1. 修改默认端口（减少被扫描的概率）
sudo nano /etc/ssh/sshd_config
# Port 2222    ← 把 22 改成其他端口（选 1024-65535 之间的）

# 2. 禁止 root 直接登录
# PermitRootLogin no

# 3. 禁止密码登录（只允许密钥认证）
# PasswordAuthentication no

# 4. 限制允许登录的用户
# AllowUsers alice bob deploy

# 5. 设置登录超时
# LoginGraceTime 30        ← 30 秒内没登录成功就断开
# ClientAliveInterval 300  ← 5 分钟无操作发心跳
# ClientAliveCountMax 2    ← 心跳失败 2 次断开

# 6. 启用 Fail2Ban（自动封禁暴力破解的 IP）
sudo apt install fail2ban -y
sudo systemctl enable fail2ban
sudo systemctl start fail2ban

# Fail2Ban 配置（SSH 防护）
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
sudo nano /etc/fail2ban/jail.local
# [sshd]
# enabled = true
# port = 2222             ← 你修改后的 SSH 端口
# maxretry = 3            ← 3 次失败就封禁
# bantime = 3600          ← 封禁 1 小时
# findtime = 600          ← 10 分钟内

# 查看 Fail2Ban 状态
sudo fail2ban-client status sshd
sudo fail2ban-client status sshd | grep "Currently banned"

# 解封误封的 IP
sudo fail2ban-client set sshd unbanip 203.0.113.50

# 7. 重启 SSH 服务使配置生效
sudo systemctl restart sshd

# ⚠️  重要：修改 SSH 配置前先保持一个 SSH 连接不要断！
# 万一配置有误，你还能用这个连接修复，否则就把自己锁在外面了
```

## 15.8 SSH 进阶技巧

```bash
# 在远程执行本地脚本
ssh user@server < script.sh
ssh user@server "bash -s" < script.sh
ssh user@server "bash -s -- arg1 arg2" < script.sh   # 传参数

# SSH 多路复用（多个 SSH 会话共享一个连接，速度更快）
# 在 ~/.ssh/config 中添加：
# Host *
#     ControlMaster auto
#     ControlPath ~/.ssh/sockets/%r@%h-%p
#     ControlPersist 600
# 然后创建目录：
mkdir -p ~/.ssh/sockets
# 之后多个 ssh/scp/rsync 到同一服务器会复用同一个连接

# 保持 SSH 连接不断开（解决 NAT 超时断连）
# 在 ~/.ssh/config 中添加：
# Host *
#     ServerAliveInterval 60
#     ServerAliveCountMax 3

# 批量在多台服务器上执行命令
for host in web1 web2 web3; do
    echo "=== $host ==="
    ssh $host "uptime && df -h / | tail -1"
done

# 用 SSH 做简单的文件服务
# 在远程服务器上：
# python3 -m http.server 8000
# 然后通过 SSH 隧道在本地访问

# SSH 连接慢？检查 DNS 反向解析
# 在服务器的 /etc/ssh/sshd_config 中设置：
# UseDNS no
```

## 15.9 SSH 自动化实战脚本

```bash
# 脚本 1：批量服务器巡检
cat > ~/ssh-audit.sh << 'SCRIPT'
#!/bin/bash
# 批量检查多台服务器的状态
SERVERS=("web1" "web2" "db1" "cache1")

echo "=== 服务器批量巡检 $(date) ==="
echo ""

for server in "${SERVERS[@]}"; do
    echo "--- $server ---"
    ssh -o ConnectTimeout=5 -o BatchMode=yes "$server" '
        echo "主机名: $(hostname)"
        echo "运行时间: $(uptime -p)"
        echo "磁盘使用: $(df -h / | awk "NR==2{print \$5}")"
        echo "内存使用: $(free -h | awk "/Mem/{print \$3\"/\"\$2}")"
        echo "CPU负载: $(cat /proc/loadavg | cut -d" " -f1-3)"
    ' 2>/dev/null || echo "  ⚠️  连接失败！"
    echo ""
done
SCRIPT
chmod +x ~/ssh-audit.sh

# 脚本 2：文件批量分发
cat > ~/ssh-deploy.sh << 'SCRIPT'
#!/bin/bash
# 将文件批量分发到多台服务器
FILE=$1
REMOTE_PATH=$2
SERVERS=("web1" "web2" "web3")

if [ -z "$FILE" ] || [ -z "$REMOTE_PATH" ]; then
    echo "Usage: $0 <local-file> <remote-path>"
    echo "Example: $0 config.yaml /etc/myapp/"
    exit 1
fi

echo "=== 批量分发 $FILE → $REMOTE_PATH ==="
for server in "${SERVERS[@]}"; do
    echo -n "  $server: "
    scp -o ConnectTimeout=5 "$FILE" "$server:$REMOTE_PATH" 2>/dev/null
    if [ $? -eq 0 ]; then
        echo "✅ 成功"
    else
        echo "❌ 失败"
    fi
done
SCRIPT
chmod +x ~/ssh-deploy.sh

# 脚本 3：SSH 连接保活（tmux + SSH 配合）
cat > ~/ssh-persistent.sh << 'SCRIPT'
#!/bin/bash
# 持久化 SSH 会话（断线自动重连）
SERVER=${1:-"web-prod"}

while true; do
    echo "[$(date)] 连接到 $SERVER ..."
    ssh -o ServerAliveInterval=30 \
        -o ServerAliveCountMax=3 \
        -o ConnectTimeout=10 \
        "$SERVER" \
        "tmux attach -t work || tmux new -s work"

    EXIT_CODE=$?
    if [ $EXIT_CODE -eq 0 ]; then
        echo "正常退出"
        break
    fi

    echo "[$(date)] 连接断开（退出码: $EXIT_CODE），5秒后重连..."
    sleep 5
done
SCRIPT
chmod +x ~/ssh-persistent.sh

# 脚本 4：SSH 密钥轮换（定期更换密钥）
cat > ~/ssh-key-rotate.sh << 'SCRIPT'
#!/bin/bash
# 轮换 SSH 密钥（生成新密钥 → 部署 → 测试 → 删除旧密钥）
SERVER=$1
OLD_KEY="$HOME/.ssh/id_ed25519"
NEW_KEY="$HOME/.ssh/id_ed25519_new"

if [ -z "$SERVER" ]; then
    echo "Usage: $0 user@server"
    exit 1
fi

echo "Step 1: 生成新密钥..."
ssh-keygen -t ed25519 -f "$NEW_KEY" -N "" -q

echo "Step 2: 部署新公钥到服务器..."
ssh-copy-id -i "$NEW_KEY.pub" "$SERVER"

echo "Step 3: 测试新密钥..."
ssh -i "$NEW_KEY" "$SERVER" "echo '新密钥测试成功'" 2>/dev/null
if [ $? -eq 0 ]; then
    echo "Step 4: 替换旧密钥..."
    mv "$OLD_KEY" "$OLD_KEY.bak"
    mv "$OLD_KEY.pub" "$OLD_KEY.pub.bak"
    mv "$NEW_KEY" "$OLD_KEY"
    mv "$NEW_KEY.pub" "$OLD_KEY.pub"
    echo "✅ 密钥轮换成功！旧密钥备份为 .bak"
else
    echo "❌ 新密钥测试失败，保留旧密钥"
    rm -f "$NEW_KEY" "$NEW_KEY.pub"
fi
SCRIPT
chmod +x ~/ssh-key-rotate.sh
```

## 15.10 Mosh：移动时代的 SSH 替代

```bash
# Mosh（Mobile Shell）专为不稳定的网络设计
# WiFi 切换、手机热点、高铁上 SSH 老断？Mosh 帮你解决！

# 安装 Mosh（服务器和客户端都要装）
sudo apt install mosh -y
# 注意：Mosh 使用 UDP 60000-61000 端口，防火墙要开放
sudo ufw allow 60000:61000/udp

# 使用 Mosh 连接（语法和 SSH 几乎一样）
mosh user@server-ip
# Mosh 先通过 SSH 建立会话，然后切换到 UDP

# Mosh 的优势：
# 1. 断线自动重连（WiFi → 4G 切换不断会话）
# 2. 本地回显（打字不延迟，即使网络卡了）
# 3. 智能预测（预测你按的键，减少等待）

# Mosh 的限制：
# 1. 不支持端口转发（需要 SSH 隧道时还得用 SSH）
# 2. 不支持 scp/rsync（只能做交互式 shell）
# 3. 需要 UDP 端口（某些网络可能屏蔽）

# 最佳实践：Mosh + tmux/screen 组合
mosh user@server -- tmux new -s work
# 即使网络完全断了 10 分钟，重连后 tmux 会话还在
```

## 15.11 SSH 日志与安全审计

```bash
# SSH 登录日志是安全审计的"监控摄像头"

# 查看 SSH 登录日志
sudo tail -100 /var/log/auth.log | grep sshd
# 输出示例：
# Jan  1 12:00:00 server sshd[1234]: Accepted publickey for deploy from 10.0.0.5 port 54321
# Jan  1 12:05:00 server sshd[1235]: Failed password for root from 198.51.100.50 port 22

# 统计登录失败的 IP（找出暴力破解者）
sudo grep "Failed password" /var/log/auth.log | \
    awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head -10
# 输出示例：
# 1523 198.51.100.50     ← 这个 IP 试了 1523 次密码！

#   45 192.168.1.50      ← 这个可能是同事输错密码

# 统计成功登录的 IP
sudo grep "Accepted" /var/log/auth.log | \
    awk '{print $(NF-3)}' | sort | uniq -c | sort -rn

# 查看最近登录的用户
last -10
# 输出示例：
# deploy  pts/0   10.0.0.5     Mon Jan  1 12:00   still logged in
# admin   pts/1   192.168.1.50 Sun Dec 31 18:00 - 20:00  (02:00)

# 查看当前登录的用户
who
w

# 查看登录失败的历史
lastb
# 需要 root 权限，读取 /var/log/btmp

# 设置登录告警（有人 SSH 登录就通知你）
# 在 /etc/pam.d/sshd 最后添加：
# session optional pam_exec.so /usr/local/bin/login-alert.sh

cat > /usr/local/bin/login-alert.sh << 'SCRIPT'

    时间: $(date)

SCRIPT
chmod +x /usr/local/bin/login-alert.sh
```

## 15.12 SSH 一键加固脚本

```bash
# 新服务器到手？一键完成 SSH 安全加固！
cat > ~/ssh-harden.sh << 'SCRIPT'
#!/bin/bash
# SSH 一键安全加固脚本
# 用法：sudo bash ssh-harden.sh [新端口号]
# 示例：sudo bash ssh-harden.sh 2222

set -e
NEW_PORT=${1:-2222}
SSHD_CONFIG="/etc/ssh/sshd_config"
BACKUP="/etc/ssh/sshd_config.bak.$(date +%s)"

echo "=== SSH 安全加固 ==="
echo "目标端口: $NEW_PORT"
echo ""

# 备份原始配置
echo "[1/8] 备份 sshd_config → $BACKUP"
cp "$SSHD_CONFIG" "$BACKUP"

# 修改端口
echo "[2/8] 修改 SSH 端口为 $NEW_PORT"
sed -i "s/^#\?Port .*/Port $NEW_PORT/" "$SSHD_CONFIG"
grep -q "^Port " "$SSHD_CONFIG" || echo "Port $NEW_PORT" >> "$SSHD_CONFIG"

# 禁止 root 登录
echo "[3/8] 禁止 root 登录"
sed -i "s/^#\?PermitRootLogin .*/PermitRootLogin no/" "$SSHD_CONFIG"
grep -q "^PermitRootLogin " "$SSHD_CONFIG" || echo "PermitRootLogin no" >> "$SSHD_CONFIG"

# 禁止密码登录
echo "[4/8] 禁止密码登录（确保密钥已配好！）"
# 注意：如果密钥没配好就禁密码，会把自己锁在外面
# 先检查当前用户是否有密钥
if [ -s /root/.ssh/authorized_keys ] || \
   ls /home/*/.ssh/authorized_keys 1>/dev/null 2>&1; then
    sed -i "s/^#\?PasswordAuthentication .*/PasswordAuthentication no/" "$SSHD_CONFIG"
    echo "    已禁止密码登录"
else
    echo "    ⚠️  未找到 authorized_keys，跳过密码禁用！"
fi

# 设置超时
echo "[5/8] 设置连接超时"
sed -i "s/^#\?LoginGraceTime .*/LoginGraceTime 30/" "$SSHD_CONFIG"
sed -i "s/^#\?ClientAliveInterval .*/ClientAliveInterval 300/" "$SSHD_CONFIG"
sed -i "s/^#\?ClientAliveCountMax .*/ClientAliveCountMax 2/" "$SSHD_CONFIG"

# 禁用空密码
echo "[6/8] 禁用空密码和 X11 转发"
sed -i "s/^#\?PermitEmptyPasswords .*/PermitEmptyPasswords no/" "$SSHD_CONFIG"
sed -i "s/^#\?X11Forwarding .*/X11Forwarding no/" "$SSHD_CONFIG"

# 禁用 DNS 反向解析（加速连接）
echo "[7/8] 禁用 UseDNS（加速 SSH 连接）"
grep -q "^UseDNS " "$SSHD_CONFIG" && \
    sed -i "s/^UseDNS .*/UseDNS no/" "$SSHD_CONFIG" || \
    echo "UseDNS no" >> "$SSHD_CONFIG"

# 验证配置
echo "[8/8] 验证配置..."
if sshd -t 2>/dev/null; then
    echo "✅ 配置验证通过！"
    systemctl restart sshd
    echo "✅ SSH 服务已重启"
    echo ""
    echo "⚠️  重要提醒："
    echo "  1. 保持当前 SSH 连接不要断！"
    echo "  2. 新开一个终端测试: ssh -p $NEW_PORT user@server"
    echo "  3. 如果新连接成功，再关旧连接"
    echo "  4. 记得开放防火墙端口: sudo ufw allow $NEW_PORT/tcp"
else
    echo "❌ 配置有误！恢复备份..."
    cp "$BACKUP" "$SSHD_CONFIG"
    systemctl restart sshd
    echo "已恢复原始配置"
fi
SCRIPT
chmod +x ~/ssh-harden.sh
```

## 15.13 SSH 连接问题排查指南

```bash
# 当 SSH 连不上时，按这个清单排查：

# 问题 1: Connection refused
# 原因：SSH 服务没运行或端口不对
sudo systemctl status sshd              # 检查服务状态
sudo ss -tlnp | grep sshd              # 检查监听端口
sudo journalctl -u sshd -n 20          # 查看 sshd 日志

# 问题 2: Connection timed out
# 原因：网络不通或防火墙拦截
ping server-ip                          # 网络通不通？
sudo ufw status                         # 防火墙开了端口没？
traceroute server-ip                    # 在哪一跳断的？

# 问题 3: Permission denied (publickey)
# 原因：密钥配置有问题
# 客户端检查：
ls -la ~/.ssh/                          # 权限对吗？（700）
ls -la ~/.ssh/id_ed25519               # 私钥权限（600）
ssh -vvv user@server                    # 详细调试模式
# 服务端检查：
sudo cat /home/user/.ssh/authorized_keys  # 公钥在里面吗？
sudo ls -la /home/user/.ssh/            # 目录权限（700）
sudo tail -20 /var/log/auth.log         # 看日志

# 问题 4: Host key verification failed
# 原因：服务器指纹变了（重装系统/换密钥）
ssh-keygen -R server-ip                 # 删除旧指纹
# 然后重新连接，接受新指纹

# 问题 5: Connection closed by remote host
# 原因：服务器主动断开
sudo tail -50 /var/log/auth.log         # 看服务端日志
# 常见原因：
# - MaxStartups 达到上限（并发连接太多）
# - AllowUsers/DenyUsers 配置限制
# - PAM 模块问题

# 万能调试命令（详细日志）
ssh -vvv user@server
# -vvv 是最详细级别，会打印每一步的协商过程
# 看最后几行的错误信息就能定位问题
```

## 15.14 常见坑与注意事项

```bash
# 坑 1：scp 的 -P（大写）vs ssh 的 -p（小写）
ssh -p 2222 user@server    # SSH 用小写 -p
scp -P 2222 file user@server  # SCP 用大写 -P（历史原因，很坑！）

# 坑 2：rsync 的末尾斜杠
rsync -avz src/  dest/     # 同步 src 的内容到 dest
rsync -avz src   dest/     # 同步 src 目录本身到 dest/src

# 坑 3：SSH 指纹变化（WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!）
# 服务器重装系统/更换密钥后会出现
# 需要手动删除旧的指纹记录：
ssh-keygen -R server-ip
# 或者编辑 ~/.ssh/known_hosts 删除对应行

# 坑 4：Permission denied (publickey)
# 检查：
# 1. 公钥是否在服务器的 ~/.ssh/authorized_keys 中
# 2. 文件权限是否正确（.ssh 700，authorized_keys 600）
# 3. 私钥文件是否正确
ls -la ~/.ssh/
# 4. 用 -v 看详细日志
ssh -v user@server

# 坑 5：rsync --delete 的杀伤力
# 先 --dry-run 确认！否则可能删掉重要文件
```

## 15.10 本章小结

SSH 是远程管理服务器的"生命线"。密钥认证比密码更安全更方便，`~/.ssh/config` 让你告别记忆端口和用户名的痛苦，rsync 是文件同步的终极武器，SSH 隧道能帮你穿透各种网络限制。安全加固不是可选的——如果你的服务器暴露在公网上，暴力破解可能在你装好系统的第 30 秒就开始了。
