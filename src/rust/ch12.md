# 第12章：Trait——共享行为的抽象

## 开篇："鸭子类型"的终极进化

在 Python 里你信奉"鸭子类型"——如果它走起来像鸭子、叫起来像鸭子，那它就是鸭子。你从来不检查类型，只关心有没有 `quack()` 方法。Java 用 `interface` 来规范化这种约定，Go 用 `interface` 做结构化子类型。

Rust 的 **Trait** 是这条演化链上的下一环：它既像接口一样定义行为契约，又支持默认实现、关联类型等高级特性，还能在编译期保证你不会在运行时遭遇 `NoSuchMethodError`。

## 什么是 Trait？

**Trait** 定义了类型可以共享的行为（方法）。如果一个类型实现了某个 Trait，就意味着它拥有该 Trait 定义的所有方法。

```rust
// 定义一个 Trait
trait Summary {
    fn summarize(&self) -> String;
}
```

这和 Java 的 `interface` 非常相似。但 Rust 的 Trait 有几个独特之处：

1. **默认实现**：Trait 方法可以有默认实现，实现者可以选择覆盖。
2. **孤儿规则**：你不能为别人的类型实现别人的 Trait（稍后详述）。
3. **Trait Bound**：可以在泛型中约束类型必须实现某些 Trait。

## 定义与实现 Trait

```rust
trait Summary {
    fn summarize_author(&self) -> String;
    fn summarize(&self) -> String {
        format!("(Read more from {}...)", self.summarize_author())
    }
}

struct NewsArticle {
    headline: String,
    author: String,
    content: String,
}

// 为 NewsArticle 实现 Summary
impl Summary for NewsArticle {
    fn summarize_author(&self) -> String {
        self.author.clone()
    }
    // summarize 使用默认实现
}

struct Tweet {
    username: String,
    content: String,
}

// 为 Tweet 实现 Summary，覆盖默认实现
impl Summary for Tweet {
    fn summarize_author(&self) -> String {
        format!("@{}", self.username)
    }

    fn summarize(&self) -> String {
        format!("@{}: {}", self.username, self.content)
    }
}

fn main() {
    let article = NewsArticle {
        headline: "Penguins Win!".to_string(),
        author: "Alice".to_string(),
        content: "The Penguins won the cup.".to_string(),
    };

    let tweet = Tweet {
        username: "bob".to_string(),
        content: "I love Rust!".to_string(),
    };

    println!("{}", article.summarize()); // (Read more from Alice...)
    println!("{}", tweet.summarize());   // @bob: I love Rust!
}
```

## 默认实现与覆盖

如上例所示，Trait 中的方法可以有默认实现。实现者可以选择：

- **不实现该方法**：使用默认实现。
- **覆盖该方法**：提供自己的版本。

但有一个微妙的限制：**默认实现可以调用同 Trait 中的其他方法（即使那些方法没有默认实现）**。这就是 `summarize` 的默认实现能调用 `summarize_author()` 的原因——即使 `summarize_author` 必须由实现者提供。

## Trait 作为参数（impl Trait 语法）

Trait 最强大的用途之一是作为函数参数，让函数接受任何实现了特定 Trait 的类型：

```rust
trait Summary {
    fn summarize(&self) -> String;
}

struct Tweet {
    username: String,
    content: String,
}

impl Summary for Tweet {
    fn summarize(&self) -> String {
        format!("@{}: {}", self.username, self.content)
    }
}

struct NewsArticle {
    headline: String,
    author: String,
}

impl Summary for NewsArticle {
    fn summarize(&self) -> String {
        format!("{} by {}", self.headline, self.author)
    }
}

// 使用 impl Trait 语法
fn notify(item: &impl Summary) {
    println!("Breaking news: {}", item.summarize());
}

// 返回 impl Trait
fn create_summary() -> impl Summary {
    Tweet {
        username: "rustlang".to_string(),
        content: "Rust 2024 is here!".to_string(),
    }
}

fn main() {
    let tweet = Tweet {
        username: "alice".to_string(),
        content: "Learning Rust!".to_string(),
    };
    let article = NewsArticle {
        headline: "Rust is popular".to_string(),
        author: "Bob".to_string(),
    };

    notify(&tweet);
    notify(&article);

    let s = create_summary();
    println!("{}", s.summarize());
}
```

`impl Summary` 读起来非常自然："接受任何实现了 `Summary` 的东西"。但这个语法有一个限制：**两个参数必须接受相同的类型**。如果需要更灵活的约束，你需要 Trait Bound。

## Trait Bound 与 where 子句

`impl Trait` 语法实际上是 Trait Bound 的简写形式：

```rust
// 这两种写法完全等价
fn notify(item: &impl Summary) { /* ... */ }
fn notify<T: Summary>(item: &T) { /* ... */ }
```

当约束变复杂时，Trait Bound 更加灵活：

```rust
use std::fmt::Display;

// 两个参数必须是同一种类型，且同时实现 Summary 和 Display
fn notify_and_display<T: Summary + Display>(item1: &T, item2: &T) {
    println!("{} and {}", item1.summarize(), item2);
}

// 两个参数可以是不同类型
fn notify_mixed(item1: &impl Summary, item2: &impl Summary) {
    println!("{} | {}", item1.summarize(), item2.summarize());
}
```

当 Trait Bound 太长影响可读性时，`where` 子句是你的救星：

```rust
// Trait Bound 写法——一行塞不下
fn some_function<T: Display + Clone, U: Clone + Debug>(t: &T, u: &U) -> i32 {
    0
}

// where 子句——清爽多了
fn some_function_clean<T, U>(t: &T, u: &U) -> i32
where
    T: Display + Clone,
    U: Clone + Debug,
{
    0
}
```

> **类比**：Java 中你会写 `<T extends Comparable<T> & Serializable>`，Rust 用 `+` 连接多个 Trait，用 `where` 处理复杂场景——本质上是同一个思路，语法更简洁。

## 常用标准库 Trait

Rust 标准库定义了大量常用 Trait，以下是最常打交道的几个：

| Trait | 用途 | 常见实现方式 |
| ------- | ------ | ------------- |
| `Display` | 用户友好的格式化输出（`{}`） | 手动实现 |
| `Debug` | 调试用的格式化输出（`{:?}`） | `#[derive(Debug)]` |
| `Clone` | 显式深拷贝 | `#[derive(Clone)]` |
| `Copy` | 隐式浅拷贝（仅限栈上类型） | `#[derive(Copy, Clone)]` |
| `PartialEq` | 部分相等比较（`==`） | `#[derive(PartialEq)]` |
| `Eq` | 完全相等比较（无 NaN 等特殊情况） | `#[derive(Eq, PartialEq)]` |
| `Hash` | 可用作 HashMap 的键 | `#[derive(Hash)]` |
| `Ord` / `PartialOrd` | 排序比较 | `#[derive(Ord, PartialOrd)]` |
| `From` / `Into` | 类型转换 | 手动实现 |
| `Iterator` | 迭代器行为 | 手动实现（第14章详述） |

## derive 宏自动生成 Trait 实现

对于很多标准 Trait，你不需要手动实现——`#[derive(...)]` 宏帮你搞定一切：

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord)]
struct Color {
    r: u8,
    g: u8,
    b: u8,
}

fn main() {
    let red = Color { r: 255, g: 0, b: 0 };
    let red2 = red.clone(); // Clone
    let blue = Color { r: 0, g: 0, b: 255 };

    println!("{:?}", red);           // Debug
    println!("{}", red == red2);     // PartialEq: true
    println!("{}", red > blue);      // PartialOrd: true (逐字段比较)

    // Hash: 可以用作 HashMap 的键
    let mut color_names = std::collections::HashMap::new();
    color_names.insert(red, "Red");
    color_names.insert(blue, "Blue");

    println!("Color names: {:?}", color_names);
}
```

`derive` 不是魔法——它在编译期自动展开为手写的 `impl` 代码。你可以用 `cargo expand` 查看展开后的结果。

## 孤儿规则（Orphan Rule）

Rust 有一条严格的规则：**你不能为别人的类型实现别人的 Trait**。更精确地说：

> 要实现一个 Trait，必须满足以下条件之一：
>
> - 该 Trait 是在你的 crate 中定义的，**或**
> - 该类型是在你的 crate 中定义的。

这条规则叫做**孤儿规则（Orphan Rule）**，它防止了不同 crate 之间的冲突。想象一下：如果 `crate_a` 和 `crate_b` 都为 `String` 实现了 `Display`，你的代码同时依赖了两者，编译器该听谁的？

```rust
// 假设你在自己的 crate 中
// 可以：为自己的类型实现标准库的 Trait
struct MyStruct;
impl std::fmt::Display for MyStruct { /* OK */ todo!() }

// 不可以：为 String（标准库的类型）实现 Display（标准库的 Trait）
// impl std::fmt::Display for String { /* 编译错误! */ todo!() }

// 可以：为自己的类型实现自己的 Trait
trait MyTrait { fn my_method(&self); }
impl MyTrait for String { /* OK! String 是外部类型，但 MyTrait 是你的 */ todo!() }
```

**绕过孤儿规则**的常见方式是 **Newtype 模式**——用元组结构体包一层：

```rust
use std::fmt;

// 用 Wrapper 包住 Vec<String>
struct Wrapper(Vec<String>);

impl fmt::Display for Wrapper {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "[{}]", self.0.join(", "))
    }
}

fn main() {
    let w = Wrapper(vec!["hello".to_string(), "world".to_string()]);
    println!("{}", w); // [hello, world]
}
```

`Wrapper` 是你定义的类型，所以你可以为它实现任何 Trait。代价是你失去了 `Vec<String>` 上直接可调用的方法——需要手动委托或通过 `Deref` trait 来解决。

## 实战：为一个自定义类型实现多个 Trait

让我们来创建一个 `Temperature` 类型，并为它实现一系列标准库 Trait：

```rust
use std::fmt;
use std::ops::Add;

#[derive(Debug, Clone, PartialEq, PartialOrd)]
struct Temperature {
    celsius: f64,
}

impl Temperature {
    fn new(celsius: f64) -> Self {
        Temperature { celsius }
    }

    fn from_fahrenheit(f: f64) -> Self {
        Temperature {
            celsius: (f - 32.0) * 5.0 / 9.0,
        }
    }

    fn to_fahrenheit(&self) -> f64 {
        self.celsius * 9.0 / 5.0 + 32.0
    }
}

// 手动实现 Display
impl fmt::Display for Temperature {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "{:.1}°C", self.celsius)
    }
}

// 实现 Add trait，让两个温度可以相加
impl Add for Temperature {
    type Output = Temperature;

    fn add(self, other: Temperature) -> Temperature {
        Temperature {
            celsius: self.celsius + other.celsius,
        }
    }
}

// 实现 From<f64>，允许从 f64 直接转换
impl From<f64> for Temperature {
    fn from(celsius: f64) -> Self {
        Temperature { celsius }
    }
}

// 实现 Default
impl Default for Temperature {
    fn default() -> Self {
        Temperature { celsius: 0.0 }
    }
}

fn main() {
    let t1 = Temperature::new(25.0);
    let t2 = Temperature::from_fahrenheit(98.6);
    let t3: Temperature = 100.0.into(); // From<f64>

    println!("t1 = {} ({:?})", t1, t1);
    println!("t2 = {} ({:.1}°F)", t2, t2.to_fahrenheit());
    println!("t3 = {}", t3);

    let combined = t1.clone() + t2.clone(); // Add + Clone
    println!("combined = {}", combined);

    println!("t1 > t2? {}", t1 > t2); // PartialOrd

    let zero = Temperature::default();
    println!("default = {}", zero);
}
```

这个例子展示了 Rust 类型系统的哲学：**通过实现不同的 Trait，让类型自然地融入 Rust 的生态**。你的 `Temperature` 可以打印（Display）、可以调试（Debug）、可以比较（PartialOrd）、可以相加（Add）、可以类型转换（From）——就像一个好公民融入了整个社会。

## 常见陷阱与易错点

**陷阱1：Trait 方法冲突**

当一个类型实现了多个 Trait，且这些 Trait 有同名方法时，需要用完全限定语法（Fully Qualified Syntax）来消除歧义：

```rust
trait Pilot {
    fn fly(&self);
}

trait Wizard {
    fn fly(&self);
}

struct Human;

impl Pilot for Human {
    fn fly(&self) { println!("Captain speaking."); }
}

impl Wizard for Human {
    fn fly(&self) { println!("Up, up, and away!"); }
}

impl Human {
    fn fly(&self) { println!("*waving arms furiously*"); }
}

fn main() {
    let h = Human;
    h.fly();                          // 调用 Human 自己的方法
    Pilot::fly(&h);                   // 调用 Pilot 的 fly
    Wizard::fly(&h);                  // 调用 Wizard 的 fly
}
```

**陷阱2：忘记 derive 的限制**

`#[derive(Clone)]` 要求结构体的**所有字段**都实现了 `Clone`。如果你有一个 `Rc<RefCell<T>>` 字段，`derive(Clone)` 会做浅拷贝（只复制引用计数），这可能不是你想要的深拷贝语义。

**陷阱3：`impl Trait` 的返回类型限制**

`fn foo() -> impl Summary` 看起来很好用，但它要求函数**所有分支都返回同一种具体类型**。不能用 `impl Trait` 根据不同条件返回不同类型——那种情况需要 `Box<dyn Trait>`（动态分发，后续章节会讲）。

## 小结

- Trait 定义了类型共享的行为，类似接口但更强大。
- 默认实现减少了样板代码。
- `impl Trait` 和 Trait Bound 让函数可以接受泛型参数同时约束其行为。
- `where` 子句让复杂的 Trait Bound 更可读。
- `#[derive(...)]` 自动生成标准 Trait 的实现。
- 孤儿规则保护了 crate 生态的一致性。

## 练习题

1. **基础**：定义一个 `Area` trait，包含 `fn area(&self) -> f64` 方法。为 `Rectangle { width: f64, height: f64 }` 和 `Circle { radius: f64 }` 分别实现它。

2. **中级**：写一个泛型函数 `print_area<T: Area>(item: &T)`，打印任意形状的面积。再用 `where` 子句重写为 `print_area_verbose`。

3. **进阶**：为你的 `Rectangle` 实现 `Display`、`Debug`、`PartialEq` 和 `Clone`（至少一个手动实现，其余用 derive）。然后写一个函数接受 `impl Display + Clone` 参数。

4. **思考题**：为什么 Rust 有孤儿规则？试着设计一个没有孤儿规则的场景，说明会导致什么问题。

5. **挑战**：实现一个 `Sortable` trait，包含 `fn sort(items: &mut Vec<Self>)` 方法，要求 `Self: PartialOrd`。为 `Vec<i32>` 和 `Vec<String>` 分别实现它（提示：你可能需要 Newtype 模式）。
