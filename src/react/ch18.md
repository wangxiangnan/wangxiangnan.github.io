## 18.1 为什么要写测试？

很多初学者（甚至一些有经验的开发者）会觉得：

> "写测试太浪费时间了，功能都做不完，哪有时间写测试？"

让我告诉你，这是一个**非常昂贵的误解**。

### 没有测试的世界

```
你改了 A 组件的一个 bug
    ↓
一周后，用户报告 B 页面的按钮不能点了
    ↓
你花了两小时排查，发现是你改 A 的时候不小心影响了 B
    ↓
你修了 B，但又不确定有没有影响到 C、D、E...
    ↓
你开始害怕改代码 😰
```

### 有测试的世界

```
你改了 A 组件的一个 bug
    ↓
运行测试：✅ 所有 50 个测试通过
    ↓
你信心满满地提交了代码 😎
    ↓
一周后，同事改了 B 组件
    ↓
运行测试：❌ 测试 #32 失败了！
    ↓
同事在影响你之前，测试就帮他发现了问题
```

### 测试的三大好处

1. **安全网**：重构代码时不害怕，测试帮你兜底
2. **活文档**：测试用例就是代码的使用说明
3. **信心**：发布新版本时，不再"祈祷式发布"

## 18.2 Vitest 基础 — 比 Jest 更快更现代

Vitest 是 Vite 原生的测试框架。如果你用 Vite 创建项目，用 Vitest 是最自然的选择 — 它和 Vite 共享配置，零额外配置就能跑起来。

### 安装

```bash
# 在你的 taskboard 项目目录下执行
npm install -D vitest @testing-library/react @testing-library/jest-dom @testing-library/user-event jsdom
```

- `vitest` — 测试运行器
- `@testing-library/react` — React 组件测试工具
- `@testing-library/jest-dom` — 扩展 DOM 断言（如 `toBeInTheDocument()`）
- `@testing-library/user-event` — 模拟用户操作（点击、输入等）
- `jsdom` — 在 Node.js 中模拟浏览器环境

### 配置

```js
// vite.config.js
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  test: {
    globals: true,        // 启用全局 API（describe, it, expect 等）
    environment: 'jsdom', // 模拟浏览器环境
    setupFiles: './src/test/setup.js', // 测试前的设置文件
    css: true,            // 启用 CSS 支持（Tailwind 等）
  },
});
```

```js
// src/test/setup.js
import '@testing-library/jest-dom';
// 这个文件在每个测试文件运行前执行
// 引入 jest-dom 来扩展 expect 的 DOM 断言能力
```

### 添加测试脚本

```json
// package.json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "test": "vitest",
    "test:ui": "vitest --ui",
    "test:run": "vitest run"
  }
}
```

### 写第一个测试

```jsx
// src/components/__tests__/ThemeToggle.test.jsx
import { render, screen, fireEvent } from '@testing-library/react';
import { describe, it, expect, beforeEach } from 'vitest';
import ThemeToggle from '../ThemeToggle';
import useThemeStore from '../../store/useThemeStore';

describe('ThemeToggle 组件', () => {
  // 每个测试前重置 store
  beforeEach(() => {
    useThemeStore.setState({ theme: 'light' });
  });

  it('应该正确渲染', () => {
    render(<ThemeToggle />);

    // 按钮应该存在
    const button = screen.getByRole('button');
    expect(button).toBeInTheDocument();
  });

  it('亮色模式下显示月亮图标（提示切换到暗色）', () => {
    render(<ThemeToggle />);

    const button = screen.getByRole('button');
    expect(button).toHaveAttribute('title', '切换到暗色模式');
  });

  it('点击后切换主题', () => {
    render(<ThemeToggle />);

    const button = screen.getByRole('button');

    // 初始是 light
    expect(useThemeStore.getState().theme).toBe('light');

    // 点击切换
    fireEvent.click(button);

    // 应该变成 dark
    expect(useThemeStore.getState().theme).toBe('dark');
  });
});
```

运行测试：

```bash
npm test
```

你会看到类似这样的输出：

```
✓ src/components/__tests__/ThemeToggle.test.jsx (3)
  ✓ ThemeToggle 组件 (3)
    ✓ 应该正确渲染
    ✓ 亮色模式下显示月亮图标（提示切换到暗色）
    ✓ 点击后切换主题

Test Files  1 passed (1)

```

> 💡 **Tip**：`npm test` 会启动 watch 模式，每次保存文件都会自动重新运行测试。这在开发时非常方便。运行 `npm run test:run` 则只运行一次（适合 CI/CD 环境）。

## 18.3 组件测试：React Testing Library

React Testing Library 的核心理念是：**像用户一样测试**。它鼓励你通过角色（role）、文本、标签等用户可见的方式来查找元素，而不是通过 CSS 选择器或组件内部状态。

### 测试渲染结果

```jsx
// src/components/__tests__/TaskCard.test.jsx
import { render, screen } from '@testing-library/react';
import { describe, it, expect, vi } from 'vitest';
import TaskCard from '../TaskCard';

// 模拟 store
vi.mock('../../store/useTaskStore', () => ({
  default: () => vi.fn(), // 模拟 deleteTask
}));

const mockTask = {
  id: '1',
  title: '学习 React',
  description: '完成本教程的所有章节',
  status: 'in-progress',
  priority: 'high',
  tags: ['学习', 'React'],
  createdAt: '2024-01-01T08:00:00Z',
  updatedAt: '2024-01-02T10:00:00Z',
};

describe('TaskCard 组件', () => {
  it('应该显示任务标题', () => {
    render(<TaskCard task={mockTask} onEdit={() => {}} />);

    // 通过文本内容查找元素
    expect(screen.getByText('学习 React')).toBeInTheDocument();
  });

  it('应该显示任务描述', () => {
    render(<TaskCard task={mockTask} onEdit={() => {}} />);

    expect(screen.getByText('完成本教程的所有章节')).toBeInTheDocument();
  });

  it('应该显示优先级标签', () => {
    render(<TaskCard task={mockTask} onEdit={() => {}} />);

    expect(screen.getByText('高')).toBeInTheDocument();
  });

  it('应该显示所有标签', () => {
    render(<TaskCard task={mockTask} onEdit={() => {}} />);

    expect(screen.getByText('学习')).toBeInTheDocument();
    expect(screen.getByText('React')).toBeInTheDocument();
  });

  it('没有描述时不显示描述区域', () => {
    const taskWithoutDesc = { ...mockTask, description: '' };
    render(<TaskCard task={taskWithoutDesc} onEdit={() => {}} />);

    expect(screen.queryByText('完成本教程的所有章节')).not.toBeInTheDocument();
  });
});
```

### 测试用户交互

```jsx
// src/components/__tests__/SearchBar.test.jsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, it, expect, beforeEach } from 'vitest';
import SearchBar from '../SearchBar';
import useTaskStore from '../../store/useTaskStore';

describe('SearchBar 组件', () => {
  beforeEach(() => {
    useTaskStore.setState({ searchQuery: '' });
  });

  it('应该渲染搜索输入框', () => {
    render(<SearchBar />);

    const input = screen.getByPlaceholderText('搜索任务...');
    expect(input).toBeInTheDocument();
  });

  it('输入文字后更新搜索状态', async () => {
    render(<SearchBar />);

    const input = screen.getByPlaceholderText('搜索任务...');
    const user = userEvent.setup();

    // 模拟用户输入
    await user.type(input, 'React');

    // 检查 store 状态是否更新
    expect(useTaskStore.getState().searchQuery).toBe('React');
  });

  it('输入后显示清除按钮', async () => {
    render(<SearchBar />);

    const input = screen.getByPlaceholderText('搜索任务...');
    const user = userEvent.setup();

    await user.type(input, 'test');

    // 清除按钮应该出现
    const clearButton = screen.getByText('✕');
    expect(clearButton).toBeInTheDocument();
  });

  it('点击清除按钮清空搜索', async () => {
    useTaskStore.setState({ searchQuery: 'React' });
    render(<SearchBar />);

    const user = userEvent.setup();
    const clearButton = screen.getByText('✕');

    await user.click(clearButton);

    expect(useTaskStore.getState().searchQuery).toBe('');
  });
});
```

### 测试异步操作

```jsx
// src/components/__tests__/TaskModal.test.jsx
import { render, screen, waitFor } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, it, expect, vi, beforeEach } from 'vitest';
import TaskModal from '../TaskModal';
import useTaskStore from '../../store/useTaskStore';

describe('TaskModal 组件', () => {
  const mockOnClose = vi.fn();

  beforeEach(() => {
    mockOnClose.mockClear();
    useTaskStore.setState({ tasks: [] });
  });

  it('新增模式下显示正确标题', () => {
    render(
      <TaskModal mode="add" task={null} defaultStatus="todo" onClose={mockOnClose} />
    );

    expect(screen.getByText('新增任务')).toBeInTheDocument();
  });

  it('编辑模式下显示正确标题', () => {
    const task = {
      id: '1',
      title: '测试任务',
      description: '测试描述',
      status: 'todo',
      priority: 'medium',
      tags: [],
    };

    render(
      <TaskModal mode="edit" task={task} defaultStatus="todo" onClose={mockOnClose} />
    );

    expect(screen.getByText('编辑任务')).toBeInTheDocument();
  });

  it('标题为空时不能提交', async () => {
    render(
      <TaskModal mode="add" task={null} defaultStatus="todo" onClose={mockOnClose} />
    );

    const user = userEvent.setup();
    const submitButton = screen.getByText('创建任务');

    await user.click(submitButton);

    // 不应该关闭对话框（因为标题为空）
    expect(mockOnClose).not.toHaveBeenCalled();
    // 任务数应该还是 0
    expect(useTaskStore.getState().tasks.length).toBe(0);
  });

  it('填写标题后可以创建任务', async () => {
    render(
      <TaskModal mode="add" task={null} defaultStatus="todo" onClose={mockOnClose} />
    );

    const user = userEvent.setup();

    // 填写标题
    const titleInput = screen.getByPlaceholderText('输入任务标题...');
    await user.type(titleInput, '我的新任务');

    // 填写描述
    const descInput = screen.getByPlaceholderText('描述这个任务...');
    await user.type(descInput, '这是一个测试任务');

    // 提交
    const submitButton = screen.getByText('创建任务');
    await user.click(submitButton);

    // 等待任务创建
    await waitFor(() => {
      const tasks = useTaskStore.getState().tasks;
      expect(tasks.length).toBe(1);
      expect(tasks[0].title).toBe('我的新任务');
    });

    // 对话框应该关闭
    expect(mockOnClose).toHaveBeenCalled();
  });

  it('按 ESC 键关闭对话框', async () => {
    render(
      <TaskModal mode="add" task={null} defaultStatus="todo" onClose={mockOnClose} />
    );

    const user = userEvent.setup();
    await user.keyboard('{Escape}');

    expect(mockOnClose).toHaveBeenCalled();
  });
});
```

### 常用的 Testing Library 查询方法

| 方法 | 用途 | 示例 |
|------|------|------|
| `getByRole` | 通过 ARIA 角色查找 | `getByRole('button')` |
| `getByText` | 通过文本内容查找 | `getByText('提交')` |
| `getByPlaceholderText` | 通过 placeholder 查找 | `getByPlaceholderText('搜索...')` |
| `getByLabelText` | 通过 label 查找 | `getByLabelText('用户名')` |
| `getByTestId` | 通过 data-testid 查找 | `getByTestId('my-element')` |
| `queryByText` | 同上，但找不到返回 null | `queryByText('不存在')` |
| `findByText` | 同上，但返回 Promise（异步） | `await findByText('加载中')` |

> 💡 **Tip**：优先使用 `getByRole`，因为它最接近用户的真实体验（屏幕阅读器就是通过 role 来理解页面的）。`getByTestId` 是最后手段，当其他方法都不方便时使用。

## 18.4 E2E 测试简介（Playwright）

单元测试和组件测试验证的是单个函数和组件。但用户不会一个一个组件地使用你的应用 — 他们会打开浏览器，点击按钮，填写表单，完成一整个流程。

**E2E（端到端）测试**就是模拟用户的完整操作流程。它打开一个真实的浏览器，像用户一样操作你的应用。

### 安装 Playwright

```bash
npm install -D @playwright/test
npx playwright install
```

### 编写 E2E 测试

```js
// e2e/taskboard.spec.js
import { test, expect } from '@playwright/test';

test.describe('TaskBoard 应用', () => {
  test.beforeEach(async ({ page }) => {
    // 每个测试前访问首页
    await page.goto('http://localhost:5173');
  });

  test('应该显示看板标题', async ({ page }) => {
    await expect(page.getByText('TaskBoard')).toBeVisible();
  });

  test('应该显示三列', async ({ page }) => {
    await expect(page.getByText('待办')).toBeVisible();
    await expect(page.getByText('进行中')).toBeVisible();
    await expect(page.getByText('已完成')).toBeVisible();
  });

  test('应该能新增任务', async ({ page }) => {
    // 点击"待办"列的添加按钮
    const addButtons = page.locator('button[title="新增任务"]');
    await addButtons.first().click();

    // 填写标题
    await page.getByPlaceholder('输入任务标题...').fill('E2E 测试任务');

    // 点击创建
    await page.getByText('创建任务').click();

    // 验证任务出现
    await expect(page.getByText('E2E 测试任务')).toBeVisible();
  });

  test('应该能搜索任务', async ({ page }) => {
    // 在搜索框输入
    await page.getByPlaceholder('搜索任务...').fill('React');

    // 验证搜索结果（只有包含"React"的任务显示）
    await expect(page.getByText('学习 React 基础')).toBeVisible();
  });

  test('应该能切换暗色模式', async ({ page }) => {
    // 检查初始是亮色模式
    const html = page.locator('html');
    await expect(html).not.toHaveClass(/dark/);

    // 点击主题切换按钮
    await page.getByRole('button', { name: /切换/ }).click();

    // 验证切换到了暗色模式
    await expect(html).toHaveClass(/dark/);
  });
});
```

### 运行 E2E 测试

```bash
# 确保开发服务器在运行
npm run dev

# 在另一个终端运行 E2E 测试
npx playwright test

# 带 UI 模式（可以看到浏览器操作过程）
npx playwright test --ui
```

> 💡 **Tip**：E2E 测试不需要覆盖所有场景（太慢了），主要用于测试**关键用户流程**，比如：用户注册流程、购物结账流程、核心业务操作等。

## 18.5 部署方案

终于到了最激动人心的环节 — 把你的应用部署上线！🚀

### 方案对比

| 平台 | 优点 | 缺点 | 适合场景 |
|------|------|------|---------|
| **Vercel** | 一键部署、免费额度大、自动 HTTPS | 国内访问较慢 | 个人项目、Demo 展示 |
| **Netlify** | 类似 Vercel、功能丰富 | 国内访问较慢 | 个人项目、博客 |
| **GitHub Pages** | 免费、和 GitHub 集成好 | 只支持静态站点 | 开源项目文档 |
| **自建服务器** | 完全控制 | 需要运维知识 | 生产环境、企业级 |

---

### 重点：Vercel 部署（推荐！）

Vercel 是 Next.js 的母公司开发的部署平台，对 React 应用支持极好。免费额度对个人项目完全够用。

#### 步骤 1：将代码推送到 GitHub

```bash
# 初始化 git 仓库
git init
git add .
git commit -m "feat: 完成 TaskBoard 任务看板应用"

# 在 GitHub 上创建一个新仓库（手动操作）
# 然后关联远程仓库
git remote add origin https://github.com/你的用户名/taskboard.git
git branch -M main
git push -u origin main
```

#### 步骤 2：在 Vercel 上部署

1. 访问 [vercel.com](https://vercel.com)，用 GitHub 账号登录
2. 点击 "Add New Project"
3. 选择你的 `taskboard` 仓库
4. Vercel 会自动检测到 Vite 项目，自动填充构建命令：
   - Framework Preset: `Vite`
   - Build Command: `npm run build`
   - Output Directory: `dist`
5. 点击 "Deploy"
6. 等待约 1 分钟...
7. 🎉 **部署成功！** 你会得到一个类似 `https://taskboard-xxx.vercel.app` 的 URL

每次你 push 代码到 GitHub，Vercel 都会**自动重新部署**！这就是 CI/CD 的魅力。

> 💡 **Tip**：Vercel 还支持自定义域名、环境变量、预览部署（每个 PR 生成独立的预览链接）等功能，非常适合团队协作。

---

### Netlify 部署

和 Vercel 类似的流程：

1. 访问 [netlify.com](https://netlify.com)，用 GitHub 账号登录
2. 点击 "Add new site" → "Import an existing project"
3. 选择 GitHub，授权并选择你的仓库
4. 构建设置：
   - Build command: `npm run build`
   - Publish directory: `dist`
5. 点击 "Deploy site"

### 自建服务器部署（Nginx）

如果你有云服务器，可以手动部署：

```bash
# 1. 构建生产版本
npm run build

# 2. 将 dist 目录上传到服务器
scp -r dist/* user@your-server:/var/www/taskboard/

# 3. 在服务器上配置 Nginx
```

```nginx
# /etc/nginx/sites-available/taskboard
server {
    listen 80;
    server_name your-domain.com;

    root /var/www/taskboard;
    index index.html;

    # SPA 路由支持 — 所有路径都返回 index.html
    # 让 React Router 处理客户端路由
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # Gzip 压缩
    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1000;
}
```

```bash
# 4. 启用配置并重载 Nginx
sudo ln -s /etc/nginx/sites-available/taskboard /etc/nginx/sites-enabled/
sudo nginx -t        # 测试配置
sudo systemctl reload nginx
```

> ⚠️ **Warning**：SPA 应用的 Nginx 配置中，`try_files $uri $uri/ /index.html;` 这一行非常重要！没有它，用户直接访问 `/dashboard` 等路径会得到 404 错误。因为 React Router 是在客户端处理路由的，服务器上没有对应的文件。

## 18.6 CI/CD 基础：GitHub Actions 自动部署

CI/CD（持续集成/持续部署）的意思是：每次你推送代码，自动运行测试、构建、部署。你再也不用手动跑 `npm run build` 然后上传了。

### 创建 GitHub Actions 工作流

```yaml
# .github/workflows/deploy.yml
name: Deploy to Vercel

on:
  push:
    branches: [main]    # 推送到 main 分支时触发
  pull_request:
    branches: [main]    # 创建 PR 时也触发（用于预览）

jobs:
  # 第一步：运行测试
  test:
    runs-on: ubuntu-latest
    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 安装 Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: 安装依赖
        run: npm ci  # ci 比 install 更快、更确定性

      - name: 运行测试
        run: npm run test:run

  # 第二步：构建和部署
  deploy:
    needs: test       # 测试通过后才能部署
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'  # 只有 main 分支才部署
    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 安装 Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: 安装依赖
        run: npm ci

      - name: 构建
        run: npm run build

      - name: 部署到 Vercel
        uses: amondnet/vercel-action@v25
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.ORG_ID }}
          vercel-project-id: ${{ secrets.PROJECT_ID }}
          vercel-args: '--prod'
```

### 流程图

```
你推送代码到 GitHub
    ↓
GitHub Actions 自动触发
    ↓
Job 1: 安装依赖 → 运行测试
    ↓
测试通过？
├── 否 → 部署取消，你收到通知去修 bug
└── 是 → Job 2: 构建 → 部署到 Vercel
          ↓
        部署成功，网站更新 ✅
```

> 💡 **Tip**：即使你不用 Vercel，也可以用 GitHub Actions 自动部署到任何平台。比如自动 SSH 到你的服务器执行 `git pull && npm run build`。

## 18.7 SEO 与 SSR 简介

我们构建的 TaskBoard 是一个**SPA（单页应用）**。SPA 有一个"天生缺陷"：

- 服务器返回的 HTML 只有一个空的 `<div id="root">`
- 所有内容都是 JavaScript 动态渲染的
- 搜索引擎的爬虫可能无法执行 JavaScript，导致**搜不到你的网站**

### 什么时候需要考虑 SEO？

| 应用类型 | 需要 SEO 吗？ | 推荐方案 |
|---------|-------------|---------|
| 内部管理系统 | ❌ 不需要 | SPA 就够了 |
| 个人博客/作品集 | ✅ 需要 | Next.js (SSG) |
| 电商网站 | ✅ 非常重要 | Next.js (SSR) |
| 内容型网站 | ✅ 非常重要 | Next.js / Astro |

### 什么是 SSR？

**SSR（Server-Side Rendering，服务端渲染）**：服务器在收到请求时，直接生成完整的 HTML 返回给浏览器。用户立刻就能看到内容，搜索引擎也能正常索引。

**Next.js** 是 React 生态中最流行的 SSR 框架，它提供了：

- SSR — 服务端渲染
- SSG — 静态站点生成
- ISR — 增量静态再生成
- API Routes — 后端 API
- 文件路由 — 无需手动配置 React Router

> 💡 **Tip**：如果你的项目是面向用户的（电商、博客、企业官网等），强烈建议使用 Next.js。如果是内部管理工具或桌面应用，SPA 就足够了。
