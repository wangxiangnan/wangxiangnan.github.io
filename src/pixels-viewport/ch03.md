# 第3章 DPR：两个世界之间的汇率

> **本章回答的问题**：DPR 这个值是谁定的？为什么 iPhone 是 3、有的安卓是 2.75？

## 3.1 定义与直觉

**DPR（Device Pixel Ratio，设备像素比）**= 在 1 倍缩放下，每个 CSS 像素对应多少个物理像素。

```
DPR = 物理像素 ÷ CSS 像素
CSS 像素 = 物理像素 ÷ DPR        （互为换算）
```

直觉理解：DPR 是物理世界和逻辑世界之间的"汇率"。汇率是 3，意味着逻辑世界里的 1 元（CSS px）兑换 3 元硬币（物理像素）。

## 3.2 谁决定 DPR

DPR **由设备厂商在操作系统层面决定，是软件定义的映射值**，不是硬件直接测出来的。决定过程分三步：

1. 硬件确定物理分辨率和 PPI（如 1320×2868、460 PPI）。
2. 厂商拿 PPI 除以**基准参考密度**，取一个整数作为 DPR：460 ÷ 160 ≈ 2.9 → 定为 3。
3. 该值写入系统，浏览器启动时从 OS 读取，暴露为 `window.devicePixelRatio`。

**为什么取整**：一是让 1 个 CSS 像素在所有设备上物理尺寸相近（约 1/160 英寸）；二是整数倍能保证物理像素映射不出"半像素"，渲染边缘锐利。非整数倍率（如 3.5x）在少数安卓机型上存在，但会引入插值损失。

**历史延续性**：Apple 的基准是初代 iPhone 的实际密度 163 PPI，定义为 1x；iPhone 4 密度翻倍到 326，DPR 顺势定为 2（@2x）；16 Pro Max 的 460 ÷ 163 ≈ 2.8，定为 @3x。每一代都是在上代基础上平滑扩展，而不是重新选值。

## 3.3 三大平台的基准对比

"除以基准密度取整"这个公式是共通的，但各平台的基准值不同：

| 平台 | 基准密度 | 逻辑单位 | 1 逻辑单位的物理意图 |
| ------ | ---------- | ---------- | ---------------------- |
| CSS / Windows | 96 PPI | CSS px / 系统 DPI 点 | 1/96 英寸 ≈ 0.265mm |
| Android | 160 PPI | dp | 1/160 英寸 ≈ 0.159mm |
| Apple | 163 PPI | pt | 1/163 英寸 ≈ 0.156mm |

三套基准殊途同归——目的都是给开发者一个不随屏幕密度变化的稳定逻辑单位。数值不同纯属历史偶然：96 继承自桌面显示器时代（Windows 选 96 让 12pt 字号恰好等于 16px；Apple 当年选 72 是为了对齐印刷的 72pt/英寸），160 由第一代 Android 手机的实际屏幕决定，163 则是初代 iPhone 的实测值。

**跨平台换算**：1dp = 96/160 = **0.6 CSS px**。同一设计稿，Android 上标注 100dp 相当于 Web 上写 60px——这是设计师切图时最常见的换算坑。

## 3.4 有效 DPR：用户也在参与定价

厂商定的是**基准 DPR**，用户操作可以在此基础上叠加：

```
有效 DPR = 厂商基准 × 系统缩放 × 浏览器缩放
```

- 桌面 Windows：系统缩放 150% + 浏览器缩放 100% → `devicePixelRatio = 1.5`；再按 Ctrl+加号到 120% → 1.8。
- 手机双指捏合：改变的是视觉呈现（见[第 4 章](/pixels-viewport/ch04)视觉视口），对 DPR 读数的影响因浏览器而异——Safari 的 DPR 恒定不随缩放变，Chrome 会变。

这就是为什么网页检测用户缩放（如"当前浏览器缩放比例"功能）可以用 `devicePixelRatio` 的变化来推算。

## 3.5 小结

- DPR 是厂商定义的汇率：PPI ÷ 基准密度，取整。
- 三大平台基准 96 / 160 / 163，服务同一个抽象目标。
- 有效 DPR = 基准 × 系统缩放 × 浏览器缩放，用户行为会改变它。

## 3.6 练习题

1. 某 Android 手机物理分辨率 1080×2340，DPR 为 3，求 CSS 像素尺寸。
2. Windows 系统缩放 125%，用户把浏览器缩放调到 80%，此时 `devicePixelRatio` 是多少？
3. 为什么厂商倾向于把 DPR 取整，而不是用精确的 2.9？

## 3.7 参考答案

> 1. 宽 1080÷3 = 360，高 2340÷3 = 780，CSS 坐标系 360×780。
> 2. 有效 DPR = 1.25 × 0.8 = 1.0，恰好回到 1 倍。
> 3. 整数倍保证物理像素映射不出现半像素插值，边缘渲染锐利；同时让 1 个 CSS 像素的物理尺寸在不同设备间保持相近。
