# 第18章：性能优化与高级技巧

> 一个程序员最沮丧的时刻，不是代码报错了，而是**编辑器卡了**。

VSCode 是一个基于 Electron 的应用——这意味着它本质上是一个跑在 Chromium 上的 Web 应用。这给了它跨平台和插件灵活性的优势，但也带来了性能挑战。本章将教你如何给 VSCode 做一次全面的"性能体检"，并掌握那些能让你效率翻倍的高级技巧。

## VSCode 性能杀手排查

### 诊断工具

VSCode 内置了多个性能诊断工具：

```bash
# 方法1：启动性能分析
# 命令面板 → Developer: Startup Performance
# 显示启动过程中每个阶段的耗时

# 方法2：运行时性能分析
# 命令面板 → Developer: Toggle Performance Profiler
# 录制一段时间的操作，分析 CPU 使用

# 方法3：扩展影响分析
# 命令面板 → Developer: Show Running Extensions
# 显示每个扩展的激活时间、消息处理时间
```

### 常见性能杀手

| 杀手 | 症状 | 解决方案 |
| ------ | ------ | ---------- |
| **过多插件** | 启动慢、内存占用高 | 禁用/卸载不常用的插件 |
| **大文件** | 编辑器卡顿、滚动不流畅 | 配置大文件处理策略 |
| **文件监听过多** | CPU 飙高、风扇狂转 | 配置 watcherExclude |
| **搜索索引过大** | 搜索缓慢 | 配置 search.exclude |
| **Minimap 渲染** | 大文件时明显卡顿 | 关闭或限制 Minimap |
| **括号对着色** | 深层嵌套时代码闪烁 | 使用内置方案替代第三方插件 |

### 检查内存使用

```bash
# 命令面板 → Developer: Toggle Developer Tools
# 在 Console 中输入：
performance.memory
# 查看 JS Heap 使用情况
```

## 文件排除策略：三管齐下

### files.exclude —— 文件树中隐藏

控制哪些文件/文件夹在侧边栏的文件树中不可见：

```json
{
  "files.exclude": {
    "**/.git": true,
    "**/.DS_Store": true,
    "**/node_modules": true,
    "**/.cache": true,
    "**/dist": true,
    "**/build": true,
    "**/.next": true,
    "**/.nuxt": true,
    "**/__pycache__": true,
    "**/*.pyc": true,
    "**/.vscode": false,
    "**/coverage": true,
    "**/.turbo": true,
    "**/.parcel-cache": true
  }
}
```

### search.exclude —— 搜索时跳过

控制全局搜索时忽略的目录：

```json
{
  "search.exclude": {
    "**/node_modules": true,
    "**/dist": true,
    "**/build": true,
    "**/coverage": true,
    "**/.git": true,
    "**/package-lock.json": true,
    "**/yarn.lock": true,
    "**/pnpm-lock.yaml": true,
    "**/.cache": true,
    "**/tmp": true,
    "**/*.min.js": true,
    "**/*.min.css": true,
    "**/*.map": true
  }
}
```

### files.watcherExclude —— 文件监听排除

**这是最重要的性能配置之一**。文件监听器会监控文件变化，如果监听目录太大（如 `node_modules`），会消耗大量 CPU：

```json
{
  "files.watcherExclude": {
    "**/.git/objects/**": true,
    "**/.git/subtree-cache/**": true,
    "**/node_modules/**": true,
    "**/dist/**": true,
    "**/build/**": true,
    "**/.next/**": true,
    "**/coverage/**": true,
    "**/.cache/**": true,
    "**/tmp/**": true,
    "**/.turbo/**": true
  }
}
```

### 大文件处理

```json
{
  // 大文件阈值（超过此大小的文件会禁用某些功能）
  "files.maxMemoryForLargeFilesMB": 4096,
  
  // 对大文件关闭 Minimap
  "editor.minimap.enabled": true,
  
  // 关闭大文件的括号对着色（性能敏感）
  // 注意：这是全局设置，VSCode 会自动对大文件降级
  
  // 限制自动保存的文件大小
  "files.autoSave": "afterDelay",
  "files.autoSaveDelay": 2000
}
```

## 插件禁用策略：精准控制

### 按工作区禁用

不是所有插件在所有项目中都有用。在特定工作区禁用不需要的插件：

1. 打开插件面板
2. 找到目标插件
3. 点击齿轮 → `Disable (Workspace)`

**推荐策略：**

```
全局启用的插件（通用工具）：
  ✅ GitLens
  ✅ Error Lens
  ✅ Peacock
  ✅ Todo Tree
  ✅ Settings Sync

按工作区启用的插件：
  📁 React 项目 → ES7 React Snippets, Tailwind CSS IntelliSense
  📁 Python 项目 → Python, Pylance, Jupyter
  📁 Go 项目 → Go
  📁 Rust 项目 → rust-analyzer
  📁 Java 项目 → Extension Pack for Java
```

### 配置文件关联禁用

某些插件可以设置为只在特定文件类型激活：

```json
{
  // 在特定语言的文件中才激活 Emmet
  "emmet.includeLanguages": {
    "javascript": "javascriptreact",
    "typescriptreact": "html",
    "vue-html": "html"
  }
}
```

### 使用 Profile（配置文件）

VSCode 支持多 Profile，每个 Profile 可以有独立的插件集合：

1. `Ctrl+Shift+P` → `Profiles: Create Profile`
2. 创建不同场景的 Profile：
   - **Frontend Dev**：启用前端相关插件
   - **Backend Dev**：启用后端相关插件
   - **Writing**：启用 Markdown 和写作相关插件
   - **Minimal**：只保留核心插件

```bash
# 切换 Profile
# 左下角齿轮 → Profiles → 选择目标 Profile
# 或者 Ctrl+Shift+P → Profiles: Switch Profile
```

## 延迟加载和工作区信任

### 工作区信任（Workspace Trust）

当你打开一个不受信任的项目时，VSCode 会限制某些插件的运行——这既是安全特性，也能提升性能：

```json
{
  "security.workspace.trust.enabled": true,
  "security.workspace.trust.startupPrompt": "always",
  "security.workspace.trust.untrustedFiles": "prompt"
}
```

### 插件的延迟加载

大多数现代插件都支持延迟加载（只在需要时才激活）。但一些老旧插件可能不支持。检查 `Developer: Show Running Extensions` 看哪些插件在启动时就被加载了。

## 快捷键系统深度定制

### keybindings.json

按 `Ctrl+K Ctrl+S`（`⌘+K ⌘+S`）打开快捷键编辑器，或按 `Ctrl+Shift+P` 搜索 `Preferences: Open Keyboard Shortcuts (JSON)` 直接编辑 JSON。

### 实用快捷键定制示例

```json
[
  // 快速切换终端
  {
    "key": "ctrl+`",
    "command": "workbench.action.terminal.toggleTerminal"
  },
  
  // 用 Ctrl+1-9 切换标签页
  {
    "key": "ctrl+1",
    "command": "workbench.action.openEditorAtIndex1"
  },
  {
    "key": "ctrl+2",
    "command": "workbench.action.openEditorAtIndex2"
  },
  
  // 快速复制当前行到下方（比 Alt+Shift+↓ 更方便）
  {
    "key": "ctrl+shift+d",
    "command": "editor.action.copyLinesDownAction",
    "when": "editorTextFocus"
  },
  
  // 快速打开最近的文件
  {
    "key": "ctrl+shift+r",
    "command": "workbench.action.openRecent"
  },
  
  // 快速格式化选中区域
  {
    "key": "ctrl+k f",
    "command": "editor.action.formatSelection",
    "when": "editorHasDocumentSelectionFormattingProvider && editorTextFocus"
  },
  
  // 在终端中运行当前文件
  {
    "key": "ctrl+shift+enter",
    "command": "workbench.action.terminal.sendSequence",
    "args": {
      "text": "node '${file}'\u000D"
    },
    "when": "editorTextFocus && editorLangId == 'javascript'"
  },
  
  // 快速切换侧边栏
  {
    "key": "ctrl+b",
    "command": "workbench.action.toggleSidebarVisibility"
  },
  
  // 关闭所有编辑器（保留工作区）
  {
    "key": "ctrl+k ctrl+w",
    "command": "workbench.action.closeAllEditors"
  },
  
  // 快速重构 - 提取函数
  {
    "key": "ctrl+shift+e",
    "command": "editor.action.codeAction",
    "args": {
      "kind": "refactor.extract.function"
    },
    "when": "editorTextFocus"
  },
  
  // 在资源管理器中显示当前文件
  {
    "key": "ctrl+shift+f1",
    "command": "workbench.files.action.showActiveFileInExplorer"
  },
  
  // 分割编辑器并移动文件
  {
    "key": "ctrl+k \\",
    "command": "workbench.action.splitEditorRight"
  }
]
```

### when 子句上下文

`when` 子句决定了快捷键在什么条件下生效。常用的上下文变量：

```
editorTextFocus          → 编辑器有焦点时
editorHasSelection       → 有文本选中时
editorLangId == 'json'   → 当前文件是 JSON 时
terminalFocus            → 终端有焦点时
sideBarFocus             → 侧边栏有焦点时
panelFocus               → 面板有焦点时
explorerViewletFocus     → 资源管理器有焦点时
inSearchEditor           → 在搜索编辑器中
suggestWidgetVisible     → 建议列表可见时
findWidgetVisible        → 查找面板可见时
```

**组合使用示例：**

```json
{
  "key": "ctrl+enter",
  "command": "editor.action.insertLineAfter",
  "when": "editorTextFocus && !suggestWidgetVisible && !findWidgetVisible"
}
```

### 查看所有快捷键冲突

在快捷键编辑器中，点击右上角的 `{}` 图标可以查看 keybindings.json 的原始内容。搜索同一个 key 可以发现冲突的绑定。

## 命令面板高级用法

### 快速命令搜索

命令面板支持模糊搜索，不需要记住完整的命令名：

```
"gp"  → "Git: Push"
"ts"  → "TypeScript: Restart TS Server"
"tr"  → "Terminal: Create New Terminal"
"fs"  → "File: Save All"
"rp"  → "Preferences: Open Remote Settings (JSON)"
```

### 自定义命令（通过扩展 API）

虽然不能直接在 settings.json 中创建自定义命令，但你可以使用一些扩展来实现：

**Multi Command 扩展（`ryuta46.multi-command`）：**

```json
{
  "multiCommand.commands": [
    {
      "command": "multiCommand.saveAndFormatAndLint",
      "sequence": [
        "editor.action.formatDocument",
        "editor.action.organizeImports",
        "eslint.executeAutofix",
        "workbench.action.files.save"
      ]
    },
    {
      "command": "multiCommand.newReactComponent",
      "sequence": [
        "explorer.newFile",
        {
          "command": "editor.action.insertSnippet",
          "args": {
            "snippet": "rfc"
          }
        }
      ]
    }
  ]
}
```

然后在 keybindings.json 中绑定快捷键：

```json
{
  "key": "ctrl+shift+s",
  "command": "multiCommand.saveAndFormatAndLint"
}
```

## 实战：做一次 VSCode 性能体检

### 步骤 1：启动性能分析

```bash
# 关闭 VSCode，然后从终端以性能模式启动：
code --prof-startup
# 或者
code --status  # 查看当前实例的状态信息
```

### 步骤 2：检查扩展负载

1. `Ctrl+Shift+P` → `Developer: Show Running Extensions`
2. 按 `Activation Time` 排序
3. 记录激活时间超过 200ms 的扩展

### 步骤 3：检查文件监听

1. `Ctrl+Shift+P` → `Developer: Watcher Exclude`（查看当前排除规则）
2. 确认 `node_modules`、`.git`、`dist` 等大目录已被排除

### 步骤 4：优化配置

根据诊断结果，在 `settings.json` 中添加优化配置：

```json
{
  // 性能优化配置
  "files.watcherExclude": {
    "**/.git/objects/**": true,
    "**/.git/subtree-cache/**": true,
    "**/node_modules/**": true,
    "**/dist/**": true,
    "**/.next/**": true,
    "**/coverage/**": true
  },
  "search.exclude": {
    "**/node_modules": true,
    "**/dist": true,
    "**/build": true,
    "**/.cache": true,
    "**/coverage": true,
    "**/package-lock.json": true
  },
  "files.exclude": {
    "**/.git": true,
    "**/.DS_Store": true,
    "**/node_modules": true,
    "**/.cache": true
  },
  
  // 降低编辑器渲染负担
  "editor.minimap.enabled": true,
  "editor.minimap.renderCharacters": false,
  "editor.renderWhitespace": "selection",
  "editor.renderLineHighlight": "line",
  "editor.matchBrackets": "near",
  "editor.occurrencesHighlight": "off",
  
  // 减少不必要的动画
  "workbench.list.smoothScrolling": false,
  "editor.cursorSmoothCaretAnimation": "off",
  "editor.smoothScrolling": false,
  
  // 延迟文件保存（减少磁盘 IO）
  "files.autoSave": "afterDelay",
  "files.autoSaveDelay": 2000,
  
  // 减少 Git 自动刷新频率
  "git.autorefresh": true,
  "git.autofetch": false
}
```

### 步骤 5：清理不用的插件

```bash
# 列出所有已安装的扩展
code --list-extensions

# 卸载不需要的扩展
code --uninstall-extension extension-id
```

### 步骤 6：定期维护

```
📅 每月做一次：
□ 检查 Running Extensions 中的耗时大户
□ 清理不再使用的扩展
□ 检查 settings.json 中是否有冗余配置

📅 每季度做一次：

□ 检查 VSCode 更新日志中的新特性

```

## 教程总结：从"会用"到"精通"的成长路径

恭喜你读到这里！让我们回顾一下这段进阶之旅的路线图：


**最后几条建议：**

1. **不要一次性应用所有配置。** 每次只尝试一两个新特性，真正用起来后再继续。
2. **保持 settings.json 的版本控制。** 把它放入 dotfiles 仓库，这是你最有价值的配置文件之一。
3. **关注 VSCode 的更新日志。** 每个月 VSCode 都会推出新功能，很多之前需要插件实现的功能现在已内置。
4. **分享你的配置。** 在团队中推广最佳实践，一个人的精通可以提升整个团队的效率。
5. **工具是为效率服务的。** 不要在定制上花太多时间而忘了写代码。最好的配置是那些你已经忘记它存在的配置——因为它们已经变成了你的肌肉记忆。
