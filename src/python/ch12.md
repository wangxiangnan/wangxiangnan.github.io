# 第 12 章 异常处理

开车上路，你不可能保证一路畅通——可能遇到红灯、堵车、爆胎、甚至下暴雨。好的司机不会假装这些问题不存在，而是提前准备好应对方案：红灯就停车等待，爆胎就换备胎，暴雨就减速慢行。

程序运行时也一样。用户可能输入非法数据，文件可能不存在，网络可能断开，内存可能不够用。这些意外情况在 Python 中叫做**异常**（exception）。这一章，你将学会如何"优雅地处理意外"，让程序不会因为一点小问题就崩溃。

## 12.1 什么是异常

当 Python 遇到无法执行的代码时，会抛出一个异常。如果没有人处理它，程序就会终止并打印错误信息（traceback）。

```python
# 除以零
# print(1 / 0)  # ZeroDivisionError: division by zero

# 访问不存在的键
# d = {"a": 1}
# print(d["b"])  # KeyError: 'b'

# 访问不存在的变量
# print(xyz)  # NameError: name 'xyz' is not defined

# 类型错误
# print("hello" + 5)  # TypeError: can only concatenate str to str

# 文件不存在
# open("no_such_file.txt")  # FileNotFoundError
```

每次看到 `XXXError`，那就是一个异常。Python 有几十种内置异常类型，它们按照层级组织在一起。

## 12.2 异常层次结构

Python 的所有异常都继承自 `BaseException`，大多数常见异常继承自 `Exception`：

```
BaseException
 +-- SystemExit           # sys.exit() 触发
 +-- KeyboardInterrupt    # Ctrl+C 触发
 +-- Exception            # 大多数异常的基类
      +-- ArithmeticError
      |    +-- ZeroDivisionError
      |    +-- OverflowError
      +-- LookupError
      |    +-- IndexError
      |    +-- KeyError
      +-- TypeError
      +-- ValueError
      +-- FileNotFoundError
      +-- IOError
      +-- ImportError
      +-- AttributeError
      +-- NameError
      +-- RuntimeError
      +-- StopIteration
      ...（还有很多）
```

了解层次结构有什么用？因为你可以捕获父类异常来同时处理多种子类异常。比如捕获 `LookupError` 就能同时处理 `IndexError` 和 `KeyError`。

## 12.3 try/except：异常处理的核心

`try/except` 是最基本的异常处理方式。把"可能出问题"的代码放在 `try` 块里，把"出了问题怎么办"放在 `except` 块里。

```python
# 基本用法
try:
    result = 10 / 0
except ZeroDivisionError:
    print("除数不能为零！")
# 输出：除数不能为零！

# 捕获异常对象，获取详细信息
try:
    numbers = [1, 2, 3]
    print(numbers[10])
except IndexError as e:
    print(f"索引越界：{e}")
# 输出：索引越界：list index out of range

# 捕获多种异常
def safe_divide(a, b):
    try:
        result = int(a) / int(b)
        return result
    except ValueError:
        print("输入必须是数字")
    except ZeroDivisionError:
        print("除数不能为零")
    except Exception as e:
        print(f"未知错误：{e}")

safe_divide("10", "3")    # 返回 3.333...
safe_divide("abc", "3")   # 输出：输入必须是数字
safe_divide("10", "0")    # 输出：除数不能为零
safe_divide("10", "abc")  # 输出：输入必须是数字
```

### 12.3.1 捕获顺序很重要

如果多个 `except` 块之间有父子关系，**子类必须写在前面**：

```python
# 错误写法：父类在前，子类永远不会被匹配
# try:
#     1 / 0
# except Exception:       # 这里会先匹配到
#     print("通用错误")
# except ZeroDivisionError:  # 永远不会执行！
#     print("除以零")

# 正确写法：子类在前
try:
    1 / 0
except ZeroDivisionError:  # 先匹配子类
    print("除以零")
except Exception:          # 兜底
    print("其他错误")
```

## 12.4 try/except/else/finally

完整的异常处理结构包含四个部分：

```python
def read_config(filepath):
    try:
        # try：可能出错的代码
        with open(filepath, "r", encoding="utf-8") as f:
            content = f.read()
    except FileNotFoundError:
        # except：出错时的处理
        print(f"配置文件 {filepath} 不存在")
        return {}
    except PermissionError:
        print(f"没有权限读取 {filepath}")
        return {}
    else:
        # else：没有出错时执行（可选）
        print("配置文件读取成功")
        return content
    finally:
        # finally：无论如何都会执行（可选）
        print("read_config 执行完毕")
```

四个部分的执行逻辑：

1. `try` 块正常执行完毕 → 执行 `else` → 执行 `finally`
2. `try` 块抛出异常 → 匹配的 `except` 处理 → 执行 `finally`（不执行 `else`）
3. `try` 块抛出异常但没有匹配的 `except` → 执行 `finally` → 异常继续向上传播

```python
# else 的用途：把"成功后"的逻辑与 try 分开，让 try 只包含可能出错的代码
try:
    value = int("42")
except ValueError:
    print("转换失败")
else:
    # 只有转换成功才会到这里
    # 如果这里出错，不会被上面的 except 捕获（这正是我们想要的）
    print(f"转换成功：{value}")
    result = value * 2
    print(f"计算结果：{result}")

# finally 的用途：清理资源
try:
    f = open("data.txt", "r")
    content = f.read()
except FileNotFoundError:
    print("文件不存在")
finally:
    # 不管有没有异常，都要关闭文件
    # （当然，用 with 更好，这里只是演示 finally）
    if 'f' in dir() and not f.closed:
        f.close()
        print("文件已关闭")
```

## 12.5 抛出异常：raise

有时候你需要**主动**抛出异常——当检测到非法输入或不符合预期的状态时。

```python
def set_age(age):
    """设置年龄，必须是 0-150 的整数"""
    if not isinstance(age, int):
        raise TypeError(f"年龄必须是整数，收到 {type(age).__name__}")
    if age < 0 or age > 150:
        raise ValueError(f"年龄必须在 0-150 之间，收到 {age}")
    return age

print(set_age(25))    # 25
# set_age(-5)         # ValueError: 年龄必须在 0-150 之间，收到 -5
# set_age("abc")      # TypeError: 年龄必须是整数，收到 str
```

### 12.5.1 重新抛出异常

在 `except` 块中，你可以用裸的 `raise` 重新抛出当前异常（通常在记录日志后）：

```python
try:
    result = 10 / 0
except ZeroDivisionError:
    print("记录日志：发生了除零错误")
    raise  # 重新抛出异常，让上层处理
```

### 12.5.2 raise ... from ... 异常链

当你捕获一个异常后想抛出另一个更合适的异常时，用 `from` 保留原始异常信息：

```python
class ConfigError(Exception):
    """配置文件错误"""
    pass

def load_config(filepath):
    try:
        with open(filepath, "r", encoding="utf-8") as f:
            return f.read()
    except FileNotFoundError as e:
        # 抛出自定义异常，同时保留原始异常信息
        raise ConfigError(f"无法加载配置文件：{filepath}") from e

# 使用时会看到完整的异常链
# try:
#     load_config("missing.json")
# except ConfigError as e:
#     print(e)
#     print(f"原因：{e.__cause__}")
```

## 12.6 自定义异常

当内置异常不能准确描述你的错误时，可以创建自定义异常。做法很简单：继承 `Exception` 类。

```python
# 定义异常类
class InsufficientFundsError(Exception):
    """余额不足异常"""
    def __init__(self, balance, amount):
        self.balance = balance
        self.amount = amount
        super().__init__(f"余额不足：当前余额 {balance}，需要 {amount}")

class InvalidAccountError(Exception):
    """无效账户异常"""
    pass

# 在业务代码中使用
class BankAccount:
    def __init__(self, owner, balance=0):
        if balance < 0:
            raise ValueError("初始余额不能为负数")
        self.owner = owner
        self.balance = balance

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("取款金额必须大于零")
        if amount > self.balance:
            raise InsufficientFundsError(self.balance, amount)
        self.balance -= amount
        return self.balance

# 使用
account = BankAccount("小明", 1000)
print(f"余额：{account.withdraw(300)}")  # 余额：700

try:
    account.withdraw(2000)
except InsufficientFundsError as e:
    print(f"取款失败！{e}")
    print(f"差额：{e.amount - e.balance}")  # 差额：1300
```

## 12.8 EAFP vs LBYL

这是 Python 社区一个重要的编程哲学话题：

- **LBYL**（Look Before You Leap）：先检查再做——"三思而后行"
- **EAFP**（Easier to Ask Forgiveness than Permission）：先做再说，出了问题再处理——"先斩后奏"

```python
# LBYL 风格：先检查
def get_value_lbyl(d, key):
    if key in d:
        return d[key]
    else:
        return "默认值"

# EAFP 风格：先尝试，出错再处理
def get_value_eafp(d, key):
    try:
        return d[key]
    except KeyError:
        return "默认值"
```

**Python 更推崇 EAFP 风格**。原因：

1. 代码更简洁，意图更清晰
2. 避免"检查时存在但使用时不存在"的竞态条件
3. 在大多数情况下性能更好（正常路径没有额外检查开销）

但 EAFP 不是万能的。以下情况 LBYL 更合适：

```python
# 用户输入验证：先检查再处理（LBYL 更好）
age = input("请输入年龄：")
if not age.isdigit():
    print("请输入数字")
elif int(age) < 0:
    print("年龄不能为负数")
else:
    process(int(age))

# 文件系统操作：有时 EAFP 更好
try:
    with open("config.json", "r", encoding="utf-8") as f:
        config = json.load(f)
except FileNotFoundError:
    config = {}  # 使用默认配置
```

### 12.8.1 不要吞掉所有异常

```python
# 极差的写法：吞掉所有异常，出了问题都不知道
try:
    do_something()
except:  # 裸 except，连 KeyboardInterrupt 都捕获了
    pass  # 什么都不做，假装没问题

# 稍好但仍然不推荐：捕获太宽
try:
    do_something()
except Exception:
    pass  # 吞掉所有 Exception，调试时找不到 bug

# 好的写法：只捕获预期内的异常
try:
    do_something()
except SpecificError as e:
    logger.error(f"具体错误：{e}")
    handle_error()
```

## 12.9 异常处理实战

### 12.9.1 重试机制

```python
import time
import random

def unreliable_api_call():
    """模拟不稳定的 API 调用"""
    if random.random() < 0.6:  # 60% 概率失败
        raise ConnectionError("网络连接失败")
    return {"status": "ok", "data": "重要数据"}

def retry(func, max_retries=3, delay=1):
    """重试装饰器"""
    for attempt in range(1, max_retries + 1):
        try:
            result = func()
            print(f"第 {attempt} 次尝试成功")
            return result
        except ConnectionError as e:
            print(f"第 {attempt} 次尝试失败：{e}")
            if attempt == max_retries:
                print("已达最大重试次数，放弃")
                raise
            time.sleep(delay)

# result = retry(unreliable_api_call)
```

### 12.9.2 安全的类型转换

```python
def safe_int(value, default=0):
    """安全的整数转换"""
    try:
        return int(value)
    except (ValueError, TypeError):
        return default

def safe_float(value, default=0.0):
    """安全的浮点数转换"""
    try:
        return float(value)
    except (ValueError, TypeError):
        return default

print(safe_int("42"))       # 42
print(safe_int("abc"))      # 0
print(safe_int(None, -1))   # -1
print(safe_float("3.14"))   # 3.14
print(safe_float("N/A"))    # 0.0
```

### 12.9.3 完整的异常处理模板

```python
import logging

logger = logging.getLogger(__name__)

def process_data(filepath):
    """处理数据文件的完整示例"""
    try:
        with open(filepath, "r", encoding="utf-8") as f:
            data = f.read()
    except FileNotFoundError:
        logger.error(f"文件不存在：{filepath}")
        return None
    except PermissionError:
        logger.error(f"没有权限读取：{filepath}")
        return None
    except UnicodeDecodeError as e:
        logger.error(f"文件编码错误：{filepath}，{e}")
        return None

    try:
        # 解析数据
        lines = data.strip().split("\n")
        numbers = [float(line) for line in lines]
    except ValueError as e:
        logger.error(f"数据格式错误：{e}")
        return None

    # 计算统计信息（这里不太可能出错）
    return {
        "count": len(numbers),
        "sum": sum(numbers),
        "average": sum(numbers) / len(numbers) if numbers else 0,
        "min": min(numbers) if numbers else None,
        "max": max(numbers) if numbers else None,
    }
```

## 12.10 小结

- 异常是 Python 处理运行时错误的机制，所有异常都继承自 `BaseException`
- `try/except` 捕获异常，`else` 在无异常时执行，`finally` 无论如何都执行
- `raise` 主动抛出异常，`raise ... from ...` 创建异常链
- 自定义异常继承 `Exception`，建议为项目创建统一的异常基类
- Python 推崇 **EAFP** 风格（先尝试再处理），但输入验证适合 **LBYL**（先检查再做）
- 永远不要写裸的 `except:` 或 `except Exception: pass`——它们会隐藏真正的 bug
- 只捕获你预期内的异常，让意外异常暴露出来

## 12.13 常见错误与避坑

**1. 裸 except 吞掉一切**

```python
# 糟糕：连 Ctrl+C 和系统退出都吞了
try:
    do_something()
except:
    pass

# 至少捕获 Exception（不包括 SystemExit 和 KeyboardInterrupt）
try:
    do_something()
except Exception as e:
    logger.error(f"错误：{e}")
```

**2. except 块里又出异常**

```python
try:
    1 / 0
except ZeroDivisionError:
    # 如果这里又出错，原始异常就丢了
    log_error()  # 如果 log_error() 抛异常怎么办？
    cleanup()    # 不会执行
```

**3. 捕获太宽泛**

```python
# 不推荐：捕获所有异常会让你错过真正的 bug
try:
    result = complex_calculation()
except Exception:
    result = 0  # 所有错误都静默返回 0，问题被掩盖了

# 推荐：只捕获预期内的异常
try:
    result = complex_calculation()
except ValueError:
    result = 0  # 只有值错误才用默认值
```

**4. 忘记 finally 中的 return 会覆盖异常**

```python
def bad_function():
    try:
        raise ValueError("出错了！")
    finally:
        return "正常返回"  # 异常被吞掉了！

print(bad_function())  # "正常返回" —— 异常消失了

# 不要在 finally 中 return
```

**5. 把异常当控制流（过度使用）**

```python
# 不推荐：用异常做正常的流程控制
for key in keys:
    try:
        process(d[key])
    except KeyError:
        continue

# 推荐：用 .get() 或 in 检查
for key in keys:
    if key in d:
        process(d[key])
    # 或
    value = d.get(key)
    if value is not None:
        process(value)
```
