## 心智模型

### 一、核心模型：一条主线

初学者面对 OpenSSL 的最大困惑，是它像个无所不包的杂货铺：算哈希、加密文件、造密钥、发证书、调试 TLS……十几个子命令家族挤在一起，不知道从哪进门。本书用一条主线把杂货铺摆成一条走廊：

```text
┌────────────────────────────────────────────────────┐
│  完整性：数据变没变过？        → 哈希   （第2章）     │
│  保密性：别人看不看得懂？      → 对称加密（第3章）    │
│  随机性：钥匙从哪来？          → 随机数 （第4章）     │
│  身份  ：对面真的是他吗？      → 非对称+证书（第5-11章）│
│  实战  ：出了问题怎么查？      → TLS 工具（第12-14章）│
│                                                    │
│  HTTPS = 证书验明身份 + 对称密钥保护数据             │
└────────────────────────────────────────────────────┘
```

这条主线展开就是一幅全景图，全书 14 章全部挂在这张图上：

```text
        你手里的数据                        网络对面的服务
┌───────────────────────┐          ┌───────────────────────┐
│ 哈希：指纹没变（完整性） │          │ 证书：身份是真的        │
│   dgst                │          │   x509 / verify       │
│ 对称加密：内容看不懂    │  ──TLS──► │                       │
│   enc + AES           │          │ TLS 通道：s_client     │
│ 非对称：钥匙能交换      │          │   证书验身份            │
│   genpkey / 签名       │          │   对称密钥保护数据      │
└───────────────────────┘          └───────────────────────┘
```

逐层解释：

- **数据层**（Part 1）：不理解哈希与对称加密，你做不了加密备份、下不了安装包的判断依据。四章拆掉「我加密过了应该挺安全吧」这类错觉。
- **身份层**（Part 2）：不理解非对称与证书，你配 HTTPS 只会复制粘贴命令，报错了束手无策。五章从密钥一路讲到证书。
- **信任层与实战**（Part 3）：自建 CA 是理解「信任如何传递」的终极实验——亲手当一回 CA，公网证书体系的所有行为立刻通透。最后一章是排错手册，前十三章的知识在这里全部用上。

每个 Part 在主线上的位置一目了然：

| Part | 对应主线上的一段 | 学完你能做到 |
| ---- | ---- | ---- |
| Part 1 地基篇 | 哈希 + 对称加密 + 随机数 | 给任意文件做「加密 + 校验」双保险 |
| Part 2 进阶篇 | 非对称密钥 + 证书 | 不查文档完成密钥、CSR、自签证书三连 |
| Part 3 实战篇 | CA + 证书链 + TLS | 自建 CA 签发证书，用 s_client 独立破案 |

### 二、易混概念：一表分清

OpenSSL 圈子里概念混淆率极高——很多坑不是命令不会敲，而是概念先搅成一团。举个真实的例子：把 base64 当加密用、把 CSR 当证书配进 nginx、拿服务器证书去当客户端证书，这三类事故在运维工单里常年霸榜，全都源于概念层面的混淆。

这十二组概念覆盖了初学者提问率的九成，现在混个脸熟，对应章节会逐一拆解；日后忘了随时回来查，这张表就是全书最好的复习索引：

| 概念 A | 概念 B | 一句话区分 | 详见 |
| ---- | ---- | ---- | ---- |
| 编码（base64） | 加密 | base64 是「换种写法」人人可读，加密需要密钥 | 第3章 |
| 摘要 | HMAC | 摘要人人可算，HMAC 带密钥，能验「没被换过」 | 第2章 |
| 哈希 | 签名 | 哈希只验完整性，签名用私钥盖的还是「身份章」 | 第7章 |
| 对称加密 | 非对称加密 | 前者一把钥匙快但难分发，后者两把钥匙慢但好交换 | 第3、5章 |
| 公钥 | 证书 | 公钥是裸钥匙，证书是把钥匙和名字钉在一起的塑封卡 | 第8章 |
| CSR | 证书 | CSR 是申请表（含公钥待 CA 盖章），证书是盖完章的成品 | 第9章 |
| 自签名 | CA 签发 | 自签是自己给自己盖章，CA 签发是权威第三方盖章 | 第9、10章 |
| 根证书 | 中间证书 | 根证书是信任的起点，中间证书是被根授权的代办 | 第11章 |
| PEM | DER | 同一内容两种皮：PEM 是 base64 文本，DER 是二进制 | 第6章 |
| .crt/.key/.p12 后缀 | 内容格式 | 后缀是习惯叫法，内容可能是 PEM 也可能是 DER | 第6章 |
| s_client | s_server | 前者是客户端探针，后者是服务端试验台 | 第12章 |
| OpenSSL | LibreSSL | macOS 自带的是 LibreSSL 分支，行为有差异 | 第1章 |

### 三、一张命令地图

学 OpenSSL 的第二大痛点是子命令太多不知道用哪个。学完本书，你脑中应该能画出这张「按任务分类」的地图——所有日常需求都能在这张表里对号入座；忘了命令名时，按「我想干什么」从左往右查，比按字母序背命令快得多：

| 任务家族 | 代表命令 | 干什么 | 出场章节 |
| ---- | ---- | ---- | ---- |
| 摘要与签名 | `dgst` | 算哈希、HMAC、文件签名与验签 | 第2、7章 |
| 对称加密 | `enc` | AES 加解密文件、base64 编解码 | 第3章 |
| 随机与口令 | `rand` / `passwd` | 造随机密钥、生成口令哈希 | 第4章 |
| 非对称密钥 | `genpkey` / `pkey` / `pkeyutl` | 生成查看密钥、小数据加解密 | 第5章 |
| 证书请求 | `req` | 生成 CSR、一条命令自签证书 | 第9章 |
| 证书处理 | `x509` | 读证书、签发、格式转换 | 第8、10章 |
| 验证与 CA | `verify` / `ca` | 验证书链、CA 签发数据库 | 第10、11章 |
| 格式转换 | `pkcs12` / `asn1parse` | 合并导出 .p12、拆解二进制结构 | 第6章 |
| TLS 客户端 | `s_client` | 连接远程服务，现场勘察握手与证书 | 第12章 |
| TLS 服务端 | `s_server` | 起一个本地 TLS 试验台 | 第13章 |

顺手记下全书反复出现的「门牌号」——本书约定使用的路径与域名：

| 路径 / 域名 | 归属 | 作用 |
| ---- | ---- | ---- |
| `~/cloudnote` | 本地 | 云笔记项目目录（与 Git 教程同一台机器） |
| `~/cloudnote/dev/` | 本地 | 本地开发用的自签证书（第9章生成） |
| `~/.cloudnote-secrets/` | 本地 | 密钥专用目录（权限 700，绝不进 Git） |
| `/etc/cloudnote-ca/` | 服务器 | 本书自建内部 CA 的约定位置 |
| `/etc/cloudnote/<服务>/` | 服务器 | 各服务的证书三件套放置位 |
| `api.cloudnote.example` | 公网 | 云笔记 API 域名（.example 为保留测试域名） |
| `auth.cloudnote.internal` | 内网 | 内网认证服务（.internal 为内网保留域名） |
| `203.0.113.10` | 服务器 | 云笔记的云服务器（Git 教程里的同一台） |

### 四、贯穿全书的主线场景：云笔记第三幕

本书所有例子延续《Git 与 SSH 完全教程》的同一个项目：**云笔记**——一个三人团队的笔记应用。Git 教程结束时它刚学会 push 即部署；本书记录它的第三幕：有了真实用户，随之而来的是数据要保护、流量要加密、内网要建信任。三个阶段的危机，恰好对应 OpenSSL 的三类能力，也对应本书的三个 Part：

| 阶段 | 剧情危机 | 规模 | 催生的学习需求 | 对应章节 |
| ---- | ---- | ---- | ---- | ---- |
| 阶段 1 | 每周 200MB 用户数据备份到云对象存储，怕泄露也怕悄悄损坏 | 日活 300 用户 | 哈希校验、对称加密、密钥生成 | 第1-4章 |
| 阶段 2 | API 要上 HTTPS；发布包被人篡改过一次差点上线；内网服务裸奔 | 1 个公网 API + 3 个内网服务 | 非对称、格式、签名、证书 | 第5-9章 |
| 阶段 3 | 内网 3 个服务需要互相认证；公网证书到期忘续费，半夜全站报错 | 内部 CA 管辖 8 张证书 | 自建 CA、证书链、TLS 排错 | 第10-14章 |

三次危机各有一个名场面，读正文时你会反复遇到：

- **危机一（第 8 周）**：备份文件静默损坏了两周没人发现——恢复时才发现 200MB 数据里有一半是零。这场事故催生了「备份必须带校验和」的铁律。
- **危机二（第 14 周）**：一台开发机被植入恶意软件，发布包在中转机上被替换成夹带后门的版本，直到上线前夕才被发现——当时的流程区分不出「王哥的包」和「恶意软件的包」。从此发布包必签名。
- **危机三（第 30 周凌晨）**：API 证书到期忘续，全站报错 40 分钟；排查时还发现内网三个服务互相之间毫无信任关系。从此建起内部 CA 与到期监控。

全书出场角色提前认识一下，正文不再介绍：

| 角色 | 设定 | 在书里的戏份 |
| ---- | ---- | ---- |
| 你 | 云笔记的工程师，前作里配好了服务器与 SSH | 全书动手的那个人 |
| 王哥 | 云笔记的另一位同事，负责安全与运维 | 每章开头的「提问担当」 |
| 阿雪 | 团队第三位同事，负责测试与对接 | 证书物流与客户端视角的「验收担当」 |

为什么主角还是云笔记？因为它足够真实：一个有用户、有数据、有内网的应用，恰好把哈希、加密、签名、证书、TLS 的全部能力用一遍；又足够连续——你在《Git 与 SSH 完全教程》里配好的那台服务器和那对密钥，本书接着用。

读这本教程不需要读过前作，但两个衔接点会反复出现：第5章的非对称直觉直接沿用前作第5章的「挂锁与钥匙」类比；第13章的部署实验直接在前作的服务器上进行。没读过也不影响主线，遇到衔接点本书会把必要的设定重新交代一遍。

为保证全书举例自洽，统一采用以下设定（各章不再重复交代）：

- 项目本地路径：`~/cloudnote`
- 你的云服务器：`203.0.113.10`，登录用户名 `wang`（沿用 Git 教程设定）
- 公网 API 域名：`api.cloudnote.example`
- 内网三个服务：`auth` / `notify` / `sync`，域名统一挂在 `cloudnote.internal` 下
- 自建 CA 的服务器目录：`/etc/cloudnote-ca/`
- 证书有效期设定：根证书 10 年，内部签发的服务器证书 90 天

### 五、建议学习路径：用这个模型去学

**完整路径**（约 4-6 天）：按 Part 顺序通读，每章实验必须动手做。密码学工具是「看懂了但一敲就错」的典型——参数顺序、文件格式、编码方式差一个字母就全盘报错，只有手上有肌肉记忆才敢在生产环境敲命令。**最小路径**（约 1 天，先能干活，再回头补全）：

1. 第1-3章：装好 OpenSSL，完成一次「加密 + 校验」的备份双保险
2. 第5、9章：生成密钥对，一条命令给本地开发签出自签证书
3. 第12章：用 s_client 看懂任意网站的证书与到期时间

最小路径刻意跳过了自建 CA（第10章）与格式转换（第6章）——前者是内网多服务的必需品但单机开发用不上，后者等真正碰到格式报错时回来查即可。

**四个里程碑自检**——过不了就回炉对应章节：

| 里程碑 | 通过标准 | 位置 |
| ---- | ---- | ---- |
| M1 | 给任意文件做「AES 加密 + SHA-256 校验」双保险，并能完整还原 | 第2-3章 |
| M2 | 不查文档完成：生成密钥对、生成 CSR、自签证书（含 SAN） | 第5-9章 |
| M3 | 自建内部 CA，给一台内网服务签发证书并配好 nginx 验证通过 | 第10-13章 |
| M4 | 面对任意 TLS 报错，能用 s_client 定位出是证书、链还是协议问题 | 第12、14章 |

里程碑不是考试，而是自检信号：M1 卡住说明实验做得太少，M4 卡住说明第 12 章需要重读。每个 Part 读完，回到这张表打一个勾。

另一个使用建议：**把第14章当全书附录用**。正文章节按顺序读，但报错字典与加固清单适合随时翻——你以后在日常工作中碰到任何 TLS 报错，第一站就是那本字典，它把全书的知识浓缩成了「按症状查药方」的形态。

**实验环境**：本书是全站对环境要求最低的一套教程——一台装了 OpenSSL 3.x 的机器即可覆盖全部实验，本地电脑就够。个别章节的部署实验需要一台 Linux 服务器（Git 教程里的 `203.0.113.10` 正好接上），没有服务器也不影响主线学习。

动笔前的环境准备清单，逐项打勾：

| 准备项 | 怎么算就绪 | 缺了去哪补 |
| ---- | ---- | ---- |
| OpenSSL 3.x | `openssl version` 输出 3.x 且非 LibreSSL | 第1章 1.2 节 |
| 类 Unix 终端 | Linux / macOS / Git Bash 任一 | 前作第2章安装指引 |
| 一个工作目录 | `~/cloudnote`（随手 mkdir 即可） | 第1章实验 |
| 一台 Linux 服务器（可选） | 能 ssh 登录、有 sudo | 仅第10、13章需要 |

**读不懂时怎么办**：密码学概念的抽象度是逐步抬升的——如果某一章卡住，八成是前一章的某个概念没焊牢，回「易混概念表」定位到对应章节重读即可；如果只是某条命令报错，直接去第14章的报错字典按关键字搜，答案常常比正文章节更快。

最后是三个高频疑问的提前回答：

1. **「我平时写业务代码，需要学这么深吗？」**——HTTPS 配置、`.env` 里的密钥、依赖包的完整性校验，这些每天都在碰的东西全是本章主线上的零件。不需要会造密码学，但需要看懂你复制粘贴的每条命令在做什么。
2. **「需要数学基础吗？」**——不需要。全书不推一个公式，个别处只出现 2^n 量级记号，所有强度论证都给出工程结论与出处；想深挖数学的人，本书指路的站内教程与各算法的 RFC 是更好的起点。
3. **「直接从第9章读证书部分行不行？」**——行，第9-13章自成闭环。但你会错过「为什么」的那一半：证书体系的每个设计决策，动机都藏在前八章的攻防里。

如果全书只让你记住一句话，就是心智模型里那条主线：**哈希管完整性，加密管保密性，证书管身份**。遇到任何困惑，先问自己「我卡在哪一层」，答案往往立刻清晰。

## 开始之前的三个约定

**约定一：平台差异只此一处交代。** 全书命令默认在类 Unix 环境（Linux、macOS 终端或 Windows 上的 Git Bash）执行。三个注意点：Windows 用户请用 Git Bash 自带的 OpenSSL 而非 CMD；macOS 自带的 `/usr/bin/openssl` 是 LibreSSL 分支，个别参数不同，建议 `brew install openssl@3` 后把 `/opt/homebrew/opt/openssl@3/bin` 放进 PATH（第1章详讲）；所有报错案例均按 OpenSSL 3.x 的输出呈现。Windows 原生 OpenSSH 与 WSL2 环境本书不专门覆盖，WSL2 用户按 Ubuntu 章节操作即可。

**约定二：代码块的展示格式。** 手动执行的命令省略 `$` 提示符；交互式会话与命令输出单独成块、原样呈现；需要 root 权限时显式写 `sudo`。所有需要动手的实验都用「实验」小节标出，建议边读边做。实验小节的标准长相是「目标 + 步骤 + 验收标准」三件套——做完之后，把验收标准里的每一条亲眼确认过，才算这一章过关；只读不做的话，第14章的排错字典你会一个字都对不上号。

**约定三：不重复造轮子。** 密码学的「为什么」（协议怎么设计、数学原理是什么）不在本书展开，需要时直接送你去站内对应章节：

| TLS 握手协议原理 | 网络协议完全教程 第15章（`/network-protocol/ch15`） | 第12章勘察握手时 |
| 公钥与私钥的直觉 | Git 与 SSH 完全教程 第5章（`/git-ssh/ch05`） | 第5章生成密钥时 |
