# 第12章：端口与多路复用——传输层的寻址

## 端口的本质：传输层内的"子地址"

IP 地址解决了"数据送到哪台机器"的问题，但一台机器上通常运行着多个网络应用程序——Web 服务器、邮件服务器、数据库、SSH 守护进程……如果所有数据都送到同一个 IP 地址，操作系统怎么知道某个数据包应该交给哪个程序？

**端口（Port）** 就是答案。它是一个 16 位的整数（范围 0~65535），作为传输层内的"子地址"，标识一台机器上的具体应用程序或进程。

打个比方：IP 地址相当于你家的街道地址，端口号相当于房间号。快递送到"阳光小区 3 号楼 501"（IP 地址），但具体是给住在主卧的人还是次卧的人（端口号），需要进一步的标识。

在 TCP 和 UDP 中，端口的作用略有不同：

- **TCP 端口**：标识一个具体的服务或连接。同一台机器上可以有多个 TCP 连接，每个连接由五元组唯一标识。
- **UDP 端口**：标识一个接收数据报的套接字（socket）。由于 UDP 无连接，同一端口可以接收来自任何源的数据。

## 端口范围：知名端口、注册端口、动态端口

IANA（Internet Assigned Numbers Authority）将 65536 个端口分为三个范围：

**知名端口（Well-Known Ports，0-1023）**

这些端口分配给最核心的网络服务，通常需要 root/管理员权限才能绑定：

| 端口 | 协议 | 用途 |
| ------ | ------ | ------ |
| 20/21 | TCP | FTP（数据/控制） |
| 22 | TCP | SSH |
| 25 | TCP | SMTP（邮件发送） |
| 53 | UDP/TCP | DNS |
| 80 | TCP | HTTP |
| 110 | TCP | POP3（邮件接收） |
| 143 | TCP | IMAP（邮件接收） |
| 443 | TCP | HTTPS |
| 993 | TCP | IMAPS（加密 IMAP） |

**注册端口（Registered Ports，1024-49151）**

这些端口可以被特定的应用程序注册使用。例如：

- 3306：MySQL
- 5432：PostgreSQL
- 6379：Redis
- 8080：HTTP 代理/备用 Web 服务
- 27017：MongoDB

注册不是强制的——任何人都可以在自己的程序中使用这些端口，但遵循约定可以避免冲突。

**动态/私有端口（Dynamic/Private Ports，49152-65535）**

这些端口由操作系统自动分配给客户端的出站连接。当你打开浏览器访问一个网站时，浏览器会请求操作系统分配一个临时端口作为源端口。连接关闭后，这个端口可以被回收重用。

注意：不同操作系统的动态端口范围不同。Linux 默认使用 32768-60999（可通过 `/proc/sys/net/ipv4/ip_local_port_range` 调整），Windows 从 Vista 开始遵循 IANA 建议使用 49152-65535。

## 多路复用与多路分解：一个 IP 上运行多个服务

**多路复用（Multiplexing）** 和 **多路分解（Demultiplexing）** 是传输层的核心功能之一：

- **多路复用**（发送端）：传输层从多个应用程序收集数据，给每个数据段加上适当的报头（包含源端口和目的端口），然后统一交给 IP 层发送。
- **多路分解**（接收端）：传输层从 IP 层收到数据段后，根据报头中的目的端口号，将数据交付给正确的应用程序。

```
发送端：
  ┌──────────┐  ┌──────────┐  ┌──────────┐
  │ Web服务   │  │ SSH服务   │  │ DNS服务   │
  │ (端口80)  │  │ (端口22)  │  │ (端口53)  │
  └─────┬────┘  └─────┬────┘  └─────┬────┘
        │              │              │
        └──────────┬───┴──────────────┘
                   │ 多路复用
              ┌────┴────┐
              │  传输层   │
              │ (TCP/UDP)│
              └────┬────┘
                   │
              ┌────┴────┐
              │  IP 层   │
              └─────────┘

接收端：
              ┌─────────┐
              │  IP 层   │
              └────┬────┘
                   │
              ┌────┴────┐
              │  传输层   │  多路分解
              │ (TCP/UDP)│  根据目的端口分发
              └────┬────┘
                   │
     ┌─────────────┼─────────────┐
     │             │             │
┌────┴────┐  ┌────┴────┐  ┌────┴────┐
│ 端口80  │  │ 端口22  │  │ 端口53  │
│ Web服务  │  │ SSH服务  │  │ DNS服务  │
└─────────┘  └─────────┘  └─────────┘
```

多路分解的规则：

- **UDP 多路分解**：根据 `(目的端口)` 二元组匹配 socket。如果有多个 UDP socket 绑定到同一个端口（使用 `SO_REUSEPORT`），操作系统会选择一个来接收。
- **TCP 多路分解**：根据 `(协议, 源IP, 源端口, 目的IP, 目的端口)` 五元组精确匹配 socket。这就是为什么同一台 Web 服务器可以同时处理来自不同客户端的数千个连接——每个连接的五元组都是唯一的。

## Socket 五元组：协议+源IP+源端口+目的IP+目的端口

TCP 连接由 **五元组（5-tuple）** 唯一标识：

```
(协议, 源IP, 源端口, 目的IP, 目的端口)
```

例如：

```
连接1: (TCP, 192.168.1.100, 49152, 93.184.216.34, 80)
连接2: (TCP, 192.168.1.100, 49153, 93.184.216.34, 80)
连接3: (TCP, 192.168.1.100, 49152, 172.217.14.206, 443)
```

连接 1 和连接 2 的源端口不同，所以是两个独立的连接——即使它们的目的相同。连接 1 和连接 3 的目的 IP 和端口都不同，也是独立的。

这个设计有一个有趣的推论：**同一台客户端可以同时与同一台服务器的同一个端口建立多个连接**，只要客户端使用不同的源端口。一个 Web 浏览器打开 6 个到同一服务器的连接来并行下载资源，靠的就是 6 个不同的源端口。

一个服务器端口（如 80）可以同时接受 **数千个连接**，因为每个连接的五元组不同——来自不同客户端（不同的源 IP 和源端口）的连接自然不同。

## 端口扫描的原理与防御

**端口扫描** 是探测一台主机上开放了哪些服务的技术。它在安全评估中有正当用途（管理员检查自己的服务器），也是攻击者侦察目标的第一步。

**常见的扫描方式：**

1. **TCP Connect 扫描**：完成三次握手。如果连接成功，端口开放；如果收到 RST，端口关闭。简单但容易被日志记录。

2. **SYN 扫描（半开扫描）**：只发送 SYN，不完成握手。如果收到 SYN+ACK，端口开放，扫描方发送 RST 终止连接。比 Connect 扫描更隐蔽，因为大多数应用层日志不会记录未完成的连接。

3. **FIN 扫描**：发送 FIN 报文。根据 RFC 793，关闭的端口应回复 RST，开放的端口不回复。可以绕过只检查 SYN 的防火墙。

4. **UDP 扫描**：向 UDP 端口发送空报文。如果收到 ICMP "端口不可达"，端口关闭；如果收到响应，端口开放；如果没有响应，可能是开放的（报文或 ICMP 被过滤了）。UDP 扫描非常慢，因为关闭的端口可能不响应（需要等待超时）。

**防御措施：**

- **最小化开放端口**：只开放必要的端口，关闭所有不需要的服务。
- **防火墙规则**：使用 `iptables`/`nftables` 限制对敏感端口的访问。
- **端口敲门（Port Knocking）**：要求客户端按特定顺序访问一组端口后，才打开目标端口。
- **入侵检测系统（IDS）**：检测异常的 SYN 扫描行为（如短时间内对多个端口的 SYN 请求）。
- **限速**：使用 `iptables` 的 `hashlimit` 模块限制单个 IP 的连接速率。

```bash
# 示例：限制 SSH 端口的新连接速率为每分钟 3 次
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
    -m hashlimit --hashlimit-above 3/min --hashlimit-mode srcip \
    --hashlimit-name ssh_limit -j DROP
```

## 编程实践：用 Python 写一个简单的端口扫描器

```python
import socket
import threading
import time
from queue import Queue

class PortScanner:
    def __init__(self, target, timeout=1.0, max_threads=50):
        self.target = target
        self.timeout = timeout
        self.max_threads = max_threads
        self.open_ports = []
        self.lock = threading.Lock()
        self.queue = Queue()

    def scan_port(self, port):
        """扫描单个端口（TCP Connect 扫描）"""
        try:
            sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
            sock.settimeout(self.timeout)
            result = sock.connect_ex((self.target, port))
            if result == 0:
                with self.lock:
                    self.open_ports.append(port)
                    try:
                        service = socket.getservbyport(port)
                    except OSError:
                        service = "unknown"
                    print(f"  [开放] 端口 {port:>5} - {service}")
            sock.close()
        except (socket.timeout, socket.error):
            pass

    def worker(self):
        """线程工作函数"""
        while True:
            port = self.queue.get()
            self.scan_port(port)
            self.queue.task_done()

    def scan(self, start_port=1, end_port=1024):
        """扫描端口范围"""
        print(f"扫描目标: {self.target}")
        print(f"端口范围: {start_port}-{end_port}")
        print(f"超时: {self.timeout}s, 线程数: {self.max_threads}")
        print("-" * 50)

        start_time = time.perf_counter()

        # 将端口加入队列
        for port in range(start_port, end_port + 1):
            self.queue.put(port)

        # 启动工作线程
        threads = []
        for _ in range(self.max_threads):
            t = threading.Thread(target=self.worker, daemon=True)
            t.start()
            threads.append(t)

        # 等待所有端口扫描完成
        self.queue.join()

        elapsed = time.perf_counter() - start_time
        print("-" * 50)
        print(f"扫描完成！耗时: {elapsed:.2f} 秒")
        print(f"开放端口数: {len(self.open_ports)}")

        if self.open_ports:
            print(f"开放端口列表: {sorted(self.open_ports)}")

        return sorted(self.open_ports)

if __name__ == '__main__':
    # 扫描本地主机的前 1024 个端口
    # 注意：扫描他人主机可能违法，请仅扫描自己授权的主机
    scanner = PortScanner('127.0.0.1', timeout=0.5, max_threads=100)
    scanner.scan(start_port=1, end_port=1024)
```

这个扫描器使用 **多线程** 来并行扫描多个端口。主要特点：

- `connect_ex()` 返回 0 表示连接成功（端口开放），返回错误码表示失败（端口关闭或被过滤）。
- 线程池模式比逐个扫描快得多——100 个线程同时扫描 100 个端口。
- `Queue` 用于线程安全的任务分发。

**安全提醒**：端口扫描在很多国家和地区属于违法行为（未经授权扫描他人主机）。请仅在你拥有或获得授权的主机上进行扫描。

## 抓包实践：观察同一主机上多个 TCP 连接的端口分配

让我们同时建立多个 TCP 连接，观察操作系统如何分配源端口：

```python
import socket
import time

def observe_port_assignment():
    """同时建立多个连接，观察源端口分配"""
    sockets = []

    for i in range(5):
        sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        sock.connect(('93.184.216.34', 80))  # 连接 example.com
        local_addr = sock.getsockname()
        print(f"连接 {i+1}: 源端口={local_addr[1]}, "
              f"目的={sock.getpeername()}")
        sockets.append(sock)

    print("\n所有连接同时存在，观察五元组...")
    for i, sock in enumerate(sockets):
        local = sock.getsockname()
        remote = sock.getpeername()
        print(f"  连接{i+1}: TCP {local[0]}:{local[1]} -> "
              f"{remote[0]}:{remote[1]}")

    # 保持连接 10 秒以便抓包
    time.sleep(2)

    for sock in sockets:
        sock.close()

observe_port_assignment()
```

同时在后台抓包：

```bash
sudo tcpdump -i any host 93.184.216.34 and port 80 -nn
```

抓包结果示例：

```
15:30:01.001 IP 192.168.1.100.54321 > 93.184.216.34.80: Flags [S], seq 1001
15:30:01.003 IP 192.168.1.100.54322 > 93.184.216.34.80: Flags [S], seq 2001
15:30:01.005 IP 192.168.1.100.54323 > 93.184.216.34.80: Flags [S], seq 3001
15:30:01.007 IP 192.168.1.100.54324 > 93.184.216.34.80: Flags [S], seq 4001
15:30:01.009 IP 192.168.1.100.54325 > 93.184.216.34.80: Flags [S], seq 5001
```

**关键观察：**

1. **源端口递增**：Linux 内核通常按顺序分配源端口（从 `ip_local_port_range` 范围中选取）。5 个连接的源端口是连续的（54321, 54322, 54323, 54324, 54325）。

2. **五元组唯一性**：所有 5 个连接的 `(协议, 源IP, 目的IP, 目的端口)` 都相同，只有源端口不同。这证明了源端口是区分同一对主机之间多个连接的关键。

3. **端口回收**：连接关闭后，这些源端口会进入 TIME_WAIT 状态（在 `ss -tan` 或 `netstat -tan` 中可以看到）。一段时间后，端口可以被新的连接重用。

可以用以下命令查看当前所有 TCP 连接及其端口：

```bash
# Linux
ss -tan state established
ss -tan state time-wait

# Windows
netstat -ano | findstr ESTABLISHED
```

你会看到类似：

```
ESTAB  0  0  192.168.1.100:54321  93.184.216.34:80
ESTAB  0  0  192.168.1.100:54322  93.184.216.34:80
ESTAB  0  0  192.168.1.100:54323  93.184.216.34:80
ESTAB  0  0  192.168.1.100:54324  93.184.216.34:80
ESTAB  0  0  192.168.1.100:54325  93.184.216.34:80
```

这就是多路复用在实际工作中的样子：五个独立的 TCP 连接共享同一个 IP 地址，通过不同的源端口和谐共存。操作系统传输层就像一个精密的邮件分拣中心——每个包裹进来，看一眼上面的端口号，就能准确无误地送到正确的应用程序手中。
