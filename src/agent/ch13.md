## 13.1 开篇：为什么需要ReAct？

在上一章中，我们实现了Function Calling——Agent可以调用工具了。但这里有一个隐藏的限制：**Function Calling本身只是"协议"，它没有规定Agent的"思考方式"。**

考虑这个复杂问题：

> "帮我分析DocMind项目在GitHub上的活跃度：统计最近30天的commit数量，计算平均每天的commit数，然后和同类项目LangChain做对比。"

要回答这个问题，Agent需要：

1. 搜索DocMind的commit数据
2. 计算日均commit数
3. 搜索LangChain的commit数据
4. 计算LangChain的日均commit数
5. 对比两者，生成分析报告

这个过程中，Agent需要**交替进行推理和行动**：

- **推理**：我需要先查DocMind的数据，然后查LangChain的，最后对比
- **行动**：调用搜索工具获取数据，调用计算工具算数

如果我们只用简单的Chain（顺序调用），是无法处理这种"需要根据中间结果动态调整下一步"的场景的。

**ReAct（Reasoning + Acting）** 就是解决这个问题的范式。它让Agent像一个人类专家一样：想一步，做一步，观察结果，再想下一步。

> 用编程的话说：ReAct就像一个`while`循环，循环体里包含`think()` -> `act()` -> `observe()`三个步骤，退出条件是"我已经有足够信息来回答了"。

> [!TIP] 🔗 回扣 Ch01
> ReAct 就是 Ch01 里 Agent 对象 `run()` 方法中那个 `while True` 循环的学术名字。`think()` = Reasoning，`call_tool()` = Acting，把工具结果追加到 `self.messages` = Observation。整个 ReAct 论文讲的就是这个循环的设计哲学：为什么要交替进行、什么时候退出循环、怎么处理死循环。你现在可以回去看 Ch01 那段代码，会发现你已经理解了 ReAct 的全部核心。

## 13.2 ReAct论文核心思想

ReAct来自2022年的论文 *"ReAct: Synergizing Reasoning and Acting in Language Models"*（Yao et al.）。核心洞察：

### 13.2.1 三种范式的对比

**纯推理（Reason only）**：

```
用户：DocMind用了哪些核心技术？
LLM：（仅靠内部知识）DocMind可能使用了NLP、向量数据库等技术...
```

问题：容易产生幻觉，没有事实依据。

**纯行动（Act only）**：

```
用户：DocMind用了哪些核心技术？
Agent：search("DocMind核心技术")
-> 得到结果
Agent：search("DocMind技术栈")
-> 得到结果
-> 直接拼接结果返回
```

问题：没有推理能力，不知道搜什么、怎么组合结果。

**ReAct（推理+行动交替）**：

```
用户：DocMind用了哪些核心技术？
Thought: 我需要搜索DocMind的技术文档来了解它用了哪些技术
Action: search("DocMind技术架构 核心技术")
Observation: 找到3篇相关文档...
Thought: 文档提到了LangChain和向量数据库，但我还需要更详细的信息
Action: search("DocMind LangChain 向量数据库 集成")
Observation: 找到了具体的技术栈描述...
Thought: 现在我有了足够的信息来回答用户的问题
Answer: DocMind使用了以下核心技术：1. LangChain... 2. 向量数据库...
```

### 13.2.2 ReAct的循环结构

```
+------------------------------------------+
|                                          |
|   +-----------+                          |
|   | Thought   | <- 我需要什么信息？下一步？|
|   +-----+-----+                          |
|         |                                |
|         v                                |
|   +-----------+                          |
|   |  Action   | <- 调用工具获取信息       |
|   +-----+-----+                          |
|         |                                |
|         v                                |
|   +-------------+                        |
|   | Observation | <- 观察工具返回的结果   |
|   +-----+-------+                        |
|         |                                |
|         v                                |
|   +----------------+    否               |
|   | 信息够了吗？    |-------+            |
|   +----------------+       |             |
|         | 是               | 回到Thought |
|         v                  |             |
|   +-----------+            |             |
|   |  Answer   |            |             |
|   +-----------+            |             |
|         ^                  |             |
|         +------------------+             |
|                                          |
+------------------------------------------+
```

> 类比理解：ReAct就像一个经验丰富的侦探——先思考线索（Thought），然后去现场调查（Action），观察发现了什么（Observation），再思考下一步（Thought），直到破案（Answer）。

## 13.3 手写ReAct Agent（从零实现）

让我们不依赖任何Agent框架，从零实现一个ReAct Agent。这是理解ReAct最好的方式。

```python
"""
从零实现ReAct Agent
不依赖LangChain的agent函数，完全手写
"""
import json
import re
from openai import OpenAI
from typing import Optional

client = OpenAI()

# ============================================================
# 第一步：定义工具（和之前一样）
# ============================================================

def search_documents(query: str) -> str:
    """搜索文档知识库"""
    mock_results = {
        "agent架构": "AI Agent由三部分组成：LLM（大脑）、Memory（记忆）、Tools（能力）。常见设计模式有ReAct、Plan-and-Execute、Multi-Agent。",
        "rag": "RAG（Retrieval Augmented Generation）通过检索外部文档来增强LLM的回答能力。核心流程：文档分块->向量化->存储->检索->生成。",
        "langchain": "LangChain是构建LLM应用的主流框架，提供Model I/O、Chains、Agents、Memory等模块。LangGraph是其状态图编排引擎。",
        "向量数据库": "常用的向量数据库有Pinecone、Weaviate、Chroma、FAISS等。它们通过余弦相似度或ANN算法进行向量检索。",
    }
    
    # 简单关键词匹配
    for key, value in mock_results.items():
        if key in query.lower():
            return f"[搜索结果] 关于'{query}': {value}"
    
    return f"[搜索结果] 未找到与'{query}'相关的文档"


def calculate(expression: str) -> str:
    """执行数学计算"""
    try:
        safe_dict = {"abs": abs, "round": round, "min": min, "max": max, "sum": sum}
        result = eval(expression, {"__builtins__": safe_dict}, {})
        return f"[计算结果] {expression} = {result}"
    except Exception as e:
        return f"[计算错误] {str(e)}"


# 工具注册表
AVAILABLE_TOOLS = {
    "search": {"func": search_documents, "description": "搜索文档知识库，参数：query(搜索关键词)"},
    "calculate": {"func": calculate, "description": "执行数学计算，参数：expression(数学表达式)"},
}

# ============================================================
# 第二步：定义ReAct的System Prompt
# 这是ReAct的灵魂——它定义了Agent的"思维模式"
# ============================================================

REACT_SYSTEM_PROMPT = """你是DocMind智能文档助手，使用ReAct模式来回答问题。

你可以使用以下工具：
{tool_descriptions}

回答格式（严格遵守）：

当你需要更多信息时：
Thought: [你的思考过程——你需要什么信息、为什么要用某个工具]
Action: [工具名称]
Action Input: [工具参数，JSON格式]

当你获得工具结果后，继续思考：
Observation: [工具返回的结果——这部分由系统自动填充]
Thought: [基于观察的新思考]

当你有足够信息可以回答时：
Thought: 我现在有足够的信息来回答用户的问题了。
Answer: [你的最终回答]

重要规则：
1. 每次只能输出一个Thought + Action + Action Input
2. 不要编造信息，如果不确定就使用search工具
3. 需要计算时使用calculate工具
4. Answer只在信息充分时才输出
"""

# 生成工具描述
tool_descriptions = ""
for name, info in AVAILABLE_TOOLS.items():
    tool_descriptions += f"- {name}: {info['description']}\n"

SYSTEM_PROMPT = REACT_SYSTEM_PROMPT.format(tool_descriptions=tool_descriptions)


# ============================================================
# 第三步：解析LLM的输出
# ============================================================

def parse_react_output(text: str) -> dict:
    """
    解析ReAct格式的输出
    提取Thought、Action、Action Input、Answer
    """
    result = {"type": None}
    
    # 提取Thought
    thought_match = re.search(r"Thought:\s*(.+?)(?=\n(?:Action|Answer):|$)", text, re.DOTALL)
    if thought_match:
        result["thought"] = thought_match.group(1).strip()
    
    # 检查是否有Answer（最终回答）
    answer_match = re.search(r"Answer:\s*(.+)", text, re.DOTALL)
    if answer_match:
        result["type"] = "answer"
        result["answer"] = answer_match.group(1).strip()
        return result
    
    # 检查是否有Action（工具调用）
    action_match = re.search(r"Action:\s*(\w+)", text)
    input_match = re.search(r"Action Input:\s*(.+?)(?=\n|$)", text, re.DOTALL)
    
    if action_match:
        result["type"] = "action"
        result["action"] = action_match.group(1).strip()
        if input_match:
            try:
                result["action_input"] = json.loads(input_match.group(1).strip())
            except json.JSONDecodeError:
                # 如果不是合法JSON，当做字符串处理
                result["action_input"] = {"query": input_match.group(1).strip().strip('"')}
        return result
    
    # 无法解析
    result["type"] = "error"
    result["raw"] = text
    return result


# ============================================================
# 第四步：执行工具
# ============================================================

def execute_action(action: str, action_input: dict) -> str:
    """执行工具调用"""
    if action not in AVAILABLE_TOOLS:
        return f"[错误] 未知工具: {action}。可用工具: {list(AVAILABLE_TOOLS.keys())}"
    
    try:
        func = AVAILABLE_TOOLS[action]["func"]
        result = func(**action_input)
        return result
    except Exception as e:
        return f"[执行错误] {str(e)}"


# ============================================================
# 第五步：ReAct主循环
# ============================================================

def react_agent(user_question: str, max_steps: int = 6, verbose: bool = True) -> str:
    """
    ReAct Agent主循环
    
    这就是ReAct的核心——一个简单的while循环：
    while not done:
        think -> act -> observe
    """
    
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": user_question}
    ]
    
    if verbose:
        print(f"\n{'='*60}")
        print(f"用户问题: {user_question}")
        print(f"{'='*60}")
    
    for step in range(max_steps):
        if verbose:
            print(f"\n--- Step {step + 1} ---")
        
        # 调用LLM
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            temperature=0,
            stop=["Observation:"]  # 遇到Observation就停止生成
        )
        
        llm_output = response.choices[0].message.content
        
        if verbose:
            print(llm_output)
        
        # 将LLM输出加入消息历史
        messages.append({"role": "assistant", "content": llm_output})
        
        # 解析输出
        parsed = parse_react_output(llm_output)
        
        if parsed["type"] == "answer":
            # Agent给出了最终回答
            if verbose:
                print(f"\n最终回答: {parsed['answer']}")
            return parsed["answer"]
        
        elif parsed["type"] == "action":
            # Agent请求调用工具
            action = parsed["action"]
            action_input = parsed.get("action_input", {})
            
            if verbose:
                print(f"  执行: {action}({action_input})")
            
            # 执行工具
            observation = execute_action(action, action_input)
            
            if verbose:
                print(f"  观察: {observation}")
            
            # 将观察结果加入消息历史
            # 注意：用user角色来"注入"观察结果
            messages.append({
                "role": "user",
                "content": f"Observation: {observation}\n"
            })
        
        elif parsed["type"] == "error":
            # 解析失败
            if verbose:
                print(f"  无法解析LLM输出，尝试让模型继续...")
            messages.append({
                "role": "user",
                "content": "请按照正确的ReAct格式继续回答。如果需要信息，请使用Action；如果信息充分，请给出Answer。"
            })
    
    return "达到最大步骤数，未能得出最终答案。"


# ============================================================
# 第六步：测试
# ============================================================

if __name__ == "__main__":
    # 测试1：需要搜索的问题
    print("\n" + "="*60)
    print("测试1: 需要搜索")
    react_agent("什么是RAG？它是怎么工作的？")
    
    # 测试2：需要搜索+计算
    print("\n\n" + "="*60)
    print("测试2: 搜索+计算")
    react_agent("搜索向量数据库的信息，如果两个维度为768的向量模长都约为20，点积为500，余弦相似度是多少？")
    
    # 测试3：多步搜索
    print("\n\n" + "="*60)
    print("测试3: 多步搜索")
    react_agent("比较一下ReAct和Plan-and-Execute两种Agent设计模式的区别")
```

### 代码中的关键设计

**1. stop参数**

```python
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    stop=["Observation:"]  # 关键！
)
```

为什么设置`stop=["Observation:"]`？因为Observation是系统（而非LLM）填充的。如果不设stop，LLM可能会自己"脑补"Observation的内容，这就失去了"让外部世界反馈真实信息"的意义。

> ⚠️ **这是ReAct实现中最常见的Bug**：忘记设置stop参数，导致LLM自己生成虚假的Observation。记住——Observation必须来自真实工具的执行结果。

**2. 错误恢复**

```python
elif parsed["type"] == "error":
    messages.append({
        "role": "user",
        "content": "请按照正确的ReAct格式继续回答..."
    })
```

当LLM的输出不符合ReAct格式时，我们不是直接报错退出，而是温和地提醒它回到正确格式。这就像给一个偶尔走神的同事一个善意的提醒。

## 13.4 LangChain的create_react_agent()

手写了ReAct之后，让我们看看LangChain怎么帮你做同样的事：

```python
使用LangChain的create_react_agent

    tools,

)

# ============================================================
# 使用Agent
# ============================================================

# 简单调用
result = agent.invoke({
    "messages": [("user", "什么是RAG？它的工作流程是什么？")]
})

# 打印最终回答
print(result["messages"][-1].content)

# 打印完整的执行轨迹（方便调试）

for msg in result["messages"]:
    print(f"[{msg.__class__.__name__}] {msg.content[:100]}...")
```

### 对比：手写 vs LangChain

| 维度 | 手写ReAct | LangChain create_react_agent |
| ------ | ---------- | --------------------------- |
| 代码量 | ~150行 | ~5行 |
| Prompt工程 | 手写ReAct格式prompt | 框架自动处理 |
| 输出解析 | 正则表达式（脆弱） | Function Calling（可靠） |
| 错误处理 | 自己实现 | 内置重试和错误恢复 |
| 可扩展性 | 需要改源码 | 配置参数即可 |
| 理解深度 | 深入理解原理 | 知其然不知其所以然 |

> **学习建议**：先手写一遍理解原理，然后在实际项目中使用LangChain版本。就像学数据结构时先手写链表，然后工作中用标准库。

## 13.5 Agent执行轨迹(Trace)分析和调试

Agent不像普通函数那样"输入->输出"那么简单。它的执行路径是动态的——可能调用0个工具，也可能调用5个。调试Agent需要特殊的技巧。

### 13.5.1 记录执行轨迹

```python
"""
Agent执行轨迹记录器
用于调试和分析Agent行为
"""
import time
import json
from dataclasses import dataclass, field
from typing import Any

@dataclass
class TraceStep:
    """轨迹中的一步"""
    step_type: str  # "thought", "action", "observation", "answer"
    content: str
    timestamp: float = field(default_factory=time.time)
    metadata: dict = field(default_factory=dict)


@dataclass
class AgentTrace:
    """完整的Agent执行轨迹"""
    steps: list[TraceStep] = field(default_factory=list)
    total_tokens: int = 0
    total_time: float = 0
    
    def add_step(self, step: TraceStep):
        self.steps.append(step)
    
    def summary(self) -> str:
        """生成轨迹摘要"""
        actions = [s for s in self.steps if s.step_type == "action"]
        observations = [s for s in self.steps if s.step_type == "observation"]
        
        return (
            f"执行摘要:\n"
            f"  总步骤数: {len(self.steps)}\n"
            f"  工具调用次数: {len(actions)}\n"
            f"  工具调用: {[s.metadata.get('tool_name', '') for s in actions]}\n"
            f"  总耗时: {self.total_time:.2f}秒\n"
            f"  总Token: {self.total_tokens}"
        )
    
    def to_dict(self) -> dict:
        """导出为字典（方便JSON序列化）"""
        return {
            "steps": [
                {
                    "type": s.step_type,
                    "content": s.content[:200],
                    "metadata": s.metadata
                }
                for s in self.steps
            ],
            "summary": self.summary()
        }


# ============================================================
# 带轨迹记录的ReAct Agent
# ============================================================

def react_agent_with_trace(user_question: str, max_steps: int = 6) -> tuple[str, AgentTrace]:
    """
    带完整轨迹记录的ReAct Agent
    返回：(最终回答, 执行轨迹)
    """
    trace = AgentTrace()
    start_time = time.time()
    
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": user_question}
    ]
    
    for step in range(max_steps):
        # 调用LLM
        llm_start = time.time()
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            temperature=0,
            stop=["Observation:"]
        )
        llm_time = time.time() - llm_start
        
        llm_output = response.choices[0].message.content
        tokens = response.usage.total_tokens if response.usage else 0
        trace.total_tokens += tokens
        
        messages.append({"role": "assistant", "content": llm_output})
        
        # 记录Thought
        parsed = parse_react_output(llm_output)
        
        if "thought" in parsed:
            trace.add_step(TraceStep(
                step_type="thought",
                content=parsed["thought"],
                metadata={"step": step + 1, "llm_time": llm_time, "tokens": tokens}
            ))
        
        if parsed["type"] == "answer":
            trace.add_step(TraceStep(
                step_type="answer",
                content=parsed["answer"],
                metadata={"step": step + 1}
            ))
            trace.total_time = time.time() - start_time
            return parsed["answer"], trace
        
        elif parsed["type"] == "action":
            action = parsed["action"]
            action_input = parsed.get("action_input", {})
            
            trace.add_step(TraceStep(
                step_type="action",
                content=f"{action}({json.dumps(action_input, ensure_ascii=False)})",
                metadata={"tool_name": action, "args": action_input}
            ))
            
            observation = execute_action(action, action_input)
            
            trace.add_step(TraceStep(
                step_type="observation",
                content=observation,
                metadata={"tool_name": action}
            ))
            
            messages.append({"role": "user", "content": f"Observation: {observation}\n"})
    
    trace.total_time = time.time() - start_time
    return "达到最大步骤数", trace


# ============================================================
# 测试并分析轨迹
# ============================================================

if __name__ == "__main__":
    answer, trace = react_agent_with_trace(
        "帮我了解一下Agent架构的核心组成部分，以及有哪些常见的设计模式"
    )
    
    print(f"\n最终回答: {answer}")
    print(f"\n{trace.summary()}")
    
    # 详细轨迹
    print("\n详细执行轨迹:")
    for i, step in enumerate(trace.steps):
        print(f"\n  [{i+1}] {step.step_type.upper()}")
        print(f"      {step.content[:200]}")
        if step.metadata:
            print(f"      (metadata: {step.metadata})")
```

### 13.5.2 常见调试场景

```python
# 场景1：Agent不调用工具，直接编造答案
# 原因：System Prompt中没有强调"必须使用工具"
# 修复：在prompt中加入"不要凭空编造信息，必须使用工具获取事实"

# 场景2：Agent反复调用同一个工具
# 原因：工具返回的结果不够明确，Agent觉得需要"再试一次"
# 修复：优化工具的返回格式，确保结果清晰

# 场景3：Agent陷入死循环
# 原因：max_steps设得太大，或者Agent没有意识到该停止
# 修复：减小max_steps，或在prompt中明确"如果已有足够信息就给出Answer"

# 场景4：Agent调用错误的工具
# 原因：工具描述不够清晰，模型分不清该用哪个
# 修复：优化工具描述，加入"什么时候该用/不该用"的说明
```

## 13.6 ReAct的局限性

ReAct是强大的，但它不是万能的。了解局限性才能做出正确的架构选择。

### 13.6.1 推理链过长

```python
# 问题场景：需要10步以上推理的复杂问题
# ReAct可能会"迷路"——忘记最初的推理目标

# 示例：
# Step 1: Thought: 我需要查A的信息
# Step 2: Action: search("A")
# Step 3: Observation: ...
# Step 4: Thought: 我还需要查B的信息
# Step 5: Action: search("B")
# ...
# Step 12: Thought: 等等，我最初要解决什么问题来着？
```

**原因**：每增加一步，消息历史就变长。LLM的注意力在超长上下文中会"稀释"，容易忘记早期的推理目标。

**缓解方案**：

- 限制最大步骤数
- 在每一步的prompt中加入"回顾原始问题"
- 使用更结构化的方法（Plan-and-Execute，见Part 4）

### 13.6.2 容易陷入循环

```python
# 问题场景：Agent在两个工具之间反复切换
# Step 1: search("X") -> 结果不包含Y
# Step 2: search("Y") -> 结果不包含X  
# Step 3: search("X Y") -> 还是不行
# Step 4: search("X AND Y") -> 还是不行...
```

**原因**：Agent没有"记忆"自己已经尝试过什么。每次Thought都是"我需要搜索..."但不知道之前已经搜过了。

**缓解方案**：

- 在prompt中要求Agent回顾已有的Observation
- 设置最大步骤数作为安全阀
- 检测重复行动并强制中断

### 13.6.3 Token消耗大

```python
# 一个5步的ReAct推理，消息历史大概长这样：
# - System Prompt: ~500 tokens
# - User Question: ~50 tokens
# - 5次LLM回复: 5 x ~200 tokens = 1000 tokens
# - 5次Observation: 5 x ~300 tokens = 1500 tokens
# - 累积的上下文: 每一步都要带上之前所有消息

# 第1步调用: ~550 tokens
# 第2步调用: ~1050 tokens  
# 第3步调用: ~1750 tokens
# 第4步调用: ~2650 tokens
# 第5步调用: ~3750 tokens
# 总计: ~9750 tokens（而不仅仅是3750！）
```

> ⚠️ **Token消耗是超线性增长的！** 因为每次LLM调用都要带上之前所有的消息历史。5步推理的token消耗大约是单步的10倍，不是5倍。对于长推理链，成本会快速膨胀。

### 13.6.4 改进方向

ReAct的这些局限性，正是**LangGraph**被创造出来的原因。LangGraph提供了：

- **更灵活的控制流**：不只是while循环，支持条件分支、并行、子图
- **状态管理**：不只是消息列表，可以有任意结构的状态
- **可视化**：图结构可以直观地展示Agent的执行流程
- **持久化**：中间状态可以保存和恢复

这些我们将在接下来的章节中详细展开。

## 13.7 实操：用ReAct模式重构DocMind

让我们把ReAct应用到DocMind项目中，让它能多步推理回答复杂问题：

```python
"""
DocMind ReAct版本
支持多步推理、工具调用、错误恢复
"""
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langgraph.prebuilt import create_react_agent
from langchain_core.messages import HumanMessage
import json

# ============================================================
# DocMind工具集（增强版）
# ============================================================

@tool
def search_knowledge_base(query: str, top_k: int = 3) -> str:
    """在DocMind知识库中搜索文档。当需要查找技术概念、项目信息、最佳实践时使用。
    
    Args:
        query: 搜索关键词，越具体越好
        top_k: 返回结果数量，默认3
    """
    knowledge = {
        "agent": "AI Agent = LLM + Memory + Tools。Agent通过推理决定使用哪些工具。核心能力：感知环境、制定计划、执行行动、从反馈中学习。",
        "react": "ReAct模式让Agent交替进行推理(Thought)和行动(Action)。优点：推理过程可解释。缺点：步骤多时容易迷路。",
        "langgraph": "LangGraph是LangChain的状态图编排引擎。核心概念：State(状态)、Node(节点)、Edge(边)。支持循环、条件分支、人机协作。",
        "rag": "RAG流程：文档加载->分块->向量化->存储->检索->生成。优化策略：查询改写、HyDE、多路召回、重排序。",
        "embedding": "Embedding将文本转换为向量。常用模型：OpenAI text-embedding-3-small/large。维度越大精度越高但成本也越高。",
        "function_calling": "Function Calling是LLM调用工具的标准协议。模型返回结构化的tool_calls而非纯文本。支持并行调用。",
    }
    
    results = []
    for key, value in knowledge.items():
        if key in query.lower() or any(word in query.lower() for word in key.split("_")):
            results.append(value)
    
    if results:
        return "\n".join([f"[{i+1}] {r}" for i, r in enumerate(results[:top_k])])
    return f"未找到与'{query}'相关的文档。建议尝试更具体的关键词。"


@tool
def calculate(expression: str) -> str:
    """执行数学计算。当需要数值计算、比较数据时使用。
    
    Args:
        expression: Python数学表达式
    """
    try:
        safe = {"abs": abs, "round": round, "min": min, "max": max, "sum": sum, "pow": pow, "len": len}
        result = eval(expression, {"__builtins__": safe}, {})
        return f"{expression} = {result}"
    except Exception as e:
        return f"计算错误: {str(e)}。请检查表达式语法。"


@tool
def compare_items(item_a: str, item_b: str, aspect: str = "overall") -> str:
    """比较两个技术概念或工具。当需要对比分析时使用。
    
    Args:
        item_a: 第一个比较对象
        item_b: 第二个比较对象
        aspect: 比较维度 (performance/features/ease_of_use/overall)
    """
    comparisons = {
        ("langchain", "langgraph"): "LangChain是线性编排(Chain)，适合简单流程。LangGraph是图编排，支持循环和条件分支，适合复杂Agent。LangGraph是LangChain的进化版。",
        ("react", "plan_and_execute"): "ReAct是边想边做，适合探索性任务。Plan-and-Execute是先规划后执行，适合结构化任务。ReAct更灵活，P&E更高效。",
        ("pinecone", "chroma"): "Pinecone是云服务，免运维但费用高。Chroma是开源本地方案，免费但需要自己管理。小项目用Chroma，生产环境用Pinecone。",
    }
    
    key = tuple(sorted([item_a.lower(), item_b.lower()]))
    for (a, b), comparison in comparisons.items():
        if key == tuple(sorted([a, b])):
            return comparison
    
    return f"暂无'{item_a}'和'{item_b}'在'{aspect}'方面的对比数据。建议分别搜索两者信息。"


# ============================================================
# 构建DocMind ReAct Agent
# ============================================================

def create_docmind_agent():
    """创建DocMind ReAct Agent"""
    
    llm = ChatOpenAI(model="gpt-4o", temperature=0)
    tools = [search_knowledge_base, calculate, compare_items]
    
    system_prompt = """你是DocMind——智能文档问答助手。

你的能力：
- 搜索知识库获取准确信息
- 进行数学计算
- 比较分析技术概念

工作原则：
1. 对于事实性问题，必须先搜索再回答，不要编造
2. 对于比较性问题，先分别搜索两者信息，再对比分析
3. 需要计算时使用calculate工具，不要心算
4. 回答使用中文，简洁清晰，必要时使用列表和代码块
5. 如果搜索结果不足以回答，如实告知用户并建议更具体的搜索词
"""
    
    agent = create_react_agent(
        llm,
        tools,
        prompt=system_prompt
    )
    
    return agent


# ============================================================
# 交互式使用
# ============================================================

def chat_with_docmind(agent):
    """与DocMind进行对话"""
    
    print("DocMind ReAct Agent 已就绪")
    print("输入你的问题，输入 'quit' 退出\n")
    
    while True:
        user_input = input("你: ").strip()
        
        if user_input.lower() in ['quit', 'exit', 'q']:
            print("再见！")
            break
        
        if not user_input:
            continue
        
        try:
            result = agent.invoke({
                "messages": [("user", user_input)]
            })
            
            # 打印执行过程（调试用）
            print("\n--- 执行过程 ---")
            for msg in result["messages"]:
                msg_type = msg.__class__.__name__
                if msg_type == "HumanMessage":
                    continue  # 跳过用户输入
                elif msg_type == "AIMessage":
                    if msg.tool_calls:
                        for tc in msg.tool_calls:
                            print(f"  工具: {tc['name']}({tc['args']})")
                    elif msg.content:
                        print(f"  回复: {msg.content[:100]}...")
                elif msg_type == "ToolMessage":
                    print(f"  工具结果: {msg.content[:100]}...")
            
            # 打印最终回答
            final_answer = result["messages"][-1].content
            print(f"\nDocMind: {final_answer}\n")
            
        except Exception as e:
            print(f"\n出错了: {e}\n")


if __name__ == "__main__":
    agent = create_docmind_agent()
    
    # 预设测试用例
    test_questions = [
        "什么是AI Agent？它有哪些核心能力？",

    ]
    
    for q in test_questions:
        print(f"\n{'='*60}")
        print(f"问题: {q}")
        result = agent.invoke({"messages": [("user", q)]})
        print(f"回答: {result['messages'][-1].content}")
```

## 13.8 本章小结

本章我们深入学习了ReAct——推理与行动交替进行的Agent范式：

1. **为什么需要ReAct**：简单Chain无法处理需要动态多步推理的问题
2. **核心思想**：Thought -> Action -> Observation循环，直到信息充分给出Answer
3. **手写实现**：从零实现了完整的ReAct循环，理解了每个细节
4. **LangChain版本**：`create_react_agent()`一行搞定
5. **调试技巧**：执行轨迹记录和分析
6. **局限性**：推理链过长、容易循环、token消耗大

### ReAct模式速查表

```
适用场景：
  需要搜索+推理的问答
  探索性的信息收集
  工具调用次数较少（<5步）

不适用场景：
  需要10步以上的复杂推理
  需要严格流程控制的任务
  对token成本极度敏感的场景
  -> 这些场景请用LangGraph（下一章）
```
