# 第23章：测试

Part VI：工程实践

## 引子：没有测试的代码就是定时炸弹

你可能听过这句话："如果你的代码没有测试，你不知道它是能工作的——你只是还没碰到触发Bug的输入。"

Rust把测试当作一等公民：`cargo test`一键运行所有测试，`#[test]`属性标记测试函数，`assert!`宏家族帮你验证预期。不需要像Java那样依赖JUnit、不需要像Python那样装pytest——测试框架内建于语言和Cargo之中。

> **类比**：如果你熟悉Python的`pytest`或Java的`JUnit`，Rust的内置测试框架会让你感到亲切——核心概念完全一样，只是语法不同。

## 单元测试：从最简单的开始

```rust
// src/lib.rs

pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

pub fn divide(a: f64, b: f64) -> Result<f64, String> {
    if b == 0.0 {
        Err("除数不能为零".to_string())
    } else {
        Ok(a / b)
    }
}

// 测试模块：用 #[cfg(test)] 标注，只在 cargo test 时编译
#[cfg(test)]
mod tests {
    use super::*;  // 引入父模块的所有公开项

    #[test]
    fn test_add_positive() {
        assert_eq!(add(2, 3), 5);
    }

    #[test]
    fn test_add_negative() {
        assert_eq!(add(-1, -2), -3);
    }

    #[test]
    fn test_add_zero() {
        assert_eq!(add(0, 0), 0);
    }

    #[test]
    fn test_divide_normal() {
        let result = divide(10.0, 3.0).unwrap();
        assert!((result - 3.333333).abs() < 0.001);
    }

    #[test]
    fn test_divide_by_zero() {
        let result = divide(10.0, 0.0);
        assert!(result.is_err());
        assert_eq!(result.unwrap_err(), "除数不能为零");
    }
}
```

三大断言宏：

| 宏 | 用途 | 失败时输出 |
| ---- | ------ | ------------ |
| `assert!(cond)` | 断言条件为真 | 条件表达式 |
| `assert_eq!(a, b)` | 断言相等 | a和b的值 |
| `assert_ne!(a, b)` | 断言不相等 | a和b的值 |

所有断言都支持自定义错误消息：

```rust
#[test]
fn test_with_message() {
    let result = add(2, 3);
    assert_eq!(result, 5, "2 + 3 应该等于 5，但得到了 {}", result);
}
```

## 测试组织：#[cfg(test)]的作用

`#[cfg(test)]`告诉编译器：**只有在运行`cargo test`时才编译这段代码**。这意味着：

1. 测试代码不会进入发布二进制文件（不增大体积）
2. 测试模块可以访问私有函数（通过`use super::*`）
3. 正常`cargo build`或`cargo run`时完全忽略测试代码

```rust
// src/lib.rs
pub fn process(data: &str) -> String {
    validate(data);
    data.to_uppercase()
}

// 私有函数：外部不可见，但测试模块可以测试
fn validate(data: &str) {
    if data.is_empty() {
        panic!("数据不能为空");
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_private_function() {
        // 可以测试私有函数！因为 tests 模块在同一个 crate 内
        validate("hello");  // 不会 panic
    }

    #[test]
    #[should_panic(expected = "数据不能为空")]
    fn test_validate_empty() {
        validate("");
    }

    #[test]
    fn test_process() {
        assert_eq!(process("hello"), "HELLO");
    }
}
```

## 运行测试：cargo test的各种姿势

```bash
# 运行所有测试
cargo test

# 只运行名字包含 "add" 的测试
cargo test add

# 显示测试中的 println! 输出（默认被隐藏）
cargo test -- --nocapture

# 只运行一个特定测试
cargo test test_divide_by_zero

# 并行运行（默认）vs 串行运行
cargo test -- --test-threads=1

# 显示被忽略的测试
cargo test -- --ignored

# 运行所有测试（包括被忽略的）
cargo test -- --include-ignored
```

标记需要长时间运行的测试为`#[ignore]`：

```rust
#[test]
#[ignore]  // 默认不运行，需要 cargo test -- --ignored 才会执行
fn expensive_integration_test() {
    // 这个测试需要连接真实数据库，耗时较长
    std::thread::sleep(std::time::Duration::from_secs(5));
    assert!(true);
}
```

## 集成测试：tests/目录

单元测试放在源码文件内的`tests`模块中。集成测试则放在项目根目录的`tests/`文件夹下，每个文件都是一个独立的测试crate：

```
my_project/
├── Cargo.toml
├── src/
│   └── lib.rs
└── tests/
    ├── integration_test.rs
    └── api_test.rs
```

```rust
// tests/integration_test.rs
// 集成测试只能访问 crate 的公开 API（和外部使用者一样）

use my_project;  // 引入你的 crate

#[test]
fn test_full_workflow() {
    let result = my_project::process("integration test");
    assert_eq!(result, "INTEGRATION TEST");
}

#[test]
fn test_edge_cases() {
    let result = my_project::process("  spaces  ");
    assert_eq!(result, "  SPACES  ");
}
```

> **单元测试 vs 集成测试**：单元测试验证内部细节（可以访问私有函数），集成测试验证公开接口的整体行为——就像用户会怎么使用你的库。

如果需要在多个集成测试文件间共享辅助代码，放在`tests/common/mod.rs`（注意不是`tests/common.rs`，否则Cargo会把它当成独立的测试文件运行）：

```rust
// tests/common/mod.rs
pub fn setup_test_data() -> Vec<String> {
    vec!["hello".into(), "world".into()]
}
```

```rust
// tests/integration_test.rs
mod common;

#[test]
fn test_with_setup() {
    let data = common::setup_test_data();
    assert_eq!(data.len(), 2);
}
```

## 文档测试（Doc Tests）：让文档永不过时

Rust有一个独特的功能：你在文档注释里写的代码示例，**会被自动当作测试运行**。这保证了文档和代码始终同步——如果API变了但文档没更新，测试会失败。

```rust
/// 将字符串转换为首字母大写。
///
/// # Examples
///
/// ```
/// use my_crate::capitalize;
/// assert_eq!(capitalize("hello"), "Hello");
/// assert_eq!(capitalize("WORLD"), "WORLD");
/// ```
///
/// 空字符串保持为空：
///
/// ```
/// use my_crate::capitalize;
/// assert_eq!(capitalize(""), "");
/// ```
pub fn capitalize(s: &str) -> String {
    let mut chars = s.chars();
    match chars.next() {
        None => String::new(),
        Some(c) => c.to_uppercase().to_string() + chars.as_str(),
    }
}
```

如果示例代码预期会panic，用`should_panic`标注：

```rust
/// ```should_panic
/// use my_crate::divide;
/// divide(10.0, 0.0).unwrap(); // 这会 panic
/// ```
```

如果示例代码太长不想运行，用`no_run`；如果只是示意不需编译，用`ignore`：

```rust
/// ```no_run
/// // 编译但不运行（比如需要网络连接）
/// let response = reqwest::blocking::get("https://example.com").unwrap();
/// ```
///
/// ```ignore
/// // 既不编译也不运行（伪代码示意）
/// let result = some_complex_setup();
/// ```
```

## 测试中的错误处理

**方法1：#[should_panic]**

```rust
#[test]
#[should_panic(expected = "索引越界")]
fn test_panic_on_out_of_bounds() {
    let v = vec![1, 2, 3];
    // 这会 panic，且消息包含"索引越界"
    let _ = v[99];
}
```

**方法2：返回Result**

```rust
#[test]
fn test_with_result() -> Result<(), String> {
    let result = divide(10.0, 2.0)?;
    if (result - 5.0).abs() < 0.001 {
        Ok(())
    } else {
        Err(format!("期望 5.0，得到 {}", result))
    }
}
```

> **最佳实践**：优先使用`Result`返回方式而不是`should_panic`，因为它能给出更清晰的错误信息，也更容易用`?`链式调用。

## Mock与测试替身简介

Rust生态中有几个Mock库，最流行的是`mockall`。当你需要测试依赖外部服务（数据库、HTTP API）的代码时，Mock是不可或缺的工具：

```rust
// Cargo.toml: mockall = "0.13"

use mockall::*;

#[automock]
pub trait Database {
    fn get_user(&self, id: u64) -> Option<String>;
    fn save_user(&self, id: u64, name: &str) -> Result<(), String>;
}

pub fn greet_user(db: &dyn Database, id: u64) -> String {
    match db.get_user(id) {
        Some(name) => format!("你好，{}！", name),
        None => "用户不存在".to_string(),
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_greet_existing_user() {
        let mut mock_db = MockDatabase::new();
        mock_db
            .expect_get_user()
            .with(eq(1u64))
            .returning(|_| Some("Alice".to_string()));

        let greeting = greet_user(&mock_db, 1);
        assert_eq!(greeting, "你好，Alice！");
    }

    #[test]
    fn test_greet_missing_user() {
        let mut mock_db = MockDatabase::new();
        mock_db
            .expect_get_user()
            .returning(|_| None);

        let greeting = greet_user(&mock_db, 999);
        assert_eq!(greeting, "用户不存在");
    }
}
```

## 基准测试（Benchmark）简介

Rust的内置基准测试需要nightly编译器。稳定工具链下推荐使用`criterion`库：

```toml
# Cargo.toml
[dev-dependencies]
criterion = { version = "0.5", features = ["html_reports"] }

[[bench]]
name = "my_benchmark"
harness = false
```

```rust
// benches/my_benchmark.rs
use criterion::{black_box, criterion_group, criterion_main, Criterion};

fn fibonacci(n: u64) -> u64 {
    match n {
        0 => 0,
        1 => 1,
        _ => fibonacci(n - 1) + fibonacci(n - 2),
    }
}

fn fibonacci_iterative(n: u64) -> u64 {
    let (mut a, mut b) = (0u64, 1u64);
    for _ in 0..n {
        let temp = a + b;
        a = b;
        b = temp;
    }
    a
}

fn bench_fibonacci(c: &mut Criterion) {
    let mut group = c.benchmark_group("fibonacci");
    group.bench_function("recursive_20", |b| {
        b.iter(|| fibonacci(black_box(20)))
    });
    group.bench_function("iterative_20", |b| {
        b.iter(|| fibonacci_iterative(black_box(20)))
    });
    group.finish();
}

criterion_group!(benches, bench_fibonacci);
criterion_main!(benches);
```

运行：`cargo bench`，会在`target/criterion/`下生成HTML报告。

## 实战：为一个库编写完整测试套件

```rust
// src/lib.rs - 一个简单的待办事项管理器

use std::collections::HashMap;

#[derive(Debug, Clone, PartialEq)]
pub struct Todo {
    pub id: u64,
    pub title: String,
    pub completed: bool,
}

pub struct TodoManager {
    todos: HashMap<u64, Todo>,
    next_id: u64,
}

impl TodoManager {
    pub fn new() -> Self {
        Self {
            todos: HashMap::new(),
            next_id: 1,
        }
    }

    pub fn add(&mut self, title: &str) -> Result<u64, String> {
        if title.trim().is_empty() {
            return Err("标题不能为空".to_string());
        }
        let id = self.next_id;
        self.next_id += 1;
        self.todos.insert(id, Todo {
            id,
            title: title.to_string(),
            completed: false,
        });
        Ok(id)
    }

    pub fn complete(&mut self, id: u64) -> Result<(), String> {
        match self.todos.get_mut(&id) {
            Some(todo) => {
                todo.completed = true;
                Ok(())
            }
            None => Err(format!("ID {} 不存在", id)),
        }
    }

    pub fn get(&self, id: u64) -> Option<&Todo> {
        self.todos.get(&id)
    }

    pub fn list_pending(&self) -> Vec<&Todo> {
        self.todos.values().filter(|t| !t.completed).collect()
    }

    pub fn remove(&mut self, id: u64) -> Result<Todo, String> {
        self.todos.remove(&id).ok_or(format!("ID {} 不存在", id))
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    // 辅助函数：创建带初始数据的 Manager
    fn setup() -> TodoManager {
        let mut mgr = TodoManager::new();
        mgr.add("学习Rust").unwrap();
        mgr.add("写单元测试").unwrap();
        mgr
    }

    #[test]
    fn test_add_todo() {
        let mut mgr = TodoManager::new();
        let id = mgr.add("测试任务").unwrap();
        assert_eq!(id, 1);
        assert_eq!(mgr.get(id).unwrap().title, "测试任务");
        assert!(!mgr.get(id).unwrap().completed);
    }

    #[test]
    fn test_add_empty_title() {
        let mut mgr = TodoManager::new();
        let result = mgr.add("");
        assert!(result.is_err());
        assert_eq!(result.unwrap_err(), "标题不能为空");
    }

    #[test]
    fn test_add_whitespace_title() {
        let mut mgr = TodoManager::new();
        assert!(mgr.add("   ").is_err());
    }

    #[test]
    fn test_complete_todo() {
        let mut mgr = setup();
        mgr.complete(1).unwrap();
        assert!(mgr.get(1).unwrap().completed);
    }

    #[test]
    fn test_complete_nonexistent() {
        let mut mgr = TodoManager::new();
        assert!(mgr.complete(999).is_err());
    }

    #[test]
    fn test_list_pending() {
        let mut mgr = setup();
        mgr.complete(1).unwrap();
        let pending = mgr.list_pending();
        assert_eq!(pending.len(), 1);
        assert_eq!(pending[0].title, "写单元测试");
    }

    #[test]
    fn test_remove_todo() {
        let mut mgr = setup();
        let removed = mgr.remove(1).unwrap();
        assert_eq!(removed.title, "学习Rust");
        assert!(mgr.get(1).is_none());
    }

    #[test]
    fn test_remove_nonexistent() {
        let mut mgr = TodoManager::new();
        assert!(mgr.remove(42).is_err());
    }

    #[test]
    fn test_id_auto_increment() {
        let mut mgr = TodoManager::new();
        let id1 = mgr.add("第一个").unwrap();
        let id2 = mgr.add("第二个").unwrap();
        let id3 = mgr.add("第三个").unwrap();
        assert_eq!(id1, 1);
        assert_eq!(id2, 2);
        assert_eq!(id3, 3);
    }
}
```

## 常见陷阱与易错点

**陷阱1：测试间的状态泄漏**
每个`#[test]`函数独立运行，但默认**并行执行**。如果你的测试共享全局状态（环境变量、文件等），会出现偶发失败。用`--test-threads=1`串行运行，或确保每个测试使用独立资源。

**陷阱2：忘记`#[cfg(test)]`**
不加这个属性，测试代码会被编译进发布版本，增大二进制体积。

**陷阱3：测试名太泛**
`test_1`、`test_2`这样的名字在测试失败时毫无帮助。用`test_功能_场景`格式命名，如`test_add_empty_title_returns_error`。

## 小结

- `#[test]` + `assert!`/`assert_eq!`/`assert_ne!` 是测试的基本武器
- `#[cfg(test)]` 让测试代码只在`cargo test`时编译
- 单元测试在源文件内，集成测试在`tests/`目录
- 文档测试让API文档永不过时
- `mockall`库帮助你隔离外部依赖
- `criterion`是稳定工具链下的基准测试首选
