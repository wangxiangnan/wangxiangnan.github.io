# 第20章：异步编程基础

Part V：异步与并发

## 引子：餐厅服务员的哲学问题

想象你是一家餐厅的唯一服务员。同步（Synchronous）模式下，你给1号桌点完菜、等厨师做好、端上桌，才去服务2号桌——客人等得花儿都谢了。多线程（Multi-threading）模式是雇10个服务员，每人服务一桌，但你要付10个人的工资（内存开销），而且他们还可能在上菜时撞到一起（数据竞争）。

异步（Asynchronous）模式则是：你给1号桌点完菜，把单子交给厨房，**立刻**去服务2号桌。菜做好了铃一响，你再端过去。一个服务员就能高效服务多桌——这就是异步的精髓。

如果你来自Python，你已经熟悉`asyncio`；来自JavaScript，整个Node.js都建立在Promise之上；来自Java，`CompletableFuture`和虚拟线程（Virtual Thread）也是同类概念。Rust的异步模型与它们相似，但有一个关键区别：**零成本抽象（Zero-cost Abstraction）**——你没用到的异步功能，不会带来任何运行时开销。

---

## 三种并发模型对比

| 模型 | 类比 | 优点 | 缺点 | 典型代表 |
| ------ | ------ | ------ | ------ | ---------- |
| 同步阻塞 | 一个服务员从头到尾服务一桌 | 简单直观 | 并发能力差 | 传统脚本 |
| 多线程 | 每桌配一个专属服务员 | 真并行、隔离性好 | 内存占用高、同步复杂 | Java线程池 |
| 异步 | 一个服务员灵活调度多桌 | 高并发、低内存 | 代码复杂度增加 | Node.js、asyncio |

Rust同时支持多线程（第16章已讲）和异步，让你按需选择。

## Future trait：异步世界的"欠条"

在Python里你返回一个`coroutine`对象，在JS里你得到一个`Promise`。在Rust里，异步操作返回一个实现了`Future` trait的值——可以把它理解为一张"结果欠条"，只有在被**轮询（poll）**时才会推进计算。

```rust
use std::future::Future;
use std::pin::Pin;
use std::task::{Context, Poll};

// Future trait 的定义（标准库中已有，这里展示给你看）：
// trait Future {
//     type Output;
//     fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
// }

// Poll 是一个枚举：
// enum Poll<T> {
//     Ready(T),   // 计算完成，这是结果
//     Pending,    // 还没好，下次再来poll我
// }
```

你通常不需要手动实现`Future`——编译器会帮你生成。但了解这个trait有助于理解底层机制。

## async/await 语法：把异步写得像同步一样

```rust
// 假设有一个异步函数，模拟从数据库读取用户信息
async fn fetch_user(user_id: u64) -> String {
    // 模拟异步网络延迟（实际项目中这里会是真实的HTTP请求）
    // 注意：这里用 tokio::time::sleep，不是 std::thread::sleep！
    tokio::time::sleep(std::time::Duration::from_millis(100)).await;
    format!("User #{}: Alice", user_id)
}

// async fn 的返回类型实际上是一个 impl Future<Output = String>
// 也就是说，调用 fetch_user(1) 不会立刻执行，而是返回一个 Future
```

`.await`是一个**关键字**（不是方法调用），它只能在`async`函数或`async`块内部使用。它的作用是"暂停当前异步任务，等待Future完成并取出结果"：

```rust
async fn greet_user(user_id: u64) {
    // 没有 .await，fetch_user 根本不会执行！（常见新手坑）
    let future = fetch_user(user_id);  // 只是创建了Future，没有执行
    // 编译器会警告你：unused Future that must be awaited

    let user = fetch_user(user_id).await;  // 正确：等待结果
    println!("你好，{}！", user);
}
```

> **来自JS的注意**：在JavaScript里，忘记`await`会得到一个`Promise`对象，程序继续运行。在Rust里，忘记`.await`则Future完全不执行，编译器还会给你一个警告——这是Rust在帮你抓Bug。

## async块：在普通函数里嵌入异步逻辑

有时你不想把整个函数标为`async`，可以用`async`块：

```rust
fn build_greeting(user_id: u64) -> impl std::future::Future<Output = String> {
    async move {
        let user = fetch_user(user_id).await;
        format!("欢迎回来，{}！", user)
    }
}
```

注意`async move`：和普通闭包一样，`move`会把捕获的变量所有权转移进异步块。这在异步代码中几乎是必须的，因为Future可能在任意时间点被poll，它必须拥有自己的数据。

## tokio运行时：让异步真正跑起来

Rust的异步需要一个**运行时（Runtime）**来驱动Future的poll循环。标准库故意不提供运行时，让你自己选择——最流行的是`tokio`。

在`Cargo.toml`中添加依赖：

```toml
[dependencies]
tokio = { version = "1", features = ["full"] }
```

最基本的用法：

```rust
// src/main.rs
#[tokio::main]
async fn main() {
    let user = fetch_user(42).await;
    println!("获取到：{}", user);
}
```

`#[tokio::main]`是一个过程宏，它把`async fn main()`展开成：

```rust
fn main() {
    tokio::runtime::Runtime::new()
        .unwrap()
        .block_on(async {
            let user = fetch_user(42).await;
            println!("获取到：{}", user);
        })
}
```

如果你想在同步代码中手动启动运行时（比如写库时），可以直接用`block_on`：

```rust
use tokio::runtime::Runtime;

fn sync_main() {
    let rt = Runtime::new().unwrap();
    let result = rt.block_on(async {
        fetch_user(1).await
    });
    println!("同步调用结果：{}", result);
}
```

## 同步与异步的边界：block_on与spawn_blocking

现实项目中，你常常需要在两个世界之间架桥。

**从同步世界进入异步世界**：用`block_on`（上面已演示）。

**从异步世界调用同步阻塞代码**：用`spawn_blocking`。比如你要读一个大文件（标准库的`std::fs::read`是同步阻塞的），直接在异步任务里调用会阻塞整个tokio工作线程，导致其他异步任务全部饿死：

```rust
#[tokio::main]
async fn main() {
    // 错误做法：在异步上下文中直接调用阻塞操作
    // let data = std::fs::read_to_string("big_file.txt").unwrap(); // 阻塞！

    // 正确做法：把阻塞操作扔进专用线程池
    let data = tokio::task::spawn_blocking(|| {
        std::fs::read_to_string("big_file.txt")
    })
    .await
    .unwrap()
    .unwrap();

    println!("文件长度：{} 字节", data.len());
}
```

> **类比**：`spawn_blocking`就像餐厅里的"专人大件搬运"——普通服务员（异步任务）处理快速请求，遇到需要长时间占用厨房的硬菜（阻塞操作），就委托给专门的重活组，自己继续服务其他桌。

## 实战：异步HTTP请求器

让我们用`reqwest`（基于tokio的HTTP客户端）写一个真实的异步HTTP请求器：

```toml
[dependencies]
tokio = { version = "1", features = ["full"] }
reqwest = { version = "0.12", features = ["json"] }
serde = { version = "1", features = ["derive"] }
```

```rust
use serde::Deserialize;
use std::time::Duration;

#[derive(Deserialize, Debug)]
struct Post {
    id: u64,
    title: String,
    body: String,
}

async fn fetch_post(id: u64) -> Result<Post, reqwest::Error> {
    let url = format!("https://jsonplaceholder.typicode.com/posts/{}", id);
    let post = reqwest::get(&url)
        .await?
        .json::<Post>()
        .await?;
    Ok(post)
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    println!("开始请求文章...");

    let post = fetch_post(1).await?;
    println!("文章标题：{}", post.title);
    println!("内容前50字：{:.50}...", post.body);

    // 顺序请求多个（后面章节会讲如何并发请求）
    for id in 2..=4 {
        let p = fetch_post(id).await?;
        println!("[{}] {}", p.id, p.title);
    }

    Ok(())
}
```

注意`?`操作符在`async fn`中完全适用，和普通函数一样优雅。

## 常见陷阱与易错点

**陷阱1：忘记`.await`，Future根本不执行**

```rust
async fn do_work() {
    fetch_post(1);  // 编译器警告：未使用的Future
    // 正确：fetch_post(1).await;
}
```

**陷阱2：在异步代码中调用`std::thread::sleep`**

```rust
// 错误：这会阻塞整个tokio工作线程！
async fn bad_sleep() {
    std::thread::sleep(Duration::from_secs(1)); // 阻塞所有并发任务
}
// 正确：
async fn good_sleep() {
    tokio::time::sleep(Duration::from_secs(1)).await;
}
```

**陷阱3：在异步上下文里用同步I/O**
`std::fs`、`std::net`的同步操作会阻塞工作线程。应该用`tokio::fs`、`tokio::net`，或者用`spawn_blocking`包装。

---

## 小结

- Rust的异步基于`Future` trait，是一种零成本抽象
- `async fn`返回`impl Future`，调用时不立即执行，需要`.await`驱动
- `tokio`是最流行的异步运行时，用`#[tokio::main]`快速启动
- 同步与异步的边界用`block_on`（同步→异步）和`spawn_blocking`（异步→同步）处理
- 在异步上下文中必须使用异步版本的I/O操作，避免阻塞工作线程
