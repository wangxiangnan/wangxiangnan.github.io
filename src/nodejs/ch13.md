# 第13章：错误处理与调试——让 Bug 无处遁形

## 引言：Bug 是程序员最好的老师

有人说，编程就是两件事：写 bug 和修 bug。

好的错误处理就像好的保险——平时觉得多余，出事了才知道重要。一个没有错误处理的 Node.js 服务器，就像一辆没有安全带的跑车——快是快，但一撞就完。

在这一章，我们不仅要学会"怎么抓虫"，更要学会"怎么设计一个虫子无处藏身的系统"。

## 13.1 Node.js 错误类型

### 系统错误（System Errors）

操作系统层面的错误，通常与 I/O 操作相关：

```javascript
import { readFile } from 'node:fs/promises';

try {
  await readFile('/不存在的文件.txt');
} catch (err) {
  console.log(err.code);    // 'ENOENT' (Error NO ENTry)
  console.log(err.syscall); // 'open'
  console.log(err.path);    // '/不存在的文件.txt'
  console.log(err.errno);   // -2
}
```

常见系统错误码：

| 错误码 | 含义 | 场景 |
| -------- | ------ | ------ |
| ENOENT | 文件/目录不存在 | readFile 找不到文件 |
| EACCES | 权限不足 | 无法读写文件 |
| EADDRINUSE | 地址已占用 | 端口被其他进程占用 |
| ECONNREFUSED | 连接被拒绝 | 目标服务器没有在监听 |
| ECONNRESET | 连接被重置 | 对方强制关闭了连接 |
| ETIMEDOUT | 操作超时 | 网络请求超时 |
| EMFILE | 打开文件数过多 | 文件描述符耗尽 |
| EPERM | 操作不允许 | 试图做没权限的操作 |

### 用户错误（Application Errors）

你的代码逻辑产生的错误：

```javascript
// TypeError
const obj = null;
obj.property; // TypeError: Cannot read properties of null

// RangeError
new Array(-1); // RangeError: Invalid array length

// ReferenceError
console.log(undefinedVar); // ReferenceError: undefinedVar is not defined

// SyntaxError（通常在 JSON.parse 时遇到）
JSON.parse('{invalid}'); // SyntaxError: Unexpected token i
```

### 断言错误（Assertion Errors）

```javascript
import { strict as assert } from 'node:assert';

// 断言失败会抛出 AssertionError
assert.equal(1 + 1, 3); // AssertionError: 2 == 3
assert.deepEqual({ a: 1 }, { a: 2 }); // AssertionError
```

## 13.2 同步 vs 异步错误处理

### 同步代码：try/catch

```javascript
// 同步错误处理很直接
function parseJSON(str: string): unknown {
  try {
    return JSON.parse(str);
  } catch (err) {
    if (err instanceof SyntaxError) {
      console.error('JSON 解析失败:', err.message);
      return null;
    }
    throw err; // 非预期的错误继续抛出
  }
}
```

### 异步代码：async/await + try/catch

```javascript
import { readFile } from 'node:fs/promises';

async function loadConfig(path: string) {
  try {
    const content = await readFile(path, 'utf8');
    return JSON.parse(content);
  } catch (err) {
    if (err.code === 'ENOENT') {
      console.log('配置文件不存在，使用默认配置');
      return getDefaultConfig();
    }
    if (err instanceof SyntaxError) {
      console.error('配置文件格式错误:', err.message);
      return getDefaultConfig();
    }
    throw err; // 未知错误继续传播
  }
}
```

### Promise 链的错误处理

```javascript
// async/await 方式（推荐）
try {
  const result = await step1();
  const data = await step2(result);
  const final = await step3(data);
} catch (err) {
  // 捕获任何一步的错误
  handleError(err);
}

// Promise.allSettled：不因一个失败而中断全部
const results = await Promise.allSettled([
  fetch('/api/users'),
  fetch('/api/orders'),
  fetch('/api/products'),
]);

for (const result of results) {
  if (result.status === 'fulfilled') {
    console.log('成功:', result.value);
  } else {
    console.error('失败:', result.reason);
  }
}
```

### 回调风格的错误处理

```javascript
import { readFile } from 'node:fs';

// 错误优先回调（Error-First Callback）
readFile('./file.txt', 'utf8', (err, data) => {
  if (err) {
    // 始终先检查 err！
    console.error('读取失败:', err.message);
    return;
  }
  console.log(data);
});
```

## 13.3 全局错误捕获

### uncaughtException：同步异常的最后防线

```javascript
process.on('uncaughtException', (err, origin) => {
  console.error('未捕获的异常!');
  console.error('错误:', err);
  console.error('来源:', origin);

  // 重要：记录日志后应该退出进程！
  // 因为此时程序状态可能已经不一致了
  gracefulShutdown().then(() => {
    process.exit(1);
  });
});

// 触发示例
setTimeout(() => {
  throw new Error('这是一个未被捕获的错误');
}, 1000);
```

**⚠️ 重要**：`uncaughtException` 触发后，程序应该**尽快退出**。因为此时：

- 内存可能已经泄漏
- 数据库连接可能处于不一致状态
- 文件可能写到一半
继续运行可能导致数据损坏。

### unhandledRejection：未处理的 Promise 拒绝

```javascript
process.on('unhandledRejection', (reason, promise) => {
  console.error('未处理的 Promise 拒绝:');
  console.error('原因:', reason);
  // 从 Node.js 15 开始，未处理的 rejection 默认会导致进程退出
});

// 触发示例
async function failingTask() {
  throw new Error('异步错误');
}
failingTask(); // 没有 await，也没有 .catch()
```

### Node.js 15+ 的行为变化

```javascript
// Node.js 14 及之前：unhandledRejection 只是一个警告
// Node.js 15+：默认行为是抛出异常（与 uncaughtException 一样会终止进程）

// 如果你想恢复旧行为（不推荐）：
// node --unhandled-rejections=warn app.js
```

## 13.4 自定义 Error 类：业务错误体系

### 基础自定义错误

```typescript
// errors.ts

export class AppError extends Error {
  public readonly statusCode: number;
  public readonly code: string;
  public readonly isOperational: boolean;

  constructor(
    message: string,
    statusCode: number = 500,
    code: string = 'INTERNAL_ERROR',
    isOperational: boolean = true
  ) {
    super(message);
    this.name = this.constructor.name;
    this.statusCode = statusCode;
    this.code = code;
    this.isOperational = isOperational;

    // 修复 prototype 链（TypeScript 的 extends Error 需要这个）
    Object.setPrototypeOf(this, new.target.prototype);

    // 捕获干净的堆栈跟踪
    Error.captureStackTrace(this, this.constructor);
  }
}

// 具体的业务错误
export class NotFoundError extends AppError {
  constructor(resource: string, id: string) {
    super(`${resource} "${id}" 不存在`, 404, 'NOT_FOUND');
  }
}

export class ValidationError extends AppError {
  public readonly fields: Record<string, string>;

  constructor(fields: Record<string, string>) {
    const message = Object.entries(fields)
      .map(([field, error]) => `${field}: ${error}`)
      .join('; ');
    super(`数据验证失败: ${message}`, 400, 'VALIDATION_ERROR');
    this.fields = fields;
  }
}

export class AuthenticationError extends AppError {
  constructor(message = '未认证') {
    super(message, 401, 'UNAUTHORIZED');
  }
}

export class ForbiddenError extends AppError {
  constructor(message = '权限不足') {
    super(message, 403, 'FORBIDDEN');
  }
}

export class ConflictError extends AppError {
  constructor(message: string) {
    super(message, 409, 'CONFLICT');
  }
}

export class RateLimitError extends AppError {
  public readonly retryAfter: number;

  constructor(retryAfter: number = 60) {
    super(`请求过于频繁，请 ${retryAfter} 秒后重试`, 429, 'RATE_LIMITED');
    this.retryAfter = retryAfter;
  }
}
```

### 使用自定义错误

```typescript
import { NotFoundError, ValidationError } from './errors.js';

async function getUser(id: string) {
  const user = await db.findUser(id);
  if (!user) {
    throw new NotFoundError('用户', id);
  }
  return user;
}

async function createUser(data: any) {
  const errors: Record<string, string> = {};

  if (!data.email) errors.email = '邮箱不能为空';
  if (!data.name) errors.name = '姓名不能为空';
  if (data.age && data.age < 0) errors.age = '年龄不能为负数';

  if (Object.keys(errors).length > 0) {
    throw new ValidationError(errors);
  }

  return await db.createUser(data);
}
```

### 区分"可操作错误"和"程序错误"

```typescript
/**
 * 可操作错误（Operational Error）：
 * - 已预料到的、可以优雅处理的错误
 * - 例如：用户输入无效、网络超时、文件不存在
 * - 处理方式：返回合适的错误响应
 *
 * 程序错误（Programmer Error）：
 * - Bug！代码写错了
 * - 例如：传入了 undefined、类型错误、逻辑错误
 * - 处理方式：修复代码！运行时应该重启进程
 */

function handleError(err: unknown): void {
  if (err instanceof AppError && err.isOperational) {
    // 可操作错误：正常处理
    console.warn(`[可操作错误] ${err.code}: ${err.message}`);
    // 返回给客户端...
  } else {
    // 程序错误：记录后退出（让 PM2 重启）
    console.error('[致命错误] 非预期错误:', err);
    process.exit(1);
  }
}
```

### Pino：高性能结构化日志

```javascript
import pino from 'pino';

// 创建 logger
const logger = pino({
  level: process.env.LOG_LEVEL || 'info',
  // 开发环境格式化输出
  transport: process.env.NODE_ENV === 'development'
    ? { target: 'pino-pretty', options: { colorize: true } }

// 基本使用
logger.info('服务器启动');
logger.error({ err: new Error('出错了') }, '处理请求时出错');
logger.warn({ userId: '123' }, '用户尝试越权访问');

// 子 logger（带上下文）
const reqLogger = logger.child({

reqLogger.info('请求处理完成');
```


### Pino vs Winston

```javascript

    new winston.transports.File({ filename: 'error.log', level: 'error' }),
```

| 特性 | Pino | Winston |
| ------ | ------ | --------- |
| 性能 | 极快（5x faster） | 一般 |
| 输出格式 | JSON | 多种可选 |
| Transport | 独立进程 | 内置 |
| 生态 | 轻量 | 庞大 |
| 适合 | 高性能场景 | 需要丰富 transport |

**推荐**：新项目用 Pino。

## 13.7 链路追踪（Tracing）入门

### 什么是链路追踪？

在微服务架构中，一个用户请求可能经过多个服务：

```
用户 → API Gateway → 用户服务 → 数据库
                    → 订单服务 → 支付服务 → 银行 API
                    → 通知服务 → 邮件 API
```

如果出了错，你怎么知道是哪个环节出的问题？——**链路追踪**。

### 基本概念

```javascript
// 使用 OpenTelemetry（行业标准）
import { trace, context } from '@opentelemetry/api';

const tracer = trace.getTracer('my-service');

async function handleRequest(req) {
  // 创建一个 Span（追踪的基本单元）
  const span = tracer.startSpan('handle-request', {
    attributes: {
      'http.method': req.method,
      'http.url': req.url,
    },
  });

  try {
    // 子 Span
    const dbSpan = tracer.startSpan('database-query');
    const user = await db.query('SELECT * FROM users WHERE id = ?', [req.userId]);
    dbSpan.end();

    return user;
  } catch (err) {
    span.recordException(err);
    span.setStatus({ code: 2, message: err.message }); // ERROR
    throw err;
  } finally {
    span.end();
  }
}
```

### AsyncLocalStorage：请求上下文传递

```typescript
import { AsyncLocalStorage } from 'node:async_hooks';

interface RequestContext {
  requestId: string;
  userId?: string;
  startTime: number;
}

const asyncLocalStorage = new AsyncLocalStorage<RequestContext>();

// 获取当前上下文
export function getContext(): RequestContext | undefined {
  return asyncLocalStorage.getStore();
}

// 在中间件中设置上下文
function requestContextMiddleware(req, res, next) {
  const context: RequestContext = {
    requestId: req.headers['x-request-id'] || crypto.randomUUID(),
    userId: req.user?.id,
    startTime: Date.now(),
  };

  // 在这个回调的所有异步操作中，都能获取到 context
  asyncLocalStorage.run(context, () => {
    next();
  });
}

// 在任何地方获取请求上下文（无需手动传递！）
async function someDeepFunction() {
  const ctx = getContext();
  console.log(`[${ctx?.requestId}] 执行深层函数`);
}
```

## 13.8 实战：构建统一错误处理中间件

```typescript
import { createServer, IncomingMessage, ServerResponse } from 'node:http';
import { AppError, NotFoundError, ValidationError } from './errors.js';
import pino from 'pino';

const logger = pino({ level: 'info' });

// 错误响应格式
interface ErrorResponse {
  success: false;
  error: {
    code: string;
    message: string;
    details?: unknown;
    requestId?: string;
  };
}

/**
 * 统一错误处理器
 */
function handleError(
  err: unknown,
  req: IncomingMessage,
  res: ServerResponse,
  requestId: string
): void {
  let statusCode = 500;
  let errorResponse: ErrorResponse;

  if (err instanceof AppError) {
    // 可操作错误：返回具体信息
    statusCode = err.statusCode;
    errorResponse = {
      success: false,
      error: {
        code: err.code,
        message: err.message,
        requestId,
        ...(err instanceof ValidationError && { details: err.fields }),
      },
    };

    // 4xx 错误用 warn，5xx 用 error
    if (statusCode >= 500) {
      logger.error({ err, requestId, url: req.url }, '服务端错误');
    } else {
      logger.warn({ err, requestId, url: req.url }, '客户端错误');
    }
  } else {
    // 程序错误：不暴露内部细节给客户端
    errorResponse = {
      success: false,
      error: {
        code: 'INTERNAL_ERROR',
        message: '服务器内部错误',
        requestId,
      },
    };

    // 记录完整错误信息（供开发者排查）
    logger.fatal({ err, requestId, url: req.url }, '未预期的错误');
  }

  res.writeHead(statusCode, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify(errorResponse));
}

// 路由处理器类型
type RouteHandler = (
  req: IncomingMessage,
  res: ServerResponse
) => Promise<unknown>;

// 路由包装器：自动捕获错误
function wrapHandler(handler: RouteHandler): RouteHandler {
  return async (req, res) => {
    const requestId = crypto.randomUUID();
    res.setHeader('X-Request-Id', requestId);

    try {
      const result = await handler(req, res);

      if (!res.headersSent) {
        res.writeHead(200, { 'Content-Type': 'application/json' });
        res.end(JSON.stringify({ success: true, data: result, requestId }));
      }
    } catch (err) {
      handleError(err, req, res, requestId);
    }
  };
}

// ====== 使用示例 ======

const routes: Record<string, RouteHandler> = {
  'GET /users': async (req, res) => {
    return [{ id: 1, name: 'Alice' }];
  },

  'GET /users/:id': async (req, res) => {
    const id = req.url?.split('/')[2];
    if (!id) throw new ValidationError({ id: 'ID 不能为空' });

    const user = await findUser(id); // 可能抛 NotFoundError
    return user;
  },

  'POST /users': async (req, res) => {
    const body = await parseBody(req);

    if (!body.email) {
      throw new ValidationError({ email: '邮箱不能为空' });
    }

    return await createUser(body);
  },
};

const server = createServer(async (req, res) => {
  const routeKey = `${req.method} ${req.url}`;
  const handler = routes[routeKey];

  if (!handler) {
    handleError(
      new NotFoundError('路由', `${req.method} ${req.url}`),
      req,
      res,
      crypto.randomUUID()
    );
    return;
  }

  await wrapHandler(handler)(req, res);
});

server.listen(3000, () => {
  logger.info('服务器启动在端口 3000');
});

// 全局未捕获错误处理
process.on('uncaughtException', (err) => {
  logger.fatal({ err }, '未捕获的异常，即将退出');
  gracefulShutdown(server).then(() => process.exit(1));
});

process.on('unhandledRejection', (reason) => {
  logger.fatal({ err: reason }, '未处理的 Promise 拒绝');
  // Node.js 15+ 会自动退出
});

// 优雅关闭
async function gracefulShutdown(server: any): Promise<void> {
  return new Promise((resolve) => {
    server.close(() => {
      logger.info('HTTP 服务器已关闭');
      // 关闭数据库连接等...
      resolve();
    });

    // 超时强制退出
    setTimeout(() => {
      logger.error('优雅关闭超时，强制退出');
      resolve();
    }, 10000);
  });
}

// 辅助函数
async function parseBody(req: IncomingMessage): Promise<any> {
  return new Promise((resolve, reject) => {
    const chunks: Buffer[] = [];
    req.on('data', (chunk) => chunks.push(chunk));
    req.on('end', () => {
      try {
        resolve(JSON.parse(Buffer.concat(chunks).toString()));
      } catch {
        reject(new ValidationError({ body: '请求体不是有效的 JSON' }));
      }
    });
    req.on('error', reject);
  });
}

async function findUser(id: string) {
  // 模拟数据库查询
  if (id === '999') throw new NotFoundError('用户', id);
  return { id, name: 'Test User' };
}

async function createUser(data: any) {
  return { id: '1', ...data };
}
```

## 13.9 Node.js 20+ diagnostics_channel

`diagnostics_channel` 是 Node.js 内置的诊断工具，允许你在不修改源代码的情况下进行监控：

```javascript
import diagnostics_channel from 'node:diagnostics_channel';

// 创建诊断通道
const channel = diagnostics_channel.channel('my-app:requests');

// 在应用代码中发布诊断信息
function handleRequest(req) {
  channel.publish({
    method: req.method,
    url: req.url,
    timestamp: Date.now(),
  });
  // ... 处理请求
}

// 在监控代码中订阅（可以是独立的模块/插件）
diagnostics_channel.subscribe('my-app:requests', (message, name) => {
  console.log(`[诊断] ${name}:`, message);
  // 发送到监控系统...
});
```

### 监听 Node.js 内置事件

```javascript
import diagnostics_channel from 'node:diagnostics_channel';

// 监听所有 HTTP 请求（Node.js 20+）
diagnostics_channel.subscribe('http.client.request.start', (message) => {
  console.log('HTTP 请求开始:', message.request.method, message.request.path);
});

diagnostics_channel.subscribe('http.client.response.finish', (message) => {
  console.log('HTTP 响应完成:', message.response.statusCode);
});

// 监听 Net 连接
diagnostics_channel.subscribe('net.client.socket', (message) => {
  console.log('TCP 连接:', message.socket.remoteAddress);
});

// TracingChannel（Node.js 20+）
import { tracingChannel } from 'node:diagnostics_channel';

const dc = tracingChannel('my-app:db');

// 使用 tracing channel 自动追踪异步操作
async function dbQuery(sql: string) {
  return dc.tracePromise(async () => {
    // 执行数据库查询
    return await database.query(sql);
  }, { sql });
}

// 订阅追踪事件
dc.subscribe({
  start(message) {
    console.log('查询开始:', message.sql);
  },
  end(message) {
    console.log('查询完成');
  },
  asyncStart(message) {
    console.log('异步阶段开始');
  },
  error(message) {
    console.error('查询错误:', message.error);
  },
});
```

## 13.10 常见坑点

### 坑1：吞掉错误

```javascript
// ❌ 捕获了错误但什么都不做（"吞掉"错误）
try {
  await riskyOperation();
} catch (err) {
  // 空的 catch 块！Bug 永远不会被发现
}

// ✅ 至少记录日志
try {
  await riskyOperation();
} catch (err) {
  logger.error({ err }, '操作失败');
  // 决定：重试？返回默认值？重新抛出？
}
```

### 坑2：过度捕获

```javascript
// ❌ 在最外层包了一个巨大的 try/catch
async function handleRequest(req, res) {
  try {
    // 几百行代码...
    // 所有的错误都被一个 catch 处理，无法精确定位
  } catch (err) {
    res.status(500).send('出错了');
  }
}

// ✅ 精确捕获，让不同类型的错误有不同的处理方式
async function handleRequest(req, res) {
  let user;
  try {
    user = await getUser(req.userId);
  } catch (err) {
    if (err instanceof NotFoundError) {
      return res.status(404).json({ error: '用户不存在' });
    }
    throw err; // 其他错误继续传播
  }

  // ... 后续逻辑
}
```

### 坑3：错误信息泄露

```javascript
// ❌ 把内部错误详情暴露给客户端
app.use((err, req, res, next) => {
  res.status(500).json({
    error: err.message,
    stack: err.stack,  // 暴露了代码路径和内部结构！
  });
});

// ✅ 生产环境只返回通用错误信息
app.use((err, req, res, next) => {
  // 记录详细错误（内部使用）
  logger.error({ err, req: { method: req.method, url: req.url } });

  // 返回安全的错误信息给客户端
  const isDev = process.env.NODE_ENV === 'development';
  res.status(err.statusCode || 500).json({
    error: err.isOperational ? err.message : '服务器内部错误',
    ...(isDev && { stack: err.stack }), // 只在开发环境返回堆栈
  });
});
```

### 坑4：EventEmitter 中的异步错误

```javascript
// ❌ EventEmitter 不会自动处理异步监听器中的错误
emitter.on('event', async () => {
  throw new Error('异步错误'); // 变成 unhandledRejection！
});

// ✅ 手动 try/catch
emitter.on('event', async () => {
  try {
    await riskyAsyncOperation();
  } catch (err) {
    emitter.emit('error', err);
  }
});

// ✅ 或者使用 events.on() + for await
import { on } from 'node:events';

try {
  for await (const [data] of on(emitter, 'event')) {
    await riskyAsyncOperation(data);
  }
} catch (err) {
  // 错误在这里被安全捕获
}
```

### 坑5：忽略异步操作的返回值

```javascript
// ❌ 忘记 await！错误会变成 unhandledRejection
async function processItems(items) {
  items.forEach(async (item) => {
    await processItem(item); // forEach 不会等待这些 Promise！
  });
  // 这里会立即执行，processItem 可能还没完成
}

// ✅ 用 for...of 或 Promise.all
async function processItems(items) {
  // 串行
  for (const item of items) {
    await processItem(item);
  }

  // 或并行
  await Promise.all(items.map(item => processItem(item)));
}
```

## 13.12 本章小结

| 场景 | 推荐做法 |
| ------ | --------- |
| 同步错误 | try/catch |
| 异步错误 | async/await + try/catch |
| 全局未捕获 | uncaughtException → 记录日志 → 退出 |
| 全局未处理 Promise | unhandledRejection → 同上 |
| 业务错误 | 自定义 Error 类继承体系 |
| 日志 | Pino（高性能）/ Winston（功能全） |
| 调试 | --inspect + Chrome DevTools |
| 链路追踪 | OpenTelemetry + AsyncLocalStorage |
| 诊断 | diagnostics_channel |

**错误处理的哲学**：

1. **不要吞掉错误**——至少记录日志
2. **区分可操作错误和程序错误**——前者优雅处理，后者快速失败
3. **不要暴露内部信息给客户端**——安全第一
4. **让错误可追踪**——requestId + 链路追踪
5. **优雅降级**——出错了也要给用户一个合理的响应
6. **设计"防御性代码"**——在可能出错的地方预判并处理

> "真正的高手不是从来不出 bug，而是出了 bug 能最快定位和修复。"
