每位开发者都有过这样的经历：代码写完了，运行报错，你盯着屏幕看了二十分钟，加了一堆 `console.log`，然后发现——是少写了一个等号。如果你有更好的调试工具，这二十分钟本可以缩短到二十秒。

## 9.1 调试架构：DAP 的故事

VSCode 的调试系统基于 **Debug Adapter Protocol（DAP）**。如果你知道 LSP（Language Server Protocol）让编辑器与语言解耦，那 DAP 就是调试领域的 LSP——它让 VSCode 的调试 UI 与具体的调试器解耦。

```
┌──────────────┐     DAP      ┌────────────────┐     原生协议    ┌──────────┐
│   VSCode     │ <─────────> │ Debug Adapter  │ <────────────> │ Debugger │
│  (UI 层)     │   JSON-RPC  │ (适配层/翻译层) │                │ (底层)   │
└──────────────┘             └────────────────┘                └──────────┘
```

这意味着：

- Node.js 用 V8 Inspector 调试
- Python 用 debugpy 调试
- Go 用 Delve 调试
- Java 用 JDI 调试

但对 VSCode 来说，它们都是同一种"语言"——DAP 消息。这就是为什么 VSCode 能以统一的 UI 调试如此多不同的语言。

## 9.2 launch.json：调试配置详解

调试配置文件位于 `.vscode/launch.json`。通过 `Ctrl+Shift+P`（⌘+Shift+P）→ **Debug: Open launch.json** 创建。

一个典型的 Node.js 调试配置：

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Launch Node.js App",
            "type": "node",
            "request": "launch",
            "program": "${workspaceFolder}/src/index.js",
            "args": ["--port", "3000"],
            "cwd": "${workspaceFolder}",
            "env": {
                "NODE_ENV": "development",
                "DEBUG": "app:*"
            },
            "console": "integratedTerminal",
            "skipFiles": [
                "<node_internals>/**",
                "**/node_modules/**"
            ],
            "sourceMaps": true,
            "outFiles": [
                "${workspaceFolder}/dist/**/*.js"
            ]
        }
    ]
}
```

## 核心属性解析

| 属性 | 说明 |
| ------ | ------ |
| `name` | 配置名称，显示在调试下拉菜单中 |
| `type` | 调试器类型（`node`、`python`、`go`、`java` 等） |
| `request` | `launch`（启动新进程）或 `attach`（附加到已运行进程） |
| `program` | 要调试的程序入口文件 |
| `args` | 程序参数 |
| `cwd` | 工作目录 |
| `env` | 环境变量 |
| `console` | 输出目标：`internalConsole`、`integratedTerminal`、`externalTerminal` |
| `skipFiles` | 调试时跳过的文件（如 node 内部模块、node_modules） |
| `sourceMaps` | 是否启用 Source Map（TypeScript/编译语言必需） |
| `preLaunchTask` | 调试前执行的任务（如先编译 TypeScript） |
| `postDebugTask` | 调试结束后执行的任务（如清理） |

## 常用变量

```json
{
    "program": "${workspaceFolder}/src/index.js",    // 工作区根目录
    "cwd": "${workspaceFolder}",
    "envFile": "${workspaceFolder}/.env",              // .env 文件路径
    "args": ["${input:serverPort}"],                   // 引用用户输入
    "python": "${command:python.interpreterPath}"       // 引用命令输出
}
```

完整变量列表：`${workspaceFolder}`、`${file}`（当前文件）、`${fileDirname}`（当前文件目录）、`${lineNumber}`（当前行号）、`${env:VAR}`（环境变量）等。

## 9.3 五种断点类型：精准定位的艺术

VSCode 支持五种断点类型，每种都有特定的使用场景。点击行号左侧的红点只是最基础的操作——让我们看看全部五种：

## 1. 普通断点（Breakpoint）

点击行号左侧，或 `F9`。最基本的"在这里暂停"。

## 2. 条件断点（Conditional Breakpoint）

右键行号 → **Add Conditional Breakpoint**。只有当条件为真时才暂停。

```javascript
// 只在特定用户的请求处暂停
req.user.id === 'admin-001'

// 只在数组长度异常时暂停
items.length > 1000

// 只在特定时间暂停（调试时间相关 bug）
new Date().getHours() === 14
```

## 3. 日志点（Logpoint / Message Breakpoint）

右键行号 → **Add Logpoint**。不暂停程序，只在调试控制台输出一条消息。这是 `console.log` 调试法的优雅替代——你不需要修改代码、不需要重新编译、不会忘记删除：

```javascript
// 基本消息
Processing request for user: {req.user.name}

// 带表达式的消息
Order total: {order.items.reduce((sum, item) => sum + item.price, 0)} USD

// 追踪函数调用
handlePayment called with amount={amount}, method={method}
```

注意花括号 `{}` 内是 JavaScript 表达式，会被求值。日志点消息会自动带上调用位置和时间戳。

## 4. 命中次数断点（Hit Count Breakpoint）

右键行号 → **Add Conditional Breakpoint** → 选择 **Hit Count**。在命中指定次数后暂停：

```
// 精确次数
hitCount == 10

// 大于等于
hitCount >= 100

// 取模（每10次暂停一次）
hitCount % 10 == 0
```

这在调试循环和递归时极为有用——你不需要在前 99 次循环中点"继续"。

## 5. 函数断点（Function Breakpoint）

在断点面板中点击 `+` → 输入函数名。当指定函数被调用时暂停，不需要知道函数在哪个文件：

```
// 暂停在函数入口
handleUserLogin

// 带条件
module.exports.processPayment
```

## 9.4 调试面板：你的调试驾驶舱

调试界面由几个核心面板组成，它们通常位于左侧活动栏或调试侧边栏中：

## 变量面板（Variables）

显示当前作用域内的所有变量。分为：

- **Local**：当前函数的局部变量
- **Closure**：闭包捕获的变量
- **Global**：全局变量（通常折叠，内容极多）

你可以：

- 点击变量查看/修改值（**Set Variable**）
- 右键 → **Add to Watch** 添加到监视面板
- 右键 → **Copy Value** 复制值
- 右键 → **Break on Value Change**（如果调试器支持）

## 监视面板（Watch）

你可以添加任意表达式，调试器会在每次暂停时自动求值：

```javascript
// 监视简单变量
user.isAuthenticated

// 监视计算表达式
cart.items.length * cart.taxRate

// 监视函数返回值（注意：可能有副作用！）
JSON.stringify(config, null, 2)

// 监视类型
typeof response.data

// 监视数组操作
users.filter(u => u.role === 'admin').map(u => u.name)
```

## 调用堆栈（Call Stack）

显示当前的函数调用链。你可以：

- 点击堆栈中的任何一帧，跳转到对应的代码位置
- 查看每一帧的局部变量（即使不在当前帧）
- 识别递归深度和调用来源

## 断点面板（Breakpoints）

集中管理所有断点：

- 启用/禁用单个断点
- 删除断点
- 查看所有断点的文件位置
- 启用/禁用所有断点（全局开关）
- 导出断点列表

## 9.5 调试控制台：不仅仅是输出

调试控制台（Debug Console）是一个功能丰富的 REPL 环境。在调试暂停时，你可以在这里：

```javascript
// 求值表达式
> user.name
"Alice"

// 修改变量（临时，不影响原始逻辑流）
> user.role = "admin"

// 调用函数
> calculateTotal(cart.items)
1299.99

// 查看对象结构
> Object.keys(config)
["port", "host", "database", "secret"]

// 执行异步操作
> await fetch('/api/health').then(r => r.json())
{status: "ok", uptime: 86400}

// 使用调试器特定命令（Node.js）
> .help            // 显示可用命令
> process.memoryUsage()  // 查看内存使用
```

## 调试控制按钮

调试工具栏（通常在编辑器顶部）的按钮：

| 按钮 | 快捷键 | 功能 |
| ------ | -------- | ------ |
| Continue | `F5` | 继续运行到下一个断点 |
| Step Over | `F10` | 执行当前行，不进入函数内部 |
| Step Into | `F11` | 进入函数内部 |
| Step Out | `Shift+F11`（⇧+F11） | 跳出当前函数 |
| Restart | `Ctrl+Shift+F5`（⌘+⇧+F5） | 重启调试 |
| Stop | `Shift+F5`（⇧+F5） | 停止调试 |

## 9.6 实战：Express.js 项目完整调试配置

让我们为一个真实的 Express + TypeScript 项目配置完整的调试环境。

项目结构：

```
express-app/
├── .vscode/
│   ├── launch.json
│   └── tasks.json
├── src/
│   ├── index.ts
│   ├── routes/
│   │   ├── users.ts
│   │   └── products.ts
│   ├── middleware/
│   │   └── auth.ts
│   └── services/
│       └── database.ts
├── tsconfig.json
└── package.json
```

## tsconfig.json

```json
{
    "compilerOptions": {
        "target": "ES2020",
        "module": "commonjs",
        "outDir": "./dist",
        "rootDir": "./src",
        "sourceMap": true,
        "strict": true,
        "esModuleInterop": true
    }
}
```

注意 `"sourceMap": true` 是调试 TypeScript 的关键——没有它，断点会打到编译后的 JS 上，完全对不上源码。

## launch.json

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Debug Express (TS-Node)",
            "type": "node",
            "request": "launch",
            "runtimeExecutable": "node",
            "runtimeArgs": [
                "--require", "ts-node/register",
                "--inspect-brk",
                "${workspaceFolder}/src/index.ts"
            ],
            "cwd": "${workspaceFolder}",
            "console": "integratedTerminal",
            "env": {
                "NODE_ENV": "development",
                "PORT": "3000",
                "TS_NODE_TRANSPILE_ONLY": "true"
            },
            "skipFiles": [
                "<node_internals>/**"
            ]
        },
        {
            "name": "Debug Express (Compiled JS)",
            "type": "node",
            "request": "launch",
            "program": "${workspaceFolder}/dist/index.js",
            "preLaunchTask": "compile",
            "sourceMaps": true,
            "outFiles": [
                "${workspaceFolder}/dist/**/*.js"
            ],
            "console": "integratedTerminal",
            "skipFiles": [
                "<node_internals>/**"
            ]
        },
        {
            "name": "Attach to Running Process",
            "type": "node",
            "request": "attach",
            "port": 9229,
            "restart": true,
            "skipFiles": [
                "<node_internals>/**"
            ]
        },
        {
            "name": "Jest Current File",
            "type": "node",
            "request": "launch",
            "program": "${workspaceFolder}/node_modules/.bin/jest",
            "args": [
                "${relativeFile}",
                "--runInBand",
                "--no-cache"
            ],
            "console": "integratedTerminal",
            "skipFiles": [
                "<node_internals>/**"
            ]
        }
    ]
}
```

## tasks.json（调试前自动编译）

```json
{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "compile",
            "type": "shell",
            "command": "npx tsc -p tsconfig.json",
            "group": "build",
            "problemMatcher": ["$tsc"],
            "presentation": {
                "reveal": "silent"
            }
        }
    ]
}
```

## 调试工作流

1. 在代码中设置断点（比如在 `routes/users.ts` 的路由处理函数中）
2. 选择 **Debug Express (TS-Node)** 配置
3. 按 `F5` 启动调试
4. 用浏览器或 Postman 发送请求到 `http://localhost:3000/api/users`
5. 断点命中，检查 `req`、`res`、数据库查询结果
6. 使用 Step Over/Into 逐步跟踪请求处理流程
7. 在调试控制台中测试不同的响应格式

## 9.7 进阶：调试工具栏自定义

VSCode 允许你自定义调试行为的一些方面：

```json
{
    // settings.json
    // 调试时显示内联变量值
    "debug.inlineValues": "on",

    // 调试时自动打开变量面板
    "debug.openDebug": "openOnSessionStart",

    // 调试时显示内部变量（以 __ 开头的）
    "debug.showInlineBreakpointCandidates": true,

    // 调试控制台的字体和行高
    "debug.console.fontSize": 14,
    "debug.console.lineHeight": 22,

    // 调试控制台中的换行
    "debug.console.wordWrap": true,

    // 断点悬浮提示
    "debug.toolBarLocation": "docked"  // floating | docked | commandCenter | hidden
}
```

## 使用 VS Code 的 "Debug: Evaluate" 代码片段

在调试控制台里，你甚至可以使用多行表达式来快速测试逻辑：

```javascript
// 快速测试数据转换
(() => {
    const data = [1, 2, 3, 4, 5];
    return data
        .filter(n => n % 2 === 0)
        .map(n => n * 10);
})()
// → [20, 40]
```

📋 **本章小结**

- VSCode 调试基于 **DAP（Debug Adapter Protocol）**，统一了不同语言的调试体验
- `launch.json` 是调试配置的蓝图，`launch` 和 `attach` 是两种核心请求模式
- 五种断点类型（普通/条件/日志点/命中次数/函数）覆盖了几乎所有调试场景
- **调试控制台**是功能完整的 REPL，支持表达式求值和异步操作
- TypeScript 调试必须启用 `sourceMap`，否则断点位置会错乱
- `preLaunchTask` 可以在调试前自动执行编译等准备工作
