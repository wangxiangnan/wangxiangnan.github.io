# 第3章 Prompt Engineering — 给 Agent 写"需求文档"

## 3.1 开篇

同一 LLM，不同 Prompt，产出天差地别。Prompt = Agent 的**需求文档（PRD）**。

---

## 3.2 三层框架

```
Layer 1: System Message — Agent是谁、能做什么
Layer 2: Few-shot — 例子教怎么回答
Layer 3: CoT — 引导思考方式
```

---

## 3.3 System Prompt — Agent 的"人设配置文件"

System Prompt 就像是一个函数的 `docstring + type hints + decorators` — 它定义了 Agent 的身份、能力边界和行为规范。

### 反面教材：模糊的 System Prompt

```python
BAD = "你是有帮助的AI助手。"
# 问题：
# 1. "有帮助"太模糊 — 什么叫有帮助？回答长还是短？技术还是通俗？
# 2. "AI助手"无边界 — 可以回答任何问题，包括它不擅长的
# 3. 无行为规范 — 可能编造信息、用"作为AI..."开头、回答过长或过短
# 类比：def func(x): pass  # 没有docstring、没有type hints、不知道做什么
```

### 正面教材：精确的 System Prompt

```python
GOOD = """你是 DocMind，Python后端和DevOps文档助手。

## 角色定位
- 身份：经验丰富的技术 Team Lead，擅长用通俗语言解释复杂概念
- 目标用户：1-5年经验的后端开发者
- 专业领域：Python / FastAPI / Docker / Kubernetes / PostgreSQL / Redis

## 能力边界
可以做：
- 解释技术概念（附代码示例）
- 排查常见错误（给出排查步骤）
- 比较技术方案（表格对比）
- 提供最佳实践建议
不可以做：
- 前端开发问题 → 推荐 MDN 或 React 官方文档
- 非技术领域 → 礼貌拒绝并引导回技术领域
- 未经验证的库/API → 标注 [UNCERTAIN]

## 输出规范
- 格式：Markdown，使用 **粗体** 标注核心概念
- 长度：简单问题 <100字，概念解释 100-300字，排查指南 300-500字
- 结构：先 TL;DR 总结，再详细展开
- 代码：必须有注释，使用 Python 3.11+ 语法
- 不确定时：标注 [UNCERTAIN]，不要编造

## 禁止行为
- 不要编造不存在的库、API、命令
- 不要用"作为AI..."开头
- 不要给出无法验证的性能数字
- 不要推荐已废弃的工具"""
```

### System Prompt 设计原则对照表

| 原则 | 类比 | 示例 |
| ------ | ------ | ------ |
| 精确角色 | 函数 docstring | "你是DocMind，Python后端文档助手" vs "你是AI助手" |
| 能力边界 | 类型注解 | "可以做X，不可以做Y" vs "尽量帮忙" |
| 行为规范 | API 文档 | "简单<100字，复杂<500字" vs "回答要合适" |
| 可测试 | assert | "不确定标注[UNCERTAIN]" vs "要诚实" |
| 结构化 | JSON Schema | 用标题/列表分隔，不是一坨文本 |

### 进阶技巧：动态 System Prompt

```python
def build_system_prompt(user_level: str, context: str) -> str:
    """根据用户水平和上下文动态生成 System Prompt"""
    base = """你是 DocMind，智能技术文档助手。
## 核心原则
- 用编程隐喻解释概念
- 代码示例必须有注释
- 不确定时标注 [UNCERTAIN]
"""
    
    # 根据用户水平调整深度
    level_config = {
        "junior": """
## 用户水平：初级（0-1年）
- 解释要通俗，避免过多术语
- 每个概念先给"一句话总结"
- 代码示例要简单，避免高级特性
- 多用类比：Redis ≈ Python dict（但持久化）
""",
        "mid": """
## 用户水平：中级（1-3年）
- 可以用术语，但要解释关键概念
- 代码示例可以用装饰器、async等中级特性
- 关注"为什么"而不仅是"怎么做"
""",
        "senior": """
## 用户水平：高级（3年+）
- 直接用术语，无需解释基础概念
- 代码示例可以用高级特性（metaclass、descriptor等）
- 关注性能、架构、权衡取舍
- 可以讨论设计哲学和trade-off
"""
    }
    
    # 根据上下文调整重点
    context_config = {
        "debug": "## 当前模式：问题排查\n- 给出系统化排查步骤\n- 优先检查常见原因",
        "learn": "## 当前模式：概念学习\n- 先给直觉理解，再深入细节\n- 附代码示例帮助理解",
        "compare": "## 当前模式：方案对比\n- 用表格对比\n- 给出推荐方案和理由"
    }
    
    return base + level_config.get(user_level, level_config["mid"]) + \
           context_config.get(context, context_config["learn"])

# 使用
junior_debug = build_system_prompt("junior", "debug")
senior_compare = build_system_prompt("senior", "compare")
print("=== Junior Debug Mode ===")
print(junior_debug[:200] + "...")
print("\n=== Senior Compare Mode ===")
print(senior_compare[:200] + "...")
```

> ⚠️ **常见坑**：System Prompt 太长（>2000 tokens）会导致：
>
> 1. 每次请求都多花钱（按 token 计费）
> 2. 占用 Context Window，留给对话历史的空间变少
> 3. LLM 可能"忘记"后面的指令（Lost in the Middle 问题）
>
> **解决方案**：
>
> - 精简措辞，删除冗余
> - 只保留核心规则，细节用 Few-shot 教
> - 定期 review，删除不再需要的规则

## 3.4 Few-shot — 用例子"教"Agent

Few-shot 就像是给函数写单元测试 — 通过几个精选示例，让 LLM 理解你想要的输入→输出映射。

### 为什么 Few-shot 有效？

```python
# Zero-shot（无示例）— LLM 猜测你想要什么
prompt_zero = "分类这个技术问题：FastAPI JWT?"
# 可能输出："这是一个关于身份验证的问题" ← 太泛

# Few-shot（有示例）— LLM 精确模仿你的格式
prompt_few = """分类技术问题，输出格式：分类:X/Y 难度:初级/中级/高级 标签:A,B,C

示例1
输入: FastAPI JWT?
输出: 分类:Web/认证 难度:中级 标签:FastAPI,JWT,Security

示例2
输入: Docker DNS?
输出: 分类:DevOps/容器 难度:中级 标签:Docker,DNS,网络

示例3
输入: Redis RDB vs AOF?
输出: 分类:DB/缓存 难度:初级 标签:Redis,持久化,配置

请处理:
输入: K8s HPA?
输出:"""
# 输出："分类:DevOps/编排 难度:高级 标签:Kubernetes,HPA,自动扩缩" ← 精确！
```

### Few-shot 基础实现

```python
from openai import OpenAI
import os

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

def few_shot_classify(question: str, examples: list[dict]) -> str:
    """Few-shot 分类器"""
    messages = [
        {"role": "system", "content": "你是技术问题分类专家。根据示例格式输出。"},
        {"role": "user", "content": "分类技术问题，输出格式：分类:X/Y 难度:初级/中级/高级 标签:A,B,C"}
    ]
    
    # 添加示例（Few-shot）
    for i, ex in enumerate(examples, 1):
        messages.append({"role": "user", "content": f"输入: {ex['in']}"})
        messages.append({"role": "assistant", "content": f"输出: {ex['out']}"})
    
    # 添加待分类问题
    messages.append({"role": "user", "content": f"输入: {question}\n输出:"})
    
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages,
        temperature=0,  # 确定性输出
        max_tokens=100
    )
    return response.choices[0].message.content

# 精选示例（覆盖不同类别）
examples = [
    {"in": "FastAPI JWT?", "out": "分类:Web/认证 难度:中级 标签:FastAPI,JWT,Security"},
    {"in": "Docker DNS?", "out": "分类:DevOps/容器 难度:中级 标签:Docker,DNS,网络"},
    {"in": "Redis RDB vs AOF?", "out": "分类:DB/缓存 难度:初级 标签:Redis,持久化,配置"},
    {"in": "Python装饰器?", "out": "分类:Python/语法 难度:中级 标签:Python,装饰器,函数"},
    {"in": "PostgreSQL索引?", "out": "分类:DB/性能 难度:高级 标签:PostgreSQL,索引,查询优化"},
]

# 测试
test_questions = [
    "K8s HPA?",
    "Celery任务队列?",
    "Nginx反向代理?",
    "Python GIL?"
]

for q in test_questions:
    result = few_shot_classify(q, examples)
    print(f"问题: {q}")
    print(f"结果: {result}\n")
```

### Few-shot 进阶：动态选择示例

```python
from difflib import SequenceMatcher

def similarity(a: str, b: str) -> float:
    """计算两个字符串的相似度"""
    return SequenceMatcher(None, a, b).ratio()

def dynamic_few_shot(question: str, all_examples: list[dict], k: int = 3) -> str:
    """动态选择最相关的 k 个示例"""
    # 按相似度排序
    scored = [(ex, similarity(question, ex['in'])) for ex in all_examples]
    scored.sort(key=lambda x: x[1], reverse=True)
    
    # 选择 top-k
    selected = [ex for ex, _ in scored[:k]]
    
    # 调用 LLM
    return few_shot_classify(question, selected)

# 示例库（可以很大）
example_bank = [
    {"in": "FastAPI JWT?", "out": "分类:Web/认证 难度:中级 标签:FastAPI,JWT"},
    {"in": "Docker DNS?", "out": "分类:DevOps/容器 难度:中级 标签:Docker,DNS"},
    {"in": "Redis持久化?", "out": "分类:DB/缓存 难度:初级 标签:Redis,持久化"},
    {"in": "K8s Service?", "out": "分类:DevOps/编排 难度:中级 标签:K8s,Service"},
    {"in": "Python GIL?", "out": "分类:Python/并发 难度:高级 标签:Python,GIL"},
    {"in": "PostgreSQL索引?", "out": "分类:DB/性能 难度:高级 标签:PostgreSQL,索引"},
    {"in": "Nginx负载均衡?", "out": "分类:Web/代理 难度:中级 标签:Nginx,负载均衡"},
    {"in": "Celery任务?", "out": "分类:Python/异步 难度:中级 标签:Celery,任务队列"},
    # ... 可以有几十个示例
]

# 动态选择最相关的
print(dynamic_few_shot("Docker网络模式?", example_bank, k=3))
# 会自动选择 Docker 相关的示例，而不是随机选
```

### Few-shot 最佳实践

```python
# ✅ 正确做法
good_practices = {
    "质量>数量": "3个精选示例 > 10个随意示例",
    "覆盖边界": "包含正常/异常/边界情况的示例",
    "格式一致": "所有示例输入输出格式完全一致",
    "多样性": "示例覆盖不同类别，避免偏见",
    "简洁": "示例输入不要太长，避免占用过多 token"
}

# ❌ 常见错误
bad_practices = {
    "太少": "只有1个示例 → LLM可能过拟合这个特例",
    "太偏": "全是简单示例 → 复杂问题处理不好",
    "格式乱": "示例1用JSON，示例2用YAML → LLM困惑",
    "太长": "每个示例100行 → token爆炸",
    "无边界": "没有展示"不应该做什么" → LLM可能越界"
}

# 示例：展示"不应该做什么"
negative_examples = [
    {"in": "今天天气怎么样?", "out": "[OUT_OF_SCOPE] 我只回答技术问题"},
    {"in": "帮我写个Python脚本", "out": "[OUT_OF_SCOPE] 我只分类问题，不生成代码"},
]
```

> ⚠️ **Few-shot 的 token 成本**：
>
> - 每个示例大约 50-200 tokens（输入+输出）
> - 5个示例 ≈ 250-1000 tokens
> - 每次请求都会带上这些示例 → 累积成本
>
> **优化策略**：
>
> 1. 示例尽量简洁（输入<20字，输出<30字）
> 2. 动态选择（只选最相关的 2-3 个）
> 3. 缓存常用示例（避免重复构建）

## 3.5 Chain-of-Thought (CoT) — 让 Agent "写注释"思考

CoT 就像是让程序员在写代码前先写伪代码/注释 — 强制分步思考，避免跳步出错。

### 为什么 CoT 有效？

```python
# 无 CoT — LLM 直接给答案（像不看题直接猜答案）
question = "一个FastAPI服务有3个endpoint，每个endpoint平均处理2个数据库查询，" \
           "每个查询50ms，网络延迟10ms，求总延迟"

# 直接问（可能出错）
direct = f"{question} 总延迟是多少？"
# LLM 可能输出："约 300ms" ← 跳步了，可能算错

# 用 CoT（强制分步）
cot = f"""{question}

让我们一步一步计算：
1. 首先，计算单个 endpoint 的延迟
2. 然后，考虑并发情况
3. 最后，给出总延迟"""
# LLM 输出：
# "1. 单endpoint: 2查询×50ms + 10ms网络 = 110ms
#  2. 3个endpoint并发: max(110ms, 110ms, 110ms) = 110ms
#  3. 如果是串行: 3×110ms = 330ms
#  总延迟: 并发110ms，串行330ms" ← 更准确！
```

### CoT 实现：手动引导

```python
from openai import OpenAI
import os

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

def solve_with_cot(question: str, steps: list[str]) -> str:
    """用显式步骤引导 CoT"""
    step_text = "\n".join(f"{i+1}. {s}" for i, s in enumerate(steps))
    
    prompt = f"""{question}

请按以下步骤分析：
{step_text}

最后给出答案。"""
    
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "你是技术专家，擅长分步分析问题。"},
            {"role": "user", "content": prompt}
        ],
        temperature=0,
        max_tokens=1000
    )
    return response.choices[0].message.content

# 使用
result = solve_with_cot(
    "PostgreSQL 查询从 100ms 变慢到 5s，可能原因？",
    steps=[
        "分析可能的原因（索引、查询、数据量、锁）",
        "对每个原因给出检查方法",
        "评估每个原因的可能性",
        "给出排查优先级和解决方案"
    ]
)
print(result)
```

### Zero-shot CoT — 一句话激活

```python
def zero_shot_cot(question: str) -> str:
    """用 magic phrase 激活 CoT（无需写步骤）"""
    # 关键句："让我们一步一步思考"（Let's think step by step）
    prompt = f"{question}\n\n让我们一步一步思考。"
    
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        temperature=0
    )
    return response.choices[0].message.content

# 对比效果
question = "Redis 和 Memcached 哪个更适合做会话存储？"

# 无 CoT
no_cot = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": question}],
    temperature=0
).choices[0].message.content

# 有 CoT
with_cot = zero_shot_cot(question)

print("=== 无 CoT ===")
print(no_cot[:200])
print("\n=== 有 CoT ===")
print(with_cot[:200])

# 研究数据：GSM8K 数学题
# 无 CoT: ~17% 准确率
# 有 CoT: ~79% 准确率（提升 4.6 倍！）
```

### Few-shot CoT — 示例+思考过程

```python
def few_shot_cot(question: str) -> str:
    """Few-shot + CoT：示例中包含思考过程"""
    messages = [
        {"role": "system", "content": "你是技术专家，分步分析问题。"},
        
        # 示例 1（包含完整思考过程）
        {"role": "user", "content": "Docker 容器 OOMKilled，怎么排查？"},
        {"role": "assistant", "content": """让我分步分析：

1. 理解问题：OOMKilled = Out of Memory Killed，容器内存超限被系统杀掉
2. 可能原因：
   - 容器 memory limit 设太低
   - 应用内存泄漏
   - 突发的内存峰值（比如大批量处理）
3. 排查步骤：
   - docker inspect 查看 memory limit
   - 检查应用日志，看是否有内存警告
   - 监控内存使用曲线，找峰值
4. 解决方案：
   - 调高 memory limit（治标）
   - 优化应用内存使用（治本）
   - 分批处理，避免峰值

建议：先用 docker stats 监控，确定是 limit 太低还是真的泄漏。"""},
        
        # 示例 2
        {"role": "user", "content": "FastAPI 接口响应慢（>2s），怎么优化？"},
        {"role": "assistant", "content": """让我分步分析：

1. 理解问题：接口响应慢，需要找出瓶颈
2. 可能瓶颈：
   - 数据库查询慢（最常见）
   - 同步阻塞操作（FastAPI 是异步的，但 sync def 会阻塞）
   - 外部 API 调用慢
   - CPU 密集计算
3. 排查步骤：
   - 用 middleware 记录每个阶段的耗时
   - 检查数据库查询（EXPLAIN ANALYZE）
   - 检查是否有 sync def 应该改成 async def
   - 用 cProfile 或 py-spy 做性能分析
4. 优化方案：
   - 数据库：加索引、优化查询、用连接池
   - 阻塞操作：改成 async 或用 run_in_executor
   - 外部API：加缓存、异步调用
   - CPU密集：用 ProcessPoolExecutor

建议：先加耗时日志，定位瓶颈，再针对性优化。"""},
        
        # 待分析问题
        {"role": "user", "content": f"{question}\n\n请分步分析。"}
    ]
    
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages,
        temperature=0
    )
    return response.choices[0].message.content

# 测试
print(few_shot_cot("Celery 任务堆积，Worker 处理不过来，怎么办？"))
```

### CoT 变体对比

| 变体 | 适用场景 | Token 成本 | 准确性 |
| ------ | ---------- | ----------- | -------- |
| Zero-shot CoT | 快速原型、简单问题 | 低 | 中（~79%） |
| Few-shot CoT | 复杂问题、需要特定格式 | 高 | 高（~90%+） |
| 手动步骤 CoT | 你知道该怎么分析 | 中 | 高（引导强） |
| Auto-CoT | 自动化场景 | 中 | 中高 |

> ⚠️ **CoT 的 trade-off**：
>
> - ✅ 提升准确性（尤其是数学、逻辑、多步推理）
> - ❌ 增加 token 消耗（思考过程也要钱）
> - ❌ 增加延迟（输出更长）
>
> **何时用 CoT**：
>
> - 多步推理（数学、逻辑）→ 必须用
> - 简单查询（概念解释）→ 不需要
> - 工具调用（Agent）→ 用 ReAct（CoT + Action）

## 3.6 ReAct — 推理 + 行动的完美结合

ReAct = **Re**asoning + **Act**ing，是 Agent 的核心思维模式。它把 CoT（思考）和 Tool Use（行动）结合成一个循环：

```
Thought: 分析问题，决定下一步
Action: 选择工具并执行
Observation: 观察工具返回结果
Thought: 根据结果继续分析
Action: ...
... (循环直到解决)
Final Answer: 给出最终答案
```

### ReAct 为什么重要？

```python
# 纯 CoT（只思考，不能行动）
# 问题："我的 Docker 容器端口 8080 被谁占用了？"
# 思考："端口被占用可能是 nginx、Apache、或其他服务..."
# ← 光想没用，需要真正去检查！
```

### ReAct 实战：DocMind 排查助手

```python
import subprocess
from typing import Callable

class SimpleReActAgent:
    """简化版 ReAct Agent（演示用，Part 2 会用 LangChain 实现完整版）"""
    
    def __init__(self, model: str = "gpt-4o-mini"):
        self.client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
        self.model = model
        self.tools = {}
    
    def register_tool(self, name: str, func: Callable, description: str):
        """注册工具"""
        self.tools[name] = {"func": func, "desc": description}
    
    def _build_system_prompt(self) -> str:
        """构建包含工具列表的 System Prompt"""
        tools_desc = "\n".join(f"- {name}: {info['desc']}" 
                               for name, info in self.tools.items())
        return f"""你是 DocMind，技术问题排查助手。

可用工具：
{tools_desc}

使用 ReAct 格式：
Thought: 分析
Action: 工具名
Action Input: 参数
Observation: (系统自动填写)
... (可重复)
Final Answer: 最终回答"""
    
    def run(self, question: str, max_steps: int = 5) -> str:
        """执行 ReAct 循环"""
        messages = [
            {"role": "system", "content": self._build_system_prompt()},
            {"role": "user", "content": question}
        ]
        
        for step in range(max_steps):
            response = self.client.chat.completions.create(
                model=self.model,
                messages=messages,
                temperature=0,
                stop=["Observation:"]  # 在 Observation 前停下
            )
            
            assistant_msg = response.choices[0].message.content
            messages.append({"role": "assistant", "content": assistant_msg})
            
            # 检查是否有 Final Answer
            if "Final Answer:" in assistant_msg:
                return assistant_msg.split("Final Answer:")[-1].strip()
            
            # 解析 Action
            if "Action:" in assistant_msg and "Action Input:" in assistant_msg:
                action = assistant_msg.split("Action:")[-1].split("\n")[0].strip()
                action_input = assistant_msg.split("Action Input:")[-1].strip()
                
                # 执行工具
                if action in self.tools:
                    try:
                        result = str(self.tools[action]["func"](action_input))
                    except Exception as e:
                        result = f"Error: {e}"
                else:
                    result = f"Tool '{action}' not found"
                
                messages.append({"role": "user", "content": f"Observation: {result}"})
            else:
                break
        
        return "Max steps reached or invalid format"

# 创建 Agent 并注册工具
agent = SimpleReActAgent()

# 工具 1：检查端口
def check_port(port_str: str) -> str:
    port = int(port_str)
    try:
        result = subprocess.run(
            ["netstat", "-tlnp"], 
            capture_output=True, text=True, timeout=5
        )
        for line in result.stdout.split('\n'):
            if f":{port}" in line:
                return line.strip()
        return f"Port {port} is not in use"
    except Exception as e:
        return f"Error checking port: {e}"

# 工具 2：执行命令
def run_command(cmd: str) -> str:
    try:
        result = subprocess.run(
            cmd.split(), 
            capture_output=True, text=True, timeout=10
        )
        return result.stdout or result.stderr
    except Exception as e:
        return f"Error: {e}"

# 工具 3：搜索文档
def search_docs(query: str) -> str:
    # 简化版，Part 2 会用向量搜索
    docs = {
        "Address already in use": "端口被占用。用 lsof/netstat 检查，或换端口。",
        "OOMKilled": "容器内存超限。检查 memory limit 和应用内存使用。",
        "Connection refused": "目标服务未启动或端口不对。"
    }
    for key, val in docs.items():
        if key.lower() in query.lower():
            return val
    return f"No docs found for: {query}"

agent.register_tool("check_port", check_port, "检查端口占用")
agent.register_tool("run_command", run_command, "执行 shell 命令")
agent.register_tool("search_docs", search_docs, "搜索技术文档")

# 使用
result = agent.run("我的 FastAPI 服务报 Address already in use，怎么排查？")
print(result)
```

> ⚠️ **ReAct 的常见坑**：
>
> 1. **无限循环**：Agent 反复调用工具但不收敛 → 设置 `max_steps`
> 2. **幻觉 Observation**：LLM 自己编造工具结果 → 用 `stop=["Observation:"]` 防止
> 3. **工具选择错误**：LLM 选了不对的工具 → 改进工具描述
> 4. **格式解析失败**：LLM 输出格式不规范 → 用正则或 JSON 格式
>
> 这些坑在 Part 2 用 LangChain 时会系统解决。

### 系统化调试方法

```python
class PromptDebugger:
    """Prompt 调试器 — 像调试代码一样调试 Prompt"""
    
    def __init__(self, base_prompt: str):
        self.base_prompt = base_prompt
        self.history = []  # 记录每次修改
    
    def bisect_debug(self, test_cases: list[dict]) -> dict:
        """二分法：找出哪部分 Prompt 导致问题
        
        类比：git bisect — 快速定位引入 bug 的 commit
        """
        # 1. 把 Prompt 分成若干段
        sections = self.base_prompt.split("\n\n")
        
        # 2. 逐段测试，找出问题段
        results = {}
        for i, section in enumerate(sections):
            test_prompt = "\n\n".join(sections[:i+1])
            result = self._test_prompt(test_prompt, test_cases)
            results[f"section_{i}"] = result
        
        # 3. 定位到问题段后，细化修复
        return results
    
    def ab_test(self, variant_a: str, variant_b: str, 
                test_cases: list[dict]) -> dict:
        """A/B 测试：对比两个 Prompt 版本
        
        类比：AB测试 — 数据说话，不靠直觉
        """
        result_a = self._test_prompt(variant_a, test_cases)
        result_b = self._test_prompt(variant_b, test_cases)
        
        return {
            "variant_a": result_a,
            "variant_b": result_b,
            "winner": "A" if result_a["score"] > result_b["score"] else "B"
        }
    
    def edge_case_test(self, prompt: str) -> dict:
        """边界测试：测试极端情况
        
        类比：单元测试的边界用例
        """
        edge_cases = [
            {"input": "", "desc": "空输入"},
            {"input": "a" * 5000, "desc": "超长输入"},
            {"input": "🔥🎉💻", "desc": "纯表情"},
            {"input": "SELECT * FROM users; DROP TABLE users;", "desc": "注入攻击"},
            {"input": "今天天气怎么样?", "desc": "超领域问题"},
            {"input": "我是初学者" + "请解释Python" * 100, "desc": "重复内容"},
        ]
        
        results = {}
        for case in edge_cases:
            try:
                result = self._test_prompt(prompt, [case])
                results[case["desc"]] = "PASS" if result["score"] > 0.5 else "FAIL"
            except Exception as e:
                results[case["desc"]] = f"ERROR: {e}"
        
        return results
    
    def _test_prompt(self, prompt: str, test_cases: list[dict]) -> dict:
        """执行测试并评分"""
        scores = []
        for case in test_cases:
            # 调用 LLM（省略具体实现）
            # response = call_llm(prompt, case["input"])
            # score = evaluate(response, case["expected"])
            # scores.append(score)
            pass
        return {"score": sum(scores) / len(scores) if scores else 0}
```

```python
debug_checklist = """

     - 可以回滚？
     - 有基准测试？
```

> 💡 **调试 Prompt 的黄金法则**：
>
> 1. **一次改一个变量** — 不要同时改多处
> 2. **用数据说话** — 准备测试集，不靠感觉
> 3. **记录每次修改** — 像 git commit 一样
> 4. **测试边界情况** — 空、长、乱、攻击
> 5. **定期 review** — Prompt 也需要重构

## 3.8 实战：DocMind System Prompt

```python
import os
from openai import OpenAI
from dotenv import load_dotenv
load_dotenv()

SP = """你是 DocMind，智能技术文档助手。
## 角色: 像经验丰富的技术Lead，目标用户1-5年后端
## 能力: 概念解释(+代码) | 问题排查(错误→步骤) | 方案比较(表格) | 代码示例(含注解)
## 规范: Markdown; **粗体**标概念; 含TL;DR; 快<100字/概念100-300字/排查300-500字
## 行为: 超领域→推荐; 歧义→确认; 危险操作→警告; 不用"作为AI..."开头"""

class DocMindV1:
    def __init__(self, m="gpt-4o-mini"):
        self.c = OpenAI(api_key=os.getenv("OPENAI_API_KEY")); self.m = m
    def chat(self, q, h=None):
        msgs = [{"role":"system","content":SP}] + (h or []) + [{"role":"user","content":q}]
        return self.c.chat.completions.create(model=self.m, messages=msgs,
            temperature=0.3, max_tokens=1500).choices[0].message.content
    def explain(self, c): return self.chat(f"解释「{c}」，面向Python开发者，附代码。")
    def troubleshoot(self, e, ctx=""):
        return self.chat(f"错误:\n```\n{e}\n```" + (f"\n上下文:{ctx}" if ctx else ""))
    def compare(self, opts, scenario):
        return self.chat(f"场景:{scenario}\n方案:\n" +
                        "\n".join(f"- {o}" for o in opts) + "\n表格对比并推荐。")

dm = DocMindV1()
print(dm.explain("Python装饰器"))
print(dm.troubleshoot("psycopg2.OperationalError: connection slots reserved",
                      "FastAPI+SQLAlchemy+PG,200并发"))
print(dm.compare(["Celery+Redis","Dramatiq+RabbitMQ","RQ"], "FastAPI异步任务"))
```
