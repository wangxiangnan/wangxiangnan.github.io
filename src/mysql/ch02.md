# 第2章 数据库与表的设计

> 建表就像盖房子，地基打不好，后面改起来要拆墙。这一章我们来聊聊怎么设计好你的"数据大厦"。

## 2.1 创建和删除数据库

```sql
-- 创建数据库，指定字符集
CREATE DATABASE IF NOT EXISTS shop_db
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- 查看创建语句
SHOW CREATE DATABASE shop_db;

-- 切换数据库
USE shop_db;

-- 删除数据库（谨慎操作！）
DROP DATABASE IF EXISTS shop_db;
```

> [!WARNING] 注意
> `DROP DATABASE` 是不可逆的操作，执行前请三思。在生产环境中，永远先备份再操作。

## 2.2 数据类型详解

选择数据类型就像选择收纳盒——大小要合适，功能要匹配。

### 数值型

```sql
-- 整数类型
-- TINYINT:  -128 ~ 127（适合存年龄、状态码）
-- SMALLINT: -32768 ~ 32767
-- INT:      -21亿 ~ 21亿（最常用）
-- BIGINT:   超大范围（订单号、雪花ID）

-- 无符号版本（只有正数，范围翻倍）
-- INT UNSIGNED: 0 ~ 42亿

-- 精确小数（金融计算必备）
DECIMAL(10, 2)   -- 总共10位，2位小数，如 99999999.99

-- 近似小数（科学计算用，别用来算钱！）
FLOAT
DOUBLE
```

> [!TIP] 提示
> 金额字段永远用`DECIMAL`，永远不要用`FLOAT`或`DOUBLE`。浮点数的精度问题会让你在算钱的时候抓狂。

### 字符串型

```sql
-- 固定长度字符串（适合身份证号、手机号）
CHAR(18)

-- 可变长度字符串（最常用）
VARCHAR(255)    -- 最大65535字节，但通常不超过255

-- 大文本
TEXT            -- 最大64KB
MEDIUMTEXT      -- 最大16MB
LONGTEXT        -- 最大4GB
```

> [!TIP] 提示
> `CHAR`和`VARCHAR`的选择原则——如果长度固定（如MD5哈希、身份证号），用`CHAR`；如果长度可变（如用户名、地址），用`VARCHAR`。`CHAR`在存储和比较时稍微高效一些。

### 日期时间型

```sql
DATE          -- 日期：2024-01-15
TIME          -- 时间：14:30:00
DATETIME      -- 日期+时间：2024-01-15 14:30:00（范围大，不受时区影响）
TIMESTAMP     -- 时间戳：2024-01-15 14:30:00（自动转UTC，受时区影响）
YEAR          -- 年份：2024
```

> [!WARNING] 注意
> `TIMESTAMP`在MySQL 8.0中范围是1970-2038年（著名的"2038年问题"）。如果你的数据可能超出这个范围，请用`DATETIME`。

### 枚举类型

```sql
-- 枚举：限定可选值
ENUM('active', 'inactive', 'banned')

-- 集合：可以多选
SET('read', 'write', 'execute')
```

> [!WARNING] 注意
> `ENUM`虽然方便，但在大型项目中建议用`TINYINT`+代码层面映射来替代。因为`ENUM`修改值列表需要`ALTER TABLE`，在大表上这个操作很慢。

## 2.3 CREATE TABLE 完整语法

让我们来设计一个电商系统的基础表：

```sql
-- 用户表
CREATE TABLE users (
  id BIGINT UNSIGNED AUTO_INCREMENT COMMENT '用户ID',
  username VARCHAR(50) NOT NULL COMMENT '用户名',
  email VARCHAR(100) NOT NULL COMMENT '邮箱',
  phone CHAR(11) DEFAULT NULL COMMENT '手机号',
  password_hash CHAR(60) NOT NULL COMMENT '密码哈希（bcrypt）',
  status ENUM('active', 'inactive', 'banned') NOT NULL DEFAULT 'active' COMMENT '账户状态',
  balance DECIMAL(12, 2) NOT NULL DEFAULT 0.00 COMMENT '账户余额',
  avatar_url VARCHAR(500) DEFAULT NULL COMMENT '头像URL',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (id),
  UNIQUE KEY uk_username (username),
  UNIQUE KEY uk_email (email),
  INDEX idx_phone (phone),
  INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户表';
```

```sql
-- 商品表
CREATE TABLE products (
  id BIGINT UNSIGNED AUTO_INCREMENT COMMENT '商品ID',
  name VARCHAR(200) NOT NULL COMMENT '商品名称',
  description TEXT COMMENT '商品描述',
  price DECIMAL(10, 2) NOT NULL COMMENT '售价',
  original_price DECIMAL(10, 2) DEFAULT NULL COMMENT '原价',
  stock INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '库存数量',
  category_id INT UNSIGNED COMMENT '分类ID',
  is_active TINYINT(1) NOT NULL DEFAULT 1 COMMENT '是否上架',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (id),
  INDEX idx_category (category_id),
  INDEX idx_price (price),
  INDEX idx_active (is_active)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='商品表';
```

```sql
-- 查看表结构
DESCRIBE users;
-- 或者简写
DESC users;

-- 查看创建语句（可以复制给别人用）
SHOW CREATE TABLE users;

-- 查看表状态
SHOW TABLE STATUS LIKE 'users';
```

## 2.4 ALTER TABLE：修改表结构

表建好了不代表万事大吉，需求变更是家常便饭：

```sql
-- 添加列
ALTER TABLE users ADD COLUMN gender ENUM('male', 'female', 'other') DEFAULT NULL COMMENT '性别' AFTER phone;

-- 修改列类型
ALTER TABLE users MODIFY COLUMN avatar_url VARCHAR(1000) DEFAULT NULL COMMENT '头像URL';

-- 重命名列（MySQL 8.0+）
ALTER TABLE users RENAME COLUMN avatar_url TO avatar;

-- 删除列（谨慎！）
ALTER TABLE users DROP COLUMN gender;

-- 添加索引
ALTER TABLE users ADD INDEX idx_created_at (created_at);

-- 删除索引
ALTER TABLE users DROP INDEX idx_created_at;

-- 修改表注释
ALTER TABLE users COMMENT = '用户信息主表';

-- 重命名表
ALTER TABLE users RENAME TO user_accounts;
-- 或者
RENAME TABLE user_accounts TO users;
```

> [!WARNING] 注意
> `ALTER TABLE`在大表上（百万级以上）可能会锁表，导致线上服务不可用。生产环境建议使用`pt-online-schema-change`或`gh-ost`等工具进行在线DDL。

## 2.5 DROP TABLE 与 TRUNCATE TABLE

这两个都能"清空"表，但本质完全不同：

```sql
-- DROP TABLE：连表结构一起删除，从地球上消失
DROP TABLE IF EXISTS temp_data;

-- TRUNCATE TABLE：清空数据但保留表结构，自增ID重置
TRUNCATE TABLE temp_data;

-- DELETE FROM：逐行删除，自增ID不重置，可以加WHERE
DELETE FROM temp_data;
DELETE FROM temp_data WHERE created_at < '2024-01-01';
```

| 特性 | DROP TABLE | TRUNCATE TABLE | DELETE FROM |
|------|-----------|----------------|-------------|
| 删除内容 | 表结构+数据 | 只清数据 | 只删数据 |
| 速度 | 快 | 快 | 慢（逐行） |
| 自增ID重置 | N/A | 是 | 否 |
| 可回滚 | 否 | 否（InnoDB中在某些事务场景可回滚） | 是（事务中） |
| 触发器 | N/A | 不触发 | 触发 |
| WHERE条件 | N/A | 不支持 | 支持 |

## 2.6 表的注释 COMMENT

**注释是写给未来的自己和接手你代码的同事看的。** 这不是可选项，这是职业素养。

```sql
-- 表级注释
CREATE TABLE orders (
  id BIGINT UNSIGNED AUTO_INCREMENT,
  -- ...
) COMMENT='订单主表，记录每笔交易';

-- 列级注释
username VARCHAR(50) NOT NULL COMMENT '用户登录名，3-50个字符'

-- 查看注释
SHOW FULL COLUMNS FROM users;
SELECT COLUMN_NAME, COLUMN_COMMENT
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_NAME = 'users';
```

## 2.7 存储引擎简介

MySQL的存储引擎就像汽车的发动机，不同的引擎有不同的特性：

```sql
-- 查看当前支持的引擎
SHOW ENGINES;

-- 查看默认引擎
SELECT @@default_storage_engine;
```

| 特性 | InnoDB | MyISAM |
|------|--------|--------|
| 事务支持 | 支持 | 不支持 |
| 行级锁 | 支持 | 只支持表级锁 |
| 外键 | 支持 | 不支持 |
| 崩溃恢复 | 支持 | 不支持 |
| 全文索引 | 支持（5.6+） | 支持 |
| 适用场景 | 绝大多数场景 | 只读/读多写少 |

> [!TIP] 提示
> 从MySQL 5.5开始，默认引擎就是InnoDB。**没有特殊理由，永远用InnoDB。** MyISAM在MySQL 8.0中已经基本不推荐使用了。

本章我们学习了数据库和表的创建与管理、各种数据类型的选择技巧、`ALTER TABLE`的使用、以及存储引擎的基本概念。记住：建表前多想一步，后期少改十步。
