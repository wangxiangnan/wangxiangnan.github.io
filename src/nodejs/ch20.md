## 20.1 V8内存模型：你的变量住在哪里？

### 20.1.1 堆内存的"小区规划"

V8的堆内存就像一个精心规划的小区，不同类型的"居民"（对象）住在不同的"楼栋"：

```
┌─────────────────────────────────────────────────────────────┐
│                     V8 Heap Memory                            │
├──────────────┬──────────────┬───────────────────────────────┤
│  New Space   │  Old Space   │  Large Object Space           │
│  (新生代)     │  (老生代)     │  (大对象空间)                  │
│  1-8 MB      │  ~1.4 GB     │  单个对象 > 新生代一半          │
├──────────────┼──────────────┼───────────────────────────────┤
│  Code Space  │  Map Space   │  Cell Space / Property Cell   │
│  (代码空间)   │  (隐藏类空间) │  (Cell空间)                    │
└──────────────┴──────────────┴───────────────────────────────┘
```

**新生代（New Space / Young Generation）**：

- 大小：默认1-8MB（可通过`--max-semi-space-size`调整）
- 存放：新创建的、存活时间短的对象
- 比喻：大学宿舍，流动性大，毕业（被回收）或者转正（晋升到老生代）

**老生代（Old Space / Old Generation）**：

- 大小：默认约1.4GB（64位系统），可通过`--max-old-space-size`调整
- 存放：从新生代晋升过来的长寿对象
- 比喻：商品房，住得久、不容易搬走

**大对象空间（Large Object Space）**：

- 存放：超过新生代一半大小的对象，直接分配到这里
- 特点：不会被移动，垃圾回收时只做标记清除
- 比喻：别墅区，占地面积大，搬家成本太高

### 20.1.2 查看内存使用情况

```typescript
// memory-inspector.ts
import { memoryUsage } from 'node:process';
import v8 from 'node:v8';

interface MemoryInfo {
  rss: string;          // 常驻内存集（进程总内存）
  heapTotal: string;    // V8堆总大小
  heapUsed: string;     // V8堆已用大小
  external: string;     // V8外部内存（C++对象绑定的内存）
  arrayBuffers: string; // ArrayBuffer占用
}

function formatBytes(bytes: number): string {
  const units = ['B', 'KB', 'MB', 'GB'];
  let unitIndex = 0;
  let size = bytes;
  
  while (size >= 1024 && unitIndex < units.length - 1) {
    size /= 1024;
    unitIndex++;
  }
  
  return `${size.toFixed(2)} ${units[unitIndex]}`;
}

function getMemoryInfo(): MemoryInfo {
  const mem = memoryUsage();
  return {
    rss: formatBytes(mem.rss),
    heapTotal: formatBytes(mem.heapTotal),
    heapUsed: formatBytes(mem.heapUsed),
    external: formatBytes(mem.external),
    arrayBuffers: formatBytes(mem.arrayBuffers),
  };
}

// V8堆统计详情
function getHeapStatistics() {
  const stats = v8.getHeapStatistics();
  return {
    totalHeapSize: formatBytes(stats.total_heap_size),
    totalHeapSizeExecutable: formatBytes(stats.total_heap_size_executable),
    totalPhysicalSize: formatBytes(stats.total_physical_size),
    totalAvailableSize: formatBytes(stats.total_available_size),
    usedHeapSize: formatBytes(stats.used_heap_size),
    heapSizeLimit: formatBytes(stats.heap_size_limit),
    mallocedMemory: formatBytes(stats.malloced_memory),
    peakMallocedMemory: formatBytes(stats.peak_malloced_memory),
    numberOfNativeContexts: stats.number_of_native_contexts,
    numberOfDetachedContexts: stats.number_of_detached_contexts,
  };
}

// V8堆空间详情
function getHeapSpaceStatistics() {
  const spaces = v8.getHeapSpaceStatistics();
  return spaces.map(space => ({
    name: space.space_name,
    size: formatBytes(space.space_size),
    used: formatBytes(space.space_used_size),
    available: formatBytes(space.space_available_size),
    physical: formatBytes(space.physical_space_size),
  }));
}

// 定时输出内存状态
setInterval(() => {
  console.log('=== Memory Status ===');
  console.table(getMemoryInfo());
  console.log('\n=== Heap Statistics ===');
  console.table(getHeapStatistics());
  console.log('\n=== Heap Spaces ===');
  console.table(getHeapSpaceStatistics());
}, 5000);
```

### 20.1.3 --max-old-space-size 配置


> **小贴士**：不要把 `--max-old-space-size` 设得比物理内存还大，否则OOM Killer会来教你做人。一般设置为物理内存的75%是个安全值。

## 20.2 垃圾回收机制：V8的"保洁阿姨"

### 20.2.1 新生代回收：Scavenge算法（捡垃圾的"翻转大法"）

新生代使用 **Scavenge** 算法（基于Cheney算法），核心思想是"空间换时间"：

```
新生代内存结构：
┌────────────────────────┬────────────────────────┐
│     From Space         │      To Space          │
│   (正在使用的半区)       │   (空闲的半区)          │
│                        │                        │
│  [A] [B] [C] [D]      │                        │
│   ↑活  ↑死  ↑活  ↑死   │                        │
└────────────────────────┴────────────────────────┘

Scavenge后：
┌────────────────────────┬────────────────────────┐
│     From Space (清空)   │   To Space (新的From)   │
│                        │                        │
│                        │  [A] [C]               │
│                        │  (存活对象被复制过来)     │
└────────────────────────┴────────────────────────┘
```

**晋升条件**（对象从新生代→老生代）：

1. 对象经历过一次Scavenge后仍然存活
2. To Space的使用率超过25%时，对象直接晋升

```typescript
// 演示新生代到老生代的晋升
// gc-demo.ts
// 运行方式: node --expose-gc --trace-gc gc-demo.js

function demonstrateGC(): void {
  const shortLived: number[][] = [];
  
  // 创建大量短生命周期对象（留在新生代）
  for (let i = 0; i < 1000; i++) {
    shortLived.push(new Array(100).fill(i));
  }
  // 释放引用，等待GC回收
  shortLived.length = 0;

  // 创建长生命周期对象（将晋升到老生代）
  const longLived: Map<string, number[]> = new Map();
  for (let i = 0; i < 100; i++) {
    longLived.set(`key-${i}`, new Array(1000).fill(i));
  }

  // 手动触发GC（需要 --expose-gc 标志）
  if (global.gc) {
    console.log('Before GC:');
    console.log(process.memoryUsage());
    
    global.gc(); // Minor GC (Scavenge)
    
    console.log('\nAfter GC:');
    console.log(process.memoryUsage());
  }

  // longLived 仍然被引用，会晋升到老生代
  console.log(`Long-lived map size: ${longLived.size}`);
}

demonstrateGC();
```

### 20.2.2 老生代回收：Mark-Sweep与Mark-Compact

老生代空间大、对象多，用Scavenge那种"复制大法"太奢侈了。所以V8用了两种算法：

**Mark-Sweep（标记清除）**：

1. **标记阶段**：从根对象（全局对象、调用栈）出发，遍历所有可达对象，标记为"活"
2. **清除阶段**：遍历整个堆，回收未标记的对象

```
标记前：
[A✓] [B✗] [C✓] [D✗] [E✓] [F✗] [G✓]

清除后：
[A✓] [___] [C✓] [___] [E✓] [___] [G✓]
       ↑ 碎片   ↑ 碎片        ↑ 碎片
```

问题：清除后产生**内存碎片**！

**Mark-Compact（标记整理）**：

- 在Mark-Sweep基础上，将存活对象向一端移动，消除碎片
- 代价：需要更新所有移动对象的指针，速度较慢

```
整理后：
[A✓] [C✓] [E✓] [G✓] [____________空闲____________]
                      ↑ 连续的空闲空间，分配效率高
```

### 20.2.3 增量标记与并发回收

V8不会"Stop The World"太久，它使用了多种优化策略：

```typescript
// 演示GC暂停对应用的影响
// 运行: node --trace-gc --expose-gc gc-pause-demo.js

import { performance, PerformanceObserver } from 'node:perf_hooks';

// 监控事件循环延迟
let lastTime = performance.now();
const delays: number[] = [];

const interval = setInterval(() => {
  const now = performance.now();
  const delay = now - lastTime - 100; // 预期100ms一次
  if (delay > 1) {
    delays.push(delay);
    console.log(`Event loop delay: ${delay.toFixed(2)}ms`);
  }
  lastTime = now;
}, 100);

// 制造内存压力
const leakyArray: object[] = [];
for (let i = 0; i < 100000; i++) {
  leakyArray.push({
    data: new Array(100).fill('x'.repeat(100)),
    timestamp: Date.now(),
    id: crypto.randomUUID(),
  });
  
  if (i % 10000 === 0) {
    // 释放一部分，制造碎片
    leakyArray.splice(0, 5000);
  }
}

setTimeout(() => {
  clearInterval(interval);
  console.log(`\nTotal GC pauses detected: ${delays.length}`);
  console.log(`Max delay: ${Math.max(...delays).toFixed(2)}ms`);
  console.log(`Avg delay: ${(delays.reduce((a, b) => a + b, 0) / delays.length).toFixed(2)}ms`);
}, 10000);
```

**V8的GC优化策略**：

| 策略 | 说明 | 效果 |
| ------ | ------ | ------ |
| 增量标记 (Incremental Marking) | 将标记工作分成小块，穿插在JS执行之间 | 减少单次暂停时间 |
| 并发标记 (Concurrent Marking) | 在后台线程进行标记，不阻塞主线程 | 几乎不暂停 |
| 并发清除 (Concurrent Sweeping) | 在后台线程进行清除 | 不阻塞主线程 |
| 惰性清除 (Lazy Sweeping) | 不立即清除所有死对象，按需清除 | 减少暂停 |
| 并行回收 (Parallel Scavenge) | 多个辅助线程并行执行新生代GC | 加速新生代回收 |

## 20.3 内存泄漏排查：找到那个"占着茅坑不拉屎"的对象

### 20.3.1 常见内存泄漏场景

```typescript
// ===== 场景1：闭包陷阱 =====
function createLeakyClosures(): void {
  let theThing: { longStr: string; someMethod: () => void } | null = null;
  
  // 这是一个经典的闭包泄漏模式
  setInterval(() => {
    const originalThing = theThing;
    
    // unused 实际上引用了 originalThing
    // 因为它们在同一个作用域，V8会为整个作用域保留闭包上下文
    const unused = function () {
      if (originalThing) console.log("hi");
    };
    
    theThing = {
      longStr: new Array(1000000).join('*'), // 1MB
      someMethod: function () {
        console.log("message");
      },
    };
    // 每次循环，theThing的旧值通过unused的闭包被保留
    // 形成了一条不断增长的引用链
  }, 1000);
}

// ===== 场景2：事件监听器未清理 =====
import { EventEmitter } from 'node:events';

class LeakyService {
  private emitter = new EventEmitter();
  private cache: Map<string, Buffer> = new Map();

  handleRequest(requestId: string): void {
    // 每次请求都注册新的监听器，但从不移除！
    this.emitter.on('data', (data: Buffer) => {
      // 闭包引用了 this.cache
      this.cache.set(requestId, data);
    });
  }
  
  // 正确做法：使用 once 或手动移除
  handleRequestFixed(requestId: string): void {
    const handler = (data: Buffer) => {
      this.cache.set(requestId, data);
      this.emitter.off('data', handler); // 用完就拆
    };
    this.emitter.on('data', handler);
  }
}

// ===== 场景3：全局缓存无限增长 =====
// 这是最常见的泄漏场景之一
const globalCache: Map<string, object> = new Map();

function processRequest(userId: string, data: object): void {
  // 只进不出的缓存 = 内存泄漏
  globalCache.set(userId, data);
  // 永远不调用 globalCache.delete()
}

// 正确做法：使用LRU缓存或WeakRef
import { LRUCache } from 'lru-cache'; // npm install lru-cache

const safeCache = new LRUCache<string, object>({
  max: 1000,           // 最多1000个条目
  ttl: 1000 * 60 * 5, // 5分钟过期
  maxSize: 50 * 1024 * 1024, // 50MB上限
  sizeCalculation: (value) => JSON.stringify(value).length,
});

// ===== 场景4：未关闭的定时器和流 =====
function leakyTimer(): void {
  const hugeData = Buffer.alloc(10 * 1024 * 1024); // 10MB
  
  // 定时器引用了 hugeData，只要定时器不清除，hugeData就不会被回收
  const timer = setInterval(() => {
    console.log(hugeData.length);
  }, 1000);
  
  // 正确做法：在适当时机清除
  setTimeout(() => clearInterval(timer), 60000);
}

// ===== 场景5：WeakRef和FinalizationRegistry（ES2021+） =====
// 使用WeakRef避免强引用导致的泄漏
class ObjectPool<T extends object> {
  private pool: WeakRef<T>[] = [];
  private registry: FinalizationRegistry<number>;

  constructor() {
    this.registry = new FinalizationRegistry((index: number) => {
      console.log(`Object at index ${index} was garbage collected`);
      this.pool[index] = undefined!;
    });
  }

  add(obj: T): void {
    const index = this.pool.length;
    this.pool.push(new WeakRef(obj));
    this.registry.register(obj, index);
  }

  get(index: number): T | undefined {
    return this.pool[index]?.deref();
  }
}
```

### 20.3.3 使用heapdump进行程序化内存分析

```typescript
// heap-analysis.ts
import v8 from 'node:v8';
import { writeFileSync } from 'node:fs';
import { join } from 'node:path';

// Node.js 20+ 内置的堆快照功能
function takeHeapSnapshot(filename?: string): string {
  const snapshotFile = filename || join(
    process.cwd(), 
    `heapdump-${process.pid}-${Date.now()}.heapsnapshot`
  );
  
  // 方法1: 使用v8.writeHeapSnapshot()（推荐）
  const actualPath = v8.writeHeapSnapshot(snapshotFile);
  console.log(`Heap snapshot written to: ${actualPath}`);
  return actualPath;
}

// 在内存超过阈值时自动dump
function setupMemoryGuard(thresholdMB: number = 500): void {
  const CHECK_INTERVAL = 30000; // 30秒检查一次
  
  setInterval(() => {
    const { heapUsed } = process.memoryUsage();
    const usedMB = heapUsed / 1024 / 1024;
    
    console.log(`[Memory Guard] Heap used: ${usedMB.toFixed(2)} MB`);
    
    if (usedMB > thresholdMB) {
      console.warn(`[Memory Guard] ⚠ Heap exceeds ${thresholdMB}MB, taking snapshot...`);
      takeHeapSnapshot();
      
      // 可选：强制GC（需要 --expose-gc）
      if (global.gc) {
        global.gc();
        const afterGC = process.memoryUsage().heapUsed / 1024 / 1024;
        console.log(`[Memory Guard] After GC: ${afterGC.toFixed(2)} MB`);
        
        if (afterGC > thresholdMB * 0.9) {
          console.error('[Memory Guard] Memory still high after GC - likely a leak!');
        }
      }
    }
  }, CHECK_INTERVAL);
}

// 使用信号触发heap dump（生产环境推荐）
process.on('SIGUSR2', () => {
  console.log('Received SIGUSR2, taking heap snapshot...');
  takeHeapSnapshot();
});

// 导出工具函数
export { takeHeapSnapshot, setupMemoryGuard };
```

```typescript
// cpu-intensive-demo.ts - 一个CPU密集型的示例
import { createServer } from 'node:http';

// 故意写的低效函数（不要在生产环境这么干！）
function inefficientSort(arr: number[]): number[] {
  // 冒泡排序 - O(n²) 的灾难
  const result = [...arr];
  for (let i = 0; i < result.length; i++) {
    for (let j = 0; j < result.length - i - 1; j++) {
      if (result[j] > result[j + 1]) {
        [result[j], result[j + 1]] = [result[j + 1], result[j]];
      }
    }
  }
  return result;
}

function generateReport(data: number[]): string {
  // 低效的字符串拼接
  let report = '';
  for (const item of data) {
    report += `Item: ${item}\n`; // 每次拼接都创建新字符串
  }
  return report;
}

const server = createServer((req, res) => {
  const data = Array.from({ length: 10000 }, () => Math.random() * 10000);
  
  const sorted = inefficientSort(data);  // CPU热点1
  const report = generateReport(sorted); // CPU热点2
  
  res.writeHead(200, { 'Content-Type': 'text/plain' });
  res.end(report);
});

server.listen(3000);
```

```
          ┌─────────────────────────────────┐
          │     inefficientSort (45%)        │  ← 宽度 = 时间占比
          ├────────────┬────────────────────┤
          │  compare   │    swap            │

│         │            │                    │          │

│  (15%)  │            │                    │         │
└─────────┴────────────┴────────────────────┴─────────┘
```

- **X轴**：不是时间轴！是函数的CPU占比（越宽 = 越耗CPU）
- **Y轴**：调用栈深度（越高 = 调用层级越深）
- **颜色**：通常随机着色，便于区分不同的栈帧
- **关注点**：寻找"平顶"（plateau）——那些又宽又平的函数就是性能瓶颈

### 20.6.3 事件循环延迟监控

```typescript
// event-loop-monitor.ts
import { monitorEventLoopDelay } from 'node:perf_hooks';
import { EventEmitter } from 'node:events';

interface EventLoopMetrics {
  min: number;
  max: number;
  mean: number;
  stddev: number;
  p50: number;
  p90: number;
  p99: number;
  exceeds: number; // 超过阈值的次数
}

class EventLoopMonitor extends EventEmitter {
  private histogram;
  private threshold: number;
  private interval: NodeJS.Timeout | null = null;
  private exceedCount = 0;

  constructor(options: { resolution?: number; threshold?: number; interval?: number } = {}) {
    super();
    const { resolution = 10, threshold = 100, interval = 5000 } = options;
    
    this.threshold = threshold;
    this.histogram = monitorEventLoopDelay({ resolution });
  }

  start(): this {
    this.histogram.enable();
    
    this.interval = setInterval(() => {
      const metrics = this.getMetrics();
      this.emit('metrics', metrics);
      
      if (metrics.p99 > this.threshold) {
        this.exceedCount++;
        this.emit('slow', { 
          p99: metrics.p99, 
          threshold: this.threshold,
          consecutiveExceeds: this.exceedCount 
        });
      } else {
        this.exceedCount = 0;
      }
      
      this.histogram.reset();
    }, 5000);

    return this;
  }

  stop(): void {
    this.histogram.disable();
    if (this.interval) {
      clearInterval(this.interval);
      this.interval = null;
    }
  }

  getMetrics(): EventLoopMetrics {
    return {
      min: this.histogram.min / 1e6,
      max: this.histogram.max / 1e6,
      mean: this.histogram.mean / 1e6,
      stddev: this.histogram.stddev / 1e6,
      p50: this.histogram.percentile(50) / 1e6,
      p90: this.histogram.percentile(90) / 1e6,
      p99: this.histogram.percentile(99) / 1e6,
      exceeds: this.exceedCount,
    };
  }
}

// 使用示例
const monitor = new EventLoopMonitor({ threshold: 50 }); // 50ms阈值

monitor.on('metrics', (metrics: EventLoopMetrics) => {
  console.log(`[EL Monitor] p50=${metrics.p50.toFixed(2)}ms p99=${metrics.p99.toFixed(2)}ms`);
});

monitor.on('slow', ({ p99, threshold, consecutiveExceeds }) => {
  console.warn(
    `[EL Monitor] ⚠ Event loop is slow! p99=${p99.toFixed(2)}ms > ${threshold}ms ` +
    `(consecutive: ${consecutiveExceeds})`
  );
  
  if (consecutiveExceeds >= 3) {
    console.error('[EL Monitor] Event loop consistently slow - consider investigating!');
    // 可以在这里触发告警、dump堆栈等
  }
});

monitor.start();

export { EventLoopMonitor, EventLoopMetrics };
```
