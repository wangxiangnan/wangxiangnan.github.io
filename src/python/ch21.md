# 第 21 章 虚拟环境与依赖管理

你在电脑上装了一堆 Python 包：项目 A 需要 `requests==2.28`，项目 B 需要 `requests==2.31`。两个版本装在同一个 Python 里——冲突了。这就像你和室友合住一个房间，你习惯 22 度空调，室友要 18 度——同一台空调只能设一个温度。解决方案？各住各的房间。

虚拟环境就是给每个 Python 项目一个"独立房间"——每个项目有自己的包集合，互不干扰。依赖管理则是记录"这个房间需要装哪些东西"的清单系统。本章将带你从最基础的 `venv` + `pip`，到现代的 `poetry` 和 `uv`，建立完整的依赖管理知识体系。

## 21.1 venv：Python 内置的虚拟环境

`venv` 是 Python 3.3+ 内置的虚拟环境模块，不需要额外安装。

### 创建与激活

```bash
# 在项目目录下创建虚拟环境（通常命名为 .venv 或 venv）
python -m venv .venv

# 激活（Windows）
.venv\Scripts\activate

# 激活（macOS / Linux）
source .venv/bin/activate

# 激活后，命令行提示符前面会出现 (.venv)
(.venv) C:\my_project> python --version
# 此时的 python 和 pip 都指向虚拟环境

# 退出虚拟环境
deactivate
```

### 工作原理

虚拟环境本质上是一个目录，包含了指向系统 Python 的符号链接和独立的 `site-packages`：

```
.venv/
├── bin/（Linux/Mac）或 Scripts/（Windows）
│   ├── python       → 指向系统 Python 的链接
│   ├── pip          → 虚拟环境自己的 pip
│   └── activate     → 激活脚本
├── lib/
│   └── python3.11/
│       └── site-packages/  → 独立的包目录
└── pyvenv.cfg      → 配置文件（记录基础 Python 路径）
```

激活虚拟环境其实是修改了 `PATH` 环境变量，让 `python` 和 `pip` 命令指向虚拟环境中的版本。

小贴士：`.venv` 目录应该加入 `.gitignore`——虚拟环境是本地的，不应该提交到 Git。

## 21.2 pip：包管理器

`pip` 是 Python 的官方包管理器，随 Python 一起安装。

### 基本操作

```bash
# 安装包
pip install requests
pip install requests==2.31.0        # 指定版本
pip install "requests>=2.28,<3.0"   # 版本范围

# 安装多个包
pip install requests flask pytest

# 卸载
pip uninstall requests

# 查看已安装的包
pip list
pip show requests  # 查看详细信息（版本、依赖、位置等）

# 升级包
pip install --upgrade requests

# 查看过期的包
pip list --outdated
```

### requirements.txt

`requirements.txt` 是最传统的依赖记录方式：

```text
# requirements.txt
requests==2.31.0
flask>=3.0.0,<4.0.0
pytest>=7.0
python-dotenv>=1.0.0
```

```bash
# 导出当前环境的所有包
pip freeze > requirements.txt

# 根据 requirements.txt 安装
pip install -r requirements.txt

# 分文件管理（开发依赖 vs 生产依赖）
# requirements-dev.txt
-r requirements.txt   # 包含基础依赖
pytest>=7.0
black>=23.0
mypy>=1.0
```

### requirements.txt 的局限

- 不区分"直接依赖"和"间接依赖"（依赖的依赖）
- `pip freeze` 导出的是精确版本号，不区分哪些是你主动安装的
- 没有锁定文件机制（`requirements.txt` 本身既是声明又是锁定）
- 不支持项目元数据（名称、版本、描述等）

这些局限催生了更现代的依赖管理工具。

## 21.3 pyproject.toml：现代 Python 项目的标配

PEP 518 引入了 `pyproject.toml`，它统一了 Python 项目的构建系统配置。现在，几乎所有现代工具（pytest、black、mypy、ruff 等）都在这个文件中配置。

```toml
# pyproject.toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "my-awesome-project"
version = "0.1.0"
description = "一个很棒的项目"
requires-python = ">=3.11"
dependencies = [
    "requests>=2.28",
    "click>=8.0",
    "pydantic>=2.0",
]

[project.optional-dependencies]
dev = [
    "pytest>=7.0",
    "black>=23.0",
    "mypy>=1.0",
    "ruff>=0.1.0",
]

[project.scripts]
mycli = "my_project.cli:main"

# 工具配置
[tool.pytest.ini_options]
testpaths = ["tests"]

[tool.black]
line-length = 88

[tool.ruff]
line-length = 88
select = ["E", "F", "I"]

[tool.mypy]
python_version = "3.11"
strict = true
```

小贴士：`pyproject.toml` 不是某个工具专属的配置文件，它是 Python 项目的"统一入口"。构建系统、项目元数据、工具配置都集中在这里。

## 21.4 Poetry：一站式项目管理

Poetry 是一个全功能的 Python 项目管理工具，集成了依赖管理、虚拟环境管理、打包发布于一体。

### 安装与初始化

```bash
# 安装 Poetry（推荐用官方安装脚本）
curl -sSL https://install.python-poetry.org | python3 -

# 创建新项目
poetry new my-project
# 自动生成标准项目结构

# 在已有项目中初始化
cd existing-project
poetry init  # 交互式创建 pyproject.toml
```

### 依赖管理

```bash
# 添加依赖
poetry add requests
poetry add "flask@^3.0"          # 兼容版本范围
poetry add --group dev pytest    # 开发依赖

# 移除依赖
poetry remove requests

# 更新依赖
poetry update                    # 更新所有
poetry update requests           # 更新指定包

# 安装所有依赖
poetry install

# 在虚拟环境中运行命令
poetry run python main.py
poetry run pytest
```

### 依赖锁定

Poetry 会生成 `poetry.lock` 文件，锁定所有依赖（包括间接依赖）的精确版本：

```bash
# poetry.lock 示例（自动生成，不要手动编辑）
[[package]]
name = "requests"
version = "2.31.0"
description = "Python HTTP for Humans."

[[package]]
name = "urllib3"
version = "2.1.0"
description = "HTTP library with thread-safe connection pooling"
# ...
```

锁定的意义：

- 开发环境和生产环境安装的包版本完全一致
- 团队协作时，所有人用相同的版本
- `poetry install` 会严格按 lock 文件安装
- `poetry update` 才会更新 lock 文件

## 21.5 uv：新一代极速包管理器

`uv` 是由 Astral（ruff 的开发团队）开发的超快速 Python 包管理器和项目管理工具。它用 Rust 编写，速度比 pip 和 Poetry 快 10-100 倍。

### 安装与基本使用

```bash
# 安装
curl -LsSf https://astral.sh/uv/install.sh | sh

# 或者用 pip
pip install uv

# 创建虚拟环境
uv venv

# 安装包
uv pip install requests flask

# 从 requirements.txt 安装
uv pip install -r requirements.txt

# 导出依赖
uv pip freeze > requirements.txt
```

### uv 作为项目管理工具

从 0.5 版本开始，uv 也可以像 Poetry 一样管理项目：

```bash
# 初始化新项目
uv init my-project
cd my-project

# 添加依赖（自动创建 pyproject.toml 和 uv.lock）
uv add requests
uv add --dev pytest black ruff

# 安装所有依赖
uv sync

# 运行脚本
uv run python main.py
uv run pytest

# 更新依赖
uv lock          # 更新 lock 文件
uv sync          # 根据 lock 文件安装
```

### uv 管理 Python 版本

uv 还能帮你管理 Python 本身：

```bash
# 安装指定版本的 Python
uv python install 3.12

# 列出可用的 Python 版本
uv python list

# 为项目指定 Python 版本
uv python pin 3.12
```

小贴士：`uv` 还在快速迭代中，功能越来越多。如果你是新项目，强烈推荐直接上手 `uv`——速度快、功能全、体验好。

## 21.6 工具选型指南

| 特性 | venv + pip | Poetry | uv |
| ------ | ----------- | -------- | ----- |
| 安装速度 | 慢 | 中等 | 极快 |
| 虚拟环境 | 手动管理 | 自动管理 | 自动管理 |
| 依赖锁定 | 无 | poetry.lock | uv.lock |
| 打包发布 | 需额外工具 | 内置 | 内置 |
| 学习曲线 | 低 | 中 | 中 |
| 成熟度 | 非常成熟 | 成熟 | 快速成长 |

推荐策略：

- **学习/小脚本**：`venv` + `pip` + `requirements.txt` 够用
- **正式项目**：`uv` 或 `poetry`（新项目优先 `uv`）
- **团队已有工具链**：跟着团队走，不要为了新潮换工具

## 21.7 依赖安全与更新

### 安全漏洞扫描

```bash
# 使用 pip-audit 检查已知漏洞
pip install pip-audit
pip-audit

# 使用 safety
pip install safety
safety check
```

### 依赖更新策略

```bash
# 查看哪些依赖有更新
pip list --outdated

# Poetry 查看
poetry show --outdated

# uv 查看
uv pip list --outdated

# 不要盲目升级到最新版本！
# 1. 先看 changelog，了解破坏性变更
# 2. 在测试环境先跑一遍测试
# 3. 逐个升级，不要一次升所有包
```

### 版本范围的最佳实践

```toml
# pyproject.toml 中的版本约束

# 太严格：只允许一个版本（升级困难）
dependencies = ["requests==2.31.0"]

# 太宽松：允许任何版本（可能引入不兼容更新）
dependencies = ["requests"]

# 推荐：允许兼容性更新（SemVer 思维）
dependencies = ["requests>=2.28,<3.0"]

# Poetry 的写法
[tool.poetry.dependencies]
requests = "^2.28"   # 允许 2.28.0 ~ 2.x.x
flask = "~3.0"       # 允许 3.0.x（更严格）
```

## 21.8 延伸阅读

- **PEP 518**：`pyproject.toml` 的引入提案
- **PEP 621**：在 `pyproject.toml` 中存储项目元数据
- **SemVer**（语义化版本）：major.minor.patch 的含义
- **pip-tools**：`pip-compile` 和 `pip-sync`，在 pip 上增加锁定功能

## 21.9 小结

- **venv**：Python 内置虚拟环境，给每个项目隔离的包空间
- **pip + requirements.txt**：最基础的依赖管理方式
- **pyproject.toml**：现代 Python 项目的统一配置文件
- **Poetry**：一站式项目管理工具，依赖管理 + 虚拟环境 + 打包
- **uv**：新一代极速工具，Rust 编写，速度碾压传统工具
- **依赖锁定**：保证团队和部署环境的一致性
- **安全扫描**：定期检查依赖的已知漏洞

6. 你的项目依赖 `flask==2.3.0`，安全扫描报告该版本有一个高危漏洞。描述你会如何处理这个情况（步骤）。

7. 对比 venv + pip、Poetry、uv 三种方案，写出各自的优缺点和适用场景。

## 21.11 参考答案

**第 2 题：**

`pip freeze` 导出环境中所有已安装包（包括间接依赖）的精确版本号。优点是完整，缺点是分不清哪些是你主动安装的、哪些是依赖拉进来的。手动维护只列出直接依赖，更清晰，但容易遗漏或忘记更新版本范围。推荐做法：直接依赖手动写版本范围，用锁定工具（Poetry/uv/pip-tools）处理精确版本。

**第 4 题：**

```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "my-web-app"
version = "0.1.0"
description = "My web application"
requires-python = ">=3.11"
dependencies = [
    "flask>=3.0,<4.0",
    "requests>=2.28,<3.0",
    "pydantic>=2.0,<3.0",
]

[project.optional-dependencies]
dev = [
    "pytest>=7.0",
    "black>=23.0",
    "ruff>=0.1.0",
]

[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-v"

[tool.ruff]
line-length = 88
select = ["E", "F", "I", "N"]
```

**第 5 题：**

SemVer `2.31.0`：2 是主版本（Major，不兼容的变更），31 是次版本（Minor，新增功能，向后兼容），0 是补丁版本（Patch，bug 修复）。`>=2.28,<3.0` 和 `^2.28`（Poetry 语法）含义相同：允许 2.28.0 到 2.x.x 的最新版本，但不允许 3.0.0。

**第 6 题：**

1. 查看漏洞详情（CVE 编号、影响范围、修复版本）
2. 检查是否有修复版本可用
3. 阅读修复版本的 changelog，确认是否有破坏性变更
4. 在开发环境升级 flask 并运行完整测试套件
5. 更新 `pyproject.toml` 或 `poetry.lock`
6. 提交 PR，在 CI 中确认测试通过
7. 部署到生产环境

## 21.12 常见错误与避坑

**1. 把虚拟环境提交到 Git**

```bash
# .gitignore 中必须有：
.venv/
venv/
__pycache__/
*.pyc
```

虚拟环境包含平台相关的二进制文件，提交到 Git 后别人克隆下来用不了。

**2. 全局安装太多包**

```bash
# 不要这样！
pip install requests flask django  # 装到系统 Python 里

# 应该在虚拟环境中安装
python -m venv .venv
source .venv/bin/activate
pip install requests flask django
```

**3. 不锁定依赖版本**

团队 A 装了 `requests==2.28`，团队 B 装了 `requests==2.31`，行为可能不同。用 `poetry.lock` 或 `uv.lock` 锁定版本。

**4. 混淆 pip install 和项目安装**

```bash
# 安装第三方包
pip install requests

# 安装你自己的项目（开发模式）
pip install -e .
# 或
pip install -e ".[dev]"  # 包括开发依赖
```

`-e`（editable）模式让你的代码修改立即生效，无需重新安装。

**5. 忘记激活虚拟环境就安装包**

新手最常犯的错误。看到命令行前面没有 `(.venv)` 就说明你没在虚拟环境里，安装的包会跑到系统 Python 中。
