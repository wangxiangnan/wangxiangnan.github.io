# 第10章：Events——发布订阅的优雅实现

## 引言：如果对象会"说话"

想象你在一个热闹的菜市场：

- 卖鱼的大叔突然吆喝："今天的带鱼便宜了！"（**发布事件**）
- 旁边所有想买鱼的人都听到了，纷纷围过来（**订阅者响应**）
- 而想买菜的人完全不受影响（**只有订阅了才会收到**）

这就是**发布-订阅模式（Pub/Sub）**，也是 Node.js 事件系统的核心思想。

在 Node.js 中，几乎所有 I/O 对象都是 EventEmitter 的实例：

- HTTP 服务器发出 'request' 事件
- Stream 发出 'data' 和 'end' 事件
- Process 发出 'exit' 事件

**EventEmitter 不只是一个工具类，它是 Node.js 的编程哲学。**

## 10.1 EventEmitter 核心 API

```javascript
import { EventEmitter } from 'node:events';

const emitter = new EventEmitter();

// on：注册监听器（持久的）
emitter.on('greet', (name: string) => {
  console.log(`Hello, ${name}!`);
});

// emit：触发事件
emitter.emit('greet', 'World');   // "Hello, World!"
emitter.emit('greet', 'Node.js'); // "Hello, Node.js!"

// once：注册一次性监听器
emitter.once('init', () => {
  console.log('只执行一次');
});
emitter.emit('init'); // "只执行一次"
emitter.emit('init'); // 无输出

// off / removeListener：移除监听器
const handler = (msg: string) => console.log(msg);
emitter.on('message', handler);
emitter.off('message', handler); // 需要传入原始函数引用！

// removeAllListeners：移除某事件的所有监听器
emitter.removeAllListeners('greet');

// listenerCount：获取监听器数量
console.log(emitter.listenerCount('greet')); // 0

// eventNames：获取所有注册了监听器的事件名
console.log(emitter.eventNames()); // ['message']
```

### 监听器执行顺序

```javascript
const emitter = new EventEmitter();

emitter.on('event', () => console.log('A'));
emitter.on('event', () => console.log('B'));
emitter.on('event', () => console.log('C'));

emitter.emit('event');
// A
// B
// C
// 按注册顺序执行（FIFO）

// prependListener：把监听器加到队列前面
emitter.prependListener('event', () => console.log('Z'));
emitter.emit('event');
// Z
// A
// B
// C
```

### emit 的返回值

```javascript
const emitter = new EventEmitter();

// emit 返回 boolean：是否有监听器被调用
console.log(emitter.emit('nobody-listens')); // false
emitter.on('someone-listens', () => {});
console.log(emitter.emit('someone-listens')); // true
```

## 10.2 继承 EventEmitter：面向事件编程

```typescript
import { EventEmitter } from 'node:events';

interface OrderEvents {
  created: [orderId: string, amount: number];
  paid: [orderId: string];
  shipped: [orderId: string, trackingNumber: string];
  cancelled: [orderId: string, reason: string];
}

class OrderService extends EventEmitter {
  // TypeScript：使用泛型约束事件类型
  declare emit: <K extends keyof OrderEvents>(
    event: K,
    ...args: OrderEvents[K]
  ) => boolean;
  declare on: <K extends keyof OrderEvents>(
    event: K,
    listener: (...args: OrderEvents[K]) => void
  ) => this;

  private orders: Map<string, { amount: number; status: string }> = new Map();

  createOrder(orderId: string, amount: number): void {
    this.orders.set(orderId, { amount, status: 'created' });
    this.emit('created', orderId, amount);
  }

  payOrder(orderId: string): void {
    const order = this.orders.get(orderId);
    if (!order) throw new Error(`订单不存在: ${orderId}`);
    order.status = 'paid';
    this.emit('paid', orderId);
  }

  shipOrder(orderId: string, trackingNumber: string): void {
    const order = this.orders.get(orderId);
    if (!order) throw new Error(`订单不存在: ${orderId}`);
    order.status = 'shipped';
    this.emit('shipped', orderId, trackingNumber);
  }

  cancelOrder(orderId: string, reason: string): void {
    const order = this.orders.get(orderId);
    if (!order) throw new Error(`订单不存在: ${orderId}`);
    order.status = 'cancelled';
    this.emit('cancelled', orderId, reason);
  }
}

// 使用
const orderService = new OrderService();

// 注册各种"关注者"
orderService.on('created', (id, amount) => {
  console.log(`[邮件系统] 新订单 ${id}，金额 ¥${amount}`);
});

orderService.on('paid', (id) => {
  console.log(`[库存系统] 订单 ${id} 已付款，准备发货`);
});

orderService.on('shipped', (id, tracking) => {
  console.log(`[短信系统] 订单 ${id} 已发货，快递号: ${tracking}`);
});

orderService.on('cancelled', (id, reason) => {
  console.log(`[退款系统] 订单 ${id} 已取消，原因: ${reason}`);
});

// 业务操作
orderService.createOrder('ORD-001', 299);
orderService.payOrder('ORD-001');
orderService.shipOrder('ORD-001', 'SF1234567890');
```

这个模式的美妙之处在于：**OrderService 不需要知道谁在监听它**。邮件系统、库存系统、短信系统都是独立的模块，它们只需要订阅感兴趣的事件。这就是**松耦合**。

## 10.3 内存泄漏警告：maxListeners

```javascript
import { EventEmitter } from 'node:events';

const emitter = new EventEmitter();

// 默认最多 10 个监听器
for (let i = 0; i < 11; i++) {
  emitter.on('event', () => {});
}
// Warning: Possible EventEmitter memory leak detected.
// 11 event listeners added to [EventEmitter].
// Use emitter.setMaxListeners() to increase limit.
```

**为什么有这个限制？**

因为如果你在循环或频繁调用的函数中不小心注册了监听器而没有移除，监听器会越来越多，最终导致内存泄漏。这个警告是 Node.js 在帮你发现这类 bug。

```javascript
// 调整限制（0 = 无限制）
emitter.setMaxListeners(20);

// 全局设置
EventEmitter.defaultMaxListeners = 20;

// 查看当前限制
console.log(emitter.getMaxListeners()); // 20
```

**最佳实践**：

```javascript
// ❌ 在循环中注册监听器而不移除
function handleRequest(req, res) {
  // 每次请求都会新增一个监听器！内存泄漏！
  db.on('connected', () => {
    res.end('ok');
  });
}

// ✅ 用 once 或者手动移除
function handleRequest(req, res) {
  db.once('connected', () => {
    res.end('ok');
  });
}
```

## 10.4 错误事件的特殊处理

在 EventEmitter 中，`'error'` 事件是特殊的：

```javascript
import { EventEmitter } from 'node:events';

const emitter = new EventEmitter();

// 如果触发 'error' 事件但没有监听器...
emitter.emit('error', new Error('出事了'));
// 💥 直接抛出异常！进程可能崩溃！

// 所以你必须监听 error 事件
emitter.on('error', (err) => {
  console.error('捕获到错误:', err.message);
});
emitter.emit('error', new Error('出事了'));
// "捕获到错误: 出事了"（安全处理）
```

**设计原则**：如果你的类继承了 EventEmitter，在发生错误时要 `emit('error', err)`。这样使用者可以自己决定怎么处理。

```javascript
class MyService extends EventEmitter {
  async doSomething() {
    try {
      // 某些操作
      await riskyOperation();
    } catch (err) {
      // 不要自己吞掉错误，emit 出去
      this.emit('error', err);
    }
  }
}
```

### 使用 errorMonitor（Node.js 13.6+）

```javascript
import { EventEmitter, errorMonitor } from 'node:events';

const emitter = new EventEmitter();

// errorMonitor 监听器不会阻止"未处理的错误"抛出
// 适合用来做日志/监控，而不影响错误处理逻辑
emitter.on(errorMonitor, (err) => {
  console.log('[监控] 捕获错误:', err.message);
  // 发送到错误追踪系统
});

// 如果没有 'error' 监听器，依然会抛出异常
// 但 errorMonitor 的回调会先执行
```

## 10.5 events.on()：将事件转为异步迭代器

```javascript
import { on } from 'node:events';
import { EventEmitter } from 'node:events';

const emitter = new EventEmitter();

// 模拟每秒发送一次数据
setInterval(() => {
  emitter.emit('data', { timestamp: Date.now(), value: Math.random() });
}, 1000);

// 5秒后停止
setTimeout(() => {
  emitter.emit('close');
}, 5000);

// 用 for await...of 消费事件
const ac = new AbortController();

setTimeout(() => ac.abort(), 5000);

try {
  for await (const [event] of on(emitter, 'data', { signal: ac.signal })) {
    console.log('收到数据:', event);
  }
} catch (err) {
  if (err.code === 'ABORT_ERR') {
    console.log('监听已停止');
  }
}
```

`events.on()` 将事件流转化为异步迭代器，这在很多场景下比 callback 更优雅：

```javascript
import { on } from 'node:events';
import { createServer } from 'node:http';

const server = createServer();
server.listen(3000);

// 用异步迭代器处理 HTTP 请求
for await (const [req, res] of on(server, 'request')) {
  res.writeHead(200, { 'Content-Type': 'text/plain' });
  res.end('Hello World\n');
}
```

## 10.6 EventTarget vs EventEmitter

Node.js 也实现了 Web 标准的 `EventTarget` API：

```javascript
// EventTarget（Web 标准）
const target = new EventTarget();

target.addEventListener('message', (event) => {
  console.log(event.type); // 'message'
  console.log(event.detail); // undefined（需要用 CustomEvent）
});

target.dispatchEvent(new Event('message'));

// 传递数据需要 CustomEvent（Node.js 19+不需要polyfill）
target.addEventListener('data', (event) => {
  console.log(event.detail); // { value: 42 }
});
target.dispatchEvent(new CustomEvent('data', { detail: { value: 42 } }));
```

### 对比

| 特性 | EventEmitter | EventTarget |
| ------ | ------------- | ------------- |
| 来源 | Node.js | Web 标准 |
| 传递参数 | 直接传参 | 包装在 Event 对象中 |
| 性能 | 更快 | 稍慢（Event 对象创建开销） |
| 跨平台 | Node.js only | 浏览器+Node.js+Deno |
| 事件类型 | 字符串/Symbol | 字符串 |
| 错误处理 | 特殊的 'error' 事件 | 无特殊处理 |

**选择建议**：Node.js 项目用 `EventEmitter`，跨平台库用 `EventTarget`。

## 10.7 AbortController / AbortSignal：优雅取消

AbortController 是取消异步操作的标准方式：

```javascript
// 取消 fetch 请求
const controller = new AbortController();

setTimeout(() => controller.abort(), 3000); // 3秒超时

try {
  const response = await fetch('https://slow-api.example.com/data', {
    signal: controller.signal,
  });
  const data = await response.json();
} catch (err) {
  if (err.name === 'AbortError') {
    console.log('请求超时，已取消');
  }
}
```

```javascript
// 取消 EventEmitter 监听
import { on } from 'node:events';

const ac = new AbortController();

// 用户按 Ctrl+C 时取消
process.on('SIGINT', () => ac.abort());

for await (const [data] of on(emitter, 'data', { signal: ac.signal })) {
  // 处理数据
}
```

```javascript
// 取消文件读取
import { readFile } from 'node:fs/promises';

const ac = new AbortController();
setTimeout(() => ac.abort(), 1000);

try {
  const data = await readFile('./huge-file.txt', {
    signal: ac.signal,
  });
} catch (err) {
  if (err.code === 'ABORT_ERR') {
    console.log('读取超时');
  }
}
```

### AbortSignal 的组合用法

```javascript
// AbortSignal.timeout()（Node.js 18+）
const signal = AbortSignal.timeout(5000); // 5秒后自动 abort

// AbortSignal.any()（Node.js 20+）
const userCancel = new AbortController();
const timeout = AbortSignal.timeout(10000);

// 任何一个信号触发都会取消
const combined = AbortSignal.any([userCancel.signal, timeout]);

try {
  await fetch(url, { signal: combined });
} catch (err) {
  if (err.name === 'AbortError') {
    console.log('请求被取消（用户操作或超时）');
  }
}
```

## 10.8 实战：带中间件的事件总线

让我们实现一个增强版的事件系统，支持中间件（类似 Express 的中间件概念）：

```typescript
import { EventEmitter } from 'node:events';

type Middleware<T = any> = (
  data: T,
  next: () => Promise<void>
) => Promise<void> | void;

interface EventBusOptions {
  maxListeners?: number;
  debug?: boolean;
}

class EventBus extends EventEmitter {
  private middlewares: Map<string, Middleware[]> = new Map();
  private debug: boolean;

  constructor(options: EventBusOptions = {}) {
    super();
    this.setMaxListeners(options.maxListeners || 100);
    this.debug = options.debug || false;
  }

  /**
   * 注册中间件
   */
  use(event: string, ...fns: Middleware[]): this {
    if (!this.middlewares.has(event)) {
      this.middlewares.set(event, []);
    }
    this.middlewares.get(event)!.push(...fns);
    return this;
  }

  /**
   * 发布事件（经过中间件处理后再分发）
   */
  async publish<T = any>(event: string, data: T): Promise<boolean> {
    const startTime = Date.now();

    if (this.debug) {
      console.log(`[EventBus] Publishing: ${event}`, data);
    }

    // 执行中间件链
    const middlewares = this.middlewares.get(event) || [];
    let index = 0;

    const next = async (): Promise<void> => {
      if (index < middlewares.length) {
        const mw = middlewares[index++];
        await mw(data, next);
      }
    };

    try {
      await next();
    } catch (err) {
      this.emit('error', err);
      return false;
    }

    // 中间件执行完毕后，触发事件
    const result = this.emit(event, data);

    if (this.debug) {
      const duration = Date.now() - startTime;
      console.log(`[EventBus] ${event} completed in ${duration}ms`);
    }

    return result;
  }

  /**
   * 订阅事件（语义化别名）
   */
  subscribe<T = any>(
    event: string,
    handler: (data: T) => void | Promise<void>
  ): this {
    this.on(event, handler);
    return this;
  }

  /**
   * 取消订阅
   */
  unsubscribe(event: string, handler: Function): this {
    this.off(event, handler as any);
    return this;
  }

  /**
   * 等待某个事件（Promise 化）
   */
  waitFor<T = any>(event: string, timeout?: number): Promise<T> {
    return new Promise((resolve, reject) => {
      const timer = timeout
        ? setTimeout(() => {
            this.off(event, handler);
            reject(new Error(`等待事件 "${event}" 超时 (${timeout}ms)`));
          }, timeout)
        : null;

      const handler = (data: T) => {
        if (timer) clearTimeout(timer);
        resolve(data);
      };

      this.once(event, handler);
    });
  }
}

// ====== 使用示例 ======

const bus = new EventBus({ debug: true });

// 中间件1：数据验证
bus.use('user:register', async (data: any, next) => {
  if (!data.email || !data.email.includes('@')) {
    throw new Error('邮箱格式无效');
  }
  console.log('[验证] 数据验证通过');
  await next();
});

// 中间件2：数据转换
bus.use('user:register', async (data: any, next) => {
  data.email = data.email.toLowerCase();
  data.createdAt = new Date().toISOString();
  console.log('[转换] 数据已标准化');
  await next();
});

// 中间件3：日志记录
bus.use('user:register', async (data: any, next) => {
  console.log('[日志] 用户注册:', JSON.stringify(data));
  await next();
});

// 订阅者：发送欢迎邮件
bus.subscribe('user:register', (data: any) => {
  console.log(`[邮件] 向 ${data.email} 发送欢迎邮件`);
});

// 订阅者：初始化用户配置
bus.subscribe('user:register', (data: any) => {
  console.log(`[配置] 为用户 ${data.email} 创建默认配置`);
});

// 错误处理
bus.on('error', (err) => {
  console.error('[EventBus Error]', err.message);
});

// 发布事件
await bus.publish('user:register', {
  email: 'Alice@Example.com',
  name: 'Alice',
});

// 等待事件
const result = await bus.waitFor('user:confirmed', 5000);
```

## 10.9 设计模式：观察者模式

EventEmitter 是观察者模式（Observer Pattern）的经典实现：

```
┌──────────────┐         emit('event')        ┌──────────────┐
│   Subject    │ ──────────────────────────▶  │  Observer A  │
│ (EventEmitter)│                              └──────────────┘
│              │                              ┌──────────────┐
│              │ ──────────────────────────▶  │  Observer B  │
│              │                              └──────────────┘
│              │                              ┌──────────────┐
│              │ ──────────────────────────▶  │  Observer C  │
└──────────────┘                              └──────────────┘
```

**观察者模式的优缺点**：

优点：

- 松耦合：发布者不需要知道订阅者
- 可扩展：新增订阅者不需要修改发布者
- 异步友好：天然适合异步编程

缺点：

- 难以追踪执行流程（事件触发链可能很长）
- 内存泄漏风险（忘记移除监听器）
- 顺序依赖时不太适用

## 10.10 常见坑点

### 坑1：this 绑定

```javascript
class MyClass extends EventEmitter {
  name = 'MyClass';

  constructor() {
    super();
    // ❌ 箭头函数：this 指向 MyClass 实例
    this.on('event', () => {
      console.log(this.name); // "MyClass" ✅
    });

    // ❌ 普通函数：this 指向 EventEmitter
    this.on('event', function () {
      console.log(this); // EventEmitter 实例，不是 MyClass！
    });
  }
}
```

### 坑2：异步监听器的错误

```javascript
const emitter = new EventEmitter();

// ❌ 异步监听器的错误不会被 'error' 事件捕获！
emitter.on('data', async (data) => {
  throw new Error('异步错误'); // 变成 unhandledRejection！
});

// ✅ 自己 try/catch
emitter.on('data', async (data) => {
  try {
    await riskyOperation(data);
  } catch (err) {
    emitter.emit('error', err);
  }
});
```

### 坑3：事件名拼写错误

```javascript
// ❌ 拼写错误不会报错，只是静默失败
emitter.on('conection', () => {}); // 少了一个 n！
emitter.emit('connection', data); // 永远不会触发上面的监听器

// ✅ 用 TypeScript + 类型声明来避免
// （见 10.2 的 OrderService 示例）
```

## 10.11 本章小结

EventEmitter 是 Node.js 事件驱动架构的基石。

| API | 用途 |
| ----- | ------ |
| on(event, fn) | 注册持久监听器 |
| once(event, fn) | 注册一次性监听器 |
| emit(event, ...args) | 触发事件 |
| off(event, fn) | 移除监听器 |
| events.on(emitter, event) | 事件转异步迭代器 |
| AbortController | 取消异步操作 |

**最佳实践**：

1. 始终监听 'error' 事件
2. 用 TypeScript 类型约束事件名和参数
3. 注意 maxListeners 警告，排查内存泄漏
4. 用 `once` 代替 `on` 防止忘记清理
5. 考虑用 AbortController 管理异步操作的生命周期
