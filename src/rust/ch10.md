# 第10章：错误处理

## 程序出错了，怎么办？

每个程序员都经历过：用户输入了非法数据、文件不存在、网络断了、数据库连不上。

Python 用 `try/except`，Java 用 `try/catch`（还有 checked exception 的噩梦），Go 用 `if err != nil`（重复到手软）。

Rust 的方案独树一帜：将错误分为两类：

- **不可恢复错误**：程序不应该继续运行 → `panic!`
- **可恢复错误**：可以合理处理的问题 → `Result<T, E>`

## panic!：不可恢复错误

```rust
fn main() {
    // panic!("程序崩溃了！");  // 会打印消息并终止程序

    // 常见触发 panic 的场景
    // let v = vec![1, 2, 3];
    // v[99];  // 数组越界 → panic

    // "123".parse::<i32>().unwrap();  // OK
    // "abc".parse::<i32>().unwrap();  // panic!
}
```

`panic!` 会打印错误消息、展开（unwind）调用栈并退出程序。在 `Cargo.toml` 中可以配置为直接中止（abort）：

```toml
[profile.release]
panic = 'abort'
```

## Result<T, E>：可恢复错误

```rust
use std::fs::File;
use std::io::Read;

fn read_file_contents(path: &str) -> Result<String, std::io::Error> {
    let result = File::open(path);

    let mut file = match result {
        Ok(f) => f,
        Err(e) => return Err(e),
    };

    let mut contents = String::new();
    match file.read_to_string(&mut contents) {
        Ok(_) => Ok(contents),
        Err(e) => Err(e),
    }
}

fn main() {
    match read_file_contents("hello.txt") {
        Ok(contents) => println!("文件内容:\n{contents}"),
        Err(e) => println!("读取文件失败: {e}"),
    }
}
```

## ? 运算符：简化错误传播

上面的代码太冗长了。`?` 运算符让错误传播变得简洁：

```rust
use std::fs::File;
use std::io::Read;

// 使用 ? 简化
fn read_file_v2(path: &str) -> Result<String, std::io::Error> {
    let mut file = File::open(path)?;     // 如果失败，直接返回 Err
    let mut contents = String::new();
    file.read_to_string(&mut contents)?;  // 如果失败，直接返回 Err
    Ok(contents)
}

// 更简洁：链式调用
fn read_file_v3(path: &str) -> Result<String, std::io::Error> {
    let mut contents = String::new();
    File::open(path)?.read_to_string(&mut contents)?;
    Ok(contents)
}

// 最简洁：直接用标准库
fn read_file_v4(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}

fn main() {
    // 测试（文件可能不存在）
    match read_file_v4("hello.txt") {
        Ok(c) => println!("成功: {} 字节", c.len()),
        Err(e) => println!("失败: {e}"),
    }
}
```

> **注意**：`?` 只能在返回 `Result` 或 `Option` 的函数中使用。在 `main` 函数中也可以用，但需要把 main 的返回类型改为 `Result<(), Box<dyn std::error::Error>>`。

## unwrap 与 expect

```rust
fn main() {
    // unwrap：如果 Err 就 panic，适合"这绝对不可能失败"的场景
    let num: i32 = "42".parse().unwrap();
    println!("{num}");

    // expect：和 unwrap 一样，但可以自定义 panic 消息
    let config = std::env::var("HOME").expect("HOME 环境变量必须存在");
    println!("HOME = {config}");
}
```

**何时使用 unwrap/expect？**

- 测试代码中
- 你 100% 确定不会失败的情况（如解析硬编码的常量字符串）
- 原型开发阶段（但生产代码应该正确处理错误）

**何时不使用？**

- 用户输入处理
- 文件/网络/数据库操作
- 任何可能合理失败的场景

## 在 main 中使用 ?

```rust
use std::fs::File;
use std::io::Read;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut file = File::open("config.txt")?;
    let mut contents = String::new();
    file.read_to_string(&mut contents)?;
    println!("配置: {contents}");
    Ok(())
}
```

## 自定义错误类型

```rust
use std::fmt;
use std::num::ParseIntError;

// 自定义错误枚举
#[derive(Debug)]
enum AppError {
    IoError(std::io::Error),
    ParseError(ParseIntError),
    InvalidInput(String),
}

// 实现 Display trait（用户友好的错误消息）
impl fmt::Display for AppError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            AppError::IoError(e) => write!(f, "IO 错误: {e}"),
            AppError::ParseError(e) => write!(f, "解析错误: {e}"),
            AppError::InvalidInput(msg) => write!(f, "无效输入: {msg}"),
        }
    }
}

// 实现 From trait，支持 ? 自动转换
impl From<std::io::Error> for AppError {
    fn from(e: std::io::Error) -> Self {
        AppError::IoError(e)
    }
}

impl From<ParseIntError> for AppError {
    fn from(e: ParseIntError) -> Self {
        AppError::ParseError(e)
    }
}

fn parse_age(input: &str) -> Result<u32, AppError> {
    let age: u32 = input.trim().parse()?;  // ParseIntError 自动转换为 AppError
    if age > 150 {
        return Err(AppError::InvalidInput(format!("年龄 {age} 不合理")));
    }
    Ok(age)
}

fn main() {
    let test_inputs = vec!["25", "abc", "200"];
    for input in test_inputs {
        match parse_age(input) {
            Ok(age) => println!("'{input}' → 年龄: {age}"),
            Err(e) => println!("'{input}' → 错误: {e}"),
        }
    }
}
```

## anyhow 与 thiserror 简介

实际项目中，手写所有 `From` 实现太繁琐。社区有两个流行的错误处理库：

**thiserror**（库作者用）—— 为自定义错误类型减少样板代码：

```rust
// Cargo.toml: thiserror = "1"
// use thiserror::Error;
//
// #[derive(Error, Debug)]
// enum AppError {
//     #[error("IO 错误: {0}")]
//     Io(#[from] std::io::Error),
//     #[error("解析错误: {0}")]
//     Parse(#[from] std::num::ParseIntError),
//     #[error("无效输入: {msg}")]
//     InvalidInput { msg: String },
// }
```

**anyhow**（应用开发者用）—— 万能错误类型，适合应用层代码：

```rust
// Cargo.toml: anyhow = "1"
// use anyhow::{Result, Context, bail};
//
// fn process(path: &str) -> Result<String> {
//     let contents = std::fs::read_to_string(path)
//         .context("读取配置文件失败")?;
//
//     if contents.is_empty() {
//         bail!("配置文件不能为空");  // 等价于 return Err(anyhow!("..."))
//     }
//
//     Ok(contents)
// }
```

## 错误处理最佳实践

```rust
use std::fs;
use std::io;

// 1. 在库代码中，返回具体的错误类型
fn read_config(path: &str) -> Result<String, io::Error> {
    fs::read_to_string(path)
}

// 2. 使用 map_err 丰富错误信息
fn load_user_data(user_id: u32) -> Result<String, String> {
    let path = format!("data/{}.json", user_id);
    fs::read_to_string(&path)
        .map_err(|e| format!("加载用户 {user_id} 的数据失败 ({path}): {e}"))
}

// 3. unwrap_or_else 提供降级方案
fn get_port() -> u16 {
    std::env::var("PORT")
        .ok()
        .and_then(|s| s.parse().ok())
        .unwrap_or(8080)  // 默认端口
}

fn main() {
    // 测试
    println!("端口: {}", get_port());

    match load_user_data(42) {
        Ok(data) => println!("数据: {data}"),
        Err(msg) => println!("错误: {msg}"),
    }
}
```

**错误处理决策树：**

```
程序出错了
├── 这个错误能否合理处理？
│   ├── 能 → 用 Result<T, E>，让调用方决定怎么处理
│   └── 不能 → 用 panic!（或 expect 带消息）
├── 你在写库还是应用？
│   ├── 库 → 用 thiserror，返回具体错误类型
│   └── 应用 → 用 anyhow，简化错误处理
└── 你在写测试或原型？
    └── 用 unwrap/expect 就好
```

## 常见陷阱

1. **滥用 unwrap()**：生产代码中应该尽量避免，它会隐藏错误
2. **? 只能用在返回 Result/Option 的函数中**：在普通函数中用会编译错误
3. **忘记处理所有错误类型**：`match` 或 `?` + `From` 要覆盖所有可能的错误
4. **错误信息不够详细**：用 `map_err` 或 `context` 添加上下文信息

## 小结

- `panic!` 用于不可恢复的错误，程序必须终止
- `Result<T, E>` 用于可恢复的错误，`Ok` 和 `Err` 两个变体
- `?` 运算符让错误传播变得简洁优雅
- `unwrap/expect` 仅在确定不会失败时使用
- 库用 `thiserror`，应用用 `anyhow`
- 错误处理是 Rust 类型系统的核心优势之一——编译器不允许你忽略错误
