# 第8章：搜索与替换高级技巧

> "Measuring programming progress by lines of code is like measuring aircraft building progress by weight." —— Bill Gates

但查找代码的进度呢？那大概可以用"找到 bug 的速度"来衡量。而搜索能力，正是决定这个速度的核心变量。VSCode 的搜索系统远比你想象的强大——它底层用的是 [ripgrep](https://github.com/BurntSushi/ripgrep)（`rg`），一个用 Rust 写的、快到离谱的搜索引擎。如果你只用过 `Ctrl+F` 搜索当前文件，那你大概只用了它 10% 的功力。

这一章，我们要把搜索系统的全部潜力释放出来——从基础的文件过滤，到正则表达式的高级模式，到搜索编辑器这种"把搜索结果当文件编辑"的黑科技。

## 8.1 搜索面板全功能解析

打开搜索面板：`Ctrl+Shift+F`（⌘+Shift+F）。你会看到搜索框下方有一排小图标和折叠区域。让我们逐一拆解：

## 搜索修饰符

| 图标/快捷键 | 功能 | 说明 |
| ------------- | ------ | ------ |
| `Aa` | 大小写敏感 | 区分 `hello` 和 `Hello` |
| `W` / `\b` | 全词匹配 | 只匹配完整单词，`cat` 不匹配 `concat` |
| `.*` | 正则表达式 | 启用正则搜索 |

这三个可以组合使用。比如开启正则 + 大小写敏感，你可以精确搜索特定模式的代码。

## 文件过滤：包含与排除

这是大项目中搜索效率的关键。搜索框下方的 **files to include** 和 **files to exclude** 支持以下语法：

```
# 包含特定目录
src/**

# 包含特定文件类型
**/*.ts

# 多个条件用逗号分隔
src/**/*.ts, lib/**/*.ts

# 排除测试文件和构建产物
**/node_modules/**, **/dist/**, **/*.test.ts

# 排除特定目录
**/.git/**, **/coverage/**
```

> 💡 **Pro Tip**: VSCode 默认会自动排除 `.gitignore` 中列出的文件（如 `node_modules`、`dist`），这由设置 `search.useIgnoreFiles` 控制。如果你需要搜索这些文件，可以在搜索面板点击"使用 .gitignore"图标切换。

## 搜索配置项

在 `settings.json` 中，以下搜索相关设置值得了解：

```json
{
    // 搜索时排除的文件/目录（全局生效）
    "search.exclude": {
        "**/node_modules": true,
        "**/dist": true,
        "**/build": true,
        "**/.git": true,
        "**/coverage": true
    },
    // 是否使用 .gitignore 规则
    "search.useIgnoreFiles": true,
    // 搜索时是否跟随符号链接
    "search.followSymlinks": false,
    // 搜索结果的最大数量（默认20000）
    "search.maxResults": 20000,
    // 搜索时是否在打开的编辑器中搜索
    "search.searchOnType": true
    // 搜索时预览（输入时实时搜索）
}
```

## 8.2 正则表达式搜索的实用模式

正则搜索是 VSCode 搜索系统的核武器。以下是一些在真实开发中极为实用的正则模式：

## 查找所有 TODO/FIXME/HACK 注释

```
(TODO|FIXME|HACK|XXX|TEMP)\s*:?[\s\w]*
```

配合 `files to include` 限定为 `src/**`，一次性看到项目中所有的"技术债务清单"。

## 查找 console.log（忘记删除的调试代码）

```
console\.(log|debug|info|warn)\(
```

找到之后，你可以一键全部替换为空或者加上条件判断：

```
// 替换为
if (process.env.NODE_ENV === 'development') console.log(
```

或者更干脆——直接批量删除。

## 查找未使用的 import（简化版）

这个比较 trick，但以下正则可以找到一些可疑的未使用导入：

```
^import\s+.*\s+from\s+['"].*['"];?\s*$
```

然后你人工检查（或者用 ESLint 的 `no-unused-imports` 规则更靠谱）。

## 查找硬编码的 URL 或 IP 地址

```
https?://[^\s'"]+|(\d{1,3}\.){3}\d{1,3}
```

这在安全审计时非常有用——快速找到代码中所有的外部链接和硬编码地址。

## 查找重复的 CSS 属性

```
(\w+\s*:\s*[^;]+;)[\s\S]*?\1
```

## 查找超过一定长度的函数

这个比较复杂，但思路是搜索函数声明和结束标记之间的大致行数：

```
function\s+\w+\s*\([^)]*\)\s*\{
```

然后用搜索结果的位置信息来判断函数体的长度（当然，用 linter 规则更可靠）。

## 8.3 跨文件批量替换的安全操作

批量替换是高风险操作——一不小心就可能改坏几十个文件。VSCode 提供了几个安全机制：

## 替换前的审查流程

1. 搜索匹配项（`Ctrl+Shift+F` / ⌘+Shift+F）
2. 展开替换框（点击搜索框左侧的 `▽` 或 `Ctrl+Shift+H` / ⌘+⌥+F）
3. **逐个审查**：点击每个搜索结果旁的替换按钮，或跳过不需要替换的
4. **批量替换**：确认无误后点击全部替换（`Ctrl+Alt+Enter` / ⌘+⌥+Enter）

## 替换中的正则引用

正则替换最强大的特性是**捕获组引用**（`$1`、`$2` 等）。例如：

**将所有 `camelCase` 变量名改成 `snake_case`**（简化版，仅处理简单情况）：

搜索：

```
(\w+)([A-Z])(\w+)
```

替换：

```
$1_$2$3
```

**将 `import { X } from 'y'` 改为 `const { X } = require('y')`**（CommonJS 迁移）：

搜索：

```
import\s+\{([^}]+)\}\s+from\s+['"]([^'"]+)['"];?
```

替换：

```
const {$1} = require('$2');
```

**将 `function foo(a, b) {` 改为箭头函数 `const foo = (a, b) => {`**：

搜索：

```
function\s+(\w+)\s*\(([^)]*)\)\s*\{
```

替换：

```
const $1 = ($2) => {
```

## 保留大小写的替换

在正则替换中，VSCode 不支持原生的大小写转换（如将捕获组转为大写）。对于这类需求，建议使用 **搜索编辑器** 配合多光标编辑，或者写一个小脚本。

## 8.4 搜索编辑器：把搜索结果当文件编辑

这是 VSCode 的一个隐藏神器。打开方式：

- `Ctrl+Shift+P`（⌘+Shift+P）→ **Search Editor: Open New Search Editor**
- 或者在搜索面板结果中右键 → **Open in Editor**

搜索编辑器是一个普通的 `.code-search` 文件，但内容是搜索结果的实时快照。你可以在里面：

- **多光标编辑**搜索结果
- **搜索替换**（在编辑器内再做一轮 refine）
- **复制粘贴**搜索结果到文档或 PR 描述中
- **保存**为文件供以后参考
- 用 `Ctrl+D`（⌘+D）选中下一个相同词，批量修改

```
# 搜索编辑器内容示例
// 文件: src/utils/api.ts (3个匹配)

12: export const API_BASE = "http://localhost:3000";
15: const timeout = 5000;
42: fetch(`${API_BASE}/users`)

// 文件: src/services/auth.ts (2个匹配)

8: import { API_BASE } from '../utils/api';
23: const url = `${API_BASE}/auth/login`;
```

在搜索编辑器中，你可以直接编辑这些行，然后 **Apply to workspace**（通过命令面板），将修改回写到对应文件的对应行。这在做精细化的跨文件重构时极为有用。

## 8.5 搜索结果的上下文显示

默认情况下，搜索结果只显示匹配行。但你可以通过设置 `search.showLineNumbers` 和编辑器搜索中的 `Toggle Context Lines` 来显示匹配行前后的上下文：

在编辑器内搜索（`Ctrl+F` / ⌘+F）时，点击搜索框右侧的 **Toggle Context Lines** 按钮（或使用设置），可以显示每处匹配前后各 N 行的内容。这在理解代码上下文时非常有用——你不需要逐个点开文件就能判断某个搜索结果是否是你需要的。

## 8.6 实战：一次真实的重构场景

假设你接手了一个老项目，需要将所有的回调风格 API 迁移到 async/await 风格。搜索系统是你的第一把武器。

**第一步：定位所有回调风格的代码**

搜索正则：

```
\w+\(\s*function\s*\(\s*(err|error)\s*,
```

这能找到所有 `xxx(function(err, data) {` 风格的回调调用。

**第二步：缩小范围**

`files to include`: `src/**/*.js`
`files to exclude`: `**/*.test.js, **/vendor/**`

**第三步：分析结果并制定替换策略**

发现有三类回调模式：

1. `fs.readFile(path, function(err, data) { ... })` → `await fs.promises.readFile(path)`
2. `request.get(url, function(err, res, body) { ... })` → `await axios.get(url)`
3. `db.query(sql, function(err, results) { ... })` → `await db.query(sql)`

**第四步：分模式批量替换**

对每种模式分别搜索和替换：

搜索（模式1）：

```
fs\.readFile\(\s*([^,]+),\s*function\s*\(err,\s*(\w+)\)\s*\{
```

替换：

```
const $2 = await fs.promises.readFile($1);
try {
```

**第五步：验证**

搜索替换后是否有遗漏：

```
function\s*\(err
```

如果结果为零，恭喜，迁移完成（当然还要跑一遍测试来确认）。

## 8.7 进阶：ripgrep 命令行直接搜索

既然 VSCode 底层用的是 ripgrep，你也可以直接在终端里用它。VSCode 内置了 `rg` 二进制文件，你也可以全局安装：

```bash
# macOS
brew install ripgrep

# Windows (scoop)
scoop install ripgrep

# Linux (Ubuntu)
sudo apt install ripgrep
```

一些比 VSCode 搜索面板更灵活的命令行用法：

```bash
# 搜索并显示前后3行上下文
rg -C 3 "TODO" src/

# 只列出包含匹配的文件名
rg -l "console\.log" --type js

# 搜索特定类型的文件
rg --type ts "interface\s+\w+Props"

# 搜索并计数
rg -c "import.*from" src/

# 使用更复杂的正则（PCRE2 模式）
rg --pcre2 "(?<=export\s)class\s+\w+"

# 搜索压缩/格式化文件（通常被跳过）
rg --search-zip "license" node_modules/

# 以 JSON 格式输出（方便脚本处理）
rg --json "TODO" src/ | jq '.data'

# 搜索并自动打开 VSCode 对应位置
rg -n "function.*deprecated" src/ | while IFS=: read file line rest; do
    code -g "$file:$line"
done
```

## 8.8 进阶：搜索替代工具集成

VSCode 的搜索虽然强大，但在某些场景下，专用工具可能更合适：

```json
// settings.json - 集成外部搜索工具
{
    // 使用 rg 作为默认终端搜索工具
    "terminal.integrated.defaultProfile.windows": "PowerShell",
    // 自定义终端命令别名
}
```

你也可以安装扩展来增强搜索体验：

- **Search Highlight**：高亮所有搜索结果
- **Todo Tree**：将 TODO 注释以树形视图展示
- **Grep**：在 VSCode 中提供 rg 的 GUI 封装

📋 **本章小结**

- VSCode 搜索底层使用 **ripgrep**，性能极强
- **files to include/exclude** 配合 glob 模式可以精确控制搜索范围
- **正则搜索**是跨文件重构的核心武器，掌握常用模式能大幅提升效率
- **批量替换**支持捕获组引用（`$1`、`$2`），可以做复杂的代码转换
- **搜索编辑器**让你像编辑文件一样编辑搜索结果，适合精细化重构
- 直接使用 **ripgrep 命令行**可以获得更灵活的搜索能力
- `.gitignore` 文件会自动影响搜索范围，通过设置可以控制此行为
