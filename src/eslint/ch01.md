# ESLint Flat Config 完全指南

> 基于 ESLint 9+ flat config，覆盖 Vue 3 + TypeScript 项目实战配置。

---

## 一、ESLint 是什么

ESLint 是一个 JavaScript/TypeScript 的**静态代码分析工具**。它不运行你的代码，而是通过解析源码生成 AST（抽象语法树），再用规则集逐条检查，发现潜在的代码质量问题和风格问题。

ESLint 的工作流程可以概括为三步：

1. **解析** — 将源码转换为 AST
2. **匹配** — 用规则遍历 AST，查找问题
3. **报告** — 输出错误或警告，部分规则支持自动修复（`--fix`）

---

## 二、Flat Config 是什么

ESLint 9 引入了 flat config（扁平配置），取代了沿用多年的 `.eslintrc` 格式。核心变化是：配置文件从 `.eslintrc.js` / `.eslintrc.json` 变为 `eslint.config.js`（或 `.mjs`），配置格式从嵌套对象变为**配置对象数组**。

### 旧版 vs Flat Config

| 特性 | 旧版 `.eslintrc` | Flat Config `eslint.config.js` |
|------|------------------|-------------------------------|
| 配置继承 | `extends` 链式层级合并 | 数组线性展开，后者覆盖前者 |
| 文件匹配 | `overrides` 嵌套 | `files` 字段直接在配置块中 |
| 插件引用 | 字符串名称，隐式解析 | 直接 import，显式注册 |
| 全局变量 | `env` 字段 | `languageOptions.globals` |
| 忽略文件 | `.eslintignore` 文件 | `ignores` 配置块 |
| 配置文件 | 多层级可叠加 | 单一入口，所见即所得 |

### 核心原则：数组有序，后者覆盖前者

Flat config 导出的数组是**有序线性合并**。每个元素是一个配置块，后面的配置块覆盖前面的。这是理解整个 flat config 的基础：

```js
export default [
  configA,    // 优先级最低
  configB,    // 覆盖 A 中的同名字段
  configC,    // 优先级最高
]
```

**覆盖规则的细节：**

- **`rules`**：合并覆盖。前面设了 10 条规则，后面只写了 2 条，结果是那 2 条被覆盖，其余 8 条保持不变。
- **`languageOptions`**：浅合并。如果后面重新赋值了 `languageOptions`，会整体替换前面的值，不会深度合并。
- **`plugins`**：合并。后面新增的插件不会清掉前面的，同名的会覆盖。
- **`files` / `ignores`**：不参与覆盖，它们是过滤器，决定当前配置块对哪些文件生效。

## 三、案例配置逐行解析

以下是一个 Vue 3 + TypeScript 项目的典型 ESLint flat config：

```js
import js from "@eslint/js";
import globals from "globals";
import tseslint from "typescript-eslint";
import pluginVue from "eslint-plugin-vue";
import { defineConfig } from "eslint/config";

export default defineConfig([
  {
    files: ["**/*.{js,mjs,cjs,ts,mts,cts,vue}"],
    plugins: { js },
    extends: ["js/recommended"],
    languageOptions: { globals: globals.browser },
  },
  tseslint.configs.recommended,
  pluginVue.configs["flat/essential"],
  {
    files: ["**/*.vue"],
    languageOptions: { parserOptions: { parser: tseslint.parser } },
  },
]);
```

下面逐块解析。

---

### 3.1 第一个配置块：JS 基础规则

```js
{
  files: ["**/*.{js,mjs,cjs,ts,mts,cts,vue}"],
  plugins: { js },
  extends: ["js/recommended"],
  languageOptions: { globals: globals.browser },
}
```

#### `files`

指定这个配置块对哪些文件生效，使用 glob 模式。这里匹配所有常见的 JS/TS/Vue 文件扩展名。不在匹配范围内的文件（如 `.json`、`.css`）不受此块影响。

#### `plugins`

注册 ESLint 插件。`{ js }` 是 ES6 属性简写，等同于 `{ js: js }`，将 `@eslint/js` 插件以 `js` 为键注册进来。注册后，规则名中可以用 `js/xxx` 前缀引用该插件的规则。

#### `extends`

继承预设规则集。`"js/recommended"` 指 `@eslint/js` 插件导出的 `recommended` 预设，包含 ESLint 官方推荐的核心规则（如 `no-unused-vars`、`no-undef` 等）。其中 `js` 对应 `plugins` 中注册的键名，`recommended` 是预设名。

#### `languageOptions.globals`

声明当前环境的全局变量，防止 `no-undef` 规则误报。`globals.browser` 包含浏览器环境的标准全局变量：

```js
globals.browser
// → { window: 'readonly', document: 'readonly', console: 'readonly',
//     setTimeout: 'readonly', fetch: 'readonly', ... }
```

值有三种：`'readonly'`（只读）、`'writable'`（可写）、`'off'`（禁用）。推荐配置中基本为 `readonly`，防止意外覆盖全局变量。

常用环境预设：

| 预设 | 包含的全局变量 | 适用场景 |
|------|---------------|---------|
| `globals.browser` | `window`, `document`, `fetch` 等 | 前端应用 |
| `globals.node` | `process`, `__dirname`, `require` 等 | Node.js 服务 / 构建脚本 |
| `globals.es2022` | `Promise`, `Map`, `globalThis` 等 | 现代 JS 标准内置对象 |

---

### 3.2 第二个配置块：TypeScript 规则

```js
tseslint.configs.recommended
```

`typescript-eslint` 是一个插件集合，为 ESLint 提供 TypeScript 支持。它导出的 `configs.recommended` 本身就是一个配置数组，包含：

- TypeScript 专属的 parser（`@typescript-eslint/parser`）
- 一套推荐的 TS 规则（如 `@typescript-eslint/no-unused-vars`、`@typescript-eslint/no-explicit-any` 等）

用 `...` 展开或直接放在数组中，这些配置块会追加到整体配置里。后面的配置优先级高于前面的，因此 TS 规则会覆盖 JS 基础规则中的同名规则。

---

### 3.3 第三个配置块：Vue 规则

```js
pluginVue.configs["flat/essential"]
```

`eslint-plugin-vue` 是 Vue 官方的 ESLint 插件，提供数十条 Vue 模板和脚本相关的规则。`flat/essential` 是专为 flat config 设计的预设，内部包含：

- **规则集**：如 `vue/no-unused-vars`、`vue/require-v-for-key` 等
- **Parser 配置**：内部已指定 `vue-eslint-parser` 作为 `.vue` 文件的外层 parser
- **文件匹配**：`files: ['**/*.vue']`

#### Parser 解析链

Vue 单文件组件（SFC）包含 `<template>` 和 `<script>` 两部分，它们不是标准的 JS/TS 语法，需要特殊的解析链：

```
.vue 文件
  ↓
外层 parser: vue-eslint-parser（拆解 SFC 结构）
  ├── <template> → 解析为 Vue 模板 AST → 供 vue 规则检查
  └── <script>   → 委托给 parserOptions.parser 解析
                    → 默认: espree（只认纯 JS）
                    → 配置后: tseslint.parser（支持 TS）
```

`pluginVue.configs["flat/essential"]` 已经设置了外层 parser 为 `vue-eslint-parser`，因此你不需要手动 import 它。

---

### 3.4 第四个配置块：为 Vue 文件指定 TS Parser

```js
{
  files: ["**/*.vue"],
  languageOptions: {
    parserOptions: {
      parser: tseslint.parser,
    },
  },
}
```

这个块专门处理 Vue 文件中 `<script lang="ts">` 的情况。

**为什么需要它？** `pluginVue.configs["flat/essential"]` 虽然设了外层 parser，但 `<script>` 部分默认委托给 `espree`（ESLint 内置 parser），只认纯 JavaScript。如果你的 Vue 组件使用了 `<script lang="ts">`，里面有类型注解、接口、泛型等 TS 语法，`espree` 无法解析，会直接报错。

**它做了什么？** 只覆盖 `parserOptions.parser`，将内层委托 parser 从 `espree` 换为 `tseslint.parser`，同时不影响外层的 `vue-eslint-parser`。

**兼容性：** `tseslint.parser` 同时支持纯 JS 和 TS 代码，所以无论 `<script>` 还是 `<script lang="ts">` 都能正确处理，无需区分配置。

---

### 3.5 整体优先级

回顾完整配置，四个块的优先级从低到高：

```
数组位置   配置块                          作用
─────────────────────────────────────────────────────
[0]       JS 基础规则块                   最宽泛的 JS 规则 + 浏览器环境
[1]       tseslint.configs.recommended   TS 规则覆盖/补充 JS 规则
[2]       pluginVue.configs.flat/essential  Vue 规则 + 模板 parser
[3]       .vue 文件的 parserOptions 块    覆盖内层 parser 为 TS parser
```

后面的配置优先级更高，这就是 flat config "线性覆盖"的核心机制。

## 四、Prettier 集成

ESLint 负责**代码质量**（逻辑错误、潜在 bug），Prettier 负责**代码格式**（缩进、引号、换行）。两者各司其职，不应混用。

### 4.1 安装

```bash
pnpm add -D prettier eslint-config-prettier -w
```

- `prettier`：格式化工具本体
- `eslint-config-prettier`：关闭所有与 Prettier 冲突的 ESLint 格式规则

### 4.2 配置

将 `prettierConfig` 放在配置数组的**最末尾**，确保它的"关闭规则"优先级最高：

```js
import prettierConfig from "eslint-config-prettier";

export default defineConfig([
  // ... 其他配置块
  prettierConfig,  // ← 必须最后
]);
```

### 4.3 为什么不使用 eslint-plugin-prettier

`eslint-plugin-prettier` 会把 Prettier 作为 ESLint 的一条规则运行，每次 lint 都启动 Prettier，速度慢且职责混乱。当前最佳实践是让两个工具独立工作：

```json
{
  "scripts": {
    "lint": "eslint .",
    "format": "prettier --write .",
    "format:check": "prettier --check ."
  }
}
```

## 五、`ignores` 字段

Flat config 取消了 `.eslintignore` 文件，忽略规则直接写在配置中。

### 全局忽略

如果一个配置块**只有** `ignores` 字段，它是全局忽略，对整个扫描范围生效，与位置无关：

```js
{
  ignores: ["**/dist/**", "**/*.config.{js,ts}", "**/*.d.ts"],
}
```

### 局部忽略

如果 `ignores` 与其他字段（如 `files`、`rules`）出现在同一块中，它只缩小当前块的生效范围：

```js
{
  files: ["**/*.ts"],
  ignores: ["**/*.test.ts"],  // 只影响当前块，不是全局忽略
  rules: { /* ... */ },
}
```

### 注意事项

- `node_modules` 和 `.git` 目录 ESLint 默认忽略，无需声明。
- 全局忽略的 `ignores` 块与数组中的位置无关，放哪都一样。
- 路径是相对于 `eslint.config.js` 所在目录的。

## 六、Monorepo 中的 ESLint 组织

在 pnpm workspace + Turborepo 的 monorepo 项目中，推荐以下结构：

```
my-monorepo/
├── apps/
│   ├── vue3-app/
│   │   └── eslint.config.js
│   └── vue2-app/
│       └── eslint.config.js
├── packages/
│   ├── utils/
│   │   └── eslint.config.js
│   └── shared-types/
│       └── eslint.config.js
├── eslint.config.js           ← 共享基础配置（导出配置块）
├── pnpm-workspace.yaml
└── turbo.json
```

### 6.1 根目录：导出可复用配置块

```js
// 根目录 eslint.config.js
import js from "@eslint/js";
import tseslint from "typescript-eslint";
import globals from "globals";

export const base = [
  js.configs.recommended,
  {
    languageOptions: {
      globals: { ...globals.node, ...globals.es2022 },
    },
    rules: {
      "no-console": "warn",
      "no-debugger": "warn",
    },
  },
  {
    ignores: ["**/dist/**", "**/*.config.{js,ts}", "**/*.d.ts"],
  },
];

export const typescript = [...tseslint.configs.recommended];
```

### 6.2 TS 库子包：最简配置

```js
// packages/utils/eslint.config.js
import { base } from "../../eslint.config.js";
import prettierConfig from "eslint-config-prettier";

export default [
  ...base,
  prettierConfig,
];
```

### 6.3 Vue 3 应用

```js
// apps/vue3-app/eslint.config.js
import { base } from "../../eslint.config.js";
import pluginVue from "eslint-plugin-vue";
import tseslint from "typescript-eslint";
import prettierConfig from "eslint-config-prettier";

export default [
  ...base,
  ...pluginVue.configs["flat/recommended"],
  {
    files: ["**/*.vue"],
    languageOptions: { parserOptions: { parser: tseslint.parser } },
  },
  prettierConfig,
];
```

### 6.4 Vue 2 应用

```js
// apps/vue2-app/eslint.config.js
import { base } from "../../eslint.config.js";
import pluginVue from "eslint-plugin-vue";
import tseslint from "typescript-eslint";
import prettierConfig from "eslint-config-prettier";

export default [
  ...base,
  ...pluginVue.configs["flat/vue2-recommended"],  // Vue 2 专属预设
  {
    files: ["**/*.vue"],
    languageOptions: { parserOptions: { parser: tseslint.parser } },
  },
  prettierConfig,
];
```

### 6.5 Turborepo 集成

```json
// turbo.json
{
  "tasks": {
    "lint": { "cache": true, "outputs": [] },
    "format:check": { "cache": true, "outputs": [] }
  }
}
```

每个子包 `package.json`：

```json
{
  "scripts": {
    "lint": "eslint .",
    "format": "prettier --write .",
    "format:check": "prettier --check ."
  }
}
```

运行 `turbo run lint` 即可并行检查所有子包，且带缓存。

## 七、常见问题

### Q1：Vue 文件里的 TS 规则不生效？

TS 规则通常配在 `files: ['**/*.ts']` 中，不会匹配 `.vue` 文件。需要给 `.vue` 文件单独配一个块，或在 TS 规则的 `files` 中同时包含 `.vue`：

```js
{ files: ["**/*.ts", "**/*.vue"], rules: { /* TS 规则 */ } }
```

### Q2：`languageOptions` 覆盖时丢失了 `globals`？

`languageOptions` 是浅合并。如果后面的配置块重新赋值了 `languageOptions` 但没写 `globals`，前面的 `globals` 会丢失。解决：每次写 `languageOptions` 时带上所有需要的字段。

### Q3：`prettierConfig` 放在 `base` 里可以吗？

不可以。`prettierConfig` 必须在整个数组的最末尾才能生效。放在 `base` 里，子包展开 `...base` 后面还有其他配置，会导致格式规则被重新开启。

### Q4：共享配置放根目录还是抽成独立包？

项目规模不大（3~4 个子包以内）放根目录即可，子包通过相对路径 import。项目大了可以抽成 `packages/eslint-config` 子包，通过包名 import，但会增加一层维护成本。

### Q5：`defineConfig` 是什么？

`defineConfig` 是 ESLint 提供的类型辅助函数，功能上等同于直接 `export default [...]`，但能为编辑器和工具提供更好的类型提示。使用它不是必须的，但推荐使用。
