# 第16章：Koa.js——洋葱模型的哲学

## 引言：Express的"精神续作"

如果Express是《街霸2》，那Koa就是《街霸4》——同一个创作者（TJ Holowaychuk），但用了全新的引擎和设计理念。

Express诞生于callback时代，基因里流淌着回调的血液。而Koa从一开始就拥抱async/await，把中间件的执行模型从"单向传送带"升级为"洋葱模型"——请求从外向内穿过每一层中间件，响应再从内向外穿出来。每一层中间件都有机会在请求**进入时**和**离开时**做不同的事情。

这听起来可能有点抽象，别担心，等你看到代码就会恍然大悟："原来如此简单！"

## 16.1 Koa vs Express：为什么需要Koa？

```
Express的问题：
1. 回调嵌套 → 虽然可以用async/await，但框架内部仍是回调
2. 中间件无法优雅地"后处理" → next()后的代码执行时机不确定
3. req/res对象被大量猴子补丁 → 不利于类型安全
4. 错误处理依赖约定（4参数） → 容易出错

Koa的解决方案：
1. 原生async/await → 用await next()代替回调
2. 洋葱模型 → 前处理和后处理自然分离
3. ctx封装 → 统一的上下文对象，更好的抽象
4. try/catch → 标准的错误处理方式
```

最简单的Koa应用：

```typescript
import Koa from 'koa';

const app = new Koa();

app.use(async (ctx) => {
  ctx.body = 'Hello Koa!';
});

app.listen(3000);
```

就这么简单。`ctx.body = ...` 相当于Express的 `res.send(...)`，但更直觉——你只是在给一个属性赋值。

## 16.2 洋葱模型可视化解释

这是理解Koa最核心的概念。让我用代码来"画"一个洋葱：

```typescript
import Koa from 'koa';

const app = new Koa();

// 最外层（洋葱皮）
app.use(async (ctx, next) => {
  console.log('→ 进入中间件1');
  await next();  // 穿入下一层
  console.log('← 离开中间件1');
});

// 中间层
app.use(async (ctx, next) => {
  console.log('  → 进入中间件2');
  await next();  // 继续穿入
  console.log('  ← 离开中间件2');
});

// 最内层（洋葱心）
app.use(async (ctx, next) => {
  console.log('    → 进入中间件3（核心处理）');
  ctx.body = 'Hello';
  console.log('    ← 离开中间件3');
  // 没有调用next()，开始"回弹"
});

app.listen(3000);

// 请求时的输出：
// → 进入中间件1
//   → 进入中间件2
//     → 进入中间件3（核心处理）
//     ← 离开中间件3
//   ← 离开中间件2
// ← 离开中间件1
```

**可视化**：

```
请求 ─→ ┌─────────────────────────────┐
         │  中间件1 (前)                │
         │  ┌─────────────────────────┐ │
         │  │  中间件2 (前)            │ │
         │  │  ┌─────────────────────┐ │ │
         │  │  │  中间件3 (核心)      │ │ │
         │  │  └─────────────────────┘ │ │
         │  │  中间件2 (后)            │ │
         │  └─────────────────────────┘ │
         │  中间件1 (后)                │
         └─────────────────────────────┘ ─→ 响应
```

这种模型的威力在于：**每个中间件可以在请求到达核心处理之前和之后都做事情**。比如计算响应时间：

```typescript
// 响应时间中间件 - 完美展示洋葱模型的优势
app.use(async (ctx, next) => {
  const start = Date.now();  // 进入时记录开始时间
  await next();              // 等待所有内层中间件完成
  const ms = Date.now() - start; // 离开时计算耗时
  ctx.set('X-Response-Time', `${ms}ms`);
  console.log(`${ctx.method} ${ctx.url} - ${ms}ms`);
});
```

在Express中实现同样的功能需要监听 `res.on('finish')` 事件，不够直觉。

## 16.3 Context对象

Koa把Node.js原生的request和response封装成了一个统一的 `ctx`（context）对象：

```typescript
import Koa from 'koa';

const app = new Koa();

app.use(async (ctx) => {
  // ============ Request 快捷方式 ============
  ctx.method;              // 'GET', 'POST'...
  ctx.url;                 // '/api/users?page=1'
  ctx.path;                // '/api/users'
  ctx.query;               // { page: '1' } (解析后的查询参数)
  ctx.querystring;         // 'page=1' (原始查询字符串)
  ctx.host;                // 'localhost:3000'
  ctx.hostname;            // 'localhost'
  ctx.headers;             // 所有请求头
  ctx.header;              // 同上（别名）
  ctx.get('Content-Type'); // 获取请求头（不区分大小写）
  ctx.ip;                  // 客户端IP
  ctx.ips;                 // 代理链中的所有IP
  ctx.is('json');          // 检查Content-Type是否为json

  // ctx.request - 完整的Koa Request对象
  ctx.request.body;        // 需要body解析中间件
  ctx.request.files;       // 上传的文件

  // ============ Response 快捷方式 ============
  ctx.status = 200;        // 设置状态码
  ctx.body = { ok: true }; // 设置响应体（自动设置Content-Type）
  ctx.set('X-Custom', 'value'); // 设置响应头
  ctx.type = 'json';       // 设置Content-Type
  ctx.redirect('/login');  // 重定向
  ctx.attachment('file.pdf'); // 设置Content-Disposition

  // ctx.response - 完整的Koa Response对象
  ctx.response.lastModified = new Date();

  // ============ ctx.state - 中间件间传递数据 ============
  // 这是推荐的中间件间数据传递方式
  ctx.state.user = { id: 1, name: 'Alice' };
  ctx.state.startTime = Date.now();

  // ============ 其他 ============
  ctx.cookies.get('name');           // 获取cookie
  ctx.cookies.set('name', 'value');  // 设置cookie
  ctx.throw(400, 'Bad Request');     // 抛出HTTP错误
  ctx.assert(ctx.state.user, 401, 'Unauthorized'); // 断言

  // 响应
  ctx.body = {
    method: ctx.method,
    path: ctx.path,
    query: ctx.query,
  };
});

app.listen(3000);
```

### 16.3.1 ctx.body的智能行为

```typescript
app.use(async (ctx) => {
  // 设置不同类型的body，Koa自动处理Content-Type

  // 字符串 → text/html 或 text/plain
  ctx.body = '<h1>Hello</h1>';  // Content-Type: text/html

  // 对象/数组 → application/json
  ctx.body = { name: 'Alice' }; // Content-Type: application/json

  // Buffer → application/octet-stream
  ctx.body = Buffer.from('binary data');

  // Stream → 直接pipe
  ctx.body = fs.createReadStream('./file.txt');

  // null/undefined → 204 No Content
  ctx.body = null;
});
```

## 16.4 中间件compose原理：koa-compose源码解析

`koa-compose` 是Koa的核心，只有不到50行代码，但实现了整个洋葱模型：

```typescript
// koa-compose 源码简化版（实际生产代码就这么短！）
type Middleware = (ctx: any, next: () => Promise<void>) => Promise<void>;

function compose(middlewares: Middleware[]) {
  // 返回一个组合后的大中间件
  return function (ctx: any, next?: () => Promise<void>) {
    let index = -1; // 防止next()被多次调用

    function dispatch(i: number): Promise<void> {
      if (i <= index) {
        return Promise.reject(new Error('next() called multiple times'));
      }
      index = i;

      let fn: Middleware | undefined = middlewares[i];

      // 最后一个中间件之后，执行外层传入的next
      if (i === middlewares.length) fn = next as any;
      if (!fn) return Promise.resolve();

      try {
        // 调用当前中间件，传入ctx和"调用下一个中间件"的函数
        return Promise.resolve(fn(ctx, dispatch.bind(null, i + 1)));
      } catch (err) {
        return Promise.reject(err);
      }
    }

    return dispatch(0); // 从第一个中间件开始
  };
}

export default compose;
```

**精妙之处**：

1. `dispatch(i)` 调用第i个中间件
2. 每个中间件接收的 `next` 实际上是 `dispatch(i+1)`
3. 当中间件 `await next()` 时，它等待后续所有中间件执行完毕
4. 这自然形成了"进入→深入→回弹"的洋葱结构

让我们手动模拟执行过程：

```typescript
// 假设有3个中间件
const middlewares = [
  async (ctx: any, next: () => Promise<void>) => {
    console.log('1-进');
    await next(); // = await dispatch(1)
    console.log('1-出');
  },
  async (ctx: any, next: () => Promise<void>) => {
    console.log('2-进');
    await next(); // = await dispatch(2)
    console.log('2-出');
  },
  async (ctx: any, next: () => Promise<void>) => {
    console.log('3-进');
    // 不调用next，开始回弹
    console.log('3-出');
  },
];

// 执行：
// dispatch(0) → 调用中间件[0]
//   '1-进'
//   await dispatch(1) → 调用中间件[1]
//     '2-进'
//     await dispatch(2) → 调用中间件[2]
//       '3-进'
//       '3-出'
//     ← dispatch(2) resolve
//     '2-出'
//   ← dispatch(1) resolve
//   '1-出'
// ← dispatch(0) resolve
```

## 16.5 常用中间件生态

### 16.5.1 koa-router

```typescript
import Koa from 'koa';
import Router from '@koa/router';

const app = new Koa();
const router = new Router();

// 基本路由
router.get('/', (ctx) => {
  ctx.body = 'Home';
});

// 参数路由
router.get('/users/:id', (ctx) => {
  ctx.body = { userId: ctx.params.id };
});

// 命名路由（用于URL生成）
router.get('user-detail', '/users/:id', (ctx) => {
  ctx.body = { userId: ctx.params.id };
});
// 生成URL: router.url('user-detail', { id: '123' }) → '/users/123'

// 路由前缀
const apiRouter = new Router({ prefix: '/api/v1' });
apiRouter.get('/posts', (ctx) => { ctx.body = []; });
apiRouter.post('/posts', (ctx) => { ctx.body = { created: true }; });

// 嵌套路由
const usersRouter = new Router({ prefix: '/users' });
const postsRouter = new Router({ prefix: '/:userId/posts' });

postsRouter.get('/', (ctx) => {
  ctx.body = { userId: ctx.params.userId, posts: [] };
});

usersRouter.use(postsRouter.routes(), postsRouter.allowedMethods());

// 路由级中间件
router.get('/admin',
  async (ctx, next) => {
    if (!ctx.state.user?.isAdmin) {
      ctx.throw(403, 'Admin only');
    }
    await next();
  },
  (ctx) => {
    ctx.body = 'Admin panel';
  }
);

// 注册路由
app.use(router.routes());
app.use(router.allowedMethods()); // 自动响应405和501

app.use(apiRouter.routes());
app.use(apiRouter.allowedMethods());

app.listen(3000);
```

## 16.6 错误处理的优雅方式

Koa的错误处理利用了async/await的天然优势——try/catch：

```typescript
import Koa from 'koa';

const app = new Koa();

// 全局错误处理中间件（放在最外层）
app.use(async (ctx, next) => {
  try {
    await next();
  } catch (err: any) {
    // 设置状态码
    ctx.status = err.statusCode || err.status || 500;

    // 构建错误响应
    ctx.body = {
      success: false,
      error: {
        message: ctx.status === 500 ? 'Internal Server Error' : err.message,
        ...(process.env.NODE_ENV === 'development' && { stack: err.stack }),
      },
    };

    // 触发app级错误事件（用于日志记录）
    ctx.app.emit('error', err, ctx);
  }
});

// 404处理
app.use(async (ctx, next) => {
  await next();
  if (ctx.status === 404 && !ctx.body) {
    ctx.status = 404;
    ctx.body = { success: false, error: { message: 'Not Found' } };
  }
});

// 业务路由
app.use(async (ctx) => {
  if (ctx.path === '/error') {
    ctx.throw(400, '这是一个业务错误'); // 自动被外层catch捕获
  }
  if (ctx.path === '/crash') {
    throw new Error('程序崩溃了！'); // 也会被捕获
  }
  ctx.body = 'OK';
});

// 应用级错误监听（用于记录日志、报警等）
app.on('error', (err, ctx) => {
  console.error(`[ERROR] ${ctx?.method} ${ctx?.url}`, err.message);
  // 这里可以发送到日志服务、Sentry等
});

app.listen(3000);
```

对比Express：

- Express：需要记住"4参数约定"，async错误需要手动传递
- Koa：标准的try/catch，async/await天然支持，简单直觉

## 16.7 Koa vs Express 性能对比

```
基准测试场景：简单的JSON响应 "Hello World"
测试工具：autocannon -c 100 -d 30

框架            请求/秒      延迟(平均)    内存占用
Express 4.x    ~15,000      6.5ms        ~45MB
Koa 2.x        ~18,000      5.4ms        ~38MB
原生HTTP        ~25,000      3.8ms        ~30MB
```

> Koa比Express快约20%。原因：
>
> 1. Koa更轻量，核心代码更少
> 2. 没有内置路由等功能的开销
> 3. 中间件组合方式更高效
>
> 但说实话，对于大多数应用，这点差距并不重要。选框架看生态和开发体验，不看这几毫秒。

## 16.8 实战：用Koa构建API服务

```typescript
import Koa from 'koa';
import Router from '@koa/router';
import { koaBody } from 'koa-body';
import cors from '@koa/cors';

const app = new Koa();
const router = new Router({ prefix: '/api' });

// ============ 中间件：响应时间 ============
app.use(async (ctx, next) => {
  const start = Date.now();
  await next();
  const ms = Date.now() - start;
  ctx.set('X-Response-Time', `${ms}ms`);
});

// ============ 中间件：请求日志 ============
app.use(async (ctx, next) => {
  const start = Date.now();
  await next();
  const ms = Date.now() - start;
  const status = ctx.status;
  const statusEmoji = status >= 500 ? '💥' : status >= 400 ? '⚠️' : '✅';
  console.log(`${statusEmoji} ${ctx.method} ${ctx.url} ${status} - ${ms}ms`);
});

// ============ 中间件：错误处理 ============
app.use(async (ctx, next) => {
  try {
    await next();
  } catch (err: any) {
    ctx.status = err.statusCode || err.status || 500;
    ctx.body = {
      success: false,
      error: { message: err.message },
    };
    if (ctx.status === 500) {
      console.error('Unhandled error:', err);
    }
  }
});

// ============ 全局中间件 ============
app.use(cors());
app.use(koaBody({ jsonLimit: '5mb' }));

// ============ 内存数据库 ============
interface Note {
  id: string;
  title: string;
  content: string;
  tags: string[];
  createdAt: string;
}

const notes: Map<string, Note> = new Map();
let noteIdCounter = 0;

// ============ 路由 ============
router.get('/notes', (ctx) => {
  const { tag, search } = ctx.query as Record<string, string>;
  let result = Array.from(notes.values());

  if (tag) {
    result = result.filter((n) => n.tags.includes(tag));
  }
  if (search) {
    const keyword = search.toLowerCase();
    result = result.filter(
      (n) => n.title.toLowerCase().includes(keyword) ||
             n.content.toLowerCase().includes(keyword),
    );
  }

  ctx.body = { success: true, data: result, total: result.length };
});

router.get('/notes/:id', (ctx) => {
  const note = notes.get(ctx.params.id);
  if (!note) ctx.throw(404, 'Note not found');
  ctx.body = { success: true, data: note };
});

router.post('/notes', (ctx) => {
  const { title, content, tags = [] } = ctx.request.body as any;

  if (!title?.trim()) ctx.throw(400, 'Title is required');

  const id = String(++noteIdCounter);
  const note: Note = {
    id,
    title: title.trim(),
    content: content || '',
    tags,
    createdAt: new Date().toISOString(),
  };

  notes.set(id, note);
  ctx.status = 201;
  ctx.body = { success: true, data: note };
});

router.put('/notes/:id', (ctx) => {
  const note = notes.get(ctx.params.id);
  if (!note) ctx.throw(404, 'Note not found');

  const { title, content, tags } = ctx.request.body as any;
  if (title !== undefined) note.title = title;
  if (content !== undefined) note.content = content;
  if (tags !== undefined) note.tags = tags;

  ctx.body = { success: true, data: note };
});

router.delete('/notes/:id', (ctx) => {
  if (!notes.delete(ctx.params.id)) {
    ctx.throw(404, 'Note not found');
  }
  ctx.status = 204;
});

// ============ 注册路由 ============
app.use(router.routes());
app.use(router.allowedMethods());

// ============ 启动 ============
app.listen(3000, () => {
  console.log('Koa API server running on http://localhost:3000');
});
```

## 16.9 常见坑点

1. **忘记 `await next()`**：如果不await，后续中间件的执行不会等待，时序会乱。
2. **多次设置 `ctx.body`**：只有最后一次赋值生效。
3. **ctx.throw vs throw**：`ctx.throw(400, 'msg')` 会设置正确的statusCode；直接 `throw new Error()` 默认500。
4. **中间件返回值无意义**：Koa不看中间件的return值，只看ctx.body。
5. **Koa本身不带路由**：需要自己安装 `@koa/router`。

```typescript
// 坑：忘记await next()
app.use(async (ctx, next) => {
  console.log('before');
  next(); // 没有await！后面的代码立即执行
  console.log('after'); // 这行在inner中间件完成之前就执行了
});

// 正确
app.use(async (ctx, next) => {
  console.log('before');
  await next(); // 等待inner完成
  console.log('after'); // inner完成后才执行
});
```

## 16.10 本章小结

| 概念 | 关键点 |
| ------ | -------- |
| 洋葱模型 | 请求进入→深入核心→回弹返回，每层都有前后处理时机 |
| ctx | 统一的上下文对象，封装request/response |
| compose | 50行代码实现中间件组合，精妙的递归+Promise |
| 错误处理 | 最外层try/catch + app.on('error') |
| vs Express | 更轻量、更现代、async原生、但生态稍小 |

**Koa适合什么？** 当你需要一个轻量、现代、对async/await友好的框架，并且不介意自己组装路由、body解析等功能时，Koa是绝佳选择。它的设计哲学让你写出的代码更清晰、更可控。
