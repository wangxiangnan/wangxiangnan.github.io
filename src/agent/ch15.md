# 第15章 LangGraph入门 — 用状态图编排Agent

## 15.1 开篇：从流水线到状态机

在前面的章节中，我们用Chain（链）和ReAct循环来编排Agent。Chain像一条流水线——数据从一头进，从另一头出，中间是顺序执行的步骤。ReAct像一个while循环——不断重复think-act-observe。

但它们都有一个共同的限制：**控制流不够灵活。**

考虑这些场景：

- 如果搜索结果质量好，走快速回答路径；质量差，走深度搜索路径
- 工具调用失败后，不是简单重试，而是切换到完全不同的工具
- 需要人类审批才能执行某些操作（比如删除文件）
- 一个Agent的输出要作为另一个Agent的输入

用Chain？做不到——它是线性的。
用ReAct？勉强可以，但所有逻辑都塞在一个大循环里，混乱且难以调试。

**LangGraph**就是为了解决这些问题而生的。它把Agent的工作流建模为一个**状态图（State Graph）**——有节点（Node）、边（Edge）、条件分支（Conditional Edge），就像一个可视化的状态机。

> 用编程的话说：Chain像是函数调用链 `f(g(h(x)))`，ReAct像是while循环 `while not done: think(); act(); observe()`，LangGraph像是有限状态机（FSM）/ 工作流引擎（如Airflow）。

## 15.2 为什么需要LangGraph？

## 15.2.1 Chain的局限

```python
# Chain模式：线性流水线
chain = load_docs | split_chunks | embed | store | retrieve | generate

# 问题1：无法根据中间结果改变流程
# 如果retrieve返回空结果怎么办？Chain会继续执行generate，得到无意义的回答

# 问题2：无法循环
# 如果generate的结果质量不好，想让Agent重新搜索？Chain做不到

# 问题3：无法并行
# 想同时搜索多个数据源然后合并结果？Chain只能串行
```

## 15.2.2 ReAct的局限

```python
# ReAct模式：while循环
while not done:
    thought = llm.think(context)
    if needs_tool(thought):
        observation = execute_tool(thought.action)
    else:
        answer = thought.answer
        done = True

# 问题1：所有逻辑在一个大循环里，难以理解和调试
# 问题2：控制流只能通过prompt"暗示"，不能精确控制
# 问题3：无法定义"在A和B之间必须经过人类审批"
# 问题4：难以可视化整个流程
```

## 15.2.3 LangGraph的解决方案

```python
# LangGraph模式：状态图
# 你可以精确定义每个步骤、每个分支、每个循环

from langgraph.graph import StateGraph, START, END

graph = StateGraph(AgentState)

# 定义节点（每个节点是一个独立的函数）
graph.add_node("search", search_node)
graph.add_node("analyze", analyze_node)
graph.add_node("answer", answer_node)
graph.add_node("human_review", human_review_node)

# 定义边（节点间的连接）
graph.add_edge(START, "search")
graph.add_edge("search", "analyze")

# 条件边（根据状态动态决定下一步）
graph.add_conditional_edges("analyze", should_use_human_review, {
    "yes": "human_review",
    "no": "answer"
})

graph.add_edge("human_review", "answer")
graph.add_edge("answer", END)

# 编译
app = graph.compile()
```

**清晰、可控、可调试、可可视化。**

## 15.3 核心概念详解

## 15.3.1 State：图的"全局状态"

State是整个图的"共享内存"。每个节点都可以读取和修改State。

```python
"""
State定义：用TypedDict声明图的状态结构
"""
from typing import TypedDict, Annotated
from langgraph.graph.message import add_messages

class SimpleState(TypedDict):
    """一个简单的状态定义"""
    user_input: str          # 用户输入
    search_results: list     # 搜索结果
    answer: str              # 最终回答
    step_count: int          # 执行步骤数


class AgentState(TypedDict):
    """更典型的Agent状态定义"""
    # messages使用add_messages reducer
    # 这意味着每次节点返回{"messages": [new_msg]}时
    # 新消息会被追加到列表，而不是替换整个列表
    messages: Annotated[list, add_messages]
    
    # 普通字段——新值会覆盖旧值
    current_tool: str
    search_quality: float
    needs_human_review: bool
```

**关键概念：Reducer**

```python
# 普通字段：新值覆盖旧值
# 如果节点A返回 {"step_count": 3}，节点B返回 {"step_count": 5}
# 最终 step_count = 5（被覆盖了）

# Reducer字段：新值与旧值合并
# messages: Annotated[list, add_messages]
# 如果节点A返回 {"messages": [msg1]}，节点B返回 {"messages": [msg2]}
# 最终 messages = [msg1, msg2]（被追加了）
```

> 类比理解：普通字段像`=`赋值（覆盖），Reducer字段像`.append()`（追加）。`add_messages`是LangGraph内置的Reducer，专门用于消息列表的追加。

## 15.3.2 Node：图中的"处理节点"

每个Node是一个函数，接收当前State，返回State的**部分更新**。

```python
"""
Node定义：每个节点是一个纯函数
输入：当前State
输出：State的部分更新（只返回需要修改的字段）
"""
from langchain_core.messages import AIMessage

def search_node(state: AgentState) -> dict:
    """搜索节点：根据用户输入搜索文档"""
    user_input = state["user_input"]
    
    # 执行搜索...
    results = perform_search(user_input)
    
    # 只返回需要更新的字段
    return {
        "search_results": results,
        "current_tool": "search",
        "messages": [AIMessage(content=f"搜索完成，找到{len(results)}条结果")]
    }


def analyze_node(state: AgentState) -> dict:
    """分析节点：评估搜索结果质量"""
    results = state["search_results"]
    
    # 评估质量...
    quality = evaluate_quality(results)
    
    return {
        "search_quality": quality,
        "needs_human_review": quality < 0.5  # 质量差需要人工审核
    }


def answer_node(state: AgentState) -> dict:
    """回答节点：基于搜索结果生成回答"""
    results = state["search_results"]
    
    # 生成回答...
    answer = generate_answer(results, state["messages"])
    
    return {
        "answer": answer,
        "messages": [AIMessage(content=answer)]
    }
```

> ⚠️ **重要原则**：Node应该是**纯函数**——只依赖State的输入，只通过返回值修改State。不要在Node里修改全局变量或外部状态。这让图变得可预测、可测试。

## 15.3.3 Edge：节点间的连接

Edge定义了节点之间的执行顺序。

```python
"""
Edge类型：
1. 普通边：A执行完后总是执行B
2. 条件边：A执行完后，根据State决定下一步是B还是C
"""

# 普通边：search总是接着analyze
graph.add_edge("search", "analyze")

# 条件边：analyze之后，根据条件决定下一步
def route_after_analyze(state: AgentState) -> str:
    """条件路由函数"""
    if state["needs_human_review"]:
        return "human_review"  # 需要人工审核
    else:
        return "answer"  # 直接回答

graph.add_conditional_edges(
    "analyze",              # 从哪个节点出发
    route_after_analyze,    # 路由函数
    {                       # 路由映射
        "human_review": "human_review",
        "answer": "answer"
    }
)
```

## 15.3.4 START和END

```python
from langgraph.graph import START, END

# START是入口节点（虚拟节点）
graph.add_edge(START, "search")  # 从入口到第一个真实节点

# END是出口节点（虚拟节点）
graph.add_edge("answer", END)   # 从最后一个节点到出口
```

## 15.4 简单示例：构建一个计数器图

让我们从最简单的例子开始，理解LangGraph的基本用法：

```python
"""
LangGraph入门示例：计数器图
目标：构建一个图，将计数器从0递增到指定目标值
这个例子虽然简单，但包含了所有核心概念
"""
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# ============================================================
# 第一步：定义State
# ============================================================

class CounterState(TypedDict):
    """计数器状态"""
    count: int        # 当前计数
    target: int       # 目标值
    history: list     # 历史记录


# ============================================================
# 第二步：定义Nodes
# ============================================================

def increment_node(state: CounterState) -> dict:
    """递增节点：计数器+1"""
    new_count = state["count"] + 1
    print(f"  递增: {state['count']} -> {new_count}")
    return {
        "count": new_count,
        "history": state.get("history", []) + [f"incremented to {new_count}"]
    }


def check_node(state: CounterState) -> dict:
    """检查节点：记录当前状态"""
    print(f"  检查: count={state['count']}, target={state['target']}")
    return {}  # 不修改任何状态


# ============================================================
# 第三步：定义条件路由
# ============================================================

def should_continue(state: CounterState) -> str:
    """判断是否继续递增"""
    if state["count"] < state["target"]:
        return "continue"  # 还没到目标，继续递增
    else:
        return "done"      # 到达目标，结束


# ============================================================
# 第四步：构建图
# ============================================================

def build_counter_graph():
    """构建计数器图"""
    
    # 创建StateGraph
    graph = StateGraph(CounterState)
    
    # 添加节点
    graph.add_node("increment", increment_node)
    graph.add_node("check", check_node)
    
    # 添加边
    graph.add_edge(START, "increment")           # 入口 -> 递增
    graph.add_edge("increment", "check")          # 递增 -> 检查
    graph.add_conditional_edges(                  # 检查 -> 条件分支
        "check",
        should_continue,
        {
            "continue": "increment",  # 继续 -> 回到递增
            "done": END               # 完成 -> 结束
        }
    )
    
    # 编译图
    return graph.compile()


# ============================================================
# 第五步：运行图
# ============================================================

if __name__ == "__main__":
    app = build_counter_graph()
    
    # 运行！
    print("运行计数器图 (target=3):")
    result = app.invoke({
        "count": 0,
        "target": 3,
        "history": []
    })
    
    print(f"\n最终结果:")
    print(f"  count: {result['count']}")
    print(f"  target: {result['target']}")
    print(f"  history: {result['history']}")
    
    # 执行流程：
    # START -> increment(0->1) -> check(1<3,continue)
    #       -> increment(1->2) -> check(2<3,continue)
    #       -> increment(2->3) -> check(3>=3,done) -> END
```

## 执行流程解析

```
START --> increment --> check --(continue)--> increment --> check --(done)--> END
              ^          |
              |          |
              +----------+
              (循环)
```

这个简单的例子展示了LangGraph的核心能力：**循环**。Chain做不到循环，但LangGraph通过条件边指回之前的节点，实现了循环。

## 15.5 进阶示例：带条件分支的决策图

让我们构建一个更复杂的例子——一个文档处理决策图：

```python
"""
进阶示例：文档处理决策图
根据文档类型和大小，走不同的处理路径
"""
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# ============================================================
# State定义
# ============================================================

class DocProcessState(TypedDict):
    """文档处理状态"""
    filename: str           # 文件名
    file_type: str          # 文件类型
    file_size_mb: float     # 文件大小(MB)
    processing_path: list   # 处理路径记录
    result: str             # 处理结果
    error: str              # 错误信息


# ============================================================
# 节点定义
# ============================================================

def classify_node(state: DocProcessState) -> dict:
    """分类节点：识别文件类型和大小"""
    filename = state["filename"]
    
    # 从文件名推断类型
    ext = filename.rsplit(".", 1)[-1].lower() if "." in filename else "unknown"
    type_map = {
        "pdf": "pdf", "md": "markdown", "txt": "text",
        "docx": "word", "xlsx": "excel", "csv": "csv",
        "py": "code", "js": "code", "ts": "code"
    }
    file_type = type_map.get(ext, "unknown")
    
    print(f"  分类: {filename} -> type={file_type}")
    
    return {
        "file_type": file_type,
        "processing_path": [f"classified as {file_type}"]
    }


def process_text_node(state: DocProcessState) -> dict:
    """处理纯文本文件"""
    print(f"  处理文本文件: {state['filename']}")
    return {
        "result": f"文本文件 '{state['filename']}' 已处理完成",
        "processing_path": state["processing_path"] + ["process_text"]
    }


def process_pdf_node(state: DocProcessState) -> dict:
    """处理PDF文件"""
    print(f"  处理PDF文件: {state['filename']}")
    
    if state["file_size_mb"] > 50:
        return {
            "result": f"PDF '{state['filename']}' 太大({state['file_size_mb']}MB)，已拆分处理",
            "processing_path": state["processing_path"] + ["process_pdf_large"]
        }
    
    return {
        "result": f"PDF文件 '{state['filename']}' 已完成OCR和文本提取",
        "processing_path": state["processing_path"] + ["process_pdf_standard"]
    }


def process_code_node(state: DocProcessState) -> dict:
    """处理代码文件"""
    print(f"  处理代码文件: {state['filename']}")
    return {
        "result": f"代码文件 '{state['filename']}' 已完成语法分析和索引",
        "processing_path": state["processing_path"] + ["process_code"]
    }


def process_unknown_node(state: DocProcessState) -> dict:
    """处理未知类型"""
    print(f"  未知文件类型: {state['filename']}")
    return {
        "error": f"不支持的文件类型: {state['file_type']}",
        "result": f"文件 '{state['filename']}' 无法处理（类型不支持）",
        "processing_path": state["processing_path"] + ["process_unknown", "error"]
    }


def report_node(state: DocProcessState) -> dict:
    """报告节点：生成处理报告"""
    path = " -> ".join(state["processing_path"])
    print(f"  处理路径: {path}")
    print(f"  结果: {state['result']}")
    
    return {
        "result": f"{state['result']}\n处理路径: {path}"
    }


# ============================================================
# 条件路由
# ============================================================

def route_by_type(state: DocProcessState) -> str:
    """根据文件类型路由到不同的处理节点"""
    file_type = state["file_type"]
    
    if file_type in ("text", "markdown", "csv"):
        return "text"
    elif file_type == "pdf":
        return "pdf"
    elif file_type == "code":
        return "code"
    else:
        return "unknown"


# ============================================================
# 构建图
# ============================================================

def build_doc_process_graph():
    """构建文档处理决策图"""
    
    graph = StateGraph(DocProcessState)
    
    # 添加节点
    graph.add_node("classify", classify_node)
    graph.add_node("process_text", process_text_node)
    graph.add_node("process_pdf", process_pdf_node)
    graph.add_node("process_code", process_code_node)
    graph.add_node("process_unknown", process_unknown_node)
    graph.add_node("report", report_node)
    
    # 添加边
    graph.add_edge(START, "classify")
    
    # 条件分支：根据文件类型路由
    graph.add_conditional_edges(
        "classify",
        route_by_type,
        {
            "text": "process_text",
            "pdf": "process_pdf",
            "code": "process_code",
            "unknown": "process_unknown"
        }
    )
    
    # 所有处理节点都汇合到报告节点
    graph.add_edge("process_text", "report")
    graph.add_edge("process_pdf", "report")
    graph.add_edge("process_code", "report")
    graph.add_edge("process_unknown", "report")
    
    # 报告后结束
    graph.add_edge("report", END)
    
    return graph.compile()


# ============================================================
# 运行测试
# ============================================================

if __name__ == "__main__":
    app = build_doc_process_graph()
    
    test_files = [
        {"filename": "report.pdf", "file_size_mb": 5.2},
        {"filename": "big_paper.pdf", "file_size_mb": 85.0},
        {"filename": "README.md", "file_size_mb": 0.01},
        {"filename": "main.py", "file_size_mb": 0.05},
        {"filename": "data.xlsx", "file_size_mb": 1.2},  # 不支持的类型
    ]
    
    for file_info in test_files:
        print(f"\n{'='*60}")
        print(f"处理文件: {file_info['filename']}")
        print(f"{'='*60}")
        
        result = app.invoke({
            "filename": file_info["filename"],
            "file_type": "",
            "file_size_mb": file_info["file_size_mb"],
            "processing_path": [],
            "result": "",
            "error": ""
        })
        
        print(f"\n最终结果: {result['result']}")
```

## 这个图的结构

```
           START
             |
          classify
         /  |  |  \
       text pdf code unknown
        \   |   |   /
         \  |   |  /
          report
             |
            END
```

这是一个典型的**扇出-扇入(Fan-out/Fan-in)**模式：从一个节点分散到多个处理节点，然后再汇聚到一个节点。这种模式在Chain中很难实现，但在LangGraph中非常自然。

## 15.6 图编译(compile)和调用(invoke/stream)

## 15.6.1 compile()

```python
# compile()做了什么？
# 1. 验证图的完整性（所有节点是否连接、是否有孤立节点）
# 2. 检查条件边的路由函数是否覆盖了所有返回值
# 3. 确保有START和END
# 4. 生成可执行的CompiledGraph对象

app = graph.compile()
# 如果图有错误，compile()会抛出异常
# 例如：ValueError: Edge from 'foo' to 'bar' references undefined node 'bar'
```

## 15.6.2 invoke() vs stream()

```python
# invoke()：等待整个图执行完毕，返回最终状态
result = app.invoke({"count": 0, "target": 5, "history": []})
print(result)  # 最终状态

# stream()：逐节点输出中间状态（适合长时间运行的图）
for event in app.stream({"count": 0, "target": 5, "history": []}):
    # 每个event是一个字典，key是节点名，value是该节点返回的状态更新
    print(f"节点执行完毕: {event}")
    # 输出示例：
    # 节点执行完毕: {'increment': {'count': 1, 'history': [...]}}
    # 节点执行完毕: {'check': {}}
    # 节点执行完毕: {'increment': {'count': 2, 'history': [...]}}
    # ...
```

## 15.6.3 流式输出的高级用法

```python
"""
stream的高级用法：实时监控图执行
"""

def run_with_monitoring(app, initial_state):
    """带监控的图执行"""
    
    print("开始执行图...\n")
    
    for step, event in enumerate(app.stream(initial_state)):
        for node_name, node_output in event.items():
            print(f"[Step {step + 1}] 节点 '{node_name}' 完成")
            
            # 检查节点输出
            if node_output:
                for key, value in node_output.items():
                    if isinstance(value, str) and len(value) > 100:
                        print(f"  {key}: {value[:100]}...")
                    else:
                        print(f"  {key}: {value}")
            print()
    
    print("图执行完毕！")


# 使用
run_with_monitoring(app, {
    "filename": "test.py",
    "file_type": "",
    "file_size_mb": 0.1,
    "processing_path": [],
    "result": "",
    "error": ""
})
```

## 15.8 完整综合示例：智能问答路由图

让我们把所有概念整合起来，构建一个完整的智能问答路由系统：

```python
"""
综合示例：智能问答路由系统
根据问题类型自动路由到不同的处理流程
"""
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langchain_core.messages import HumanMessage, AIMessage, SystemMessage

# ============================================================
# State定义
# ============================================================

class QAState(TypedDict):
    """问答系统状态"""
    messages: Annotated[list, add_messages]  # 消息列表
    question_type: str                        # 问题类型
    search_results: str                       # 搜索结果
    answer: str                               # 最终回答
    confidence: float                         # 回答置信度


# ============================================================
# 节点定义
# ============================================================

def classify_question(state: QAState) -> dict:
    """分类问题类型"""
    last_message = state["messages"][-1].content
    
    # 简单的规则分类（实际项目中可以用LLM分类）
    if any(kw in last_message for kw in ["什么是", "解释", "介绍", "概念"]):
        q_type = "concept"  # 概念解释类
    elif any(kw in last_message for kw in ["怎么", "如何", "步骤", "方法"]):
        q_type = "howto"    # 操作指南类
    elif any(kw in last_message for kw in ["比较", "对比", "区别", "差异"]):
        q_type = "compare"  # 对比分析类
    elif any(kw in last_message for kw in ["多少", "计算", "统计"]):
        q_type = "calculate"  # 数值计算类
    else:
        q_type = "general"   # 一般对话类
    
    print(f"  问题分类: {q_type}")
    return {"question_type": q_type}


def search_and_answer(state: QAState) -> dict:
    """搜索并回答（概念类问题）"""
    question = state["messages"][-1].content
    print(f"  搜索知识库...")
    
    answer = f"根据知识库搜索结果，关于'{question}'的回答是：这是一个重要的技术概念..."
    
    return {
        "search_results": "搜索结果...",
        "answer": answer,
        "confidence": 0.85,
        "messages": [AIMessage(content=answer)]
    }


def generate_guide(state: QAState) -> dict:
    """生成操作指南（how-to类问题）"""
    question = state["messages"][-1].content
    print(f"  生成操作指南...")
    
    answer = f"关于'{question}'的操作步骤：\n1. 第一步...\n2. 第二步...\n3. 第三步..."
    
    return {
        "answer": answer,
        "confidence": 0.80,
        "messages": [AIMessage(content=answer)]
    }


def compare_analysis(state: QAState) -> dict:
    """对比分析（比较类问题）"""
    question = state["messages"][-1].content
    print(f"  进行对比分析...")
    
    answer = f"关于'{question}'的对比分析：\n| 维度 | A | B |\n|------|---|---|\n| 性能 | ... | ... |"
    
    return {
        "answer": answer,
        "confidence": 0.75,
        "messages": [AIMessage(content=answer)]
    }


def do_calculation(state: QAState) -> dict:
    """数值计算（计算类问题）"""
    question = state["messages"][-1].content
    print(f"  执行计算...")
    
    answer = f"计算结果：根据您的问题'{question}'，答案是42。"
    
    return {
        "answer": answer,
        "confidence": 0.95,
        "messages": [AIMessage(content=answer)]
    }


def general_chat(state: QAState) -> dict:
    """一般对话"""
    question = state["messages"][-1].content
    print(f"  一般对话...")
    
    answer = f"你好！我是DocMind智能助手。关于'{question}'，建议使用搜索功能获取更准确的信息。"
    
    return {
        "answer": answer,
        "confidence": 0.60,
        "messages": [AIMessage(content=answer)]
    }


# ============================================================
# 条件路由
# ============================================================

def route_by_question_type(state: QAState) -> str:
    """根据问题类型路由"""
    return state["question_type"]


# ============================================================
# 构建图
# ============================================================

def build_qa_graph():
    """构建智能问答路由图"""
    
    graph = StateGraph(QAState)
    
    # 添加节点
    graph.add_node("classify", classify_question)
    graph.add_node("search", search_and_answer)
    graph.add_node("guide", generate_guide)
    graph.add_node("compare", compare_analysis)
    graph.add_node("calc", do_calculation)
    graph.add_node("chat", general_chat)
    
    # 边
    graph.add_edge(START, "classify")
    
    graph.add_conditional_edges(
        "classify",
        route_by_question_type,
        {
            "concept": "search",
            "howto": "guide",
            "compare": "compare",
            "calculate": "calc",
            "general": "chat"
        }
    )
    
    # 所有处理节点都到END
    for node in ["search", "guide", "compare", "calc", "chat"]:
        graph.add_edge(node, END)
    
    return graph.compile()


# ============================================================
# 测试
# ============================================================

if __name__ == "__main__":
    app = build_qa_graph()
    
    test_questions = [
        "什么是RAG？请解释一下它的概念",
        "如何配置LangChain的向量数据库？",
        "Pinecone和Chroma有什么区别？",
        "1024 * 768 等于多少？",
        "你好，今天天气怎么样？"
    ]
    
    for q in test_questions:
        print(f"\n{'='*60}")
        print(f"问题: {q}")
        result = app.invoke({
            "messages": [HumanMessage(content=q)],
            "question_type": "",
            "search_results": "",
            "answer": "",
            "confidence": 0.0
        })
        print(f"\n回答: {result['answer']}")
        print(f"置信度: {result['confidence']}")
```

## 15.9 本章小结

LangGraph是Agent编排的"状态机引擎"，核心概念只有五个：

| 概念 | 类比 | 作用 |
| ------ | ------ | ------ |
| State | 全局变量 | 图的共享状态 |
| Node | 函数/处理器 | 执行具体逻辑 |
| Edge | 连线/管道 | 定义执行顺序 |
| Conditional Edge | if-else | 动态路由 |
| START/END | 入口/出口 | 图的边界 |

## 关键收获

1. **Chain是流水线（顺序），LangGraph是状态机（灵活）**
2. **State用TypedDict定义，Reducer控制字段更新方式**
3. **Node是纯函数：输入State，输出State的部分更新**
4. **条件边让图能根据状态动态选择路径**
5. **stream()可以实时监控图的执行过程**

## 什么时候用LangGraph？

```
适合使用的场景：
  需要循环（搜索->评估->不满意->重新搜索）
  需要条件分支（根据结果走不同路径）
  需要人机协作（中间暂停等待人类确认）
  需要可视化工作流
  需要精确控制Agent行为

不适合使用的场景：
  简单的线性Chain（杀鸡不用牛刀）
  纯ReAct就能搞定的简单Agent
```
