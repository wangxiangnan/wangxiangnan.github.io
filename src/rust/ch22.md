# 第22章：宏（Macro）

## 引子：你每天都在用宏，却不知道

你已经写过无数次`println!`、`vec!`、`format!`。它们看起来像函数，但名字后面有个`!`——这就是Rust的宏（Macro）。如果你来自C/C++，你可能对`#define`宏有阴影：脆弱的文本替换、难以调试的错误信息。Rust的宏完全不同，它是**类型安全的代码生成工具**，是Rust最强大的元编程（Metaprogramming）机制之一。

> **类比**：如果C的宏是"复制粘贴大师"，那Rust的宏是"类型安全的代码工厂"。Java的注解处理器（Annotation Processor）和Python的装饰器（Decorator）也能做代码生成，但Rust的宏更灵活、更安全。

---

## 什么是宏？代码生成代码

宏的本质是：**在编译时，把一段代码（Token Stream）转换成另一段代码**。你在写`vec![1, 2, 3]`时，编译器会把它展开成一段手动构建`Vec`的代码。

宏分两大类：

- **声明式宏（Declarative Macros）**：用`macro_rules!`定义，基于模式匹配，像增强版的`match`
- **过程宏（Procedural Macros）**：用Rust代码编写，接收Token Stream并输出Token Stream，能力更强大

---

## 声明式宏：macro_rules

最简单的宏，就是"看到这种模式，就替换成那种代码"：

```rust
// 定义一个简单的宏，打印变量名和值
macro_rules! debug_var {
    ($var:expr) => {
        println!("{} = {:?}", stringify!($var), $var);
    };
}

fn main() {
    let x = 42;
    let name = String::from("Rust");
    debug_var!(x);       // 输出：x = 42
    debug_var!(name);    // 输出：name = "Rust"
    debug_var!(x + 10);  // 输出：x + 10 = 52
}
```

来拆解这个宏的结构：

- `$var:expr`：一个**模式变量（metavariable）**，类型为`expr`（表达式）
- `=>`：匹配成功后展开成右边的代码
- `stringify!`：内置宏，把Token原样转成字符串

---

## 宏的模式匹配：多种分支

宏可以有多个分支，类似`match`的不同臂：

```rust
macro_rules! calculate {
    // 分支1：单个表达式，打印结果
    ($op:literal, $a:expr) => {
        println!("{} {} = {}", stringify!($a), $op, $a);
    };
    // 分支2：两个表达式的二元运算
    ($a:expr, $op:tt, $b:expr) => {
        println!("{} {} {} = {}", stringify!($a), stringify!($op), stringify!($b), $a $op $b);
    };
}

fn main() {
    calculate!("平方", 5 * 5);         // 5 * 5 平方 = 25
    calculate!(10, +, 20);             // 10 + 20 = 30
    calculate!(100, /, 4);             // 100 / 4 = 25
}
```

常用的模式类型（Fragment Specifier）：

| 类型 | 匹配内容 | 示例 |
| ------ | ---------- | ------ |
| `expr` | 表达式 | `1 + 2`, `foo()` |
| `ty` | 类型 | `i32`, `Vec<String>` |
| `ident` | 标识符 | `my_var`, `MyStruct` |
| `literal` | 字面量 | `42`, `"hello"` |
| `tt` | 单个Token树 | `+`, `{...}`, 任意单个token |
| `stmt` | 语句 | `let x = 5` |
| `path` | 路径 | `std::io::Result` |

## 重复模式：处理可变数量的参数

宏最强大的能力之一是处理任意数量的参数：

```rust
// 自定义 vec! 的简化版
macro_rules! my_vec {
    // 空 vec
    () => {
        Vec::new()
    };
    // 一个或多个元素
    ($($elem:expr),* $(,)?) => {{
        let mut v = Vec::new();
        $(
            v.push($elem);
        )*
        v
    }};
}

fn main() {
    let empty: Vec<i32> = my_vec![];
    let nums = my_vec![1, 2, 3, 4, 5];
    let strs = my_vec!["a", "b", "c",]; // 支持尾部逗号

    println!("{:?} {:?}", empty, nums);
    println!("{:?}", strs);
}
```

模式语法说明：

- `$($elem:expr),*`：匹配零个或多个`expr`，用逗号分隔
- `$($elem:expr),+`：匹配一个或多个
- `$(,)?`：可选的尾部逗号
- `$(...)*`：在展开部分，对每个匹配重复执行

## vec!和println!的展开真相

来看看你熟悉的宏展开后是什么样子（可用`cargo expand`查看）：

```rust
// 你写的：
let v = vec![1, 2, 3];

// 编译器展开后（简化）：
let v = {
    let mut v = Vec::new();
    v.push(1);
    v.push(2);
    v.push(3);
    v
};

// 你写的：
println!("Hello, {}!", name);

// 编译器展开后（简化）：
std::io::_print(format_args!("Hello, {}!", name));
```

每次调用宏不会有函数调用开销——它在编译时被展开成内联代码。

## 过程宏（Procedural Macros）：真正的代码生成

过程宏用普通Rust代码来操作Token Stream，能力远超声明式宏。它们必须在独立的crate中定义（`lib`类型，带`proc-macro = true`），分三种：

**1. derive宏**（最常见，你肯定用过）

```rust
// 你在结构体上写的 #[derive(Debug, Clone, Serialize)]
// 这些都是过程宏在编译时为你生成了 impl 块

use serde::Serialize;

#[derive(Debug, Clone, Serialize)]
struct User {
    name: String,
    age: u32,
}
// 编译器自动生成了：
// impl Debug for User { ... }
// impl Clone for User { ... }
// impl Serialize for User { ... }
```

**2. 类属性宏（Attribute-like Macros）**

```rust
// tokio 的 #[tokio::main] 就是类属性宏
#[tokio::main]
async fn main() { /* ... */ }

// 展开后：
fn main() {
    tokio::runtime::Builder::new_multi_thread()
        .enable_all()
        .build()
        .unwrap()
        .block_on(async { /* ... */ })
}
```

**3. 类函数宏（Function-like Macros）**

```rust
// 比如 sqlx 的编译期 SQL 验证
// let user = sqlx::query!("SELECT * FROM users WHERE id = ?", user_id)
//     .fetch_one(&pool)
//     .await?;
// 这个宏在编译时连接数据库验证 SQL 语句的正确性！
```

## 编写一个实用的声明式宏

让我们来写一个测试辅助宏，它同时检查条件并打印调试信息：

```rust
macro_rules! assert_with_context {
    ($cond:expr, $msg:literal) => {
        if !$cond {
            panic!(
                "断言失败 [{}:{}]：{}\n条件：{}",
                file!(), line!(), $msg, stringify!($cond)
            );
        }
    };
    ($cond:expr) => {
        assert_with_context!($cond, "无附加信息");
    };
}

fn validate_age(age: i32) -> bool {
    age >= 0 && age <= 150
}

fn main() {
    let age = 25;
    assert_with_context!(validate_age(age), "年龄必须在合理范围内");
    println!("年龄验证通过：{}", age);

    // 这会触发 panic，带有文件名和行号信息
    // assert_with_context!(validate_age(-5), "年龄不能为负数");
}
```

再写一个更复杂的：实现一个简单的DSL（领域特定语言）来定义状态机：

```rust
macro_rules! define_states {
    (
        $( $state:ident => { $( $transition:ident -> $target:ident ),* $(,)? } )*
    ) => {
        #[derive(Debug, Clone, PartialEq)]
        enum State {
            $( $state, )*
        }

        #[derive(Debug, Clone, PartialEq)]
        enum Event {
            $( $( $transition, )* )*
        }

        fn transition(current: &State, event: &Event) -> Option<State> {
            match (current, event) {
                $(
                    $(
                        (State::$state, Event::$transition) => Some(State::$target),
                    )*
                )*
                _ => None,
            }
        }
    };
}

define_states! {
    Locked => {
        InsertCoin -> Unlocked,
        BreakLock -> Unlocked
    }
    Unlocked => {
        PushThrough -> Locked,
        InsertCoin -> Unlocked
    }
}

fn main() {
    let mut state = State::Locked;
    println!("初始状态：{:?}", state);

    state = transition(&state, &Event::InsertCoin).unwrap();
    println!("投币后：{:?}", state);  // Unlocked

    state = transition(&state, &Event::PushThrough).unwrap();
    println!("通过后：{:?}", state);  // Locked
}
```

## 宏的卫生性（Hygiene）

宏卫生性是指：宏内部定义的变量**不会**与调用处的变量冲突。Rust的声明式宏是**部分卫生**的：

```rust
macro_rules! using_x {
    () => {
        let x = 100;  // 宏内部的 x
        println!("宏内部 x = {}", x);
    };
}

fn main() {
    let x = 42;        // 外部的 x
    using_x!();        // 打印：宏内部 x = 100
    println!("外部 x = {}", x);  // 打印：外部 x = 42（不受影响！）
}
```

如果宏需要"注入"变量到调用方作用域（少数场景），可以用`$var:ident`模式显式传入变量名。

> **注意**：过程宏**不是**卫生的——它们操作原始Token Stream，可以故意引入或遮蔽变量。这是过程宏强大但也危险的原因之一。

## 常见陷阱与易错点

**陷阱1：宏展开后类型不匹配**

```rust
macro_rules! add {
    ($a:expr, $b:expr) => {
        $a + $b  // 如果 $a 和 $b 类型不同，编译错误在调用处，难以定位
    };
}
// add!(1i32, 2u64)  // 编译错误，但错误信息可能令人困惑
```

**陷阱2：宏中的分号问题**

```rust
macro_rules! maybe_return {
    ($val:expr) => {
        $val  // 作为表达式使用时不要加分号
    };
}
let x = maybe_return!(42);  // 正确
// let x = maybe_return!(42;);  // 如果宏里有分号，这里可能出错
```

**陷阱3：宏的递归展开限制**
Rust默认限制宏递归展开深度为128层，超深层递归需要用`#![recursion_limit = "256"]`调整。

## 小结

- 声明式宏（`macro_rules!`）基于模式匹配，适合简单的代码模板生成
- 过程宏用Rust代码编写，能力强大，分derive宏、类属性宏、类函数宏三种
- 宏支持重复模式（`$()*`、`$()+`），可处理可变参数
- Rust的声明式宏具有部分卫生性，避免变量名冲突
- 宏在编译时展开，没有运行时开销，但会让编译错误更难定位
- 善用宏可以消除大量重复代码，但不要滥用——简单场景优先用函数和泛型
