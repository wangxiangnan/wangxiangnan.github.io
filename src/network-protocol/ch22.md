# 第22章：网络安全协议——防火墙、VPN 与零信任

## 网络安全的基本威胁模型

在讨论安全协议之前，先搞清楚我们在防御什么：

1. **窃听（Eavesdropping）**：攻击者在链路上抓包，读取明文数据。防御：加密（TLS、IPsec）。
2. **篡改（Tampering）**：攻击者修改传输中的数据。防御：完整性校验（HMAC、数字签名）。
3. **重放（Replay）**：攻击者录制合法请求，稍后重放。防御：Nonce、时间戳、序列号。
4. **DDoS（分布式拒绝服务）**：用海量请求淹没目标。防御：流量清洗、速率限制、Anycast 分散。

## 防火墙的类型与原理

防火墙是网络的第一道防线——在内外网之间设卡检查。

**包过滤防火墙（Packet Filter）**

最基础的防火墙，逐包检查 IP 头和 TCP/UDP 头，基于规则决定放行或丢弃：

```bash
# 典型规则示例
# 允许 SSH（端口 22）从管理网段访问
ALLOW TCP src=10.0.1.0/24 dst=* port=22
# 允许已建立的连接的返回流量
ALLOW TCP state=ESTABLISHED,RELATED
# 拒绝其他所有入站流量
DENY ALL
```

它只看 IP 和端口，不理解应用层语义。如果攻击者把恶意数据放在端口 80 上，包过滤防火墙看不出问题。

**状态检测防火墙（Stateful Inspection）**

维护一个**连接状态表**，跟踪每个 TCP 连接的状态（SYN_SENT、ESTABLISHED、FIN_WAIT 等）。只有属于已建立连接的包才能通过，防止了"无中生有"的攻击。

**应用层防火墙（WAF，Web Application Firewall）**

工作在 HTTP 层，能理解请求语义。比如检测 SQL 注入：

```
# 正常请求
GET /user?id=123 HTTP/1.1

# SQL 注入攻击——WAF 应该拦截
GET /user?id=123'+OR+'1'='1 HTTP/1.1
```

WAF 通过规则引擎或机器学习检测这类攻击模式。

## VPN 协议族

**IPsec：传输模式 vs 隧道模式**

IPsec 是 IP 层的安全协议，有两种工作模式：

- **传输模式（Transport Mode）**：只加密 IP 载荷，IP 头保持明文。适合端到端通信。
- **隧道模式（Tunnel Mode）**：整个原始 IP 包被加密，外层套一个新的 IP 头。适合站点到站点的 VPN。

IPsec 有两个核心协议：

- **AH（Authentication Header）**：提供完整性和认证，但不加密。协议号 51。
- **ESP（Encapsulating Security Payload）**：提供加密 + 完整性 + 认证。协议号 50。

```
隧道模式 ESP 封装过程：
原始包: [IP头][TCP头][数据]
  ↓ 加密 TCP 头和数据
  ↓ 添加 ESP 头和尾
  ↓ 添加新的外层 IP 头
结果: [新IP头][ESP头][加密的TCP头+数据][ESP尾][ESP认证]
```

**WireGuard：现代化的 VPN 协议**

WireGuard 是 2020 年合入 Linux 内核的新一代 VPN 协议，代码量只有约 4000 行（OpenVPN 约 10 万行）。它的哲学是：**少即是多，少即是安全**。

- 只使用一种加密方案（ChaCha20-Poly1305 + Curve25519）
- 没有协商机制（减少了攻击面）
- 连接建立极快（1-RTT 握手）
- 内核态实现，性能接近原生网络

**OpenVPN vs WireGuard 对比：**

| 特性 | OpenVPN | WireGuard |
| --- | --- | --- |
| 代码量 | ~100K 行 | ~4K 行 |
| 加密算法 | 可协商（AES、ChaCha20 等） | 固定（ChaCha20-Poly1305） |
| 连接建立 | 较慢（基于 TLS） | 极快（Noise 协议） |
| NAT 穿透 | 需要额外配置 | 内置支持 |
| 连接迁移 | 不支持 | 支持（类似 QUIC 的设计） |

## TLS 与证书管理的实战问题

HTTPS 需要 TLS 证书，证书管理在生产环境中是个大问题：

**Let's Encrypt** 提供免费、自动化的 TLS 证书。它的核心流程（ACME 协议）：

1. 你向 Let's Encrypt 证明你拥有某个域名
2. Let's Encrypt 给你一个短期证书（90 天有效期）
3. 你的服务器自动续期，永不过期

```bash
# 使用 certbot 自动获取和续期证书
sudo certbot --nginx -d example.com -d www.example.com

# certbot 会自动设置 cron 任务，每天检查是否需要续期
# 证书续期后自动重载 nginx
```

## 零信任网络（Zero Trust）：从"信任内网"到"永不信任"

传统网络安全模型是"城堡与护城河"：防火墙外面是危险的，里面是安全的。一旦你通过 VPN 进入内网，你就被信任了——你可以访问所有内部服务。

问题是：**如果攻击者攻破了内网中的一台机器怎么办？** 在传统模型下，攻击者可以在内网中横向移动，访问所有服务。

**零信任**的核心原则：**Never trust, always verify.**

- 没有"内网"的概念，每个服务都独立认证
- 每次请求都要验证身份、设备状态、权限
- 即使你在办公室的 WiFi 上，访问内部 API 也需要 mTLS（双向 TLS）
- 基于身份的访问控制，而非基于网络位置

```
传统模型:
  Internet → [防火墙] → 内网（一切可信）

零信任模型:
  Internet → [认证网关] → 服务A（独立认证）
                        → 服务B（独立认证）
                        → 服务C（独立认证）
  每个服务之间也需要 mTLS 认证
```

## 编程实践：用 iptables 配置防火墙规则

```bash
#!/bin/bash
# 简单的 iptables 防火墙配置脚本
# 注意：此脚本需要 root 权限，且会立即生效
# 在生产环境使用前请先测试

# 清除现有规则
iptables -F
iptables -X

# 默认策略：丢弃所有入站，允许所有出站
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# 允许回环接口（localhost 通信）
iptables -A INPUT -i lo -j ACCEPT

# 允许已建立的连接和关联连接的流量
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# 允许 SSH（端口 22），限制速率防止暴力破解
iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
  -m limit --limit 3/min --limit-burst 5 -j ACCEPT

# 允许 HTTP 和 HTTPS
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# 允许 ICMP（ping），限制速率
iptables -A INPUT -p icmp --icmp-type echo-request \
  -m limit --limit 1/sec -j ACCEPT

# 记录被丢弃的包（用于审计）
iptables -A INPUT -m limit --limit 5/min -j LOG \
  --log-prefix "iptables-dropped: " --log-level 4

echo "Firewall rules applied."
```

## 抓包实践：对比 IPsec 隧道内外的报文

```bash
# 在未启用 IPsec 时抓取明文 HTTP 流量
tshark -i eth0 -f "tcp port 80" -c 5 -V | head -30
# 你能看到完整的 HTTP 请求内容

# 启用 IPsec 隧道后，抓取相同流量
tshark -i eth0 -f "esp" -c 5 -V
# 你看到的是 ESP 封装的密文，协议号 50
# ESP Header: SPI: 0x12345678, Sequence: 1
# ESP Payload: [encrypted data - 不可读]
```

在隧道外抓包，你只能看到 ESP 协议号和加密的载荷，完全无法得知内部传输的是 HTTP、SSH 还是其他任何协议。这就是 IPsec 隧道的保护效果。
