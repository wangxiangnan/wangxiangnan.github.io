# Ch05: 共享包开发 — packages/shared

## 本章目标

> 打造一个真正意义上的"共享知识层"——让前端和后端使用同一套类型定义、同一套验证逻辑、同一套常量枚举。这不是简单的"复制粘贴"，而是通过 pnpm workspace 的包引用机制，实现代码级别的单一数据源（Single Source of Truth）。

## 5.1 创建 @taskflow/shared 包

首先，在 `packages/shared` 目录下初始化包：

```bash
cd packages/shared
pnpm init
```

然后配置 `package.json`。这是整个共享包的"身份证"，每一个字段都有其存在的理由：

```json
{
  "name": "@taskflow/shared",
  "version": "0.1.0",
  "description": "共享类型、工具函数和常量",
  "type": "module",
  "exports": {
    ".": {
      "development": "./src/index.ts",
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js"
    },
    "./types": {
      "development": "./src/types/index.ts",
      "types": "./dist/types/index.d.ts",
      "import": "./dist/types/index.js"
    },
    "./utils": {
      "development": "./src/utils/index.ts",
      "types": "./dist/utils/index.d.ts",
      "import": "./dist/utils/index.js"
    },
    "./constants": {
      "development": "./src/constants/index.ts",
      "types": "./dist/constants/index.d.ts",
      "import": "./dist/constants/index.js"
    }
  },
  "files": ["dist"],
  "scripts": {
    "build": "tsc -p tsconfig.json",
    "dev": "tsc -p tsconfig.json --watch",
    "typecheck": "tsc --noEmit",
    "clean": "node --input-type=module -e \"import{rmSync}from'node:fs';['dist','.turbo'].forEach(d=>rmSync(d,{recursive:true,force:true}))\""
  },
  "devDependencies": {
    "@taskflow/tsconfig": "workspace:*",
    "typescript": "^7.0.2"
  }
}
```

**为什么这样设计 `exports` 字段？**

传统的 `main` + `types` 只能暴露一个入口。而 `exports` 是 Node.js 的 Subpath Exports 规范，它允许消费者按需引入：

```typescript
// 只引入类型 — tree-shaking 友好
import type { User } from '@taskflow/shared/types';

// 只引入工具函数
import { formatDate } from '@taskflow/shared/utils';

// 引入全部内容
import { User, formatDate, API_ROUTES } from '@taskflow/shared';
```

三个条件的分工是：

- **`development`**：给 Vite 和 `tsx --conditions=development` 用，直接指向 `src/` 的 TS 源码。改 shared 后前端 HMR 立即生效，不需要先构建。
- **`types`**：给 TypeScript 类型检查用，必须放在 `import` 之前。
- **`import`**：给生产构建和 Node.js 运行时用，指向 `dist/`。

> **为什么不再同时输出 CJS？** 本教程的 web 和 api 都是 ESM（`"type": "module"`），共享包只需要 ESM。双格式会让 `exports` 复杂一倍，还会带来“双重包危害”（同一模块被 ESM/CJS 各加载一次）。只有当你确实要发布给 CJS 消费者时，才需要额外产出 `.cjs`（可以用 tsup 或 `tsc` 双配置）。

安装依赖：

```bash
pnpm install
```

## 5.2 类型定义：共享的 TypeScript 类型

创建 `packages/shared/src/types/index.ts`：

```typescript
// ============================================
// 基础实体类型
// ============================================

/** 健康检查接口的返回结构（Ch03 引入，后续章节继续复用） */
export interface HealthResponse {
  status: 'ok';
  version: string;
  timestamp: string;
}

/** 用户实体 — 前后端通用的"用户"概念 */
export interface User {
  id: string;
  username: string;
  email: string;
  avatar?: string;
  role: UserRole;
  createdAt: string;  // ISO 8601 格式，前后端统一用字符串传输
  updatedAt: string;
}

/** 用户角色枚举 */
export enum UserRole {
  ADMIN = 'admin',
  EDITOR = 'editor',
  VIEWER = 'viewer',
}

// ============================================
// API 响应类型 — 统一所有接口的返回格式
// ============================================

/** 通用 API 响应包装器 */
export interface ApiResponse<T = unknown> {
  success: boolean;
  data?: T;
  error?: ApiError;
  meta?: PaginationMeta;
}

/** API 错误信息 */
export interface ApiError {
  code: string;        // 机器可读的错误码，如 'USER_NOT_FOUND'
  message: string;     // 人类可读的错误描述
  details?: unknown;   // 可选的详细错误信息（如字段验证失败）
}

/** 分页元信息 */
export interface PaginationMeta {
  page: number;
  pageSize: number;
  total: number;
  totalPages: number;
}

// ============================================
// 请求/响应 DTO（Data Transfer Object）
// ============================================

/** 创建用户的请求数据 */
export interface CreateUserDto {
  username: string;
  email: string;
  password: string;
  role?: UserRole;
}

/** 更新用户的请求数据 — 所有字段可选 */
export interface UpdateUserDto {
  username?: string;
  email?: string;
  avatar?: string;
  role?: UserRole;
}

/** 用户登录请求 */
export interface LoginDto {
  email: string;
  password: string;
}

/** 登录成功响应 */
export interface LoginResponse {
  user: User;
  accessToken: string;
  refreshToken: string;
  expiresIn: number;  // 秒
}

/** 用户列表查询参数 */
export interface UserListQuery {
  page?: number;
  pageSize?: number;
  search?: string;
  role?: UserRole;
  sortBy?: 'createdAt' | 'username' | 'email';
  sortOrder?: 'asc' | 'desc';
}
```

**为什么要定义 DTO 而不是直接复用实体类型？**

这是一个关键的架构决策。实体类型（`User`）描述的是"数据长什么样"，DTO 描述的是"传输时需要什么"。比如创建用户时不需要 `id` 和 `createdAt`（这些由服务端生成），但需要 `password`（这在 `User` 中不应该出现，因为 API 响应永远不会返回密码）。分离 DTO 和实体类型，让你的类型系统精确匹配每个场景的实际需求。

## 5.3 工具函数：通用逻辑的单一来源

创建 `packages/shared/src/utils/index.ts`：

```typescript
import type {
  ApiResponse,
  ApiError,
  PaginationMeta,
  HealthResponse,
} from "../types/index.js";

// ============================================
// 健康检查
// ============================================

/** 共享包版本号，与 packages/shared/package.json 的 version 保持一致 */
export const SHARED_VERSION = "0.1.0";

/** 生成统一的健康检查响应，前端和运维脚本可以共用 */
export function createHealthResponse(): HealthResponse {
  return {
    status: "ok",
    version: SHARED_VERSION,
    timestamp: new Date().toISOString(),
  };
}

// ============================================
// 验证函数
// ============================================

/** 邮箱格式验证 */
export function isValidEmail(email: string): boolean {
  // 使用 RFC 5322 简化版正则，覆盖 99% 的真实场景
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  return emailRegex.test(email);
}

/** 用户名验证：3-20 个字符，只允许字母、数字、下划线和连字符 */
export function isValidUsername(username: string): boolean {
  const usernameRegex = /^[a-zA-Z0-9_-]{3,20}$/;
  return usernameRegex.test(username);
}

/** 密码强度验证：至少 8 位，包含大小写字母和数字 */
export function isValidPassword(password: string): boolean {
  if (password.length < 8) return false;
  if (!/[a-z]/.test(password)) return false;
  if (!/[A-Z]/.test(password)) return false;
  if (!/[0-9]/.test(password)) return false;
  return true;
}

/**
 * 通用的 DTO 验证函数
 * 返回错误信息数组，空数组表示验证通过
 */
export function validateCreateUserDto(data: {
  username: string;
  email: string;
  password: string;
}): string[] {
  const errors: string[] = [];

  if (!isValidUsername(data.username)) {
    errors.push('用户名需要 3-20 个字符，只允许字母、数字、下划线和连字符');
  }
  if (!isValidEmail(data.email)) {
    errors.push('邮箱格式不正确');
  }
  if (!isValidPassword(data.password)) {
    errors.push('密码至少 8 位，需包含大小写字母和数字');
  }

  return errors;
}

// ============================================
// 日期格式化
// ============================================

/**
 * 将日期格式化为 ISO 8601 字符串
 * 为什么不用 Date.toISOString()？因为这个函数能处理更多边界情况，
 * 并且可以指定时区。
 */
export function formatDate(date: Date | string | number): string {
  const d = new Date(date);
  if (isNaN(d.getTime())) {
    throw new Error(`Invalid date: ${date}`);
  }
  return d.toISOString();
}

/** 格式化为人类可读的日期：2024-01-15 */
export function formatDateShort(date: Date | string | number): string {
  const d = new Date(date);
  if (isNaN(d.getTime())) {
    throw new Error(`Invalid date: ${date}`);
  }
  const year = d.getFullYear();
  const month = String(d.getMonth() + 1).padStart(2, '0');
  const day = String(d.getDate()).padStart(2, '0');
  return `${year}-${month}-${day}`;
}

/** 计算"多久前"，用于前端显示 */
export function timeAgo(date: Date | string | number): string {
  const d = new Date(date);
  const now = new Date();
  const seconds = Math.floor((now.getTime() - d.getTime()) / 1000);

  const intervals: [number, string][] = [
    [31536000, '年'],
    [2592000, '个月'],
    [86400, '天'],
    [3600, '小时'],
    [60, '分钟'],
    [1, '秒'],
  ];

  for (const [secs, label] of intervals) {
    const count = Math.floor(seconds / secs);
    if (count >= 1) {
      return `${count} ${label}前`;
    }
  }
  return '刚刚';
}

// ============================================
// 自定义错误类
// ============================================

/**
 * 应用级错误基类
 * 为什么自定义错误类？因为 try/catch 中需要区分"业务错误"和"系统错误"，
 * 不同的错误类型对应不同的处理策略（返回给前端 vs. 记录日志并报警）。
 */
export class AppError extends Error {
  constructor(
    public readonly code: string,
    message: string,
    public readonly statusCode: number = 500,
    public readonly details?: unknown,
  ) {
    super(message);
    this.name = 'AppError';
    // 修复 TypeScript 中继承内置类的原型链问题
    Object.setPrototypeOf(this, AppError.prototype);
  }

  /** 转换为 API 错误响应格式 */
  toApiError(): ApiError {
    return {
      code: this.code,
      message: this.message,
      details: this.details,
    };
  }
}

/** 常见的业务错误 — 使用工厂模式简化创建 */
export class NotFoundError extends AppError {
  constructor(resource: string, id?: string) {
    super(
      'NOT_FOUND',
      id ? `${resource}（ID: ${id}）不存在` : `${resource}不存在`,
      404,
    );
    this.name = 'NotFoundError';
    Object.setPrototypeOf(this, NotFoundError.prototype);
  }
}

export class ValidationError extends AppError {
  constructor(message: string, details?: unknown) {
    super('VALIDATION_ERROR', message, 400, details);
    this.name = 'ValidationError';
    Object.setPrototypeOf(this, ValidationError.prototype);
  }
}

export class UnauthorizedError extends AppError {
  constructor(message: string = '未授权，请先登录') {
    super('UNAUTHORIZED', message, 401);
    this.name = 'UnauthorizedError';
    Object.setPrototypeOf(this, UnauthorizedError.prototype);
  }
}

export class ForbiddenError extends AppError {
  constructor(message: string = '权限不足，无法执行此操作') {
    super('FORBIDDEN', message, 403);
    this.name = 'ForbiddenError';
    Object.setPrototypeOf(this, ForbiddenError.prototype);
  }
}

// ============================================
// API 响应构造器
// ============================================

/** 构造成功的 API 响应 */
export function successResponse<T>(data: T, meta?: PaginationMeta): ApiResponse<T> {
  return {
    success: true,
    data,
    ...(meta && { meta }),
  };
}

/** 构造失败的 API 响应 */
export function errorResponse(error: ApiError): ApiResponse<never> {
  return {
    success: false,
    error,
  };
}
```

**为什么把错误类和响应构造器放在 shared 里？**

这实现了"端到端类型安全"。后端抛出的 `NotFoundError`，它的 `code` 字段是 `'NOT_FOUND'`；前端收到响应后，可以通过 `response.error?.code === 'NOT_FOUND'` 精确匹配错误类型——这个字符串不是随便写的，它由 TypeScript 的类型系统保证一致性。

## 5.4 常量管理

创建 `packages/shared/src/constants/index.ts`：

```typescript
// ============================================
// API 路由常量 — 前后端共用，改一处全局生效
// ============================================

export const API_ROUTES = {
  AUTH: {
    LOGIN: '/api/auth/login',
    LOGOUT: '/api/auth/logout',
    REFRESH: '/api/auth/refresh',
  },
  USERS: {
    BASE: '/api/users',
    BY_ID: (id: string) => `/api/users/${id}` as const,
    PROFILE: '/api/users/profile',
  },
} as const;

// ============================================
// HTTP 状态码 — 语义化的常量
// ============================================

export const HTTP_STATUS = {
  OK: 200,
  CREATED: 201,
  NO_CONTENT: 204,
  BAD_REQUEST: 400,
  UNAUTHORIZED: 401,
  FORBIDDEN: 403,
  NOT_FOUND: 404,
  CONFLICT: 409,
  UNPROCESSABLE_ENTITY: 422,
  INTERNAL_SERVER_ERROR: 500,
} as const;

// ============================================
// 通用常量
// ============================================

export const DEFAULT_PAGE_SIZE = 20;
export const MAX_PAGE_SIZE = 100;

export const PASSWORD_MIN_LENGTH = 8;
export const USERNAME_MIN_LENGTH = 3;
export const USERNAME_MAX_LENGTH = 20;

/** JWT 相关配置 */
export const JWT_CONFIG = {
  ACCESS_TOKEN_EXPIRY: 3600,       // 1 小时（秒）
  REFRESH_TOKEN_EXPIRY: 604800,    // 7 天（秒）
} as const;

/** 支持的排序字段 */
export const USER_SORT_FIELDS = ['createdAt', 'username', 'email'] as const;
export type UserSortField = typeof USER_SORT_FIELDS[number];
```

**为什么路由常量要放在 shared 里？**

在传统项目中，前端的路由字符串往往是硬编码的 `"api/users"` 散落各处。当后端决定将 `/api/users` 改为 `/api/v2/users` 时，你需要全局搜索替换——这极易遗漏。而共享路由常量后，修改 `API_ROUTES.USERS.BASE` 这一个值，前后端都会自动更新，TypeScript 还会帮你检查所有引用点是否正确。

## 5.5 入口文件和构建配置

创建 `packages/shared/src/index.ts` 作为统一导出入口：

```typescript
// 导出所有类型
export type {
  HealthResponse,
  User,
  ApiResponse,
  ApiError,
  PaginationMeta,
  CreateUserDto,
  UpdateUserDto,
  LoginDto,
  LoginResponse,
  UserListQuery,
} from "./types/index.js";

export { UserRole } from "./types/index.js";

// 导出所有工具函数
export {
  SHARED_VERSION,
  createHealthResponse,
  isValidEmail,
  isValidUsername,
  isValidPassword,
  validateCreateUserDto,
  formatDate,
  formatDateShort,
  timeAgo,
  successResponse,
  errorResponse,
} from "./utils/index.js";

export {
  AppError,
  NotFoundError,
  ValidationError,
  UnauthorizedError,
  ForbiddenError,
} from "./utils/index.js";

// 导出所有常量
export {
  API_ROUTES,
  HTTP_STATUS,
  DEFAULT_PAGE_SIZE,
  MAX_PAGE_SIZE,
  PASSWORD_MIN_LENGTH,
  USERNAME_MIN_LENGTH,
  USERNAME_MAX_LENGTH,
  JWT_CONFIG,
  USER_SORT_FIELDS,
} from "./constants/index.js";

export type { UserSortField } from "./constants/index.js";
```

注意 `type` 关键字在导出接口时的使用——这不是可选的，它告诉 TypeScript 这些是纯类型导出，不会出现在运行时代码中，有助于 tree-shaking。

创建 `packages/shared/tsconfig.json`：

```json
{
  "extends": "@taskflow/tsconfig/base.json",
  "compilerOptions": {
    "outDir": "dist",
    "rootDir": "src"
  },
  "include": ["src"],
  "exclude": ["dist", "node_modules"]
}
```

**为什么用 tsc 而不是 tsup？**

共享包只输出 ESM，且目录结构需要与 `exports` 的子路径一一对应。`tsc -p` 会把 `src/types/index.ts` 原样编译到 `dist/types/index.js` 并生成对应的 `.d.ts`，不需要额外配置 entry 映射；`tsup` 则需要为每个入口手写 entry，且默认会做打包/代码分割，反而容易把子路径结构打平。

如果将来确实需要产出 CJS，或者要发布到 npm 并做 tree-shaking 优化，可以再加一个 tsup 构建步骤；但不要为了“双格式”牺牲当前的简单性。

在 `packages/shared` 中执行构建：

```bash
pnpm build
```

**在 Vue 前端中使用（apps/web）：**

```vue
<script setup lang="ts">
import { ref } from 'vue';
import type { User, ApiResponse, CreateUserDto } from '@taskflow/shared/types';
import { isValidEmail, validateCreateUserDto } from '@taskflow/shared/utils';
import { API_ROUTES } from '@taskflow/shared/constants';

const form = ref<CreateUserDto>({
  username: '',
  email: '',
  password: '',
});

const errors = ref<string[]>([]);

function handleSubmit() {
  // 使用共享的验证函数 — 和后端完全一致的验证逻辑
  errors.value = validateCreateUserDto(form.value);
  if (errors.value.length > 0) return;

  // API_ROUTES.USERS.BASE 直接引用共享常量
  fetch(API_ROUTES.USERS.BASE, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(form.value),
  })
    .then(res => res.json())
    .then((response: ApiResponse<User>) => {
      if (response.success) {
        console.log('创建成功:', response.data);
      }
    });
}
</script>

<template>
  <form @submit.prevent="handleSubmit">
    <div v-if="errors.length" class="error-box">
      <p v-for="err in errors" :key="err">{{ err }}</p>
    </div>
    <input v-model="form.username" placeholder="用户名" />
    <input v-model="form.email" type="email" placeholder="邮箱" />
    <input v-model="form.password" type="password" placeholder="密码" />
    <button type="submit">注册</button>
  </form>
</template>
```

**在 Express 后端中使用（apps/api）：**

```typescript
import express from 'express';
import type { User, CreateUserDto, ApiResponse } from '@taskflow/shared/types';
import {
  validateCreateUserDto,
  successResponse,
  errorResponse,
  NotFoundError,
} from '@taskflow/shared/utils';
import { API_ROUTES, HTTP_STATUS } from '@taskflow/shared/constants';

const app = express();
app.use(express.json());

// 路由路径直接使用共享常量，确保前后端一致
app.post(API_ROUTES.USERS.BASE, (req, res) => {
  const dto: CreateUserDto = req.body;

  // 使用共享的验证函数
  const errors = validateCreateUserDto(dto);
  if (errors.length > 0) {
    res.status(HTTP_STATUS.BAD_REQUEST).json(
      errorResponse({ code: 'VALIDATION_ERROR', message: '输入验证失败', details: errors })
    );
    return;
  }

  // 模拟创建用户
  const user: User = {
    id: crypto.randomUUID(),
    username: dto.username,
    email: dto.email,
    role: dto.role ?? 'viewer',
    createdAt: new Date().toISOString(),
    updatedAt: new Date().toISOString(),
  };

  res.status(HTTP_STATUS.CREATED).json(successResponse(user));
});

app.listen(3000, () => console.log('API server running on port 3000'));
```

看到了吗？前端和后端使用了**完全相同的验证函数** `validateCreateUserDto`。当产品需求变化（比如"用户名现在允许中文"），你只需要修改 `packages/shared/src/utils/index.ts` 中的一个函数，前后端都会自动更新。这就是 monorepo 共享包的核心价值。

## 本章小结

- `@taskflow/shared` 通过 `exports` 字段提供多入口按需引入
- 类型定义（接口、DTO、枚举）是前后端类型安全的基石
- 工具函数和错误类共享确保业务逻辑一致性
- 常量共享消除了"前后端硬编码不同步"的隐患
- 共享包用 `tsc` 输出 ESM 和子路径声明文件，开发模式通过 `development` 条件直读源码，生产构建读取 `dist/`
