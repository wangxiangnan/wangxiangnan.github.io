# 第7章：任务系统与自动化

> "Any task you do more than twice should be automated." —— 某个凌晨三点还在手动跑构建脚本的程序员遗言

如果你是一名开发者，你的日常大概率是这样的：保存代码、运行构建、检查 lint 错误、跑一遍测试、再看一眼输出有没有异常。这一套流程下来，就像游戏里的"刷日常任务"——每天重复，但每天都得做。好消息是，VSCode 的任务系统（Task System）就是为此而生的——它能把你的"日常任务"变成真正的自动化流水线，你只需要按一个快捷键，剩下的交给它。

如果把 VSCode 比作一个操作系统，那任务系统就是它的 `cron + Makefile + shell script` 的合体。但比这三者都优雅得多。

## 7.1 tasks.json：你的自动化蓝图

第一步：将项目配置为受信工作区。`Ctrl+Shift+P`（⌘+Shift+P）打开命令面板，输入**Workspaces: Manage Workspace Trust**

第二步：允许自动化任务。打开工作区或用户级的settings（用户设置是打开命令面板，输入**Preferences: Open User Settings(JSON)**）

```json
{
    "task.allowAutomaticTasks": "on",
}
```

任务系统的核心配置文件是 `.vscode/tasks.json`。你可以通过 `Ctrl+Shift+P`（⌘+Shift+P）打开命令面板，输入 **Tasks: Configure Tasks** 来生成初始模板。

让我们从一个最简单的任务开始，逐步升级到一个完整的项目自动化流水线：

```json
{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "echo",
            "type": "shell",
            "command": "echo Hello, Task System!",
            "problemMatcher": []
        }
    ]
}
```

这就像一个编程世界的 "Hello, World!"——它什么都没干，但证明了你的任务系统已经活过来了。通过 `Ctrl+Shift+B`（⌘+Shift+B）或者命令面板的 **Tasks: Run Task** 就能触发它。

## tasks.json 核心字段详解

`version: "2.0.0"` 是当前标准版本，别用 1.0.0 了，那是上古时代的遗物。每个 task 对象可以包含以下关键属性：

| 字段 | 类型 | 说明 |
| ------ | ------ | ------ |
| `label` | string | 任务的唯一标识名，也是你在任务列表中看到的名字 |
| `type` | string | 任务类型：`shell`（在终端运行）或 `process`（直接执行进程） |
| `command` | string | 要执行的命令 |
| `args` | string[] | 命令参数 |
| `options` | object | 运行选项（cwd、env、shell配置） |
| `problemMatcher` | string/object | 问题匹配器，用于解析输出中的错误信息 |
| `group` | string/object | 任务分组（build、test等） |
| `dependsOn` | string/string[] | 依赖的其他任务 |
| `presentation` | object | 终端面板显示控制 |
| `runOptions` | object | 运行选项（如 runOn） |

## 7.2 两种任务类型：shell vs process

**shell 类型** 是最常用的，它会在集成终端中运行你的命令——这意味着你可以使用管道符 `|`、重定向 `>`、环境变量 `$VAR` 等所有 shell 特性：

```json
{
    "label": "build-and-notify",
    "type": "shell",
    "command": "npm run build && echo '✅ Build Success' || echo '❌ Build Failed'",
    "problemMatcher": ["$tsc"]
}
```

**process 类型** 则直接执行一个可执行文件，不经过 shell 解析。它更安全（不受 shell 注入影响），但也更受限：

```json
{
    "label": "run-node",
    "type": "process",
    "command": "node",
    "args": ["--inspect", "dist/server.js"],
    "problemMatcher": []
}
```

什么时候用哪个？简单原则：**如果你的命令里有 `|`、`&&`、`>` 或者环境变量展开，用 shell；如果只是执行一个程序加参数，用 process。**

## 7.3 problemMatcher（问题匹配器）：让构建错误可点击跳转

`problemMatcher` 有两种用法:① 解析任务输出,把错误/警告报入"问题"面板;② 通过 `background` 块作为**"告诉 VS Code 后台任务何时完成"的信号器**,让依赖任务能正确等待。

### 是什么

`problemMatcher` 是 VS Code 任务(`tasks.json`)的一个配置项,用于**解析任务的终端输出,从中提取错误/警告信息**。提取结果会报入"问题"面板,并在编辑器中标记出错的文件和行号,可以点击跳转。

### 为什么需要它l

任务本质上是"跑一条命令"。任务本身只产生一行 `终端中的文本`,VS Code 并不知道 `ERROR in ./src/app.js (3:5)` 这种输出意味着什么、怎么定位。problemMatcher 就是用**正则表达式 + 命名捕获组**告诉 VS Code 怎么"读懂"这些输出。

### 内置的 problemMatcher

常见工具不需要手写,直接引用内置的即可:

```json
"problemMatcher": ["$tsc", "$eslint-stylish"]
```

常用的有:`$tsc`(TypeScript)、`$eslint-compact` / `$eslint-stylish`(ESLint)、`$msCompile`(MSVC)、`$gulp-tsc`、`$jshint` 等。

### 自定义 pattern

一个典型的错误解析配置:

```json
"problemMatcher": {
  "owner": "webpack",
  "source": "webpack",
  "fileLocation": ["relative", "${workspaceFolder}"],
  "pattern": {
    "regexp": "ERROR in (.*):(\\d+):(\\d+)\\s+(.*)",
    "file": 1,
    "line": 2,
    "column": 3,
    "message": 4,
    "severity": 3,
    "loop": true
  }
}
```

| 字段 | 说明 |
| ------ | ------ |
| `owner` | 问题归属方,同名问题会归到一组,避免不同任务互相覆盖 |
| `source` | 在"问题"面板中显示的来源标签 |
| `fileLocation` | 输出中文件路径的类型(`relative` / `absolute` / `autodetect` 等) |
| `regexp` | 每个捕获组的位置用 `file`、`line`、`column`、`message`、`severity`、`code` 声明,序号从 1 开始 |
| `loop: true` | 一段输出中连续匹配多条问题(多行错误日志场景) |

### background 模式:不是报错,是任务生命周期信号

对长驻任务(`isBackground: true`,如 dev server)来说,任务永远不会"结束",VS Code 无法判断它什么时候完成启动。这时 problemMatcher 的 `background` 块用来**声明"何时算开始、何时算完成"**:

```json
"problemMatcher": {
  "owner": "webpack",
  "pattern": { "regexp": "." },
  "background": {
    "activeOnStart": true,
    "beginsPattern": "Starting development server",
    "endsPattern": "App running at|ERROR"
  }
}
```

| 字段 | 作用 |
| ------ | ------ |
| `activeOnStart: true` | 任务一开始就进入监控状态 |
| `beginsPattern` | 输出中出现该正则时,标记"新一轮编译/启动开始了" |
| `endsPattern` | 输出中出现该正则时,标记"编译/启动结束"(无论成败) |

实际效果:

1. **依赖等待**:其他任务若声明 `dependsOn` 指向该任务,会等 `endsPattern` 出现后才执行,而不是后台任务一开就跑。
2. **状态正确**:任务的"运行中"状态能正确反映编译进度。

#### 为什么 pattern 是 `{ "regexp": "." }`

这是**占位符**。background 模式必须配一个基础 pattern,但 `.` 只匹配任意行、且没有任何捕获组,所以不会有任何条目进入"问题"面板——纯粹为了让 `background` 配置合法存在。这种"只用 background、不报问题"的用法在 dev server 类任务中很常见。

### 内置匹配器

VSCode 预置了一堆常见工具的问题匹配器：

```json
// TypeScript / JavaScript 编译错误
"problemMatcher": ["$tsc"]

// ESLint 输出
"problemMatcher": ["$eslint-stylish"]

// GCC/Clang 编译错误
"problemMatcher": ["$gcc"]

// MSBuild 编译错误
"problemMatcher": ["$msCompile"]

// less / sass 编译错误
"problemMatcher": ["$lessc", "$node-sass"]
```

### 自定义问题匹配器

当你的工具没有内置匹配器时，可以自己写一个。问题匹配器的核心是一个正则表达式，用来从输出文本中提取 **文件名、行号、列号、错误信息** 等关键信息：

```json
{
    "label": "run-pytest",
    "type": "shell",
    "command": "pytest",
    "args": ["--tb=short"],
    "problemMatcher": {
        "owner": "python",
        "severity": "error",
        "fileLocation": "absolute",
        "pattern": [
            {
                "regexp": "^(.+)\\.(\\w+):(\\d+):\\s+(.+)$",
                "file": 1,
                "line": 3,
                "message": 4
            }
        ]
    }
}
```

你也可以将匹配器定义为全局复用，放在 `tasks.json` 的顶层，然后在多个任务中引用：

```json
{
    "version": "2.0.0",
    "problemMatchers": {
        "myLinter": {
            "owner": "mytool",
            "fileLocation": ["relative", "${workspaceFolder}"],
            "pattern": {
                "regexp": "^(.+):(\\d+):(\\d+):\\s+(warning|error):\\s+(.+)$",
                "file": 1,
                "line": 2,
                "column": 3,
                "severity": 4,
                "message": 5
            }
        }
    },
    "tasks": [
        {
            "label": "lint",
            "type": "shell",
            "command": "my-linter src/",
            "problemMatcher": "$myLinter"
        }
    ]
}
```

## 7.4 任务依赖和执行顺序：构建你的流水线

真实项目中的任务从来不是孤立的。构建之前要清理旧产物，测试之前要先构建，部署之前要通过所有检查。`dependsOn` 字段就是为此而生的：

```json
{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "clean",
            "type": "shell",
            "command": "rm -rf dist",
            "problemMatcher": []
        },
        {
            "label": "build",
            "type": "shell",
            "command": "tsc -p tsconfig.json",
            "dependsOn": "clean",
            "group": {
                "kind": "build",
                "isDefault": true
            },
            "problemMatcher": ["$tsc"]
        },
        {
            "label": "lint",
            "type": "shell",
            "command": "eslint src/ --ext .ts",
            "problemMatcher": ["$eslint-stylish"],
            "group": "test"
        },
        {
            "label": "test",
            "type": "shell",
            "command": "jest",
            "dependsOn": "build",
            "group": "test",
            "problemMatcher": []
        },
        {
            "label": "ci-pipeline",
            "dependsOn": ["lint", "test"],
            "dependsOrder": "sequence",
            "problemMatcher": []
        }
    ]
}
```

注意几个关键点：

- `dependsOn` 可以是单个字符串，也可以是数组
- 数组形式默认为**并行执行**，如果需要顺序执行，加上 `"dependsOrder": "sequence"`
- `group` 设为 `"build"` 后，`Ctrl+Shift+B`（⌘+Shift+B）会直接触发它；设为 `"test"` 则通过 **Tasks: Run Test Task** 触发
- `isDefault: true` 表示这是该组的默认任务

## 7.5 自动运行任务：解放双手的终极形态

`runOptions` 可以让任务在特定时机自动触发，就像 React 的生命周期钩子一样：

```json
{
    "label": "format-on-save",
    "type": "shell",
    "command": "prettier --write ${file}",
    "runOptions": {
        "runOn": "folderOpen"
    },
    "problemMatcher": []
}
```

`runOn` 有两个值：

- `"folderOpen"`：打开文件夹时自动运行（适合初始化环境、安装依赖）
- `"default"`：只能通过手动触发

> ⚠️ 注意：VSCode 原生不支持 "onSave" 自动触发任务，这需要通过文件监视器或者编辑器自身的 `on-save` 钩子（如 `editor.formatOnSave`）来实现。如果你真的需要保存时触发任务，可以用一个变通方案——在任务中使用 `chokidar` 或 `fswatch` 做文件监视。

## 7.6 实战：Node.js 项目完整任务链

让我们为一个真实的 Express + TypeScript 项目搭建完整的任务链。项目结构如下：

```
my-express-app/
├── .vscode/
│   └── tasks.json
├── src/
│   ├── index.ts
│   └── routes/
├── tests/
├── package.json
└── tsconfig.json
```

完整 `tasks.json`：

```json
{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "install-deps",
            "type": "shell",
            "command": "npm install",
            "runOptions": { "runOn": "folderOpen" },
            "presentation": { "reveal": "silent" },
            "problemMatcher": []
        },
        {
            "label": "clean",
            "type": "shell",
            "command": "npx rimraf dist",
            "problemMatcher": []
        },
        {
            "label": "compile",
            "type": "shell",
            "command": "tsc -p tsconfig.json",
            "dependsOn": "clean",
            "group": { "kind": "build", "isDefault": true },
            "problemMatcher": ["$tsc"],
            "presentation": {
                "reveal": "always",
                "panel": "shared"
            }
        },
        {
            "label": "lint",
            "type": "shell",
            "command": "eslint",
            "args": ["src/", "--ext", ".ts", "--fix"],
            "group": "test",
            "problemMatcher": ["$eslint-stylish"]
        },
        {
            "label": "unit-test",
            "type": "shell",
            "command": "jest",
            "args": ["--coverage", "--passWithNoTests"],
            "dependsOn": "compile",
            "group": "test",
            "problemMatcher": []
        },
        {
            "label": "dev-server",
            "type": "shell",
            "command": "npx ts-node-dev --respawn --transpile-only src/index.ts",
            "isBackground": true,
            "presentation": {
                "reveal": "always",
                "panel": "dedicated",
                "group": "servers"
            },
            "problemMatcher": []
        },
        {
            "label": "build-all",
            "dependsOn": ["lint", "compile", "unit-test"],
            "dependsOrder": "sequence",
            "group": { "kind": "build", "isDefault": false },
            "problemMatcher": []
        }
    ]
}
```

使用方式：

- `Ctrl+Shift+B`（⌘+Shift+B）：一键编译（clean → compile）
- 命令面板 → **Tasks: Run Test Task**：运行 lint 或 unit-test
- 命令面板 → **Tasks: Run Task** → 选择 `dev-server` 启动开发服务器
- 打开文件夹时自动执行 `npm install`

## 7.7 presentation 面板控制：多终端管理

`presentation` 字段控制任务输出在终端面板中的显示行为，这是多任务并行时的关键：

```json
"presentation": {
    "reveal": "always",       // always | silent | never
    "panel": "dedicated",     // shared | dedicated | new
    "group": "buildGroup",    // 相同 group 的任务共享一个终端 tab
    "focus": false,           // 是否自动聚焦终端
    "showReuseMessage": false,
    "clear": true,            // 每次运行前清除上次输出
    "echo": true,             // 是否显示正在执行的命令
    "close": false            // 任务结束后是否关闭终端
}
```

建议的终端面板组织方式：

- 编译任务用 `"panel": "dedicated", "group": "compile"`
- 测试任务用 `"panel": "dedicated", "group": "test"`
- 开发服务器用 `"panel": "dedicated", "group": "servers"`

## 7.8 进阶：输入变量与交互式任务

任务可以定义用户输入，让任务在运行时动态获取参数，就像函数接收参数一样：

```json
{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "deploy",
            "type": "shell",
            "command": "npm run deploy -- --env=${input:environment} --region=${input:region}",
            "problemMatcher": []
        }
    ],
    "inputs": [
        {
            "id": "environment",
            "type": "pickString",
            "description": "Select deployment environment",
            "options": ["staging", "production", "preview"],
            "default": "staging"
        },
        {
            "id": "region",
            "type": "pickString",
            "description": "Select target region",
            "options": ["us-east-1", "eu-west-1", "ap-southeast-1"],
            "default": "us-east-1"
        }
    ]
}
```

输入类型有三种：

- `pickString`：下拉选择
- `promptString`：文本输入框
- `command`：执行另一个命令的返回值作为输入

## 7.9 进阶：自定义任务提供者插件

如果你想更深度地集成，VSCode 提供了 Task Provider API，允许插件动态提供任务——不需要 `tasks.json`，由插件代码生成任务列表：

```typescript
// 插件中的任务提供者概念代码
import * as vscode from 'vscode';

class MyBuildToolProvider implements vscode.TaskProvider {
    static readonly type = 'mybuildtool';

    provideTasks(): vscode.Task[] {
        // 扫描项目，动态生成任务列表
        const tasks: vscode.Task[] = [];
        const workspaceFolders = vscode.workspace.workspaceFolders;
        if (!workspaceFolders) return tasks;

        for (const folder of workspaceFolders) {
            const buildTask = new vscode.Task(
                { type: MyBuildToolProvider.type, task: 'build' },
                folder,
                'build',
                MyBuildToolProvider.type,
                new vscode.ShellExecution('mybuild --compile')
            );
            buildTask.group = vscode.TaskGroup.Build;
            tasks.push(buildTask);
        }
        return tasks;
    }

    resolveTask(task: vscode.Task): vscode.Task | undefined {
        // 用户自定义的任务，解析并补充执行细节
        return task;
    }
}
```

这是很多语言扩展（如 CMake Tools、Gradle）背后的机制——它们扫描项目文件，自动发现构建目标，让你在任务列表里直接看到和运行。

📋 **本章小结**

- **tasks.json 2.0.0** 是 VSCode 自动化的核心，支持 shell 和 process 两种任务类型
- **problemMatcher** 让构建输出变成可点击的错误信息，大幅提升问题定位效率
- **dependsOn + group** 构建任务依赖链和逻辑分组
- **runOptions.runOn** 实现文件夹打开时自动执行
- **presentation** 精细控制终端面板行为，多任务并行时尤其重要
- **inputs** 让任务支持交互式参数输入
- **Task Provider API** 允许插件动态注入任务，是深度集成的终极手段
