# 第6章 桌面平行世界：Windows 分辨率与缩放

> **本章回答的问题**：Windows 的"分辨率"和"缩放"是什么关系？它和移动端体系如何对应？

移动端的两层体系在桌面上有完全对应的构造，理解这边可以反向巩固认知。

## 6.1 分辨率 = 物理像素

Windows 显示设置里的"分辨率"（1920×1080、2560×1440、3840×2160）就是屏幕的物理像素数，推荐值即面板原生分辨率。手动改低分辨率时，GPU 以更少的物理像素渲染再拉伸上屏——非原生分辨率会发虚，原理与 980 兼容模式的整体缩小类似，只是发生在渲染管线里。

## 6.2 缩放 = 系统 DPR

设置里的"缩放"（100%、125%、150%、200%）就是 Windows 版的 DPR：

```
有效 DPR = 缩放百分比        （100% → 1，150% → 1.5）
系统 DPI 值 = 96 × 缩放      （96 DPI = 100%，144 DPI = 150%）
```

96 基准的来历在[第 3 章](/frontend/pixels-viewport/ch03)已讲：早期显示器约 96 PPI，Windows 定 1 逻辑像素 = 1/96 英寸并沿用至今。

**缩放的意义**：27 寸 4K 屏不缩放的话，按钮文字小到无法使用。设 150% 后，应用看到的逻辑桌面变成 3840÷1.5 = 2560×1440——既保留 4K 的细腻度，又获得 2K 的"逻辑大小"。这与手机"物理分辨率 ÷ DPR = CSS 坐标系"是同一个公式。

## 6.3 逻辑分辨率与 DPI 感知

缩放引入了一个兼容性问题：程序必须知道自己工作在哪个坐标系。

- **DPI 感知（Per-Monitor DPI Aware）**：现代程序，按逻辑像素渲染，系统按 DPR 映射到物理像素，任何缩放下都锐利。
- **DPI 不感知**：老式 GDI 程序，以为自己在 96 DPI 下工作，系统把它的渲染结果**位图拉伸**到目标大小——这就是某些老软件在高分屏上模糊的原因。

浏览器属于前者，并且把"系统缩放 × 浏览器缩放"作为有效 DPR 报给网页。至此可以给出全体系的统一公式：

```
有效 DPR = 厂商基准（PPI ÷ 基准密度取整）× 系统缩放 × 浏览器缩放
1 CSS px 的物理像素数 = 有效 DPR
```

## 6.4 小结

- Windows 的"分辨率"与"缩放"分别对应物理像素和系统 DPR。
- 逻辑分辨率 = 物理 ÷ 缩放，与移动端 CSS 坐标系推导同构。
- DPI 感知与否决定了程序在高分屏上是锐利还是模糊。

## 6.5 练习题

1. 2560×1440 的屏幕设 125% 缩放，逻辑分辨率是多少？
2. 系统缩放 150% 时，Windows 内部的 DPI 值是多少？
3. 一款 2010 年的老软件在 4K 屏 150% 缩放下界面模糊，原因是什么？

## 6.6 参考答案

> 1. 2560÷1.25 = 2048，1440÷1.25 = 1152，逻辑分辨率 2048×1152。
> 2. 96 × 1.5 = 144 DPI。
> 3. 它是 DPI 不感知程序，以为自己运行在 96 DPI 环境下，系统把它的渲染结果位图拉伸到目标尺寸，插值导致模糊。
