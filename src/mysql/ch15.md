# 第15章 存储过程与自定义函数

**生活类比：** 你每天早上起床后有一套固定流程：刷牙 -> 洗脸 -> 做早餐 -> 出门。你不需要每次重新思考每一步，因为这套流程已经"封装"在你的习惯里了。存储过程就是数据库中的"封装好的流程"——你把一系列SQL操作打包成一个"程序"，需要时直接调用。

## 15.1 DELIMITER 与基础语法

MySQL默认用分号(;)作为语句结束符。但存储过程中包含多条语句，每条都有分号，所以我们需要临时更换结束符：

```sql
-- 更换结束符为 $$
DELIMITER $$

CREATE PROCEDURE hello_world()
BEGIN
    SELECT 'Hello, MySQL Stored Procedure!' AS greeting;
END$$

-- 恢复默认结束符
DELIMITER ;

-- 调用存储过程
CALL hello_world();
```

> [!TIP] 提示
> DELIMITER 只是客户端（如MySQL命令行）的功能，不是SQL语句。在应用程序中通过JDBC、Python等调用时，不需要设置DELIMITER。

## 15.2 参数类型：IN / OUT / INOUT

```sql
DELIMITER $$

-- IN 参数：传入值（默认类型）
CREATE PROCEDURE get_employee_count(IN dept_name VARCHAR(50))
BEGIN
    SELECT COUNT(*) AS employee_count
    FROM employees
    WHERE department = dept_name;
END$$

-- OUT 参数：传出值
CREATE PROCEDURE get_max_salary(OUT max_sal DECIMAL(10,2))
BEGIN
    SELECT MAX(salary) INTO max_sal FROM employees;
END$$

-- INOUT 参数：既传入又传出
CREATE PROCEDURE double_value(INOUT val INT)
BEGIN
    SET val = val * 2;
END$$

DELIMITER ;
```

```sql
-- 调用示例
CALL get_employee_count('技术部');

-- OUT 参数需要使用变量接收
CALL get_max_salary(@max_salary);
SELECT @max_salary;

-- INOUT 参数
SET @my_val = 10;
CALL double_value(@my_val);
SELECT @my_val;  -- 结果: 20
```

## 15.3 变量声明与赋值

```sql
DELIMITER $$

CREATE PROCEDURE demo_variables()
BEGIN
    -- 声明局部变量（必须在BEGIN之后、其他语句之前）
    DECLARE v_count INT DEFAULT 0;
    DECLARE v_name VARCHAR(50);
    DECLARE v_salary DECIMAL(10,2);

    -- 方式一：SET 赋值
    SET v_count = 100;

    -- 方式二：SELECT INTO 赋值（从查询结果赋值）
    SELECT name, salary INTO v_name, v_salary
    FROM employees
    WHERE id = 1;

    -- 使用变量
    SELECT CONCAT(v_name, ' 的薪资是 ', v_salary) AS info;
END$$

DELIMITER ;
```

> [!WARNING] 注意
> DECLARE 语句必须放在 BEGIN...END 块的最前面，在其他任何语句之前。这是新手最容易犯的错误之一。

## 15.4 流程控制

```sql
DELIMITER $$

-- IF-THEN-ELSE
CREATE PROCEDURE check_salary(IN emp_id INT, OUT result VARCHAR(20))
BEGIN
    DECLARE v_salary DECIMAL(10,2);
    SELECT salary INTO v_salary FROM employees WHERE id = emp_id;

    IF v_salary > 20000 THEN
        SET result = '高薪';
    ELSEIF v_salary > 10000 THEN
        SET result = '中等';
    ELSE
        SET result = '待提升';
    END IF;
END$$

-- CASE 语句
CREATE PROCEDURE dept_report(IN dept_name VARCHAR(50), OUT report TEXT)
BEGIN
    DECLARE v_count INT;
    DECLARE v_avg_salary DECIMAL(10,2);

    SELECT COUNT(*), AVG(salary) INTO v_count, v_avg_salary
    FROM employees WHERE department = dept_name;

    CASE
        WHEN v_count > 100 THEN SET report = CONCAT(dept_name, ' 是大部门，有', v_count, '人');
        WHEN v_count > 50  THEN SET report = CONCAT(dept_name, ' 是中等部门，有', v_count, '人');
        ELSE SET report = CONCAT(dept_name, ' 是小部门，有', v_count, '人');
    END CASE;
END$$

DELIMITER ;
```

**循环结构：**

```sql
DELIMITER $$

-- WHILE 循环
CREATE PROCEDURE while_demo(IN n INT, OUT total INT)
BEGIN
    DECLARE i INT DEFAULT 1;
    SET total = 0;

    WHILE i <= n DO
        SET total = total + i;
        SET i = i + 1;
    END WHILE;
END$$

-- LOOP 循环（需要 LEAVE 退出）
CREATE PROCEDURE loop_demo(IN n INT, OUT total INT)
BEGIN
    DECLARE i INT DEFAULT 1;
    SET total = 0;

    calc_loop: LOOP
        IF i > n THEN
            LEAVE calc_loop;  -- 相当于 break
        END IF;

        SET total = total + i;
        SET i = i + 1;
    END LOOP calc_loop;
END$$

-- REPEAT 循环（后判断条件）
CREATE PROCEDURE repeat_demo(IN n INT, OUT total INT)
BEGIN
    DECLARE i INT DEFAULT 1;
    SET total = 0;

    REPEAT
        SET total = total + i;
        SET i = i + 1;
    UNTIL i > n
    END REPEAT;
END$$

DELIMITER ;
```

## 15.5 游标(Cursor)

游标就像一根"指针"，让你可以逐行处理查询结果。虽然SQL擅长集合操作，但有时候确实需要逐行处理。

```sql
DELIMITER $$

CREATE PROCEDURE process_employees()
BEGIN
    DECLARE v_id INT;
    DECLARE v_name VARCHAR(50);
    DECLARE v_salary DECIMAL(10,2);
    DECLARE v_done INT DEFAULT 0;

    -- 声明游标（必须在变量声明之后）
    DECLARE emp_cursor CURSOR FOR
        SELECT id, name, salary FROM employees WHERE department = '技术部';

    -- 声明"未找到数据"的处理程序
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = 1;

    -- 创建临时表存放结果
    CREATE TEMPORARY TABLE IF NOT EXISTS bonus_report (
        emp_id INT,
        emp_name VARCHAR(50),
        bonus DECIMAL(10,2)
    );
    TRUNCATE TABLE bonus_report;

    -- 打开游标
    OPEN emp_cursor;

    -- 逐行读取
    read_loop: LOOP
        FETCH emp_cursor INTO v_id, v_name, v_salary;

        IF v_done = 1 THEN
            LEAVE read_loop;
        END IF;

        -- 根据薪资计算奖金
        INSERT INTO bonus_report (emp_id, emp_name, bonus)
        VALUES (v_id, v_name, v_salary * 0.1);
    END LOOP read_loop;

    -- 关闭游标
    CLOSE emp_cursor;

    -- 查看结果
    SELECT * FROM bonus_report;
    DROP TEMPORARY TABLE bonus_report;
END$$

DELIMITER ;
```

> [!WARNING] 注意
> 游标的性能通常不如集合操作。如果能用一条SQL搞定的事情，不要用游标拆成多步。游标适合那些确实需要逐行判断和处理的复杂业务逻辑。

## 15.6 异常处理

```sql
DELIMITER $$

CREATE PROCEDURE safe_insert_employee(
    IN p_name VARCHAR(50),
    IN p_email VARCHAR(100),
    IN p_dept VARCHAR(50),
    IN p_salary DECIMAL(10,2),
    OUT p_result VARCHAR(100)
)
BEGIN
    -- 声明异常处理程序
    DECLARE EXIT HANDLER FOR 1062  -- 唯一键冲突
    BEGIN
        SET p_result = CONCAT('插入失败：邮箱 ', p_email, ' 已存在');
    END;

    DECLARE EXIT HANDLER FOR SQLEXCEPTION  -- 其他所有异常
    BEGIN
        SET p_result = '插入失败：发生未知错误';
        ROLLBACK;
    END;

    START TRANSACTION;

    INSERT INTO employees (name, email, department, salary, hire_date)
    VALUES (p_name, p_email, p_dept, p_salary, CURDATE());

    SET p_result = CONCAT('成功插入员工：', p_name);

    COMMIT;
END$$

DELIMITER ;
```

**使用 SIGNAL 主动抛出异常：**

```sql
DELIMITER $$

CREATE PROCEDURE transfer_money(
    IN from_id INT,
    IN to_id INT,
    IN amount DECIMAL(10,2)
)
BEGIN
    DECLARE v_balance DECIMAL(10,2);

    SELECT balance INTO v_balance FROM accounts WHERE user_id = from_id FOR UPDATE;

    IF v_balance < amount THEN
        -- 主动抛出异常
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '余额不足，无法转账';
    END IF;

    UPDATE accounts SET balance = balance - amount WHERE user_id = from_id;
    UPDATE accounts SET balance = balance + amount WHERE user_id = to_id;
END$$

DELIMITER ;
```

## 15.7 自定义函数

```sql
DELIMITER $$

CREATE FUNCTION calculate_tax(salary DECIMAL(10,2))
RETURNS DECIMAL(10,2)
DETERMINISTIC
READS SQL DATA
BEGIN
    DECLARE tax DECIMAL(10,2);

    IF salary <= 5000 THEN
        SET tax = 0;
    ELSEIF salary <= 10000 THEN
        SET tax = (salary - 5000) * 0.03;
    ELSEIF salary <= 30000 THEN
        SET tax = 5000 * 0.03 + (salary - 10000) * 0.10;
    ELSE
        SET tax = 5000 * 0.03 + 20000 * 0.10 + (salary - 30000) * 0.20;
    END IF;

    RETURN tax;
END$$

DELIMITER ;

-- 使用自定义函数（就像内置函数一样）
SELECT name, salary, calculate_tax(salary) AS tax
FROM employees;
```

## 15.8 存储过程 vs 函数

| 对比项 | 存储过程 | 函数 |
|--------|---------|------|
| 调用方式 | CALL 调用 | 可在SQL语句中使用 |
| 返回值 | 通过OUT参数返回多个值 | 只能RETURN一个值 |
| 参数类型 | IN/OUT/INOUT | 只有IN（默认） |
| SQL中使用 | 不能直接在SELECT中 | 可以在SELECT中直接使用 |
| 副作用 | 可以修改数据（DML） | 通常不应修改数据 |

## 15.9 调用与管理

```sql
-- 调用存储过程
CALL get_employee_count('技术部');

-- 调用函数
SELECT calculate_tax(15000);

-- 查看所有存储过程
SHOW PROCEDURE STATUS WHERE Db = 'your_database';

-- 查看所有函数
SHOW FUNCTION STATUS WHERE Db = 'your_database';

-- 查看存储过程的创建语句
SHOW CREATE PROCEDURE get_employee_count;

-- 删除存储过程
DROP PROCEDURE IF EXISTS get_employee_count;

-- 删除函数
DROP FUNCTION IF EXISTS calculate_tax;
```

## 15.10 优缺点与适用场景

**适合使用存储过程的场景：**

- 复杂的多步业务逻辑（如月结、批量处理）
- 需要减少网络往返的场景（多次SQL合成一次调用）
- 数据迁移和ETL脚本

**不太推荐的场景：**

- 简单CRUD操作（用ORM更方便）
- 需要频繁修改的业务逻辑（存储过程难以版本控制和调试）
- 需要水平扩展的系统（存储过程的计算在数据库端，不易扩展）

> [!WARNING] 注意
> 在现代微服务架构中，很多团队倾向于把业务逻辑放在应用层而不是数据库层。存储过程不是"银弹"，要根据团队技术栈和架构风格来决定是否使用。

## 小结

存储过程和函数让你把常用的SQL逻辑封装成可复用的"数据库程序"。它们有变量、条件判断、循环和异常处理，功能强大。但也要注意不要过度使用——数据库擅长的是数据存储和检索，复杂的业务逻辑放在应用层往往更利于维护和扩展。
