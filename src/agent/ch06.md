## 6.1 Transformer Block：从零件到整机

零件都齐了：Token（第3章）、带位置的语义向量（第4章）、注意力（第5章）。现在把它们组装成一块可复制的积木——Transformer Block。

### 一个 Transformer Block 的完整结构

```
输入 X: (seq_len, d_model)
    │
    ├──── [Multi-Head Self-Attention]
    │           │
    │     [Add & LayerNorm]  ← 残差连接 + 层归一化
    │           │
    ├──── [Feed-Forward Network (FFN)]
    │           │
    │     [Add & LayerNorm]  ← 残差连接 + 层归一化
    │           │
    ▼
输出: (seq_len, d_model)
```

### 残差连接 —— 让信息能"直通"

```python
# 残差连接 (Residual Connection) 的直觉
#
# 没有残差连接:
#   X → MHA → FFN → output
#   如果 MHA 或 FFN 学得不好，信息可能丢失
#
# 有残差连接:
#   X → MHA → + X → FFN → + X → output
#              ↑          ↑
#          残差连接    残差连接
#
# 编程类比: try-catch 中的原始数据备份
#   try:
#       result = transform(data)   # MHA/FFN 尝试处理
#   except:
#       result = data              # 处理失败就保留原始数据
#   残差连接确保: 即使中间层"搞砸了"，原始信息不会丢失

# 层归一化 (Layer Normalization) 的作用
# 对每个 Token 的向量做归一化（均值为0，方差为1）
# 防止深层网络中数值爆炸或消失
# 类比: 每次函数调用后做一次 assert 检查，确保数据在合理范围内
```

**表 6-1｜残差连接前后对比**：

| 对比项 | 无残差连接 | 有残差连接 |
| ------ | ------ | ------ |
| 信息通路 | X → MHA → FFN → output | X → MHA → +X → FFN → +X → output |
| 中间层学坏时 | 信息可能丢失 | 原始信息经直通车道保留 |
| 编程类比 | 无备份的直接变换 | try-catch 中的原始数据备份：处理失败就保留原始数据 |

### Feed-Forward Network —— 注意力之后的"思考"

```python
class FeedForward:
    """
    Feed-Forward Network (FFN)
    
    如果 Attention 是"从其他 Token 收集信息"
    那 FFN 就是"对收集到的信息做深度加工"
    
    结构: Linear(升维) → 激活函数 → Linear(降维)
    
    为什么先升维再降维？
    - 升维到高维空间: 在高维空间中，数据更容易线性可分
    - 激活函数引入非线性: 让模型能学习复杂模式
    - 降维回来: 压缩回原始维度，保留有用的特征
    
    编程类比: 把 JSON 解析成内存对象（升维）→ 处理逻辑（激活函数）→ 序列化回 JSON（降维）
    """
    
    def __init__(self, d_model: int, d_ff: int):
        """
        d_ff 通常是 d_model 的 4 倍
        GPT-2 small: d_model=768, d_ff=3072
        LLaMA: 使用 SwiGLU 激活函数，d_ff ≈ 2.67 × d_model
        """
        self.W1 = np.random.randn(d_model, d_ff) * 0.02  # 升维
        self.W2 = np.random.randn(d_ff, d_model) * 0.02  # 降维
    
    @staticmethod
    def gelu(x: np.ndarray) -> np.ndarray:
        """
        GELU 激活函数 (GPT 系列使用)
        比 ReLU 更平滑，允许微小的负值通过
        
        ReLU: max(0, x) — 简单粗暴，负值直接归零
        GELU: x × Φ(x)  — 负值有概率通过（概率随值增大而增加）
        
        直觉: ReLU 是硬阈值（及格/不及格）
              GELU 是软阈值（接近及格线的有一定概率通过）
        """
        return 0.5 * x * (1 + np.tanh(np.sqrt(2/np.pi) * (x + 0.044715 * x**3)))
    
    @staticmethod
    def silu(x: np.ndarray) -> np.ndarray:
        """
        SiLU/Swish 激活函数: silu(x) = x · sigmoid(x)
        SwiGLU 门控分支使用的激活函数
        """
        return x / (1 + np.exp(-x))

    @staticmethod
    def swiglu(x: np.ndarray, gate: np.ndarray) -> np.ndarray:
        """
        SwiGLU 激活函数 (LLaMA/DeepSeek 使用)

        公式: swiglu(x) = silu(W_gate·x) ⊙ (W_up·x)
        即门控分支用 SiLU/Swish 激活（而不是 sigmoid），再与值分支逐元素相乘

        比 GELU 多了一个"门控"机制
        gate 决定哪些信息可以通过

        编程类比: 像 if-statement 的动态版本
          gate > 0 → 信息通过
          gate < 0 → 信息被抑制
        但 gate 经 SiLU 后是连续值，不是简单的 0/1
        """
        # 门控分支: SiLU/Swish 激活后与值分支逐元素相乘
        return x * silu(gate)
    
    def forward(self, X: np.ndarray) -> np.ndarray:
        """FFN 前向传播: 升维 → 激活 → 降维"""
        hidden = X @ self.W1              # (seq_len, d_ff) — 升维
        activated = self.gelu(hidden)     # (seq_len, d_ff) — 非线性激活
        output = activated @ self.W2      # (seq_len, d_model) — 降维
        return output


# 参数量计算
d_model = 768
d_ff = 3072  # 4 × d_model

ffn_params = d_model * d_ff + d_ff * d_model
mha_params = 4 * d_model * d_model  # 近似值

print(f"=== 一个 Transformer Block 的参数量 (GPT-2 small) ===")
print(f"MHA 参数: {mha_params:,} ({mha_params/1e6:.1f}M)")
print(f"FFN 参数: {ffn_params:,} ({ffn_params/1e6:.1f}M)")
print(f"总计:     {mha_params + ffn_params:,} ({(mha_params + ffn_params)/1e6:.1f}M)")
print()
print(f"→ FFN 的参数约占总参数的 2/3")
print(f"→ 这就是为什么有人说 Transformer 的大部分'知识'存在 FFN 里")
```

### 完整的 Transformer（Decoder-Only 架构）

注意力负责"收集信息"，FFN 负责"深度加工"，残差与 LayerNorm 负责稳定——把它们按 N 层堆起来，接上输出投影，就是一个完整的 Decoder-Only 模型（下面代码复用第5章的 MultiHeadSelfAttention、softmax，以及本节上面的 FeedForward）：

```python
class TransformerDecoder:
    """
    简化版 Decoder-Only Transformer (GPT/LLaMA/DeepSeek 架构)
    
    完整的处理流程:
    
    1. Token Embedding + 位置编码 → 初始表示
    2. 通过 N 个 Transformer Block (每个Block = MHA + FFN + 残差 + LayerNorm)
    3. 最终的 Layer Normalization
    4. 输出投影 (Language Model Head): 映射回词汇表大小的 logits
    5. Softmax → 下一个 Token 的概率分布
    """
    
    def __init__(self, vocab_size, d_model, num_heads, num_layers, d_ff):
        self.vocab_size = vocab_size
        self.d_model = d_model
        self.num_layers = num_layers
        
        # Embedding 层
        self.token_embedding = np.random.randn(vocab_size, d_model) * 0.02
        
        # N 个 Transformer Block
        self.blocks = []
        for _ in range(num_layers):
            block = {
                'mha': MultiHeadSelfAttention(d_model, num_heads),
                'ffn': FeedForward(d_model, d_ff),
            }
            self.blocks.append(block)
        
        # 输出投影: d_model → vocab_size
        self.lm_head = np.random.randn(d_model, vocab_size) * 0.02
    
    def forward(self, token_ids: list) -> np.ndarray:
        """
        完整前向传播
        
        Args:
            token_ids: Token ID 列表, 如 [15496, 2159, 739]
        
        Returns:
            logits: 每个位置对词汇表中每个 Token 的预测分数
                    shape = (seq_len, vocab_size)
        """
        seq_len = len(token_ids)
        
        # Step 1: Token Embedding
        X = self.token_embedding[token_ids]  # (seq_len, d_model)
        
        # Step 2: 通过 N 个 Transformer Block
        for block in self.blocks:
            # Multi-Head Self-Attention (带残差连接)
            attn_out = block['mha'].forward(X, causal=True)
            X = X + attn_out  # 残差连接
            # (省略 LayerNorm 的简化)
            
            # Feed-Forward Network (带残差连接)
            ffn_out = block['ffn'].forward(X)
            X = X + ffn_out  # 残差连接
            # (省略 LayerNorm 的简化)
        
        # Step 3: 输出投影
        # 每个位置的 d_model 维向量 → vocab_size 维的 logits
        logits = X @ self.lm_head  # (seq_len, vocab_size)
        
        return logits
    
    def generate(self, prompt_ids: list, max_new_tokens: int, temperature: float = 1.0) -> list:
        """
        自回归生成: 逐步生成新 Token
        
        每次把已有 Token 送入模型，取最后一个位置的输出
        选择概率最高的 Token，追加到序列中，重复
        
        这就是"自回归"的含义 — 自己的输出变成自己的输入
        """
        generated = list(prompt_ids)
        
        for _ in range(max_new_tokens):
            # 前向传播（所有 Token）
            logits = self.forward(generated)
            
            # 取最后一个位置的 logits（预测下一个 Token）
            next_logits = logits[-1] / temperature
            
            # Softmax → 概率分布
            probs = softmax(next_logits.reshape(1, -1))[0]
            
            # 采样（实际实现中有 Top-k / Top-p 等策略）
            next_token = np.random.choice(len(probs), p=probs)
            
            generated.append(next_token)
        
        return generated
```

从 GPT-2 Small 到 DeepSeek V3 都长一个样，只是积木数不同——最后一行的 DeepSeek V3 采用 MoE（Mixture of Experts，混合专家）架构：单个专家的 FFN 维度较小，总容量分散在大量专家中，每个 Token 只激活其中一部分（37B active）。

| 模型 | d_model | 层数 | 注意力头数 | FFN/专家 | 词表大小 | 总参数 |
| ------ | ------ | ------ | ------ | ------ | ------ | ------ |
| GPT-2 Small | 768 | 12 | 12 | 3072 | 50,257 | 117M |
| LLaMA 2 7B | 4096 | 32 | 32 | 11,008 | 32,000 | 6.7B |
| LLaMA 3 70B | 8192 | 80 | 64 | 28,672 | 128,256 | 70B |

模型变大主要体现在：d_model 增大、层数增多、词汇表扩大；但每个 Transformer Block 的结构完全相同——**"大模型"本质上是"同一个积木搭了更多层"**。

## 6.2 从 Transformer 到 Agent——这些知识怎么影响你

原理篇四章到此闭环。把一句话送进模型的完整旅程连起来看：

```text
"AI Agent is powerful"
    │ 第3章 Tokenization（BPE）: [3081, 15891, 318, 4762]
    │ 第4章 Embedding + 位置编码: 每个 Token → 768 维向量（语义 + 位置）
    │ 第5-6章 Transformer Block × N（重复 N 次）:
    │     Multi-Head Attention → Add & LayerNorm → FFN → Add & LayerNorm
    │ 第6章 输出投影 → Softmax + 采样: 下一个 Token "!"（概率 0.73）
    ▼ 自回归: 把 "AI Agent is powerful!" 送回模型，预测下一个 Token……
```

接下来回答最初的问题：这些知识怎么影响你写 Agent？三个最直接的现实约束：

### 上下文窗口是硬约束，不是软限制

```
上下文窗口 = 模型一次能处理的最大 Token 数

GPT-4o:       128K tokens ≈ 10 万个英文单词 ≈ 300 页书
DeepSeek V3:  128K tokens
Llama 3:      8K tokens（128K 为 Llama 3.1）
Claude 4:     200K tokens

但这不是"能读多少"的问题，而是注意力机制的物理约束:
- Attention 的计算复杂度 = O(n²)（n = Token 数）
- n 越大，计算量平方级增长
- 128K Token 的注意力矩阵 = 128000 × 128000 = 163 亿个浮点数
- 这不是软件限制，是硬件和数学的限制
```

**对 Agent 的影响**：当你的 Agent 需要处理长文档时，你不能把整篇文档塞进 Prompt。这就是为什么 RAG（Retrieval-Augmented Generation，检索增强生成）存在——**先检索最相关的片段，只把这些片段送进模型**。

### Lost-in-the-Middle —— Agent 的"注意力盲区"

```python
"""
实验证明: Transformer 对 Prompt 开头和结尾的信息关注度最高，中间的信息容易被"遗忘"

注意力分布示意 (128K context 中):

  注意力强度
  ▲
  │██                                    ██
  │██                                  ████
  │████                              ██████
  │██████                          ████████
  │████████                      ██████████
  │██████████░░░░░░░░░░░░░░░░░░░████████████
  │████████████░░░░░░░░░░░░░░░██████████████
  └─────────────────────────────────────────────→ 位置
   开头           中间（盲区）           结尾

原因:
1. 开头: 所有 Token 都关注 System Prompt（它是全局上下文）
2. 结尾: 最近的 Token 有更高的注意力权重（recency bias）
3. 中间: 距离开头远、距离结尾也远，两面不讨好
"""
```

**表 6-3｜绕开注意力盲区的 Prompt 排布原则**：

| 原则 | 做法 |
| ------ | ------ |
| 把关键指令放在开头 | System Prompt 中的核心规则放最前面 |
| 把检索结果放在靠近结尾的位置 | RAG 检索到的文档片段放在用户消息末尾 |
| 避免把关键信息埋在中间 | 如果检索了 10 个片段，最重要的排第 1 和第 10 |
| 使用结构化标记 | 用 XML 标签或 markdown 标题帮助模型定位关键段落 |

### KV Cache —— Agent 流式输出的秘密

```python
"""
自回归生成的性能问题:

生成第 1 个 Token: 处理 prompt 的全部 Token → 预测
生成第 2 个 Token: 处理 prompt + 第1个新Token → 预测
生成第 3 个 Token: 处理 prompt + 前2个新Token → 预测
...

问题: 每次生成都要重新处理 prompt 部分（大量重复计算）

解决方案: KV Cache
- 第一次处理 prompt 时，缓存每个 Transformer 层的 K 和 V 矩阵
- 后续生成新 Token 时，只需要计算新 Token 的 Q，和缓存的 K/V 做 Attention
- 计算量从 O(n) 降到 O(1)（每个新 Token）

类比: 就像数据库的连接池
- 没有 KV Cache: 每次查询都重新建立数据库连接（慢）
- 有 KV Cache: 复用已有连接，只执行新查询（快）
"""
```

**表 6-4｜KV Cache 解释的四个日常现象**：

| 现象 | 原因 |
| ------ | ------ |
| 流式输出第一个 Token 之后很快 | 第一个 Token 慢（要处理整个 Prompt），后续 Token 快（有 KV Cache） |
| 长 Prompt 首个 Token 特别慢 | Prompt 越长，首次计算的 K/V 矩阵越大 |
| 重复前缀可以省钱 | 很多 API 支持 Prompt Caching，相同前缀复用 KV Cache |
| Agent 多轮对话越来越慢 | 每轮对话累积更多 Token，KV Cache 越来越大 |

这就是为什么 Agent 架构中 Memory 管理如此重要：不是"记住越多越好"，而是"每多一个 Token 的上下文，就多一份计算成本"。好的 Agent 会：

1. 定期摘要压缩对话历史（减少上下文长度）
2. 只检索最相关的记忆（精准而非全面）
3. 使用滑动窗口限制上下文大小

### 温度（Temperature）和 Agent 的确定性

```python
"""
Temperature 从 Transformer 的视角理解:

LLM 的最后一步: logits → softmax → 概率 → 采样

logits = 模型输出的原始分数（未归一化）
softmax(logits / temperature) = 最终的概率分布

temperature = 0.0 → argmax（永远选概率最高的 Token）→ 完全确定性
temperature = 0.5 → 概率分布变"尖锐"（高概率更高，低概率更低）→ 偏确定性
temperature = 1.0 → 原始概率分布 → 模型"自然"输出
temperature = 2.0 → 概率分布变"平坦"（低概率的也有机会被选中）→ 偏随机性
"""

import numpy as np

def demonstrate_temperature():
    """可视化 Temperature 对概率分布的影响"""
    
    # 假设模型对 5 个候选 Token 的 logits
    logits = np.array([5.0, 3.0, 1.0, 0.5, 0.1])
    
    temperatures = [0.1, 0.5, 1.0, 2.0]
    
    print("=== Temperature 对 Token 选择的影响 ===\n")
    print(f"{'Token':>6}", end="")
    for t in temperatures:
        print(f"  T={t:.1f}", end="")
    print()
    print("-" * 40)
    
    for i in range(5):
        print(f"  Tok{i+1}", end="")
        for t in temperatures:
            probs = softmax((logits / t).reshape(1, -1))[0]
            print(f"  {probs[i]:.3f}", end="")
        print()
    
    print()
    print("T=0.1: Token1 概率≈1.000，几乎确定选它")
    print("T=2.0: Token1 概率≈0.590，其他 Token 也有机会")
    print()
    print("→ Agent 工具调用建议 T=0.0~0.2（需要确定性）")
    print("→ Agent 创意写作建议 T=0.7~1.0（需要多样性）")

demonstrate_temperature()
```

## 本章小结

- Transformer Block = Multi-Head Attention + Add & LayerNorm + FFN + Add & LayerNorm，所有主流模型都是这块积木的堆叠
- 残差连接（Residual Connection）给信息留了直通车道：中间层学砸了，原始信息也不丢
- FFN 先升维再降维（d_ff 约为 d_model 的 4 倍，LLaMA 用 SwiGLU），参数约占 2/3——"知识"多半存在 FFN 里
- 大模型 = 同一块积木搭更多层：GPT-2 Small 117M 到 DeepSeek V3 671B（37B active），结构完全相同
- 上下文窗口是注意力的物理约束：计算复杂度 O(n²)，128K Token 的注意力矩阵 = 128000² = 163 亿个浮点数
- Lost-in-the-Middle 是真实问题：关键指令放开头、检索片段放靠近结尾处，别埋在中间
- KV Cache 是性能关键：首个 Token 慢在处理整个 Prompt，之后靠缓存加速；Prompt Caching 省钱也靠它
- Temperature 是确定性的旋钮：工具调用 T=0.0-0.2，创意写作 T=0.7-1.0
