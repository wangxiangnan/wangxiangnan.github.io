# 第18章：复杂滤镜链实战

经过前 5 章的学习，你已经掌握了 FFmpeg 滤镜系统的各种"招式"——调色、降噪、叠加、合成、转场、特效。但真正的高手不只是会单个招式，而是能把它们**流畅地组合**成一套"连招"。本章将通过 4 个实战项目，教你如何设计和构建复杂的滤镜链，同时分享性能优化和调试的实战技巧。

## 18.1 复杂滤镜图全面讲解

在开始实战之前，让我们系统性地回顾 `-filter_complex` 的核心概念。

### 基本结构

```
-filter_complex "
  [输入流]滤镜1[中间流1];
  [中间流1]滤镜2[中间流2];
  ...
  [中间流N]滤镜M[输出流]
"
```

关键点：

1. **分号 `;`** 分隔不同的滤镜节点
2. **方括号 `[...]`** 中的是流标签，用于在节点之间传递数据
3. **输入标签**在滤镜前面，**输出标签**在滤镜后面
4. 标签名可以自定义（如 `[main]`、`[logo]`、`[vout]`），只要不重复

### 隐式 split

当你多次引用同一个流时，FFmpeg 会自动 `split`：

```bash
# [0:v] 被引用了两次，FFmpeg 自动 split
-filter_complex "[0:v]eq=brightness=0.1[bright];[0:v]eq=brightness=-0.1[dark]"
```

但为了可读性和明确性，建议显式使用 `split`：

```bash
-filter_complex "[0:v]split[bright_input][dark_input];[bright_input]eq=brightness=0.1[bright];[dark_input]eq=brightness=-0.1[dark]"
```

## 18.2 滤镜图的"流程图"思维

复杂滤镜链容易让人迷失，特别是当滤镜节点超过 5 个时。一个有效的思维工具是**画流程图**：

```
以"画中画 + 水印 + 背景音乐"为例：

[0:v] main video
   │
   ▼
[scale] → [main]
                      [1:v] pip video
                         │
                         ▼
                      [scale] → [pip_scaled]
                                    │
[main] + [pip_scaled] ──────────────┘
   │
   ▼
[overlay] → [with_pip]
                        [2:v] logo.png
                           │
                           ▼
                        [format=rgba] → [logo]
                                          │
[with_pip] + [logo] ─────────────────────┘
   │
   ▼
[overlay] → [final_video]

[0:a] original audio
   │
   ▼
[volume] → [voice]

[3:a] bgm.mp3
   │
   ▼
[volume=0.3] → [bgm_quiet]

[voice] + [bgm_quiet]
   │
   ▼
[amix] → [final_audio]
```

在写命令之前先画这样的流程图，会大大降低出错概率。

## 18.3 实战1：画中画 + 水印 + 字幕一步到位

**需求**：主视频右下角叠加一个小视频窗口，左上角有半透明 Logo 水印，底部有字幕条。

```bash
ffmpeg -i main.mp4 -i pip.mp4 -i logo.png \
  -filter_complex "\
    [0:v]scale=1920:1080[main];\
    [1:v]scale=400:225[pip];\
    [main][pip]overlay=W-w-20:H-h-20:shortest=1[with_pip];\
    [2:v]format=rgba,colorchannelmixer=aa=0.7[logo];\
    [with_pip][logo]overlay=20:20[with_logo];\
    [with_logo]drawbox=x=0:y=ih-80:w=iw:h=80:color=black@0.5:t=fill,\
    drawtext=text='欢迎来到 FFmpeg 进阶课堂':fontsize=32:fontcolor=white:x=(w-tw)/2:y=h-60" \
  -c:v libx264 -preset medium -crf 20 -c:a copy \
  output.mp4
```

**拆解分析**：

1. **缩放主视频**：`[0:v]scale=1920:1080[main]`
2. **缩放画中画**：`[1:v]scale=400:225[pip]`
3. **叠加画中画**：`[main][pip]overlay=W-w-20:H-h-20`（右下角，20px 边距）
4. **处理 Logo 透明度**：`format=rgba,colorchannelmixer=aa=0.7`（70% 不透明）
5. **叠加 Logo**：`[with_pip][logo]overlay=20:20`（左上角）
6. **绘制字幕条**：`drawbox` 画半透明黑色矩形 + `drawtext` 添加文字

## 18.4 实战2：多输入源合成（背景音乐 + 解说 + 视频）

**需求**：一个教学视频，包含原始视频画面、解说音频、背景音乐，背景音乐音量要低于解说。

```bash
ffmpeg -i lecture_video.mp4 -i narration.mp3 -i bgm.mp3 \
  -filter_complex "\
    [0:v]scale=1920:1080,format=yuv420p[video];\
    [1:a]volume=1.0,alimiter=limit=0.95[voice];\
    [2:a]volume=0.15,afade=t=in:st=0:d=2,afade=t=out:st=580:d=5[bgm];\
    [voice][bgm]amix=inputs=2:duration=first:dropout_transition=3[audio]" \
  -map "[video]" -map "[audio]" \
  -c:v libx264 -preset medium -crf 22 -c:a aac -b:a 192k \
  output.mp4
```

**关键设计决策**：

- `volume=0.15`：背景音乐降到 15%，确保解说清晰可闻
- `afade=t=in:d=2`：背景音乐开头 2 秒淡入，避免突兀
- `afade=t=out:st=580:d=5`：结尾 5 秒淡出（假设总长 585 秒左右）
- `alimiter=limit=0.95`：防止解说音量过高导致削波
- `amix=duration=first`：输出长度以解说音频为准
- `dropout_transition=3`：如果背景音乐比解说短，3 秒内平滑过渡

## 18.5 实战3：视频拼接 + 转场效果

**需求**：将 4 段旅行视频拼接成一段 Vlog，每段之间使用不同的转场效果。

假设 4 段视频每段 10 秒，转场 1.5 秒：

```bash
ffmpeg -i clip1.mp4 -i clip2.mp4 -i clip3.mp4 -i clip4.mp4 \
  -filter_complex "\
    [0:v]scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=30[v0];\
    [1:v]scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=30[v1];\
    [2:v]scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=30[v2];\
    [3:v]scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=30[v3];\
    [v0][v1]xfade=transition=fade:duration=1.5:offset=8.5[t01];\
    [t01][v2]xfade=transition=wiperight:duration=1.5:offset=17[t012];\
    [t012][v3]xfade=transition=circlecrop:duration=1.5:offset=25.5[vout];\
    [0:a][1:a]acrossfade=d=1.5[a01];\
    [a01][2:a]acrossfade=d=1.5[a012];\
    [a012][3:a]acrossfade=d=1.5[aout]" \
  -map "[vout]" -map "[aout]" \
  -c:v libx264 -preset medium -crf 20 -c:a aac -b:a 192k \
  output.mp4
```

**offset 计算**（每段 10 秒，转场 1.5 秒）：

- 第 1 个转场：`offset = 10 - 1.5 = 8.5`
- 第 2 个转场：`offset = 10 + 10 - 2×1.5 = 17`
- 第 3 个转场：`offset = 10 + 10 + 10 - 3×1.5 = 25.5`

**统一输入的技巧**：注意每个输入都先做了 `scale` + `pad` + `setsar` + `fps` 处理。这是因为 `xfade` 要求两个输入的分辨率、帧率和像素格式完全一致。

## 18.6 实战4：制作短视频片头（图片 + 文字动画 + 音乐）

**需求**：用一张背景图 + Logo + 标题文字 + 背景音乐制作 5 秒的片头动画。

```bash
ffmpeg -loop 1 -t 5 -i bg.jpg -i logo.png -i title_music.mp3 \
  -filter_complex "\
    [0:v]scale=1920:1080,zoompan=z='min(zoom+0.001,1.1)':x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':d=150:s=1920x1080:fps=30[bg];\
    [1:v]scale=200:-1,format=rgba,\
    fade=t=in:st=0:d=1:alpha=1[logo];\
    [bg][logo]overlay=(W-w)/2:(H-h)/2-100[v1];\
    [v1]drawtext=text='我的频道':fontsize=72:fontcolor=white:\
    x=(w-tw)/2:y=(h+th)/2+50:\
    alpha='if(lt(t,1),0,if(lt(t,2),(t-1),1))':\
    shadowcolor=black:shadowx=2:shadowy=2,\
    fade=t=out:st=4:d=1" \
  -i title_music.mp3 -t 5 \
  -map 0:v_unused -map 2:a \
  -c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p \
  -c:a aac -b:a 192k -shortest \
  intro.mp4
```

> 这个命令比较复杂，实际使用中建议分步制作——先用 `color` 或简单图片测试滤镜链，确认效果后再用正式素材。

**效果拆解**：

1. **背景缓慢放大**（Ken Burns 效果）：`zoompan=z='min(zoom+0.001,1.1)'`
2. **Logo 淡入**：`fade=t=in:st=0:d=1:alpha=1`（1 秒内 Alpha 通道从 0 到 1）
3. **文字延迟出现**：`alpha='if(lt(t,1),0,if(lt(t,2),(t-1),1))'`（第 1 秒前不可见，1-2 秒淡入）
4. **整体淡出**：`fade=t=out:st=4:d=1`（最后 1 秒画面渐黑）

## 18.7 滤镜链的性能优化

复杂滤镜链可能导致处理时间急剧增长。以下是关键的优化策略：

### 1. 尽早降低分辨率

```bash
# 不好：在 4K 上做降噪，然后再缩放到 1080p
[0:v]nlmeans=...,scale=1920:1080

# 好：先缩放到 1080p，再做降噪
[0:v]scale=1920:1080,nlmeans=...
```

处理像素数减少到 1/4，降噪速度提升约 4 倍。

### 2. 避免不必要的格式转换

```bash
# 不好：多次格式转换
[0:v]format=rgb24,eq=...,format=yuv420p,format=rgb24,curves=...

# 好：尽量减少格式转换次数
[0:v]format=rgb24,eq=...,curves=...,format=yuv420p
```

### 3. 善用 split 避免重复计算

```bash
# 不好：两次读取和解码原始视频
[0:v]scale=1280:720[scaled];[0:v]scale=640:360[thumb]

# 好：先缩放一次，再从缩放后的流继续
[0:v]scale=1280:720[scaled];[scaled]scale=640:360[thumb]
```

### 4. 选择合适的编码参数

```bash
# 快速预览（编码快，质量低）
-c:v libx264 -preset ultrafast -crf 28

# 正式发布（编码慢，质量高）
-c:v libx264 -preset slow -crf 18
```

### 5. 利用硬件加速

```bash
# 使用 NVIDIA GPU 加速编码
-c:v h264_nvenc -preset p4 -cq 22

# 使用 AMD GPU 加速
-c:v h264_amf -quality balanced
```

## 18.8 split 和 asplit：流的复制与分发

当一条流需要被多个滤镜使用时，需要 `split`（视频）或 `asplit`（音频）：

```bash
# 将一个视频流分成两份，分别做不同处理
ffmpeg -i input.mp4 \
  -filter_complex "\
    [0:v]split[original][processed];\
    [processed]eq=saturation=0[bw];\
    [original][bw]hstack=inputs=2" \
  output.mp4
```

这个命令将原始视频和黑白版本左右对比——非常实用的"before/after"效果。

```bash
# 音频 split：将原始音频同时送到响度分析和输出
ffmpeg -i input.mp4 \
  -filter_complex "\
    [0:a]asplit[for_output][for_analysis];\
    [for_analysis]ebur128" \
  -map "[for_output]" output.mp4
```

## 18.9 滤镜链调试技巧

### 1. 逐步构建法

永远不要一次写完一个包含 10 个节点的滤镜链然后直接运行。正确的做法是：

```bash
# Step 1: 只测试第一个节点
ffmpeg -i input.mp4 -filter_complex "[0:v]scale=1920:1080[v]" -map "[v]" step1.mp4

# Step 2: 加入第二个节点
ffmpeg -i input.mp4 -filter_complex "\
  [0:v]scale=1920:1080[v];\
  [v]eq=brightness=0.05[v2]" -map "[v2]" step2.mp4

# Step 3: 加入第三个节点
# ... 以此类推
```

### 2. 检查中间结果

在复杂滤镜图中，随时"截取"中间流来检查：

```bash
# 不看最终结果，只看中间某一步的输出
ffmpeg -i input.mp4 -i logo.png \
  -filter_complex "\
    [0:v]scale=1280:720[scaled];\
    [1:v]format=rgba[logo_rgba]" \
  -map "[scaled]" check_scaled.mp4 \
  -map "[logo_rgba]" check_logo.png
```

### 3. 利用 ffplay 实时调试

```bash
# 用 ffplay 实时预览复杂滤镜图
ffplay -i input.mp4 -i logo.png \
  -filter_complex "[0:v][1:v]overlay=W-w-10:10"

# 调整参数后按 'c' 重新加载（或关闭后重新运行）
```

### 4. 常见错误排查

| 错误信息 | 原因 | 解决方案 |
| --------- | ------ | --------- |
| `Invalid file index` | 输入文件索引超出范围 | 检查 `-i` 参数数量和索引 |
| `Filter has an unconnected output` | 有输出流没有被映射 | 添加 `-map` 或确保所有输出都被使用 |
| `Input pixel format mismatch` | 输入像素格式不匹配 | 在滤镜前加 `format=yuv420p` |
| `First input is not a video stream` | 第一个输入不是视频 | 检查流标签是否正确（`[0:v]` vs `[0:a]`） |

## 18.10 滤镜链设计思路：从需求到实现

面对一个复杂的视频处理需求，建议按照以下流程设计：

1. **明确输入和输出**：有几个输入文件？每个文件的哪些流需要处理？最终输出是什么？
2. **画流程图**：在纸上或文本中画出数据流向，标注每个节点
3. **统一输入规格**：确保所有输入的分辨率、帧率、像素格式一致（如需要）
4. **逐个实现节点**：从流程图的最上游开始，逐个添加滤镜节点
5. **测试每个节点**：每加一个节点就测试一次
6. **优化性能**：检查是否有可以提前缩放、减少格式转换的地方
7. **最终整合**：添加编码参数，进行最终输出

```
设计模板：

输入文件：
  [0] main_video.mp4 → 视频流 [0:v] + 音频流 [0:a]
  [1] overlay.mp4    → 视频流 [1:v]
  [2] bgm.mp3        → 音频流 [2:a]

处理流程：
  视频：[0:v] → scale → [main] → overlay with [1:v] → [vout]
  音频：[0:a] + [2:a](volume=0.2) → amix → [aout]

输出：
  -map [vout] -map [aout]
```
