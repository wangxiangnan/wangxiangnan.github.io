# 第十三章：类型体操入门——映射类型、条件类型与 infer

所谓"类型体操"，是指用 TypeScript 类型系统编写复杂的类型操作。它听起来很吓人，但其实只是前面知识的组合运用。

## 映射类型

映射类型可以根据一个已有类型生成新类型：

```ts
type Readonly<T> = {
  readonly [P in keyof T]: T[P];
};

type Partial<T> = {
  [P in keyof T]?: T[P];
};
```

TypeScript 内置了很多映射类型工具：`Partial<T>`、`Required<T>`、`Readonly<T>`、`Record<K, T>`、`Pick<T, K>`、`Omit<T, K>`、`Exclude<T, U>`、`Extract<T, U>`、`NonNullable<T>`、`ReturnType<T>`、`Parameters<T>` 等。

熟练使用这些工具类型，可以大幅减少重复的类型定义。

## 条件类型

条件类型类似三元表达式：

```ts
type IsString<T> = T extends string ? true : false;

type A = IsString<"hello">; // true
type B = IsString<123>;     // false
```

`extends` 在条件类型中表示"是否是……的子类型"。

### 分发行为

条件类型作用在"裸类型参数"上时会自动分发：

```ts
type ToArray<T> = T extends any ? T[] : never;

type X = ToArray<string | number>; // string[] | number[]
```

联合类型被拆开、逐个判断、再合并。多数时候这正是想要的行为，但有两个副作用要记住：

- 想整体判断、不分发，把两边都套上元组：`[T] extends [any] ? ... : ...`。
- `never` 会在分发中"消失"：`ToArray<never>` 的结果是 `never`，而不是 `never[]`。

## infer

`infer` 用于在条件类型中推断类型：

```ts
type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

function greet() {
  return "hello";
}

type GreetReturn = ReturnType<typeof greet>; // string
```

`infer R` 会捕获函数返回值的类型。

## 模板字面量类型

类型层面也能拼接字符串，写法仿照 JS 的模板字符串：

```ts
type Greeting = `hello ${string}`;

type EventName<T extends string> = `on${Capitalize<T>}`;

type OnClick = EventName<"click">; // "onClick"
type OnBlur = EventName<"blur">;   // "onBlur"
```

配合内置的 `Uppercase`、`Lowercase`、`Capitalize`、`Uncapitalize` 四个字符串工具类型，可以在类型层面变换字符串。适合约束路由路径、事件名、CSS 属性这类"字符串有固定套路"的场景。

## 一个实用例子：DeepReadonly

```ts
type DeepReadonly<T> = {
  readonly [P in keyof T]: T[P] extends object ? DeepReadonly<T[P]> : T[P];
};
```

这个类型会把对象的所有层级都变成只读。

## 类型体操的边界

类型体操很强大，但不要为了炫技而滥用。一个项目的类型定义应该服务于业务逻辑，而不是反过来。如果你写出的类型比业务代码还难懂，那就过头了。

好的类型设计是：**让正确的事情容易做，让错误的事情难做**。
