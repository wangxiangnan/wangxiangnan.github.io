# 第1章：OpenSSL 全景：一个工具箱的三副面孔

> [!TIP] Part 1: 工具箱入门篇（地基篇）
> 开篇第一章。先搞清楚 OpenSSL 到底是什么、装哪一版、怎么查帮助——工具箱的构造摸清了，后面十三章的每一条命令才放得进正确的抽屉。

《Git 与 SSH 完全教程》结束时的云笔记已经 push 即部署，但第三幕的麻烦马上来了：日活涨到 300，每周要从服务器导出 200MB 用户数据备份到云对象存储。王哥（本书设定中云笔记的另一位同事）提了两个问题，一个比一个扎心：这份数据放在云上，别人能不能看？备份文件损坏了，我们两周后才发现——怎么知道它没坏？这两个问题的答案分别是「加密」与「哈希」，而干这两件事的头号工具，就是你大概率已经听过一万次、却很少真正用明白的 OpenSSL。

## 1.1 OpenSSL 到底是什么

大多数人对 OpenSSL 的印象是「一个命令行工具」。这个印象只对了三分之一。完整的 OpenSSL 是三样东西的合体：

| 面孔 | 是什么 | 谁在用 | 本书怎么用 |
| ---- | ---- | ---- | ---- |
| libcrypto | 密码学算法库：哈希、加密、签名、随机数的全部原语 | 几乎所有语言的标准库底层 | 不直接调用，但你在用 Python、Go 写加密代码时，底下多半是它 |
| libssl | TLS 协议实现：负责把明文通道变成加密通道 | nginx、curl、OpenSSH | 不直接调用，第12-13章调试的每一个 TLS 连接背后都是它 |
| openssl CLI | 命令行工具：把库里的能力暴露成几百个子命令 | 运维、开发、你我 | **本书的主战场** |

```text
┌─────────────────────────────────────────────┐
│              openssl 命令行（CLI）            │  ← 本书主战场
├──────────────────────┬──────────────────────┤
│  libssl（TLS 协议）   │  libcrypto（密码学库） │  ← 底层引擎
├──────────────────────┴──────────────────────┤
│  操作系统的随机数源 / 文件系统 / 网络            │
└─────────────────────────────────────────────┘
```

「谁在用它」这张名单值得看一眼，因为它解释了为什么这门手艺值得学：nginx 的 HTTPS、curl 拉取依赖、Python 的 `ssl` 模块、OpenSSH 的加密底座、各发行版的系统证书库——全互联网的加密流量里，相当一部分在链路的某一端经过 OpenSSL。2014 年的 Heartbleed 漏洞之所以震动整个行业，正是因为它在 libcrypto 这个「地基」上砸出一个洞，全球数十万台服务器同时暴露私钥。学 OpenSSL 不是学一个工具，是学互联网信任体系的地基怎么施工。

顺手把简史扫一眼，几个里程碑年份在后续章节还会遇到：

| 年份 | 事件 | 对本书的意义 |
| ---- | ---- | ---- |
| 1998 | OpenSSL 从 SSLeay 分支诞生 | 老古董命令写法的源头 |
| 2014 | Heartbleed 漏洞曝光 | 行业开始重视开源安全的「公共品困境」 |
| 2015 | LibreSSL 从 OpenSSL 分叉 | macOS 自带版差异的由来（1.2 节） |
| 2021 | OpenSSL 3.0 发布 | providers 架构与命令代际分界线 |
| 2023 | 1.1.1 停止维护 | 网上老教程与 3.x 行为不一致的根源 |

## 1.2 安装与版本

OpenSSL 的安装政策是「大多数时候你已经有了」：

| 平台 | 现状 | 建议动作 |
| ---- | ---- | ---- |
| Linux（Ubuntu/Debian） | 系统自带 3.x | 直接用，无需安装 |
| Linux（CentOS/RHEL） | 系统自带 | 直接用 |
| macOS | 自带的 `/usr/bin/openssl` 是 **LibreSSL** 分支 | `brew install openssl@3`，并把它放进 PATH |
| Windows | Git Bash 自带一份 | 用 Git Bash，别用 CMD |

macOS 那一行是全书第一个坑，单独展开。当年 OpenSSL 版权与维护策略的分歧让苹果改用了社区分支 LibreSSL——它兼容大部分日常命令，但输出格式、个别参数行为与 OpenSSL 有差异。判断自己用的是哪家，一条命令：

```text
$ openssl version
LibreSSL 3.3.6
```

看到 `LibreSSL` 就说明是苹果自带的那份，本书后续的部分输出会和你机器上的不一样。修复方式：

```bash
brew install openssl@3
echo 'export PATH="/opt/homebrew/opt/openssl@3/bin:$PATH"' >> ~/.zshrc
exec zsh
```

再跑 `openssl version`，应该看到 `OpenSSL 3.x.x`。Windows 用户在 Git Bash 里敲同一条命令，通常直接是 `OpenSSL 3.x.x`。

一个容易被忽略的细节：**PATH 优先级决定你用的是哪一份**。如果系统里同时存在多份 OpenSSL（比如 macOS 的 LibreSSL 与 brew 装的新版），shell 沿 PATH 从前到后找第一个匹配的。验证与排查两连：

```bash
which -a openssl        # 列出 PATH 上所有的 openssl
openssl version -a      # -a 额外显示编译参数与 OPENSSLDIR 等细节
```

`version -a` 输出里的 `OPENSSLDIR` 值得一记——它是 OpenSSL 找默认配置与系统证书库的位置（Linux 上通常是 `/usr/lib/ssl` 或 `/etc/ssl`），第11章配置信任库时会和它打交道。

版本数字的含义：

- **3.x**：现行主线。本书所有示例基于 3.x，3.0、3.3、3.5 各代均可。
- **1.1.1**：2023 年 9 月已停止维护，遇到它建议升级系统，而不是凑合用。
- **0.9.x / 1.0.x**：远古版本，只会在老系统考古时遇到，本书不覆盖。

> [!WARNING] 版本先于一切
> 密码学工具的行为随版本演进变化很大：同一份教程命令，在 1.1.1 与 3.x 上可能输出不同、甚至参数不同。**每次排错前先跑 `openssl version`**——这是第14章排错手册的第一条军规。实在无法升级环境时，可以用 Docker 兜底：`docker run --rm -it -v "$PWD:/work" -w /work debian:stable-slim bash`，进容器 `apt-get update && apt-get install -y openssl`，得到一个干净的 3.x 环境。

## 1.3 子命令地图与 help 体系

OpenSSL CLI 的结构是「一个入口，几百个子命令」：`openssl 子命令 参数`。子命令家族的全貌用一条命令看：

```text
$ openssl list -commands
asn1parse      ca            ciphers       cmp
crl            crl2pkcs7     dgst          dhparam
dsa            dsaparam      ec            ecparam
enc            engine        errstr        fipsinstall
gendsa         genpkey       genrsa        info
kdf            mac           nseq          ocsp
passwd         pkcs12        pkcs7         pkcs8
pkey           pkeyparam     pkeyutl       prime
rand           rehash        req           rsa
rsautl         s_client      s_server      s_time
sess_id        smime         speed         spkac
srp            storeutl      ts            verify
version        x509
```

四十多个子命令一次看到难免眼晕，但按任务分组后（ch00 的命令地图），日常高频使用的其实只有十个左右：`dgst`、`enc`、`rand`、`passwd`、`genpkey`、`pkey`、`req`、`x509`、`verify`、`s_client`。本书将带你在真实场景里逐个解锁。

`list` 家族还能继续下钻，查某类算法的可用名单——这在你对接陌生环境、想确认「这台机器支不支持某算法」时特别有用：

```bash
openssl list -cipher-algorithms | head -8
openssl list -signature-algorithms | head -8
```

```text
{ 2.16.840.1.101.3.4.1.2, AES-128-CBC } @ default
{ 2.16.840.1.101.3.4.1.42, AES-256-CBC } @ default
...
ED25519 @ default
ECDSA @ default
RSA @ default
```

行尾的 `@ default` 表示该算法由 default 提供者提供——`list` 输出与 1.4 节的 providers 架构在这里接上了头。

离开本章前，先睹为快——把全书要练的十个子命令各抽一行代表命令放在一起，不求看懂，只求混个脸熟（括号里是详细讲解的章号）：

```bash
openssl dgst -sha256 backup.tar.gz        # 算指纹，验证完整性（第2章）
openssl enc -aes-256-cbc -pbkdf2 -in a -out b  # 对称加密（第3章）
openssl rand -hex 32                      # 造随机数，密钥的原料（第4章）
openssl genpkey -algorithm ED25519        # 生成非对称密钥对（第5章）
openssl pkey -in k.pem -pubout            # 从私钥导出公钥（第5、6章）
openssl req -new -key k.pem -out r.csr    # 造证书签名请求（第9章）
openssl x509 -in c.pem -noout -text       # 解剖一张证书（第8章）
openssl verify -CAfile ca.pem c.pem       # 验证证书链（第11章）
openssl s_client -connect host:443        # TLS 现场勘察（第12章）
openssl passwd -6 'mypass'                # 口令哈希（第4章）
```

这十行覆盖了云笔记三次危机的全部应对动作：查损坏、防泄露、管身份、上 TLS。每一行单拎出来都是一条可以立刻敲进终端的真命令——第2章起我们会逐行展开。

帮助体系有三层，查问题的姿势全在这里：

| 姿势 | 命令 | 得到什么 |
| ---- | ---- | ---- |
| 看全部子命令 | `openssl list -commands` | 命令名单 |
| 看某个子命令的参数 | `openssl dgst -help` | 该命令的参数速查（最快） |
| 看某个子命令的手册 | `man openssl-dgst` | 完整文档（Linux/macOS） |

忘参数时默认走中间层：`openssl 子命令 -help`，一屏看完不用离开终端。注意写法是**先写子命令再加 `-help`**——直接 `openssl -help` 给出的是入口级帮助，查不到 `dgst` 的参数细节。Man 页在新版里按 `openssl-<子命令>` 命名，比如 `man openssl-req` 才是 req 的手册，老式的 `man req` 在部分系统会指向别的东西。

## 1.4 OpenSSL 3.x 变了什么

如果你在网上搜到的教程命令忽而 `genrsa` 忽而 `genpkey`，不是有人写错了，而是 OpenSSL 3.x 做了一次架构级换代。三个与你直接相关的变化：

**变化一：providers 架构。** 3.x 把算法实现拆成了可插拔的「提供者（Provider）」：`default` 承载现代算法，`legacy` 收容老算法（DES、MD4 这类活化石），`fips` 提供过 FIPS 认证的算法集。想确认自己环境里有哪些：

```text
$ openssl list -providers
Providers:
  default
    name: OpenSSL Default Provider
    version: 3.2.1
  legacy
    name: OpenSSL Legacy Provider
    version: 3.2.1
```

平时你感觉不到它的存在；只有当某条老命令报 `unsupported` 时，才会发现是算法被关进了 legacy 提供者——这是 3.x 排错的专属新坑，第14章会再遇到它。完整启用 legacy 的姿势了解一下即可（原则上不应再启用老算法）：

```bash
openssl list -providers -provider default -provider legacy -verbose
```

参数 `-provider` 可叠加，用于**本次命令**临时启用某个提供者——它不改变系统全局配置，用完即止，这正是 providers 架构的设计意图：把「用什么算法」的决定权交还给每一条命令。

**变化二：老命令进入淘汰倒计时。** `genrsa`、`rsa`、`dsaparam` 这批 1.x 时代的子命令还在，但官方文档已标注 deprecated。新旧对照记一张表就够：

| 老写法（1.x，已淘汰） | 新写法（3.x，本书采用） |
| ---- | ---- |
| `openssl genrsa -out k.pem 2048` | `openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out k.pem` |
| `openssl rsa -in k.pem -pubout` | `openssl pkey -in k.pem -pubout` |
| `openssl ecparam -genkey` | `openssl genpkey -algorithm EC ...` |

新写法更长，但一套 `genpkey`/`pkey` 通吃 RSA、EC、Ed25519 全家族——一次学会，全算法通用，这就是统一的价值。

**变化三：默认行为更安全。** 3.x 生成的 PKCS#12 文件默认用现代加密算法（老软件打不开时要加 `-legacy`，第6章细说）；PEM 输出统一走新的封装格式。原则一句话：**网上的命令先看年代，1.x 时代的命令优先换算成 3.x 写法**。

三个变化合起来的排错启示：以后遇到「教程命令我照抄了却报错」，按顺序问三个问题——版本是 3.x 吗（`openssl version`）？算法是不是被收进 legacy 了（`list -providers` 对照）？命令写法是不是 1.x 的老古董（对照本章表格）？三问过后，绝大多数「玄学报错」都会现出原形。

## 1.5 实验：装好你的工具箱

两个验收实验，五分钟内完成。通过标准只有一个：三条命令的输出与本书一致。

**实验一：版本与算法清单。** 确认环境是 OpenSSL 3.x，并看一眼你的环境支持多少摘要算法：

```bash
openssl version
openssl list -digest-algorithms | head -20
```

第二行会滚出几十个算法名，`SHA2-256`、`SHA3-512`、`MD5`……暂时不用认识它们，第2章会给这份名单排座次。现在只需要确认：列表能出来，说明工具箱活着。

**实验二：第一个密码学操作。** 用 `rand` 造 16 字节随机数，再用 base64 编成文本——这是全书最短的一行代码，也是后面所有密钥的出生方式：

```bash
openssl rand -hex 16
openssl rand -base64 32
```

```text
3f9a1c7e5b2d8f40a6c1e9d3b7f25a80
kR9xV2mQ7pL4wN8yT1cE6uH3jB5sZ0aF+dGqXvMn2Po=
```

第一条输出 32 个十六进制字符（16 字节的 hex 展开），第二条输出 44 个 base64 字符（32 字节的编码，结尾可能有 `=` 填充）。为什么一个 16 一个 32、一个 32 字符一个 44 字符？hex 与 base64 的换算关系正是第4章的主题之一，届时你会算得像口算一样快。

验收清单收个尾：

| 验收项 | 命令 | 期望结果 |
| ---- | ---- | ---- |
| 版本是 3.x 且非 LibreSSL | `openssl version` | `OpenSSL 3.x.x` |
| 算法清单可列出 | `openssl list -digest-algorithms` | 滚出算法列表 |
| 随机数可生成且两次不同 | 连跑两次 `openssl rand -hex 8` | 两次输出不同 |
| 帮助体系可达 | `openssl dgst -help` | 打印 dgst 参数表 |

> [!WARNING] 永远不要用「在线加密工具」处理真实数据
> 搜索「在线 AES 加密」「在线生成密钥」会出现大量网页工具——它们的工作原理是把你的数据与密钥**发送到别人的服务器**上运算。第4章之后你会知道：密钥一旦离开本机，保密承诺就是一句台词。真实数据的所有密码学操作，只允许发生在你控制的机器上——这正是 OpenSSL CLI 存在的理由之一。

两个实验都通过，工具箱验收完毕。你可能注意到：第一章几乎没有真正「加密」任何东西——这是故意的。密码学工具的学习成本不在命令本身，而在概念地基：第2章先打第一块砖，从最简单也最被低估的哈希开始。

## 本章小结

- OpenSSL 是三合体：libcrypto 算法库、libssl TLS 实现、openssl CLI——**本书主战场是 CLI，但背后全在调前两者**
- 简史四个锚点：1998 诞生、2014 Heartbleed、2015 LibreSSL 分叉、2021 3.0 换代——老教程的命令写法大多出自 2021 年之前
- 版本先行：`openssl version`（含 `-a` 看细节）是一切排错的第一步；本书基于 3.x，macOS 自带的 LibreSSL 要用 brew 换掉
- CLI 结构是「一个入口，几百个子命令」，日常高频约十个；查帮助走三层：`list -commands` → `子命令 -help` → `man openssl-<子命令>`
- 3.x 两大变化：providers 架构（老算法住进 legacy，`-provider` 参数按命令启用）、老命令淘汰（`genrsa` → `genpkey -algorithm RSA`）
- 网上搜到的命令先看年代：1.x 写法优先换算成 3.x 的统一写法；「照抄却报错」三问：版本？providers？年代？
- 随机数是所有密钥的出生证明：`openssl rand` 这一行命令，后面每章都会遇到
