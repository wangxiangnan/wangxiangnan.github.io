# 第3章：异步编程（上）——回调、Promise 与 async/await

## 引言：为什么 Node.js 选择异步？

让我给你讲个故事。

假设你开了一家餐厅，有两种经营模式：

**模式A（同步/阻塞）**：只有一个服务员。客人A点完菜，服务员去厨房等菜做好，端给客人A，然后才去服务客人B。如果厨房要20分钟做一道菜，客人B就得干等20分钟才能点菜。

**模式B（异步/非阻塞）**：还是只有一个服务员。但这次服务员聪明了——客人A点完菜，服务员把单子交给厨房，不等了！转身去服务客人B。等厨房做好菜，喊一声"菜好了"，服务员再去端。

Node.js 选择了模式B。这个唯一的服务员就是**主线程**，厨房就是**操作系统的 I/O 子系统**，"菜好了"就是**回调函数**。

### 为什么这对 I/O 密集型应用特别有效？

Web 服务器 90% 的时间都在等待 I/O：

- 等数据库查询返回（几毫秒到几百毫秒）
- 等文件读取（几毫秒）
- 等网络请求返回（几十到几百毫秒）
- 等用户发送数据

在这些等待的时间里，CPU 其实是空闲的。同步模型白白浪费了这些时间，而异步模型让 CPU 在等待期间去做其他有意义的事。

**关键数字感受**：

```
CPU 周期          ~0.3ns      | 1秒
L1 缓存           ~1ns       | 3秒
L2 缓存           ~4ns       | 12秒
内存访问          ~100ns      | 5分钟
SSD 随机读取      ~150μs      | 6天
机械硬盘寻址      ~10ms       | 1年
网络往返(同城)    ~0.5ms      | 18天
网络往返(跨洋)    ~150ms      | 15年
```

看到了吗？当你发起一次网络请求，相对于 CPU 来说，就像等了"15年"。你的 CPU 如果只是干等，那简直是犯罪级别的浪费。

## 3.1 回调函数：最原始的异步方案

### 基本模式

```javascript
// Node.js 的回调约定：Error-First Callback
// 第一个参数永远是 error，没错误时为 null
import { readFile } from 'node:fs';

readFile('./config.json', 'utf-8', (error, data) => {
  if (error) {
    console.error('读取文件失败:', error.message);
    return;  // 别忘了 return！否则下面的代码还会执行
  }
  console.log('文件内容:', data);
});

console.log('这行先执行！');  // ← 这行会先打印
```

### Error-First Callback 的约定

```javascript
/**
 * Node.js 回调函数的标准签名
 * @callback NodeCallback
 * @param {Error | null} error - 错误对象，null 表示成功
 * @param {T} result - 成功时的结果
 */

// 自己写一个遵循约定的异步函数
import { readFile } from 'node:fs';

function readJsonFile(filePath, callback) {
  readFile(filePath, 'utf-8', (err, data) => {
    if (err) {
      callback(err, null);
      return;
    }
    try {
      const parsed = JSON.parse(data);
      callback(null, parsed);
    } catch (parseError) {
      callback(parseError, null);
    }
  });
}

// 使用
readJsonFile('./package.json', (err, pkg) => {
  if (err) {
    console.error('失败:', err);
    return;
  }
  console.log(`包名: ${pkg.name}, 版本: ${pkg.version}`);
});
```

### 回调地狱：真实案例

假设你需要：读取配置文件 → 连接数据库 → 查询用户 → 获取用户订单 → 发送邮件

```javascript
// 😱 回调地狱（Callback Hell / Pyramid of Doom）
readFile('./config.json', 'utf-8', (err, configStr) => {
  if (err) { handleError(err); return; }
  const config = JSON.parse(configStr);

  connectDatabase(config.dbUrl, (err, db) => {
    if (err) { handleError(err); return; }

    db.query('SELECT * FROM users WHERE id = ?', [userId], (err, user) => {
      if (err) { handleError(err); return; }

      db.query('SELECT * FROM orders WHERE user_id = ?', [user.id], (err, orders) => {
        if (err) { handleError(err); return; }

        sendEmail(user.email, formatOrders(orders), (err, result) => {
          if (err) { handleError(err); return; }

          console.log('邮件发送成功:', result);
          // 如果这里还要继续嵌套...你就疯了
        });
      });
    });
  });
});
```

这段代码有什么问题？

1. **可读性差**：嵌套太深，一眼看不清逻辑
2. **错误处理重复**：每层都要 `if (err)` 检查
3. **难以修改**：想在中间加一步？得改缩进和花括号
4. **无法复用**：逻辑耦合在嵌套结构里

## 3.2 Promise：异步操作的"承诺"

Promise 是 ES6 引入的异步编程解决方案。它代表一个异步操作的最终结果——就像你在奶茶店点了一杯奶茶，店员给你一个小票（Promise），这个小票"承诺"了你最终会得到一杯奶茶（fulfilled）或者被告知卖完了（rejected）。

### 三种状态

```
                    ┌─── fulfilled（已兑现）→ 有结果值 value
                    │
pending（等待中）──┤
                    │
                    └─── rejected（已拒绝）→ 有原因 reason

状态转换规则：
- pending → fulfilled（不可逆）
- pending → rejected（不可逆）
- fulfilled/rejected 统称 settled（已定型）
```

### 创建 Promise

```javascript
// 方式1：new Promise 构造函数
const promise = new Promise((resolve, reject) => {
  // 模拟异步操作
  setTimeout(() => {
    const random = Math.random();
    if (random > 0.5) {
      resolve(`成功！随机数: ${random}`);  // 将状态变为 fulfilled
    } else {
      reject(new Error(`失败！随机数: ${random}`));  // 将状态变为 rejected
    }
  }, 1000);
});

// 方式2：Promise.resolve / Promise.reject
const resolved = Promise.resolve(42);  // 直接创建 fulfilled 的 Promise
const rejected = Promise.reject(new Error('oops'));  // 直接创建 rejected 的 Promise

// 方式3：async 函数自动返回 Promise
async function fetchData() {
  return 42;  // 等同于 return Promise.resolve(42)
}
```

### 链式调用

```javascript
import { readFile } from 'node:fs/promises';

// 改写回调地狱为 Promise 链
readFile('./config.json', 'utf-8')
  .then(configStr => JSON.parse(configStr))
  .then(config => connectDatabase(config.dbUrl))
  .then(db => db.query('SELECT * FROM users WHERE id = ?', [userId]))
  .then(user => {
    return db.query('SELECT * FROM orders WHERE user_id = ?', [user.id])
      .then(orders => ({ user, orders }));  // 同时保留 user 和 orders
  })
  .then(({ user, orders }) => sendEmail(user.email, formatOrders(orders)))
  .then(result => console.log('成功:', result))
  .catch(error => console.error('失败:', error))  // 一个 catch 处理所有错误
  .finally(() => console.log('无论成败都执行'));
```

比回调地狱好多了，但还是有点长。让我们看看终极方案。

### Promise 的微任务特性

```javascript
console.log('1. 同步代码开始');

Promise.resolve().then(() => {
  console.log('3. Promise 微任务');
});

setTimeout(() => {
  console.log('4. setTimeout 宏任务');
}, 0);

console.log('2. 同步代码结束');

// 输出顺序：1 → 2 → 3 → 4
// Promise.then 回调是微任务，优先于 setTimeout 的宏任务
```

## 3.3 async/await：优雅的语法糖

async/await 是 ES2017 引入的语法糖，让异步代码看起来像同步代码一样直观。

### 基本用法

```javascript
import { readFile } from 'node:fs/promises';

// 用 async/await 改写
async function processUserOrders(userId: string): Promise<void> {
  try {
    // 每个 await 都在等待 Promise resolve
    const configStr = await readFile('./config.json', 'utf-8');
    const config = JSON.parse(configStr);

    const db = await connectDatabase(config.dbUrl);
    const user = await db.query('SELECT * FROM users WHERE id = ?', [userId]);
    const orders = await db.query('SELECT * FROM orders WHERE user_id = ?', [user.id]);

    const result = await sendEmail(user.email, formatOrders(orders));
    console.log('邮件发送成功:', result);
  } catch (error) {
    // 一个 try/catch 捕获所有错误
    console.error('处理失败:', error);
  } finally {
    console.log('清理资源...');
  }
}

processUserOrders('user-123');
```

看到了吗？同样的逻辑，从回调地狱变成了清晰的顺序代码。这就是 async/await 的魔力。

### async/await 的本质

```javascript
// async/await 本质上是 Promise + Generator 的语法糖
// 下面两段代码是等价的：

// async/await 版本
async function fetchUser(id) {
  const response = await fetch(`/api/users/${id}`);
  const user = await response.json();
  return user;
}

// 展开后的 Promise 版本
function fetchUser(id) {
  return fetch(`/api/users/${id}`)
    .then(response => response.json())
    .then(user => user);
}

// async 函数永远返回 Promise
// await 只是让你"暂停"当前 async 函数的执行，
// 等 Promise resolve 后继续
```

### 经典误区：串行 vs 并行

```javascript
// ❌ 错误：不需要顺序执行的操作不应该串行等待
async function loadPageData() {
  const user = await fetchUser(userId);        // 等 2 秒
  const posts = await fetchPosts(userId);      // 等 2 秒
  const comments = await fetchComments(userId); // 等 2 秒
  // 总共 6 秒！但这三个请求之间没有依赖关系
  return { user, posts, comments };
}

// ✅ 正确：无依赖关系的操作应该并行
async function loadPageData() {
  const [user, posts, comments] = await Promise.all([
    fetchUser(userId),       // ┐
    fetchPosts(userId),      // ├── 三个同时发出
    fetchComments(userId),   // ┘
  ]);
  // 总共约 2 秒（取最慢的那个）
  return { user, posts, comments };
}
```

## 3.4 Promise 组合器：all / allSettled / race / any

### Promise.all：全部成功才算成功

```javascript
// 所有 Promise 都 fulfill 时，返回结果数组
// 任何一个 reject，立即返回第一个 reject 的 reason

async function fetchAllData(): Promise<{users: User[], products: Product[], orders: Order[]}> {
  const [users, products, orders] = await Promise.all([
    fetch('/api/users').then(r => r.json()),
    fetch('/api/products').then(r => r.json()),
    fetch('/api/orders').then(r => r.json()),
  ]);
  return { users, products, orders };
}

// 典型应用：加载页面所有必要数据
// 如果任何一个接口挂了，整体就失败
```

### Promise.allSettled：全部完成，不管成败

```javascript
// 等所有 Promise 都 settled（fulfilled 或 rejected）
// 永远不会 reject，返回每个 Promise 的状态和结果

interface SettledResult<T> {
  status: 'fulfilled' | 'rejected';
  value?: T;      // fulfilled 时有值
  reason?: any;   // rejected 时有原因
}

async function tryFetchAll() {
  const results = await Promise.allSettled([
    fetch('/api/users').then(r => r.json()),
    fetch('/api/broken-endpoint').then(r => r.json()),  // 这个会失败
    fetch('/api/products').then(r => r.json()),
  ]);

  // 分类处理
  const successes = results.filter(r => r.status === 'fulfilled');
  const failures = results.filter(r => r.status === 'rejected');

  console.log(`成功: ${successes.length}, 失败: ${failures.length}`);

  // 获取成功的结果
  const data = successes.map(r => r.value);
  // 记录失败原因
  failures.forEach(r => console.error('请求失败:', r.reason));
}

// 典型应用：批量操作中需要知道每个的结果，不希望一个失败影响其他
```

### Promise.race：第一个完成的胜出

```javascript
// 返回第一个 settled 的结果（无论 fulfill 还是 reject）

// 经典应用：请求超时
async function fetchWithTimeout<T>(
  promise: Promise<T>,
  timeoutMs: number
): Promise<T> {
  const timeout = new Promise<never>((_, reject) => {
    setTimeout(() => reject(new Error(`请求超时 (${timeoutMs}ms)`)), timeoutMs);
  });

  return Promise.race([promise, timeout]);
}

// 使用
try {
  const data = await fetchWithTimeout(
    fetch('https://slow-api.example.com/data').then(r => r.json()),
    5000  // 5 秒超时
  );
  console.log('获取成功:', data);
} catch (error) {
  console.error(error.message); // "请求超时 (5000ms)"
}
```

### Promise.any：第一个成功的胜出

```javascript
// 返回第一个 fulfill 的结果
// 只有所有都 reject 时才 reject（AggregateError）

// 经典应用：多源竞速，取最快的响应
async function fetchFromFastestMirror(url: string): Promise<Response> {
  const mirrors = [
    `https://mirror1.example.com${url}`,
    `https://mirror2.example.com${url}`,
    `https://mirror3.example.com${url}`,
  ];

  try {
    const response = await Promise.any(
      mirrors.map(mirror => fetch(mirror))
    );
    console.log('最快的镜像响应了');
    return response;
  } catch (error) {
    // AggregateError: All promises were rejected
    console.error('所有镜像都挂了:', error.errors);
    throw error;
  }
}
```

### 组合器对比表

| 方法 | 成功条件 | 失败条件 | 返回值 |
| ------ | --------- | --------- | -------- |
| `Promise.all` | 全部 fulfill | 任一 reject | 结果数组 |
| `Promise.allSettled` | 永远 fulfill | 永远不 reject | 状态数组 |
| `Promise.race` | 第一个 settle | 第一个 settle | 单个结果 |
| `Promise.any` | 任一 fulfill | 全部 reject | 单个结果 |

## 3.5 错误处理：异步世界的护栏

### try/catch（async/await 的好搭档）

```javascript
async function riskyOperation() {
  try {
    const data = await someAsyncCall();
    const result = await processData(data);
    return result;
  } catch (error) {
    // 捕获 await 的任何 rejection
    if (error instanceof NetworkError) {
      console.error('网络错误，重试中...');
      return await retryOperation();
    }
    if (error instanceof ValidationError) {
      console.error('数据验证失败:', error.message);
      return null;
    }
    // 未知错误，向上抛出
    throw error;
  }
}
```

### .catch()（Promise 链的守护者）

```javascript
// 如果你用 .then 链，用 .catch 兜底
fetchData()
  .then(processData)
  .then(saveResult)
  .catch(error => {
    // 捕获链中任何一步的错误
    console.error('管道处理失败:', error);
  });
```

### unhandledRejection：最后的防线

```javascript
// 全局捕获未处理的 Promise rejection
// 这是最后的安全网，表示你代码中有 Promise 忘了 catch

process.on('unhandledRejection', (reason, promise) => {
  console.error('未处理的 Promise rejection:', reason);
  console.error('问题 Promise:', promise);
  // 在生产环境，可能需要：
  // 1. 记录日志
  // 2. 发送告警
  // 3. 优雅地关闭进程
});

// 从 Node.js 15 开始，未处理的 rejection 会导致进程退出（默认行为）
// 这是好事！强制你处理所有错误

// uncaughtException：同步代码的最后防线
process.on('uncaughtException', (error) => {
  console.error('未捕获的异常:', error);
  // 在这里只应该做：记日志、关闭服务器、退出进程
  // 不要试图"恢复"——程序状态可能已经不一致了
  process.exit(1);
});
```

### 错误处理最佳实践

```javascript
// ✅ 实用的错误处理工具函数
type Result<T, E = Error> = 
  | { ok: true; value: T }
  | { ok: false; error: E };

async function trySafe<T>(promise: Promise<T>): Promise<Result<T>> {
  try {
    const value = await promise;
    return { ok: true, value };
  } catch (error) {
    return { ok: false, error: error instanceof Error ? error : new Error(String(error)) };
  }
}

// 使用：不用 try/catch，用返回值判断
async function handleRequest() {
  const userResult = await trySafe(fetchUser(userId));
  if (!userResult.ok) {
    console.error('获取用户失败:', userResult.error);
    return;
  }
  // userResult.value 在这里是 User 类型（TypeScript 类型收窄）
  console.log('用户:', userResult.value.name);
}
```

## 3.6 Top-level await

Node.js 14.8+ 支持在 ESM 模块的顶层使用 await：

```javascript
// config.mjs
// 不需要包在 async 函数里！
import { readFile } from 'node:fs/promises';

const configStr = await readFile('./config.json', 'utf-8');
export const config = JSON.parse(configStr);

// 异步初始化数据库连接
export const db = await createDatabaseConnection(config.database);

console.log('模块初始化完成');
```

```javascript
// app.mjs
import { config, db } from './config.mjs';
// 导入时会等待 config.mjs 中的 await 完成
// 这里 config 和 db 保证已经初始化好了

console.log('配置已加载:', config.app.name);
```

**注意事项**：

- 只在 ESM 中可用（CJS 不支持）
- 使用 top-level await 的模块会阻塞所有导入它的模块
- 适合做一次性的初始化操作（加载配置、连接数据库）
- 不适合需要重试或错误恢复的场景

## 3.7 实战：并发控制器

真实场景：你有 1000 个 URL 要爬取，但不能同时发 1000 个请求（服务器会封你IP，你的网络也会炸）。需要限制并发数，比如最多同时 5 个。

```javascript
// concurrent-limiter.mjs

/**
 * 并发控制的 Promise 调度器
 * @template T
 */
class ConcurrencyLimiter {
  /** @type {number} 最大并发数 */
  #maxConcurrent;
  /** @type {number} 当前正在运行的任务数 */
  #running = 0;
  /** @type {Array<() => void>} 等待队列 */
  #queue = [];

  /**
   * @param {number} maxConcurrent - 最大并发数
   */
  constructor(maxConcurrent) {
    if (maxConcurrent < 1) throw new Error('并发数至少为 1');
    this.#maxConcurrent = maxConcurrent;
  }

  /**
   * 添加一个任务到调度器
   * @template T
   * @param {() => Promise<T>} task - 返回 Promise 的任务函数
   * @returns {Promise<T>}
   */
  async add(task) {
    // 如果达到最大并发数，等待
    if (this.#running >= this.#maxConcurrent) {
      await new Promise(resolve => this.#queue.push(resolve));
    }

    this.#running++;
    try {
      return await task();
    } finally {
      this.#running--;
      // 释放一个等待中的任务
      if (this.#queue.length > 0) {
        const next = this.#queue.shift();
        next();
      }
    }
  }

  /** 当前运行中的任务数 */
  get running() { return this.#running; }

  /** 队列中等待的任务数 */
  get waiting() { return this.#queue.length; }
}

// ===== 使用示例 =====

const limiter = new ConcurrencyLimiter(3); // 最多同时 3 个

// 模拟异步任务
function createTask(id, duration) {
  return async () => {
    console.log(`[开始] 任务 ${id}，预计 ${duration}ms`);
    await new Promise(resolve => setTimeout(resolve, duration));
    console.log(`[完成] 任务 ${id}`);
    return `结果-${id}`;
  };
}

// 提交 10 个任务，但最多同时运行 3 个
const tasks = Array.from({ length: 10 }, (_, i) =>
  limiter.add(createTask(i + 1, Math.random() * 2000 + 500))
);

const results = await Promise.all(tasks);
console.log('所有任务完成:', results);
```

运行效果：

```
[开始] 任务 1，预计 1200ms
[开始] 任务 2，预计 800ms
[开始] 任务 3，预计 1500ms     ← 最多同时 3 个
[完成] 任务 2
[开始] 任务 4，预计 600ms      ← 2完成后，4立即开始
[完成] 任务 1
[开始] 任务 5，预计 900ms
...
所有任务完成: ['结果-1', '结果-2', ...]
```

### 进阶版：带重试和超时

```javascript
// advanced-limiter.mjs

/**
 * @typedef {Object} TaskOptions
 * @property {number} [retries=0] - 重试次数
 * @property {number} [timeout=0] - 超时时间(ms)，0表示无限制
 * @property {(error: Error, attempt: number) => boolean} [shouldRetry] - 是否应该重试
 */

class AdvancedLimiter {
  #maxConcurrent;
  #running = 0;
  #queue = [];
  #completed = 0;
  #failed = 0;

  constructor(maxConcurrent) {
    this.#maxConcurrent = maxConcurrent;
  }

  /**
   * @template T
   * @param {() => Promise<T>} task
   * @param {TaskOptions} [options]
   * @returns {Promise<T>}
   */
  async add(task, options = {}) {
    const { retries = 0, timeout = 0, shouldRetry = () => true } = options;

    if (this.#running >= this.#maxConcurrent) {
      await new Promise(resolve => this.#queue.push(resolve));
    }

    this.#running++;

    try {
      let lastError;
      for (let attempt = 0; attempt <= retries; attempt++) {
        try {
          const result = timeout > 0
            ? await this.#withTimeout(task(), timeout)
            : await task();
          this.#completed++;
          return result;
        } catch (error) {
          lastError = error;
          if (attempt < retries && shouldRetry(error, attempt)) {
            // 指数退避
            const delay = Math.min(1000 * 2 ** attempt, 10000);
            await new Promise(resolve => setTimeout(resolve, delay));
            continue;
          }
        }
      }
      this.#failed++;
      throw lastError;
    } finally {
      this.#running--;
      if (this.#queue.length > 0) {
        this.#queue.shift()();
      }
    }
  }

  #withTimeout(promise, ms) {
    return Promise.race([
      promise,
      new Promise((_, reject) =>
        setTimeout(() => reject(new Error(`任务超时 (${ms}ms)`)), ms)
      )
    ]);
  }

  get stats() {
    return {
      running: this.#running,
      waiting: this.#queue.length,
      completed: this.#completed,
      failed: this.#failed
    };
  }
}

// 使用示例
const limiter = new AdvancedLimiter(5);

const urls = [
  'https://api.example.com/data/1',
  'https://api.example.com/data/2',
  // ... 更多URL
];

const results = await Promise.allSettled(
  urls.map(url =>
    limiter.add(
      () => fetch(url).then(r => r.json()),
      {
        retries: 3,
        timeout: 5000,
        shouldRetry: (err) => err.message.includes('timeout') || err.message.includes('ECONNRESET')
      }
    )
  )
);

console.log('统计:', limiter.stats);
```

## 3.8 常见坑点

### 坑1：忘记 await

```javascript
// ❌ 忘了 await，result 是一个 Promise 对象！
async function getData() {
  const result = fetchData(); // 忘了 await
  console.log(result); // Promise { <pending> }
  return result.name; // undefined！Promise 对象没有 .name 属性
}

// ✅
async function getData() {
  const result = await fetchData();
  console.log(result); // 实际数据
  return result.name;
}
```

### 坑2：在循环中不当使用 await

```javascript
// ❌ 串行执行，如果有 100 个用户就要等 100 倍时间
async function processUsers(userIds) {
  const results = [];
  for (const id of userIds) {
    const user = await fetchUser(id); // 每次都等上一个完成
    results.push(user);
  }
  return results;
}

// ✅ 并行执行（如果不需要保序或不超过并发限制）
async function processUsers(userIds) {
  return Promise.all(userIds.map(id => fetchUser(id)));
}

// ✅ 有限并发（用我们上面写的调度器）
async function processUsers(userIds) {
  const limiter = new ConcurrencyLimiter(10);
  return Promise.all(
    userIds.map(id => limiter.add(() => fetchUser(id)))
  );
}
```

### 坑3：async 函数中的错误被静默吞掉

```javascript
// ❌ 调用 async 函数但不 await/catch
function startApp() {
  initializeDatabase(); // async 函数，忘了 await
  // 如果 initializeDatabase 内部抛错，这里完全不知道！
  startServer();
}

// ✅ 确保处理所有 async 调用的错误
async function startApp() {
  try {
    await initializeDatabase();
    await startServer();
  } catch (error) {
    console.error('启动失败:', error);
    process.exit(1);
  }
}
```

### 坑4：Promise 构造函数中的异步

```javascript
// ❌ Promise 构造函数中使用 async（常见反模式）
const promise = new Promise(async (resolve, reject) => {
  try {
    const data = await fetchSomething();
    resolve(data);
  } catch (err) {
    reject(err);
  }
});
// 问题：如果 reject 没被调用，错误会被吞掉

// ✅ 直接返回 async 函数的结果
const promise = fetchSomething(); // async 函数已经返回 Promise 了！
```

## 3.9 本章小结

| 进化阶段 | 语法 | 优点 | 缺点 |
| --------- | ------ | ----- | ------ |
| 回调函数 | `callback(err, data)` | 简单直接 | 回调地狱、错误处理繁琐 |
| Promise | `.then().catch()` | 链式调用、统一错误处理 | 链太长也不好读 |
| async/await | `await promise` | 同步风格、try/catch | 需要注意串行/并行 |

**核心理念**：异步不是目的，是手段。目的是让单线程的 Node.js 在等待 I/O 时不闲着。下一章我们将深入事件循环的内部机制，搞清楚 Node.js 到底是怎么调度这些异步操作的。
