# 第10章 窗口函数（MySQL 8.0 新特性）

## 10.1 窗口函数的概念：SQL界的"高阶函数"

如果说GROUP BY是"把所有人按部门分组后只告诉你每组的统计结果"，那窗口函数就是"每个人都能看到统计结果，但自己的行不会被合并"。这是理解窗口函数的关键——它提供了聚合计算的能力，但不像GROUP BY那样压缩行数。

打个更形象的比方：GROUP BY就像公司年会颁奖——主持人只宣布"技术部平均绩效最高"，但不逐一点名每个人的具体成绩；窗口函数就像给每个人发一张单独的成绩单——上面不仅有你自己的成绩，还有班级平均分、你在班里的排名、和上一名的差距。每个人的成绩单是单独一行，但信息量远比GROUP BY丰富。

窗口函数是MySQL 8.0引入的最令人兴奋的新特性之一（实际上PostgreSQL、SQL Server、Oracle中早已存在）。它彻底改变了很多以前需要写复杂自关联或相关子查询才能实现的查询模式。掌握窗口函数，你的SQL功力会有一个质的飞跃。

## 10.2 OVER() 语法详解：PARTITION BY、ORDER BY、窗口框架

窗口函数的核心语法结构如下。`PARTITION BY` 定义分区（类似GROUP BY的分组），`ORDER BY` 定义分区内的排序，窗口框架（Frame）定义函数的计算范围：

```sql
-- 窗口函数基本语法框架
-- 函数名(...) OVER (
--     [PARTITION BY 列1, 列2, ...]  -- 分区：按什么分组
--     [ORDER BY 列3, ...]           -- 排序：组内按什么排序
--     [窗口框架]                    -- 框架：计算范围（可选）
-- )

-- 最简单的用法：给所有员工按工资从高到低编号
SELECT emp_name, department, salary,
    ROW_NUMBER() OVER (ORDER BY salary DESC) AS salary_rank
FROM employees;

-- 加上PARTITION BY：在每个部门内部分别编号
SELECT emp_name, department, salary,
    ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS dept_rank
FROM employees;
```

窗口框架定义了函数的"视野范围"——它能看到当前行周围多大范围的数据。默认情况下，如果OVER中有ORDER BY，框架是从分区起始到当前行；如果没有ORDER BY，框架是整个分区。你可以通过ROWS BETWEEN精确控制：

```sql
-- 窗口框架关键字说明
-- CURRENT ROW          当前行
-- UNBOUNDED PRECEDING  分区起始（第一行）
-- UNBOUNDED FOLLOWING  分区结束（最后一行）
-- N PRECEDING          当前行前面N行
-- N FOLLOWING          当前行后面N行

-- 示例：三行移动平均（当前行和前后各一行，共3行的平均值）
SELECT order_date, amount,
    AVG(amount) OVER (
        ORDER BY order_date
        ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING
    ) AS moving_avg_3
FROM orders;
```

## 10.3 排名函数：ROW_NUMBER、RANK、DENSE_RANK、NTILE

排名函数是最常用的窗口函数家族，解决了"在每个分组内对数据排名"的需求。四个排名函数的行为差异主要体现在如何处理并列值上：

- **ROW_NUMBER()**：严格递增的连续编号，即使值相同也会分配不同的序号（不并列）
- **RANK()**：值相同时并列，下一个排名跳号（如1,1,3——没有第2名）
- **DENSE_RANK()**：值相同时并列，下一个排名不跳号（如1,1,2——紧凑排列）
- **NTILE(n)**：把数据平均分成n个桶，返回桶编号

```sql
-- 演示四个排名函数的区别（假设有相同工资的员工）
SELECT emp_name, salary,
    ROW_NUMBER() OVER (ORDER BY salary DESC) AS row_num,
    RANK() OVER (ORDER BY salary DESC) AS rank_val,
    DENSE_RANK() OVER (ORDER BY salary DESC) AS dense_rank_val,
    NTILE(4) OVER (ORDER BY salary DESC) AS quartile
FROM employees;
-- row_num:  1,2,3,4,5,6...（严格递增）
-- rank_val: 1,2,2,4,4,6...（并列跳号）
-- dense:    1,2,2,3,3,4...（并列不跳号）
-- quartile: 1,1,1,2,2,3...（四等分桶号）
```

> [!TIP] 提示
> 当有并列值时，ROW_NUMBER()会随机分配序号（不保证每次查询结果稳定）。如果你需要一个稳定的排序结果，在ORDER BY中加上一个唯一列（如emp_id或主键）作为次级排序条件，这样即使工资相同也会按emp_id的固定顺序排列。

```sql
-- 最实用的场景：每个部门按工资排名
SELECT emp_name, department, salary,
    DENSE_RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS dept_rank
FROM employees
ORDER BY department, dept_rank;
```

## 10.4 聚合窗口函数：SUM/AVG/COUNT OVER

所有你熟悉的聚合函数（SUM、AVG、COUNT、MAX、MIN）都可以作为窗口函数使用。和GROUP BY不同的是，它们不会把多行合并成一行，而是在每一行上附加聚合计算的结果：

```sql
-- 累计求和（Running Total）和全局总计
SELECT emp_name, department, salary,
    SUM(salary) OVER (ORDER BY emp_id) AS running_total,
    SUM(salary) OVER () AS grand_total
FROM employees;
-- running_total: 随着emp_id递增，逐步累加
-- grand_total: 每一行都显示全公司的工资总和

-- 部门内占比计算
SELECT emp_name, department, salary,
    SUM(salary) OVER (PARTITION BY department) AS dept_total,
    ROUND(salary / SUM(salary) OVER (PARTITION BY department) * 100, 2) AS pct_in_dept,
    ROUND(salary / SUM(salary) OVER () * 100, 2) AS pct_in_company
FROM employees ORDER BY department, salary DESC;
```

## 10.5 偏移函数：LAG、LEAD、FIRST_VALUE、LAST_VALUE、NTH_VALUE

偏移函数让你可以访问当前行"前面"或"后面"的行数据，这在计算环比、同比、变化量时特别有用。LAG(n)获取前面第n行的值，LEAD(n)获取后面第n行的值：

```sql
-- LAG()和LEAD()：获取前/后一行的值
SELECT emp_name, salary,
    LAG(salary) OVER (ORDER BY emp_id) AS prev_salary,
    LEAD(salary) OVER (ORDER BY emp_id) AS next_salary,
    salary - LAG(salary) OVER (ORDER BY emp_id) AS diff_from_prev
FROM employees;
-- 第一行的prev_salary为NULL（没有前一行），最后一行的next_salary为NULL

-- 带默认值的LAG/LEAD（避免NULL）
SELECT emp_name, salary,
    LAG(salary, 1, 0) OVER (ORDER BY emp_id) AS prev_salary,
    LEAD(salary, 1, 0) OVER (ORDER BY emp_id) AS next_salary
FROM employees;
```

FIRST_VALUE、LAST_VALUE和NTH_VALUE可以获取分区中指定位置的值。这里有一个非常重要的坑要注意——LAST_VALUE的默认窗口框架是"从分区起始到当前行"，所以"最后一行"其实就是当前行本身，而不是分区中真正的最后一行：

```sql
SELECT emp_name, department, salary,
    FIRST_VALUE(emp_name) OVER (
        PARTITION BY department ORDER BY salary DESC
    ) AS top_earner,
    -- 注意：必须显式指定窗口框架到UNBOUNDED FOLLOWING才能拿到真正的最后一行
    LAST_VALUE(emp_name) OVER (
        PARTITION BY department ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS lowest_earner,
    NTH_VALUE(salary, 2) OVER (
        PARTITION BY department ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS second_highest_salary
FROM employees;
```

> [!WARNING] 注意
> LAST_VALUE()的默认窗口框架是 `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`，这意味着在当前框架内"最后一行"就是当前行自己！如果你想获取分区中真正的最后一行的值，必须显式写上 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`。这是窗口函数中最常见的坑，无数人在这里栽过跟头。

## 10.6 窗口函数 vs GROUP BY 的区别

这两者经常让初学者困惑。简单来说，GROUP BY是"压缩模式"——把多行合并成一行，你只能看到每组的汇总信息；窗口函数是"增强模式"——在保持每一行不变的前提下，给每一行附加统计信息。如果你想同时看到个体数据和统计信息，用窗口函数；如果只需要汇总结果，用GROUP BY：

```sql
-- GROUP BY：每组只返回一行（3个部门 = 3行结果）
SELECT department, AVG(salary) AS avg_salary FROM employees GROUP BY department;

-- 窗口函数：每行都保留，同时显示统计（8个员工 = 8行结果）
SELECT emp_name, department, salary,
    AVG(salary) OVER (PARTITION BY department) AS dept_avg
FROM employees;
```

## 10.7 实际场景：Top-N查询

找出每个部门工资最高的N名员工——这是窗口函数最经典的用例。用GROUP BY或子查询来实现这个问题会非常别扭，但用窗口函数就优雅多了：

```sql
-- 每个部门工资最高的2名员工
WITH ranked AS (
    SELECT emp_name, department, salary,
        ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS rn
    FROM employees
)
SELECT * FROM ranked WHERE rn <= 2;
```

> [!TIP] 提示
> 为什么用ROW_NUMBER()而不是LIMIT？因为LIMIT只能限制整体结果集的行数，不能按分区限制。你无法用 `LIMIT 2` 来实现"每个部门取2个"这种需求。窗口函数配合WHERE过滤是Top-N问题的标准解法。

## 10.8 实际场景：累计计算与同比环比

窗口函数在财务和数据分析场景中大量使用。累计计算（Year-to-Date、Month-to-Date）用SUM() OVER配合ORDER BY就能实现；环比（和上一个周期比较）用LAG函数；同比（和去年同期比较）用LAG(12)：

```sql
-- 创建月度销售数据
CREATE TABLE monthly_sales (sale_month DATE, amount DECIMAL(10,2));
INSERT INTO monthly_sales VALUES
('2025-01-01', 10000), ('2025-02-01', 12000),
('2025-03-01', 11000), ('2025-04-01', 15000),
('2025-05-01', 13000), ('2025-06-01', 16000);

-- 累计销售额 + 环比增长率
SELECT
    DATE_FORMAT(sale_month, '%Y-%m') AS month,
    amount,
    SUM(amount) OVER (ORDER BY sale_month) AS cumulative_amount,
    LAG(amount) OVER (ORDER BY sale_month) AS prev_month_amount,
    ROUND(
        (amount - LAG(amount) OVER (ORDER BY sale_month))
        / LAG(amount) OVER (ORDER BY sale_month) * 100, 2
    ) AS mom_growth_pct
FROM monthly_sales;

-- 同比增长率（假设我们有两年的数据，LAG偏移12个月）
SELECT DATE_FORMAT(sale_month, '%Y-%m') AS month, amount,
    LAG(amount, 12) OVER (ORDER BY sale_month) AS same_month_last_year,
    ROUND(
        (amount - LAG(amount, 12) OVER (ORDER BY sale_month))
        / LAG(amount, 12) OVER (ORDER BY sale_month) * 100, 2
    ) AS yoy_growth_pct
FROM monthly_sales;
```

## 小结

窗口函数是MySQL 8.0最重要的新特性之一。它让你在不压缩行数的前提下获得聚合统计、排名、偏移等丰富的分析信息。排名函数（ROW_NUMBER/RANK/DENSE_RANK/NTILE）解决Top-N和分组排名问题，LAG/LEAD解决环比同比和变化量问题，SUM() OVER解决累计计算问题。牢记窗口框架的默认值，特别是LAST_VALUE()那个容易踩的坑。
