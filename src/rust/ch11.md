# 第11章：泛型编程

Part III：泛型、Trait与生命周期

恭喜你来到了 Rust 进阶之路的分水岭！前 10 章里你已经掌握了所有权、借用和基础数据结构——这些是 Rust 的"语法基本功"。而接下来这四章，将带你解锁 Rust 真正令人拍案叫绝的三大核心机制：**泛型**、**Trait** 和 **生命周期**，外加一对黄金搭档——**闭包**与**迭代器**。

如果你来自 Java/C# 世界，你会发现 Rust 的泛型和 Trait 似曾相识却又别有洞天；如果你来自 Python/JS 阵营，这些概念会帮你理解"静态类型语言是怎么做到既安全又灵活的"。总之，这四章学完，你就能写出真正"Rust 味"的代码了。

## 开篇：一个令人抓狂的场景

想象一下，你正在写一个工具函数，功能是"返回两个值中较大的那个"。你写了 `max_i32`，然后发现需要比较 `f64`，于是又写了 `max_f64`。接着 `String` 来了，`max_string`……你开始怀疑人生：

```rust
fn max_i32(a: i32, b: i32) -> i32 {
    if a > b { a } else { b }
}

fn max_f64(a: f64, b: f64) -> f64 {
    if a > b { a } else { b }
}
```

逻辑完全一样，只是类型不同。在 Python 里你根本不需要操心——`max(a, b)` 通吃一切。在 Java 里你有泛型 `T`。而 Rust 的答案，也是一种优雅的泛型系统。

## 为什么需要泛型？

**泛型（Generics）** 的本质是一种**代码抽象**：把"类型"也变成参数，让同一段逻辑适用于多种数据类型。

不同语言实现泛型的方式大不相同：

| 特性 | Java 泛型 | C++ 模板 | Rust 泛型 |
| ------ | ----------- | ---------- | ----------- |
| 实现机制 | 类型擦除（Type Erasure） | 模板实例化（编译期展开） | 单态化（Monomorphization） |
| 运行时开销 | 有（装箱/拆箱） | 零成本 | 零成本 |
| 编译期检查 | 较弱（擦除后变 Object） | 报错信息冗长 | 强，通过 Trait Bound 约束 |
| 类型参数约束 | `extends`/`super` | 隐式（SFINAE） | Trait Bound |

简单说：Rust 的泛型兼具 C++ 的零成本性能和 Java 的类型安全，代价是编译时间略长——但这是一笔划算的交易。

## 函数中的泛型

让我们用泛型重写那个 `max` 函数：

```rust
fn max_value<T: PartialOrd>(a: T, b: T) -> T {
    if a > b { a } else { b }
}

fn main() {
    println!("{}", max_value(10, 20));       // i32
    println!("{}", max_value(3.14, 2.71));   // f64
    println!("{}", max_value("hello", "world")); // &str
}
```

`<T: PartialOrd>` 的含义是：类型参数 `T` 必须实现 `PartialOrd` 这个 Trait（即支持部分比较）。别急，Trait 会在下一章详细展开——你暂时可以把它理解为 Java 的接口约束。

> **类比**：Java 中你会写 `<T extends Comparable<T>>`，Rust 写的是 `<T: PartialOrd>`，语义几乎一致，但 Rust 的 Trait 系统更灵活。

## 结构体中的泛型

泛型不只用在函数上，结构体也可以拥有类型参数：

```rust
#[derive(Debug)]
struct Point<T> {
    x: T,
    y: T,
}

fn main() {
    let integer_point = Point { x: 5, y: 10 };
    let float_point = Point { x: 1.5, y: 4.2 };

    println!("{:?}", integer_point); // Point { x: 5, y: 10 }
    println!("{:?}", float_point);   // Point { x: 1.5, y: 4.2 }
}
```

注意：`Point<T>` 中的 `x` 和 `y` 必须是**同一种类型**，因为它们共用同一个 `T`。如果你想让 `x` 和 `y` 类型不同呢？用两个类型参数就行：

```rust
#[derive(Debug)]
struct MixedPoint<T, U> {
    x: T,
    y: U,
}

fn main() {
    let p = MixedPoint { x: 5, y: 4.0 };
    println!("{:?}", p); // MixedPoint { x: 5, y: 4.0 }
}
```

## 枚举中的泛型（Option\<T\> 与 Result\<T, E\> 回顾）

其实在前面的章节里，你已经不知不觉地使用过泛型了！`Option<T>` 和 `Result<T, E>` 就是标准库中最经典的泛型枚举：

```rust
// Option<T> 的源码定义（简化版）
enum Option<T> {
    Some(T),
    None,
}

// Result<T, E> 的源码定义（简化版）
enum Result<T, E> {
    Ok(T),
    Err(E),
}

fn main() {
    let some_number: Option<i32> = Some(42);
    let no_number: Option<i32> = None;

    let ok_result: Result<String, String> = Ok("成功".to_string());
    let err_result: Result<String, String> = Err("出错".to_string());

    println!("{:?} {:?}", some_number, no_number);
    println!("{:?} {:?}", ok_result, err_result);
}
```

这正是泛型的魅力：**一份定义，万千类型**。`Option<i32>`、`Option<String>`、`Option<Vec<u8>>`——全都由同一个枚举定义派生而来。

## 泛型方法

结构体或枚举可以有泛型方法，方法的类型参数可以与结构体本身的类型参数相同，也可以不同：

```rust
struct Point<T> {
    x: T,
    y: T,
}

impl<T> Point<T> {
    // 方法：返回 x 的引用
    fn x(&self) -> &T {
        &self.x
    }

    // 方法：交换 x 和 y（需要 T 可交换，这里简单克隆）
    fn swap(self) -> Point<T> {
        Point { x: self.y, y: self.x }
    }
}

// 为特定类型实现方法——只有 f64 的 Point 才有 distance_from_origin
impl Point<f64> {
    fn distance_from_origin(&self) -> f64 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}

fn main() {
    let p = Point { x: 3.0, y: 4.0 };
    println!("x = {}", p.x());
    println!("distance = {}", p.distance_from_origin());

    let p2 = p.swap();
    println!("swapped: x = {}, y = {}", p2.x, p2.y);
}
```

注意到 `impl Point<f64>` 这个写法——你可以为**特定的泛型实例**单独实现方法，其他类型的 `Point<T>` 无法调用 `distance_from_origin`。这种"特化"在 Rust 中非常有用。

方法也可以引入新的类型参数：

```rust
struct Point<T, U> {
    x: T,
    y: U,
}

impl<T, U> Point<T, U> {
    // mixup 引入新的类型参数 V, W
    fn mixup<V, W>(self, other: Point<V, W>) -> Point<T, W> {
        Point {
            x: self.x,
            y: other.y,
        }
    }
}

fn main() {
    let p1 = Point { x: 5, y: 10.0 };       // Point<i32, f64>
    let p2 = Point { x: "hello", y: 'c' };   // Point<&str, char>

    let p3 = p1.mixup(p2); // Point<i32, char>
    println!("p3.x = {}, p3.y = {}", p3.x, p3.y);
}
```

## 单态化（Monomorphization）：零成本抽象的秘密

这是 Rust 泛型最核心的实现机制，也是面试高频考点。

**单态化**发生在编译期：编译器会找到所有实际使用的泛型实例，然后为每种具体类型生成一份独立的代码。

```rust
fn add<T: std::ops::Add<Output = T>>(a: T, b: T) -> T {
    a + b
}

fn main() {
    let int_sum = add(1, 2);
    let float_sum = add(1.5, 2.5);
}
```

编译后，编译器实际生成的代码类似于：

```rust
// 编译器自动生成的代码（伪代码，不是真正的 Rust）
fn add_i32(a: i32, b: i32) -> i32 {
    a + b
}

fn add_f64(a: f64, b: f64) -> f64 {
    a + b
}

fn main() {
    let int_sum = add_i32(1, 2);
    let float_sum = add_f64(1.5, 2.5);
}
```

**优点**：

- **零运行时开销**：没有虚函数表查找、没有类型擦除后的装箱拆箱，性能与手写特定类型代码完全一致。
- **编译期内联优化**：因为每种类型都有独立代码，编译器可以激进地进行内联和其他优化。

**代价**：

- **编译产物膨胀**：如果你用了 `Vec<i32>`、`Vec<String>`、`Vec<MyStruct>`，那确实会生成三份 `Vec` 的代码。不过在大多数实际项目中，这个膨胀是可控的。
- **编译时间增加**：单态化需要编译器做更多工作。

> **类比 Java**：Java 的泛型是"类型擦除"——`List<Integer>` 和 `List<String>` 在运行时都是 `List<Object>`，所以有装箱开销。Rust 走的是相反路线：宁可编译慢一点，运行时也不妥协。这和 C++ 模板的理念一脉相承。

## 实战：实现一个泛型栈（Stack）

让我们把本章所学融会贯通，实现一个经典的泛型数据结构——栈：

```rust
#[derive(Debug)]
struct Stack<T> {
    elements: Vec<T>,
}

impl<T> Stack<T> {
    fn new() -> Stack<T> {
        Stack {
            elements: Vec::new(),
        }
    }

    fn push(&mut self, item: T) {
        self.elements.push(item);
    }

    fn pop(&mut self) -> Option<T> {
        self.elements.pop()
    }

    fn peek(&self) -> Option<&T> {
        self.elements.last()
    }

    fn is_empty(&self) -> bool {
        self.elements.is_empty()
    }

    fn len(&self) -> usize {
        self.elements.len()
    }
}

// 为 Display 类型的 Stack 实现 Display
impl<T: std::fmt::Display> std::fmt::Display for Stack<T> {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "Stack[")?;
        for (i, item) in self.elements.iter().enumerate() {
            if i > 0 {
                write!(f, ", ")?;
            }
            write!(f, "{}", item)?;
        }
        write!(f, "]")
    }
}

fn main() {
    // 整数栈
    let mut int_stack = Stack::new();
    int_stack.push(1);
    int_stack.push(2);
    int_stack.push(3);

    println!("{}", int_stack);           // Stack[1, 2, 3]
    println!("peek: {:?}", int_stack.peek()); // peek: Some(3)
    println!("pop: {:?}", int_stack.pop());   // pop: Some(3)
    println!("{}", int_stack);           // Stack[1, 2]

    // 字符串栈
    let mut str_stack = Stack::new();
    str_stack.push("hello".to_string());
    str_stack.push("world".to_string());
    println!("{}", str_stack);           // Stack[hello, world]
}
```

这个 `Stack<T>` 可以对任何类型工作。当你写 `Stack::<i32>::new()` 时，编译器会生成一份 `i32` 专版代码；当你写 `Stack::<String>::new()` 时，又会生成一份 `String` 专版——单态化在幕后默默完成。

## 常见陷阱与易错点

**陷阱1：忘记 Trait Bound**

```rust
// 错误！编译器不知道 T 能否比较
fn largest<T>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list {
        if item > largest { // 编译错误：T 没有实现 PartialOrd
            largest = item;
        }
    }
    largest
}
```

修复：加上 `T: PartialOrd`。编译器不会猜测你想要什么约束，你必须明确告诉它。

**陷阱2：泛型结构体方法中的 Self 类型**

```rust
struct Wrapper<T> {
    value: T,
}

impl<T> Wrapper<T> {
    // 返回 Wrapper<T> 而不是裸的 T
    fn into_inner(self) -> T {
        self.value
    }
}
```

在 `impl` 块中，`Self` 代表 `Wrapper<T>`（完整泛型类型），而非 `Wrapper`。注意区分。

**陷阱3：过度泛型化**

不要为了泛型而泛型。如果一个函数只处理 `i32`，就没必要加 `<T>`。泛型化会增加代码复杂度和编译时间，只在真正需要多态时再使用。

## 小结

- 泛型让你用类型参数编写可复用的代码，同时保持零运行时开销。
- 函数、结构体、枚举、方法都可以使用泛型。
- `Option<T>` 和 `Result<T, E>` 是标准库中泛型最经典的用例。
- 单态化在编译期为每种实际类型生成独立代码，实现零成本抽象。
- Trait Bound 用来约束泛型参数的行为能力。

## 练习题

1. **基础**：实现一个泛型函数 `first_element<T>(slice: &[T]) -> Option<&T>`，返回切片的第一个元素（空切片返回 `None`）。

2. **中级**：定义一个泛型结构体 `Pair<T>`，包含两个字段 `first: T` 和 `second: T`。为其实现一个方法 `both_equal(&self) -> bool`（需要 `T: PartialEq`），当两个字段相等时返回 `true`。

3. **进阶**：扩展实战中的 `Stack<T>`，添加一个 `map` 方法：`fn map<U, F: FnMut(T) -> U>(self, f: F) -> Stack<U>`，将栈中每个元素转换后返回新栈。

4. **思考题**：为什么 Rust 选择单态化而非类型擦除来实现泛型？尝试分析两种方案在性能和灵活性上的取舍。

5. **挑战**：实现一个泛型函数 `count_occurrences<T: PartialEq>(list: &[T], target: &T) -> usize`，统计 `target` 在 `list` 中出现的次数。
