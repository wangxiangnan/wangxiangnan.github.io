# 第3章 CRUD 操作

> CRUD——Create、Read、Update、Delete，这是你和数据库打交道的基本功。就像学武功要先练扎马步一样，CRUD玩不溜，后面学再多高级技巧也是空中楼阁。

## 3.1 INSERT：数据插入

### 单行插入

```sql
-- 指定所有列
INSERT INTO users (username, email, phone, password_hash, status)
VALUES ('alice', 'alice@example.com', '13800138001', '$2b$10$xxxxx', 'active');

-- 更安全的写法：明确列出列名
INSERT INTO users (username, email, password_hash)
VALUES ('bob', 'bob@example.com', '$2b$10$yyyyy');
```

### 批量插入

批量插入的效率比逐条插入高得多：

```sql
-- 一次性插入多条记录
INSERT INTO products (name, price, stock, category_id) VALUES
('iPhone 15 Pro', 7999.00, 500, 1),
('MacBook Air M3', 8999.00, 300, 2),
('AirPods Pro 2', 1799.00, 1000, 3),
('iPad Pro 12.9', 8999.00, 200, 4),
('Apple Watch Ultra', 5999.00, 150, 5);

-- 插入查询结果（从一个表复制到另一个表）
INSERT INTO products_archive (name, price, stock, category_id)
SELECT name, price, stock, category_id
FROM products
WHERE is_active = 0;
```

> [!TIP] 提示
> 批量插入时，单条SQL不要太大。MySQL有`max_allowed_packet`限制（默认4MB），建议每批控制在1000-5000条左右。

### INSERT IGNORE

遇到唯一键冲突时，忽略错误继续插入：

```sql
-- 如果username已存在，忽略这条插入，不报错
INSERT IGNORE INTO users (username, email, password_hash)
VALUES ('alice', 'alice_new@example.com', '$2b$10$zzzzz');
```

### ON DUPLICATE KEY UPDATE（Upsert）

这是MySQL的杀手锏功能——"有就更新，没有就插入"：

```sql
-- 如果username已存在，更新邮箱；否则插入新记录
INSERT INTO users (username, email, password_hash)
VALUES ('alice', 'alice_updated@example.com', '$2b$10$zzzzz')
ON DUPLICATE KEY UPDATE
  email = VALUES(email),
  updated_at = CURRENT_TIMESTAMP;
```

### REPLACE INTO

`REPLACE` 的行为是：如果唯一键冲突，**先删除旧记录，再插入新记录**。注意，这会改变记录的ID！

```sql
-- 如果username冲突，删除旧行，插入新行（ID会变）
REPLACE INTO users (username, email, password_hash)
VALUES ('alice', 'alice_replaced@example.com', '$2b$10$aaaaa');
```

> [!WARNING] 注意
> `REPLACE INTO`和`ON DUPLICATE KEY UPDATE`看似相似，但有本质区别。`REPLACE`会删除旧记录（触发DELETE触发器），`ON DUPLICATE KEY UPDATE`只是更新（触发UPDATE触发器）。大多数场景下推荐用`ON DUPLICATE KEY UPDATE`。

## 3.2 SELECT：数据查询

### 基础查询

```sql
-- 查询所有列（开发/调试用，生产环境别这么干）
SELECT * FROM users;

-- 查询指定列（推荐写法）
SELECT id, username, email, status FROM users;

-- 给列起别名，让结果更好读
SELECT
  id AS user_id,
  username AS name,
  email AS contact_email
FROM users;

-- 使用表达式
SELECT
  name,
  price,
  price * 0.9 AS discounted_price,
  stock * price AS total_value
FROM products;

-- 查询函数
SELECT
  NOW() AS current_time,
  DATABASE() AS current_db,
  VERSION() AS mysql_version;
```

### DISTINCT 去重

```sql
-- 查询所有不同的分类ID
SELECT DISTINCT category_id FROM products;

-- 多列去重：两列组合不重复
SELECT DISTINCT category_id, is_active FROM products;
```

> [!TIP] 提示
> `DISTINCT`是在所有列上生效的，不是只针对第一列。`SELECT DISTINCT a, b`意味着a和b的组合不能重复。

## 3.3 UPDATE：数据更新

### 单表更新

```sql
-- 更新单条记录
UPDATE users
SET status = 'banned',
    updated_at = CURRENT_TIMESTAMP
WHERE id = 42;

-- 更新多条记录
UPDATE products
SET price = price * 0.8,
    updated_at = CURRENT_TIMESTAMP
WHERE category_id = 1 AND stock > 100;

-- 使用CASE实现条件更新（批量修改不同值）
UPDATE products
SET price = CASE
  WHEN category_id = 1 THEN price * 0.9
  WHEN category_id = 2 THEN price * 0.85
  ELSE price
END
WHERE is_active = 1;
```

### 多表更新

```sql
-- 根据订单表更新用户表的总消费
UPDATE users u
INNER JOIN (
  SELECT user_id, SUM(total_amount) AS total_spent
  FROM orders
  GROUP BY user_id
) o ON u.id = o.user_id
SET u.total_spent = o.total_spent;
```

> [!WARNING] 注意
> `UPDATE`不加`WHERE`条件会更新**整张表的所有行**！MySQL有个安全模式（`SQL_SAFE_UPDATES`），可以防止不带WHERE的UPDATE/DELETE。建议开启：`SET SQL_SAFE_UPDATES = 1;`

## 3.4 DELETE：数据删除

```sql
-- 按条件删除
DELETE FROM users WHERE status = 'banned' AND updated_at < '2023-01-01';

-- 删除关联数据（先删子表，再删主表）
DELETE FROM order_items WHERE order_id IN (
  SELECT id FROM orders WHERE user_id = 42
);
DELETE FROM orders WHERE user_id = 42;

-- 清空表（保留结构，重置自增ID）
TRUNCATE TABLE temp_logs;
```

### DELETE vs TRUNCATE 再强调

```sql
-- DELETE：可回滚、可带条件、触发触发器、不重置自增
DELETE FROM logs WHERE created_at < '2024-01-01';

-- TRUNCATE：快、不可回滚（一般情况）、无条件、重置自增
TRUNCATE TABLE logs;
```

### 安全删除策略

在生产环境中，直接删除数据是危险的。推荐使用**软删除**：

```sql
-- 添加软删除标记列
ALTER TABLE users ADD COLUMN deleted_at DATETIME DEFAULT NULL COMMENT '软删除时间';

-- "删除"操作实际上是更新
UPDATE users SET deleted_at = NOW() WHERE id = 42;

-- 查询时过滤掉已删除的记录
SELECT * FROM users WHERE deleted_at IS NULL;
```

> [!TIP] 提示
> 软删除的好处：数据可恢复、审计友好、不破坏外键关联。缺点：需要每个查询都加`WHERE deleted_at IS NULL`，容易遗漏。可以考虑用视图来统一处理。

## 3.5 UPSERT 模式详解

UPSERT = UPDATE + INSERT，是一种"存在就更新，不存在就插入"的模式：

```sql
-- 场景：统计页面访问量，每天一条记录
CREATE TABLE page_views (
  id BIGINT UNSIGNED AUTO_INCREMENT,
  page_id INT UNSIGNED NOT NULL,
  view_date DATE NOT NULL,
  view_count INT UNSIGNED NOT NULL DEFAULT 1,
  PRIMARY KEY (id),
  UNIQUE KEY uk_page_date (page_id, view_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='页面访问统计';

-- 每次访问时，UPSERT
INSERT INTO page_views (page_id, view_date, view_count)
VALUES (1001, CURDATE(), 1)
ON DUPLICATE KEY UPDATE
  view_count = view_count + 1;
```

这个模式非常适合计数器、缓存更新、数据同步等场景。

## 小结

CRUD是数据库操作的基础。本章我们不仅学了基本语法，还掌握了批量插入、UPSERT、软删除等实用技巧。记住几条铁律：UPDATE/DELETE一定要加WHERE、用软删除代替硬删除、批量操作注意性能。
