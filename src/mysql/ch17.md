# 第17章 用户管理与权限控制

**生活类比：** 想象一栋办公楼——前台访客只能进大厅，普通员工能进自己的办公区，部门经理能进自己部门的会议室，而CEO有所有门的钥匙。MySQL的用户管理和这栋楼的门禁系统一模一样：不同角色拥有不同的权限，而且遵循"最小权限原则"——只给你需要的，不多给一把钥匙。

## 17.1 MySQL用户模型

MySQL的用户由两部分组成：**用户名 + 主机名**。同一个用户名从不同主机连接，可以是不同的账号。

```sql
-- 查看当前用户
SELECT CURRENT_USER();

-- 查看所有用户
SELECT user, host FROM mysql.user;
```

## 17.2 用户管理基础

```sql
-- 创建用户：只允许从localhost连接
CREATE USER 'app_user'@'localhost' IDENTIFIED BY 'StrongP@ss123!';

-- 创建用户：允许从任意主机连接
CREATE USER 'app_user'@'%' IDENTIFIED BY 'StrongP@ss123!';

-- 创建用户：只允许从特定IP段连接
CREATE USER 'app_user'@'192.168.1.%' IDENTIFIED BY 'StrongP@ss123!';

-- 修改密码
ALTER USER 'app_user'@'localhost' IDENTIFIED BY 'NewP@ss456!';

-- 重命名用户
RENAME USER 'app_user'@'localhost' TO 'app_admin'@'localhost';

-- 删除用户
DROP USER 'app_user'@'%';
```

> [!WARNING] 注意
> '%' 通配符匹配任意主机，但不包括 localhost。在Unix系统上，localhost 连接默认使用 Unix Socket，不走TCP/IP，所以 'user'@'%' 和 'user'@'localhost' 是两个不同的账号。

## 17.3 密码策略与认证插件

MySQL 8.0 默认使用 `caching_sha2_password` 认证插件，比老版本的 `mysql_native_password` 更安全：

```sql
-- 查看当前密码策略
SHOW VARIABLES LIKE 'validate_password%';

-- 安装密码验证组件（如果未安装）
-- 在 my.cnf 中添加：
-- [mysqld]
-- validate_password.policy = MEDIUM
-- validate_password.length = 8

-- 使用特定认证插件创建用户
CREATE USER 'legacy_user'@'localhost'
IDENTIFIED WITH mysql_native_password BY 'OldStylePass123!';

-- 查看用户使用的认证插件
SELECT user, host, plugin FROM mysql.user;
```

密码强度策略等级：

- **LOW**：只验证密码长度
- **MEDIUM**（默认）：长度 + 数字 + 大小写 + 特殊字符
- **STRONG**：MEDIUM + 字典检查

## 17.4 权限管理：GRANT / REVOKE

```sql
-- 授予特定数据库的所有权限
GRANT ALL PRIVILEGES ON shop_db.* TO 'app_user'@'localhost';

-- 授予特定表的查询权限
GRANT SELECT ON shop_db.products TO 'readonly_user'@'localhost';

-- 授予多张表的多种权限
GRANT SELECT, INSERT, UPDATE ON shop_db.orders TO 'order_user'@'localhost';
GRANT SELECT, INSERT, UPDATE ON shop_db.order_items TO 'order_user'@'localhost';

-- 授予列级权限
GRANT SELECT (name, email), UPDATE (email) ON shop_db.users TO 'user_mgr'@'localhost';

-- 刷新权限（修改权限后执行）
FLUSH PRIVILEGES;
```

```sql
-- 撤销权限
REVOKE INSERT, UPDATE ON shop_db.orders FROM 'order_user'@'localhost';

-- 撤销所有权限
REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'order_user'@'localhost';
```

## 17.5 权限层级

MySQL的权限从粗到细分为四个层级：

```sql
-- 全局权限：对所有数据库生效
GRANT SELECT ON *.* TO 'admin'@'localhost';

-- 数据库权限：对指定数据库生效
GRANT ALL ON shop_db.* TO 'shop_admin'@'localhost';

-- 表权限：对指定表生效
GRANT SELECT, INSERT ON shop_db.orders TO 'order_user'@'localhost';

-- 列权限：对指定列生效
GRANT SELECT (order_id, status) ON shop_db.orders TO 'report_user'@'localhost';
```

> [!TIP] 提示
> 权限的存储位置不同：全局权限在 mysql.user 表，数据库权限在 mysql.db 表，表权限在 mysql.tables_priv 表，列权限在 mysql.columns_priv 表。了解这些有助于直接排查权限问题。

## 17.6 角色(Role)管理

MySQL 8.0 引入了角色管理，大大简化了权限分配：

```sql
-- 创建角色
CREATE ROLE 'developer_role';
CREATE ROLE 'analyst_role';
CREATE ROLE 'admin_role';

-- 给角色分配权限
GRANT SELECT, INSERT, UPDATE, DELETE ON shop_db.* TO 'developer_role';
GRANT SELECT ON shop_db.* TO 'analyst_role';
GRANT ALL PRIVILEGES ON shop_db.* TO 'admin_role';

-- 把角色授予用户
GRANT 'developer_role' TO 'zhangsan'@'localhost';
GRANT 'analyst_role' TO 'lisi'@'localhost';
GRANT 'admin_role' TO 'wangwu'@'localhost';

-- 一个用户可以拥有多个角色
GRANT 'analyst_role' TO 'zhangsan'@'localhost';

-- 设置默认角色（用户登录后自动激活）
SET DEFAULT ROLE ALL TO 'zhangsan'@'localhost';

-- 手动激活角色（如果没设置默认角色）
SET ROLE 'developer_role';
```

```sql
-- 撤销角色
REVOKE 'analyst_role' FROM 'zhangsan'@'localhost';

-- 撤销角色的权限
REVOKE INSERT, UPDATE, DELETE ON shop_db.* FROM 'developer_role';

-- 删除角色
DROP ROLE 'analyst_role';
```

## 17.7 查看权限

```sql
-- 查看当前用户的权限
SHOW GRANTS;

-- 查看指定用户的权限
SHOW GRANTS FOR 'app_user'@'localhost';

-- 查看角色的权限
SHOW GRANTS FOR 'developer_role';
```

## 17.8 安全最佳实践

**最小权限原则：** 只给用户完成工作所需的最少权限。

```sql
-- 反面教材：给应用账号全局DBA权限
GRANT ALL PRIVILEGES ON *.* TO 'app_user'@'%' WITH GRANT OPTION;

-- 正确做法：只给必要的数据库和表权限
GRANT SELECT, INSERT, UPDATE ON shop_db.orders TO 'app_user'@'192.168.1.%';
GRANT SELECT ON shop_db.products TO 'app_user'@'192.168.1.%';
```

**其他安全建议：**

1. **禁止root远程登录**：root只在localhost使用
2. **定期审查权限**：离职员工及时删除账号
3. **使用强密码**：结合validate_password组件强制执行
4. **限制连接来源**：不要用 '%'，指定具体的IP或IP段
5. **应用账号不给FILE权限**：防止读取服务器文件

```sql
-- 检查是否有空密码的用户
SELECT user, host FROM mysql.user WHERE authentication_string = '';

-- 检查是否有过于宽泛的权限
SELECT user, host FROM mysql.user WHERE host = '%';

-- 撤销危险的权限
REVOKE FILE, PROCESS, SUPER ON *.* FROM 'app_user'@'localhost';
```

> [!WARNING] 注意
> FILE权限允许用户读取MySQL服务器上的文件（通过 LOAD DATA INFILE），PROCESS权限允许查看所有用户的查询，SUPER权限允许关闭服务器和修改全局变量。这些权限绝不能给普通应用账号。

## 17.9 审计日志简介

MySQL企业版提供了审计插件（audit log），可以记录所有用户活动。社区版可以使用第三方方案如 MariaDB Audit Plugin：

```sql
-- 安装审计插件（MariaDB Audit Plugin示例）
INSTALL PLUGIN server_audit SONAME 'server_audit.so';

-- 配置审计
SET GLOBAL server_audit_logging = ON;
SET GLOBAL server_audit_events = 'CONNECT,QUERY,TABLE';

-- 查看审计状态
SHOW VARIABLES LIKE 'server_audit%';
```

## 小结

用户管理和权限控制是数据库安全的第一道防线。记住：每个用户都应该有明确的身份（用户名+主机名），每个账号只拥有完成工作所需的最小权限。善用角色(Role)可以大幅简化权限管理。定期审计用户和权限，是运维人员的必修课。
