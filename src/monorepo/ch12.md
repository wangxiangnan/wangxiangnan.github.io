# Ch12：测试策略

## 本章目标

- 在 monorepo 中配置 Vitest 并实现测试共享
- 掌握三个层次的测试：单元测试（shared）、组件测试（Vue）、API 测试（Express）
- 集成端到端测试（Playwright）
- 实现覆盖率收集与汇总
- 利用 Turborepo 只运行受影响的测试

## 12.1 为什么 monorepo 的测试需要特别设计？

在多包项目中，测试面临几个独特挑战：

1. **依赖链影响**：修改 `shared` 包可能影响 `ui`、`web`、`api` 的测试
2. **配置重复**：每个包都需要 Vitest 配置，但大部分配置是相同的
3. **运行效率**：不想每次都运行所有测试，只想运行受影响的
4. **覆盖率汇总**：需要把各个包的覆盖率合并成一份报告

我们将逐一解决这些问题。

## 12.2 Vitest 在 monorepo 中的配置和共享

### 创建共享的 Vitest 配置

在 `packages/` 下创建一个 `vitest-config` 包（或者直接放在根目录的 `configs/` 下）来存放共享配置：

```bash
# 在 monorepo 根目录
mkdir -p packages/vitest-config/src
```

```json
{
  "name": "@monorepo/vitest-config",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "main": "./src/index.ts",
  "types": "./src/index.ts",
  "exports": {
    ".": "./src/index.ts",
    "./vue": "./src/vue.ts",
    "./node": "./src/node.ts"

  "dependencies": {
    "vitest": "^3.0.0",
    "@vue/test-utils": "^2.4.0"
```

**packages/vitest-config/src/node.ts**（Node.js 后端测试配置）：

```typescript
import { defineConfig, mergeConfig } from 'vitest/config';
import { baseConfig } from './index';

const nodeConfig = defineConfig({
  test: {
    environment: 'node',
    include: ['src/**/*.{test,spec}.ts', 'tests/**/*.{test,spec}.ts'],
    // API 测试可能需要更长的超时时间
    testTimeout: 30000,
    // 全局 setup（如数据库连接）
    setupFiles: [],
  },
});

```

> **为什么分成三个配置？** 前端组件测试需要 `jsdom` 环境和 Vue 插件，后端测试需要 `node` 环境和更长的超时时间。共享基础配置避免重复，各自扩展满足不同需求。

## 12.3 单元测试：测试 packages/shared

假设 `packages/shared` 中有以下工具函数：

**packages/shared/src/utils.ts**：

```typescript
/**
 * 格式化价格为带货币符号的字符串
 */
export function formatPrice(amount: number, currency: string = 'CNY'): string {
  if (amount < 0) {
    throw new Error('Price cannot be negative');
  }
  const symbols: Record<string, string> = {
    CNY: '¥',
    USD: '$',
    EUR: '€',
  };
  const symbol = symbols[currency] || currency;
  return `${symbol}${amount.toFixed(2)}`;
}

/**
 * 验证邮箱格式
 */
export function isValidEmail(email: string): boolean {
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  return emailRegex.test(email);
}

/**
 * 将对象中的 undefined 值过滤掉
 */
export function omitUndefined<T extends Record<string, unknown>>(
  obj: T
): Partial<T> {
  return Object.fromEntries(
    Object.entries(obj).filter(([_, value]) => value !== undefined)
  ) as Partial<T>;
}

/**
 * 延迟指定毫秒
 */
export function delay(ms: number): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

/**
 * 重试执行异步函数
 */
export async function retry<T>(
  fn: () => Promise<T>,
  maxAttempts: number = 3,
  delayMs: number = 1000
): Promise<T> {
  let lastError: Error | undefined;
  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    try {
      return await fn();
    } catch (error) {
      lastError = error as Error;
      if (attempt < maxAttempts) {
        await delay(delayMs);
      }
    }
  }
  throw lastError;
}
```

## 12.4 组件测试：Vue 组件的 Vitest + @vue/test-utils

假设 `packages/ui` 中有一个 Button 组件：

**packages/ui/src/components/Button.vue**：

```vue
<template>
  <button
    :class="['btn', `btn-${variant}`, `btn-${size}`, { 'btn-loading': loading }]"
    :disabled="disabled || loading"
    @click="handleClick"
  >
    <span v-if="loading" class="btn-spinner" />
    <slot />
  </button>
</template>

<script setup lang="ts">
interface Props {
  variant?: 'primary' | 'secondary' | 'danger';
  size?: 'sm' | 'md' | 'lg';
  disabled?: boolean;
  loading?: boolean;
}

const props = withDefaults(defineProps<Props>(), {
  variant: 'primary',
  size: 'md',
  disabled: false,
  loading: false,
});

const emit = defineEmits<{
  click: [event: MouseEvent];
}>();

function handleClick(event: MouseEvent) {
  if (!props.disabled && !props.loading) {
    emit('click', event);
  }
}
</script>
```

## 12.5 API 测试：supertest + 共享类型

假设 `apps/api` 中有以下 Express 应用：

**apps/api/src/app.ts**：

```typescript
import express from 'express';
import type { Request, Response } from 'express';
import type { User, ApiResponse } from '@monorepo/shared';

const app = express();
app.use(express.json());

// 模拟用户数据
const users: User[] = [
  { id: '1', name: 'Alice', email: 'alice@example.com' },
  { id: '2', name: 'Bob', email: 'bob@example.com' },
];

// 获取所有用户
app.get('/api/users', (_req: Request, res: Response) => {
  const response: ApiResponse<User[]> = {
    success: true,
    data: users,
  };
  res.json(response);
});

// 获取单个用户
app.get('/api/users/:id', (req: Request, res: Response) => {
  const user = users.find((u) => u.id === req.params.id);
  if (!user) {
    const response: ApiResponse<null> = {
      success: false,
      data: null,
      error: 'User not found',
    };
    res.status(404).json(response);
    return;
  }
  const response: ApiResponse<User> = {
    success: true,
    data: user,
  };
  res.json(response);
});

// 创建用户
app.post('/api/users', (req: Request, res: Response) => {
  const { name, email } = req.body;
  if (!name || !email) {
    const response: ApiResponse<null> = {
      success: false,
      data: null,
      error: 'Name and email are required',
    };
    res.status(400).json(response);
    return;
  }

  const newUser: User = {
    id: String(users.length + 1),
    name,
    email,
  };
  users.push(newUser);

  const response: ApiResponse<User> = {
    success: true,
    data: newUser,
  };
  res.status(201).json(response);
});

export default app;
```

**apps/api/src/app.test.ts**：


> **为什么用 Playwright 而不是 Cypress？** 两者都可以在 monorepo 中使用，但 Playwright 有几个优势：原生支持多浏览器、不需要修改 webpack/vite 配置、`webServer` 配置可以自动启动和关闭依赖服务。在 monorepo 中，这种自动服务管理特别方便。

## 12.7 覆盖率收集与汇总

### 在每个包中配置覆盖率

确保各包的 `vitest.config.ts` 中包含覆盖率配置（已在共享配置中定义）。运行覆盖率测试时：

```bash
# 在单个包中运行覆盖率测试
pnpm --filter @monorepo/shared test -- --coverage

# 或者通过 turbo 运行
turbo run test -- --coverage
```

### 汇总覆盖率报告

在根目录创建一个覆盖率汇总脚本：

**scripts/merge-coverage.ts**：

```typescript
import { execSync } from 'child_process';
import { existsSync, mkdirSync, readdirSync, copyFileSync } from 'fs';
import { join, resolve } from 'path';

const root = resolve(__dirname, '..');
const packagesDir = join(root, 'packages');
const appsDir = join(root, 'apps');
const outputDir = join(root, 'coverage');

// 创建汇总目录
if (!existsSync(outputDir)) {
  mkdirSync(outputDir, { recursive: true });
}

// 收集所有包的覆盖率报告
const dirs = [
  ...readdirSync(packagesDir).map((d) => join(packagesDir, d)),
  ...readdirSync(appsDir).map((d) => join(appsDir, d)),
];

for (const dir of dirs) {
  const coverageDir = join(dir, 'coverage');
  if (existsSync(coverageDir)) {
    const pkgName = require(join(dir, 'package.json')).name.replace(
      /@monorepo\//,
      ''
    );
    const targetDir = join(outputDir, pkgName);
    mkdirSync(targetDir, { recursive: true });

    // 复制覆盖率报告
    const files = readdirSync(coverageDir);
    for (const file of files) {
      copyFileSync(join(coverageDir, file), join(targetDir, file));
    }
    console.log(`✓ Copied coverage from ${pkgName}`);
  }
}

console.log(`\nCoverage reports collected to: ${outputDir}`);
```

## 12.8 Turborepo 与测试任务的配合：只运行受影响的测试

这是 Turborepo 在测试场景下最强大的特性之一。通过正确的配置，Turborepo 可以自动判断哪些测试需要运行：

**turbo.json 中的测试任务配置**：

```json
{
  "tasks": {
    "test": {
      "dependsOn": ["build"],
      "inputs": [
        "src/**",
        "tests/**",
        "__tests__/**",
        "*.test.*",
        "*.spec.*",
        "vitest.config.ts"
      ],
      "outputs": ["coverage/**"]
    }
  }
}
```

**使用 `--filter` 配合 Git 变更**：

```bash
# 只运行受最近提交影响的包的测试
turbo run test --filter="...[HEAD~1]"

# 只运行与 main 分支有差异的包的测试
turbo run test --filter="...[origin/main]"

# 在 PR 的 CI 中，只运行变更涉及的包
turbo run test --filter="...[origin/$GITHUB_BASE_REF]"
```

**实际效果**：

```bash
# 假设你只修改了 packages/shared/src/utils.ts
$ turbo run test --filter="...[origin/main]"

# Turborepo 分析出以下包受影响：
# - @monorepo/shared（直接修改）
# - @monorepo/ui（依赖 shared）
# - @monorepo/web（依赖 shared 和 ui）
# - @monorepo/api（依赖 shared）
# 但不会运行 @monorepo/database 的测试（不依赖 shared）
```

这在大型 monorepo 中可以大幅缩短 CI 时间。一个 20 包的 monorepo，如果只改了 1 个底层包，可能只需要运行 5 个包的测试而不是全部 20 个。

## 本章小结

1. **共享配置**：通过 `@monorepo/vitest-config` 包共享 Vitest 基础配置，各包只需导入并扩展
2. **三个测试层次**：
   - 单元测试（shared）：测试纯函数和工具方法
   - 组件测试（ui）：用 `@vue/test-utils` 测试 Vue 组件的行为
   - API 测试（api）：用 `supertest` 测试 HTTP 端点
3. **E2E 测试**：Playwright 作为独立 app，自动启动依赖服务
4. **覆盖率**：各包独立生成，通过脚本汇总
5. **智能运行**：Turborepo 结合 Git diff 只运行受影响的测试
