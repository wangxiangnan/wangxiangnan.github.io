## 贯穿项目：DocMind

全书不写零散的 Demo，而是用一个贯穿始终的实战项目驱动学习：**DocMind——智能文档问答助手**。设定很具体：你手上有一个 **1247 篇技术文档**的文档库（**Markdown 与 PDF** 两种格式），希望用自然语言提问，让 Agent 自己检索相关内容、组织出答案。技术选型全书固定：LangChain 负责组件编排，LangGraph 负责推理流程控制，底层模型统一用 **deepseek-chat**。

全书还给 DocMind 定了一个硬指标：**首字延迟小于 1 秒**。这几个数字——1247 篇文档、两种格式、一个模型、一秒首字——是全书反复出现的锚点：分词为什么影响成本（ch03）、检索怎么提速（ch23）、评估怎么量化（ch26）、部署怎么压延迟（ch28），都围绕它们展开。

随着教程推进，DocMind 分四个阶段逐步长出能力：

| 阶段 | 章节 | 能力 |
| ------ | ------ | ------ |
| 认知基础 | ch01-ch09 | 理解 Agent 与 LLM，掌握 Token、Embedding、注意力等大脑原理，会用 Prompt 与推理策略，看懂 Agent 架构全景 |
| 开发基础 | ch10-ch15 | 搭好环境，掌握 LCEL、Model I/O、Prompt 模板、Memory、Tools 五件套 |
| 推理引擎 | ch16-ch21 | ReAct 循环 + Function Calling + LangGraph 状态图，加上持久化与 Human-in-the-Loop，DocMind 的推理引擎成型 |
| 生产实战 | ch22-ch28 | 接入文档库与 RAG、开发自定义 Tool、引入多 Agent 协作，最后完成评估、安全加固与生产部署 |

每个阶段结束时，DocMind 都是一个能实际运行的系统，区别只在能力的边界——这让每一章的学习成果都立即可见。

## 心智模型

### 核心模型：Agent 是一个有状态的对象

在写第一行 LangChain 代码之前，先用你每天都在用的编程概念给 Agent 建模——**Agent（智能体）就是一个有状态的对象（stateful object）**：

```python
class Agent:
    """对象模型视角下的 Agent 本质"""

    def __init__(self):
        # 状态 (State)
        self.messages = []           # 对话历史
        self.memory = {}             # 长期记忆
        self.tools = {}              # 可用方法（工具）
        self.context = ""            # 当前上下文

    def run(self, user_input: str) -> str:
        """主方法：接收输入，循环处理，输出结果"""

        # 1. 把用户输入加入状态
        self.messages.append({"role": "user", "content": user_input})

        # 2. 循环：思考 → 行动 → 观察
        while True:
            # 思考：LLM 决定下一步该做什么
            thought = self.think()

            # 判断：是否需要调用方法（工具）？
            if thought.needs_tool:
                # 行动：调用已有方法，更新状态
                result = self.call_tool(thought.tool_name, thought.tool_args)
                self.messages.append({"role": "tool", "content": result})
                # 继续循环（带着工具结果再思考）
            else:
                # 输出：LLM 决定给出最终回答
                return thought.final_answer

    def think(self):
        """LLM 推理——本质上就是一个函数调用"""
        # 把当前所有状态（消息 + 记忆 + 工具列表）打包给 LLM
        # LLM 返回：要么"调用工具X"，要么"给出最终答案"
        return llm.chat(self.messages, self.tools)

    def call_tool(self, name, args):
        """调用已有方法——就是对象的方法调用"""
        return self.tools[name](**args)
```

这段代码不是玩具——ch19 里用 LangGraph 写出的 DocMind 推理引擎，骨架和它一模一样。它抓住了 Agent 的三个本质特征：

**封装**——Agent 内部的状态（对话历史、记忆、工具结果）对外部是不可见的。用户只看到输入和输出，不知道中间循环了几次、调了哪些工具。这跟对象的封装一模一样。

**消息驱动**——`run()` 方法被调用后，内部通过方法调用链（`think()` → `call_tool()` → `think()` → ...）自动运转，直到返回结果。Agent 也是：收到用户消息后，内部自动循环推理和行动，直到生成回答。

**状态可变**——每次循环都更新内部状态（新的工具结果、新的消息），下次思考基于更新后的状态。这跟有状态对象的行为完全一致。

一句话：**Agent 就是一个有状态的对象，它的"方法"是工具，它的"决策逻辑"是 LLM，它的"主循环"是 ReAct 循环。** 所有的框架（LangChain、LangGraph）都是在帮你更优雅地写这个"对象"而已。

这个类比还能直接映射到全书的主线框架 LangGraph 上：

```txt
你的类比              LangGraph 的实现
─────────────────────────────────────
对象的状态            State (TypedDict)
对象的方法            Node (函数)
用户输入              START 节点的输入
循环                  条件边 → 回到之前的 Node
判断                  Conditional Edge (if 走哪条边)
处理状态              每个 Node 读取 State、更新 State
输出结果              END 节点的输出
```

LangGraph 的 StateGraph 本质上就是"对象"，只不过它把状态流转用图（Graph）而不是 while 循环来表达——因为图比循环更灵活（可以分支、可以并行、可以回退）。核心思想完全一致，从 ch18 起你会反复见到这套对应关系。

### 易混概念对照表

这些概念贯穿全书，也最容易混。先各给一句区分要点，正文对应章会展开：

| 易混概念 | 一句话区分 | 详见 |
| ------ | ------ | ------ |
| LLM vs Agent | LLM 只负责"给定输入生成文本"；Agent 围绕 LLM 加上状态、工具和循环，让它能自主多步完成任务 | ch02 / ch01 |
| Token vs 词 | Token（词元）是模型实际处理的最小单位，一个英文单词可能被切成多个 Token，一个汉字也可能被拆开，和"词"不是一一对应 | ch03 |
| Embedding vs 全文检索 | 全文检索匹配的是"字面重不重合"，Embedding（嵌入向量）匹配的是"语义相不相似"——换了说法也能搜到 | ch04 |
| Memory vs Checkpointer | Memory（记忆）管单次会话内的上下文；Checkpointer（检查点器）把每一步状态落盘，重启、回溯、跨会话都靠它 | ch14 / ch20 |
| LangChain vs LangGraph | LangChain 提供组件和声明式编排语法（LCEL）；LangGraph 用状态图管理循环与分支，复杂 Agent 的骨架在 LangGraph | ch11 / ch18 |
| ReAct vs Function Calling | Function Calling（函数调用）是模型"说要调哪个工具"的通信协议；ReAct 是把思考、行动、观察串成闭环的执行范式 | ch17 / ch16 |

### 学习路径建议

- **有 LLM API 经验（调过 chat 接口、写过 Prompt）**：Part 1-3 可以快读、当手册查，直接从 ch10 起读——先按 ch10 到 ch15 补齐 LangChain 基本功，再进入 Part 5 的核心范式。
- **后端工程师、目标直指生产**：主线抓 ch16-ch21（LangGraph 编排）和 ch26-ch28（评估、安全、部署），RAG 相关的 ch22-ch23 与多 Agent 的 ch25 按项目需要穿插，原理篇 ch03-ch06 可后置到遇到问题时回查。

### 赛车手比喻：七个 Part 的完整旅程

把七个 Part 想象成把一个普通人培养成顶级赛车手的完整过程：

**Part 1 认知觉醒：看懂比赛**。理论课。先搞清楚赛车和家用车的区别（什么是 Agent），发动机为什么会转（LLM）。不上车，先明白车为什么能跑。

**Part 2 大脑原理：拆开发动机**。把引擎拆开看内部：燃油分子怎么计量（Token），油品怎么按特性归类（Embedding），点火正时怎么协调（注意力），发动机总成怎么组装（Transformer Block）。看不懂发动机，后面的调校就无从谈起。

**Part 3 提示与推理：学会跟车队沟通**。比赛不是一个人在开——你得会给工程师写清楚需求文档（Prompt Engineering），听得懂调度台的战术指令（推理策略），心里装着整辆车的构造图（Agent 架构）。

**Part 4 装备升级：考驾照**。熟悉仪表盘：油门在哪（Model I/O），刹车在哪（Tools），方向盘怎么握（Prompt 模板），后视镜怎么看（Memory）。能开动，但只敢在直线龟速行驶。

**Part 5 核心范式：职业车手的跟趾动作与漂移**。掌握在弯道中动态控制车身（ReAct 循环），听懂车载电台的对话协议（Function Calling），看懂赛道全图并规划路线（LangGraph），进站维修不丢圈速（持久化），失控时让领航员接管（Human-in-the-Loop）。这是赛车手和普通司机的分水岭。

**Part 6 进阶实战：拉力赛**。真实路况远比训练场复杂——学会让导航员帮你读路书（RAG 读文档），给自己打造专属工具箱（自定义 Tool），一个人忙不过来时组车队（多 Agent 系统）。

**Part 7 生产上线：正式参赛**。计时圈要跑出成绩（评估与测试），比赛有安全条例（Prompt 注入与权限管控），赛车要过年检、后勤要跟上（生产部署）。不只是自己开得快，还要经得起赛会的检验。

总结一句：**认知决定你看不看得透，原理决定你懂不懂车，策略决定你会不会调度，装备决定你写不写得动，范式决定你控不控得住，实战决定你强不强大，生产决定你落不落得地。**

这七个词串起来，就是一名 AI 应用工程师从"听别人说"到"自己动手造"再到"扛住生产压力"的完整心路历程，也正是本书七个 Part 的展开顺序。
