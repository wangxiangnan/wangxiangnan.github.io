# 第23章：微服务架构——从单体到分布式

## 引言：当你的"全能选手"变成了"臃肿怪物"

还记得你的应用刚开始时的样子吗？一个`app.js`搞定一切，简单、美丽、高效。

然后需求来了：用户系统、商品管理、订单处理、支付对接、库存管理、物流跟踪、消息推送、数据分析... 你的`app.js`变成了5000行的"意大利面条代码"，每次改一个小功能都像是在做心脏手术——牵一发而动全身。

每次部署都像在拆炸弹："改了订单模块的代码，会不会影响支付模块？"

这时候，微服务架构就像是把一个巨型工厂拆分成多个专业车间——每个车间独立运作，专注做一件事，通过标准化的"传送带"（API/消息队列）协作。

但请注意：**微服务不是银弹**。它解决了一些问题，但也引入了新的复杂性。让我们来深入了解。

---

## 23.1 单体 vs 微服务：什么时候该拆分

### 23.1.1 决策矩阵

```
你应该用微服务吗？

团队规模 < 5人？          → 大概率不需要，单体就够了
代码库 < 10万行？         → 大概率不需要
部署频率 < 每天一次？      → 大概率不需要
不同模块的扩展需求差异大？  → 可以考虑
需要使用不同技术栈？       → 可以考虑
组织架构已经按领域划分？    → 可以考虑

全部满足"可以考虑" → 微服务可能适合你
否则 → 先用模块化单体(Modular Monolith)
```

import { EventEmitter } from 'node:events';

type EventMap = {
  'user.created': { userId: number; email: string };
  'order.placed': { orderId: number; userId: number; amount: number };
  'order.paid': { orderId: number; paymentId: string };
  'product.stock_low': { productId: number; currentStock: number };
};

class InternalEventBus {
  private emitter = new EventEmitter();

  emit<K extends keyof EventMap>(event: K, data: EventMap[K]): void {
    this.emitter.emit(event, data);
  }

  on<K extends keyof EventMap>(event: K, handler: (data: EventMap[K]) => void): void {
    this.emitter.on(event, handler);
  }

  off<K extends keyof EventMap>(event: K, handler: (data: EventMap[K]) => void): void {
    this.emitter.off(event, handler);
  }
}

### 23.2.1 HTTP/REST调用

```typescript
// services/http-client.ts - 带重试和超时的HTTP客户端
interface RequestOptions {
  method?: string;
  headers?: Record<string, string>;
  body?: unknown;
  timeout?: number;
  retries?: number;
  retryDelay?: number;
}

interface ServiceConfig {
  baseUrl: string;
  timeout: number;
  headers?: Record<string, string>;
}

class ServiceClient {
  private config: ServiceConfig;

  constructor(config: ServiceConfig) {
    this.config = config;
  }

  async request<T>(path: string, options: RequestOptions = {}): Promise<T> {
    const {
      method = 'GET',
      headers = {},
      body,
      timeout = this.config.timeout,
      retries = 3,
      retryDelay = 1000,
    } = options;

    const url = `${this.config.baseUrl}${path}`;
    
    for (let attempt = 0; attempt <= retries; attempt++) {
      try {
        const controller = new AbortController();
        const timer = setTimeout(() => controller.abort(), timeout);

        const response = await fetch(url, {
          method,
          headers: {
            'Content-Type': 'application/json',
            ...this.config.headers,
            ...headers,
          },
          body: body ? JSON.stringify(body) : undefined,
          signal: controller.signal,
        });

        clearTimeout(timer);

        if (!response.ok) {
          const error = await response.text();
          throw new Error(`HTTP ${response.status}: ${error}`);
        }

        return await response.json() as T;
      } catch (error) {
        if (attempt === retries) throw error;
        
        // 指数退避
        const delay = retryDelay * Math.pow(2, attempt);
        console.warn(`Request failed (attempt ${attempt + 1}/${retries + 1}), retrying in ${delay}ms...`);
        await new Promise(r => setTimeout(r, delay));
      }
    }

    throw new Error('Unreachable');
  }

  get<T>(path: string, options?: RequestOptions): Promise<T> {
    return this.request<T>(path, { ...options, method: 'GET' });
  }

  post<T>(path: string, body: unknown, options?: RequestOptions): Promise<T> {
    return this.request<T>(path, { ...options, method: 'POST', body });
  }

  put<T>(path: string, body: unknown, options?: RequestOptions): Promise<T> {
    return this.request<T>(path, { ...options, method: 'PUT', body });
  }

  delete<T>(path: string, options?: RequestOptions): Promise<T> {
    return this.request<T>(path, { ...options, method: 'DELETE' });
  }
}

// 服务注册表
const services = {
  user: new ServiceClient({ 
    baseUrl: process.env.USER_SERVICE_URL || 'http://localhost:3001',
    timeout: 5000,
  }),
  order: new ServiceClient({ 
    baseUrl: process.env.ORDER_SERVICE_URL || 'http://localhost:3002',
    timeout: 10000,
  }),
  product: new ServiceClient({ 
    baseUrl: process.env.PRODUCT_SERVICE_URL || 'http://localhost:3003',
    timeout: 5000,
  }),
};

export { services, ServiceClient };
```

        name: `${role} User ${count}`,
        email: `${role}${count}@test.com`,

      count++;

## 23.3 断路器模式（Circuit Breaker）

```typescript
// patterns/circuit-breaker.ts

enum CircuitState {
  CLOSED = 'CLOSED',     // 正常状态，请求正常通过
  OPEN = 'OPEN',         // 熔断状态，请求直接失败
  HALF_OPEN = 'HALF_OPEN', // 半开状态，允许部分请求试探
}

interface CircuitBreakerOptions {
  failureThreshold: number;   // 失败次数阈值
  successThreshold: number;   // 半开状态下成功次数阈值
  timeout: number;            // 熔断持续时间(ms)
  monitorInterval?: number;   // 监控间隔(ms)
}

class CircuitBreaker {
  private state: CircuitState = CircuitState.CLOSED;
  private failureCount = 0;
  private successCount = 0;
  private lastFailureTime = 0;
  private options: CircuitBreakerOptions;
  private name: string;

  constructor(name: string, options: CircuitBreakerOptions) {
    this.name = name;
    this.options = options;
  }

  async execute<T>(fn: () => Promise<T>, fallback?: () => T | Promise<T>): Promise<T> {
    if (this.state === CircuitState.OPEN) {
      // 检查是否可以进入半开状态
      if (Date.now() - this.lastFailureTime >= this.options.timeout) {
        this.state = CircuitState.HALF_OPEN;
        console.log(`[CircuitBreaker:${this.name}] State: OPEN → HALF_OPEN`);
      } else {
        // 熔断中，执行降级
        if (fallback) return fallback();
        throw new Error(`Circuit breaker [${this.name}] is OPEN`);
      }
    }

    try {
      const result = await fn();
      this.onSuccess();
      return result;
    } catch (error) {
      this.onFailure();
      if (fallback) return fallback();
      throw error;
    }
  }

  private onSuccess(): void {
    if (this.state === CircuitState.HALF_OPEN) {
      this.successCount++;
      if (this.successCount >= this.options.successThreshold) {
        this.state = CircuitState.CLOSED;
        this.failureCount = 0;
        this.successCount = 0;
        console.log(`[CircuitBreaker:${this.name}] State: HALF_OPEN → CLOSED`);
      }
    } else {
      this.failureCount = 0; // 重置失败计数
    }
  }

  private onFailure(): void {
    this.failureCount++;
    this.lastFailureTime = Date.now();
    
    if (this.failureCount >= this.options.failureThreshold) {
      this.state = CircuitState.OPEN;
      console.log(`[CircuitBreaker:${this.name}] State: → OPEN (failures: ${this.failureCount})`);
    }
  }

  getState(): { state: CircuitState; failures: number; successes: number } {
    return { state: this.state, failures: this.failureCount, successes: this.successCount };
  }
}

// 使用示例
const paymentBreaker = new CircuitBreaker('payment-service', {
  failureThreshold: 5,    // 连续5次失败则熔断
  successThreshold: 3,    // 半开状态下3次成功则恢复
  timeout: 30000,         // 熔断30秒后尝试恢复
});

async function processPayment(orderId: number, amount: number) {
  return paymentBreaker.execute(
    // 正常逻辑
    async () => {
      const result = await fetch('http://payment-service/pay', {
        method: 'POST',
        body: JSON.stringify({ orderId, amount }),
      });
      if (!result.ok) throw new Error(`Payment failed: ${result.status}`);
      return result.json();
    },
    // 降级逻辑
    async () => {
      // 支付服务不可用时，将订单放入待处理队列
      await orderQueue.add('retry-payment', { orderId, amount });
      return { status: 'pending', message: 'Payment queued for retry' };
    }
  );
}

export { CircuitBreaker, CircuitState };
```

## 23.4 分布式事务：Saga模式

```typescript
// patterns/saga.ts
// Saga模式：通过补偿事务来实现分布式事务

interface SagaStep<T = unknown> {
  name: string;
  execute: (context: T) => Promise<unknown>;
  compensate: (context: T) => Promise<void>;
}

class SagaOrchestrator<T extends Record<string, unknown>> {
  private steps: SagaStep<T>[] = [];
  private completedSteps: SagaStep<T>[] = [];

  addStep(step: SagaStep<T>): this {
    this.steps.push(step);
    return this;
  }

  async execute(context: T): Promise<{ success: boolean; results: unknown[]; error?: string }> {
    const results: unknown[] = [];
    this.completedSteps = [];

    for (const step of this.steps) {
      try {
        console.log(`[Saga] Executing step: ${step.name}`);
        const result = await step.execute(context);
        results.push(result);
        this.completedSteps.push(step);
      } catch (error) {
        console.error(`[Saga] Step "${step.name}" failed:`, error);
        
        // 执行补偿（逆序）
        await this.compensate(context);
        
        return {
          success: false,
          results,
          error: error instanceof Error ? error.message : 'Unknown error',
        };
      }
    }

    return { success: true, results };
  }

  private async compensate(context: T): Promise<void> {
    console.log(`[Saga] Starting compensation for ${this.completedSteps.length} steps...`);
    
    // 逆序执行补偿
    for (const step of [...this.completedSteps].reverse()) {
      try {
        console.log(`[Saga] Compensating: ${step.name}`);
        await step.compensate(context);
      } catch (error) {
        // 补偿失败是严重问题，需要人工介入
        console.error(`[Saga] CRITICAL: Compensation failed for "${step.name}":`, error);
        // 这里应该发告警、记日志
      }
    }
  }
}

// 实战：电商下单Saga
interface OrderContext {
  userId: number;
  orderId?: number;
  productId: number;
  quantity: number;
  amount: number;
  paymentId?: string;
  reservationId?: string;
}

const createOrderSaga = new SagaOrchestrator<OrderContext>()
  // 步骤1：创建订单
  .addStep({
    name: 'create-order',
    async execute(ctx) {
      const order = await services.order.post('/orders', {
        userId: ctx.userId, productId: ctx.productId, quantity: ctx.quantity, amount: ctx.amount,
      });
      ctx.orderId = (order as any).id;
      return order;
    },
    async compensate(ctx) {
      if (ctx.orderId) {
        await services.order.put(`/orders/${ctx.orderId}/cancel`, {});
      }
    },
  })
  // 步骤2：预扣库存
  .addStep({
    name: 'reserve-stock',
    async execute(ctx) {
      const reservation = await services.product.post('/products/reserve', {
        productId: ctx.productId, quantity: ctx.quantity,
      });
      ctx.reservationId = (reservation as any).id;
      return reservation;
    },
    async compensate(ctx) {
      if (ctx.reservationId) {
        await services.product.post('/products/release', { reservationId: ctx.reservationId });
      }
    },
  })
  // 步骤3：扣款
  .addStep({
    name: 'process-payment',
    async execute(ctx) {
      const payment = await services.user.post('/payments', {
        userId: ctx.userId, amount: ctx.amount, orderId: ctx.orderId,
      });
      ctx.paymentId = (payment as any).id;
      return payment;
    },
    async compensate(ctx) {
      if (ctx.paymentId) {
        await services.user.post('/payments/refund', { paymentId: ctx.paymentId });
      }
    },
  });

// 使用
async function placeOrder(userId: number, productId: number, quantity: number, amount: number) {
  const result = await createOrderSaga.execute({
    userId, productId, quantity, amount,
  });
  
  if (!result.success) {
    throw new Error(`Order failed: ${result.error}. All changes have been rolled back.`);
  }
  
  return result.results;
}

// 这里services是前面定义的ServiceClient实例
const services = {
  order: { post: async (path: string, body: any) => ({ id: 1 }), put: async (path: string, body: any) => ({}) },
  product: { post: async (path: string, body: any) => ({ id: 1 }) },
  user: { post: async (path: string, body: any) => ({ id: 1 }) },
};

export { SagaOrchestrator, createOrderSaga, placeOrder };
```

// tracing/custom-spans.ts
import { trace, SpanKind, SpanStatusCode } from '@opentelemetry/api';

const tracer = trace.getTracer('my-service');

// 创建自定义Span追踪业务逻辑
async function processOrder(orderId: number): Promise<void> {
  // 创建一个Span
  await tracer.startActiveSpan('processOrder', {
    kind: SpanKind.INTERNAL,
    attributes: { 'order.id': orderId },
  }, async (span) => {
    try {
      // 子Span：验证订单
      await tracer.startActiveSpan('validateOrder', async (validateSpan) => {
        // 验证逻辑...
        validateSpan.setAttribute('order.valid', true);
        validateSpan.end();
      });

      // 子Span：处理支付
      await tracer.startActiveSpan('processPayment', {
        attributes: { 'payment.method': 'credit_card' },
      }, async (paymentSpan) => {
        // 支付逻辑...
        paymentSpan.addEvent('payment_initiated');
        await new Promise(r => setTimeout(r, 100));
        paymentSpan.addEvent('payment_completed');
        paymentSpan.end();
      });

      span.setStatus({ code: SpanStatusCode.OK });
    } catch (error) {
      span.setStatus({
        code: SpanStatusCode.ERROR,
        message: error instanceof Error ? error.message : 'Unknown error',
      });
      span.recordException(error as Error);
      throw error;
    } finally {
      span.end();
    }
  });
}

export { processOrder };

## 23.7 常见坑点

### 坑点1：分布式系统的谬误

```typescript
// 八大谬误（你以为的 vs 现实）：
// 1. 网络是可靠的          → 网络随时会断
// 2. 延迟为零             → 延迟不可预测
// 3. 带宽是无限的          → 带宽有限
// 4. 网络是安全的          → 处处有风险
// 5. 拓扑不会变            → 服务随时上下线
// 6. 只有一个管理员        → 多人多团队维护
// 7. 传输成本为零          → 序列化/网络有开销
// 8. 网络是同质的          → 多种协议和设备

// 结论：任何远程调用都要考虑超时、重试、降级！
```
