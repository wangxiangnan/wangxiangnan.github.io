## 21.1 中断机制：interrupt_before与interrupt_after

在第16-20章里，Agent始终完全自主运行——它自己决定调用什么工具、怎么回答。但有些情况你必须能"踩一脚刹车"：

- **高风险操作**：Agent要删除一个文件、发送一封邮件、执行一笔交易——你确定不需要人类确认一下？
- **质量审查**：Agent生成了法律文档或医疗建议——你敢不经审核就发出去？
- **权限控制**：Agent想访问敏感数据——当前用户有这个权限吗？
- **纠偏**：Agent的推理走偏了——人类想中途纠正它

这种"人类审批"模式在LangGraph中有原生支持，叫做**中断机制（Interrupt）**。编译图时用两个参数声明在哪里暂停：

```python
# interrupt_before：在指定节点执行前暂停
# 适合：在执行前审查Agent的计划
app = graph.compile(
    interrupt_before=["tools"]  # 在执行工具之前暂停
)

# interrupt_after：在指定节点执行后暂停
# 适合：在执行后审查结果
app = graph.compile(
    interrupt_after=["agent"]  # Agent回复后暂停
)
```

| 参数 | 暂停时机 | 适合审查什么 |
| ---- | ---- | ---- |
| interrupt_before=["tools"] | 工具执行前 | Agent的行动计划：要调什么工具、参数对不对 |
| interrupt_after=["agent"] | Agent节点执行后 | Agent的产出：回复内容或tool_calls |

### 21.1.1 工作流程

```text
正常流程：  START -> agent -> tools -> agent -> END

interrupt_before=["tools"]时：
  START -> agent -> [暂停，等待人类确认] -> tools -> agent -> END
  
  人类可以：
  1. 批准（approve）-> 继续执行tools
  2. 拒绝（reject）  -> 修改状态后重新规划
  3. 修改（edit）    -> 改变工具参数后继续
```

> [!NOTE] 新版LangGraph的函数式中断API interrupt()
> 新版本还提供了函数式的`interrupt()` API（`from langgraph.types import interrupt, Command`），配合checkpointer可以在节点内部直接"抛出"一个中断，等待人类输入后带着结果恢复执行。本章讲解的`interrupt_before`是经典的图结构方式，两者思路一致：都在某个边界暂停图、等待人类决策、再恢复执行。掌握本章机制后，迁移到`interrupt()`会非常自然。

## 21.2 审批模式实现

让我们实现一个审批模式——Agent在执行敏感操作前需要人类确认。完整图在agent与tools之外多出两个节点：check（敏感度检查）与wait_approval（等待审批的占位节点）。与第19章的两节点图相比，差异集中在三处，逐个看。

第一处差异在State——多了两个审批字段：

```python
class ApprovalState(TypedDict):
    messages: Annotated[list, add_messages]
    pending_approval: bool    # 是否有待审批的敏感操作
    review_decision: str      # 人类的决定："approved" / "rejected"
```

第二处差异是check节点——把Agent请求的工具调用分成"敏感"与"安全"两堆：

```python
SENSITIVE_TOOLS = {"send_email", "delete_document"}   # 高风险：必须审批
SAFE_TOOLS = {"search_documents"}                     # 安全：自动通过

def check_sensitivity(state: ApprovalState) -> dict:
    """检查Agent请求的工具调用里有没有敏感操作"""
    last_message = state["messages"][-1]
    calls = getattr(last_message, "tool_calls", [])
    needs = any(tc["name"] in SENSITIVE_TOOLS for tc in calls)
    return {"pending_approval": needs}
```

第三处差异是wait_approval占位节点加编译期中断声明：

```python
def wait_approval(state: ApprovalState) -> dict:
    """占位节点：interrupt_before会让图在进入它之前暂停。

    人类通过update_state写入review_decision后，图从这里恢复：
    - approved：不做额外操作，由条件边路由到execute执行工具
    - rejected：给最后一条AI消息里悬空的tool_calls补上拒绝ToolMessage，
      再路由回agent重新规划（不补的话，下次调LLM会协议报错）
    """
    if state.get("review_decision") == "rejected":
        last_ai = next(
            m for m in reversed(state["messages"]) if isinstance(m, AIMessage)
        )
        rejections = [
            ToolMessage(
                content="用户拒绝了该操作，工具未执行。请调整方案或改用其他方式。",
                tool_call_id=tc["id"],
                name=tc["name"],
            )
            for tc in last_ai.tool_calls
        ]
        return {"messages": rejections, "pending_approval": False}
    return {"pending_approval": False}
```

拼装时要注意一个关键设计：**wait_approval之后不能直连END，必须用条件边分流**——批准走execute，拒绝回agent。否则批准之后工具永远没机会执行，闭环走不通：

```python
graph.add_node("agent", agent_node)          # 与第19章一致，此处不展开
graph.add_node("check", check_sensitivity)
graph.add_node("execute", execute_tools)     # 与第19章的ToolNode同职责
graph.add_node("wait_approval", wait_approval)

graph.add_edge(START, "agent")
graph.add_conditional_edges("agent", route_after_agent)   # 有tool_calls走check，否则END
graph.add_conditional_edges("check", route_after_check)   # 需审批走wait_approval，否则execute
graph.add_edge("execute", "agent")
graph.add_conditional_edges("wait_approval", route_after_review, {
    "approved": "execute",     # 批准 -> 真正执行工具
    "rejected": "agent",       # 拒绝 -> 回到Agent重新规划
})

app = graph.compile(
    checkpointer=MemorySaver(),          # 中断恢复的前提
    interrupt_before=["wait_approval"],  # 在等待审批前暂停
)
```

三个路由函数（route_after_agent、route_after_check、route_after_review）都只是"读状态、返回节点名"的一行逻辑，完整定义见 21.5。人类侧的恢复永远是同一套四步——invoke触发并暂停，get_state确认暂停点，update_state写入决定，invoke(None)从断点恢复：

```python
config = {"configurable": {"thread_id": "approval-demo-1"}}
app.invoke(
    {"messages": [HumanMessage(content="给zhangsan@example.com发封邮件，主题是项目进度")],
     "pending_approval": False, "review_decision": ""},
    config=config,
)
# 图在wait_approval前暂停

state = app.get_state(config)
print(state.next)        # ('wait_approval',) —— 正在等人表态

app.update_state(config, {"review_decision": "approved"})
result = app.invoke(None, config=config)   # 从断点恢复，工具这才真正执行
```

以上是机制骨架。补全工具定义、agent与execute两个节点的实现以及交互式审批循环，就是 21.5 的DocMind实操——那里的代码可直接运行，本节不再重复。

## 21.3 状态修改（Edit State）

Human-in-the-Loop不只是"批准/拒绝"——人类能做的有三件事：

| 介入方式 | 人类做什么 | 实现手段 |
| ---- | ---- | ---- |
| 批准（Approve） | 确认执行 | update_state 写入 approved，再 invoke(None) 恢复 |
| 拒绝（Reject） | 否决并说明原因 | 回填拒绝ToolMessage，路由回agent重新规划 |
| 修改（Edit） | 纠正参数或补充上下文 | update_state 注入HumanMessage |

第三种"修改"值得单独演示——人类可以**修改Agent的中间状态**：

```python
"""
状态修改：人类纠正Agent的中间结果
"""

def demo_state_editing():
    """演示状态修改"""
    
    app = build_approval_graph()   # 21.2 的碎片拼装成的审批图（可运行版见 21.5）
    config = {"configurable": {"thread_id": "edit-demo-1"}}
    
    # Agent想要搜索"Agent"但搜索词太模糊
    print("--- Agent搜索'Agent' ---")
    result = app.invoke(
        {"messages": [HumanMessage(content="搜索Agent相关内容")],
         "pending_approval": False, "review_decision": ""},
        config=config
    )
    
    # 获取当前状态
    current_state = app.get_state(config)
    print(f"\n当前消息数: {len(current_state.values['messages'])}")
    
    # 修改状态：注入一条额外的上下文
    app.update_state(config, {
        "messages": [HumanMessage(
            content="补充信息：我说的Agent是指AI Agent，不是普通代理人。请搜索'AI Agent architecture'。"
        )]
    })
    
    # 继续执行，Agent会看到新的上下文
    result = app.invoke(None, config=config)
    print(f"\nAgent的改进回答: {result['messages'][-1].content[:200]}")
```

### 21.3.1 状态修改的常见用途

```python
# 1. 修改工具参数
# Agent想删除doc_001，但人类说应该删除doc_002
app.update_state(config, {
    "messages": [HumanMessage(content="请删除doc_002而不是doc_001")]
})

# 2. 注入额外上下文
# Agent缺少某个信息，人类补充
app.update_state(config, {
    "messages": [HumanMessage(content="补充：这个项目的截止日期是下周五")]
})

# 3. 撤销上一步操作
# Agent做错了，人类想回退
# （更完整的回退功能见第20章Checkpointer的时间旅行）
```

## 21.4 断点(Breakpoint)的使用

断点（Breakpoint）是调试Agent的强大工具——就像IDE里的断点一样，让图在指定位置暂停：

```python
"""
断点调试：逐步执行Agent图
"""

def demo_breakpoint_debugging():
    """使用断点调试Agent"""
    
    # 编译时设置中断点
    # 注意：interrupt_before只能在compile()时指定，编译后无法动态修改；
    # 如需运行时动态控制中断，请用条件路由配合状态字段来实现
    app = build_approval_graph()
    
    config = {"configurable": {"thread_id": "debug-demo"}}
    
    # 第一次执行——会在第一个中断点暂停
    print("--- 开始执行 ---")
    result = app.invoke(
        {"messages": [HumanMessage(content="搜索RAG文档，然后发邮件给boss汇报进度")],
         "pending_approval": False, "review_decision": ""},
        config=config
    )
    
    # 查看当前状态
    state = app.get_state(config)
    print(f"\n当前在哪个节点暂停: {state.next}")
    print(f"消息历史: {len(state.values['messages'])} 条")
    
    # 继续执行到下一个中断点
    print("\n--- 继续执行 ---")
    result = app.invoke(None, config=config)
    
    state = app.get_state(config)
    print(f"下一个暂停点: {state.next}")
    
    # 再次继续
    print("\n--- 再次继续 ---")
    result = app.invoke(None, config=config)
    
    print(f"\n最终回答: {result['messages'][-1].content[:200]}")
```

## 21.5 实操：为DocMind添加人类审核环节

本节是本章唯一的完整实现——21.2 的机制骨架在这里全部落地，还多了交互式循环与"m=修改"分支。让我们把所有Human-in-the-Loop的知识应用到DocMind项目中：

```python
"""
DocMind with Human-in-the-Loop
为DocMind添加人类审核：
- 删除操作需确认
- 敏感信息过滤
- 外部操作（发邮件、调API）需审批
"""
from typing import TypedDict, Annotated, Literal
import json
import re

from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.checkpoint.memory import MemorySaver
from langchain_core.messages import (
    HumanMessage, AIMessage, SystemMessage, ToolMessage
)
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI


# ============================================================
# 工具定义
# ============================================================

@tool
def search_documents(query: str, top_k: int = 3) -> str:
    """搜索文档知识库。安全操作，无需审批。
    
    Args:
        query: 搜索关键词
        top_k: 返回结果数
    """
    return f"找到关于'{query}'的{top_k}条结果：\n1. AI Agent架构概述...\n2. RAG技术详解...\n3. LangGraph实战..."


@tool
def delete_document(doc_id: str, reason: str = "") -> str:
    """删除指定文档。高风险操作！需要用户确认。
    
    Args:
        doc_id: 文档ID
        reason: 删除原因
    """
    return f"文档 {doc_id} 已删除。原因：{reason}"


@tool
def export_report(query: str, format: str = "pdf") -> str:
    """导出分析报告。涉及外部操作，需要确认。
    
    Args:
        query: 报告主题
        format: 导出格式 (pdf/csv/json)
    """
    return f"报告已导出为{format}格式：report_{query}.{format}"


@tool
def notify_admin(message: str, priority: str = "normal") -> str:
    """向管理员发送通知。需要确认。
    
    Args:
        message: 通知内容
        priority: 优先级 (low/normal/high/critical)
    """
    return f"通知已发送（优先级:{priority}）: {message}"


# 工具分类
SAFE_TOOLS = {"search_documents"}
SENSITIVE_TOOLS = {"delete_document", "export_report", "notify_admin"}

all_tools = [search_documents, delete_document, export_report, notify_admin]
tool_map = {t.name: t for t in all_tools}


# ============================================================
# State定义
# ============================================================

class DocMindHITLState(TypedDict):
    messages: Annotated[list, add_messages]
    needs_approval: bool
    pending_actions: list  # [{"tool": "name", "args": {...}}]
    review_decision: str  # 用户的审核决定："approved" / "rejected"


# ============================================================
# 节点定义
# ============================================================

def docmind_agent(state: DocMindHITLState) -> dict:
    """DocMind Agent节点"""
    llm = ChatOpenAI(model="deepseek-chat", temperature=0)
    llm_with_tools = llm.bind_tools(all_tools)
    
    messages = state["messages"]
    if not messages or not isinstance(messages[0], SystemMessage):
        messages = [SystemMessage(content="""你是DocMind智能文档助手。

你可以：
- search_documents: 搜索文档（安全）
- delete_document: 删除文档（需确认）
- export_report: 导出报告（需确认）
- notify_admin: 发送通知（需确认）

重要规则：
1. 搜索类操作可以直接执行
2. 删除、导出、通知等操作，系统会先请求用户确认
3. 使用中文回答
""")] + messages
    
    response = llm_with_tools.invoke(messages)
    return {"messages": [response]}


def sensitivity_checker(state: DocMindHITLState) -> dict:
    """敏感度检查节点"""
    last_msg = state["messages"][-1]
    
    if not hasattr(last_msg, "tool_calls") or not last_msg.tool_calls:
        return {"needs_approval": False, "pending_actions": []}
    
    sensitive_actions = []
    for tc in last_msg.tool_calls:
        if tc["name"] in SENSITIVE_TOOLS:
            sensitive_actions.append({
                "tool": tc["name"],
                "args": tc["args"],
                "id": tc["id"]
            })
    
    if sensitive_actions:
        action_descriptions = []
        for action in sensitive_actions:
            args_str = json.dumps(action["args"], ensure_ascii=False)
            action_descriptions.append(f"  - {action['tool']}({args_str})")
        
        print(f"\n[需要确认] 以下敏感操作等待审批：")
        print("\n".join(action_descriptions))
        
        return {
            "needs_approval": True,
            "pending_actions": sensitive_actions
        }
    
    return {"needs_approval": False, "pending_actions": []}


def execute_tools(state: DocMindHITLState) -> dict:
    """执行工具节点（只执行安全的或已审批的工具）"""
    last_ai = None
    for msg in reversed(state["messages"]):
        if isinstance(msg, AIMessage):
            last_ai = msg
            break
    
    if not last_ai or not last_ai.tool_calls:
        return {"messages": []}
    
    tool_messages = []
    for tc in last_ai.tool_calls:
        name, args, tid = tc["name"], tc["args"], tc["id"]
        try:
            result = tool_map[name].invoke(args) if name in tool_map else f"工具不存在: {name}"
        except Exception as e:
            result = f"执行失败: {str(e)}"
        
        tool_messages.append(ToolMessage(
            content=str(result), tool_call_id=tid, name=name
        ))
    
    return {"messages": tool_messages}


def human_review_node(state: DocMindHITLState) -> dict:
    """人类审核节点（占位，实际通过interrupt实现）"""
    # 这个节点本身不做事
    # interrupt_before会让图在执行它之前暂停
    # 人类审批后通过update_state写入review_decision，
    # 再由review节点后的条件边决定走向
    return {"needs_approval": False}


# ============================================================
# 条件路由
# ============================================================

def route_after_agent(state: DocMindHITLState) -> Literal["check", "__end__"]:
    last_msg = state["messages"][-1]
    if hasattr(last_msg, "tool_calls") and last_msg.tool_calls:
        return "check"
    return "__end__"


def route_after_check(state: DocMindHITLState) -> Literal["review", "execute"]:
    if state.get("needs_approval"):
        return "review"
    return "execute"


def route_after_review(state: DocMindHITLState) -> Literal["approved", "rejected"]:
    # 批准 → 去执行工具；拒绝 → 回到Agent重新规划
    return "approved" if state.get("review_decision") == "approved" else "rejected"


# ============================================================
# 构建图
# ============================================================

def build_docmind_hitl():
    """构建带人类审核的DocMind"""
    
    graph = StateGraph(DocMindHITLState)
    
    graph.add_node("agent", docmind_agent)
    graph.add_node("check", sensitivity_checker)
    graph.add_node("execute", execute_tools)
    graph.add_node("review", human_review_node)
    
    graph.add_edge(START, "agent")
    
    graph.add_conditional_edges("agent", route_after_agent)
    graph.add_conditional_edges("check", route_after_check)
    
    graph.add_edge("execute", "agent")   # 执行完工具回到Agent
    # 审核节点后按用户的决定路由：批准→执行，拒绝→回到Agent重新规划
    graph.add_conditional_edges("review", route_after_review, {
        "approved": "execute",
        "rejected": "agent"
    })
    
    checkpointer = MemorySaver()
    return graph.compile(
        checkpointer=checkpointer,
        interrupt_before=["review"]  # 在审核节点前中断
    )


# ============================================================
# 交互式使用
# ============================================================

def interactive_docmind():
    """交互式DocMind（带人类审核）"""
    
    app = build_docmind_hitl()
    thread_id = "interactive-session-1"
    config = {"configurable": {"thread_id": thread_id}}
    
    print("DocMind (带人类审核) 已启动")
    print("输入问题，输入 'quit' 退出\n")
    
    while True:
        user_input = input("你: ").strip()
        
        if user_input.lower() in ['quit', 'exit']:
            break
        
        if not user_input:
            continue
        
        # 发送消息
        result = app.invoke(
            {"messages": [HumanMessage(content=user_input)],
             "needs_approval": False, "pending_actions": [], "review_decision": ""},
            config=config
        )
        
        # 检查是否中断（等待审批）
        state = app.get_state(config)
        
        if state.next:  # 图被中断了
            print(f"\n[审核请求] Agent想要执行敏感操作")
            actions = state.values.get("pending_actions", [])
            for action in actions:
                print(f"  操作: {action['tool']}({json.dumps(action['args'], ensure_ascii=False)})")
            
            decision = input("\n批准？(y=批准/n=拒绝/m=修改): ").strip().lower()
            
            if decision == 'y':
                print("[已批准] 继续执行...")
                app.update_state(config, {
                    "needs_approval": False,
                    "review_decision": "approved"
                })
                result = app.invoke(None, config=config)

            elif decision == 'n':
                print("[已拒绝]")
                # 给最后一条AI消息里所有悬空的 tool_calls 补拒绝 ToolMessage
                # （包括与敏感操作一起请求的安全工具），避免下次调用 LLM 时协议报错
                last_ai = next(
                    m for m in reversed(state.values["messages"])
                    if isinstance(m, AIMessage)
                )
                rejection_msgs = [
                    ToolMessage(content="用户拒绝了这个操作，请用其他方式完成任务。",
                                tool_call_id=tc["id"], name=tc["name"])
                    for tc in last_ai.tool_calls
                ]
                app.update_state(config, {
                    "needs_approval": False,
                    "review_decision": "rejected",
                    "messages": rejection_msgs
                })
                result = app.invoke(None, config=config)

            elif decision == 'm':
                modification = input("请输入修改意见: ").strip()
                # 与拒绝分支同理：给所有悬空的 tool_calls 补一条"未批准+修改意见"的消息
                last_ai = next(
                    m for m in reversed(state.values["messages"])
                    if isinstance(m, AIMessage)
                )
                rejection_msgs = [
                    ToolMessage(content=f"用户未批准原操作，修改要求：{modification}",
                                tool_call_id=tc["id"], name=tc["name"])
                    for tc in last_ai.tool_calls
                ]
                app.update_state(config, {
                    "needs_approval": False,
                    "review_decision": "rejected",
                    "messages": rejection_msgs
                })
                result = app.invoke(None, config=config)
        
        # 显示最终回答
        final = result["messages"][-1]
        if hasattr(final, "content") and final.content:
            print(f"\nDocMind: {final.content}\n")


if __name__ == "__main__":
    interactive_docmind()
```

## 21.6 思考题

1. **概念题**：interrupt_before和interrupt_after有什么区别？各自适合什么场景？
2. **设计题**：设计一个"分级审批系统"——低风险自动通过，中风险需要主管审批，高风险需要管理员审批。
3. **实践题**：为审批流程添加超时机制——如果30秒内人类没有响应，自动拒绝操作。
4. **思考题**：Human-in-the-Loop会降低用户体验（每次都问"确认吗？"很烦）。你怎么设计才能既保证安全又不打扰用户？
5. **挑战题**：实现一个"批量审批"功能——Agent同时请求5个操作，人类可以逐个批准/拒绝，也可以一键全部批准。

## 本章小结

- **interrupt_before与interrupt_after在compile时声明**，分别让图在指定节点执行前、执行后暂停；编译后不能动态增删，运行时动态中断要靠条件路由配合状态字段实现。
- **中断恢复四步**：invoke触发并暂停 → get_state确认暂停点 → update_state写入决定 → invoke(None)从断点恢复。
- **checkpointer是中断恢复的前提**——没有它，暂停后的状态无从谈起，这也是第20章是本章前置的原因。
- **审批节点之后必须条件边分流**：批准路由到执行节点，拒绝回agent重新规划；直连END会让被批准的工具永远不执行。
- **拒绝时要给最后一条AI消息里所有悬空的tool_calls补ToolMessage**（包括与敏感操作一起请求的安全工具），否则下次调LLM会协议报错。
- **人类不止批准/拒绝**：update_state还能注入上下文、纠正参数（Edit State），让纠偏发生在错误扩大之前。
- **设计原则**：安全操作自动通过，别让用户审批每个搜索；审批信息具体到操作本身（"是否删除doc_001"而非"是否继续"）；尽量支持修改而不只是二选一。
