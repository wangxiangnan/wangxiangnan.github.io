# 第6章：TypeScript + Node.js——给 JS 穿上盔甲

## 引言：为什么要给 JavaScript 穿盔甲？

JavaScript 是一门动态类型语言。这就像是光着身子去打仗——灵活是真灵活，伤得快也是真快。

```javascript
// JavaScript 的"自由"
function processUser(user) {
  return user.name.toUpperCase(); // user 是什么？name 一定存在？是字符串吗？
}

processUser({ name: "Alice" });  // ✅ 正常
processUser({ Name: "Bob" });    // ❌ undefined.toUpperCase() → 运行时崩溃
processUser(null);               // ❌ Cannot read properties of null
processUser("hello");            // ❌ "hello".name → undefined.toUpperCase()
```

这些错误只有在代码**运行时**才会暴露。如果这是一个深埋在某个分支里的边界情况，可能上线几个月后才在凌晨3点把你炸醒。

TypeScript 的解决方案：**在编译时就发现这些问题**。

```typescript
// TypeScript：编译时就能发现问题
interface User {
  name: string;
  email: string;
  age?: number;
}

function processUser(user: User): string {
  return user.name.toUpperCase(); // IDE 知道 name 是 string，提供自动补全
}

processUser({ Name: "Bob" });  // ❌ 编译错误！属性 'Name' 不存在于类型 'User'
processUser(null);             // ❌ 编译错误！不能将 null 分配给类型 'User'
processUser("hello");          // ❌ 编译错误！字符串不是 User 类型
```

### 理由1：自文档化

```typescript

  username: string;
  email: string;
  password: string;
  role?: 'admin' | 'user' | 'moderator';
  avatar?: string;
  metadata?: Record<string, unknown>;

async function createUser(options: CreateUserOptions): Promise<User> {
  // 看到函数签名，你就知道：
  // 1. 需要传什么参数
  // 2. 哪些是必填、哪些是可选
  // 3. role 只有三种选择
  // 4. 返回值是 User 类型的 Promise
}
```

### 理由2：重构安全

```typescript
// 当你重命名一个字段时，TypeScript 会告诉你所有受影响的地方
interface User {
  name: string;   // 想改成 fullName
}

// 全局替换？太危险了！
// TypeScript：直接改接口定义，编译器会标记所有需要修改的位置
```

### 理由3：更好的 IDE 体验

TypeScript 让 VSCode 变成了一个半智能的 AI 助手：

- 精确的自动补全
- 实时错误提示
- 安全的自动重构
- 跳转到定义/引用

### 理由4：大型项目的必需品

当项目超过 5000 行代码、超过 3 个开发者时，没有类型系统就像是在没有地图的情况下建城市——一开始很自由，后面全是迷路。

### 完整配置详解

```json
{
  "compilerOptions": {
    // ===== 模块系统 =====
    "module": "NodeNext",
    // 指定编译产物的模块格式
    // "NodeNext"：根据 package.json 的 "type" 自动选择 CJS/ESM
    // "ESNext"：总是输出 ESM
    // "CommonJS"：总是输出 CJS
    // 推荐 Node.js 项目用 "NodeNext"

    "moduleResolution": "NodeNext",
    // 模块解析策略
    // "NodeNext"：支持 package.json exports、.mjs/.cjs
    // "Bundler"：适用于 Vite/webpack 等打包工具环境
    // "Node10"(旧名"Node")：旧版 Node.js 解析，不支持 exports
    // 推荐和 module 保持一致

    // ===== 编译目标 =====
    "target": "ES2022",
    // 编译产物的 JS 版本
    // Node.js 20 支持 ES2023，所以 ES2022 很安全
    // 设置太低会增加额外的编译产物（polyfill）

    // Node.js 不需要 "DOM"！

    // ===== 输出控制 =====
    "outDir": "./dist",
    // 编译输出目录

    "rootDir": "./src",
    // 源码根目录

    "declaration": true,
    // 生成 .d.ts 类型声明文件（发布 npm 包时必须）

    "declarationMap": true,
    // 生成 .d.ts 的 source map（方便消费者 Go to Definition）

    "sourceMap": true,
    // 生成 .js.map（调试时定位到 TS 源码）

    // ===== 严格模式 =====
    "strict": true,
    // 启用所有严格检查，包括：
    // strictNullChecks: 不允许 null/undefined 赋值给非可空类型
    // strictFunctionTypes: 函数参数逆变检查
    // strictBindCallApply: bind/call/apply 参数检查
    // noImplicitAny: 不允许隐式 any
    // noImplicitThis: 不允许 this 类型为 any
    // alwaysStrict: 输出 "use strict"
    // useUnknownInCatchVariables: catch 中 error 类型为 unknown

    // ===== 额外检查 =====
    "noUncheckedIndexedAccess": true,
    // obj[key] 返回 T | undefined（不是 T）
    // 防止数组越界访问的隐性 bug

    "noUnusedLocals": true,
    // 未使用的局部变量报错

    "noUnusedParameters": true,
    // 未使用的函数参数报错（用 _ 前缀跳过）

    "exactOptionalPropertyTypes": true,
    // 区分 "属性不存在" 和 "属性值为 undefined"

    "noFallthroughCasesInSwitch": true,
    // switch case 必须 break 或 return

    // ===== 互操作 =====
    "esModuleInterop": true,
    // 允许 import express from 'express'
    // 而不是 import * as express from 'express'

    "allowSyntheticDefaultImports": true,
    // 配合 esModuleInterop 使用

    "resolveJsonModule": true,
    // 允许 import json 文件

    "isolatedModules": true,
    // 确保每个文件都可以独立编译（esbuild/swc 要求）

    // ===== 路径映射 =====
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"],
      "@config/*": ["./src/config/*"],
      "@utils/*": ["./src/utils/*"]
    },

    // ===== 其他 =====
    "skipLibCheck": true,
    // 跳过 .d.ts 文件的类型检查（加速编译）

    "forceConsistentCasingInFileNames": true
    // 文件名大小写必须一致（避免 macOS/Linux 差异）
```

## 6.4 ESM + TypeScript 的正确姿势

### 关键规则

在 `"module": "NodeNext"` 配置下，TypeScript 要求你遵循 Node.js ESM 的规则：

```typescript
// ⚠️ 关键：import 路径必须包含扩展名！
// 即使源文件是 .ts，import 时要写 .js（因为编译后的文件是 .js）

// src/utils/helper.ts
export function helper() { return 'hello'; }

// src/index.ts
// ❌ 错误：找不到模块
import { helper } from './utils/helper';

// ✅ 正确：写 .js 扩展名（编译后的扩展名）
import { helper } from './utils/helper.js';

// ✅ 导入目录下的 index 也要完整路径
import { something } from './modules/index.js';
```

这看起来很奇怪（明明文件是 .ts 却要写 .js），但这是设计决定——TypeScript 不修改 import 路径，编译后的 .js 文件确实需要 .js 后缀才能在 Node.js ESM 中运行。

## 6.5 开发时运行 TypeScript：tsx vs ts-node vs swc

开发时我们想直接运行 .ts 文件，不想每次都先编译。

### tsx（推荐）

```bash
npm install -D tsx

# 直接运行
npx tsx src/index.ts

# 监视模式
npx tsx watch src/index.ts

# 或者用 node 的 --import 标志（Node.js 20.6+）
node --import tsx src/index.ts
```

**优点**：

- 基于 esbuild，速度极快
- 零配置，支持 ESM 和 CJS
- 不需要 tsconfig.json 就能跑（但推荐有）
- 支持路径别名

### ts-node

```bash
npm install -D ts-node

# ESM 模式需要额外配置
# tsconfig.json
{
  "ts-node": {
    "esm": true
  }
}

# 运行
npx ts-node --esm src/index.ts
```

**现状**：ts-node 曾是事实标准，但在 ESM 支持上问题较多。新项目推荐用 tsx。

### swc（通过 @swc-node/register）

```bash
npm install -D @swc-node/register @swc/core

# 运行
node --require @swc-node/register src/index.ts
# 或 ESM
node --loader @swc-node/register/esm src/index.ts
```

### 对比

| 工具 | 速度 | ESM 支持 | 配置复杂度 | 类型检查 |
| ------ | ------ | --------- | ----------- | --------- |
| tsx | 极快 | 完美 | 零配置 | ❌ 不做 |
| ts-node | 慢 | 需额外配置 | 复杂 | ✅ 可选 |
| swc | 极快 | 需配置 | 中等 | ❌ 不做 |
| tsc --watch | 快 | 完美 | 标准 | ✅ 完整 |

**推荐工作流**：

- 开发时：`tsx watch`（快速迭代）
- 类型检查：`tsc --noEmit`（单独运行或作为 pre-commit hook）
- 生产构建：`tsc`（正式编译）

## 6.6 类型体操在 Node.js 中的实际应用

### 实际场景1：类型安全的环境变量

```typescript
// src/env.ts
import { z } from 'zod'; // 或者不用第三方库，纯 TS 实现

// 方案1：纯 TypeScript + 运行时验证
function getEnvVar(key: string): string {
  const value = process.env[key];
  if (value === undefined) {
    throw new Error(`环境变量 ${key} 未设置`);
  }
  return value;
}

// 类型安全的环境配置
interface EnvConfig {
  port: number;
  databaseUrl: string;
  secretKey: string;
  nodeEnv: 'development' | 'production' | 'test';
  logLevel: 'debug' | 'info' | 'warn' | 'error';
}

function loadConfig(): EnvConfig {
  return {
    port: parseInt(getEnvVar('PORT'), 10),
    databaseUrl: getEnvVar('DATABASE_URL'),
    secretKey: getEnvVar('SECRET_KEY'),
    nodeEnv: getEnvVar('NODE_ENV') as EnvConfig['nodeEnv'],
    logLevel: (process.env.LOG_LEVEL ?? 'info') as EnvConfig['logLevel'],
  };
}

export const config: EnvConfig = loadConfig();
// 之后所有地方 import { config } 都有完整类型
```

### 实际场景2：类型安全的事件系统

```typescript
// src/typed-events.ts
import { EventEmitter } from 'node:events';

// 定义事件映射类型
interface AppEvents {
  'user:created': { id: string; email: string; createdAt: Date };
  'user:deleted': { id: string; reason: string };
  'order:placed': { orderId: string; userId: string; amount: number };
  'error': Error;
}

// 类型安全的 EventEmitter
class TypedEventEmitter<TEvents extends Record<string, any>> {
  private emitter = new EventEmitter();

  on<K extends keyof TEvents>(
    event: K,
    listener: (data: TEvents[K]) => void
  ): this {
    this.emitter.on(event as string, listener);
    return this;
  }

  emit<K extends keyof TEvents>(event: K, data: TEvents[K]): boolean {
    return this.emitter.emit(event as string, data);
  }

  off<K extends keyof TEvents>(
    event: K,
    listener: (data: TEvents[K]) => void
  ): this {
    this.emitter.off(event as string, listener);
    return this;
  }

  once<K extends keyof TEvents>(
    event: K,
    listener: (data: TEvents[K]) => void
  ): this {
    this.emitter.once(event as string, listener);
    return this;
  }
}

// 使用
const bus = new TypedEventEmitter<AppEvents>();

// ✅ 完美的类型推断和自动补全
bus.on('user:created', (data) => {
  console.log(data.id);       // ✅ string
  console.log(data.email);    // ✅ string
  console.log(data.createdAt); // ✅ Date
});

// ❌ 编译错误：事件名不存在
bus.on('user:whatever', () => {});

// ❌ 编译错误：数据类型不匹配
bus.emit('user:created', { id: 123 }); // id 应该是 string
```

### 实际场景3：类型安全的路由处理

```typescript
// src/router.ts

// 定义路由参数提取类型
type ExtractParams<T extends string> =
  T extends `${infer _Start}:${infer Param}/${infer Rest}`
    ? { [K in Param | keyof ExtractParams<Rest>]: string }
    : T extends `${infer _Start}:${infer Param}`
      ? { [K in Param]: string }
      : {};

// 测试类型
type Test1 = ExtractParams<'/users/:id'>;
// { id: string }

type Test2 = ExtractParams<'/users/:userId/posts/:postId'>;
// { userId: string; postId: string }

// 类型安全的路由定义
interface RouteHandler<TParams = {}> {
  (params: TParams, req: Request): Response | Promise<Response>;
}

class Router {
  private routes: Map<string, RouteHandler<any>> = new Map();

  get<T extends string>(
    path: T,
    handler: RouteHandler<ExtractParams<T>>
  ): this {
    this.routes.set(path, handler);
    return this;
  }
}

// 使用
const router = new Router();

router.get('/users/:userId/posts/:postId', (params) => {
  // params 自动推断为 { userId: string; postId: string }
  console.log(params.userId);  // ✅
  console.log(params.postId);  // ✅
  console.log(params.whatever); // ❌ 编译错误！
  return new Response('ok');
});
```

### 实际场景4：工厂函数与泛型

```typescript
// src/repository.ts

interface Entity {
  id: string;
  createdAt: Date;
  updatedAt: Date;
}

interface Repository<T extends Entity> {
  findById(id: string): Promise<T | null>;
  findMany(filter: Partial<T>): Promise<T[]>;
  create(data: Omit<T, 'id' | 'createdAt' | 'updatedAt'>): Promise<T>;
  update(id: string, data: Partial<Omit<T, 'id' | 'createdAt' | 'updatedAt'>>): Promise<T>;
  delete(id: string): Promise<void>;
}

// 泛型工厂函数
function createRepository<T extends Entity>(
  collectionName: string
): Repository<T> {
  return {
    async findById(id) {
      // 数据库查询逻辑
      return null;
    },
    async findMany(filter) {
      return [];
    },
    async create(data) {
      const now = new Date();
      return {
        ...data,
        id: crypto.randomUUID(),
        createdAt: now,
        updatedAt: now,
      } as T;
    },
    async update(id, data) {
      return {} as T;
    },
    async delete(id) {
      // 删除逻辑
    }
  };
}

// 定义实体
interface User extends Entity {
  email: string;
  name: string;
  role: 'admin' | 'user';
}

interface Post extends Entity {
  title: string;
  content: string;
  authorId: string;
  published: boolean;
}

// 使用
const userRepo = createRepository<User>('users');
const postRepo = createRepository<Post>('posts');

// 完整的类型安全
const user = await userRepo.create({
  email: 'alice@example.com',
  name: 'Alice',
  role: 'user'
}); // 返回类型自动推断为 User

const posts = await postRepo.findMany({ published: true }); // Post[]
```

## 6.7 声明文件（.d.ts）编写

### 什么时候需要写 .d.ts？

1. 为没有类型的 JS 库添加类型
2. 发布 npm 包时提供类型
3. 声明全局类型/变量

### 为无类型的 JS 模块添加声明

```typescript
// types/legacy-lib.d.ts

declare module 'legacy-csv-parser' {
  interface ParseOptions {
    delimiter?: string;
    headers?: boolean;
    skipEmpty?: boolean;
  }

  interface CsvRow {
    [key: string]: string;
  }

  export function parse(input: string, options?: ParseOptions): CsvRow[];
  export function stringify(data: CsvRow[], options?: ParseOptions): string;
}
```

### 声明全局变量

```typescript
// types/global.d.ts
// 不需要 import/export，这个文件自动成为全局声明

declare global {
  // 扩展 globalThis
  var __APP_VERSION__: string;
  var __BUILD_TIME__: string;

  function sleep(ms: number): Promise<void>;

// 必须有这行才能让文件成为"模块化的全局声明"
```

```typescript
// src/utils/logger.ts
type LogLevel = 'debug' | 'info' | 'warn' | 'error';

interface LogEntry {
  level: LogLevel;
  message: string;
  timestamp: string;
  context?: Record<string, unknown>;
}

class Logger {
  private level: LogLevel;
  private static LEVELS: Record<LogLevel, number> = {
    debug: 0,
    info: 1,
    warn: 2,
    error: 3,
  };

  constructor(level: LogLevel = 'info') {
    this.level = level;
  }

  private shouldLog(level: LogLevel): boolean {
    return Logger.LEVELS[level] >= Logger.LEVELS[this.level];
  }

  private formatEntry(entry: LogEntry): string {
    const base = `[${entry.timestamp}] [${entry.level.toUpperCase()}] ${entry.message}`;
    if (entry.context) {
      return `${base} ${JSON.stringify(entry.context)}`;
    }
    return base;
  }

  private log(level: LogLevel, message: string, context?: Record<string, unknown>): void {
    if (!this.shouldLog(level)) return;

    const entry: LogEntry = {
      level,
      message,
      timestamp: new Date().toISOString(),
      context,
    };

    const formatted = this.formatEntry(entry);
    if (level === 'error') {
      console.error(formatted);
    } else if (level === 'warn') {
      console.warn(formatted);
    } else {
      console.log(formatted);
    }
  }

  debug(message: string, context?: Record<string, unknown>): void {
    this.log('debug', message, context);
  }

  info(message: string, context?: Record<string, unknown>): void {
    this.log('info', message, context);
  }

  warn(message: string, context?: Record<string, unknown>): void {
    this.log('warn', message, context);
  }

  error(message: string, context?: Record<string, unknown>): void {
    this.log('error', message, context);
  }
}

export const logger = new Logger(
  (process.env.LOG_LEVEL as LogLevel) ?? 'info'
);
```

```typescript
      .map(([field, error]) => `${field}: ${error}`)
      .join('; ');
    super(`验证失败: ${message}`, 400);
    this.fields = fields;
```

```typescript
// src/index.ts
import { createServer } from 'node:http';
import { config } from './config/index.js';
import { logger } from './utils/logger.js';
import { AppError } from './utils/errors.js';

const server = createServer(async (req, res) => {
  const startTime = performance.now();
  const requestId = crypto.randomUUID();

  logger.info(`← ${req.method} ${req.url}`, { requestId });

  try {
    // 简单路由（生产中用框架）
    const url = new URL(req.url!, `http://localhost:${config.port}`);

    if (url.pathname === '/health') {
      res.writeHead(200, { 'Content-Type': 'application/json' });
      res.end(JSON.stringify({
        status: 'ok',
        uptime: process.uptime(),
        timestamp: new Date().toISOString(),
      }));
    } else if (url.pathname === '/api/users' && req.method === 'GET') {
      // 模拟异步操作
      const users = [
        { id: '1', name: 'Alice', email: 'alice@example.com' },
        { id: '2', name: 'Bob', email: 'bob@example.com' },
      ];
      res.writeHead(200, { 'Content-Type': 'application/json' });
      res.end(JSON.stringify(users));
    } else {
      res.writeHead(404, { 'Content-Type': 'application/json' });
      res.end(JSON.stringify({ error: 'Not Found' }));
    }
  } catch (error) {
    const statusCode = error instanceof AppError ? error.statusCode : 500;
    const message = error instanceof AppError ? error.message : 'Internal Server Error';

    logger.error('请求处理失败', {
      requestId,
      error: error instanceof Error ? error.message : String(error),
    });

    res.writeHead(statusCode, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ error: message, requestId }));
  } finally {
    const duration = (performance.now() - startTime).toFixed(2);
    logger.info(`→ ${res.statusCode} (${duration}ms)`, { requestId });
  }
});

// 优雅关闭
function gracefulShutdown(signal: string): void {
  logger.info(`收到 ${signal} 信号，开始优雅关闭...`);
  server.close(() => {
    logger.info('服务器已关闭');
    process.exit(0);
  });

  // 如果 10 秒内没关完，强制退出
  setTimeout(() => {
    logger.error('关闭超时，强制退出');
    process.exit(1);
  }, 10000);
}

process.on('SIGTERM', () => gracefulShutdown('SIGTERM'));
process.on('SIGINT', () => gracefulShutdown('SIGINT'));

// 全局错误处理
process.on('uncaughtException', (error) => {
  logger.error('未捕获的异常', { error: error.message, stack: error.stack });
  process.exit(1);
});

process.on('unhandledRejection', (reason) => {
  logger.error('未处理的 Promise rejection', {
    reason: reason instanceof Error ? reason.message : String(reason),
  });
});

// 启动服务器
server.listen(config.port, () => {
  logger.info(`服务器已启动`, {
    port: config.port,
    env: config.nodeEnv,
    nodeVersion: process.version,
    pid: process.pid,
  });
});
```

## 6.9 常见坑点

### 坑1：import 路径扩展名问题

```typescript
// 当 module 设为 "NodeNext" 时
// ❌
import { helper } from './utils/helper';      // 找不到模块
import { helper } from './utils/helper.ts';   // 不允许 .ts 扩展名

// ✅
import { helper } from './utils/helper.js';   // 正确！写编译后的扩展名
```

### 坑2：类型导入要用 type 关键字

```typescript
// ✅ 推荐：明确标记类型导入
import type { User, AppConfig } from './types/index.js';
import { createUser } from './services/user.service.js';

// 混合导入
import { createUser, type CreateUserDTO } from './services/user.service.js';

// 为什么？
// 1. 更清晰地表达意图
// 2. 确保类型在编译后被完全擦除（不会产生空的 import 语句）
// 3. 避免循环依赖问题
```

### 坑3：ESM 中的 __dirname 替代

```typescript
// ❌ ESM 中不存在
console.log(__dirname);  // ReferenceError

// ✅ Node.js 21+
const dir = import.meta.dirname;

// ✅ Node.js 20

import { fileURLToPath } from 'node:url';
```

### 坑4：any 的滥用

```typescript
// ❌ 偷懒用 any
function processData(data: any) {
  return data.result.items.map((i: any) => i.name);
  // 0 类型安全，和写 JS 没区别
}

// ✅ 用 unknown + 类型收窄
function processData(data: unknown): string[] {
  if (
    typeof data === 'object' &&
    data !== null &&
    'result' in data &&
    typeof (data as any).result === 'object'
  ) {
    // 类型收窄后安全访问
    const result = (data as { result: { items: { name: string }[] } }).result;
    return result.items.map(i => i.name);
  }
  throw new Error('Invalid data format');
}

// ✅ 更好：定义接口 + 使用校验库（如 zod）
import { z } from 'zod';

const DataSchema = z.object({
  result: z.object({
    items: z.array(z.object({ name: z.string() }))
  })
});

function processData(data: unknown): string[] {
  const parsed = DataSchema.parse(data); // 运行时验证 + 类型推断
  return parsed.result.items.map(i => i.name);
}
```
