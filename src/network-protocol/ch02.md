# 第2章：为什么要分层——OSI 与 TCP/IP 模型

## 分层的动机

在写上一章的 KV 服务器时，你可能注意到了一个问题：我们的程序直接操作了 TCP socket。这意味着我们把"应用逻辑"（KV 存储）和"传输逻辑"（TCP 连接管理）混在了一起。如果以后想换成 UDP 呢？如果想加上加密呢？如果想在不同的物理网络上传输呢？

答案是：**我们需要分层。**

分层（Layering）是计算机网络中最伟大的设计思想之一，它的核心动机有三个：

**关注点分离（Separation of Concerns）。** 每一层只负责一个明确的功能。应用层负责"用户想做什么"，传输层负责"数据如何可靠到达"，网络层负责"数据走哪条路"，链路层负责"数据在一段线路上怎么传"。各层独立开发、独立测试、独立替换。

**抽象（Abstraction）。** 上层不需要知道下层的实现细节。你写 HTTP 服务器时不需要知道 IP 包是怎么路由的，就像你寄信时不需要知道邮递员骑自行车还是开电瓶车。层与层之间通过明确的**接口**通信，接口不变，内部实现可以随便换。

**可替换性（Replaceability）。** 因为接口是标准化的，所以某一层的实现可以自由替换。比如你可以把底层的 Ethernet 换成 Wi-Fi，把 TCP 换成 QUIC，把 IPv4 换成 IPv6——只要接口不变，上层完全感知不到。

这就像盖房子：地基层、结构层、水电层、装修层，每一层有自己的职责，你可以在不拆地基的情况下重新装修。如果所有东西混在一起，换个水管就得拆整栋楼。

## OSI 七层模型

1984 年，国际标准化组织（ISO）发布了 OSI（Open Systems Interconnection）参考模型。这是一个理论性很强的七层架构：

| 层号 | 名称 | 职责 | 典型协议/技术 |
| ------ | ------ | ------ | --------------- |
| 7 | **应用层（Application）** | 为用户应用程序提供网络服务接口 | HTTP, FTP, SMTP, DNS |
| 6 | **表示层（Presentation）** | 数据格式转换、加密/解密、压缩 | SSL/TLS, JPEG, ASCII |
| 5 | **会话层（Session）** | 建立、管理、终止会话 | NetBIOS, RPC |
| 4 | **传输层（Transport）** | 端到端的可靠/不可靠数据传输 | TCP, UDP |
| 3 | **网络层（Network）** | 逻辑寻址与路由 | IP, ICMP |
| 2 | **数据链路层（Data Link）** | 相邻节点间的帧传输 | Ethernet, Wi-Fi, PPP |
| 1 | **物理层（Physical）** | 比特的物理传输 | 电缆、光纤、无线电波 |

OSI 模型的每层都有明确的边界和职责，在理论上非常优雅。但它有一个致命的问题：**太理想化了。** 在工程实践中，表示层和会话层很难清晰分离（事实上，SSL/TLS 既做加密又管会话），而七层实现起来过于复杂，导致没有任何一个完整的 OSI 协议栈被广泛部署。

OSI 模型的命运是：**作为理论框架被广泛教授，作为工程标准被彻底抛弃。**

## TCP/IP 四层模型

在 OSI 模型还在纸上画图的年代，美国国防部资助的一个项目已经在实践中打造出了真正可用的协议栈——TCP/IP。

TCP/IP 模型只有四层：

| 层 | 名称 | 对应 OSI | 典型协议 |
| ---- | ------ | ---------- | ---------- |
| 4 | **应用层（Application）** | OSI 5-7 层合并 | HTTP, DNS, FTP, SSH |
| 3 | **传输层（Transport）** | OSI 第 4 层 | TCP, UDP |
| 2 | **网际层（Internet）** | OSI 第 3 层 | IP, ICMP, ARP |
| 1 | **网络接口层（Network Access）** | OSI 1-2 层合并 | Ethernet, Wi-Fi |

TCP/IP 模型的设计哲学是实用主义：**能跑就行，能互联就行。** 它不在乎理论上的完美，只在乎"数据包能不能从 A 到达 B"。结果是，TCP/IP 成为了互联网的基石，而 OSI 只活在教科书和考试中。

## 五层混合模型

教科书中常用一种折中方案——**五层模型**：

| 层 | 名称 | 说明 |
| ---- | ------ | ------ |
| 5 | 应用层 | 应用程序协议 |
| 4 | 传输层 | 端到端传输 |
| 3 | 网络层 | 路由与寻址 |
| 2 | 数据链路层 | 相邻节点传输 |
| 1 | 物理层 | 比特传输 |

五层模型把 TCP/IP 的"网络接口层"拆成了"数据链路层"和"物理层"，同时又去掉了 OSI 中尴尬的"表示层"和"会话层"。它是教学中最实用的分层方式，也是本书主要采用的模型。

## 层与层的关系：服务与被服务、封装与解封装

层与层之间的关系可以用两个关键词概括：**服务（Service）**和**封装（Encapsulation）**。

**服务关系：** 下层为上层提供服务。网络层为传输层提供"把包从源送到目的"的服务；传输层为应用层提供"可靠的字节流传输"的服务。上层是服务的**使用者**，下层是服务的**提供者**。

**封装过程：** 数据从上层到下层时，每经过一层，都会被加一个"信封"——也就是该层的**报头（Header）**。这个过程就像寄快递：你写了一封信（应用数据），装进快递袋（TCP 段），贴上地址标签（IP 包），最后放进运输车（以太网帧）。每加一层包装，就多一层控制信息。

接收端做相反的事——**解封装（Decapsulation）**：每收到一帧，拆开一层信封，把里面的内容交给上层处理。

```
发送端:                         接收端:
┌──────────┐                   ┌──────────┐
│ 应用数据  │                   │ 应用数据  │
└────┬─────┘                   └────▲─────┘
     │ 加 TCP 头                      │ 去 TCP 头
┌────▼─────┐                   ┌────┴─────┐
│ TCP 段   │                   │ TCP 段   │
└────┬─────┘                   └────▲─────┘
     │ 加 IP 头                       │ 去 IP 头
┌────▼─────┐                   ┌────┴─────┐
│ IP 包    │                   │ IP 包    │
└────┬─────┘                   └────▲─────┘
     │ 加以太网头/尾                   │ 去以太网头/尾
┌────▼─────────┐               ┌────┴─────────┐
│ 以太网帧      │ ────网络────→ │ 以太网帧      │
└──────────────┘               └──────────────┘
```

## 抓包实践：在 Wireshark 中观察一个 HTTP 请求的分层结构

理论说够了，来看真实的数据。打开 Wireshark，选择一个活跃的网络接口，在浏览器中访问 `http://example.com`，然后在 Wireshark 的过滤器中输入 `http`，你会看到类似这样的包列表：

```
No.  Time        Source           Destination      Protocol  Length  Info
1    0.000000    192.168.1.100    93.184.216.34    TCP       66      52341 → 80 [SYN]
2    0.045231    93.184.216.34    192.168.1.100    TCP       66      80 → 52341 [SYN, ACK]
3    0.045312    192.168.1.100    93.184.216.34    TCP       54      52341 → 80 [ACK]
4    0.045498    192.168.1.100    93.184.216.34    HTTP      150     GET / HTTP/1.1
5    0.091832    93.184.216.34    192.168.1.100    TCP       54      80 → 52341 [ACK]
6    0.092514    93.184.216.34    192.168.1.100    HTTP      1314    HTTP/1.1 200 OK
```

点击第 4 个包（HTTP GET 请求），展开 Wireshark 的详情面板，你会清晰地看到分层结构：

**第一层：Frame（物理层+链路层的信息）**

```
Frame 4: 150 bytes on wire (1200 bits), 150 bytes captured
  Arrival Time: Mar 15, 2025 10:23:45.123456
  Frame Number: 4
  Frame Length: 150 bytes
```

**第二层：Ethernet II（数据链路层）**

```
Ethernet II, Src: Dell_a1:b2:c3 (00:1a:2b:3c:4d:5e), Dst: Router_f1:e2:d3 (00:0c:29:d1:e2:f3)
  Destination: 00:0c:29:d1:e2:f3
  Source: 00:1a:2b:3c:4d:5e
  Type: IPv4 (0x0800)
```

`Type: 0x0800` 告诉链路层："我携带的数据是一个 IPv4 包。"这个字段就是层与层之间的"接口"。

**第三层：Internet Protocol Version 4（网络层）**

```
Internet Protocol Version 4, Src: 192.168.1.100, Dst: 93.184.216.34
  Version: 4
  Header Length: 20 bytes (5)
  Total Length: 96
  Identification: 0x4a3b (19003)
  Time to Live: 64
  Protocol: TCP (6)
  Header Checksum: 0xb5c2
  Source: 192.168.1.100
  Destination: 93.184.216.34
```

`Protocol: TCP (6)` 告诉网络层："我携带的数据是一个 TCP 段。"

**第四层：Transmission Control Protocol（传输层）**

```
Transmission Control Protocol, Src Port: 52341, Dst Port: 80
  Source Port: 52341
  Destination Port: 80
  Sequence Number: 1    (relative)
  Acknowledgment Number: 1    (relative)
  Header Length: 32 bytes (8)
  Flags: 0x018 (PSH, ACK)
  Window Size: 65535
  Checksum: 0x3f4a
```

**第五层：Hypertext Transfer Protocol（应用层）**

```
Hypertext Transfer Protocol
  GET / HTTP/1.1\r\n
  Host: example.com\r\n
  User-Agent: Mozilla/5.0\r\n
  Accept: text/html\r\n
  \r\n
```

看到了吗？五层嵌套，每层都有自己的报头，每层都通过一个"类型字段"告诉下一层如何处理数据。这就是分层模型在真实世界中的样子——不是一个抽象的框图，而是一个个真实的数据包。
