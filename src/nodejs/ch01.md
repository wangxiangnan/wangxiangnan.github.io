# 第1章：启程——Node.js 是什么 & 环境搭建

## 引言：当 JavaScript 越狱成功

想象一下，JavaScript 是一个被关在浏览器监狱里的囚犯。十几年来，它只能在浏览器的小窗户里看世界——操作 DOM、发发 AJAX 请求、做做动画。直到 2009 年的一天，一个叫 Ryan Dahl 的人用 C++ 撬开了监狱的门，对 JavaScript 说："兄弟，外面的世界很大，来服务器端逛逛？"

这就是 Node.js 的诞生故事。但如果你以为 Node.js 只是"跑在服务器上的 JavaScript"，那就太小看它了——这就像说飞机只是"会飞的汽车"一样离谱。

## 1.1 Node.js 的真正定义

### 官方定义（但我们要拆解它）

> Node.js 是一个基于 Chrome V8 引擎的 JavaScript 运行时环境。

这句话里有三个关键词需要解释：

**运行时环境（Runtime）**：不是框架，不是语言，不是库。它是一个让 JavaScript 能脱离浏览器独立运行的"生存环境"。就像鱼需要水缸（浏览器），Node.js 给了鱼一片海洋（操作系统）。

**V8 引擎**：Google 开发的 JavaScript 引擎，用 C++ 写的，负责把 JavaScript 代码编译成机器码。它快到什么程度？当年 V8 发布时，其他 JS 引擎看它的表现就像看刘翔跑步——"这玩意儿合法吗？"

**Chrome**：是的，就是那个 Chrome。V8 引擎原本是给 Chrome 浏览器开发的，Ryan Dahl 把它"借"了出来。

### Node.js 不只是"服务端 JS"

很多教程一上来就说"Node.js 用于服务端开发"，这其实是一种思维限制。Node.js 的能力远不止于此：

```
Node.js 能做什么？
├── Web 服务器（Express、Koa、Fastify、Hono）
├── CLI 工具（webpack、eslint、prettier、create-react-app）
├── 桌面应用（Electron → VSCode、Discord）
├── 移动开发工具链（React Native CLI、Expo）
├── IoT / 嵌入式（Johnny-Five、Espruino）
├── 机器学习（TensorFlow.js）
├── 区块链（Hardhat、Truffle）
├── 实时通信（Socket.io、WebRTC 信令服务器）
├── 构建工具（Vite、esbuild、Turbopack）
└── Serverless Functions（AWS Lambda、Vercel）
```

所以更准确的定义应该是：**Node.js 是一个通用的 JavaScript 运行平台，让 JS 获得了访问操作系统底层能力（文件系统、网络、进程等）的超能力。**

## 1.2 架构解密：V8 + libuv 双引擎驱动

### 整体架构（文字版架构图）

```
┌─────────────────────────────────────────────────────────┐
│                    你写的 JavaScript 代码                    │
├─────────────────────────────────────────────────────────┤
│                     Node.js API 层                        │
│     (fs, http, path, crypto, stream, events...)         │
├────────────────────────┬────────────────────────────────┤
│                        │                                │
│    ┌─────────────┐     │     ┌──────────────────┐       │
│    │   V8 引擎    │     │     │     libuv        │       │
│    │             │     │     │                  │       │
│    │ • JS 解析    │     │     │ • 事件循环        │       │
│    │ • JIT 编译   │     │     │ • 异步 I/O       │       │
│    │ • 内存管理   │     │     │ • 线程池         │       │
│    │ • 垃圾回收   │     │     │ • 跨平台抽象     │       │
│    └─────────────┘     │     └──────────────────┘       │
│                        │                                │
├────────────────────────┴────────────────────────────────┤
│              操作系统（Linux / macOS / Windows）            │
└─────────────────────────────────────────────────────────┘
```

### V8 引擎：翻译官

V8 的工作就像一个超级翻译官，把 JavaScript（人类语言）翻译成机器码（CPU 能懂的语言）。但它不是逐行翻译的，而是用了 JIT（Just-In-Time）编译技术：

1. **解析阶段**：先把 JS 代码转成 AST（抽象语法树）
2. **Ignition（点火器）**：把 AST 编译成字节码，快速开始执行
3. **TurboFan（涡轮风扇）**：监控热点代码，把频繁执行的函数优化编译成高效的机器码

这就像是：先请个实习生（Ignition）粗略翻译，能跑就行；然后监控哪些段落被反复阅读，再请大师（TurboFan）精翻那些段落。

### libuv：大内总管

libuv 是 Node.js 的异步 I/O 引擎，用 C 语言编写。如果说 V8 是大脑（负责计算），那 libuv 就是手脚（负责干活）。

它的核心职责：

- **事件循环（Event Loop）**：Node.js 异步的核心机制（第4章详解）
- **线程池**：默认 4 个线程处理文件 I/O、DNS 查询、加密操作等
- **跨平台抽象**：在 Linux 上用 epoll，macOS 上用 kqueue，Windows 上用 IOCP
- **异步网络 I/O**：TCP/UDP/DNS/文件监视等

### 一个请求的旅程

当你的 Node.js 服务器收到一个 HTTP 请求时，发生了什么？

```
1. [网络层] 操作系统收到 TCP 连接
2. [libuv]  事件循环检测到新连接，触发回调
3. [V8]     执行你的 JavaScript 回调函数
4. [你的代码] 比如要读取数据库
5. [libuv]  将数据库查询交给线程池异步处理
6. [V8]     主线程继续处理其他请求（不阻塞！）
7. [libuv]  数据库查询完成，将结果放入事件队列
8. [事件循环] 下一轮循环时执行回调
9. [V8]     执行你的回调，发送 HTTP 响应
```

这就是 Node.js 能用单线程处理高并发的秘密——**它不是不干活，而是聪明地干活**。就像一个优秀的餐厅服务员，不会在一桌客人点菜时傻等，而是记下单子交给厨房，转身去服务下一桌。

## 1.3 安装方式大比拼

### 方式一：官网直接下载（新手友好，但不推荐长期使用）

去 [https://nodejs.org](https://nodejs.org) 下载 LTS 版本，一路 Next。

**优点**：简单粗暴
**缺点**：只能安装一个版本，升级要手动重新下载

适合人群：第一次接触 Node.js、只是想试试的同学。

### 方式二：nvm（Node Version Manager）——老牌选手

```bash
# macOS / Linux 安装
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# 安装 Node.js 20 LTS
nvm install 20
nvm use 20

# 查看已安装版本
nvm ls

# 设置默认版本
nvm alias default 20

# 切换版本就像切换频道
nvm use 18
nvm use 20
nvm use 21
```

**Windows 用户**：nvm 原版不支持 Windows，要用 [nvm-windows](https://github.com/coreybutler/nvm-windows)。

**优点**：久经考验，社区庞大
**缺点**：每次打开终端要加载 shell 脚本，稍微影响启动速度；Windows 体验不佳

### 方式三：fnm（Fast Node Manager）——新生代速度王

```bash
# macOS (Homebrew)
brew install fnm

# Windows (Scoop)
scoop install fnm

# Linux
curl -fsSL https://fnm.vercel.app/install | bash

# 使用方式和 nvm 类似
fnm install 20
fnm use 20
fnm default 20

# 项目级版本管理（读取 .node-version 或 .nvmrc）
fnm install
fnm use
```

**优点**：Rust 编写，速度快到飞起（比 nvm 快 40 倍）；跨平台；支持 .node-version 文件
**缺点**：相对较新，生态不如 nvm 成熟

### 方式四：Volta——工具链管理器

```bash
# 安装 Volta
curl https://get.volta.sh | bash

# 安装 Node.js
volta install node@20

# Volta 的杀手锏：项目级固定版本
volta pin node@20.11.0
volta pin npm@10.2.0
# 这会写入 package.json 的 "volta" 字段
```

**优点**：不仅管理 Node.js 版本，还管理 npm/yarn/pnpm 版本；自动切换版本；团队协作神器
**缺点**：相对小众，某些场景兼容性问题

### 我的推荐

| 场景 | 推荐工具 |
| ------ | --------- |
| 个人开发，macOS/Linux | fnm |
| 个人开发，Windows | fnm 或 volta |
| 团队协作，需要统一版本 | volta |
| 就想简单试试 | 官网下载 |

### 验证安装


## 1.4 第一个程序：从 Hello World 到 HTTP 服务器

### Hello World（仪式感还是要有的）

创建文件 `hello.mjs`：

```javascript
// hello.mjs
// .mjs 后缀表示这是一个 ES Module 文件
console.log('Hello, Node.js! 🚀');
console.log(`当前 Node.js 版本: ${process.version}`);
console.log(`当前操作系统: ${process.platform}`);
console.log(`当前工作目录: ${process.cwd()}`);
console.log(`当前文件路径: ${import.meta.url}`);
```

运行：

```bash
node hello.mjs
```

输出：

```
Hello, Node.js! 🚀
当前 Node.js 版本: v20.11.0
当前操作系统: darwin
当前工作目录: /Users/you/projects/node-tutorial
当前文件路径: file:///Users/you/projects/node-tutorial/hello.mjs
```

注意看 `import.meta.url`——这是 ESM 特有的获取当前文件路径的方式，替代了 CommonJS 中的 `__filename`。

### 进阶：创建 HTTP 服务器

```javascript
// server.mjs
import { createServer } from 'node:http';

// 端口号用环境变量，养成好习惯
const PORT = process.env.PORT || 3000;

const server = createServer((request, response) => {
  // 设置响应头
  response.writeHead(200, {
    'Content-Type': 'application/json',
    'X-Powered-By': 'Node.js Tutorial'
  });

  // 构造响应数据
  const data = {
    message: 'Hello from Node.js!',
    timestamp: new Date().toISOString(),
    method: request.method,
    url: request.url,
    headers: request.headers,
    nodeVersion: process.version
  };

  // 发送响应
  response.end(JSON.stringify(data, null, 2));
});

server.listen(PORT, () => {
  console.log(`🚀 服务器已启动: http://localhost:${PORT}`);
  console.log(`📝 按 Ctrl+C 停止服务器`);
});
```

运行后打开浏览器访问 `http://localhost:3000`，你就有了一个活生生的 HTTP 服务器！

**代码解读**：

- `import { createServer } from 'node:http'`：注意 `node:` 前缀，这是 Node.js 内置模块的推荐写法（Node.js 16+），可以避免和第三方包同名冲突
- `createServer` 接收一个回调函数，每次有请求进来就执行
- `response.writeHead` 设置状态码和响应头
- `response.end` 发送响应体并结束连接

### 加个路由试试

```javascript
// router-server.mjs
import { createServer } from 'node:http';

const PORT = process.env.PORT || 3000;

/**
 * 简单路由表
 * @type {Record<string, (req: import('http').IncomingMessage, res: import('http').ServerResponse) => void>}
 */
const routes = {
  '/': (req, res) => {
    res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    res.end('<h1>首页</h1><p>欢迎来到 Node.js 世界！</p>');
  },
  '/api/time': (req, res) => {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ time: new Date().toISOString() }));
  },
  '/api/random': (req, res) => {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ number: Math.random() }));
  }
};

const server = createServer((req, res) => {
  const url = new URL(req.url, `http://localhost:${PORT}`);
  const handler = routes[url.pathname];

  if (handler) {
    handler(req, res);
  } else {
    res.writeHead(404, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ error: 'Not Found', path: url.pathname }));
  }
});

server.listen(PORT, () => {
  console.log(`🚀 服务器已启动: http://localhost:${PORT}`);
  console.log(`📍 可用路由: ${Object.keys(routes).join(', ')}`);
});
```

看，不用任何框架，纯 Node.js 就能写路由。当然，生产环境我们会用 Express/Fastify 等框架，但理解底层原理很重要——**知其然更要知其所以然**。

## 1.5 REPL：你的 JavaScript 游乐场

REPL = Read-Eval-Print-Loop（读取-求值-打印-循环）。在终端输入 `node` 就能进入：

```bash
$ node
Welcome to Node.js v20.11.0.
Type ".help" for more information.
>
```

### REPL 妙用

```javascript
// 快速测试表达式
> 2 ** 10
1024

// 测试字符串方法
> 'Hello World'.split('').reverse().join('')
'dlroW olleH'

// 查看模块有哪些方法
> const fs = require('fs')
> Object.keys(fs).filter(k => k.startsWith('read'))
[ 'read', 'readFile', 'readFileSync', 'readdir', 'readdirSync', 'readlink', 'readlinkSync' ]

// 多行输入（自动检测）
> function add(a, b) {
...   return a + b;
... }
undefined
> add(1, 2)
3

// 访问上一个表达式的结果
> 'hello'.toUpperCase()
'HELLO'
> _.length
5
```

### REPL 特殊命令

```
.help    - 显示帮助
.break   - 退出多行表达式
.clear   - 重置上下文
.editor  - 进入编辑器模式（多行输入更方便）
.exit    - 退出 REPL
.load    - 加载文件到 REPL
.save    - 保存 REPL 历史到文件
```

### REPL 的 `.editor` 模式超好用

```bash
> .editor
// 进入编辑器模式，可以随意写多行代码
// 按 Ctrl+D 执行，Ctrl+C 取消

const greet = (name) => {
  const time = new Date().getHours();
  if (time < 12) return `早上好，${name}！`;
  if (time < 18) return `下午好，${name}！`;
  return `晚上好，${name}！`;
};

console.log(greet('Node.js学习者'));
// 按 Ctrl+D
```

**Pro tip**：REPL 特别适合快速验证一个 API 用法、测试正则表达式、或者当计算器用（别笑，我真的经常用 `node -e "console.log(1024*1024*100)"` 算内存大小）。

## 1.6 package.json 详解：项目的身份证

每个 Node.js 项目的根目录都应该有一个 `package.json`——它就是项目的身份证、说明书、配置中心。

### 创建 package.json

```bash
# 交互式创建（一路回车用默认值）
npm init

# 直接生成默认的（零交互）
npm init -y
```

### 完整字段解析

```json
{
  // ===== 基本信息 =====
  "name": "my-awesome-app",
  // 包名规则：小写、可用连字符和点、不能以.或_开头
  // 作用域包：@myorg/my-package

  "version": "1.0.0",
  // 语义化版本 SemVer：主版本.次版本.修订号
  // 详见第5章

  "description": "这是一个很棒的 Node.js 应用",
  // npm search 会用到这个字段

  "keywords": ["node", "tutorial", "awesome"],
  // 帮助别人在 npm 上找到你的包

  "author": "Your Name <your@email.com> (https://yoursite.com)",
  // 也可以用对象形式：{ "name": "...", "email": "...", "url": "..." }

  "license": "MIT",
  // 常见：MIT, Apache-2.0, ISC, GPL-3.0

  // ===== 入口文件 =====
  "main": "./dist/index.cjs",
  // CommonJS 入口（require 时用）

  "module": "./dist/index.mjs",
  // ESM 入口（bundler 用，非 Node.js 官方字段）

  "types": "./dist/index.d.ts",
  // TypeScript 类型声明入口

  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    },
    "./utils": {
      "types": "./dist/utils.d.ts",
      "import": "./dist/utils.mjs",
      "require": "./dist/utils.cjs"
    }
  },
  // 条件导出（Node.js 12+）：精确控制不同模块系统看到不同入口
  // 这是现代 Node.js 包的推荐方式

  // ===== 模块类型 =====
  "type": "module",
  // "module" → .js 文件按 ESM 解析
  // "commonjs"（默认）→ .js 文件按 CJS 解析
  // 详见第2章

  // ===== 脚本命令 =====
  "scripts": {
    "dev": "node --watch src/index.mjs",
    "start": "node dist/index.mjs",
    "build": "tsc",
    "test": "node --test",
    "lint": "eslint src/",
    "format": "prettier --write .",
    "prepare": "husky install",
    "pretest": "npm run lint"
  },
  // npm run <script-name> 执行
  // 特殊脚本：start/test/stop/restart 可以省略 run

  // ===== 依赖管理 =====
  "dependencies": {
    "express": "^4.18.2"
  },
  // 生产依赖：应用运行时需要的包

  "devDependencies": {
    "typescript": "^5.3.0",
    "@types/node": "^20.10.0",
    "eslint": "^8.55.0"
  },
  // 开发依赖：只在开发时需要

  "peerDependencies": {
    "react": ">=18.0.0"
  },
  // 同伴依赖：声明"我需要宿主环境也装了这个包"
  // 常见于插件/库

  "optionalDependencies": {},
  // 可选依赖：安装失败不会中断整体安装

  // ===== 文件与发布 =====
  "files": ["dist", "README.md", "LICENSE"],
  // 发布到 npm 时包含哪些文件（白名单）
  // .npmignore 是黑名单方式

  "bin": {
    "my-cli": "./bin/cli.mjs"
  },
  // 可执行文件，npm install -g 后可直接在命令行使用

  // ===== 引擎要求 =====
  "engines": {
    "node": ">=20.0.0",
    "npm": ">=10.0.0"
  },
  // 声明项目需要的 Node.js 和 npm 最低版本

  // ===== 仓库信息 =====
  "repository": {
    "type": "git",
    "url": "https://github.com/you/my-awesome-app.git"
  },
  "bugs": {
    "url": "https://github.com/you/my-awesome-app/issues"
  },
  "homepage": "https://github.com/you/my-awesome-app#readme",

  // ===== Volta 版本固定 =====
  "volta": {
    "node": "20.11.0",
    "npm": "10.2.4"
  }
}
```

## 1.7 node 命令行参数：隐藏的超能力

Node.js 20+ 带来了很多实用的命令行参数，让你少装好多工具。

### --watch：内置的文件监视器（再见 nodemon！）

```bash
# 文件变动时自动重启
node --watch server.mjs

# 只监视特定目录
node --watch-path=./src --watch-path=./config server.mjs
```

以前我们要 `npm install -g nodemon`，现在不用了。Node.js 18+ 内置了这个功能！

### --env-file：内置环境变量加载（再见 dotenv！）

```bash
# 加载 .env 文件
node --env-file=.env server.mjs

# 加载多个 env 文件
node --env-file=.env --env-file=.env.local server.mjs
```

`.env` 文件格式：

```env
# .env
PORT=3000
DATABASE_URL=postgres://localhost:5432/mydb
SECRET_KEY=my-super-secret
NODE_ENV=development
```

Node.js 20.6+ 支持，Node.js 21+ 稳定。以前要 `npm install dotenv`，现在原生支持！

### --test：内置测试运行器（再见 Jest？也许吧）

```javascript
// math.test.mjs
import { describe, it } from 'node:test';
import assert from 'node:assert/strict';

function add(a, b) { return a + b; }

describe('add 函数', () => {
  it('应该正确相加两个正数', () => {
    assert.strictEqual(add(1, 2), 3);
  });

  it('应该处理负数', () => {
    assert.strictEqual(add(-1, -2), -3);
  });

  it('应该处理零', () => {
    assert.strictEqual(add(0, 0), 0);
  });
});
```

## 1.8 常见坑点

### 坑1：PATH 环境变量

安装完 Node.js 但命令行找不到 `node` 命令？大概率是 PATH 没配对。

```bash
# 检查 PATH
echo $PATH  # macOS/Linux
echo %PATH% # Windows CMD
$env:PATH   # Windows PowerShell
```

### 坑2：权限问题

macOS/Linux 上全局安装包报 `EACCES` 错误？

```bash
# 错误示例
npm install -g typescript
# Error: EACCES: permission denied

# 解决方案1：使用 nvm/fnm（推荐，从根源解决）
# 解决方案2：修改 npm 全局目录
mkdir ~/.npm-global
npm config set prefix '~/.npm-global'
# 然后在 ~/.bashrc 或 ~/.zshrc 中添加：
# export PATH=~/.npm-global/bin:$PATH

# 千万不要用 sudo npm install -g ！！！
# 这会导致权限混乱，后患无穷
```

### 坑3：Windows 上的换行符

Windows 用 CRLF (`\r\n`)，Linux/macOS 用 LF (`\n`)。如果你在 Windows 上开发，提交到 Linux 服务器运行，可能会遇到 `#!/usr/bin/env node\r` 这样的错误。

解决方案：配置 Git 和编辑器统一使用 LF。

```bash
# Git 配置
git config --global core.autocrlf input  # macOS/Linux
git config --global core.autocrlf true   # Windows
```

### 坑4：Node.js 版本不对

项目要求 Node.js 20，你用的是 16？这时候 `engines` 字段就派上用场了：

```json
{
  "engines": {
    "node": ">=20.0.0"
  }
}
```

配合 `.npmrc`：

```ini
engine-strict=true
```

这样 `npm install` 时如果 Node.js 版本不对会直接报错。
