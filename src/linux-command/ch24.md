# 第24章：性能调优与故障排查——当服务器出了问题

## 为什么学故障排查？

作为Linux用户或运维人员，你迟早会遇到这些场景：服务器突然变慢、网站响应超时、磁盘满了、SSH连不上......这时候你需要的不是慌张，而是一套系统化的排查方法论和一组趁手的工具。

本章就是给你装备这些武器的。我们会学习USE方法论（每个资源都看利用率、饱和度、错误率），然后掌握strace、lsof、/proc、vmstat、iostat等一系列诊断工具，最后通过真实案例来演练。把这些学完，当服务器出问题的时候，你就能像老中医一样望闻问切、药到病除。

## 24.1 故障排查方法论——USE方法

在拿起工具之前，先建立正确的排查思维。USE方法（Utilization/Saturation/Errors）是Brendan Gregg提出的系统化排查框架，它像一张检查清单，确保你不会遗漏任何维度。

```
USE 方法三维度：
┌──────────────┬──────────────────────────────────────────────┐
│ 维度         │ 含义                                         │
├──────────────┼──────────────────────────────────────────────┤
│ Utilization  │ 资源利用率（CPU用了多少%、磁盘用了多少%）      │
│ Saturation   │ 资源饱和度（排队长度、等待队列深度）            │
│ Errors       │ 错误数（丢包、IO错误、内存错误）               │
└──────────────┴──────────────────────────────────────────────┘

检查顺序：
1. 先确定问题范围（单机？集群？某个服务？）
2. 对每个资源（CPU/内存/磁盘/网络）检查 USE 三维度
3. 定位瓶颈 → 深入分析 → 修复验证
```

```bash
# USE 方法快速检查清单

# === CPU ===
# Utilization（利用率）
top -bn1 | head -5                 # CPU使用率概览
mpstat -P ALL 1 3                  # 每个CPU核心的利用率

# Saturation（饱和度）
uptime                             # load average
vmstat 1 5                         # r列（运行队列）

# Errors
dmesg | grep -i "cpu\|error"       # CPU相关错误

# === 内存 ===
# Utilization
free -h                            # 内存使用情况
cat /proc/meminfo | head -20       # 详细内存信息

# Saturation
vmstat 1 5                         # si/so列（swap in/out）
sar -B 1 5                         # pgscank/pgscand（页面扫描）

# Errors
dmesg | grep -i "oom\|memory"      # OOM killer记录

# === 磁盘 ===
# Utilization
iostat -xz 1 5                     # %util列
df -h                              # 磁盘空间使用

# Saturation
iostat -xz 1 5                     # avgqu-sz列（队列深度）

# Errors
dmesg | grep -i "error\|fail"      # 磁盘IO错误
smartctl -a /dev/sda               # SMART健康检查

# === 网络 ===
# Utilization
sar -n DEV 1 5                     # 网络接口流量

# Saturation
ss -s                              # socket统计
cat /proc/net/snmp | grep Tcp      # TCP连接统计

# Errors
ifconfig | grep errors             # 网络接口错误计数
ip -s link                         # 链路统计
```

## 24.2 strace——系统调用追踪器

strace是Linux调试的终极武器。它追踪进程发出的每一个系统调用，让你看到程序"到底在干什么"。当程序莫名其妙地卡住、报错、或者行为不符合预期时，strace往往能一锤定音。

```bash
# ============================
# 基础用法
# ============================

# 追踪一个命令的所有系统调用
strace ls -la
# 输出类似：
# execve("/usr/bin/ls", ["ls", "-la"], 0x7ffd...) = 0
# brk(NULL)                               = 0x55a2...
# mmap(NULL, 8192, PROT_READ|PROT_WRITE, ...) = 0x7f8c...
# openat(AT_FDCWD, "/etc/ld.so.cache", ...) = 3
# ...

# 追踪一个正在运行的进程
strace -p <PID>

# ============================
# 常用选项
# ============================

# -e: 只追踪特定的系统调用
strace -e open,read,write ls -la
# 只看文件打开、读、写操作

strace -e network curl https://example.com
# 只看网络相关的系统调用

strace -e file cat /etc/hosts
# 只看文件操作

# -f: 追踪子进程（fork出来的子进程也追踪）
strace -f bash -c "ls | wc -l"

# -t: 显示时间戳
strace -t ls -la
# 21:30:45 execve("/usr/bin/ls", ...) = 0

# -tt: 精确到微秒
strace -tt ls -la
# 21:30:45.123456 execve("/usr/bin/ls", ...) = 0

# -T: 显示每个系统调用的耗时
strace -T ls -la
# execve("/usr/bin/ls", ...) = 0 <0.001234>

# -c: 统计摘要（每个系统调用的次数和耗时）
strace -c ls -la
# % time     seconds  usecs/call     calls    errors syscall
# ------ ----------- ----------- --------- --------- --------
#  35.71    0.000123          12        10           mmap
#  25.00    0.000086          14         6           openat

# -o: 输出到文件
strace -o trace.log -f ./myprogram

# ============================
# 实用调试场景
# ============================

# 场景1：程序找不到配置文件
strace -e open,openat ./myprogram 2>&1 | grep "ENOENT"
# 查看所有打开失败的文件

# 场景2：程序卡住了，看它在等什么
strace -p <PID>
# 通常会看到 read()、select()、futex() 等阻塞调用

# 场景3：程序启动很慢，看时间花在哪里
strace -tt -T ./slow_program 2> trace.log
# 然后分析 trace.log 找最慢的系统调用

# 场景4：查看程序访问了哪些文件
strace -e open,openat,stat -f ./myprogram 2>&1 | grep -v ENOENT
```

## 24.3 lsof——列出打开的文件

在Linux中，"一切皆文件"——普通文件、目录、网络socket、设备、管道都是文件。lsof（List Open Files）能列出当前系统上所有被打开的文件，是排查端口占用、文件锁定等问题的利器。

```bash
# ============================
# 基础用法
# ============================

# 列出所有打开的文件（输出可能很长）
lsof

# 查看谁在使用某个文件
lsof /var/log/syslog
# COMMAND   PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
# rsyslogd  856 root   12w  REG  253,0    12345   123 /var/log/syslog

# 查看某个进程打开的所有文件
lsof -p <PID>

# 查看某个用户打开的所有文件
lsof -u username

# ============================
# 网络相关（最常用的场景）
# ============================

# 查看谁在监听某个端口
lsof -i :80
# COMMAND  PID  USER   FD   TYPE  DEVICE SIZE/OFF NODE NAME
# nginx   1234  root   6u  IPv4  12345    0t0     TCP *:http (LISTEN)
# nginx   1235  www   6u  IPv4  12345    0t0     TCP *:http (LISTEN)

# 查看谁在监听TCP 443端口
lsof -i TCP:443

# 查看所有TCP连接
lsof -i TCP

# 查看所有ESTABLISHED连接
lsof -i TCP -s TCP:ESTABLISHED

# 查看所有LISTEN端口
lsof -i -P -n | grep LISTEN
# -P 显示端口号而不是服务名
# -n 显示IP地址而不是主机名

# ============================
# 实用场景
# ============================

# 端口被谁占了？（最常见的用法）
lsof -i :3000
# 找到PID后 kill 掉

# 文件被谁锁了？
lsof /path/to/locked/file

# 查看某个目录被谁在使用（删除目录前的安全检查）
lsof +D /var/www/html
# +D 递归搜索目录

# 找出已删除但仍被占用的文件（磁盘空间没释放的原因）
lsof +L1
# 或者
lsof | grep deleted

# 查看所有网络连接（替代netstat）
lsof -i -P -n
```

## 24.4 /proc 与 /sys——内核信息宝库

/proc 和 /sys 是Linux内核的"控制面板"——它们看起来像普通文件系统，但里面的"文件"其实是内核状态的实时快照。读懂它们，你就能直接看到系统的"内脏"。

```bash
# ============================
# /proc 核心文件
# ============================

# /proc/cpuinfo - CPU信息
cat /proc/cpuinfo
# 每个核心的型号、频率、缓存等

# 快速获取CPU核心数
grep -c ^processor /proc/cpuinfo
# 或
nproc

# /proc/meminfo - 内存详细信息
cat /proc/meminfo
# MemTotal:       16384000 kB
# MemFree:         8192000 kB
# MemAvailable:   12288000 kB
# Buffers:          512000 kB
# Cached:          3072000 kB
# SwapTotal:       2048000 kB
# SwapFree:        2048000 kB

# /proc/loadavg - 系统负载
cat /proc/loadavg
# 1.23 0.98 0.87 2/456 12345
# 1分钟/5分钟/15分钟负载  运行进程/总进程  最新PID

# /proc/uptime - 运行时间
cat /proc/uptime
# 86400.00 172000.00（运行秒数 空闲秒数）

# /proc/filesystems - 支持的文件系统
cat /proc/filesystems

# /proc/mounts - 当前挂载
cat /proc/mounts

# /proc/interrupts - 中断统计
cat /proc/interrupts

# ============================
# 进程相关的 /proc
# ============================

# 每个进程在 /proc 下都有自己的目录（以PID命名）
ls /proc/1/        # PID 1 (systemd) 的信息

# 进程的命令行参数
cat /proc/<PID>/cmdline | tr '\0' ' '

# 进程的环境变量
cat /proc/<PID>/environ | tr '\0' '\n'

# 进程打开的文件描述符
ls -la /proc/<PID>/fd/

# 进程的内存映射
cat /proc/<PID>/maps

# 进程的状态
cat /proc/<PID>/status
# Name:   nginx
# State:  S (sleeping)
# VmPeak:   123456 kB
# Threads: 4

# ============================
# /sys 核心文件
# ============================

# CPU调频信息
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq

# 块设备信息
ls /sys/block/
cat /sys/block/sda/queue/scheduler    # IO调度器

# 网络设备信息
ls /sys/class/net/
cat /sys/class/net/eth0/speed         # 网卡速率

# ============================
# 实用技巧
# ============================

# 查看系统支持的最大文件描述符数
cat /proc/sys/fs/file-max

# 临时修改内核参数
echo 65536 > /proc/sys/fs/file-max

# 查看TCP连接参数
cat /proc/sys/net/ipv4/tcp_max_syn_backlog
cat /proc/sys/net/core/somaxconn
```

## 24.5 vmstat——虚拟内存统计

```bash
# ============================
# 基础用法
# ============================

# 实时监控（每秒刷新，共5次）
vmstat 1 5

# 输出解读：
# procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
#  r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
#  2  0      0 8192000 512000 3072000  0    0    10    20  100  200 15  5 78  2  0
#  ↑  ↑                                                  ↑   ↑  ↑  ↑  ↑  ↑  ↑  ↑
#  │  │                                                  │   │  │  │  │  │  │  │
#  │  阻塞进程数                                         │   │  │  │  │  │  │  steal
#  运行队列长度                                     中断数 │  │  │  │  │  │  IO等待
#                                                    上下文切换│  │  │  │  │  空闲
#                                                        用户 │  │  │  │  系统
#                                                            IO读 IO写  │

# ============================
# 关键指标解读
# ============================

# r（运行队列）：如果持续大于CPU核心数，说明CPU饱和
# b（阻塞进程）：如果有进程持续阻塞，可能在等IO
# si/so（swap in/out）：如果持续非0，说明物理内存不足
# wa（IO等待）：如果持续高，说明磁盘是瓶颈
# bi/bo（块IO）：磁盘读写量

# ============================
# 实用技巧
# ============================

# 宽屏输出（更易读）
vmstat -w 1 5

# 查看统计摘要
vmstat -s
#       16384000 K total memory
#        8192000 K used memory
#       12288000 K active memory
#        ...

# 查看磁盘统计
vmstat -d
```

## 24.6 iostat——磁盘IO监控

```bash
# ============================
# 安装
# ============================
sudo apt install sysstat    # iostat 在 sysstat 包中

# ============================
# 基础用法
# ============================

# 实时监控（-x 扩展输出，每秒刷新，共5次）
iostat -xz 1 5

# 输出解读（关键列）：
# Device   r/s    w/s   rkB/s   wkB/s  await  svctm  %util
# sda     10.5   20.3   420.0   812.0   5.2    2.1   12.3
#           ↑      ↑      ↑       ↑      ↑      ↑      ↑
#           │      │      │       │      │      │      利用率(%)
#           │      │      │       │      │      平均服务时间(ms)
#           │      │      │       │      平均等待时间(ms)
#           │      │      │       写速度(KB/s)
#           │      │      读速度(KB/s)
#           │      每秒写次数
#           每秒读次数

# ============================
# 关键指标解读
# ============================

# %util: 磁盘利用率
#   < 70%  : 正常
#   70-90% : 需要注意
#   > 90%  : 磁盘可能是瓶颈

# await: 平均IO等待时间
#   < 5ms  : 很好（SSD通常<1ms）
#   5-20ms : 一般
#   > 50ms : 严重延迟

# r/s, w/s: IOPS（每秒IO操作数）
# rkB/s, wkB/s: 吞吐量

# ============================
# 实用技巧
# ============================

# 显示设备名称而非设备号
iostat -N -xz 1 5

# 只显示磁盘部分（不显示CPU）
iostat -d -xz 1 5

# 以MB为单位显示
iostat -xm 1 5
```

## 24.7 sar——系统活动报告（历史数据）

```bash

# 安装与启用
# ============================

# ============================

# ============================

# 内存使用

# 网络流量

# 磁盘IO

# 负载
sar -q 1 5

# ============================
# 查看历史数据（sar的杀手级功能）
# ============================

# 查看今天的CPU历史
sar -u -f /var/log/sysstat/sa15

# 查看今天的内存历史
sar -r -f /var/log/sysstat/sa15

# 查看昨天的数据
sar -u -f /var/log/sysstat/sa14

# 实用：查看昨天凌晨2点发生了什么（排查夜间故障）
sar -u -f /var/log/sysstat/sa14 | grep "02:"
```

## 24.8 free 与内存深度分析

```bash
# ============================
# free 命令详解
# ============================

free -h
#               total        used        free      shared  buff/cache   available
# Mem:           16Gi       6.2Gi       4.1Gi       256Mi       5.7Gi       9.2Gi
# Swap:         2.0Gi          0B       2.0Gi

# 关键理解：buff/cache 不是"浪费"
# Linux会把空闲内存用于缓存文件数据，加速IO
# 当应用需要更多内存时，缓存会自动释放

# available 才是真正可用内存（= free + 可回收的 buff/cache）

# ============================
# 内存使用分析
# ============================

# 查看各进程的内存使用
ps aux --sort=-%mem | head -15 | \
    awk 'NR==1 || NR>1 {printf "%-8s %-6s %5s %5s %s\n", $1, $2, $4"%", $6/1024"MB", $11}'

# 查看Slab内存使用（内核缓存）
cat /proc/meminfo | grep Slab
slabtop -o | head -20

# 查看内存碎片
cat /proc/buddyinfo

# 清理页面缓存（谨慎使用！）
# sync && echo 1 > /proc/sys/vm/drop_caches    # 清理页面缓存
# sync && echo 2 > /proc/sys/vm/drop_caches    # 清理dentries和inodes
# sync && echo 3 > /proc/sys/vm/drop_caches    # 清理所有缓存

# ============================
# OOM Killer 排查
# ============================

# 查看是否发生了OOM（Out of Memory）
dmesg | grep -i "oom\|killed process"
journalctl -k | grep -i oom

# 查看进程的OOM得分（分数越高越容易被OOM Killer选中）
for pid in $(ps aux -eo pid --no-headers); do
    if [ -f /proc/$pid/oom_score ]; then
        score=$(cat /proc/$pid/oom_score)
        cmd=$(cat /proc/$pid/cmdline 2>/dev/null | tr '\0' ' ' | head -c 50)
        [ -n "$cmd" ] && echo "$score $pid $cmd"
    fi
done | sort -rn | head -10
```

## 24.9 uptime 与 load average

```bash
# ============================
# uptime 详解
# ============================

uptime
# 10:30:00 up 45 days, 3:21, 2 users, load average: 1.23, 0.98, 0.87
#                                              1分钟 ↑    ↑    ↑
#                                              5分钟 ──┘    │
#                                              15分钟 ──────┘

# ============================
# 理解 load average
# ============================

# load average 表示平均运行队列长度
# 它包含了正在运行的进程 + 等待运行的进程 + 等待IO的进程

# 判断标准（对于N核CPU）：
# load < N     : CPU有空闲，一切正常
# load = N     : CPU刚好满载
# load > N     : CPU过载，进程在排队
# load > N*5   : 严重过载！

# 获取CPU核心数
nproc        # 如: 4

# 示例判断
load=$(uptime | awk -F'load average:' '{print $2}' | cut -d',' -f1 | tr -d ' ')
cores=$(nproc)
echo "负载: $load, 核心数: $cores"

# 如果 load > cores，需要进一步分析是CPU密集还是IO密集
# 看 top 的 wa% (IO等待百分比)
top -bn1 | grep "Cpu(s)"
```

```bash
dmesg

dmesg | grep -i usb

# 查看OOM Killer事件

# 查看启动时的硬件检测
dmesg | head -50

journalctl --since "1 hour ago" --until "now"
```

## 24.11 常见故障排查案例

### 案例1：CPU飙高

```bash
# ============================
# 步骤1：确认CPU使用情况
# ============================
top -bn1 | head -5
# 看 %Cpu(s) 行

# ============================
# 步骤2：找出哪个进程占用CPU
# ============================
ps aux --sort=-%cpu | head -10
# 或
top -c              # 按 P 键按CPU排序

# ============================
# 步骤3：分析该进程
# ============================
# 查看进程的线程
top -Hp <PID>

# 用 strace 看它在干什么
strace -p <PID> -c

# 用 perf 分析热点（需要安装 linux-tools）
sudo perf top -p <PID>

# ============================
# 步骤4：常见原因
# ============================
# - 死循环（代码bug）
# - 大量GC（Java/Go应用）
# - 正则表达式回溯（灾难性回溯）
# - 大量并发计算
# - 挖矿程序（安全事件！）
```

### 案例2：内存泄漏

```bash
# ============================
# 步骤1：确认内存使用
# ============================
free -h
# 看 used 和 available

# ============================
# 步骤2：找出内存大户
# ============================
ps aux --sort=-%mem | head -15

# 更精确地看RSS（实际物理内存）
ps -eo pid,rss,comm --sort=-rss | head -15 | \
    awk '{printf "%-8s %8s KB  %s\n", $1, $2, $3}'

# ============================
# 步骤3：监控内存变化趋势
# ============================
# 每5秒记录一次
for i in $(seq 1 60); do
    echo "$(date '+%H:%M:%S') $(free -m | awk '/^Mem:/ {print $3}')MB"
    sleep 5
done

# ============================
# 步骤4：常见原因
# ============================
# - 应用内存泄漏（没有释放不再使用的内存）
# - 缓存无限增长
# - 大量连接/socket未关闭
# - 内核Slab泄漏（查看 slabtop）
```

### 案例3：磁盘满了

```bash
# ============================
# 步骤1：确认磁盘使用
# ============================
df -h

# ============================
# 步骤2：找出大文件/目录
# ============================
# 找出当前目录下最大的10个目录
du -sh */ | sort -rh | head -10

# 找出最大的10个文件
find / -type f -exec du -h {} \; 2>/dev/null | sort -rh | head -10

# 更快的方式（只看一级目录）
du -sh /* 2>/dev/null | sort -rh | head -10

# ============================
# 步骤3：磁盘满了但找不到大文件？
# ============================
# 可能是已删除的文件仍被进程持有
lsof +L1
# 或
lsof | grep deleted

# 解决方法：重启持有文件的进程，或 kill 掉
# 然后空间就会释放

# ============================
# 步骤4：常见空间消耗大户
# ============================
du -sh /var/log/*    | sort -rh | head -5    # 日志
du -sh /tmp/*        | sort -rh | head -5    # 临时文件
du -sh /var/cache/*  | sort -rh | head -5    # 缓存

# 清理日志
sudo journalctl --vacuum-size=100M           # 限制systemd日志大小
sudo find /var/log -name "*.gz" -mtime +30 -delete  # 删除30天前的压缩日志
```

## 24.12 实战：排查"服务器响应变慢"的完整案例

```bash
#!/usr/bin/env bash
# ============================================================
# diagnose.sh - 服务器性能诊断脚本
# 功能：快速收集系统诊断信息，定位性能瓶颈
# 用法：sudo ./diagnose.sh
# ============================================================

set -euo pipefail

REPORT_FILE="/tmp/diagnose_$(date '+%Y%m%d_%H%M%S').txt"

log() { echo "[$(date '+%H:%M:%S')] $*"; }
section() { echo -e "\n========== $1 =========="; }

{
echo "服务器性能诊断报告"
echo "时间: $(date)"
echo "主机: $(hostname)"
echo ""

# ---- 系统概览 ----
section "系统概览"
uptime
uname -r
echo "CPU核心数: $(nproc)"
free -h
df -h /

# ---- CPU分析 ----
section "CPU分析"
echo "--- top CPU进程 ---"
ps aux --sort=-%cpu | head -8

echo ""
echo "--- 负载分析 ---"
echo "负载: $(cat /proc/loadavg)"
echo "CPU核心: $(nproc)"

# ---- 内存分析 ----
section "内存分析"
free -h

echo ""
echo "--- top 内存进程 ---"
ps aux --sort=-%mem | head -8

echo ""
echo "--- OOM记录 ---"
dmesg 2>/dev/null | grep -i "oom\|killed process" | tail -5 || echo "无OOM记录"

# ---- 磁盘IO分析 ----
section "磁盘IO分析"
if command -v iostat &>/dev/null; then
    iostat -xz 1 3
else
    echo "iostat未安装，使用vmstat替代"
    vmstat 1 3
fi

echo ""
echo "--- 磁盘空间 ---"
df -h

# ---- 网络分析 ----
section "网络分析"
ss -s
echo ""
echo "--- 连接数TOP ---"
ss -tn state established | awk '{print $5}' | cut -d: -f1 | \
    sort | uniq -c | sort -rn | head -10

# ---- 进程分析 ----
section "进程概览"
echo "进程总数: $(ps aux | wc -l)"
echo ""
echo "僵尸进程:"
ps aux | awk '$8 ~ /Z/ {print}' || echo "无僵尸进程"

echo ""
echo "D状态进程（不可中断的IO等待）:"
ps aux | awk '$8 ~ /D/ {print}' || echo "无D状态进程"

} 2>&1 | tee "$REPORT_FILE"

log ""
log "诊断报告已保存到: $REPORT_FILE"
```
