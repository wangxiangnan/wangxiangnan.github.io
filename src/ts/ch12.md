# 第十二章：类型兼容性与结构类型系统

TypeScript 使用**结构类型系统**（structural typing），而不是**名义类型系统**（nominal typing）。这是它类型系统的核心哲学之一。

## 结构类型 vs 名义类型

在名义类型系统里（比如 Java、C#），两个类型是否相同，取决于它们是否显式声明为同一个类型：

```java
class Dog { String name; }
class Cat { String name; }
// Dog 和 Cat 是不同的类型，即使结构一样
```

在结构类型系统里，只要两个类型的结构相同，它们就是兼容的：

```ts
interface Dog {
  name: string;
}

interface Cat {
  name: string;
}

let dog: Dog = { name: "Buddy" };
let cat: Cat = dog; // OK，因为结构相同
```

这种设计让 TypeScript 更灵活，但也意味着你不能像 Java 那样靠类型名来强制区分。

## 对象类型的兼容性

对象类型的兼容性遵循"鸭式辩型法"：只要一个对象包含目标类型要求的所有属性，且属性类型兼容，就可以赋值。

```ts
interface Point2D {
  x: number;
  y: number;
}

interface Point3D {
  x: number;
  y: number;
  z: number;
}

const point3D: Point3D = { x: 1, y: 2, z: 3 };
const point2D: Point2D = point3D; // OK，Point3D 包含 Point2D 的所有属性
```

但反过来不行：

```ts
const p2: Point2D = { x: 1, y: 2 };
const p3: Point3D = p2; // 错误，缺少 z
```

## 函数类型的兼容性

函数类型的兼容性更复杂。TypeScript 遵循以下规则：

1. 参数个数：目标函数参数可以比源函数少（函数可以忽略多余参数）。
2. 参数类型：源函数参数类型必须兼容目标函数参数类型。
3. 返回值类型：源函数返回值必须兼容目标函数返回值。

```ts
let fn1 = (a: number) => 0;
let fn2 = (a: number, b: string) => 0;

fn2 = fn1; // OK
fn1 = fn2; // 错误
```

这个规则看起来很反直觉，但想想回调函数就明白了：一个接收两个参数的函数，可以被一个只接收一个参数的函数替代，因为多余的参数会被忽略。

### 参数的协变与逆变

参数类型之间怎么比较？设 `Animal` 是 `Dog` 的父类型：

```ts
interface Animal {
  name: string;
}

interface Dog extends Animal {
  bark(): void;
}

let handleDog = (d: Dog) => d.bark();
let handleAnimal = (a: Animal) => a.name;

handleDog = handleAnimal; // OK：能处理任意动物的函数，当然能处理狗
handleAnimal = handleDog; // 严格模式下报错：只会处理狗的函数应付不了猫
```

第二个赋值在旧版 TypeScript 中居然是允许的（参数按"双向协变"比较，图方便但埋雷）。开启 `strictFunctionTypes`（第十一章）后，函数参数按**逆变**检查：只允许"参数更宽"的函数替换"参数更窄"的函数。这也是 `strict` 提升类型安全的一个例子。

## 泛型的兼容性

泛型的兼容性取决于类型参数是否被实际使用：

```ts
interface Empty<T> {}

let x: Empty<number>;
let y: Empty<string>;

x = y; // OK，因为 T 没有被使用
```

如果泛型参数影响了结构，兼容性就会按实际结构判断。

## 想要名义类型？给类型"打品牌"

结构类型的灵活性偶尔也会碍事：`UserId` 和 `OrderId` 底层都是 `string`，可以互相赋值，这通常不是你想要的。常见解法是加一个"品牌"标记：

```ts
type UserId = string & { readonly __brand: "UserId" };
type OrderId = string & { readonly __brand: "OrderId" };

function createUserId(raw: string): UserId {
  return raw as UserId; // 全项目唯一允许断言的"收口"
}

function createOrderId(raw: string): OrderId {
  return raw as OrderId;
}

function getUser(id: UserId) {
  /* ... */
}

const uid = createUserId("u-1");
const oid = createOrderId("o-1");

getUser(uid); // OK
getUser(oid); // 编译错误：OrderId 不能赋给 UserId
```

交叉类型让两个结构相同的 `string` 不再互相兼容，靠类型系统拦住"张冠李戴"。这个技巧在区分数据库 ID、金额单位（分 / 元）等易混淆的原始值时非常实用。

## 为什么理解类型兼容性很重要

类型兼容性决定了一个值能不能赋值给另一个类型。理解结构类型系统，能帮你避免很多"为什么这里能赋值"或"为什么这里不能赋值"的困惑。
