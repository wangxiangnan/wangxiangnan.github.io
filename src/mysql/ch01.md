# 第1章 MySQL 简介与安装

## 1.1 MySQL是什么？

想象你有一个超级智能的文件柜。普通的文件柜只能按文件夹分类存放资料，而这个智能文件柜能帮你自动建立索引、支持多人同时查阅、还能保证数据不会丢失——这就是关系型数据库的哲学。

MySQL就是这样一个"智能文件柜"。它由瑞典MySQL AB公司开发，后来被Sun收购，再后来被Oracle收入囊中。但MySQL始终是开源的，这也是它能成为世界上最流行的开源数据库的核心原因之一。

**关系型数据库的核心概念：**

- **表（Table）** = 电子表格的超级进化版，每一行是一条记录，每一列是一个字段
- **关系（Relation）** = 表与表之间的逻辑关联，比如"用户表"和"订单表"通过用户ID关联
- **SQL** = 结构化查询语言，你和数据库沟通的"普通话"

## 1.2 MySQL vs PostgreSQL vs SQLite

选数据库就像选交通工具，不同的场景需要不同的选择：

| 特性 | MySQL | PostgreSQL | SQLite |
|------|-------|------------|--------|
| 定位 | Web应用主力 | 学术/企业级重型 | 嵌入式/移动端 |
| 安装 | 需要安装服务 | 需要安装服务 | 零配置，单文件 |
| 并发 | 高并发支持好 | 高并发支持好 | 写并发较弱 |
| JSON支持 | 8.0+支持 | 原生支持很好 | 基础支持 |
| 社区生态 | 极其丰富 | 专业但稍小 | 广泛 |
| 适用场景 | Web后端、电商 | 数据分析、GIS | 移动App、本地缓存 |

> **Tip：** 如果你做Web开发，MySQL是默认选项；如果做数据分析或需要高级特性，PostgreSQL值得考虑；如果是移动端或小型工具，SQLite是最佳搭档。

## 1.3 安装MySQL

### 方式一：官方安装包

去[MySQL官网](https://dev.mysql.com/downloads/)下载对应操作系统的安装包。安装过程中会提示设置root密码，**请一定记住这个密码**，忘了会很麻烦。

> **Warning：** 安装时不要选"只安装Server"，建议选"Complete"或者至少加上MySQL Shell和MySQL Workbench。

### 方式二：Docker（推荐）

Docker安装是最干净利落的方式，不会污染你的系统环境：

```bash
# 拉取MySQL 8.0镜像
docker pull mysql:8.0

# 启动MySQL容器
docker run -d \
  --name mysql-tutorial \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=root123 \
  -e MYSQL_DATABASE=tutorial_db \
  mysql:8.0

# 查看容器状态
docker ps | grep mysql
```

连接Docker中的MySQL：

```bash
docker exec -it mysql-tutorial mysql -u root -p
```

### 方式三：Homebrew（macOS）

```bash
brew install mysql
brew services start mysql
mysql_secure_installation
```

## 1.4 首次连接

### mysql命令行

这是最原始也最强大的连接方式：

```bash
# 基本连接
mysql -u root -p

# 指定主机和端口
mysql -u root -p -h 127.0.0.1 -P 3306

# 直接指定数据库
mysql -u root -p -D tutorial_db
```

### MySQL Workbench

Oracle官方的图形化工具，适合可视化管理。下载安装后，点击"New Connection"，填入连接信息即可。

### DBeaver

一个通用的数据库管理工具，支持MySQL、PostgreSQL、SQLite等几乎所有主流数据库。如果你需要同时管理多种数据库，DBeaver是很好的选择。

## 1.5 验证安装

连上MySQL后，运行以下命令验证一切正常：

```sql
-- 查看MySQL版本
SELECT VERSION();
-- 输出示例：8.0.35

-- 查看当前用户
SELECT CURRENT_USER();
-- 输出示例：root@localhost

-- 查看所有数据库
SHOW DATABASES;
-- 输出示例：
-- +--------------------+
-- | Database           |
-- +--------------------+
-- | information_schema |
-- | mysql              |
-- | performance_schema |
-- | sys                |
-- | tutorial_db        |
-- +--------------------+

-- 查看服务器状态
SHOW STATUS LIKE 'Uptime';
```

> **Tip：** `information_schema`、`mysql`、`performance_schema`、`sys` 这四个是MySQL的系统数据库，不要随便动它们，尤其是`mysql`库——里面存着用户权限信息。

## 1.6 配置文件简介

MySQL的配置文件在不同系统上位置不同：

- **Linux/macOS**: `/etc/my.cnf` 或 `/etc/mysql/my.cnf`
- **Windows**: `C:\ProgramData\MySQL\MySQL Server X.X\my.ini`

一个基本的配置文件长这样：

```ini
[mysqld]
# 端口设置
port = 3306

# 最大连接数
max_connections = 200

# 字符集设置
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci

# InnoDB缓冲池大小（建议设为物理内存的50%-70%）
innodb_buffer_pool_size = 1G

[client]
default-character-set = utf8mb4
```

## 1.7 字符集与排序规则

这是很多初学者踩坑的地方。记住一条铁律：**永远使用 `utf8mb4`，不要用 `utf8`**。

为什么？因为MySQL的`utf8`只支持最多3字节的UTF-8编码，这意味着它无法存储emoji表情和一些特殊字符。`utf8mb4`才是完整的UTF-8支持（最多4字节）。

```sql
-- 查看当前字符集设置
SHOW VARIABLES LIKE 'character_set%';

-- 查看排序规则
SHOW VARIABLES LIKE 'collation%';

-- 查看所有可用的字符集
SHOW CHARACTER SET;

-- 查看所有可用的排序规则
SHOW COLLATION;
```

> **Warning：** 如果你的项目有可能出现emoji（用户昵称、评论内容等），从建库开始就必须使用`utf8mb4`。后期改字符集是个痛苦的过程，而且可能导致数据损坏。

## 小结

本章我们了解了MySQL的基本概念、对比了主流数据库、完成了安装配置、并验证了环境。最重要的是，我们学到了`utf8mb4`的重要性——这是很多教程不会强调的细节。

## 练习题

1. **基础题：** 安装MySQL（任选一种方式），连接到服务器，运行`SELECT VERSION();`确认版本号。
2. **探索题：** 运行`SHOW VARIABLES LIKE '%timeout%';`，找出MySQL的各种超时设置，想想它们各自的作用。
3. **思考题：** 如果你要开发一个面向全球用户的社交App，除了`utf8mb4`，你觉得字符集排序规则（collation）应该怎么选？为什么？
