## 7.2 Vite 配置与 Monorepo 的配合

编辑 `apps/web/vite.config.ts`：

```typescript
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import { fileURLToPath, URL } from 'node:url';

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
  server: {
    port: 5173,
    proxy: {
      // 开发环境下，将 /api 请求代理到后端服务
      '/api': {
        target: 'http://localhost:3000',
        changeOrigin: true,
      },
    },
  },
  // 不需要 optimizeDeps.include：workspace 链接包默认不参与预构建，
  // shared 的 development 条件导出直接指向 TS 源码，修改后 HMR 生效
});
```

**为什么不需要把 `@taskflow/shared` 放进 `optimizeDeps.include`？**

Vite 的依赖预构建只处理 `node_modules` 中的第三方依赖，workspace 链接包默认被排除在外。`@taskflow/shared` 的 `exports` 中，`development` 条件指向 `src/*.ts` 源码，开发服务器会像处理业务代码一样编译它，并纳入 HMR。如果强行 `include`，它会退化成"预构建依赖"——修改源码会触发重新预构建和整页刷新，反而失去细粒度热更新。共享包是纯 ESM，也不需要 `commonjsOptions.transformMixedEsModules`。

生产构建时 Vite 使用 `import` 条件读取 `dist/*.js`，因此构建前必须先构建 shared（Turborepo 的 `dependsOn: ["^build"]` 会自动保证顺序）。开发用源码、构建用产物，是 monorepo 前端最常见的组合。

## 7.3 集成共享包：直接 import 类型和工具

在 Ch03 创建的 `apps/web/src/types/env.d.ts` 中补充环境变量类型：

```typescript
interface ImportMetaEnv {
  // 后端服务源地址；留空表示同源请求（开发时由 Vite proxy 转发）
  readonly VITE_API_ORIGIN: string;
  readonly VITE_APP_TITLE: string;
}

interface ImportMeta {
  readonly env: ImportMetaEnv;
}
```

创建 `.env` 文件（`apps/web/.env`）：

```bash
# 留空：开发时请求走 Vite 代理，生产时由 Nginx / 网关转发 /api
VITE_API_ORIGIN=
VITE_APP_TITLE=TaskFlow
```

再创建 `.env.example`，把同样的键提交到 Git，作为新成员和部署平台的模板：

```bash
VITE_API_ORIGIN=
VITE_APP_TITLE=TaskFlow
```

`.env` 必须在 `.gitignore` 中；`.env.example` 不含真实值，可以安全提交。Web 的这两个变量都不敏感——`VITE_*` 会被打进前端产物，任何密钥都不能放在这里。

**为什么这里是空值，而不是 `http://localhost:3000`？**

`@taskflow/shared` 中的 `API_ROUTES` 已经带了 `/api` 前缀（例如 `/api/users`）。如果 `baseURL` 写死为 `http://localhost:3000`，开发时请求会绕过 Vite 代理直连后端；如果写成 `/api`，又会与路由常量拼接成 `/api/api/users`。留空表示"同源"：开发时由 `server.proxy` 把 `/api` 转发到 3000 端口，生产环境则由反向代理完成同样的转发。需要前后端分域部署时，把该变量设为 `https://api.example.com` 即可，axios 会把它与 `/api/...` 拼成完整地址。

## 7.4 路由配置（Vue Router）

创建 `apps/web/src/router/index.ts`：

```typescript
import { createRouter, createWebHistory } from 'vue-router';
import type { RouteRecordRaw } from 'vue-router';

// 路由懒加载 — 每个路由对应的组件在首次访问时才加载
const routes: RouteRecordRaw[] = [
  {
    path: '/',
    name: 'Home',
    component: () => import('@/views/HomeView.vue'),
    meta: { title: '首页', requiresAuth: false },
  },
  {
    path: '/users',
    name: 'UserList',
    component: () => import('@/views/UserListView.vue'),
    meta: { title: '用户列表' },
  },
  {
    path: '/users/:id',
    name: 'UserDetail',
    component: () => import('@/views/UserDetailView.vue'),
    meta: { title: '用户详情' },
    // 路由参数类型校验
    props: (route) => ({ id: String(route.params.id) }),
  },
  {
    path: '/login',
    name: 'Login',
    component: () => import('@/views/LoginView.vue'),
    meta: { title: '登录', requiresAuth: false },
  },
  {
    path: '/:pathMatch(.*)*',
    name: 'NotFound',
    component: () => import('@/views/NotFoundView.vue'),
    meta: { title: '404', requiresAuth: false },
  },
];

const router = createRouter({
  history: createWebHistory(),
  routes,
});

// 全局导航守卫 — 返回路由地址即重定向，无需调用 next
router.beforeEach((to) => {
  // 设置页面标题
  const title = to.meta.title as string | undefined;
  document.title = title
    ? `${title} - ${import.meta.env.VITE_APP_TITLE}`
    : import.meta.env.VITE_APP_TITLE;

  // 认证检查
  if (to.meta.requiresAuth !== false && !localStorage.getItem('accessToken')) {
    return { name: 'Login', query: { redirect: to.fullPath } };
  }
});

export default router;
```

> 首页、登录页和 404 显式标记了 `requiresAuth: false`，其余路由默认需要登录。采用"默认受保护、公开页面显式声明"的策略，可以避免新增页面时忘记加鉴权。

## 7.5 状态管理（Pinia）与共享类型

创建 `apps/web/src/stores/user.ts`：

```typescript
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';
import type { User, LoginDto, LoginResponse, ApiResponse } from '@taskflow/shared/types';
import { UserRole } from '@taskflow/shared/types';
import { API_ROUTES } from '@taskflow/shared/constants';
import { apiClient } from '@/utils/api';

export const useUserStore = defineStore('user', () => {
  // ====== State ======
  const currentUser = ref<User | null>(null);
  const isLoading = ref(false);
  const error = ref<string | null>(null);

  // ====== Getters ======
  const isLoggedIn = computed(() => currentUser.value !== null);
  const isAdmin = computed(() => currentUser.value?.role === UserRole.ADMIN);
  const displayName = computed(() => currentUser.value?.username ?? '游客');

  // ====== Actions ======
  async function login(credentials: LoginDto): Promise<boolean> {
    isLoading.value = true;
    error.value = null;

    try {
      const response = await apiClient.post<ApiResponse<LoginResponse>>(
        API_ROUTES.AUTH.LOGIN,
        credentials,
      );

      if (response.data.success && response.data.data) {
        const { user, accessToken, refreshToken } = response.data.data;
        currentUser.value = user;
        localStorage.setItem('accessToken', accessToken);
        localStorage.setItem('refreshToken', refreshToken);
        return true;
      }

      error.value = response.data.error?.message ?? '登录失败';
      return false;
    } catch (err) {
      error.value = err instanceof Error ? err.message : '网络请求失败';
      return false;
    } finally {
      isLoading.value = false;
    }
  }

  async function logout(): Promise<void> {
    try {
      await apiClient.post(API_ROUTES.AUTH.LOGOUT);
    } catch {
      // 即使请求失败也要清理本地状态
    } finally {
      currentUser.value = null;
      localStorage.removeItem('accessToken');
      localStorage.removeItem('refreshToken');
    }
  }

  async function fetchProfile(): Promise<void> {
    isLoading.value = true;
    try {
      const response = await apiClient.get<ApiResponse<User>>(
        API_ROUTES.USERS.PROFILE,
      );
      if (response.data.success && response.data.data) {
        currentUser.value = response.data.data;
      }
    } catch (err) {
      error.value = err instanceof Error ? err.message : '获取用户信息失败';
    } finally {
      isLoading.value = false;
    }
  }

  return {
    // State
    currentUser,
    isLoading,
    error,
    // Getters
    isLoggedIn,
    isAdmin,
    displayName,
    // Actions
    login,
    logout,
    fetchProfile,
  };
});
```

**为什么使用 Composition API 风格的 Pinia Store？**

Pinia 支持 Options API 和 Composition API 两种风格。Composition API 风格（使用 `setup` 函数 + `ref` / `computed`）与 Vue 3 的 `<script setup>` 保持一致，代码更灵活，类型推导也更好。特别是在使用共享类型时，`ref<User | null>` 的类型声明比 Options API 的 state 函数更直观。

## 7.6 API 请求封装（axios + 共享类型推导）

创建 `apps/web/src/utils/api.ts`：

```typescript
import axios from 'axios';
import type { AxiosInstance, InternalAxiosRequestConfig, AxiosResponse } from 'axios';
import type { ApiResponse } from '@taskflow/shared/types';
import { HTTP_STATUS } from '@taskflow/shared/constants';
import router from '@/router';

/**
 * 创建 axios 实例
 * 为什么不直接用全局 axios？因为全局配置会影响所有请求，
 * 包括第三方库发出的请求。独立实例让配置隔离。
 */
export const apiClient: AxiosInstance = axios.create({
  // 留空时 axios 直接使用 API_ROUTES 中的 /api/... 路径，由代理转发
  baseURL: import.meta.env.VITE_API_ORIGIN || undefined,
  timeout: 10000,
  headers: {
    'Content-Type': 'application/json',
  },
});

// ====== 请求拦截器：自动附加 JWT Token ======
apiClient.interceptors.request.use(
  (config: InternalAxiosRequestConfig) => {
    const token = localStorage.getItem('accessToken');
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error) => Promise.reject(error),
);

// ====== 响应拦截器：统一错误处理 ======
apiClient.interceptors.response.use(
  (response: AxiosResponse) => response,
  async (error) => {
    if (error.response) {
      const status = error.response.status;
      // 后端异常时响应体不一定是 ApiResponse，按可选处理
      const data = error.response.data as ApiResponse | undefined;

      switch (status) {
        case HTTP_STATUS.UNAUTHORIZED:
          // Token 过期或无效，跳转到登录页
          localStorage.removeItem('accessToken');
          localStorage.removeItem('refreshToken');
          router.push({ name: 'Login' });
          break;

        case HTTP_STATUS.FORBIDDEN:
          // 权限不足，可以显示全局提示
          console.error('权限不足:', data?.error?.message);
          break;

        case HTTP_STATUS.INTERNAL_SERVER_ERROR:
          console.error('服务器错误:', data?.error?.message);
          break;
      }
    } else if (error.request) {
      // 请求已发出但没有收到响应 — 网络问题
      console.error('网络连接失败，请检查网络设置');
    }

    return Promise.reject(error);
  },
);
```

**关于 Token 存储的安全提示：** 示例把 access token 放在 `localStorage`，实现简单，但任何 XSS 漏洞都能读取它。生产环境更安全的做法是由后端通过 `HttpOnly; Secure; SameSite=Lax` Cookie 下发会话，前端只保留非敏感的用户信息；如果必须使用 Bearer Token，应缩短有效期、配合刷新令牌轮换，并严格审查所有 `v-html` 和第三方脚本。

**类型推导的端到端体验：**

```typescript
// 在组件中使用时，类型推导是完整的：
const response = await apiClient.get<ApiResponse<User>>(API_ROUTES.USERS.BY_ID('123'));

// response.data 的类型是 ApiResponse<User>
// response.data.data 的类型是 User | undefined
// response.data.data.username 的类型是 string — 完整的类型推导链！
```

这就是"端到端类型安全"的威力：从后端数据库查出的 `User` 对象，到前端组件中渲染的用户名，整条链路上的类型都是关联的。如果后端的 `User` 接口增加了一个字段，前端使用到该字段的地方会自动获得类型提示；如果字段被删除或改名，TypeScript 会在编译时报错。

## 7.7 共享 Vue 组件库：packages/ui

在 monorepo 中创建共享组件包：

```bash
mkdir -p packages/ui/src/components
```

创建 `packages/ui/package.json`：

```json
{
  "name": "@taskflow/ui",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "types": "./src/index.ts",
  "exports": {
    ".": {
      "types": "./src/index.ts",
      "import": "./src/index.ts"
    }
  },
  "scripts": {
    "typecheck": "vue-tsc --noEmit"
  },
  "peerDependencies": {
    "vue": "^3.5.41"
  },
  "devDependencies": {
    "@taskflow/tsconfig": "workspace:*",
    "typescript": "^7.0.2",
    "vue": "^3.5.41",
    "vue-tsc": "^3.3.14"
  }
}
```

`exports` 中把 `types` 放在 `import` 前面，是 TypeScript 解析条件导出的硬性要求。这个包只被 Vite 消费，因此直接暴露 `.ts` 和 `.vue` 源码即可，`types` 与 `import` 指向同一个文件。

`private: true` 同样是有意为之：`ui` 直接发布源码、没有 `dist` 构建产物，只适合 workspace 内部消费。要对外发布组件库，需要先增加构建步骤（产出 JS + `.d.ts`），再移除 private 并配置 `publishConfig`——那是另一个话题，不在本教程范围内。

为了让 `vue-tsc --noEmit` 正常工作，还需要创建 `packages/ui/tsconfig.json`：

```json
{
  "extends": "@taskflow/tsconfig/vue-app.json",
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]
    }
  },
  "include": ["src/**/*.ts", "src/**/*.vue"]
}
```

**为什么共享组件库直接导出源码（`./src/index.ts`）而不是构建产物？**

在开发阶段，直接引用源码有两个优势：

1. **即时 HMR**：修改组件代码后，Vite 能立即检测到变化并热更新，不需要先构建
2. **简化配置**：不需要 tsup/vite 的 library mode 构建步骤

当需要发布到 npm 时，再切换到构建产物导出。对于 monorepo 内部使用，源码导出是更高效的方案。

在 `apps/web/package.json` 中添加依赖：

```json
{
  "dependencies": {
    "@taskflow/ui": "workspace:*"
  }
}
```

然后执行 `pnpm install`，pnpm 会在 `apps/web/node_modules` 中创建指向 `packages/ui` 的符号链接。

创建输入框组件 `packages/ui/src/components/BaseInput.vue`：

```vue
<script setup lang="ts">
interface Props {
  modelValue?: string;
  type?: 'text' | 'email' | 'password' | 'number';
  placeholder?: string;
  disabled?: boolean;
  error?: string;
  label?: string;
}

const props = withDefaults(defineProps<Props>(), {
  modelValue: '',
  type: 'text',
  placeholder: '',
  disabled: false,
  error: '',
  label: '',
});

const emit = defineEmits<{
  'update:modelValue': [value: string];
}>();

function handleInput(event: Event) {
  const target = event.target as HTMLInputElement;
  emit('update:modelValue', target.value);
}
</script>

<template>
  <div class="base-input-wrapper">
    <label v-if="props.label" class="base-input-label">
      {{ props.label }}
    </label>
    <input
      :type="props.type"
      :value="props.modelValue"
      :placeholder="props.placeholder"
      :disabled="props.disabled"
      :class="['base-input', { 'base-input--error': props.error }]"
```

## 7.8 在 apps/web 中使用共享组件

创建登录页面 `apps/web/src/views/LoginView.vue`：

```vue
<script setup lang="ts">
import { ref, reactive } from 'vue';
import { useRouter, useRoute } from 'vue-router';
import { BaseButton, BaseInput } from '@taskflow/ui';
import type { LoginDto } from '@taskflow/shared/types';
import { isValidEmail } from '@taskflow/shared/utils';
import { useUserStore } from '@/stores/user';

const router = useRouter();
const route = useRoute();
const userStore = useUserStore();

const form = reactive<LoginDto>({
  email: '',
  password: '',
});

const errors = reactive({
  email: '',
  password: '',
});

function validate(): boolean {
  let valid = true;
  errors.email = '';
  errors.password = '';

  if (!form.email) {
    errors.email = '请输入邮箱';
    valid = false;
  } else if (!isValidEmail(form.email)) {
    errors.email = '邮箱格式不正确';
    valid = false;
  }

  if (!form.password) {
    errors.password = '请输入密码';
    valid = false;
  }

  return valid;
}

async function handleLogin() {
  if (!validate()) return;

  const success = await userStore.login(form);
  if (!success) return;

  router.push(safeRedirect(route.query.redirect));
}

/** 只接受站内路径，阻止 //evil.com 这类协议相对地址造成开放重定向 */
function safeRedirect(raw: unknown): string {
  if (typeof raw !== 'string') return '/';
  return raw.startsWith('/') && !raw.startsWith('//') ? raw : '/';
}
</script>

<template>
  <div class="login-page">
    <div class="login-card">
      <h2>登录</h2>

      <p v-if="userStore.error" class="global-error">
        {{ userStore.error }}
      </p>

      <form @submit.prevent="handleLogin">
        <BaseInput
          v-model="form.email"
          type="email"
          label="邮箱"
          placeholder="your@email.com"
          :error="errors.email"
        />

        <BaseInput
          v-model="form.password"
          type="password"
          label="密码"
          placeholder="输入密码"
          :error="errors.password"

          type="submit"
          variant="primary"
          :loading="userStore.isLoading"
          class="login-button"
        >
          登录
        </BaseButton>
      </form>
    </div>
  </div>
</template>
```

**为什么登录后不能直接 `router.push(route.query.redirect as string)`？**

`redirect` 来自 URL 查询参数，属于不可信输入。如果攻击者构造 `/login?redirect=//evil.com`，而代码原样跳转，就可能把用户带到站外（开放重定向）。`safeRedirect` 只接受以单个 `/` 开头的站内路径，其他值一律回退到首页。导航守卫在写入 `redirect` 时也应使用 `to.fullPath`（只包含路径和查询串），而不是完整 URL。

## 本章小结

- Vite 通过 `workspace:*` 引用共享包；`exports` 的 `development` 条件指向 TS 源码，修改 shared 后 HMR 立即生效，生产构建则读取 `dist`
- Vue Router 5 的懒加载、返回值式导航守卫和 `safeRedirect` 共同构成了可靠的路由层
- Pinia 4 使用 Composition API 风格，与共享类型和 `<script setup>` 保持一致
- axios 封装层利用共享常量和类型实现统一的错误处理，并避免 baseURL 与 API_ROUTES 重复拼接
- `packages/ui` 直接导出源码，开发时零构建、类型检查用 vue-tsc，在效率和类型安全之间取得平衡
