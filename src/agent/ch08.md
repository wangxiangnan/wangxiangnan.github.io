# 第8章 Model I/O — LangChain 的模型抽象层

## 8.1 开篇：为什么需要"模型抽象层"？

在上一章中，我们用 `ChatOpenAI` 成功调用了 OpenAI 的模型。但你有没有想过这些问题：

- 如果我想切换到 Anthropic 的 Claude，是不是要把所有代码都改一遍？
- 如果我想在开发时用便宜的模型、生产时用强大的模型，怎么切换？
- 如果网络抖动导致 API 调用失败，我需要自己写重试逻辑吗？

这就是"模型抽象层"的价值所在。还记得我们在第2章讲的"API 调用"吗？当时我们直接用 OpenAI 的 SDK 调用。LangChain 在此基础上多加了一层抽象——就像你不会直接在代码里写 SQL 而是用 ORM 一样，LangChain 的 Model I/O 让你不用直接和 API 打交道。

这层抽象的好处是：**你的业务逻辑不依赖于特定的模型提供商**。今天用 OpenAI，明天换 Anthropic，后天用本地模型——你只需要改一行配置，而不是重写整个代码。

## 8.2 LLM vs ChatModel：选择你的"对话方式"

LangChain 提供两种模型接口：`LLM` 和 `ChatModel`。它们的关系就像"文本输入框"和"聊天窗口"——功能相似，但交互方式不同。

### 8.2.1 核心区别

| 特性 | LLM (旧式) | ChatModel (推荐) |
| ------ | ----------- | ------------------ |
| 输入格式 | 纯字符串 | 消息列表（Messages） |
| 输出格式 | 纯字符串 | AIMessage 对象 |
| 多轮对话 | 需要自己拼接上下文 | 天然支持消息列表 |
| 角色区分 | 不支持 | 支持 System/User/AI |
| 函数调用 | 不支持 | 原生支持 |
| 适用场景 | 简单的文本补全 | 几乎所有场景 |

```python
# 不推荐：使用旧式 LLM
from langchain_openai import OpenAI

llm = OpenAI(model="gpt-3.5-turbo-instruct")
result = llm.invoke("什么是 Python？")
# result 是一个字符串

# 推荐：使用 ChatModel
from langchain_openai import ChatOpenAI

chat_model = ChatOpenAI(model="gpt-4o-mini")
result = chat_model.invoke([
    ("system", "你是一个技术导师。"),
    ("human", "什么是 Python？"),
])
# result 是一个 AIMessage 对象，包含丰富的元数据
```

> ⚠️ **强烈建议只用 ChatModel**。旧式 LLM 接口已经逐步被弃用，而且很多新功能（如工具调用、结构化输出）只在 ChatModel 上可用。

### 8.2.2 ChatModel 的底层逻辑

ChatModel 本质上是把"消息列表"翻译成特定 API 的格式。当你调用 `ChatOpenAI.invoke()` 时，它做了这些事：

```
1. 接收 LangChain 消息列表
   [SystemMessage, HumanMessage, AIMessage, HumanMessage]

2. 转换为 OpenAI API 格式
   [
     {"role": "system", "content": "..."},
     {"role": "user", "content": "..."},
     {"role": "assistant", "content": "..."},
     {"role": "user", "content": "..."}
   ]

3. 发送 HTTP 请求到 OpenAI API

4. 解析响应，包装为 AIMessage 对象返回
```

无论你用 `ChatOpenAI`、`ChatAnthropic` 还是 `ChatOllama`，你的代码结构是一样的——LangChain 帮你做了翻译工作。

## 8.3 ChatOpenAI 配置详解

### 8.3.1 模型选择策略

OpenAI 提供了多个模型，每个有不同的能力和价格。选择模型就像选择汽车——你需要根据场景来选：

| 模型 | 能力 | 速度 | 价格 | 适用场景 |
| ------ | ------ | ------ | ------ | --------- |
| gpt-4o | 最强 | 中 | 高 | 复杂推理、代码生成 |
| gpt-4o-mini | 强 | 快 | 低 | 日常对话、简单任务 |
| gpt-4-turbo | 很强 | 中 | 中高 | 需要长上下文的场景 |
| o1-preview | 推理最强 | 慢 | 最高 | 数学、复杂逻辑推理 |

```python
from langchain_openai import ChatOpenAI

# 开发/测试环境：用便宜快速的模型
dev_model = ChatOpenAI(
    model="gpt-4o-mini",
    temperature=0.0,  # 开发时用确定性输出，方便调试
)

# 生产环境：用更强的模型
prod_model = ChatOpenAI(
    model="gpt-4o",
    temperature=0.7,  # 适当创造性
)

# 复杂推理场景
reasoning_model = ChatOpenAI(
    model="o1-preview",
    # 注意：o1 系列不支持 temperature 参数
)
```

### 8.3.2 核心参数详解

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    # === 基础参数 ===
    model="gpt-4o-mini",      # 模型名称
    
    # === 控制输出的参数 ===
    temperature=0.7,           # 温度：0.0-2.0
    # 0.0 = 确定性最高，总是选择最可能的下一个 token
    # 0.7 = 平衡创造性和准确性（推荐默认值）
    # 1.0+ = 更多创造性，但可能出现幻觉
    # 2.0 = 最大随机性
    
    max_tokens=2048,           # 最大输出 token 数
    # 注意：这是"输出"的最大长度，不是"输入+输出"
    # 如果回复被截断，增大这个值
    
    top_p=1.0,                 # 核采样：0.0-1.0
    # 和 temperature 类似，但通常不要同时调两个
    # 推荐：保持 1.0，只调 temperature
    
    # === 性能参数 ===
    streaming=False,           # 是否启用流式输出
    max_retries=2,             # API 调用失败时的重试次数
    request_timeout=30,        # 请求超时时间（秒）
    
    # === 高级参数 ===
    frequency_penalty=0.0,     # 频率惩罚：减少重复
    presence_penalty=0.0,      # 存在惩罚：鼓励新话题
)
```

### 8.3.3 temperature 的直觉理解

很多教程把 `temperature` 解释为"创造性"，但这不够准确。更精确的理解是：

**temperature 控制的是模型输出的"确定性"**。

- **temperature=0.0**：模型总是选择概率最高的 token。同样的输入总是得到同样的输出。适合代码生成、数据分析等需要准确性的场景。
- **temperature=0.7**：模型会在高概率的 token 中引入一些随机性。适合大多数对话场景。
- **temperature=1.5+**：模型可能会选择低概率的 token，导致输出更"有创意"但也更"离谱"。

```python
# 实验：同一个问题，不同温度
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

question = "用一句话描述'递归'。"

for temp in [0.0, 0.5, 1.0, 1.5]:
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=temp)
    response = llm.invoke([HumanMessage(content=question)])
    print(f"[temp={temp}] {response.content}")
```

## 8.4 消息类型系统：对话的"类型安全"

在第3章，我们学习了 Prompt Engineering 中的 System Prompt。LangChain 把它包装成了类型化的消息对象——这不仅仅是语法糖，而是提供了真正的"类型安全"。

### 8.4.1 四种核心消息类型

```python
from langchain_core.messages import (
    SystemMessage,    # 系统消息：定义 AI 的角色和行为
    HumanMessage,     # 人类消息：用户的输入
    AIMessage,        # AI 消息：AI 的回复
    ToolMessage,      # 工具消息：工具调用的结果（Ch12 详讲）
)

# SystemMessage — "你是谁"
system_msg = SystemMessage(
    content="你是 DocMind，一个智能文档问答助手。你擅长用类比解释技术概念。"
)

# HumanMessage — "用户说了什么"
human_msg = HumanMessage(content="什么是 API？")

# AIMessage — "AI 回复了什么"
ai_msg = AIMessage(
    content="API 就像餐厅的服务员——你不需要知道厨房里怎么做菜，"
            "只需要通过菜单（API）告诉服务员你想要什么。"
)

# ToolMessage — "工具返回了什么"（第12章会详细使用）
tool_msg = ToolMessage(
    content='{"result": "找到3篇相关文档"}',
    tool_call_id="call_abc123",  # 关联到具体的工具调用
)
```

### 8.4.2 快捷语法：元组形式

LangChain 也支持更简洁的元组语法——它会自动转换为对应的消息对象：

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini")

# 元组语法：(role, content)
messages = [
    ("system", "你是 DocMind，一个智能文档问答助手。"),
    ("human", "什么是 RESTful API？"),
]

response = llm.invoke(messages)

# 这两种写法是等价的：
# ("system", "xxx")  对应 SystemMessage(content="xxx")
# ("human", "xxx")   对应 HumanMessage(content="xxx")
# ("ai", "xxx")      对应 AIMessage(content="xxx")
```

### 8.4.3 消息列表就是"对话上下文"

在多轮对话中，消息列表就是整个对话的历史。每次调用 LLM 时，你需要把**完整的历史消息**都发送过去——因为 LLM 本身是无状态的。

```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, AIMessage, SystemMessage

llm = ChatOpenAI(model="gpt-4o-mini")

# 构建对话历史
messages = [
    SystemMessage(content="你是 DocMind。"),
    
    # 第一轮对话
    HumanMessage(content="什么是微服务？"),
    AIMessage(content="微服务是一种将应用拆分为多个独立部署的小型服务的架构风格。"),
    
    # 第二轮对话（LLM 可以看到前面的上下文）
    HumanMessage(content="它和单体架构有什么区别？"),
    # LLM 知道"它"指的是微服务，因为历史消息提供了上下文
]

response = llm.invoke(messages)
print(response.content)
```

> ⚠️ **消息列表会越来越大**：每轮对话都会增加消息，而这些消息会消耗 token。当消息列表超出模型的上下文窗口时，你需要"裁剪"——这就是第11章 Memory 要解决的问题。

## 8.5 流式输出(Streaming)：让用户不再干等

在第7章中我们初步体验了流式输出。现在让我们深入理解它的机制和高级用法。

### 8.5.1 流式输出的原理

普通的 `.invoke()` 是"同步等待"——发送请求，等模型生成完所有内容，然后一次性返回。

`.stream()` 是"增量接收"——发送请求后，模型一边生成一边返回，你可以实时处理每个片段。

这和前端中 `fetch` vs `EventSource` (SSE) 的关系类似。

```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

llm = ChatOpenAI(model="gpt-4o-mini", streaming=True)

# 方式一：简单的 for 循环
print("方式一：for 循环")
for chunk in llm.stream([HumanMessage(content="解释什么是 Docker。")]):
    # chunk 是一个 AIMessageChunk 对象
    # 它的 content 是本次新增的文本片段
    print(chunk.content, end="", flush=True)

print("\n")

# 方式二：收集完整响应
print("方式二：收集完整响应")
full_response = ""
for chunk in llm.stream([HumanMessage(content="解释什么是 Kubernetes。")]):
    full_response += chunk.content
    print(chunk.content, end="", flush=True)

print(f"\n\n完整响应长度: {len(full_response)} 字符")
```

### 8.5.2 流式输出中的元数据

LangChain 的流式输出不仅仅是返回文本片段——每个 chunk 都包含丰富的信息：

```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

llm = ChatOpenAI(model="gpt-4o-mini", streaming=True)

messages = [HumanMessage(content="用两句话介绍 Python。")]

for chunk in llm.stream(messages):
    # chunk.content — 本次的文本片段
    # chunk.response_metadata — 元数据（最后一个 chunk 中比较完整）
    # chunk.usage_metadata — token 使用量（最后一个 chunk）
    
    if chunk.content:
        print(chunk.content, end="", flush=True)
    
    # 最后一个 chunk 通常包含使用统计
    if chunk.usage_metadata:
        print(f"\n\nToken 使用统计:")
        print(f"  输入: {chunk.usage_metadata.get('input_tokens', 'N/A')}")
        print(f"  输出: {chunk.usage_metadata.get('output_tokens', 'N/A')}")
```

### 8.5.3 异步流式输出

在 Web 应用中，你通常需要异步处理流式输出。LangChain 也支持：

```python
import asyncio
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

async def async_stream():
    """异步流式输出示例"""
    llm = ChatOpenAI(model="gpt-4o-mini", streaming=True)
    
    messages = [HumanMessage(content="解释什么是 WebSocket。")]
    
    # 使用 astream() 进行异步流式输出
    async for chunk in llm.astream(messages):
        print(chunk.content, end="", flush=True)
        await asyncio.sleep(0)  # 让出控制权

# 运行异步函数
asyncio.run(async_stream())
```

## 8.6 结构化输出：让 LLM 返回你需要的格式

这可能是 LangChain 最实用的功能之一。在真实项目中，你很少需要 AI 返回一段自由文本——你通常需要结构化的数据，比如 JSON 对象、数据库记录、或者 Pydantic 模型。

### 8.6.1 问题：LLM 的"自由发挥"

```python
# 不推荐：让 LLM 自由输出，然后用正则解析
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

llm = ChatOpenAI(model="gpt-4o-mini")

response = llm.invoke([
    HumanMessage(
        content="请分析这段代码：def add(a, b): return a + b\n"
                "请给出函数名、参数列表、返回值类型。"
    )
])

# response.content 可能是：
# "函数名是 add，有两个参数 a 和 b，返回值类型取决于输入参数的类型..."
# 你需要用正则或字符串分割来提取信息——脆弱且不可靠
```

### 8.6.2 解决方案：.with_structured_output()

```python
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field
from typing import Optional

# 第一步：定义你期望的输出结构
class CodeAnalysis(BaseModel):
    """代码分析结果"""
    function_name: str = Field(description="函数名称")
    parameters: list[str] = Field(description="参数名称列表")
    return_type: str = Field(description="返回值类型")
    complexity: str = Field(description="复杂度评估：简单/中等/复杂")
    summary: str = Field(description="一句话功能总结")

# 第二步：创建模型并绑定输出格式
llm = ChatOpenAI(model="gpt-4o-mini")
structured_llm = llm.with_structured_output(CodeAnalysis)

# 第三步：调用 — 返回值直接是 CodeAnalysis 对象！
result = structured_llm.invoke(
    "请分析这段代码：def add(a, b): return a + b"
)

# result 是一个 CodeAnalysis 实例
print(f"函数名: {result.function_name}")        # "add"
print(f"参数: {result.parameters}")              # ["a", "b"]
print(f"返回类型: {result.return_type}")         # "Any"
print(f"复杂度: {result.complexity}")            # "简单"
print(f"总结: {result.summary}")
```

### 8.6.3 更复杂的结构化输出

```python
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field
from enum import Enum

class Severity(str, Enum):
    """问题严重程度"""
    LOW = "low"
    MEDIUM = "medium"
    HIGH = "high"
    CRITICAL = "critical"

class CodeIssue(BaseModel):
    """代码中的一个问题"""
    line_number: int = Field(description="问题所在行号")
    description: str = Field(description="问题描述")
    severity: Severity = Field(description="严重程度")
    suggestion: str = Field(description="修复建议")

class CodeReview(BaseModel):
    """代码审查结果"""
    overall_quality: int = Field(description="总体质量评分 (1-10)", ge=1, le=10)
    issues: list[CodeIssue] = Field(description="发现的问题列表")
    strengths: list[str] = Field(description="代码的优点")
    summary: str = Field(description="总体评价")

# 使用
llm = ChatOpenAI(model="gpt-4o-mini")
reviewer = llm.with_structured_output(CodeReview)

code = """
def process_user(user_dict):
    name = user_dict['name']
    age = user_dict['age']
    if age > 18:
        return f"{name} is an adult"
    return f"{name} is a minor"
"""

result = reviewer.invoke(f"请审查以下 Python 代码：\n{code}")

print(f"质量评分: {result.overall_quality}/10")
print(f"\n发现的问题:")
for issue in result.issues:
    print(f"  [{issue.severity.value}] 行{issue.line_number}: {issue.description}")
    print(f"    建议: {issue.suggestion}")
print(f"\n优点:")
for strength in result.strengths:
    print(f"  - {strength}")
```

### 8.6.4 结构化输出的工作原理

当你调用 `.with_structured_output()` 时，LangChain 背后做了这些事：

1. **把你的 Pydantic 模型转换为 JSON Schema** — 让 LLM 知道输出应该是什么格式
2. **使用 Function Calling / Tool Use** — 告诉 LLM "你必须调用这个函数"
3. **解析 LLM 的函数调用结果** — 把 JSON 转换回 Pydantic 对象

> ⚠️ **结构化输出的限制**：不是所有模型都支持 Function Calling。目前 OpenAI 的 GPT 系列和 Anthropic 的 Claude 系列都支持，但一些开源模型可能不支持。

## 8.7 多模型切换：同一套代码，不同的 AI 大脑

### 8.7.1 为什么需要多模型？

在真实项目中，你可能需要：

- **开发时用便宜模型，生产用强模型** — 省钱
- **不同任务用不同模型** — 简单任务用快速模型，复杂推理用强模型
- **本地测试用 Ollama** — 不消耗 API 额度

### 8.7.2 切换模型只需改一行

```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage

def create_model(provider: str = "openai"):
    """工厂函数：根据 provider 创建不同的模型"""
    
    if provider == "openai":
        return ChatOpenAI(model="gpt-4o-mini", temperature=0.7)
    
    elif provider == "anthropic":
        from langchain_anthropic import ChatAnthropic
        return ChatAnthropic(model="claude-3-5-sonnet-20241022", temperature=0.7)
    
    elif provider == "ollama":
        from langchain_ollama import ChatOllama
        return ChatOllama(model="llama3.1", temperature=0.7)
    
    else:
        raise ValueError(f"不支持的 provider: {provider}")

# 核心业务逻辑完全不依赖特定模型
def ask_question(llm, question: str) -> str:
    """这个函数不关心你用的是哪个模型"""
    messages = [
        SystemMessage(content="你是 DocMind，一个智能文档问答助手。"),
        HumanMessage(content=question),
    ]
    response = llm.invoke(messages)
    return response.content

# 使用不同的模型
for provider in ["openai"]:  # 可以添加 "anthropic", "ollama"
    llm = create_model(provider)
    answer = ask_question(llm, "什么是微服务？")
    print(f"[{provider}] {answer[:100]}...")
```

### 8.7.3 模型回退策略

在生产环境中，你可能需要一个"回退"机制——当主模型不可用时，自动切换到备用模型：

```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage
import time

class ModelRouter:
    """模型路由器：支持回退策略"""
    
    def __init__(self):
        self.models = [
            ChatOpenAI(model="gpt-4o", temperature=0.7),       # 首选
            ChatOpenAI(model="gpt-4o-mini", temperature=0.7),  # 回退1
        ]
    
    def invoke(self, messages, max_retries=3):
        """尝试调用模型，失败时回退到下一个"""
        for model in self.models:
            for attempt in range(max_retries):
                try:
                    return model.invoke(messages)
                except Exception as e:
                    print(f"模型调用失败 (尝试 {attempt + 1}): {e}")
                    if attempt < max_retries - 1:
                        time.sleep(2 ** attempt)  # 指数退避
            print(f"模型不可用，尝试下一个...")
        raise RuntimeError("所有模型都不可用！")

# 使用
router = ModelRouter()
response = router.invoke([HumanMessage(content="你好")])
print(response.content)
```

## 8.8 错误处理和重试策略

### 8.8.1 常见错误类型

| 错误类型 | 含义 | 处理策略 |
| --------- | ------ | --------- |
| APIConnectionError | 网络连接失败 | 检查网络，重试 |
| RateLimitError | 超出速率限制 | 等待后重试（指数退避） |
| APITimeoutError | 请求超时 | 增加超时时间或重试 |
| AuthenticationError | API Key 无效 | 检查 API Key（不要重试） |
| BadRequestError | 请求参数错误 | 检查请求参数（不要重试） |
| InternalServerError | 服务器端错误 | 等待后重试 |

### 8.8.2 完整的错误处理方案

```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage
import time
import logging

logger = logging.getLogger(__name__)

class SafeChatModel:
    """带完整错误处理的 ChatModel 包装器"""
    
    def __init__(self, model_name="gpt-4o-mini", max_retries=3):
        self.llm = ChatOpenAI(
            model=model_name,
            max_retries=max_retries,  # LangChain 内置重试
            request_timeout=30,       # 30秒超时
        )
        self.max_retries = max_retries
    
    def safe_invoke(self, messages):
        """安全调用：处理各种异常情况"""
        for attempt in range(self.max_retries):
            try:
                return self.llm.invoke(messages)
            except Exception as e:
                error_name = type(e).__name__
                
                # 不可重试的错误 — 直接抛出
                if "Authentication" in error_name:
                    logger.error("API Key 无效，请检查 .env 文件")
                    raise
                if "BadRequest" in error_name:
                    logger.error(f"请求参数错误: {e}")
                    raise
                
                # 可重试的错误 — 指数退避
                wait_time = 2 ** attempt
                logger.warning(
                    f"网络/速率错误 (尝试 {attempt + 1}): {e}，"
                    f"等待 {wait_time} 秒后重试..."
                )
                time.sleep(wait_time)
        
        raise RuntimeError(f"调用失败，已重试 {self.max_retries} 次")

# 使用示例
safe_model = SafeChatModel()
try:
    response = safe_model.safe_invoke([HumanMessage(content="你好，DocMind！")])
    print(response.content)
except Exception as e:
    print(f"最终失败: {e}")
```

## 8.9 实战演练：DocMind 的模型层封装

```python
# src/agent/base.py — DocMind 的模型层
"""DocMind 模型层封装"""

from typing import Optional, Type
from pydantic import BaseModel
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage, AIMessage

load_dotenv()

class DocMindConfig(BaseModel):
    """DocMind 模型配置"""
    model_name: str = "gpt-4o-mini"
    temperature: float = 0.7
    max_tokens: int = 2048
    streaming: bool = True
    max_retries: int = 3
    request_timeout: int = 30

class DocMindModel:
    """DocMind 模型封装"""
    
    def __init__(self, config: Optional[DocMindConfig] = None):
        self.config = config or DocMindConfig()
        self._llm = ChatOpenAI(
            model=self.config.model_name,
            temperature=self.config.temperature,
            max_tokens=self.config.max_tokens,
            streaming=self.config.streaming,
            max_retries=self.config.max_retries,
            request_timeout=self.config.request_timeout,
        )
    
    def chat(self, user_input: str,
             system_prompt: str = "你是 DocMind，一个智能文档问答助手。",
             history: Optional[list] = None) -> str:
        """简单的聊天接口"""
        messages = [SystemMessage(content=system_prompt)]
        if history:
            messages.extend(history)
        messages.append(HumanMessage(content=user_input))
        response = self._llm.invoke(messages)
        return response.content
    
    def stream_chat(self, user_input: str,
                    system_prompt: str = "你是 DocMind，一个智能文档问答助手。",
                    history: Optional[list] = None):
        """流式聊天接口"""
        messages = [SystemMessage(content=system_prompt)]
        if history:
            messages.extend(history)
        messages.append(HumanMessage(content=user_input))
        for chunk in self._llm.stream(messages):
            if chunk.content:
                yield chunk.content
    
    def structured_output(self, output_schema: Type[BaseModel]):
        """获取结构化输出的模型"""
        return self._llm.with_structured_output(output_schema)
    
    def get_llm(self) -> ChatOpenAI:
        """获取底层的 LangChain LLM 实例"""
        return self._llm

# 使用示例
if __name__ == "__main__":
    model = DocMindModel()
    
    # 基础聊天
    print("=== 基础聊天 ===")
    response = model.chat("用一句话解释什么是 API。")
    print(f"DocMind: {response}\n")
    
    # 流式输出
    print("=== 流式输出 ===")
    print("DocMind: ", end="")
    for text in model.stream_chat("用两句话解释什么是 Docker。"):
        print(text, end="", flush=True)
    print("\n")
    
    # 结构化输出
    print("=== 结构化输出 ===")
    class TechConcept(BaseModel):
        name: str
        category: str
        difficulty: str
        one_line_explanation: str
    
    structured_model = model.structured_output(TechConcept)
    result = structured_model.invoke("请解释 Kubernetes 这个技术概念。")
    print(f"概念: {result.name}")
    print(f"分类: {result.category}")
    print(f"难度: {result.difficulty}")
    print(f"一句话解释: {result.one_line_explanation}")
```

## 8.10 本章小结

1. **LLM vs ChatModel** — 推荐始终使用 ChatModel，它支持消息列表、角色区分和函数调用。
2. **消息类型系统** — SystemMessage、HumanMessage、AIMessage、ToolMessage 构成了对话的"类型安全"。
3. **流式输出** — 使用 `.stream()` 实现打字机效果，提升用户体验。
4. **结构化输出** — `.with_structured_output()` 让 LLM 直接返回 Pydantic 对象，告别字符串解析。
5. **多模型切换** — 同一套业务代码，只需改一行配置就能切换模型提供商。
6. **错误处理** — 区分可重试错误和不可重试错误，实现指数退避重试。
