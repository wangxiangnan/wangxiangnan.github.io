# 第12章 Tools — Agent 的"手"和"脚"

## 12.1 开篇：从"只会说"到"能做事"

在前面的章节中，DocMind 已经能对话、能读文档、有记忆。但它还缺少一个关键能力：**做事**。

目前 DocMind 的所有回复都是 LLM 直接生成的文本。但如果用户说"帮我搜索一下项目文档里关于 Docker 的内容"，LLM 不可能直接访问你的文档数据库——它只能"说"，不能"做"。

Tool（工具）就是让 Agent 从"只会说"变成"能做事"的桥梁。把 Tool 想象成 API endpoint——每个 Tool 有一个名称、一段描述、一个输入格式，Agent 决定何时调用哪个 Tool，然后拿到 Tool 的结果来生成最终回答。

在 Part 1 的第4章中，我们了解了 Agent 四大组件中的"行动"。Tool 就是"行动"的具体实现。

## 12.2 Tool 的三要素

每个 Tool 都有三个核心要素：

| 要素 | 说明 | 类比 |
|------|------|------|
| name | 工具名称（英文，简洁） | API endpoint 的路径 |
| description | 工具描述（告诉 LLM 何时使用） | API 文档 |
| args_schema | 输入参数定义（Pydantic 模型） | API 的请求体 Schema |

LLM 通过阅读 `description` 来决定是否使用这个工具——所以描述的质量直接决定了 Agent 会不会在正确的时机调用工具。

## 12.3 @tool 装饰器：快速创建自定义 Tool

```python
from langchain_core.tools import tool

@tool
def search_documents(query: str, k: int = 3) -> str:
    """在文档库中搜索与查询相关的内容。
    当用户询问关于特定技术概念、API 用法或项目文档内容时使用此工具。
    
    Args:
        query: 搜索查询关键词
        k: 返回结果数量，默认3条
    """
    # 这里是你的实际搜索逻辑
    # 例如：调用向量数据库的检索功能
    results = f"找到 {k} 条关于 '{query}' 的相关文档"
    return results

# 查看工具信息
print(f"名称: {search_documents.name}")
print(f"描述: {search_documents.description}")
print(f"参数: {search_documents.args}")
```

> ⚠️ **description 的质量至关重要**：LLM 完全依赖 description 来决定何时调用工具。写得不好，Agent 要么不调用工具，要么在不该调用时调用。要像写 API 文档一样认真地写 description。

## 12.4 StructuredTool.from_function()：更精细的定义

```python
from langchain_core.tools import StructuredTool
from pydantic import BaseModel, Field

class SearchInput(BaseModel):
    """搜索工具的输入参数"""
    query: str = Field(description="搜索查询关键词")
    k: int = Field(default=3, description="返回结果数量", ge=1, le=10)
    category: str = Field(default="all", description="搜索分类：all/python/docker/api")

def search_impl(query: str, k: int = 3, category: str = "all") -> str:
    """搜索实现"""
    return f"在 [{category}] 中找到 {k} 条关于 '{query}' 的结果"

search_tool = StructuredTool.from_function(
    func=search_impl,
    name="search_documents",
    description="在技术文档库中搜索相关内容。当用户询问特定技术概念或查找文档时使用。",
    args_schema=SearchInput,
)

# 调用
result = search_tool.invoke({"query": "Docker", "k": 5, "category": "docker"})
print(result)
```

## 12.6 Tool 的错误处理

```python
from langchain_core.tools import tool

@tool
def safe_search(query: str) -> str:
    """安全搜索工具，包含错误处理"""
    try:
        # 模拟可能失败的操作
        if not query.strip():
            raise ValueError("查询不能为空")
        
        results = f"搜索结果: {query}"
        return results
        
    except ValueError as e:
        # 返回错误信息而不是抛出异常
        # 这样 Agent 可以理解错误并调整策略
        return f"搜索出错: {e}。请检查查询关键词。"
    except Exception as e:
        return f"搜索服务暂时不可用，请稍后重试。错误: {type(e).__name__}"
```

> ⚠️ **Tool 中不要抛出未捕获的异常**：如果 Tool 抛出异常，整个 Agent 的执行链可能会中断。应该捕获异常并返回有意义的错误信息，让 Agent 能够理解并做出调整。

"""DocMind 代码分析工具"""
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

@tool
def analyze_code(code: str, language: str = "python") -> str:
    """分析代码片段，找出问题并给出改进建议。
    当用户提供代码并希望获得分析、审查或优化建议时使用此工具。
    
    Args:
        code: 要分析的代码片段
        language: 编程语言，默认 python
    """
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
    prompt = f"""请分析以下 {language} 代码：

```{language}
{code}
```

请给出：

1. 功能概述（1句话）
2. 潜在问题
3. 改进建议
4. 改进后的代码"""

    response = llm.invoke([HumanMessage(content=prompt)])
    return response.content

# src/tools/summarizer.py — 文档摘要工具

"""DocMind 文档摘要工具"""
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

@tool
def generate_summary(content: str, style: str = "concise") -> str:
    """为技术文档生成摘要。
    当用户需要快速了解一篇长文档的核心内容时使用此工具。

    Args:
        content: 要摘要的文档内容
        style: 摘要风格 - concise(简洁) / detailed(详细) / bullet_points(要点)
    """
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.3)
    
    style_instructions = {
        "concise": "用3-5句话概括核心内容",
        "detailed": "详细概括，保留关键技术细节和代码示例",
        "bullet_points": "用要点列表的形式列出核心内容",
    }
    
    prompt = f"""请为以下技术文档生成摘要。
风格要求：{style_instructions.get(style, style_instructions['concise'])}

文档内容：
{content[:3000]}"""

    response = llm.invoke([HumanMessage(content=prompt)])
    return response.content

def get_tool_by_name(name: str):
    """通过名称获取工具"""

        print(f"  参数: {list(t.args.keys())}")

## 12.8 Tool 设计最佳实践

1. **名称简洁明确** — `search_documents` 比 `search_for_documents_in_the_database` 好
2. **描述要具体** — 告诉 LLM "什么时候用"和"什么时候不用"
3. **参数要有默认值** — 减少 LLM 需要"猜测"的参数数量
4. **返回值要有意义** — 返回结构化的信息，而不是一段混乱的文本
5. **错误要优雅** — 捕获异常，返回有用的错误信息

## 12.8 ToolKit：Tool 的组合和管理

当你的项目有越来越多的 Tool 时，你需要一种方式来组织和管理它们。就像你不会把所有函数都放在一个文件里一样，Tool 也需要分组管理。

```python
# src/tools/toolkit.py — 工具集管理
"""DocMind 工具集管理器"""

from typing import List
from langchain_core.tools import BaseTool

class DocMindToolkit:
    """工具集管理器"""
    
    def __init__(self):
        self._tools: List[BaseTool] = []
    
    def register(self, tool: BaseTool):
        """注册一个工具"""
        self._tools.append(tool)
        print(f"  注册工具: {tool.name}")
    
    def get_tools(self) -> List[BaseTool]:
        """获取所有工具"""
        return self._tools
    
    def get_tool_names(self) -> List[str]:
        """获取所有工具名称"""
        return [t.name for t in self._tools]
    
    def describe_tools(self) -> str:
        """生成工具描述（供 Agent 使用）"""
        lines = ["可用工具："]
        for t in self._tools:
            lines.append(f"- {t.name}: {t.description[:80]}...")
        return "\n".join(lines)

def create_docmind_toolkit() -> DocMindToolkit:
    """创建 DocMind 的标准工具集"""
    from src.tools.search import search_documents
    from src.tools.code_analyzer import analyze_code
    from src.tools.summarizer import generate_summary
    
    toolkit = DocMindToolkit()
    toolkit.register(search_documents)
    toolkit.register(analyze_code)
    toolkit.register(generate_summary)
    
    return toolkit

# 使用
toolkit = create_docmind_toolkit()
print(toolkit.describe_tools())
```

## 12.9 Part 3 预告：让 Agent 真正"思考"和"行动"

到现在为止，DocMind 已经有了所有"零件"：

- **大脑**（Model I/O） — 能思考和生成回答
- **眼睛**（RAG） — 能读取文档
- **记忆**（Memory） — 能记住对话
- **手脚**（Tools） — 能执行操作

但还缺少一个关键的"指挥官"——**谁来协调这些组件？谁来决定什么时候该搜索文档、什么时候该直接回答、什么时候该分析代码？**

这就是 Part 3 要解决的问题。在 Part 3（Ch13-Ch18）中，我们将学习：

- **Function Calling** — LLM 如何自动决定调用哪个工具
- **ReAct 模式** — 让 Agent 学会"思考-行动-观察"的循环
- **LangGraph 入门** — 用图结构编排复杂的 Agent 工作流
- **Agent 实战** — 把 DocMind 升级为一个真正的 AI Agent
- **Human-in-the-loop** — 在关键决策点让人类介入
- **持久化** — 让 Agent 能"记住"自己的执行状态

DocMind 即将从一个"有零件的机器人"进化为一个"有自主意识的 AI Agent"。

## 12.10 本章小结

1. **Tool 的本质** — 让 Agent 从"只会说"变成"能做事"，每个 Tool 就像一个 API endpoint。
2. **三要素** — name（名称）、description（描述）、args_schema（参数定义）。
3. **创建方式** — `@tool` 装饰器最简单，`StructuredTool.from_function()` 更精细。
4. **错误处理** — Tool 中应捕获异常并返回有意义的错误信息。
5. **设计原则** — 名称简洁、描述具体、参数有默认值、返回有意义。
