# 第7章 实战应用

> **本章回答的问题**：理论如何落地？1px 边框、高清图、响应式检查清单这些经典问题怎么解决？

## 7.1 经典难题：1px 边框

设计稿（通常以 @2x 或 @3x 出图）上的 1px 细线，指 1 个**物理**像素。而 CSS 里写 `border: 1px` 是 1 个 CSS 像素 = 3 个物理像素（@3x 屏），显得粗。

方案一（推荐）：按 DPR 缩放伪元素

```css
.hairline {
  position: relative;
}
.hairline::after {
  content: '';
  position: absolute;
  left: 0; bottom: 0;
  width: 100%;
  height: 1px;
  background: #ddd;
  transform: scaleY(calc(1 / var(--dpr, 1)));  /* 3x 屏压成 1/3 高 */
  transform-origin: 0 0;
}
```

JS 里把 `devicePixelRatio` 写入 `--dpr` 即可。原理：把 1 个 CSS 像素的高度再除以 DPR，落到 1 个物理像素。

方案二：`0.5px`。iOS Safari 支持 0.5px 渲染为半像素，Android 部分设备会四舍五入成 0 或 1px，需要特性检测，兼容性不如方案一稳定。

**动手验证：三种画法对比**——保存为 `hairline.html` 在真机打开，肉眼对比三条线的粗细；A 与 C 的差异随 DPR 增大越明显：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>1px 边框对比</title>
<style>
  body { font: 16px/1.8 system-ui, sans-serif; max-width: 480px; margin: 0 auto; padding: 16px; }
  .label { color: #666; font-size: 14px; margin-bottom: 4px; }
  .row { padding: 12px 0; }
  .b1  { border-bottom: 1px solid #333; }
  .b05 { border-bottom: 0.5px solid #333; }
  .hair { position: relative; }
  .hair::after {
    content: '';
    position: absolute; left: 0; bottom: 0;
    width: 100%; height: 1px; background: #333;
    transform: scaleY(calc(1 / var(--dpr, 1)));
    transform-origin: 0 0;
  }
</style>
</head>
<body>
  <h3>1px 边框的三种画法（当前 DPR：<span id="outDpr">–</span>）</h3>
  <div class="row">
    <p class="label">A. border: 1px —— 占 DPR 个物理像素，@3x 屏上是 3 物理像素粗</p>
    <div class="b1">内容内容内容</div>
  </div>
  <div class="row">
    <p class="label">B. border: 0.5px —— iOS Safari 有效，部分安卓四舍五入成 0 或 1px</p>
    <div class="b05">内容内容内容</div>
  </div>
  <div class="row">
    <p class="label">C. 伪元素 scaleY(1/DPR) —— 稳定落到 1 个物理像素</p>
    <div class="hair">内容内容内容</div>
  </div>
<script>
  const dpr = window.devicePixelRatio || 1;
  document.getElementById('outDpr').textContent = dpr;
  document.documentElement.style.setProperty('--dpr', dpr);
</script>
</body>
</html>
```

## 7.2 高清图：@2x/@3x 与 srcset

图片小于其显示尺寸 × DPR 时会被拉伸发虚。在 DPR 3 的屏幕上，一张实际 300px 宽的图片以 `width: 100px`（CSS）显示，需要 300 物理像素，恰好 1:1 清晰；若图片只有 100 物理像素宽，则每个物理像素被放大 3 倍，模糊。

用 `srcset` 让浏览器按 DPR 自动选图：

```html
<img src="photo-1x.jpg"
     srcset="photo-2x.jpg 2x, photo-3x.jpg 3x"
     alt="示例图">
```

导出规则：设计稿 @3x 出图，图片物理像素数 = CSS 显示尺寸 × 3。Safari 的 DPR 恒定 3，选择稳定；桌面 Chrome 上用户缩放会改变 DPR，`srcset` 也会随之切换，浏览器已处理好，无需 JS 干预。

## 7.3 响应式开发检查清单

1. `<meta name="viewport" content="width=device-width, initial-scale=1">` 是否存在——没有它，一切媒体查询都基于 980 而失效。
2. 布局单位优先用 `%` / `flex` / `grid` / `vw`，避免依赖固定 px 值铺宽度。
3. 媒体查询断点基于 CSS 像素写（如 768、1024），它们已是逻辑值，不要除以 DPR。
4. 需要物理像素精度时（细边框、阴影、发丝线）才用 `devicePixelRatio` 做换算。
5. iOS 上不要依赖 `user-scalable=no` 禁缩放；布局适配刘海用 `viewport-fit=cover` + `env(safe-area-inset-*)`。

## 7.4 常见错误与误区

| 误区 | 真相 |
| ------ | ------ |
| "retina 屏上 1 CSS px = 1 物理像素" | 等于 DPR 个物理像素（@3x 屏 = 3 个） |
| "device-width 是物理宽度" | 是 CSS 像素宽度（440，不是 1320） |
| "DPR 是硬件参数，永远不变" | 桌面上随系统缩放和浏览器缩放实时变化；iOS Safari 上则固定 |
| "outerWidth 和 innerWidth 在手机上一样" | iOS 上 outerWidth 恒等于 screen.width，与 innerWidth（980/440）是两回事 |
| "96 DPI 和 160 PPI 是同一个东西的不同写法" | 是两套平台的基准密度定义，1dp = 0.6 CSS px |
| "设计稿 1px = CSS 1px" | @3x 设计稿的 1px 通常指物理像素，边框类需要换算 |

## 7.5 练习题

1. 某安卓手机物理分辨率 1440×3200，PPI 513，Android 基准 160。求 DPR 与 CSS 像素尺寸。
2. 在加了 `width=device-width, initial-scale=1` 的 iPhone 16 Pro Max 上，重测[第 5 章](/pixels-viewport/ch05)四个值，结果如何？
3. Windows 电脑 3840×2160、缩放 200%、浏览器缩放 100%。网页里 `width: 200px` 的元素占多少物理像素？此时 `devicePixelRatio` 是多少？
4. Android 设计稿上按钮宽 120dp，换算成 CSS 像素应写多少？

## 7.6 参考答案

> 1. DPR = 513 ÷ 160 ≈ 3.2 → 厂商通常取 3，CSS 尺寸 = 1440÷3 × 3200÷3 = 480×1067。部分机型会取 3.5x（CSS 宽约 411），以实测 `devicePixelRatio` 为准。
> 2. innerWidth = 440（布局视口 = 理想视口）；outerWidth = 440、screen.width = 440、devicePixelRatio = 3 均不变（设备固有属性）——四个值里只有 innerWidth 随 viewport 标签改变。
> 3. 有效 DPR = 2 × 1 = 2，元素占 400×400 物理像素；逻辑上占 1920×1080 逻辑桌面中的 200 个单位。
> 4. 1dp = 0.6 CSS px，120dp = 72px。
